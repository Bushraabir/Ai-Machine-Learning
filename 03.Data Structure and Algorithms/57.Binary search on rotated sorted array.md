## 1. Intuition First

### The Core Idea

Picture a clock face. The numbers 1 through 12 are in order, but the sequence _wraps_: after 12 comes 1. If someone asks "is 9 between 6 and 3?" you can't answer with a simple comparison — you have to know _which direction_ they mean. A rotated sorted array is exactly this: a sequence `[4, 5, 6, 7, 0, 1, 2]` that was once cleanly sorted, then "rotated" — cut at some pivot and the two halves swapped.

The array has one crucial structural property: **even after rotation, at least one of the two halves formed by any midpoint is strictly sorted**. Always. Without exception.

This is the load-bearing observation. A classic binary search works by knowing, after comparing `arr[mid]` to `target`, _which half to discard_. In a rotated array you cannot discard a half based on value alone — but you _can_ identify which half is cleanly sorted, check whether `target` lies within that sorted half's range, and then discard accordingly. The O(log n) structure is preserved.

### Why This Exists

The naive solution is O(n): scan every element. The standard binary search assumes a globally sorted array, which the rotation destroys. The rotated case appears precisely because:

- In practice, cyclic buffers, circular logs, and round-robin rotation of sorted data are common data structures.
- In CP, it is a canonical "make the student prove they understand the _invariant_ of binary search, not just its mechanics."
- It is the simplest example of binary search on a **non-globally-monotone** array — the predicate is not monotone over the whole array, but _locally monotone_ in recoverable pieces.

The gap: a student who memorised binary search as "go left if `arr[mid] > target`, go right if `arr[mid] < target`" will fail here. The correct framing is: **binary search requires the ability to discard half the search space at each step. To discard, you must identify a half you are certain the answer is NOT in.**

### The "Aha" Moment

At any `mid`, compare `arr[lo]` with `arr[mid]`.

- If `arr[lo] <= arr[mid]`: the **left half `[lo, mid]` is sorted**. You know its exact range. Check if `target` is within `[arr[lo], arr[mid]]`. If yes, go left. Otherwise, the target must be in the right half (which contains the rotation point) — go right.
- If `arr[lo] > arr[mid]`: the **right half `[mid, hi]` is sorted**. Check if `target` is within `[arr[mid], arr[hi]]`. If yes, go right. Otherwise go left.

You are always working with the _sorted_ half because its boundaries are known and trustworthy. The unsorted half is where you go when the sorted half definitively excludes the target.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

Rotated array problems appear in every major interview bank (LeetCode 33, 81, 153, 154) and in Codeforces problems involving cyclic sequences. The pattern generalises to:

- Finding the minimum/maximum in a rotated sorted array (locate the pivot).
- Searching in a rotated array with duplicates (LC 81) — a nastier variant.
- Range queries on arrays that have been "rolled" or cyclically shifted.
- Problems where a sorted dataset undergoes circular rotation (e.g., time-indexed logs that wrap at midnight).

**Pattern signal:** You see a sorted array with a note that it "may have been rotated" or you see values that decrease exactly once in the array. Immediate trigger: _two-region binary search_.

**Common trap — the duplicate variant:**

When duplicates are present (`[3, 1, 3, 3, 3]`), the condition `arr[lo] == arr[mid]` gives no information about which side is sorted. The standard fix is to increment `lo` (or decrement `hi`) by 1 when this ambiguity occurs — but this degrades worst-case to O(n) (all elements equal). Failing to handle this produces wrong answers on inputs like `[3, 3, 3, 1, 3]` searching for 1.

**Second common trap — the boundary comparison:**

Some implementations compare `arr[mid]` to `arr[hi]` instead of `arr[lo]`. Both are correct if done consistently, but mixing the two comparison bases in one implementation produces subtly wrong half-selection. Pick one base and derive all four cases from it.

### Machine Learning / AI

**Circular buffers in streaming inference:** Real-time ML systems (e.g., sliding-window anomaly detectors, online learning pipelines) maintain fixed-size ring buffers of recent observations. The buffer is a physically allocated array with a write head that wraps around — logically sorted by timestamp, but physically rotated at the write head. Binary-searching for a specific timestamp threshold requires exactly this algorithm. This is not hypothetical: the `collections.deque` in Python is a doubly-linked list, but numpy-based ring buffers in production inference servers use the rotated array structure directly.

**Learning rate schedules — cosine annealing with restarts:** Cosine annealing with warm restarts (SGDR, Loshchilov & Hutter 2016) produces a loss curve that oscillates — it decreases, then jumps up, then decreases again. The _schedule_ is computed from a cyclic index, which is modular arithmetic on a sorted sequence: structurally rotated. Understanding the rotation-point logic helps when implementing custom schedulers that need to binary-search for the current cycle phase given an iteration count.

**Rotation-invariant feature detection:** In computer vision, finding keypoint descriptors that are stable under image rotation involves checking whether a feature vector (sorted by angle) contains a target angle — the sort order wraps at 360°. Efficient implementations use the rotated binary search to avoid O(n) scans of descriptor histograms.

**`bisect` on wrapped sequences:** Pandas `DatetimeIndex` with cyclic time (e.g., "hour of day" features 0–23, then back to 0) sometimes requires searching a wrapped sorted index. The standard `bisect` module fails; the rotation-aware search is the correct tool. Understanding _why_ bisect fails here (it assumes global monotonicity) is the ML engineer's version of this problem.

## 3. Algorithm / Pattern

### Core Algorithm — Search in Rotated Sorted Array (No Duplicates)

**Plain English:**

1. Standard binary search loop: maintain `[lo, hi]` inclusive.
2. Compute `mid`.
3. If `arr[mid] == target`: found, return `mid`.
4. Determine which half is sorted:
    - **Left half sorted:** `arr[lo] <= arr[mid]`
        - If `arr[lo] <= target < arr[mid]`: target is in the sorted left → `hi = mid - 1`
        - Else: target is in the right (possibly unsorted) → `lo = mid + 1`
    - **Right half sorted:** `arr[mid] < arr[lo]` (equivalently `arr[mid] < arr[hi]` if you prefer the right anchor)
        - If `arr[mid] < target <= arr[hi]`: target is in the sorted right → `lo = mid + 1`
        - Else: target is in the left → `hi = mid - 1`
5. If `lo > hi`: target absent, return -1.

### Sub-problem: Find Rotation Index (Minimum Element)

The rotation index is the index of the minimum element. Its location splits the array into two sorted halves.

- If `arr[mid] > arr[hi]`: the minimum is in the right half → `lo = mid + 1`
- Else: the minimum is in the left half (including `mid`) → `hi = mid`
- Terminate when `lo == hi`: `lo` is the rotation index.

This is itself a binary search: the predicate is `arr[mid] > arr[hi]` (True = rotation point is to the right).

### Decision Tree

```
Rotated sorted array, search for target:

arr[mid] == target?
  → Return mid

arr[lo] <= arr[mid]?  (left half is sorted)
  ├── arr[lo] <= target < arr[mid]?
  │     → hi = mid - 1   (target in sorted left)
  └── else
        → lo = mid + 1   (target in unsorted right)

arr[lo] > arr[mid]?   (right half is sorted)
  ├── arr[mid] < target <= arr[hi]?
  │     → lo = mid + 1   (target in sorted right)
  └── else
        → hi = mid - 1   (target in unsorted left)
```

### Complexity

- **Time:** O(log n). Each iteration strictly halves the interval: either `lo` increases past `mid` or `hi` decreases below `mid`. After at most ⌈log₂ n⌉ iterations, `lo > hi`.
- **Space:** O(1). Iterative, no auxiliary structures.
- **Duplicates variant:** O(log n) average, O(n) worst case (all identical elements). The degenerate case requires falling back to linear scan; this is unavoidable — information-theoretically, when `arr[lo] == arr[mid] == arr[hi]`, no comparison can distinguish which side the rotation is on.

## 4. Pseudocode

```
SEARCH_ROTATED(arr, n, target):
    lo ← 0
    hi ← n - 1                         // inclusive bounds

    while lo <= hi:
        mid ← lo + (hi - lo) / 2

        if arr[mid] == target:
            return mid                  // found

        // Determine which half is guaranteed sorted
        if arr[lo] <= arr[mid]:         // left half [lo..mid] is sorted
            if arr[lo] <= target AND target < arr[mid]:
                hi ← mid - 1           // target in sorted left
            else:
                lo ← mid + 1           // target in right (contains pivot)

        else:                           // right half [mid..hi] is sorted
            if arr[mid] < target AND target <= arr[hi]:
                lo ← mid + 1           // target in sorted right
            else:
                hi ← mid - 1           // target in left (contains pivot)

    return -1                           // target not present


FIND_ROTATION_INDEX(arr, n):
    // Returns index of minimum element (= rotation point)
    // arr has no duplicates

    lo ← 0
    hi ← n - 1

    if arr[lo] <= arr[hi]:
        return 0                        // already sorted, no rotation

    while lo < hi:
        mid ← lo + (hi - lo) / 2
        if arr[mid] > arr[hi]:
            lo ← mid + 1               // min is in right half
        else:
            hi ← mid                   // min is at mid or left of mid

    return lo                           // lo == hi == rotation index


SEARCH_ROTATED_WITH_DUPLICATES(arr, n, target):
    lo ← 0
    hi ← n - 1

    while lo <= hi:
        mid ← lo + (hi - lo) / 2

        if arr[mid] == target:
            return mid

        // Ambiguous case: cannot determine sorted half
        if arr[lo] == arr[mid] AND arr[mid] == arr[hi]:
            lo ← lo + 1               // shrink both ends by 1
            hi ← hi - 1               // worst case O(n) total

        else if arr[lo] <= arr[mid]:  // left sorted
            if arr[lo] <= target AND target < arr[mid]:
                hi ← mid - 1
            else:
                lo ← mid + 1

        else:                          // right sorted
            if arr[mid] < target AND target <= arr[hi]:
                lo ← mid + 1
            else:
                hi ← mid - 1

    return -1
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <vector>
#include <iostream>
#include <cassert>

// ──────────────────────────────────────────────
// Search in rotated sorted array — no duplicates
// Returns index of target, or -1 if absent.
// Time: O(log n)  Space: O(1)
// ──────────────────────────────────────────────
int searchRotated(const std::vector<int>& arr, int target) {
    int lo = 0, hi = static_cast<int>(arr.size()) - 1;

    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;

        if (arr[mid] == target) return mid;

        if (arr[lo] <= arr[mid]) {
            // Left half [lo..mid] is sorted
            if (arr[lo] <= target && target < arr[mid]) {
                hi = mid - 1;   // target in sorted left half
            } else {
                lo = mid + 1;   // target in right half (contains pivot)
            }
        } else {
            // Right half [mid..hi] is sorted
            if (arr[mid] < target && target <= arr[hi]) {
                lo = mid + 1;   // target in sorted right half
            } else {
                hi = mid - 1;   // target in left half (contains pivot)
            }
        }
    }
    return -1;
}


// ──────────────────────────────────────────────
// Find rotation index (index of minimum element)
// Returns 0 if array is not rotated.
// Time: O(log n)  Space: O(1)
// ──────────────────────────────────────────────
int findRotationIndex(const std::vector<int>& arr) {
    int lo = 0, hi = static_cast<int>(arr.size()) - 1;

    if (arr[lo] <= arr[hi]) return 0;  // not rotated

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] > arr[hi]) {
            lo = mid + 1;   // min is in right half
        } else {
            hi = mid;       // min is at mid or left of it
        }
    }
    return lo;  // lo == hi == index of minimum
}


// ──────────────────────────────────────────────
// Search in rotated sorted array — WITH duplicates
// Worst case O(n) when all elements are equal.
// Time: O(log n) avg, O(n) worst  Space: O(1)
// ──────────────────────────────────────────────
bool searchRotatedDuplicates(const std::vector<int>& arr, int target) {
    int lo = 0, hi = static_cast<int>(arr.size()) - 1;

    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;

        if (arr[mid] == target) return true;

        // Ambiguous: can't determine which half is sorted
        if (arr[lo] == arr[mid] && arr[mid] == arr[hi]) {
            ++lo;
            --hi;
        } else if (arr[lo] <= arr[mid]) {
            // Left half sorted
            if (arr[lo] <= target && target < arr[mid]) {
                hi = mid - 1;
            } else {
                lo = mid + 1;
            }
        } else {
            // Right half sorted
            if (arr[mid] < target && target <= arr[hi]) {
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }
    }
    return false;
}


// ──────────────────────────────────────────────
// Bonus: Two-phase approach using rotation index
// Cleaner logic, same O(log n), slightly more code
// ──────────────────────────────────────────────
int searchRotatedTwoPhase(const std::vector<int>& arr, int target) {
    int n = static_cast<int>(arr.size());
    if (n == 0) return -1;

    int pivot = findRotationIndex(arr);

    // Choose which sorted segment to binary search
    int lo, hi;
    if (pivot == 0 || target < arr[0]) {
        // Target is in right segment [pivot, n-1]
        lo = pivot; hi = n - 1;
    } else {
        // Target is in left segment [0, pivot-1]
        lo = 0; hi = pivot - 1;
    }

    // Standard binary search on the chosen segment
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] == target)  return mid;
        if (arr[mid] < target)   lo = mid + 1;
        else                     hi = mid - 1;
    }
    return -1;
}


int main() {
    // ── No-duplicate tests ──
    std::vector<int> arr1 = {4, 5, 6, 7, 0, 1, 2};

    assert(searchRotated(arr1, 0) == 4);
    assert(searchRotated(arr1, 3) == -1);
    assert(searchRotated(arr1, 4) == 0);   // at rotation boundary
    assert(searchRotated(arr1, 2) == 6);   // last element

    // ── Rotation index ──
    assert(findRotationIndex(arr1) == 4);                  // arr[4] == 0
    assert(findRotationIndex({1, 2, 3, 4, 5}) == 0);      // not rotated
    assert(findRotationIndex({2, 1}) == 1);
    assert(findRotationIndex({3, 4, 5, 1, 2}) == 3);

    // ── Two-phase approach ──
    assert(searchRotatedTwoPhase(arr1, 0) == 4);
    assert(searchRotatedTwoPhase(arr1, 3) == -1);

    // ── Duplicate variant ──
    assert(searchRotatedDuplicates({2, 5, 6, 0, 0, 1, 2}, 0) == true);
    assert(searchRotatedDuplicates({2, 5, 6, 0, 0, 1, 2}, 3) == false);
    assert(searchRotatedDuplicates({3, 1, 3, 3, 3}, 1)       == true);
    assert(searchRotatedDuplicates({1, 1, 1, 1, 1}, 2)       == false); // O(n) case

    // ── Edge cases ──
    assert(searchRotated({1}, 1) == 0);
    assert(searchRotated({1}, 0) == -1);
    assert(searchRotated({1, 3}, 3) == 1);

    std::cout << "All assertions passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
"""
Binary Search on Rotated Sorted Array
======================================
Core insight: at any midpoint, at least one half is strictly sorted.
Identify the sorted half, check if target is in it, discard accordingly.

Time:  O(log n) — no duplicates
       O(log n) average, O(n) worst — with duplicates
Space: O(1)
"""

from __future__ import annotations


def search_rotated(arr: list[int], target: int) -> int:
    """
    Search target in rotated sorted array with no duplicates.
    Returns index of target, or -1 if absent.
    """
    lo, hi = 0, len(arr) - 1

    while lo <= hi:
        mid = (lo + hi) // 2

        if arr[mid] == target:
            return mid

        if arr[lo] <= arr[mid]:              # left half [lo..mid] is sorted
            if arr[lo] <= target < arr[mid]: # target in sorted left
                hi = mid - 1
            else:                            # target in right (has pivot)
                lo = mid + 1
        else:                                # right half [mid..hi] is sorted
            if arr[mid] < target <= arr[hi]: # target in sorted right
                lo = mid + 1
            else:                            # target in left (has pivot)
                hi = mid - 1

    return -1


def find_rotation_index(arr: list[int]) -> int:
    """
    Find the index of the minimum element (rotation point).
    Returns 0 if the array is not rotated.
    Predicate: arr[mid] > arr[hi]  →  min is to the right.
    """
    lo, hi = 0, len(arr) - 1

    if arr[lo] <= arr[hi]:  # not rotated
        return 0

    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] > arr[hi]:
            lo = mid + 1   # min is in right half
        else:
            hi = mid       # min is at mid or left
    return lo


def search_rotated_two_phase(arr: list[int], target: int) -> int:
    """
    Two-phase approach: first find rotation index, then standard binary search.
    Cleaner reasoning at the cost of one extra O(log n) pass.
    """
    if not arr:
        return -1

    pivot = find_rotation_index(arr)

    # Decide which sorted segment contains the target
    if pivot == 0 or target < arr[0]:
        lo, hi = pivot, len(arr) - 1   # right segment
    else:
        lo, hi = 0, pivot - 1          # left segment

    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:   return mid
        if arr[mid] < target:    lo = mid + 1
        else:                    hi = mid - 1
    return -1


def search_rotated_duplicates(arr: list[int], target: int) -> bool:
    """
    Search in rotated sorted array that may contain duplicates.
    Falls back to O(n) when arr[lo] == arr[mid] == arr[hi].
    Returns True if target exists.
    """
    lo, hi = 0, len(arr) - 1

    while lo <= hi:
        mid = (lo + hi) // 2

        if arr[mid] == target:
            return True

        # Cannot determine sorted half — shrink both ends
        if arr[lo] == arr[mid] == arr[hi]:
            lo += 1
            hi -= 1
        elif arr[lo] <= arr[mid]:            # left sorted
            if arr[lo] <= target < arr[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                                # right sorted
            if arr[mid] < target <= arr[hi]:
                lo = mid + 1
            else:
                hi = mid - 1

    return False


# ── Tests ──────────────────────────────────────────────────────────────────

if __name__ == "__main__":
    arr = [4, 5, 6, 7, 0, 1, 2]

    # Core search
    assert search_rotated(arr, 0) == 4
    assert search_rotated(arr, 3) == -1
    assert search_rotated(arr, 4) == 0
    assert search_rotated(arr, 2) == 6

    # Rotation index
    assert find_rotation_index(arr) == 4
    assert find_rotation_index([1, 2, 3, 4, 5]) == 0   # not rotated
    assert find_rotation_index([2, 1]) == 1
    assert find_rotation_index([3, 4, 5, 1, 2]) == 3

    # Two-phase
    assert search_rotated_two_phase(arr, 0) == 4
    assert search_rotated_two_phase(arr, 3) == -1
    assert search_rotated_two_phase([1], 1) == 0

    # Duplicates
    assert search_rotated_duplicates([2, 5, 6, 0, 0, 1, 2], 0) is True
    assert search_rotated_duplicates([2, 5, 6, 0, 0, 1, 2], 3) is False
    assert search_rotated_duplicates([3, 1, 3, 3, 3], 1)       is True
    assert search_rotated_duplicates([1, 1, 1, 1, 1], 2)       is False

    # Edge cases
    assert search_rotated([1], 0) == -1
    assert search_rotated([1, 3], 3) == 1
    assert search_rotated([3, 1], 1) == 1

    print("All tests passed.")
```

## 7. Common Variations & Extensions

### 7.1 Find minimum in rotated sorted array (LC 153)

This is `findRotationIndex` exactly. The predicate is `arr[mid] > arr[hi]` — if True, the minimum is in the right half. No target needed; just find where the "drop" is.

```python
def find_min(arr: list[int]) -> int:
    lo, hi = 0, len(arr) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] > arr[hi]:
            lo = mid + 1
        else:
            hi = mid
    return arr[lo]
```

With duplicates (LC 154): add `elif arr[mid] == arr[hi]: hi -= 1` before the else branch. Worst case O(n).

### 7.2 Rotated search as two clean binary searches

Find the pivot index first (O(log n)), then decide which sorted half to search, and run a standard binary search (O(log n)). Total: O(log n). This is the "two-phase" approach in the implementation section. It is slightly slower in practice (two passes) but much easier to reason about correctness — preferred in interviews where clarity matters.

### 7.3 Search in nearly sorted or k-rotated array

If an array is sorted but each element may be displaced by at most k positions from its sorted position, binary search still works with a modified window: instead of discarding exactly half, only discard indices more than k away from mid. Useful in fuzzy-sorted streaming datasets.

### 7.4 Searching in infinite / unbounded rotated arrays

If the array is unbounded (you don't know n), first use exponential search to find a bound, then apply rotated binary search. This connects to [[55.Binary search on a sorted array — exact match]] and [[62.Fractional binary search — real-valued search spaces]].

### 7.5 Connection to binary search on answer

Once you can reason about "which half is safe to discard," the [[59.The binary search on answer template — monotonic predicate]] generalises this: instead of two concrete sorted halves, you have a predicate that is monotone over the whole search space. The rotated array case is harder precisely because the predicate is _not_ globally monotone — it is only locally monotone within each chunk. This contrast sharpens the understanding of what "monotone predicate" really requires.

**Progression:** 33 (the canonical problem, implement `searchRotated`) → 153 (find min, implement `findRotationIndex`) → 154 (find min with duplicates, add the `arr[mid]==arr[hi]` branch) → 81 (search with duplicates, add `arr[lo]==arr[mid]==arr[hi]` branch) → 1095 (mountain array, generalisation of the same half-identification logic).

## 9. CP Contest Application

### Typical Codeforces / AtCoder structure

The rotated array problem rarely appears _verbatim_ in CF rounds — instead, it appears as a component:

**Pattern 1 — Cyclic array queries:**  
"Given a circular array of n elements (sorted before rotation), answer q queries: does value v exist?"  
Offline sort all queries, but each lookup is O(log n) via rotated search. Total: O(q log n).

**Pattern 2 — Range minimum in circular array:**  
Find the global minimum of a cyclically shifted sorted array, then use it as the split point for range queries. The rotation index is the split point.

**Pattern 3 — Bitonic / mountain array:**  
A mountain array increases then decreases — it is the rotated search idea applied to a unimodal function. Find the peak, then binary search each side. This is LC 162 and a staple in CF Div. 2 C/D problems.

### Time limits where this matters

At n = 10^6 and q = 10^5 queries: naïve O(nq) = 10^11 operations → definite TLE at 10^8 ops/sec. Rotated binary search: O((n + q) log n) ≈ 2 × 10^6 → well within limits. The pattern is recognisable under time pressure: sorted + rotation + search + tight time limit = this algorithm.

### Optimisation note

In C++, the STL has no built-in for rotated search. Implement it as a free function with `const std::vector<int>&` parameter and `int` bounds to avoid iterator overhead in tight loops. Avoid `std::rotate` (it mutates in O(n)) — you never need to physically un-rotate the array.
