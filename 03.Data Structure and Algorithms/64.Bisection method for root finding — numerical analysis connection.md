## 1. Intuition First

### The Core Idea

You have a continuous function `f(x)` and you know two things:

- `f(a) < 0`
- `f(b) > 0`

By the **Intermediate Value Theorem** (IVT), `f` must cross zero somewhere in `[a, b]`. You don't know where. You want to find it.

The bisection method is the most conservative imaginable strategy: evaluate `f` at the midpoint `m = (a + b) / 2`. If `f(m) > 0`, the root is in `[a, m]`. If `f(m) < 0`, it's in `[m, b]`. If `f(m) = 0`, you found it exactly. Either way, the interval containing the root is halved. Repeat until the interval is smaller than your tolerance `ε`.

This is binary search. Not an analogy — it is _literally_ binary search applied to a continuous function over the real line, where the "array" is the function's domain and the "predicate" is the sign of `f`.

The connection runs deeper than metaphor. In [[62.Fractional binary search — real-valued search spaces]], the predicate was `feasible(x)` — a boolean function that switches from false to true at some threshold `x*`. Here the predicate is `f(x) ≥ 0` — which switches from false to true exactly at a root. The two problems are **identical in structure**. Fractional binary search _is_ bisection; bisection _is_ fractional binary search.

What makes this worth its own note is the numerical analysis context: how fast does it converge, why is it sometimes inferior to Newton's method, why is it sometimes _superior_, and exactly where does it appear inside ML systems — not as an abstraction but as the literal algorithm running in `scipy.optimize.brentq`.

### Why This Exists

Root finding is ubiquitous. Any equation of the form `g(x) = c` is a root-finding problem: define `f(x) = g(x) − c` and find `f(x) = 0`. This covers:

- Finding where a loss function equals a target value.
- Finding the learning rate where gradient norm crosses a threshold.
- Solving the score equation in maximum likelihood estimation (MLE).
- Finding the zero-crossing of a derivative for analytical optimisation.
- Computing the inverse CDF (quantile function) for any distribution where the CDF has no closed-form inverse.

Alternatives exist — Newton's method, secant method, Brent's method — but they all have failure modes. Newton's method requires `f'(x)` and diverges if the initial guess is outside a basin of convergence. Bisection requires nothing beyond evaluability of `f` and the sign-change bracket. It **always converges** given a valid bracket. That guarantee is the reason it appears in every numerical library as the fallback beneath faster methods.

### The "Aha" Moment

> **Every root-finding problem is a binary search problem. Every binary search problem on a monotone predicate is a root-finding problem. The two communities developed the same algorithm independently — one for data, one for functions.**

The IVT is the continuous analog of the discrete fact that a sorted array must pass through every integer value between its endpoints. The sign change `f(a) < 0, f(b) > 0` is the continuous analog of `arr[lo] < target ≤ arr[hi]`. The bisection step is `mid = (lo + hi) / 2` in both.

Once you see this, you can transfer intuitions between domains. The "100 iterations gives full float64 precision" rule from [[62.Fractional binary search — real-valued search spaces]] applies identically here. The convergence rate O(log(1/ε)) is the same as O(log n) in binary search — they are the same formula with different interpretations.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

Root finding in CP appears in disguised forms:

**Direct occurrences:**

- **Geometry problems**: find the x-coordinate where two curves intersect. Define `f(x) = curve1(x) − curve2(x)` and bisect.
- **Physics simulation**: find the time `t` at which a projectile hits the ground. Define `f(t) = height(t)` and bisect on `[0, t_max]`.
- **Convex function minimisation**: the minimum of a convex `g(x)` satisfies `g'(x) = 0`. If you can evaluate `g'(x)` (or approximate it), bisect on `g'` to find its zero — the minimum.

**Pattern signal:**

> When you see: _"find the value x where [continuous quantity] equals [target]"_ and you can evaluate the quantity at any x → **bisect on f(x) = quantity(x) − target**.

**Common trap:** Bisection requires a **sign change bracket** `[a, b]` with `f(a)` and `f(b)` having opposite signs. If you pick `a` and `b` with the same sign, bisection gives no information. In CP, the failure mode is picking `lo = 0` when `f(0)` is already positive — no bracket exists. Always verify the bracket before bisecting: `assert f(a) * f(b) < 0`.

A second trap is **multiple roots**: if `f` has two roots in `[a, b]`, bisection finds _one_ of them but not necessarily the one you want. For CP problems with multiple intersection points, bisect on sub-intervals separately.

---

### Machine Learning / AI

**This is where bisection lives in production.**

_1. Inverse CDF sampling (quantile functions):_ Many distributions — Beta, Gamma, Chi-squared, Student's t — have CDFs with no closed-form inverse. To sample from them or compute quantiles, you solve `CDF(x) = p` for `x`. Since `CDF` is monotone (it's a CDF), this is a monotone root-finding problem. `scipy.stats` distributions compute quantiles via `ppf()` (percent point function), which internally uses Brent's method — bisection with quadratic interpolation acceleration. Every call to `norm.ppf(0.975)` (the 97.5th percentile of a normal, giving 1.96) triggers this machinery.

_2. Temperature scaling (calibration):_ Guo et al. (2017) find the optimal temperature `T*` minimising Expected Calibration Error (ECE). The objective is: $$\text{ECE}(T) = \sum_b \frac{|B_b|}{n} \left| \text{acc}(B_b) - \text{conf}(B_b, T) \right|$$ This is not differentiable everywhere (due to bin boundaries), but it is approximately monotone in `T`. The implementation in the calibration library uses `scipy.optimize.brentq` — bisection — on the log-ECE gradient rather than gradient descent, because gradient descent would require backpropagating through the binning operation.

_3. Finding the learning rate at the loss inflection point (LR range test):_ The learning rate range test (Smith, 2017) sweeps LR and records loss. The "optimal LR" is near the point where loss starts increasing steeply — the inflection point of the loss-vs-LR curve. Finding this point is a root-finding problem on `d(loss)/d(lr) = threshold`. In practice, `fast.ai` implements this as a sweep (O(n) evaluations); the bisection version does it in O(log n) evaluations.

_4. SVM dual problem and KKT conditions:_ Training an SVM with SMO (Sequential Minimal Optimisation) requires solving quadratic sub-problems. The bias term `b` in `f(x) = w·x + b` is found by requiring the KKT conditions, which gives an equation `g(b) = 0` solved by bisection when the analytical formula is numerically unstable near the support vectors.

_5. Quantile regression and pinball loss:_ In quantile regression at quantile `τ`, the optimal prediction `q*` satisfies: $$\mathbb{P}(Y \leq q^*) = \tau$$ This is `CDF(q*) = τ`, a root-finding problem on the empirical CDF. For large datasets, `np.quantile` uses a sort-and-interpolate approach (O(n log n)), but for streaming data or parametric models, bisection on the CDF is the correct approach.

_6. Newton's method for logistic regression — when it fails and bisection steps in:_ Newton's method for logistic regression updates: $$\theta \leftarrow \theta - H^{-1} \nabla \mathcal{L}$$ When the Hessian is nearly singular (near-collinear features), the Newton step overshoots. The line search that corrects the step size — finding `α` such that `L(θ + α Δθ) ≤ L(θ) + c α ∇L·Δθ` — is a root-finding problem on `α`. The Wolfe conditions line search uses bisection as its fallback. This appears in `scipy.optimize.minimize(method='Newton-CG')` and in `statsmodels` logistic regression.

**Framework reference:**

- `scipy.optimize.bisect(f, a, b, xtol=1e-12)` — pure bisection.
- `scipy.optimize.brentq(f, a, b)` — Brent's method (bisection + secant + inverse quadratic interpolation). Almost always faster than pure bisection; bisection is its guaranteed-convergence fallback.
- `scipy.optimize.brenth` — variant of Brent's method with different interpolation.
- `numpy.roots` — finds polynomial roots via eigenvalues of companion matrix, not bisection.
- `torch.optim` line searches in L-BFGS internally use strong Wolfe conditions with bisection fallback.

## 3. Algorithm / Pattern

### The Bisection Algorithm

**Precondition:** `f` is continuous on `[a, b]`, `f(a)` and `f(b)` have opposite signs (sign change bracket).

**Guarantee:** the algorithm converges to a root in `[a, b]` with error ≤ `(b − a) / 2ⁿ` after `n` iterations.

**Step-by-step:**

```
1. Verify bracket:  f(a) * f(b) < 0  (opposite signs)
2. Compute midpoint: m = a + (b - a) / 2
3. Evaluate f(m)
4. If |f(m)| < ε (tolerance on function value) OR (b - a) < δ (tolerance on interval): STOP
5. If sign(f(m)) == sign(f(a)): root is in [m, b] → a = m
6. Else: root is in [a, m] → b = m
7. Go to 2
```

### Convergence Analysis

After `n` bisection steps the interval width is: $$\text{error}_n = \frac{b - a}{2^n}$$

To achieve tolerance `ε`: $$n \geq \log_2!\left(\frac{b-a}{\varepsilon}\right)$$

This is **linear convergence** (error reduces by a constant factor per step — factor 2). Compare:

|Method|Convergence rate|Derivative needed?|Diverges?|
|---|---|---|---|
|Bisection|Linear: error × 1/2 per step|No|Never (given bracket)|
|Newton's method|Quadratic: error² per step|Yes (`f'`)|Yes (bad initial guess)|
|Secant method|Superlinear: error^1.618 per step|No|Yes (bad initial guess)|
|Brent's method|Superlinear (adaptive)|No|Never (given bracket)|

**Practical implication:** Newton's method needs ~7 iterations to go from error `10⁻¹` to `10⁻¹²⁸` (quadratic: `10⁻¹ → 10⁻² → 10⁻⁴ → 10⁻⁸ → ...`). Bisection needs `log₂(10¹¹) ≈ 37` iterations. For cheap function evaluations, Newton wins. For expensive evaluations (e.g., running a neural network forward pass), bisection wins by minimising evaluation count.

### When to Use vs. When to Avoid

|Use bisection when|Use Newton/Brent instead when|
|---|---|
|`f'` is unavailable or expensive|`f'` is cheap and available|
|Convergence guarantee is critical|Speed is paramount and divergence risk is acceptable|
|`f` is non-smooth (Lipschitz but not differentiable)|`f` is smooth — Brent's method converges faster with same guarantees|
|Only need moderate precision (6–9 digits)|Need high precision (15 digits) quickly — Newton gets there in ~7 steps|
|First pass / exploratory numerical work|Production numerics with known-smooth objectives|

The rule of thumb in numerical analysis:

> **Use Brent's method by default. Use bisection when you need to understand what's happening or when implementing from scratch. Use Newton when you have the derivative and convergence speed matters.**

## 4. Pseudocode

```
BISECT(f, a, b, tol_x=1e-12, tol_f=1e-12, max_iter=200):
    // f:      continuous function R → R
    // a, b:   bracket endpoints with f(a)*f(b) < 0
    // tol_x:  stop when interval width < tol_x (x-tolerance)
    // tol_f:  stop when |f(mid)| < tol_f (function-value tolerance)
    // Returns: approximate root x* with |f(x*)| < tol_f or interval < tol_x

    fa ← f(a)
    fb ← f(b)

    // Precondition: bracket must exist
    IF fa * fb > 0:
        ERROR "No sign change in [a, b]: bracket invalid"

    IF fa == 0: RETURN a    // a is already a root
    IF fb == 0: RETURN b    // b is already a root

    FOR iter FROM 1 TO max_iter:
        mid ← a + (b - a) / 2.0    // numerically stable midpoint

        fm ← f(mid)

        // Termination: root found or interval small enough
        IF |fm| < tol_f OR (b - a) < tol_x:
            RETURN mid

        // Update bracket: keep the half with the sign change
        IF sign(fm) == sign(fa):
            a ← mid          // root is in [mid, b]
            fa ← fm
        ELSE:
            b ← mid          // root is in [a, mid]
            // fb ← fm  (not needed — we only track fa's sign)

    // Reached max_iter without convergence — return best estimate
    RETURN (a + b) / 2.0


// ── Brent's Method (production version) ──
// Combines bisection with secant and inverse quadratic interpolation.
// Falls back to bisection whenever interpolation would give a bad step.

BRENT(f, a, b, tol=1e-12):
    fa ← f(a),  fb ← f(b)
    ASSERT fa * fb < 0

    // Ensure |fb| <= |fa| (b is closer to root)
    IF |fa| < |fb|:
        SWAP(a, b),  SWAP(fa, fb)

    c, fc ← a, fa         // c is the previous b
    mflag ← true          // use bisection on first step

    LOOP:
        IF fb == 0 OR |b - a| < tol: RETURN b

        IF fa != fc AND fb != fc:
            // Inverse quadratic interpolation (3 distinct points)
            s ← a*fb*fc/((fa-fb)*(fa-fc)) + b*fa*fc/((fb-fa)*(fb-fc)) + c*fa*fb/((fc-fa)*(fc-fb))
        ELSE:
            // Secant method (2 points)
            s ← b - fb*(b-a)/(fb-fa)

        // Conditions to reject interpolation and fall back to bisection
        use_bisection ← NOT (
            s is in [(3a+b)/4, b] AND
            (mflag AND |s-b| < |b-c|/2) OR
            (NOT mflag AND |s-b| < |c-d|/2)
        )

        IF use_bisection:
            s ← (a + b) / 2.0   // bisection step
            mflag ← true
        ELSE:
            mflag ← false

        fs ← f(s)
        d ← c,  c ← b,  fc ← fb

        IF fa * fs < 0:
            b ← s,  fb ← fs
        ELSE:
            a ← s,  fa ← fs

        IF |fa| < |fb|:
            SWAP(a, b),  SWAP(fa, fb)
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

/**
 * Bisection Method — Root Finding
 *
 * Finds x* in [a, b] such that f(x*) ≈ 0, given f(a)*f(b) < 0.
 *
 * Time:  O(log((b-a)/tol) * cost_of_f)
 * Space: O(1)
 */

struct RootResult {
    double root;
    double f_value;
    int    iterations;
    bool   converged;
};

template <typename F>
RootResult bisect(F f, double a, double b,
                  double tol_x = 1e-12,
                  double tol_f = 1e-12,
                  int    max_iter = 200)
{
    double fa = f(a), fb = f(b);

    // Validate bracket
    if (fa * fb > 0) {
        throw invalid_argument("f(a) and f(b) must have opposite signs");
    }
    if (fa == 0.0) return {a, 0.0, 0, true};
    if (fb == 0.0) return {b, 0.0, 0, true};

    // Ensure fa < 0 < fb (orient the bracket)
    // This simplifies sign logic: we track which side is negative
    bool flipped = (fa > 0);
    if (flipped) { swap(a, b); swap(fa, fb); }

    double mid = a, fm = fa;
    int iter = 0;

    for (; iter < max_iter; ++iter) {
        mid = a + (b - a) / 2.0;   // numerically stable
        fm  = f(mid);

        if (abs(fm) < tol_f || (b - a) < tol_x) {
            break;
        }

        if (fm < 0) {
            a = mid;    // root in [mid, b]
        } else {
            b = mid;    // root in [a, mid]
        }
    }

    return {mid, fm, iter, (abs(fm) < tol_f || (b - a) < tol_x)};
}

// ── Application 1: Inverse CDF of a distribution ──
// Find the x-th quantile of the logistic distribution CDF(x) = 1/(1+e^{-x})
// i.e., solve 1/(1+e^{-x}) = p  →  f(x) = 1/(1+e^{-x}) - p = 0

double logistic_ppf(double p) {
    if (p <= 0.0 || p >= 1.0) throw invalid_argument("p must be in (0,1)");
    auto f = [p](double x) { return 1.0 / (1.0 + exp(-x)) - p; };
    // Analytical answer: log(p/(1-p)) -- bisect to verify
    auto result = bisect(f, -100.0, 100.0);
    return result.root;
}

// ── Application 2: Find optimal learning rate from loss curve ──
// Given a discrete loss-vs-lr curve, find the lr where loss equals target
// by interpolating and bisecting.

double find_threshold_lr(const vector<double>& lrs,
                          const vector<double>& losses,
                          double target_loss)
{
    // Linear interpolation between sampled points, then bisect
    int n = lrs.size();
    assert(n == (int)losses.size() && n >= 2);

    // Find the interval [lrs[i], lrs[i+1]] containing the crossing
    int crossing = -1;
    for (int i = 0; i < n - 1; ++i) {
        double f_i   = losses[i]   - target_loss;
        double f_ip1 = losses[i+1] - target_loss;
        if (f_i * f_ip1 <= 0) { crossing = i; break; }
    }
    if (crossing == -1) throw runtime_error("No crossing found");

    // Interpolated function on [lrs[crossing], lrs[crossing+1]]
    double x0 = lrs[crossing], x1 = lrs[crossing + 1];
    double y0 = losses[crossing], y1 = losses[crossing + 1];
    auto f = [&](double x) {
        // Linear interpolation
        double t = (x - x0) / (x1 - x0);
        return y0 + t * (y1 - y0) - target_loss;
    };

    auto result = bisect(f, x0, x1);
    return result.root;
}

// ── Application 3: Newton's method with bisection fallback (line search) ──
// Find step size alpha satisfying Armijo condition:
// f(x + alpha * d) <= f(x) + c * alpha * grad_f(x) . d

double armijo_line_search(
    function<double(double)> f_along_line,  // f(x + alpha*d) as function of alpha
    double f0,       // f(x)
    double df0,      // grad_f(x) . d (directional derivative, should be < 0)
    double c = 1e-4) // Armijo constant
{
    // Armijo condition: h(alpha) = f(x + alpha*d) - f(x) - c*alpha*df0 <= 0
    // We want the largest alpha satisfying this.
    // h(0) = 0 (trivially satisfied), h(1) may not be satisfied.
    // Find the root of h'(alpha) approximately, then bracket.

    auto h = [&](double alpha) {
        return f_along_line(alpha) - f0 - c * alpha * df0;
    };

    // h(0) = 0. If h(1) <= 0, alpha=1 works (full Newton step).
    if (h(1.0) <= 0) return 1.0;

    // Binary search for largest alpha in (0, 1] where h(alpha) <= 0
    // h is roughly monotone increasing (convex f along direction d)
    // Find the sign change: h(0)=0, h(1)>0 → root near 0
    double lo = 0.0, hi = 1.0;
    for (int i = 0; i < 60; ++i) {
        double mid = lo + (hi - lo) / 2.0;
        if (h(mid) <= 0) lo = mid;
        else             hi = mid;
    }
    return lo;
}

int main() {
    // Test 1: Find sqrt(2) = root of f(x) = x^2 - 2
    {
        auto f = [](double x) { return x * x - 2.0; };
        auto r = bisect(f, 1.0, 2.0);
        printf("sqrt(2) via bisection: %.15f\n", r.root);
        printf("Expected:              %.15f\n", sqrt(2.0));
        printf("Error: %.2e, Iterations: %d\n\n", abs(r.root - sqrt(2.0)), r.iterations);
    }

    // Test 2: Inverse CDF of logistic at p=0.75 (should be ln(3) ≈ 1.0986)
    {
        double q = logistic_ppf(0.75);
        printf("logistic_ppf(0.75): %.10f\n", q);
        printf("Expected log(3):    %.10f\n\n", log(3.0));
    }

    // Test 3: Find crossing of x^3 - x - 1 = 0 (has one real root ≈ 1.3247)
    {
        auto f = [](double x) { return x*x*x - x - 1.0; };
        auto r = bisect(f, 1.0, 2.0, 1e-15);
        printf("Root of x^3-x-1: %.15f\n", r.root);
        printf("f(root) = %.2e, converged: %s\n\n",
               r.f_value, r.converged ? "yes" : "no");
    }

    // Test 4: No bracket — should throw
    {
        auto f = [](double x) { return x * x + 1.0; };  // no real roots
        try {
            bisect(f, -10.0, 10.0);
            printf("ERROR: should have thrown\n");
        } catch (const invalid_argument& e) {
            printf("Correctly caught: %s\n\n", e.what());
        }
    }

    // Test 5: Multiple roots — bisection finds one
    {
        // f(x) = (x-1)(x-3) = x^2 - 4x + 3, roots at 1 and 3
        auto f = [](double x) { return (x-1.0)*(x-3.0); };
        auto r1 = bisect(f, 0.0, 2.0);   // finds root near 1
        auto r2 = bisect(f, 2.0, 4.0);   // finds root near 3
        printf("Root in [0,2]: %.10f (expected 1.0)\n", r1.root);
        printf("Root in [2,4]: %.10f (expected 3.0)\n", r2.root);
    }

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations
from typing import Callable, NamedTuple
import math


class RootResult(NamedTuple):
    root: float
    f_value: float
    iterations: int
    converged: bool


def bisect(
    f: Callable[[float], float],
    a: float,
    b: float,
    tol_x: float = 1e-12,
    tol_f: float = 1e-12,
    max_iter: int = 200,
) -> RootResult:
    """
    Find a root of f in [a, b] using the bisection method.

    Requires f(a) and f(b) to have opposite signs (sign-change bracket).
    Guaranteed to converge; error after n steps = (b-a) / 2^n.

    Args:
        f:        Continuous function R -> R.
        a, b:     Bracket endpoints. f(a) * f(b) must be < 0.
        tol_x:    Stop when interval width < tol_x.
        tol_f:    Stop when |f(mid)| < tol_f.
        max_iter: Maximum iterations (200 gives ~60 decimal places of precision).

    Returns:
        RootResult with root approximation, function value, iteration count,
        and convergence flag.

    Time:  O(max_iter * cost_of_f)  =  O(log((b-a)/tol_x) * cost_of_f)
    Space: O(1)
    """
    fa, fb = f(a), f(b)

    if fa * fb > 0:
        raise ValueError(
            f"f(a)={fa:.6g} and f(b)={fb:.6g} have the same sign. "
            "No guaranteed root in [{a}, {b}]."
        )
    if fa == 0.0:
        return RootResult(a, 0.0, 0, True)
    if fb == 0.0:
        return RootResult(b, 0.0, 0, True)

    # Orient: ensure fa < 0 (a is on the negative side)
    if fa > 0:
        a, b = b, a
        fa, fb = fb, fa

    mid = a
    fm = fa
    for i in range(max_iter):
        mid = a + (b - a) / 2.0      # numerically stable midpoint
        fm = f(mid)

        if abs(fm) < tol_f or (b - a) < tol_x:
            return RootResult(mid, fm, i + 1, True)

        if fm < 0:
            a = mid     # root is in [mid, b]
        else:
            b = mid     # root is in [a, mid]

    return RootResult(mid, fm, max_iter, False)


# ── Application 1: Inverse CDF (quantile function) via bisection ──

def inverse_cdf(cdf: Callable[[float], float],
                p: float,
                lo: float,
                hi: float) -> float:
    """
    Compute the p-th quantile of a distribution with given CDF.
    Solves CDF(x) = p by bisecting on f(x) = CDF(x) - p.

    This is what scipy.stats.*.ppf() does internally via Brent's method.

    Args:
        cdf: Monotone non-decreasing function [lo, hi] -> [0, 1].
        p:   Target probability in (0, 1).
        lo:  Lower search bound (CDF(lo) must be < p).
        hi:  Upper search bound (CDF(hi) must be > p).

    Returns:
        x* such that CDF(x*) ≈ p.
    """
    if not (0 < p < 1):
        raise ValueError(f"p must be in (0, 1), got {p}")
    result = bisect(lambda x: cdf(x) - p, lo, hi)
    return result.root


# ── Application 2: Newton's method with bisection as fallback ──

def newton_with_bisection_fallback(
    f: Callable[[float], float],
    df: Callable[[float], float],
    x0: float,
    bracket: tuple[float, float] | None = None,
    tol: float = 1e-12,
    max_iter: int = 100,
) -> float:
    """
    Newton's method for root finding, with bisection fallback.

    Newton's method converges quadratically near a root but can diverge.
    When a bracket [a, b] is known, we use it to constrain Newton steps:
    if a Newton step leaves the bracket, fall back to bisection step.
    This is the core idea behind Brent's method.

    Args:
        f:       Function whose root we seek.
        df:      Derivative of f.
        x0:      Initial guess.
        bracket: Optional (a, b) with f(a)*f(b) < 0. Used as safety net.
        tol:     Convergence tolerance.
        max_iter: Maximum iterations.

    Returns:
        Approximate root x*.
    """
    x = x0
    a, b = bracket if bracket else (x0 - 1e6, x0 + 1e6)
    fa = f(a)

    for i in range(max_iter):
        fx = f(x)
        if abs(fx) < tol:
            return x

        dfx = df(x)
        if abs(dfx) < 1e-15:
            # Derivative near zero — Newton step undefined, use bisection
            x = a + (b - a) / 2.0
        else:
            newton_step = x - fx / dfx
            if a <= newton_step <= b:
                x = newton_step     # Newton step is safe
            else:
                x = a + (b - a) / 2.0  # Bisection fallback

        # Update bracket
        if f(x) * fa < 0:
            b = x
        else:
            a = x
            fa = f(x)

    return x


# ── Application 3: Convergence rate comparison ──

def compare_convergence(f: Callable[[float], float],
                         df: Callable[[float], float],
                         a: float, b: float,
                         true_root: float) -> None:
    """
    Compare bisection vs Newton's method on the same problem.
    Shows linear vs quadratic convergence empirically.
    """
    print(f"{'Iter':>4}  {'Bisection error':>18}  {'Newton error':>18}")
    print("-" * 46)

    # Bisection state
    ba, bb = a, b
    if f(ba) > 0:
        ba, bb = bb, ba

    # Newton state
    nx = (a + b) / 2.0  # start Newton from midpoint

    for i in range(12):
        # Bisection step
        bm = ba + (bb - ba) / 2.0
        if f(bm) < 0:
            ba = bm
        else:
            bb = bm
        b_err = abs(bm - true_root)

        # Newton step
        fnx = f(nx)
        dfnx = df(nx)
        if abs(dfnx) > 1e-15:
            nx = nx - fnx / dfnx
        n_err = abs(nx - true_root)

        print(f"{i+1:>4}  {b_err:>18.2e}  {n_err:>18.2e}")


# ── Application 4: Log-sum-exp root finding (ML numerical stability) ──

def stable_logsumexp(log_probs: list[float]) -> float:
    """
    Compute log(sum(exp(log_probs))) stably.
    Related to [[221.Numerical stability]] — shown here for context.
    The inverse (finding log_prob* such that softmax sums to 1 under a
    temperature parameter) is a root-finding problem solved by bisection.
    """
    c = max(log_probs)
    return c + math.log(sum(math.exp(lp - c) for lp in log_probs))


def find_temperature_for_entropy(
    logits: list[float],
    target_entropy: float,
    t_lo: float = 1e-3,
    t_hi: float = 1e3,
) -> float:
    """
    Find temperature T such that softmax(logits/T) has the given entropy.

    Entropy H(T) = -sum(p_i * log(p_i)) where p_i = softmax(logits/T).
    H(T) is monotone increasing in T (higher T → more uniform → higher entropy).

    This is a root-finding problem: H(T) - target_entropy = 0.
    Solved by bisection on T in [t_lo, t_hi].

    Applications: language model temperature calibration, policy entropy
    regularisation in RL (e.g., SAC algorithm's entropy target).
    """
    def entropy_at(T: float) -> float:
        scaled = [l / T for l in logits]
        # Stable softmax
        c = max(scaled)
        exps = [math.exp(s - c) for s in scaled]
        total = sum(exps)
        probs = [e / total for e in exps]
        return -sum(p * math.log(p + 1e-15) for p in probs)

    f = lambda T: entropy_at(T) - target_entropy
    result = bisect(f, t_lo, t_hi)
    return result.root
```

## 7. Common Variations & Extensions

### Variation 1: Brent's Method — Bisection with Acceleration

Brent's method (1973) is the production-grade root finder. It combines three strategies: bisection (guaranteed convergence), secant method (superlinear convergence near root), and inverse quadratic interpolation (even faster near root). The key rule: always take an interpolation step _unless_ it would give a step smaller than the last bisection step or leave the bracket — in which case fall back to bisection. This ensures `scipy.optimize.brentq` is both fast (like Newton's) and guaranteed to converge (like bisection). Understanding bisection is the prerequisite for understanding Brent.

### Variation 2: Regula Falsi (False Position)

Instead of always taking the midpoint, regula falsi interpolates linearly: $$m = a - f(a) \cdot \frac{b - a}{f(b) - f(a)}$$ This is the x-intercept of the secant line through `(a, f(a))` and `(b, f(b))`. Faster than bisection when `f` is smooth near the root; slower when one endpoint is stuck (the "Illinois algorithm" fixes this pathology). Useful context: regula falsi is to bisection what secant method is to Newton's — a derivative-free acceleration that can be beaten by the basic method on pathological inputs.

### Variation 3: Bisection in Higher Dimensions — Interval Newton Method

In 1D, bisection requires only a sign change. In multiple dimensions, the analog is the **interval Newton method**: compute a bounding box for `f(x) = 0` and iteratively halve the box. This is used in verified computing (rigorous numerical bounds) and connects to **branch-and-bound** algorithms in integer programming — the same recursive halving idea applied to feasibility regions rather than intervals.

### Variation 4: Stochastic Bisection (Noisy Function Evaluations)

When `f(x)` is only available with noise (e.g., estimated from samples), deterministic bisection can be fooled by noise. **Stochastic bisection** (Waeber et al., 2013) replaces the binary sign comparison with a probabilistic update: `P(root > mid) ← P(root > mid) × P(f(mid) > 0 | root < mid)`. This is Bayesian bisection — it connects to [[195.Bayes' theorem — derivation and intuition]] and appears in bandit algorithms for threshold estimation.

### Variation 5: Bisection for Non-Monotone Functions (Scan + Bracket)

When `f` may have multiple roots (not monotone), bisection alone can't find all of them. The standard approach: **scan** the domain at coarse resolution to find all sign-change intervals, then **bisect within each interval** to localise each root precisely. This O(scan + k × log(1/ε)) approach appears in polynomial root refinement and in computational physics for finding all eigenvalues of a tridiagonal matrix via Sturm sequences.

## 9. CP Contest Application

### When Bisection Appears in Contests

**Geometry track (Div. 1 D/E):**

- "Find the radius of the largest circle fitting in a polygon" — binary search on radius, feasibility = can you place the circle without intersection (O(n) check per query).
- "Find the water level when volume = V in an irregular vessel" — binary search on level, feasibility computed via integration.

**Physics track:**

- Projectile problems: binary search on time, feasibility = height ≥ 0.
- Two-body collision: binary search on time, feasibility = distance ≤ threshold.

**Optimisation track:**

- "Minimise the maximum [value] over [continuous parameter]" → if the feasibility check is O(n), bisect. Connects directly to [[60.Minimise the maximum or maximise the minimum — canonical pattern]].

### Numerical Precision in Contest Code

Contests that require real-valued bisection almost always accept answers within `1e-6` or `1e-9` absolute/relative error. The standard contest template:

```cpp
// CP template: 100 iterations, always correct
double lo = /* lower bound */, hi = /* upper bound */;
for (int i = 0; i < 100; ++i) {
    double mid = lo + (hi - lo) / 2.0;
    if (feasible(mid)) hi = mid;
    else               lo = mid;
}
printf("%.9f\n", (lo + hi) / 2.0);
```

**Never** use `while (lo < hi)` for floats (see [[62.Fractional binary search — real-valued search spaces]] Section 6).

### The Hidden Cost: Function Evaluation Count

In problems where the feasibility check runs an O(n) or O(n log n) algorithm, total complexity is O(100 × n log n). At n = 10⁵:

- Each feasibility call: ~10⁵ × 17 = 1.7 × 10⁶ operations.
- 100 iterations: 1.7 × 10⁸ operations.
- At 10⁸ ops/sec in C++: ~1.7 seconds — tight for a 2-second TL.

Optimisation: reduce from 100 to `ceil(log₂((hi - lo) / 1e-9))` iterations (often 50–60), halving the constant factor.

### Relationship to Newton's Method in CP

Newton's method for integer problems (finding the integer part of √n) converges in ~7 iterations instead of ~30 for bisection. For problems requiring the integer square root exactly:

```cpp
// Newton's method for integer sqrt — faster than bisection in CP
long long isqrt(long long n) {
    if (n < 0) return -1;
    long long x = sqrt((double)n);
    // Correct for floating-point error
    while (x * x > n) --x;
    while ((x+1) * (x+1) <= n) ++x;
    return x;
}
```

This connects to the broader theme: bisection is the safe, correct baseline. Newton (or Brent) is the speed optimisation — applied when the analytical structure (smooth derivative) is available. Both are root-finding methods; only their use of derivative information differs. The numerical analysis connection is what separates a practitioner who "knows binary search" from one who understands the entire landscape of root-finding algorithms and can choose appropriately.
