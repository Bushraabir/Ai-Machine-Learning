## 1. Intuition First

### The Core Idea

Imagine you are an auditor reviewing a ledger of transactions, one line at a time. You do not jump around. You read left to right, you maintain a running mental note — the current total, the last anomaly you spotted, the index where something suspicious happened — and you update that note as each new entry is processed.

That is linear scan with index tracking in its most distilled form: **a single pass through a sequence, maintaining one or more tracked variables that encode the history of what you have already seen**.

The elegance is in the constraint. Because you move in only one direction and never revisit an element, the algorithm is forced to extract everything it needs from the current element _before_ moving on. This discipline — "I get one shot at each element" — is what drives the design of every variable you choose to track.

### Why This Exists

The naive approach to most array problems is brute force: for every position, look backward or forward at all other positions. This gives O(n²) time. For n = 10⁵, that is 10¹⁰ operations — unusable.

Linear scan works because many problems have **optimal substructure in the sequential direction**: the answer for the prefix ending at index `i` can be derived from the answer for the prefix ending at `i-1` plus a constant-time update. The tracked variable _is_ the compressed representation of that prefix.

The complexity gap is not marginal. O(n) vs O(n²) is the difference between a 100ms and 27-hour runtime on a dataset of size 10⁶.

### The "Aha" Moment

> **You do not need to remember the entire past. You only need to remember the right summary of the past.**

Every linear scan problem reduces to answering: _what is the minimal information I must carry forward so that, when I look at the next element, I can update my answer in O(1)?_

For "find the maximum so far" — track one integer.  
For "find the first index where condition X was met" — track one index.  
For "find whether a target sum exists ending here" — track a running sum and a set of previously seen sums (this is [[24.Subarray sum equals k — prefix sum + HashMap]]).

The tracked variables are your state. Designing them correctly is the entire problem.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Linear scan is the most common underlying mechanism in Codeforces Div. 2 A/B problems and appears as a sub-step in virtually every harder problem. Recognise it when the problem says:

- "Find the first/last index where..."
- "Count elements satisfying a condition as you sweep"
- "Maximum/minimum of something computed as you walk the array"
- "Check if array is non-decreasing / find the first violation"

**Pattern signal:** If you can write a solution where the loop body only reads `a[i]` and updates O(1) variables (never re-reading `a[j]` for `j < i`), you are doing linear scan. If you are tempted to write a nested loop, ask: _can I precompute or carry forward the information I would have looked up in the inner loop?_

**Common trap:** Tracking the _value_ when you need the _index_, or tracking the _index_ when you need the _value_. Problems that ask for a sub-range (e.g., "return the start and end of the longest valid subarray") require you to track both the start index and the length simultaneously, updating the start index lazily when the current state invalidates the window. Forgetting to record the index at the moment the optimal value was achieved — saving `max_val` but not `max_idx` — kills many submissions.

**Second trap:** Off-by-one errors when the answer is the index _after_ the last valid element vs the index _of_ the last valid element. Be explicit about whether your tracked index is inclusive or exclusive.

### Machine Learning / AI

Linear scan is not just an algorithmic primitive — it is the computational skeleton of several core ML operations:

**Feature engineering on sequences:** `pandas.Series.rolling()` and `DataFrame.expanding()` are stateful linear scans. Internally, Pandas maintains a running window state and updates it element-by-element — it does not recompute each window from scratch. Understanding this tells you why `rolling().mean()` is O(n) and not O(n·k), and why you should never implement rolling statistics with a Python loop when Pandas already does it in C.

**Normalisation passes:** Batch normalisation during inference requires a single linear scan to compute the running mean and variance of activations. The Welford online algorithm (an incremental mean/variance update) is exactly "linear scan with tracked mean and sum-of-squared-deviations." PyTorch's `BatchNorm` uses this pattern when `track_running_stats=True`.

**Sequence labelling with CRF/HMM:** The forward algorithm in a Hidden Markov Model is a linear scan over the observation sequence, maintaining a `forward[t]` vector that summarises all paths ending at time `t`. The Viterbi algorithm (see [[186.Viterbi algorithm — DP for HMM decoding]]) does the same with a `max` instead of `sum`. Both are linear scans where the tracked state is a vector of partial probabilities.

**Data pipeline scanning:** During dataset construction in PyTorch/TensorFlow, computing class frequencies, dataset statistics, or writing TFRecord shards all require a single linear pass with tracked counters. Understanding this means you implement these with streaming accumulators, not `len(list(filter(...)))` materialised in memory.

## 3. Algorithm / Pattern

### Step-by-Step Logic

1. **Initialise** your tracked variables before the loop. These encode the state of the "empty prefix" — often: `max_val = -∞`, `min_idx = 0`, `count = 0`, `running_sum = 0`.
2. **Iterate** from left to right (index 0 to n-1, inclusive). Each iteration reads exactly `a[i]` and the current tracked state.
3. **Update** tracked variables using `a[i]`. The update is O(1) — no inner loops, no lookups into previous array positions.
4. **Record** the answer if the current index satisfies the answer condition. Store the index, not just the value, if the problem requires position.
5. **Return** the final tracked state or recorded answer after the loop.

### Decision Tree

```
Do you need to process each element once in order?
  └── Yes → Linear scan candidate
        ├── Do you only need the final aggregate? → Single tracked variable (max, sum, count)
        ├── Do you need the position of the answer? → Track both value AND index
        ├── Do you need per-element output? → Maintain running prefix, write output[i] = f(state, a[i])
        └── Do you need the relationship between two positions? → See [[16.Opposite-end two pointers]]
                                                                  or [[24.Subarray sum equals k]]
```

### Complexity

**Time: O(n)**  
Each element is visited exactly once. The loop body is O(1) by design (if update requires O(log n), the full scan becomes O(n log n) — see heap-augmented scans in [[152.k-th largest element]]).

**Space: O(1)** auxiliary  
The tracked variables are O(1) regardless of n. Input array is O(n) but not auxiliary — you already have it.

**When to use:** Any problem where the answer for the whole array can be assembled from O(1) information maintained per-step.

**When to avoid:** When the problem requires non-local information (e.g., "is this element the k-th largest globally?") that cannot be summarised in O(1) state. In those cases, augment with a heap, segment tree, or hash map — the scan becomes O(n log n) or O(n) with O(n) space.

## 4. Pseudocode

```
function linear_scan(a[0..n-1]):
    # Initialise: encode the empty-prefix state
    best_val   ← -INFINITY      # tracked aggregate
    best_idx   ← -1             # tracked position of best
    state      ← initial_state  # any additional carried info

    for i from 0 to n-1:
        # Step 1: use a[i] and state to update the answer candidate
        candidate ← compute(a[i], state)

        # Step 2: decide whether to update the recorded best
        if candidate is better than best_val:
            best_val ← candidate
            best_idx ← i        # CRITICAL: record the index, not just the value

        # Step 3: update carried state for the next iteration
        # This is O(1) and uses only a[i] and current state
        state ← update(state, a[i])

    return best_val, best_idx
```

**Why record `best_idx` at the moment of update?**  
After the loop, `state` has moved past the best position. You cannot recover the index from the final state. Record it _when you find it_.

**Why update `state` after checking the answer?**  
Some problems require the state to reflect the prefix _ending at_ `i`, while others require the prefix _strictly before_ `i`. Decide which and be consistent. For "maximum of prefix sum ending here," you update state before checking; for "first time running sum exceeds target," you check before updating.

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ─────────────────────────────────────────────────────────────────────────────
// Problem: Given array a, find the maximum element and its FIRST occurrence.
// Returns {max_value, first_index_of_max}.
// Edge case: empty array returns {INT_MIN, -1}.
// O(n) time, O(1) space.
// ─────────────────────────────────────────────────────────────────────────────
pair<int,int> find_max_with_index(const vector<int>& a) {
    if (a.empty()) return {INT_MIN, -1};

    int best_val = a[0];   // Initialise with first element, not -INF,
    int best_idx = 0;      // so the return index is valid even for n=1.

    for (int i = 1; i < (int)a.size(); ++i) {
        // Strict '>' preserves FIRST occurrence.
        // Use '>=' to preserve LAST occurrence.
        if (a[i] > best_val) {
            best_val = a[i];
            best_idx = i;   // Record position at the exact moment of update.
        }
    }
    return {best_val, best_idx};
}

// ─────────────────────────────────────────────────────────────────────────────
// Problem: Find the index of the first element that breaks the non-decreasing
// property. Returns -1 if array is non-decreasing.
// O(n) time, O(1) space.
// ─────────────────────────────────────────────────────────────────────────────
int first_violation(const vector<int>& a) {
    // Track previous element. Start scan at index 1.
    for (int i = 1; i < (int)a.size(); ++i) {
        if (a[i] < a[i-1]) return i;   // First violation is at i.
    }
    return -1;  // Array is non-decreasing.
}

// ─────────────────────────────────────────────────────────────────────────────
// Problem: Given prices[], find the max profit from one buy-sell transaction.
// Classic: track min price seen so far (the "best buy point to date").
// O(n) time, O(1) space.
// ─────────────────────────────────────────────────────────────────────────────
int max_profit(const vector<int>& prices) {
    if (prices.size() < 2) return 0;

    int min_so_far = prices[0];   // Best buy price seen in the past.
    int max_profit  = 0;

    for (int i = 1; i < (int)prices.size(); ++i) {
        // Current profit if we sold today at prices[i]:
        max_profit = max(max_profit, prices[i] - min_so_far);

        // Update the tracked minimum for future iterations.
        // Note: update AFTER computing profit — you cannot sell before buying.
        min_so_far = min(min_so_far, prices[i]);
    }
    return max_profit;
}

// ─────────────────────────────────────────────────────────────────────────────
// Minimal test driver
// ─────────────────────────────────────────────────────────────────────────────
int main() {
    // Test find_max_with_index
    vector<int> a = {3, 1, 4, 1, 5, 9, 2, 6};
    auto [val, idx] = find_max_with_index(a);
    assert(val == 9 && idx == 5);

    // Test first_violation
    vector<int> b = {1, 2, 3, 2, 5};
    assert(first_violation(b) == 3);
    vector<int> c = {1, 2, 3, 4};
    assert(first_violation(c) == -1);

    // Test max_profit
    vector<int> prices = {7, 1, 5, 3, 6, 4};
    assert(max_profit(prices) == 5);  // Buy at 1, sell at 6.

    cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import Optional

def find_max_with_index(a: list[int]) -> tuple[int, int]:
    """
    Returns (max_value, first_index_of_max) via a single linear scan.

    Time:  O(n)
    Space: O(1) auxiliary

    Edge case: empty list raises ValueError.
    """
    if not a:
        raise ValueError("Array must be non-empty.")

    best_val, best_idx = a[0], 0  # Initialise with first element.

    for i in range(1, len(a)):
        if a[i] > best_val:
            best_val = a[i]
            best_idx = i    # Capture position at the moment of improvement.

    return best_val, best_idx


def first_violation(a: list[int]) -> int:
    """
    Returns index of first element that breaks non-decreasing order, or -1.

    Time:  O(n)
    Space: O(1)
    """
    for i in range(1, len(a)):
        if a[i] < a[i - 1]:
            return i
    return -1


def max_profit(prices: list[int]) -> int:
    """
    Maximum profit from a single buy-sell transaction (LeetCode 121).

    Key insight: track the minimum price seen so far. At each step,
    the best profit *if we sell today* is prices[i] - min_so_far.

    Time:  O(n)
    Space: O(1)
    """
    if len(prices) < 2:
        return 0

    min_so_far = prices[0]
    best = 0

    for price in prices[1:]:
        best = max(best, price - min_so_far)
        min_so_far = min(min_so_far, price)
        # Order matters: compute profit before updating min.
        # (You cannot buy and sell on the same day and profit from that in this model.)

    return best


# ─── Naive vs optimised comparison ───────────────────────────────────────────
def max_profit_naive(prices: list[int]) -> int:
    """O(n^2) brute force — compare every pair. Included to show the gap."""
    best = 0
    n = len(prices)
    for i in range(n):
        for j in range(i + 1, n):
            best = max(best, prices[j] - prices[i])
    return best


# ─── Tests ───────────────────────────────────────────────────────────────────
if __name__ == "__main__":
    assert find_max_with_index([3, 1, 4, 1, 5, 9, 2, 6]) == (9, 5)
    assert find_max_with_index([7]) == (7, 0)

    assert first_violation([1, 2, 3, 2, 5]) == 3
    assert first_violation([1, 2, 3]) == -1

    prices = [7, 1, 5, 3, 6, 4]
    assert max_profit(prices) == max_profit_naive(prices) == 5

    prices2 = [7, 6, 4, 3, 1]
    assert max_profit(prices2) == 0  # Strictly declining — no profit possible.

    print("All tests passed.")
```

### Diagram 1 — Max Profit with Tracked Minimum

Walk through `prices = [7, 1, 5, 3, 6, 4]`:

```
Index:       0    1    2    3    4    5
prices:      7    1    5    3    6    4
             │    │    │    │    │    │
             ▼    ▼    ▼    ▼    ▼    ▼

min_so_far:  7 →  1 →  1 →  1 →  1 →  1
                  ↑
            New minimum found at i=1.
            No further minimums after this.

profit today: —   0    4    2    5    3
              (no sell before buy)

best_profit:  0   0    4    4    5    5
                            ↑
                     Best found at i=4: sell at 6, buy at 1.

ANSWER: 5
```

The tracked variable `min_so_far` is the "memory" — it prevents us from needing to look back at all previous prices when computing the profit at index `i`.

### Diagram 2 — Two Tracked Variables: Value + Index

Why you must track the index _at the moment of update_:

```
a = [3, 9, 2, 9, 1]
     ↑            ↑
     i=0          i=4

Scan:
  i=0: a[0]=3  → best_val=3,  best_idx=0
  i=1: a[1]=9  → best_val=9,  best_idx=1  ← update index HERE
  i=2: a[2]=2  → no update
  i=3: a[3]=9  → 9 == best_val, no update (strict >, preserves FIRST)
  i=4: a[4]=1  → no update

Result: best_val=9, best_idx=1   ✓ (first occurrence)

MISTAKE: If you saved best_val=9 but forgot best_idx, and tried to
         recover index after the loop with a.index(9), you would get
         index 1 by accident here — but a.index() always returns the
         first, and is also O(n), adding a hidden second pass.
         In problems with duplicates or where you need the LAST
         occurrence, this would silently give the wrong answer.
```

### Diagram 3 — The State Machine View

Every linear scan is a state machine over the array:

```
State S encodes everything needed from prefix a[0..i-1]
                    │
                    ▼
  ┌─────────────────────────────────────────┐
  │   S₀  →[a[0]]→  S₁  →[a[1]]→  S₂  →  …  →  Sₙ  │
  └─────────────────────────────────────────┘
        ↑                              ↑
   Initial state                  Final state
   (empty prefix)                 (full array)

At each transition:
  answer_candidate = f(Sᵢ, a[i])       ← O(1)
  Sᵢ₊₁ = update(Sᵢ, a[i])             ← O(1)

The art of the problem: choosing S so that f and update are both O(1).
```

This view is identical to the **forward algorithm** in HMMs — the tracked state vector `α[t]` is exactly `Sᵢ` in this diagram. See [[186.Viterbi algorithm — DP for HMM decoding]].

## 7. Common Variations & Extensions

### Variation 1 — Tracking Two Indices (Range Answer)

When the answer is a subarray `[l, r]`, not just a single index, you track a candidate start `l_cand` and update `(l, r)` only when the current window beats the best. The key discipline: update `l_cand` _eagerly_ when the current window is invalidated, but update the answer `(l, r)` _lazily_ only when the current window is the new best.

→ This is the foundation of [[12.Variable-size sliding window — shrink and expand logic]].

### Variation 2 — Running Aggregate with Rollback

Some problems require you to track the running sum _and_ allow "undo" of the last few elements. This arises when the scan must consider both including and excluding the current element. The standard form is Kadane's algorithm (maximum subarray):

```
current_sum = max(a[i], current_sum + a[i])
```

The `max` is an implicit "start a new subarray here if it is better" — a rollback of the tracked state to just `a[i]`. See [[167.Maximum subarray — Kadane's algorithm and its DP interpretation]].

### Variation 3 — Index Tracking in Two Arrays Simultaneously

Problems like "find the minimum absolute difference between any element of A and any element of B" (when both are sorted) use two pointers, each tracking an index in a separate array. This generalises linear scan to two simultaneous state machines advancing through two arrays. See [[16.Opposite-end two pointers]].

### Variation 4 — Scan with a HashMap as State

When the O(1) state becomes too large for a single integer but remains bounded, you upgrade the tracked variable to a dictionary. The canonical case: "number of subarrays with sum equal to k" tracks a frequency map of all prefix sums seen. The scan is still O(n) because each HashMap operation is O(1) expected. See [[24.Subarray sum equals k — prefix sum + HashMap]].

## 9. CP Contest Application

### Typical Codeforces Structure

**Problem type (Div. 2 A–B):** "Given array of n integers, find the minimum number of operations to make the array non-decreasing, where one operation replaces one element."

The solution scans left to right, tracking the previous valid element. The answer is the count of indices where `a[i] < a[i-1]`. Pure O(n) linear scan, zero extra data structures.

**Problem type (Div. 2 B–C augmented):** "Given array a, for each index i report the maximum value of `a[j] - a[k]` where `k < j ≤ i`." This requires scanning with tracked min and max, updated correctly relative to each other. The trap: you must track the minimum that appeared _before the current maximum_, not just the global minimum.

### Time Limits

Linear scan problems are rarely bottlenecked by time — O(n) with n ≤ 10⁶ runs in ~10ms in C++. The performance risk is **hidden O(n²) from accidentally calling `.index()`, `.find()`, or `std::find()` inside the loop** — each of which is an O(n) scan, turning the whole thing O(n²).

**Rule:** If you call any function inside your scan loop, verify its complexity. `std::unordered_map::find()` is O(1) average. `std::vector::find()` is O(n). This distinction kills Codeforces submissions.

### Optimisation Tricks

- **Loop unrolling:** Not usually needed for linear scan, but if you process 4 elements per iteration manually (SIMD-style), you can improve cache line utilisation by ~2×. Relevant only for n ≥ 10⁷.
- **Branch elimination:** Instead of `if (a[i] > best) best = a[i]`, write `best = max(best, a[i])`. Modern compilers (`-O2`) generate a `cmov` (conditional move) instruction for the latter, eliminating branch mispredictions.
- **Iterator vs index:** In C++, range-based `for (int x : a)` is identical in performance to index-based `for (int i = 0; i < n; i++)` with `-O2`. Use index-based only when you need `i`.
