## 1. Intuition First

### The Core Idea

Every string of length $n$ has exactly $n$ suffixes. For `"banana"`:

```
Suffix 0: banana
Suffix 1: anana
Suffix 2: nana
Suffix 3: ana
Suffix 4: na
Suffix 5: a
```

Now sort these suffixes lexicographically:

```
Rank 0: a        (starts at index 5)
Rank 1: ana      (starts at index 3)
Rank 2: anana    (starts at index 1)
Rank 3: banana   (starts at index 0)
Rank 4: na       (starts at index 4)
Rank 5: nana     (starts at index 2)
```

The **suffix array** SA is simply the array of starting indices in sorted order: `SA = [5, 3, 1, 0, 4, 2]`. That's it — a permutation of $[0, n-1]$ that sorts the suffixes.

The **LCP array** (Longest Common Prefix) stores, for each consecutive pair in the suffix array, the length of their longest common prefix:

```
LCP[0] = 0         (undefined / 0 by convention)
LCP[1] = 1         lcp("a", "ana")    = "a"       → 1
LCP[2] = 3         lcp("ana", "anana") = "ana"    → 3
LCP[3] = 0         lcp("anana", "banana") = ""    → 0
LCP[4] = 0         lcp("banana", "na") = ""       → 0
LCP[5] = 2         lcp("na", "nana")  = "na"      → 2
```

Together, SA and LCP encode the _entire suffix structure_ of the string. Every string algorithm that previously required a suffix tree — pattern matching, longest repeated substring, number of distinct substrings, longest common substring of two strings — can be solved using SA + LCP, often more cache-efficiently than a suffix tree.

### Why This Exists

A [[29.Trie (prefix tree) — insert, search, startsWith|trie]] of all suffixes (a suffix trie) answers the same queries but uses O(n²) space in the worst case (e.g., string `"abcde..."` has no shared prefixes among suffixes). A suffix tree compresses the trie to O(n) space and time, but the implementation is notoriously complex (Ukkonen's algorithm has ~5 cases with subtle invariants).

The suffix array achieves near-identical power with:

- **O(n log n)** construction (O(n) is possible but rarely needed in practice)
- **O(n)** space (just two arrays of integers)
- **Implementation complexity** that fits in ~50 lines of clean code

The tradeoff: a suffix tree answers LCP queries in O(1) after O(n) preprocessing; a suffix array requires an additional RMQ (Range Minimum Query) structure over the LCP array to match this. But for most problems, the simpler SA + LCP construction is the right engineering choice.

### The "Aha" Moment

The O(n log n) construction — the **prefix-doubling** (DC3/SA-IS are O(n) but far more complex) — works by sorting suffixes in rounds. In round $k$, you sort suffixes by their first $2^k$ characters. You start with $2^0 = 1$ character (just the first letter), then $2^1 = 2$, then $4$, $8$, $\ldots$ until $2^k \geq n$.

The key insight: **when sorting by $2^{k+1}$ characters, you're sorting pairs of already-sorted $2^k$-length blocks.** If you've assigned rank numbers after round $k$ (so each suffix has a "rank" based on its first $2^k$ chars), then sorting by the first $2^{k+1}$ chars means sorting by `(rank[i], rank[i + 2^k])` — a pair of previously computed integers. This turns a string-comparison sort into an integer-pair sort, which can be done stably in O(n log n) using radix sort or O(n log n) using standard sort with integer comparators.

$\lceil \log_2 n \rceil$ rounds × O(n log n) per round = **O(n log² n)** with standard sort. Using radix sort in each round drops this to **O(n log n)**. This doubling structure is the same insight behind merge sort — each round doubles the "sorted prefix" length.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- "Longest repeated substring" → longest value in LCP array
- "Number of distinct substrings" → $\frac{n(n+1)}{2} - \sum \text{LCP}[i]$
- "Longest common substring of two strings" → concatenate with a separator, build SA+LCP, find adjacent SA entries from different strings with max LCP
- "Count occurrences of pattern P in text T" → binary search on SA for the range where suffixes start with P; range length = count
- "Minimum number of palindromic substrings" (hard) → uses SA + LCP + other structures
- Any problem mentioning "all substrings" with $n \leq 10^5$ and a time limit that rules out O(n²)

**Signal patterns that point to suffix arrays:**

- $n \leq 2 \times 10^5$, string problem, query involves substrings of arbitrary length
- "Lexicographically smallest rotation" → suffix array on `s + s`
- "Longest substring appearing at least $k$ times" → binary search on LCP array using sliding window minimum
- Multiple strings, queries about their common substrings → concatenate with unique separators, build single SA

**The canonical trap — off-by-one in LCP binary search:** When using SA to find all occurrences of pattern $P$: binary search for the leftmost and rightmost suffix that starts with $P$. The comparison function must compare only the first $|P|$ characters of each suffix against $P$. Getting the comparison boundary wrong produces wrong counts. Always test with a pattern that appears at the very start and end of the string.

**Second trap — the sentinel character:** Appending `'$'` (or `'\0'`) to the string before building SA is not just a convention — it ensures the empty suffix sorts first and that no suffix is a prefix of another (which would make the sort ill-defined for LCP computation). Forgetting the sentinel produces subtle bugs in LCP computation.

**Third trap — O(n log² n) vs O(n log n):** Using `std::sort` (O(n log n) comparison-based) inside each of O(log n) rounds gives O(n log² n) total. For $n = 10^5$ this is fine (≈$10^5 \times 17 \times 17 \approx 2.9 \times 10^7$). For $n = 5 \times 10^5$ with a tight time limit, you need radix sort in each round for O(n log n) total.

### Machine Learning / AI

**1. Full-text search and information retrieval.** The FM-index — used in `bowtie2` and `bwa` for DNA read alignment, and in compressed text indices for information retrieval — is built on a suffix array combined with the Burrows-Wheeler Transform (BWT). The BWT of a string is obtained directly from its suffix array: `BWT[i] = s[SA[i] - 1]`. Every genome alignment pipeline for sequencing data (including those feeding into protein structure prediction preprocessing) uses this. AlphaFold's MSA (multiple sequence alignment) preprocessing uses BWA, which is SA-based.

**2. Repetition detection in training corpora.** LLM pretraining pipelines require deduplication at multiple granularities: document-level (MinHash, see [[39.MinHash — estimating Jaccard similarity at scale]]) and substring-level. The paper "Deduplicating Training Data Makes Language Models Better" (Lee et al., 2022) uses suffix arrays to find all repeated substrings of length ≥ 50 tokens across the entire training corpus — a dataset of hundreds of GB. Suffix arrays scale to this regime; tries do not.

**3. Data compression.** The Burrows-Wheeler Transform, which powers `bzip2` and is the basis of modern compression algorithms like `zstd`'s dictionary training, uses suffix arrays for construction. `zstd` dictionary training (used to compress ML model weights and training data in production systems) directly uses SA-based BWT.

**4. Tokenisation and vocabulary construction.** SentencePiece's unigram language model training — used by T5, ALBERT, mBART, and XLNet — requires finding the most frequent substrings across a corpus to build a vocabulary. Efficient implementations use suffix arrays to enumerate all distinct substrings with their frequencies in O(n) after O(n log n) construction, rather than the O(n²) trie-based approach.

**5. Approximate string matching for RAG.** Retrieval-Augmented Generation systems need to match query strings against large document corpora. While semantic search uses embedding similarity, exact and near-exact substring retrieval (for code, formulas, proper nouns) uses inverted indices built with suffix-array-style preprocessing. Elasticsearch's underlying Lucene engine uses a variant of suffix arrays for term frequency indexing.

## 3. Algorithm / Pattern

### Part A: Suffix Array Construction (O(n log² n) — the one to implement)

**Prefix doubling (Manber-Myers algorithm):**

Round 0: Sort suffixes by their first $2^0 = 1$ character. Assign ranks. Round $k \to k+1$: Sort by $(rank[i], rank[i + 2^k])$. Assign new ranks. Stop when all ranks are distinct (or after $\lceil \log_2 n \rceil$ rounds).

At each round, the pair $(rank[i], rank[i + 2^k])$ uniquely characterises the first $2^{k+1}$ characters of suffix $i$ — because $rank[i]$ encodes the first $2^k$ chars, and $rank[i + 2^k]$ encodes the next $2^k$ chars (which we've already sorted in the previous round). Suffixes shorter than $2^k$ from position $i$ get a sentinel rank of $-1$ or $0$.

### Part B: LCP Array Construction — Kasai's Algorithm (O(n))

**The key theorem (Kasai et al.):** If suffix at position $i$ has LCP value $\ell$ with its SA-neighbor, then suffix at position $i+1$ has LCP value $\geq \ell - 1$ with its SA-neighbor.

**Why:** Suffix $i+1$ is suffix $i$ with its first character removed. If suffix $i$ shares $\ell$ characters with its SA-neighbor $j$, then suffix $i+1$ shares at least $\ell - 1$ characters with SA-neighbor $j+1$ (because removing the first character from both reduces LCP by at most 1). This means we can compute LCP values in suffix order (not SA order), and the LCP value never drops by more than 1 per step — so the total number of increments across all steps is at most $n$, giving O(n) total.

**Algorithm:**

1. Build the inverse SA: `rank[SA[i]] = i` (rank of suffix starting at position $i$).
2. Iterate $i$ from 0 to $n-1$ (in _string_ order, not SA order).
3. Maintain a running `h` (current LCP height). For suffix at position $i$:
    - Find its SA-rank: `r = rank[i]`.
    - If `r == 0`, set `h = 0` (first in SA, no left neighbor), continue.
    - Compare suffix $i$ with suffix `SA[r-1]` (its left SA-neighbor) starting from position `h` (exploiting the lower bound).
    - Extend `h` while characters match.
    - Set `LCP[r] = h`.
    - Decrement `h` by 1 (for the next iteration's lower bound).

### Complexity

|Step|Time|Space|
|---|---|---|
|SA construction (doubling + std::sort)|O(n log² n)|O(n)|
|SA construction (doubling + radix sort)|O(n log n)|O(n)|
|SA construction (SA-IS)|O(n)|O(n)|
|LCP construction (Kasai)|O(n)|O(n)|
|Pattern search (binary search on SA)|O(m log n)|O(1)|
|Pattern search (with LCP, Z-array trick)|O(m + log n)|O(n)|
|RMQ on LCP (sparse table)|O(n log n) build, O(1) query|O(n log n)|

**Derivation of Kasai O(n):** `h` starts at 0. Each iteration either increases `h` (by extending the match) or decreases it by 1. Since `h ≥ 0` always and `h ≤ n`, total increments ≤ $n$ and total decrements ≤ $n$, so total inner-loop iterations ≤ $2n$ = O(n).

```
// ── PART A: Suffix Array via Prefix Doubling ──────────────────────

function BUILD_SUFFIX_ARRAY(s):
    s ← s + "$"           // Append sentinel (lexicographically smallest char)
    n ← length(s)
    SA ← [0, 1, ..., n-1] // Initially: suffixes in original order

    // Step 1: Initial sort by first character
    Sort SA by s[SA[i]] (stable)
    rank ← assign_ranks(SA, s, compare_by_1_char)
    // rank[i] = lexicographic rank of suffix starting at i, by first char

    gap ← 1
    while gap < n and not all_ranks_distinct(rank):
        // Step 2: Sort by (rank[i], rank[i + gap])
        // rank[i + gap] = -1 (sentinel) if i + gap >= n
        Sort SA by (rank[SA[i]], rank[SA[i] + gap] if SA[i]+gap < n else -1) (stable)
        rank ← assign_ranks(SA, prev_rank, gap)
        gap ← gap * 2

    return SA[1:]   // Optionally drop the sentinel suffix at SA[0]


function ASSIGN_RANKS(SA, key_fn, ...):
    // Assigns integer ranks based on sorted order.
    // Equal keys get equal ranks (required for correctness of next round).
    n ← length(SA)
    rank ← array of n zeros
    rank[SA[0]] ← 0
    for i from 1 to n-1:
        rank[SA[i]] ← rank[SA[i-1]]
        if key_fn(SA[i]) != key_fn(SA[i-1]):  // Different key → new rank
            rank[SA[i]] ← rank[SA[i]] + 1
    return rank


// ── PART B: LCP Array via Kasai's Algorithm ──────────────────────

function BUILD_LCP_ARRAY(s, SA):
    n ← length(s)
    rank ← array of n zeros
    for i from 0 to n-1:
        rank[SA[i]] ← i   // Inverse of SA: rank[i] = SA-position of suffix i

    LCP ← array of n zeros
    h ← 0   // Current LCP height (lower bound for next iteration)

    for i from 0 to n-1:          // Iterate suffixes in STRING order
        r ← rank[i]
        if r == 0:
            h ← 0                  // First suffix in SA has no left neighbor
            continue

        j ← SA[r - 1]             // Left SA-neighbor of suffix i
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h ← h + 1             // Extend match (each step here costs O(1))

        LCP[r] ← h
        if h > 0:
            h ← h - 1             // Key: Kasai's lower-bound decrement


    return LCP


// ── APPLICATION: Count occurrences of pattern P in text ──────────

function COUNT_OCCURRENCES(s, SA, P):
    // Binary search for leftmost suffix starting with P
    lo, hi ← 0, length(SA)
    while lo < hi:
        mid ← (lo + hi) / 2
        if s[SA[mid] : SA[mid] + |P|] < P:  lo ← mid + 1
        else:                                 hi ← mid
    left ← lo

    // Binary search for rightmost suffix starting with P
    lo, hi ← 0, length(SA)
    while lo < hi:
        mid ← (lo + hi) / 2
        if s[SA[mid] : SA[mid] + |P|] <= P:  lo ← mid + 1  // Note: <=
        else:                                  hi ← mid
    right ← lo

    return right - left   // Number of suffixes starting with P
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <algorithm>
#include <numeric>
#include <cassert>

// ─────────────────────────────────────────────────────────────────
// Suffix Array — O(n log² n) via prefix doubling + std::sort
// Clean, contest-ready. For n ≤ 3×10^5 this fits within 2s limits.
// ─────────────────────────────────────────────────────────────────
std::vector<int> build_suffix_array(const std::string& s_orig) {
    std::string s = s_orig + "$";   // Sentinel: sorts before all other chars
    int n = (int)s.size();

    std::vector<int> sa(n), rank_(n), tmp(n);
    std::iota(sa.begin(), sa.end(), 0);  // sa = [0, 1, ..., n-1]

    // Initial rank = character value
    for (int i = 0; i < n; ++i) rank_[i] = s[i];

    for (int gap = 1; gap < n; gap *= 2) {
        // Comparator: sort by (rank[i], rank[i+gap])
        auto cmp = [&](int a, int b) {
            if (rank_[a] != rank_[b]) return rank_[a] < rank_[b];
            int ra = (a + gap < n) ? rank_[a + gap] : -1;
            int rb = (b + gap < n) ? rank_[b + gap] : -1;
            return ra < rb;
        };
        std::sort(sa.begin(), sa.end(), cmp);

        // Recompute ranks from sorted order
        tmp[sa[0]] = 0;
        for (int i = 1; i < n; ++i)
            tmp[sa[i]] = tmp[sa[i-1]] + (cmp(sa[i-1], sa[i]) ? 1 : 0);
        rank_ = tmp;

        // Early termination: all ranks distinct → fully sorted
        if (rank_[sa[n-1]] == n - 1) break;
    }

    // Drop the sentinel suffix (it's always at sa[0] after construction)
    return std::vector<int>(sa.begin() + 1, sa.end());
}

// ─────────────────────────────────────────────────────────────────
// LCP Array — Kasai's O(n) algorithm
// Requires the suffix array (without sentinel suffix).
// ─────────────────────────────────────────────────────────────────
std::vector<int> build_lcp_array(const std::string& s,
                                  const std::vector<int>& sa) {
    int n = (int)s.size();
    std::vector<int> rank_(n), lcp(n, 0);

    // Build inverse SA (rank): rank[sa[i]] = i
    for (int i = 0; i < n; ++i) rank_[sa[i]] = i;

    int h = 0;  // Current LCP height (Kasai's running lower bound)
    for (int i = 0; i < n; ++i) {
        int r = rank_[i];
        if (r == 0) { h = 0; continue; }  // No left neighbor

        int j = sa[r - 1];  // Left SA-neighbor
        while (i + h < n && j + h < n && s[i + h] == s[j + h])
            ++h;

        lcp[r] = h;
        if (h > 0) --h;  // Kasai's key step: h decreases by at most 1
    }
    return lcp;
}

// ─────────────────────────────────────────────────────────────────
// Pattern search: count occurrences of pattern in s using SA
// O(m log n) where m = |pattern|
// ─────────────────────────────────────────────────────────────────
int count_occurrences(const std::string& s, const std::vector<int>& sa,
                       const std::string& pattern) {
    int n = (int)sa.size(), m = (int)pattern.size();

    // Find leftmost position where suffix >= pattern (as prefix)
    int lo = (int)(std::lower_bound(sa.begin(), sa.end(), 0,
        [&](int idx, int) {
            return s.substr(idx, m) < pattern;
        }) - sa.begin());

    // Find rightmost position where suffix <= pattern (as prefix)
    int hi = (int)(std::upper_bound(sa.begin(), sa.end(), 0,
        [&](int, int idx) {
            return pattern < s.substr(idx, m);
        }) - sa.begin());

    return hi - lo;
}

// ─────────────────────────────────────────────────────────────────
// Longest repeated substring: maximum value in LCP array
// ─────────────────────────────────────────────────────────────────
std::string longest_repeated_substring(const std::string& s,
                                        const std::vector<int>& sa,
                                        const std::vector<int>& lcp) {
    int max_lcp = 0, max_idx = 0;
    for (int i = 1; i < (int)lcp.size(); ++i) {
        if (lcp[i] > max_lcp) {
            max_lcp = lcp[i];
            max_idx = i;
        }
    }
    return s.substr(sa[max_idx], max_lcp);
}

// ─────────────────────────────────────────────────────────────────
// Number of distinct substrings
// Total substrings = n*(n+1)/2. Subtract duplicates (= sum of LCP).
// ─────────────────────────────────────────────────────────────────
long long count_distinct_substrings(const std::string& s,
                                     const std::vector<int>& lcp) {
    long long n = (long long)s.size();
    long long total = n * (n + 1) / 2;
    long long duplicates = 0;
    for (int v : lcp) duplicates += v;
    return total - duplicates;
}

// ─────────────────────────────────────────────────────────────────
// Longest common substring of two strings s1 and s2
// Concatenate with unique separator, find max LCP between SA entries
// from different strings. O((n+m) log²(n+m)).
// ─────────────────────────────────────────────────────────────────
std::string longest_common_substring(const std::string& s1,
                                      const std::string& s2) {
    std::string combined = s1 + "#" + s2;  // '#' must not appear in s1 or s2
    auto sa  = build_suffix_array(combined);
    auto lcp = build_lcp_array(combined, sa);

    int n1 = (int)s1.size();
    int best_len = 0, best_pos = 0;

    for (int i = 1; i < (int)sa.size(); ++i) {
        // Check if sa[i] and sa[i-1] come from different strings
        bool from_s1_curr = (sa[i]   <= n1);
        bool from_s1_prev = (sa[i-1] <= n1);
        if (from_s1_curr != from_s1_prev && lcp[i] > best_len) {
            best_len = lcp[i];
            best_pos = sa[i];
        }
    }
    return combined.substr(best_pos, best_len);
}

// ─────────────────────────────────────────────────────────────────
// Tests
// ─────────────────────────────────────────────────────────────────
int main() {
    std::string s = "banana";
    auto sa  = build_suffix_array(s);
    auto lcp = build_lcp_array(s, sa);

    // SA expected: [5, 3, 1, 0, 4, 2]
    std::cout << "SA: ";
    for (int v : sa) std::cout << v << " ";
    std::cout << "\n";

    // LCP expected: [0, 1, 3, 0, 0, 2]
    std::cout << "LCP: ";
    for (int v : lcp) std::cout << v << " ";
    std::cout << "\n";

    // Pattern count
    std::cout << count_occurrences(s, sa, "ana") << "\n";   // Expected: 2
    std::cout << count_occurrences(s, sa, "an")  << "\n";   // Expected: 2
    std::cout << count_occurrences(s, sa, "xyz") << "\n";   // Expected: 0

    // Longest repeated substring
    std::cout << longest_repeated_substring(s, sa, lcp) << "\n";  // "ana"

    // Distinct substrings
    std::cout << count_distinct_substrings(s, lcp) << "\n";  // Expected: 15

    // Longest common substring
    std::cout << longest_common_substring("abcdef", "zbcdf") << "\n";  // "bcd"

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import List, Tuple


def build_suffix_array(s: str) -> List[int]:
    """
    Build the suffix array of s using prefix doubling (O(n log² n)).

    Returns SA: a permutation of [0, n-1] such that
    s[SA[0]:] < s[SA[1]:] < ... < s[SA[n-1]:] lexicographically.

    A sentinel '$' is appended internally and stripped from the result.

    Time:  O(n log² n)
    Space: O(n)
    """
    s = s + "$"       # Sentinel ensures no suffix is a prefix of another
    n = len(s)
    sa = list(range(n))
    rank = [ord(c) for c in s]

    gap = 1
    while gap < n:
        def sort_key(i: int) -> Tuple[int, int]:
            return (rank[i], rank[i + gap] if i + gap < n else -1)

        sa.sort(key=sort_key)

        # Recompute ranks: equal keys get equal ranks
        new_rank = [0] * n
        new_rank[sa[0]] = 0
        for i in range(1, n):
            new_rank[sa[i]] = new_rank[sa[i-1]]
            if sort_key(sa[i]) != sort_key(sa[i-1]):
                new_rank[sa[i]] += 1
        rank = new_rank

        if rank[sa[-1]] == n - 1:  # All ranks distinct → done
            break
        gap *= 2

    return sa[1:]   # Drop sentinel suffix (always first after sort)


def build_lcp_array(s: str, sa: List[int]) -> List[int]:
    """
    Build the LCP array using Kasai's O(n) algorithm.

    LCP[i] = length of longest common prefix between s[SA[i-1]:] and s[SA[i]:]
    LCP[0] = 0 by convention.

    Requires the suffix array WITHOUT the sentinel suffix.

    Time:  O(n)
    Space: O(n)
    """
    n = len(s)
    rank = [0] * n
    for i, v in enumerate(sa):
        rank[v] = i  # Inverse SA

    lcp = [0] * n
    h = 0  # Running LCP height (Kasai's lower bound)

    for i in range(n):
        r = rank[i]
        if r == 0:
            h = 0
            continue
        j = sa[r - 1]  # Left SA-neighbor
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h += 1
        lcp[r] = h
        if h > 0:
            h -= 1  # Kasai: h can only drop by 1 per step

    return lcp


def count_occurrences(s: str, sa: List[int], pattern: str) -> int:
    """
    Count occurrences of pattern in s using binary search on SA.
    Time: O(m log n) where m = len(pattern).
    """
    import bisect
    n, m = len(sa), len(pattern)

    # We binary search on SA using the first m characters of each suffix
    keys = [s[sa[i]:sa[i]+m] for i in range(n)]  # O(nm) for precomputation
    # For large n, compare lazily in the bisect comparator instead

    left  = bisect.bisect_left(keys, pattern)
    right = bisect.bisect_right(keys, pattern)
    return right - left


def longest_repeated_substring(s: str, sa: List[int], lcp: List[int]) -> str:
    """
    Find the longest substring that appears at least twice.
    Answer = suffix s[SA[i]:] of length max(LCP). O(n).
    """
    if not lcp:
        return ""
    max_lcp = max(lcp)
    if max_lcp == 0:
        return ""
    idx = lcp.index(max_lcp)
    return s[sa[idx]:sa[idx] + max_lcp]


def count_distinct_substrings(s: str, lcp: List[int]) -> int:
    """
    Count distinct non-empty substrings of s.
    Formula: n*(n+1)/2 - sum(LCP).
    Intuition: each suffix contributes (n - SA[i]) substrings (its prefixes),
    but LCP[i] of those are shared with the previous suffix in SA order.
    Time: O(n).
    """
    n = len(s)
    return n * (n + 1) // 2 - sum(lcp)


def longest_common_substring(s1: str, s2: str) -> str:
    """
    Find the longest substring common to s1 and s2.
    Method: concatenate s1 + '#' + s2 (separator not in either string),
    build SA+LCP, find max LCP between adjacent SA entries from different strings.
    Time: O((n+m) log²(n+m)).
    """
    sep = "#"
    combined = s1 + sep + s2
    sa  = build_suffix_array(combined)
    lcp = build_lcp_array(combined, sa)

    n1 = len(s1)
    best_len, best_pos = 0, 0

    for i in range(1, len(sa)):
        # sa[i] <= n1 means the suffix is from s1 (indices 0..n1)
        # sa[i] > n1 means it's from s2 (indices n1+1..end)
        from_s1_curr = sa[i]   <= n1
        from_s1_prev = sa[i-1] <= n1
        if from_s1_curr != from_s1_prev and lcp[i] > best_len:
            best_len = lcp[i]
            best_pos = sa[i]

    return combined[best_pos:best_pos + best_len]


# ── Tests ──────────────────────────────────────────────────────────────────
if __name__ == "__main__":
    s = "banana"
    sa  = build_suffix_array(s)
    lcp = build_lcp_array(s, sa)

    assert sa  == [5, 3, 1, 0, 4, 2], f"SA wrong: {sa}"
    assert lcp == [0, 1, 3, 0, 0, 2], f"LCP wrong: {lcp}"

    # Pattern counting
    assert count_occurrences(s, sa, "ana") == 2
    assert count_occurrences(s, sa, "an")  == 2
    assert count_occurrences(s, sa, "xyz") == 0
    assert count_occurrences(s, sa, "a")   == 3

    # Longest repeated substring
    assert longest_repeated_substring(s, sa, lcp) == "ana"

    # Distinct substrings
    # banana: 6*7/2 - (0+1+3+0+0+2) = 21 - 6 = 15
    assert count_distinct_substrings(s, lcp) == 15

    # Longest common substring
    assert longest_common_substring("abcdef", "zbcdf") == "bcd"
    assert longest_common_substring("abc",    "xyz")    == ""
    assert longest_common_substring("abab",   "baba")   == "aba"

    print("All tests passed.")
```

### Kasai's LCP Algorithm — Worked Example

```
s = "banana",  SA = [5, 3, 1, 0, 4, 2]
rank (inverse SA): rank[5]=0, rank[3]=1, rank[1]=2, rank[0]=3, rank[4]=4, rank[2]=5

Iterate i from 0 to 5 (STRING order, not SA order):

i=0: r=rank[0]=3,  j=SA[2]=1,  h=0
  Compare s[0+0]='b' vs s[1+0]='a' → mismatch. LCP[3]=0. h stays 0.

i=1: r=rank[1]=2,  j=SA[1]=3,  h=0
  s[1+0]='a' == s[3+0]='a' → h=1
  s[1+1]='n' == s[3+1]='n' → h=2
  s[1+2]='a' == s[3+2]='a' → h=3
  s[1+3]='n' vs s[3+3]='$' → mismatch. LCP[2]=3. h→2.

i=2: r=rank[2]=5,  j=SA[4]=4,  h=2  ← starts from lower bound h=2!
  s[2+2]='n' == s[4+2]='$'? No. LCP[5]=2. h→1.

i=3: r=rank[3]=1,  j=SA[0]=5,  h=1  ← starts from h=1
  s[3+1]='n' vs s[5+1]='$'? No (s[5]='a', s[5+1] out of bounds). LCP[1]=1. h→0.

i=4: r=rank[4]=4,  j=SA[3]=0,  h=0
  s[4+0]='n' vs s[0+0]='b' → mismatch. LCP[4]=0. h stays 0.

i=5: r=rank[5]=0   → first in SA, skip. h→0.

LCP = [0, 1, 3, 0, 0, 2]  ✓

KEY: At i=2, we started h=2 instead of 0 — saved 2 comparisons.
At i=3, we started h=1 instead of 0 — saved 1 comparison.
These savings accumulate to O(n) total — the h-decrement-by-1 invariant.
```

## 7. Common Variations & Extensions

### 7.1 LCP Range Minimum Query — O(1) Per Query After O(n log n) Preprocessing

For many problems you need `lcp(i, j)` — the LCP between suffix `SA[i]` and suffix `SA[j]` for arbitrary $i, j$ (not just adjacent). The answer is `min(LCP[i+1], LCP[i+2], ..., LCP[j])` (the minimum over the range between them in the LCP array). Building a sparse table for range minimum queries (see [[155.Segment tree — range query and point update O(log n)]]) on the LCP array enables O(1) LCP queries after O(n log n) preprocessing. This transforms the suffix array from a "linear scan" tool into a fully general string oracle.

### 7.2 Burrows-Wheeler Transform (BWT)

The BWT of $s$ is `BWT[i] = s[SA[i] - 1]` (character before each suffix in sorted order, with wraparound). The BWT has the remarkable property that it groups repeated characters together, enabling extremely efficient compression (run-length encoding of the BWT becomes the basis of `bzip2` and modern genomic read aligners). Computing BWT from a suffix array is O(n) — a direct loop. The inverse (recovering $s$ from BWT) requires building the FM-index using the BWT and a character occurrence table.

### 7.3 Suffix Automaton (SAM) — The O(n) Alternative

The Suffix Automaton is a compact DFA that accepts all suffixes of $s$, with only O(n) states and transitions. It answers many of the same queries as SA+LCP (distinct substrings, occurrences, LCS) in O(n) construction time. SAM is strictly more powerful for online construction (insert characters one by one) and for some counting problems. The trade-off: SAM implementation is significantly more complex (~80 lines vs ~30 for SA), and the constant factors are larger. For competitive programming: if the problem screams "distinct substrings" or "count occurrences of all substrings simultaneously", SAM may be preferred. If the problem is "find a specific pattern" or "LCS of two strings", SA+LCP is cleaner.

### 7.4 SA-IS — O(n) Linear Construction

The SA-IS (Suffix Array Induced Sorting) algorithm builds the suffix array in O(n) time and O(n) space. It classifies each suffix as S-type or L-type, identifies LMS (Left-Most S-type) suffixes, and uses a bucket-sort induction scheme. For competitive programming, SA-IS is rarely necessary — O(n log² n) handles $n = 2 \times 10^5$ comfortably. It becomes relevant for $n \geq 10^7$ (e.g., processing whole chromosomes) or when the suffix array is just one step in a larger O(n) pipeline.

## 9. CP Contest Application

### Typical Problem Structures

**1. "Longest repeated substring" (Codeforces Div 1 B/C, AtCoder ABC/ARC):** Maximum value in the LCP array. Standard SA+LCP solve in O(n log² n). For $n \leq 2 \times 10^5$, this fits comfortably. For $n \leq 10^6$, use O(n log n) with radix sort or SA-IS.

**2. "Number of distinct substrings" (Div 1 B, educational rounds):** `n*(n+1)/2 - sum(LCP)`. Two-line answer after SA+LCP build.

**3. "Longest common substring of k strings" (Div 1 C/D):** Concatenate all strings with unique separators. Build one SA+LCP. Slide a window over the LCP array maintaining that the window covers suffixes from all $k$ strings. The minimum LCP in the window is the LCS length for that window. Use a monotonic deque (see [[95.Sliding window maximum with monotonic deque]]) for O(n) window sliding.

**4. "Does pattern P appear in text T?" with multiple queries (Div 2 D/E):** Build SA once (O(n log² n)), then answer each query with binary search (O(m log n)). For $q$ queries of length $m$: O(n log² n + qm log n). Compare to KMP per query: O(n + m) per query = O(qn) total — SA wins when $q$ is large.

### Time Limit and Memory Considerations

For $n = 2 \times 10^5$: SA construction ≈ $2 \times 10^5 \times 17 \times 17 \approx 5.8 \times 10^7$ operations in C++ — runs in ~400ms. LCP construction (Kasai) ≈ $4 \times 10^5$ operations — negligible. Total well within 2s.

For $n = 10^6$: O(n log² n) = $\sim 4 \times 10^8$ — marginal. Use O(n log n) variant (radix sort in each doubling round) or SA-IS.

Memory: Two int arrays of size $n$ (SA and LCP) = $8n$ bytes. For $n = 10^6$: 8MB — fine. The prefix doubling code allocates 3–4 temporary arrays during construction, peaking at ~6 arrays of size $n$.

**Fingerprinting optimisation:** For pattern search with many queries, precompute a sparse table on LCP for O(1) LCP queries, then use the "LCP-accelerated binary search" that reduces pattern search from O(m log n) to O(m + log n). This matters when $m$ is large (e.g., $m = n/2$) and $q$ is large.
