# 11. Fixed-Size Sliding Window — Maximum, Minimum, Sum

> _"Instead of re-computing the whole room temperature every second, just note what changed at the door and what left through the window."_

---

## The Problem It Solves

You have an array `A` of `n` numbers and a window of fixed width `k`. For every contiguous sub-array of length `k`, report some aggregate — **sum**, **max**, or **min**.

**Naïve approach:** For each of the (n − k + 1) windows, compute the aggregate from scratch in O(k). Total: **O(n · k)**. For n = 10⁵ and k = 10³, that is 10⁸ operations — too slow.

**Sliding window idea:** Maintain a running data structure as the window slides one step right. Each element enters once and leaves once, so each element is processed a constant number of times. Total: **O(n)** for sum; **O(n)** amortized for max/min.

---

## Part 1 — Sliding Window Sum

This is the simplest case and the foundation for understanding the others.

### Core idea

When the window moves one step right:

- Element `A[i + k]` **enters** from the right.
- Element `A[i]` **leaves** from the left.

So instead of re-summing k numbers, we do:

```
new_sum = old_sum + A[i + k] - A[i]
```

One addition, one subtraction. O(1) per step.

### Implementation

```python
def sliding_window_sum(A, k):
    n = len(A)
    if n < k:
        return []

    window_sum = sum(A[:k])          # first window O(k)
    result = [window_sum]

    for i in range(n - k):           # slide n-k times
        window_sum += A[i + k]       # new element enters
        window_sum -= A[i]           # old element leaves
        result.append(window_sum)

    return result


# Example
A = [2, 1, 5, 1, 3, 2]
print(sliding_window_sum(A, 3))
# [8, 7, 9, 6]
# Windows: [2,1,5]=8  [1,5,1]=7  [5,1,3]=9  [1,3,2]=6
```

### NumPy

```python
import numpy as np

def sliding_sum_np(A, k):
    cs = np.cumsum(A)
    cs = np.concatenate(([0], cs))        # prepend 0 for clean indexing
    return cs[k:] - cs[:-k]              # cs[i+k] - cs[i] for all i

A = np.array([2, 1, 5, 1, 3, 2])
print(sliding_sum_np(A, 3))              # [8 7 9 6]
```

This is O(n) time, O(1) extra space (result array aside). The `np.cumsum` trick computes all window sums simultaneously via vectorised subtraction of two shifted prefix-sum arrays.

## Part 2 — Sliding Window Maximum (and Minimum)

Adding `A[i+k]` and subtracting `A[i]` works perfectly for sums because subtraction is O(1). But for **maximum**, you cannot simply subtract the leaving element — you don't know if the max was inside the window at all, let alone whether removing one element changes it.

Naïve per-window max: O(k) per window → O(n · k) total. Still too slow.

The correct tool is a **monotonic deque**.

### The monotonic deque

A **deque** (double-ended queue) is a data structure that supports O(1) push and pop from both ends.

We maintain a deque that stores **indices** of elements in the current window, with this invariant:

> The deque is always sorted in decreasing order of `A[index]`. Its front always holds the index of the current window's maximum.

As the window slides:

1. **Expire old indices:** If the front of the deque is an index that has fallen outside the window (`deque[0] <= i - 1`), pop it from the front.
2. **Maintain the invariant for the new element:** Before pushing index `i + k` onto the back, pop from the back any indices whose values are ≤ `A[i + k]`. Those elements can never be the maximum of any future window (the new element is both larger and more recent).
3. **Push** the new index onto the back.
4. **Read the max:** `A[deque[0]]` — always the front.

### Why this is O(n) amortized

Each index is pushed onto the deque at most once and popped at most once. Total pushes + pops across all n steps ≤ 2n. So despite the inner while-loop, the total work is O(n).

### Implementation

```python
from collections import deque

def sliding_window_max(A, k):
    n = len(A)
    dq = deque()       # stores indices
    result = []

    for i in range(n):
        # Step 1: remove indices outside the window
        while dq and dq[0] < i - k + 1:
            dq.popleft()

        # Step 2: maintain decreasing order — pop smaller elements from back
        while dq and A[dq[-1]] <= A[i]:
            dq.pop()

        dq.append(i)

        # Window is fully formed starting at index k-1
        if i >= k - 1:
            result.append(A[dq[0]])

    return result


# Example
A = [1, 3, -1, -3, 5, 3, 6, 7]
print(sliding_window_max(A, 3))
# [3, 3, 5, 5, 6, 7]
```

Trace for `A = [1, 3, -1, -3, 5, 3, 6, 7]`, k = 3:

|i|A[i]|Deque (indices)|Window|Max|
|---|---|---|---|---|
|0|1|[0]|—|—|
|1|3|[1]|—|—|
|2|-1|[1, 2]|[1,3,-1]|3|
|3|-3|[1, 2, 3]|[3,-1,-3]|3|
|4|5|[4]|[-1,-3,5]|5|
|5|3|[4, 5]|[-3,5,3]|5|
|6|6|[6]|[5,3,6]|6|
|7|7|[7]|[3,6,7]|7|

At i=4, all of [1,2,3] get popped because A[4]=5 ≥ all of them. The deque stays lean.

### Sliding window minimum

Identical code — just flip the comparison in step 2:

```python
# Replace:   A[dq[-1]] <= A[i]
# With:      A[dq[-1]] >= A[i]
```

Now the deque is increasing from front to back, and `A[dq[0]]` is the minimum.

---

## Formal Proof of the Deque Invariant

**Claim:** At every step after the first window is formed, `A[dq[0]]` is the maximum of the current window `A[i-k+1 .. i]`.

**Proof:**

_The maximum is in the deque._ Suppose the true maximum of the window is at index `m`. When index `m` was processed, either: (a) nothing was popped after it (it is already at the back, so it is still there), or (b) a later index `j > m` with `A[j] > A[m]` was pushed — but then `A[j] ≥ A[m]`, so `j` is the (strictly larger) maximum of the window, contradicting that `m` was the max. So the max element's index is always in the deque.

_The front of the deque is the maximum._ By construction, the deque is decreasing in value. All indices in the deque are in the current window (expired ones are popped). Since the deque is decreasing and the front is the oldest (leftmost) index remaining, the front is the largest. ✓

_The deque contains only valid window indices._ Step 1 pops any index that has aged out. So every index in the deque satisfies `dq[k] ∈ [i-k+1, i]`. ✓

## Complexity Summary

|Problem|Strategy|Time|Space|
|---|---|---|---|
|Sliding window sum|Running sum|O(n)|O(1)|
|Sliding window max|Monotonic deque (decreasing)|O(n) amortized|O(k)|
|Sliding window min|Monotonic deque (increasing)|O(n) amortized|O(k)|
|Naïve max/min|Re-scan each window|O(n · k)|O(1)|

Space O(k) because the deque holds at most k indices at any time (one per element currently in the window).

## Full Python Reference

```python
from collections import deque
import numpy as np

def sliding_window_sum(A, k):
    n = len(A)
    s = sum(A[:k])
    res = [s]
    for i in range(n - k):
        s += A[i + k] - A[i]
        res.append(s)
    return res

def sliding_window_max(A, k):
    dq, res = deque(), []
    for i in range(len(A)):
        while dq and dq[0] < i - k + 1:
            dq.popleft()
        while dq and A[dq[-1]] <= A[i]:
            dq.pop()
        dq.append(i)
        if i >= k - 1:
            res.append(A[dq[0]])
    return res

def sliding_window_min(A, k):
    dq, res = deque(), []
    for i in range(len(A)):
        while dq and dq[0] < i - k + 1:
            dq.popleft()
        while dq and A[dq[-1]] >= A[i]:
            dq.pop()
        dq.append(i)
        if i >= k - 1:
            res.append(A[dq[0]])
    return res

# NumPy vectorised sum (all windows at once)
def sliding_sum_np(A, k):
    cs = np.concatenate(([0], np.cumsum(A)))
    return cs[k:] - cs[:-k]

# Example usage
A = [2, 1, 5, 1, 3, 2]
k = 3
print(sliding_window_sum(A, k))    # [8, 7, 9, 6]
print(sliding_window_max(A, k))    # [5, 5, 5, 3]
print(sliding_window_min(A, k))    # [1, 1, 1, 1]
```

## Connection to AI / ML / Deep Learning

The sliding window pattern is one of the most directly applicable algorithmic ideas in practical ML work.

### 1. Convolutional Neural Networks (CNNs)

A 1D convolution with kernel size k is exactly a sliding window operation — at each position, compute the dot product of the kernel with the k-element window. In NumPy:

```python
import numpy as np

def conv1d_naive(signal, kernel):
    k = len(kernel)
    n = len(signal)
    out = []
    for i in range(n - k + 1):
        out.append(np.dot(signal[i:i+k], kernel))
    return out
```

This is O(n · k). Efficient implementations (FFT-based or `np.convolve`) exploit the structure, but the window pattern is the conceptual core. A 2D conv (image convolution) is a 2D sliding window. Every filter in a CNN is a learned kernel applied via this exact mechanism.

### 2. Pooling layers

Max-pooling and average-pooling in CNNs are literally sliding window maximum and sliding window mean over spatial (or temporal) windows. The monotonic deque algorithm is what makes O(n) max-pooling possible in inference optimisations.

```python
# What nn.MaxPool1d(kernel_size=3, stride=1) computes:
output = sliding_window_max(feature_map, k=3)
```

### 3. Time-series feature engineering

Every rolling statistic used in forecasting — rolling mean, rolling std, rolling max drawdown — is a sliding window computation. Libraries like Pandas use sliding-window strategies under the hood:

```python
import pandas as pd
s = pd.Series([2, 1, 5, 1, 3, 2])
print(s.rolling(3).sum())    # [NaN, NaN, 8.0, 7.0, 9.0, 6.0]
print(s.rolling(3).max())    # [NaN, NaN, 5.0, 5.0, 5.0, 3.0]
```

### 4. Attention in Transformers — local / sliding window attention

Full self-attention is O(n²) in sequence length n. Longformer, BigBird, and similar architectures replace it with **sliding window attention**: each token only attends to a window of k neighbours. This reduces attention computation to O(n · k). The deque-based view of which tokens are "in scope" is the same invariant.

### 5. Online learning and stream statistics

In reinforcement learning and online learning, the "effective horizon" (how far back to look) defines a sliding window over recent rewards or gradients. Running statistics (mean, variance) over a fixed-size recent window use the O(1) update rule: `new_stat = old_stat + contribution(new) − contribution(old)`.

### 6. Gradient clipping by window

Some RL algorithms clip rewards or advantages over a recent window of episodes. The sliding window min/max gives the normalization bounds in O(n) across the replay buffer.

## Common Mistakes

```python
# Mistake 1: Off-by-one — window not yet full
for i in range(n):
    result.append(A[dq[0]])   # WRONG — appends before window is full

if i >= k - 1:                # correct guard
    result.append(A[dq[0]])

# Mistake 2: Storing values instead of indices in the deque
dq.append(A[i])               # WRONG — cannot check if element has expired
dq.append(i)                  # correct — store index, look up value with A[i]

# Mistake 3: Wrong expiry condition
while dq and dq[0] < i - k:   # WRONG — off-by-one, misses the leftmost valid element
while dq and dq[0] < i - k + 1:  # correct

# Mistake 4: Wrong monotone direction for min
# For MAX: pop while A[dq[-1]] <= A[i]   (keep decreasing deque)
# For MIN: pop while A[dq[-1]] >= A[i]   (keep increasing deque)
# Swapping these gives you the opposite answer silently.

# Mistake 5: Using a sorted list instead of a deque
# Inserting into a sorted list is O(k), making the total O(n·k).
# The deque works because we only ever pop from the ends.

# Mistake 6: Forgetting the deque holds INDICES, not values
max_val = dq[0]               # WRONG — dq[0] is an index
max_val = A[dq[0]]            # correct
```

## Variants

|Variant|Technique|
|---|---|
|Fixed-size window sum|O(1) running sum update|
|Fixed-size window max/min|O(n) monotonic deque|
|Variable-size window (shrink when condition violated)|Two-pointer / variable sliding window|
|Window max with range queries|Sparse table (O(n log n) build, O(1) query)|
|All-pair window stats|Segment tree or Fenwick tree|

The variable-size sliding window (where you shrink the window when a constraint is violated) is covered separately — it is a different algorithm despite the similar name.

## Summary

|Concept|One-liner|
|---|---|
|Window sum in O(1)|`new_sum = old_sum + A[right] − A[left]`|
|Window max in O(n)|Monotonic decreasing deque of indices|
|Window min in O(n)|Monotonic increasing deque of indices|
|Why deque not sorted list|Only push/pop from ends → O(1) per operation|
|Deque invariant|Front = current max; all indices in `[i−k+1, i]`|
|CNN connection|Conv layer = sliding dot product; max-pool = sliding max|
|Key implementation detail|Store indices, not values, in the deque|
