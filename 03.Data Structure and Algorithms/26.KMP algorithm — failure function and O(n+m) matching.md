## 1. Intuition First

### The Core Idea

In naive string matching (see [[25.String matching — naive O(nm) and why it matters]]), after a partial match of j characters followed by a mismatch, you slide the pattern one position right and restart the inner loop from j=0. You throw away everything you learned about those j matched characters.

KMP refuses to do that.

The key observation: when you've matched the first j characters of the pattern and then hit a mismatch, those j matched characters tell you something about the text you're sitting in. Specifically, you know the last j characters of the text are exactly `pattern[0..j-1]`. If `pattern[0..j-1]` has a proper prefix that is also a suffix — say, of length k — then you already know the text contains `pattern[0..k-1]` at the current position minus k. You don't need to reverify those k characters. You can resume matching from position k in the pattern, without moving the text pointer backward at all.

This is the entire algorithm. The failure function (also called the partial match table or `lps` array — Longest Proper Prefix which is also Suffix) precomputes, for every prefix of the pattern, the length of the longest proper prefix of that prefix that is also its suffix. During matching, it tells you how far back to fall in the pattern when a mismatch occurs.

The text pointer **never moves backward**. The pattern pointer moves backward (via the failure function) but the total amount it can move backward is bounded by the total amount it has moved forward, which is at most n. This gives O(n) matching after O(m) preprocessing — total O(n+m).

### Why This Exists — The Complexity Gap

Naive is O(nm) worst case. For n = 10⁵ and m = 10³, that's 10⁸ operations — borderline TLE. For DNA sequence matching where n = 10⁸ (human genome) and m = 150 (read length), naive is simply impossible.

KMP achieves O(n+m) deterministically, with O(m) preprocessing space and zero randomness. Unlike Rabin-Karp (see [[27.Rabin-Karp — rolling hash for pattern matching]]), it has no false positives, no modular arithmetic, and no probability of failure. It is the canonical correct solution to the exact string matching problem.

### The "Aha" Moment

Build the pattern `"ababc"` and ask: if you matched `"abab"` and then failed on `"c"`, where should you restart?

You matched `"abab"`. The longest proper prefix of `"abab"` that is also a suffix is `"ab"` (length 2). So the last 2 characters of the text you just scanned are `"ab"` — which equals `pattern[0..1]`. You don't need to recheck them. Drop the pattern pointer back to position 2 and continue. You haven't moved the text pointer at all.

The failure function encodes exactly this: `lps[j]` = the length of the longest proper prefix of `pattern[0..j]` that is also a suffix of `pattern[0..j]`. When a mismatch occurs after matching j characters, don't restart at 0 — restart at `lps[j-1]`.

The failure function itself is computed using the same logic applied to the pattern matching itself against itself. That recursive elegance is why KMP is beautiful: the preprocessing and the matching use the same underlying idea.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

KMP appears in contests in the following forms:

**Direct pattern matching:** "Find all occurrences of pattern P in text T" with n, m ≤ 10⁵ or larger. Naive TLEs; KMP passes.

**Period of a string:** The smallest period of a string of length m is `m - lps[m-1]`. If `m % (m - lps[m-1]) == 0`, the string is composed entirely of repetitions of that period. This is a clean O(m) solution to a problem that looks like it needs O(m²). LeetCode 459 — Repeated Substring Pattern — is the canonical example.

**String rotation detection:** String B is a rotation of string A if and only if B appears in AA (A concatenated with itself). Run KMP with pattern=B on text=AA. O(n) total.

**Matching in a circular buffer:** When the text wraps around (e.g., circular DNA, ring buffers), concatenate the text with itself and search.

**The signal:** Any problem requiring O(n) or O(n+m) string matching, especially with the worst case invocable (small alphabet, repetitive text), or problems involving periodicity, rotations, or prefix-suffix relationships in strings.

**Common trap:** The failure function is 0-indexed and the value at index j covers `pattern[0..j]`, not `pattern[0..j-1]`. Off-by-one errors in the lps array construction are the most common KMP bug. Always verify your lps array on a hand-traced example before submitting.

**Second trap:** When a match is found at position i (i.e., `j == m`), you must continue searching — don't return immediately unless you only want the first match. After a full match, fall back using `j = lps[j-1]` (same as a mismatch recovery) to catch overlapping matches.

### Machine Learning / AI

**Tokenisation and vocabulary construction:** BPE (Byte Pair Encoding), used by GPT-2, RoBERTa, and virtually all modern LLMs, iteratively finds and merges the most frequent adjacent byte pairs in a corpus. The "find all occurrences of pair XY in the corpus" step is a string matching problem. For large corpora, HuggingFace's `tokenizers` library (Rust backend) uses Boyer-Moore-Horspool for this, but KMP is the conceptually cleaner solution. The failure function's role in avoiding redundant scans maps directly to avoiding redundant pair scans.

**Biological sequence analysis — genomics pipelines:** Tools like BWA (Burrows-Wheeler Aligner) and Bowtie align short DNA reads to reference genomes. The inner alignment kernel is a linear-time string matching problem. KMP (and its FM-index generalisation) is the foundation. Understanding KMP's text-pointer-never-moves-backward invariant is the prerequisite for understanding why BWT-based aligners work.

**Intrusion detection and network packet inspection:** Deep Packet Inspection (DPI) systems in network security scan packet payloads for malicious byte patterns. The Snort IDS uses Aho-Corasick (the multi-pattern generalisation of KMP via a trie with failure links) for signature matching. KMP on a single pattern is the conceptual atom from which Aho-Corasick is built. Understanding KMP failure links = understanding Aho-Corasick failure links.

**Log parsing in ML infrastructure:** ML training pipelines generate logs that must be scanned for specific error patterns. `grep` with fixed strings uses Boyer-Moore or Aho-Corasick internally. The failure function concept — don't re-examine characters you've already passed — is the same principle that makes log scanning on petabyte-scale training logs tractable.

**Autoregressive stopping criteria:** In text generation, detecting when a generated sequence contains a specific stop sequence (e.g., `"<|endoftext|>"`) requires exact string matching on a stream. KMP is ideal here: process tokens as they arrive (text pointer never goes back), O(m) state carried between tokens, O(1) per new token after preprocessing the stop sequence.

## 3. Algorithm / Pattern

### Part 1 — Building the Failure Function (lps array)

`lps[j]` = length of the longest proper prefix of `pattern[0..j]` that is also a suffix of `pattern[0..j]`.

"Proper" means the prefix/suffix cannot be the entire string — `lps[j] < j+1` always.

**Initialisation:** `lps[0] = 0` always (no proper prefix of a single character).

**Building lps[1..m-1]:** Maintain a pointer `k` = length of the current matching prefix. For each position j:

- If `pattern[j] == pattern[k]`: both extend — `lps[j] = k + 1`, advance both j and k.
- If mismatch and `k > 0`: fall back via `k = lps[k-1]`. Do not advance j.
- If mismatch and `k == 0`: `lps[j] = 0`, advance j.

This is the same sliding logic as the matching phase, applied to the pattern matching against itself.

### Part 2 — Matching Phase

Maintain text pointer `i` (never decrements) and pattern pointer `j` (advances on match, falls back on mismatch):

- If `text[i] == pattern[j]`: both advance.
- If `j == m`: match found at position `i - m`. Fall back: `j = lps[j-1]`.
- If mismatch and `j > 0`: fall back `j = lps[j-1]`. Do not advance i.
- If mismatch and `j == 0`: advance i only.

### Complexity Derivation

**Preprocessing O(m):** The pointer k can increase by at most 1 per iteration of j. j increases from 0 to m-1 (m increments). k can decrease at most as many times as it increased. So total operations ≤ 2m → O(m).

**Matching O(n):** The text pointer i increments from 0 to n-1 (n increments total). The pattern pointer j can increase by at most 1 per increment of i. j can decrease via lps fallback, but each decrease corresponds to a past increase, so total decreases ≤ total increases ≤ n. Total pattern pointer movements ≤ 2n → O(n).

**Total: O(n + m).** The text pointer never moves backward — this is the invariant that makes the analysis clean.

**Space: O(m)** for the lps array. The matching itself uses O(1) additional space.

## 4. Pseudocode

```
FUNCTION build_lps(pattern):
    m ← length(pattern)
    lps ← array of m zeros

    // lps[0] is always 0 — no proper prefix for a single character
    k ← 0       // length of current matching proper prefix-suffix
    j ← 1       // scan through pattern[1..m-1]

    WHILE j < m:
        IF pattern[j] == pattern[k]:
            // Extend the matching prefix-suffix by one
            k ← k + 1
            lps[j] ← k
            j ← j + 1
        ELSE IF k > 0:
            // Mismatch after some matches: fall back without advancing j
            // (same logic as the matching phase: use previously computed lps)
            k ← lps[k - 1]
        ELSE:
            // k == 0: no prefix-suffix possible at position j
            lps[j] ← 0
            j ← j + 1

    RETURN lps


FUNCTION kmp_search(text, pattern):
    n ← length(text)
    m ← length(pattern)
    matches ← empty list

    IF m == 0: RETURN [0, 1, ..., n]
    IF m > n:  RETURN []

    lps ← build_lps(pattern)

    i ← 0       // text pointer — NEVER decrements
    j ← 0       // pattern pointer — can fall back via lps

    WHILE i < n:
        IF text[i] == pattern[j]:
            i ← i + 1
            j ← j + 1
        
        IF j == m:
            // Full match found; match starts at i - m
            APPEND (i - m) TO matches
            // Fall back to continue searching (catches overlapping matches)
            j ← lps[j - 1]
        ELSE IF i < n AND text[i] != pattern[j]:
            IF j > 0:
                j ← lps[j - 1]   // fall back; do NOT increment i
            ELSE:
                i ← i + 1        // j == 0: no fallback possible, advance text

    RETURN matches
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <cassert>

// Build the lps (Longest Proper Prefix which is also Suffix) array.
// lps[j] = length of the longest proper prefix of pattern[0..j]
//           that is also a suffix of pattern[0..j].
// Time: O(m) | Space: O(m)
std::vector<int> build_lps(const std::string& pattern) {
    const int m = static_cast<int>(pattern.size());
    std::vector<int> lps(m, 0);

    int k = 0;  // length of current matching prefix-suffix
    int j = 1;

    while (j < m) {
        if (pattern[j] == pattern[k]) {
            lps[j] = ++k;
            ++j;
        } else if (k > 0) {
            // Fall back: don't advance j, use previously computed lps
            k = lps[k - 1];
        } else {
            lps[j] = 0;
            ++j;
        }
    }

    return lps;
}

// KMP string search — all occurrences of pattern in text.
// Time: O(n + m) | Space: O(m) for lps array
std::vector<int> kmp_search(const std::string& text, const std::string& pattern) {
    std::vector<int> matches;
    const int n = static_cast<int>(text.size());
    const int m = static_cast<int>(pattern.size());

    if (m == 0) {
        for (int i = 0; i <= n; ++i) matches.push_back(i);
        return matches;
    }
    if (m > n) return matches;

    const std::vector<int> lps = build_lps(pattern);

    int i = 0;  // text pointer — never decrements
    int j = 0;  // pattern pointer

    while (i < n) {
        if (text[i] == pattern[j]) {
            ++i;
            ++j;
        }

        if (j == m) {
            matches.push_back(i - m);   // match starts at i - m
            j = lps[j - 1];             // fall back for overlapping matches
        } else if (i < n && text[i] != pattern[j]) {
            if (j > 0) {
                j = lps[j - 1];         // fall back without moving i
            } else {
                ++i;                    // j == 0: can't fall back further
            }
        }
    }

    return matches;
}

// Application 1: Check if pattern is a substring of text (O(n+m))
bool kmp_contains(const std::string& text, const std::string& pattern) {
    return !kmp_search(text, pattern).empty();
}

// Application 2: Smallest period of a string.
// A string s has period p if s[i] == s[i % p] for all i.
// Smallest period = m - lps[m-1].
// If m % (m - lps[m-1]) == 0, s is a repetition of its period.
int smallest_period(const std::string& s) {
    if (s.empty()) return 0;
    const std::vector<int> lps = build_lps(s);
    return static_cast<int>(s.size()) - lps.back();
}

// Application 3: Check if B is a rotation of A.
// B is a rotation of A iff B appears in A+A.
bool is_rotation(const std::string& a, const std::string& b) {
    if (a.size() != b.size()) return false;
    return kmp_contains(a + a, b);
}

int main() {
    // --- lps correctness ---
    // "ababc": lps = [0,0,1,2,0]
    // "aabaabaaa": lps = [0,1,0,1,2,3,4,2,3] — let's verify manually
    assert((build_lps("ababc") == std::vector<int>{0, 0, 1, 2, 0}));
    assert((build_lps("aabaabaaa") == std::vector<int>{0, 1, 0, 1, 2, 3, 4, 2, 3}));
    assert((build_lps("abcabc") == std::vector<int>{0, 0, 0, 1, 2, 3}));
    assert((build_lps("aaaa") == std::vector<int>{0, 1, 2, 3}));
    assert((build_lps("abcde") == std::vector<int>{0, 0, 0, 0, 0})); // no prefix-suffix

    // --- matching correctness ---
    assert((kmp_search("abcabc", "abc") == std::vector<int>{0, 3}));
    assert((kmp_search("aaaaaa", "aaa") == std::vector<int>{0, 1, 2, 3})); // overlapping
    assert((kmp_search("hello", "world") == std::vector<int>{}));
    assert((kmp_search("ababababc", "ababc") == std::vector<int>{4}));

    // --- worst case: would be O(nm) for naive, O(n+m) for KMP ---
    std::string worst_text(100000, 'a');
    std::string worst_pat(1000, 'a');
    worst_pat.back() = 'b';
    auto result = kmp_search(worst_text, worst_pat); // must be empty, runs instantly
    assert(result.empty());

    // --- applications ---
    assert(smallest_period("abababab") == 2);   // period "ab"
    assert(smallest_period("abcabcabc") == 3);  // period "abc"
    assert(smallest_period("abcde") == 5);      // no repetition → period = itself

    assert(is_rotation("abcde", "cdeab") == true);
    assert(is_rotation("abcde", "abced") == false);
    assert(is_rotation("aa", "aa") == true);

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
def build_lps(pattern: str) -> list[int]:
    """
    Build the Longest Proper Prefix-Suffix (lps) array for pattern.

    lps[j] = length of the longest proper prefix of pattern[0..j]
              that is also a suffix of pattern[0..j].

    'Proper' means strictly shorter than the full string (lps[j] <= j).

    Time:  O(m) — each character considered at most twice
    Space: O(m)

    Examples:
        >>> build_lps("ababc")
        [0, 0, 1, 2, 0]
        >>> build_lps("aabaabaaa")
        [0, 1, 0, 1, 2, 3, 4, 2, 3]
        >>> build_lps("aaaa")
        [0, 1, 2, 3]
    """
    m = len(pattern)
    lps = [0] * m

    k = 0  # length of the current longest prefix-suffix
    j = 1  # scan position through pattern

    while j < m:
        if pattern[j] == pattern[k]:
            # Characters match: extend the prefix-suffix
            k += 1
            lps[j] = k
            j += 1
        elif k > 0:
            # Mismatch after some matches: fall back using previous lps
            # Critical: do NOT increment j here
            k = lps[k - 1]
        else:
            # k == 0: no prefix-suffix possible here
            lps[j] = 0
            j += 1

    return lps


def kmp_search(text: str, pattern: str) -> list[int]:
    """
    KMP string search — all starting positions of pattern in text.

    The text pointer i NEVER moves backward.
    The pattern pointer j falls back via lps on mismatch.

    Time:  O(n + m) — preprocessing O(m), matching O(n)
    Space: O(m) for the lps array

    Examples:
        >>> kmp_search("abcabc", "abc")
        [0, 3]
        >>> kmp_search("aaaaaa", "aaa")    # overlapping matches
        [0, 1, 2, 3]
        >>> kmp_search("ababababc", "ababc")
        [4]
    """
    n, m = len(text), len(pattern)
    if m == 0:
        return list(range(n + 1))
    if m > n:
        return []

    lps = build_lps(pattern)
    matches = []

    i = 0  # text pointer — NEVER decrements
    j = 0  # pattern pointer

    while i < n:
        if text[i] == pattern[j]:
            i += 1
            j += 1

        if j == m:
            # Full match at text position i - m
            matches.append(i - m)
            # Fall back to search for overlapping matches
            j = lps[j - 1]
        elif i < n and text[i] != pattern[j]:
            if j > 0:
                j = lps[j - 1]   # fall back; i stays put
            else:
                i += 1           # no fallback: advance text

    return matches


def smallest_period(s: str) -> int:
    """
    Return the length of the smallest period of s.
    Period p means s[i] == s[i % p] for all i.

    Uses the identity: period = len(s) - lps[-1].
    If len(s) % period == 0, s is composed entirely of that period.

    Examples:
        >>> smallest_period("abababab")
        2
        >>> smallest_period("abcde")
        5   # no repetition; period is the string itself
    """
    if not s:
        return 0
    lps = build_lps(s)
    return len(s) - lps[-1]


def is_rotation(a: str, b: str) -> bool:
    """
    Check if b is a rotation of a using KMP.
    b is a rotation of a iff b appears in a+a.

    Time: O(n)  (where n = len(a) = len(b))

    Examples:
        >>> is_rotation("abcde", "cdeab")
        True
        >>> is_rotation("abcde", "abced")
        False
    """
    if len(a) != len(b):
        return False
    return bool(kmp_search(a + a, b))

    return [i for i in range(n - m + 1)
            if all(text[i + j] == pattern[j] for j in range(m))]
```

## 6. Visual Explanation

### Building the lps Array for `"ababc"`

```
pattern:  a  b  a  b  c
index:    0  1  2  3  4

j=0: lps[0] = 0 always (no proper prefix for single char)

j=1: pattern[1]='b' vs pattern[k=0]='a' → mismatch, k=0
     lps[1] = 0

j=2: pattern[2]='a' vs pattern[k=0]='a' → match!
     k=1, lps[2]=1, advance j
     "aba": longest proper prefix = suffix = "a" (length 1) ✓

j=3: pattern[3]='b' vs pattern[k=1]='b' → match!
     k=2, lps[3]=2, advance j
     "abab": longest proper prefix = suffix = "ab" (length 2) ✓

j=4: pattern[4]='c' vs pattern[k=2]='a' → mismatch, k=2>0
     fall back: k = lps[k-1] = lps[1] = 0
     pattern[4]='c' vs pattern[k=0]='a' → mismatch, k=0
     lps[4] = 0, advance j

Final lps: [0, 0, 1, 2, 0]
```

### Matching `"ababababc"` against pattern `"ababc"` (lps = `[0,0,1,2,0]`)

```
text:    a  b  a  b  a  b  a  b  c
index:   0  1  2  3  4  5  6  7  8

i=0,j=0: a==a ✓  i=1,j=1
i=1,j=1: b==b ✓  i=2,j=2
i=2,j=2: a==a ✓  i=3,j=3
i=3,j=3: b==b ✓  i=4,j=4
i=4,j=4: a≠c ✗   j=lps[3]=2   ← fall back; i stays at 4

i=4,j=2: a==a ✓  i=5,j=3
i=5,j=3: b==b ✓  i=6,j=4
i=6,j=4: a≠c ✗   j=lps[3]=2   ← fall back; i stays at 6

i=6,j=2: a==a ✓  i=7,j=3
i=7,j=3: b==b ✓  i=8,j=4
i=8,j=4: c==c ✓  i=9,j=5
j==m=5 → MATCH at i-m = 9-5 = 4
         j = lps[4] = 0

i=9: loop ends (i >= n=9)

Result: [4]

Key observation: text pointer i moved from 0 to 9 — strictly forward.
Pattern pointer j moved: 0→1→2→3→4 (back to 2) →3→4 (back to 2) →3→4→5 (back to 0)
Total j increments: 9. Total j decrements: 3. Net: 6. Always ≤ n.
```

### The Fallback in the lps Build — Why `k = lps[k-1]`

```
pattern:  a  a  b  a  a  b  a  a  c
lps so far when we reach j=7, k=5 and get a mismatch on 'c':

We've established: lps[5]=3, meaning "aab" is both a prefix and suffix of "aabaaб".
When we fall back, we ask: what's the longest prefix-suffix of "aab"?
That's lps[k-1] = lps[4] = 2, meaning "aa".

So: if "aab" matched as a prefix AND as a suffix, then "aa" (a prefix of "aab")
also matches as a suffix. We don't need to recheck — it's guaranteed.

This is why the fallback uses lps[k-1] and not k-1:
we exploit the already-computed prefix-suffix information recursively.
```

## 7. Common Variations & Extensions

### Variation 1: KMP Automaton (Finite State Machine View)

The lps array implicitly defines a DFA (Deterministic Finite Automaton) over the pattern. State j means "we have matched j characters of the pattern." Transitions: on character c at state j, go to state j+1 if `pattern[j]==c`, else fall back repeatedly until you find the longest state k where `pattern[k]==c`, then go to k+1. You can precompute the full transition table (m × σ entries) for O(1) per text character instead of the while-loop fallback — useful when you match the same pattern against many texts.

### Variation 2: Period and Border Structure

`lps[m-1]` gives the length of the longest proper border of the pattern (a string that is both a prefix and suffix). Iterating `lps[lps[m-1]-1]`, `lps[lps[lps[m-1]-1]-1]`, etc., gives all border lengths in decreasing order — all periods of the pattern. This is useful for problems asking "how many ways can the pattern tile itself?"

### Variation 3: Z-algorithm Equivalence

The Z-array (see [[28.Z-algorithm — prefix-suffix matching]]) and the lps array encode the same information differently. `Z[i]` = length of the longest substring starting at position i that is also a prefix of the string. You can convert between them. Z-algorithm is often easier to implement correctly under contest pressure; KMP's lps is more directly useful for the periodicity and automaton applications.

### Variation 4: Aho-Corasick — KMP for Multiple Patterns

Build a trie of all patterns, then compute failure links across trie nodes using the same lps logic applied to the trie structure. Each failure link points to the longest proper suffix of the current node's string that is also a prefix of some pattern in the trie. This gives O(n + M + output) matching for all patterns simultaneously, where M is total pattern length. This is the foundation for multi-pattern DPI, Snort IDS signatures, and multi-keyword text search — the direct generalisation of KMP.

## 9. CP Contest Application

### Typical Problem Structures

**Codeforces Div. 2 C–D, Div. 1 A–B:** "Given strings S and T (|S|, |T| ≤ 10⁶), find all positions where T occurs in S" — direct KMP. Time limit 2 seconds, n=10⁶ makes naive TLE.

**Periodicity problems:** "Find the smallest period of the given string" — one lps build, one subtraction. O(m). These appear as sub-problems inside harder problems (e.g., tiling, compression, pattern counting).

**Construction problems:** "Construct the shortest string that contains both S and T as substrings" — find the longest suffix of S that is a prefix of T using KMP (append T to S, search for T in the concatenation).

### Implementation Speed Under Contest Pressure

KMP has two components — lps build and matching — each ~10 lines. The most common contest mistake is merging them into one function and confusing the two pointer pairs (k,j for lps vs i,j for matching). Keep them separate. Under pressure, the cleanest approach:

1. Write `build_lps` first, test it on `"ababc"` → `[0,0,1,2,0]`.
2. Write `kmp_search` using the lps array, verify on one overlapping case.
3. Submit.

### Handling Multiple Queries

If the same pattern is queried against many texts, precompute the lps array once — O(m) — and reuse it for each text at O(n) per query. If the same text is queried with many patterns, KMP doesn't help directly (build a suffix array instead, see [[30.Suffix array — construction and LCP array]]). KMP is optimised for the one-pattern, many-texts direction.

_KMP's deeper lesson is not the algorithm itself but the idea behind it: when you fail, don't start over — use what you already know. The lps array is a precomputed map of what you already know at every possible failure point. This principle — exploit structure in failure to avoid redundant work — appears in branch-and-bound, alpha-beta pruning, and every form of memoisation. KMP is the simplest place to see it in pure form._
