## 1. Intuition First

### The Core Idea

In standard combinations ([[74.Generating all combinations — nCr without repetition]]), once you select an element, it leaves the pool — you cannot pick it again. Combinations _with repetition_ (also called **multiset combinations** or **combinations with replacement**) relax this: after selecting element `x`, `x` remains available for subsequent selections.

The canonical example: you have flavours {vanilla, chocolate, strawberry} and you want to choose 2 scoops. With repetition, {vanilla, vanilla} is valid — you can pick the same flavour twice. Without repetition, it is not.

The count of k-combinations with repetition from n distinct types is:

$$\binom{n + k - 1}{k} = \frac{(n+k-1)!}{k!,(n-1)!}$$

This is the **stars and bars** formula (see [[190.Stars and bars — distributing identical objects]]): imagine placing k identical balls into n distinct bins, where each bin can hold any number. The number of ways is C(n+k−1, k). The equivalence is exact — a combination with repetition _is_ a multiset, and a multiset _is_ a distribution of k identical items into n types.

The algorithm change from [[74.Generating all combinations — nCr without repetition]] is a single character: recurse with `start = i` instead of `start = i + 1`. This one change allows re-selecting the same element while still preventing reorderings (enforcing the canonical non-decreasing order).

### Why This Exists

Many real-world selection processes allow repetition:

- Choosing k items from a menu (same dish can be ordered multiple times)
- Rolling a die k times and recording outcomes in sorted order
- Distributing k identical resources among n recipients
- Selecting k tokens from a vocabulary (with replacement) for a multiset-of-words model

The key distinction from permutations with repetition (where order matters): combinations with repetition only care about _how many times_ each element appears, not the sequence. {A, A, B} and {A, B, A} are the same combination but different permutations.

### The "Aha" Moment

The code change — `i` instead of `i+1` — has a precise semantic meaning:

> **`start = i+1` (no repetition): "I've used element i; future picks must come from strictly later positions."** **`start = i` (with repetition): "I've used element i; future picks may reuse element i or come from later positions."**

The non-decreasing order constraint (only picking indices ≥ start) still eliminates reorderings — {A, B, A} is never generated because after picking B (index 1), you can only pick index ≥ 1, so a second A (index 0) is impossible. The sorted/non-decreasing output structure is maintained automatically.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- Coin change variants: "how many ways to make amount X using unlimited coins of given denominations?" — generating all multisets of coins summing to X
- "Choose k items from n types, items can repeat" — explicit problem statement
- Distributing identical objects: map directly to stars-and-bars count, or enumerate when k and n are small
- Unbounded knapsack enumeration: enumerate all multisets of items fitting in capacity

**Pattern signals:**

```
"unlimited supply" or "each item can be used multiple times"  →  repetition allowed
"arrange k objects chosen from n types, order irrelevant"     →  combinations with repetition
n small (≤ 10), k small (≤ 15)                               →  enumerate directly
Count only (not enumerate)                                    →  stars-and-bars: C(n+k-1, k)
```

**Count comparison: without vs with repetition**

```
n=3, k=3:
  Without:  C(3,3) = 1        (only {1,2,3})
  With:     C(5,3) = 10       ({1,1,1},{1,1,2},{1,1,3},{1,2,2},{1,2,3},
                                {1,3,3},{2,2,2},{2,2,3},{2,3,3},{3,3,3})

n=5, k=3:
  Without:  C(5,3) = 10
  With:     C(7,3) = 35
```

**Common traps:**

1. **Using `i+1` when the problem allows repetition.** The single most common bug — copying the standard combination template without changing `i+1` to `i`. The result silently generates too few combinations, missing all multisets with repeated elements.
    
2. **Confusing with permutations with repetition.** nⁿ (or nᵏ for k picks) counts ordered selections with repetition. C(n+k−1,k) counts unordered. If the problem says "order doesn't matter," you want combinations with repetition; if "order matters," you want permutations with repetition (just enumerate all nᵏ strings/sequences).
    
3. **Forgetting that the count grows faster than without-repetition for large k.** C(n+k−1,k) ≈ nᵏ/k! for large k relative to n, which can exceed memory for moderate n and k. Always check the count before enumerating.
    
4. **Combination sum (LC 39) trap:** The problem "find all combinations summing to target using numbers from candidates, each number usable unlimited times" is _not_ standard combinations with repetition from a fixed n types — the set of choices changes because you filter by sum. The correct approach is backtracking with `start = i` (repetition allowed) and a sum constraint, not a size constraint.
    

### Machine Learning / AI

**1. Bag-of-words and multiset representations.** A document in the bag-of-words model is a multiset of vocabulary tokens — a combination with repetition from the vocabulary. A document of length k drawn from vocabulary of size V is one of C(V+k−1, k) possible multisets. Understanding this count is understanding why exact bag-of-words models are intractable for large V: C(50000+100−1, 100) is astronomically large, which is why probabilistic models (LDA, word2vec) are necessary.

**2. Multinomial sampling and language model generation.** Sampling k tokens from a language model's vocabulary (with replacement, ignoring order) is combination-with-repetition sampling. The multinomial distribution over vocabulary types is the probability distribution over these C(V+k−1,k) multisets. Top-k sampling and nucleus sampling in autoregressive language models constrain the vocabulary to the top-k or top-p tokens before multinomial sampling — conceptually restricting n to make the multiset space tractable.

**3. Data augmentation via token resampling.** In text augmentation, replacing words in a sentence by sampling with replacement from a synonym set generates multiset combinations of synonyms. If a sentence has 5 words each with 3 synonyms, the number of distinct augmented sentences (ignoring order among replacements) is related to the multiset coefficient. This connects to EDA (Easy Data Augmentation, Wei & Zou 2019).

**4. Hyperparameter grid search with repetition.** When hyperparameter values can be reused across multiple components (e.g., choosing the same learning rate for multiple heads in a multi-task model), the search space is combinations with repetition. For n=5 learning rate values and k=3 heads: C(7,3)=35 combinations rather than P(5,3)=60 ordered or C(5,3)=10 without-repetition.

**5. Unbounded knapsack as multiset optimisation.** The unbounded knapsack problem (see [[176.Unbounded knapsack — item taken any number of times]]) asks: given items with weights and values, and unlimited copies of each, find the maximum-value multiset fitting in weight W. The brute-force baseline is enumerating all multisets (combinations with repetition) of items fitting in W — DP is the efficient version of this enumeration, but understanding the combinatorial structure helps design the DP state.

## 3. Algorithm / Pattern

### The One-Line Difference from Standard Combinations

```
Standard combinations (no repetition):
    backtrack(i + 1, path)   # advance past i — can't reuse

Combinations with repetition:
    backtrack(i, path)       # stay at i — can reuse element i
```

This single change transforms the algorithm. Everything else — the `start` parameter enforcing non-decreasing selection, the base case, the result collection — is identical.

### Why Non-Decreasing Order Still Prevents Duplicates

With `start = i`, the invariant becomes: "elements in path are in non-decreasing index order." Since we only move forward (or stay) in the index array, sequences like [B, A] (index 1, then index 0) are impossible. Every multiset is generated in exactly one canonical form: non-decreasing.

### Formal Structure

```
State:      (start_index, current_path)
Choice:     pick any index i ∈ [start, n−1]
Recurse:    with start = i  (same index — repetition allowed)
Terminal:   len(path) == k
Count:      C(n+k−1, k) leaves
```

### Pruning for Sum-Constrained Variant

When there is no fixed size k but a sum target (like LC 39), the terminal condition changes to `remaining_sum == 0` and the pruning becomes `nums[i] > remaining_sum`. For sorted input, this `break` eliminates all subsequent elements when the current is already too large.

### Complexity

```
Count:      C(n+k−1, k)
Time:       O(k × C(n+k−1, k))   — k to copy each combination
Space:      O(k) recursion depth
```

For n=5, k=5: C(9,5) = 126. For n=10, k=10: C(19,10) = 92,378. Grows polynomially in n for fixed k, but exponentially in k for fixed n.

## 4. Pseudocode

```
# ── Core: k combinations with repetition from n elements ──────────────────

FUNCTION combinations_with_rep(nums, k):
    result ← []
    CALL backtrack(start=0, path=[])
    RETURN result

FUNCTION backtrack(start, path):
    IF len(path) == k:
        result.APPEND(COPY of path)
        RETURN

    FOR i FROM start TO n - 1:
        path.APPEND(nums[i])
        CALL backtrack(i, path)       # KEY: i, not i+1 — allows repetition
        path.POP()


# ── Comparison: the only difference from no-repetition ────────────────────

# No repetition:    backtrack(i + 1, path)   start advances past i
# With repetition:  backtrack(i,     path)   start stays at i


# ── Sum-target variant (LC 39 style): no fixed k, sum constraint ───────────

FUNCTION combination_sum(candidates, target):
    SORT candidates
    result ← []
    CALL backtrack_sum(start=0, path=[], remaining=target)
    RETURN result

FUNCTION backtrack_sum(start, path, remaining):
    IF remaining == 0:
        result.APPEND(COPY of path)    # found valid combination
        RETURN

    FOR i FROM start TO len(candidates) - 1:
        IF candidates[i] > remaining:
            BREAK                      # sorted → all subsequent are larger too
        path.APPEND(candidates[i])
        CALL backtrack_sum(i, path, remaining - candidates[i])  # i, not i+1
        path.POP()


# ── Stars and bars: count only (no enumeration) ────────────────────────────

FUNCTION count_combinations_with_rep(n, k):
    RETURN C(n + k - 1, k)            # binomial coefficient
    # C(n+k-1, k) = (n+k-1)! / (k! * (n-1)!)
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <numeric>
#include <cassert>

// ─────────────────────────────────────────────────────────────────────────────
// Core: k combinations with repetition
// The ONLY difference from standard combination: recurse with i, not i+1
// ─────────────────────────────────────────────────────────────────────────────
void backtrack_rep(int start, int k, std::vector<int>& path,
                   const std::vector<int>& nums,
                   std::vector<std::vector<int>>& result) {
    if ((int)path.size() == k) {
        result.push_back(path);
        return;
    }
    for (int i = start; i < (int)nums.size(); ++i) {
        path.push_back(nums[i]);
        backtrack_rep(i, k, path, nums, result);   // i, NOT i+1
        path.pop_back();
    }
}

std::vector<std::vector<int>> combinations_with_rep(
        const std::vector<int>& nums, int k) {
    if (k == 0) return {{}};
    std::vector<std::vector<int>> result;
    std::vector<int> path;
    backtrack_rep(0, k, path, nums, result);
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Stars and bars: count only, no enumeration
// C(n+k-1, k) — computed iteratively to avoid overflow on large inputs
// ─────────────────────────────────────────────────────────────────────────────
long long count_with_rep(int n, int k) {
    // C(n+k-1, k) — use the smaller of k and (n-1) as the loop count
    int top = n + k - 1;
    int bot = std::min(k, n - 1);
    long long result = 1;
    for (int i = 0; i < bot; ++i) {
        result = result * (top - i) / (i + 1);
    }
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Combination sum (LC 39): unlimited use, no fixed size, sum target
// candidates may be unsorted — sort first for the break optimisation
// ─────────────────────────────────────────────────────────────────────────────
void backtrack_sum(int start, int remaining,
                   std::vector<int>& path,
                   const std::vector<int>& cands,
                   std::vector<std::vector<int>>& result) {
    if (remaining == 0) {
        result.push_back(path);
        return;
    }
    for (int i = start; i < (int)cands.size(); ++i) {
        if (cands[i] > remaining) break;   // sorted: all further too large
        path.push_back(cands[i]);
        backtrack_sum(i, remaining - cands[i], path, cands, result);  // i, not i+1
        path.pop_back();
    }
}

std::vector<std::vector<int>> combination_sum(
        std::vector<int> candidates, int target) {
    std::sort(candidates.begin(), candidates.end());
    std::vector<std::vector<int>> result;
    std::vector<int> path;
    backtrack_sum(0, target, path, candidates, result);
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Side-by-side comparison: the single-character difference
// Same function body — only the recursive call changes
// ─────────────────────────────────────────────────────────────────────────────
void demo_difference(int start, int k, std::vector<int>& path,
                     const std::vector<int>& nums,
                     std::vector<std::vector<int>>& no_rep,
                     std::vector<std::vector<int>>& with_rep) {
    // Collect for both simultaneously to show the contrast
    if ((int)path.size() == k) {
        // Both record at the same depth — difference is only in recursion
        return;
    }
    for (int i = start; i < (int)nums.size(); ++i) {
        path.push_back(nums[i]);

        // Without repetition: i+1 — advance past current
        demo_difference(i + 1, k, path, nums, no_rep, with_rep);
        // Above line, if collecting at base: gives C(n,k) results

        // With repetition: i — stay at current
        // demo_difference(i, k, path, nums, no_rep, with_rep);
        // Above line, if collecting at base: gives C(n+k-1,k) results

        path.pop_back();
    }
}

int main() {
    std::vector<int> nums = {1, 2, 3};

    // k=2 with repetition: C(3+2-1,2) = C(4,2) = 6
    auto r = combinations_with_rep(nums, 2);
    assert((int)r.size() == 6);
    // Expected: {1,1},{1,2},{1,3},{2,2},{2,3},{3,3}
    std::vector<std::vector<int>> expected = {
        {1,1},{1,2},{1,3},{2,2},{2,3},{3,3}
    };
    assert(r == expected);

    // k=3 with repetition: C(5,3) = 10
    auto r3 = combinations_with_rep(nums, 3);
    assert((int)r3.size() == 10);

    // Count verification
    assert(count_with_rep(3, 2) == 6);
    assert(count_with_rep(3, 3) == 10);
    assert(count_with_rep(5, 3) == 35);
    assert(count_with_rep(1, 5) == 1);   // only one type: {x,x,x,x,x}

    // Edge cases
    assert(combinations_with_rep({1}, 3).size() == 1);  // {{1,1,1}}
    assert(combinations_with_rep(nums, 0).size() == 1);  // {{}}

    // k=2 WITHOUT repetition from same input: C(3,2) = 3
    // {1,2},{1,3},{2,3} — missing {1,1},{2,2},{3,3}
    // (tested by count: 3 < 6)

    // Combination sum
    auto cs = combination_sum({2, 3, 6, 7}, 7);
    // {7} and {2,2,3} are the two solutions
    assert(cs.size() == 2);
    std::sort(cs.begin(), cs.end());
    assert(cs[0] == std::vector<int>({2, 2, 3}));
    assert(cs[1] == std::vector<int>({7}));

    auto cs2 = combination_sum({2, 3, 5}, 8);
    // {2,2,2,2},{2,3,3},{3,5}
    assert(cs2.size() == 3);

    // No solution
    assert(combination_sum({3, 5}, 4).empty());

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from itertools import combinations_with_replacement as itertools_cwr
from math import comb

# ─────────────────────────────────────────────────────────────────────────────
# Core: combinations with repetition — the i vs i+1 difference made explicit
# ─────────────────────────────────────────────────────────────────────────────

def combinations_with_rep(nums: list[int], k: int) -> list[list[int]]:
    """
    Generate all C(n+k-1, k) combinations of size k from nums,
    where each element may be chosen more than once.

    The single algorithmic difference from combinations() in
    [[74.Generating all combinations — nCr without repetition]]:
        combinations:          backtrack(i + 1, path)  ← advance
        combinations_with_rep: backtrack(i,     path)  ← stay (allow reuse)

    Output is in non-decreasing order because start never moves backward:
    once you're at index i, you only choose index ≥ i.

    Time:  O(k × C(n+k-1, k))
    Space: O(k) recursion depth

    >>> combinations_with_rep([1,2,3], 2)
    [[1,1],[1,2],[1,3],[2,2],[2,3],[3,3]]
    """
    n = len(nums)
    result = []

    def backtrack(start: int, path: list[int]) -> None:
        if len(path) == k:
            result.append(path[:])
            return
        for i in range(start, n):
            path.append(nums[i])
            backtrack(i, path)        # i, NOT i+1 — this is the entire difference
            path.pop()

    if k == 0:
        return [[]]
    backtrack(0, [])
    return result


def combinations_no_rep(nums: list[int], k: int) -> list[list[int]]:
    """
    Standard combinations (no repetition) — shown for direct comparison.
    The ONLY difference from combinations_with_rep: backtrack(i+1, ...).
    """
    n = len(nums)
    result = []

    def backtrack(start: int, path: list[int]) -> None:
        if len(path) == k:
            result.append(path[:])
            return
        for i in range(start, n - (k - len(path)) + 1):
            path.append(nums[i])
            backtrack(i + 1, path)    # i+1, NOT i — no reuse
            path.pop()

    if k == 0: return [[]]
    if k > n: return []
    backtrack(0, [])
    return result


# ─────────────────────────────────────────────────────────────────────────────
# Stars and bars: count without enumeration
# ─────────────────────────────────────────────────────────────────────────────

def count_with_rep(n: int, k: int) -> int:
    """
    Count k-combinations with repetition from n distinct types.

    Formula: C(n+k-1, k) — from the stars-and-bars bijection:
    choosing k items from n types WITH repetition ≡
    distributing k identical balls into n distinct bins ≡
    counting non-decreasing sequences of length k over {0,...,n-1}.

    See [[190.Stars and bars — distributing identical objects]].

    >>> count_with_rep(3, 2)   # {1,1},{1,2},{1,3},{2,2},{2,3},{3,3}
    6
    >>> count_with_rep(10, 3)
    220
    """
    return comb(n + k - 1, k)


# ─────────────────────────────────────────────────────────────────────────────
# Combination sum (LC 39): no fixed k, sum target, repetition allowed
# This is the most common contest/interview form of this pattern
# ─────────────────────────────────────────────────────────────────────────────

def combination_sum(candidates: list[int], target: int) -> list[list[int]]:
    """
    Find all combinations of candidates (unlimited reuse) that sum to target.
    Each combination is a multiset — {2,2,3} appears once, not as permutations.

    Key differences from combinations_with_rep:
    - No fixed k: stop when remaining == 0, not when len(path) == k
    - Sum pruning: break when candidates[i] > remaining (requires sorted input)
    - Backtrack start is still i (not i+1) — same repetition semantics

    Time:  O(n^(target/min_candidate)) worst case
    Space: O(target/min_candidate) recursion depth

    >>> combination_sum([2, 3, 6, 7], 7)
    [[2, 2, 3], [7]]
    """
    candidates.sort()   # required for the break optimisation
    result = []

    def backtrack(start: int, path: list[int], remaining: int) -> None:
        if remaining == 0:
            result.append(path[:])
            return
        for i in range(start, len(candidates)):
            if candidates[i] > remaining:
                break               # sorted: all subsequent also too large
            path.append(candidates[i])
            backtrack(i, path, remaining - candidates[i])   # i, not i+1
            path.pop()

    backtrack(0, [], target)
    return result


# ─────────────────────────────────────────────────────────────────────────────
# Combination sum II (LC 40): duplicates in input, each element used once
# This is [[74]]-style (no repetition) with dedup — NOT this topic
# Included here to sharpen the contrast between the two patterns
# ─────────────────────────────────────────────────────────────────────────────

def combination_sum_no_rep(candidates: list[int], target: int) -> list[list[int]]:
    """
    Find all combinations (each candidate used at most once) summing to target.
    Candidates may have duplicates → need dedup condition.

    Uses i+1 (no repetition) + dedup skip.
    Contrast with combination_sum above which uses i (repetition).
    """
    candidates.sort()
    result = []

    def backtrack(start: int, path: list[int], remaining: int) -> None:
        if remaining == 0:
            result.append(path[:])
            return
        for i in range(start, len(candidates)):
            if candidates[i] > remaining:
                break
            if i > start and candidates[i] == candidates[i - 1]:
                continue            # dedup: same value at same recursion level
            path.append(candidates[i])
            backtrack(i + 1, path, remaining - candidates[i])   # i+1: no reuse
            path.pop()

    backtrack(0, [], target)
    return result


# ─────────────────────────────────────────────────────────────────────────────
# Multiset generation: enumerate all multisets of size k
# from a vocabulary — ML application (bag-of-words sampling)
# ─────────────────────────────────────────────────────────────────────────────

def all_multisets(vocab: list[str], k: int) -> list[tuple[str, ...]]:
    """
    Generate all C(n+k-1, k) multisets of size k from vocabulary.

    A document in the bag-of-words model is one of these multisets.
    For |vocab|=5, k=3: C(7,3)=35 possible multisets.
    For |vocab|=50000, k=100: astronomically many — hence probabilistic models.

    >>> all_multisets(['a','b','c'], 2)
    [('a','a'),('a','b'),('a','c'),('b','b'),('b','c'),('c','c')]
    """
    n = len(vocab)
    result = []

    def backtrack(start: int, path: list[str]) -> None:
        if len(path) == k:
            result.append(tuple(path))
            return
        for i in range(start, n):
            path.append(vocab[i])
            backtrack(i, path)       # i: repetition allowed
            path.pop()

    backtrack(0, [])
    return result

    # Multisets
    ms = all_multisets(['a','b','c'], 2)
    assert ms == [('a','a'),('a','b'),('a','c'),('b','b'),('b','c'),('c','c')]
    assert len(all_multisets(['a','b','c','d'], 3)) == count_with_rep(4, 3)

    print("All tests passed.")
```

### Stars and Bars: The Counting Bijection

Why C(n+k−1, k) for n types, k choices with repetition?

```
Choosing 3 items from types {A, B, C} with repetition:

Example distribution "2 A's, 0 B's, 1 C":  ★★ | | ★

Total symbols: k stars + (n-1) dividers = 3 + 2 = 5 symbols
Choose k=3 positions for stars from 5 positions: C(5,3) = C(n+k-1, k) = 10

All 10 multisets of size 3 from {A,B,C}:
  ★★★ | |   → {A,A,A}     (3,0,0)
  ★★ |★|    → {A,A,B}     (2,1,0)
```

## 7. Common Variations & Extensions

**Permutations with repetition.** If order _does_ matter (selecting k items from n types with repetition, all orderings distinct), the count is nᵏ. Generate by standard DFS with a `start = 0` always (no advancement), building sequences of length k from n options. This is simpler than combinations because no dedup logic is needed — every sequence is distinct. The code is a k-level nested loop flattened into recursion.

**Bounded repetition: each element used at most m times.** The count is the coefficient of xᵏ in the expansion of (1 + x + x² + ... + xᵐ)ⁿ. Generate by tracking a count array alongside the path: at element `i`, only add it if `path.count(nums[i]) < m`. This generalises both the no-repetition case (m=1) and the unlimited-repetition case (m=k). Relevant to the bounded knapsack problem (see [[177.Bounded knapsack — item taken at most k times]]).

**Multiset permutations.** The number of distinct permutations of a multiset (e.g., how many ways to arrange MISSISSIPPI) is the multinomial coefficient n! / (n₁! × n₂! × ... × nₖ!). Generate by the used-array backtracking from [[73.Generating all permutations — swap-based and insert-based]] with the dedup condition — this produces all distinct orderings of a multiset, which is the intersection of permutations and multisets.

**Generating the m-th combination with repetition.** As with standard combinations, there is a ranking/unranking scheme based on the combinatorial number system extended to multisets. This allows O(k × log n) random access to any specific combination without generating all C(n+k−1,k), useful in distributed search where each worker handles a slice of the multiset space.

## 9. CP Contest Application

**The canonical template and its three variants — one per recursion call style:**

```python
# Variant A: combinations NO repetition, fixed size k
#   backtrack(i + 1, ...)  +  stop at len(path) == k

# Variant B: combinations WITH repetition, fixed size k (this note)
#   backtrack(i, ...)      +  stop at len(path) == k

# Variant C: combination sum, repetition, sum target (LC 39)
#   backtrack(i, ...)      +  stop at remaining == 0

# Variant D: combination sum, NO repetition, sum target (LC 40)
#   backtrack(i + 1, ...)  +  stop at remaining == 0  +  dedup skip

# The 2×2 matrix: (repetition?) × (size or sum constraint?)
#                 | fixed size k    | sum target       |
# no repetition:  | standard C(n,k) | LC 40            |
# with repetition:| this note       | LC 39            |
```

**When enumeration becomes infeasible and DP takes over:**

The crossover point is roughly when C(n+k−1,k) > 10⁷ (for Python) or 10⁸ (C++). Beyond that, counting problems (how many combinations sum to target?) require DP over the multiset structure — exactly the unbounded knapsack DP (see [[176.Unbounded knapsack — item taken any number of times]]). The DP state `dp[s]` = number of multisets summing to `s` is the counting version of the enumeration here. Enumerating first and counting second is the pedagogical path; DP is the production path.
