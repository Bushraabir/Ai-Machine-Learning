## 1. Intuition First

### The Core Idea

Imagine you are navigating a massive labyrinth. Two guards are assigned to find the exit.

**Guard A (BFS)** walks with a rope tied to the entrance. She fans out in concentric rings — every path that is 1 step away, then every path that is 2 steps away, and so on. She is _guaranteed_ to find the shortest exit, but her rope gets exponentially heavier with every step she takes. At depth 20, she is simultaneously holding 2²⁰ ≈ 1,000,000 rope ends.

**Guard B (DFS / Backtracking)** picks one corridor and walks as deep as she can. The moment she hits a dead end or smells something wrong, she retraces her steps and tries the next corridor. Her rope stays thin — she only ever holds the _current path_ in her hand. At depth 20 she is holding exactly 20 rope-ends, regardless of how many corridors branch off along the way.

This is the core insight: **BFS trades memory for optimality guarantees; DFS trades optimality for memory efficiency, unlocked further by pruning.**

Backtracking is not "just DFS." Backtracking is **DFS equipped with a kill switch**: at any point during the descent, if a partial solution _cannot possibly_ lead to a valid complete solution, the entire subtree is abandoned. This transforms the worst-case exponential search space into something tractable when the pruning is tight.

### Why This Exists

For a problem with branching factor _b_ and solution depth _d_:

- BFS memory: O(b^d) — every node at the frontier must be stored simultaneously.
- DFS memory: O(d) — only the current path from root to leaf.

For combinatorial problems where _d_ is large and _b_ is moderate (e.g., placing 8 queens on an 8×8 board, generating all valid subsets), BFS becomes completely infeasible in memory. The search tree for N-Queens at N=15 has ≈10¹² nodes. BFS would require storing tens of millions of board states simultaneously. DFS with pruning explores a tiny fraction of those nodes and uses O(N) memory.

BFS is the right choice when:

1. The solution depth is shallow and roughly uniform.
2. You need the **shortest** path in an unweighted space.
3. The branching factor is small enough that the frontier stays manageable.

Backtracking is the right choice when:

1. You need _any_ valid solution (or _all_ valid solutions), not the shortest path.
2. Constraints can be checked incrementally — many branches can be killed early.
3. Memory is the bottleneck, not time.

### The "Aha" Moment

**BFS guarantees level-by-level shortest paths because it exhausts all paths of length _k_ before any path of length _k+1_. Backtracking doesn't care about length ordering — it cares about constraint satisfaction at each node.**

The switch from BFS to backtracking is therefore not a tradeoff in solution quality for constraint satisfaction problems (CSPs) — there is no "shorter" valid placement of N queens. The switch is purely about _feasibility_: BFS makes the problem unsolvable in practice; backtracking makes it fast.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Any problem asking you to enumerate, generate, or verify combinatorial objects — valid parenthesizations, permutations with constraints, graph colourings, exact cover, word ladders where you want all solutions, Sudoku solving.

**Pattern signals:**

- "Find all valid arrangements of..." → backtracking.
- "Can you reach state X?" with unit-cost edges and small depth → BFS.
- "Find the minimum number of steps to..." → BFS on implicit graph.
- "Generate/count all X satisfying constraint Y" → backtracking with pruning.
- You see small N (N ≤ 20) with hard combinatorial constraints → backtracking.
- You see an unweighted graph with "fewest moves" or "shortest sequence" → BFS.

**Common trap that kills submissions:**

Using BFS for a constraint satisfaction problem because "BFS is for graphs" and then running out of memory or time limit, or using backtracking for a shortest-path problem and getting a suboptimal answer because DFS does not explore nodes in order of depth. The critical mistake is confusing _reachability_ problems (BFS wins) with _enumeration/satisfaction_ problems (backtracking wins).

A subtler trap: implementing backtracking without early pruning — writing a "generate-then-filter" pattern. This defeats the purpose entirely. The constraint check _must_ happen during the descent, not after reaching a leaf.

**Time limit guidance:** On Codeforces, backtracking with pruning can solve N-Queens up to N≈15 within 2s. Beyond that, you typically need bitmask DP (see [[105. Bitmask DP — state compression]]). BFS with a `visited` set is usually safe up to ~10⁶–10⁷ states before hitting memory limits.

### Machine Learning / AI

**Classical AI search is the direct ancestor.** AIMA (Russell & Norvig) formalises this explicitly: BFS is used for uninformed shortest-path search; DFS/backtracking is used for constraint satisfaction problems (CSPs) like map colouring, scheduling, and timetabling. The `python-constraint` library and OR-Tools' CP-SAT solver both implement backtracking as their core engine.

**Neural Architecture Search (NAS):** The search space for NAS (choosing layer types, widths, connections) is a combinatorial tree. Early NAS systems (Zoph & Le, 2016) explored this with reinforcement learning, but the _search space structure_ is exactly a backtracking tree — a sequence of architecture decisions with constraints (e.g., valid tensor shapes, memory budget). DARTS (Liu et al., 2019, ICLR) reformulates this as continuous relaxation, but the underlying discrete space is a backtracking problem. Understanding why brute-force BFS over NAS is infeasible (exponential states) and why pruning (early stopping of unpromising architectures) is necessary comes directly from this analysis.

**Hyperparameter search:** Grid search is BFS over a discretised hyperparameter space (exhaustive, level-by-level). Random search and Bayesian optimisation are best understood as informed backtracking — they commit to a path through the hyperparameter space and abandon it early if the loss signal is bad (pruning). Optuna's tree-structured Parzen estimator (TPE) builds a probabilistic model of which regions of the search tree are worth descending into — this is exactly the `bound()` function in branch-and-bound backtracking.

**Beam search in NLP** is the middle ground: it is BFS with a beam width _k_, keeping only the top-k candidates at each depth. It combines BFS's level-order guarantee with a memory bound. Understanding that beam search degenerates to BFS as k→∞ and to greedy DFS as k→1 makes the tradeoff immediately clear.

## 3. Algorithm / Pattern

### The Decision Framework

```
Is an optimal (shortest/fewest-steps) solution required?
├── YES → Does the state space fit in memory?
│         ├── YES → BFS (guarantees shortest path)
│         └── NO  → A* or bidirectional BFS (informed pruning of BFS)
└── NO  → Are solutions defined by constraint satisfaction?
          ├── YES → Backtracking (DFS + constraint checking + pruning)
          └── NO  → Any DFS (iterative deepening if memory is tight)
```

### Backtracking Template Logic

1. **State:** A partial solution built incrementally (e.g., queens placed so far, digits assigned).
2. **Choose:** Select the next decision point (e.g., which column to place the next queen in).
3. **Constraint check:** Before recursing, verify the partial solution is still valid. If not, return immediately (**prune**).
4. **Explore:** Recurse with the extended partial solution.
5. **Unchoose:** Undo the choice and try the next option (**backtrack**).

### Why BFS Cannot Prune the Same Way

BFS maintains an _explicit frontier_ — all states at depth _d_ must be stored before exploring depth _d+1_. Pruning in BFS means not enqueuing invalid states, which helps, but the _valid_ states at depth _d_ must still all be held in memory simultaneously. Backtracking holds only the current path, so pruning eliminates an exponential subtree without any memory overhead.

### Complexity

Let _b_ = branching factor, _d_ = maximum depth, _P_ = pruning ratio (fraction of nodes pruned, 0 ≤ P < 1).

|Method|Time|Space|
|---|---|---|
|BFS|O(b^d)|O(b^d)|
|DFS (no pruning)|O(b^d)|O(d)|
|Backtracking (pruning)|O(b^d · (1-P)) ≈ much less|O(d)|

The key insight: both BFS and DFS are O(b^d) in the worst case on time, but BFS is also O(b^d) on _space_, which is the killer. Backtracking's practical advantage comes from the multiplicative pruning factor collapsing the effective b.

For N-Queens, the naive b=N (any column per row), but with constraint propagation b_effective ≈ N/3, collapsing the search from N! to roughly N!/(N/3)! in practice.

## 4. Pseudocode

```
// BFS Template — for shortest-path / reachability
BFS(start, goal):
    queue ← [(start, 0)]        // (state, depth)
    visited ← {start}
    while queue is not empty:
        (state, depth) ← dequeue(queue)
        if state == goal:
            return depth         // guaranteed minimum depth
        for each neighbour of state:
            if neighbour not in visited and is_valid(neighbour):
                visited.add(neighbour)
                enqueue(queue, (neighbour, depth + 1))
    return -1  // unreachable

// Backtracking Template — for constraint satisfaction / enumeration
Backtracking(partial_solution, results):
    if is_complete(partial_solution):
        results.append(copy(partial_solution))
        return

    for each choice in generate_choices(partial_solution):
        // PRUNE: check constraint BEFORE recursing
        if is_valid(partial_solution + choice):
            partial_solution.add(choice)           // choose
            Backtracking(partial_solution, results) // explore
            partial_solution.remove(choice)         // unchoose (backtrack)
```

Key distinction: BFS checks validity _before enqueuing_ (space constraint). Backtracking checks validity _before recursing_ (time constraint via tree pruning). The difference is when and how many states you need to remember.

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ============================================================
// BFS: Shortest word ladder (implicit graph, state = string)
// Time: O(N * L^2) where N = word count, L = word length
// Space: O(N * L) for the frontier queue
// ============================================================
int bfsWordLadder(const string& begin, const string& end,
                  const unordered_set<string>& wordList) {
    if (wordList.find(end) == wordList.end()) return 0;

    unordered_set<string> visited;
    queue<pair<string, int>> q;
    q.push({begin, 1});
    visited.insert(begin);

    while (!q.empty()) {
        auto [word, steps] = q.front();
        q.pop();

        for (int i = 0; i < (int)word.size(); ++i) {
            string next = word;
            for (char c = 'a'; c <= 'z'; ++c) {
                next[i] = c;
                if (next == end) return steps + 1;
                if (wordList.count(next) && !visited.count(next)) {
                    visited.insert(next);
                    q.push({next, steps + 1});
                }
            }
        }
    }
    return 0; // unreachable
}

// ============================================================
// BACKTRACKING: N-Queens — find ALL valid placements
// Time: O(N!) upper bound; O(N! / (N/3)!) with pruning in practice
// Space: O(N) call stack + O(N^2) per solution stored
// ============================================================
class NQueens {
public:
    vector<vector<string>> solveNQueens(int n) {
        vector<vector<string>> results;
        vector<int> queens(n, -1); // queens[row] = col

        // Bitsets for O(1) conflict checking
        unordered_set<int> cols, diag1, diag2;

        auto solve = [&](auto& self, int row) -> void {
            if (row == n) {
                // Reconstruct board
                vector<string> board(n, string(n, '.'));
                for (int r = 0; r < n; ++r) board[r][queens[r]] = 'Q';
                results.push_back(board);
                return;
            }
            for (int col = 0; col < n; ++col) {
                // PRUNE: check all three conflict sets in O(1)
                if (cols.count(col) || diag1.count(row - col) || diag2.count(row + col))
                    continue;
                // Choose
                queens[row] = col;
                cols.insert(col);
                diag1.insert(row - col);
                diag2.insert(row + col);
                // Explore
                self(self, row + 1);
                // Unchoose (backtrack)
                cols.erase(col);
                diag1.erase(row - col);
                diag2.erase(row + col);
            }
        };

        solve(solve, 0);
        return results;
    }
};

// ============================================================
// COMPARISON DEMO: Generate all subsets
// BFS-style (level order expansion) vs Backtracking (DFS)
// Both O(2^N * N) time, but BFS holds 2^(N/2) states in memory
// ============================================================
vector<vector<int>> subsetsBFS(vector<int>& nums) {
    vector<vector<int>> result = {{}};
    for (int num : nums) {
        int sz = result.size();
        // BFS: each level appends num to ALL existing subsets
        for (int i = 0; i < sz; ++i) {
            result.push_back(result[i]);
            result.back().push_back(num);
        }
    }
    return result; // must hold all 2^N subsets simultaneously
}

vector<vector<int>> subsetsBacktrack(vector<int>& nums) {
    vector<vector<int>> result;
    vector<int> current;
    
    function<void(int)> bt = [&](int start) {
        result.push_back(current); // valid at every node, not just leaves
        for (int i = start; i < (int)nums.size(); ++i) {
            current.push_back(nums[i]);
            bt(i + 1);
            current.pop_back(); // backtrack
        }
    };
    bt(0);
    return result; // builds subsets one at a time, O(N) stack depth
}

// ============================================================
// Test driver
// ============================================================
int main() {
    // BFS word ladder
    unordered_set<string> wordList = {"hot","dot","dog","lot","log","cog"};
    cout << "Word ladder hit->cog: " 
         << bfsWordLadder("hit", "cog", wordList) << "\n"; // 5

    // Backtracking N-Queens
    NQueens nq;
    auto solutions = nq.solveNQueens(4);
    cout << "4-Queens solutions: " << solutions.size() << "\n"; // 2

    // Subset comparison
    vector<int> nums = {1, 2, 3};
    auto r1 = subsetsBFS(nums);
    auto r2 = subsetsBacktrack(nums);
    cout << "BFS subsets: " << r1.size() << "\n";         // 8
    cout << "Backtrack subsets: " << r2.size() << "\n";   // 8
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from collections import deque
from typing import Optional

# ============================================================
# BFS: Shortest path in unweighted graph
# Use when: fewest steps/hops, level-order guarantees required
# Time: O(V + E), Space: O(V)
# ============================================================
def bfs_shortest_path(graph: dict[int, list[int]], start: int, goal: int) -> int:
    """
    Find the shortest path length from start to goal in an unweighted graph.
    
    Returns -1 if goal is unreachable.
    
    The BFS guarantee: nodes are dequeued in non-decreasing order of depth.
    The first time we reach 'goal', it is via the shortest path.
    """
    if start == goal:
        return 0
    
    visited = {start}
    queue: deque[tuple[int, int]] = deque([(start, 0)])
    
    while queue:
        node, depth = queue.popleft()
        for neighbour in graph.get(node, []):
            if neighbour == goal:
                return depth + 1
            if neighbour not in visited:
                visited.add(neighbour)
                queue.append((neighbour, depth + 1))
    
    return -1  # unreachable


# ============================================================
# BACKTRACKING: Combination sum
# Use when: all solutions required, constraint satisfaction, 
#           memory matters more than order of solutions
# Time: O(2^N * N) upper bound, much less with pruning
# Space: O(target / min(candidates)) for call depth
# ============================================================
def combination_sum(candidates: list[int], target: int) -> list[list[int]]:
    """
    Find all unique combinations of candidates summing to target.
    Each candidate may be used unlimited times.
    
    Pruning condition: if running_sum > target at any node, 
    prune the entire subtree (all deeper sums are larger).
    This converts an infinite recursion into a bounded tree.
    """
    results: list[list[int]] = []
    candidates.sort()  # enables early pruning: stop when candidate > remaining
    
    def backtrack(start: int, current: list[int], remaining: int) -> None:
        if remaining == 0:
            results.append(current[:])  # copy, not reference
            return
        
        for i in range(start, len(candidates)):
            c = candidates[i]
            # PRUNE: sorted list means all subsequent candidates also exceed remaining
            if c > remaining:
                break
            current.append(c)               # choose
            backtrack(i, current, remaining - c)  # explore (i, not i+1: reuse allowed)
            current.pop()                   # unchoose
    
    backtrack(0, [], target)
    return results


# ============================================================
# BEAM SEARCH: The ML middle ground
# k=1 → greedy DFS; k=inf → BFS; k=5 → typical NLP decoder
# Time: O(k * b * d) where b = vocab size, d = output length
# Space: O(k * d) — only top-k sequences at each depth
# ============================================================
def beam_search_decode(
    score_fn,          # score_fn(sequences) -> scores for next tokens
    vocab_size: int,
    max_len: int,
    beam_width: int = 5,
    eos_token: int = 0
) -> list[int]:
    """
    Beam search: BFS with bounded frontier width.
    
    Why this exists in ML: 
    - BFS (beam_width=inf): too much memory for large vocab
    - Greedy DFS (beam_width=1): locally optimal, globally suboptimal
    - Beam search: practical compromise used in all seq2seq models
    
    The connection to backtracking: beam search does NOT backtrack —
    it is still BFS with pruning of the frontier. True backtracking
    would be used if you needed to enumerate all valid sequences.
    """
    # Each beam: (cumulative_log_prob, token_sequence)
    beams: list[tuple[float, list[int]]] = [(0.0, [])]
    completed: list[tuple[float, list[int]]] = []
    
    for _ in range(max_len):
        candidates: list[tuple[float, list[int]]] = []
        
        for log_prob, seq in beams:
            if seq and seq[-1] == eos_token:
                completed.append((log_prob, seq))
                continue
            
            # Expand: score all next tokens
            next_scores = score_fn([seq])  # shape: [vocab_size]
            
            # Keep only top beam_width extensions
            top_k = sorted(enumerate(next_scores), key=lambda x: -x[1])[:beam_width]
            for token_id, token_score in top_k:
                candidates.append((log_prob + token_score, seq + [token_id]))
        
        # Prune: retain only top beam_width candidates (BFS width bound)
        beams = sorted(candidates, key=lambda x: -x[0])[:beam_width]
        
        if not beams:
            break
    
    all_results = completed + beams
    best = max(all_results, key=lambda x: x[0])
    return best[1]


# ============================================================
# Test
# ============================================================
if __name__ == "__main__":
    # BFS shortest path
    graph = {1: [2, 3], 2: [4], 3: [4, 5], 4: [6], 5: [6], 6: []}
    print(f"BFS 1→6: {bfs_shortest_path(graph, 1, 6)} hops")   # 3

    # Backtracking combination sum
    result = combination_sum([2, 3, 6, 7], 7)
    print(f"Combination sum to 7: {result}")  # [[2,2,3],[7]]
    
    result2 = combination_sum([2, 3, 5], 8)
    print(f"Combination sum to 8: {result2}")  # [[2,2,2,2],[2,3,3],[3,5]]
```

## 7. Common Variations & Extensions

**Iterative Deepening DFS (IDDFS):** Runs DFS with a depth limit _d_, then DFS with limit _d+1_, and so on. Achieves BFS's optimal-path guarantee with DFS's O(d) memory. The overhead is revisiting nodes at each iteration, but since most nodes are at the deepest level, the total work is only ~b/(b-1) × BFS work. See [[113. BFS]] for when IDDFS is better than BFS.

**Branch and Bound:** Backtracking augmented with a _bounding function_ that computes an upper/lower bound on the best possible completion of a partial solution. If the bound is worse than the current best known solution, prune. This is the industrial-strength version used in integer programming solvers (Gurobi, CPLEX) and is the theoretical underpinning of A*. Ties directly to [[80. Pruning strategies — forward checking, bounding functions]].

**Bidirectional BFS:** Run BFS simultaneously from start and goal. When the frontiers meet, the shortest path is found. Reduces space from O(b^d) to O(b^(d/2)) — a dramatic improvement for large graphs. Used in route planning (Google Maps) and knowledge graph traversal. Backtracking has no natural bidirectional analog since it is constraint-driven, not path-length-driven.

**Monte Carlo Tree Search (MCTS):** Combines backtracking-style tree exploration with random rollouts to estimate the value of unexplored subtrees. The famous AlphaGo/AlphaZero systems use MCTS, which is essentially adaptive backtracking guided by a neural network heuristic. The branching factor of Go is ~250; BFS is completely infeasible; pure backtracking is too slow; MCTS with neural pruning makes it tractable. This is the most important ML generalisation of this note's core idea.

## 9. CP Contest Application

**Typical Codeforces / AtCoder problem structure:**

Problems with the phrase "find any valid assignment" or "list all valid configurations" with N ≤ 20 are backtracking. Problems with "minimum number of operations" or "shortest path between states" with a describable state space are BFS. A frequent CF pattern: a grid where you can move between states with custom transitions and need the minimum transitions to reach the target — this is always BFS on the implicit state graph, not DFS.

**Specific patterns and limits:**

- Backtracking problems on CF typically have N ≤ 15 for O(2^N) solutions, N ≤ 20 with tight pruning.
- BFS state-space problems: up to ~10^6 states comfortably within 256MB memory.
- If the state space is too large for BFS but the solution depth is known, IDDFS is the bridge.
- `std::bitset` can compress backtracking state (e.g., which cells are visited) to improve cache performance — important when N is around 20 and constant factors matter.

**Template for "is state reachable in k steps?" questions:**

```cpp
// Always BFS, not backtracking
// Encode state as integer / string / tuple for the visited set
unordered_set<State> visited;
queue<pair<State, int>> q;
q.push({initial_state, 0});
while (!q.empty()) {
    auto [state, depth] = q.front(); q.pop();
    if (state == target) return depth;
    for (auto next : transitions(state))
        if (!visited.count(next)) { visited.insert(next); q.push({next, depth+1}); }
}
```

**Template for "find all valid assignments" questions:**

```cpp
// Always backtracking with pruning
void bt(State& partial, vector<State>& results) {
    if (is_complete(partial)) { results.push_back(partial); return; }
    for (auto choice : choices(partial)) {
        if (!is_valid(partial, choice)) continue; // PRUNE
        apply(partial, choice);
        bt(partial, results);
        undo(partial, choice);
    }
}
```

Knowing which template to reach for in the first 30 seconds of reading a problem is the contest skill this note builds.

---

_Commentary:_ The deepest insight here is not algorithmic but _epistemic_: BFS and backtracking answer **different questions**. BFS answers "what is the minimum cost to reach a goal?" Backtracking answers "what solutions satisfy all constraints?" Conflating these two questions — the most common mistake — leads to either wrong answers (DFS on shortest-path problems) or memory explosions (BFS on constraint satisfaction). The moment you can read a problem statement and immediately classify it into one of these two regimes, you have internalised this note.

The ML connection runs deeper than it looks: every modern neural network training loop is an implicit compromise between these two extremes. Gradient descent is greedy DFS (follow the steepest local direction). Learning rate schedules, adaptive optimisers, and early stopping are all forms of pruning. Beam search in generation and MCTS in game playing are the engineered middle grounds. The combinatorial substrate is always there.
