## 1. Intuition First

### The Core Idea

You are looking for a name in a physical dictionary. You do not start at page one and read forward. You open the book near the middle. If the name you want comes alphabetically _before_ what you see, you throw away the right half and repeat in the left half. If it comes _after_, you throw away the left half and repeat in the right half. You halve the search space with every single page-open, and you reach your target in O(log n) steps rather than O(n).

Binary search is this dictionary strategy formalised. Given a sorted array and a target value, it works by maintaining a live search window `[lo, hi]` and repeatedly computing the midpoint `mid = (lo + hi) / 2`. Three outcomes are possible at each step:

- `arr[mid] == target` → found, return `mid`
- `arr[mid] < target` → target must be in the right half, so `lo = mid + 1`
- `arr[mid] > target` → target must be in the left half, so `hi = mid - 1`

When `lo > hi`, the window is empty and the target does not exist.

The correctness relies on one invariant: **if the target exists in the array, it always lies within `[lo, hi]`**. Every update preserves this invariant. When the window collapses, the invariant can no longer be maintained, which means the target is absent.

### Why This Exists

Linear scan — checking every element from left to right — finds a target in O(n) time. For n = 10⁹ elements, that is roughly 10⁹ comparisons. Binary search does log₂(10⁹) ≈ 30 comparisons. The gap between O(n) and O(log n) is qualitative, not just quantitative: it separates "infeasible in practice" from "instant."

The reason binary search can do this is **sortedness**. A sorted array gives you monotone structure: for any index i, all elements left of i are ≤ arr[i] and all elements right of i are ≥ arr[i]. This monotonicity lets a single comparison eliminate half the remaining candidates with certainty. Without sortedness, you cannot safely discard half the array — the target could be anywhere.

This is why sorting is often a preprocessing investment. A dataset sorted once pays off every subsequent search. For k searches over n elements, sorting + binary search costs O(n log n + k log n), which beats linear scan's O(kn) for any k ≥ 2 when n is large.

### The "Aha" Moment

Binary search is not fundamentally about sorted arrays. It is about **monotone predicates**. A sorted array happens to make the predicate "is the target to the right of this position?" monotone: false, false, false, ..., true, true, true. Binary search finds the boundary between the false region and the true region.

This generalisation — **binary search on answer** — is what makes the technique powerful far beyond "find a value in a sorted array." Every time you can express a problem as "find the smallest x such that P(x) is true" where P is monotone, binary search applies. The exact-match problem is the simplest instance. [[59.The binary search on answer template — monotonic predicate]] generalises this to arbitrary monotone predicates over continuous or discrete domains.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Binary search on a sorted array is the building block for nearly every search operation in CP. It appears:

- Directly: "given sorted array, find index of target" — O(log n) lookup
- As a subroutine: in Dijkstra (sorted edge relaxation), LIS (patience sorting), segment tree queries, and merge sort
- As the pattern seed: every binary-search-on-answer problem is this algorithm with a custom predicate

**The pattern signal:**

> "Sorted array + query for a specific value or position" → binary search immediately "Is it possible to achieve X?" where X varies monotonically → binary search on answer (see [[59.The binary search on answer template — monotonic predicate]]) Time limit is tight and naive O(n) per query is too slow → consider sorting + binary search

**Common traps that kill submissions:**

1. **Integer overflow in midpoint computation.** `mid = (lo + hi) / 2` overflows when `lo + hi > INT_MAX`. The safe formula is `mid = lo + (hi - lo) / 2`. This is the single most common binary search bug in C++ CP.
    
2. **Infinite loop from wrong boundary update.** If you ever write `lo = mid` instead of `lo = mid + 1`, the window may never shrink (when `lo == hi - 1`, `mid = lo`, and `lo = mid = lo` loops forever). Rule: for exact match, always use `lo = mid + 1` and `hi = mid - 1`.
    
3. **Off-by-one in the return condition.** After the loop exits with `lo > hi`, you must check whether `arr[mid]` (or `arr[lo]` if you track it separately) actually equals the target. It is easy to accidentally return the last `mid` value even when the target is not present.
    
4. **Applying binary search to an unsorted array.** Sounds obvious, but under contest pressure, forgetting to sort before searching is a real mistake. Always verify sortedness as a precondition.
    

### Machine Learning / AI

Binary search on a sorted array is the conceptual prototype for a family of O(log n) lookup patterns that appear throughout ML systems:

**1. Embedding lookup and vocabulary indexing** When a tokeniser maps a string token to an integer ID, the underlying data structure is often a sorted vocabulary list with binary search for the mapping. In Hugging Face `tokenizers`, the vocabulary is stored as a sorted trie or sorted array, and token-to-ID lookup uses binary search. For a vocabulary of 50,257 tokens (GPT-2), each lookup is 16 comparisons instead of 50,257. At tokenisation throughput of 10⁶ tokens/second, this is the difference between lookup being negligible and being a bottleneck.

**2. Discretisation and bin lookup in gradient boosting** LightGBM and XGBoost discretise continuous features into integer bin indices during training. At inference, for each new sample and each feature, the model must find which bin the feature value falls into. This is a binary search on the sorted bin boundary array — O(log num_bins) per feature per sample. For `num_bins = 256` and `num_features = 1000`, each prediction requires up to 1000 × 8 = 8000 comparisons. The `std::lower_bound` call in the C++ inference kernel is this binary search.

**3. Sorted replay buffers in reinforcement learning (prioritised experience replay)** Prioritised experience replay (PER, Schaul et al., 2015) maintains a sorted structure of experience priorities so that high-priority transitions are sampled more frequently. When sampling a transition, the algorithm binary searches the cumulative priority array to find the transition corresponding to a random draw. `np.searchsorted` — Python's binary search on a sorted array — is the exact function used in PER implementations. See [[185.Bellman equation in RL — DP as the foundation of Q-learning]].

**4. Monotone function inversion — the generalisation** Any time you have a monotonically increasing function f and want to find x such that f(x) = target, you are doing binary search on the real line. The `scipy.optimize.brentq` root-finder, learning rate schedulers that find the epoch at which loss crosses a threshold, calibration search for classification thresholds — all are binary search in disguise. [[63.Threshold optimisation — binary search on decision boundary]] and [[64.Bisection method for root finding — numerical analysis connection]] develop this connection in full.

**5. `np.searchsorted` — the production NumPy function**

```python
arr = np.array([1, 3, 5, 7, 9])
np.searchsorted(arr, 5)    # → 2  (index where 5 would be inserted to keep sorted)
np.searchsorted(arr, 6)    # → 3  (6 would go between index 2 and 3)
```

`np.searchsorted` is binary search on a sorted NumPy array. It is called in histogram binning (`np.digitize`), quantile computation, and anywhere you need to locate a value in a sorted array. Understanding its O(log n) cost and exact-vs-insertion semantics is essential ML engineering knowledge.

## 3. Algorithm / Pattern

### Step-by-Step Logic

**Precondition:** Array `arr` is sorted in non-decreasing order.

1. Initialise `lo = 0`, `hi = n - 1`.
2. While `lo <= hi`: a. Compute `mid = lo + (hi - lo) / 2` (safe midpoint, no overflow). b. If `arr[mid] == target`: return `mid`. c. If `arr[mid] < target`: `lo = mid + 1` (target is to the right). d. If `arr[mid] > target`: `hi = mid - 1` (target is to the left).
3. If the loop exits: return `-1` (target not found).

### Invariant Maintenance

At every iteration, the invariant is: _if `target` is in `arr`, then `target` is in `arr[lo..hi]`._

- Initialisation: trivially true — the whole array is `[lo, hi]`.
- Step c: `arr[mid] < target` means target cannot be at index ≤ mid (all those elements are ≤ arr[mid] < target by sortedness). Setting `lo = mid + 1` preserves the invariant.
- Step d: Symmetric argument.
- Termination: `lo > hi` means the window is empty. The invariant implies target is not in `arr`.

### Complexity

**Time:** O(log n) — each iteration halves the window. Starting with n elements, after k iterations the window has at most n/2ᵏ elements. The loop terminates when n/2ᵏ < 1, i.e., k > log₂ n. So at most ⌈log₂(n + 1)⌉ iterations.

**Space:** O(1) — only three integer variables (`lo`, `hi`, `mid`). No recursion, no auxiliary arrays.

### When to Use vs. Avoid

|Use|Avoid|
|---|---|
|Array is sorted|Array is unsorted (sort first, or use hash map)|
|Exact match query on large arrays|Very small arrays (n ≤ 8): linear scan is comparable and simpler)|
|Multiple queries on the same sorted data|Single query: sort cost O(n log n) dominates|
|Need O(log n) per query|Need index of _all_ occurrences → use `lower_bound` + `upper_bound`|

## 4. Pseudocode

```
BINARY_SEARCH(arr, n, target):
    """
    Find the index of target in sorted array arr[0..n-1].
    Returns the index if found, -1 otherwise.
    """
    lo ← 0
    hi ← n - 1

    while lo <= hi:
        // Safe midpoint: avoids integer overflow (lo + hi may overflow)
        mid ← lo + (hi - lo) / 2

        if arr[mid] == target:
            return mid              // Exact match found

        else if arr[mid] < target:
            lo ← mid + 1           // Target is in the right half
                                   // Everything arr[lo..mid] < target — discard

        else:                      // arr[mid] > target
            hi ← mid - 1          // Target is in the left half
                                   // Everything arr[mid..hi] > target — discard

    // Loop exits when lo > hi: search window is empty
    return -1                      // Target not present in arr
```

**Recursive variant** (pedagogically useful, not recommended for production due to call stack overhead):

```
BINARY_SEARCH_RECURSIVE(arr, lo, hi, target):
    if lo > hi:
        return -1                  // Base case: empty window

    mid ← lo + (hi - lo) / 2

    if arr[mid] == target:
        return mid
    else if arr[mid] < target:
        return BINARY_SEARCH_RECURSIVE(arr, mid + 1, hi, target)
    else:
        return BINARY_SEARCH_RECURSIVE(arr, lo, mid - 1, target)
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <vector>
#include <optional>
#include <algorithm>   // std::binary_search, std::lower_bound

/**
 * Binary search: find the index of target in a sorted array.
 *
 * Returns the index of target if found, -1 otherwise.
 * If there are duplicates, returns the index of ONE occurrence (not
 * necessarily the first or last). Use lower_bound / upper_bound for
 * first/last occurrence. See note 56.
 *
 * Precondition: arr is sorted in non-decreasing order.
 *
 * Time:  O(log n)
 * Space: O(1)
 */
int binarySearch(const std::vector<int>& arr, int target) {
    int lo = 0;
    int hi = static_cast<int>(arr.size()) - 1;

    while (lo <= hi) {
        // Safe midpoint: lo + (hi - lo) / 2 avoids overflow
        // when lo and hi are both near INT_MAX
        int mid = lo + (hi - lo) / 2;

        if (arr[mid] == target) {
            return mid;           // Found
        } else if (arr[mid] < target) {
            lo = mid + 1;         // Target is to the right
        } else {
            hi = mid - 1;         // Target is to the left
        }
    }

    return -1;                    // Not found
}

/**
 * Binary search returning std::optional<int> — more idiomatic C++17.
 * Conveys intent: the return value may not exist.
 */
std::optional<int> binarySearchOpt(const std::vector<int>& arr, int target) {
    int lo = 0, hi = static_cast<int>(arr.size()) - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if      (arr[mid] == target) return mid;
        else if (arr[mid] <  target) lo = mid + 1;
        else                         hi = mid - 1;
    }
    return std::nullopt;
}

/**
 * Using the standard library — prefer this in production CP code.
 *
 * std::binary_search: returns bool (found or not) — O(log n)
 * std::lower_bound:   returns iterator to first element >= target — O(log n)
 *                     Use this to get the index.
 */
int binarySearchSTL(const std::vector<int>& arr, int target) {
    auto it = std::lower_bound(arr.begin(), arr.end(), target);
    // lower_bound gives the first element >= target.
    // It is the target iff: it != end AND *it == target.
    if (it != arr.end() && *it == target) {
        return static_cast<int>(it - arr.begin());
    }
    return -1;
}

/**
 * Generic template version: works for any sorted container and type
 * that supports operator< and operator==.
 */
template<typename T>
int binarySearchGeneric(const std::vector<T>& arr, const T& target) {
    int lo = 0, hi = static_cast<int>(arr.size()) - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if      (arr[mid] == target) return mid;
        else if (arr[mid] <  target) lo = mid + 1;
        else                         hi = mid - 1;
    }
    return -1;
}
```

### Python (Readable + Pythonic)

```python
import bisect
from typing import Optional


def binary_search(arr: list[int], target: int) -> int:
    """
    Find the index of target in a sorted array.
    Returns the index if found, -1 if not present.

    Note: If duplicates exist, returns ONE valid index (not necessarily
    the first or last). Use bisect_left / bisect_right for boundary queries.

    Precondition: arr is sorted in non-decreasing order.

    Time:  O(log n)
    Space: O(1)
    """
    lo, hi = 0, len(arr) - 1

    while lo <= hi:
        # Python integers don't overflow, but this form is good habit
        mid = lo + (hi - lo) // 2

        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1    # target is to the right; arr[lo..mid] all < target
        else:
            hi = mid - 1    # target is to the left;  arr[mid..hi] all > target

    return -1   # target not in arr


def binary_search_stdlib(arr: list[int], target: int) -> int:
    """
    Binary search using Python's bisect module — prefer this in production.

    bisect_left(arr, target) returns the leftmost index where target
    could be inserted to keep arr sorted. If arr[index] == target,
    then target is present at that index.

    Time:  O(log n)
    Space: O(1)
    """
    idx = bisect.bisect_left(arr, target)
    if idx < len(arr) and arr[idx] == target:
        return idx
    return -1


def binary_search_recursive(arr: list[int], target: int,
                             lo: int = 0, hi: int = -1) -> int:
    """
    Recursive binary search — for pedagogical clarity.
    Not recommended for production: Python has a default recursion
    limit of 1000, and this has O(log n) call overhead vs O(1) iterative.

    Time:  O(log n)
    Space: O(log n) — call stack depth
    """
    if hi == -1:            # first call: set hi to last index
        hi = len(arr) - 1

    if lo > hi:             # base case: empty search window
        return -1

    mid = lo + (hi - lo) // 2

    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search_recursive(arr, target, mid + 1, hi)
    else:
        return binary_search_recursive(arr, target, lo, mid - 1)


# --- Demo and edge cases ---
if __name__ == "__main__":
    arr = [1, 3, 5, 7, 9, 11, 13]

    # Standard cases
    assert binary_search(arr, 1)  == 0,  "first element"
    assert binary_search(arr, 13) == 6,  "last element"
    assert binary_search(arr, 7)  == 3,  "middle"
    assert binary_search(arr, 4)  == -1, "between elements"
    assert binary_search(arr, 0)  == -1, "before first"
    assert binary_search(arr, 14) == -1, "after last"

    # Edge cases
    assert binary_search([42], 42) == 0,  "single element, found"
    assert binary_search([42], 43) == -1, "single element, not found"
    assert binary_search([], 1)    == -1, "empty array"

    # With duplicates — returns ONE valid index, not guaranteed first/last
    dup = [1, 2, 2, 2, 3]
    result = binary_search(dup, 2)
    assert dup[result] == 2, "duplicate: found some occurrence"

    # Stdlib version
    assert binary_search_stdlib(arr, 7)  == 3
    assert binary_search_stdlib(arr, 4)  == -1

    # np.searchsorted equivalent
    import numpy as np
    np_arr = np.array(arr)
    idx = np.searchsorted(np_arr, 7)          # → 3
    found = idx < len(np_arr) and np_arr[idx] == 7
    assert found and idx == 3

    print("All tests passed.")
```

## 7. Common Variations & Extensions

### 7.1 First and Last Occurrence (When Duplicates Exist)

Exact-match binary search with duplicates returns _an_ occurrence, not necessarily the first or last. When you need boundaries, use `lower_bound` (first index where `arr[i] >= target`) and `upper_bound` (first index where `arr[i] > target`). This is developed fully in [[56.lower_bound and upper_bound — first and last occurrence]].

```python
# Count occurrences of target in sorted arr — O(log n)
left  = bisect.bisect_left(arr, target)   # first occurrence index
right = bisect.bisect_right(arr, target)  # one past last occurrence
count = right - left                      # O(1) after O(log n) setup
```

### 7.2 Search in Rotated Sorted Array

When a sorted array has been rotated (e.g., `[4, 5, 6, 7, 0, 1, 2]`), the sortedness invariant is broken globally but holds locally in each half. Binary search still works with a modified condition to determine which half is sorted. See [[57.Binary search on rotated sorted array]].

### 7.3 Binary Search on 2D Matrix

A row-major sorted matrix (each row sorted, first element of each row > last element of previous row) can be treated as a flattened 1D sorted array. Binary search on the virtual index, converting to `(row, col)` via division and modulo. See [[58.Binary search on 2D matrix]].

### 7.4 Binary Search on Floating-Point Domain

When searching for a real-valued x satisfying f(x) = target with f monotone, the same logic applies with a termination condition based on precision rather than window size. Terminate when `hi - lo < epsilon`. See [[64.Bisection method for root finding — numerical analysis connection]].

```python
def bisection(f, lo: float, hi: float, target: float,
              eps: float = 1e-9) -> float:
    """Find x in [lo, hi] such that f(x) ≈ target. f must be monotone."""
    while hi - lo > eps:
        mid = (lo + hi) / 2.0
        if f(mid) < target:
            lo = mid
        else:
            hi = mid
    return (lo + hi) / 2.0
```

### 7.5 `np.searchsorted` — vectorised binary search

For production ML code with NumPy arrays, `np.searchsorted` is the tool:

```python
import numpy as np

arr = np.array([1, 3, 5, 7, 9])

# Scalar query — O(log n)
np.searchsorted(arr, 5)          # → 2

# Batch queries — O(m log n) for m query values
queries = np.array([0, 3, 6, 10])
np.searchsorted(arr, queries)    # → [0, 1, 3, 5]
# result[i] = index where queries[i] would be inserted to keep sorted

# Exact-match check from searchsorted result
def np_binary_search(arr: np.ndarray, target: int) -> int:
    idx = np.searchsorted(arr, target)
    if idx < len(arr) and arr[idx] == target:
        return int(idx)
    return -1
```

`np.searchsorted` on a sorted array of 10⁶ elements runs in ~1μs per scalar query — the O(log n) advantage is fully realised in hardware.

## 9. CP Contest Application

### Identifying Binary Search Opportunities

In contest problems, binary search on a sorted array appears in two modes:

**Mode 1 — Explicit sorted array:** The problem gives you a sorted array or asks you to sort and search. Recognise: "given n sorted values, for each query find..." → `std::lower_bound` or `std::upper_bound` in C++, `bisect` in Python.

**Mode 2 — Implicit sorted structure:** The search domain is implicitly sorted (integers from 0 to 10⁹, times from 0 to T, real values). The problem reduces to: "find the smallest x such that condition(x) is true." This is binary search on answer — [[59.The binary search on answer template — monotonic predicate]] — and it is one of the highest-frequency patterns at Codeforces Div. 2 C/D level.

### Time Complexity in Context

```
Problem: n ≤ 10^5 elements, q ≤ 10^5 queries, 1-second time limit

Naive (linear scan per query):  O(n × q) = O(10^10) → TLE (needs ~10s)
Sort + binary search:           O(n log n + q log n)
                               = O(10^5 × 17 + 10^5 × 17)
                               = O(3.4 × 10^6) → AC (needs ~3ms)
```

### The Three C++ STL Functions to Know

```cpp
#include <algorithm>

std::vector<int> arr = {1, 3, 5, 5, 5, 7, 9};

// 1. binary_search: returns bool — just tells you if target exists
bool found = std::binary_search(arr.begin(), arr.end(), 5);  // true

// 2. lower_bound: iterator to FIRST element >= target
auto lo = std::lower_bound(arr.begin(), arr.end(), 5);
int lo_idx = lo - arr.begin();   // 2 (arr[2] = 5, first 5)

// 3. upper_bound: iterator to FIRST element > target
auto hi = std::upper_bound(arr.begin(), arr.end(), 5);
int hi_idx = hi - arr.begin();   // 5 (arr[5] = 7, first element > 5)

// Count occurrences: upper_bound - lower_bound
int count = hi_idx - lo_idx;     // 3 (three 5s at indices 2, 3, 4)

// Get index from iterator (pattern you'll use constantly in CP):
int idx = std::lower_bound(arr.begin(), arr.end(), 5) - arr.begin();
```

These three functions cover every binary search need on a sorted array in CP. Memorise them. The key distinction: `binary_search` gives only existence, `lower_bound` gives the first position (insertion point from the left), `upper_bound` gives one past the last position (insertion point from the right).
