## 1. Intuition First

### The Core Idea

Deduplication is the act of answering one question, repeated n times: _"Have I seen this before?"_

The naive answer is to keep a sorted list and binary-search it — O(log n) per query, O(n log n) total. A better naive answer is to sort the entire collection once and scan for adjacent duplicates — O(n log n) total, O(1) per check, but requires seeing all data first. Neither works when data arrives as a stream, when n is in the billions, or when you need the answer _at insertion time_.

A HashSet collapses the question to O(1) amortised. You hash the incoming item, probe the table, and either find it already there (duplicate — discard) or not (new — insert and pass through). The entire deduplication pipeline is a single pass: O(n) time, O(d) space where d is the number of _distinct_ elements, not total elements.

**The analogy:** Imagine a nightclub bouncer with a guest list written on index cards, sorted alphabetically. Every arriving guest requires a binary search through the cards — slow. Now replace the cards with a hash-indexed binder: the bouncer flips directly to the hash slot and checks one entry. That's a HashSet. The binder doesn't need to be fully sorted; it just needs fast addressing.

### Why This Exists

The gap deduplication fills is not merely algorithmic — it's _architectural_. In ML pipelines:

- **Training data leaks** between train and test sets are a form of duplication failure. A model trained on data that appears in the test set reports inflated metrics — this is a real-world disaster.
- **Web-scale corpora** (Common Crawl, LAION-5B, The Pile) contain massive redundancy — estimated 30–70% duplicate or near-duplicate documents. Training on duplicates wastes compute, biases frequency distributions, and causes models to memorise rather than generalise.
- **Feature stores** accumulate records from multiple upstream systems; duplicate rows silently corrupt aggregations, counts, and join cardinalities.

Sorting-based dedup is O(n log n) and requires the full dataset in memory. HashSet-based dedup is O(n) and streaming. For a 10B-row dataset, the difference is the gap between _possible_ and _impossible_.

### The "Aha" Moment

> _"Deduplication is just membership testing, and membership testing on a set is O(1). The only question is what you're hashing: the raw item, a fingerprint of it, or a sketch of it."_

Once you see it this way, the generalisation is obvious: exact dedup hashes the full item; near-dedup (MinHash, SimHash) hashes a _sketch_ of the item. The algorithmic core is identical. Only the hash function changes.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

Deduplication in CP is rarely the _problem_ — it's the _prerequisite_. You need it to:

- **Remove duplicates before two-sum / k-sum:** When the problem asks for unique pairs or tuples, insert all elements into an `unordered_set` first, or use the sort-and-unique approach.
- **Visit tracking in BFS/DFS:** The `visited` set in [[112.Depth-First Search (DFS) — recursive and iterative]] and [[113.Breadth-First Search (BFS) — level-order, shortest path in unweighted graph]] is deduplication — mark a node as seen so you never process it twice.
- **Dedup intermediate results:** In backtracking (e.g., [[78.N-Queens — the canonical backtracking problem]]), you often insert partial states into a set to avoid reprocessing equivalent branches.

**Pattern signal:**

```
"Process each unique X exactly once"  →  HashSet for visited/seen tracking
"Remove duplicate results"            →  Insert into set, convert back to vector
"Count distinct elements"             →  HashSet cardinality
```

**Common traps:**

1. Using `unordered_set<vector<int>>` — vectors are not hashable by default in C++. You must either sort + stringify, or use a custom hash. Python's `set` has the same restriction for lists (use `tuple`).
2. Deduplicating floats with a HashSet — float equality is unreliable. Hash floats only if you understand the representation. See [[106.Floating point bit representation — IEEE 754 intuition]].
3. Forgetting that `set` in C++ is O(log n) per operation, not O(1). Use `unordered_set` when you need O(1).

### Machine Learning / AI

This is where the note earns its `[T1]` classification. HashMap-based deduplication is not a footnote in ML engineering — it is infrastructure.

**Exact Deduplication in Dataset Preprocessing:**

The standard pipeline for web-crawled text (e.g., C4, RefinedWeb, Dolma) applies exact dedup using SHA-256 or MurmurHash3 fingerprints:

1. Compute a hash of each document (or paragraph, or n-gram shingle).
2. Insert into a HashSet.
3. Discard any document whose hash is already present.

This is O(n) over the dataset size, streaming-compatible, and parallelisable across shards (compute hashes independently, merge HashSets). The LLM Datasheet paper (2023) and the C4 preprocessing pipeline (used for T5) both apply this step before near-dedup.

**Vocabulary Construction in Tokenisers:**

When building a BPE (Byte-Pair Encoding) vocabulary — as used in GPT-2, LLaMA, Mistral — the first step is counting unique token frequencies over the corpus. This is a HashMap from token → count. Every token in every document is hashed and its count incremented. For a 1T-token corpus, this requires a streaming count-min sketch or a distributed HashMap (e.g., via Apache Beam or Spark's `groupByKey`).

**Embedding Deduplication in Vector Databases:**

Systems like FAISS, Pinecone, and Weaviate store vectors indexed by a string ID. When ingesting documents, exact-dedup on the document ID (via a HashMap) prevents inserting the same vector twice, which would corrupt nearest-neighbour queries by artificially inflating the density around duplicated points.

**Feature Store Deduplication:**

In online feature stores (Feast, Tecton, Hopsworks), each feature row is keyed by `(entity_id, timestamp)`. A HashMap from this composite key to feature values ensures that late-arriving duplicate events (common in Kafka-based pipelines) don't overwrite correct values. This is the _upsert_ pattern: `if key in map: skip else: insert`.

**Why understanding this makes you a better ML engineer:**

When you know the HashMap is doing O(1) amortised work per item, you stop reaching for Pandas `drop_duplicates()` (which sorts under the hood — O(n log n)) on 100M-row DataFrames. You instead use:

```python
seen = set()
filtered = [x for x in stream if not (x in seen or seen.add(x))]
```

or Polars' `unique()` which uses a hash-based approach. For distributed data, you think in terms of hash-partitioning: route all records with the same hash to the same worker, and each worker deduplicates its partition independently — MapReduce's `reduceByKey` does exactly this.

## 3. Algorithm / Pattern

### Exact Deduplication (Streaming)

1. Initialise empty HashSet `seen`.
2. For each incoming item `x`: a. Compute `h = hash(x)` — this is implicit in `seen.add(x)`. b. If `x in seen`: discard (duplicate). c. Else: `seen.add(x)`, emit `x` (new unique item).
3. Total: one pass, O(n) time, O(d) space (d = distinct count).

### Dedup with Frequency Counting

When you need to know _how many times_ each item appeared (not just whether it's a duplicate):

1. Use a HashMap `freq: item → count`.
2. For each item `x`: `freq[x] += 1` (default 0 if absent).
3. Items with `freq[x] == 1` appeared once (unique). Items with `freq[x] > 1` are duplicates.

This pattern appears in [[21.HashMap frequency counting — arbitrary keys]] and is the foundation of the vocabulary construction step in tokenisers.

### Content-Addressed Dedup (Fingerprinting)

For large objects (documents, images, audio files), hashing the full content is expensive if done naively. Use a **content fingerprint** instead:

1. Apply a fast non-cryptographic hash (MurmurHash3, xxHash, FNV-1a) to the serialised content.
2. Store fingerprint → item in a HashMap.
3. On collision: either trust the fingerprint (probabilistic) or do a full content comparison to confirm (deterministic).

For ML datasets, the probabilistic approach with a 128-bit hash has a collision probability of 1/2¹²⁸ — negligibly small for any realistic dataset size.

### Decision Tree

```
Do you need exact dedup?
├── Items are small (strings, ints, tuples)
│   └── HashSet on raw item  →  O(1) per item
├── Items are large (documents, arrays, images)
│   └── Hash to fingerprint first, HashSet on fingerprint
│       └── On hash collision: full equality check as fallback
└── Items arrive as a stream of unknown length?
    └── Same HashSet approach — streaming is natural for HashSets

Do you need near-dedup (similar but not identical)?
└── Use MinHash + LSH  →  [[39.MinHash — estimating Jaccard similarity at scale]]
    └── Exact dedup as a preprocessing step before near-dedup
```

### Complexity

|Operation|HashSet|Sorted Array|BST (std::set)|
|---|---|---|---|
|Insert|O(1) amortised|O(n)|O(log n)|
|Lookup|O(1) amortised|O(log n)|O(log n)|
|Full dedup pass|O(n)|O(n log n)|O(n log n)|
|Space|O(d)|O(n)|O(n)|
|Streaming-compatible|✓|✗|✓ but slower|

d = number of distinct elements ≤ n.

**Worst case caveat:** With a bad hash function or adversarial inputs, all n items land in the same bucket — O(n) per lookup, O(n²) total. This is why [[31.Hash function design — properties, uniformity, avalanche]] matters in practice and why CP solutions need the splitmix64 anti-hack hash. For ML pipelines, use MurmurHash3 or xxHash — both have strong avalanche properties and are collision-resistant against natural data distributions.

## 4. Pseudocode

```
// ─── STREAMING EXACT DEDUPLICATION ──────────────────────────────────────────
function dedup_stream(stream):
    seen ← empty HashSet          // stores hashes or items directly

    for each item x in stream:
        if x in seen:
            continue              // duplicate — discard
        seen.add(x)
        emit x                    // unique — pass through to output


// ─── DEDUP WITH FREQUENCY COUNTING ──────────────────────────────────────────
function count_and_dedup(items):
    freq ← empty HashMap          // item → count

    for each item x in items:
        freq[x] ← freq.get(x, 0) + 1

    // Return items that appeared more than once, with counts
    duplicates ← [(x, freq[x]) for x in freq if freq[x] > 1]
    unique     ← [x for x in freq if freq[x] == 1]
    return unique, duplicates


// ─── FINGERPRINT-BASED DEDUP (for large objects) ────────────────────────────
function fingerprint_dedup(documents):
    seen_fingerprints ← empty HashSet
    output ← []

    for each doc in documents:
        fp ← murmurhash3_128(serialise(doc))   // fast 128-bit fingerprint

        if fp in seen_fingerprints:
            continue                            // probable duplicate

        seen_fingerprints.add(fp)
        output.append(doc)

    return output


// ─── UPSERT PATTERN (feature store / database style) ────────────────────────
function upsert(store, key, value):
    // Insert if absent, update if present
    if key in store:
        // Policy decision: keep first, keep last, or merge
        store[key] ← merge(store[key], value)   // or: skip (keep-first)
    else:
        store[key] ← value
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <algorithm>
#include <cstdint>
#include <functional>
#include <iostream>
#include <span>
#include <string>
#include <string_view>
#include <unordered_map>
#include <unordered_set>
#include <vector>

// ─── BASIC STREAMING DEDUP ────────────────────────────────────────────────────
// Returns deduplicated vector preserving first-occurrence order.
// Time: O(n)  Space: O(d) where d = distinct count
template <typename T>
std::vector<T> dedup_preserve_order(const std::vector<T>& items) {
    std::unordered_set<T> seen;
    seen.reserve(items.size());          // avoid rehashing mid-insert

    std::vector<T> result;
    result.reserve(items.size());        // upper bound

    for (const auto& x : items) {
        if (seen.insert(x).second) {     // insert() returns {iterator, bool}
            result.push_back(x);         // .second is true iff insertion happened
        }
    }
    return result;
}


// ─── FREQUENCY-BASED DEDUP ────────────────────────────────────────────────────
// Returns {unique_items, duplicate_items_with_counts}.
template <typename T>
std::pair<std::vector<T>, std::vector<std::pair<T, int>>>
count_and_dedup(const std::vector<T>& items) {
    std::unordered_map<T, int> freq;
    freq.reserve(items.size());

    for (const auto& x : items) {
        ++freq[x];
    }

    std::vector<T> unique_items;
    std::vector<std::pair<T, int>> duplicates;

    for (auto& [val, count] : freq) {
        if (count == 1) unique_items.push_back(val);
        else            duplicates.emplace_back(val, count);
    }
    return {unique_items, duplicates};
}


// ─── FINGERPRINT-BASED DEDUP (FNV-1a 64-bit) ──────────────────────────────────
// For large objects: hash first, compare fingerprints.
// Production note: prefer MurmurHash3 or xxHash for better avalanche.
// FNV-1a shown here for zero-dependency illustration.
uint64_t fnv1a_64(std::string_view data) {
    constexpr uint64_t FNV_OFFSET = 14695981039346656037ULL;
    constexpr uint64_t FNV_PRIME  = 1099511628211ULL;
    uint64_t hash = FNV_OFFSET;
    for (unsigned char c : data) {
        hash ^= c;
        hash *= FNV_PRIME;
    }
    return hash;
}

// Dedup a vector of strings by their FNV-1a fingerprint.
// Collision probability: ~1/2^64 per pair. Acceptable for most ML workloads.
// For safety-critical use, fall back to full string comparison on fingerprint hit.
std::vector<std::string> fingerprint_dedup(const std::vector<std::string>& docs) {
    std::unordered_set<uint64_t> seen_fps;
    seen_fps.reserve(docs.size());

    std::vector<std::string> result;
    result.reserve(docs.size());

    for (const auto& doc : docs) {
        uint64_t fp = fnv1a_64(doc);
        if (seen_fps.insert(fp).second) {
            result.push_back(doc);
        }
    }
    return result;
}


// ─── UPSERT PATTERN (keep-first policy) ───────────────────────────────────────
// Simulates a feature store: first write wins, duplicates discarded.
template <typename K, typename V>
class KeepFirstStore {
    std::unordered_map<K, V> store_;
public:
    explicit KeepFirstStore(size_t expected_size = 0) {
        store_.reserve(expected_size);
    }

    // Returns true if this was a new insertion (not a duplicate).
    bool upsert(const K& key, const V& value) {
        return store_.emplace(key, value).second;
    }

    const V* get(const K& key) const {
        auto it = store_.find(key);
        return (it != store_.end()) ? &it->second : nullptr;
    }

    size_t size()     const { return store_.size(); }
    size_t capacity() const { return store_.bucket_count(); }
};


// ─── DEDUP ACROSS MULTIPLE SHARDS (parallel-safe merge) ───────────────────────
// Pattern: each shard deduplicates independently, then merge sets.
// Mirrors MapReduce dedup: map phase = per-shard dedup, reduce = set union.
std::vector<int> distributed_dedup(
    const std::vector<std::vector<int>>& shards
) {
    std::unordered_set<int> global_seen;

    for (const auto& shard : shards) {
        for (int x : shard) {
            global_seen.insert(x);
        }
    }

    return {global_seen.begin(), global_seen.end()};
    // Note: order is not preserved. Sort if needed.
}


// ─── TESTS ────────────────────────────────────────────────────────────────────
#include <cassert>

int main() {
    // Basic dedup — order preserved
    auto r1 = dedup_preserve_order<int>({3, 1, 4, 1, 5, 9, 2, 6, 5, 3});
    assert((r1 == std::vector<int>{3, 1, 4, 5, 9, 2, 6}));

    // Frequency dedup
    auto [uniq, dups] = count_and_dedup<int>({1, 2, 2, 3, 3, 3, 4});
    assert(uniq.size() == 2);  // 1 and 4
    assert(dups.size() == 2);  // 2 (x2) and 3 (x3)

    // Fingerprint dedup
    auto r3 = fingerprint_dedup({"hello", "world", "hello", "foo", "world"});
    assert(r3.size() == 3);  // "hello", "world", "foo"

    // Upsert store
    KeepFirstStore<std::string, int> store(100);
    assert( store.upsert("user_1", 42));   // new
    assert(!store.upsert("user_1", 99));   // duplicate — discarded
    assert(*store.get("user_1") == 42);    // first value preserved

    std::cout << "All tests passed.\n";
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations

import hashlib
import struct
from collections import defaultdict
from typing import Callable, Generator, Hashable, Iterable, Iterator, TypeVar

T = TypeVar("T", bound=Hashable)


# ─── STREAMING DEDUP (generator — memory-efficient) ──────────────────────────
def dedup_stream(stream: Iterable[T]) -> Generator[T, None, None]:
    """
    Yield each item from stream exactly once (first occurrence).

    Works on infinite/streaming iterables — does not materialise the full input.

    Time:  O(n) amortised
    Space: O(d) where d = number of distinct items
    """
    seen: set[T] = set()
    for item in stream:
        if item not in seen:
            seen.add(item)
            yield item


# ─── DEDUP WITH FREQUENCY COUNTING ───────────────────────────────────────────
def count_and_dedup(items: Iterable[T]) -> dict[T, int]:
    """
    Return a frequency map. Items with count > 1 are duplicates.

    This is the basis of vocabulary construction in tokenisers:
    pass all tokens from all documents, get a frequency-sorted vocabulary.

    Time:  O(n)
    Space: O(d)
    """
    freq: dict[T, int] = defaultdict(int)
    for item in items:
        freq[item] += 1
    return dict(freq)


# ─── FINGERPRINT-BASED DEDUP (for large/non-hashable objects) ─────────────────
def fingerprint_dedup(
    documents: Iterable[str | bytes],
    hash_fn: Callable[[bytes], str] | None = None,
) -> list[str | bytes]:
    """
    Dedup large documents by content fingerprint.

    Default: SHA-256 (128-bit collision resistance, safe for ML datasets).
    For speed: swap hash_fn for MurmurHash3 via mmh3 library.

    Time:  O(n * L) where L = average document length (dominated by hashing)
    Space: O(d * H) where H = fingerprint size in bytes (32 for SHA-256)

    In production ML pipelines (C4, RefinedWeb, Dolma), this is applied
    at paragraph or document granularity before near-dedup (MinHash).
    """
    if hash_fn is None:
        def hash_fn(content: bytes) -> str:
            return hashlib.sha256(content).hexdigest()

    seen_fingerprints: set[str] = set()
    result = []

    for doc in documents:
        raw = doc.encode() if isinstance(doc, str) else doc
        fp = hash_fn(raw)

        if fp not in seen_fingerprints:
            seen_fingerprints.add(fp)
            result.append(doc)

    return result


# ─── UPSERT STORE ─────────────────────────────────────────────────────────────
class UpsertStore:
    """
    HashMap-backed key-value store with configurable duplicate policy.

    Mirrors the upsert semantics of feature stores (Feast, Tecton).
    Policy options:
        "keep_first"  — ignore duplicate keys (default)
        "keep_last"   — overwrite with latest value
        "keep_all"    — accumulate all values as a list
    """

    def __init__(self, policy: str = "keep_first") -> None:
        assert policy in {"keep_first", "keep_last", "keep_all"}
        self._policy = policy
        self._store: dict = {}

    def upsert(self, key: Hashable, value) -> bool:
        """Returns True if this was a new insertion, False if duplicate."""
        if key not in self._store:
            self._store[key] = [value] if self._policy == "keep_all" else value
            return True

        if self._policy == "keep_first":
            pass                                  # ignore duplicate
        elif self._policy == "keep_last":
            self._store[key] = value
        elif self._policy == "keep_all":
            self._store[key].append(value)

        return False

    def get(self, key: Hashable, default=None):
        return self._store.get(key, default)

    def __len__(self) -> int:
        return len(self._store)


# ─── ML PIPELINE DEDUP: DATASET DEDUP WITH SHARDING ──────────────────────────
def dedup_dataset_sharded(
    shards: list[list[str]],
    fingerprint_fn: Callable[[str], str] | None = None,
) -> list[str]:
    """
    Dedup a dataset split across shards.

    Pattern mirrors MapReduce:
      Map phase:    each shard fingerprints its own documents
      Reduce phase: merge fingerprint sets, keep only first-seen documents

    In distributed systems (Apache Beam, Spark), the map phase runs in parallel
    across workers, and the reduce phase merges the per-shard seen-sets.

    Time:  O(n * L) for hashing + O(n) for set ops
    Space: O(d) for the global fingerprint set
    """
    if fingerprint_fn is None:
        def fingerprint_fn(doc: str) -> str:
            return hashlib.md5(doc.encode(), usedforsecurity=False).hexdigest()

    global_seen: set[str] = set()
    result: list[str] = []

    for shard in shards:
        for doc in shard:
            fp = fingerprint_fn(doc)
            if fp not in global_seen:
                global_seen.add(fp)
                result.append(doc)

    return result
```

```
Step 4:  item=1   seen={3,1,4}    → 1 IN seen     → DISCARD   seen={3,1,4}
Step 5:  item=5   seen={3,1,4}    → 5 not in seen → EMIT 5    seen={3,1,4,5}
Step 6:  item=9   seen={3,1,4,5}  → 9 not in seen → EMIT 9    seen={3,1,4,5,9}
Step 7:  item=2   seen={...}      → 2 not in seen → EMIT 2    seen={3,1,4,5,9,2}

Step 10: item=3   seen={...}      → 3 IN seen     → DISCARD   seen unchanged
```

### Fingerprint Dedup in an ML Data Pipeline

```
Raw Web Crawl (100B docs)
         │
         ▼
  ┌─────────────┐
  │  Shard 1    │──hash──► seen_fps_1  ─┐
  │  Shard 2    │──hash──► seen_fps_2  ─┤── merge ──► global_seen_fps
  │  Shard 3    │──hash──► seen_fps_3  ─┘                │
  └─────────────┘                                         │
                                                          ▼
                                               ┌──────────────────┐
                                               │  Deduplicated    │
                                               │  Corpus          │
                                               │  (~40-60B docs)  │
                                               └──────────────────┘

Within each shard:
  doc ──► hash(doc) ──► lookup in seen_fps
              │               │
              │         IN seen → DISCARD
              │         NOT in → add to seen_fps, EMIT

Key insight: hashing is O(L) per doc (L = length),
             but lookup is O(1). The bottleneck is I/O, not the HashSet.
```

### Exact vs Near Dedup: When to Use Which

```
Document A: "The quick brown fox jumps over the lazy dog"
Document B: "The quick brown fox jumps over the lazy dog"    ← EXACT duplicate
Document C: "The quick brown fox jumped over a lazy dog"     ← NEAR duplicate

                      SHA-256(A) == SHA-256(B)?   YES → exact dedup catches this
                      SHA-256(A) == SHA-256(C)?   NO  → exact dedup MISSES this

For near-duplicates:                                        ┌─────────────────┐
  MinHash(A) ≈ MinHash(C)  →  LSH bucket collision  →     │  [[39.MinHash]] │
                                                            └─────────────────┘
Pipeline order:
  Raw data  →  [Exact dedup: HashSet on SHA-256]
             →  [Near dedup: MinHash + LSH on unique docs]
             →  Clean training corpus
```

## 7. Common Variations & Extensions

### 7.1 Bloom Filter — Space-Efficient Probabilistic Dedup

When d is enormous (trillions of URLs in a web crawler), a HashSet of full 128-bit fingerprints is too large to fit in RAM. A **Bloom filter** is a bit array with k hash functions: insert sets k bits, lookup checks all k bits. False positives possible (never false negatives). Space: O(n · log(1/ε) / ln 2) bits for error rate ε, vs O(n · 128 bits) for an exact HashSet. Google's Crawl used Bloom filters. This is the probabilistic generalisation of the HashSet membership test.

### 7.2 Count-Min Sketch — Dedup + Frequency Estimation Under Memory Constraint

When you need approximate frequency counts (not just presence) over a stream too large to store: a Count-Min Sketch is a 2D array of counters with multiple hash functions. For each item, increment all `k` counters at `hash_i(x) % width`. Frequency estimate is `min` across the row. Connects to [[39.MinHash — estimating Jaccard similarity at scale]] and the broader family of streaming algorithms.

### 7.3 Dedup as a Preprocessing Step for Two-Sum / k-Sum

Before solving [[35.Two-sum and k-sum — the canonical HashMap pattern]], dedup the input if the problem requires unique pairs. Without deduplication, the complement check can pair an element with a later copy of itself. The standard approach: deduplicate the input array first (O(n) HashSet pass), then solve on the unique elements. Or: sort and use `std::unique` in C++ (O(n log n) but no extra space).

### 7.4 Dedup in BFS/DFS — The `visited` Set

Every BFS/DFS implementation uses a `visited` HashSet to ensure each node is processed at most once — this is deduplication applied to graph nodes. Without it, the traversal loops infinitely on cyclic graphs. See [[112.Depth-First Search (DFS) — recursive and iterative]] and [[113.Breadth-First Search (BFS) — level-order, shortest path in unweighted graph]] for full treatment. The `visited` set is the dedup HashSet; the graph is the stream of states.

## 9. CP Contest Application

### Typical Problem Patterns

**"Count distinct elements in a range"** — build a prefix-sum over a HashMap of first occurrences. For offline queries, Mo's algorithm processes range queries by maintaining a `freq` HashMap and incrementing a `distinct_count` when `freq[x]` transitions from 0→1 (insertion) or 1→0 (deletion).

**"Process each component/state exactly once in graph search"** — the `visited` HashSet is the dedup mechanism. In multi-source BFS, initialise the queue with all sources simultaneously and mark all as visited at initialisation — this prevents any source from being processed as a neighbour of another source.

**"Remove duplicates, then answer queries"** — always dedup first, answer second. The dedup is O(n), and subsequent operations benefit from the reduced d ≤ n size.

### Performance Notes

For CP with n ≤ 10⁶ and `unordered_set<int>`:

- `reserve(n)` before any insertions — avoids up to log₂(n) rehash operations.
- `max_load_factor(0.25)` reduces collision chains at the cost of 4× memory — worthwhile for tight time limits.
- For `unordered_set<string>`: hashing a string is O(L). For long strings, consider hashing to a 64-bit integer first (polynomial rolling hash or FNV-1a), then deduplicating the integers.

```cpp
// Fast string dedup via rolling hash (CP-safe)
auto poly_hash = [](const std::string& s) -> uint64_t {
    const uint64_t BASE = 131, MOD = (1ULL << 61) - 1;
    uint64_t h = 0;
    for (char c : s) h = (__uint128_t(h) * BASE + c) % MOD;
    return h;
};

std::unordered_set<uint64_t> seen;
for (const auto& s : strings) {
    seen.insert(poly_hash(s));  // O(L) hash, O(1) set op
}
// Distinct count = seen.size()
// Note: polynomial hash has collision probability ~L/MOD per pair
// For MOD = 2^61 - 1, this is negligible for |strings| ≤ 10^6
```

This pattern appears in Codeforces problems involving string grouping, anagram detection ([[22.Anagram detection and group-by-signature patterns]]), and substring distinctness — all reducible to dedup on a fingerprint.
