## 1. Intuition First

### The Core Idea

You read `3 + 4 * 2` and instantly know the answer is 11, not 14. You do this because you've been trained to respect operator precedence — multiplication before addition. But a computer, reading left-to-right with no "look-ahead", cannot evaluate this directly without a strategy.

The **infix** notation (`3 + 4 * 2`) is how humans write expressions. It is **ambiguous by design** — it requires precedence rules and parentheses to resolve ordering. The machine needs a form where evaluation order is _structurally encoded_, not implied.

**Postfix notation** (also called Reverse Polish Notation, or RPN) encodes the order of operations without any parentheses or precedence rules. The same expression becomes `3 4 2 * +`. Reading left-to-right: push 3, push 4, push 2, see `*` → pop 4 and 2, push 8, see `+` → pop 3 and 8, push 11. Done. **No rules needed — the structure is the instruction.**

The insight is this: **postfix externalises the operator precedence into the sequence itself**. When you convert infix → postfix (via the Shunting-Yard algorithm), you are encoding all the parenthesis and precedence information into a linear order that can be evaluated with a single left-to-right pass and a stack.

### Why This Exists

Naive evaluation of infix expressions requires either:

- Parsing the full expression into a tree (AST), then evaluating: O(n) time and O(n) space, but complex to implement correctly.
- Repeated scans for the highest-precedence operator: O(n²) passes, ugly and error-prone.

Postfix evaluation is **O(n) time, O(n) space, single pass, trivially correct**. The Shunting-Yard conversion is also O(n). Together they form a complete, elegant pipeline.

### The "Aha" Moment

The stack IS the operator precedence system. When you hold a lower-precedence operator on the stack waiting for a higher-precedence one to resolve first, you are implementing precedence without a grammar or recursive descent. **The stack depth mirrors the nesting depth of operations.** This is not a trick — it is the canonical connection between sequential notation and recursive structure.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- Expression parsing problems with nested brackets and mixed operators.
- Calculator implementation problems (LC 224, 227, 772).
- Problems where you must evaluate a string formula: `"3+2*2"` → `7`.
- Simplification of boolean or arithmetic expressions in constraints.

**Pattern signal:**

> "When you see a string with operators, numbers, and parentheses that needs evaluation → think two-stack (operator + operand) or convert to postfix first."

The Shunting-Yard algorithm is the template. Once you recognise the pattern, it is mechanical to implement.

**Common traps:**

1. **Unary minus**: `-3 + 4` is not the same as `3 - 4`. Handle unary minus by inserting a `0` before it or treating it as a special token.
2. **Right-associativity of exponentiation**: `2 ^ 3 ^ 2` = `2 ^ (3 ^ 2)` = 512, not `(2 ^ 3) ^ 2` = 64. Flip the comparison: pop only if incoming precedence is **strictly greater** for left-associative, **greater or equal** for right-associative. For `^`, pop only if stack top has **strictly greater** precedence.
3. **Multi-digit numbers**: tokenise the string character by character, accumulating digits into a number before emitting it as a token.
4. **Spaces in input**: strip them or handle in the tokeniser.

### Machine Learning / AI

**Computation Graphs and Autograd:**  
The postfix / RPN evaluation model is the _direct ancestor_ of how deep learning frameworks execute forward passes. In PyTorch's `autograd`, the computation graph is a DAG (directed acyclic graph) where each node is an operation and edges are tensors. Executing the forward pass is a **topological traversal** of this DAG — which is structurally identical to postfix evaluation. Operands (tensors) are "pushed" in, operations consume them and produce outputs. See [[224.Computational graph — forward pass as DAG traversal]].

**Symbolic Differentiation:**  
SymPy's expression evaluator internally parses infix expressions into an AST, then traverses it in postorder (left subtree → right subtree → root) to apply differentiation rules. The postorder traversal of an expression tree **is** postfix evaluation.

**ONNX Runtime and TensorFlow XLA:**  
ONNX represents a model as a serialised list of operator nodes with named inputs/outputs — essentially a postfix linearisation of the computation graph. The runtime evaluates it sequentially, maintaining a dictionary of computed tensors (analogous to the operand stack). Understanding this makes you better at writing ONNX-compatible models: avoid circular dependencies, keep the graph a DAG, understand why certain ops cannot be fused.

**Neural Architecture Search (NAS):**  
Expression encoding is used in NAS to represent architectures as sequences of tokens. Works like DeepMind's AlphaTensor use postfix-style encodings to represent operation sequences for matrix multiplication. See [[82.Feature subset search as backtracking — ML connection]].

## 3. Algorithm / Pattern

### Step-by-Step: Infix → Postfix (Shunting-Yard Algorithm)

**Inputs:** A tokenised infix expression.  
**Output:** A postfix token sequence.  
**Data structures:** One output queue, one operator stack.

**Precedence table (higher = tighter binding):**

|Operator|Precedence|Associativity|
|---|---|---|
|`+`, `-`|1|Left|
|`*`, `/`, `%`|2|Left|
|`^`|3|Right|

**Logic per token:**

```
For each token T:
  If T is a NUMBER      → emit to output
  If T is a FUNCTION    → push to operator stack
  If T is a COMMA       → pop operators to output until '(' seen
  If T is an OPERATOR O:
    While (stack top is an operator with HIGHER precedence,
           OR EQUAL precedence AND O is LEFT-associative)
           AND stack top is NOT '(':
        → pop stack top to output
    Push O onto operator stack
  If T is '('           → push to operator stack
  If T is ')':
    While stack top ≠ '(':
        → pop stack top to output
    Discard the '(' (pop and throw away)
    If stack top is a FUNCTION → pop it to output

After all tokens:
  Pop all remaining operators from stack to output
```

**Why this works:** The stack acts as a "pending higher-priority operations" buffer. Lower-priority operators wait. When a higher-priority operator finishes (or a closing paren forces resolution), everything accumulated gets flushed to output in the correct order.

### Step-by-Step: Postfix Evaluation

```
For each token T in postfix sequence:
  If T is a NUMBER → push to operand stack
  If T is an OPERATOR:
    right = pop()   ← NOTE: right operand comes off first
    left  = pop()
    result = apply(T, left, right)
    push result

Return the single value remaining on the stack
```

**Critical detail:** For non-commutative operations (`-`, `/`), pop order matters. The second pop is the left operand.

### Complexity

|Operation|Time|Space|
|---|---|---|
|Infix → Postfix|O(n)|O(n) — operator stack + output|
|Postfix Evaluation|O(n)|O(n) — operand stack|
|Combined|O(n)|O(n)|

**Derivation:** Each token is processed once. Each operator is pushed to the stack at most once and popped at most once. The stack depth is bounded by the number of operators, which is O(n). No token is visited more than twice in total.

### Decision Tree

```
Need to evaluate an arithmetic expression string?
├─ Only numbers and operators, no parentheses, left-to-right evaluation?
│   └─ Two-variable scan (current + pending) — O(n)
├─ Operators with precedence but no parens?
│   └─ Shunting-Yard → postfix evaluation — O(n)
├─ Full expression with parens, precedence, maybe functions?
│   └─ Shunting-Yard → postfix evaluation — O(n)
└─ Need to support variables, differentiation, symbolic manipulation?
    └─ Build an AST (parse tree), then traverse — O(n)
```

**When to avoid postfix:** If you need lazy evaluation (short-circuit `&&`, `||`), postfix doesn't naturally support it — you need AST evaluation with conditional branching.

## 4. Pseudocode

```
FUNCTION infix_to_postfix(tokens):
    output   ← empty list
    op_stack ← empty stack
    
    FOR token IN tokens:
        IF token is a number:
            output.append(token)
        
        ELIF token is an operator:
            # Pop higher or equal precedence left-assoc operators
            WHILE (op_stack is not empty
                   AND op_stack.top() is an operator
                   AND (precedence(op_stack.top()) > precedence(token)
                        OR (precedence(op_stack.top()) == precedence(token)
                            AND is_left_associative(token)))
                   AND op_stack.top() != '('):
                output.append(op_stack.pop())
            op_stack.push(token)
        
        ELIF token == '(':
            op_stack.push(token)
        
        ELIF token == ')':
            # Flush until matching '('
            WHILE op_stack.top() != '(':
                output.append(op_stack.pop())
            op_stack.pop()  # discard the '('
    
    # Drain remaining operators
    WHILE op_stack is not empty:
        output.append(op_stack.pop())
    
    RETURN output


FUNCTION evaluate_postfix(tokens):
    operand_stack ← empty stack
    
    FOR token IN tokens:
        IF token is a number:
            operand_stack.push(token)
        ELSE:  # token is an operator
            right ← operand_stack.pop()   # pop RIGHT first
            left  ← operand_stack.pop()   # then LEFT
            
            IF token == '+': operand_stack.push(left + right)
            IF token == '-': operand_stack.push(left - right)
            IF token == '*': operand_stack.push(left * right)
            IF token == '/': operand_stack.push(left / right)  # integer or float?
    
    RETURN operand_stack.pop()  # single remaining value
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ─────────────────────────────────────────────────────────────────────────────
// Expression Evaluator: Infix → Postfix → Result
// Supports: +, -, *, /, ^ (right-assoc), parentheses, multi-digit integers
// Time: O(n)   Space: O(n)
// ─────────────────────────────────────────────────────────────────────────────

struct ExpressionEvaluator {

    static int precedence(char op) {
        if (op == '+' || op == '-') return 1;
        if (op == '*' || op == '/') return 2;
        if (op == '^')              return 3;
        return 0;
    }

    static bool is_left_assoc(char op) {
        return op != '^';  // only ^ is right-associative
    }

    // Tokenise: splits "3+4*2" → ["3", "+", "4", "*", "2"]
    // Handles multi-digit numbers and unary minus (converts to "0 - x")
    static vector<string> tokenise(const string& expr) {
        vector<string> tokens;
        int i = 0, n = expr.size();
        while (i < n) {
            if (isspace(expr[i])) { i++; continue; }
            
            if (isdigit(expr[i])) {
                string num;
                while (i < n && isdigit(expr[i])) num += expr[i++];
                tokens.push_back(num);
            } else {
                // Detect unary minus: at start, or after '(' or another operator
                char c = expr[i];
                if (c == '-' && (tokens.empty() || tokens.back() == "("
                                  || tokens.back() == "+" || tokens.back() == "-"
                                  || tokens.back() == "*" || tokens.back() == "/")) {
                    tokens.push_back("0");  // insert implicit zero: 0 - x
                }
                tokens.push_back(string(1, c));
                i++;
            }
        }
        return tokens;
    }

    // Shunting-Yard: infix tokens → postfix tokens
    static vector<string> to_postfix(const vector<string>& tokens) {
        vector<string> output;
        stack<string> ops;

        for (const string& tok : tokens) {
            if (isdigit(tok[0]) || (tok.size() > 1)) {
                // It's a number (possibly multi-digit)
                output.push_back(tok);

            } else if (tok == "(") {
                ops.push(tok);

            } else if (tok == ")") {
                // Pop until matching '('
                while (!ops.empty() && ops.top() != "(") {
                    output.push_back(ops.top()); ops.pop();
                }
                if (!ops.empty()) ops.pop();  // discard '('

            } else {
                // It's an operator
                char op = tok[0];
                while (!ops.empty() && ops.top() != "(" &&
                       (precedence(ops.top()[0]) > precedence(op) ||
                        (precedence(ops.top()[0]) == precedence(op) && is_left_assoc(op)))) {
                    output.push_back(ops.top()); ops.pop();
                }
                ops.push(tok);
            }
        }

        // Drain remaining operators
        while (!ops.empty()) {
            output.push_back(ops.top()); ops.pop();
        }
        return output;
    }

    // Evaluate a postfix token sequence
    static double eval_postfix(const vector<string>& postfix) {
        stack<double> stk;
        for (const string& tok : postfix) {
            if (isdigit(tok[0]) || (tok.size() > 1 && isdigit(tok[1]))) {
                stk.push(stod(tok));
            } else {
                if (stk.size() < 2) throw runtime_error("Malformed expression");
                double right = stk.top(); stk.pop();
                double left  = stk.top(); stk.pop();
                switch (tok[0]) {
                    case '+': stk.push(left + right); break;
                    case '-': stk.push(left - right); break;
                    case '*': stk.push(left * right); break;
                    case '/':
                        if (right == 0) throw runtime_error("Division by zero");
                        stk.push(left / right); break;
                    case '^': stk.push(pow(left, right)); break;
                    default:  throw runtime_error("Unknown operator");
                }
            }
        }
        return stk.top();
    }

    // Public interface: evaluate an infix expression string
    static double evaluate(const string& expr) {
        auto tokens  = tokenise(expr);
        auto postfix = to_postfix(tokens);
        return eval_postfix(postfix);
    }
};

// ─────────────────────────────────────────────────────────────────────────────
// LC 227: Basic Calculator II (no parentheses, integers, +,-,*,/)
// One-pass variant using the "pending operator" approach
// ─────────────────────────────────────────────────────────────────────────────
class BasicCalculatorII {
public:
    int calculate(string s) {
        stack<int> stk;
        int num = 0;
        char op = '+';  // treat first number as if preceded by '+'

        for (int i = 0; i < (int)s.size(); i++) {
            char c = s[i];
            if (isdigit(c)) num = num * 10 + (c - '0');

            if ((!isdigit(c) && c != ' ') || i == (int)s.size() - 1) {
                // Flush current number based on the PREVIOUS operator
                if      (op == '+') stk.push( num);
                else if (op == '-') stk.push(-num);
                else if (op == '*') { int top = stk.top(); stk.pop(); stk.push(top * num); }
                else if (op == '/') { int top = stk.top(); stk.pop(); stk.push(top / num); }
                op = c;
                num = 0;
            }
        }

        int result = 0;
        while (!stk.empty()) { result += stk.top(); stk.pop(); }
        return result;
    }
};

// ─────────────────────────────────────────────────────────────────────────────
// Test
// ─────────────────────────────────────────────────────────────────────────────
int main() {
    // Full evaluator with precedence and parentheses
    cout << fixed << setprecision(2);
    cout << ExpressionEvaluator::evaluate("3+4*2")          << "\n";  // 11.00
    cout << ExpressionEvaluator::evaluate("(3+4)*2")        << "\n";  // 14.00
    cout << ExpressionEvaluator::evaluate("2^3^2")          << "\n";  // 512.00 (right-assoc)
    cout << ExpressionEvaluator::evaluate("-3+4")           << "\n";  // 1.00
    cout << ExpressionEvaluator::evaluate("10+2*6")         << "\n";  // 22.00
    cout << ExpressionEvaluator::evaluate("100*2+12")       << "\n";  // 212.00
    cout << ExpressionEvaluator::evaluate("100*(2+12)/14")  << "\n";  // 100.00

    // LC 227
    BasicCalculatorII calc;
    cout << calc.calculate("3+2*2")  << "\n";  // 7
    cout << calc.calculate(" 3/2 ")  << "\n";  // 1
    cout << calc.calculate(" 3+5 / 2 ") << "\n";  // 5

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import Union
import operator

# ─────────────────────────────────────────────────────────────────────────────
# Full Expression Evaluator: Infix → Postfix → Result
# Supports: +, -, *, /, **, parentheses, multi-digit integers/floats
# Time: O(n)   Space: O(n)
# ─────────────────────────────────────────────────────────────────────────────

PRECEDENCE: dict[str, int] = {'+': 1, '-': 1, '*': 2, '/': 2, '**': 3}
LEFT_ASSOC: set[str] = {'+', '-', '*', '/'}  # '**' is right-associative
OPS = {
    '+': operator.add,
    '-': operator.sub,
    '*': operator.mul,
    '/': operator.truediv,
    '**': operator.pow,
}


def tokenise(expr: str) -> list[str]:
    """
    Convert expression string to a list of tokens.
    Handles multi-digit integers and unary minus.
    '3 + -4 * 2' → ['3', '+', '0', '-', '4', '*', '2']
    """
    tokens: list[str] = []
    i, n = 0, len(expr)
    while i < n:
        if expr[i].isspace():
            i += 1
            continue
        if expr[i].isdigit() or (expr[i] == '.' and i + 1 < n and expr[i+1].isdigit()):
            j = i
            while j < n and (expr[j].isdigit() or expr[j] == '.'):
                j += 1
            tokens.append(expr[i:j])
            i = j
        elif expr[i:i+2] == '**':
            tokens.append('**')
            i += 2
        else:
            c = expr[i]
            # Unary minus: at start or after '(' or operator
            if c == '-' and (not tokens or tokens[-1] in ('(', '+', '-', '*', '/', '**')):
                tokens.append('0')  # synthesise zero: treat as 0 - x
            tokens.append(c)
            i += 1
    return tokens


def to_postfix(tokens: list[str]) -> list[str]:
    """
    Shunting-Yard algorithm: infix token list → postfix token list.

    Complexity: O(n) — each token pushed/popped at most once.
    """
    output: list[str] = []
    op_stack: list[str] = []

    for tok in tokens:
        if tok not in PRECEDENCE and tok not in ('(', ')'):
            # It's a number (operand)
            output.append(tok)
        elif tok == '(':
            op_stack.append(tok)
        elif tok == ')':
            # Pop to output until matching '('
            while op_stack and op_stack[-1] != '(':
                output.append(op_stack.pop())
            op_stack.pop()  # discard '('
        else:
            # tok is an operator
            while (op_stack
                   and op_stack[-1] != '('
                   and op_stack[-1] in PRECEDENCE
                   and (PRECEDENCE[op_stack[-1]] > PRECEDENCE[tok]
                        or (PRECEDENCE[op_stack[-1]] == PRECEDENCE[tok]
                            and tok in LEFT_ASSOC))):
                output.append(op_stack.pop())
            op_stack.append(tok)

    # Drain remaining operators
    while op_stack:
        output.append(op_stack.pop())

    return output


def eval_postfix(tokens: list[str]) -> float:
    """
    Evaluate a postfix token list.
    Returns the numeric result.

    Complexity: O(n) — single left-to-right pass.
    """
    stack: list[float] = []
    for tok in tokens:
        if tok in OPS:
            if len(stack) < 2:
                raise ValueError(f"Malformed postfix expression at token '{tok}'")
            right = stack.pop()  # right operand off first
            left  = stack.pop()  # then left
            if tok == '/' and right == 0:
                raise ZeroDivisionError("Division by zero")
            stack.append(OPS[tok](left, right))
        else:
            stack.append(float(tok))
    if len(stack) != 1:
        raise ValueError("Malformed expression: multiple values remain")
    return stack[0]


def evaluate(expr: str) -> float:
    """
    Public interface: evaluate an infix arithmetic expression string.

    >>> evaluate("3 + 4 * 2")
    11.0
    >>> evaluate("(3 + 4) * 2")
    14.0
    >>> evaluate("2 ** 3 ** 2")   # right-associative: 2^(3^2) = 512
    512.0
    >>> evaluate("-3 + 4")
    1.0
    """
    tokens  = tokenise(expr)
    postfix = to_postfix(tokens)
    return eval_postfix(postfix)


# ─────────────────────────────────────────────────────────────────────────────
# LC 227: Basic Calculator II — optimised single-pass, no full postfix
# ─────────────────────────────────────────────────────────────────────────────

def basic_calculator_ii(s: str) -> int:
    """
    Evaluate string expression with +, -, *, / (no parentheses).
    Uses a stack to defer addition/subtraction until end.

    Key insight: push positive/negative numbers for + and -,
    but for * and / immediately combine with the stack top.

    Time: O(n)   Space: O(n)
    """
    stack: list[int] = []
    num, op = 0, '+'

    for i, c in enumerate(s):
        if c.isdigit():
            num = num * 10 + int(c)
        if (not c.isdigit() and c != ' ') or i == len(s) - 1:
            if   op == '+': stack.append( num)
            elif op == '-': stack.append(-num)
            elif op == '*': stack.append(stack.pop() * num)
            elif op == '/': stack.append(int(stack.pop() / num))  # truncate toward zero
            op, num = c, 0

    return sum(stack)


# ─────────────────────────────────────────────────────────────────────────────
# Tests
# ─────────────────────────────────────────────────────────────────────────────
if __name__ == "__main__":
    cases = [
        ("3+4*2",           11.0),
        ("(3+4)*2",         14.0),
        ("2**3**2",         512.0),   # right-associative exponentiation
        ("-3+4",            1.0),
        ("10+2*6",          22.0),
        ("100*(2+12)/14",   100.0),
        ("100*2+12",        212.0),
    ]
    for expr, expected in cases:
        result = evaluate(expr)
        status = "✓" if abs(result - expected) < 1e-9 else "✗"
        print(f"{status} evaluate('{expr}') = {result}  (expected {expected})")

    print()
    lc_cases = [("3+2*2", 7), (" 3/2 ", 1), (" 3+5 / 2 ", 5)]
    for s, expected in lc_cases:
        result = basic_calculator_ii(s)
        status = "✓" if result == expected else "✗"
        print(f"{status} calc_ii('{s.strip()}') = {result}  (expected {expected})")
```

## 7. Common Variations & Extensions

### 7.1 Two-Stack Direct Evaluation (No Explicit Postfix)

Instead of converting first, maintain two stacks simultaneously: one for operands, one for operators. When a new operator arrives, apply pending higher-precedence operators immediately. This is equivalent to Shunting-Yard but evaluates in-place. Used in LC 224 (with spaces and unary minus) and LC 772 (full calculator with `±*/` and nested parens). See [[83.Stack operations — push, pop, peek, isEmpty in O(1)]].

### 7.2 Recursive Descent Parsing

For more complex grammars (variables, functions, conditionals), Shunting-Yard breaks down. Recursive descent parsing defines mutually recursive functions `parse_expr()`, `parse_term()`, `parse_factor()` that naturally encode precedence in the call hierarchy. This is how Python's `ast` module and compilers like GCC's front-end parse expressions. The call stack IS the operator stack — making it the implicit, recursive version of Shunting-Yard.

### 7.3 Expression Trees (AST Representation)

Convert postfix to a binary tree: numbers are leaves, operators are internal nodes. Evaluate by postorder traversal. This representation supports:

- Symbolic differentiation (apply chain rule at each node)
- Expression simplification (`x + 0 = x`)
- Code generation (emit instructions bottom-up) Related: [[215.Gradient computation as a graph traversal — autograd intuition]]

### 7.4 Boolean Expression Evaluation

The same pattern applies to boolean expressions: `&&`, `||`, `!` with their precedence rules (`!` > `&&` > `||`). Short-circuit evaluation requires AST traversal rather than postfix, since you need to skip branches. Used in constraint checkers, SQL WHERE clause evaluation, and PyTorch's `torch.where` compilation.

## 9. CP Contest Application

### Typical Codeforces/AtCoder Problem Structure

**Pattern 1 — Formula Evaluation:**  
Given a mathematical expression string of length up to 10⁵, compute its value modulo some prime. Direct evaluation with Shunting-Yard, evaluate in the integers modulo p.

**Pattern 2 — Expression Simplification:**  
Given a polynomial expression with variables, expand and collect like terms. Parse to AST, then recurse on subtrees. Common in CF Div. 2 D/E problems.

**Pattern 3 — Custom Operators:**  
Operators with unusual precedence or non-standard semantics. The Shunting-Yard template is directly applicable — just modify the precedence table.

### Time Limits Where This Matters

- Expression strings of length n = 10⁶: O(n) Shunting-Yard passes comfortably in 1–2 seconds.
- Naive O(n²) "find highest-precedence operator, evaluate, repeat" will TLE at n ≥ 10⁴.

### Common CP Optimisation Tricks

1. **Avoid `std::string` tokens** — use indices into the original character array. Reduces allocations.
2. **Integer tokenisation on-the-fly** — don't build a token vector; process tokens as you scan.
3. **Fused scan-and-evaluate** — for problems without parentheses, the two-stack direct approach (LC 227 pattern) is faster in practice than converting to postfix first.
4. **Precompute precedence** — a `constexpr` array indexed by character ASCII value gives O(1) precedence lookup without a map.

```cpp
// CP-speed precedence lookup — no map overhead
constexpr int PREC[128] = {
    // All zeros by default; set specific operators:
    ['+'] = 1, ['-'] = 1, ['*'] = 2, ['/'] = 2  
};
// Usage: PREC[(int)op]
```
