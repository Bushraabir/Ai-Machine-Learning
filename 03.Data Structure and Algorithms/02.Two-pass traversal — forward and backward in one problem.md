
## 1. Intuition First

### The Core Idea

A customs agent at a border checks every traveller twice: once when entering the country and once when leaving. The entry check builds a record; the exit check uses it. Neither pass alone is sufficient — the final judgement requires both perspectives.

Two-pass traversal is exactly this: a **forward pass** that builds a left-context summary for each index, and a **backward pass** that builds a right-context summary, after which every index holds the combined view of its entire neighbourhood.

The canonical example is the "product of all elements except self" problem. At index `i`, you need `a[0] × a[1] × … × a[i-1]` (everything to the left) and `a[i+1] × … × a[n-1]` (everything to the right). No single left-to-right scan can produce both for every `i`. But two passes — one forward accumulating a left product, one backward accumulating a right product — compose into the full answer at every index in O(n) total, O(1) auxiliary space.

The geometry is important: think of each index as a point on a number line. The forward pass sweeps a beam from left to right, depositing "left context" at each point as it passes. The backward pass sweeps a beam from right to left, depositing "right context". After both sweeps, every point is lit from both sides.

### Why This Exists

Single-pass approaches fail when the answer at index `i` depends simultaneously on elements both before _and_ after `i`. A naive solution loops, for each `i`, over all other elements — O(n²). The two-pass insight collapses this: instead of asking "what is the aggregate of everything else?" in one shot per index, you split the dependency. The left aggregate is computed incrementally going forward; the right aggregate is computed incrementally going backward. Each is O(n). The combination at each index is O(1). Total: O(n) time, O(1) auxiliary space (the output array itself is not auxiliary).

The complexity gap is O(n²) → O(n). For n = 10⁶, this is the difference between seconds and hours.

### The "Aha" Moment

> **Whenever an index needs information from both its left and its right, split the problem: build the left answer in one pass, build the right answer in another, and combine.**

A single pass can carry the past but not the future. Two passes — one forward, one backward — give you both. The combination step at each index is always O(1), so the total work is 2n, which is still O(n).

Once you see this, you recognise it everywhere: prefix products, candy distribution with two constraints, trapping rainwater's left-max and right-max arrays, and the backward pass in neural network backpropagation.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Two-pass problems are common in Codeforces Div. 2 C and Div. 3 D. They almost always involve an array where each element's answer depends on a _left aggregate_ and a _right aggregate_ simultaneously. Recognise the signal:

- "Each element's score depends on all elements to its left and all elements to its right"
- "Assign values to an array such that a local condition holds at every position"
- "Minimum cost where cost at position `i` involves both prefix and suffix information"
- Greedy problems where you must respect both a left-neighbour constraint and a right-neighbour constraint (e.g., the Candy problem: LeetCode 135)

**Pattern signal → decision rule:**

```
If answer[i] = f(left_context[i], right_context[i]):
    → Two-pass traversal
    Forward pass:  build left_context[i] from left_context[i-1] and a[i]
    Backward pass: build right_context[i] from right_context[i+1] and a[i]
    Combine:       answer[i] = f(left_context[i], right_context[i])
```

**Common trap 1 — conflating the two passes:** A single array is used for both the forward result and the in-progress backward computation, overwriting information needed later. Always finish the forward pass completely before starting the backward pass, or use two separate arrays.

**Common trap 2 — off-by-one in what "left context" means:** Does `left[i]` mean the aggregate of `a[0..i-1]` (exclusive of `i`) or `a[0..i]` (inclusive)? This depends on the problem. For product-except-self, it must be exclusive. For prefix-max arrays used in trapping rainwater, it must be inclusive. Decide before you code and annotate it in your variable name: `prefix_max_inclusive` vs `left_product_exclusive`.

**Common trap 3 — assuming two passes always means two arrays:** Many two-pass problems can be done with one output array plus a single running variable in the backward pass, saving O(n) space. The backward pass updates the output array in-place using a running accumulator. This is a standard interview optimisation.

### Machine Learning / AI

Two-pass traversal is not a curiosity — it is the structural foundation of three distinct areas of ML:

**1. Backpropagation in neural networks.**  
Training a neural network is a two-pass algorithm over the computation graph. The forward pass computes activations at every layer and caches them. The backward pass traverses the same graph in reverse, computing gradients layer by layer using the cached activations. The backward pass at layer `l` requires both the upstream gradient (from the right, i.e., later layers) and the cached activation (from the left, i.e., the forward pass). This is exactly the two-pass structure: forward pass deposits left-context (cached activations); backward pass uses right-context (upstream gradients) and left-context together to compute the local gradient. PyTorch's `loss.backward()` is a backward-pass traversal of a DAG, not a single scan. See [[215.Gradient computation as a graph traversal — autograd intuition]] and [[224.Computational graph — forward pass as DAG traversal]].

**2. CRF / HMM inference.**  
The forward-backward algorithm for Hidden Markov Models is literally named for this pattern. The forward pass computes `α[t]` = probability of the observation sequence up to time `t` ending in state `s`. The backward pass computes `β[t]` = probability of the observation sequence from time `t+1` to the end, given state `s` at time `t`. The posterior state probability at time `t` is proportional to `α[t] × β[t]` — the product of left-context and right-context, combined at every position. This is two-pass traversal on a sequence, and it is the inference engine of every CRF used in NLP sequence labelling (NER, POS tagging). See [[186.Viterbi algorithm — DP for HMM decoding]].

**3. Feature engineering — left and right rolling statistics.**  
In time-series ML, certain features require both the past and the future context around a point: "how does this reading compare to the 5-step rolling mean before and after it?" In a non-causal (offline) setting, you can compute a backward rolling mean with `df[::-1].rolling(5).mean()[::-1]` in Pandas — a backward pass. The combination of forward and backward rolling features is a two-pass construction. In production pipelines, this distinction matters: causal models can only use the forward pass (no future leakage), while offline evaluation can use both.

## 3. Algorithm / Pattern

### The General Template

**Setup:** Array `a[0..n-1]`. Answer at each index requires `left[i]` and `right[i]`.

```
Forward pass (left to right):
  left[0] = identity_element   ← empty left context
  for i = 1 to n-1:
    left[i] = combine(left[i-1], a[i-1])   ← note: a[i-1], not a[i], for exclusive

Backward pass (right to left):
  right[n-1] = identity_element   ← empty right context
  for i = n-2 downto 0:
    right[i] = combine(right[i+1], a[i+1])   ← note: a[i+1], not a[i], for exclusive

Combine:
  for i = 0 to n-1:
    answer[i] = f(left[i], right[i])
```

**Space optimisation (eliminate the `right` array):**  
Run the backward pass directly on the output array, carrying a running accumulator:

```
# After forward pass, output[i] = left[i].
running = identity_element
for i = n-1 downto 0:
    output[i] = f(output[i], running)   ← combine existing left[i] with running right
    running = combine(running, a[i])    ← update running right context
```

### Decision Tree

```
Does answer[i] depend only on elements before i?
  └── Yes → Single linear scan. See [[01.Linear scan and index tracking]]

Does answer[i] depend on elements both before AND after i?
  └── Yes → Two-pass candidate
        ├── Is the combination at each index O(1)?
        │     └── Yes → Two-pass traversal
        ├── Does the left/right context need to handle range queries?
        │     └── Yes → [[06.1D prefix sum]] or segment tree
        └── Is the combination non-trivial (DP-like)?
              └── Yes → Consider [[160.Overlapping subproblems and optimal substructure]]
```

### Complexity

**Time: O(n)**  
Two passes, each O(n). Constant work per element in each pass.

**Space: O(1) auxiliary** (with the in-place backward pass optimisation)  
Or O(n) if both `left[]` and `right[]` arrays are materialised explicitly.

**Identity elements by operation:**

|Operation|Identity|
|---|---|
|Sum|0|
|Product|1|
|Max|−∞|
|Min|+∞|
|AND|all 1s|
|OR|0|

## 4. Pseudocode

```
// ─── Template: Product of Array Except Self ───────────────────────────────
// Demonstrates the space-optimised version (O(1) auxiliary).

function product_except_self(a[0..n-1]) → output[0..n-1]:

    // ── Forward pass ──────────────────────────────────────────────────────
    // output[i] will hold the product of a[0..i-1] (exclusive of a[i]).
    // The "left product" of the first element is empty → identity = 1.

    output[0] ← 1
    for i from 1 to n-1:
        output[i] ← output[i-1] × a[i-1]
        // output[i] = a[0] × a[1] × … × a[i-1]

    // ── Backward pass (in-place, O(1) extra space) ────────────────────────
    // running accumulates the product of a[i+1..n-1] (right context).
    // We multiply each output[i] by the running right product.

    running ← 1
    for i from n-1 downto 0:
        output[i] ← output[i] × running      // combine left × right
        running   ← running × a[i]           // extend right product leftward

    return output


// ─── Template: Greedy with Left and Right Constraints ────────────────────
// e.g., Candy problem: each child rated higher than neighbour gets more candy.

function candy(ratings[0..n-1]) → total_candies:

    candies ← array of n ones   // minimum 1 candy each

    // ── Forward pass ──────────────────────────────────────────────────────
    // Enforce: if ratings[i] > ratings[i-1], give more candy than left neighbour.
    for i from 1 to n-1:
        if ratings[i] > ratings[i-1]:
            candies[i] ← candies[i-1] + 1

    // ── Backward pass ─────────────────────────────────────────────────────
    // Enforce: if ratings[i] > ratings[i+1], give more candy than right neighbour.
    // Take the max to respect both constraints simultaneously.
    for i from n-2 downto 0:
        if ratings[i] > ratings[i+1]:
            candies[i] ← max(candies[i], candies[i+1] + 1)

    return sum(candies)
```

**Why `max` in the backward pass?** The forward pass already established a lower bound for `candies[i]` based on the left constraint. The backward pass cannot reduce it — doing so would violate the already-satisfied left constraint. It can only _increase_ it if the right constraint demands more. `max` is the correct combiner here, not assignment.

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ─────────────────────────────────────────────────────────────────────────────
// Product of Array Except Self (LeetCode 238)
// Returns output[i] = product of all elements except a[i].
// Constraint: do not use division; O(n) time, O(1) auxiliary space.
// ─────────────────────────────────────────────────────────────────────────────
vector<int> product_except_self(const vector<int>& a) {
    int n = a.size();
    vector<int> out(n);

    // Forward pass: out[i] = product of a[0..i-1]
    out[0] = 1;
    for (int i = 1; i < n; ++i)
        out[i] = out[i-1] * a[i-1];

    // Backward pass: multiply in the right product on-the-fly.
    // 'running' = product of a[i+1..n-1] at the time we process index i.
    int running = 1;
    for (int i = n-1; i >= 0; --i) {
        out[i] *= running;      // left product × right product
        running *= a[i];        // extend right product one step left
    }
    return out;
}

// ─────────────────────────────────────────────────────────────────────────────
// Candy (LeetCode 135)
// Each child must have at least 1 candy. A child rated higher than an adjacent
// neighbour must have more candies than that neighbour.
// Returns the minimum total candies needed.
// ─────────────────────────────────────────────────────────────────────────────
int candy(const vector<int>& ratings) {
    int n = ratings.size();
    vector<int> candies(n, 1);  // Every child starts with 1 candy.

    // Forward pass: satisfy left-neighbour constraint.
    for (int i = 1; i < n; ++i)
        if (ratings[i] > ratings[i-1])
            candies[i] = candies[i-1] + 1;

    // Backward pass: satisfy right-neighbour constraint without breaking left.
    for (int i = n-2; i >= 0; --i)
        if (ratings[i] > ratings[i+1])
            candies[i] = max(candies[i], candies[i+1] + 1);
            // max preserves the forward-pass result when it is already larger.

    return accumulate(candies.begin(), candies.end(), 0);
}

// ─────────────────────────────────────────────────────────────────────────────
// Trapping Rain Water (LeetCode 42) — two-pass version
// At each index, water = min(max_left, max_right) - height[i].
// ─────────────────────────────────────────────────────────────────────────────
int trap(const vector<int>& h) {
    int n = h.size();
    if (n < 3) return 0;

    // Forward pass: left_max[i] = max(h[0..i])
    vector<int> left_max(n);
    left_max[0] = h[0];
    for (int i = 1; i < n; ++i)
        left_max[i] = max(left_max[i-1], h[i]);

    // Backward pass: right_max[i] = max(h[i..n-1])
    // Computed in-place using a running variable to save space.
    int water = 0;
    int right_max = h[n-1];
    for (int i = n-2; i >= 1; --i) {
        right_max = max(right_max, h[i]);
        // Water above position i = min wall on both sides minus height.
        water += max(0, min(left_max[i], right_max) - h[i]);
    }
    return water;
}

// ─────────────────────────────────────────────────────────────────────────────
// Minimal test driver
// ─────────────────────────────────────────────────────────────────────────────
int main() {
    // Product except self
    auto r1 = product_except_self({1, 2, 3, 4});
    assert((r1 == vector<int>{24, 12, 8, 6}));

    auto r2 = product_except_self({-1, 1, 0, -3, 3});
    assert((r2 == vector<int>{0, 0, 9, 0, 0}));

    // Candy
    assert(candy({1, 0, 2}) == 5);   // [2, 1, 2]
    assert(candy({1, 2, 2}) == 4);   // [1, 2, 1]
    assert(candy({1, 3, 2, 2, 1}) == 7); // [1, 2, 1, 2, 1] — tricky plateau

    // Trapping rain water
    assert(trap({0,1,0,2,1,0,1,3,2,1,2,1}) == 6);
    assert(trap({4,2,0,3,2,5}) == 9);

    cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
def product_except_self(a: list[int]) -> list[int]:
    """
    Returns output[i] = product of all elements in a except a[i].
    No division. O(n) time, O(1) auxiliary space (output array not counted).

    Two-pass structure:
      Forward:  out[i] = a[0] * a[1] * ... * a[i-1]
      Backward: multiply in a[i+1] * ... * a[n-1] via running accumulator.
    """
    n = len(a)
    out = [1] * n

    # Forward pass: left products
    for i in range(1, n):
        out[i] = out[i - 1] * a[i - 1]

    # Backward pass: multiply right products in-place
    running = 1
    for i in range(n - 1, -1, -1):
        out[i] *= running
        running *= a[i]

    return out


def candy(ratings: list[int]) -> int:
    """
    Minimum candies: each child ≥ 1 candy; higher-rated neighbour gets more.
    Two passes enforce left and right constraints independently, then merge with max.

    Time:  O(n)
    Space: O(n) for the candies array
    """
    n = len(ratings)
    candies = [1] * n

    # Forward pass: left-neighbour constraint
    for i in range(1, n):
        if ratings[i] > ratings[i - 1]:
            candies[i] = candies[i - 1] + 1

    # Backward pass: right-neighbour constraint (take max to preserve left result)
    for i in range(n - 2, -1, -1):
        if ratings[i] > ratings[i + 1]:
            candies[i] = max(candies[i], candies[i + 1] + 1)

    return sum(candies)


def trap(height: list[int]) -> int:
    """
    Trapping Rainwater via two-pass left_max / right_max arrays.
    Water at index i = max(0, min(left_max[i], right_max[i]) - height[i]).

    Time:  O(n)
    Space: O(n) for left_max; right_max handled with a running variable.
    """
    n = len(height)
    if n < 3:
        return 0

    # Forward pass: left_max[i] = max height in height[0..i]
    left_max = [0] * n
    left_max[0] = height[0]
    for i in range(1, n):
        left_max[i] = max(left_max[i - 1], height[i])

    # Backward pass: right_max computed on-the-fly
    water = 0
    right_max = height[-1]
    for i in range(n - 2, 0, -1):      # exclude endpoints: no water there
        right_max = max(right_max, height[i])
        water += max(0, min(left_max[i], right_max) - height[i])

    return water


# ─── Naive O(n²) reference for correctness checking ──────────────────────────
def trap_naive(height: list[int]) -> int:
    """O(n²) brute force: for each index, scan left and right for max walls."""
    n, water = len(height), 0
    for i in range(1, n - 1):
        left_max  = max(height[:i + 1])
        right_max = max(height[i:])
        water += max(0, min(left_max, right_max) - height[i])
    return water


# ─── Tests ───────────────────────────────────────────────────────────────────
if __name__ == "__main__":
    assert product_except_self([1, 2, 3, 4]) == [24, 12, 8, 6]
    assert product_except_self([-1, 1, 0, -3, 3]) == [0, 0, 9, 0, 0]
    assert product_except_self([1, 1]) == [1, 1]

    assert candy([1, 0, 2]) == 5
    assert candy([1, 2, 2]) == 4
    assert candy([1, 3, 2, 2, 1]) == 7

    h1 = [0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]
    h2 = [4, 2, 0, 3, 2, 5]
    assert trap(h1) == trap_naive(h1) == 6
    assert trap(h2) == trap_naive(h2) == 9

    print("All tests passed.")
```

### Diagram 3 — The Backpropagation Analogy

The structural parallel between two-pass array traversal and neural network training:

```
── Neural network forward pass ──────────────────────────────────────────────

  Input x  →  [Layer 1]  →  [Layer 2]  →  [Layer 3]  →  Loss L
               cache a₁       cache a₂      cache a₃
               ↑               ↑              ↑
               "left context" deposited at each node during forward pass

── Neural network backward pass ─────────────────────────────────────────────

  ∂L/∂a₃  ←  [Layer 3]  ←  [Layer 2]  ←  [Layer 1]  ←  ∂L/∂L = 1
  (uses a₃)   (uses a₂)     (uses a₁)
     ↑
     "right context" (upstream gradient) flows right-to-left
     Combined with cached "left context" (activation) → local gradient

── Array analogy ────────────────────────────────────────────────────────────

  Array index i  →  left[i] (forward)  +  right[i] (backward)  →  answer[i]
  Layer l        →  activation aₗ (forward)  +  δₗ (backward)  →  ∂L/∂Wₗ

  Both are: forward pass deposits state; backward pass uses state + upstream.
```

This is not a loose analogy — it is the same algorithmic structure. See [[215.Gradient computation as a graph traversal — autograd intuition]].

## 7. Common Variations & Extensions

### Variation 1 — Three-Pass Problems

Some problems require three passes: a forward pass, a backward pass, and a second forward pass to handle tie-breaking or plateau conditions. The classic example is `candy` with a variant where equal ratings also require non-decreasing allocations in one direction. The structure extends cleanly: add a third pass to resolve any conflicts introduced by the second pass. This is rare but appears occasionally in harder greedy problems.

### Variation 2 — Two-Pass on a 2D Grid

The 2D version: a forward pass fills each cell using its top and left neighbours; a backward pass fills using bottom and right neighbours. This is the basis of [[07.2D prefix sum — submatrix sum queries]], where the prefix sum is built by a two-pass sweep over rows then columns (or equivalently, a single pass that uses both the cell above and the cell to the left).

### Variation 3 — Two-Pass for Running Statistics (Welford)

Computing variance in a single pass with numerical stability requires the Welford online algorithm, which is structurally a single-pass accumulator — but some distributed implementations require a forward pass to compute the mean and a backward pass (over batches) to compute the variance relative to that mean. This shows up in PyTorch's `torch.var()` when called on large tensors split across devices.

### Variation 4 — Two-Pass String Problems

Some string problems require a forward pass to build a left character state and a backward pass to build a right character state. Example: "find all indices where the character is unique in both its left and right context." The left state is a frequency map of characters seen so far; the right state is a frequency map of characters to the right. This connects to [[13.Sliding window with frequency map — character problems]] and [[20.Character frequency arrays — fixed alphabet O(1) space]].

## 9. CP Contest Application

### Typical Problem Structure

**Codeforces Div. 2 C / Div. 3 D archetype:**

> "You have an array of n integers. For each position i, compute `f(i)` where `f(i)` depends on the maximum element to the left of i and the minimum element to the right of i. Output the sum of all `f(i)`."

This is a textbook two-pass: forward pass builds `left_max[i]`; backward pass builds `right_min[i]`; a final O(n) combination pass computes the sum. Three total passes, all O(n).

**Harder variant (Div. 2 D):** The combining function at each index is not just `max/min` but involves a second constraint that was set by the forward pass and must be _respected_ (not overwritten) by the backward pass. This is the `candy`-style problem. The key insight — use `max` to combine, not assignment — is the non-obvious step that separates accepted from wrong-answer.

### Time Limits

Two-pass solutions for n ≤ 10⁶ run in ~20ms in C++ with `-O2`. The constant factor is twice that of a single pass (2n operations) but well within the typical 1–2 second limit.

**Trap:** Using `std::accumulate` or Python's `sum()` at the end of the backward pass adds a third O(n) scan. This is fine for correctness but unnecessary — you can accumulate the sum during the backward pass itself by adding `out[i]` to a running total as you update it. At n = 10⁷ this saves ~30ms and can matter.

### Optimisation Tricks

- **Combine the three passes into two:** If the combination step (`f(left[i], right[i])`) is commutative, you can fold it into the backward pass, processing the output array in-place while keeping a `running` accumulator. This eliminates the third pass entirely and halves memory writes.
- **Avoid materialising both arrays:** In the product-except-self and rainwater patterns, only the forward array needs to be materialised. The backward array can always be collapsed into a running scalar, saving O(n) memory. This matters for n = 10⁷ where the memory bandwidth of two large array reads dominates runtime.
- **SIMD note:** Forward and backward passes are inherently sequential (each iteration depends on the previous). Unlike embarrassingly parallel operations, these cannot be trivially vectorised. This is why hardware-optimised implementations of backpropagation (in cuDNN) use more complex algorithms rather than a naive two-pass.
