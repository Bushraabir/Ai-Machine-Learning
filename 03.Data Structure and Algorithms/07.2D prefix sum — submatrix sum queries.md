# 07. 2D Prefix Sum — Submatrix Sum Queries

> _"Precompute once. Answer forever."_

---

## The Problem We Are Solving

You have a 2D grid (matrix) of numbers. Someone asks you:

> "What is the sum of all elements in the rectangle from row $r_1$, column $c_1$ to row $r_2$, column $c_2$?"

They ask this **ten thousand times** on different rectangles.

**Naïve approach:** For each query, loop through every cell in the rectangle and add them up.

- Each query costs $O((r_2 - r_1) \times (c_2 - c_1))$ — could be $O(N^2)$ per query.
- $10^4$ queries on a $10^3 \times 10^3$ grid = $10^{10}$ operations. **Too slow.**

**2D Prefix Sum approach:** Precompute a helper table in $O(NM)$ once. Then answer **every** query in $O(1)$.

---

## The 1D Intuition First

Before going 2D, recall the 1D version.

For array `A = [3, 1, 4, 1, 5, 9]`, build a prefix sum `P` where:

$$P[i] = A[0] + A[1] + \cdots + A[i-1]$$

```
Index:  0   1   2   3   4   5
A:      3   1   4   1   5   9
P:      0   3   4   8   9  14  23
```

Sum of `A[2..4]` = `P[5] - P[2]` = `14 - 4` = `10`. Done in $O(1)$.

**The key idea:** A range sum is just the difference of two prefix sums. We extend this exact idea to two dimensions.

---

## Building the 2D Prefix Sum Table

### Definition

Given a matrix $A$ of size $N \times M$, define:

$$P[i][j] = \sum_{r=0}^{i-1} \sum_{c=0}^{j-1} A[r][c]$$

In plain English: **$P[i][j]$ is the sum of all elements in the rectangle from $(0,0)$ to $(i-1, j-1)$.**

We use 1-indexed $P$ with a padding row and column of zeros at the top and left. This is the standard trick to avoid edge-case checks.

```
     col→  0   1   2   3   4
row↓
  0         0   0   0   0   0     ← padding row
  1         0  P11 P12 P13 P14
  2         0  P21 P22 P23 P24
  3         0  P31 P32 P33 P34
  4         0  P41 P42 P43 P44
```

### The Recurrence

To fill $P$, use the **inclusion-exclusion principle**:

$$P[i][j] = A[i-1][j-1] + P[i-1][j] + P[i][j-1] - P[i-1][j-1]$$

**Why subtract $P[i-1][j-1]$?**

Because $P[i-1][j]$ and $P[i][j-1]$ both include the top-left rectangle $P[i-1][j-1]$. We added it twice, so we subtract it once.

```
┌─────────────┬────────┐
│             │        │
│  P[i-1][j-1]│        │  ← P[i-1][j]
│             │        │
├─────────────┼────────┤
│             │A[i-1]  │
│  P[i][j-1]  │ [j-1]  │
└─────────────┴────────┘
                P[i][j]  = top + left - top-left + current cell
```

### Python Implementation

```python
import numpy as np

def build_2d_prefix(A):
    """
    A: 2D list or numpy array, shape (N, M)
    Returns P: numpy array, shape (N+1, M+1), 1-indexed with zero padding
    """
    A = np.array(A, dtype=np.int64)
    N, M = A.shape
    P = np.zeros((N + 1, M + 1), dtype=np.int64)

    for i in range(1, N + 1):
        for j in range(1, M + 1):
            P[i][j] = (A[i-1][j-1]
                       + P[i-1][j]
                       + P[i][j-1]
                       - P[i-1][j-1])
    return P

# ── Vectorised NumPy version (much faster) ──────────────────────────
def build_2d_prefix_fast(A):
    A = np.array(A, dtype=np.int64)
    P = np.zeros((A.shape[0] + 1, A.shape[1] + 1), dtype=np.int64)
    P[1:, 1:] = A
    P = P.cumsum(axis=0).cumsum(axis=1)   # two 1D prefix sums!
    return P
```

> `np.cumsum(axis=0)` gives prefix sums down each column. `np.cumsum(axis=1)` on the result gives prefix sums across each row. Two sequential 1D prefix sums = one 2D prefix sum. This is not a coincidence — it follows from the separability of the recurrence.

## Answering Queries in O(1)

**Query:** sum of all elements in rows $r_1 \ldots r_2$, columns $c_1 \ldots c_2$ (0-indexed in $A$).

Convert to 1-indexed $P$:

$$\text{sum} = P[r_2+1][c_2+1] - P[r_1][c_2+1] - P[r_2+1][c_1] + P[r_1][c_1]$$

Again inclusion-exclusion: you take the big rectangle, subtract the top strip, subtract the left strip, then add back the top-left corner that you subtracted twice.

```python
def query(P, r1, c1, r2, c2):
    """
    All indices are 0-based in the original matrix A.
    P is the (N+1) x (M+1) prefix table.
    """
    return (P[r2+1][c2+1]
            - P[r1][c2+1]
            - P[r2+1][c1]
            + P[r1][c1])
```

### Concrete Example

```
A =
  [1, 2, 3, 4]
  [5, 6, 7, 8]
  [9, 0, 1, 2]

Query: sum of rows 0..1, cols 1..2  →  expected: 2+3+6+7 = 18
```

```python
A = [[1,2,3,4],
     [5,6,7,8],
     [9,0,1,2]]

P = build_2d_prefix_fast(A)
print(P)
# [[ 0  0  0  0  0]
#  [ 0  1  3  6 10]
#  [ 0  6 14 24 36]
#  [ 0 15 23 34 48]]

print(query(P, 0, 1, 1, 2))   # → 18  ✓
```

## The Geometry — Why It Works

Label the four corners of the query rectangle:

```
        c1        c2+1
   r1   ┌──────────┐
        │  query   │
   r2+1 └──────────┘
```

In the prefix table $P$:

|Term|What it represents|
|---|---|
|$P[r_2+1][c_2+1]$|Everything from $(0,0)$ to $(r_2, c_2)$|
|$-P[r_1][c_2+1]$|Remove the top strip above the query|
|$-P[r_2+1][c_1]$|Remove the left strip to the left of the query|
|$+P[r_1][c_1]$|Add back the top-left corner removed twice|

This is just the **2D version of $P[b] - P[a]$** from 1D.

---

## Proof of the Recurrence

**Claim:** $P[i][j] = A[i-1][j-1] + P[i-1][j] + P[i][j-1] - P[i-1][j-1]$

**Proof:** By the definition $P[i][j] = \sum_{r < i} \sum_{c < j} A[r][c]$,

$$P[i][j] = \sum_{r=0}^{i-1} \sum_{c=0}^{j-1} A[r][c]$$

Split off the last row and last column:

$$= A[i-1][j-1] + \sum_{r=0}^{i-2}\sum_{c=0}^{j-1} A[r][c] + \sum_{r=0}^{i-1}\sum_{c=0}^{j-2} A[r][c] - \sum_{r=0}^{i-2}\sum_{c=0}^{j-2} A[r][c]$$

$$= A[i-1][j-1] + P[i-1][j] + P[i][j-1] - P[i-1][j-1] \qquad \blacksquare$$

## Complexity

||Time|Space|
|---|---|---|
|Build prefix table|$O(NM)$|$O(NM)$|
|Single query|$O(1)$|—|
|$Q$ queries|$O(NM + Q)$|$O(NM)$|

Compare to naïve: $O(NM \cdot Q)$.

## Common Mistakes

```python
# Mistake 1: forgetting the +P[r1][c1] term
wrong = P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1]
# You subtracted the top-left corner twice. Add it back.

# Mistake 2: using 0-indexed P without padding
# → off-by-one errors at the boundary. Always use (N+1)×(M+1) P.

# Mistake 3: integer overflow with large values
# Use dtype=np.int64, not int32. A 1000×1000 grid of 10^9 values
# overflows int32 (max ~2.1×10^9). int64 handles up to ~9.2×10^18.

# Mistake 4: querying with r1 > r2 or c1 > c2
# Always assert r1 <= r2 and c1 <= c2 before querying.

# Mistake 5: modifying A after building P
# P is a snapshot. If A changes, you must rebuild P.
```

## Full Working Example

```python
import numpy as np

def build_2d_prefix_fast(A):
    A = np.array(A, dtype=np.int64)
    P = np.zeros((A.shape[0] + 1, A.shape[1] + 1), dtype=np.int64)
    P[1:, 1:] = A
    return P.cumsum(axis=0).cumsum(axis=1)

def query(P, r1, c1, r2, c2):
    return int(P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1])

# Matrix
A = [
    [ 3,  0,  1,  4,  2],
    [ 5,  6,  3,  2,  1],
    [ 1,  2,  0,  1,  5],
    [ 4,  1,  0,  1,  7],
    [ 1,  0,  3,  0,  5],
]

P = build_2d_prefix_fast(A)

# Sum of rows 1..3, cols 1..3
# Manual: 6+3+2 + 2+0+1 + 1+0+1 = 16
print(query(P, 1, 1, 3, 3))   # 16 ✓

# Entire matrix
print(query(P, 0, 0, 4, 4))   # 59 ✓

# Single cell A[2][3]
print(query(P, 2, 3, 2, 3))   # 1 ✓
```

## Variations Worth Knowing

**Difference array (inverse operation):** If you want to _add_ a constant $v$ to every cell in a rectangle and then recover the final matrix, build a difference array instead and apply prefix sums at the end. The exact inverse of this technique.

**3D prefix sum:** Extend to a 3D grid — sum of a rectangular box in $O(1)$ using an $O(N^3)$ precomputation. The recurrence has $2^3 - 1 = 7$ terms (inclusion-exclusion on 3 dimensions).

**Rolling prefix (space optimised):** If you only ever query full rows, you can keep only one extra row at a time.

---

## Connection to AI / ML / Deep Learning

This is not an academic curiosity. 2D prefix sums appear in the core of modern vision systems.

**Integral images (Viola-Jones face detector, 2001):** The first real-time face detector used integral images — which _are_ 2D prefix sums — to compute Haar-like features in $O(1)$ per feature rectangle instead of $O(k^2)$. This made detecting faces in video practical for the first time.

**Summed Area Tables in CNNs:** Pooling operations (average pooling over a patch) can be computed in $O(1)$ per patch using a prefix table built once per feature map.

**Attention mask computation:** When computing cumulative attention sums over a 2D attention map, prefix sums reduce the complexity from $O(N^2 \cdot K)$ to $O(N^2 + K)$ per layer.

**Data augmentation / patch sampling:** Efficient random sampling of image patches with a minimum sum constraint (e.g., "sample patches with at least $t$ active pixels") is done in $O(1)$ per candidate patch using a prefix table.

**General rule:** Any time you are doing repeated aggregation queries over fixed data in ML pipelines — feature maps, attention scores, token embeddings — ask whether a prefix structure can precompute the work.
