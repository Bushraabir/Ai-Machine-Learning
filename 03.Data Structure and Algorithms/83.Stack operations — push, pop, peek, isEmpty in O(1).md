## 1. Intuition First

### The Core Idea

Imagine a stack of dinner plates. You can only ever add a new plate to the top, take a plate from the top, or glance at the top plate without removing it. You cannot reach into the middle. You cannot add to the bottom. The structure enforces one rule: **the last plate placed is the first plate removed** — LIFO, Last In First Out.

This single constraint turns out to be extraordinarily useful. Every time a process needs to _undo the most recent thing_ or _defer work until later and then process it in reverse order_, the stack is the natural data structure.

The "dinner plate" analogy maps cleanly to operations:

- **push(x)** — place plate `x` on top
- **pop()** — remove and return the top plate
- **peek()** — look at the top plate without removing it
- **isEmpty()** — check whether the stack has any plates at all

All four operations touch only the top of the stack. There is no scanning, no shifting, no searching. Each operation is $O(1)$ — constant time, regardless of how many elements are already in the stack.

### Why This Exists

The naive alternative to a stack is a plain array with a variable tracking the "current top." That _is_ essentially what a stack is — but abstracting it into an ADT (Abstract Data Type) forces discipline: callers cannot accidentally index into the middle, cannot pop without checking emptiness, cannot confuse the top index. The abstraction makes bugs impossible by construction.

The deeper reason stacks exist: **recursion and call stacks**. When your CPU executes a function call, it pushes a stack frame; when the function returns, it pops that frame. The stack is not a convenience — it is the actual mechanism by which function calls work in hardware. Understanding a stack means understanding how your own code executes.

### The "Aha" Moment

A stack is not "an array with restrictions." It is **the canonical way to reverse order**. Push a sequence in order A→B→C; pop it and you get C→B→A. This reversal property is the engine behind bracket matching, expression evaluation, DFS, undo systems, and the call stack itself. Every algorithm that needs to "come back to something in reverse order" is secretly using a stack.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

Stacks appear in CP when you need to:

- Process elements in reverse arrival order
- Remember context while descending into a subproblem (DFS, parsing)
- Find the nearest "dominant" element to the left or right (monotonic stack — see [[87.Monotonic increasing stack — next greater element]])

**Signal patterns:**

- "Valid parentheses / bracket matching" → immediate stack
- "Evaluate an expression" → two-stack approach (operators + operands)
- "Next greater / smaller element" → monotonic stack variant
- "Implement a function that requires undo" → stack
- Any DFS problem where you convert recursion to iterative form → explicit stack

**Common trap:** Forgetting to check `isEmpty()` before `pop()` or `peek()`. In C++ this is undefined behaviour on an empty `std::stack`; in Python it throws `IndexError`. One unchecked pop on an empty stack kills your submission. Always guard.

**Second trap:** Using a `std::vector` directly and treating `back()` as peek. This works, but you lose the semantic contract — the reviewer (and your future self) cannot immediately see "this is a stack," and you risk accidentally accessing non-top elements.

### Machine Learning / AI

Stacks appear in ML systems in several specific, non-obvious ways:

**1. The call stack is the autograd engine.** PyTorch's `autograd` records a computation graph during the forward pass. During `.backward()`, it traverses this graph in reverse topological order — a process that is structurally equivalent to draining a stack of deferred gradient computations. The `torch.autograd.Function` mechanism pushes `ctx` (saved tensors, saved constants) onto a conceptual stack during forward, then pops and uses it during backward. See [[215.Gradient computation as a graph traversal — autograd intuition]].

**2. Recursive model architectures.** Parsing models (e.g., RNNG — Recurrent Neural Network Grammars by Dyer et al., 2016) maintain an explicit stack data structure as a differentiable component. The stack holds partially built parse trees; push and pop operations are differentiable via stack LSTMs. The stack ADT here is not metaphorical — it is a literal tensor-valued stack inside the model.

**3. Beam search and DFS decoding.** Some decoding strategies for sequence models use depth-first exploration of the token tree, implemented with an explicit stack rather than the more common BFS beam. Stack-based DFS decoding is common in constrained generation (e.g., generating valid JSON or code).

**4. Data pipeline orchestration.** ML workflow tools like Apache Airflow and Prefect maintain a call stack of nested task contexts — when you enter a `with Flow():` block and then a `with task():` block, those contexts are pushed/popped from a thread-local stack. Understanding this is why `with` blocks in these frameworks behave exactly like function scopes.

Understanding the stack at the ADT level makes all of the above legible rather than magical.

## 3. Algorithm / Pattern

### Step-by-step Logic

A stack maintains a collection of elements with a single access point: the **top**.

**Internal representation:** An array (dynamic or fixed-size) with an integer `top` that tracks the index of the most recently pushed element. Alternatively, a linked list where the head is the top.

**push(x):**

1. If using a fixed-size array, check capacity. If full, either error or resize.
2. Increment `top`.
3. Write `x` at `array[top]`.

**pop():**

1. If `isEmpty()`, raise an error (undefined behaviour to pop nothing).
2. Read `array[top]` into a temporary variable.
3. Decrement `top` (the slot is now logically empty; no need to zero it).
4. Return the temporary.

**peek():**

1. If `isEmpty()`, raise an error.
2. Return `array[top]` without modifying `top`.

**isEmpty():**

1. Return `top == -1` (for array-based) or `head == nullptr` (for linked-list-based).

### Decision Tree

```
Do you need LIFO access?
├─ Yes → Stack
│   ├─ Fixed maximum size known? → Array-based stack (cache friendly, no allocation)
│   └─ Dynamic size needed?     → std::stack (backed by deque) or Python list
└─ No → Probably not a stack. Check Queue, Deque, HashMap.

Before every pop/peek:
└─ isEmpty()? → Error/return sentinel
```

### Complexity

|Operation|Time|Space|
|---|---|---|
|push|$O(1)$ amortised*|$O(1)$|
|pop|$O(1)$|$O(1)$|
|peek|$O(1)$|$O(1)$|
|isEmpty|$O(1)$|$O(1)$|
|**Total space**|—|$O(n)$ for $n$ elements|

*Amortised $O(1)$ for dynamic arrays due to occasional $O(n)$ resize, which is amortised across $n$ pushes.

**Derivation of $O(1)$:** Every operation modifies only the `top` pointer (or the head pointer in a linked list) and accesses at most one array slot. There is no loop, no comparison against other elements, no traversal. Hence constant time regardless of stack size.

## 4. Pseudocode

```
class Stack:
    array[0..MAX-1]  // backing store
    top = -1         // -1 signals empty stack

    // Add element to top
    procedure push(x):
        if top == MAX - 1:
            raise OverflowError       // fixed-size variant
        top ← top + 1
        array[top] ← x
        // Why top+1 first? Because top=-1 means empty;
        // after first push, top=0, array[0] holds the element.

    // Remove and return top element
    procedure pop() → element:
        if top == -1:
            raise UnderflowError      // always guard before pop
        element ← array[top]
        top ← top - 1                 // logically remove; no need to zero
        return element

    // Inspect top without removing
    procedure peek() → element:
        if top == -1:
            raise UnderflowError
        return array[top]

    // O(1) emptiness check
    procedure isEmpty() → bool:
        return top == -1

    // Optional: current count of elements
    procedure size() → int:
        return top + 1
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <stdexcept>
#include <vector>
#include <stack>

// ── Option A: Custom array-based stack (educational, cache-friendly) ──────────
template<typename T>
class ArrayStack {
    std::vector<T> data_;

public:
    // push: amortised O(1) via vector growth
    void push(const T& val) {
        data_.push_back(val);
    }

    // pop: O(1) — removes top element
    T pop() {
        if (isEmpty())
            throw std::underflow_error("pop() called on empty stack");
        T top = data_.back();
        data_.pop_back();
        return top;
    }

    // peek: O(1) — const; does not modify stack
    const T& peek() const {
        if (isEmpty())
            throw std::underflow_error("peek() called on empty stack");
        return data_.back();
    }

    bool isEmpty() const { return data_.empty(); }
    std::size_t size() const { return data_.size(); }
};

// ── Option B: std::stack (production use — backed by std::deque) ──────────────
// std::stack<int> s;
// s.push(42);
// s.top();      // peek
// s.pop();      // void — does not return value!
// s.empty();    // isEmpty

// ── Demonstration ─────────────────────────────────────────────────────────────
int main() {
    ArrayStack<int> s;

    s.push(10);
    s.push(20);
    s.push(30);

    std::cout << "Peek: " << s.peek() << "\n";  // 30
    std::cout << "Pop:  " << s.pop()  << "\n";  // 30
    std::cout << "Pop:  " << s.pop()  << "\n";  // 20
    std::cout << "Size: " << s.size() << "\n";  // 1

    // Reverse a sequence using a stack
    std::vector<int> input = {1, 2, 3, 4, 5};
    std::stack<int> reverser;
    for (int x : input) reverser.push(x);

    std::vector<int> reversed;
    while (!reverser.empty()) {
        reversed.push_back(reverser.top());
        reverser.pop();          // std::stack::pop() is void — get top first!
    }
    // reversed == {5, 4, 3, 2, 1}
    for (int x : reversed) std::cout << x << " ";
    std::cout << "\n";

    return 0;
}
```

**Critical C++ note:** `std::stack::pop()` returns `void`, unlike most educational stack ADTs. You must call `top()` first, _then_ `pop()`. Forgetting this is a common source of bugs when porting pseudocode to C++.

### Python (Readable + Pythonic)

```python
from typing import TypeVar, Generic, Optional

T = TypeVar('T')


class Stack(Generic[T]):
    """
    LIFO stack backed by a Python list.
    
    All operations are O(1) amortised.
    list.append() and list.pop() are O(1) amortised in CPython
    because list is a dynamic array with 1.125x growth factor.
    """

    def __init__(self) -> None:
        self._data: list[T] = []

    def push(self, val: T) -> None:
        """Add element to top of stack."""
        self._data.append(val)

    def pop(self) -> T:
        """Remove and return top element. Raises IndexError if empty."""
        if self.is_empty():
            raise IndexError("pop from empty stack")
        return self._data.pop()  # list.pop() removes last element — O(1)

    def peek(self) -> T:
        """Return top element without removing it. Raises IndexError if empty."""
        if self.is_empty():
            raise IndexError("peek on empty stack")
        return self._data[-1]    # negative indexing: O(1)

    def is_empty(self) -> bool:
        return len(self._data) == 0

    def size(self) -> int:
        return len(self._data)

    def __repr__(self) -> str:
        return f"Stack({self._data})"


# ── In practice: Python list IS a stack ──────────────────────────────────────
# Most CP and production code skips the wrapper and uses list directly:

def demo_raw_list_as_stack() -> None:
    s: list[int] = []

    s.append(10)   # push
    s.append(20)
    s.append(30)

    print(s[-1])   # peek  → 30
    print(s.pop()) # pop   → 30
    print(s.pop()) # pop   → 20
    print(bool(s)) # not empty → True

    # Reverse a sequence: O(n) pushes + O(n) pops
    seq = [1, 2, 3, 4, 5]
    stack = list(seq)          # push all at once
    reversed_seq = [stack.pop() for _ in range(len(stack))]
    print(reversed_seq)        # [5, 4, 3, 2, 1]


# ── Validate brackets using a stack ──────────────────────────────────────────
def is_valid_brackets(s: str) -> bool:
    """
    Classic application: O(n) time, O(n) space.
    Directly leads to LC 20 (Valid Parentheses).
    """
    stack: list[str] = []
    match = {')': '(', ']': '[', '}': '{'}

    for ch in s:
        if ch in '([{':
            stack.append(ch)
        elif ch in ')]}':
            if not stack or stack[-1] != match[ch]:
                return False
            stack.pop()

    return len(stack) == 0  # empty stack = all brackets matched


if __name__ == "__main__":
    demo_raw_list_as_stack()
    print(is_valid_brackets("({[]})"))  # True
    print(is_valid_brackets("({[})"))   # False
```

## 7. Common Variations & Extensions

### Variation 1: Stack with O(1) Minimum/Maximum

Augment the stack with a parallel "min-stack" that tracks the running minimum. Each push records both the element _and_ the current minimum up to that point. Each pop removes from both stacks simultaneously.

This is the core insight behind LC 155 (Min Stack). The space cost is $O(n)$ for the auxiliary stack. Connects to [[152.k-th largest element — heap vs quickselect]] where you need order statistics efficiently.

### Variation 2: Monotonic Stack

Restrict the stack so that elements are always in non-increasing (or non-decreasing) order from bottom to top. When pushing a new element, first pop all elements that violate the monotonicity property. This gives you the **next greater element** for every popped item at pop time — a single $O(n)$ pass replaces the naive $O(n^2)$ double loop.

Full coverage: [[87.Monotonic increasing stack — next greater element]], [[89.Largest rectangle in histogram — the canonical monotonic stack problem]].

### Variation 3: Two-Stack Queue (Amortised O(1) Dequeue)

Simulate a queue using two stacks: an `inbox` and an `outbox`. Push always goes to `inbox`. Pop (dequeue) pulls from `outbox`; if `outbox` is empty, pour all of `inbox` into `outbox` (reversing the order). Each element is moved at most once, giving amortised $O(1)$ per operation. This pattern appears in LC 232 and connects to [[92.Queue operations — enqueue, dequeue, FIFO]].

### Variation 4: Iterative DFS via Explicit Stack

Recursive DFS implicitly uses the call stack. Replacing it with an explicit stack gives you:

- Control over stack depth (avoid stack overflow on deep graphs)
- Ability to pause and resume traversal (useful in streaming/coroutine systems)
- The exact traversal pattern used in PyTorch's backward pass

See [[112.Depth-First Search (DFS) — recursive and iterative]] and [[215.Gradient computation as a graph traversal — autograd intuition]].

## 9. CP Contest Application

### Codeforces / AtCoder Problem Structure

Stack problems in competitive programming fall into three archetypes:

**Archetype 1 — Simulation of LIFO process.** Problem describes a sequence of push/pop operations; you simulate them. Usually Div. 3 / Div. 2 A-B difficulty. Time limit: 1s, up to $n = 10^6$ operations. Use `std::stack` or `vector`. Complexity must be $O(n)$ — no nested loops.

**Archetype 2 — Expression parsing / bracket problems.** Count or validate nested structures. Codeforces Div. 2 B-C. The trick is always "push on open, match on close." Watch for problems with multiple bracket types or weighted scores per nesting level.

**Archetype 3 — Monotonic stack for range queries.** These appear at Div. 2 C-D / Div. 1 A-B level. The tell: the problem asks about "the nearest element to the left/right satisfying property P." Naive $O(n^2)$ TLEs at $n = 10^5$. Monotonic stack does it in $O(n)$.

### Optimization Tricks

- **In C++ CP code:** `std::stack` is backed by `std::deque` by default, which is slower than vector for cache access. Prefer `std::stack<int, std::vector<int>>` to use a vector backend.
- **Reserve capacity:** If you know the stack will hold at most $n$ elements, call `data.reserve(n)` before the loop. Eliminates all reallocations.
- **Avoid `std::stack` in tight loops:** For performance-critical monotonic stack implementations, use a plain `int stk[MAXN]` array with an `int top = -1` index. This is zero-overhead and maximally cache-friendly.

```cpp
// Fast CP-style monotonic stack (no STL overhead)
const int MAXN = 1e5 + 5;
int stk[MAXN], top_idx = -1;

// push
stk[++top_idx] = x;

// pop
int val = stk[top_idx--];

// peek
int val = stk[top_idx];

// isEmpty
if (top_idx == -1) { /* empty */ }
```
