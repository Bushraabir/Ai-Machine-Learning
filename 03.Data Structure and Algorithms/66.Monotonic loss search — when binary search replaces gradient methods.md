## 1. Intuition First

### The Core Idea

Gradient descent is the hammer of ML optimisation. Given a loss surface, compute the gradient, step downhill, repeat. It is powerful, general, and almost universally applied. But it has a silent prerequisite: the loss must be **differentiable** at the operating point, and the gradient must point toward the optimum with enough fidelity to guide convergence.

Now consider a different situation: you are not searching over a continuous weight space — you are searching over a **single scalar parameter**, and you know the loss is **monotone** (or the feasibility condition flips exactly once) in that parameter. The loss decreases as the parameter increases, then stops decreasing, or vice versa. In this case, gradient descent is not just unnecessary — it is the wrong tool. You do not need a gradient. You need a **comparison**. And binary search gives you the answer in `O(log n)` evaluations instead of `O(n)`.

The real insight is about _what structure you are exploiting_. Gradient descent exploits the geometry of the loss surface — specifically its local differentiable structure — to take steps of decreasing size toward a minimum. Binary search exploits **global monotone structure** — the fact that the answer space has a clean split between "too low" and "too high". These are different structures. When the monotone structure is present, binary search is strictly superior: fewer evaluations, no learning rate to tune, no risk of oscillation or saddle points, and an exact convergence guarantee.

### Why This Exists

There is a class of ML problems where the "parameter" being optimised is not a neural network weight but a **decision variable** with a monotone relationship to a metric: a threshold, a budget, a regularisation coefficient, a temperature, a margin. For these, practitioners reflexively reach for gradient methods (or worse, grid search), not realising the structure permits something much cheaper.

The gap is stark: gradient descent on a 1D convex function converges in `O(1/ε)` steps for a first-order method and `O(1/√ε)` for accelerated methods. Binary search converges in `O(log(1/ε))` steps — a qualitatively different rate. For `ε = 10⁻⁶`, gradient descent needs up to 10⁶ steps; binary search needs 20.

The reason practitioners miss this: they are not thinking about the _structure_ of what they are optimising — they are thinking about the _tool they already know_.

### The "Aha" Moment

Gradient descent solves: _"Which direction reduces the loss?"_

Binary search solves: _"Is the current value too high or too low?"_

**Both are oracle queries. But the binary search oracle is cheaper to implement and gives a global guarantee.** When your loss is monotone in a scalar, the gradient is just a more expensive way of answering the same question the binary search oracle answers directly. You do not need the magnitude of the gradient. You only need its sign. And the sign of the gradient of a monotone function is constant — which means one comparison suffices at each step, not a full backpropagation pass.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

In CP, "monotonic loss search" appears whenever the optimisation objective has the form: _minimise (or maximise) f(x) subject to g(x) ≤ c_, where `f` is monotone in `x` and `g(x) ≤ c` defines a feasibility boundary that flips exactly once.

**Pattern signal:**

- The problem asks for a minimum or maximum of some quantity.
- You can check in `O(n)` or `O(n log n)` whether a given value of that quantity is achievable.
- The achievability is monotone: if value `v` is achievable, all values `v' > v` (or `v' < v`) are also achievable.

This is the "binary search on answer" pattern from [[59.The binary search on answer template — monotonic predicate]], but the _loss-search framing_ makes the ML connection legible. In CP, the "loss" is the infeasibility signal — you are minimising the smallest feasible answer.

**Common trap:** In problems with floating-point answer spaces, the number of bisection iterations is often fixed (e.g., 100 iterations) rather than using a termination condition, because floating-point epsilon comparisons are fragile. This avoids infinite loops from rounding.

**When it matters most:** Codeforces Div. 2 C/D problems involving allocation, scheduling, or spatial arrangement. Also appears in interactive problems where the oracle is the judge itself.

### Machine Learning / AI

This is where the topic's real weight lies. Here are the specific settings where binary search **replaces** gradient methods:

**1. Threshold optimisation in classification**

After training a binary classifier, the output scores `s ∈ [0, 1]` are thresholded at `τ` to produce labels. The task: find `τ` such that recall ≥ 0.95 (a hard business constraint). Recall is monotone decreasing in `τ` (higher threshold → fewer positives → lower recall). Binary search on the sorted score array finds the exact `τ` in `O(log n)`. Gradient descent is inapplicable here — recall is not differentiable. This is standard practice in production ML systems.

**2. Temperature scaling for calibration (Guo et al., 2017)**

Neural networks are often overconfident. Temperature scaling divides the logits by a scalar `T` before softmax: `p = softmax(z / T)`. Higher `T` → softer distribution → lower confidence. The calibration loss (negative log-likelihood on a validation set) is convex and monotone in `T` for miscalibrated models. The original paper uses L-BFGS, but for the 1D case, bisection is simpler, has no hyperparameters, and converges in ~50 evaluations to machine precision. Several production calibration libraries (e.g., `netcal`) implement this as bisection.

**3. Lagrangian dual variable optimisation (constrained ML)**

Constrained optimisation problems of the form: minimise `L(θ)` subject to `c(θ) ≤ 0` are solved via Lagrangian duality: `min_θ max_λ L(θ) + λ·c(θ)`. For a fixed `θ`, the dual function `g(λ) = min_θ [L(θ) + λ·c(θ)]` is concave in `λ`. For convex problems, the dual gap is zero, and the optimal `λ*` can be found by bisection on `g'(λ) = c(θ*(λ))` — which is monotone by strong duality. This appears in fairness-constrained ML (Cotter et al., 2018), where each constraint introduces a dual variable found by bisection.

**4. Beam search width and length penalty (NLP)**

In sequence generation (Transformer beam search), the length penalty `α` controls the trade-off between sequence length and log-probability. For a fixed `α`, you can measure the average output length. Average length is monotone increasing in `α`. If you need a specific average output length (for a downstream budget constraint), binary search on `α` finds it in `O(log(range/ε))` beam search evaluations — far fewer than a grid sweep.

**5. Quantisation bit-width search**

In post-training quantisation, the quantisation error (measured by perplexity or task metric) is monotone in the bit-width `b`: more bits → less error. For a target perplexity budget, binary search finds the minimum bit-width achieving that budget. GPTQ (Frantar et al., 2022) and related work use variants of this reasoning for per-layer bit allocation.

**6. `scipy.optimize.brentq` — the production implementation**

`scipy.optimize.brentq` is Brent's method: a hybrid of bisection, secant method, and inverse quadratic interpolation. For ML practitioners, the critical insight is that `brentq` is called when you have a **root-finding** problem (find `x` where `f(x) = 0`) with a monotone `f` — exactly the structure of loss search. It is used internally in `sklearn`'s `calibration` module and in several SciPy statistical tests. Understanding that `brentq` is "smart bisection with superlinear convergence" demystifies a frequently encountered function.

## 3. Algorithm / Pattern

### The Core Structure

Monotonic loss search applies when three conditions hold simultaneously:

```
1. SCALAR DOMAIN:     The optimisation variable is a single scalar h ∈ [lo, hi].
2. MONOTONE METRIC:   The loss L(h) (or feasibility f(h)) is monotone in h.
3. ORACLE AVAILABLE:  You can evaluate L(h) at any point h, but computing
                      dL/dh is either impossible (non-differentiable) or
                      unnecessary (gradient sign is constant by monotonicity).
```

**Step-by-step logic:**

1. Identify the scalar parameter and its domain `[lo, hi]`.
2. Determine the direction of monotonicity: "as `h` increases, does the metric increase or decrease?"
3. Formulate the oracle: either
    - **Root-finding form:** `f(h) = 0` (e.g., find `T` where calibration error = 0)
    - **Threshold form:** `oracle(h) = (metric(h) ≥ target)` (e.g., find `τ` where recall ≥ 0.95)
4. Run bisection (or Brent's method for speed):
    - Maintain invariant: `f(lo)` and `f(hi)` have opposite signs (root-finding) or `oracle(lo) ≠ oracle(hi)` (threshold form).
    - Evaluate at `mid`, update the appropriate bound.
    - Terminate when `|hi - lo| < ε` or iteration budget exhausted.
5. Return the found value.

**When to use binary search instead of gradient descent:**

|Condition|Use Gradient Descent|Use Binary Search|
|---|---|---|
|Optimising over|High-dimensional weight space|Single scalar parameter|
|Loss structure|Differentiable (almost everywhere)|Monotone (or unimodal → ternary search)|
|Gradient computation|Cheap (backprop)|Expensive or undefined|
|Convergence guarantee|Local minimum only|Global optimum (for monotone case)|
|Hyperparameters needed|Learning rate, schedule, momentum|None (just domain bounds + ε)|
|Iterations to ε = 10⁻⁶|Up to 10⁶ (gradient) / 10³ (Newton)|~20 (bisection)|

**Decision tree:**

```
Is the loss differentiable at the operating point?
├── No (threshold, recall, F1) → Binary search (or ternary search if unimodal)
└── Yes
    ├── Is the optimisation 1D and monotone?
    │   ├── Yes → Binary search (fewer evaluations, no LR tuning, global guarantee)
    │   └── No → Gradient descent / Newton's method
    └── Is the optimisation 1D and convex but not monotone (unimodal)?
        └── Ternary search or Golden section search

Is the loss noisy (stochastic evaluations)?
└── Bisection on noisy oracles: average over k evaluations per query,
    or use robust bisection (Waeber et al., 2013): O(log n / k) with k samples.
```

**Complexity:**

- **Bisection:** `O(log₂((hi - lo) / ε))` evaluations. For `hi - lo = 10`, `ε = 10⁻⁶`: 23 evaluations.
- **Brent's method:** same worst case as bisection, but superlinear convergence near the root (typically 10–15 evaluations in practice for smooth functions).
- **Gradient descent (1D convex):** `O((hi - lo)² / (ε · μ))` iterations for µ-strongly convex loss, where each iteration requires a gradient evaluation.
- **Grid search over `n` points:** `O(n)` evaluations, no guarantee of finding exact boundary.

## 4. Pseudocode

```
MONOTONIC_LOSS_SEARCH(lo, hi, loss_fn, target, epsilon, direction):
    """
    Find h* in [lo, hi] such that loss_fn(h*) = target.
    
    direction = +1: loss_fn is monotone increasing in h
    direction = -1: loss_fn is monotone decreasing in h
    
    Equivalently (root-finding form): find h* where f(h) = loss_fn(h) - target = 0.
    
    Invariant: f(lo) * f(hi) < 0  (opposite signs — bracket exists)
    """
    
    f_lo = loss_fn(lo) - target
    f_hi = loss_fn(hi) - target
    
    # Validate bracket: signs must be opposite for bisection to work
    if f_lo * f_hi > 0:
        return ERROR("No bracket: loss_fn(lo) and loss_fn(hi) are on the same side of target")
    if abs(f_lo) < epsilon:
        return lo    # lo is already a solution
    if abs(f_hi) < epsilon:
        return hi    # hi is already a solution
    
    # Bisection loop
    # Invariant: f(lo) < 0 < f(hi)  (or the reverse, depending on direction)
    while (hi - lo) > epsilon:
        mid = lo + (hi - lo) / 2.0
        f_mid = loss_fn(mid) - target
        
        if abs(f_mid) < epsilon:
            return mid    # Close enough — converged
        
        # Update bracket: preserve the invariant that lo and hi straddle the root
        if sign(f_lo) == sign(f_mid):
            lo = mid      # mid is on the same side as lo; move lo up
            f_lo = f_mid
        else:
            hi = mid      # mid is on the same side as hi; move hi down
    
    return (lo + hi) / 2.0    # Midpoint of final bracket


BRENT_METHOD(lo, hi, f, epsilon):
    """
    Brent's method: bisection with superlinear acceleration.
    Uses inverse quadratic interpolation when the interpolant stays within bounds;
    falls back to bisection when it doesn't. Guaranteed O(log(1/epsilon)) worst case.
    
    This is what scipy.optimize.brentq implements.
    Use this in production when:
    - f is smooth near the root (get superlinear speedup)
    - You need a robust fallback guarantee (bisection backstop)
    """
    
    # Initialise with guaranteed bracket [a, b]
    a, b = lo, hi
    fa, fb = f(a), f(b)
    assert fa * fb < 0, "f(lo) and f(hi) must have opposite signs"
    
    c, fc = a, fa    # c is the previous iterate
    
    while abs(b - a) > epsilon and abs(fb) > epsilon:
        
        # Try inverse quadratic interpolation (IQI) if three distinct points available
        if fa != fc and fb != fc:
            # IQI: fit quadratic through (a, fa), (b, fb), (c, fc), find root
            s = (a * fb * fc / ((fa - fb) * (fa - fc))
               + b * fa * fc / ((fb - fa) * (fb - fc))
               + c * fa * fb / ((fc - fa) * (fc - fb)))
        else:
            # Secant step: linear interpolation
            s = b - fb * (b - a) / (fb - fa)
        
        # Bisect if IQI/secant step is out of bounds or converging too slowly
        if not (3*a + b) / 4 < s < b:
            s = (a + b) / 2.0    # Fall back to bisection
        
        fs = f(s)
        c, fc = b, fb    # Update history
        
        if fa * fs < 0:
            b, fb = s, fs    # Root is in [a, s]
        else:
            a, fa = s, fs    # Root is in [s, b]
        
        if abs(fa) < abs(fb):
            a, b = b, a    # Keep b as the best approximation
            fa, fb = fb, fa
    
    return b
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <functional>
#include <cmath>
#include <stdexcept>
#include <vector>
#include <algorithm>
#include <numeric>

/**
 * MonotonicLossSearch
 *
 * Finds h* in [lo, hi] such that loss_fn(h*) ≈ target.
 * Uses bisection (guaranteed) with optional Brent acceleration.
 *
 * Template parameter T: float or double.
 *
 * Complexity: O(log((hi - lo) / epsilon)) loss_fn evaluations.
 * No gradient required. No learning rate to tune.
 * Global convergence guarantee (unlike gradient descent).
 */

template<typename T>
struct SearchResult {
    T value;
    T loss_at_value;
    int evaluations;
    bool converged;
};

// ─────────────────────────────────────────────────────────────────
// Core bisection: find root of f(h) = loss_fn(h) - target = 0
// ─────────────────────────────────────────────────────────────────
template<typename T>
SearchResult<T> bisection_loss_search(
    T lo,
    T hi,
    std::function<T(T)> loss_fn,
    T target,
    T epsilon = static_cast<T>(1e-7),
    int max_iter = 100
) {
    auto f = [&](T h) { return loss_fn(h) - target; };

    T f_lo = f(lo);
    T f_hi = f(hi);
    int evals = 2;

    // Bracket check: the root must be bracketed
    if (f_lo * f_hi > 0) {
        throw std::runtime_error(
            "No bracket: loss_fn(lo) and loss_fn(hi) are on the same side of target. "
            "Either the function is not monotone, or target is outside [loss(lo), loss(hi)]."
        );
    }

    if (std::abs(f_lo) < epsilon) return {lo, loss_fn(lo), evals, true};
    if (std::abs(f_hi) < epsilon) return {hi, loss_fn(hi), evals, true};

    // Ensure f(lo) < 0 < f(hi) for consistent logic
    // If reversed, swap (monotone decreasing case)
    if (f_lo > 0) {
        std::swap(lo, hi);
        std::swap(f_lo, f_hi);
    }

    // Invariant: f(lo) <= 0 <= f(hi)
    for (int iter = 0; iter < max_iter; ++iter) {
        if (hi - lo <= epsilon) break;

        T mid = lo + (hi - lo) / static_cast<T>(2);  // Numerically safe
        T f_mid = f(mid);
        evals++;

        if (std::abs(f_mid) < epsilon) {
            return {mid, loss_fn(mid), evals, true};
        }

        if (f_mid < 0) {
            lo = mid;    // f(mid) < 0: mid is on the lo side
            f_lo = f_mid;
        } else {
            hi = mid;    // f(mid) > 0: mid is on the hi side
            f_hi = f_mid;
        }
    }

    T best = (lo + hi) / static_cast<T>(2);
    return {best, loss_fn(best), evals, (hi - lo) <= epsilon};
}


// ─────────────────────────────────────────────────────────────────
// Brent's method: bisection + superlinear acceleration
// scipy.optimize.brentq is this algorithm
// ─────────────────────────────────────────────────────────────────
template<typename T>
SearchResult<T> brent_loss_search(
    T lo,
    T hi,
    std::function<T(T)> loss_fn,
    T target,
    T epsilon = static_cast<T>(1e-7),
    int max_iter = 100
) {
    auto f = [&](T h) { return loss_fn(h) - target; };

    T a = lo, b = hi;
    T fa = f(a), fb = f(b);
    int evals = 2;

    if (fa * fb > 0) {
        throw std::runtime_error("Brent: no bracket found. f(lo) and f(hi) must have opposite signs.");
    }

    T c = a, fc = fa;
    T d = b - a, e = d;

    for (int iter = 0; iter < max_iter; ++iter) {
        if (fb * fc > 0) {
            c = a; fc = fa;
            d = e = b - a;
        }
        if (std::abs(fc) < std::abs(fb)) {
            a = b; b = c; c = a;
            fa = fb; fb = fc; fc = fa;
        }

        T tol = static_cast<T>(2) * std::numeric_limits<T>::epsilon() * std::abs(b) + epsilon / 2;
        T xm = (c - b) / 2;

        if (std::abs(xm) <= tol || std::abs(fb) < epsilon) {
            return {b, loss_fn(b), evals, true};
        }

        T s;
        if (std::abs(e) >= tol && std::abs(fa) > std::abs(fb)) {
            // Attempt interpolation
            T p, q, r;
            if (a == c) {
                // Secant method
                s = fb / fa;
                p = 2 * xm * s;
                q = 1 - s;
            } else {
                // Inverse quadratic interpolation
                q = fa / fc;
                r = fb / fc;
                s = fb / fa;
                p = s * (2 * xm * q * (q - r) - (b - a) * (r - 1));
                q = (q - 1) * (r - 1) * (s - 1);
            }
            if (p > 0) q = -q; else p = -p;

            s = e;
            e = d;

            // Accept interpolation if in bounds and not too large
            if (2 * p < std::min(3 * xm * q - std::abs(tol * q), std::abs(s * q))) {
                d = p / q;
            } else {
                d = e = xm;  // Fall back to bisection
            }
        } else {
            d = e = xm;  // Bisection step
        }

        a = b; fa = fb;
        b += (std::abs(d) > tol) ? d : (xm > 0 ? tol : -tol);
        fb = f(b);
        evals++;
    }

    return {b, loss_fn(b), evals, false};
}


// ─────────────────────────────────────────────────────────────────
// Application 1: Temperature scaling for calibration
// Find T* such that NLL(T*) = minimum (NLL'(T*) = 0, monotone in T)
// ─────────────────────────────────────────────────────────────────
double simulate_nll(double temperature, const std::vector<double>& logits,
                    const std::vector<int>& labels) {
    // NLL after temperature scaling: -sum_i log(softmax(z_i / T)[y_i])
    // For 2-class case simplified here
    double nll = 0.0;
    for (size_t i = 0; i < logits.size(); ++i) {
        double scaled = logits[i] / temperature;
        double log_prob = (labels[i] == 1)
            ? -std::log(1.0 + std::exp(-scaled))
            : -std::log(1.0 + std::exp(scaled));
        nll -= log_prob;
    }
    return nll / logits.size();
}

// The derivative of NLL w.r.t. T is monotone for overconfident models.
// We find T* where dNLL/dT = 0 — equivalently, where ECE is minimised.
// Here we use a finite-difference oracle for the gradient sign.
double nll_derivative(double T, const std::vector<double>& logits,
                      const std::vector<int>& labels, double dT = 1e-5) {
    return (simulate_nll(T + dT, logits, labels) -
            simulate_nll(T - dT, logits, labels)) / (2 * dT);
}


// ─────────────────────────────────────────────────────────────────
// Application 2: Decision threshold for recall constraint
// ─────────────────────────────────────────────────────────────────
double recall_at_threshold(double tau, const std::vector<double>& scores,
                           const std::vector<int>& labels) {
    int tp = 0, fn = 0;
    for (size_t i = 0; i < scores.size(); ++i) {
        if (labels[i] == 1) {
            if (scores[i] >= tau) tp++;
            else fn++;
        }
    }
    return (tp + fn > 0) ? static_cast<double>(tp) / (tp + fn) : 0.0;
}


int main() {
    // ── Example 1: Temperature Scaling ──
    // Overconfident model: logits are large, need T > 1 to calibrate
    std::vector<double> logits = {3.0, -2.5, 4.1, -1.8, 2.9, -3.2, 1.5, -0.8};
    std::vector<int>    labels = {1,    0,    1,    0,    1,   0,    1,    0  };

    // Find T where NLL derivative = 0 (calibration point)
    // NLL'(T) is negative for T < T*, positive for T > T*
    // This is root-finding: find T where dNLL/dT = 0
    auto nll_grad = [&](double T) -> double {
        return nll_derivative(T, logits, labels);
    };

    auto temp_result = brent_loss_search<double>(
        0.1, 10.0,
        nll_grad,
        0.0,    // target: find T where gradient = 0
        1e-6
    );

    std::cout << "=== Temperature Scaling ===\n";
    std::cout << "Optimal temperature T* = " << temp_result.value << "\n";
    std::cout << "NLL at T=1 (uncalibrated): "
              << simulate_nll(1.0, logits, labels) << "\n";
    std::cout << "NLL at T*  (calibrated):   "
              << simulate_nll(temp_result.value, logits, labels) << "\n";
    std::cout << "Evaluations: " << temp_result.evaluations
              << " (vs ~1000 for fine LR grid search)\n\n";

    // ── Example 2: Decision Threshold for Recall = 0.90 ──
    std::vector<double> scores = {0.9, 0.8, 0.7, 0.6, 0.55, 0.45, 0.35, 0.2, 0.1, 0.05};
    std::vector<int>    slabels = {1,   1,   1,   1,   0,    1,    0,    0,   1,   0  };

    // Recall is monotone decreasing in threshold
    // Find smallest threshold where recall >= 0.90
    auto recall_fn = [&](double tau) -> double {
        return recall_at_threshold(tau, scores, slabels);
    };

    // Binary search: oracle(tau) = (recall(tau) >= 0.90)
    // Equivalent loss search: find tau where recall_fn(tau) = 0.90
    // Note: recall is decreasing in tau, so we flip: find tau where 0.90 - recall(tau) = 0
    auto recall_loss = [&](double tau) -> double {
        return 0.90 - recall_at_threshold(tau, scores, slabels);
    };

    // For discrete score arrays, use sorted unique thresholds
    std::vector<double> sorted_scores = scores;
    std::sort(sorted_scores.begin(), sorted_scores.end());
    sorted_scores.erase(std::unique(sorted_scores.begin(), sorted_scores.end()),
                        sorted_scores.end());
    int n = sorted_scores.size();

    // Discrete bisection: smallest index where recall >= 0.90
    int lo = 0, hi = n - 1, evals = 0;
    while (lo < hi) {
        int mid = (lo + hi) / 2;
        double rec = recall_at_threshold(sorted_scores[mid], scores, slabels);
        evals++;
        if (rec >= 0.90) {
            hi = mid;  // mid works; look for higher (stricter) threshold
        } else {
            lo = mid + 1;
        }
    }

    std::cout << "=== Decision Threshold ===\n";
    std::cout << "Threshold for recall >= 0.90: tau = " << sorted_scores[lo] << "\n";
    std::cout << "Recall at tau: " << recall_at_threshold(sorted_scores[lo], scores, slabels) << "\n";
    std::cout << "Evaluations: " << evals << " (vs " << n << " for linear scan)\n";

    return 0;
}
```

### Python (Readable + Pythonic)

```python
"""
Monotonic Loss Search — When Binary Search Replaces Gradient Methods
Topic 66, Tier T2

Key insight: when a loss is monotone in a scalar parameter, gradient descent
is unnecessary. Binary search (or Brent's method) finds the optimum in
O(log(1/epsilon)) evaluations with no learning rate to tune and a global
convergence guarantee.
"""

from __future__ import annotations
import math
from dataclasses import dataclass
from typing import Callable
import numpy as np
from scipy.optimize import brentq  # Production-grade Brent's method


@dataclass
class SearchResult:
    value: float
    loss_at_value: float
    evaluations: int
    converged: bool


# ─────────────────────────────────────────────────────────────────
# Core: bisection for monotone loss search
# ─────────────────────────────────────────────────────────────────

def bisection_loss_search(
    lo: float,
    hi: float,
    loss_fn: Callable[[float], float],
    target: float,
    epsilon: float = 1e-7,
    max_iter: int = 100,
) -> SearchResult:
    """
    Find h* in [lo, hi] such that loss_fn(h*) ≈ target.

    This is root-finding: find the zero of f(h) = loss_fn(h) - target.
    Requires loss_fn to be monotone (either increasing or decreasing) in h.

    Why not gradient descent?
    - loss_fn may not be differentiable (e.g., recall, F1, quantile metrics)
    - Even if differentiable, the gradient of a 1D monotone function has constant
      sign — a comparison is sufficient, not a full gradient evaluation
    - Bisection converges in O(log(1/epsilon)) steps vs O(1/epsilon) for GD

    Complexity: O(log((hi - lo) / epsilon)) loss_fn evaluations.
    """
    def f(h: float) -> float:
        return loss_fn(h) - target

    f_lo = f(lo)
    f_hi = f(hi)
    evals = 2

    # Validate bracket — required for bisection correctness
    if f_lo * f_hi > 0:
        raise ValueError(
            f"No bracket: f({lo:.4f})={f_lo:.4f} and f({hi:.4f})={f_hi:.4f} "
            f"have the same sign. Either loss_fn is not monotone over [lo, hi], "
            f"or target={target} is outside [loss_fn(lo), loss_fn(hi)]."
        )

    if abs(f_lo) < epsilon:
        return SearchResult(lo, loss_fn(lo), evals, True)
    if abs(f_hi) < epsilon:
        return SearchResult(hi, loss_fn(hi), evals, True)

    # Normalise: ensure f(lo) <= 0 and f(hi) >= 0
    if f_lo > 0:
        lo, hi = hi, lo
        f_lo, f_hi = f_hi, f_lo

    # Bisection loop. Invariant: f(lo) <= 0 <= f(hi).
    for _ in range(max_iter):
        if hi - lo <= epsilon:
            break

        mid = lo + (hi - lo) / 2.0  # Numerically safe midpoint

        f_mid = f(mid)
        evals += 1

        if abs(f_mid) < epsilon:
            return SearchResult(mid, loss_fn(mid), evals, True)

        if f_mid < 0:
            lo, f_lo = mid, f_mid   # mid is on the "lo" side
        else:
            hi, f_hi = mid, f_mid   # mid is on the "hi" side

    best = (lo + hi) / 2.0
    return SearchResult(best, loss_fn(best), evals, (hi - lo) <= epsilon)


# ─────────────────────────────────────────────────────────────────
# Application 1: Temperature Scaling for Neural Network Calibration
# (Guo et al., 2017 — "On Calibration of Modern Neural Networks")
# ─────────────────────────────────────────────────────────────────

class TemperatureScaler:
    """
    Calibrate a classifier's output probabilities via temperature scaling.

    The model outputs logits z ∈ R^K. Temperature scaling applies:
        p = softmax(z / T)

    The optimal T* minimises the Negative Log-Likelihood (NLL) on a validation set.
    For overconfident models (typical for modern deep networks), T* > 1.

    Key observation: dNLL/dT is monotone increasing in T for overconfident models.
    This makes the optimum findable via bisection on dNLL/dT = 0.
    No backpropagation through the model required. No learning rate to tune.

    Compare to: the original paper uses L-BFGS. For the 1D case, bisection is
    simpler, as fast, and has cleaner convergence guarantees.
    """

    def __init__(self, logits: np.ndarray, labels: np.ndarray):
        """
        Args:
            logits: shape (N, K) — raw pre-softmax outputs from the classifier
            labels: shape (N,)   — integer class labels in [0, K)
        """
        self.logits = logits
        self.labels = labels
        self.temperature: float | None = None
        self._evals = 0

    def _nll(self, T: float) -> float:
        """Negative log-likelihood at temperature T."""
        self._evals += 1
        scaled = self.logits / T
        # Numerically stable log-softmax (see [[221.Numerical stability]])
        log_softmax = scaled - np.log(np.sum(np.exp(
            scaled - scaled.max(axis=1, keepdims=True)
        ), axis=1, keepdims=True)) - scaled.max(axis=1, keepdims=True)
        nll = -log_softmax[np.arange(len(self.labels)), self.labels].mean()
        return float(nll)

    def _nll_derivative(self, T: float, dT: float = 1e-4) -> float:
        """Finite-difference approximation of dNLL/dT. Monotone for overconfident models."""
        return (self._nll(T + dT) - self._nll(T - dT)) / (2 * dT)

    def fit(self, lo: float = 0.05, hi: float = 10.0, epsilon: float = 1e-5) -> float:
        """
        Find T* that minimises NLL by bisecting on dNLL/dT = 0.

        Returns optimal temperature T*.
        """
        self._evals = 0

        # Use scipy's brentq for production robustness
        # brentq is Brent's method: bisection + superlinear acceleration
        # It is exactly the right tool for 1D monotone root-finding
        T_star = brentq(
            self._nll_derivative,
            lo, hi,
            xtol=epsilon,
            maxiter=50,
        )
        self.temperature = T_star
        return T_star

    def calibrate(self, logits: np.ndarray) -> np.ndarray:
        """Apply temperature scaling to new logits."""
        if self.temperature is None:
            raise RuntimeError("Call fit() before calibrate().")
        scaled = logits / self.temperature
        exp_scaled = np.exp(scaled - scaled.max(axis=1, keepdims=True))
        return exp_scaled / exp_scaled.sum(axis=1, keepdims=True)


# ─────────────────────────────────────────────────────────────────
# Application 2: Lagrangian Dual Variable Search (Fairness-Constrained ML)
# (Cotter et al., 2018 — "Training Well-Generalizing Classifiers for Fairness Constraints")
# ─────────────────────────────────────────────────────────────────

def find_lagrange_multiplier(
    primal_constraint_fn: Callable[[float], float],
    lo: float = 0.0,
    hi: float = 100.0,
    epsilon: float = 1e-6,
) -> SearchResult:
    """
    Solve a Lagrangian dual problem: find λ* such that c(θ*(λ)) = 0.

    In constrained ML (e.g., fairness constraints, resource budgets):
      - Primal: min_θ L(θ)  subject to  c(θ) ≤ 0
      - Dual:   max_λ g(λ)  where  g(λ) = min_θ [L(θ) + λ·c(θ)]

    For convex problems: c(θ*(λ)) is monotone decreasing in λ.
      - Low λ: constraint is cheap → model ignores it → c(θ*(λ)) > 0 (constraint violated)
      - High λ: constraint is expensive → model satisfies it easily → c(θ*(λ)) < 0

    The optimal λ* satisfies c(θ*(λ*)) = 0.
    This is a root-finding problem: find λ where constraint_fn(λ) = 0.

    primal_constraint_fn(λ): trains model with multiplier λ, returns c(θ*(λ)).
                             Negative = constraint satisfied; Positive = violated.

    Why bisection instead of gradient ascent on g(λ)?
    - g(λ) is concave but may not be differentiable (piecewise linear)
    - c(θ*(λ)) is the subgradient of g — but we only need its sign
    - Bisection on c(θ*(λ)) = 0 is cleaner and more robust

    Complexity: O(log((hi - lo) / epsilon)) primal training runs.
    """
    return bisection_loss_search(
        lo=lo,
        hi=hi,
        loss_fn=primal_constraint_fn,
        target=0.0,
        epsilon=epsilon,
    )


# ─────────────────────────────────────────────────────────────────
# Application 3: Beam Search Length Penalty Tuning
# ─────────────────────────────────────────────────────────────────

def find_length_penalty(
    beam_search_fn: Callable[[float], float],
    target_avg_length: float,
    lo: float = 0.1,
    hi: float = 2.0,
    epsilon: float = 1e-4,
) -> SearchResult:
    """
    Find length penalty α such that beam search produces sequences of
    target_avg_length on average.

    In Transformer beam search, the score for a sequence of length L is:
        score(Y) = log P(Y|X) / ((5 + L) / 6)^α

    Higher α penalises short sequences → longer average output.
    Average length is monotone increasing in α.
    Target: find α* such that avg_length(α*) = target_avg_length.

    beam_search_fn(α): runs beam search with length penalty α,
                       returns average output length on evaluation set.

    This is a root-finding problem on a monotone function.
    Replace grid search over α ∈ {0.0, 0.1, ..., 2.0} (20 beam searches)
    with bisection (~7 beam searches).
    """
    return bisection_loss_search(
        lo=lo,
        hi=hi,
        loss_fn=beam_search_fn,
        target=target_avg_length,
        epsilon=epsilon,
    )


# ─────────────────────────────────────────────────────────────────
# Application 4: Quantisation bit-width per-layer search
# ─────────────────────────────────────────────────────────────────

def find_min_bitwidth(
    quantisation_error_fn: Callable[[int], float],
    target_perplexity: float,
    lo_bits: int = 2,
    hi_bits: int = 16,
) -> tuple[int, int]:
    """
    Find minimum bit-width b such that quantised model achieves ≤ target_perplexity.

    Perplexity is monotone decreasing in bit-width: more bits → less error.
    Discrete bisection over integer bit-widths.

    quantisation_error_fn(b): quantises model to b bits, returns perplexity.

    Returns (optimal_bits, evaluations).
    Used in GPTQ-style per-layer bit allocation.
    """
    evals = 0

    if quantisation_error_fn(hi_bits) > target_perplexity:
        evals += 1
        raise ValueError(f"Even {hi_bits} bits doesn't achieve target perplexity {target_perplexity}.")

    if quantisation_error_fn(lo_bits) <= target_perplexity:
        evals += 2
        return lo_bits, evals

    lo, hi = lo_bits, hi_bits

    while lo < hi:
        mid = (lo + hi) // 2
        perplexity = quantisation_error_fn(mid)
        evals += 1

        if perplexity <= target_perplexity:
            hi = mid      # mid works; try fewer bits
        else:
            lo = mid + 1  # mid too lossy; need more bits

    return lo, evals
```

### Diagram 2: The Bracket Invariant — What Bisection Maintains

```
  Root-finding: f(h) = loss(h) - target = 0

  At all times, bisection maintains:
      f(lo) < 0   AND   f(hi) > 0
  (or the reverse — but opposite signs guaranteed)

  Iteration trace:

  f(h)
    │
  + │               •hi
    │              /
    │             /
  0 │────────────╳────────── h         ← root f(h) = 0
    │           /│
    │          / │
  - │•lo──────╯  │
    │             │
    └─────────────────────── h
       lo   ...  h*  ...  hi

  After Step 1 (mid = (lo+hi)/2):
    f(mid) < 0  →  lo = mid  (f(lo) stays negative)
    f(mid) > 0  →  hi = mid  (f(hi) stays positive)

  The bracket [lo, hi] halves each step.
  The invariant is never violated — bisection is guaranteed to converge.

  Brent's method: same invariant, but uses IQI/secant to sometimes take
  a larger step. Falls back to bisection when the accelerated step would
  violate the bracket. Result: superlinear convergence near the root,
  bisection guarantee far from it.
```

## 7. Common Variations & Extensions

### Variation 1: Noisy Oracle — Robust Bisection

The standard bisection assumes each oracle evaluation is exact. In ML, each evaluation is stochastic (different mini-batches, random seeds). If `oracle(mid)` can return the wrong sign with probability `p`, standard bisection accumulates errors. The fix: **robust bisection** (Waeber et al., 2013) averages `k` evaluations at each step, reducing the error probability to `O(exp(-k))`. This multiplies evaluation cost by `k`, but the logarithmic savings from bisection still dominate grid search. Alternatively, use **noisy binary search** (Ben-Or & Hassidim, 2008), which achieves `O(log(n) / (1 - 2p)²)` evaluations for error probability `p < 0.5`.

### Variation 2: Bisection on the Regularisation Path

For convex models with L1 or L2 regularisation, the entire **regularisation path** (the set of solutions for all values of `λ`) can be computed efficiently using warm starts. But if you only need the solution at one specific `λ*`, bisection on the validation loss is faster than computing the full path. This is how `sklearn`'s `LassoCV` works internally for a fixed grid — the extension to bisection replaces the grid with a logarithmic search. See [[62.Fractional binary search — real-valued search spaces]] for the continuous-domain handling.

### Variation 3: Bisection in Reinforcement Learning — Value Iteration Convergence Check

In value iteration (the DP foundation of Q-learning, see [[185.Bellman equation in RL — DP as the foundation of Q-learning]]), the stopping criterion is `||V_{t+1} - V_t||_∞ < ε`. The convergence of this norm to zero is monotone in the number of iterations. If you need to find the first iteration where the policy stabilises (for analysis purposes), that is a bisection on the iteration count. More practically, in **policy evaluation**, bisection on the discount factor `γ` to achieve a target value norm is a monotone 1D search.

### Variation 4: Golden Section Search (Unimodal Extension)

When the loss is unimodal rather than monotone (single minimum over the search space), bisection breaks but **golden section search** applies. It maintains a bracket `[lo, hi]` and two interior probe points at the golden ratio positions, discarding one third at each step. Achieves `O(log_{φ}(1/ε))` evaluations where `φ = (1 + √5)/2 ≈ 1.618` — slightly more evaluations than bisection per step, but the correct tool for the unimodal case. Used in learning rate range searches and hyperparameter tuning when the loss has a single minimum in the search range. Connects to [[65.Binary search in hyperparameter tuning — conceptual model]] for the unimodal LR case.

## 9. CP Contest Application

### Typical Problem Structure

Problems amenable to this pattern share a common form on Codeforces and AtCoder:

> _"You want to minimise (or maximise) value X. For a fixed X, you can check if it is achievable in O(n) or O(n log n). The achievability is monotone in X."_

The loss-search framing makes the ML connection: the "achievability check" is the oracle, and X is the parameter being searched. In CP, this oracle is often a greedy feasibility check; in ML, it is a model evaluation.

**Canonical CP problems using this structure:**

- **Aggressive Cows (SPOJ/Codeforces):** Maximise minimum distance between cows. Oracle: can we place C cows with minimum gap ≥ D? Greedy in O(n log n) (sort, then greedy place). Binary search on D.
- **Painter's Partition Problem:** Minimise the maximum load across k painters. Oracle: can k painters finish with max load ≤ L? Greedy scan in O(n). Binary search on L.
- **Koko Eating Bananas (LC 875):** Same structure, different skin.

**Time limit considerations:**

```
Oracle complexity    │ Answer range    │ Total complexity  │ n=10^5 check
────────────────────┼─────────────────┼───────────────────┼──────────────
O(n)                │ [1, 10^9]       │ O(n log 10^9)     │ ~30n ≈ 3×10^6  ✓
O(n log n)          │ [1, 10^9]       │ O(n log n log V)  │ ~30·17n ≈ 5×10^7  ✓ tight
O(n^2)              │ [1, 10^9]       │ O(n^2 log V)      │ ~30n^2 → TLE  ✗
```

**The critical optimization trick:** In floating-point binary search (real-valued answer), fix the iteration count to 100 rather than using `|hi - lo| < ε`. This avoids infinite loops from floating-point comparison instability, runs in exactly 100 oracle calls, and achieves precision of `(hi - lo) / 2^100 ≈ 0` for any reasonable initial domain. Every competitive programmer should have this as muscle memory:

```cpp
// Fixed-iteration float bisection — use this in contests, not epsilon termination
double lo = 0, hi = 1e9;
for (int iter = 0; iter < 100; ++iter) {
    double mid = (lo + hi) / 2;
    if (feasible(mid)) hi = mid;
    else lo = mid;
}
// Answer: hi
```

**Interactive problems:** Some Codeforces interactive problems give you a budget of 30 queries to find a hidden value in `[1, 10^9]`. This is bisection with an implicit oracle (the judge). `log₂(10^9) ≈ 30` — the budget is set by this exact calculation. Understanding monotonic loss search makes interactive problem structure immediately legible.
