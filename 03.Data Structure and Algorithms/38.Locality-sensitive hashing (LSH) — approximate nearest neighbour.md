## 1. Intuition First

### The Core Idea

You have a database of one million 768-dimensional embedding vectors — one per document in your corpus. A user submits a query. You want to return the 10 most similar documents. The exact answer requires computing the distance from the query to all one million vectors: 10⁶ × 768 multiplications, repeated for every query. At 10,000 queries per second, that is 7.68 × 10¹² multiply-accumulate operations per second. This is not a throughput problem — it is physically impossible at query latency requirements.

**The key observation:** You do not need the _exact_ nearest neighbours. You need neighbours that are _close enough_, found _fast enough_. This is the approximate nearest neighbour (ANN) problem, and LSH is one of its foundational solutions.

LSH inverts the design goal of a normal hash function. A normal hash function is engineered so that similar inputs produce _completely different_ outputs — this is the avalanche property from [[31.Hash function design — properties, uniformity, avalanche]], and it is exactly what makes HashMap buckets uniform. LSH does the opposite: it is a hash function family where **similar inputs land in the same bucket with high probability, and dissimilar inputs land in different buckets with high probability**.

**The geometric picture:** Project your high-dimensional vectors onto a random line. Divide that line into segments (bins). Two vectors that are close in high-dimensional space will, after projection, land in the same bin with probability proportional to their similarity. Two vectors that are far apart will, after projection, almost never share a bin. The hash _preserves locality_.

**The "Aha" Moment:**

> _A normal hash function destroys spatial structure to achieve uniformity. LSH deliberately preserves spatial structure — nearby points hash to the same bucket. This turns a nearest-neighbour search (scan all n points) into a bucket lookup (scan only the points in the query's bucket)._

### Why This Exists

Exact nearest-neighbour search in d dimensions requires O(n) time per query — you must check every point. For n = 10⁶ and d = 768, with tight latency budgets (< 100ms), this is infeasible. Tree-based structures like KD-trees work well for d ≤ 20 but degrade to O(n) in high dimensions — the **curse of dimensionality**: in high dimensions, all points are approximately equidistant from any query, making tree pruning useless.

LSH achieves sub-linear query time O(n^ρ) where ρ < 1 depends on the approximation ratio, by trading a small probability of missing the true nearest neighbour for a dramatic speedup. For practical ANN problems (embedding lookup in RAG pipelines, image retrieval, deduplication), a 95–99% recall at 10× speedup is an excellent trade.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

LSH is not a CP contest topic. The underlying mathematical tools, however, appear directly:

**Random projections as dot products:** The core LSH operation for cosine similarity is `sign(w · x)` where `w` is a random Gaussian vector. This is a dot product — matrix-vector multiply — which underlies many CP problems involving geometry and linear algebra.

**Hashing for string similarity:** The CP problem "find all pairs of strings with edit distance ≤ k" can be solved with LSH-style hashing: generate multiple random hash functions where strings with small edit distance hash to the same bucket. This converts an O(n²) pairwise comparison to O(n · bucket_size) comparisons. The pattern signal:

```
"Find all pairs satisfying a similarity condition"  →  Think LSH bucketing
"Exact pairwise comparison is O(n²) and too slow"   →  Think ANN / LSH
```

**The birthday paradox connection:** The probability analysis of LSH collision rates uses the same combinatorial reasoning as [[40.The birthday paradox and collision probability]]. If a single hash function has collision probability p for a similar pair, using b independent hash functions in a band reduces false-negative probability to (1 - pᵣ)^b — a direct application of independence and complementary probability.

### Machine Learning / AI

LSH is infrastructure for the ML similarity stack. It appears in production at every major ML platform.

**1. Semantic Search and RAG Pipelines**

Retrieval-Augmented Generation (RAG) — as used in ChatGPT's retrieval tools, LlamaIndex, LangChain — requires finding the top-k document embeddings most similar to a query embedding. For corpora up to ~10M documents, FAISS with an IVF (Inverted File Index) structure — which is LSH-inspired partitioning — handles this at millisecond latency. The IVF index is essentially LSH: cluster centroids are the hash buckets, and queries search only the nearest centroid's bucket.

**2. Near-Duplicate Detection in Training Data**

The LLM training data pipelines for GPT-3 (WebText2), LLaMA (RefinedWeb, Dolma), and BLOOM all apply near-duplicate detection using MinHash-LSH (see [[39.MinHash — estimating Jaccard similarity at scale]]). Exact dedup (from [[36.HashMap for O(1) deduplication — ML pipeline application]]) handles identical documents; LSH handles paraphrases, reformatted duplicates, and boilerplate-heavy near-duplicates. The pipeline order is always: exact dedup first (O(n)), then near-dedup via LSH (O(n · bands)).

**3. Recommendation Systems (Item-Item Similarity)**

Netflix, Spotify, and YouTube use embedding-based collaborative filtering where item similarity is computed in embedding space. With O(10⁸) items, exact pairwise similarity is infeasible. LSH-based ANN (via FAISS, ScaNN, or HNSW) reduces item-item similarity search from O(n²) to O(n · n^ρ). Spotify's Annoy library and Google's ScaNN paper (2020) both describe this application.

**4. Image and Multimodal Retrieval**

CLIP embeddings (OpenAI, 2021) map images and text to the same 512-dimensional space. Building a CLIP-based image search over a 1B-image corpus (as in LAION-5B) requires ANN search. Meta's FAISS library, built specifically for this, implements multiple LSH variants (IVF-PQ, HNSW) and is used in production at Meta, Google Brain, and hundreds of ML teams. The core indexing structure is LSH: partition the embedding space into Voronoi cells (hash buckets), assign each vector to its cell at index time, search only the query's cell and its neighbours at query time.

**5. Anomaly Detection**

LSH for anomaly detection: normal data points cluster in high-density regions; anomalies hash to sparse buckets (few or no neighbours). If a query point's LSH bucket contains fewer than k neighbours, it is flagged as anomalous. This is used in fraud detection systems and network intrusion detection, where exact distance computation over streaming high-dimensional feature vectors is infeasible.

**Why understanding this makes you a better ML engineer:**

When you set FAISS `nlist` (number of Voronoi cells / hash buckets) and `nprobe` (number of buckets to search at query time), you are directly tuning LSH parameters — the recall-speed tradeoff. Understanding that `nlist` controls bucket granularity and `nprobe` controls how many buckets you search makes index tuning principled rather than empirical. Doubling `nprobe` increases recall toward exact-search levels but linearly increases query time — you can reason about this tradeoff analytically.

## 3. Algorithm / Pattern

### The LSH Framework: Three Similarity Regimes

LSH works differently depending on which distance/similarity metric you use. There is a different LSH family for each:

|Similarity Metric|LSH Family|Hash Operation|
|---|---|---|
|Cosine similarity|SimHash / Random Hyperplane|`sign(w · x)`, w ~ N(0,I)|
|Jaccard similarity|MinHash|Min of permuted element indices|
|Euclidean distance|p-stable LSH|`floor((w·x + b) / r)`, w ~ N(0,I), b ~ Uniform(0,r)|
|Hamming distance|Bit sampling|Sample a random bit position|

### Random Hyperplane LSH (Cosine Similarity) — The Core Idea

**Setup:**

1. Sample k random unit vectors `w₁, w₂, ..., wₖ` from N(0, I_d).
2. The hash of vector `x` is the k-bit string: `h(x) = [sign(w₁·x), sign(w₂·x), ..., sign(wₖ·x)]`.

**Why this works:** The probability that two vectors `x` and `y` produce the same bit for a random hyperplane `w` is:

```
P[sign(w·x) = sign(w·y)] = 1 - θ/π
```

where θ is the angle between x and y. When θ = 0 (identical direction), collision probability = 1. When θ = π/2 (orthogonal), collision probability = 0.5. When θ = π (opposite), collision probability = 0.

So **cosine similarity maps directly to collision probability** — this is the locality-sensitive property.

### The Amplification Scheme: AND + OR Construction

A single hash bit gives a noisy signal. The standard amplification uses:

- **AND construction (bands):** Concatenate r hash bits into a "band". Two vectors must agree on _all r bits_ to be in the same band-bucket. This reduces false positive rate: `P[same band] = P[same bit]^r`.
- **OR construction (tables):** Use b independent band hash functions. Two vectors are candidates if they collide in _any one_ of the b bands. This reduces false negative rate: `P[candidate] = 1 - (1 - P[same band])^b`.

Together, the OR-of-ANDs creates an S-curve: pairs with similarity above a threshold θ* are candidates with high probability; pairs below θ* are almost never candidates.

The threshold where the S-curve is steepest: `θ* ≈ (1/b)^(1/r)`.

**Choosing r and b:**

- More r → sharper threshold, fewer false positives, more false negatives
- More b → higher recall, more false positives, more memory
- Rule of thumb: set r and b so that θ* matches your similarity threshold, then tune b for desired recall.

### Query Process

1. **Index phase** (offline): For each database vector x, compute its (r × b) hash codes. Insert x into b hash tables, one per band.
2. **Query phase** (online): For query q, compute its b band hashes. Retrieve all candidates from each of the b hash tables. Compute exact distances to candidates only. Return top-k.

**Query time complexity:** O(b · (hash_time + bucket_retrieval) + candidate_count · d)

For well-tuned parameters, `candidate_count << n`, giving sub-linear effective query time.

### Complexity

|Phase|Time|Space|
|---|---|---|
|Index construction|O(n · b · r · d)|O(n · b)|
|Single query|O(b · r · d + C · d)|O(1)|
|Exact NN (baseline)|O(n · d)|O(1)|

C = average candidate set size (ideally much smaller than n). n = database size, d = dimension, b = number of bands, r = rows per band.

**The sub-linear guarantee:** Under the (r,c)-ANN problem definition — find a point within distance cr of the nearest neighbour — LSH achieves query time O(n^ρ + d · n^ρ) where ρ = 1/c² for Euclidean LSH. For c = 2 (2-approximation), ρ = 0.25 — query time grows as n^0.25 instead of n.

## 4. Pseudocode

```
// ─── RANDOM HYPERPLANE LSH (COSINE SIMILARITY) ────────────────────────────────

// SETUP
function build_lsh_index(vectors, num_bands b, rows_per_band r, dimension d):
    // Generate b*r random hyperplanes (Gaussian random vectors)
    hyperplanes ← sample b*r vectors of dimension d from N(0, I_d)
    // Shape: (b, r, d) — b bands, each with r hyperplanes

    // b separate hash tables (one per band)
    tables ← array of b empty HashMaps  // band_hash → list of vector IDs

    for each vector x with ID idx:
        for band from 0 to b-1:
            band_hash ← compute_band_hash(x, hyperplanes[band])
            // band_hash is an r-bit integer: bit i = sign(hyperplanes[band][i] · x)
            tables[band][band_hash].append(idx)

    return hyperplanes, tables


// BAND HASH COMPUTATION
function compute_band_hash(x, band_hyperplanes):
    // band_hyperplanes: shape (r, d)
    bits ← []
    for each hyperplane w in band_hyperplanes:
        bit ← 1 if dot(w, x) >= 0 else 0
        bits.append(bit)
    return bits_to_int(bits)              // r-bit integer


// QUERY
function query_lsh(q, hyperplanes, tables, b, r, vectors, k):
    candidate_ids ← empty set

    // Collect candidates from all b bands (OR construction)
    for band from 0 to b-1:
        band_hash ← compute_band_hash(q, hyperplanes[band])
        if band_hash in tables[band]:
            candidate_ids.union(tables[band][band_hash])

    // Exact distance computation only on candidates
    candidates ← [(cosine_similarity(q, vectors[id]), id)
                  for id in candidate_ids]

    // Return top-k by similarity
    sort candidates by similarity descending
    return candidates[:k]


// COSINE SIMILARITY
function cosine_similarity(a, b):
    return dot(a, b) / (norm(a) * norm(b))
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <algorithm>
#include <cmath>
#include <numeric>
#include <random>
#include <unordered_map>
#include <vector>
#include <iostream>
#include <cassert>
#include <functional>

// ─── RANDOM HYPERPLANE LSH FOR COSINE SIMILARITY ──────────────────────────────
// Implements the AND-OR amplification scheme.
// b bands, r rows per band → b*r random hyperplanes total.
// Index: O(n * b * r * d)   Query: O(b * r * d + C * d)
class RandomHyperplaneLSH {
public:
    // dim:    embedding dimension
    // bands:  number of hash tables (OR construction) — controls recall
    // rows:   bits per band hash (AND construction) — controls precision
    RandomHyperplaneLSH(int dim, int bands = 10, int rows = 8)
        : dim_(dim), bands_(bands), rows_(rows),
          tables_(bands), rng_(42)
    {
        // Sample b*r random Gaussian hyperplanes, shape: [bands][rows][dim]
        std::normal_distribution<float> gauss(0.0f, 1.0f);
        hyperplanes_.resize(bands, std::vector<std::vector<float>>(
            rows, std::vector<float>(dim)));

        for (auto& band : hyperplanes_)
            for (auto& hp : band)
                for (auto& w : hp)
                    w = gauss(rng_);
    }

    // Add all vectors to the index.
    // vectors[i] is the i-th embedding vector of dimension dim_.
    void build(const std::vector<std::vector<float>>& vectors) {
        vectors_ = &vectors;
        for (int idx = 0; idx < static_cast<int>(vectors.size()); ++idx) {
            for (int b = 0; b < bands_; ++b) {
                uint64_t band_hash = compute_band_hash(vectors[idx], b);
                tables_[b][band_hash].push_back(idx);
            }
        }
    }

    // Return up to k approximate nearest neighbours by cosine similarity.
    std::vector<std::pair<float, int>> query(
        const std::vector<float>& q, int k = 10
    ) const {
        assert(vectors_ != nullptr);

        // Collect candidates via OR of band collisions
        std::unordered_set<int> candidates;
        for (int b = 0; b < bands_; ++b) {
            uint64_t band_hash = compute_band_hash(q, b);
            auto it = tables_[b].find(band_hash);
            if (it != tables_[b].end()) {
                for (int idx : it->second)
                    candidates.insert(idx);
            }
        }

        // Exact cosine similarity for candidates only
        std::vector<std::pair<float, int>> scored;
        scored.reserve(candidates.size());
        for (int idx : candidates) {
            float sim = cosine_similarity(q, (*vectors_)[idx]);
            scored.emplace_back(sim, idx);
        }

        // Sort descending by similarity, return top-k
        int take = std::min(k, static_cast<int>(scored.size()));
        std::partial_sort(scored.begin(), scored.begin() + take, scored.end(),
            [](const auto& a, const auto& b){ return a.first > b.first; });
        scored.resize(take);
        return scored;
    }

    // Recall@k: fraction of true top-k found in LSH results.
    // Useful for parameter tuning.
    float evaluate_recall(
        const std::vector<std::vector<float>>& queries,
        int k = 10
    ) const {
        assert(vectors_ != nullptr);
        int total_found = 0;
        const int n = static_cast<int>(vectors_->size());

        for (const auto& q : queries) {
            // Exact top-k (brute force)
            std::vector<std::pair<float,int>> exact;
            exact.reserve(n);
            for (int i = 0; i < n; ++i)
                exact.emplace_back(cosine_similarity(q, (*vectors_)[i]), i);
            std::partial_sort(exact.begin(), exact.begin() + k, exact.end(),
                [](const auto& a, const auto& b){ return a.first > b.first; });

            std::unordered_set<int> true_top_k;
            for (int i = 0; i < k; ++i) true_top_k.insert(exact[i].second);

            // LSH results
            auto lsh_results = query(q, k);
            for (auto& [sim, idx] : lsh_results)
                if (true_top_k.count(idx)) ++total_found;
        }
        return static_cast<float>(total_found) / (queries.size() * k);
    }

private:
    int dim_, bands_, rows_;
    std::vector<std::vector<std::vector<float>>>           hyperplanes_;
    std::vector<std::unordered_map<uint64_t, std::vector<int>>> tables_;
    const std::vector<std::vector<float>>*                 vectors_ = nullptr;
    mutable std::mt19937                                   rng_;

    // Compute r-bit hash for one band: bit i = sign(hyperplanes_[b][i] · x)
    uint64_t compute_band_hash(const std::vector<float>& x, int b) const {
        uint64_t h = 0;
        for (int r = 0; r < rows_; ++r) {
            float dot = 0.0f;
            for (int i = 0; i < dim_; ++i)
                dot += hyperplanes_[b][r][i] * x[i];
            if (dot >= 0.0f) h |= (1ULL << r);  // set bit r if positive side
        }
        return h;
    }

    static float cosine_similarity(
        const std::vector<float>& a, const std::vector<float>& b
    ) {
        float dot = 0, na = 0, nb = 0;
        for (int i = 0; i < static_cast<int>(a.size()); ++i) {
            dot += a[i] * b[i];
            na  += a[i] * a[i];
            nb  += b[i] * b[i];
        }
        float denom = std::sqrt(na) * std::sqrt(nb);
        return denom > 1e-9f ? dot / denom : 0.0f;
    }
};
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations

import numpy as np
from collections import defaultdict
from typing import Optional


# ─── RANDOM HYPERPLANE LSH (COSINE SIMILARITY) ────────────────────────────────
class RandomHyperplaneLSH:
    """
    LSH for approximate cosine nearest-neighbour search.

    Uses the AND-OR amplification scheme:
      - b bands (hash tables)  → OR: find candidates in ANY band  → boosts recall
      - r rows per band        → AND: must agree on ALL r bits     → reduces false positives

    The collision probability for a pair with angle θ:
        P[same band] = (1 - θ/π)^r
        P[candidate] = 1 - (1 - (1 - θ/π)^r)^b

    Parameters
    ----------
    dim    : embedding dimension
    bands  : number of hash tables b (more → higher recall, more memory)
    rows   : hash bits per band r (more → sharper threshold, lower recall)

    Index time:  O(n * b * r * d)
    Query time:  O(b * r * d + C * d)  where C = avg candidate set size
    Space:       O(n * b)
    """

    def __init__(self, dim: int, bands: int = 10, rows: int = 8,
                 seed: int = 42) -> None:
        self.dim   = dim
        self.bands = bands
        self.rows  = rows
        rng = np.random.default_rng(seed)

        # Random hyperplanes: shape (bands, rows, dim)
        # Each row in each band is one random Gaussian unit vector
        self.hyperplanes = rng.standard_normal((bands, rows, dim)).astype(np.float32)

        # b hash tables: band_hash (int) → list of vector indices
        self.tables: list[dict[int, list[int]]] = [
            defaultdict(list) for _ in range(bands)
        ]
        self.vectors: Optional[np.ndarray] = None  # shape (n, dim)

    def _band_hash(self, x: np.ndarray, band: int) -> int:
        """
        Compute r-bit integer hash for vector x in the given band.

        dot products with all r hyperplanes → r signs → r-bit integer.
        Shape: x is (dim,), hyperplanes[band] is (rows, dim).
        """
        # dots shape: (rows,)
        dots = self.hyperplanes[band] @ x      # (rows, dim) @ (dim,) → (rows,)
        bits = (dots >= 0).astype(np.uint8)    # 1 if positive side, 0 if negative
        # Pack r bits into a single integer
        return int(np.packbits(bits, bitorder='little')[0]
                   if self.rows <= 8
                   else sum(int(b) << i for i, b in enumerate(bits)))

    def build(self, vectors: np.ndarray) -> None:
        """
        Index all vectors.

        vectors: shape (n, dim), should be L2-normalised for cosine similarity.
        """
        assert vectors.shape[1] == self.dim, \
            f"Dimension mismatch: expected {self.dim}, got {vectors.shape[1]}"
        self.vectors = vectors.astype(np.float32)

        for idx in range(len(vectors)):
            for b in range(self.bands):
                h = self._band_hash(vectors[idx], b)
                self.tables[b][h].append(idx)

    def query(self, q: np.ndarray, k: int = 10) -> list[tuple[float, int]]:
        """
        Return top-k approximate nearest neighbours for query q.

        Returns list of (cosine_similarity, index) sorted descending.
        """
        assert self.vectors is not None, "Call build() first."
        q = q.astype(np.float32)

        # Collect candidates from all b bands (OR construction)
        candidates: set[int] = set()
        for b in range(self.bands):
            h = self._band_hash(q, b)
            candidates.update(self.tables[b].get(h, []))

        if not candidates:
            return []

        # Vectorised cosine similarity for all candidates at once
        cand_list   = list(candidates)
        cand_matrix = self.vectors[cand_list]          # (C, dim)

        # Assuming pre-normalised vectors: cosine sim = dot product
        sims = cand_matrix @ q                         # (C,)

        # Sort and return top-k
        order  = np.argsort(sims)[::-1][:k]
        return [(float(sims[i]), cand_list[i]) for i in order]

    def recall_at_k(
        self, queries: np.ndarray, k: int = 10
    ) -> float:
        """
        Compute Recall@k: fraction of true top-k found by LSH.

        Brute-force exact search for ground truth.
        queries: shape (q, dim)
        """
        assert self.vectors is not None

        total = 0
        for q in queries:
            # Exact top-k (brute force)
            exact_sims = self.vectors @ q.astype(np.float32)
            true_top_k = set(np.argsort(exact_sims)[::-1][:k].tolist())

            # LSH top-k
            lsh_results = {idx for _, idx in self.query(q, k)}
            total += len(true_top_k & lsh_results)

        return total / (len(queries) * k)


# ─── S-CURVE ANALYSIS: TUNE b AND r ──────────────────────────────────────────
def collision_probability(theta: float, r: int, b: int) -> float:
    """
    P[two vectors with angle theta are LSH candidates].

    P[same bit]  = 1 - theta/pi
    P[same band] = (1 - theta/pi)^r
    P[candidate] = 1 - (1 - P[same band])^b
    """
    p_bit  = 1.0 - theta / np.pi
    p_band = p_bit ** r
    return 1.0 - (1.0 - p_band) ** b


def plot_scurve(r: int, b: int) -> None:
    """
    Print an ASCII S-curve showing collision probability vs angle.
    Useful for visualising the recall-precision tradeoff for chosen r, b.
    """
    print(f"\nS-curve: r={r} rows, b={b} bands")
    print(f"{'Angle':>8}  {'Cosine':>8}  {'P[candidate]':>14}  {'Bar':}")
    print("-" * 55)
    for deg in range(0, 181, 15):
        theta   = deg * np.pi / 180
        cosine  = np.cos(theta)
        p_cand  = collision_probability(theta, r, b)
        bar     = "█" * int(p_cand * 40)
        print(f"{deg:>7}°  {cosine:>8.3f}  {p_cand:>14.4f}  {bar}")

    assert recall > 0.5, f"Recall too low: {recall:.3f}"

    # Verify a specific query returns results in sorted order
    result = lsh.query(queries[0], k=5)
    assert len(result) <= 5
    if len(result) >= 2:
        assert result[0][0] >= result[1][0], "Results not sorted by similarity"

    # S-curve: show how r and b shape the threshold
    plot_scurve(r=4, b=10)
    plot_scurve(r=8, b=20)

    # Collision probability sanity checks
    p_identical = collision_probability(0.0, r=4, b=10)   # angle=0 → should be ~1
    p_orthogonal = collision_probability(np.pi/2, r=4, b=10)  # angle=90° → ~0.5 for one bit
    assert p_identical > 0.99, f"Identical vectors should collide: {p_identical}"
    assert 0.1 < p_orthogonal < 0.9

    print("\nAll tests passed.")
```

## 7. Common Variations & Extensions

### 7.1 MinHash LSH — Jaccard Similarity

When comparing _sets_ (documents as bags of words, user interaction histories), Jaccard similarity is more natural than cosine. MinHash is the LSH family for Jaccard — see [[39.MinHash — estimating Jaccard similarity at scale]] for full treatment. The AND-OR amplification scheme is identical; only the hash function changes from `sign(w·x)` to `min(π(S))` where π is a random permutation of set elements.

### 7.2 p-Stable LSH — Euclidean Distance

For Euclidean distance (L2), use the p-stable distribution family: `h(x) = floor((w·x + b) / r)` where `w ~ N(0, I)` and `b ~ Uniform(0, r)`. The bucket width `r` controls the similarity threshold — wider buckets = more candidates. The collision probability is `1 - 2Φ(-r/‖x-y‖) - (2/√(2π·r/‖x-y‖))(1 - e^(-r²/(2‖x-y‖²)))` — a decreasing function of ‖x-y‖, which gives the locality-sensitive property. This is what FAISS IVF uses conceptually.

### 7.3 FAISS IVF — Production LSH

Facebook AI Similarity Search (FAISS) implements ANN search at billion-vector scale. The IVF (Inverted File Index) is a learned version of LSH: instead of random hyperplanes, it uses k-means cluster centroids as "hash buckets". At query time, it searches the `nprobe` nearest centroids' buckets. This is LSH with learned (not random) hash functions — better adapted to the data distribution. IVF-PQ additionally quantises residuals to 8-bit integers, enabling vectors to be stored in ~32 bytes regardless of dimension. Understanding random hyperplane LSH makes IVF-PQ immediately interpretable.

### 7.4 SimHash — Fingerprinting for Near-Duplicate Detection

SimHash (Charikar 2002, used in Google's web index) is random hyperplane LSH applied to near-duplicate detection. The SimHash of a document is a single d-bit integer (e.g., 64 bits). Two near-duplicate documents have SimHashes that differ in few bits (small Hamming distance). Querying for near-duplicates: find all stored SimHashes within Hamming distance 3. This connects to [[36.HashMap for O(1) deduplication — ML pipeline application]] — SimHash is the near-dedup extension of exact dedup.

## 9. CP Contest Application

LSH itself does not appear in contests. The mathematical components do:

**Random projections in geometry problems:** The Johnson-Lindenstrauss lemma ([[212.Random projections — Johnson-Lindenstrauss lemma (conceptual)]]) guarantees that projecting n points from ℝᵈ to ℝᵏ (k = O(log n / ε²)) preserves all pairwise distances within (1 ± ε). CP problems occasionally require dimensionality reduction as a preprocessing step before geometric algorithms.

**Bit hashing for string matching:** The pattern of converting a similarity problem to a hash-collision problem appears in competitive programming:

```cpp
// CP pattern: random bit hashing to find similar strings fast
// Each string s gets a hash: XOR of random 64-bit values for each character
// Two strings with the same set of characters (anagrams) hash to the same value
// This is a special case of LSH for Jaccard similarity on character sets

uint64_t set_hash(const std::string& s, const std::array<uint64_t, 26>& rand_vals) {
    uint64_t h = 0;
    for (char c : s) h ^= rand_vals[c - 'a'];  // XOR = symmetric, order-independent
    return h;  // same hash iff same character set (for XOR-based hash)
}
// Group strings by hash → O(n) grouping of anagrams
// False positive rate depends on hash function quality
```

This XOR-based set hashing is a degenerate LSH where identical sets always collide and different sets collide with probability 2⁻⁶⁴ — the CP-practical tradeoff between correctness guarantees and implementation simplicity.

**Time complexity guidance:** For n ≤ 10⁵ strings of length L, the LSH-inspired grouping runs in O(n · L) for hashing + O(n) for bucketing — feasible within 1-2s limits where O(n² · L) exact comparison is not.
