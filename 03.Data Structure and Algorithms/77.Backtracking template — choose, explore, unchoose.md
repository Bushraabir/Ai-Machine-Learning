## 1. Intuition First

### The Core Idea

Imagine you're navigating a city you've never been to, trying to find a specific building. You have no map — only the ability to walk down streets and look for landmarks. Your strategy: at each intersection, **choose** a direction, walk down it fully until you either find the building or hit a dead end, then **undo** your path back to that intersection and try a different direction.

That's backtracking. It's a systematic method for exploring a combinatorial space — a space where the total number of candidates is exponentially large — by making incremental choices and abandoning partial candidates the moment you determine they cannot lead to a valid solution.

The three-word mantra encodes the entire algorithm:

1. **Choose:** Add an element to the current partial solution (pick a street)
2. **Explore:** Recurse deeper, extending the partial solution further (walk down the street)
3. **Unchoose:** Remove what you added and try the next option (backtrack to the intersection)

The key invariant that makes this correct: **the state before and after a recursive call is identical**. The "unchoose" step restores the state exactly as it was. This is what separates backtracking from naive enumeration — rather than generating all candidates up front and filtering, you prune entire subtrees of the search space before generating them.

### Why This Exists

The naive approach to combinatorial problems is to generate all possibilities and check each one. For a problem with $n$ choices, this is $O(2^n)$ or $O(n!)$ work with no savings. Backtracking doesn't change the worst case (the space is still exponential), but it makes the _expected_ case dramatically better by **pruning invalid branches early**.

Consider generating all $n$-digit numbers with no repeated digits. Naively: generate all $n!$ permutations, filter. With backtracking: the moment you choose digit $d$ at position $i$, you never even generate the subtree where $d$ appears again. If a constraint eliminates half the choices at every level, backtracking reduces $O(n!)$ to $O((n/2)!)$ — exponentially better.

### The "Aha" Moment

The insight is this: **a partial solution is either extendable or it isn't**. If it isn't — because you've already violated a constraint — then no solution in that entire subtree can be valid, and you can prune all $b^{d}$ nodes in that subtree at once (where $b$ is the branching factor and $d$ is the remaining depth). The "unchoose" step is what lets you _reuse_ the same state object across the entire search, rather than copying it at every node.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Any time the problem asks for all valid configurations, the lexicographically first valid arrangement, or the count of valid configurations where constraints eliminate many candidates.

**Pattern signals:**

- "Find all valid X" or "count the number of valid X" → backtracking
- Small constraint bounds ($n \leq 20$ for subsets, $n \leq 8$–$12$ for permutations) → backtracking is fast enough
- A constraint that can be checked _incrementally_ as you build the solution → enables pruning
- Grid problems asking for a valid path/placement with local constraints (N-Queens, Sudoku) → backtracking with constraint checking

**Common traps:**

- **Not restoring state.** If your "unchoose" step is incomplete — you removed the element from `path` but forgot to update the frequency counter — you'll get wrong answers that are hard to debug because the recursion still terminates.
- **Missing the base case.** If you forget to record the current path when it's a valid complete solution (vs just when it satisfies a constraint), you'll lose answers.
- **Choosing the wrong state representation.** Representing used elements as a set vs. a boolean array changes lookup from $O(1)$ to $O(1)$ but copying cost from $O(n)$ to $O(1)$ — matters at scale.
- **Confusing "find one" vs "find all."** For "find one solution," you can return `true` immediately upon finding it and short-circuit. For "find all," you must continue.

### Machine Learning / AI

**Where this appears in ML systems:**

**1. Neural Architecture Search (NAS):** The search for optimal neural network architectures is literally a backtracking problem over the space of possible layer types, connection patterns, and hyperparameters. Early NAS systems (Zoph & Le, 2016) used reinforcement learning to navigate this space, but the underlying enumeration is combinatorial. Modern NAS tools like Google's AutoML use pruning strategies identical to backtracking's branch bounding — the moment a partial architecture's proxy metric falls below threshold, the subtree is abandoned.

**2. Combinatorial feature selection:** In scikit-learn's `SequentialFeatureSelector` with backward elimination, the algorithm iteratively removes features and evaluates subsets. This is greedy, not full backtracking — but the full version (exhaustive feature search over all $2^n$ subsets with constraint pruning) is exactly [[82.Feature subset search as backtracking — ML connection]].

**3. Constraint satisfaction in probabilistic graphical models:** Belief propagation on factor graphs with hard constraints uses backtracking search when message passing fails to converge. Libraries like `pgmpy` fall back to exhaustive CSP search using a choose-explore-unchoose pattern when the graph has cycles and exact inference is required.

**4. Beam search as pruned backtracking:** In NLP decoding (transformers, seq2seq models), beam search is a width-limited backtracking traversal of the token sequence space. Each step corresponds to "choose token, explore, unchoose if beam rank is too low." PyTorch's `GenerationMixin.beam_search()` implements this — understanding the backtracking substrate makes you understand _why_ beam width is a quality/compute tradeoff.

**Writing better ML code:** When you implement a custom search over discrete parameter spaces (layer configs, graph structures, discrete action spaces in RL), the choose-explore-unchoose pattern with explicit undo is almost always more memory-efficient than copying state at every node.

## 3. Algorithm / Pattern

### Step-by-Step Logic

The template is universal. Every backtracking problem is a specialisation of the same three-step skeleton:

1. **Base case check:** Is the current partial solution complete and valid? If so, record it (or return `true` if seeking one solution).
2. **Constraint check:** Is the current partial solution already invalid? If so, return immediately (this is the pruning step).
3. **Iterate over choices:** For each valid next choice at this decision point: a. **Choose:** Add the choice to the current state. b. **Explore:** Recurse with the updated state. c. **Unchoose:** Remove the choice from the current state (restore exactly).

### Decision Tree

```
You see a problem → Ask:
├── "Find all valid X of length n"
│   └── Loop over choices, recurse, undo → collect all solutions
├── "Does a valid X exist?"
│   └── Same loop, but return true immediately on first find
├── "Count valid X"
│   └── Same loop, accumulate counter instead of collecting
└── "Find optimal X" (minimize/maximize something)
    └── Backtracking + bounding: prune when current partial cost
        already exceeds best known (branch and bound)
```

### Complexity Analysis

Let $b$ = branching factor (choices at each step), $d$ = depth of recursion (solution length).

- **Without pruning:** $O(b^d)$ nodes, $O(d)$ space for call stack.
- **With pruning:** Depends entirely on constraint density. In the best case (many invalid branches caught early), can be near-linear. In the worst case (no pruning possible), still $O(b^d)$.

For the canonical examples:

- **Subsets of size $k$ from $n$:** $O\binom{n}{k} \cdot k$ time — only valid-length paths are explored.
- **Permutations of $n$:** $O(n \cdot n!)$ time — $n!$ leaves, $n$ work per path.
- **N-Queens:** $O(n!)$ worst case, but pruning reduces it dramatically — empirically much faster.

**Space:** $O(d)$ for the call stack plus $O(d)$ for the `path` array = $O(d)$ total, plus output space.

### When to Use vs. Avoid

|Use backtracking|Avoid / use alternatives|
|---|---|
|$n \leq 20$ (subsets) or $n \leq 12$ (permutations)|$n > 25$ without strong pruning|
|Need all valid solutions|Need the count only and DP is possible|
|Constraints eliminate subtrees early|No constraint to prune on|
|State can be cheaply restored|State restoration is $O(n)$ per step and $n$ is large|

## 4. Pseudocode

```
function backtrack(path, choices, state):
    // BASE CASE: solution is complete
    if is_complete(path, state):
        record(path)          // add to results, or return true for "find one"
        return

    // PRUNING: prune invalid partial states before iterating
    if is_invalid(path, state):
        return

    // ITERATE over all choices available at this level
    for each choice in generate_choices(state):

        // CHOOSE: apply the choice
        apply(choice, path, state)

        // EXPLORE: recurse deeper
        backtrack(path, choices, state)

        // UNCHOOSE: undo the choice exactly
        undo(choice, path, state)
        // Invariant: state is identical to before apply()
```

The `is_invalid` check can also be inlined into `generate_choices` — only yielding choices that don't immediately violate constraints — which is equivalent but cleaner for problems with a clear "valid next choice" definition.

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ─────────────────────────────────────────────────────────
//  EXAMPLE 1: Generate all subsets of [1..n] of size k
// ─────────────────────────────────────────────────────────
class SubsetGenerator {
public:
    vector<vector<int>> combine(int n, int k) {
        vector<vector<int>> results;
        vector<int> path;
        backtrack(1, n, k, path, results);
        return results;
    }

private:
    void backtrack(int start, int n, int k,
                   vector<int>& path, vector<vector<int>>& results) {
        // BASE CASE: path has exactly k elements → valid complete solution
        if ((int)path.size() == k) {
            results.push_back(path);
            return;
        }

        // PRUNING: not enough elements remain to complete the combination
        // Elements remaining: [start, n] → count = n - start + 1
        // Elements still needed: k - path.size()
        // Prune if remaining < needed
        int needed = k - (int)path.size();
        for (int i = start; i <= n - needed + 1; ++i) {
            path.push_back(i);              // CHOOSE
            backtrack(i + 1, n, k, path, results);  // EXPLORE
            path.pop_back();               // UNCHOOSE
        }
    }
};

// ─────────────────────────────────────────────────────────
//  EXAMPLE 2: Generate all permutations of a string
//  with duplicate handling (sorted input required)
// ─────────────────────────────────────────────────────────
class PermutationGenerator {
public:
    vector<string> permuteUnique(string s) {
        sort(s.begin(), s.end());           // sort to group duplicates
        vector<string> results;
        string path;
        vector<bool> used(s.size(), false);
        backtrack(s, path, used, results);
        return results;
    }

private:
    void backtrack(const string& s, string& path,
                   vector<bool>& used, vector<string>& results) {
        if (path.size() == s.size()) {
            results.push_back(path);
            return;
        }

        for (int i = 0; i < (int)s.size(); ++i) {
            // Skip if already used in this path
            if (used[i]) continue;

            // Skip duplicate: if s[i] == s[i-1] and s[i-1] is NOT used,
            // we've already explored this branch via s[i-1]
            // (ensures we pick the leftmost duplicate first)
            if (i > 0 && s[i] == s[i - 1] && !used[i - 1]) continue;

            used[i] = true;
            path.push_back(s[i]);           // CHOOSE
            backtrack(s, path, used, results);  // EXPLORE
            path.pop_back();               // UNCHOOSE
            used[i] = false;
        }
    }
};

// ─────────────────────────────────────────────────────────
//  EXAMPLE 3: Generic template with explicit state type
//  Problem: all paths in a grid from top-left to bottom-right
//  that avoid '#' cells
// ─────────────────────────────────────────────────────────
class GridPathFinder {
    const int dx[4] = {0, 0, 1, -1};
    const int dy[4] = {1, -1, 0, 0};

public:
    vector<vector<pair<int,int>>> findAllPaths(vector<string>& grid) {
        int m = grid.size(), n = grid[0].size();
        vector<vector<pair<int,int>>> results;
        vector<pair<int,int>> path;
        vector<vector<bool>> visited(m, vector<bool>(n, false));

        if (grid[0][0] != '#') {
            visited[0][0] = true;
            path.push_back({0, 0});
            backtrack(grid, 0, 0, m, n, path, visited, results);
        }
        return results;
    }

private:
    void backtrack(vector<string>& grid, int r, int c, int m, int n,
                   vector<pair<int,int>>& path,
                   vector<vector<bool>>& visited,
                   vector<vector<pair<int,int>>>& results) {
        // BASE CASE: reached bottom-right
        if (r == m - 1 && c == n - 1) {
            results.push_back(path);
            return;
        }

        for (int d = 0; d < 4; ++d) {
            int nr = r + dx[d], nc = c + dy[d];

            // PRUNING: out of bounds, wall, or already visited
            if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
            if (grid[nr][nc] == '#' || visited[nr][nc]) continue;

            visited[nr][nc] = true;
            path.push_back({nr, nc});       // CHOOSE
            backtrack(grid, nr, nc, m, n, path, visited, results);  // EXPLORE
            path.pop_back();               // UNCHOOSE
            visited[nr][nc] = false;
        }
    }
};

// ─────────────────────────────────────────────────────────
//  Driver for quick testing
// ─────────────────────────────────────────────────────────
int main() {
    // Test 1: C(4,2) = 6 combinations
    SubsetGenerator sg;
    auto combos = sg.combine(4, 2);
    cout << "C(4,2): " << combos.size() << " combinations\n"; // 6

    // Test 2: Permutations with duplicates
    PermutationGenerator pg;
    auto perms = pg.permuteUnique("aab");
    cout << "Perms of 'aab': " << perms.size() << "\n"; // 3: aab,aba,baa

    // Test 3: Grid paths
    vector<string> grid = {"...", ".#.", "..."};
    GridPathFinder gf;
    auto paths = gf.findAllPaths(grid);
    cout << "Grid paths: " << paths.size() << "\n";

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import List, Callable, TypeVar, Optional

# ─────────────────────────────────────────────────────────
#  Universal backtracking template (higher-order function)
#  Time: O(b^d) worst case, Space: O(d) call stack
# ─────────────────────────────────────────────────────────

T = TypeVar('T')

def backtrack_template(
    path: list,
    is_complete: Callable[[list], bool],
    get_choices: Callable[[list], list],
    apply_choice: Callable[[list, T], None],
    undo_choice: Callable[[list, T], None],
    results: list,
    find_one: bool = False
) -> bool:
    """
    Generic backtracking template.
    
    is_complete: returns True when path is a valid complete solution
    get_choices: returns valid next choices given current path
                 (can embed pruning here — return [] to prune)
    apply_choice / undo_choice: mutate path symmetrically
    find_one: if True, stop after finding the first solution
    
    Returns True if a solution was found (useful for find_one mode).
    """
    if is_complete(path):
        results.append(list(path))  # record a copy, not the mutable path
        return True

    for choice in get_choices(path):
        apply_choice(path, choice)              # CHOOSE
        found = backtrack_template(             # EXPLORE
            path, is_complete, get_choices,
            apply_choice, undo_choice, results, find_one
        )
        undo_choice(path, choice)               # UNCHOOSE

        if find_one and found:
            return True  # short-circuit after first solution

    return False


# ─────────────────────────────────────────────────────────
#  EXAMPLE 1: All subsets of size k (combinations)
#  LC: 77 (Combinations)
# ─────────────────────────────────────────────────────────

def combine(n: int, k: int) -> List[List[int]]:
    """
    Generate all k-length combinations from [1, n].
    Time: O(C(n,k) * k), Space: O(k) excluding output.
    """
    results: List[List[int]] = []

    def backtrack(start: int, path: List[int]) -> None:
        if len(path) == k:
            results.append(list(path))
            return

        # Pruning: need (k - len(path)) more elements;
        # only iterate up to n - (k - len(path)) + 1
        for i in range(start, n - (k - len(path)) + 2):
            path.append(i)          # CHOOSE
            backtrack(i + 1, path)  # EXPLORE (next start is i+1, no repeats)
            path.pop()              # UNCHOOSE

    backtrack(1, [])
    return results


# ─────────────────────────────────────────────────────────
#  EXAMPLE 2: All permutations with possible duplicates
#  LC: 47 (Permutations II)
# ─────────────────────────────────────────────────────────

def permute_unique(nums: List[int]) -> List[List[int]]:
    """
    All unique permutations of nums (may contain duplicates).
    Time: O(n * n!), Space: O(n) call stack.
    
    Key insight: sort first, then skip a duplicate element
    if its left twin was NOT used — this ensures we always
    use the leftmost copy first, preventing duplicate branches.
    """
    nums.sort()
    results: List[List[int]] = []
    used = [False] * len(nums)

    def backtrack(path: List[int]) -> None:
        if len(path) == len(nums):
            results.append(list(path))
            return

        for i in range(len(nums)):
            if used[i]:
                continue
            # Skip: same value as previous, and previous is NOT currently
            # in path. This means we already explored a branch with
            # nums[i-1] at this position, which is equivalent.
            if i > 0 and nums[i] == nums[i - 1] and not used[i - 1]:
                continue

            used[i] = True
            path.append(nums[i])    # CHOOSE
            backtrack(path)         # EXPLORE
            path.pop()              # UNCHOOSE
            used[i] = False

    backtrack([])
    return results


# ─────────────────────────────────────────────────────────
#  EXAMPLE 3: Word search on grid — "find one" mode
#  LC: 79 (Word Search)
# ─────────────────────────────────────────────────────────

def word_search(board: List[List[str]], word: str) -> bool:
    """
    Check if word exists as a path on the board (4-directional).
    Time: O(m*n * 4^L) where L = len(word), Space: O(L).
    
    Demonstrates the 'visited' array as state requiring undo.
    """
    m, n = len(board), len(board[0])
    directions = [(0, 1), (0, -1), (1, 0), (-1, 0)]

    def backtrack(r: int, c: int, idx: int) -> bool:
        # BASE CASE: matched all characters
        if idx == len(word):
            return True

        # PRUNING: out of bounds, wrong character, or already visited
        if r < 0 or r >= m or c < 0 or c >= n:
            return False
        if board[r][c] != word[idx]:
            return False

        # CHOOSE: mark as visited by temporarily overwriting
        temp = board[r][c]
        board[r][c] = '#'           # CHOOSE (mark visited)

        # EXPLORE
        found = any(
            backtrack(r + dr, c + dc, idx + 1)
            for dr, dc in directions
        )

        board[r][c] = temp          # UNCHOOSE (restore)
        return found

    # Try starting from every cell
    return any(
        backtrack(r, c, 0)
        for r in range(m)
        for c in range(n)
    )


# ─────────────────────────────────────────────────────────
#  Quick tests
# ─────────────────────────────────────────────────────────
if __name__ == "__main__":
    # Test 1: C(4,2) = 6
    assert len(combine(4, 2)) == 6

    # Test 2: Unique permutations
    perms = permute_unique([1, 1, 2])
    assert len(perms) == 3  # [[1,1,2],[1,2,1],[2,1,1]]

    # Test 3: Word search
    board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]]
    assert word_search(board, "ABCCED") == True
    assert word_search(board, "SEE")    == True
    assert word_search(board, "ABCB")   == False

    print("All tests passed.")
```

## 7. Common Variations & Extensions

### Variation 1: Subsets with Duplicates (Combination Sum II)

When the input contains duplicates and you want unique subsets, sort the input and skip `nums[i]` when `i > start && nums[i] == nums[i-1]`. This is the same deduplication trick as in `permute_unique` — you only pick the first of a group of identical values at each decision level. See LC 40 (Combination Sum II).

### Variation 2: Partition Problems

Problems like "partition string into palindromes" or "partition array into equal subsets" use backtracking with a different definition of a "valid choice": instead of picking an element to add, you pick a _cut point_ that creates a valid segment. The "state" is the current index, and `is_complete` is "reached the end of the string." See [[175.0-1 Knapsack — item taken or not]] for the DP version of partition — sometimes both approaches are valid.

### Variation 3: Branch-and-Bound (Backtracking + Optimisation)

When you want the _optimal_ solution (not all solutions), maintain a global `best` value and prune branches where the current partial cost already exceeds `best`. This transforms backtracking from an exhaustive search into a directed search. Used in TSP solvers, scheduling problems, and game tree search (though game trees use alpha-beta, which is branch-and-bound for minimax). See [[80.Pruning strategies — forward checking, bounding functions]].

### Variation 4: Constraint Propagation + Backtracking

Instead of only pruning at the current level, propagate constraints _forward_ before recursing — eliminating invalid choices from future decision levels. This is Arc Consistency (AC-3) combined with backtracking, used in [[79.Sudoku solver — constraint propagation + backtracking]]. The result is much stronger pruning: you might discover a dead end three levels deep without recursing there at all.

## 9. CP Contest Application

### Typical Codeforces Problem Structure

**Format:** Small $n$ ($\leq 20$), grid with blocked cells ($m \times n \leq 20 \times 20$), or combinatorial constraints.

**Example pattern (Codeforces 550B "Prepared for Reason"):** Given $n \leq 20$ items, find a subset satisfying multiple inequality constraints. Pure backtracking with constraint checking at each level, time limit 2s. With good pruning, $2^{20} = 1M$ states explored in microseconds.

### Time Limits and When This Matters

- $n \leq 15$: backtracking trivially fast ($2^{15} = 32768$ states)
- $n = 20$: backtracking is feasible if pruning is good; borderline without ($2^{20} = 1M$)
- $n = 25$: only feasible with aggressive pruning or meet-in-the-middle (split into two halves, backtrack each, combine — see [[104.Subset enumeration with bitmask — iterating over all 2^n subsets]])
- $n > 30$: bitmask DP or meet-in-the-middle; pure backtracking will TLE

### Common CP Optimisations

1. **Iterate in sorted order and prune remaining candidates:** If choices are sorted and the current sum exceeds target, `break` (not `continue`) — all subsequent choices are also too large.
2. **Precompute validity:** For N-Queens, maintain three bitsets (column attacks, left-diagonal, right-diagonal). Checking validity is $O(1)$ with bitwise AND instead of $O(n)$ scanning.
3. **Undo with XOR instead of boolean toggle:** For visited sets represented as integers, `state ^= (1 << i)` both sets and unsets in one operation — branchless.
4. **Pass-by-reference throughout:** Avoid copying `path` at every recursive level; `push_back` + `pop_back` on a single vector is faster than constructing new vectors.
