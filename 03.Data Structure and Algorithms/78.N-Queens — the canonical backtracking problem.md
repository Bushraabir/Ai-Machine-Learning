## 1. Intuition First

### The Core Idea

Imagine you are placing 8 chess queens on an 8×8 board. A queen attacks every square in her row, column, and both diagonals. The problem: place N queens such that none attacks another.

The naive approach — try every possible placement of N queens on N² squares — gives us C(N², N) possibilities. For N=8, that's C(64, 8) ≈ 4.4 billion configurations to check. Clearly intractable.

The first insight that cuts this down: **each queen must occupy a distinct row** (since any two queens in the same row attack each other). Similarly, **each column must contain exactly one queen**. So the problem reduces to: find a permutation of columns [c₀, c₁, ..., c_{N-1}] such that queen in row i is placed at column cᵢ, and no two queens share a diagonal.

Now we have N! possibilities — still 40,320 for N=8, but the diagonal constraint eliminates most branches early.

### Why This Exists

The naive O(N²ᴺ) enumeration cannot work even for N=12. The key observation enabling backtracking: **a partial configuration is immediately detectable as invalid**. If we've placed queens in rows 0..k and queen k conflicts with any previous queen, there is no point extending this configuration to rows k+1..N-1. We prune the entire subtree.

This is the core power of backtracking: **we detect infeasibility early and avoid exploring exponential subtrees rooted at invalid states**.

The diagonal constraint is the elegant heart of the implementation. Two queens at (r₁, c₁) and (r₂, c₂) share a diagonal if and only if:

```
|r₁ - r₂| == |c₁ - c₂|
```

Since we place one queen per row in row order, r₁ - r₂ = row_difference is exactly the row gap. So the condition becomes: `c₁ - c₂ ≠ ±row_gap`, which can be tracked with two diagonal sets:

- **Positive diagonal** (`/`): characterized by `r - c = constant`
- **Negative diagonal** (`\`): characterized by `r + c = constant`

### The "Aha" Moment

The single insight that makes N-Queens clean: **encode all three attack constraints as O(1) set lookups — columns, (r-c) diagonals, (r+c) anti-diagonals — and backtracking becomes a sequential column assignment with instant validity checks**.

Once you see this, the recursive structure is trivial: try each column for the current row, check three sets, recurse if valid, undo if we need to backtrack. The algorithm's elegance comes entirely from this encoding, not from clever recursion.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Any problem requiring exact combinatorial enumeration with hard exclusion constraints. N-Queens itself appears in competitions rarely — the _pattern_ it teaches appears constantly.

**The signal:** Look for these keywords:

- "Place / assign / select exactly N items with no two conflicting"
- "Count valid configurations" where validity is compositional (partial solutions can be validated)
- "Generate all solutions" with mutual exclusion constraints
- Grid/board problems where row/column/diagonal conflicts arise

**Decision trigger:**

```
Is the search space too large to enumerate naively?
    ↓ yes
Can a partial solution be validated in O(1) or O(k)?
    ↓ yes
Does an invalid partial solution guarantee no valid extension?
    ↓ yes
→ Backtracking with constraint encoding is the approach
```

**Common trap / submission killer:** Forgetting to **undo the state** after recursing. The backtracking template is _choose → explore → unchoose_. If you add queen to `col_set` before recursing but forget to remove it after, the set leaks state across sibling branches. This is the single most common backtracking bug.

Second trap: re-checking all previous queens inside `is_valid()` in an O(N) loop. Experienced contestants use the three-set encoding for O(1) validation per placement. An O(N) check adds a factor of N to each recursive call, mattering at N=15+.

**Codeforces context:** Direct N-Queens problems appear in Div. 2 C/D range. More importantly, the constraint-encoding pattern appears in:

- Grid colouring with mutual exclusion
- Assignment problems with forbidden pairs
- Permutation construction under multiple constraints

### Machine Learning / AI

**Constraint Satisfaction as Search:** N-Queens is the textbook Constraint Satisfaction Problem (CSP). The ML relevance is deep:

1. **Neural Architecture Search (NAS):** Searching for valid neural network architectures is a backtracking problem over a discrete search space. Tools like Google's AutoML NAS and Microsoft's NNI use forms of constraint-guided search where invalid partial architectures are pruned. Understanding N-Queens' pruning logic directly informs why NAS uses predictors to avoid evaluating doomed sub-architectures.
    
2. **Feature Selection / Subset Search:** [[82.Feature subset search as backtracking — ML connection]] — selecting a subset of features subject to multicollinearity constraints (no two features with correlation > threshold) is structurally N-Queens. Libraries like `mlxtend`'s `SequentialFeatureSelector` do greedy versions; exhaustive search uses backtracking.
    
3. **Hyperparameter Constraint Spaces:** When hyperparameters have mutual exclusion constraints (e.g., "use dropout OR batch norm, not both" or "kernel_size ≤ input_size"), valid configuration spaces are navigated with backtracking in tools like Optuna and Ray Tune's `conditional parameter spaces`.
    
4. **Combinatorial Optimisation in Operations Research (used in ML Pipelines):** Scheduling ML training jobs on GPUs with memory constraints, assigning data shards to workers without overlap — these are assignment CSPs solved with backtracking or ILP. Understanding the algorithmic substrate makes you a better ML infrastructure engineer.
    
5. **AlphaZero / MCTS connection:** Monte Carlo Tree Search explores a game tree using selective expansion. The "pruning invalid moves" step in MCTS is backtracking's spiritual successor. When DeepMind's AlphaGo/AlphaZero prunes illegal moves, it is doing exactly what N-Queens does: detecting infeasibility before exploring subtrees.

## 3. Algorithm / Pattern

### Step-by-Step Logic

```
Place queens row by row, from row 0 to row N-1.

At each row r:
  For each column c in [0, N-1]:
    IF c is not in used_cols
    AND (r - c) is not in used_diag1      # '/' diagonal
    AND (r + c) is not in used_diag2:     # '\' diagonal
        Place queen at (r, c)             # CHOOSE
        Recurse to row r+1                # EXPLORE
        Remove queen from (r, c)          # UNCHOOSE

Base case:
  If r == N: a complete valid placement found → record it
```

### Decision Tree for Attack Constraint Encoding

```
Given queen at (r, c):
  Row conflict     → track which columns are occupied (col_set)
  '/' diagonal     → all cells on same '/' share (r - c) value → diag1_set
  '\' diagonal     → all cells on same '\' share (r + c) value → diag2_set

Query: is (r, c) safe?
  → c not in col_set
  AND (r-c) not in diag1_set
  AND (r+c) not in diag2_set
  All O(1) with hash sets.
```

### Complexity Analysis

**Time:** The number of recursive calls is bounded by the number of nodes in the backtracking search tree. In the worst case, we explore:

```
N × (N-1) × (N-2) × ... × 1 = N!
```

leaves (one choice per row after removing already-used columns). With diagonal pruning, the actual count is much smaller. Empirically for N=8 there are 92 solutions and the tree has ~15,000 nodes. The complexity is written as O(N!) but practical branching factor is far below N.

**Space:** O(N) for the recursion stack (depth = N) plus O(N) for the three constraint sets. The board representation for storing all solutions takes O(N² × S) where S is the number of solutions (grows roughly as N!/6 for large N).

### When to Use vs. Avoid

|Use backtracking when|Avoid when|
|---|---|
|Constraints eliminate large subtrees early|All constraints can only be checked after full placement|
|You need _all_ solutions or _count_ of solutions|Problem has optimal substructure → use DP instead|
|N is small (≤ 15 for most problems)|N is large and approximate solution is acceptable → use heuristics|
|Mutual exclusion constraints are compositional|Problem is a pure permutation problem without constraints → just enumerate|

## 4. Pseudocode

```
function SOLVE_N_QUEENS(n):
    solutions ← []
    board ← array of size n, initialized to -1   // board[r] = column of queen in row r
    col_set ← empty set
    diag1_set ← empty set    // stores (r - c) values
    diag2_set ← empty set    // stores (r + c) values

    function BACKTRACK(row):
        // Base case: all rows filled → valid complete solution
        if row == n:
            solutions.append(copy of board)
            return

        for col in [0, 1, ..., n-1]:
            // Constraint check: O(1) using three sets
            if col in col_set: continue
            if (row - col) in diag1_set: continue
            if (row + col) in diag2_set: continue

            // CHOOSE: place queen at (row, col)
            board[row] ← col
            col_set.add(col)
            diag1_set.add(row - col)
            diag2_set.add(row + col)

            // EXPLORE: move to next row
            BACKTRACK(row + 1)

            // UNCHOOSE: remove queen — critical step
            board[row] ← -1
            col_set.remove(col)
            diag1_set.remove(row - col)
            diag2_set.remove(row + col)

    BACKTRACK(0)
    return solutions

function BOARD_TO_STRING(board, n):
    // Convert column array to list of strings (LeetCode format)
    result ← []
    for r in [0, ..., n-1]:
        row_str ← '.' × n
        row_str[board[r]] ← 'Q'
        result.append(row_str)
    return result
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

class NQueens {
public:
    /**
     * Returns all distinct solutions to the N-Queens puzzle.
     * Each solution is a vector<string> where 'Q' marks a queen and '.' marks empty.
     *
     * Time:  O(N!) worst case — but diagonal pruning makes practical cost << N!
     * Space: O(N) for recursion stack + constraint sets
     */
    vector<vector<string>> solveNQueens(int n) {
        vector<vector<string>> solutions;
        vector<int> board(n, -1);       // board[row] = column of queen in that row

        unordered_set<int> col_set;
        unordered_set<int> diag1_set;   // (row - col) constant on '/' diagonals
        unordered_set<int> diag2_set;   // (row + col) constant on '\' diagonals

        backtrack(0, n, board, col_set, diag1_set, diag2_set, solutions);
        return solutions;
    }

    /**
     * Count-only variant — avoids storing all solutions.
     * Useful for the "totalNQueens" LeetCode problem.
     */
    int totalNQueens(int n) {
        int count = 0;
        unordered_set<int> col_set, diag1_set, diag2_set;
        countBacktrack(0, n, col_set, diag1_set, diag2_set, count);
        return count;
    }

private:
    void backtrack(
        int row, int n,
        vector<int>& board,
        unordered_set<int>& col_set,
        unordered_set<int>& diag1_set,
        unordered_set<int>& diag2_set,
        vector<vector<string>>& solutions
    ) {
        // Base case: placed queens in all rows
        if (row == n) {
            solutions.push_back(boardToStrings(board, n));
            return;
        }

        for (int col = 0; col < n; ++col) {
            // O(1) constraint checks using hash sets
            if (col_set.count(col)) continue;
            if (diag1_set.count(row - col)) continue;
            if (diag2_set.count(row + col)) continue;

            // CHOOSE
            board[row] = col;
            col_set.insert(col);
            diag1_set.insert(row - col);
            diag2_set.insert(row + col);

            // EXPLORE
            backtrack(row + 1, n, board, col_set, diag1_set, diag2_set, solutions);

            // UNCHOOSE — must mirror every insertion above
            board[row] = -1;
            col_set.erase(col);
            diag1_set.erase(row - col);
            diag2_set.erase(row + col);
        }
    }

    void countBacktrack(
        int row, int n,
        unordered_set<int>& col_set,
        unordered_set<int>& diag1_set,
        unordered_set<int>& diag2_set,
        int& count
    ) {
        if (row == n) { ++count; return; }
        for (int col = 0; col < n; ++col) {
            if (col_set.count(col) || diag1_set.count(row - col) || diag2_set.count(row + col))
                continue;
            col_set.insert(col); diag1_set.insert(row - col); diag2_set.insert(row + col);
            countBacktrack(row + 1, n, col_set, diag1_set, diag2_set, count);
            col_set.erase(col); diag1_set.erase(row - col); diag2_set.erase(row + col);
        }
    }

    vector<string> boardToStrings(const vector<int>& board, int n) {
        vector<string> result(n, string(n, '.'));
        for (int r = 0; r < n; ++r)
            result[r][board[r]] = 'Q';
        return result;
    }
};

// ── Bitmask variant: O(N) per level, cache-friendly ──────────────────────────
// For competitive programming where N ≤ 15 and speed matters.
// Uses bitmasks to represent col, diag1, diag2 instead of hash sets.
class NQueensBitmask {
    int n, count = 0;
    int full_mask;

    void solve(int row, int col_mask, int diag1_mask, int diag2_mask) {
        if (row == n) { ++count; return; }
        // available = columns not attacked in this row
        int available = full_mask & ~(col_mask | diag1_mask | diag2_mask);
        while (available) {
            int bit = available & (-available);         // lowest set bit = rightmost free column
            available &= available - 1;                 // remove that bit
            solve(row + 1,
                  col_mask  | bit,
                  (diag1_mask | bit) << 1,              // '/' diagonal shifts left each row
                  (diag2_mask | bit) >> 1);             // '\' diagonal shifts right each row
        }
    }

public:
    int totalNQueens(int n_) {
        n = n_;
        full_mask = (1 << n) - 1;
        solve(0, 0, 0, 0);
        return count;
    }
};

// ── Minimal test ──────────────────────────────────────────────────────────────
int main() {
    NQueens solver;
    auto solutions = solver.solveNQueens(4);
    cout << "N=4 solutions: " << solutions.size() << "\n";   // expected: 2
    for (auto& sol : solutions) {
        for (auto& row : sol) cout << row << "\n";
        cout << "\n";
    }

    NQueens s8;
    cout << "N=8 solutions: " << s8.solveNQueens(8).size() << "\n";  // expected: 92

    NQueensBitmask bm;
    cout << "N=8 bitmask count: " << bm.totalNQueens(8) << "\n";     // expected: 92
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import List, Set

def solve_n_queens(n: int) -> List[List[str]]:
    """
    Return all solutions to the N-Queens problem.

    Each solution is a list of n strings, where 'Q' marks a queen.

    Time:  O(N!) worst-case; pruning makes practical cost << N!
    Space: O(N) stack + O(N) constraint sets
    """
    solutions: List[List[str]] = []
    board: List[int] = [-1] * n          # board[row] = column of queen

    col_set: Set[int] = set()
    diag1_set: Set[int] = set()          # stores (row - col) values
    diag2_set: Set[int] = set()          # stores (row + col) values

    def backtrack(row: int) -> None:
        # Base case: all rows have queens
        if row == n:
            solutions.append(board_to_strings(board, n))
            return

        for col in range(n):
            # O(1) validity check — the three constraints
            if col in col_set:           continue
            if row - col in diag1_set:   continue
            if row + col in diag2_set:   continue

            # CHOOSE: place queen at (row, col)
            board[row] = col
            col_set.add(col)
            diag1_set.add(row - col)
            diag2_set.add(row + col)

            # EXPLORE: recurse to next row
            backtrack(row + 1)

            # UNCHOOSE: remove queen — mirrors every add() above
            board[row] = -1
            col_set.discard(col)
            diag1_set.discard(row - col)
            diag2_set.discard(row + col)

    backtrack(0)
    return solutions


def board_to_strings(board: List[int], n: int) -> List[str]:
    """Convert column-index board to list-of-strings format."""
    result = []
    for col in board:
        row_str = ['.'] * n
        row_str[col] = 'Q'
        result.append(''.join(row_str))
    return result


def total_n_queens(n: int) -> int:
    """Count solutions only — avoids storing all boards."""
    count = 0
    col_set: Set[int] = set()
    diag1_set: Set[int] = set()
    diag2_set: Set[int] = set()

    def backtrack(row: int) -> None:
        nonlocal count
        if row == n:
            count += 1
            return
        for col in range(n):
            if col in col_set or (row - col) in diag1_set or (row + col) in diag2_set:
                continue
            col_set.add(col); diag1_set.add(row - col); diag2_set.add(row + col)
            backtrack(row + 1)
            col_set.discard(col); diag1_set.discard(row - col); diag2_set.discard(row + col)

    backtrack(0)
    return count


# ── Bitmask variant (concise, fast) ──────────────────────────────────────────
def total_n_queens_bitmask(n: int) -> int:
    """
    Bitmask backtracking: encode col/diag1/diag2 as integers.
    Bit position = column index. O(1) bitmask ops replace set operations.
    """
    full = (1 << n) - 1   # all N columns available = N ones

    def solve(col_mask: int, diag1_mask: int, diag2_mask: int) -> int:
        if col_mask == full:   # all columns occupied → valid placement
            return 1
        total = 0
        # available: columns not under attack in current row
        available = full & ~(col_mask | diag1_mask | diag2_mask)
        while available:
            bit = available & (-available)         # isolate lowest set bit
            available &= available - 1             # remove it
            total += solve(
                col_mask  | bit,
                (diag1_mask | bit) << 1,           # '/' diagonal propagates left
                (diag2_mask | bit) >> 1,           # '\' diagonal propagates right
            )
        return total

    return solve(0, 0, 0)


# ── Tests ─────────────────────────────────────────────────────────────────────
if __name__ == "__main__":
    print(f"N=1: {total_n_queens(1)}")              # 1
    print(f"N=4: {len(solve_n_queens(4))}")         # 2
    print(f"N=8: {total_n_queens(8)}")              # 92
    print(f"N=8 bitmask: {total_n_queens_bitmask(8)}")  # 92
    print(f"N=9: {total_n_queens_bitmask(9)}")      # 352

    # Show one N=4 solution
    for sol in solve_n_queens(4):
        for row in sol: print(row)
        print()
```

                               → col_set  += {3}
                               → diag1_set += {1-3 = -2}
                               → diag2_set += {1+3 =  4}

row 2:    ?   ?   ?   ?       Trying to place queen:

  col=0: (2-0)=2 ∉ diag1 ✓   (2+0)=2 ∉ diag2 ✓   col=0 ∉ col_set ✓  → VALID ✓
  col=1: col=1 ∈ col_set  ✗  → SKIP
  col=2: (2-2)=0 ∉ diag1 ✓   (2+2)=4 ∈ diag2  ✗  → SKIP (anti-diag conflict with (1,3))
  col=3: col=3 ∈ col_set  ✗  → SKIP

  → Only col=0 is valid for row 2

         row1   row1   row1   row1
        ┌─┴─┐  ┌─┴─┐  ┌─┴─┐  ┌─┴─┐
       c=2 c=3 c=3  X  X  c=0 c=0  X

### Diagram 3: Bitmask Encoding (N=4)

```
full_mask = 0b1111  (columns 0,1,2,3 all available)

After placing queen at col=1 (row 0):
  col_mask  = 0b0010
  diag1 propagates LEFT  each row: 0b0010 << 1 = 0b0100
  diag2 propagates RIGHT each row: 0b0010 >> 1 = 0b0001

Row 1 attack mask = col_mask | diag1 | diag2
                  = 0b0010 | 0b0100 | 0b0001

                   → only column 3 is free  ✓  (matches diagram 1)

Each bit-operation replaces a set.add() + set.discard() pair.
This is why the bitmask version is 3-5x faster in practice.
```

## 7. Common Variations & Extensions

### 7.1 Total Count Only (LeetCode 52)

If you only need the _count_ of solutions (not the boards), drop the `board_to_strings` step and increment a counter at the base case. This reduces memory from O(N² × solutions) to O(1) extra. The bitmask variant is especially natural here — no board array needed at all.

### 7.2 N-Queens with Blocked Cells

Some contest variants pre-block certain cells (e.g., "cell (r, c) cannot have a queen"). Extend the validity check with an additional `blocked_set.contains((r, c))` condition. The backtracking structure is unchanged — you're just adding one more constraint to the O(1) check.

### 7.3 N-Rooks Problem

Remove the diagonal constraints entirely — place N rooks such that no two share a row or column. This reduces to: find any permutation of columns, i.e., N! solutions all valid. The backtracking becomes a permutation generator — see [[73.Generating all permutations — swap-based and insert-based]].

### 7.4 Generalised Constraint Satisfaction (Sudoku)

N-Queens is the gateway to general CSP. [[79.Sudoku solver — constraint propagation + backtracking]] takes this further: instead of N identical constraints (one per row), Sudoku has heterogeneous row/column/box constraints. The same _choose → explore → unchoose_ template applies, with a more complex constraint propagation step. The key upgrade is **arc consistency** (AC-3 algorithm), which [[80.Pruning strategies — forward checking, bounding functions]] covers — it prunes domains before even recursing, dramatically reducing tree size.

### 7.5 First Solution Only (Early Exit)

To find just one solution, add `if solutions: return` after the base case append, or use a boolean return value from `backtrack()`. Once `True` is returned from a recursive call, propagate it up without exploring siblings. This can be orders of magnitude faster when you only need existence.

## 9. CP Contest Application

### Typical Contest Structure

N-Queens itself rarely appears verbatim in modern competitive programming. The pattern appears in problems like:

- **Grid placement with mutual exclusion:** "Place K bishops on an N×N board such that no two attack each other" — same diagonal constraint, adapted constraint sets.
- **Assignment CSPs:** "Assign N tasks to N workers such that pairs (i, j) in a forbidden set are not co-assigned." Column = worker, row = task, forbidden pairs replace diagonal constraints.
- **Counting with constraints:** Codeforces Div. 2 D/E often asks for count of valid configurations modulo 1e9+7. Backtracking count + memoisation of partial states.

### Time Limit Considerations

For N ≤ 15 in a 1-2 second time limit:

- Hash-set backtracking is fine for N ≤ 13
- Bitmask backtracking handles N ≤ 20 comfortably (no allocation overhead)
- Profile pruning: if fewer than 50% of recursive calls are pruned, consider whether constraint representation is incomplete

### Optimisation Tricks

1. **Symmetry breaking:** The board has 8-fold symmetry (4 rotations × reflection). For counting problems only, generate solutions for column ≤ N/2 in row 0 and multiply — halves or quarters the search time. Don't apply for "generate all" problems.
    
2. **Column ordering heuristic:** Try the most-constrained column first (the column with the fewest remaining valid placements). This is the "fail-first" or MRV (Minimum Remaining Values) heuristic from CSP literature. For N=20+, this reduces backtracking nodes by 10x+ in practice.
    
3. **Precomputed attack bitmasks:** For fixed-constraint problems, precompute which cells each queen position attacks as a bitmask, then use bitwise OR to aggregate. This is the bitmask variant taken to its logical extreme.
    
4. **Profile DP for exact counting:** For very large N where you don't need the boards, profile dynamic programming (DP over column permutation profiles) can count solutions in O(N × N!) with memoisation — equivalent to the bitmask DP idea in [[105.Bitmask DP — state compression]].
