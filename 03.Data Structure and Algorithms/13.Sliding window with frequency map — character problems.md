# 13. Sliding Window with Frequency Map — Character Problems

> _"The window doesn't just track positions. It carries a living histogram of what's inside it — and the histogram is the state that makes complex character constraints solvable in O(n)."_

---

## What Makes This a Distinct Pattern

Notes [[11]] and [[12]] used simple scalar state — a running sum or a distinct-count integer. Character problems need richer state: not just _how many_ characters are in the window, but _which_ characters and _how often_. The **frequency map** (a hash map from character → count) is that richer state.

The key operations are still O(1) amortised:

```python
# add a character entering the window
freq[c] += 1               # or freq[c] = freq.get(c, 0) + 1

# remove a character leaving the window
freq[c] -= 1
if freq[c] == 0:
    del freq[c]            # keep the map clean — only live characters
```

Everything else from notes 11–12 applies directly. The frequency map is the state; the window mechanics are unchanged.

---

## The Three Canonical Problems

### Problem 1 — Permutation in String

> Given strings `s` and `p`, return `True` if any permutation of `p` is a substring of `s`.

**Insight:** A window of length `|p|` over `s` is a permutation of `p` if and only if their frequency maps are identical. Instead of comparing full maps at every step (O(|p|) per step), maintain a `need` counter: the number of character slots in `p` that the current window has not yet satisfied.

```python
from collections import Counter

def check_inclusion(s: str, p: str) -> bool:
    if len(p) > len(s):
        return False

    need = Counter(p)           # freq map of p — what we must satisfy
    have = {}                   # freq map of current window
    satisfied = 0               # chars whose count in window >= count in need
    required = len(need)        # number of distinct chars we must satisfy

    left = 0

    for right in range(len(s)):
        # ── EXPAND ──
        c = s[right]
        have[c] = have.get(c, 0) + 1
        if c in need and have[c] == need[c]:
            satisfied += 1      # this char is now exactly satisfied

        # ── SHRINK (fixed window: slide when size > |p|) ──
        if right - left + 1 > len(p):
            lc = s[left]
            if lc in need and have[lc] == need[lc]:
                satisfied -= 1  # about to lose a satisfied char
            have[lc] -= 1
            if have[lc] == 0:
                del have[lc]
            left += 1

        # ── CHECK ──
        if satisfied == required:
            return True

    return False


# Examples
print(check_inclusion("eidbaooo", "ab"))   # True  — "ba" at index 3
print(check_inclusion("eidboaoo", "ab"))   # False
```

**The `satisfied` counter is the key trick.** Instead of comparing two dicts every step, we track how many characters are "fully covered." When `satisfied == required`, the window is a valid permutation. This makes the check O(1) per step.

### Problem 2 — Find All Anagrams in a String

> Return the start indices of all anagram substrings of `s` that are permutations of `p`.

Same logic as Problem 1, but collect all valid window start positions instead of returning on the first match.

```python
from collections import Counter

def find_anagrams(s: str, p: str) -> list[int]:
    if len(p) > len(s):
        return []

    need = Counter(p)
    have = {}
    satisfied = 0
    required = len(need)
    result = []
    left = 0

    for right in range(len(s)):
        c = s[right]
        have[c] = have.get(c, 0) + 1
        if c in need and have[c] == need[c]:
            satisfied += 1

        if right - left + 1 > len(p):
            lc = s[left]
            if lc in need and have[lc] == need[lc]:
                satisfied -= 1
            have[lc] -= 1
            if have[lc] == 0:
                del have[lc]
            left += 1

        if satisfied == required:
            result.append(left)     # window [left..right] is valid

    return result


# s = "cbaebabacd", p = "abc"
print(find_anagrams("cbaebabacd", "abc"))   # [0, 6]
# Window [0,2] = "cba" ✓   Window [6,8] = "bac" ✓
```

**Complexity:** O(n + |p|) time, O(|p|) space (the maps hold at most |p| distinct characters).

### Problem 3 — Minimum Window Substring

> Given strings `s` and `t`, find the shortest substring of `s` that contains all characters of `t` (including duplicates).

This is variable-size (Flavour B from note 12): shrink the window greedily as long as it remains valid, recording the minimum length.

```python
from collections import Counter

def min_window(s: str, t: str) -> str:
    if not t or not s:
        return ""

    need = Counter(t)
    have = {}
    satisfied = 0
    required = len(need)

    left = 0
    best_len = float('inf')
    best_l = 0

    for right in range(len(s)):
        # EXPAND
        c = s[right]
        have[c] = have.get(c, 0) + 1
        if c in need and have[c] == need[c]:
            satisfied += 1

        # SHRINK while valid (Flavour B: record inside the while loop)
        while satisfied == required:
            window_len = right - left + 1
            if window_len < best_len:
                best_len = window_len
                best_l = left

            lc = s[left]
            have[lc] -= 1
            if lc in need and have[lc] < need[lc]:
                satisfied -= 1      # lost coverage of this character
            if have[lc] == 0:
                del have[lc]
            left += 1

    return "" if best_len == float('inf') else s[best_l : best_l + best_len]


# Examples
print(min_window("ADOBECODEBANC", "ABC"))  # "BANC"
print(min_window("a", "aa"))               # "" — impossible
print(min_window("aa", "aa"))              # "aa"
```

### Problem 4 — Longest Substring with Exactly K Distinct Characters

A subtle but important variant: "exactly K" is harder than "at most K" because the window can violate the constraint in two directions (too few or too many). The standard trick:

```
exactly_k(A, k) = at_most_k(A, k) - at_most_k(A, k-1)
```

```python
from collections import defaultdict

def at_most_k_distinct(s: str, k: int) -> int:
    """Longest substring with AT MOST k distinct characters."""
    freq = defaultdict(int)
    left = 0
    best = 0
    for right in range(len(s)):
        freq[s[right]] += 1
        while len(freq) > k:
            freq[s[left]] -= 1
            if freq[s[left]] == 0:
                del freq[s[left]]
            left += 1
        best = max(best, right - left + 1)
    return best

def exactly_k_distinct(s: str, k: int) -> int:
    """Longest substring with EXACTLY k distinct characters."""
    if k == 0:
        return 0
    return at_most_k_distinct(s, k) - at_most_k_distinct(s, k - 1)


# s = "eceba", k = 2
print(exactly_k_distinct("eceba", 2))   # 3  ("ece")
```

This decomposition appears repeatedly in competitive programming whenever "exactly k" resists the direct sliding window approach.

## The `satisfied` Counter — Deep Dive

This is the most reusable insight in this entire topic. Maintain:

- `need[c]` = how many of character `c` are required
- `have[c]` = how many of character `c` are in the current window
- `satisfied` = number of distinct chars `c` where `have[c] >= need[c]`
- `required = len(need)`

Window is **valid** ⟺ `satisfied == required`.

Update rules:

```python
# When c ENTERS the window:
have[c] += 1
if c in need and have[c] == need[c]:
    satisfied += 1          # exactly reached the threshold — not exceeded

# When c LEAVES the window:
if c in need and have[c] == need[c]:
    satisfied -= 1          # about to drop below threshold
have[c] -= 1
if have[c] == 0:
    del have[c]
```

The subtlety: `satisfied` only changes when a count _crosses_ the threshold (goes from `need[c]-1` to `need[c]` or vice versa). Going from `need[c]` to `need[c]+1` does **not** change `satisfied` — you are already satisfied on that character.

This is why the check `have[c] == need[c]` appears on the entering side (not `>=`) and again on the leaving side (not `<`).

---

## Formal Correctness

**Claim (for fixed-size window, Problem 1):** At every step after the first window of size `|p|` is formed, `satisfied == required` if and only if the current window is a permutation of `p`.

**Proof:**

(⇒) If `satisfied == required`, then for every `c` in `need`, `have[c] >= need[c]`. The total characters in the window equals `|p|` (fixed size). Since `∑ need[c] = |p|` and `∑ have[c] = |p|` and `have[c] >= need[c]` for all `c`, we must have `have[c] == need[c]` for all `c`. So the frequency maps are equal — the window is a permutation of `p`. ✓

(⇐) If the window is a permutation, then `have[c] == need[c]` for all `c` in `need`, so every character is satisfied. ✓

The fixed-size constraint is load-bearing in this proof: without it, `have[c] >= need[c]` for all `c` does not imply equality.

## Complexity

|Problem|Time|Space|
|---|---|---|
|Permutation in string|O(n + \|p\|)|O(\|p\|)|
|Find all anagrams|O(n + \|p\|)|O(\|p\|)|
|Minimum window substring|O(n + \|t\|)|O(\|t\| + alphabet)|
|At most K distinct|O(n)|O(k)|
|Exactly K distinct|O(n)|O(k)|

All are linear in `|s|` because each character is added to the window once and removed at most once.

## NumPy / Vectorised Approach for Fixed Alphabet

When the alphabet is small and fixed (e.g., lowercase a–z = 26 characters), you can represent `need` and `have` as **length-26 arrays** and compare them with `np.array_equal`. This is often faster in practice for large inputs.

```python
import numpy as np

def find_anagrams_np(s: str, p: str) -> list[int]:
    """Vectorised version using 26-element count arrays."""
    if len(p) > len(s):
        return []

    def char_vec(string: str) -> np.ndarray:
        v = np.zeros(26, dtype=np.int32)
        for c in string:
            v[ord(c) - ord('a')] += 1
        return v

    need = char_vec(p)
    have = char_vec(s[:len(p)])         # first window
    result = []
    k = len(p)

    if np.array_equal(need, have):
        result.append(0)

    for i in range(len(s) - k):
        outgoing = ord(s[i]) - ord('a')
        incoming = ord(s[i + k]) - ord('a')
        have[outgoing] -= 1
        have[incoming] += 1
        if np.array_equal(need, have):
            result.append(i + 1)

    return result


print(find_anagrams_np("cbaebabacd", "abc"))   # [0, 6]
```

For very long strings with a small fixed alphabet, `np.array_equal` on two 26-element arrays is faster than dict comparison due to contiguous memory access and SIMD acceleration.

## Connection to AI / ML / Deep Learning

### 1. Vocabulary frequency tracking in tokenisers

Byte-pair encoding (BPE) — used in GPT models — builds a vocabulary by repeatedly merging the most frequent adjacent character pair in the training corpus. The underlying operation is maintaining frequency maps over sliding contexts in the text, exactly this pattern.

### 2. Bag-of-words and n-gram features

Classical NLP feature engineering computes character or word n-gram histograms over sliding windows of text. Sentiment analysis, authorship attribution, and language identification all use frequency maps over fixed or variable windows. The `have` / `need` pattern maps directly onto computing whether a document window "covers" a query's vocabulary.

### 3. Attention masks over character sequences

When Transformers process character-level inputs (e.g., CharBERT, ByT5), attention is sometimes restricted to windows over the character sequence. The frequency map tracks which characters are "in scope" for each token's local attention — same data structure, different name.

### 4. Sequence-to-sequence coverage mechanisms

In seq2seq models with coverage (to prevent repeating source words), a coverage vector accumulates how many times each source token has been attended to. The "coverage deficit" — `need[c] - have[c]` — is exactly the gap tracked by `satisfied < required`. Coverage loss in models like Pointer Networks penalises uncovered source tokens, an analogue of the `satisfied != required` condition.

### 5. Regular expression matching engines

Many regex engines implement character-class matching (`[abc]`, `[^xyz]`) using frequency maps or bitsets. A sliding window over the input with a bitmask of present characters is the vectorised form of the frequency map approach — and this is how `re` engines achieve near-linear matching for character-class patterns.

### 6. DNA sequence analysis

Bioinformatics frequently asks: "does any window of length k over this genome contain at least one copy of each of these k-mer fragments?" This is the permutation-in-string / all-anagrams problem at biological scale, solved identically.

## Common Mistakes

```python
# Mistake 1: Using >= in the satisfied-entry update
if c in need and have[c] >= need[c]:    # WRONG — fires every time, not just at threshold
    satisfied += 1
# Fix: strict equality at the exact threshold crossing
if c in need and have[c] == need[c]:    # correct

# Mistake 2: Forgetting to decrement satisfied BEFORE removing from have
have[lc] -= 1                           # WRONG — threshold check now compares wrong value
if lc in need and have[lc] == need[lc]:
    satisfied -= 1
# Fix: check threshold BEFORE modifying have
if lc in need and have[lc] == need[lc]:
    satisfied -= 1                      # correct order
have[lc] -= 1

# Mistake 3: Not cleaning zero-count keys
have[lc] -= 1                           # count drops to 0 but key stays
len(have)                               # still counts 'lc' — wrong distinct count

if have[lc] == 0:
    del have[lc]                        # correct: prune the map

# Mistake 4: Initialising have from s[:len(p)] AND running the full loop
# This double-counts the first window. Either:
#   (a) start the loop at index 0 (let the loop build the first window)
#   (b) pre-fill have and start the loop at index len(p)
# Never do both.

# Mistake 5: Forgetting characters not in `need` still enter `have`
# have can contain chars not in need — that's fine.
# Only check `if c in need` before updating satisfied.

# Mistake 6: Using Counter subtraction as a shortcut check
Counter(need) == Counter(have)           # O(|p|) per step — defeats the purpose
# Use the satisfied counter instead: O(1) per step.
```

## Template Reference

```python
from collections import Counter

def freq_window_template(s: str, pattern: str, fixed: bool) -> ...:
    need = Counter(pattern)
    have = {}
    satisfied = 0
    required = len(need)
    left = 0
    # answer tracking depends on problem type

    for right in range(len(s)):
        # ── EXPAND ──────────────────────────────────────────
        c = s[right]
        have[c] = have.get(c, 0) + 1
        if c in need and have[c] == need[c]:
            satisfied += 1

        # ── SHRINK ──────────────────────────────────────────
        if fixed:
            # fixed-size window: slide when oversized
            if right - left + 1 > len(pattern):
                lc = s[left]
                if lc in need and have[lc] == need[lc]:
                    satisfied -= 1
                have[lc] -= 1
                if have[lc] == 0: del have[lc]
                left += 1
        else:
            # variable-size: shrink while valid (Flavour B, shortest)
            while satisfied == required:
                # record answer here (shortest window)
                lc = s[left]
                if lc in need and have[lc] == need[lc]:
                    satisfied -= 1
                have[lc] -= 1
                if have[lc] == 0: del have[lc]
                left += 1

        # ── RECORD ──────────────────────────────────────────
        if fixed and satisfied == required:
            pass  # record here (anagram found, permutation exists, etc.)
        # for variable-size, recording is inside the while loop above

    return ...
```

## Summary

|Concept|One-liner|
|---|---|
|Core state|`have`: freq map of window chars; `need`: freq map of target|
|`satisfied` counter|Number of chars `c` where `have[c] >= need[c]`|
|Valid window|`satisfied == required` (O(1) check)|
|Enter update|`have[c] += 1`; if `have[c] == need[c]`: `satisfied += 1`|
|Leave update|if `have[c] == need[c]`: `satisfied -= 1`; then `have[c] -= 1`|
|Fixed window|Slide when `right - left + 1 > len(pattern)`|
|Variable window (shortest)|Shrink while `satisfied == required`; record inside loop|
|"Exactly k" trick|`exactly_k = at_most_k(k) - at_most_k(k-1)`|
|NumPy optimisation|26-element count array + `np.array_equal` for fixed alphabet|
