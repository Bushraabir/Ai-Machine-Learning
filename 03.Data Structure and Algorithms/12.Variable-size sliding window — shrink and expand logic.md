# 12. Variable-Size Sliding Window — Shrink and Expand Logic

> _"You don't always know how big your window needs to be. So you grow it until it breaks a rule, then shrink it until it's valid again — and every position in between is a candidate answer."_

---

## How It Differs From Fixed-Size

In [[11. Fixed-Size Sliding Window]], `k` is given. The window always has exactly `k` elements; left pointer and right pointer move in lockstep.

In the **variable-size** version, the window size is not fixed. It is determined by a **constraint**: a condition that the window's contents must satisfy (or maximally violate). The two pointers move **independently**:

- `right` expands the window by including a new element.
- `left` shrinks the window by excluding the oldest element — but only when the constraint is violated.

This asymmetry is the core insight.

---

## The Universal Template

Every variable-size sliding window problem fits this skeleton:

```python
def sliding_window(A, constraint):
    left = 0
    state = initial_state()        # e.g. current sum, char count, freq map
    answer = default_answer()      # e.g. 0, float('inf'), []

    for right in range(len(A)):
        # 1. EXPAND: include A[right] in the window
        update_state(state, A[right], add=True)

        # 2. SHRINK: restore constraint while it is violated
        while constraint_violated(state):
            update_state(state, A[left], add=False)
            left += 1

        # 3. RECORD: current window [left..right] is valid
        answer = update_answer(answer, right - left + 1)

    return answer
```

The `while` on line 2 is the shrink loop. When the constraint is _met_, the outer `for` loop moves `right` forward (expand). When the constraint is _violated_, the inner `while` loop moves `left` forward (shrink). Together they implement an accordion.

**Amortised O(n):** Each element is added to the window exactly once and removed at most once → total operations ≤ 2n.

---

## The Two Flavours of Constraint

### Flavour A — Find the longest window satisfying a condition

_"What is the longest subarray/substring where [condition]?"_

The shrink loop fires when the condition is **violated**. After shrinking back to validity, the window `[left..right]` is the longest valid window ending at `right`. Update `answer = max(answer, right - left + 1)`.

### Flavour B — Find the shortest window satisfying a condition

_"What is the shortest subarray/substring that satisfies [condition]?"_

The shrink loop fires when the condition is **met** (you want to greedily shrink while it is still satisfied). After recording, try to shrink further. Update `answer = min(answer, right - left + 1)` **inside** the while loop, not after it.

The template is almost identical — only the while-condition and where you record the answer change.

## Four Worked Examples

### Example 1 — Longest subarray with sum ≤ target (Flavour A)

```python
def longest_subarray_sum_le(A, target):
    """Find the longest contiguous subarray with sum ≤ target."""
    left = 0
    curr_sum = 0
    best = 0

    for right in range(len(A)):
        curr_sum += A[right]                   # expand

        while curr_sum > target:               # shrink while violated
            curr_sum -= A[left]
            left += 1

        best = max(best, right - left + 1)     # record

    return best


# A = [1, 2, 3, 4, 5], target = 7
# Trace:
# right=0: sum=1, window=[1], best=1
# right=1: sum=3, window=[1,2], best=2
# right=2: sum=6, window=[1,2,3], best=3
# right=3: sum=10 > 7 → shrink: sum=9 (left=1), sum=7 (left=2), window=[3,4], best=3
# right=4: sum=12 > 7 → shrink: sum=9 (left=3), sum=5 (left=4), window=[5], best=3
# Answer: 3  (subarray [1,2,3] or [3,4])
print(longest_subarray_sum_le([1, 2, 3, 4, 5], 7))  # 3
```

### Example 2 — Longest substring with at most K distinct characters (Flavour A)

A classic interview problem. State = frequency map of characters in the window.

```python
from collections import defaultdict

def longest_k_distinct(s, k):
    """Longest substring with at most k distinct characters."""
    freq = defaultdict(int)
    left = 0
    best = 0

    for right in range(len(s)):
        freq[s[right]] += 1                    # expand: add right char

        while len(freq) > k:                   # shrink: too many distinct chars
            freq[s[left]] -= 1
            if freq[s[left]] == 0:
                del freq[s[left]]
            left += 1

        best = max(best, right - left + 1)     # window is valid here

    return best


# s = "eceba", k = 2
# right=0: freq={e:1},          window="e",     best=1
# right=1: freq={e:1,c:1},      window="ec",    best=2
# right=2: freq={e:2,c:1},      window="ece",   best=3
# right=3: freq={e:2,c:1,b:1},  3 distinct > 2
#           shrink: remove e→{c:1,b:1,e:1}→still 3, remove c→{b:1,e:1}
#           left=2, window="eb", best=3
# right=4: freq={b:1,e:1,a:1},  3 distinct > 2
#           shrink: remove e→{b:1,a:1}, left=3, window="ba", best=3
# Answer: 3 ("ece")
print(longest_k_distinct("eceba", 2))  # 3
```

### Example 3 — Minimum window substring (Flavour B)

Given strings `s` and `t`, find the shortest window in `s` that contains all characters of `t`.

This is Flavour B: shrink **as long as the window is still valid**, recording the minimum each time.

```python
from collections import Counter

def min_window_substring(s, t):
    """Shortest substring of s containing all chars of t."""
    need = Counter(t)          # required frequencies
    have = {}                  # current window frequencies
    formed = 0                 # how many chars satisfy their required count
    required = len(need)

    left = 0
    best_len = float('inf')
    best_l = 0

    for right in range(len(s)):
        c = s[right]
        have[c] = have.get(c, 0) + 1
        if c in need and have[c] == need[c]:
            formed += 1                        # one more char is satisfied

        # Shrink as long as window is valid (Flavour B)
        while formed == required:
            window_len = right - left + 1
            if window_len < best_len:          # record INSIDE the while loop
                best_len = window_len
                best_l = left

            # shrink from left
            lc = s[left]
            have[lc] -= 1
            if lc in need and have[lc] < need[lc]:
                formed -= 1                    # lost a satisfied character
            left += 1

    if best_len == float('inf'):
        return ""
    return s[best_l : best_l + best_len]


# s = "ADOBECODEBANC", t = "ABC"
print(min_window_substring("ADOBECODEBANC", "ABC"))  # "BANC"
```

The key difference from Flavour A: the `while` condition is `formed == required` (i.e., the window **is** valid), and we record inside the while before shrinking further.

### Example 4 — Longest substring without repeating characters (Flavour A, classic)

```python
def length_of_longest_substring(s):
    seen = {}        # char → most recent index
    left = 0
    best = 0

    for right in range(len(s)):
        c = s[right]
        # If c was seen and is inside the current window, jump left past it
        if c in seen and seen[c] >= left:
            left = seen[c] + 1
        seen[c] = right
        best = max(best, right - left + 1)

    return best


# s = "abcabcbb"
# right=0: c='a', left=0, window="a",   best=1
# right=1: c='b', left=0, window="ab",  best=2
# right=2: c='c', left=0, window="abc", best=3
# right=3: c='a', seen['a']=0 >= left=0 → left=1, window="bca", best=3
# right=4: c='b', seen['b']=1 >= left=1 → left=2, window="cab", best=3
# right=5: c='c', seen['c']=2 >= left=2 → left=3, window="abc", best=3
# right=6: c='b', seen['b']=4 >= left=3 → left=5, window="cb",  best=3
# right=7: c='b', seen['b']=6 >= left=5 → left=7, window="b",   best=3
# Answer: 3 ("abc")
print(length_of_longest_substring("abcabcbb"))  # 3
```

Note: this version uses a hash map to jump `left` directly instead of a while loop — an optimisation that works when the shrink step can be computed in O(1) without iterating.

## Choosing the Right State

The choice of `state` determines everything:

|Problem type|State data structure|Update cost|
|---|---|---|
|Sum constraint|Integer `curr_sum`|O(1)|
|Count of distinct values|`len(freq_map)`|O(1) amortized|
|"Contains all of t"|Satisfied count `formed`|O(1)|
|All chars unique|Last-seen index map|O(1)|
|Max/min in window|Monotonic deque|O(1) amortized (see note 11)|
|At most K distinct|`defaultdict(int)`|O(1) amortized|

The rule: if updating and reverting the state takes O(1), the whole algorithm is O(n). If state update is O(k), the total is O(n · k).

---

## Formal Correctness — Why Two Pointers Work

**Claim:** The shrink-expand procedure visits every valid window and no invalid window is ever recorded.

**Proof sketch:**

Fix `right`. The window `[left..right]` is valid if and only if `left ≥ L*(right)` where `L*(right)` is the minimum left pointer that makes the window valid.

The shrink loop advances `left` until `L*(right)` is reached. At that point, `[left..right]` is the longest valid window ending at `right` (Flavour A) or the shortest (Flavour B, where we recorded before shrinking and now try to go further).

Crucially, `L*(right)` is non-decreasing: as `right` grows, you never need to move `left` back. This is the **monotonicity property** that makes two pointers correct. If the problem's constraint does not have this property (e.g., the constraint is non-contiguous), the two-pointer approach does not apply.

**Monotonicity condition:** If `[l, r]` violates the constraint, then `[l, r+1]` also violates it (i.e., adding more elements cannot fix a violated constraint). This holds for sum constraints, distinct-character constraints, "contains-all-of-t" constraints — essentially any constraint that degrades (not improves) as the window grows.

---

## Complexity

|Phase|Work|
|---|---|
|`right` advances|n times, once per element|
|`left` advances|at most n times total (across all shrink loops)|
|State update per step|O(1) for most problems|
|**Total**|**O(n)**|
|Space|O(alphabet size) or O(k) for the state|

The inner `while` loop may execute many times at a single `right` position, but averaged over all positions, `left` moves at most n steps total. This is the standard amortised argument.

---

## When NOT to Use Two Pointers

The variable-size sliding window fails when:

1. **The array has negative numbers** and the constraint is on sum → negatives break monotonicity (shrinking the window can increase the sum). Use Kadane's algorithm or prefix sums + hash map instead.
2. **The constraint requires a non-contiguous region** → need DP or backtracking.
3. **Elements are not ordered / indexable** → need a different data structure.
4. **You need all valid windows, not just the optimal one** → still O(n) but must output all; check if shrink-expand output format fits.

## Connection to AI / ML / Deep Learning

### 1. Tokenisation — longest valid token

Byte-pair encoding (BPE) and other tokenisation algorithms greedily extend a window as long as the current substring is a valid token in the vocabulary. This is Flavour A: extend right until the substring is no longer in the vocab, then record the token.

### 2. Sequence-to-sequence attention masks

In processing variable-length sequences with attention, attention masks define a valid window of positions each token can attend to. Variable-size masking (e.g., global attention + local window in Longformer) uses exactly the two-pointer logic to determine which (i, j) pairs are within the allowed window.

### 3. Online learning — sliding data window

When training on streaming data, models are sometimes retrained on only the most recent `N` samples satisfying some criterion (e.g., non-anomalous). The window expands with each new sample and shrinks when the criterion is violated — two-pointer style.

### 4. Text preprocessing — minimum covering window

NLP pipelines often need to find the shortest passage in a document that covers all query terms (passage retrieval). This is precisely the minimum window substring problem (Example 3 above), applied at the word level.

### 5. Data augmentation — valid crop selection

When randomly cropping images under a constraint (e.g., at least X% foreground pixels), a two-pointer sweep over rows determines the range of valid crop boundaries in O(n) instead of O(n²).

### 6. Reward shaping — valid experience window

In RL, experience replay buffers are sometimes filtered to retain only transitions satisfying a constraint (e.g., reward above a threshold in a recent window). The shrink-expand logic identifies the longest valid window of transitions for each training step.

## Template Reference — All Variants

```python
from collections import defaultdict

# ── VARIANT A: longest window satisfying a condition ──────────────────────────
def longest_valid_window(A, condition_ok, initial_state, add, remove):
    state = initial_state()
    left = 0
    best = 0
    for right in range(len(A)):
        add(state, A[right])
        while not condition_ok(state):
            remove(state, A[left])
            left += 1
        best = max(best, right - left + 1)
    return best

# ── VARIANT B: shortest window satisfying a condition ─────────────────────────
def shortest_valid_window(A, condition_ok, initial_state, add, remove):
    state = initial_state()
    left = 0
    best = float('inf')
    for right in range(len(A)):
        add(state, A[right])
        while condition_ok(state):          # while VALID, try to shrink
            best = min(best, right - left + 1)
            remove(state, A[left])
            left += 1
    return best if best < float('inf') else -1

# ── VARIANT C: count all valid windows ───────────────────────────────────────
def count_valid_windows(A, condition_ok, initial_state, add, remove):
    state = initial_state()
    left = 0
    count = 0
    for right in range(len(A)):
        add(state, A[right])
        while not condition_ok(state):
            remove(state, A[left])
            left += 1
        count += right - left + 1          # all windows [l..r], [l+1..r], ..., [r..r] are valid
    return count
```

## Common Mistakes

```python
# Mistake 1: Moving left past right (empty window)
while not condition_ok(state):
    remove(state, A[left])
    left += 1                   # left might exceed right — add a guard:
# Fix:
while left <= right and not condition_ok(state):
    ...

# Mistake 2: Recording the answer before the window is valid (Flavour A)
for right in range(len(A)):
    add(state, A[right])
    best = max(best, right - left + 1)   # WRONG — may record invalid window
    while not condition_ok(state):
        ...
# Fix: record AFTER the shrink loop:
    while not condition_ok(state): ...
    best = max(best, right - left + 1)   # correct

# Mistake 3: Recording the answer outside the while loop (Flavour B)
for right in range(len(A)):
    add(state, A[right])
    while condition_ok(state):
        remove(state, A[left])
        left += 1
    best = min(best, right - left + 1)   # WRONG — window may be invalid here
# Fix: record INSIDE the while loop, before shrinking:
    while condition_ok(state):
        best = min(best, right - left + 1)   # correct
        remove(state, A[left])
        left += 1

# Mistake 4: Using a while loop when an O(1) jump is possible
while freq.get(s[right], 0) > 0:   # slow if many duplicates
    freq[s[left]] -= 1
    left += 1
# Fix: for unique-char problems, store last_seen index and jump directly:
if s[right] in last_seen and last_seen[s[right]] >= left:
    left = last_seen[s[right]] + 1    # O(1) jump

# Mistake 5: Forgetting to delete zero-count keys from freq map
freq[s[left]] -= 1
left += 1
# len(freq) still counts s[left] even with count 0 → wrong distinct-char count
# Fix:
freq[s[left]] -= 1
if freq[s[left]] == 0:
    del freq[s[left]]
left += 1

# Mistake 6: Applying two pointers when the array has negatives + sum constraint
# e.g. "longest subarray with sum ≤ k" in an array with negatives
# Monotonicity breaks — shrinking may increase sum — two pointers give wrong answer
# Use prefix sums + sorted structure or DP instead
```

## Decision Tree — Which Variant to Use?

```
Is the window size fixed?
├── YES → Fixed-size sliding window (note 11)
└── NO  → Variable-size sliding window
          │
          ├── Find the LONGEST valid window?
          │     └── Flavour A: shrink while violated, record after while loop
          │
          ├── Find the SHORTEST window covering something?
          │     └── Flavour B: shrink while valid, record inside while loop
          │
          └── Count all valid windows?
                └── Variant C: after shrink, count += (right - left + 1)
```

## Summary

|Concept|One-liner|
|---|---|
|Core idea|`right` always expands; `left` shrinks only when the constraint is violated|
|Monotonicity|`L*(right)` is non-decreasing — the invariant that makes two pointers correct|
|Flavour A (longest)|Shrink while violated; record answer after the while loop|
|Flavour B (shortest)|Shrink while valid; record answer inside the while loop|
|Complexity|O(n) time — each element enters and exits at most once|
|State choices|int for sums, dict for frequencies, counter for "satisfies t"|
|When it fails|Negative numbers + sum constraint; non-contiguous constraints|
|ML connection|BPE tokenisation, passage retrieval, replay buffer filtering|
