## 1. Intuition First

### The Core Idea

Every probabilistic classifier — logistic regression, random forest, neural network, SVM with Platt scaling — outputs a **score** in [0, 1]. That score is not a decision. The decision requires a **threshold** `t`: predict positive if `score ≥ t`, negative otherwise.

The default threshold is 0.5 — chosen for mathematical convenience, not operational optimality. In almost every real deployment, 0.5 is wrong.

Consider a fraud detection system. Your model outputs a fraud probability for every transaction. Setting `t = 0.5` means you flag every transaction the model thinks is more likely fraud than not. But the cost of a missed fraud (false negative) is 50× the cost of a false alert (false positive). The operationally correct threshold is much lower than 0.5 — you should flag transactions with even a 5–10% fraud probability.

The question is: **how do you find the optimal threshold efficiently?**

The naïve approach: sweep `t` from 0 to 1 in steps of 0.001, compute the metric at each value, return the best. This evaluates the metric 1000 times.

The insight: **many evaluation metrics are monotone in `t`**, or have monotone components. Precision increases as `t` increases (you only flag things you're very sure about). Recall decreases as `t` increases (you miss more positives). If your constraint is "precision must be ≥ 0.90, maximise recall subject to that", then you want the **smallest `t` such that precision ≥ 0.90** — and precision is monotone in `t`. That is exactly a binary search on answer problem over a continuous search space.

This is [[62.Fractional binary search — real-valued search spaces]] applied to the ML evaluation layer. The algorithm is bisection. The feasibility check is: compute precision at threshold `t` on the validation set. The answer space is `[0, 1]`. After 50 iterations you have the answer to 15 significant figures, using 50 metric evaluations instead of 1000.

### Why This Exists

The gap between "model training" and "model deployment" is often exactly this: a trained model with default threshold 0.5 performs poorly on the deployment objective, and the team sweeps thresholds post-hoc with a grid search. This is:

1. **Slow**: 1000-point grid sweep × cost of evaluating metric = unnecessary compute.
2. **Coarse**: 0.001 step size misses the true optimum if it falls between grid points.
3. **Unprincipled**: no guarantee of finding a global optimum even when one exists.

Binary search on the decision boundary solves all three, provided the metric (or the constraint) is monotone in `t`. Even when it isn't perfectly monotone (due to discrete datasets), it is monotone _in expectation_ on large-enough validation sets, and small non-monotonicities can be handled by smoothing or by searching over sorted score values directly.

### The "Aha" Moment

> **The classifier doesn't change. Only the threshold changes. And on a fixed sorted list of predicted scores, every metric is a step function of the threshold — and step functions over a sorted list are exactly what binary search was built for.**

Once you sort your predictions by score, threshold optimisation becomes a search problem over a sorted array of real values. Every distinct score value is a candidate threshold. Binary search finds the optimal one in O(log n) metric evaluations instead of O(n). This is the bridge from the abstract "binary search on answer" template to a concrete, deployable ML engineering pattern.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

Threshold optimisation in the CP sense appears as: **"find the minimum value `t` such that [some count or quality condition holds]"** over a sorted array of predictions or scores.

**When it appears:**

- "Given a sorted array of test scores, find the minimum passing threshold such that at least `k` students pass and the average score of passing students exceeds `μ`."
- "Given n bids sorted by value, find the reserve price that maximises revenue subject to at least m winners."
- Problems involving **cutpoints on sorted data** — find the partition value that satisfies a compound constraint.

**Pattern signal:**

> When you see: _"find a threshold on a sorted set of scores such that some aggregate property of the items above/below the threshold satisfies a constraint"_ → binary search on the sorted score array + O(n) or O(1) feasibility check using prefix sums.

**Common trap:** When the score array has **ties** (multiple items with the same score), the threshold must be applied carefully: "score ≥ t" vs "score > t" can give different results. In CP, the convention matters and the wrong one costs a WA. Always check the problem statement's comparison direction and test explicitly with an all-equal-scores case.

A second trap: when using actual prediction scores as candidate thresholds (as opposed to a continuous real search), the valid candidate thresholds are exactly the unique score values — not the full real line. Searching the real line with bisection will converge to a value between two score values; you must then snap to the nearest valid candidate. In CP, sort the unique scores and binary search the resulting array with `lower_bound` / `upper_bound`.

---

### Machine Learning / AI

This is the primary home of threshold optimisation. The CP version is a simplified special case.

**Exact appearance in ML systems:**

_1. Precision-Recall operating point selection:_ After training a binary classifier, you produce a precision-recall curve by varying `t` from 0 to 1. The standard approach uses `sklearn.metrics.precision_recall_curve`, which computes precision and recall at every unique predicted score — effectively evaluating the metric at O(n) candidate thresholds. If you have a specific operating constraint (e.g., "precision ≥ 0.95"), you can replace this O(n) sweep with O(log n) bisection. For n = 10⁶ predictions: 1,000,000 evaluations vs 20 bisection steps.

_2. ROC curve optimal threshold (Youden's J statistic):_ The point on the ROC curve maximising `sensitivity + specificity − 1` (Youden's J) is the threshold that maximises the geometric mean of true positive rate and true negative rate. Since TPR is monotone decreasing in `t` and TNR is monotone increasing, their sum is unimodal — use **ternary search** (see [[62.Fractional binary search — real-valued search spaces]] Variation 1), not bisection.

_3. F-beta score threshold optimisation:_ `F_β = (1 + β²) × precision × recall / (β² × precision + recall)`. This is unimodal in `t` for fixed `β` — use ternary search. But the **constrained** version ("find minimum `t` such that `F_β ≥ target`") is monotone in `t` for large enough `target` — use bisection.

_4. Platt scaling and temperature calibration:_ After logistic regression or neural network training, **Platt scaling** fits a sigmoid `P(y=1) = σ(At + B)` to the raw scores. The calibrated probabilities are then thresholded. Calibration itself involves finding parameters `A, B` (or temperature `T` in temperature scaling) via bisection on the expected calibration error — exactly the fractional binary search pattern from [[62.Fractional binary search — real-valued search spaces]]. Once calibrated, threshold search on the calibrated probabilities is cleaner because the probabilities are now meaningful.

_5. Anomaly detection score thresholds:_ Isolation Forest, One-Class SVM, and Autoencoder reconstruction error all produce anomaly scores with no natural threshold. The operational threshold is found by bisecting on: "what `t` gives false positive rate ≤ 1% on a clean validation set?" — a direct monotone predicate (FPR is monotone decreasing in `t`).

_6. Beam search length penalty threshold (NLP):_ In sequence generation, a length penalty parameter `α` is applied to scores. Finding the `α` at which output length crosses a target is a threshold bisection problem embedded in the decoding loop of systems like mT5 and BART.

**Framework internals:**

- `sklearn.metrics.precision_recall_curve(y_true, y_scores)` returns arrays of length n (one entry per unique score). This is the O(n) sweep. Under the hood it sorts scores and computes TP/FP/FN cumulatively — essentially building the full step function so you can pick any operating point.
- `sklearn.metrics.roc_curve` is identical in structure.
- `optuna` (Bayesian hyperparameter optimisation) falls back to `scipy.optimize.bisect` internally when the search space for a parameter is 1D and the objective is detected to be monotone.
- `transformers` library: `pipeline("text-classification", threshold=0.5)` — the threshold here is the exact parameter we are optimising.

**Why understanding this makes you a better ML engineer:** You can replace post-hoc grid sweeps over thresholds with a 20-line bisection function that runs in O(log n) evaluations. More importantly, you can express deployment constraints precisely as monotone predicates and solve them optimally — rather than picking a threshold by visual inspection of the PR curve, which is the industry norm and is both imprecise and not reproducible.

## 3. Algorithm / Pattern

### The Two Fundamental Setups

**Setup A — Continuous score space, closed-form metric:** Scores are real-valued, metric formula is computable in O(n) given a threshold. Use bisection on `[0, 1]` with the metric formula as the feasibility check.

**Setup B — Discrete candidate thresholds (sorted unique scores):** Scores come from a finite dataset. Valid thresholds are the n unique score values. Use binary search on the sorted score array with `lower_bound`. This is O(log n) candidate evaluations, each O(1) with precomputed prefix sums.

### Core Metrics and Their Monotonicity

|Metric|Monotone in t?|Direction|Search type|
|---|---|---|---|
|Precision|Yes (approximately)|↑ as t ↑|Bisection|
|Recall (TPR)|Yes|↓ as t ↑|Bisection|
|FPR|Yes|↓ as t ↑|Bisection|
|F1 / Fβ|No (unimodal)|—|Ternary search|
|Youden's J|No (unimodal)|—|Ternary search|
|Accuracy|No (may be unimodal)|—|Ternary search|
|Constrained metric|Depends on constraint|—|Bisection on constraint|

**The key pattern:** pure precision or recall constraints are monotone → bisection. Composite metrics are unimodal → ternary search. Constrained optimisation ("maximise recall such that precision ≥ 0.9") → bisect on the constraint (precision), return the recall at that threshold.

### Algorithm for Constrained Threshold Optimisation

```
Given: sorted predictions [(score_i, label_i)], constraint: precision ≥ P_target
Find: minimum t* such that precision(t*) ≥ P_target

Step 1 — Sort by score descending (or ascending — be consistent).
Step 2 — Precompute prefix sums of positives and negatives for O(1) metric eval.
Step 3 — Binary search on t in [min_score, max_score]:
          feasible(t) = (precision_at_threshold(t) >= P_target)
Step 4 — Return lo (smallest t satisfying constraint).
Step 5 — Report recall(t*), F1(t*), any other secondary metrics.
```

### Decision Tree

```
Is there a threshold to optimise?
├── YES → Is the primary metric monotone in the threshold?
│   ├── YES (precision, recall, FPR) →
│   │   Is the goal to find the threshold satisfying a constraint?
│   │   ├── YES → Bisect on threshold, feasibility = metric ≥ target.
│   │   └── NO (pure optimise) → Trivially t=0 (max recall) or t=1 (max precision).
│   │                             Interesting only in the constrained case.
│   └── NO (F1, accuracy, Youden's J — unimodal) →
│       ├── Ternary search on threshold in [0, 1].
│       └── Or: sort unique scores, evaluate at each, O(n) sweep.
└── NO → Not a threshold problem.
```

### Time/Space Complexity

**Setup A (continuous bisection):**

- Time: O(100 × n) = O(n) — 100 iterations, each computing metric in O(n).
- Space: O(n) for storing predictions.

**Setup B (discrete binary search with prefix sums):**

- Preprocessing: O(n log n) to sort scores, O(n) to build prefix sums.
- Search: O(log n) iterations × O(1) metric evaluation = O(log n).
- Total: O(n log n) preprocessing + O(log n) search = **O(n log n)**.
- Compare to naive sweep: O(n) thresholds × O(1) eval = O(n) after O(n log n) preprocessing — asymptotically the same, but bisection finds the exact optimum in [0,1] rather than the best among n candidates.

## 4. Pseudocode

```
// ── Setup B: Discrete threshold search with prefix sums ──

THRESHOLD_OPTIMISE(scores, labels, P_target):
    // scores[i]: predicted probability for sample i (float in [0,1])
    // labels[i]: true binary label (0 or 1)
    // P_target:  minimum required precision
    // Returns:   optimal threshold t* and resulting (precision, recall)

    n ← length(scores)

    // Step 1: Sort by score descending
    indices ← argsort(scores, descending=true)
    sorted_scores ← scores[indices]
    sorted_labels ← labels[indices]

    // Step 2: Precompute cumulative TP and FP counts
    // At rank i (threshold = sorted_scores[i]):
    //   Predicting positive for top i+1 samples
    cum_tp[0] ← 0
    cum_fp[0] ← 0
    FOR i FROM 0 TO n-1:
        IF sorted_labels[i] == 1:
            cum_tp[i+1] ← cum_tp[i] + 1
            cum_fp[i+1] ← cum_fp[i]
        ELSE:
            cum_tp[i+1] ← cum_tp[i]
            cum_fp[i+1] ← cum_fp[i] + 1

    total_positives ← cum_tp[n]    // total ground-truth positives

    // Step 3: Define metric evaluation at a threshold index
    PRECISION_AT(k):
        // k = number of top samples predicted positive
        IF k == 0: RETURN 1.0      // convention: precision = 1 when nothing predicted
        RETURN cum_tp[k] / k

    RECALL_AT(k):
        IF total_positives == 0: RETURN 0.0
        RETURN cum_tp[k] / total_positives

    // Step 4: Binary search on k (number predicted positive)
    // Precision is monotone decreasing in k (more positives → lower precision)
    // We want the LARGEST k such that precision >= P_target
    // (largest k = lowest threshold = best recall at the precision constraint)

    lo ← 0                         // k=0: precision=1.0 (feasible, but recall=0)
    hi ← n                         // k=n: all predicted positive

    // First check if the constraint is satisfiable at all
    IF PRECISION_AT(n) >= P_target:
        RETURN sorted_scores[n-1], PRECISION_AT(n), RECALL_AT(n)  // use all

    WHILE lo < hi - 1:
        mid ← lo + (hi - lo) / 2
        IF PRECISION_AT(mid) >= P_target:
            lo ← mid               // mid is feasible, try predicting more positives
        ELSE:
            hi ← mid               // mid is infeasible, predict fewer positives

    // lo is the largest k with precision >= P_target
    optimal_k ← lo
    optimal_threshold ← sorted_scores[optimal_k - 1]  // score of last included sample

    RETURN optimal_threshold, PRECISION_AT(optimal_k), RECALL_AT(optimal_k)


// ── Continuous bisection variant (for large-scale or streaming settings) ──

BISECT_THRESHOLD(score_fn, label_fn, P_target, n_samples, eps=1e-6):
    // score_fn(t) -> float: metric at threshold t (computed on held-out set)
    // This variant is used when you can't materialise all predictions at once

    FEASIBLE(t):
        tp, fp, fn ← 0, 0, 0
        FOR EACH (score, label) IN dataset:
            predicted ← (score >= t) ? 1 : 0
            IF predicted == 1 AND label == 1: tp += 1
            IF predicted == 1 AND label == 0: fp += 1
            IF predicted == 0 AND label == 1: fn += 1
        precision ← tp / (tp + fp) if (tp + fp) > 0 else 1.0
        RETURN precision >= P_target

    lo ← 0.0
    hi ← 1.0
    FOR i FROM 1 TO 100:
        mid ← lo + (hi - lo) / 2.0
        IF FEASIBLE(mid):
            lo ← mid               // precision >= target, try lower threshold
        ELSE:
            hi ← mid               // precision < target, raise threshold
    RETURN (lo + hi) / 2.0
```

**Edge cases handled:**

- `total_positives == 0`: recall is undefined; return NaN or 0.0 per convention.
- `k == 0` (nothing predicted positive): precision = 1.0 by convention (vacuous truth), recall = 0.
- All scores identical: binary search still converges, returns the only meaningful threshold.
- `P_target = 0`: constraint is always satisfied; optimal threshold = 0 (predict everything positive for maximum recall).
- `P_target = 1`: must find threshold where every predicted positive is a true positive; binary search finds it correctly.

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

/**
 * Threshold Optimisation — Binary Search on Decision Boundary
 *
 * Finds the optimal classification threshold satisfying a precision constraint
 * while maximising recall. Uses prefix sums for O(1) metric evaluation.
 *
 * Time:  O(n log n) preprocessing + O(log n) search
 * Space: O(n)
 */

struct ThresholdResult {
    double threshold;
    double precision;
    double recall;
    double f1;
    int    true_positives;
    int    false_positives;
    int    false_negatives;
};

class ThresholdOptimiser {
public:
    // predictions: vector of (score, label) pairs
    explicit ThresholdOptimiser(vector<pair<double,int>> predictions)
        : n_(predictions.size())
    {
        // Sort descending by score
        sort(predictions.begin(), predictions.end(),
             [](const auto& a, const auto& b){ return a.first > b.first; });

        scores_.reserve(n_);
        cum_tp_.resize(n_ + 1, 0);
        cum_fp_.resize(n_ + 1, 0);

        for (int i = 0; i < n_; ++i) {
            scores_.push_back(predictions[i].first);
            cum_tp_[i+1] = cum_tp_[i] + (predictions[i].second == 1 ? 1 : 0);
            cum_fp_[i+1] = cum_fp_[i] + (predictions[i].second == 0 ? 1 : 0);
        }
        total_pos_ = cum_tp_[n_];
    }

    // Find the largest k (most predicted positives) such that precision >= min_precision.
    // This gives the lowest threshold (highest recall) satisfying the constraint.
    ThresholdResult optimise_precision_constrained(double min_precision) const {
        if (n_ == 0) return {1.0, 1.0, 0.0, 0.0, 0, 0, total_pos_};

        // Edge: even predicting everything doesn't meet constraint → return t=1 (predict nothing)
        // precision at k=n: cum_tp[n] / n
        if (precision_at(n_) < min_precision) {
            // No threshold achieves the constraint — return the highest-precision single prediction
            return make_result(1);
        }

        // Binary search: find largest k with precision >= min_precision
        // Invariant: precision_at(lo) >= min_precision, precision_at(hi) < min_precision
        int lo = 1, hi = n_;

        // First check if the full set satisfies the constraint (handled above).
        // Now search for the boundary.
        while (lo < hi) {
            int mid = lo + (hi - lo + 1) / 2;  // upper mid to avoid infinite loop
            if (precision_at(mid) >= min_precision) {
                lo = mid;   // mid satisfies constraint, try predicting more
            } else {
                hi = mid - 1;  // mid fails, predict fewer
            }
        }
        return make_result(lo);
    }

    // Maximise F-beta via ternary search over k (number predicted positive)
    // F-beta is unimodal in k — not monotone.
    ThresholdResult optimise_fbeta(double beta = 1.0) const {
        if (n_ == 0) return {1.0, 1.0, 0.0, 0.0, 0, 0, total_pos_};

        double beta2 = beta * beta;
        auto fbeta_at = [&](int k) -> double {
            if (k == 0) return 0.0;
            double p = precision_at(k);
            double r = recall_at(k);
            if (p + r < 1e-12) return 0.0;
            return (1 + beta2) * p * r / (beta2 * p + r);
        };

        // Ternary search on k in [1, n]
        int lo = 1, hi = n_;
        while (hi - lo > 2) {
            int m1 = lo + (hi - lo) / 3;
            int m2 = hi - (hi - lo) / 3;
            if (fbeta_at(m1) < fbeta_at(m2)) lo = m1;
            else                              hi = m2;
        }
        // Evaluate remaining candidates
        int best_k = lo;
        for (int k = lo; k <= hi; ++k) {
            if (fbeta_at(k) > fbeta_at(best_k)) best_k = k;
        }
        return make_result(best_k);
    }

private:
    int n_, total_pos_;
    vector<double> scores_;
    vector<int> cum_tp_, cum_fp_;

    double precision_at(int k) const {
        if (k == 0) return 1.0;
        return static_cast<double>(cum_tp_[k]) / k;
    }

    double recall_at(int k) const {
        if (total_pos_ == 0) return 0.0;
        return static_cast<double>(cum_tp_[k]) / total_pos_;
    }

    ThresholdResult make_result(int k) const {
        double p = precision_at(k);
        double r = recall_at(k);
        double f1 = (p + r > 1e-12) ? 2*p*r/(p+r) : 0.0;
        double threshold = (k > 0 && k <= n_) ? scores_[k-1] : 1.0;
        return {threshold, p, r, f1, cum_tp_[k], cum_fp_[k], total_pos_ - cum_tp_[k]};
    }
};

int main() {
    // Test: binary classification with known optimal threshold
    // 10 samples: scores and labels
    vector<pair<double,int>> predictions = {
        {0.95, 1}, {0.87, 1}, {0.80, 0}, {0.75, 1}, {0.70, 1},
        {0.65, 0}, {0.55, 0}, {0.45, 1}, {0.30, 0}, {0.10, 0}
    };
    // True positives: indices with label=1 → scores: 0.95,0.87,0.75,0.70,0.45

    ThresholdOptimiser opt(predictions);

    // Find threshold achieving precision >= 0.80, maximising recall
    auto result = opt.optimise_precision_constrained(0.80);
    printf("Precision constraint >= 0.80:\n");
    printf("  Threshold: %.4f\n", result.threshold);
    printf("  Precision: %.4f\n", result.precision);
    printf("  Recall:    %.4f\n", result.recall);
    printf("  F1:        %.4f\n", result.f1);
    printf("  TP=%d  FP=%d  FN=%d\n\n",
           result.true_positives, result.false_positives, result.false_negatives);

    // Find threshold maximising F1
    auto f1_result = opt.optimise_fbeta(1.0);
    printf("F1-optimal threshold:\n");
    printf("  Threshold: %.4f\n", f1_result.threshold);
    printf("  Precision: %.4f\n", f1_result.precision);
    printf("  Recall:    %.4f\n", f1_result.recall);
    printf("  F1:        %.4f\n", f1_result.f1);

    // Edge case: all same score
    vector<pair<double,int>> tied = {{0.7,1},{0.7,0},{0.7,1},{0.7,0}};
    ThresholdOptimiser opt2(tied);
    auto tied_result = opt2.optimise_precision_constrained(0.60);
    printf("\nTied scores, precision >= 0.60:\n");
    printf("  Threshold: %.4f, P=%.4f, R=%.4f\n",
           tied_result.threshold, tied_result.precision, tied_result.recall);

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations
from typing import NamedTuple
import numpy as np


class ThresholdResult(NamedTuple):
    threshold: float
    precision: float
    recall: float
    f1: float
    true_positives: int
    false_positives: int
    false_negatives: int


def optimise_threshold_precision_constrained(
    scores: np.ndarray,
    labels: np.ndarray,
    min_precision: float,
) -> ThresholdResult:
    """
    Find the lowest threshold t* such that precision(t*) >= min_precision,
    maximising recall subject to that constraint.

    Uses prefix sums for O(1) metric evaluation after O(n log n) preprocessing.
    Binary search finds the optimal threshold in O(log n) evaluations.

    Args:
        scores:        1-D array of predicted probabilities in [0, 1].
        labels:        1-D array of true binary labels (0 or 1).
        min_precision: Minimum required precision (e.g., 0.90).

    Returns:
        ThresholdResult with threshold, precision, recall, F1, and confusion matrix counts.

    Time:  O(n log n) sort + O(log n) search = O(n log n)
    Space: O(n)
    """
    n = len(scores)
    assert len(labels) == n, "scores and labels must have the same length"
    assert 0.0 <= min_precision <= 1.0

    # Sort descending by score — lower threshold = more items predicted positive
    order = np.argsort(scores)[::-1]
    sorted_labels = labels[order]
    sorted_scores = scores[order]

    # Prefix sums: cum_tp[k] = true positives among top-k predictions
    cum_tp = np.concatenate([[0], np.cumsum(sorted_labels)])
    total_pos = int(cum_tp[-1])

    def precision_at(k: int) -> float:
        """Precision when predicting top-k samples as positive."""
        if k == 0:
            return 1.0  # vacuous: nothing predicted positive
        return float(cum_tp[k]) / k

    def recall_at(k: int) -> float:
        """Recall when predicting top-k samples as positive."""
        if total_pos == 0:
            return 0.0
        return float(cum_tp[k]) / total_pos

    def make_result(k: int) -> ThresholdResult:
        p = precision_at(k)
        r = recall_at(k)
        f1 = 2 * p * r / (p + r) if (p + r) > 1e-12 else 0.0
        threshold = float(sorted_scores[k - 1]) if 0 < k <= n else 1.0
        tp = int(cum_tp[k])
        fp = k - tp
        fn = total_pos - tp
        return ThresholdResult(threshold, p, r, f1, tp, fp, fn)

    # Edge: predicting everything doesn't meet constraint
    if precision_at(n) < min_precision:
        # Return best single prediction (highest-score sample)
        return make_result(1)

    # Binary search: find the largest k with precision_at(k) >= min_precision
    # Precision is monotone non-increasing in k (more positives → dilutes precision)
    # We want the LARGEST such k → maximises recall
    lo, hi = 1, n
    while lo < hi:
        # Upper-biased mid to avoid infinite loop when lo+1 == hi
        mid = lo + (hi - lo + 1) // 2
        if precision_at(mid) >= min_precision:
            lo = mid   # mid satisfies constraint, try predicting more
        else:
            hi = mid - 1  # mid fails, predict fewer

    return make_result(lo)


def optimise_threshold_fbeta(
    scores: np.ndarray,
    labels: np.ndarray,
    beta: float = 1.0,
) -> ThresholdResult:
    """
    Find threshold maximising F-beta score using ternary search.

    F-beta is unimodal (not monotone) in the threshold, so ternary search
    is used instead of bisection.

    Time:  O(n log n) preprocessing + O(log n) ternary search
    Space: O(n)
    """
    n = len(scores)
    order = np.argsort(scores)[::-1]
    sorted_labels = labels[order]
    sorted_scores = scores[order]

    cum_tp = np.concatenate([[0], np.cumsum(sorted_labels)])
    total_pos = int(cum_tp[-1])
    beta2 = beta ** 2

    def fbeta_at(k: int) -> float:
        if k == 0:
            return 0.0
        p = float(cum_tp[k]) / k
        r = float(cum_tp[k]) / total_pos if total_pos > 0 else 0.0
        denom = beta2 * p + r
        return (1 + beta2) * p * r / denom if denom > 1e-12 else 0.0

    # Ternary search over integer k in [1, n]
    lo, hi = 1, n
    while hi - lo > 2:
        m1 = lo + (hi - lo) // 3
        m2 = hi - (hi - lo) // 3
        if fbeta_at(m1) < fbeta_at(m2):
            lo = m1
        else:
            hi = m2

    # Evaluate remaining small interval exhaustively
    best_k = max(range(lo, hi + 1), key=fbeta_at)

    def make_result(k: int) -> ThresholdResult:
        p = float(cum_tp[k]) / k if k > 0 else 1.0
        r = float(cum_tp[k]) / total_pos if total_pos > 0 else 0.0
        f1 = 2 * p * r / (p + r) if p + r > 1e-12 else 0.0
        threshold = float(sorted_scores[k - 1]) if 0 < k <= n else 1.0
        tp = int(cum_tp[k])
        return ThresholdResult(threshold, p, r, f1, tp, k - tp, total_pos - tp)

    return make_result(best_k)


# ── Sklearn interop: compare with precision_recall_curve ──

def compare_with_sklearn(scores: np.ndarray, labels: np.ndarray,
                          min_precision: float = 0.85) -> None:
    """
    Demonstrate that binary search gives identical result to sklearn sweep.
    sklearn: O(n) evaluations across all thresholds.
    Our approach: O(log n) evaluations, same answer.
    """
    from sklearn.metrics import precision_recall_curve  # type: ignore

    # sklearn sweep (O(n) evaluations)
    precisions, recalls, thresholds = precision_recall_curve(labels, scores)
    # Find best recall where precision >= min_precision
    mask = precisions[:-1] >= min_precision  # last entry is boundary artifact
    if mask.any():
        best_idx = np.where(mask)[0][-1]  # largest index = lowest threshold = best recall
        sklearn_threshold = thresholds[best_idx]
        sklearn_precision = precisions[best_idx]
        sklearn_recall    = recalls[best_idx]
    else:
        sklearn_threshold = 1.0
        sklearn_precision = 1.0
        sklearn_recall    = 0.0

    # Our bisection (O(log n) evaluations)
    our_result = optimise_threshold_precision_constrained(scores, labels, min_precision)

    print(f"Constraint: precision >= {min_precision}")
    print(f"  sklearn:  t={sklearn_threshold:.6f}  P={sklearn_precision:.4f}  R={sklearn_recall:.4f}")
    print(f"  bisect:   t={our_result.threshold:.6f}  P={our_result.precision:.4f}  R={our_result.recall:.4f}")
    print(f"  Match: {abs(our_result.threshold - sklearn_threshold) < 1e-9}")


# ── Tests ──

if __name__ == "__main__":
    rng = np.random.default_rng(42)

    # Generate synthetic predictions
    n = 1000
    true_labels = rng.integers(0, 2, size=n)
    # Simulate a decent classifier: true positives score higher on average
    scores = np.where(
        true_labels == 1,
        rng.beta(5, 2, size=n),   # positives: skewed toward 1
        rng.beta(2, 5, size=n),   # negatives: skewed toward 0
    )

    # Test 1: precision-constrained optimisation
    result = optimise_threshold_precision_constrained(scores, true_labels, min_precision=0.85)
    print(f"Precision >= 0.85:")
    print(f"  Threshold={result.threshold:.4f}  P={result.precision:.4f}"
          f"  R={result.recall:.4f}  F1={result.f1:.4f}")
    assert result.precision >= 0.85 - 1e-9, "Constraint violated!"

    # Test 2: F1-optimal threshold
    f1_result = optimise_threshold_fbeta(scores, true_labels, beta=1.0)
    print(f"\nF1-optimal:")
    print(f"  Threshold={f1_result.threshold:.4f}  P={f1_result.precision:.4f}"
          f"  R={f1_result.recall:.4f}  F1={f1_result.f1:.4f}")

    # Test 3: Sklearn comparison
    print()
    compare_with_sklearn(scores, true_labels, min_precision=0.85)

    # Test 4: Edge — all labels positive
    all_pos = np.ones(50, dtype=int)
    scores_ap = rng.uniform(0, 1, size=50)
    r = optimise_threshold_precision_constrained(scores_ap, all_pos, 0.90)
    assert r.precision >= 0.90 - 1e-9 or r.precision == 1.0
    print(f"\nAll positives: P={r.precision:.4f}  R={r.recall:.4f}")

    # Test 5: Edge — constraint impossible (all negatives)
    all_neg = np.zeros(50, dtype=int)
    r2 = optimise_threshold_precision_constrained(rng.uniform(0,1,50), all_neg, 0.90)
    print(f"All negatives: P={r2.precision:.4f}  R={r2.recall:.4f}")

    print("\nAll tests passed.")
```

## 7. Common Variations & Extensions

### Variation 1: Multi-Class Threshold Optimisation

For multi-class classification (softmax over K classes), each class has its own score and its own threshold. The optimisation decomposes into K independent binary threshold problems — one per class — in a one-vs-rest setup. However, if the constraint is global ("overall macro-F1 ≥ target"), the thresholds interact and the problem becomes a K-dimensional search. Approaches: coordinate descent (optimise one threshold at a time), or random search over threshold vectors. Pure bisection does not directly apply.

### Variation 2: Cost-Sensitive Threshold (Bayes Optimal Threshold)

When false negative cost is `C_FN` and false positive cost is `C_FP`, the Bayes-optimal threshold under a calibrated model is: $$t^* = \frac{C_{FP}}{C_{FP} + C_{FN}}$$ This is a closed-form result requiring no search at all — provided the model is well-calibrated (see Platt scaling above). The binary search approach is needed when the cost function is not this simple (e.g., non-linear costs, fairness constraints).

### Variation 3: Fairness-Constrained Threshold

Increasingly common in production ML: find the threshold `t` maximising accuracy subject to demographic parity (the positive prediction rate must be equal across groups A and B). This is a 2D constraint — bisect on `t` while checking parity. Connects to algorithmic fairness literature (Hardt et al., 2016 "Equality of Opportunity in Supervised Learning").

### Variation 4: Threshold Optimisation in Object Detection (NMS)

In object detection (YOLO, Faster R-CNN), non-maximum suppression uses two thresholds: a confidence threshold and an IoU threshold. Finding the optimal confidence threshold for a given precision-recall trade-off on a validation set is exactly this problem — binary search on confidence with the AP metric as the objective. The AP is not monotone in confidence, but the constrained version (precision ≥ target) is. See [[195.Bayes' theorem — derivation and intuition]] for the probabilistic interpretation of confidence scores.

### Variation 5: Online Threshold Adaptation

In streaming classification (e.g., fraud detection on live transactions), the optimal threshold drifts as the data distribution shifts (concept drift). An online algorithm maintains a running estimate of the optimal threshold using the [[223.Online learning algorithms — update rules without storing all data]] framework — updating the threshold after each batch rather than rerunning the full binary search.

## 9. CP Contest Application

### Typical Problem Structure

Threshold problems in CP usually appear as: **"given a sorted array and a target count, find the minimum/maximum value such that exactly k / at least k elements satisfy a condition."**

**Direct structural mapping:**

|CP Problem Phrasing|ML Analog|
|---|---|
|"Find minimum passing grade so that ≥ k students pass"|"Find threshold so that recall ≥ target"|
|"Find maximum price so that ≥ k buyers can afford"|"Find threshold so that coverage ≥ target"|
|"Find minimum distance such that ≤ m pairs are closer"|"Find threshold so that FPR ≤ target"|
|"H-index: find max h such that ≥ h papers have ≥ h citations"|"Find operating point on PR curve"|

**LeetCode 275 (H-Index II) as the canonical template:**

```
Sorted citations (ascending): [0, 1, 3, 5, 6]
Find max h: at least h papers with >= h citations.

Binary search on h in [0, n]:
  feasible(h) = citations[n - h] >= h
  (if top-h papers each have >= h citations)

lo=0, hi=5
mid=3: citations[5-3]=citations[2]=3 >= 3 ✓ → lo=3
mid=4: citations[5-4]=citations[1]=1 >= 4 ✗ → hi=3
lo=hi=3 → Answer: 3
```

This is the same binary search template as precision-constrained threshold optimisation — the monotone predicate, the sorted array, the prefix count.

### Optimisation Tricks for CP

**1. Sort once, query many times:** In problems where you must answer multiple threshold queries on the same dataset, sort the array once in O(n log n) and answer each query in O(log n) with `lower_bound`. Total: O(n log n + Q log n) instead of O(Qn).

**2. Prefix sums for O(1) feasibility:** Build `cum_tp` and `cum_fp` arrays once. Each feasibility evaluation is O(1) — no loop inside the binary search. This is the key that makes the overall complexity O(n log n) rather than O(n log² n).

**3. The non-monotonicity trap in practice:** For real datasets with ties in scores, precision is not perfectly monotone. The standard fix in competitive problems: treat `feasible(k) = (cum_tp[k] * required_denominator >= required_numerator * k)` using integer arithmetic to avoid floating-point comparison issues. This is a direct application of [[106.Floating point bit representation — IEEE 754 intuition]] — avoid floats inside the binary search predicate whenever possible.

**4. Time limits:** At n = 10⁵ and Q = 10⁵ queries: O((n + Q) log n) ≈ 3 × 10⁶ operations. Comfortably within 1 second in C++. The float-comparison version may TLE due to branch misprediction on floating-point ops — integer arithmetic is 2–5× faster inside the tight loop.
