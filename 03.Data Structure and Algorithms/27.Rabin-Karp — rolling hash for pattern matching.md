## 1. Intuition First

### The Core Idea

Imagine you're looking for a specific 5-letter word in a book of 10,000 letters. The naive approach reads every character of every candidate window — five characters per window, about 10,000 windows. That's 50,000 character comparisons.

Now imagine instead you assigned a **numerical fingerprint** to every 5-letter sequence — a single number that summarises the entire window. To check if a candidate matches the pattern, you just compare two numbers. Comparing numbers is O(1). The trick that makes this work is a **rolling** computation: when the window slides one position forward, you don't recompute the fingerprint from scratch. You mathematically remove the leftmost character and add the rightmost one. This "roll" costs O(1).

This is Rabin-Karp in one sentence: **use a rolling polynomial hash to reduce window comparison from O(m) to O(1), then verify only when hashes match.**

The hash function used is a **polynomial rolling hash**:

$$H(s[i..i+m-1]) = \sum_{j=0}^{m-1} s[i+j] \cdot b^{m-1-j} \pmod{q}$$

where $b$ is a base (typically a prime like 31 or 256) and $q$ is a large prime modulus.

When sliding from position $i$ to $i+1$:

$$H_{new} = \left( (H_{old} - s[i] \cdot b^{m-1}) \cdot b + s[i+m] \right) \pmod{q}$$

This is the "roll" — constant time per step, regardless of $m$.

### Why This Exists

[[25.String matching — naive O(nm) and why it matters]] costs O(nm) in the worst case. [[26.KMP algorithm — failure function and O(n+m) matching]] achieves O(n+m) worst case using structural information about the pattern. KMP is strictly better than Rabin-Karp for single-pattern matching. So why does Rabin-Karp exist?

**Rabin-Karp's superpower is multi-pattern matching.** Suppose you have $k$ patterns, each of length $m$. KMP requires building $k$ separate failure functions and running $k$ separate automata — O(km) preprocessing, O(kn) search. Rabin-Karp stores all $k$ pattern hashes in a HashSet and checks every window against all $k$ patterns in O(1) amortised — O(km) preprocessing, O(n + km) search total. For large $k$, this is a qualitative win.

Additionally, Rabin-Karp generalises naturally to **2D pattern matching** (finding a submatrix in a matrix), which KMP cannot do without significant rework.

### The "Aha" Moment

The insight is that **hashing converts a string comparison problem into an arithmetic problem**. Once you have a polynomial hash, you can use modular arithmetic to add/remove "digits" from either end of a window. The hash behaves like a number in base $b$ — sliding the window is like shifting a number left, dropping the most significant digit, and appending a new least-significant digit. The polynomial structure is what enables O(1) update; a non-polynomial hash (like summing character values) would only support addition/subtraction, not the full sliding structure needed for strong collision resistance.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Substring search problems, especially when:

- You need to find if a pattern exists in a string (and KMP would also work, but you want a quick implementation)
- You're asked to find **all occurrences** of multiple patterns simultaneously
- You need to detect **duplicate substrings** of a given length (hint: "longest duplicate substring" → binary search on length + rolling hash)
- The problem involves 2D grids and you need to find a submatrix pattern

**Signal patterns that scream Rabin-Karp:**

- "Find all positions where pattern P appears in string S" with $|P|$ and $|S|$ both large
- "Given $k$ patterns, which ones appear in S?" — multi-pattern matching
- "Is there a repeated substring of length $\geq L$?" — combine with binary search on $L$
- Any 2D string/grid matching problem

**The canonical trap — hash collision (false positive):** A hash match does not guarantee a string match. Two different strings can have the same hash value. This is not a bug; it's an expected property of any hash function (see [[40.The birthday paradox and collision probability]]). The standard fix is **verification**: whenever $H(\text{window}) = H(\text{pattern})$, do a full O(m) character comparison to confirm. In most inputs this adds negligible cost, but an adversary can craft inputs with many false positives to force O(nm) worst case.

The professional defence is **double hashing**: use two independent hash functions with different bases and moduli. The probability of both colliding simultaneously is $\approx \frac{1}{q_1 \cdot q_2}$, which for 64-bit primes makes adversarial attack computationally infeasible. In competitive programming, using a single hash with a known modulus (like $10^9 + 7$) on a judge that has anti-hash tests will fail. Use two hashes or a random modulus.

**Common submission killers:**

1. Forgetting to take modulo during the rolling update, causing integer overflow
2. Negative modulo results in C++ — `((val % mod) + mod) % mod` instead of `val % mod`
3. Verifying every match even when the problem guarantees no adversarial input (unnecessary O(m) slowdown)
4. Not precomputing `pow[m-1]` — recomputing it per window step turns O(n) into O(nm)

### Machine Learning / AI

Rabin-Karp is not directly invoked as a library, but its **algorithmic ideas permeate several ML systems**:

**1. Byte Pair Encoding (BPE) tokenisation** — used in GPT-2/3/4, LLaMA, and virtually all modern LLMs — operates on substring frequency detection. During vocabulary construction, it repeatedly finds the most frequent bigram in the corpus. Efficient implementations use rolling hash-like structures to maintain frequency counts over sliding windows in O(n) rather than recomputing from scratch.

**2. Locality-Sensitive Hashing (LSH)** (see [[38.Locality-sensitive hashing (LSH) — approximate nearest neighbour]]) is conceptually descended from rolling hash thinking: rather than comparing vectors exactly, map them to hash buckets such that similar vectors collide. MinHash (see [[39.MinHash — estimating Jaccard similarity at scale]]) for Jaccard similarity estimation directly uses polynomial-style hashing over shingles — fixed-length substrings of a document — to represent documents as sets efficiently.

**3. Sequence deduplication in pretraining pipelines** — large language model pretraining requires deduplicating terabytes of text. The standard approach (used in the Pile, RedPajama, and Dolma datasets) uses MinHash over character n-grams of documents, which is a direct application of rolling polynomial hashing over fixed windows of characters.

**4. Approximate string matching in NLP preprocessing** — fuzzy deduplication of near-duplicate training examples uses rolling hash fingerprints of k-gram windows (Simhash, Nilsimsa) rather than character-by-character comparison.

**5. Convolutional neural networks (CNNs) on sequences** — the convolution operation over a 1D sequence is structurally identical to the pattern-matching scan: a fixed-size kernel slides over the input, computing a dot product at each position. Rabin-Karp replaces the dot product with a hash comparison and adds an early-termination condition. Understanding this parallel helps you reason about why 1D convolutions for text (used in early NLP models like TextCNN) are efficient.

Understanding Rabin-Karp makes you write better ML code because: (a) you understand why character n-gram hashing is the right data structure for text deduplication at scale, and (b) you can implement custom tokenisation preprocessing without relying on opaque library calls.

## 3. Algorithm / Pattern

### Step-by-Step Logic

**Preprocessing:**

1. Compute $H(\text{pattern})$ — a single hash of the length-$m$ pattern string.
2. Compute $H(\text{text}[0..m-1])$ — hash of the first window of the text.
3. Precompute $b^{m-1} \pmod{q}$ — the "high power" needed to remove the leftmost character when sliding.

**Search:** 4. Compare $H(\text{window})$ with $H(\text{pattern})$. 5. If equal, **verify** by direct character comparison (to rule out false positives). 6. Slide the window: remove the leftmost character contribution, multiply by base, add rightmost character. 7. Repeat from step 4 until end of text.

**Rolling formula:** $$H_{\text{new}} = \left((H_{\text{old}} - \text{text}[i] \cdot b^{m-1}) \cdot b + \text{text}[i+m]\right) \pmod{q}$$

### Decision Tree

```
Is the problem asking about substrings of FIXED length k?
├─ YES → Rolling hash is natural (window = k, slide by 1)
│   ├─ Single pattern search → Use KMP (O(n+m) worst case, no false positives)
│   │   UNLESS you want a quick implementation → Rabin-Karp
│   ├─ Multiple pattern search → Rabin-Karp with HashSet of pattern hashes
│   ├─ Detect DUPLICATE substrings → Binary search on length + rolling hash
│   └─ 2D pattern matching → Row-wise + column-wise rolling hash
└─ NO → Rabin-Karp not directly applicable
    └─ Variable-length pattern → Aho-Corasick (multi-pattern) or KMP (single)
```

### Complexity Analysis

**Time:**

- Preprocessing: O(m) to compute initial hash of pattern and first window
- Per step: O(1) for hash update + O(1) expected for comparison
- Total expected: **O(n + m)**
- Worst case (adversarial hash collisions): O(nm) — every window is a false positive
- With double hashing: O(n + m) with overwhelming probability (negligible false positive rate)

**Derivation of expected case:** In each of the $n - m + 1$ positions, we spend O(1) for the hash comparison. A false positive triggers an O(m) verification. Expected number of false positives = $(n-m+1)/q \approx 0$ for $q \gg n$. Hence expected total verification cost = O(m) · O(n/q) ≈ O(nm/q) ≈ O(1) for large $q$.

**Space:** O(1) auxiliary (just storing the hash values and the high power). O(k) for multi-pattern matching where you store k pattern hashes.

### When to Use vs. Avoid

**Use when:**

- Multi-pattern matching (k patterns simultaneously)
- Duplicate substring detection combined with binary search
- 2D pattern matching in a grid
- Quick implementation where O(nm) worst case is acceptable or adversarial input is not a concern
- You need to extend pattern matching to non-string domains (matrix rows, numeric sequences)

**Avoid when:**

- Single-pattern matching with adversarial inputs → use KMP
- Pattern length varies (rolling hash requires fixed-size windows)
- You need guaranteed O(n+m) worst case → KMP guarantees this, Rabin-Karp does not

## 4. Pseudocode

```
function RABIN_KARP(text, pattern, base, modulus):
    n ← length(text)
    m ← length(pattern)
    
    if m > n: return []  # Edge case: pattern longer than text
    
    # Precompute base^(m-1) mod q — the "high power" for removing leftmost char
    high_power ← 1
    for i from 1 to m-1:
        high_power ← (high_power * base) mod modulus
    
    # Compute hash of pattern and first window of text
    pattern_hash ← 0
    window_hash  ← 0
    for i from 0 to m-1:
        pattern_hash ← (pattern_hash * base + ord(pattern[i])) mod modulus
        window_hash  ← (window_hash  * base + ord(text[i]))    mod modulus
    
    matches ← []
    
    for i from 0 to n-m:
        # Step 1: Compare hashes (cheap O(1) gate)
        if window_hash == pattern_hash:
            # Step 2: Verify character by character (avoid false positives)
            if text[i : i+m] == pattern:
                matches.append(i)
        
        # Step 3: Roll the hash to the next window (if not at the last window)
        if i < n - m:
            # Remove leftmost character: subtract text[i] * base^(m-1)
            # Multiply everything by base (shift left)
            # Add new rightmost character: text[i+m]
            window_hash ← (window_hash - ord(text[i]) * high_power) mod modulus
            window_hash ← (window_hash * base + ord(text[i+m]))      mod modulus
            window_hash ← (window_hash + modulus) mod modulus  # Ensure non-negative
    
    return matches
```

**Why each piece exists:**

- `high_power` computed once upfront: reusing it avoids O(m) recomputation per window step
- `(window_hash + modulus) mod modulus`: C-style modulo can return negative values for negative operands; this ensures the result is always in $[0, q)$
- The verify step `text[i:i+m] == pattern` after hash match: eliminates false positives
- The condition `if i < n - m` on the roll step: prevents array out-of-bounds on the last window

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <functional>

// Rabin-Karp with double hashing to eliminate false positives in adversarial inputs.
// Single-hash version is provided separately for clarity.
// Complexity: O(n + m) expected time, O(1) space (excluding output).

// ─────────────────────────────────────────────────
// Single-hash version — educational, fast in practice
// ─────────────────────────────────────────────────
std::vector<int> rabin_karp_single(const std::string& text,
                                    const std::string& pattern) {
    const long long BASE = 31;
    const long long MOD  = 1e9 + 9;  // Large prime

    int n = (int)text.size();
    int m = (int)pattern.size();
    std::vector<int> result;

    if (m > n) return result;

    // Precompute base^(m-1) mod MOD
    long long high_power = 1;
    for (int i = 0; i < m - 1; ++i)
        high_power = (high_power * BASE) % MOD;

    // Compute hash of pattern and first window
    // Using (char - 'a' + 1) maps 'a'...'z' to 1...26 (avoids hash(empty) == hash("a") if we used 0-indexed)
    auto char_val = [](char c) -> long long { return c - 'a' + 1; };

    long long pat_hash  = 0;
    long long win_hash  = 0;
    for (int i = 0; i < m; ++i) {
        pat_hash = (pat_hash * BASE + char_val(pattern[i])) % MOD;
        win_hash = (win_hash * BASE + char_val(text[i]))    % MOD;
    }

    for (int i = 0; i <= n - m; ++i) {
        // O(1) hash gate before O(m) verification
        if (win_hash == pat_hash) {
            if (text.substr(i, m) == pattern)   // Verify to eliminate false positives
                result.push_back(i);
        }

        // Roll the window (skip for last position)
        if (i < n - m) {
            win_hash = (win_hash - char_val(text[i]) * high_power % MOD + MOD) % MOD;
            win_hash = (win_hash * BASE + char_val(text[i + m])) % MOD;
        }
    }
    return result;
}

// ─────────────────────────────────────────────────
// Double-hash version — adversarial-safe
// Probability of false positive: ~1/(q1 * q2) ≈ 0
// ─────────────────────────────────────────────────
std::vector<int> rabin_karp_double(const std::string& text,
                                    const std::string& pattern) {
    // Two independent (base, modulus) pairs
    const long long B1 = 31,       M1 = 1e9 + 9;
    const long long B2 = 37,       M2 = 1e9 + 7;

    int n = (int)text.size();
    int m = (int)pattern.size();
    std::vector<int> result;

    if (m > n) return result;

    auto val = [](char c) -> long long { return c - 'a' + 1; };

    long long hp1 = 1, hp2 = 1;
    for (int i = 0; i < m - 1; ++i) {
        hp1 = hp1 * B1 % M1;
        hp2 = hp2 * B2 % M2;
    }

    long long ph1 = 0, ph2 = 0, wh1 = 0, wh2 = 0;
    for (int i = 0; i < m; ++i) {
        ph1 = (ph1 * B1 + val(pattern[i])) % M1;
        ph2 = (ph2 * B2 + val(pattern[i])) % M2;
        wh1 = (wh1 * B1 + val(text[i]))    % M1;
        wh2 = (wh2 * B2 + val(text[i]))    % M2;
    }

    for (int i = 0; i <= n - m; ++i) {
        // Both hashes must match — false positive probability ≈ 1/(10^18)
        if (wh1 == ph1 && wh2 == ph2)
            result.push_back(i);
            // With double hashing, verification step is typically omitted in CP
            // (probability of collision is negligible). Keep it for production code.

        if (i < n - m) {
            wh1 = (wh1 - val(text[i]) * hp1 % M1 + M1) % M1;
            wh1 = (wh1 * B1 + val(text[i + m])) % M1;
            wh2 = (wh2 - val(text[i]) * hp2 % M2 + M2) % M2;
            wh2 = (wh2 * B2 + val(text[i + m])) % M2;
        }
    }
    return result;
}

// Multi-pattern matching — the key advantage over KMP
// k patterns, all of same length m → O(n + km) total
// ─────────────────────────────────────────────────
#include <unordered_set>
#include <unordered_map>

std::unordered_map<int, std::vector<int>>
rabin_karp_multi(const std::string& text,
                  const std::vector<std::string>& patterns) {
    if (patterns.empty()) return {};
    int m = (int)patterns[0].size();  // Assumes all patterns same length

    const long long BASE = 31, MOD = 1e9 + 9;
    auto val = [](char c) -> long long { return c - 'a' + 1; };

    long long hp = 1;
    for (int i = 0; i < m - 1; ++i) hp = hp * BASE % MOD;

    // Build HashSet of pattern hashes
    std::unordered_map<long long, std::vector<int>> pat_map; // hash → pattern indices
    for (int pi = 0; pi < (int)patterns.size(); ++pi) {
        long long h = 0;
        for (char c : patterns[pi]) h = (h * BASE + val(c)) % MOD;
        pat_map[h].push_back(pi);
    }

    int n = (int)text.size();
    std::unordered_map<int, std::vector<int>> result;  // pattern_idx → positions

    long long wh = 0;
    for (int i = 0; i < m; ++i) wh = (wh * BASE + val(text[i])) % MOD;

    for (int i = 0; i <= n - m; ++i) {
        auto it = pat_map.find(wh);
        if (it != pat_map.end()) {
            // Check which patterns at this hash actually match
            for (int pi : it->second) {
                if (text.substr(i, m) == patterns[pi])
                    result[pi].push_back(i);
            }
        }
        if (i < n - m) {
            wh = (wh - val(text[i]) * hp % MOD + MOD) % MOD;
            wh = (wh * BASE + val(text[i + m])) % MOD;
        }
    }
    return result;
}

    for (int p : pos2) std::cout << p << " ";
    std::cout << "\n";

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import List, Dict


def rabin_karp(text: str, pattern: str,
               base: int = 31, mod: int = 10**9 + 9) -> List[int]:
    """
    Find all occurrences of pattern in text using Rabin-Karp rolling hash.

    Args:
        text:    The string to search in. Length n.
        pattern: The pattern to find.   Length m.
        base:    Polynomial base (prime recommended).
        mod:     Hash modulus (large prime to reduce collisions).

    Returns:
        List of starting indices where pattern occurs in text.

    Complexity:
        Time:  O(n + m) expected, O(nm) worst case (adversarial hash collisions)
        Space: O(1) auxiliary

    Note:
        For adversarial-safe matching, use rabin_karp_double() below.
        For guaranteed worst-case O(n+m), use KMP (see note 26).
    """
    n, m = len(text), len(pattern)
    if m > n:
        return []

    def char_val(c: str) -> int:
        return ord(c) - ord('a') + 1  # 'a'->1, 'b'->2, ... avoids 0-hash ambiguity

    # Precompute base^(m-1) mod mod_val
    high_power = pow(base, m - 1, mod)

    # Initial hashes for pattern and first window
    pat_hash = 0
    win_hash = 0
    for i in range(m):
        pat_hash = (pat_hash * base + char_val(pattern[i])) % mod
        win_hash = (win_hash * base + char_val(text[i]))    % mod

    matches = []

    for i in range(n - m + 1):
        # O(1) hash comparison — the gate
        if win_hash == pat_hash:
            # Verify to eliminate false positives
            if text[i:i+m] == pattern:
                matches.append(i)

        # Roll the window to position i+1
        if i < n - m:
            # Remove leftmost character
            win_hash = (win_hash - char_val(text[i]) * high_power) % mod
            # Shift left and add new rightmost character
            win_hash = (win_hash * base + char_val(text[i + m])) % mod
            # Python's % always returns non-negative, but explicit safety:
            win_hash %= mod

    return matches


def rabin_karp_double(text: str, pattern: str) -> List[int]:
    """
    Double-hash Rabin-Karp. False positive probability ≈ 1/(10^18).
    Suitable for adversarial inputs without explicit verification.

    Complexity: O(n + m) with overwhelming probability.
    """
    B1, M1 = 31, 10**9 + 9
    B2, M2 = 37, 10**9 + 7

    n, m = len(text), len(pattern)
    if m > n:
        return []

    def v(c):
        return ord(c) - ord('a') + 1

    hp1, hp2 = pow(B1, m-1, M1), pow(B2, m-1, M2)

    ph1 = ph2 = wh1 = wh2 = 0
    for i in range(m):
        ph1 = (ph1 * B1 + v(pattern[i])) % M1
        ph2 = (ph2 * B2 + v(pattern[i])) % M2
        wh1 = (wh1 * B1 + v(text[i]))    % M1
        wh2 = (wh2 * B2 + v(text[i]))    % M2

    matches = []
    for i in range(n - m + 1):
        if wh1 == ph1 and wh2 == ph2:
            matches.append(i)  # No explicit verify needed with double hash in practice

        if i < n - m:
            wh1 = (wh1 - v(text[i]) * hp1 % M1 + M1) % M1
            wh1 = (wh1 * B1 + v(text[i + m])) % M1
            wh2 = (wh2 - v(text[i]) * hp2 % M2 + M2) % M2
            wh2 = (wh2 * B2 + v(text[i + m])) % M2

    return matches


def rabin_karp_multi(text: str, patterns: List[str]) -> Dict[str, List[int]]:
    """
    Multi-pattern Rabin-Karp. All patterns must have the same length.
    This is the PRIMARY advantage of Rabin-Karp over KMP.

    Complexity: O(n + km) where k = len(patterns), m = pattern length.
    Compare to k independent KMP runs: O(kn + km) — significantly worse for large k.
    """
    if not patterns:
        return {}

    m = len(patterns[0])
    BASE, MOD = 31, 10**9 + 9

    def v(c):
        return ord(c) - ord('a') + 1

    hp = pow(BASE, m - 1, MOD)

    # Build: hash → list of patterns with that hash
    from collections import defaultdict
    hash_to_pats: Dict[int, List[str]] = defaultdict(list)
    for pat in patterns:
        h = 0
        for c in pat:
            h = (h * BASE + v(c)) % MOD
        hash_to_pats[h].append(pat)

    n = len(text)
    result: Dict[str, List[int]] = {pat: [] for pat in patterns}

    wh = 0
    for i in range(m):
        wh = (wh * BASE + v(text[i])) % MOD

    for i in range(n - m + 1):
        if wh in hash_to_pats:
            window = text[i:i+m]
            for pat in hash_to_pats[wh]:
                if window == pat:
                    result[pat].append(i)

        if i < n - m:
            wh = (wh - v(text[i]) * hp % MOD + MOD) % MOD
            wh = (wh * BASE + v(text[i + m])) % MOD

    return result


# ── Tests ──────────────────────────────────────────
if __name__ == "__main__":
    # Basic single match
    assert rabin_karp("abcabcabc", "abc") == [0, 3, 6], "Test 1 failed"

    # Pattern at start and end
    assert rabin_karp("aababaa", "aa") == [0, 5], "Test 2 failed"

    # Pattern not found
    assert rabin_karp("abcdef", "xyz") == [], "Test 3 failed"

    # Edge: pattern equals text
    assert rabin_karp("hello", "hello") == [0], "Test 4 failed"

    # Multi-pattern
    result = rabin_karp_multi("abcabcabc", ["abc", "bca", "cab"])
    assert result["abc"] == [0, 3, 6], "Multi test 1 failed"
    assert result["bca"] == [1, 4, 7], "Multi test 2 failed"

    # Double hash matches single hash
    assert rabin_karp_double("abcabcabc", "abc") == [0, 3, 6], "Double hash test failed"

    print("All tests passed.")
```

### The Rolling Hash Arithmetic

```
Window at i=0: "abc"
Hash = val(a)·b² + val(b)·b¹ + val(c)·b⁰
     = 1·b²   + 2·b    + 3

Rolling to i=1 "bca":
1. Remove 'a' (leftmost): subtract val(a)·b^(m-1) = 1·b²
   → 2·b + 3
2. Shift left (multiply by b): × b
   → 2·b² + 3·b
3. Add 'a' (rightmost): + val(a) = 1
   → 2·b² + 3·b + 1
   = val(b)·b² + val(c)·b + val(a)·1
   = H("bca")  ✓ Correct!

KEY INSIGHT: Each step costs O(1) arithmetic operations, regardless of m.
The O(m) cost is paid ONCE (initial hash), then amortised across all n windows.
```

### Multi-Pattern Matching: Why Rabin-Karp Wins Over KMP

```
k=3 patterns: {"abc", "bca", "xyz"}  (all length m=3)

KMP approach: Build 3 automata, run 3 passes = O(3n) = O(kn) total search

Rabin-Karp approach:
                   HashSet: { H("abc"), H("bca"), H("xyz") }
                              ↑           ↑          ↑
                           Pattern     Pattern    Pattern
                              1           2          3

At each window position i:
    Compute H(window[i..i+m]) → O(1) rolling update
    Check: H(window) ∈ HashSet? → O(1) set lookup
    If yes: verify which pattern(s) match → O(m) only on hits

Total: O(n) rolling + O(1)·n lookups = O(n + km) preprocessing
               ↑
         Regardless of k!

For k = 1000 patterns, KMP = O(1000n), Rabin-Karp ≈ O(n). No contest.
```

## 7. Common Variations & Extensions

### 7.1 Longest Duplicate Substring (Binary Search + Rolling Hash)

The problem: find the longest substring that appears at least twice. Direct approach is O(n²) with a HashSet of all substrings. The key insight: if a duplicate exists at length $L$, it exists at all lengths $< L$ (monotonic property). Binary search on the length $L \in [1, n]$, and for each candidate $L$, use Rabin-Karp to check all windows of length $L$ for duplicates in O(n). Total: O(n log n).

This is a canonical application of "binary search on answer" (see [[59.The binary search on answer template — monotonic predicate]]) combined with rolling hash — two techniques that marry beautifully.

### 7.2 2D Pattern Matching

Find a $p \times q$ submatrix in an $n \times m$ matrix. Method: apply row-wise rolling hash to reduce each row of the pattern to a single hash value, then treat the $n \times m$ matrix as a 1D problem where each "character" is the hash of a $q$-element row segment. Apply column-wise rolling hash on these "characters". This achieves O(nm) total, the same as reading the input, with no wasted work.

### 7.3 Rolling Hash for String Palindrome Detection

To check if any substring is a palindrome efficiently, maintain two rolling hashes simultaneously — one for the forward direction and one for the reverse. If $H(\text{forward}) = H(\text{reverse})$ at any window, you have a palindrome candidate (verify to confirm). Related: [[174.Palindrome DP — longest palindromic subsequence, partitioning]].

### 7.4 Document Similarity with Shingling

For ML/NLP applications: represent a document as the set of all k-gram hashes (k-character substrings). Use MinHash (see [[39.MinHash — estimating Jaccard similarity at scale]]) on these hash sets to estimate Jaccard similarity between documents in O(n) per document. This is how large-scale near-duplicate detection works in web crawling and LLM pretraining pipelines. The k-gram hash computation is exactly a batch of rolling hash evaluations.

## 9. CP Contest Application

### Typical Problem Structure

**Codeforces/AtCoder problem archetypes:**

1. **"Find all occurrences" (Codeforces Div 2 C/D):** Given string $S$ (|S| up to $10^6$) and pattern $P$ (|P| up to $10^5$), find all starting positions. Time limit 2s. Rolling hash or KMP both work; double hash is safer.
    
2. **"Shortest string that contains all given strings as substrings" (Div 2 D/E):** Requires checking all pairwise suffix-prefix overlaps → multi-pattern matching, Rabin-Karp speeds up the check.
    
3. **"Longest repeated substring" (Div 1 C/D):** Binary search on length $L$, rolling hash to detect duplicates at each $L$. Typical time limit 3s for $n \leq 2 \cdot 10^5$.
    
4. **2D grid matching (Educational round D/E):** Find $k \times k$ pattern in $n \times n$ grid. Apply rolling hash rowwise then columnwise in O(n²) for a grid of size $n \times n$.
    

### Time Limit Considerations

- Single hash: ~100-200ms for $n = 10^6$ in C++. Fast enough for most 2s limits.
- Double hash: ~2× overhead. Still fine for $n = 10^6$ within 3s.
- The O(m) verification step is the danger zone: if the judge has a test with $O(n)$ matches (e.g., text = "aaaa...a", pattern = "aaa"), total verification cost = O(nm). Use double hash to skip verification.

### Optimisation Tricks

- **Precompute all powers of base** up to $n$: `pow[i] = base^i mod q`. Avoids repeated `pow()` calls.
- **Use `__int128` or `unsigned long long`** in C++ to delay modular reduction: accumulate products without `% MOD` on every step if overflow won't happen within 2-3 multiplications.
- **Anti-hash test defence:** If the problem setter uses a known modulus (like $10^9 + 7$), choose a random modulus at runtime: `long long MOD = uniform_int_distribution<long long>(1e9, 2e9)(rng)` where `rng` is seeded with `chrono::steady_clock`. This makes it impossible to craft adversarial inputs.
- **String hashing as a building block:** Many problems use rolling hash not just for pattern matching but for any "compare two substrings efficiently" query — e.g., finding the longest common prefix of two suffixes in O(log n) via binary search + hash comparison. This is the basis of suffix array construction in some implementations and connects directly to [[30.Suffix array — construction and LCP array]].
