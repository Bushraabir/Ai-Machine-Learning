## 1. Intuition First

### The Core Idea

Imagine you're searching for two people in a line-up who together weigh exactly 200kg. The line-up is already **sorted by weight**, lightest on the left, heaviest on the right. You don't scan every pair — that's O(n²). Instead, you start with two scouts: one at the far left (the lightest) and one at the far right (the heaviest). You check their combined weight:

- **Too heavy?** Move the right scout one step left — you need a lighter heavy person.
- **Too light?** Move the left scout one step right — you need a heavier light person.
- **Exact match?** Done.

Each check eliminates an entire row of possibilities, not just one candidate. That's the power of opposite-end two pointers: **monotonicity of a sorted structure collapses a 2D search space into a 1D scan**.

### Why This Exists

The naive approach to "find a pair with property P" is a nested loop: fix one element, scan all others — O(n²). For n = 10⁵, that's 10¹⁰ operations. Infeasible.

A HashMap can do it in O(n) time (see [[35.Two-sum and k-sum — the canonical HashMap pattern]]), but costs O(n) extra space. The opposite-end pointer technique achieves O(n) time and **O(1) space**, by leveraging the sorted order as implicit information. Sorted order is free structure — the two-pointer technique is how you exploit it.

The key insight is that in a sorted array, moving a pointer is never wasted. If `arr[left] + arr[right] > target`, then every pair `(left, right')` where `right' > right` would also exceed the target — those pairs are dead to us. So we shrink from the right. Every pointer move eliminates an entire half-space of the 2D pair grid.

### The "Aha" Moment

> **The sorted array is not just a data structure — it's a decision tree compressed into a line.** Every pointer move is a branch: you eliminate an entire row or column of the O(n²) pair matrix in O(1).

Draw the n×n grid where cell (i, j) represents the pair (arr[i], arr[j]). The two-pointer traversal carves a staircase path from top-right to bottom-left, hitting every necessary cell and skipping provably-irrelevant ones. The O(n²) grid shrinks to an O(n) diagonal walk.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- Any problem asking for pairs, triplets, or partitions satisfying a sum/product constraint on a sorted (or sortable) array.
- Keywords: "two numbers that sum to", "closest pair", "valid triangle", "minimum absolute difference", "container with most water", "palindrome check on sorted-adjacent structure".

**Signal pattern:**

```
Sorted array + find two elements + optimise/check a pairwise property
→ try opposite-end two pointers before any other approach
```

**Classic triggers:**

- "Two Sum II — sorted input" (immediately two-pointer)
- "3Sum" — sort, then fix one, two-pointer on the rest (see [[18.Three pointers — Dutch National Flag, 3Sum]])
- "Trapping Rain Water" (see [[90.Trapping rainwater — two-pointer and stack approaches]])
- "Squares of a Sorted Array" — merge from both ends

**Common trap that kills submissions:**

The pointer movement condition must be **strictly monotonic**. A common bug:

```cpp
// BUG: doesn't handle duplicates — infinite loop if arr[left] == arr[right]
while (left < right) {
    if (arr[left] + arr[right] == target) return {left, right};
    else if (arr[left] + arr[right] < target) left++;
    else right--;
    // Missing: what if we need ALL pairs? Must advance BOTH pointers past duplicates
}
```

For "find all unique pairs", after recording a match you must skip duplicates:

```cpp
while (left < right && arr[left] == arr[left+1]) left++;
while (left < right && arr[right] == arr[right-1]) right--;
```

Forgetting this gives TLE or Wrong Answer on problems with duplicate-heavy inputs.

---

### Machine Learning / AI

**Where this appears:**

1. **Cosine similarity search on sorted embeddings:** When embeddings are sorted by a scalar projection (e.g., along a principal component after PCA), finding pairs above a similarity threshold reduces to a two-pointer scan rather than exhaustive O(n²) dot products. This is the conceptual basis of how **FAISS** (Facebook AI Similarity Search) organises its inverted file index — sort by cluster centroid distance, then scan inward.
    
2. **Sorted minibatch construction:** When constructing minibatches by sequence length for RNN/Transformer training (to minimise padding waste), a common strategy is **two-end packing**: pair the longest and shortest sequences together to balance batch length distributions. PyTorch's `BucketSampler` does this implicitly — sort by length, pair from both ends to create balanced buckets.
    
3. **Ranking evaluation metrics:** Computing metrics like **Kendall's τ** (rank correlation) requires counting concordant/discordant pairs. After sorting by one ranking, a two-pointer sweep on the other can count these in O(n log n) instead of O(n²). This is used in `scipy.stats.kendalltau` under the hood.
    
4. **Binary classification threshold search:** Finding the operating point on a precision-recall curve where precision ≈ recall. After sorting predictions by confidence score, a left pointer on predicted positives and right pointer on actual positives sweeps through to find the crossover — a direct two-pointer application. Scikit-learn's `precision_recall_curve` computes this via a similar sorted sweep.
    

**Why understanding this makes you better at ML code:**

When you see a pairwise operation in ML code that scales quadratically with dataset size, ask: "Is the data sortable, and does my criterion respect that order?" If yes, you can replace an O(n²) nested loop with an O(n log n) sort + O(n) sweep — a 1000× speedup for n = 10⁵.

## 3. Algorithm / Pattern

### Step-by-Step Logic

**Pre-condition:** Array must be sorted (ascending). If not, sort it first — O(n log n).

1. Set `left = 0`, `right = n - 1`.
2. While `left < right`: a. Compute `current = f(arr[left], arr[right])` where f is your criterion (sum, product, absolute difference, etc.) b. If `current == target`: record result, advance both pointers (handle duplicates if needed) c. If `current < target`: advance `left++` (need larger left element to increase sum) d. If `current > target`: advance `right--` (need smaller right element to decrease sum)
3. Terminate when pointers cross.

### Decision Tree

```
Problem involves pairs in a sorted array?
├── Yes → Apply opposite-end two pointers
│   ├── Criterion is a SUM/DIFFERENCE?
│   │   ├── sum < target → left++
│   │   └── sum > target → right--
│   ├── Criterion is a PRODUCT? (all positives)
│   │   ├── product < target → left++
│   │   └── product > target → right--
│   └── Need ALL unique pairs?
│       └── After match: skip duplicates on both ends
└── No → Consider HashMap (O(n) time, O(n) space)
         or Binary Search (O(n log n))
```

**When to avoid:**

- Array is **not sortable** (e.g., you need original indices and sorting would disrupt them — use HashMap instead)
- Criterion is **not monotone** in either pointer direction (e.g., a non-linear interaction where moving left doesn't consistently increase/decrease the criterion)
- Problem asks for k-nearest pairs where k is large — a heap is cleaner

### Complexity

**Time:** O(n log n) if sorting is required + O(n) for the two-pointer scan = **O(n log n)**  
If array is pre-sorted: **O(n)**

**Derivation of O(n) scan:** Each pointer starts at an endpoint and only moves inward. `left` only increments, `right` only decrements. Together they take at most n steps before crossing. ∑ moves ≤ n. Therefore O(n).

**Space:** O(1) auxiliary (excluding output). No hash table, no additional array.

## 4. Pseudocode

```
function TWO_POINTER_SUM(arr[0..n-1], target):
    # Precondition: arr is sorted in ascending order
    
    left  ← 0
    right ← n - 1
    results ← []

    while left < right:
        current_sum ← arr[left] + arr[right]

        if current_sum == target:
            # Found a valid pair
            results.append((arr[left], arr[right]))

            # CRITICAL: skip duplicates to find ALL unique pairs
            while left < right and arr[left] == arr[left + 1]:
                left ← left + 1
            while left < right and arr[right] == arr[right - 1]:
                right ← right - 1

            # Advance past the matched elements themselves
            left  ← left + 1
            right ← right - 1

        elif current_sum < target:
            # Sum too small: increase by moving left pointer right
            # Justification: arr[left] is the smallest untried left element.
            # All pairs (left, right'), right' <= right, also too small.
            # Safely eliminate entire left column.
            left ← left + 1

        else:  # current_sum > target
            # Sum too large: decrease by moving right pointer left
            # Justification: arr[right] is the largest untried right element.
            # All pairs (left', right), left' >= left, also too large.
            # Safely eliminate entire right row.
            right ← right - 1

    return results
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <algorithm>
#include <vector>
#include <iostream>

// ─────────────────────────────────────────────────────────────────
// Two Sum II — find ALL unique pairs that sum to target
// Input:  sorted array (ascending), target integer
// Output: vector of pairs {a, b} where a + b == target
// Time:   O(n)   Space: O(1) auxiliary, O(k) output
// ─────────────────────────────────────────────────────────────────
std::vector<std::pair<int,int>> two_sum_sorted(
    const std::vector<int>& arr, int target)
{
    std::vector<std::pair<int,int>> results;
    int left = 0, right = static_cast<int>(arr.size()) - 1;

    while (left < right) {
        int sum = arr[left] + arr[right];

        if (sum == target) {
            results.emplace_back(arr[left], arr[right]);

            // Skip duplicate values to ensure unique pairs
            while (left < right && arr[left]  == arr[left  + 1]) ++left;
            while (left < right && arr[right] == arr[right - 1]) --right;

            ++left;
            --right;
        } else if (sum < target) {
            ++left;   // need larger sum → advance left
        } else {
            --right;  // need smaller sum → retreat right
        }
    }

    return results;
}

// ─────────────────────────────────────────────────────────────────
// Closest Pair to Target (variant)
// Returns the pair whose sum is closest to target
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
std::pair<int,int> closest_pair(
    const std::vector<int>& arr, int target)
{
    int left = 0, right = static_cast<int>(arr.size()) - 1;
    int best_diff = std::abs(arr[left] + arr[right] - target);
    std::pair<int,int> best = {arr[left], arr[right]};

    while (left < right) {
        int sum  = arr[left] + arr[right];
        int diff = std::abs(sum - target);

        if (diff < best_diff) {
            best_diff = diff;
            best = {arr[left], arr[right]};
        }

        if (sum < target)      ++left;
        else if (sum > target) --right;
        else                   break;  // exact match — can't do better
    }

    return best;
}

// ─────────────────────────────────────────────────────────────────
// Valid Triangle Count (classic CP variant)
// Count triplets (i,j,k) with i<j<k where arr[i]+arr[j] > arr[k]
// Fix largest side k, use two pointers on [0, k-1]
// Time: O(n²)   Space: O(1)   [sorting is the bottleneck]
// ─────────────────────────────────────────────────────────────────
int count_valid_triangles(std::vector<int> arr) {
    std::sort(arr.begin(), arr.end());
    int n = static_cast<int>(arr.size()), count = 0;

    for (int k = n - 1; k >= 2; --k) {
        int left = 0, right = k - 1;
        while (left < right) {
            if (arr[left] + arr[right] > arr[k]) {
                // arr[left..right-1] + arr[right] ALL > arr[k]
                count += (right - left);
                --right;
            } else {
                ++left;
            }
        }
    }

    return count;
}

// ─────── Minimal test ───────────────────────────────────────────
int main() {
    // Test 1: Two-sum sorted
    std::vector<int> arr = {-3, -1, 0, 2, 4, 5, 8};
    auto pairs = two_sum_sorted(arr, 4);
    // Expected: (-1, 5) and (-3, 7 - no), actually: {-1,5} and {0,4}
    for (auto [a, b] : pairs)
        std::cout << "(" << a << ", " << b << ") ";
    std::cout << "\n";  // Output: (-1, 5) (0, 4)

    // Test 2: Closest pair
    auto [a, b] = closest_pair(arr, 3);
    std::cout << "Closest: (" << a << ", " << b << ")\n";  // (0, 4) or (-1, 4)

    // Test 3: Triangle count
    std::vector<int> sides = {2, 2, 3, 4};
    std::cout << "Triangles: " << count_valid_triangles(sides) << "\n";  // 3

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import List, Tuple


def two_sum_sorted(arr: List[int], target: int) -> List[Tuple[int, int]]:
    """
    Find all unique pairs in a sorted array that sum to target.

    Args:
        arr:    Sorted list of integers (ascending).
        target: Desired pair sum.

    Returns:
        List of (a, b) tuples where a + b == target, no duplicates.

    Complexity:
        Time:  O(n)
        Space: O(1) auxiliary, O(k) output where k = number of valid pairs
    """
    results: List[Tuple[int, int]] = []
    left, right = 0, len(arr) - 1

    while left < right:
        current = arr[left] + arr[right]

        if current == target:
            results.append((arr[left], arr[right]))

            # Skip duplicate values on both sides
            while left < right and arr[left] == arr[left + 1]:
                left += 1
            while left < right and arr[right] == arr[right - 1]:
                right -= 1

            left += 1
            right -= 1

        elif current < target:
            left += 1   # need a larger element on the left
        else:
            right -= 1  # need a smaller element on the right

    return results


def closest_pair(arr: List[int], target: int) -> Tuple[int, int]:
    """
    Return the pair in sorted arr whose sum is closest to target.

    Complexity: O(n) time, O(1) space (assumes pre-sorted).
    """
    left, right = 0, len(arr) - 1
    best: Tuple[int, int] = (arr[left], arr[right])
    best_diff = abs(arr[left] + arr[right] - target)

    while left < right:
        s = arr[left] + arr[right]
        diff = abs(s - target)

        if diff < best_diff:
            best_diff = diff
            best = (arr[left], arr[right])

        if s < target:
            left += 1
        elif s > target:
            right -= 1
        else:
            break  # exact match

    return best


def count_valid_triangles(arr: List[int]) -> int:
    """
    Count triplets (a, b, c) with a <= b <= c where a + b > c.

    Fix c (largest side), use two pointers on prefix.
    
    Complexity: O(n²) time, O(1) space (sort is the bottleneck O(n log n))
    """
    arr = sorted(arr)
    n, count = len(arr), 0

    for k in range(n - 1, 1, -1):  # k is index of largest side
        left, right = 0, k - 1
        while left < right:
            if arr[left] + arr[right] > arr[k]:
                # All pairs (left, left+1, ..., right-1) with arr[right] also valid
                count += right - left
                right -= 1
            else:
                left += 1

    return count


# ─── Quick smoke tests ───────────────────────────────────────────
if __name__ == "__main__":
    arr = [-3, -1, 0, 2, 4, 5, 8]

    print(two_sum_sorted(arr, 4))       # [(-1, 5), (0, 4)]
    print(two_sum_sorted(arr, 100))     # []
    print(two_sum_sorted(arr, -1))      # [(-3, 2)]
    print(closest_pair(arr, 3))         # (-1, 4) — sum=3, exact
    print(count_valid_triangles([2, 2, 3, 4]))  # 3
```

## 6. Visual Explanation

### The O(n²) Grid and the Two-Pointer Path

For `arr = [1, 3, 5, 7, 9]`, `target = 10`. Each cell (i,j) is the sum `arr[i] + arr[j]`. We only care about cells where `i < j` (upper-right triangle):

```
         j=0   j=1   j=2   j=3   j=4
         [1]   [3]   [5]   [7]   [9]
i=0 [1]   --     4     6     8    10 ✓
i=1 [3]   --    --     8    10 ✓   12
i=2 [5]   --    --    --    12    14
i=3 [7]   --    --    --    --    16
i=4 [9]   --    --    --    --    --

Two-pointer staircase path:
Start → (i=0, j=4): sum=10 ✓  → Record, advance both
      → (i=1, j=3): sum=10 ✓  → Record, advance both
      → (i=2, j=2): left >= right, STOP

Each move eliminates an entire row or column of the n×n grid.
```

### Window Movement Step-by-Step

```
arr = [-4, -1, 0, 3, 10, 15],  target = 11

Step 1:
  [-4, -1,  0,  3, 10, 15]
    L                    R        sum = -4+15 = 11 ✓  → RECORD (-4,15)
    
Step 2: advance both, skip duplicates (none here)
  [-4, -1,  0,  3, 10, 15]
         L           R           sum = -1+10 = 9 < 11  → L++

Step 3:
  [-4, -1,  0,  3, 10, 15]
              L        R         sum = 0+10 = 10 < 11  → L++

Step 4:
  [-4, -1,  0,  3, 10, 15]
                 L     R         sum = 3+10 = 13 > 11  → R--

Step 5:
  [-4, -1,  0,  3, 10, 15]
                 L  R            L(3) >= R(10)? No.
                                 sum = 3+10... wait L=3, R=4 (index)
                                 Actually now L=3, R=3 → L >= R → STOP

Result: [(-4, 15)]
```

### Why Moving One Pointer Eliminates an Entire Half-Space

```
Sorted:  a₀ ≤ a₁ ≤ ... ≤ aₗ ≤ ... ≤ aᵣ ≤ ... ≤ aₙ₋₁
                          ↑                ↑
                        LEFT             RIGHT

If aₗ + aᵣ > target:
   Then for any r' > r: aₗ + aᵣ' ≥ aₗ + aᵣ > target
   → All (l, r'), r' ≥ r are invalid. Entire right column eliminated.
   → Move RIGHT pointer inward.

If aₗ + aᵣ < target:
   Then for any l' < l: aₗ' + aᵣ ≤ aₗ + aᵣ < target
   → All (l', r), l' ≤ l are invalid. Entire left row eliminated.
   → Move LEFT pointer inward.
```

## 7. Common Variations & Extensions

### Variation 1: 3Sum / kSum

Fix k−2 elements with nested loops, apply two-pointer on the remaining sorted subarray. 3Sum becomes O(n²); 4Sum becomes O(n³). See [[18.Three pointers — Dutch National Flag, 3Sum]].

```python
# 3Sum skeleton
arr.sort()
for i in range(len(arr) - 2):
    if i > 0 and arr[i] == arr[i-1]: continue  # skip outer duplicates
    left, right = i + 1, len(arr) - 1
    two_pointer_core(arr, left, right, -arr[i])  # find pairs summing to -arr[i]
```

### Variation 2: Maximum Area / Product

"Container With Most Water" (LC 11) — here the criterion isn't a sum but `min(height[left], height[right]) * width`. The pointer move rule changes: always move the pointer pointing to the **shorter** side, because keeping the shorter side can never increase the area (width decreases, height doesn't improve). Same skeleton, different move condition.

### Variation 3: Palindrome Check

For a sorted-adjacent string comparison (see [[19.Two pointers on strings — palindrome, matching]]), the opposite-end pattern checks `s[left] == s[right]` and moves both inward. The "sorted" precondition doesn't apply here — the symmetry of the string replaces it.

### Variation 4: Squares of Sorted Array

Given sorted (possibly negative) array, return sorted squares. Two pointers from both ends comparing absolute values, building the output array **from right to left** (largest square first):

```python
def sorted_squares(arr):
    n = len(arr)
    result = [0] * n
    left, right, pos = 0, n - 1, n - 1
    while left <= right:
        if abs(arr[left]) >= abs(arr[right]):
            result[pos] = arr[left] ** 2; left += 1
        else:
            result[pos] = arr[right] ** 2; right -= 1
        pos -= 1
    return result
```

### Connection to Binary Search

Two-pointer on sorted arrays and [[55.Binary search on a sorted array — exact match]] are siblings. Binary search answers "does X exist?" in O(log n). Two-pointer answers "find a pair satisfying P" in O(n). When the outer problem has a monotonic structure (like "minimum possible answer"), [[59.The binary search on answer template — monotonic predicate]] wraps around a two-pointer inner check.

## 9. CP Contest Application

### Typical Codeforces Problem Structure

**Pattern:** "Given array of n integers (n ≤ 2×10⁵), find the number of pairs (i, j) with i < j such that `arr[i] + arr[j] ≤ k`."

**Solution:** Sort → two pointers → for each `right`, `left` points to the largest element ≤ `k - arr[right]`. Count = `left + 1`. This runs in O(n log n) and comfortably fits in a 2-second time limit.

**Common Codeforces problem types:**

- Count pairs with property → sort + two-pointer counting (O(n log n))
- Minimize the maximum pairwise sum → sort + greedy two-pointer pairing
- Find if a valid partition exists → sort + two-pointer feasibility check

### Time Limit Considerations

|n|Two-pointer O(n)|Naive O(n²)|Verdict|
|---|---|---|---|
|10⁵|~10⁵ ops|~10¹⁰ ops|Two-ptr required|
|10³|~10³ ops|~10⁶ ops|Both ok|
|2×10⁵|~2×10⁵ ops|TLE|Two-ptr required|

**Optimization trick for CP:** When counting pairs instead of finding them, avoid appending to a results vector (cache-unfriendly). Use a counter integer and increment atomically:

```cpp
long long count = 0;
while (left < right) {
    if (arr[left] + arr[right] <= target) {
        count += (right - left);  // All pairs (left, left+1, ..., right-1) valid
        ++left;
    } else {
        --right;
    }
}
```

This counting trick (adding `right - left` instead of iterating) is what makes two-pointer run O(n) even when the answer has O(n²) pairs.
