## 1. Intuition First

### The Core Idea

Take any string — say `"aabxaa"`. For every position $i$, ask one question: **how long is the longest substring starting at $i$ that also matches a prefix of the entire string?**

Position 0: trivially the whole string, length 6 (by convention, Z[0] is undefined or set to 0/n). Position 1: `"abxaa"` starts with `'a'`, and the prefix also starts with `'a'`, but `'b' ≠ 'a'` — so length 1. Position 4: `"aa"` starts with `"aa"`, which matches the prefix `"aa"` — length 2. Position 2: `"bxaa"` — `'b' ≠ 'a'`, length 0.

The array of these lengths is called the **Z-array**. For `"aabxaa"`: `Z = [_, 1, 0, 0, 2, 1]`.

This array encodes, at every position, how much of the string's prefix is "echoed" at that location. Pattern matching becomes trivial: concatenate `pattern + "$" + text` (the `"$"` is a separator guaranteed not to appear in either string), compute the Z-array of the concatenated string, and look for any position in the text part where $Z[i] = |pattern|$. That position is a match.

### Why This Exists

The naive approach tries to match from every position: O(nm) worst case. [[26.KMP algorithm — failure function and O(n+m) matching]] solves this by precomputing a _failure function_ that encodes how the pattern overlaps with itself — essentially the same information as the Z-array, just framed differently.

The Z-algorithm and KMP solve the _same core problem_ from different angles:

- KMP asks: "given a mismatch at position $j$ in the pattern, where is the longest proper prefix of `pattern[0..j-1]` that is also a suffix?" (backward-looking, within the pattern)
- Z-algorithm asks: "starting at position $i$ in the string, how long does the match with the prefix run?" (forward-looking, from every position)

KMP's failure function and the Z-array carry equivalent information and can be converted to each other. Neither is strictly more powerful. The Z-algorithm is often _easier to derive from scratch_ in a contest, because the invariant is more intuitive: at every step, you maintain a "Z-box" — a window `[L, R]` representing the rightmost known match of a prefix — and exploit it to avoid redundant comparisons.

The Z-algorithm also generalises more naturally to problems that explicitly ask about prefix-suffix structure: "count positions where a prefix ends", "find the smallest period of a string", "find all substrings that are also prefixes".

### The "Aha" Moment

The O(n) efficiency comes from one insight: **you never move the right boundary $R$ of the Z-box backward.** Every time you extend $R$, you pay one character comparison. Since $R$ can only increase (from 0 to at most $n$), the total number of comparisons across all positions is at most $n$. The Z-box is a _cache_ of previously computed matches; using it correctly means you never re-examine a character that's already been confirmed to match.

This is the same insight behind KMP (the failure function as a cache of prefix knowledge) and behind rolling hash in Rabin-Karp (the hash as a cache of window content). **All three algorithms achieve O(n) by finding a way to reuse previous work rather than restarting.**

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- Any problem asking: "how many times does pattern $P$ appear in text $T$?"
- "Find the shortest string that is both a prefix and a suffix of $S$"
- "Find the smallest period of a string"
- "Given string $S$, for each prefix $S[0..k]$, count how many times it appears in $S$"
- Problems involving string border structures (a border = a string that is both a proper prefix and a proper suffix)

**Signal patterns:**

- "prefix that is also a suffix" → Z-array directly
- "smallest repeating unit/period" → Z-array: period $p$ iff $Z[p] = n - p$ (and $p$ divides $n$ for exact tiling)
- Any problem where you construct a concatenated string with a separator and scan for equality — this is the canonical Z-algorithm setup

**The canonical trap — confusing Z[0]:** $Z[0]$ is conventionally undefined, set to 0 or $n$ depending on the implementation. Using $Z[0]$ in your logic almost always introduces an off-by-one bug. In pattern matching with the concatenated string `P + "$" + T`, valid matches only exist in the text part (positions $\geq |P| + 1$), so $Z[0]$ is never relevant for the answer. Explicitly skipping index 0 is the standard practice.

**Second trap — the separator character:** The separator `"$"` must not appear in $P$ or $T$. If the input is arbitrary bytes or Unicode, choose a sentinel that's guaranteed absent (e.g., `'\0'` for ASCII text, or a character outside the alphabet). If you forget this, Z values can "bleed" across the separator boundary and give false positives.

**Third trap — misreading the period condition:** A string has period $p$ if $S[i] = S[i-p]$ for all $i \geq p$. This is equivalent to $Z[p] \geq n - p$. Students often write $Z[p] = n - p$, which is only correct for exact tiling (no leftover). For the general "smallest period" question, use the $\geq$ condition.

### Machine Learning / AI

The Z-algorithm is not a library function in PyTorch or scikit-learn, but its conceptual structure appears in several ML contexts:

**1. Tokenisation and subword structure.** BPE (Byte Pair Encoding), used in every major LLM (GPT-4, LLaMA 3, Mistral), operates on prefix-suffix overlaps between tokens during vocabulary construction. The merge step — finding the most frequent adjacent pair — implicitly reasons about prefix/suffix alignment. Understanding Z-array logic makes it easier to reason about why certain token splits arise and why "prefix" tokens (like `"Ġ"` in GPT-2's vocabulary) exist.

**2. Sequence models and prefix matching.** In beam search decoding (used in every seq2seq model — T5, BART, mBART), the decoder maintains partial prefix hypotheses. Checking whether a hypothesis prefix matches a known good string is structurally a prefix-matching problem. Trie-based constrained decoding (used in structured generation libraries like Outlines and Guidance) uses prefix automata that are directly related to Z-array structure.

**3. Self-similarity in time series (ML feature engineering).** The Z-array of a time series computes, for every position $i$, how long the subsequence starting at $i$ matches the subsequence starting at 0. This is a measure of self-similarity at different lags — directly related to autocorrelation. In time series ML (forecasting with ARIMA, Prophet, or Temporal Fusion Transformers), detecting periodicity is essential. The Z-algorithm computes an exact discrete version of this in O(n).

**4. Suffix arrays and NLP.** [[30.Suffix array — construction and LCP array]] is constructed efficiently using a process that relies on Z-array-style prefix comparisons. Suffix arrays underlie fast full-text search (used in compressed language model indices like FM-index and BWT-compressed text), which appears in retrieval-augmented generation (RAG) systems for exact substring retrieval from large corpora.

**5. DNA/protein sequence alignment.** Bioinformatics ML pipelines (protein structure prediction like AlphaFold preprocessing, genomic variant calling) require fast exact and approximate string matching. BLAST's seed-and-extend model uses exact short substring matches (seeds) as anchors — the seed lookup is a Z-algorithm-style prefix match in disguise.

## 3. Algorithm / Pattern

### Step-by-Step Logic

**Input:** String $S$ of length $n$. **Output:** Z-array where $Z[i]$ = length of the longest substring starting at $S[i]$ that matches a prefix of $S$. By convention $Z[0] = 0$ (or $n$, but 0 is safer for most applications).

**Maintain a Z-box $[L, R]$:** the interval such that $S[L..R-1]$ is a prefix of $S$, and $R$ is maximised over all intervals seen so far. Initially $L = R = 0$.

**For each position $i$ from 1 to $n-1$:**

**Case 1: $i \geq R$ (outside the Z-box)** No prior information applies. Extend naively by comparing $S[i], S[i+1], \ldots$ with $S[0], S[1], \ldots$ until a mismatch. Set $Z[i]$ to the match length. If any match was found (Z[i] > 0), update $L = i$, $R = i + Z[i]$.

**Case 2: $i < R$ (inside the Z-box)** We know $S[i..R-1]$ matches $S[i-L..R-L-1]$. The position $i' = i - L$ is the corresponding position in the known prefix. Two sub-cases:

- **Sub-case 2a: $Z[i'] < R - i$** (the known Z-value is strictly within the box) The match at $i'$ doesn't reach the edge of the box, so it's fully confirmed by the Z-box. Set $Z[i] = Z[i']$. No extension needed. $L$ and $R$ stay unchanged.
    
- **Sub-case 2b: $Z[i'] \geq R - i$** (the known Z-value reaches or exceeds the box edge) We know at least $R - i$ characters match. The match might extend beyond $R$ (into unverified territory). Extend from $R$ forward by naive comparison. Update $Z[i]$ and move $R$ forward. Set $L = i$.
    

### Complexity Analysis

**Time: O(n)** $R$ is a monotonically non-decreasing integer bounded by $n$. Every character comparison either (a) increments $R$ (at most $n$ times total) or (b) finds a mismatch (at most $n$ times total, once per position). Total comparisons: O(n).

**Derivation:** Assign a "credit" to each character comparison. Comparisons that extend $R$ cost one credit each; since $R \leq n$, these total at most $n$. Comparisons that find a mismatch terminate the inner loop for position $i$ — at most one such comparison per position, for $n-1$ positions total. Grand total: $\leq 2n$ comparisons.

**Space: O(n)** for the Z-array. O(1) auxiliary (just $L$, $R$, and loop variables).

### Decision Tree

```
Does the problem involve:
├─ Finding pattern occurrences in text?
│   └─ Construct S = pattern + "$" + text
│      → Z[i] == len(pattern) at positions i > len(pattern) → MATCH
├─ "Prefix that is also a suffix"?
│   └─ Z[i] + i == n → position i starts a suffix that equals a prefix of length Z[i]
├─ Smallest period of a string?
│   └─ Find smallest p > 0 where Z[p] >= n - p
├─ Count how many times prefix S[0..k-1] appears in S?
│   └─ Count positions i where Z[i] >= k (plus the prefix itself at i=0)
└─ Longest substring that is both prefix and suffix (not equal to whole string)?
    └─ Max Z[i] where Z[i] + i == n and i > 0
```

## 4. Pseudocode

```
function BUILD_Z_ARRAY(S):
    n ← length(S)
    Z ← array of n zeros

    L ← 0   // Left boundary of the current Z-box
    R ← 0   // Right boundary (exclusive) of the current Z-box
    // Invariant: S[L..R-1] == S[0..R-L-1], R is maximal

    for i from 1 to n - 1:

        if i < R:
            // i is inside the Z-box [L, R)
            // Mirror position in the known prefix: i' = i - L
            // We know at least min(Z[i - L], R - i) characters match
            Z[i] ← min(Z[i - L], R - i)
            // Why min? If Z[i-L] < R-i, the match is confirmed within the box.
            // If Z[i-L] >= R-i, we can only guarantee R-i characters (box boundary);
            // the rest needs explicit checking below.

        // Extend naively from Z[i] (either 0 if i >= R, or the guaranteed floor if i < R)
        while i + Z[i] < n and S[Z[i]] == S[i + Z[i]]:
            Z[i] ← Z[i] + 1
            // Each iteration of this while loop advances R (when it runs)

        // Update the Z-box if we've extended beyond the current R
        if i + Z[i] > R:
            L ← i
            R ← i + Z[i]

    return Z


function Z_PATTERN_MATCH(text, pattern):
    separator ← "$"   // Must not appear in text or pattern
    S ← pattern + separator + text
    Z ← BUILD_Z_ARRAY(S)

    m ← length(pattern)
    matches ← []

    for i from m + 1 to length(S) - 1:
        if Z[i] == m:
            matches.append(i - m - 1)   // Convert back to text index

    return matches
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <algorithm>

// ─────────────────────────────────────────────────────────
// Core Z-array construction
// Time: O(n), Space: O(n)
// ─────────────────────────────────────────────────────────
std::vector<int> build_z_array(const std::string& s) {
    int n = (int)s.size();
    std::vector<int> z(n, 0);

    // Z[0] is conventionally 0; some define it as n but 0 is safer for applications
    int L = 0, R = 0;  // Z-box: s[L..R-1] == s[0..R-L-1]

    for (int i = 1; i < n; ++i) {
        if (i < R) {
            // Inside the Z-box: use the mirror value as a floor
            z[i] = std::min(z[i - L], R - i);
        }
        // Extend naively beyond the guaranteed floor
        while (i + z[i] < n && s[z[i]] == s[i + z[i]])
            ++z[i];

        // Update Z-box if we pushed R forward
        if (i + z[i] > R) {
            L = i;
            R = i + z[i];
        }
    }
    return z;
}

// ─────────────────────────────────────────────────────────
// Pattern matching: find all occurrences of pattern in text
// Returns 0-indexed positions in text
// Time: O(n + m), Space: O(n + m)
// ─────────────────────────────────────────────────────────
std::vector<int> z_pattern_match(const std::string& text,
                                  const std::string& pattern) {
    if (pattern.empty() || pattern.size() > text.size())
        return {};

    // Concatenate: pattern + sentinel + text
    // Sentinel must not appear in either string
    std::string s = pattern + "$" + text;
    std::vector<int> z = build_z_array(s);

    int m = (int)pattern.size();
    std::vector<int> matches;

    // Valid match positions start at index m+1 (past pattern and sentinel)
    for (int i = m + 1; i < (int)s.size(); ++i) {
        if (z[i] == m)
            matches.push_back(i - m - 1);  // Map back to text index
    }
    return matches;
}

// ─────────────────────────────────────────────────────────
// Smallest period of a string
// Period p: s[i] == s[i - p] for all i >= p
// Equivalently: Z[p] >= n - p (the suffix starting at p matches as a prefix)
// Returns the smallest p in [1, n]; returns n if no shorter period exists
// ─────────────────────────────────────────────────────────
int smallest_period(const std::string& s) {
    int n = (int)s.size();
    if (n <= 1) return n;

    std::vector<int> z = build_z_array(s);
    for (int p = 1; p < n; ++p) {
        // z[p] >= n - p means: the suffix at p matches the prefix for at least (n-p) chars
        // i.e., the string can tile itself with period p (possibly with a partial last tile)
        if (z[p] >= n - p)
            return p;
    }
    return n;  // No period shorter than n
}

// ─────────────────────────────────────────────────────────
// Longest proper border (prefix == suffix, not the whole string)
// A border at position i: Z[i] + i == n  →  suffix S[i..n-1] == prefix S[0..n-i-1]
// Returns the length of the longest such border (0 if none)
// ─────────────────────────────────────────────────────────
int longest_border(const std::string& s) {
    int n = (int)s.size();
    if (n <= 1) return 0;

    std::vector<int> z = build_z_array(s);
    int best = 0;
    for (int i = 1; i < n; ++i) {
        if (i + z[i] == n)        // Suffix starting at i matches a prefix of length z[i]
            best = std::max(best, z[i]);
    }
    return best;
}

// ─────────────────────────────────────────────────────────
// Count occurrences of each prefix S[0..k-1] in S
// prefix_count[k] = number of positions i (including i=0) where Z[i] >= k
// Useful for: "how many times does the prefix of length k appear in S?"
// ─────────────────────────────────────────────────────────
std::vector<int> prefix_occurrence_count(const std::string& s) {
    int n = (int)s.size();
    std::vector<int> z = build_z_array(s);
    std::vector<int> cnt(n + 1, 0);

    // i=0: the prefix itself (always contributes to all lengths 1..n)
    cnt[1]++;   // The prefix of length 1 at position 0 always exists
    // Actually, increment the bin for ALL prefix lengths at position 0:
    // Easier: for i >= 1, Z[i] tells us prefix[0..Z[i]-1] appears at position i
    for (int i = 1; i < n; ++i)
        if (z[i] > 0)
            cnt[z[i]]++;  // Prefix of length z[i] appears starting at i

    // For prefix of length k, it appears at i=0 PLUS however many i>0 have Z[i] >= k
    // Convert to suffix sum: cnt[k] = number of i > 0 with Z[i] == k (current)
    // Then prefix_count[k] = 1 + sum(cnt[j] for j >= k)
    // Compute suffix sum in-place:
    for (int k = n - 1; k >= 1; --k)
        cnt[k] += cnt[k + 1];
    // Now cnt[k] = number of i > 0 with Z[i] >= k
    // Add 1 for the prefix itself at position 0:
    for (int k = 1; k <= n; ++k)
        cnt[k] += 1;

    return cnt;  // cnt[k] = total occurrences of prefix of length k in s
}

// ─────────────────────────────────────────────────────────
// Minimal test
// ─────────────────────────────────────────────────────────
int main() {
    // Z-array
    std::string s = "aabxaab";
    auto z = build_z_array(s);
    // Expected: z = [0, 1, 0, 0, 3, 1, 0]
    // (Z[4]=3 because s[4..6]="aab" == s[0..2]="aab")
    for (int v : z) std::cout << v << " ";
    std::cout << "\n";

    // Pattern matching
    auto pos = z_pattern_match("aabxaab", "aab");
    // Expected: [0, 4]
    for (int p : pos) std::cout << p << " ";
    std::cout << "\n";

    // Smallest period
    std::cout << smallest_period("abababab") << "\n";  // Expected: 2
    std::cout << smallest_period("abcabc")   << "\n";  // Expected: 3
    std::cout << smallest_period("abcd")     << "\n";  // Expected: 4

    // Longest border
    std::cout << longest_border("abacaba") << "\n";  // Expected: 3 ("aba")
    std::cout << longest_border("aaaa")    << "\n";  // Expected: 3 ("aaa")

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import List


def build_z_array(s: str) -> List[int]:
    """
    Compute the Z-array of string s.

    Z[i] = length of the longest substring starting at s[i]
           that matches a prefix of s.
    Z[0] = 0 by convention (the whole string is excluded).

    Time:  O(n)
    Space: O(n)
    """
    n = len(s)
    z = [0] * n
    L, R = 0, 0  # Z-box: s[L:R] == s[0:R-L]

    for i in range(1, n):
        if i < R:
            # Inside the Z-box: mirror gives a guaranteed floor
            # z[i - L] is the Z-value at the mirror position
            # We can use it as long as it doesn't exceed the box boundary
            z[i] = min(z[i - L], R - i)

        # Extend naively from the guaranteed floor
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1

        # Update Z-box if we've extended past R
        if i + z[i] > R:
            L, R = i, i + z[i]

    return z


def z_pattern_match(text: str, pattern: str) -> List[int]:
    """
    Find all occurrences of pattern in text using the Z-algorithm.

    Returns list of 0-indexed start positions in text.

    Time:  O(n + m) where n = len(text), m = len(pattern)
    Space: O(n + m) for the concatenated string and Z-array

    The sentinel '$' must not appear in text or pattern.
    For general inputs, use a character known to be absent.
    """
    if not pattern or len(pattern) > len(text):
        return []

    m = len(pattern)
    # Concatenation trick: Z[i] == m exactly when pattern found at text[i - m - 1]
    combined = pattern + "$" + text
    z = build_z_array(combined)

    return [i - m - 1 for i in range(m + 1, len(combined)) if z[i] == m]


def smallest_period(s: str) -> int:
    """
    Find the smallest period p of s (1 <= p <= len(s)).

    Period p means s[i] == s[i % p] for all i.
    Equivalently: z[p] >= len(s) - p.

    Returns len(s) if no shorter period exists (aperiodic string).

    Time: O(n)
    """
    n = len(s)
    if n <= 1:
        return n
    z = build_z_array(s)
    for p in range(1, n):
        if z[p] >= n - p:
            return p
    return n


def longest_border(s: str) -> int:
    """
    Find the length of the longest proper border of s.

    A border is a string that is both a proper prefix and a proper suffix.
    Condition: i + z[i] == n  (suffix at i matches a prefix of length z[i])

    Example: "abacaba" → border "aba" (length 3)

    Time: O(n)
    """
    n = len(s)
    if n <= 1:
        return 0
    z = build_z_array(s)
    return max((z[i] for i in range(1, n) if i + z[i] == n), default=0)


def count_prefix_occurrences(s: str) -> List[int]:
    """
    Returns an array cnt where cnt[k] = number of times the
    prefix s[0:k] appears in s (as a substring).

    cnt[0] = 0 (empty prefix, undefined)
    cnt[k] >= 1 always (the prefix itself appears at position 0)

    Uses suffix-sum over Z-array bucket counts.
    Time: O(n)
    """
    n = len(s)
    z = build_z_array(s)
    cnt = [0] * (n + 1)

    for i in range(1, n):
        if z[i] > 0:
            cnt[z[i]] += 1  # prefix of length z[i] ends at position i+z[i]-1

    # Suffix sum: cnt[k] = number of i > 0 with z[i] >= k
    for k in range(n - 1, 0, -1):
        cnt[k] += cnt[k + 1]

    # Add 1 for the occurrence of the prefix at position 0 itself
    for k in range(1, n + 1):
        cnt[k] += 1

    return cnt


# ── Tests ──────────────────────────────────────────────────────────
if __name__ == "__main__":
    # Z-array correctness
    z = build_z_array("aabxaab")
    assert z == [0, 1, 0, 0, 3, 1, 0], f"Z-array wrong: {z}"

    z2 = build_z_array("aaaaa")
    assert z2 == [0, 4, 3, 2, 1], f"Z-array wrong: {z2}"

    # Pattern matching
    assert z_pattern_match("aabxaab", "aab")  == [0, 4]
    assert z_pattern_match("abcabcabc", "abc") == [0, 3, 6]
    assert z_pattern_match("aaaa", "aa")       == [0, 1, 2]
    assert z_pattern_match("abc", "xyz")        == []
    assert z_pattern_match("hello", "hello")    == [0]

    # Smallest period
    assert smallest_period("abababab") == 2
    assert smallest_period("abcabc")   == 3
    assert smallest_period("abcd")     == 4
    assert smallest_period("aaaa")     == 1

    # Longest border
    assert longest_border("abacaba") == 3   # "aba"
    assert longest_border("aaaa")    == 3   # "aaa"
    assert longest_border("abcd")    == 0   # no border

    # Prefix occurrence count
    cnt = count_prefix_occurrences("aabxaab")
    # prefix "a"   (k=1): appears at 0,1,4,5 → 4 times
    # prefix "aa"  (k=2): appears at 0,4 → 2 times
    # prefix "aab" (k=3): appears at 0,4 → 2 times
    assert cnt[1] == 4, f"cnt[1]={cnt[1]}"
    assert cnt[2] == 2, f"cnt[2]={cnt[2]}"
    assert cnt[3] == 2, f"cnt[3]={cnt[3]}"

    print("All tests passed.")
```

## 6. Visual Explanation

### Z-Array Construction Step by Step

```
String S: a  a  b  x  a  a  b
Index:    0  1  2  3  4  5  6

Build Z-array (Z[0] = 0 by convention):

i=1, [L=0, R=0]: i >= R (outside box) → extend naively
  S[0]='a' == S[1]='a' ✓ → z[1]++  →  z[1]=1
  S[1]='a' != S[2]='b' ✗ → stop
  z[1] = 1, update box: L=1, R=2

i=2, [L=1, R=2]: i >= R (outside box) → extend naively
  S[0]='a' != S[2]='b' ✗ → stop immediately
  z[2] = 0. No box update.

i=3, [L=1, R=2]: i >= R → extend naively
  S[0]='a' != S[3]='x' ✗ → stop
  z[3] = 0. No box update.

i=4, [L=1, R=2]: i >= R → extend naively
  S[0]='a' == S[4]='a' ✓ → z[4]++  →  z[4]=1
  S[1]='a' == S[5]='a' ✓ → z[4]++  →  z[4]=2
  S[2]='b' == S[6]='b' ✓ → z[4]++  →  z[4]=3
  S[3]='x' — out of bounds (i+z[4]=7=n) → stop
  z[4] = 3, update box: L=4, R=7

i=5, [L=4, R=7]: i < R → use mirror!
  Mirror position: i' = i - L = 5 - 4 = 1
  z[1] = 1, R - i = 7 - 5 = 2
  z[i'] < R - i: z[5] = z[1] = 1 (guaranteed, no extension needed)
  Attempt extension: S[1]='a' == S[6]='b'? NO → stop (z[5] stays 1)
  z[5] = 1. No box update (i + z[5] = 6 < R = 7).

i=6, [L=4, R=7]: i < R → use mirror!
  Mirror position: i' = 6 - 4 = 2
  z[2] = 0, R - i = 7 - 6 = 1
  z[i'] < R - i: z[6] = z[2] = 0 (guaranteed)
  Attempt extension: S[0]='a' == S[6]='b'? NO → stop
  z[6] = 0.

Final Z-array: [0, 1, 0, 0, 3, 1, 0]
                           ↑
               Z[4]=3: "aab" starting at index 4
                        matches prefix "aab" ✓
```

### Pattern Matching via Concatenation

```
Pattern P = "aab"  (m=3)
Text    T = "xaabaabc"  (n=8)

Concatenated S = "aab$xaabaabc"
Index:           0123456789...

Build Z-array of S:
Z = [0, 1, 0, 0, 0, 3, 1, 0, 3, 1, 0, 0]
                    ↑         ↑
                   i=5       i=8

Check positions i > m (= 3), i.e., i >= 4:
  i=5: Z[5] = 3 == m=3 → MATCH at text index 5 - 3 - 1 = 1
  i=8: Z[8] = 3 == m=3 → MATCH at text index 8 - 3 - 1 = 4

Note: Z[3]=0 (the "$" separator) — it can NEVER equal m=3.
The sentinel guarantees Z-values never bleed across the boundary.

Text:  x  a  a  b  a  a  b  c
Index: 0  1  2  3  4  5  6  7
              ↑           ↑
           match@1     match@4  ✓
```

### The Z-Box Reuse Principle

```
When we're inside the Z-box [L, R):

       0         L         i'  R-L       (positions in the confirmed prefix region)
S: [  prefix  ][  ...  ][  ][  ] ...
       ↕ known match ↕
       L         i         R            (positions in the Z-box in the original string)
S: ...[ Z-box: S[L..R-1] == S[0..R-L-1] ]...
                    ↑
                position i, with mirror i' = i - L

Since S[L..R-1] == S[0..R-L-1], we know:
  S[i..R-1] == S[i'..R-L-1]

So Z[i] is AT LEAST min(Z[i'], R-i):
  • If Z[i'] < R-i: the match at i' ends before the box edge.
    We're certain about EXACTLY Z[i'] chars at position i. No extension.
  • If Z[i'] >= R-i: we know at least R-i chars match at i.
    Beyond R is uncharted — must extend from there.

This is the ENTIRE algorithm. Everything else is just bookkeeping.
```

## 7. Common Variations & Extensions

### 7.1 Z-Algorithm ↔ KMP Failure Function Conversion

The Z-array and the KMP failure function (also called the "partial match" or "pi" array) encode equivalent information about a string's self-overlap structure. You can convert one to the other in O(n):

**Z → KMP failure function:** For each $i$ from $1$ to $n-1$, if $Z[i] > 0$, it means the prefix of length $Z[i]$ appears at position $i$. So for the last character of that match, at position $i + Z[i] - 1$, the failure function value is at least $Z[i]$ (take the maximum over all contributing $i$).

```python
def z_to_kmp_failure(z: list) -> list:
    n = len(z)
    fail = [0] * n
    for i in range(1, n):
        if z[i] > 0:
            # The prefix s[0..z[i]-1] ends at position i+z[i]-1
            fail[i + z[i] - 1] = max(fail[i + z[i] - 1], z[i])
    # Propagate: failure function encodes LONGEST border, not just z-derived values
    for i in range(1, n):
        fail[i] = max(fail[i], fail[i-1] - 1 if fail[i-1] > 0 else 0)
    return fail
```

The reverse (KMP → Z) is similarly O(n). This means knowing either one fully determines the other — they're two views of the same structure.

### 7.2 Counting Palindromic Substrings with Z

After reducing a palindrome problem to a string self-match problem (e.g., using Eertree or Manacher's algorithm), Z-algorithm can verify candidate palindrome centers. Alternatively, for checking if a string is a rotation of another: `s1` is a rotation of `s2` iff `s1` appears in `s2 + s2` — a direct Z-array application. Related: [[19.Two pointers on strings — palindrome, matching]].

### 7.3 String Compression via Z-Array (Smallest Period)

The smallest period $p$ of a string $s$ (where $Z[p] \geq n - p$) gives the shortest string $r$ such that $s$ is a prefix of $r^k$ (infinite repetition of $r$). This is the basis of the **string compression** problem: "find the shortest string $r$ such that $s = r^k$ for some integer $k$" — which requires additionally checking that $p$ divides $n$.

```python
def is_exact_repetition(s: str) -> tuple[bool, str]:
    """Returns (True, shortest_unit) if s = unit^k for some k >= 2, else (False, s)."""
    n = len(s)
    p = smallest_period(s)
    if n % p == 0 and p < n:
        return True, s[:p]
    return False, s
```

### 7.4 Suffix Array Construction via Z-Algorithm

The Z-algorithm appears inside some O(n log n) suffix array construction algorithms (SA-IS and DC3/skew use different approaches, but simpler O(n log² n) constructions use repeated doubling with Z-style comparisons). Understanding Z-array structure is a prerequisite for reasoning about [[30.Suffix array — construction and LCP array]], particularly the LCP array computation step.

## 9. CP Contest Application

### Typical Problem Structures

**1. "Count occurrences / find all positions" (Codeforces Div 2 B/C, Div 1 A/B):** Standard concatenation + Z-array. The challenge is usually in recognising that the problem _is_ a pattern matching problem underneath some disguise (e.g., rotations, character substitutions, or matching against a reversed string).

**2. "Smallest period / string compression" (Div 2 C/D):** `smallest_period(s)` returns the answer. The two-step check (period + divisibility) is a frequent source of wrong answers. Period $p$ exists (possibly non-exact) iff `Z[p] >= n - p`. Exact tiling (s = unit^k) additionally requires `n % p == 0`.

**3. "Is T a rotation of S?" (Div 2 B):** Build `s = T + "$" + S + S`, check if `Z[i] == len(T)` for any `i > len(T)`. O(n) solution to what many contestants solve with O(n²) string rotation comparison.

**4. "Longest border" (Div 1 B/C):** Appears in problems about string "borders" or "autocorrelation" — find the longest string that is both a prefix and suffix. `longest_border(s)` is the answer; the condition `i + Z[i] == n` is the key.

### Time Limit Considerations

The Z-algorithm is uniformly O(n). For $n = 10^6$, it runs in well under 100ms in C++. The concatenation approach adds $n + m + 1$ total characters; for $n, m \leq 10^6$ you stay within memory. No special optimisation is needed in practice — the algorithm is cache-friendly (sequential array accesses) and has minimal branching.

**Anti-hack note:** Unlike [[27.Rabin-Karp — rolling hash for pattern matching]], the Z-algorithm has no false positives and no hash collision vulnerability. It gives exact answers unconditionally. For competitive programming, when the problem has adversarial string inputs and requires exact matching, Z-algorithm (or KMP) is strictly preferable to a single-hash Rabin-Karp.

### Z vs. KMP — When to Choose Which

|Situation|Prefer|
|---|---|
|Quick implementation from memory|Z-algorithm (simpler invariant)|
|Need failure function for other purposes (e.g., counting borders of all prefixes)|KMP|
|Online matching (pattern fixed, text streams in)|KMP (processes text left-to-right without storing it)|
|Offline matching (full text available)|Either; Z-array is arguably cleaner|
|Multi-pattern matching|Neither — use [[27.Rabin-Karp — rolling hash for pattern matching]] or Aho-Corasick|
|Need the smallest period|Z-algorithm (direct)|
