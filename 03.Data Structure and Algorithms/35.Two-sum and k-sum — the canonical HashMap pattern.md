## 1. Intuition First

### The Core Idea

You are handed a list of numbers and asked: _"Do any two of these add up to a target T?"_

The naive approach scans every pair — for each element `a[i]`, scan all elements after it and check if `a[j] == T - a[i]`. That's O(n²). Fine for n = 100. Catastrophic for n = 10⁶.

Here is the insight that changes everything: **the complement is determined the moment you read an element.**

If you're standing at element `x`, you don't need to _search_ for `T - x`. You need to _have already seen_ `T - x`, or _remember x so a future element can find it_. This is the difference between searching and remembering.

A HashMap transforms the second pass into a lookup. You iterate once, and at each element `x`, you ask: "Is `T - x` in my HashMap?" If yes — done. If no — insert `x` into the HashMap and continue. The entire algorithm lives in a single linear pass.

**The "Aha" Moment:** Every two-sum-like problem reduces to: _"For each element, what complement am I looking for, and have I stored the information needed to verify it?"_ Once you phrase the problem this way, HashMap is the natural tool because it answers set-membership in O(1).

### Why This Exists

Sorted arrays let you use [[16.Opposite-end two pointers — sorted array problems]] to solve two-sum in O(n) — but only after paying O(n log n) to sort. HashMap gives you O(n) time with O(n) space **without sorting**, and crucially, it **preserves index information**, which sorting destroys. Problems that ask for _indices_ (LeetCode 1) are unsolvable with the two-pointer approach unless you sort index-value pairs — messy and slower.

For k-sum with k ≥ 3, the pattern generalises: reduce k-sum to (k−1)-sum recursively, using sorting + two pointers for the innermost two-sum layer. HashMap handles two-sum; sorting + two-pointer handles the rest. Understanding _why_ each tool is chosen at each layer is the real lesson here.

### The "Aha" Moment

> _"I don't need to find the pair. I only need to find one element of the pair — and I already know what the other one must be."_

The HashMap stores everything you've seen so far. The complement check is O(1). The problem is solved.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Almost every contest has one. Two-sum is the warm-up, but the real test is recognising the disguised form:

- _"Count pairs with difference k"_ → same pattern, complement is `x + k` or `x - k`
- _"Count pairs with product k"_ → same pattern, complement is `k / x` (watch for division by zero)
- _"Find two elements where one is twice the other"_ → complement is `2x` or `x/2`
- _"Subarray sum equals k"_ → this is [[24.Subarray sum equals k — prefix sum + HashMap]] — prefix sums turn it into two-sum on prefix values

**Pattern signal:**

```
"Find two/three/k elements that satisfy a pairwise condition on their values"
→ Think HashMap (k=2) or sort + recursion + two-pointer (k≥3)
```

**Common traps:**

1. **Same element used twice.** LeetCode 1 says "two different indices" — a HashMap that stores values (not indices) will incorrectly pair `x` with itself if `T = 2x`. Fix: store index, not just presence.
2. **Duplicate elements in k-sum.** In 3Sum (LC 15), after sorting, you must skip duplicate values of the outer loop pointer and the two inner pointers after a valid find — otherwise you emit duplicate triplets.
3. **HashMap for k=2 is O(n) but k-sum via full recursion without pruning is O(nᵏ⁻¹).** Always reduce to 2Sum at the innermost layer and use two pointers, not another HashMap, at that level.
4. **Overflow.** For sum problems with large values in C++, use `long long` before adding.

### Machine Learning / AI

**Embedding lookup is two-sum at scale.** When a transformer model looks up a token embedding, it performs `embedding_table[token_id]` — this is O(1) HashMap access on a table indexed by token id. The entire vocabulary lookup layer in `nn.Embedding` (PyTorch) is a HashMap at the hardware level.

**Feature crossing in recommendation systems.** Given user features and item features, systems like Google's Wide & Deep and Meta's DLRM compute pairwise interactions by hashing feature pairs: `hash(feature_a, feature_b)` → embedding index. This is two-sum's generalisation to a feature-space lookup problem. The "complement" is a co-occurring feature, and the HashMap is a hash table of size 2³² or larger.

**Deduplication in data pipelines.** Before training, datasets must be deduplicated. For exact deduplication, a HashSet over content hashes is the standard approach — [[36.HashMap for O(1) deduplication — ML pipeline application]]. For near-deduplication, [[38.Locality-sensitive hashing (LSH) — approximate nearest neighbour]] generalises this.

**Why understanding this makes you a better ML engineer:** When you understand that `dict` lookups cost amortised O(1) but have real constant-factor overhead (hashing + potential collision resolution), you make better choices: avoid rebuilding large dicts inside training loops, prefer pre-built lookup tables for static mappings, and understand why `torch.nn.Embedding` uses index-based lookup rather than a dense linear layer for vocabulary sizes above ~50k.

## 3. Algorithm / Pattern

### Two-Sum (HashMap, O(n))

1. Initialise an empty HashMap `seen: value → index`.
2. For each element `x` at index `i`: a. Compute complement `c = target - x`. b. If `c` is in `seen` and `seen[c] ≠ i` → return `[seen[c], i]`. c. Otherwise, store `seen[x] = i`.
3. Return empty (no solution).

**Why step 2b:** Prevents using the same element at the same index twice. Storing index (not just presence) makes this check free.

### Two-Sum Variants Decision Tree

```
Is the array sorted?
├── Yes → Two-pointer O(n), no extra space (but loses index info)
└── No  → HashMap O(n) time, O(n) space

Do you need indices?
├── Yes → HashMap only (two-pointer destroys index order)
└── No  → Either; two-pointer preferred if sorted

Do duplicates exist and result must be unique pairs?
└── Sort first, skip duplicates after finding valid pair
```

### k-Sum General Pattern

For k ≥ 3, sort the array once (O(n log n)), then:

- Outer loop: fix elements `a[0]` ... `a[k-3]`, reducing target by each fixed element
- Recurse down to **2Sum** at the innermost layer, solved with two pointers on the sorted suffix

**Why two pointers at the base, not HashMap?** At the 2Sum layer inside k-Sum, the array is already sorted and you don't need indices — just existence. Two pointers are O(n) with O(1) space and trivially handle duplicate-skipping. Using a HashMap here adds O(n) space per recursion level for no benefit.

### Complexity

|Problem|Time|Space|
|---|---|---|
|Two-Sum (HashMap)|O(n)|O(n)|
|Two-Sum (sorted array, two pointers)|O(n) (after sort)|O(1)|
|3Sum|O(n²)|O(1) (in-place, excluding output)|
|4Sum|O(n³)|O(1) (in-place, excluding output)|
|k-Sum|O(nᵏ⁻¹)|O(k) recursion stack|

**Derivation for 3Sum:** Outer loop runs n times. Inner two-pointer scan runs O(n) per outer iteration. Total: O(n²). The sort is O(n log n) which is dominated.

**Why kSum is O(nᵏ⁻¹) and not O(nᵏ):** Each recursion reduces n by 1 (the fixed element) and reduces k by 1, bottoming out at 2Sum which is O(n). The recurrence is T(n, k) = n · T(n−1, k−1), T(n, 2) = O(n), which solves to O(nᵏ⁻¹).

## 4. Pseudocode

```
// ─── TWO-SUM ───────────────────────────────────────────────────────────────
function twoSum(nums, target):
    seen ← empty HashMap            // maps value → index

    for i from 0 to len(nums) - 1:
        complement ← target - nums[i]

        // Check if we've seen the complement before
        if complement in seen:
            return [seen[complement], i]   // found: return both indices

        // Haven't found it yet — record this element for future lookups
        seen[nums[i]] ← i

    return []   // no valid pair exists


// ─── K-SUM (general, returns all unique k-tuples) ──────────────────────────
function kSum(nums, target, k):
    sort(nums)                      // O(n log n), enables duplicate skipping
    return kSumHelper(nums, target, k, 0)

function kSumHelper(nums, target, k, start):
    result ← []

    // Base case: reduce to 2Sum with two pointers
    if k == 2:
        left ← start
        right ← len(nums) - 1

        while left < right:
            s ← nums[left] + nums[right]

            if s == target:
                result.append([nums[left], nums[right]])
                // Skip duplicates on both sides
                while left < right and nums[left] == nums[left + 1]:  left++
                while left < right and nums[right] == nums[right - 1]: right--
                left++
                right--

            else if s < target: left++
            else:               right--

        return result

    // Recursive case: fix one element, reduce to (k-1)-Sum
    for i from start to len(nums) - k:
        // Pruning 1: skip duplicate values at this level
        if i > start and nums[i] == nums[i - 1]:
            continue

        // Pruning 2: impossible if smallest k elements exceed target
        if nums[i] * k > target: break

        // Pruning 3: impossible if largest k elements are less than target
        if nums[i + k - 1] * k < target: continue

        // Fix nums[i], recurse on remaining
        subResults ← kSumHelper(nums, target - nums[i], k - 1, i + 1)
        for each sub in subResults:
            result.append([nums[i]] + sub)

    return result
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <algorithm>
#include <unordered_map>
#include <vector>
#include <numeric>

// ─── TWO-SUM ─────────────────────────────────────────────────────────────────
// Returns the indices of two numbers that add up to target.
// Exactly one solution guaranteed (per problem statement).
// Time: O(n)   Space: O(n)
std::vector<int> twoSum(const std::vector<int>& nums, int target) {
    std::unordered_map<int, int> seen; // value → index
    seen.reserve(nums.size());         // avoid rehashing

    for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
        int complement = target - nums[i];
        if (auto it = seen.find(complement); it != seen.end()) {
            return {it->second, i};
        }
        seen[nums[i]] = i;
    }
    return {}; // unreachable if exactly one solution guaranteed
}


// ─── THREE-SUM ────────────────────────────────────────────────────────────────
// Returns all unique triplets [a, b, c] such that a + b + c == 0.
// Time: O(n²)   Space: O(1) auxiliary (output not counted)
std::vector<std::vector<int>> threeSum(std::vector<int>& nums) {
    std::sort(nums.begin(), nums.end());
    std::vector<std::vector<int>> result;
    const int n = static_cast<int>(nums.size());

    for (int i = 0; i < n - 2; ++i) {
        // Skip duplicate values for the fixed element
        if (i > 0 && nums[i] == nums[i - 1]) continue;
        // Pruning: smallest possible triplet sum is already too large
        if (nums[i] + nums[i + 1] + nums[i + 2] > 0) break;
        // Pruning: largest possible triplet sum is still too small
        if (nums[i] + nums[n - 2] + nums[n - 1] < 0) continue;

        int left = i + 1, right = n - 1;
        while (left < right) {
            int sum = nums[i] + nums[left] + nums[right];
            if (sum == 0) {
                result.push_back({nums[i], nums[left], nums[right]});
                // Skip duplicates on both ends
                while (left < right && nums[left]  == nums[left  + 1]) ++left;
                while (left < right && nums[right] == nums[right - 1]) --right;
                ++left; --right;
            } else if (sum < 0) {
                ++left;
            } else {
                --right;
            }
        }
    }
    return result;
}


// ─── K-SUM (general) ─────────────────────────────────────────────────────────
// Returns all unique k-tuples that sum to target.
// Time: O(n^(k-1))   Space: O(k) recursion stack
namespace detail {
    void kSumHelper(const std::vector<int>& nums, long long target, int k,
                    int start, std::vector<int>& current,
                    std::vector<std::vector<int>>& result) {
        const int n = static_cast<int>(nums.size());

        if (k == 2) {
            int left = start, right = n - 1;
            while (left < right) {
                long long s = static_cast<long long>(nums[left]) + nums[right];
                if (s == target) {
                    result.push_back(current);
                    result.back().push_back(nums[left]);
                    result.back().push_back(nums[right]);
                    while (left < right && nums[left]  == nums[left  + 1]) ++left;
                    while (left < right && nums[right] == nums[right - 1]) --right;
                    ++left; --right;
                } else if (s < target) {
                    ++left;
                } else {
                    --right;
                }
            }
            return;
        }

        for (int i = start; i <= n - k; ++i) {
            if (i > start && nums[i] == nums[i - 1]) continue; // skip dups
            // Pruning bounds
            if (static_cast<long long>(nums[i]) * k > target) break;
            if (static_cast<long long>(nums[i + k - 1]) * k < target) continue;

            current.push_back(nums[i]);
            kSumHelper(nums, target - nums[i], k - 1, i + 1, current, result);
            current.pop_back();
        }
    }
}

std::vector<std::vector<int>> kSum(std::vector<int>& nums, long long target, int k) {
    std::sort(nums.begin(), nums.end());
    std::vector<std::vector<int>> result;
    std::vector<int> current;
    detail::kSumHelper(nums, target, k, 0, current, result);
    return result;
}


// ─── MINIMAL TEST ─────────────────────────────────────────────────────────────
#include <cassert>
#include <iostream>

int main() {
    // Two-sum
    auto r1 = twoSum({2, 7, 11, 15}, 9);
    assert((r1 == std::vector<int>{0, 1}));

    // Three-sum
    std::vector<int> v2 = {-1, 0, 1, 2, -1, -4};
    auto r2 = threeSum(v2);
    assert(r2.size() == 2); // {-1,-1,2} and {-1,0,1}

    // Four-sum via kSum
    std::vector<int> v3 = {1, 0, -1, 0, -2, 2};
    auto r3 = kSum(v3, 0, 4);
    assert(r3.size() == 3);

    std::cout << "All tests passed.\n";
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations
from typing import Optional


# ─── TWO-SUM ──────────────────────────────────────────────────────────────────
def two_sum(nums: list[int], target: int) -> list[int]:
    """
    Return indices [i, j] such that nums[i] + nums[j] == target.

    Exactly one solution is guaranteed (LeetCode 1 contract).

    Time:  O(n)
    Space: O(n) — for the complement table
    """
    seen: dict[int, int] = {}   # value → index

    for i, x in enumerate(nums):
        complement = target - x
        if complement in seen:
            return [seen[complement], i]
        seen[x] = i

    return []   # guaranteed not reached if one solution exists


# ─── THREE-SUM ────────────────────────────────────────────────────────────────
def three_sum(nums: list[int]) -> list[list[int]]:
    """
    Return all unique triplets [a, b, c] with a + b + c == 0.

    Time:  O(n²)
    Space: O(1) auxiliary (output excluded)
    """
    nums.sort()
    result: list[list[int]] = []
    n = len(nums)

    for i in range(n - 2):
        # Skip duplicate outer values
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        # Pruning: minimum possible sum is already too large
        if nums[i] + nums[i + 1] + nums[i + 2] > 0:
            break
        # Pruning: maximum possible sum is still too small
        if nums[i] + nums[-2] + nums[-1] < 0:
            continue

        left, right = i + 1, n - 1
        while left < right:
            s = nums[i] + nums[left] + nums[right]
            if s == 0:
                result.append([nums[i], nums[left], nums[right]])
                # Skip duplicates on both ends
                while left < right and nums[left]  == nums[left  + 1]: left  += 1
                while left < right and nums[right] == nums[right - 1]: right -= 1
                left += 1
                right -= 1
            elif s < 0:
                left += 1
            else:
                right -= 1

    return result


# ─── K-SUM (general, recursive) ───────────────────────────────────────────────
def k_sum(nums: list[int], target: int, k: int) -> list[list[int]]:
    """
    Return all unique k-tuples from nums that sum to target.

    Time:  O(n^(k-1))
    Space: O(k) recursion depth
    """
    nums.sort()
    return _k_sum_helper(nums, target, k, 0)


def _k_sum_helper(
    nums: list[int], target: int, k: int, start: int
) -> list[list[int]]:
    result: list[list[int]] = []
    n = len(nums)

    # Base case: two-pointer two-sum on the sorted subarray
    if k == 2:
        left, right = start, n - 1
        while left < right:
            s = nums[left] + nums[right]
            if s == target:
                result.append([nums[left], nums[right]])
                while left < right and nums[left]  == nums[left  + 1]: left  += 1
                while left < right and nums[right] == nums[right - 1]: right -= 1
                left += 1
                right -= 1
            elif s < target:
                left += 1
            else:
                right -= 1
        return result

    # Recursive case: fix one element, solve (k-1)-sum on remainder
    for i in range(start, n - k + 1):
        # Skip duplicate values at this recursion level
        if i > start and nums[i] == nums[i - 1]:
            continue
        # Pruning: smallest k values from here already exceed target
        if nums[i] * k > target:
            break
        # Pruning: largest k values from here still fall short of target
        if nums[i + k - 1] * k < target:
            continue

        for sub in _k_sum_helper(nums, target - nums[i], k - 1, i + 1):
            result.append([nums[i]] + sub)

    return result


# ─── TESTS ────────────────────────────────────────────────────────────────────
if __name__ == "__main__":
    # Two-sum
    assert two_sum([2, 7, 11, 15], 9)     == [0, 1]
    assert two_sum([3, 2, 4], 6)          == [1, 2]
    assert two_sum([3, 3], 6)             == [0, 1]

    # Three-sum
    r = three_sum([-1, 0, 1, 2, -1, -4])
    assert sorted(map(sorted, r)) == [[-1, -1, 2], [-1, 0, 1]]

    r = three_sum([0, 0, 0])
    assert r == [[0, 0, 0]]

    # Four-sum via k_sum
    r = k_sum([1, 0, -1, 0, -2, 2], 0, 4)
    assert len(r) == 3

    # k=2 should behave like two-sum (returns values, not indices)
    r = k_sum([1, 2, 3, 4], 5, 2)
    assert sorted(map(sorted, r)) == [[1, 4], [2, 3]]

    print("All tests passed.")
```

## 6. Visual Explanation

### Two-Sum: Single-Pass HashMap Trace

```
nums = [2, 7, 11, 15],  target = 9

Step 1: i=0, x=2, complement=7
        seen = {}  →  7 not in seen
        Insert: seen = {2: 0}

Step 2: i=1, x=7, complement=2
        seen = {2: 0}  →  2 IS in seen!
        Return [seen[2], 1] = [0, 1]  ✓

           ┌───────────┐
  seen:    │  2 → idx 0│
           └───────────┘
                  ↑
              stored here   ←──── complement 2 found here
  array: [ 2 ,  7 , 11, 15]
          i=0  i=1
                └── x=7, looking for T-x = 9-7 = 2
```

### 3Sum: Outer Fix + Two-Pointer Inner Scan

```
nums = [-4, -1, -1, 0, 1, 2],  target = 0

Outer i=0  (nums[i]=-4):
  need two_sum on [-1,-1,0,1,2] that sum to 4
  left=1(-1), right=5(2)  →  sum=-1+2=1 < 4  →  left++
  left=2(-1), right=5(2)  →  sum=-1+2=1 < 4  →  left++
  left=3(0),  right=5(2)  →  sum=0+2=2  < 4  →  left++
  left=4(1),  right=5(2)  →  sum=1+2=3  < 4  →  left++
  left=5 ≥ right=5  →  stop. No triplet with -4.

Outer i=1  (nums[i]=-1):
  need two_sum on [-1, 0, 1, 2] that sum to 1
  left=2(-1), right=5(2)  →  sum=-1+2=1 == 1  ✓  emit [-1,-1,2]
    skip dups: nums[left]=nums[left+1]? -1=0? No → left=3, right=4
  left=3(0),  right=4(1)  →  sum=0+1=1  == 1  ✓  emit [-1,0,1]
    left=4 ≥ right=4  →  stop.

Outer i=2  (nums[i]=-1):
  i>0 and nums[2]==nums[1] (-1==-1) → SKIP (duplicate outer)

Outer i=3  (nums[i]=0):
  minimum sum = 0+1+2=3 > 0  →  BREAK (pruning)

Result: [[-1,-1,2], [-1,0,1]]
```

### The General Pattern: Reduce k→2 Every Time

```
k=4:  Fix a[i]  →  k=3 subproblem  (target - a[i])
       ↓
k=3:  Fix a[j]  →  k=2 subproblem  (target - a[i] - a[j])
       ↓
k=2:  Two-pointer scan on sorted suffix  →  O(n)
       ↓
      emit [a[i], a[j], left, right]

Total work:  n × n × O(n) = O(n^(k-1)) = O(n³) for 4Sum
```

## 7. Common Variations & Extensions

### 7.1 Two-Sum II — Sorted Input

When the input is already sorted (LeetCode 167), skip the HashMap entirely and use [[16.Opposite-end two pointers — sorted array problems]]. O(n) time, O(1) space. Use this whenever sorting is either given or acceptable and you don't need the original indices.

### 7.2 Two-Sum with a Data Structure (LeetCode 170)

You need to support `add(number)` and `find(value)` operations. `add` inserts into a HashMap (value → count); `find(target)` iterates all stored values `x` and checks if `target - x` is also stored (with care when `x == target - x` to ensure count ≥ 2). HashMap beats a sorted list here because `add` is O(1) amortised vs O(log n) for a BST.

### 7.3 Pair Difference Equals K

Instead of `a + b == target`, you want `|a - b| == k`. The complement becomes `x + k` or `x - k`. Same HashMap pattern, two lookups per element. Watch: if `k == 0`, you need to count frequency (find any element appearing twice), so you need a frequency map, not just a set. This connects to [[21.HashMap frequency counting — arbitrary keys]].

### 7.4 Subarray Sum Equals K

This is the 2D version in disguise. Build prefix sums as you go; the question "does prefix[j] - prefix[i] == k" is exactly two-sum on prefix values. See [[24.Subarray sum equals k — prefix sum + HashMap]] for full treatment. The HashMap maps `prefix_sum → count`, not `value → index`, because multiple subarrays can share the same prefix.

### 7.5 4Sum Count (LeetCode 454)

Given four arrays A, B, C, D: count tuples (i,j,k,l) where A[i]+B[j]+C[k]+D[l] == 0. This is _not_ the same as 4Sum on one array. The trick: build a HashMap of all A[i]+B[j] sums (O(n²) entries), then for each C[k]+D[l], look up `-(C[k]+D[l])` in the map. Time: O(n²), Space: O(n²). A direct 4Sum approach would be O(n³).

## 9. CP Contest Application

### Typical Contest Structure

Two-sum in contests almost always appears in a **disguised** form, combined with another technique:

- **Two-sum + prefix sum:** "Count subarrays with sum divisible by k" → prefix sum mod k + HashMap (count of remainders). Appears frequently in Codeforces Div. 2 C/D problems.
- **Two-sum + sorting + binary search:** "Closest pair of points with sum ≤ target" → sort, then for each element do `upper_bound(target - x)` to find the best partner. O(n log n).
- **Two-sum on a stream:** "At each step, answer whether any two seen elements sum to target" → maintain a HashMap; each insert is O(1) and a query is also O(1). Appears in online/interactive problems.

### Time Limits

- Pure 2Sum: n ≤ 10⁶ with time limit 1s → HashMap is the only viable approach. Two-pointer requires pre-sorting and loses indices.
- 3Sum: n ≤ 3000 → O(n²) is fine (9 × 10⁶ ops, ~0.1s). n ≤ 10⁵ → need a smarter approach or the problem is not vanilla 3Sum.
- 4Sum: n ≤ 500 → O(n³) is fine. n > 1000 → requires meet-in-the-middle (see below).

### Meet-in-the-Middle for Large k

For n ≤ 10⁶ and k = 4 (e.g., 4Sum Count style), split into two pairs. Build a HashMap of all pair sums from one half (O(n²)), query complements from the other half. Total: O(n²) time, O(n²) space. This is the HashMap two-sum idea applied at the _pair_ level instead of the _element_ level — the same abstraction, one level higher.

### C++ Optimization Notes for CP

```cpp
// 1. Reserve capacity to avoid rehashing
unordered_map<int, int> seen;
seen.reserve(1 << 17);    // next power of 2 above expected n
seen.max_load_factor(0.25);  // fewer collisions, more memory

// 2. Custom hash to defeat anti-hash tests (Codeforces)
struct custom_hash {
    static uint64_t splitmix64(uint64_t x) {
        x += 0x9e3779b97f4a7c15;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9;
        x = (x ^ (x >> 27)) * 0x94d049bb133111eb;
        return x ^ (x >> 31);
    }
    size_t operator()(uint64_t x) const {
        static const uint64_t FIXED_RANDOM =
            std::chrono::steady_clock::now().time_since_epoch().count();
        return splitmix64(x + FIXED_RANDOM);
    }
};
unordered_map<int, int, custom_hash> safe_map;
// Use this when TLE or WA on Codeforces with unordered_map
```

The custom hash prevents adversarial inputs that force O(n) per lookup in the default hash — a known attack on Codeforces problems that accept `unordered_map` solutions.
