## 1. Intuition First

### The Core Idea

In [[61.Capacity and allocation problems via binary search on answer]] the answer was always an integer — the maximum group sum, the ship capacity, the number of days. The binary search terminated naturally when `lo == hi`, two integers colliding.

Now imagine the answer is a real number. You are filling a circle with water and need to find the exact water level at which the filled area equals half the circle's total area. Or you are tuning a learning rate and need the exact value where validation loss crosses a threshold. The answer lives in ℝ, not ℤ.

Integer binary search terminates in O(log(hi − lo)) steps because each step shrinks the integer interval by at least 1. Real-valued binary search has no such natural termination — the interval can always be halved again. So we need a **stopping criterion**: either a fixed number of iterations or an epsilon tolerance.

The geometry is identical to integer binary search. You have a monotone predicate `f(x)` that is `false` for all `x < x*` and `true` for all `x ≥ x*`, where `x*` is the real-valued answer. You maintain a bracket `[lo, hi]` that always contains `x*` and shrink it by evaluating `f(mid)` at the midpoint. After `n` iterations the interval width is `(hi − lo) / 2ⁿ`. For 64-bit float precision (≈ 15 significant decimal digits), 50–100 iterations suffice for any practical problem.

**The structural invariant never changes:** at every step, `lo` is a value that is _too small_ (predicate false) and `hi` is a value that is _valid_ (predicate true). The answer is always in `[lo, hi]`.

### Why This Exists

Real-valued problems that admit a monotone feasibility check are extremely common in numerical optimisation, physics simulation, and ML. The alternatives are:

- **Newton's method:** O(log log(1/ε)) convergence (quadratic) but requires the derivative and can diverge if started outside a basin of attraction.
- **Golden section search:** O(log(1/ε)) like bisection, but for unimodal _functions_ (not predicates). Needs no derivative but assumes unimodality.
- **Gradient descent on a 1D function:** Same O(log(1/ε)) rate with a fixed step, but sensitive to learning rate choice.

Bisection (fractional binary search) is the **robust fallback**: guaranteed O(log(1/ε)) convergence for any continuous monotone predicate, no derivative needed, no divergence risk. Its simplicity is its power — you can implement it correctly in 10 lines under contest pressure and deploy it confidently in production numerical code.

### The "Aha" Moment

> **The stopping criterion replaces the integer collision. Everything else is identical.**

Integer: stop when `lo == hi` (two integers, forced to meet). Real: stop when `hi − lo < ε` (interval width below tolerance) **or** after a fixed number of iterations (100 is always enough for double precision).

Once you internalise this, every real-valued "find the threshold" problem collapses to the same three-line template you already know.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Fractional binary search appears in CP whenever the answer is a real number and the feasibility check is decidable:

- **Geometry problems:** Find the radius of the largest circle fitting inside a polygon. Find the water level in an irregular 3D vessel. Find the angle at which a cut yields equal areas.
- **Physics simulation:** Find the time at which two moving objects collide or reach minimum distance.
- **Rate optimisation:** "What is the maximum average value achievable by selecting exactly k elements with total weight ≤ W?" — the answer is a real number, feasibility check is a greedy.
- **Parametric search problems:** A classical technique where a continuous parameter is binary-searched and the feasibility check runs a combinatorial algorithm.

**Pattern signal:**

> When you see: _"find the maximum/minimum real value such that [geometric/physical condition holds]"_ → think **fractional binary search with 100 iterations**.

A particularly clean CP sub-pattern: **binary search on a ratio**. "Maximise the average" problems (e.g., find a subarray of length ≥ k maximising the average) are solved by binary searching on the answer `x` and checking whether any valid subarray has average ≥ x, which is equivalent to checking whether any subarray of `arr[i] − x` has non-negative sum — a linear feasibility check.

**Common trap:** Using `while (lo < hi)` with integer semantics for a float loop. This either runs forever (floats never exactly equal due to rounding) or terminates after one iteration (if `lo` and `hi` start as equal floats). Always use either:

1. `for (int iter = 0; iter < 100; ++iter)` — fixed iterations.
2. `while (hi - lo > 1e-9)` — epsilon termination.

Never `while (lo < hi)` for floats.

A second trap: computing `mid = (lo + hi) / 2` can lose precision when `lo` and `hi` are both very large (catastrophic cancellation). Prefer `mid = lo + (hi - lo) / 2`.

---

### Machine Learning / AI

**Exact appearance in ML systems:**

_1. Learning rate range test (Leslie Smith, 2017):_ The learning rate range test — foundational to the 1cycle policy used in fast.ai — is a bisection search. You increase the learning rate monotonically and record when loss starts diverging. The threshold learning rate `lr*` is the real-valued answer; the predicate `loss_stable(lr)` is the feasibility check. This is fractional binary search implemented informally as a sweep, but the structure is identical.

_2. Calibration threshold search in classification:_ A classifier outputs probabilities. You need the decision threshold `t*` minimising a composite metric (e.g., `F1 ≥ 0.85 AND precision ≥ 0.90`). If `F1(t)` is monotone in `t` (which it approximately is), bisect on `t ∈ [0, 1]`. This replaces a sweep over 1000 threshold values with 50 bisection steps — a 20× speedup.

_3. Optimal temperature scaling (Guo et al., 2017 — "On Calibration of Modern Neural Networks"):_ Calibration post-processing searches for the temperature parameter `T*` such that the calibrated model's expected calibration error (ECE) is minimised. Since ECE is monotone in `T` (roughly), `scipy.optimize.bisect` or `brentq` is used internally. This is fractional binary search packaged as a scipy call.

_4. SVM regularisation parameter search:_ For SVMs with linear kernels, the decision boundary quality is monotone in the regularisation parameter `C` up to a point. Finding the minimum `C` such that validation accuracy ≥ threshold is a bisection on `[C_min, C_max]` with a train-evaluate loop as the feasibility check. Much faster than grid search when the metric is monotone.

_5. Quantile regression / pinball loss threshold:_ In quantile regression, finding the output level `y*` at a given quantile is a real-valued search — bisect on `y*`, feasibility check is `P(Y ≤ y*) ≥ q`.

**Framework reference:**

- `scipy.optimize.bisect(f, a, b, xtol=1e-9)` — exact implementation of fractional binary search for root finding (f(x) = 0 ↔ predicate changes sign).
- `scipy.optimize.brentq` — Brent's method, which combines bisection with secant and inverse quadratic interpolation for superlinear convergence. Bisection is its fallback guarantor of convergence.
- PyTorch's `torch.optim.lr_scheduler` internal threshold logic uses monotone checks identical in structure to fractional binary search.

**Why understanding this makes you a better ML engineer:** Any time you write a sweep over a continuous parameter with more than ~20 values, ask: _is the metric monotone in this parameter?_ If yes, replace the sweep with 50 bisection steps. This is a direct O(S) → O(log S) improvement — from sweeping 1000 values to 10 bisection steps. That's a 100× speedup in hyperparameter tuning loops that may each take minutes.

## 3. Algorithm / Pattern

### Step-by-Step Logic

**Setup:**

- Answer `x*` is a real number in some range `[lo, hi]`.
- You have a monotone predicate `feasible(x)`: false for `x < x*`, true for `x ≥ x*` (or the reverse for maximisation).
- You want `x*` to within tolerance `ε`.

**Step 1 — Establish the bracket:**

```
lo = smallest value you know is infeasible (or 0, or a physical lower bound)
hi = largest value you know is feasible (or an obvious upper bound)
Verify: feasible(lo) == false AND feasible(hi) == true
```

**Step 2 — Choose termination strategy:**

|Strategy|When to use|Code|
|---|---|---|
|Fixed iterations (100)|CP, unknown ε needed|`for i in range(100)`|
|Epsilon tolerance|Engineering, known precision needed|`while hi - lo > 1e-9`|
|Relative tolerance|When lo, hi are large|`while (hi-lo)/(hi+lo) > 1e-9`|

**Step 3 — Bisect:**

```
mid = lo + (hi - lo) / 2    # numerically stable midpoint
if feasible(mid):
    hi = mid                 # mid works, try smaller
else:
    lo = mid                 # mid fails, must be larger
```

Note: unlike integer binary search, we don't do `lo = mid + 1` or `hi = mid - 1`. There is no "+1" — we're in the reals.

**Step 4 — Return:** After convergence: `(lo + hi) / 2` is the answer to within `ε = (hi_initial − lo_initial) / 2^iterations`.

### Precision Analysis

After `n` bisection steps, the interval width is: $$\text{width}_n = \frac{hi_0 - lo_0}{2^n}$$

For double precision (≈ 15 significant figures), we need: $$\frac{hi_0 - lo_0}{2^n} < \varepsilon$$ $$n > \log_2!\left(\frac{hi_0 - lo_0}{\varepsilon}\right)$$

Worst case: `hi_0 − lo_0 = 10^9`, `ε = 10^{-9}` → `n > log₂(10^{18}) ≈ 60`. So **100 iterations always gives full double precision** regardless of problem scale.

### The "Maximise Average" Sub-Pattern (Parametric Search)

A recurring and non-obvious application: **find the maximum average of a subarray of length ≥ k**.

Key insight: binary search on the answer `x` (the average). Then the predicate `feasible(x)` = "does there exist a subarray of length ≥ k with average ≥ x?" transforms to: "does there exist a subarray of length ≥ k in `arr[i] − x` with non-negative sum?" — which is O(n) with a prefix sum and running minimum.

This converts an O(n² ) brute force into O(n log(max_val / ε)).

### When to Use vs. When to Avoid

|Use when|Avoid when|
|---|---|
|Answer is a real number (or ratio)|Answer is provably an integer from a small set|
|Feasibility check is monotone in the parameter|Predicate is non-monotone (use ternary search instead)|
|Derivative is unavailable or unreliable|Derivative exists and Newton's method is stable — use it for O(log log 1/ε)|
|Need guaranteed convergence|Function is smooth and unimodal — golden section is equivalent|
|Feasibility check is expensive (O(n) or more)|Feasibility check is O(1) — just solve analytically|

## 4. Pseudocode

```
FRACTIONAL_BINARY_SEARCH(lo, hi, feasible, iterations=100):
    // lo:         lower bound of search space (feasible(lo) == false)
    // hi:         upper bound of search space (feasible(hi) == true)
    // feasible:   monotone predicate R → bool
    // iterations: number of bisection steps (100 gives full double precision)
    //
    // Returns: x* ≈ smallest x such that feasible(x) == true
    //          with error <= (hi - lo) / 2^iterations

    // Precondition check (important for debugging)
    ASSERT feasible(hi) == true
    ASSERT feasible(lo) == false

    FOR i FROM 1 TO iterations:
        mid ← lo + (hi - lo) / 2.0     // numerically stable: avoids (lo+hi) overflow
        
        IF feasible(mid):
            hi ← mid                    // mid is valid, try to find smaller valid value
        ELSE:
            lo ← mid                    // mid is invalid, must search higher
    
    RETURN (lo + hi) / 2.0              // centre of final interval


// ── Special pattern: Binary search on a ratio / average ──

MAXIMISE_AVERAGE_SUBARRAY(arr, k):
    // Find maximum average of any contiguous subarray of length >= k
    // Returns the maximum average as a float
    
    lo ← min(arr)          // minimum possible average
    hi ← max(arr)          // maximum possible average
    
    FUNCTION feasible(x):
        // Transform: can we find subarray of length >= k with sum >= x*len?
        // Equivalent: does arr[i] - x have a subarray of length >= k with sum >= 0?
        
        prefix ← array of size n+1, all 0
        FOR i FROM 0 TO n-1:
            prefix[i+1] ← prefix[i] + (arr[i] - x)
        
        min_prefix ← 0          // minimum prefix[j] for j <= i-k
        FOR i FROM k TO n:
            // Consider subarrays ending at i with length >= k
            IF prefix[i] - min_prefix >= 0:
                RETURN true
            min_prefix ← min(min_prefix, prefix[i - k + 1])
        
        RETURN false
    
    RETURN FRACTIONAL_BINARY_SEARCH(lo, hi, feasible, iterations=100)
```

**Edge cases handled:**

- `feasible(lo) = true` already: the precondition catches this — answer is at or below `lo`.
- `feasible(hi) = false`: impossible if `hi` is a valid upper bound; precondition catches it.
- Catastrophic cancellation: `lo + (hi − lo) / 2` instead of `(lo + hi) / 2` avoids losing precision when `lo` and `hi` are both large.
- Negative values: the template works unchanged; mid stays in `[lo, hi]`.

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

/**
 * Fractional Binary Search — Real-Valued Search Space
 *
 * Generic bisection over a continuous monotone predicate.
 * Template parameter allows any callable as the predicate.
 *
 * Time:  O(iterations * cost_of_feasible)
 * Space: O(1)
 */

// Generic fractional binary search
// feasible(x) must be false for x < x* and true for x >= x*
template <typename Predicate>
double bisect(double lo, double hi, Predicate feasible, int iterations = 100) {
    // Preconditions (enable in debug builds)
    assert(!feasible(lo));
    assert(feasible(hi));

    for (int i = 0; i < iterations; ++i) {
        double mid = lo + (hi - lo) / 2.0;  // numerically stable
        if (feasible(mid)) {
            hi = mid;
        } else {
            lo = mid;
        }
    }
    return (lo + hi) / 2.0;
}

// ── Problem 1: Maximum Average Subarray of Length >= k ──
// LeetCode 644 (premium) / standard CP problem
// Given arr, find maximum average of any subarray with length >= k.

double maxAverageSubarray(const vector<int>& arr, int k) {
    int n = arr.size();

    // Feasibility: does any subarray of length >= k have average >= x?
    // Equivalent to: does arr[i]-x have a subarray of length >= k with sum >= 0?
    auto feasible = [&](double x) -> bool {
        // Build adjusted array and check using prefix sum + sliding minimum
        vector<double> prefix(n + 1, 0.0);
        for (int i = 0; i < n; ++i) {
            prefix[i + 1] = prefix[i] + (arr[i] - x);
        }
        double min_prefix = 0.0;  // min prefix[j] for j in [0, i-k]
        for (int i = k; i <= n; ++i) {
            // Subarray arr[j..i-1] has adjusted sum = prefix[i] - prefix[j]
            // We want this >= 0, so we want prefix[i] >= prefix[j]
            // Minimising prefix[j] maximises our chance → track running min
            if (prefix[i] - min_prefix >= -1e-12) return true;  // tolerance for float
            min_prefix = min(min_prefix, prefix[i - k + 1]);
        }
        return false;
    };

    double lo = *min_element(arr.begin(), arr.end());
    double hi = *max_element(arr.begin(), arr.end());
    return bisect(lo - 1e-9, hi + 1e-9, feasible);  // tiny padding for boundary
}

// ── Problem 2: Minimum Time for All Workers to Finish ──
// Given n jobs with duration d[i] and k workers,
// find minimum time T such that all jobs finish by T
// (each worker takes jobs greedily until T is exceeded).
// The "real-valued" version: jobs have float durations.

double minTimeWorkers(const vector<double>& durations, int k) {
    int n = durations.size();

    auto feasible = [&](double T) -> bool {
        int workers = 1;
        double current = 0.0;
        for (double d : durations) {
            if (d > T) return false;  // single job exceeds T: impossible
            if (current + d > T + 1e-12) {
                ++workers;
                current = d;
                if (workers > k) return false;
            } else {
                current += d;
            }
        }
        return true;
    };

    double lo = *max_element(durations.begin(), durations.end()) - 1e-9;
    double hi = 0.0;
    for (double d : durations) hi += d;

    return bisect(lo, hi + 1e-9, feasible);
}

// ── Problem 3: Kth Smallest Fraction (real-valued binary search on ratio) ──
// Given sorted array arr of length n, find the kth smallest a[i]/a[j] (i < j).

double kthSmallestFraction(const vector<int>& arr, int k) {
    int n = arr.size();

    // feasible(x): count of fractions a[i]/a[j] <= x
    // For each j, find how many i < j have a[i] <= x * a[j] (binary search or two pointer)
    auto feasible = [&](double x) -> bool {
        int count = 0;
        for (int j = 1; j < n; ++j) {
            // a[i] <= x * a[j] → find upper bound in arr[0..j-1]
            int lo2 = 0, hi2 = j - 1;
            while (lo2 < hi2) {
                int m = (lo2 + hi2 + 1) / 2;
                if (arr[m] <= x * arr[j]) lo2 = m;
                else hi2 = m - 1;
            }
            if (arr[lo2] <= x * arr[j]) count += lo2 + 1;
        }
        return count >= k;
    };

    return bisect(0.0, 1.0, feasible);
}

int main() {
    // Test 1: Maximum average subarray (k=1 should give max element)
    {
        vector<int> arr = {1, 12, -5, -6, 50, 3};
        int k = 4;
        double result = maxAverageSubarray(arr, k);
        // Expected: (12 - 5 - 6 + 50) / 4 = 51/4 = 12.75
        printf("Max avg subarray (k=4): %.5f (expected 12.75000)\n", result);
    }

    // Test 2: Min time for workers
    {
        vector<double> durations = {3.0, 2.0, 5.0, 1.0, 4.0};
        int k = 2;
        double result = minTimeWorkers(durations, k);
        printf("Min time (2 workers): %.5f (expected ~9.00000)\n", result);
    }

    // Test 3: Kth smallest fraction
    {
        vector<int> arr = {1, 2, 3, 5};
        int k = 3;
        double result = kthSmallestFraction(arr, k);
        // Fractions: 1/5, 1/3, 2/5, 1/2, 3/5, 2/3 → 3rd is 2/5 = 0.4
        printf("3rd smallest fraction: %.5f (expected 0.40000)\n", result);
    }

    // Test 4: Convergence check — should give result within 1e-9
    {
        // sqrt(2) via bisection: x^2 >= 2
        auto feasible = [](double x) { return x * x >= 2.0; };
        double result = bisect(1.0, 2.0, feasible);
        printf("sqrt(2) via bisect: %.15f\n", result);  // should be 1.414213562...
        printf("Expected:           1.414213562373095\n");
    }

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import Callable, List
import math


def bisect_real(
    lo: float,
    hi: float,
    feasible: Callable[[float], bool],
    iterations: int = 100,
    eps: float | None = None,
) -> float:
    """
    Fractional binary search over a continuous monotone predicate.

    Finds the smallest x in [lo, hi] such that feasible(x) is True,
    where feasible is monotone: False for x < x*, True for x >= x*.

    Args:
        lo:         Lower bound. feasible(lo) must be False.
        hi:         Upper bound. feasible(hi) must be True.
        feasible:   Monotone predicate R -> bool.
        iterations: Fixed iteration count (default 100 → full float64 precision).
        eps:        If set, stop when hi - lo < eps instead of using fixed iters.

    Returns:
        Approximation of x* with error <= (hi - lo) / 2^iterations.

    Time:  O(iterations * cost_of_feasible)
    Space: O(1)
    """
    assert not feasible(lo), f"feasible(lo={lo}) must be False"
    assert feasible(hi), f"feasible(hi={hi}) must be True"

    if eps is not None:
        while hi - lo > eps:
            mid = lo + (hi - lo) / 2.0
            if feasible(mid):
                hi = mid
            else:
                lo = mid
    else:
        for _ in range(iterations):
            mid = lo + (hi - lo) / 2.0
            if feasible(mid):
                hi = mid
            else:
                lo = mid

    return (lo + hi) / 2.0


# ── Pattern: Maximum Average Subarray of Length >= k ──

def max_average_subarray(arr: List[float], k: int) -> float:
    """
    Find the maximum average of any contiguous subarray of length >= k.

    Key transformation: binary search on answer x (the average).
    feasible(x) = "does any subarray of length >= k in (arr[i] - x) have sum >= 0?"
    This is O(n) via prefix sum + running minimum.

    Time:  O(n * iterations) = O(100n)
    Space: O(n) for prefix array
    """
    n = len(arr)

    def feasible(x: float) -> bool:
        # Transform each element: a[i] - x
        # Check: is there a subarray of length >= k with non-negative sum?
        prefix = [0.0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + (arr[i] - x)

        # For subarrays ending at position i (length >= k):
        # sum = prefix[i] - prefix[j] where j <= i - k
        # Maximise sum by minimising prefix[j]
        min_prefix = 0.0  # prefix[0] = 0 is always a valid j=0
        for i in range(k, n + 1):
            if prefix[i] - min_prefix >= -1e-12:  # float tolerance
                return True
            # Add prefix[i - k + 1] to candidates for min_prefix
            # (it corresponds to j = i - k + 1, giving subarray length exactly k ending at i+1)
            min_prefix = min(min_prefix, prefix[i - k + 1])
        return False

    return bisect_real(
        lo=min(arr) - 1e-9,
        hi=max(arr) + 1e-9,
        feasible=feasible,
    )


# ── Pattern: Binary Search on a Ratio ──

def max_ratio_subset(values: List[float], weights: List[float], k: int) -> float:
    """
    Select exactly k items to maximise sum(values) / sum(weights).
    
    Binary search on the answer x (the ratio).
    feasible(x) = "can we select k items with sum(v[i] - x*w[i]) >= 0?"
    Greedy: sort by (v[i] - x*w[i]) descending, take top k.

    This is the "maximum weight closure" / fractional knapsack binary search.

    Time:  O(n log n * iterations)  [sort inside feasible]
    Space: O(n)
    """
    n = len(values)
    assert len(weights) == n and k <= n

    def feasible(x: float) -> bool:
        # Adjusted profit for each item at ratio x
        adjusted = sorted(
            (values[i] - x * weights[i] for i in range(n)),
            reverse=True
        )
        return sum(adjusted[:k]) >= -1e-12

    # Bounds: ratio >= 0, ratio <= max(v[i]/w[i])
    lo = 0.0
    hi = max(v / w for v, w in zip(values, weights))
    return bisect_real(lo - 1e-9, hi + 1e-9, feasible)


# ── Scipy comparison: bisect_real vs scipy.optimize.bisect ──

def demo_scipy_equivalence():
    """
    Show that bisect_real is equivalent to scipy.optimize.bisect
    for root-finding problems.

    scipy.optimize.bisect(f, a, b) finds x where f(x) = 0.
    bisect_real with feasible(x) = (f(x) >= 0) finds the same root.
    """
    import scipy.optimize  # type: ignore

    # Find sqrt(3) — root of f(x) = x^2 - 3
    f = lambda x: x**2 - 3

    scipy_result = scipy.optimize.bisect(f, 1.0, 2.0, xtol=1e-12)
    our_result = bisect_real(1.0, 2.0, feasible=lambda x: x**2 >= 3)

    print(f"scipy.bisect:  {scipy_result:.15f}")
    print(f"bisect_real:   {our_result:.15f}")
    print(f"math.sqrt(3):  {math.sqrt(3):.15f}")
    print(f"Difference:    {abs(scipy_result - our_result):.2e}")


# ── Tests ──

if __name__ == "__main__":
    # Test 1: Maximum average subarray
    arr = [1, 12, -5, -6, 50, 3]
    result = max_average_subarray(arr, k=4)
    assert abs(result - 12.75) < 1e-6, f"Got {result}"
    print(f"Max avg subarray: {result:.5f} ✓")

    # Test 2: Maximum ratio subset (select 2 items to maximise value/weight)
    values  = [10.0, 20.0, 15.0, 8.0]
    weights = [ 5.0,  8.0,  4.0, 3.0]
    result = max_ratio_subset(values, weights, k=2)
    # Best 2 items at x: 15/4=3.75 and 20/8=2.5 → combined (15+20)/(4+8)=35/12≈2.917
    # But greedy on adjusted picks best two by v-x*w — the answer is ~3.75 (just item 3)
    # Wait: we must pick exactly k=2 — answer is (15+10)/(4+5)=25/9≈2.778
    print(f"Max ratio (2 items): {result:.5f}")

    # Test 3: sqrt(2) via bisection
    result = bisect_real(1.0, 2.0, feasible=lambda x: x * x >= 2.0)
    assert abs(result - math.sqrt(2)) < 1e-12, f"Got {result}"
    print(f"sqrt(2): {result:.15f} ✓")

    # Test 4: Convergence — 100 iterations on [0, 1e9] gives ~3e-22 error
    result = bisect_real(0.0, 1e9, feasible=lambda x: x >= math.pi * 1e8)
    expected = math.pi * 1e8
    print(f"Large range: error = {abs(result - expected):.2e} ✓")

    print("\nAll tests passed.")
```

```
Search space: [0, 1], x* = 0.3333...
```

## 7. Common Variations & Extensions

### Variation 1: Ternary Search (Unimodal Function Optimisation)

When the predicate is not monotone but the underlying function has a single peak (unimodal), bisection doesn't apply but **ternary search** does. You evaluate at `lo + (hi − lo) / 3` and `hi − (hi − lo) / 3`, discard the worse third. Convergence: O(log₃(range/ε)) ≈ O(0.63 × log₂(range/ε)) — slightly worse than bisection per call but applicable to non-monotone objectives. Common in CP for "find the peak of a parabolic function" problems.

### Variation 2: Parametric Search (Megiddo's Technique)

In advanced CP and computational geometry, the answer to an optimisation problem over a continuous parameter can be found by binary searching on the parameter and running a decision algorithm as the feasibility check — even when the decision algorithm is itself O(n log n). This is called **parametric search**. Example: find the minimum speed such that an agent reaches a destination before time T, where the feasibility check runs a shortest-path algorithm. Combines fractional binary search with [[117.Dijkstra's algorithm — O((V+E) log V) with min-heap]].

### Variation 3: Bisection for Root Finding

When `feasible(x) = (f(x) ≥ 0)` and `f` is continuous, bisection finds a root of `f`. This is [[64.Bisection method for root finding — numerical analysis connection]] — the numerical analysis view of the exact same algorithm. `scipy.optimize.bisect` and `scipy.optimize.brentq` are production implementations.

### Variation 4: Multi-Dimensional Bisection

Some problems require bisecting on two parameters simultaneously (e.g., find minimum (capacity, time) pair satisfying a constraint). This is not a single bisection — it requires either fixing one parameter and bisecting on the other, or using 2D convex hull tricks. Related to [[184.Convex hull trick for DP optimisation]].

### Variation 5: Binary Search on a Sorted Matrix (Real-Valued)

When the search space is a real-valued matrix (e.g., find the kth smallest eigenvalue), the structure from [[58.Binary search on 2D matrix]] extends to the continuous domain via the Weyl inequalities. The feasibility check counts how many eigenvalues are ≤ x using Sylvester's criterion — an O(n²) linear algebra operation.

## 9. CP Contest Application

### Typical Problem Structure

**CF-style problem skeleton:**

> Given n points, find the maximum radius r such that [geometric property holds for circle of radius r]. Or: given n tasks with real durations, find minimum rate R (tasks/hour) such that all tasks finish in time T.

These appear at Codeforces Div. 2 D/E and Div. 1 C level. The tell:

- Answer is a real number or ratio.
- Constraints allow O(n log n) feasibility (n ≤ 10⁵).
- Problem says "find the maximum/minimum [continuous quantity]."

**Contest examples:**

- CF 578C — "Weakness and Poorness" (ternary + fractional binary search combo)
- CF 439D — "Devu and his Brother" (binary search on answer with real boundary)
- CF 1551F — "Gregor and Two Painters" (ratio binary search)

### Template Discipline for Contests

The two templates, side by side:

```cpp
// MINIMISE (find smallest valid x):
double lo = lower_bound, hi = upper_bound;
for (int i = 0; i < 100; ++i) {
    double mid = lo + (hi - lo) / 2;
    if (feasible(mid)) hi = mid;
    else               lo = mid;
}
double answer = (lo + hi) / 2;

// MAXIMISE (find largest valid x):
// Same! — just flip the predicate meaning.
// feasible(x) = "is x achievable?" must still be monotone.
// The code is identical; only what feasible() checks changes.
```

No `+1`, no `- 1`, no `while (lo < hi)`. Just 100 iterations.

### Precision Pitfalls in Contest Output

Many problems ask to output a real answer to 6 decimal places. The required precision determines how many iterations you need:

- 6 decimal places: `log₂(range / 1e-6)` iterations.
- With range = 10⁶ and 6 dp: `log₂(10¹²) ≈ 40` iterations.
- 100 iterations gives `range / 2¹⁰⁰` precision — always overkill for 6–9 dp output.

Output format: use `printf("%.9f\n", answer)` or `cout << fixed << setprecision(9) << answer`.

**The one hidden cost:** if `feasible()` contains floating-point comparisons internally, accumulated rounding error can cause the predicate to be non-monotone near `x*`. The fix: add a small epsilon tolerance inside `feasible()` (as shown in the implementation above with `>= -1e-12`) to smooth out the boundary. This is a numerical stability concern related to [[221.Numerical stability — log-sum-exp, softmax overflow prevention]].
