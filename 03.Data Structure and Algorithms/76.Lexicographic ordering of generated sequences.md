## 1. Intuition First

### The Core Idea

**Lexicographic order** is dictionary order generalised to arbitrary sequences. Two sequences are compared element by element from left to right: the first position where they differ determines which comes first — the sequence with the smaller element at that position is lexicographically smaller. If one sequence is a prefix of the other, the shorter one comes first.

For the alphabet {A, B, C}: A < B < C. So:

```
[A]       < [A, A]    < [A, B]    < [A, C]
[A, C]    < [B]       < [B, A]    < [C, C, C]
```

For integers {1, 2, 3}: 1 < 2 < 3. So:

```
[1] < [1,1] < [1,2] < [1,3] < [2] < [2,1] < [2,2] < [3,3,3]
```

This is exactly the order you would find these sequences in a dictionary if each sequence were a word and each element a letter.

The critical insight is that **lexicographic order is a total order on sequences of any length** — every pair of distinct sequences has a well-defined ordering. This makes it possible to:

- Enumerate all sequences of a type in a predictable canonical order
- Find the _k-th_ sequence in that order without generating all previous ones
- Find the _next_ sequence from any current sequence in O(n) time
- Rank any sequence — map it to its position in the lexicographic enumeration

### Why This Exists

Without a canonical ordering, combinatorial objects — subsets, permutations, combinations — are an unstructured bag. Imposing lexicographic order transforms that bag into a **linearly indexed sequence**: you can speak of "the 7th combination" or "the next permutation after [3,1,2]" or "enumerate all sequences between [1,2] and [2,4]."

This matters for:

- **Deterministic generation:** backtracking naturally produces sequences in lexicographic order when the input is sorted and the loop iterates forward — the order falls out for free
- **k-th element queries:** find the k-th subset/permutation/combination without enumerating the first k−1
- **Resumable enumeration:** given any sequence, compute its successor without rewinding to the beginning
- **Sorted output:** problems that require "return all combinations in sorted order" — just sort the input and use standard backtracking

### The "Aha" Moment

Lexicographic order on combinatorial sequences is structurally identical to counting in a variable-base number system. The sequence [2, 1, 3] in permutations of {1,2,3} is like the number "213" — each digit position has a value, and incrementing means finding the rightmost position you can increase, incrementing it, and filling everything to the right with the smallest possible continuation.

> **The `next_permutation` algorithm, the `next_combination` algorithm, and the `next_subset` algorithm are all the same concept: find the rightmost position that can be incremented, increment it, reset everything to its right to the lexicographic minimum.**

This single observation unifies the "next X" algorithms across all combinatorial sequence types.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- "Return all results in lexicographic order" — sort input, backtrack naturally produces this
- "Find the k-th permutation/combination/subset" — use the factorial/combinatorial number system
- "Find the next permutation" — C++ `std::next_permutation`, or implement manually (see [[73.Generating all permutations — swap-based and insert-based]])
- "Is sequence A lexicographically smaller than B?" — string/array comparison
- Problems involving lexicographically smallest/largest valid construction
- "Generate all sequences of length k from alphabet Σ in lex order"

**Pattern signals:**

```
"lexicographically smallest"  →  greedy: always pick smallest valid choice
"lexicographically largest"   →  greedy: always pick largest valid choice
"k-th in lex order"           →  factorial number system / combinatorial ranking
"next permutation"            →  next_permutation algorithm
"sorted output"               →  sort input, standard backtracking
```

**Common traps:**

1. **Forgetting to sort the input before backtracking.** Standard backtracking on a sorted input produces lexicographic output automatically. On an unsorted input, the output order is arbitrary. If the problem requires lex order, the fix is one `sort` call.
    
2. **Off-by-one in k-th element computation.** When finding the k-th permutation, problems use both 0-indexed ("0th permutation") and 1-indexed ("1st permutation"). The factorial number system derivation assumes 0-indexed k; subtract 1 before applying if the problem is 1-indexed.
    
3. **String lex order vs integer lex order.** Strings "10" < "9" lexicographically because '1' < '9', but integer 10 > 9 numerically. This matters in problems mixing string and numeric comparisons. Always clarify which ordering is intended.
    
4. **Confusing lexicographic order with length-first (shortlex) order.** Shortlex orders by length first, then lexicographically within same length. Standard lex order does NOT sort by length — [1,2] < [2] because 1 < 2 at position 0. When a problem says "shorter sequences first," it wants shortlex, not lex.
    

### Machine Learning / AI

**1. Tokenisation and vocabulary ordering.** Byte-pair encoding (BPE), the tokenisation algorithm used in GPT-2/3/4, builds a vocabulary by iteratively merging the most frequent adjacent byte pairs. The final vocabulary is a set of variable-length token strings. Storing and searching this vocabulary requires a total ordering — lexicographic order on byte sequences is the natural choice. Python's `str` comparison and the standard string sort are lexicographic, making vocabulary lookups and sorted vocabulary files directly compatible.

**2. Sorted feature generation in tree-based models.** Decision trees (see [[158.Decision tree structure — how CART maps to a binary tree]]) and gradient boosting frameworks (XGBoost, LightGBM) iterate over feature-split combinations in sorted order to find the best split. The combination of (feature index, threshold value) pairs is enumerated in a canonical order — essentially lexicographic on (feature_index, threshold) — to ensure deterministic, reproducible model training.

**3. Beam search output ordering.** Beam search in sequence generation (language models, machine translation) maintains a set of partial hypotheses. When multiple hypotheses have equal scores, lexicographic ordering provides a deterministic tiebreaker, ensuring reproducible outputs. Frameworks like Hugging Face's `generate()` internally sort beam candidates using Python's default sequence comparison, which is lexicographic.

**4. Canonical form for graph isomorphism.** The canonical labelling of a graph — assigning labels so that isomorphic graphs get the same label — relies on lexicographic ordering of adjacency sequences. The Weisfeiler-Lehman graph isomorphism test (used as the theoretical foundation for graph neural networks — see [[135.Graph neural networks — conceptual bridge from classical to ML graphs]]) assigns canonical hashes to node neighbourhoods by sorting and concatenating neighbour labels lexicographically. The sort is what makes the hash invariant to the original node ordering.

**5. K-th sequence for dataset sharding.** In distributed ML training, a common pattern is to shard a dataset by assigning worker `i` the items at positions `[i*shard_size, (i+1)*shard_size)` in some canonical ordering. When the dataset consists of combinatorial objects (e.g., all pairs of images for contrastive learning), ranking and unranking combinations (the lexicographic k-th combination algorithm) allows each worker to compute its assigned pairs without materialising the full pair list — essential at scale.

## 3. Algorithm / Pattern

### Lexicographic Order Falls Out of Sorted Backtracking

When input is sorted and the backtracking loop iterates `i` from `start` to `n−1` in increasing order, the output is automatically lexicographic. No additional work needed. The first result is always the lexicographically smallest (all leftmost choices), and the last is always the largest (all rightmost choices).

```
Input sorted: nums = [1, 2, 3], k = 2
Backtracking output order: [1,2], [1,3], [2,3]  ← lexicographic ✓
[1,2] < [1,3] because at position 1: 2 < 3
[1,3] < [2,3] because at position 0: 1 < 2
```

### The "Next Sequence" Algorithm (General Pattern)

All "find the next sequence" algorithms follow the same template:

```
Given current sequence S = [s₀, s₁, ..., sₙ₋₁]:

1. FIND: scan right to left for the rightmost position i where sᵢ can be incremented
         while maintaining the sequence's validity constraints

2. INCREMENT: increase sᵢ to the next valid value

3. RESET: fill positions i+1 to n−1 with the lexicographically smallest
          valid continuation from that state
```

Applied to different sequence types:

- **Next permutation:** position i = rightmost descent; increment to next larger available; fill right with ascending sort
- **Next combination (no repetition):** position i = rightmost element that can increase without exceeding n−(k−1−i); increment by 1; fill right with consecutive values
- **Next subset:** treat as binary number; add 1 (with carry propagation)

### Ranking and Unranking

**Rank** of a sequence = its 0-indexed position in lexicographic order. **Unrank** = given a rank r, produce the sequence at position r.

These are inverse operations. Both run in O(n × log n) or O(n × k) depending on the type.

For **k-th permutation** (0-indexed k):

```
At each position i (0 to n−1):
  block_size = (n−1−i)!          # permutations per block at this position
  digit = k // block_size         # which element to place at position i
  place remaining[digit] at position i
  remove it from remaining
  k = k % block_size
```

For **k-th combination** (0-indexed k, choosing r elements from n):

```
At each selection step (r elements to choose):
  for each candidate c starting from current minimum:
    count = C(n−c−1, r−1)        # combinations starting with this c
    if k < count: place c, recurse with r−1, n, k
    else: k -= count, try next candidate
```

### Complexity Summary

|Operation|Time|Space|
|---|---|---|
|Generate all in lex order|O(output size)|O(depth)|
|Next permutation|O(n)|O(1)|
|Next combination|O(k)|O(1)|
|k-th permutation (unrank)|O(n²) naïve, O(n log n) with Fenwick|O(n)|
|k-th combination (unrank)|O(k × n)|O(k)|
|Rank a permutation|O(n²) naïve, O(n log n) with Fenwick|O(n)|

## 4. Pseudocode

```
# ── Lexicographic comparison of two sequences ──────────────────────────────

FUNCTION lex_less(a, b):
    FOR i FROM 0 TO min(len(a), len(b)) - 1:
        IF a[i] < b[i]: RETURN True
        IF a[i] > b[i]: RETURN False
    RETURN len(a) < len(b)        # equal prefix: shorter is smaller


# ── Sorted backtracking → automatic lex output ─────────────────────────────

FUNCTION generate_lex(nums, k):
    SORT nums                      # prerequisite: sorted input
    result ← []
    CALL backtrack(start=0, path=[])
    RETURN result                  # result is already in lex order

FUNCTION backtrack(start, path):
    IF len(path) == k:
        result.APPEND(COPY of path)
        RETURN
    FOR i FROM start TO n-1:      # increasing i → lex order
        path.APPEND(nums[i])
        CALL backtrack(i+1, path)
        path.POP()


# ── Next combination (no repetition) ──────────────────────────────────────

FUNCTION next_combination(combo, n):
    # combo: current k-combination of indices in [0..n-1], sorted ascending
    k ← len(combo)

    # Find rightmost index that can be incremented
    i ← k - 1
    WHILE i >= 0 AND combo[i] == n - k + i:   # at maximum value for this position
        i ← i - 1
    IF i < 0: RETURN None          # combo is already the last one

    combo[i] ← combo[i] + 1       # increment
    FOR j FROM i+1 TO k-1:
        combo[j] ← combo[i] + (j - i)   # fill right with consecutive values
    RETURN combo


# ── k-th permutation (0-indexed) ───────────────────────────────────────────

FUNCTION kth_permutation(nums, k):
    SORT nums
    result ← []
    factorials ← [1, 1, 2, 6, 24, ...]    # precompute 0! through (n-1)!

    FOR i FROM n-1 DOWN TO 0:
        block_size ← factorials[i]
        digit ← k // block_size
        result.APPEND(nums[digit])
        nums.REMOVE(nums[digit])
        k ← k % block_size

    RETURN result


# ── k-th combination (0-indexed) ───────────────────────────────────────────

FUNCTION kth_combination(n, r, k):
    result ← []
    start ← 0

    WHILE r > 0:
        FOR c FROM start TO n-1:
            count ← C(n - c - 1, r - 1)   # combos with this c as current element
            IF k < count:
                result.APPEND(c)
                start ← c + 1
                r ← r - 1
                BREAK
            k ← k - count

    RETURN result
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <numeric>
#include <cassert>
#include <functional>

// ─────────────────────────────────────────────────────────────────────────────
// Lexicographic comparison — works on any vector<T> where T is comparable
// ─────────────────────────────────────────────────────────────────────────────
template<typename T>
bool lex_less(const std::vector<T>& a, const std::vector<T>& b) {
    for (int i = 0; i < (int)std::min(a.size(), b.size()); ++i) {
        if (a[i] < b[i]) return true;
        if (a[i] > b[i]) return false;
    }
    return a.size() < b.size();   // equal prefix: shorter is smaller
}

// ─────────────────────────────────────────────────────────────────────────────
// Next combination (index-based): given current k-combination of indices
// into [0..n-1], advance to the next in lex order. Returns false if at last.
// ─────────────────────────────────────────────────────────────────────────────
bool next_combination_indices(std::vector<int>& combo, int n) {
    int k = combo.size();

    // Find rightmost index that is NOT at its maximum value
    // Position i has max value: n - k + i  (0-indexed)
    int i = k - 1;
    while (i >= 0 && combo[i] == n - k + i) --i;
    if (i < 0) return false;   // all at max — this is the last combination

    ++combo[i];                // increment rightmost incrementable position
    for (int j = i + 1; j < k; ++j)
        combo[j] = combo[i] + (j - i);  // fill right with consecutive values

    return true;
}

// Iterate all k-combinations of {0..n-1} in lex order using next_combination
std::vector<std::vector<int>> all_combinations_lex(int n, int k) {
    if (k > n) return {};
    std::vector<std::vector<int>> result;
    std::vector<int> combo(k);
    std::iota(combo.begin(), combo.end(), 0);   // start: [0,1,2,...,k-1]

    do {
        result.push_back(combo);
    } while (next_combination_indices(combo, n));

    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// k-th permutation (0-indexed k) using factorial number system
// O(n²) time — acceptable for n ≤ 20
// ─────────────────────────────────────────────────────────────────────────────
std::vector<int> kth_permutation(int n, long long k) {
    // Precompute factorials
    std::vector<long long> fact(n + 1, 1);
    for (int i = 1; i <= n; ++i) fact[i] = fact[i-1] * i;

    // Available digits: {1, 2, ..., n}
    std::vector<int> available(n);
    std::iota(available.begin(), available.end(), 1);

    std::vector<int> result;
    result.reserve(n);

    for (int i = n; i >= 1; --i) {
        long long block = fact[i - 1];   // each block has (i-1)! permutations
        int digit = k / block;           // which block we're in
        result.push_back(available[digit]);
        available.erase(available.begin() + digit);
        k %= block;
    }
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// k-th combination (0-indexed k): choose r elements from {1..n} in lex order
// Uses the combinatorial number system
// ─────────────────────────────────────────────────────────────────────────────
long long cnk(int n, int r) {
    if (r < 0 || r > n) return 0;
    if (r == 0 || r == n) return 1;
    r = std::min(r, n - r);
    long long result = 1;
    for (int i = 0; i < r; ++i)
        result = result * (n - i) / (i + 1);
    return result;
}

std::vector<int> kth_combination(int n, int r, long long k) {
    std::vector<int> result;
    int start = 1;   // current minimum candidate (1-indexed: {1..n})

    while (r > 0) {
        for (int c = start; c <= n; ++c) {
            long long count = cnk(n - c, r - 1);  // combos with c as current element
            if (k < count) {
                result.push_back(c);
                start = c + 1;
                --r;
                break;
            }
            k -= count;
        }
    }
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Rank a combination: given a sorted combination, find its 0-indexed rank
// Inverse of kth_combination
// ─────────────────────────────────────────────────────────────────────────────
long long rank_combination(const std::vector<int>& combo, int n) {
    // combo: sorted k-combination of values from {1..n}
    long long rank = 0;
    int r = combo.size();
    int prev = 0;   // previous element (for range counting)

    for (int i = 0; i < r; ++i) {
        // Count all combinations that would come before this one at position i
        // i.e., all combinations with a smaller value at position i
        for (int v = prev + 1; v < combo[i]; ++v) {
            rank += cnk(n - v, r - 1 - i);
        }
        prev = combo[i];
    }
    return rank;
}

// ─────────────────────────────────────────────────────────────────────────────
// Demo and tests
// ─────────────────────────────────────────────────────────────────────────────
int main() {
    // Lex comparison
    assert(lex_less<int>({1,2,3}, {1,2,4}));
    assert(lex_less<int>({1,2},   {1,2,3}));
    assert(!lex_less<int>({2},    {1,9,9}));
    assert(!lex_less<int>({1,2},  {1,2}));   // equal → not less

    // Next combination
    auto combos = all_combinations_lex(4, 2);
    assert(combos.size() == 6);
    assert(combos[0] == std::vector<int>({0,1}));   // first
    assert(combos[5] == std::vector<int>({2,3}));   // last

    // Verify lex order
    for (int i = 0; i + 1 < (int)combos.size(); ++i)
        assert(lex_less(combos[i], combos[i+1]));

    // k-th permutation (n=4, 0-indexed)
    // Permutations of {1,2,3,4} in lex order: 0th=[1,2,3,4], 23rd=[4,3,2,1]
    assert(kth_permutation(4, 0)  == std::vector<int>({1,2,3,4}));
    assert(kth_permutation(4, 23) == std::vector<int>({4,3,2,1}));
    assert(kth_permutation(4, 1)  == std::vector<int>({1,2,4,3}));
    assert(kth_permutation(3, 3)  == std::vector<int>({2,1,3}));

    // k-th combination C(5,3): 0th=[1,2,3], 9th=[3,4,5]
    assert(kth_combination(5, 3, 0) == std::vector<int>({1,2,3}));
    assert(kth_combination(5, 3, 9) == std::vector<int>({3,4,5}));
    assert(kth_combination(5, 3, 4) == std::vector<int>({1,4,5}));

    // Round-trip: rank → unrank
    for (long long r = 0; r < 10; ++r) {
        auto combo = kth_combination(5, 3, r);
        assert(rank_combination(combo, 5) == r);
    }

    // k-th permutation full sweep
    std::vector<std::vector<int>> all_perms;
    for (int i = 0; i < 6; ++i)   // 3! = 6
        all_perms.push_back(kth_permutation(3, i));
    // Must be in lex order
    for (int i = 0; i + 1 < 6; ++i)
        assert(lex_less(all_perms[i], all_perms[i+1]));

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from math import comb, factorial
from itertools import combinations, permutations

# ─────────────────────────────────────────────────────────────────────────────
# Lexicographic comparison — Python's default < on lists/tuples is already lex
# Shown explicitly to make the logic visible
# ─────────────────────────────────────────────────────────────────────────────

def lex_less(a: list, b: list) -> bool:
    """
    True if sequence a is lexicographically less than b.

    Python's built-in list < already does this — this function makes
    the element-by-element comparison explicit for teaching purposes.

    >>> lex_less([1,2,3], [1,2,4])
    True
    >>> lex_less([1,2], [1,2,3])   # prefix: shorter is smaller
    True
    >>> lex_less([2], [1,9,9])
    False
    """
    for x, y in zip(a, b):
        if x < y: return True
        if x > y: return False
    return len(a) < len(b)


# ─────────────────────────────────────────────────────────────────────────────
# Sorted backtracking → guaranteed lex output
# ─────────────────────────────────────────────────────────────────────────────

def combinations_lex(nums: list[int], k: int) -> list[list[int]]:
    """
    Generate all C(n,k) combinations in lexicographic order.

    Lex order falls out naturally from:
    1. sorted input (nums.sort() beforehand)
    2. forward-only loop (for i in range(start, n))

    The first element of the output is always the lexicographically smallest
    combination; the last is always the largest. No post-sorting needed.

    >>> combinations_lex([3,1,2], 2)  # unsorted input sorted internally
    [[1, 2], [1, 3], [2, 3]]
    """
    nums = sorted(nums)
    result = []

    def backtrack(start: int, path: list[int]) -> None:
        if len(path) == k:
            result.append(path[:])
            return
        remaining = k - len(path)
        for i in range(start, len(nums) - remaining + 1):
            path.append(nums[i])
            backtrack(i + 1, path)
            path.pop()

    backtrack(0, [])
    return result   # already in lex order


# ─────────────────────────────────────────────────────────────────────────────
# Next combination: O(k) advancement without regenerating from scratch
# Works on index-based combinations in [0..n-1]
# ─────────────────────────────────────────────────────────────────────────────

def next_combination(combo: list[int], n: int) -> bool:
    """
    Advance combo (a k-combination of indices in [0..n-1]) to the next
    lexicographic combination in-place. Returns False if already at last.

    Position i has maximum value n - k + i (0-indexed).
    Find rightmost position that's below its maximum, increment it,
    fill everything to its right with consecutive values.

    Time:  O(k) per call
    Space: O(1)

    >>> c = [0,1,2]; next_combination(c, 4); c
    True
    [0, 1, 3]
    >>> c = [1,2,3]; next_combination(c, 4); c
    False  (was already last)
    [0, 1, 2]  ← wraps to first
    """
    k = len(combo)
    i = k - 1
    while i >= 0 and combo[i] == n - k + i:
        i -= 1
    if i < 0:
        # Wrap around to first combination
        for j in range(k):
            combo[j] = j
        return False
    combo[i] += 1
    for j in range(i + 1, k):
        combo[j] = combo[i] + (j - i)
    return True


def iterate_combinations_lex(n: int, k: int):
    """
    Yield all C(n,k) index-combinations in lex order using next_combination.
    Memory-efficient: O(k) space, generates one at a time.

    >>> list(iterate_combinations_lex(4, 2))
    [[0,1],[0,2],[0,3],[1,2],[1,3],[2,3]]
    """
    if k > n:
        return
    combo = list(range(k))
    while True:
        yield combo[:]
        if not next_combination(combo, n):
            break


# ─────────────────────────────────────────────────────────────────────────────
# k-th permutation (0-indexed): factorial number system
# O(n²) — use a Fenwick tree for O(n log n) if n is large
# ─────────────────────────────────────────────────────────────────────────────

def kth_permutation(nums: list[int], k: int) -> list[int]:
    """
    Return the k-th (0-indexed) permutation of nums in lexicographic order.

    Uses the factorial number system:
    - There are (n-1)! permutations starting with each element
    - Digit at position i = k // (i)!
    - Remainder k = k % (i)!

    No need to generate the first k permutations.

    Time:  O(n²) due to list removal — O(n log n) with sorted container
    Space: O(n)

    >>> kth_permutation([1,2,3,4], 0)   # first
    [1, 2, 3, 4]
    >>> kth_permutation([1,2,3,4], 23)  # last
    [4, 3, 2, 1]
    >>> kth_permutation([1,2,3], 3)
    [2, 1, 3]
    """
    nums = sorted(nums)
    n = len(nums)
    result = []

    for i in range(n - 1, -1, -1):
        block = factorial(i)      # (n-1)! permutations per block at this step
        digit = k // block        # which element to place at current position
        result.append(nums[digit])
        nums.pop(digit)           # remove chosen element from pool
        k %= block                # advance within the chosen block

    return result


# ─────────────────────────────────────────────────────────────────────────────
# k-th combination (0-indexed): combinatorial number system
# ─────────────────────────────────────────────────────────────────────────────

def kth_combination(n: int, r: int, k: int) -> list[int]:
    """
    Return the k-th (0-indexed) r-combination from {1..n} in lex order.

    Algorithm: at each step, count how many combinations start with
    each candidate value c. When k < that count, c is our next element.
    Otherwise subtract the count and try the next c.

    Time:  O(r × n) — at most r×n calls to comb()
    Space: O(r)

    >>> kth_combination(5, 3, 0)   # C(5,3): first combination
    [1, 2, 3]
    >>> kth_combination(5, 3, 9)   # last combination
    [3, 4, 5]
    >>> kth_combination(5, 3, 4)
    [1, 4, 5]
    """
    result = []
    start = 1   # minimum candidate (1-indexed)

    while r > 0:
        for c in range(start, n + 1):
            # Combinations starting with c: choose remaining r-1 from c+1..n
            count = comb(n - c, r - 1)
            if k < count:
                result.append(c)
                start = c + 1
                r -= 1
                break
            k -= count

    return result


def rank_combination(combo: list[int], n: int) -> int:
    """
    Return the 0-indexed rank of combo among all C(n,r) combinations in lex order.
    Inverse of kth_combination. combo must be sorted ascending, values in {1..n}.

    Time:  O(r × n)
    Space: O(1)

    >>> rank_combination([1,2,3], 5)   # first of C(5,3)
    0
    >>> rank_combination([3,4,5], 5)   # last
    9
    """
    rank = 0
    r = len(combo)
    prev = 0

    for i, val in enumerate(combo):
        # Count combinations with a smaller value at position i
        for v in range(prev + 1, val):
            rank += comb(n - v, r - 1 - i)
        prev = val
        r -= 1

    return rank


# ─────────────────────────────────────────────────────────────────────────────
# Lexicographically smallest valid construction — greedy pattern
# Demonstrates lex-min as a greedy algorithm
# ─────────────────────────────────────────────────────────────────────────────

def lex_smallest_combination_with_sum(nums: list[int], k: int, target: int) \
        -> list[int] | None:
    """
    Find the lexicographically smallest k-combination from nums summing to target.

    Greedy: at each position, choose the smallest element that leaves
    enough remaining elements to complete the combination.

    This is NOT the same as running backtracking and taking the first result —
    it's O(n×k) greedy vs O(k × C(n,k)) backtracking.

    >>> lex_smallest_combination_with_sum([1,2,3,4,5], 3, 9)
    [1, 3, 5]  # 1+3+5=9; [1,2,6] would be smaller but 6 not in nums
    >>> lex_smallest_combination_with_sum([1,2,3,4,5], 3, 15)
    None  # max sum is 3+4+5=12 < 15
    """
    nums = sorted(nums)
    n = len(nums)

    def backtrack(start: int, path: list[int], remaining: int) -> list[int] | None:
        if len(path) == k:
            return path[:] if remaining == 0 else None
        slots = k - len(path)
        for i in range(start, n - slots + 1):
            if nums[i] > remaining:
                break
            result = backtrack(i + 1, path + [nums[i]], remaining - nums[i])
            if result is not None:
                return result   # first valid = lex smallest (input sorted)
        return None

    return backtrack(0, [], target)


# ─────────────────────────────────────────────────────────────────────────────
```

## 6. Visual Explanation

### Lex Order as a Trie

Lexicographic order corresponds to depth-first left-to-right traversal of a trie. The lex-smallest sequence is the leftmost path from root to terminal; the lex-largest is the rightmost.

```
Trie of all 2-combinations from {1,2,3,4}:

root
├── 1 ──┬── 2 ──→  [1,2]  (rank 0)
│       ├── 3 ──→  [1,3]  (rank 1)
│       └── 4 ──→  [1,4]  (rank 2)
├── 2 ──┬── 3 ──→  [2,3]  (rank 3)
│       └── 4 ──→  [2,4]  (rank 4)
└── 3 ──└── 4 ──→  [3,4]  (rank 5)

Left-to-right DFS: [1,2],[1,3],[1,4],[2,3],[2,4],[3,4] ← lexicographic order
Backtracking with sorted input and start=i+1 IS this left-to-right DFS.
```

### The Next-Combination Advance: Finding the Rightmost Non-Max Position

For k=3, n=6, current combo [1, 3, 5] (0-indexed: [0, 2, 4]):

```
Positions:     0    1    2
Max values:  n-k  n-k+1  n-k+2  =  3   4   5  (0-indexed max for each position)

Current:      0    2    4
Max:          3    4    5
At max?       no   no   no   ← rightmost non-max is position 2 (i=2)

Increment position 2: 4 → 5
Fill right of position 2: nothing to fill (i is last)
Result: [0, 2, 5]  →  combination [1, 3, 6]

Next advance from [0, 2, 5]:
Current:      0    2    5
Max:          3    4    5
At max?       no   no   YES  ← position 2 at max, move left
              no   no        ← position 1: 2 < 4, not at max. i=1

Increment position 1: 2 → 3
Fill right of position 1 with consecutive: position 2 = 3+1 = 4
Result: [0, 3, 4]  →  combination [1, 4, 5]
```

### k-th Permutation: Factorial Number System

Finding the 14th (0-indexed) permutation of {1,2,3,4}:

```
n=4, k=14.  Total: 4! = 24 permutations.

Step i=3 (n-1): block = 3! = 6
  digit = 14 // 6 = 2  → place available[2] = 3
  remaining k = 14 % 6 = 2
  available: [1, 2, 4]

Step i=2: block = 2! = 2
  digit = 2 // 2 = 1   → place available[1] = 2
  remaining k = 2 % 2 = 0
  available: [1, 4]

Step i=1: block = 1! = 1
  digit = 0 // 1 = 0   → place available[0] = 1
  remaining k = 0 % 1 = 0
  available: [4]

Step i=0: block = 0! = 1
  digit = 0 // 1 = 0   → place available[0] = 4
  available: []

Result: [3, 2, 1, 4]

Verification: permutations of {1,2,3,4} starting with 1: ranks 0-5
                                             starting with 2: ranks 6-11
                                             starting with 3: ranks 12-17
rank 14 → third group (starts with 3) → within that: rank 14-12=2
  sub-perms of {1,2,4} rank 2: {2,1,4} → [3,2,1,4] ✓
```

## 7. Common Variations & Extensions

**Lexicographically smallest permutation satisfying a constraint.** A common contest pattern: given a permutation, apply a set of swaps to produce the lexicographically smallest result. Greedy approach: from left to right, find the smallest element achievable at each position via an allowed operation. This is a direct application of lex-min-first greedy — always commit to the smallest valid choice at each position, then recurse.

**Lexicographic order on strings with a non-standard alphabet ordering.** If the problem defines a custom alphabet order (e.g., "aeiou" < "bcdfg..."), the comparison function changes but the structure does not. Implement by mapping each character to its rank in the custom ordering, then compare numerically. This appears in problems like "sort words according to an alien dictionary order" (LC 953).

**Ranking permutations with duplicates: multinomial rank.** If the sequence has repeated elements, the total number of distinct permutations is n!/(n₁! × n₂! × ... × nₖ!) and the rank computation must account for multiplicities. The formula sums, at each position, the number of permutations with a smaller element placed there, divided by the appropriate factorial for remaining duplicates.

**Next subset in lex order (Gray code-adjacent subset enumeration).** Enumerating subsets in lex order is equivalent to counting in binary from 0 to 2ⁿ−1. But a different natural order is the **binary-reflected Gray code**, where consecutive subsets differ by exactly one element (one bit flip). This minimises "transition cost" between successive subsets and is useful when each evaluation is expensive and you want to reuse computation between adjacent subsets. The Gray code sequence for n=3: 000, 001, 011, 010, 110, 111, 101, 100.

## 9. CP Contest Application

**The lex-greedy pattern** — used when the answer is "the lexicographically smallest X satisfying property P":

```python
# Template: greedy lex-min construction
result = []
for position in range(target_length):
    for candidate in sorted(available_choices):   # try smallest first
        if is_valid(result + [candidate], remaining_positions):
            result.append(candidate)
            update_state(candidate)
            break   # commit to smallest valid choice, move to next position
```

This works because lex order is defined position by position from left to right — committing to the smallest valid element at position 0 guarantees the result starts with the smallest possible prefix, regardless of what comes after. Then repeat for position 1, and so on.

**Combinatorial ranking in contest problems:** Problems asking for the k-th combination or permutation among up to 10¹⁸ sequences require 64-bit integers for k and careful overflow handling in C++. Use `__int128` or precomputed binomial coefficients with early clamping when counts exceed the target k (no need to compute C(100,50) exactly if k < 10⁹ — just check if count > k and move on).

```cpp
// Safe comb for ranking — clamp to avoid overflow
long long safe_comb(int n, int r, long long limit) {
    if (r < 0 || r > n) return 0;
    long long result = 1;
    for (int i = 0; i < std::min(r, n-r); ++i) {
        result = result / (i+1) * (n-i) + result % (i+1) * (n-i) / (i+1);
        if (result >= limit) return limit;   // clamp — we only need > or < comparison
    }
    return result;
}
```
