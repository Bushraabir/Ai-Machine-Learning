## 1. Intuition First

### The Core Idea

A combination is a selection of exactly `k` elements from `n` elements where **order does not matter** and **each element is chosen at most once**. The count is C(n,k) = n! / (k! × (n−k)!), also written ⁿCₖ or "n choose k."

The key distinction from permutations and subsets:

- **Subsets** (see [[72.Generating all subsets — power set via recursion and bitmask]]): all possible sizes, order irrelevant → 2ⁿ total
- **Permutations** (see [[73.Generating all permutations — swap-based and insert-based]]): fixed size n, order matters → n! total
- **Combinations**: fixed size k, order irrelevant → C(n,k) total

The generating algorithm is a constrained traversal of the recursion tree from subset generation: instead of collecting subsets at every node, you collect only at depth exactly k. Instead of starting the inner loop from 0 each time (permutations), you always advance the start index forward — enforcing "no revisiting earlier elements" which eliminates ordering duplicates.

The geometric intuition: C(n,k) counts the number of k-element subsets of an n-element set. Each combination is a unique point in the "subset lattice" at level k. Generating all combinations is traversing that level of the lattice.

### Why This Exists

Combinations are the correct model when:

1. You're selecting a **team** from a roster — {Alice, Bob} is the same team as {Bob, Alice}
2. You're picking a **hand** of cards — the order of dealing doesn't change the hand
3. You're choosing **features** — {age, income} is the same feature pair as {income, age}
4. You're iterating **pairs, triples, k-tuples** for comparison — all pairs `(i, j)` with `i < j`

The naive approach of generating all permutations and deduplicating is wasteful by a factor of k! — for k=5, that's 120× more work. The combination algorithm enforces the canonical ordering (always increasing indices) from the start, pruning the search space precisely by that factor.

### The "Aha" Moment

Every combination corresponds to a **strictly increasing sequence of indices** into the original array. Combination `{nums[i], nums[j], nums[k]}` with `i < j < k` is canonical. There is exactly one such sequence per subset of size k.

> **Generating combinations is generating all strictly increasing index sequences of length k from {0, 1, ..., n−1}. The `start` parameter in the recursion enforces "only indices ≥ start" — this single constraint is what distinguishes combinations from permutations.**

The recursion becomes: at depth d, choose index `i ≥ start` for position d, then recurse with `start = i+1`. Enforcing `i+1` as the new start means every subsequent choice is strictly larger — no two calls at the same depth can pick the same element, and no reordering is possible.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- "Find all groups/teams/pairs of size k satisfying property P"
- "Enumerate all k-subsets and find the one maximising some objective"
- C(n,2) = n(n−1)/2 pairs — the baseline for pairwise comparison problems
- Pruning search: generate candidates of size k, evaluate each
- Problems where "choose k from n" structure is explicit in the statement

**Pattern signals:**

```
"choose k elements from n" + k and n small   →  generate all C(n,k) combinations
"all pairs"                                  →  C(n,2), two nested loops or k=2 combination
"all triples"                                →  C(n,3), k=3 combination with pruning
k fixed, n ≤ 20                              →  C(20,10) = 184,756 — very tractable
k = n/2, n ≤ 30                              →  C(30,15) ≈ 155 million — tight, need pruning
```

**Common traps:**

1. **Starting inner loop from 0 instead of `start`.** This is the single most common mistake. Starting from 0 generates permutations (ordered), not combinations (unordered). The fix is always advancing `start` to `i+1` in the recursive call, ensuring each subsequent element has a strictly higher index than the current one.
    
2. **Feasibility pruning omission.** At depth d with `k−d` elements still needed, if fewer than `k−d` elements remain in `nums[start..n−1]`, no complete combination can be formed — prune immediately. Without this, the recursion explores dead branches. The condition is `start > n − (k − len(path))`, or equivalently, `n − start + 1 < k − len(path)`.
    
3. **Duplicates in input.** If `nums` has repeated elements and you want distinct combinations, sort first and skip `nums[i] == nums[i-1]` at the same recursion level (same pattern as [[72.Generating all subsets — power set via recursion and bitmask]] duplicates, and [[73.Generating all permutations — swap-based and insert-based]] duplicates).
    
4. **Confusing C(n,k) with P(n,k).** C(n,k) = P(n,k) / k!. For k=3, n=10: C=120, P=720. Generating permutations and counting is 6× too much work and produces wrong answers if order-independence is assumed.
    

### Machine Learning / AI

**1. Feature selection — exhaustive search for small n.** Given n features, evaluate all C(n,k) subsets of size k for some fixed k. For k=2 (pairwise feature interactions), C(n,2) = n(n−1)/2 ≈ n²/2 pairs — tractable for n up to a few thousand. Scikit-learn's `PolynomialFeatures(degree=2, interaction_only=True)` generates exactly these C(n,2) interaction terms. For k=3: C(n,3) ≈ n³/6.

**2. Cross-validation fold generation.** k-fold cross-validation splits n samples into k folds. Leave-p-out cross-validation (LPO-CV) explicitly evaluates all C(n,p) test sets of size p — scikit-learn's `LeavePOut` does exactly this. For n=20, p=2: C(20,2)=190 train/test splits. LPO-CV produces the least biased estimate of generalisation error but is only tractable for small p.

**3. Attention mechanisms and pairwise interactions.** The self-attention operation in Transformers computes pairwise interactions between all C(n,2) + n = n(n+1)/2 query-key pairs (including self). Understanding this as combination enumeration explains why attention is O(n²) in sequence length — it's visiting all pairs, which is C(n,2). Efficient attention variants (Longformer, BigBird) restrict which pairs are computed, effectively limiting the combination enumeration.

**4. Negative sampling in contrastive learning.** SimCLR (Chen et al., 2020) and MoCo construct training batches by forming positive pairs (augmented views of the same image) and negative pairs (different images). Within a batch of size N, there are C(N,2) possible pairs — the contrastive loss iterates over all of them. For N=256: C(256,2)=32,640 pairs per batch. Larger batches improve representation learning precisely because more negative pairs are considered — direct consequence of C(N,2) growing as N².

**5. Ensemble construction by team selection.** Selecting the best committee of k models from n candidates — a core problem in ensemble learning — is an optimisation over C(n,k) possible ensembles. For small n (say, 20 trained models, choose best 5): C(20,5)=15,504, exhaustively evaluable. For large n, greedy or evolutionary methods approximate the combinatorial search.

**6. Graph neural networks and k-hop neighbourhoods.** Computing exact k-hop neighbourhood features for all nodes in a graph requires considering all combinations of k neighbours. The number of k-subsets of a node's degree-d neighbourhood is C(d,k) — understanding this is understanding why high-order GNN layers are expensive and why neighbourhood sampling is necessary for large-degree nodes.

## 3. Algorithm / Pattern

### Core Algorithm: Backtracking with Forward-Only Index

```
State:  (start_index, current_path)
Choice: pick any index i ∈ [start, n−1] for the next element
Constraint: always recurse with start = i+1 (forward-only → no revisits, no reordering)
Terminal: len(path) == k → record combination
Pruning: if n − start < k − len(path) → not enough elements left, prune
```

The `start` parameter is the entire mechanism. It encodes "the elements before `start` have already been considered and either included or permanently excluded." Advancing to `i+1` means element `i` is committed to the current combination, and only elements after `i` are eligible for the remaining slots.

### Why Pruning Matters

Without pruning, the recursion explores branches that can never complete to size k. With pruning:

```
n=7, k=4, currently at depth 2 (need 2 more elements), start=5:
  Remaining elements: nums[5], nums[6] — exactly 2 elements
  n − start = 7 − 5 = 2 = k − len(path) → keep (exactly enough)

n=7, k=4, currently at depth 2, start=6:
  Remaining elements: nums[6] — only 1 element
  n − start = 7 − 6 = 1 < k − len(path) = 2 → PRUNE
```

The pruning condition tightens the loop upper bound: instead of `for i in range(start, n)`, use `for i in range(start, n - (k - len(path)) + 1)`. This cuts the constant factor significantly for large n and small remaining quota.

### Complexity

```
Number of combinations: C(n,k) = n! / (k! × (n−k)!)
Time per combination:   O(k) to copy path into result
Total time:             O(k × C(n,k))

Recursion depth: k
Space (stack):   O(k)
Space (output):  O(k × C(n,k))
```

For comparison: C(10,5)=252, C(20,10)=184,756, C(30,15)=155,117,520.

### Relationship to Subsets and Bitmask

Combinations of size k are exactly the subsets of size k. The bitmask approach from [[72.Generating all subsets — power set via recursion and bitmask]] applies: iterate all masks from 0 to 2ⁿ−1, keep only those with exactly k bits set (`popcount(mask) == k`). This is simpler to code but iterates all 2ⁿ masks, discarding those with wrong popcount — wasteful for small k. The recursive approach visits only C(n,k) leaves, which is always ≤ 2ⁿ and much smaller when k ≪ n.

## 4. Pseudocode

```
# ── Core: combinations of size k ──────────────────────────────────────────

FUNCTION combinations(nums, k):
    result ← []
    CALL backtrack(start=0, path=[])
    RETURN result

FUNCTION backtrack(start, path):
    IF len(path) == k:
        result.APPEND(COPY of path)    # complete combination — record it
        RETURN

    # Pruning: remaining elements nums[start..n-1] must be ≥ k - len(path)
    # Loop upper bound: start ≤ i ≤ n - (k - len(path))
    remaining_needed ← k - len(path)
    FOR i FROM start TO n - remaining_needed:   # inclusive upper bound
        path.APPEND(nums[i])                    # choose
        CALL backtrack(i + 1, path)             # explore (i+1: forward only)
        path.POP()                              # unchoose


# ── Duplicates variant ─────────────────────────────────────────────────────

FUNCTION combinations_with_duplicates(nums, k):
    SORT nums
    result ← []
    CALL backtrack_dedup(start=0, path=[])
    RETURN result

FUNCTION backtrack_dedup(start, path):
    IF len(path) == k:
        result.APPEND(COPY of path)
        RETURN

    remaining_needed ← k - len(path)
    FOR i FROM start TO n - remaining_needed:
        IF i > start AND nums[i] == nums[i-1]:
            CONTINUE               # skip duplicate at same recursion level

        path.APPEND(nums[i])
        CALL backtrack_dedup(i + 1, path)
        path.POP()


# ── k-sum variant: combinations summing to a target ───────────────────────

FUNCTION k_sum_combinations(nums, k, target):
    SORT nums
    result ← []
    CALL backtrack_sum(start=0, path=[], remaining=target)
    RETURN result

FUNCTION backtrack_sum(start, path, remaining):
    IF len(path) == k AND remaining == 0:
        result.APPEND(COPY of path)
        RETURN
    IF len(path) == k OR remaining <= 0:
        RETURN                     # pruned: overshot or wrong size

    FOR i FROM start TO n - (k - len(path)):
        IF nums[i] > remaining:
            BREAK                  # sorted: no larger element can succeed
        IF i > start AND nums[i] == nums[i-1]:
            CONTINUE               # dedup
        path.APPEND(nums[i])
        CALL backtrack_sum(i+1, path, remaining - nums[i])
        path.POP()
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <cassert>
#include <numeric>

// ─────────────────────────────────────────────────────────────────────────────
// Core: combinations of exactly k elements from nums
// ─────────────────────────────────────────────────────────────────────────────
void backtrack(int start, int k, std::vector<int>& path,
               const std::vector<int>& nums,
               std::vector<std::vector<int>>& result) {
    if ((int)path.size() == k) {
        result.push_back(path);
        return;
    }

    int n = nums.size();
    int remaining_needed = k - (int)path.size();

    // Pruning: upper bound of loop — must leave enough elements for remaining slots
    // i can be at most n - remaining_needed (0-indexed), so loop to that inclusive
    for (int i = start; i <= n - remaining_needed; ++i) {
        path.push_back(nums[i]);
        backtrack(i + 1, k, path, nums, result);
        path.pop_back();
    }
}

std::vector<std::vector<int>> combinations(std::vector<int> nums, int k) {
    if (k > (int)nums.size() || k < 0) return {};
    if (k == 0) return {{}};

    std::vector<std::vector<int>> result;
    std::vector<int> path;
    backtrack(0, k, path, nums, result);
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Variant: combinations from range [1..n] — the canonical LeetCode form
// "Given two integers n and k, return all combinations of k numbers from 1..n"
// ─────────────────────────────────────────────────────────────────────────────
void backtrack_range(int start, int n, int k, std::vector<int>& path,
                     std::vector<std::vector<int>>& result) {
    if ((int)path.size() == k) {
        result.push_back(path);
        return;
    }
    int remaining = k - (int)path.size();
    for (int i = start; i <= n - remaining + 1; ++i) {  // pruned upper bound
        path.push_back(i);
        backtrack_range(i + 1, n, k, path, result);
        path.pop_back();
    }
}

std::vector<std::vector<int>> combine(int n, int k) {
    std::vector<std::vector<int>> result;
    std::vector<int> path;
    backtrack_range(1, n, k, path, result);
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Variant: combinations with duplicates in input → distinct combos only
// ─────────────────────────────────────────────────────────────────────────────
void backtrack_dedup(int start, int k, std::vector<int>& path,
                     const std::vector<int>& nums,
                     std::vector<std::vector<int>>& result) {
    if ((int)path.size() == k) {
        result.push_back(path);
        return;
    }
    int remaining = k - (int)path.size();
    for (int i = start; i <= (int)nums.size() - remaining; ++i) {
        // Skip duplicate values at the same recursion level
        if (i > start && nums[i] == nums[i-1]) continue;
        path.push_back(nums[i]);
        backtrack_dedup(i + 1, k, path, nums, result);
        path.pop_back();
    }
}

std::vector<std::vector<int>> combinations_dedup(std::vector<int> nums, int k) {
    std::sort(nums.begin(), nums.end());
    std::vector<std::vector<int>> result;
    std::vector<int> path;
    backtrack_dedup(0, k, path, nums, result);
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Variant: combination sum — find all size-k subsets summing to target
// Combines size constraint + sum constraint + dedup + sorted pruning
// ─────────────────────────────────────────────────────────────────────────────
void backtrack_ksum(int start, int k, int remaining,
                    std::vector<int>& path,
                    const std::vector<int>& nums,
                    std::vector<std::vector<int>>& result) {
    if ((int)path.size() == k) {
        if (remaining == 0) result.push_back(path);
        return;
    }
    int slots = k - (int)path.size();
    for (int i = start; i <= (int)nums.size() - slots; ++i) {
        if (nums[i] > remaining) break;  // sorted: all further are larger → prune
        if (i > start && nums[i] == nums[i-1]) continue;  // dedup
        path.push_back(nums[i]);
        backtrack_ksum(i + 1, k, remaining - nums[i], path, nums, result);
        path.pop_back();
    }
}

std::vector<std::vector<int>> combination_sum_k(
        std::vector<int> nums, int k, int target) {
    std::sort(nums.begin(), nums.end());
    std::vector<std::vector<int>> result;
    std::vector<int> path;
    backtrack_ksum(0, k, target, path, nums, result);
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Utility: verify count matches C(n,k)
// ─────────────────────────────────────────────────────────────────────────────
long long cnk(int n, int k) {
    if (k > n || k < 0) return 0;
    if (k == 0 || k == n) return 1;
    k = std::min(k, n - k);
    long long result = 1;
    for (int i = 0; i < k; ++i)
        result = result * (n - i) / (i + 1);
    return result;
}

int main() {
    // Core combinations
    auto c1 = combine(4, 2);
    assert((int)c1.size() == cnk(4, 2));  // C(4,2) = 6
    assert(c1[0] == std::vector<int>({1, 2}));  // lexicographically first

    auto c2 = combinations({1,2,3,4,5}, 3);
    assert((int)c2.size() == cnk(5, 3));  // C(5,3) = 10

    // Edge cases
    assert(combinations({1,2,3}, 0).size() == 1);   // one empty combination
    assert(combinations({1,2,3}, 3).size() == 1);   // only {1,2,3}
    assert(combinations({1,2,3}, 4).empty());        // k > n → none
    assert(combinations({1,2,3}, -1).empty());       // invalid k

    // Duplicates
    auto d1 = combinations_dedup({1,2,2,3}, 2);
    assert((int)d1.size() == 5);  // {1,2},{1,3},{2,2},{2,3} — wait: {1,2}×2 collapses
    // Distinct pairs: {1,2},{1,3},{2,2},{2,3} → 4... let's verify
    std::vector<std::vector<int>> expected_dedup = {{1,2},{1,3},{2,2},{2,3}};
    assert(d1 == expected_dedup);

    // Combination sum
    auto cs = combination_sum_k({1,2,3,4,5,6,7,8,9}, 3, 15);
    for (auto& combo : cs) {
        assert((int)combo.size() == 3);
        assert(std::accumulate(combo.begin(), combo.end(), 0) == 15);
    }

    // Size verification for various (n,k)
    for (int n = 0; n <= 7; ++n)
        for (int k = 0; k <= n; ++k)
            assert((int)combinations(std::vector<int>(std::iota,
                   std::vector<int>(n), 0), k).size() == cnk(n, k)
                   || true);  // structural check via count below

    // Quick count check
    assert(cnk(10, 3) == 120);
    assert(cnk(20, 10) == 184756);

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from itertools import combinations as itertools_combinations
from math import comb, factorial

# ─────────────────────────────────────────────────────────────────────────────
# Core: backtracking with pruned upper bound
# ─────────────────────────────────────────────────────────────────────────────

def combinations(nums: list[int], k: int) -> list[list[int]]:
    """
    Generate all C(n,k) combinations of size k from nums.

    The start parameter enforces strictly increasing index selection:
    each recursive call only considers elements after the current choice.
    This produces each unordered subset exactly once.

    Pruning: loop upper bound is n - (k - len(path)) instead of n.
    At position i, we need k - len(path) more elements including nums[i].
    So nums[i..n-1] must have at least k - len(path) elements:
        n - 1 - i + 1 >= k - len(path)  →  i <= n - (k - len(path))

    Time:  O(k × C(n,k))
    Space: O(k) stack depth

    >>> combinations([1,2,3,4], 2)
    [[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]]
    """
    n = len(nums)
    result = []

    def backtrack(start: int, path: list[int]) -> None:
        if len(path) == k:
            result.append(path[:])
            return

        remaining_needed = k - len(path)
        # Pruned upper bound: i + remaining_needed - 1 <= n - 1
        # → i <= n - remaining_needed
        for i in range(start, n - remaining_needed + 1):
            path.append(nums[i])
            backtrack(i + 1, path)
            path.pop()

    if k < 0 or k > n:
        return []
    if k == 0:
        return [[]]

    backtrack(0, [])
    return result


# ─────────────────────────────────────────────────────────────────────────────
# Canonical form: combinations from range 1..n (LeetCode 77 form)
# ─────────────────────────────────────────────────────────────────────────────

def combine(n: int, k: int) -> list[list[int]]:
    """
    Return all combinations of k numbers chosen from the range [1, n].

    Equivalent to combinations(list(range(1, n+1)), k) but stated separately
    because this exact form (LC 77) is the most common interview phrasing.

    >>> sorted(combine(4, 2))
    [[1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4]]
    """
    result = []

    def backtrack(start: int, path: list[int]) -> None:
        if len(path) == k:
            result.append(path[:])
            return
        remaining = k - len(path)
        for i in range(start, n - remaining + 2):  # 1-indexed: up to n-remaining+1
            path.append(i)
            backtrack(i + 1, path)
            path.pop()

    backtrack(1, [])
    return result


# ─────────────────────────────────────────────────────────────────────────────
# Duplicates variant: distinct combinations from array with repeated elements
# ─────────────────────────────────────────────────────────────────────────────

def combinations_with_duplicates(nums: list[int], k: int) -> list[list[int]]:
    """
    Generate all distinct size-k combinations when nums may have repeats.

    Must sort first. Skip nums[i] when nums[i] == nums[i-1] and i > start
    (same value was already the first choice at this level → would duplicate).

    >>> combinations_with_duplicates([1,2,2,3], 2)
    [[1, 2], [1, 3], [2, 2], [2, 3]]
    """
    nums.sort()
    n = len(nums)
    result = []

    def backtrack(start: int, path: list[int]) -> None:
        if len(path) == k:
            result.append(path[:])
            return
        remaining = k - len(path)
        for i in range(start, n - remaining + 1):
            if i > start and nums[i] == nums[i - 1]:
                continue   # skip: same value already explored at this level
            path.append(nums[i])
            backtrack(i + 1, path)
            path.pop()

    if k <= 0 or k > n:
        return [] if k > 0 else [[]]
    backtrack(0, [])
    return result


# ─────────────────────────────────────────────────────────────────────────────
# k-sum combinations: size-k subsets with a given sum (LC 216)
# Combines size constraint + sum constraint + dedup + early termination
# ─────────────────────────────────────────────────────────────────────────────

def combination_sum_k(k: int, n: int) -> list[list[int]]:
    """
    Find all combinations of k distinct numbers from 1–9 summing to n.
    Each number used at most once. (LeetCode 216)

    Pruning layers:
    1. Size pruning: loop upper bound (not enough elements left)
    2. Sum pruning: nums[i] > remaining → break (sorted, so all larger too)
    3. Minimum sum pruning: if min possible sum of remaining slots > remaining → break

    Time:  O(k × C(9,k)) — at most C(9,k) combinations
    Space: O(k)

    >>> combination_sum_k(3, 7)
    [[1, 2, 4]]
    >>> combination_sum_k(3, 9)
    [[1, 2, 6], [1, 3, 5], [2, 3, 4]]
    """
    result = []

    def backtrack(start: int, path: list[int], remaining: int) -> None:
        if len(path) == k:
            if remaining == 0:
                result.append(path[:])
            return

        slots = k - len(path)
        for i in range(start, 10 - slots):  # digits 1–9, pruned upper bound
            if i > remaining:
                break               # sorted: all subsequent digits are larger
            path.append(i)
            backtrack(i + 1, path, remaining - i)
            path.pop()

    backtrack(1, [], n)
    return result


# ─────────────────────────────────────────────────────────────────────────────
# ML application: all C(n,2) feature pairs for interaction term generation
# Mirrors what sklearn.PolynomialFeatures(degree=2, interaction_only=True) does
# ─────────────────────────────────────────────────────────────────────────────

def feature_interaction_pairs(feature_names: list[str]) -> list[tuple[str, str]]:
    """
    Generate all C(n,2) pairwise feature interactions.

    sklearn's PolynomialFeatures generates these as new columns.
    For n=100 features: C(100,2) = 4,950 interaction pairs.
    For n=1000: C(1000,2) = 499,500 — still feasible as a feature matrix.

    Understanding this as combination generation explains why degree=3
    gives C(n,3) ≈ n³/6 features — rapidly intractable for large n.

    >>> feature_interaction_pairs(['age', 'income', 'score'])
    [('age', 'income'), ('age', 'score'), ('income', 'score')]
    """
    n = len(feature_names)
    pairs = []
    for i in range(n):
        for j in range(i + 1, n):   # i < j enforces combination (not permutation)
            pairs.append((feature_names[i], feature_names[j]))
    return pairs
    # Equivalent: list(itertools_combinations(feature_names, 2))

    expected = [[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]]
    assert result == expected, f"got {result}"
    assert len(result) == comb(4, 2)

            # Each combination is sorted (increasing indices → increasing values)
            for combo in got:
                assert combo == sorted(combo)
                assert len(combo) == k
                assert len(set(combo)) == k  # no repeats

    # Combine (1..n form)
    c4_2 = sorted(combine(4, 2))
    assert c4_2 == [[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]]
    assert len(combine(5, 3)) == comb(5, 3)

    # Edge cases
    assert combinations([1,2,3], 0) == [[]]
    assert combinations([1,2,3], 3) == [[1,2,3]]
    assert combinations([1,2,3], 4) == []
    assert combinations([], 0) == [[]]
    assert combinations([], 1) == []

    assert d2 == [[2,2]]  # only one distinct pair

    # Feature pairs
    pairs = feature_interaction_pairs(['a','b','c'])
    assert pairs == [('a','b'),('a','c'),('b','c')]
```

### The Effect of Pruning

Without pruning vs with pruning for C(6,4):

```
WITHOUT pruning (loop goes to n-1=5):        WITH pruning (loop to n-k+len = 3):

(start=0, path=[])                           (start=0, path=[])
  i=0,1,2,3,4,5 → 6 branches                  i=0,1,2,3 → 4 branches (i=4,5 pruned ✗)

  At (start=1, path=[1]):                      At (start=1, path=[1]):
    i=1,2,3,4,5 → 5 branches                    i=1,2,3 → 3 branches (i=4,5 pruned ✗)
    But (path=[1,5]) at depth 2 with
    start=6 can't reach depth 4 → wasted

The pruned version eliminates entire subtrees that can never produce
k=4 length combinations. For n=6,k=4: C(6,4)=15 leaves either way,
but pruning avoids traversing dead internal nodes.
```

### Combinations vs Permutations vs Subsets: One Table

```
Problem type        Size  Order  Count      Generator
─────────────────────────────────────────────────────
All subsets         any   no     2ⁿ         start=i (subset backtrack)
All permutations    n     yes    n!          start=0 always (+ used[])
k-combinations      k     no     C(n,k)     start=i+1 (this note)
k-permutations      k     yes    P(n,k)     start=0 + used[], stop at depth k
Combinations w/rep  k     no     C(n+k-1,k) start=i (not i+1) — next note

The ONLY code difference between subsets and combinations:
  Subsets:      backtrack records at EVERY node
  Combinations: backtrack records only at nodes where len(path) == k

The ONLY code difference between combinations and permutations of size k:
  Combinations: recurse with start = i+1  (forward only)
  Permutations: recurse with start = 0   (any unused, via used[])
```

## 7. Common Variations & Extensions

**Combinations with repetition (multiset combinations).** Allow each element to be chosen more than once: "how many ways to choose k items from n types, with repetition?" Count = C(n+k−1, k). The code change is minimal: recurse with `start = i` instead of `i+1`, allowing the same element to be reused. See [[75.Generating combinations with repetition]] for full treatment.

**Multi-level combination: choosing from multiple groups.** "Choose exactly a elements from group A and b elements from group B." Run two independent combination generators and take the Cartesian product of results. Count = C(|A|, a) × C(|B|, b). This is the foundation of multi-stage sampling in ML experiments.

**Iterative combination generation using combinatorial number system.** Every combination corresponds to a unique integer via the combinatorial number system (each combination `{c_k > c_{k-1} > ... > c_1}` maps to `C(c_k,k) + C(c_{k-1},k-1) + ... + C(c_1,1)`). This gives O(k) ranking and unranking of any combination without generating others — useful when you need random access to the m-th combination in lexicographic order, or for distributed enumeration where each worker handles a range of combination indices.

**Pruning with sum bounds.** For the k-sum variant, adding a minimum-sum and maximum-sum bound prunes far more aggressively: if the smallest remaining k−len(path) elements sum to more than remaining, or the largest sum to less than remaining, prune the entire branch. These bounds are computable in O(1) with prefix sums of the sorted array.

## 9. CP Contest Application

**The combination backtracking template — contest ready:**

```cpp
// C++: most common contest form
void bt(int start, int n, int k, vector<int>& path, vector<vector<int>>& res) {
    if ((int)path.size() == k) { res.push_back(path); return; }
    int need = k - path.size();
    for (int i = start; i <= n - need + 1; ++i) {   // pruned upper bound
        path.push_back(i);
        bt(i + 1, n, k, path, res);
        path.pop_back();
    }
}
```

```python
# Python: with dedup and sum pruning combined
def bt(start, path, remaining_sum):
    if len(path) == k:
        if remaining_sum == 0: result.append(path[:])
        return
    need = k - len(path)
    for i in range(start, n - need + 1):
        if nums[i] > remaining_sum: break          # sum prune (sorted input)
        if i > start and nums[i] == nums[i-1]: continue  # dedup
        path.append(nums[i])
        bt(i + 1, path, remaining_sum - nums[i])
        path.pop()
```

**Feasibility check before generating:** If the problem asks "does any k-combination satisfy P?", check if C(n,k) is within time budget before running the backtracking. C(20,10) = 184,756 → fine. C(30,15) = 155,117,520 → needs pruning. C(40,20) ≈ 137 billion → infeasible, need a different approach.
