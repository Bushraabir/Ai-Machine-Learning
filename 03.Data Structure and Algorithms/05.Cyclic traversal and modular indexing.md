## 1. Intuition First

### The Core Idea

A clock face has 12 positions. After position 12 comes position 1 — not position 13. The clock does not have an edge or a boundary in the way a ruler does. It wraps. Any position on the clock can be described as `(current_position + steps) mod 12`, and this formula works whether you move forward one tick or forward one thousand ticks. The modulo operation is what converts unbounded linear progress into bounded circular position.

This is cyclic traversal: treating a finite linear array as if its last element connects back to its first. Index `n` wraps to index `0`, index `n+1` wraps to `1`, and index `-1` wraps to `n-1`. The mechanism is always the same operation:

$$\text{circular_index}(i) = \left((i\ %\ n) + n\right)\ %\ n$$

The double-mod `((i % n) + n) % n` handles both positive and negative `i` correctly in languages where `%` can return negative values for negative operands (C++, Java). In Python, `i % n` is always non-negative for positive `n`, so the single form suffices.

The deeper idea: **modular indexing is a coordinate transformation**. It maps the infinite integer line onto a finite ring of size `n`. Any algorithm that works on the infinite line can be made to work on the ring by composing every index access with this transformation. The ring does not have a start or an end — only a size.

### Why This Exists

Many real problems are inherently circular: tasks in a round-robin scheduler, positions in a ring buffer, elements in a rotating array, nodes in a circular linked list, days of the week, positions on a circular track. Representing these with a linear array creates an artificial boundary at index 0 and index n-1 that does not exist in the problem domain. Cyclic traversal eliminates this artificial boundary.

Without modular indexing, every algorithm that touches the boundary needs a special case: "if `i == n-1`, the next element is at index `0`, not index `n`." With modular indexing, `next = (i + 1) % n` — uniform, no branch, correct at every position including the boundary.

The complexity change is not in asymptotic time — it is in code correctness and branch elimination. A circular buffer with a mishandled wraparound fails silently on exactly the inputs that hit the boundary, which are often the least-tested.

### The "Aha" Moment

> **Modular indexing does not change the algorithm — it changes the address space. Every index access `a[i]` becomes `a[i % n]`, and the algorithm runs on a ring instead of a line. The algorithm itself needs no other modification.**

Once you see this, the implementation strategy for any "circular" problem becomes mechanical: write the linear version, replace every bare index `i` with `i % n`, double-check that `i` can grow beyond `n` (extend the loop if needed), and handle the no-copy vs copy tradeoff depending on whether the problem allows it.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Cyclic traversal is signalled by any problem where elements "wrap around," indices repeat, or the structure is described as circular, rotating, or periodic:

- "Array is rotated k times" → index `i` maps to original index `(i + k) % n`
- "Circular array, next of last is first" → `next[i] = (i + 1) % n`
- "Find next greater element in circular array" → traverse `2n` positions using `i % n`
- "Josephus problem, every k-th person eliminated" → `(current + k - 1) % remaining`
- "Task scheduler, round-robin" → slot `i` assigned to task `i % num_tasks`
- "Maximum sum circular subarray" → the circular extension of Kadane's (see [[167.Maximum subarray — Kadane's algorithm and its DP interpretation]])

**Pattern signal → decision rule:**

```
Does the problem say "circular," "rotating," "wraps around," or "next of last is first"?
  └── Yes → Cyclic traversal
        ├── Need to traverse all n elements starting from any position?
        │     └── Loop i from start to start+n, access a[i % n]
        ├── Need next/previous element with wraparound?
        │     └── next = (i+1) % n,  prev = (i-1+n) % n
        └── Need to "unroll" the circle for a linear algorithm?
              └── Duplicate the array: b = a + a, run linear algorithm on b[0..2n-1]
```

**Common trap 1 — negative modulo in C++:** `(-1) % n` in C++ is implementation-defined before C++11 and `-1` (not `n-1`) from C++11 onward. The safe formula for any signed integer `i` is `((i % n) + n) % n`. Forgetting this causes index `-1` to be used as a real array index — an out-of-bounds access. Python does not have this problem: `-1 % 5 == 4` always.

**Common trap 2 — forgetting to extend the loop for circular traversal:** To visit all elements starting from position `start` in a circular array, the loop must run `n` iterations, not until `i == n`. The correct loop: `for i in range(start, start + n)`, accessing `a[i % n]`. Running only until `i < n` means elements before `start` are never visited.

**Common trap 3 — the duplication trick introduces O(n) extra space:** Duplicating the array (`b = a + a`) makes a circular problem linear but uses O(n) extra space. For problems with tight memory limits, the explicit modular index `a[i % n]` is the O(1)-space alternative.

### Machine Learning / AI

**1. Circular / ring buffers in data streaming pipelines.** In online learning and real-time inference, data arrives as a continuous stream. A ring buffer of size `k` stores the last `k` elements without ever allocating more memory. The write pointer advances as `write_ptr = (write_ptr + 1) % k` after each write. Reading the last `k` elements traverses from `(write_ptr - k + k) % k` to `write_ptr - 1`. This is exactly cyclic traversal, and it is the implementation of `collections.deque(maxlen=k)` in Python — which uses a ring buffer internally. In PyTorch's `DataLoader` with `prefetch_factor`, the prefetch queue is a ring buffer. See [[220.Data pipeline design — streaming vs batch, shuffling, prefetching]].

**2. Positional encodings in Transformers — periodic signals.** The sinusoidal positional encodings introduced in "Attention Is All You Need" (Vaswani et al., 2017) are:

$$PE(pos, 2i) = \sin!\left(\frac{pos}{10000^{2i/d}}\right), \quad PE(pos, 2i+1) = \cos!\left(\frac{pos}{10000^{2i/d}}\right)$$

These are periodic functions — they are the continuous analogue of modular indexing. The intuition is identical: position is represented not as a single integer but as a point on multiple rings of different frequencies. RoPE (Rotary Position Embedding, Su et al., 2021), used in LLaMA and Mistral, makes this even more explicit: token positions are encoded as rotations in 2D planes, and composing rotations is the continuous version of `(i + k) % n`. Understanding cyclic traversal makes positional encoding design intuitive rather than mysterious.

**3. Convolutional padding modes — `circular` padding.** PyTorch's `torch.nn.Conv1d` and `Conv2d` support `padding_mode='circular'`. This treats the input as a ring: the padding on the left of the tensor is filled with the rightmost elements of the input, and vice versa. This is used for processing signals that are inherently periodic (audio, certain physics simulations), where zero-padding or reflect-padding would introduce artificial discontinuities at the boundary. The implementation is `torch.roll` (a cyclic shift) applied before convolution. Understanding that `roll(x, k)` is equivalent to accessing `x[(i - k) % n]` for each index is the algorithmic foundation.

**4. Hash table open addressing — linear probing with wraparound.** When a hash table uses open addressing (no chaining), inserting a key that collides at slot `h` probes slots `h, h+1, h+2, ...` until an empty slot is found. The probe sequence wraps around: slot `(h + step) % capacity`. This is cyclic traversal of the hash table's backing array. Without modular indexing, the probe sequence would walk off the end of the array. See [[32.Collision resolution — chaining vs open addressing]].

## 3. Algorithm / Pattern

### The Five Core Patterns

**Pattern 1 — Next/Previous with wraparound (O(1) per query):**

```
next(i)     = (i + 1) % n
prev(i)     = (i - 1 + n) % n      ← +n before % to avoid negative result
advance(i,k)= (i + k) % n
retreat(i,k)= (i - k % n + n) % n  ← normalise k first, then add n
```

**Pattern 2 — Full circular traversal starting at position s (O(n) total):**

```
for step in range(n):
    i = (s + step) % n
    process(a[i])
```

**Pattern 3 — Array duplication trick (converts circular to linear, O(n) space):**

```
b = a + a                    ← length 2n
# Now any subarray of a[] that wraps around corresponds to a
# contiguous subarray of b[] within b[0..2n-1].
run_linear_algorithm(b)
```

**Pattern 4 — Rotation by reversal (O(n) time, O(1) space):**

```
# Rotate right by k: a[i] goes to position (i + k) % n
# Equivalently: last k elements move to front.
k = k % n                    ← normalise
reverse(a, 0, n-1)
reverse(a, 0, k-1)
reverse(a, k, n-1)
# See [[03.In-place modification — overwriting the input array]] for derivation
```

**Pattern 5 — Cycle following (for permutation problems):**

```
# Given a permutation where a[i] says "element i maps to position a[i],"
# follow the cycle: start at i, go to a[i], then a[a[i]], etc.
visited = [False] * n
for start in range(n):
    if not visited[start]:
        i = start
        while not visited[i]:
            visited[i] = True
            i = a[i]            ← follow the permutation, wraps naturally
```

### Complexity

**Time:** O(1) per modular index operation. O(n) for a full circular traversal. No asymptotic overhead versus linear traversal.

**Space:** O(1) auxiliary for patterns 1, 2, 4, 5. O(n) for pattern 3 (duplication).

**When to use duplication (Pattern 3) vs modular indexing (Pattern 2):**

|Criterion|Use duplication|Use modular index|
|---|---|---|
|Algorithm requires contiguous subarray|✓ (e.g., sliding window)|✗|
|Memory is tight|✗|✓|
|Multiple passes needed|Saves recomputing `% n` each time|Simpler code|
|Problem constraint: no extra space|✗|✓|

## 4. Pseudocode

```
// ─── Pattern 2: Next Greater Element in Circular Array ───────────────────
// For each element, find the next element in circular order that is greater.
// Traverse 2n positions (two loops around the circle) using i % n.

function next_greater_circular(a[0..n-1]) → result[0..n-1]:
    result ← array of n values, all initialised to −1
    stack  ← empty stack          // stores indices, not values

    for i from 0 to 2n-1:         // two full traversals
        idx ← i % n               // circular index

        // Resolve all stack entries for which a[idx] is the answer
        while stack is not empty and a[stack.top()] < a[idx]:
            result[stack.pop()] ← a[idx]

        // Only push during the first traversal
        // (second traversal only resolves, never adds new queries)
        if i < n:
            stack.push(idx)

    return result


// ─── Pattern 3: Maximum Sum Circular Subarray via Duplication ────────────
// Reduces circular problem to linear by doubling the array.
// Then slide a window of maximum size n over the 2n array.
// (Preferred: see the direct formula in [[167.Maximum subarray]])

function max_circular_sum_naive(a[0..n-1]) → max_sum:
    b ← a concatenated with a     // length 2n
    // Run a sliding window of max size n using a deque for window max sum
    // This is O(n) but O(n) space. See the cleaner total-minus-min approach.
    return sliding_window_max_sum(b, max_window_size=n)


// ─── Pattern 5: Rotate Array in Place ────────────────────────────────────
// Rotate right by k using cyclic replacement: follow each cycle of the permutation.

function rotate_cyclic(a[0..n-1], k):
    k   ← k % n
    if k == 0: return

    count ← 0           // total elements placed correctly
    start ← 0

    while count < n:
        current ← start
        prev    ← a[start]

        repeat:
            next_idx    ← (current + k) % n
            temp        ← a[next_idx]
            a[next_idx] ← prev
            prev        ← temp
            current     ← next_idx
            count       ← count + 1
        until current == start   // completed one cycle

        start ← start + 1       // move to next cycle start


// ─── Ring Buffer: Enqueue and Dequeue ────────────────────────────────────

struct RingBuffer(capacity):
    data  ← array of size capacity
    head  ← 0        // index of oldest element (next to dequeue)
    tail  ← 0        // index of next write position
    size  ← 0

    function enqueue(val):
        if size == capacity: error "buffer full"
        data[tail] ← val
        tail  ← (tail + 1) % capacity
        size  ← size + 1

    function dequeue() → val:
        if size == 0: error "buffer empty"
        val  ← data[head]
        head ← (head + 1) % capacity
        size ← size − 1
        return val
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ─────────────────────────────────────────────────────────────────────────────
// Safe modular index — handles negative i correctly in C++.
// Use this whenever i might be negative (e.g., prev pointer).
// ─────────────────────────────────────────────────────────────────────────────
inline int mod_idx(int i, int n) {
    return ((i % n) + n) % n;
}

// ─────────────────────────────────────────────────────────────────────────────
// Next Greater Element II — Circular Array (LeetCode 503)
// For each element a[i], find the next element (circularly) that is greater.
// Uses monotonic stack + 2n traversal with i % n.
// O(n) time, O(n) space.
// ─────────────────────────────────────────────────────────────────────────────
vector<int> next_greater_circular(const vector<int>& a) {
    int n = a.size();
    vector<int> result(n, -1);
    stack<int> st;              // stores indices

    for (int i = 0; i < 2 * n; ++i) {
        int idx = i % n;

        // Pop elements for which a[idx] is the "next greater"
        while (!st.empty() && a[st.top()] < a[idx]) {
            result[st.top()] = a[idx];
            st.pop();
        }

        // Only push during the first traversal (i < n)
        // Second traversal exists only to resolve remaining stack elements.
        if (i < n) st.push(idx);
    }
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Ring Buffer — fixed-capacity circular queue.
// Uses head/tail pointers with modular advance.
// O(1) enqueue, dequeue, peek.
// ─────────────────────────────────────────────────────────────────────────────
template<typename T>
class RingBuffer {
    vector<T> data;
    int head = 0;   // index of oldest element (next dequeue)
    int tail = 0;   // index of next write slot
    int sz   = 0;
    int cap;

public:
    explicit RingBuffer(int capacity) : data(capacity), cap(capacity) {}

    void enqueue(T val) {
        if (sz == cap) throw runtime_error("Buffer full");
        data[tail] = val;
        tail = (tail + 1) % cap;    // cyclic advance
        ++sz;
    }

    T dequeue() {
        if (sz == 0) throw runtime_error("Buffer empty");
        T val = data[head];
        head = (head + 1) % cap;    // cyclic advance
        --sz;
        return val;
    }

    T peek() const {
        if (sz == 0) throw runtime_error("Buffer empty");
        return data[head];
    }

    // Access element k steps from head (0 = oldest, sz-1 = newest)
    T at(int k) const {
        if (k < 0 || k >= sz) throw out_of_range("Index out of range");
        return data[(head + k) % cap];   // cyclic index from head
    }

    int size()     const { return sz; }
    bool empty()   const { return sz == 0; }
    bool full()    const { return sz == cap; }
};

// ─────────────────────────────────────────────────────────────────────────────
// Rotate Array — cyclic replacement method.
// O(n) time, O(1) space. Follows each permutation cycle.
// ─────────────────────────────────────────────────────────────────────────────
void rotate_cyclic(vector<int>& a, int k) {
    int n = a.size();
    k %= n;
    if (k == 0) return;

    int count = 0;          // total elements placed in their final position
    int start = 0;

    while (count < n) {
        int current = start;
        int prev    = a[start];

        do {
            int next_idx    = (current + k) % n;
            int temp        = a[next_idx];
            a[next_idx]     = prev;
            prev            = temp;
            current         = next_idx;
            ++count;
        } while (current != start);    // completed this cycle

        ++start;    // next cycle begins at start+1
    }
}

// ─────────────────────────────────────────────────────────────────────────────
// Josephus Problem — every k-th person eliminated from a circle of n.
// Returns 0-indexed position of the survivor.
// Recurrence: f(n,k) = (f(n-1,k) + k) % n,  f(1,k) = 0
// O(n) time, O(1) space.
// ─────────────────────────────────────────────────────────────────────────────
int josephus(int n, int k) {
    int pos = 0;                // survivor position in group of 1
    for (int i = 2; i <= n; ++i) {
        pos = (pos + k) % i;   // extend to group of i: shift position by k, wrap
    }
    return pos;                 // 0-indexed
}

// ─────────────────────────────────────────────────────────────────────────────
// Test driver
// ─────────────────────────────────────────────────────────────────────────────
int main() {
    // mod_idx — negative index handling
    assert(mod_idx(-1, 5) == 4);
    assert(mod_idx(-6, 5) == 4);
    assert(mod_idx( 7, 5) == 2);

    // next_greater_circular
    auto r1 = next_greater_circular({1, 2, 1});
    assert((r1 == vector<int>{2, -1, 2}));

    auto r2 = next_greater_circular({5, 4, 3, 2, 1});
    assert((r2 == vector<int>{-1, 5, 5, 5, 5}));

    // RingBuffer
    RingBuffer<int> rb(3);
    rb.enqueue(10); rb.enqueue(20); rb.enqueue(30);
    assert(rb.full());
    assert(rb.at(0) == 10 && rb.at(2) == 30);
    assert(rb.dequeue() == 10);
    rb.enqueue(40);
    assert(rb.at(0) == 20 && rb.at(2) == 40);
    assert(rb.dequeue() == 20);
    assert(rb.dequeue() == 30);
    assert(rb.dequeue() == 40);
    assert(rb.empty());

    // rotate_cyclic
    vector<int> a = {1, 2, 3, 4, 5, 6, 7};
    rotate_cyclic(a, 3);
    assert((a == vector<int>{5, 6, 7, 1, 2, 3, 4}));

    vector<int> b = {-1, -100, 3, 99};
    rotate_cyclic(b, 2);
    assert((b == vector<int>{3, 99, -1, -100}));

    // Josephus
    assert(josephus(7, 3) == 3);    // 0-indexed: survivor is person 4 (1-indexed)
    assert(josephus(1, 1) == 0);
    assert(josephus(6, 2) == 4);

    cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from collections import deque
from typing import TypeVar, Generic, Optional

T = TypeVar('T')


# ─── Modular index (Python: % is always non-negative for positive n) ──────────
def mod_idx(i: int, n: int) -> int:
    """
    Safe circular index. In Python, i % n is always in [0, n-1] for n > 0,
    so this is just i % n. Provided for explicitness and C++ parity.
    """
    return i % n     # Python's % handles negatives correctly: -1 % 5 == 4


# ─── Next Greater Element II — Circular (LeetCode 503) ───────────────────────

def next_greater_circular(a: list[int]) -> list[int]:
    """
    For each element, find the next greater element in circular order.
    Returns -1 if no greater element exists (only possible for the global max).

    Key insight: traverse 2n positions (i = 0..2n-1), access a[i % n].
    This simulates two trips around the circle, which is sufficient because
    any element's "next greater" is within n steps of it.

    First traversal (i < n):  push indices onto the monotonic stack.
    Second traversal (i >= n): only resolve remaining stack entries, don't push.

    Time:  O(n)
    Space: O(n) for the stack and result
    """
    n      = len(a)
    result = [-1] * n
    stack  = []         # monotonic stack of indices (decreasing values)

    for i in range(2 * n):
        idx = i % n

        while stack and a[stack[-1]] < a[idx]:
            result[stack.pop()] = a[idx]

        if i < n:
            stack.append(idx)

    return result


# ─── Ring Buffer ──────────────────────────────────────────────────────────────

class RingBuffer(Generic[T]):
    """
    Fixed-capacity circular buffer. O(1) enqueue, dequeue, and random access.

    Implementation: array of size `capacity` with two cyclic pointers:
      head: index of the oldest element (next to be dequeued)
      tail: index of the next write slot

    The two pointers are advanced with (ptr + 1) % capacity — cyclic traversal.
    When head == tail: buffer is empty (disambiguated by self._size).

    This is the data structure behind:
      - collections.deque(maxlen=k) in Python
      - PyTorch DataLoader prefetch queue
      - Linux kernel kfifo
    """
    def __init__(self, capacity: int) -> None:
        self._data: list[Optional[T]] = [None] * capacity
        self._cap  = capacity
        self._head = 0      # oldest element
        self._tail = 0      # next write slot
        self._size = 0

    def enqueue(self, val: T) -> None:
        if self._size == self._cap:
            raise OverflowError("Buffer full")
        self._data[self._tail] = val
        self._tail = (self._tail + 1) % self._cap   # cyclic advance
        self._size += 1

    def dequeue(self) -> T:
        if self._size == 0:
            raise IndexError("Buffer empty")
        val = self._data[self._head]
        self._head = (self._head + 1) % self._cap   # cyclic advance
        self._size -= 1
        return val  # type: ignore

    def at(self, k: int) -> T:
        """
        Access element k steps from head. k=0 is oldest, k=size-1 is newest.
        Uses modular index: (head + k) % capacity.
        """
        if not (0 <= k < self._size):
            raise IndexError(f"Index {k} out of range [0, {self._size})")
        return self._data[(self._head + k) % self._cap]  # type: ignore

    def __len__(self) -> int:   return self._size
    def full(self)  -> bool:    return self._size == self._cap
    def empty(self) -> bool:    return self._size == 0


# ─── Circular Traversal Starting at Arbitrary Position ───────────────────────

def circular_sum_starting_at(a: list[int], start: int) -> int:
    """
    Sum of all elements in circular order starting from index `start`.
    Demonstrates the core pattern: loop n times, access a[(start + step) % n].

    Time:  O(n)
    Space: O(1)
    """
    n   = len(a)
    total = 0
    for step in range(n):
        total += a[(start + step) % n]
    return total   # always == sum(a), but demonstrates the traversal pattern


# ─── Josephus Problem ─────────────────────────────────────────────────────────

def josephus(n: int, k: int) -> int:
    """
    n people in a circle, every k-th person eliminated. Returns 0-indexed
    position of the last survivor.

    Recurrence (DP on group size):
      f(1, k) = 0
      f(i, k) = (f(i-1, k) + k) % i   for i = 2..n

    Derivation: after eliminating person k-1 (0-indexed) from a group of i,
    the remaining i-1 people are renumbered. The survivor's position in the
    new numbering is f(i-1, k). Mapping back: (f(i-1,k) + k) % i.

    Time:  O(n)
    Space: O(1)
    """
    pos = 0
    for i in range(2, n + 1):
        pos = (pos + k) % i
    return pos


# ─── Rotate Array using cyclic replacement ────────────────────────────────────

def rotate_cyclic(a: list[int], k: int) -> None:
    """
    Rotate array right by k in-place. Cyclic replacement: follow each
    permutation cycle, placing each element in its final position.

    Number of cycles = gcd(n, k). Each cycle has length n // gcd(n, k).
    Total replacements = n (each element placed exactly once).

    Time:  O(n)
    Space: O(1)
    """
    from math import gcd
    n = len(a)
    k %= n
    if k == 0:
        return

    num_cycles = gcd(n, k)   # each start index 0..num_cycles-1 begins a cycle

    for start in range(num_cycles):
        prev    = a[start]
        current = start
        while True:
            next_idx    = (current + k) % n
            a[next_idx], prev = prev, a[next_idx]
            current     = next_idx
            if current == start:
                break

    assert josephus(5, 1) == 4   # last person standing in count-by-1

    # rotate_cyclic
    a = [1, 2, 3, 4, 5, 6, 7]
    rotate_cyclic(a, 3)
    assert a == [5, 6, 7, 1, 2, 3, 4], f"Got {a}"

    b = [-1, -100, 3, 99]
    rotate_cyclic(b, 2)
    assert b == [3, 99, -1, -100], f"Got {b}"

    c = [1, 2]
    rotate_cyclic(c, 3)       # k=3 normalises to k=1
    assert c == [2, 1], f"Got {c}"

    print("All tests passed.")
```

### Diagram 1 — The Ring Address Space

Array `a = [3, 1, 4, 1, 5]` treated as a circular ring:

```
        index 0 (value 3)
             │
   index 4   │   index 1
  (value 5) ─┤─ (value 1)
             │
   index 3   │   index 2
  (value 1) ─┤─ (value 4)
             │

Linear access:  a[0], a[1], a[2], a[3], a[4], a[5]? → OUT OF BOUNDS
Circular access: a[0], a[1], a[2], a[3], a[4], a[5%5=0], a[6%5=1], ...
                  → wraps forever, no boundary

Starting at index 3, traverse all 5 elements:
  step 0: (3+0)%5 = 3 → a[3] = 1
  step 1: (3+1)%5 = 4 → a[4] = 5
  step 2: (3+2)%5 = 0 → a[0] = 3   ← wraparound
  step 3: (3+3)%5 = 1 → a[1] = 1
  step 4: (3+4)%5 = 2 → a[2] = 4
  Visited: [1, 5, 3, 1, 4] — all 5 elements, starting from index 3.
```

## 7. Common Variations & Extensions

### Variation 1 — Sliding Window on Circular Array

The maximum sum subarray of length exactly `k` in a circular array cannot be solved directly with a linear sliding window. Two approaches: (a) duplicate the array to length `2n` and slide a window of size `k` over positions `0..2n-k-1` (but the window must not span more than `n` elements, so `k ≤ n` is required); (b) use the deque-based sliding window maximum of [[14.Sliding window maximum — monotonic deque approach]] on the duplicated array. Both reduce to the linear problem via the duplication trick.

### Variation 2 — Josephus Problem Variants

The classic Josephus problem (every k-th person eliminated) has the O(n) DP recurrence shown above. Variants include: every 2nd person eliminated (k=2, closed-form solution: `2L + 1` where n = `2^m + L`); eliminating from both ends simultaneously; the "counting out" problem with variable k. All rely on the same modular position mapping `(pos + k) % remaining`.

### Variation 3 — Cyclic Rotation Detection (Rotated Sorted Array)

A sorted array rotated by some unknown amount k can be searched in O(log n) using binary search with a modified condition. The rotation point (pivot) is the index where `a[i] > a[(i+1) % n]`. Finding the pivot takes O(log n) via binary search, after which two binary searches on the two sorted halves give the answer. The pivot detection condition itself uses modular indexing. See [[57.Binary search on rotated sorted array]].

### Variation 4 — Cyclic Coordinate Systems in ML: RoPE

Rotary Position Embedding (RoPE) encodes position `m` as a rotation matrix applied to the query and key vectors. For a 2D subspace with frequency `θ`, position `m` corresponds to angle `m × θ`. The relative position between tokens `m` and `n` is angle `(m - n) × θ` — a difference, not an absolute value, making RoPE naturally shift-invariant. This is the continuous version of `(i - j) % n`: difference of positions on a ring. Understanding the discrete ring arithmetic here gives direct intuition for why RoPE preserves relative position information in attention computation. See [[135.Graph neural networks — conceptual bridge from classical to ML graphs]].

## 9. CP Contest Application

### Typical Problem Structures

**Codeforces Div. 2 B / C — circular array query:**

> "You have a circular array of n elements. Process q queries, each asking for the sum of elements from position l to position r (going clockwise). Positions wrap around."

Precompute prefix sums. A circular query `(l, r)` where `l > r` (wraps) equals `prefix[n] - prefix[l] + prefix[r+1]`. The modular indexing appears in the query decomposition, not the sum computation itself. An alternate approach: duplicate the prefix sum array for `0..2n-1`, then any circular range becomes a contiguous range in the duplicated array.

**Div. 2 C / D — circular scheduling:**

> "n tasks must be processed in round-robin order. Task i requires t[i] time. Starting from task s, find the first task that cannot complete before deadline D."

This is cyclic traversal with early termination: loop `i = 0..n-1`, process task `(s + i) % n`, accumulate time, check against D. The modular index is the entire algorithmic content.

### Optimisation Notes

**Avoid `%` inside tight inner loops:** On modern CPUs, integer division (and thus `%`) takes 20–40 clock cycles — significantly more expensive than addition or comparison. For a loop that runs 10⁸ times with `i % n` inside, the modulo operation alone costs ~2–4 billion cycles. Alternatives:

1. **Conditional reset:** Instead of `i = (i + 1) % n`, write:
    
    ```cpp
    ++i;
    if (i == n) i = 0;
    ```
    
    A branch with a predictable pattern (true once every n iterations) is faster than a division.
    
2. **Power-of-2 sizes:** If `n` is a power of 2, `i % n == i & (n-1)`. Bitwise AND is a single-cycle operation. Ring buffers in performance-critical code (Linux kernel, network drivers) always use power-of-2 capacities for this reason.
    
3. **Loop unrolling for the boundary:** Process elements 0 through n-2 linearly, then handle the element at index n-1 with an explicit check for the wraparound case. This completely eliminates modulo from the inner loop at the cost of code duplication for one element.
