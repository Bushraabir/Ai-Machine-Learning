## 1. Intuition First

### The Core Idea

Imagine you are standing in a crowd at a concert. You want to know, for every person, who is the first shorter person to their **right**. A naïve way: for every person, scan all people to their right until you find someone shorter — that is O(n²).

Now think differently. Walk left to right and carry a **notepad** (the stack). When you arrive at a person of height `h`:

- Everyone on your notepad who is **taller than** `h` finally has their answer: _you_ are their next shorter person. Cross them off.
- Write yourself on the notepad.

At the end, anyone still on the notepad never found a shorter person to their right — their answer is `-1` (or `∞`, depending on convention).

The notepad always lists people in **decreasing order of height from bottom to top** — the shortest person at the top. This is the **monotonic decreasing stack**: elements stored in it are non-increasing from bottom to top.

### Why This Exists

The naïve scan is O(n²). The insight that breaks this barrier: **each element is pushed once and popped once**. The total number of push + pop operations across the entire array is exactly `2n`, giving O(n) amortised.

Without this structure, problems like "largest rectangle in histogram" reduce to nested loops. With it, the same problem collapses to a linear scan. The complexity gap is the difference between timing out in competitive programming and passing.

### The "Aha" Moment

> **The stack doesn't just store elements — it stores unresolved questions.** Every element on the stack is asking "have you found my next smaller yet?" When a new element arrives and it's smaller than the top, it _answers_ the top's question. This reframe makes the pop condition obvious: pop when the invariant (decreasing order) would be violated.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- "For each element, find the nearest smaller/greater to its left/right"
- "Largest rectangle" or "maximum area" under a histogram
- Stock price span, daily temperatures, building visibility
- Any problem where you need to efficiently find the _next_ or _previous_ element satisfying a monotone condition

**Signal pattern:**

> When you see _"for each index i, find the nearest j > i such that arr[j] < arr[i]"_ → reach for a monotonic decreasing stack. If you see _"j < i"_ (previous smaller), traverse right-to-left with the same structure.

**Common traps that kill submissions:**

1. **Off-by-one on indices vs values** — the stack should store _indices_, not values, so you can compute distances (`j - i`). Storing values loses positional information.
2. **Forgetting the leftover stack** — elements remaining after full traversal have no next smaller element. Always set their answer to `-1` or `n` (array length) depending on what the problem requires.
3. **Strict vs non-strict inequality** — "next **strictly** smaller" vs "next **smaller or equal**" changes the pop condition from `stack.top() > arr[i]` to `stack.top() >= arr[i]`. One wrong character = wrong answer.

---

### Machine Learning / AI

**Where this algorithmic idea appears:**

1. **Attention masking in transformers (causal / autoregressive models):** The causal mask in GPT-style models prevents position `i` from attending to positions `j > i`. Constructing this mask efficiently for variable-length sequences uses the same "maintain a boundary, resolve when condition met" logic as a monotonic stack.
    
2. **Activation pruning and early exit networks:** In networks like BranchyNet or multi-exit architectures, each layer's output is compared against a confidence threshold. The first layer whose confidence _drops below_ a threshold triggers an exit — structurally identical to "next element smaller than threshold."
    
3. **Feature importance in gradient boosting (XGBoost / LightGBM):** Tree construction finds split points where gain drops below a minimum. Internally, sorted candidate split arrays are scanned with a stack-like structure to efficiently track which splits remain competitive — a direct analogue of the decreasing stack popping dominated candidates.
    
4. **Pandas `rolling().min()` implementation:** `pd.Series.rolling(window).min()` uses a monotonic deque (a generalised version of this stack) internally. Understanding the stack mechanism tells you _why_ this operation is O(n) and not O(n·k).
    

**Practical implication:** If you are writing a custom CUDA kernel or Numba-accelerated loop for sliding minimum across a time-series feature (common in financial ML), you _cannot_ call Pandas — you implement this stack yourself. Knowing the invariant is the difference between O(n) and O(nk).

## 3. Algorithm / Pattern

### Step-by-Step Logic

```
Given array arr[0..n-1], find for each index i the index of the 
next element strictly smaller than arr[i]. Return -1 if none exists.

1. Initialise result array ans[0..n-1] = -1
2. Initialise empty stack S (stores indices)
3. For i from 0 to n-1:
    a. While S is not empty AND arr[S.top()] > arr[i]:
         - idx = S.pop()
         - ans[idx] = i          ← i is the "next smaller" for idx
    b. S.push(i)
4. Remaining indices in S have ans = -1 (already initialised)
5. Return ans
```

**Decision Tree:**

```
New element arr[i] arrives
│
├─ Stack is empty? → push i, continue
│
└─ arr[stack.top()] > arr[i]?
    ├─ YES → pop top, record answer, check again (while loop)
    └─ NO  → push i, continue
             (arr[i] >= arr[top]: maintain non-increasing invariant)
```

### Complexity Analysis

**Time:** Each index is pushed exactly once and popped at most once. The total number of stack operations across all `n` iterations is bounded by `2n`. Therefore the entire algorithm is **O(n)**.

More formally: the while loop at step 3a may seem like it could run O(n) per iteration, but summing across all iterations: $$\sum_{i=0}^{n-1} \text{(pops at step } i\text{)} \leq n \quad \text{since each element pops at most once}$$

**Space:** The stack holds at most `n` indices simultaneously (worst case: strictly increasing array, nothing ever pops). **O(n)** auxiliary space.

### When to Use vs. When to Avoid

|Use|Avoid|
|---|---|
|Finding nearest smaller/larger in O(n)|When you need **all** smaller elements (not just nearest) → different structure|
|Problems reducible to "next boundary"|When elements are processed in non-left-to-right order|
|Histogram area, span, visibility problems|When the comparison condition depends on more than the current element (e.g., sums) → consider [[06.1D prefix sum — construction and range query in O(1)]]|
|Streaming data where past answers are final|When you may need to update past answers (use segment tree → [[155.Segment tree — range query and point update O(log n)]])|

## 4. Pseudocode

```
FUNCTION nextSmallerElement(arr[0..n-1]):
    ans ← array of size n, initialised to -1
    S   ← empty stack of integers  // stores indices

    FOR i FROM 0 TO n-1:
        // Invariant: S contains indices in non-increasing order of arr values
        // i.e., arr[S[0]] >= arr[S[1]] >= ... >= arr[S.top()]
        
        WHILE S is not empty AND arr[S.top()] > arr[i]:
            // arr[i] is the FIRST element smaller than arr[S.top()]
            // so it answers S.top()'s pending question
            idx    ← S.pop()
            ans[idx] ← i     // next smaller for idx is at position i
        END WHILE

        S.push(i)  // i's question remains unanswered; enqueue for future
    END FOR

    // Any index still in S has no smaller element to its right
    // ans[idx] = -1 already (initialised)

    RETURN ans
```

**Edge Cases Handled:**

- **All increasing** (e.g., `[1,2,3,4]`): nothing ever pops; all answers are `-1`.
- **All equal** (e.g., `[3,3,3]`): pop condition `>` (strict) means nothing pops; `-1` for all. If problem uses `>=`, adjust the condition.
- **All decreasing** (e.g., `[4,3,2,1]`): every new element pops all previous; answers are `i+1` for all except the last.
- **Single element**: stack holds it; answer is `-1`.

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <vector>
#include <stack>
#include <cassert>

/**
 * Next Smaller Element (to the right)
 *
 * For each index i, returns the index j > i such that arr[j] < arr[i]
 * and j is minimised. Returns -1 if no such j exists.
 *
 * Time:  O(n) amortised — each element pushed and popped at most once
 * Space: O(n) for the stack
 *
 * @param arr  Input array of integers
 * @return     Vector of indices (or -1) representing next smaller position
 */
std::vector<int> nextSmallerElement(const std::vector<int>& arr) {
    int n = static_cast<int>(arr.size());
    std::vector<int> ans(n, -1);   // default: no next smaller found
    std::stack<int> st;            // monotonic decreasing stack of indices

    for (int i = 0; i < n; ++i) {
        // Pop all indices whose stored value is strictly greater than arr[i]
        // arr[i] is the "next smaller element" for all of them
        while (!st.empty() && arr[st.top()] > arr[i]) {
            ans[st.top()] = i;
            st.pop();
        }
        st.push(i);
    }
    // Remaining indices in stack have ans = -1 (no next smaller element)
    return ans;
}

/**
 * Variant: Next Smaller Element (to the LEFT)
 * Traverse right-to-left, same logic.
 */
std::vector<int> prevSmallerElement(const std::vector<int>& arr) {
    int n = static_cast<int>(arr.size());
    std::vector<int> ans(n, -1);
    std::stack<int> st;

    for (int i = n - 1; i >= 0; --i) {
        while (!st.empty() && arr[st.top()] > arr[i]) {
            ans[st.top()] = i;
            st.pop();
        }
        st.push(i);
    }
    return ans;
}

/**
 * Variant: Return actual VALUES instead of indices.
 * Useful when distance doesn't matter, only the value.
 */
std::vector<int> nextSmallerValues(const std::vector<int>& arr) {
    int n = static_cast<int>(arr.size());
    std::vector<int> ans(n, -1);
    std::stack<int> st;  // store indices to access arr[top]

    for (int i = 0; i < n; ++i) {
        while (!st.empty() && arr[st.top()] > arr[i]) {
            ans[st.top()] = arr[i];  // store value, not index
            st.pop();
        }
        st.push(i);
    }
    return ans;
}

// ─── Minimal test driver ────────────────────────────────────────────────────
int main() {
    // Test 1: Mixed array
    {
        std::vector<int> arr = {4, 5, 2, 10, 8, 3};
        auto res = nextSmallerElement(arr);
        //              arr:  4   5   2  10   8   3
        // expected idx:      2   2  -1   5   5  -1
        std::vector<int> expected = {2, 2, -1, 5, 5, -1};
        assert(res == expected);
    }

    // Test 2: All increasing → all -1
    {
        std::vector<int> arr = {1, 2, 3, 4};
        auto res = nextSmallerElement(arr);
        assert(res == std::vector<int>({-1, -1, -1, -1}));
    }

    // Test 3: All decreasing → each is answered by the next
    {
        std::vector<int> arr = {4, 3, 2, 1};
        auto res = nextSmallerElement(arr);
        assert(res == std::vector<int>({1, 2, 3, -1}));
    }

    // Test 4: Single element
    {
        std::vector<int> arr = {7};
        auto res = nextSmallerElement(arr);
        assert(res == std::vector<int>({-1}));
    }

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations


def next_smaller_element(arr: list[int]) -> list[int]:
    """
    For each index i, find the index j > i such that arr[j] < arr[i]
    and j is minimised. Return -1 if no such j exists.

    Uses a monotonic decreasing stack of indices.

    Time:  O(n)  — each element pushed and popped at most once
    Space: O(n)  — stack holds at most n indices

    Args:
        arr: Input list of integers.

    Returns:
        List where result[i] is the index of the next smaller element,
        or -1 if none exists.

    Examples:
        >>> next_smaller_element([4, 5, 2, 10, 8, 3])
        [2, 2, -1, 5, 5, -1]
        >>> next_smaller_element([1, 2, 3])
        [-1, -1, -1]
        >>> next_smaller_element([3, 2, 1])
        [1, 2, -1]
    """
    n = len(arr)
    ans = [-1] * n          # default: no next smaller found
    stack: list[int] = []   # monotonic decreasing stack (stores indices)

    for i in range(n):
        # While the top of stack has a value GREATER than arr[i],
        # arr[i] is the answer (next smaller) for that index.
        while stack and arr[stack[-1]] > arr[i]:
            idx = stack.pop()
            ans[idx] = i
        stack.append(i)

    # Remaining elements in stack have no next smaller → ans stays -1
    return ans


def prev_smaller_element(arr: list[int]) -> list[int]:
    """
    For each index i, find the index j < i such that arr[j] < arr[i]
    and j is maximised (i.e., the nearest smaller to the left).

    Same logic, traversed right-to-left.

    Time:  O(n)
    Space: O(n)
    """
    n = len(arr)
    ans = [-1] * n
    stack: list[int] = []

    for i in range(n - 1, -1, -1):
        while stack and arr[stack[-1]] > arr[i]:
            idx = stack.pop()
            ans[idx] = i
        stack.append(i)

    return ans


def next_smaller_values(arr: list[int]) -> list[int]:
    """
    Returns the actual value (not index) of the next smaller element.
    Useful when only the value matters, not its position.

    Examples:
        >>> next_smaller_values([4, 5, 2, 10, 8, 3])
        [2, 2, -1, 3, 3, -1]
    """
    n = len(arr)
    ans = [-1] * n
    stack: list[int] = []

    for i in range(n):
        while stack and arr[stack[-1]] > arr[i]:
            ans[stack.pop()] = arr[i]   # store VALUE, not index
        stack.append(i)

    return ans


# ─── Self-test ────────────────────────────────────────────────────────────────
if __name__ == "__main__":
    # Mixed
    assert next_smaller_element([4, 5, 2, 10, 8, 3]) == [2, 2, -1, 5, 5, -1]
    # All increasing
    assert next_smaller_element([1, 2, 3, 4]) == [-1, -1, -1, -1]
    # All decreasing
    assert next_smaller_element([4, 3, 2, 1]) == [1, 2, 3, -1]
    # Single element
    assert next_smaller_element([7]) == [-1]
    # All equal (strict inequality: no smaller, so all -1)
    assert next_smaller_element([3, 3, 3]) == [-1, -1, -1]
    # Values version
    assert next_smaller_values([4, 5, 2, 10, 8, 3]) == [2, 2, -1, 3, 3, -1]

    print("All assertions passed.")
```

## 7. Common Variations & Extensions

### 7.1 Next Smaller + Previous Smaller → Contribution Technique

Many "sum over all subarrays" problems require knowing for each element `arr[i]`:

- `left[i]` = nearest index to the left where `arr[j] < arr[i]`
- `right[i]` = nearest index to the right where `arr[j] < arr[i]`

The contribution of `arr[i]` as the **minimum** of some subarray is: $$\text{contribution}(i) = \text{arr}[i] \times (i - \text{left}[i]) \times (\text{right}[i] - i)$$

Run two monotonic decreasing stacks (one left-to-right, one right-to-left) and combine. This solves "Sum of Subarray Minimums" in O(n).

**Handle duplicates carefully:** use strict `<` for one direction and `≤` for the other to avoid double-counting.

→ See also [[89.Largest rectangle in histogram — the canonical monotonic stack problem]] for a direct application.

### 7.2 Monotonic Deque — Sliding Window Minimum

Extend the stack to a **deque** (double-ended queue) to support a fixed window:

- Pop from **front** when the leftmost element exits the window.
- Pop from **back** when new element violates the decreasing invariant.

This gives the **minimum in every window of size k** in O(n). Direct application in:

- Rolling minimum features in time-series ML pipelines
- [[95.Sliding window maximum with monotonic deque]] (same idea, flip to maximum)

### 7.3 Strict vs Non-Strict: Equal Elements

|Problem says|Pop condition|Behaviour on ties|
|---|---|---|
|Next strictly smaller|`arr[top] > arr[i]`|Equal elements remain on stack|
|Next smaller or equal|`arr[top] >= arr[i]`|Equal elements are answered|

Wrong choice here causes off-by-one errors on arrays with duplicates. Always read the problem statement for `<` vs `≤`.

### 7.4 Circular Array

For a circular array, simulate two passes (concatenate arr with itself or use modular indexing). Run the stack for `2n` elements but only record answers for the first `n`.

```python
n = len(arr)
ans = [-1] * n
stack = []
for i in range(2 * n):
    while stack and arr[stack[-1] % n] > arr[i % n]:
        ans[stack.pop() % n] = i % n
    if i < n:
        stack.append(i)
```

→ Related to [[05.Cyclic traversal and modular indexing]]

## 9. CP Contest Application

### Typical Codeforces / AtCoder Problem Structure

**Pattern A — Direct query:**

> _"Given an array, for each i output the closest j to the right such that a[j] < a[i]. If none, output -1."_ One-pass monotonic stack, O(n). Fits comfortably within 1–2 second TL for n ≤ 10⁶.

**Pattern B — Contribution / sum over subarrays:**

> _"Find the sum of minimums (or maximums) over all contiguous subarrays."_ Combine left-smaller and right-smaller stacks; careful with duplicate handling. O(n) time; modular arithmetic required (answers are typically mod 10⁹+7).

**Pattern C — Histogram / area under profile:**

> _"Given heights, find the maximum rectangle area."_ [[89.Largest rectangle in histogram — the canonical monotonic stack problem]] — stack pops trigger area computation.

**Time limit considerations:**

- n ≤ 10⁶: O(n) stack solution always passes within 1–2s.
- n ≤ 10⁵ with q queries: Stack still fine; precompute next smaller, answer queries in O(1).
- n ≤ 10⁷: Prefer array-based stack (avoid `std::stack` overhead in C++) — use `int stk[MAXN]; int top = 0;`.

**CP Optimisation tricks:**

```cpp
// Faster than std::stack for CP — avoid overhead of deque-backed stack
const int MAXN = 1e6 + 5;
int stk[MAXN], top_ptr = 0;

// Push:  stk[top_ptr++] = i;
// Pop:   top_ptr--;
// Top:   stk[top_ptr - 1]
// Empty: top_ptr == 0
```

This array-based stack is cache-friendlier and 20–30% faster than `std::stack` in tight loops, which can matter when the constant factor is squeezed.
