## 1. Intuition First

### The Core Idea

Full sorting answers: _where does every element belong?_ Partial sorting answers a weaker question: _which elements belong in the top-k (or bottom-k) positions?_ — and critically, it does not care about the order among those k elements.

This relaxation is not cosmetic. It is an algorithmic contract change that unlocks O(n) expected time where full sorting requires Ω(n log n). The moment you stop requiring sorted order within the selected partition, you are free to use partition-based selection rather than comparison-based sorting.

`np.partition(arr, k)` implements exactly this contract:

- `result[k]` is the element that would be at position k in a fully sorted array
- `result[:k]` contains the k smallest elements, **in arbitrary order**
- `result[k+1:]` contains the remaining elements, **in arbitrary order**

The unsorted-within-partition guarantee is not a bug or a limitation — it is a deliberate design choice that makes the operation O(n) instead of O(n log k). If you then need the k elements sorted, call `np.sort(result[:k])` separately in O(k log k). The total cost is O(n + k log k), which beats O(n log n) whenever k ≪ n.

### Why This Exists

Consider the k-nearest neighbours query: given a query point q and n candidate points, find the k closest. The naive pipeline:

1. Compute all n distances: O(n)
2. Sort distances: O(n log n)
3. Return the first k: O(k)

Step 2 does vastly more work than necessary. You don't need distances ranked 1 through n. You need only the k smallest — their internal ranking is irrelevant unless you intend to process them in order (which most k-NN algorithms do not). Replacing `np.sort` with `np.partition` collapses step 2 from O(n log n) to O(n) expected, a win that compounds across millions of queries.

The same argument applies everywhere a ranking-and-truncation pattern appears: top-k recommendations, beam search vocabulary pruning, percentile thresholding, feature selection by importance score, anomaly detection by deviation rank.

### The "Aha" Moment

Full sort is answering a question nobody asked. When you need the top-k, full sort wastes all the work it spends establishing the relative order _among_ the top-k and _among_ the bottom (n−k). `np.partition` does exactly and only what the question requires: it establishes the **boundary** between the top-k and the rest, and nothing more.

This is a general principle in algorithm design: weaker output specifications admit faster algorithms. The more you weaken the required output contract, the fewer comparisons are forced. The selection problem (find the k-th element) sits precisely between the trivial minimum/maximum problem (O(n), output contract: one element) and the sorting problem (O(n log n), output contract: total order on all n elements).

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Partial sort is rarely the _explicit_ topic of a CP problem, but it underlies solutions to:

- **k-th order statistic problems**: find the k-th smallest/largest — this is `np.partition`'s direct analogue. In C++: `std::nth_element`.
- **Greedy problems requiring top-k selection**: "select k tasks to maximise total value subject to a deadline" — you need the k highest-value tasks, not their sorted order. `std::nth_element` then process `arr[0..k-1]`.
- **Median-based problems**: finding the median is `np.partition(arr, n//2)`.

**The pattern signal:**

> "Find the k items with highest/lowest score" without needing their relative order → `std::nth_element` / `np.partition` thinking. If the problem says "output them in order", you pay O(k log k) on top.

**Common trap:** Using `std::sort` (O(n log n)) when `std::nth_element` (O(n)) suffices. For n = 10⁷ with a tight 1-second time limit, this is the difference between AC and TLE. The instinct to always `sort()` first is a common inefficiency.

**C++ CP idiom:**

```cpp
// Get k smallest elements (unordered) in O(n)
std::nth_element(arr.begin(), arr.begin() + k, arr.end());
// arr[0..k-1] are the k smallest, in arbitrary order

// Get k-th smallest element
std::nth_element(arr.begin(), arr.begin() + k, arr.end());
int kth = arr[k];

// Get k largest elements (unordered) — use reverse comparator
std::nth_element(arr.begin(), arr.begin() + k, arr.end(), std::greater<int>());
// arr[0..k-1] are the k largest, in arbitrary order
```

### Machine Learning / AI

This is where partial sort earns its place as a T2 topic. `np.partition` and `np.argpartition` are the workhorse operations in ML inference pipelines. Every ML engineer should have these reflexively in their toolkit.

**1. k-Nearest Neighbours — the canonical use case**

In `sklearn.neighbors.KNeighborsClassifier` with `algorithm='brute'`, the prediction pipeline for a single query point is:

```python
distances = cdist(query.reshape(1, -1), X_train)  # O(n × d)
# WRONG (slower): indices = np.argsort(distances)[0, :k]  — O(n log n)
# RIGHT (faster): indices = np.argpartition(distances, k)[0, :k]  — O(n)
```

For n = 10⁶ training points and k = 10, `np.argsort` examines all 10⁶ distances and sorts them. `np.argpartition` partitions in O(n) and returns the k=10 smallest indices in arbitrary order. The O(n log n) vs O(n) gap is 20× for n = 10⁶. If you're running 10⁴ queries/second, this is the difference between 5ms and 100ms per query — the difference between meeting and missing a latency SLA.

**2. Beam Search in Sequence-to-Sequence Models**

In transformer-based text generation (GPT, T5, BART), beam search maintains B beams. At each decoding step, you score V vocabulary tokens for each beam, giving B×V scores total. You then keep the top B candidates.

```python
# Shape: (batch_size, beam_width, vocab_size)
# Need top beam_width candidates from each row

# WRONG: full sort of vocab_size (~50k) scores
top_indices = torch.argsort(scores, dim=-1, descending=True)[:, :, :beam_width]

# RIGHT: partial sort — only find beam_width-th threshold
top_indices = torch.topk(scores, beam_width, dim=-1).indices
# torch.topk uses a partial sort internally (heap or quickselect)
```

`torch.topk` is called at every decoding step, for every layer that uses it (some models apply top-k filtering for nucleus sampling). For a 50-token output with vocab size 50,257 and beam width 5, full sort vs. partial sort is 50 × (50257 log 50257) vs. 50 × 50257. The savings compound across batch dimension.

**3. Top-k Recommendations in Production Systems**

Recommendation systems maintain an embedding table of M items (M ∈ [10⁵, 10⁸]). At inference time, the system computes similarity scores between a user embedding and all M item embeddings, then returns the top-k recommendations.

```python
# scores shape: (M,) — dot product of user embedding with all item embeddings
scores = user_emb @ item_embeddings.T  # O(M × d)

# Top-k selection: O(M) not O(M log M)
top_k_indices = np.argpartition(scores, -k)[-k:]
top_k_scores  = scores[top_k_indices]

# If you need them sorted (for ranked display):
sort_order    = np.argsort(top_k_scores)[::-1]  # O(k log k) — cheap
top_k_ranked  = top_k_indices[sort_order]
```

For M = 10⁶, k = 100: `np.argpartition` does O(10⁶), then `np.argsort` on 100 elements does O(100 × 7) ≈ O(700). Total: ≈ 10⁶ operations. Full `np.argsort` on 10⁶ elements: ≈ 20 × 10⁶ operations. 20× speedup, and the sorted output contract is fully preserved — you sort only the k winners.

**4. Feature Selection by Importance**

```python
# RandomForest or XGBoost feature importances
importances = model.feature_importances_  # shape: (n_features,)

# Select top-k most important features
k = 50
top_k_feature_idx = np.argpartition(importances, -k)[-k:]
# Now train on X[:, top_k_feature_idx] — no need to rank importances
```

`sklearn.feature_selection.SelectKBest` uses this pattern internally. Understanding that it is O(n_features), not O(n_features log n_features), matters when n_features is large (e.g., genomics datasets with 100k+ features).

**5. Anomaly Detection Thresholding**

```python
# Reconstruction errors from an autoencoder
errors = np.abs(X - autoencoder.predict(X))  # shape: (n_samples,)

# Flag top-p% as anomalies
p = 0.01  # top 1%
threshold_idx = int(n * (1 - p))

# O(n) threshold finding — no need to sort all n errors
threshold = np.partition(errors, threshold_idx)[threshold_idx]
anomaly_mask = errors > threshold
```

This is equivalent to computing the (1−p)-th quantile without full sorting. For n = 10⁸ sensor readings, O(n) vs O(n log n) is the difference between seconds and minutes.

## 3. Algorithm / Pattern

### The Three Contracts

Understanding partial sort requires distinguishing three related output contracts, each with different cost:

|Operation|Output Contract|Time Complexity|C++|Python/NumPy|
|---|---|---|---|---|
|Full sort|All n elements in sorted order|O(n log n)|`std::sort`|`np.sort` / `sorted()`|
|Partial sort|Top-k in sorted order, rest unordered|O(n log k)|`std::partial_sort`|`np.sort(np.partition(a,k)[:k])`|
|Selection (partition)|Top-k in arbitrary order, rest unordered|O(n) expected|`std::nth_element`|`np.partition` / `np.argpartition`|

The step from "top-k sorted" to "top-k unordered" saves the O(k log k) internal sort. The step from "full sort" to "top-k unordered" saves O(n log n) → O(n). Both transitions are meaningful depending on k.

### Decision Logic

```
Do you need all n elements in order?
  Yes → np.sort / std::sort — O(n log n), no alternative
  No  ↓

Do you need the exact k-th element (threshold/rank)?
  Yes → np.partition(arr, k)[k] — O(n), gives one value
  No  ↓

Do you need the k smallest/largest elements?
  Unsorted output OK?
    Yes → np.argpartition(arr, k)[:k] — O(n), indices unordered
    No  → np.argpartition then argsort the slice — O(n + k log k)
  
  k is very small (k ≤ log n)?
    Yes → min-heap of size k — O(n log k), lower constant than partition
    No  → np.argpartition — O(n), better for large k
```

### When Heap Beats Partition

For extremely small k (say k ≤ 20 for n = 10⁶), a max-heap of size k has excellent cache behaviour:

```python
import heapq

# k smallest using heap: O(n log k)
# For tiny k, this can beat np.partition's O(n) due to constant factors
k_smallest = heapq.nsmallest(k, arr)   # returns sorted!
k_largest  = heapq.nlargest(k, arr)    # returns sorted!
```

`heapq.nsmallest` and `heapq.nlargest` use a heap for small k and `sorted()` for large k, with a crossover point around k = n/2 (tuned in CPython). For ML use cases with k ≤ 10 and n ≥ 10⁵, profile both — the result is hardware-dependent.

### `np.argpartition` — the index variant (most common in ML)

In ML you almost always need **indices**, not values. `np.partition` returns rearranged values; `np.argpartition` returns the indices of those values in the original array — the ML-critical version.

```python
arr = np.array([0.9, 0.2, 0.8, 0.1, 0.7])

# np.partition: returns rearranged VALUES
np.partition(arr, 2)        # → [0.1, 0.2, 0.8, 0.9, 0.7] (arr[2]=0.8 is correct)

# np.argpartition: returns INDICES into original arr
np.argpartition(arr, 2)     # → [3, 1, 2, 0, 4] (indices such that arr[idx[2]]=0.8)

# Get indices of 2 smallest values (unordered):
idx = np.argpartition(arr, 2)[:2]   # → [3, 1] (indices of 0.1 and 0.2)
arr[idx]                             # → [0.1, 0.2]

# Get indices of 2 largest values (unordered) — use -k:
idx = np.argpartition(arr, -2)[-2:]  # → [0, 2] (indices of 0.9 and 0.8)
arr[idx]                             # → [0.9, 0.8]
```

### 2D Batch Operations (the real ML use case)

In ML, arrays are almost always 2D or higher. `np.argpartition` operates along a specified axis:

```python
# scores: shape (n_queries, n_items)
scores = np.random.randn(1000, 50000)  # 1000 queries, 50000 items each

# Get indices of top-k items per query — O(n_queries × n_items)
k = 10
# WRONG: np.argsort(scores, axis=1)[:, :k]  — O(n_queries × n_items × log(n_items))
# RIGHT:
top_k_idx = np.argpartition(scores, -k, axis=1)[:, -k:]
# top_k_idx shape: (1000, 10) — top-10 indices per query, UNORDERED within each row

# If you need them sorted (for ranked output):
# Gather the top-k scores, then argsort those k scores per row
top_k_scores = np.take_along_axis(scores, top_k_idx, axis=1)
sorted_local  = np.argsort(top_k_scores, axis=1)[:, ::-1]  # O(n_queries × k log k)
top_k_ranked  = np.take_along_axis(top_k_idx, sorted_local, axis=1)
# top_k_ranked: (1000, 10) — top-10 indices per query, sorted by score descending
```

Total cost: O(n_queries × n_items) for partition + O(n_queries × k log k) for final sort. This is the production pattern used in batch k-NN inference, recommendation retrieval, and multi-class top-k accuracy computation.

## 4. Pseudocode

```
PARTIAL_SORT_TOP_K(arr, k):
    """
    Return the k largest elements of arr in sorted order (descending).
    Uses selection + sort decomposition: O(n) + O(k log k) total.
    """
    n ← length(arr)
    
    // STEP 1: Partition to find the (n-k)-th smallest element as pivot.
    // After this, arr[n-k..n-1] contains the k largest (unordered).
    threshold_idx ← n - k
    QUICKSELECT(arr, threshold_idx)         // O(n) expected — see note 52
    
    // arr[threshold_idx] = the k-th largest element (the boundary value)
    // arr[threshold_idx+1..n-1] ≥ arr[threshold_idx]  (unordered)
    // arr[0..threshold_idx-1]   ≤ arr[threshold_idx]  (unordered)
    
    // STEP 2: Extract the top-k partition
    top_k ← arr[threshold_idx .. n-1]      // O(k) copy
    
    // STEP 3: Sort only the k winners
    SORT(top_k)                             // O(k log k)
    REVERSE(top_k)                          // descending order
    
    return top_k


NP_ARGPARTITION_LOGIC(arr, k):
    """
    Returns an index array idx such that:
      arr[idx[k]] == k-th smallest of arr
      {arr[idx[i]] : i < k} == k smallest elements (set, not ordered)
      {arr[idx[i]] : i > k} == n-k largest elements (set, not ordered)
    
    Equivalent to np.argpartition(arr, k).
    """
    n ← length(arr)
    idx ← [0, 1, 2, ..., n-1]              // Identity permutation
    
    // Perform Quickselect on idx, using arr[idx[i]] as the comparison key
    // This rearranges idx without touching arr
    QUICKSELECT_INDIRECT(idx, arr, lo=0, hi=n-1, k=k)
    
    // Now: arr[idx[k]] is the k-th smallest
    //      idx[0..k-1] are indices of the k smallest (unordered)
    //      idx[k+1..n-1] are indices of the rest (unordered)
    return idx
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <vector>
#include <algorithm>
#include <numeric>
#include <stdexcept>

/**
 * Partial sort: return the k largest elements in sorted (descending) order.
 * Uses nth_element (introselect, O(n)) + sort of k elements (O(k log k)).
 *
 * Time:  O(n + k log k) — always better than O(n log n) for k < n
 * Space: O(k) for the result
 */
std::vector<int> topKSorted(std::vector<int> arr, int k) {
    int n = static_cast<int>(arr.size());
    if (k <= 0 || k > n) throw std::out_of_range("k out of range");
    if (k == n) {
        std::sort(arr.begin(), arr.end(), std::greater<int>());
        return arr;
    }

    // Partition: arr[n-k..n-1] will contain the k largest (unordered)
    // std::nth_element uses introselect: O(n) worst case guaranteed
    std::nth_element(arr.begin(),
                     arr.begin() + (n - k),
                     arr.end());

    // Extract and sort only the k winners
    std::vector<int> result(arr.begin() + (n - k), arr.end());
    std::sort(result.begin(), result.end(), std::greater<int>());
    return result;
}

/**
 * argpartition: return indices of the k smallest elements (unordered).
 * Equivalent to np.argpartition(arr, k)[:k].
 *
 * Time:  O(n) expected (randomised pivot via std::nth_element)
 * Space: O(n) for the index array
 */
std::vector<int> argpartitionKSmallest(const std::vector<int>& arr, int k) {
    int n = static_cast<int>(arr.size());
    if (k <= 0 || k > n) throw std::out_of_range("k out of range");

    // Build index array [0, 1, ..., n-1]
    std::vector<int> idx(n);
    std::iota(idx.begin(), idx.end(), 0);

    // Indirect nth_element: sort idx using arr values as keys
    std::nth_element(idx.begin(),
                     idx.begin() + k,
                     idx.end(),
                     [&arr](int a, int b) { return arr[a] < arr[b]; });

    // idx[0..k-1] are indices of the k smallest elements (unordered)
    return std::vector<int>(idx.begin(), idx.begin() + k);
}

/**
 * Sliding window top-k: for each position i, find the top-k elements
 * in arr[i..i+window-1]. Returns a (n-window+1) × k matrix of indices.
 *
 * Time:  O(n × window) — can be optimised with monotonic deque for k=1
 * Space: O(n × k)
 * Note:  Demonstrates the batch argpartition pattern common in ML.
 */
std::vector<std::vector<int>> slidingTopK(
    const std::vector<int>& arr, int window, int k)
{
    int n = static_cast<int>(arr.size());
    if (window < k) throw std::invalid_argument("window must be >= k");

    std::vector<std::vector<int>> result;
    result.reserve(n - window + 1);

    for (int i = 0; i <= n - window; ++i) {
        std::vector<int> win(arr.begin() + i, arr.begin() + i + window);
        // nth_element on the window — O(window)
        std::nth_element(win.begin(), win.begin() + (window - k), win.end());
        // Top-k are win[window-k..window-1], unordered
        result.push_back(std::vector<int>(win.begin() + (window - k), win.end()));
    }
    return result;
}
```

### Python (Readable + Pythonic)

```python
import numpy as np
import heapq
from typing import Optional


def top_k_unsorted(arr: np.ndarray, k: int) -> np.ndarray:
    """
    Return indices of the k largest elements in arr (unordered).
    O(n) expected via np.argpartition.

    Args:
        arr: 1D numpy array of scores.
        k:   Number of top elements to select.

    Returns:
        1D array of k indices into arr (unordered).

    Time:  O(n) expected
    Space: O(n)
    """
    if k <= 0 or k > len(arr):
        raise ValueError(f"k={k} must be in [1, {len(arr)}]")
    # np.argpartition(arr, -k)[-k:] gives indices of k largest
    # The -k means "partition around the k-th from the end"
    return np.argpartition(arr, -k)[-k:]


def top_k_sorted(arr: np.ndarray, k: int) -> tuple[np.ndarray, np.ndarray]:
    """
    Return indices and values of the k largest elements, sorted descending.
    O(n + k log k) — always beats O(n log n) full sort for k < n.

    Returns:
        (sorted_indices, sorted_values): both shape (k,), descending order.

    Time:  O(n) partition + O(k log k) sort
    Space: O(k)
    """
    # Step 1: O(n) partition — find k-th boundary, unordered top-k
    top_idx = np.argpartition(arr, -k)[-k:]        # indices of top-k, unordered

    # Step 2: O(k log k) sort — rank the k winners
    top_vals = arr[top_idx]
    sort_order = np.argsort(top_vals)[::-1]         # descending within top-k
    sorted_idx = top_idx[sort_order]
    sorted_vals = arr[sorted_idx]

    return sorted_idx, sorted_vals


def batch_top_k(
    scores: np.ndarray,
    k: int,
    axis: int = -1,
    sorted: bool = False,
) -> np.ndarray:
    """
    For a 2D score matrix, find top-k indices along the given axis.
    The canonical pattern for batched k-NN and recommendation retrieval.

    Args:
        scores: 2D array of shape (n_queries, n_items).
        k:      Number of top items to retrieve per query.
        axis:   Axis along which to apply partition (default: -1 = last).
        sorted: If True, sort the top-k within each row (O(n_queries × k log k)).

    Returns:
        Index array of shape (n_queries, k).
        If sorted=True, each row is sorted by score descending.

    Time:  O(n_queries × n_items) + O(n_queries × k log k) if sorted
    Space: O(n_queries × k)
    """
    if scores.ndim != 2:
        raise ValueError("scores must be 2D")
    n_queries, n_items = scores.shape
    if k > n_items:
        raise ValueError(f"k={k} > n_items={n_items}")

    # O(n_queries × n_items) — partition each row independently
    top_k_idx = np.argpartition(scores, -k, axis=axis)[:, -k:]

    if not sorted:
        return top_k_idx

    # O(n_queries × k log k) — sort within each row
    top_k_scores = np.take_along_axis(scores, top_k_idx, axis=1)
    local_order  = np.argsort(top_k_scores, axis=1)[:, ::-1]
    return np.take_along_axis(top_k_idx, local_order, axis=1)


def quantile_threshold(arr: np.ndarray, q: float) -> float:
    """
    Find the q-th quantile of arr in O(n) expected time.
    Equivalent to np.quantile(arr, q) for integer-index quantiles,
    but explicitly uses np.partition for pedagogical clarity.

    Args:
        arr: 1D array.
        q:   Quantile in [0, 1]. q=0.5 → median, q=0.99 → 99th percentile.

    Returns:
        The value at the q-th quantile.

    Time:  O(n) expected
    """
    n = len(arr)
    idx = int(np.floor(q * (n - 1)))          # 0-indexed rank
    return float(np.partition(arr, idx)[idx])


def anomaly_threshold(errors: np.ndarray, contamination: float = 0.01) -> float:
    """
    Find the error threshold above which points are flagged as anomalies.
    Uses O(n) partial sort instead of O(n log n) full sort.

    Args:
        errors:        1D array of reconstruction errors or anomaly scores.
        contamination: Expected fraction of anomalies (default 1%).

    Returns:
        Threshold value. Points with errors > threshold are anomalies.
    """
    return quantile_threshold(errors, 1.0 - contamination)

    print(f"\nBatch top-10 (1000 × 50000): {t_batch:.1f} ms")
    print(f"Result shape: {result.shape}")  # (1000, 10)
```

## 6. Visual Explanation

### np.partition Contract vs. np.sort Contract

```
Input arr: [7, 2, 5, 1, 8, 3, 9, 4, 6]   n=9, k=3 (find 3 smallest)

─────────────────────────────────────────────────────────────
np.sort(arr)  — O(n log n)
Output: [1, 2, 3, 4, 5, 6, 7, 8, 9]
         ↑ ↑ ↑  ← want these 3        ↑ ↑ ↑ ↑ ↑ ↑  ← wasted work
         Sorts ALL n elements. Every comparison here beyond what
         establishes the top-3 boundary is unnecessary.

─────────────────────────────────────────────────────────────
np.partition(arr, 3)  — O(n) expected
Output: [1, 2, 3, | 4, 5, 6, 7, 8, 9]  ← one valid output
  OR    [2, 1, 3, | 8, 7, 9, 4, 5, 6]  ← also valid (unordered within halves)
  OR    [3, 2, 1, | 6, 9, 8, 7, 4, 5]  ← also valid

         ↑ ↑ ↑       ↑ ↑ ↑ ↑ ↑ ↑
         The 3 smallest (arbitrary order)   The 6 largest (arbitrary order)
              │                                      │
         arr[3] = 4 is GUARANTEED correct       everything here is
                  (4th smallest)                ≥ arr[3]

─────────────────────────────────────────────────────────────
np.argpartition(arr, 3)  — O(n) expected
Output: [3, 1, 0, | 7, 4, 2, 8, 5, 6]  ← indices into original arr
         ↑  ↑  ↑
         idx of 1 (arr[3]=1), idx of 2 (arr[1]=2), idx of 7? no...

Actual: arr = [7, 2, 5, 1, 8, 3, 9, 4, 6]
               0  1  2  3  4  5  6  7  8  ← indices

argpartition output (one valid): [3, 1, 5, 7, 0, 2, 4, 6, 8]
                                   ↑  ↑  ↑  ← indices of 3 smallest (1, 2, 3)
                                              (unordered, could be any permutation)
arr[[3, 1, 5]] = [1, 2, 3]  ← the 3 smallest values, confirmed ✓
```

### The O(n + k log k) Two-Phase Pattern

```
Phase 1: O(n) partition                Phase 2: O(k log k) sort of winners

arr: ─────────────────────────────────      winners: ──────────────
     │   n-k losers (unordered)   │ k │              │ k elements │
     │   all ≤ boundary           │win│              │ sorted ↓   │
     ─────────────────────────────────              ─────────────
           n comparisons needed          only k log k comparisons needed

Total: n + k log k
                     │
          k=1:  n + 0      = n        (minimum — just argmin)
          k=√n: n + √n·½log(n) ≈ n   (√n log n ≪ n for large n)
          k=n/2: n + n/2·log(n/2)    (≈ n log n — close to full sort)
          k=n:  n + n·log(n)  = O(n log n)  (degenerates to full sort)

The O(n + k log k) formula interpolates smoothly between
O(n) selection (k=1) and O(n log n) full sort (k=n).
Partial sort is fastest for k ≪ n.
```

## 7. Common Variations & Extensions

### 7.1 `np.partition` with Multiple k Values

You can pass a list of indices to `np.partition`, and it will correctly position all of them simultaneously — useful for computing multiple quantiles in one pass:

```python
arr = np.random.randn(1000)
# Compute Q1, median, Q3 simultaneously — still O(n), not 3 × O(n)
result = np.partition(arr, [249, 499, 749])
q1, median, q3 = result[249], result[499], result[749]
```

Internally, NumPy performs multiple partition passes but shares the partially-sorted state between them, making this faster than three separate `np.partition` calls.

### 7.2 `torch.topk` — GPU-Accelerated Partial Sort

`torch.topk(tensor, k, dim=-1, largest=True, sorted=True)` is PyTorch's equivalent. Key differences from `np.argpartition`:

- `sorted=True` (default): returns values _and_ indices sorted by value — O(n + k log k)
- `sorted=False`: returns unordered top-k — O(n), equivalent to `np.argpartition`
- Runs on CUDA: GPU-accelerated for large tensors, not available via NumPy

For production inference, always use `torch.topk` on GPU tensors rather than `.cpu().numpy()` + `np.argpartition`. The round-trip memory transfer dominates for large tensors.

```python
import torch
scores = torch.randn(1000, 50000, device='cuda')
# Top-10 per row, sorted — O(n_queries × n_items) on GPU
values, indices = torch.topk(scores, k=10, dim=1, sorted=True)
```

### 7.3 Approximate Top-k for Extreme Scale

When n > 10⁸ and a single `np.argpartition` is too slow, approximate methods apply:

- **Reservoir sampling** ([[210.Reservoir sampling — uniform sampling from a stream]]): uniformly sample m ≪ n items, run top-k on the sample. Not exact but O(n) with a small constant.
- **Count-Min Sketch + heavy hitters**: O(1) per update, identifies approximate top-k frequent items for categorical data.
- **FAISS** (`faiss.knn`): GPU-accelerated approximate k-NN using IVF/HNSW indexing — see [[219.Approximate nearest neighbour — LSH, HNSW, FAISS conceptual overview]]. For high-dimensional embeddings, exact `np.argpartition` over millions of vectors is replaced by FAISS, which trades exactness for speed.

### 7.4 `sklearn.feature_selection.SelectKBest` Internals

```python
from sklearn.feature_selection import SelectKBest, f_classif

# Under the hood, SelectKBest.fit() calls:
#   scores, _ = score_func(X, y)          # O(n_samples × n_features)
#   mask = np.zeros(n_features, dtype=bool)
#   mask[np.argpartition(scores, -k)[-k:]] = True  # O(n_features)
# Total: O(n_samples × n_features) — dominated by score computation
```

The feature selection step itself is O(n_features) via `np.argpartition`. The bottleneck is always the score computation, not the selection.

## 9. CP Contest Application

### The `std::partial_sort` vs `std::nth_element` Decision in Contests

C++ offers two standard-library functions for order statistics:

```cpp
// std::partial_sort: O(n log k) — top-k IN SORTED ORDER
// Use when: you need the k smallest in order (output them ranked)
std::partial_sort(arr.begin(), arr.begin() + k, arr.end());
// arr[0..k-1] are the k smallest, sorted ascending

// std::nth_element: O(n) — top-k IN ARBITRARY ORDER
// Use when: you only need the k smallest as a set, or just the k-th element
std::nth_element(arr.begin(), arr.begin() + k, arr.end());
// arr[0..k-1] are the k smallest, UNORDERED
// arr[k] is the (k+1)-th smallest — guaranteed correct
```

**Contest rule:** Always ask "do I need the k elements sorted, or just identified?" If the problem asks you to _output_ the k elements ranked, use `partial_sort` (O(n log k)) or `nth_element` + sort of first k (O(n + k log k)). If you just need the set or a sum, use `nth_element`.

### Performance on Contest Constraints

```
n = 10^7, k = 100 (a common pattern: large n, small k):

std::sort:          ~1.4s  — likely TLE at 2s limit
std::partial_sort:  ~0.15s — 100 × log(10^7) ≈ 2300 ops per element
std::nth_element:   ~0.08s — O(n), small constant
```

For n = 10⁷ with k ≪ n, `std::nth_element` is typically 10–20× faster than `std::sort`. This margin matters for tight time limits. The habit of reaching for `sort` first is one of the most common performance mistakes in CP at the intermediate level.

### The k-th Element as a Binary Search Pivot

A powerful CP pattern: binary search on the answer space, with `nth_element`-based rank counting as the feasibility check.

```
"Does the k-th smallest pairwise sum lie below threshold T?"
  → Count pairs with sum < T using two pointers: O(n)
  → Binary search T over all possible values: O(log(max_val))
  → Total: O(n log(max_val))

This beats naive generation of all pairs (O(n²)) + selection (O(n²)).
```

See [[59.The binary search on answer template — monotonic predicate]] and [[60.Minimise the maximum or maximise the minimum — canonical pattern]] for the full binary-search-on-answer framework that this feeds into.
