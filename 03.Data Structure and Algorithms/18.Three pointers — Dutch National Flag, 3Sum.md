## 1. Intuition First

### The Core Idea

The Dutch National Flag problem asks: given an array of elements coloured red, white, or blue (or equivalently: 0, 1, 2), sort them in-place in a single pass. You are not allowed to count and refill — you must swap elements into place as you go, knowing only what you see right now.

The solution is Dijkstra's three-way partition. Maintain three regions simultaneously, separated by three pointers:

```
[  all 0s  |  all 1s  |  unknown  |  all 2s  ]
           ↑          ↑          ↑
          low        mid        high
```

- Everything left of `low` is confirmed 0.
- Everything between `low` and `mid` is confirmed 1.
- Everything between `mid` and `high` is the unexamined frontier.
- Everything right of `high` is confirmed 2.

`mid` is the active probe. At each step, look at `arr[mid]` and decide:

- It's 0 → swap with `arr[low]`, advance both `low` and `mid` (the swapped element is a 1, already examined).
- It's 1 → it's already in the right region, just advance `mid`.
- It's 2 → swap with `arr[high]`, retreat `high` only (the swapped element from the right is _unknown_, must re-examine `mid`).

The algorithm terminates when `mid > high` — the unknown region is empty.

For **3Sum**, three pointers serve a different purpose: fix one element with an outer loop index `i`, then use [[16.Opposite-end two pointers — sorted array problems]] with `left = i+1` and `right = n-1` to find pairs that complete the triplet. The third "pointer" is the fixed index `i`. They cooperate across two levels of iteration to reduce an O(n³) brute force to O(n²).

### Why This Exists

**DNF:** Two-pointer sort works when you have two categories (partition around one pivot). For _three_ categories, two-pointer fails: you can't maintain two confirmed boundaries simultaneously with only two pointers without either doing two passes or losing the O(1) per-step invariant. Three pointers restore the single-pass, O(1)-per-element guarantee by making the middle pointer both a probe and a boundary owner.

**3Sum:** The naive O(n³) fix-two-elements approach is hopeless at n = 10³ (10⁹ operations, TLE). A HashMap-based fix-one + lookup is O(n²) time and O(n) space, but it struggles to handle duplicates cleanly — you end up doing complex deduplication on the hash results. The sorted + two-pointer approach is O(n²) time and O(1) space, and duplicate skipping becomes a simple linear scan on sorted data.

### The "Aha" Moment

> **DNF:** The asymmetry in the three cases is the key. When you swap a 0 to the left, `mid` advances because the element that came from `low` must have been a 1 (the invariant guarantees `[low..mid-1]` is all 1s). When you swap a 2 to the right, `mid` does _not_ advance because you just received an unknown element from the unexamined right region — you must inspect it before moving on.

> **3Sum:** Sorting converts a 3D search space (choose three indices freely) into a 2D space (fix one, search the other two in a line) with a monotone criterion (sum increases as you move left pointer right, decreases as you move right pointer left). One sorted structure, three pointers, one pass of the outer loop: O(n²).

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- Any "sort array of k distinct values in-place" → DNF generalisation (k-way partition).
- "Find all unique triplets summing to target" → 3Sum template.
- "Count triplets with product < k", "closest 3Sum to target", "4Sum" (fix two, two-pointer on rest) → all 3Sum variants.
- Quicksort's three-way partition (fat partition) to handle duplicate-heavy inputs — without it, quicksort degrades to O(n²) on arrays like `[5,5,5,5,5,5]`.

**Signal pattern:**

```
Array with exactly 3 distinct values, sort in-place, one pass
→ Dutch National Flag (three-way partition)

Find triplets with sum = target, all unique
→ Sort + fix one + two-pointer (3Sum template)

Quicksort and input has many duplicates
→ Three-way partition instead of two-way
```

**Common traps that kill submissions:**

**Trap 1 — DNF: advancing `mid` after swapping a 2.**

```cpp
// BUG: arr[mid] just received an unknown element from arr[high].
// Must NOT advance mid — the newly arrived element must be inspected.
case 2:
    swap(arr[mid], arr[high]);
    high--;
    mid++;  // ← WRONG. Remove this line.
```

**Trap 2 — 3Sum: forgetting to skip duplicates at both the outer loop and inner pointers.**

```cpp
// BUG: produces duplicate triplets like [-1,-1,2],[-1,-1,2]
for (int i = 0; i < n-2; i++) {
    // Missing: if (i > 0 && nums[i] == nums[i-1]) continue;
    int left = i+1, right = n-1;
    while (left < right) {
        if (nums[left]+nums[right]+nums[i] == 0) {
            result.push_back({nums[i], nums[left], nums[right]});
            left++; right--;
            // Missing: skip duplicate lefts and rights
        }
    }
}
```

**Trap 3 — 3Sum: integer overflow.** If values reach 10⁴ and you compare `nums[i] + nums[left] + nums[right]`, the sum fits in int. But if the problem uses values up to 10⁹, the sum requires `long long`. Always check value ranges.

---

### Machine Learning / AI

**Where this appears:**

1. **Three-way data splitting (train/val/test) as a DNF analogue:** When splitting a dataset, you partition indices into three non-overlapping, exhaustive regions. The production implementation in scikit-learn's `train_test_split` (called twice) is sequential, but the optimal single-pass version is exactly DNF: one pointer for train boundary, one for val boundary, scanning from left. NumPy's `np.split` with computed indices does this. Understanding DNF makes you think about _why_ you want a single scan — to avoid loading the dataset twice when working with memory-mapped files or `IterableDataset` in HuggingFace.
    
2. **Three-way merge in external sorting for large ML datasets:** Training data pipelines often need to merge multiple sorted shards (from distributed preprocessing). A three-way merge — maintaining one pointer per sorted shard — is the generalisation of the merge step in merge sort extended to k sources. PyTorch's `ConcatDataset` and TensorFlow's `tf.data.Dataset.zip` both perform this conceptually. The three-pointer merge is O(n log k) for k shards using a heap, but for k=3, a direct three-pointer approach with O(1) overhead per element is cache-optimal.
    
3. **Triplet loss in metric learning:** The 3Sum pattern of "fix one, search for a completing pair" maps directly to **triplet mining** in metric learning (used in FaceNet, sentence embeddings, CLIP fine-tuning). Given an anchor embedding `a`, you need pairs (positive `p`, negative `n`) such that `d(a,p) - d(a,n) + margin < 0` (hard triplets). After sorting candidates by distance to the anchor, you run a two-pointer sweep to find valid (p, n) pairs — exactly 3Sum's pattern. The `pytorch-metric-learning` library's `BatchHardTripletMiner` does this implicitly.
    
4. **Quicksort's three-way partition in `pandas.DataFrame.sort_values`:** Pandas uses a variant of introsort (introspective sort = quicksort + heapsort fallback), and the quicksort mode uses three-way partitioning internally when the data has many duplicate keys (e.g., a categorical column with 5 unique values across 10M rows). Without three-way partition, quicksort degrades to O(n²) on this input. Understanding this is why `sort_values(kind='quicksort')` is documented as potentially slower than `mergesort` on low-cardinality columns — it depends on whether the implementation uses true three-way partitioning.
    
5. **Ternary classification post-processing:** In multi-class calibration (e.g., calibrating a three-class model with Platt scaling), you sometimes need to partition predictions into three confidence bins (high/medium/low) in a single pass before fitting per-bin calibrators. The DNF pointer structure — maintaining three growing regions simultaneously — is precisely the right algorithmic tool. The alternative (three separate filter passes) reads the prediction array three times, which matters when predictions don't fit in L3 cache.
    

**Why this makes you better at ML code:**

The three-way partition mindset — _maintain multiple invariant regions simultaneously in a single scan_ — is directly applicable whenever you're categorising streaming data. Instead of N filter passes (one per category), you do one pass with N-1 boundaries. At 10⁸ rows, this is often the difference between a 2-second pipeline and a 10-second one, purely from cache and memory bandwidth savings.

## 3. Algorithm / Pattern

### Algorithm A: Dutch National Flag (Three-Way Partition)

**Invariant at every step:**

- `arr[0..low-1]` = all 0s (confirmed)
- `arr[low..mid-1]` = all 1s (confirmed)
- `arr[mid..high]` = unknown (unexamined)
- `arr[high+1..n-1]` = all 2s (confirmed)

**Termination condition:** `mid > high` (unknown region is empty).

**Step logic:**

```
Examine arr[mid]:

Case arr[mid] == 0:
    swap(arr[low], arr[mid])
    low++, mid++
    [The element that moved from low to mid was a 1 (invariant),
     so it's now correctly placed in the 1-region. Both boundaries advance.]

Case arr[mid] == 1:
    mid++
    [Already in correct region. Just expand the 1-zone rightward.]

Case arr[mid] == 2:
    swap(arr[mid], arr[high])
    high--
    [arr[mid] now holds an unknown element from the right.
     Do NOT advance mid — must inspect this new element next iteration.]
```

**Complexity:**

- Time: O(n) — `mid` advances or `high` retreats at every step, and they can meet at most n times total. Each element is examined at most once (elements behind `low` and beyond `high` are never re-examined).
- Space: O(1) — three integer pointers.

**Generalisation to k values:** For k distinct values, maintain k+1 regions with k-1 boundaries. Still O(n) time for k=O(1) distinct values. For large k, this degrades — at k = n, you need counting sort instead (see [[49.Counting sort — O(n + k) for integer keys]]).

---

### Algorithm B: 3Sum

**Pre-condition:** Sort the array. This costs O(n log n) but enables the two-pointer inner loop.

**Outer loop:** Fix `nums[i]` as the first element of the triplet. Iterate `i` from 0 to n-3.

**Skip outer duplicates:** If `nums[i] == nums[i-1]` (and `i > 0`), skip — this `i` would generate the same triplets as the previous iteration.

**Inner two-pointer:** Set `left = i+1`, `right = n-1`. Find pairs summing to `-nums[i]`:

- `sum < target` → `left++`
- `sum > target` → `right--`
- `sum == target` → record triplet, skip duplicate `left` values, skip duplicate `right` values, advance both.

**Termination:** Inner loop when `left >= right`; outer loop when `i >= n-2`.

**Complexity:**

- Sorting: O(n log n)
- Outer loop: O(n) iterations
- Inner two-pointer per iteration: O(n) amortised (left and right together take ≤ n steps per outer iteration)
- Total: O(n²)
- Space: O(1) auxiliary (O(k) for output, where k = number of triplets)

**Why O(n²) not O(n³):** For each fixed `i`, the two-pointer inner loop does at most `right - left ≤ n` total moves across the entire inner execution — not O(n) per element examined, but O(n) total for the entire inner sweep. The outer loop runs O(n) times. Together: O(n) × O(n) = O(n²).

### Decision Tree

```
Three-element problem type?
│
├── "Sort array with exactly 3 distinct values, in-place, one pass"
│   └── Dutch National Flag
│       └── Invariant: [0s | 1s | unknown | 2s], mid is the probe
│
├── "Find all unique triplets with sum = 0 (or target)"
│   └── 3Sum: sort + fix i + two-pointer on [i+1..n-1]
│       ├── Must deduplicate: skip outer i duplicates
│       └── Must deduplicate: skip inner left/right duplicates after match
│
├── "Partition around a pivot (quicksort with duplicates)"
│   └── Three-way partition (DNF variant): [<pivot | =pivot | >pivot]
│       └── See [[44.Quicksort — partition, pivot selection, expected O(n log n)]]
│
└── "k ≥ 4 elements summing to target"
    └── Fix k-2 elements with nested loops, two-pointer on innermost
        kSum: O(n^(k-1)) time
```

## 4. Pseudocode

### Dutch National Flag

```
function DUTCH_NATIONAL_FLAG(arr[0..n-1]):
    low  ← 0        # next position for a confirmed 0
    mid  ← 0        # current element under examination
    high ← n - 1    # next position for a confirmed 2

    while mid ≤ high:

        if arr[mid] == 0:
            swap(arr[low], arr[mid])
            low ← low + 1
            mid ← mid + 1
            # arr[low-1] is now 0 (confirmed).
            # The element that came from arr[low] was a 1
            # (invariant: arr[low..mid-1] are all 1s before swap),
            # so arr[mid-1] = 1 is correctly placed. Both advance.

        elif arr[mid] == 1:
            mid ← mid + 1
            # Already in the 1-region. Expand rightward.

        else:  # arr[mid] == 2
            swap(arr[mid], arr[high])
            high ← high - 1
            # arr[high+1] is now 2 (confirmed).
            # arr[mid] now holds an UNKNOWN element from the right.
            # Do NOT advance mid. Re-examine arr[mid] next iteration.
```

### 3Sum

```
function THREE_SUM(arr[0..n-1], target):
    sort(arr)           # O(n log n) — enables two-pointer inner loop
    results ← []

    for i ← 0 to n - 3:

        # Skip duplicate values for the first element
        if i > 0 AND arr[i] == arr[i - 1]:
            continue

        # Early exit: smallest possible triplet already exceeds target
        if arr[i] + arr[i+1] + arr[i+2] > target:
            break

        # Early exit: largest possible triplet still below target
        if arr[i] + arr[n-2] + arr[n-1] < target:
            continue

        left  ← i + 1
        right ← n - 1
        need  ← target - arr[i]    # find pair summing to need

        while left < right:
            s ← arr[left] + arr[right]

            if s == need:
                results.append([arr[i], arr[left], arr[right]])

                # Skip duplicate left values
                while left < right AND arr[left] == arr[left + 1]:
                    left ← left + 1
                # Skip duplicate right values
                while left < right AND arr[right] == arr[right - 1]:
                    right ← right - 1

                left  ← left + 1
                right ← right - 1

            elif s < need:
                left ← left + 1    # sum too small, need larger left

            else:
                right ← right - 1  # sum too large, need smaller right

    return results
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <algorithm>
#include <vector>
#include <iostream>
#include <cassert>

// ─────────────────────────────────────────────────────────────────
// Dutch National Flag — sort array of {0,1,2} in one pass
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
void dutchNationalFlag(std::vector<int>& arr) {
    int low = 0, mid = 0, high = static_cast<int>(arr.size()) - 1;

    while (mid <= high) {
        switch (arr[mid]) {
            case 0:
                std::swap(arr[low++], arr[mid++]);
                // arr[low-1] = 0 (confirmed), arr[mid-1] = 1 (from invariant)
                break;
            case 1:
                mid++;
                break;
            case 2:
                std::swap(arr[mid], arr[high--]);
                // arr[high+1] = 2 (confirmed), arr[mid] = unknown — don't advance mid
                break;
        }
    }
}

// ─────────────────────────────────────────────────────────────────
// Three-way partition (generalised DNF for quicksort)
// Partitions arr[lo..hi] around pivot value.
// Returns {left, right} such that:
//   arr[lo..left-1]  < pivot
//   arr[left..right] == pivot
//   arr[right+1..hi] > pivot
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
std::pair<int,int> threeWayPartition(std::vector<int>& arr, int lo, int hi, int pivot) {
    int low = lo, mid = lo, high = hi;

    while (mid <= high) {
        if (arr[mid] < pivot) {
            std::swap(arr[low++], arr[mid++]);
        } else if (arr[mid] == pivot) {
            mid++;
        } else {
            std::swap(arr[mid], arr[high--]);
        }
    }

    return {low, high};  // [low..high] are all == pivot
}

// ─────────────────────────────────────────────────────────────────
// 3Sum — find all unique triplets summing to target
// Time: O(n²)   Space: O(1) auxiliary, O(k) output
// ─────────────────────────────────────────────────────────────────
std::vector<std::vector<int>> threeSum(std::vector<int>& nums, int target = 0) {
    std::vector<std::vector<int>> result;
    const int n = static_cast<int>(nums.size());

    if (n < 3) return result;

    std::sort(nums.begin(), nums.end());

    for (int i = 0; i < n - 2; ++i) {

        // Skip duplicate outer elements
        if (i > 0 && nums[i] == nums[i - 1]) continue;

        // Pruning: minimum possible sum with this i already exceeds target
        if (nums[i] + nums[i + 1] + nums[i + 2] > target) break;

        // Pruning: maximum possible sum with this i is still below target
        if (nums[i] + nums[n - 2] + nums[n - 1] < target) continue;

        int left = i + 1, right = n - 1;
        int need = target - nums[i];

        while (left < right) {
            int sum = nums[left] + nums[right];

            if (sum == need) {
                result.push_back({nums[i], nums[left], nums[right]});

                // Skip duplicate left values
                while (left < right && nums[left]  == nums[left  + 1]) ++left;
                // Skip duplicate right values
                while (left < right && nums[right] == nums[right - 1]) --right;

                ++left;
                --right;

            } else if (sum < need) {
                ++left;
            } else {
                --right;
            }
        }
    }

    return result;
}

// ─────────────────────────────────────────────────────────────────
// Closest 3Sum — find triplet whose sum is closest to target
// Time: O(n²)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
int threeSumClosest(std::vector<int>& nums, int target) {
    std::sort(nums.begin(), nums.end());
    const int n = static_cast<int>(nums.size());
    int closest = nums[0] + nums[1] + nums[2];

    for (int i = 0; i < n - 2; ++i) {
        if (i > 0 && nums[i] == nums[i - 1]) continue;

        int left = i + 1, right = n - 1;

        while (left < right) {
            int sum = nums[i] + nums[left] + nums[right];

            if (std::abs(sum - target) < std::abs(closest - target)) {
                closest = sum;
            }

            if      (sum < target) ++left;
            else if (sum > target) --right;
            else    return sum;   // exact match — can't do better
        }
    }

    return closest;
}

// ─────── Tests ───────────────────────────────────────────────────
int main() {
    // DNF
    std::vector<int> colors = {2, 0, 2, 1, 1, 0};
    dutchNationalFlag(colors);
    assert((colors == std::vector<int>{0, 0, 1, 1, 2, 2}));

    // DNF edge cases
    std::vector<int> all_same = {1, 1, 1};
    dutchNationalFlag(all_same);
    assert((all_same == std::vector<int>{1, 1, 1}));

    // 3Sum
    std::vector<int> nums = {-1, 0, 1, 2, -1, -4};
    auto triplets = threeSum(nums);
    // Expected: {-1,-1,2}, {-1,0,1}
    assert(triplets.size() == 2);
    assert((triplets[0] == std::vector<int>{-1, -1, 2}));
    assert((triplets[1] == std::vector<int>{-1,  0, 1}));

    // 3Sum no solution
    std::vector<int> no_sol = {0, 1, 1};
    assert(threeSum(no_sol).empty());

    // Closest 3Sum
    std::vector<int> c = {-1, 2, 1, -4};
    assert(threeSumClosest(c, 1) == 2);  // {-1,2,1} sums to 2

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import List, Tuple


def dutch_national_flag(arr: List[int]) -> None:
    """
    Sort an array of {0, 1, 2} in-place in a single pass.

    Three regions maintained at all times:
        arr[0..low-1]   → all 0s (confirmed)
        arr[low..mid-1] → all 1s (confirmed)
        arr[mid..high]  → unknown (unexamined)
        arr[high+1..]   → all 2s (confirmed)

    Complexity: O(n) time, O(1) space
    """
    low, mid, high = 0, 0, len(arr) - 1

    while mid <= high:
        if arr[mid] == 0:
            arr[low], arr[mid] = arr[mid], arr[low]
            low += 1
            mid += 1
            # Element from arr[low] was a 1 (invariant) → now at mid-1, correct.
        elif arr[mid] == 1:
            mid += 1
            # Already in correct region. Expand 1-zone.
        else:  # arr[mid] == 2
            arr[mid], arr[high] = arr[high], arr[mid]
            high -= 1
            # arr[mid] is now unknown (came from right). Do NOT advance mid.


def three_way_partition(arr: List[int], lo: int, hi: int, pivot: int) -> Tuple[int, int]:
    """
    Partition arr[lo..hi] into three regions around pivot:
        arr[lo..left-1]  < pivot
        arr[left..right] == pivot
        arr[right+1..hi] > pivot

    Returns (left, right) boundaries of the equal region.
    Used as the core of three-way quicksort (fat partition).

    Complexity: O(hi - lo) time, O(1) space
    """
    low, mid, high = lo, lo, hi

    while mid <= high:
        if arr[mid] < pivot:
            arr[low], arr[mid] = arr[mid], arr[low]
            low += 1
            mid += 1
        elif arr[mid] == pivot:
            mid += 1
        else:
            arr[mid], arr[high] = arr[high], arr[mid]
            high -= 1

    return low, high  # [low..high] are all == pivot


def three_sum(nums: List[int], target: int = 0) -> List[List[int]]:
    """
    Find all unique triplets in nums that sum to target.

    Strategy: sort → fix first element → two-pointer on remainder.
    Duplicate skipping at both the outer index and inner pointers
    ensures uniqueness without a HashSet.

    Complexity: O(n²) time, O(1) auxiliary space
    """
    nums.sort()
    n = len(nums)
    result: List[List[int]] = []

    for i in range(n - 2):

        # Skip duplicate values for the fixed element
        if i > 0 and nums[i] == nums[i - 1]:
            continue

        # Pruning: even the three smallest remaining exceed target
        if nums[i] + nums[i + 1] + nums[i + 2] > target:
            break

        # Pruning: even the two largest remaining can't reach target
        if nums[i] + nums[n - 2] + nums[n - 1] < target:
            continue

        left, right = i + 1, n - 1
        need = target - nums[i]

        while left < right:
            s = nums[left] + nums[right]

            if s == need:
                result.append([nums[i], nums[left], nums[right]])

                # Skip duplicate left values
                while left < right and nums[left] == nums[left + 1]:
                    left += 1
                # Skip duplicate right values
                while left < right and nums[right] == nums[right - 1]:
                    right -= 1

                left += 1
                right -= 1

            elif s < need:
                left += 1
            else:
                right -= 1

    return result


def three_sum_closest(nums: List[int], target: int) -> int:
    """
    Return the sum of the triplet closest to target.
    On tie, return the smaller sum.

    Complexity: O(n²) time, O(1) space
    """
    nums.sort()
    n = len(nums)
    closest = nums[0] + nums[1] + nums[2]

    for i in range(n - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue

        left, right = i + 1, n - 1

        while left < right:
            s = nums[i] + nums[left] + nums[right]

            if abs(s - target) < abs(closest - target):
                closest = s

            if s < target:
                left += 1
            elif s > target:
                right -= 1
            else:
                return s  # exact match

    return closest


def four_sum(nums: List[int], target: int) -> List[List[int]]:
    """
    Find all unique quadruplets summing to target.
    Extends 3Sum: fix two outer elements, two-pointer on the rest.

    Complexity: O(n³) time, O(1) auxiliary space

    This demonstrates the kSum pattern: each additional fixed element
    adds one O(n) outer loop, multiplying total complexity by n.
    """
    nums.sort()
    n = len(nums)
    result: List[List[int]] = []

    for i in range(n - 3):
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        if nums[i] + nums[i+1] + nums[i+2] + nums[i+3] > target:
            break
        if nums[i] + nums[n-3] + nums[n-2] + nums[n-1] < target:
            continue

        for j in range(i + 1, n - 2):
            if j > i + 1 and nums[j] == nums[j - 1]:
                continue
            if nums[i] + nums[j] + nums[j+1] + nums[j+2] > target:
                break
            if nums[i] + nums[j] + nums[n-2] + nums[n-1] < target:
                continue

            left, right = j + 1, n - 1
            need = target - nums[i] - nums[j]

            while left < right:
                s = nums[left] + nums[right]
                if s == need:
                    result.append([nums[i], nums[j], nums[left], nums[right]])
                    while left < right and nums[left]  == nums[left  + 1]: left  += 1
                    while left < right and nums[right] == nums[right - 1]: right -= 1
                    left += 1
                    right -= 1
                elif s < need:
                    left += 1
                else:
                    right -= 1

    return result
```

## 6. Visual Explanation

### DNF: The Three-Region Invariant in Motion

Input: `[2, 0, 2, 1, 1, 0]`

```
Initial state:
  [2,  0,  2,  1,  1,  0]
   L                    H     low=0, mid=0, high=5
   M

Step 1: arr[mid=0]=2 → swap(mid,high), high--
  [0,  0,  2,  1,  1,  2]
   L               H         (arr[5]=2 confirmed)
   M               

Step 2: arr[mid=0]=0 → swap(low,mid), low++, mid++
  [0,  0,  2,  1,  1,  2]
       L            H         (arr[0]=0 confirmed)
       M

Step 3: arr[mid=1]=0 → swap(low,mid), low++, mid++
  [0,  0,  2,  1,  1,  2]
            L        H        (arr[1]=0 confirmed)
            M

Step 4: arr[mid=2]=2 → swap(mid,high), high--
  [0,  0,  1,  1,  2,  2]
            L   H             (arr[4]=2 confirmed)
            M

Step 5: arr[mid=2]=1 → mid++
  [0,  0,  1,  1,  2,  2]
            L   H
                M

Step 6: arr[mid=3]=1 → mid++
  [0,  0,  1,  1,  2,  2]
            L   H
                    M

Now mid(4) > high(3) → STOP.

Final: [0, 0, 1, 1, 2, 2] ✓

Region trace at termination:
  [0, 0, | 1, 1, | — | 2, 2]
         L       M         H
  (unknown region is empty: mid > high)
```

### Why `mid` Doesn't Advance After Swapping a 2

```
Before swap:
  [ ...confirmed 0s... | ...confirmed 1s... | ? | ? | ? | ...confirmed 2s... ]
                        low                mid                           high

arr[mid] = 2. We swap arr[mid] with arr[high]:

After swap:
  [ ...confirmed 0s... | ...confirmed 1s... | X | ? | ? | 2 | ...conf. 2s... ]
                        low                mid               high

X came from arr[high] — it was in the UNKNOWN region. We have no
information about X. We must inspect it before calling mid "safe."

If we advanced mid, X would silently enter the "confirmed 1s" region —
corrupting the invariant.

Contrast with swapping a 0:
  arr[low] was in the confirmed-1s region [low..mid-1].
  So the element arriving at arr[mid] from arr[low] IS a 1.
  We can safely advance both pointers.
```

### 3Sum: The Three-Pointer Geometry

For `nums = [-4, -1, -1, 0, 1, 2]`, target = 0, outer `i=1` (nums[i]=-1):

```
Sorted: [-4, -1, -1,  0,  1,  2]
              i   L              R     need = 0-(-1) = 1
              ↑                  ↑
            fixed              right

Step 1: L=2, R=5: nums[L]+nums[R] = -1+2 = 1 = need → RECORD [-1,-1,2]
        Skip dup L: nums[2]=-1==nums[3]=0? No. Skip dup R: nums[5]=2==nums[4]=1? No.
        L→3, R→4

Step 2: L=3, R=4: nums[L]+nums[R] = 0+1 = 1 = need → RECORD [-1,0,1]
        L→4, R→3

Step 3: L(4) >= R(3) → inner loop ends.

Outer loop i=2: nums[2]=-1 == nums[1]=-1 → SKIP (duplicate outer)
Outer loop i=3: nums[3]=0, need=0. L=4, R=5.
  nums[4]+nums[5]=1+2=3 > 0 → R--. L≥R → done.
```

## 7. Common Variations & Extensions

### Variation 1: Three-Way Quicksort (Fat Partition)

When input has many duplicates, standard two-way quicksort degrades to O(n²) — every partition step only removes one element (the pivot). Three-way partition groups _all_ elements equal to the pivot into a "fat middle" region in one pass, then only recurses on the strictly-smaller and strictly-larger regions. This makes quicksort O(n log n) even on inputs like `[5,5,5,5,5,5]`. See [[44.Quicksort — partition, pivot selection, expected O(n log n)]] and [[45.Quicksort — worst case, randomised pivot, introsort]].

```python
def quicksort_3way(arr: list, lo: int, hi: int) -> None:
    if lo >= hi:
        return
    pivot = arr[(lo + hi) // 2]
    left, right = three_way_partition(arr, lo, hi, pivot)
    quicksort_3way(arr, lo, left - 1)
    quicksort_3way(arr, right + 1, hi)
```

### Variation 2: 3Sum Smaller / 3Sum Larger

"Count triplets with sum < target." After fixing `i`, the two-pointer inner loop: whenever `nums[left]+nums[right] < need`, all pairs `(left, left+1, ..., right-1)` with `right` also satisfy the condition — add `right - left` to count. O(n²) with no result list needed, no duplicate management required.

```python
def three_sum_smaller(nums: list, target: int) -> int:
    nums.sort()
    count = 0
    for i in range(len(nums) - 2):
        left, right = i + 1, len(nums) - 1
        while left < right:
            if nums[i] + nums[left] + nums[right] < target:
                count += right - left  # all pairs (left, left+1..right-1) valid
                left += 1
            else:
                right -= 1
    return count
```

### Variation 3: k-Way Partition for k > 3

Generalise DNF to k distinct values. With k regions, maintain k-1 boundary pointers. The unknown region shrinks from both ends. For k ≤ 5, explicit pointer logic is tractable; for larger k, use counting sort instead (see [[49.Counting sort — O(n + k) for integer keys]]). The decision boundary between these approaches: if k = O(1), use DNF generalisation; if k = O(n), use counting sort.

### Variation 4: Sort Colors with Arbitrary Values (Not 0,1,2)

If the three categories aren't 0/1/2 but arbitrary values (e.g., "low/medium/high" based on a threshold), define a `classify(x)` function returning {0,1,2} and apply DNF using that function. The pointer logic is identical; only the comparison changes. This appears in ML pipeline batch sorting: classify samples as "easy/medium/hard" by loss value in curriculum learning, then batch them into three groups in a single array pass.

### Connection to Sorting Landscape

DNF is counting sort's spiritual sibling for k=3. Counting sort (see [[49.Counting sort — O(n + k) for integer keys]]) does two passes: count then place. DNF does one pass but requires swaps. DNF is preferable when swapping is cheap and two passes would require reading the array twice (e.g., memory-mapped files). Counting sort is preferable when k is known and you want to avoid swaps (e.g., object arrays where swaps are expensive copy operations).

## 9. CP Contest Application

### Typical Problem Structures

**Type 1 — DNF / Three-way partition (Div. 2 B):** "Given an array, partition it into three groups (elements < k, = k, > k) in-place without extra memory." Straightforward DNF application. The marker is "in-place" + "exactly three categories." At n = 2×10⁵, any approach doing multiple passes reads 4×10⁵ elements from memory; DNF reads 2×10⁵ — twice as cache-friendly.

**Type 2 — 3Sum Count (Div. 2 C / Div. 1 B):** "Count the number of triplets (i,j,k) with i<j<k such that `a[i]+a[j]+a[k] = 0`." Fix `i` with outer loop, two-pointer count for `j` and `k`. Crucially, when `nums[left]+nums[right] == need`, you must count _all combinations_ of duplicates, not just one — this requires counting the run lengths of equal values at both ends before advancing:

```cpp
// Count variant of 3Sum inner loop:
if (sum == need) {
    if (nums[left] == nums[right]) {
        // All pairs from this equal block
        long long cnt = right - left + 1;
        result += cnt * (cnt - 1) / 2;
        break;
    }
    long long left_cnt = 1, right_cnt = 1;
    while (left + left_cnt < right && nums[left] == nums[left + left_cnt])
        left_cnt++;
    while (right - right_cnt > left && nums[right] == nums[right - right_cnt])
        right_cnt++;
    result += left_cnt * right_cnt;
    left  += left_cnt;
    right -= right_cnt;
}
```

**Type 3 — Three-way quicksort on a specific key (Div. 1 C):** Problems involving "sort an array where many elements repeat" with strict time limits (0.5s). Standard `std::sort` (introsort) already handles this, but if you're implementing a custom sort for a non-standard comparison (e.g., sort by parity then magnitude), three-way partition on the first key before recursing on the second is 2–3× faster than a generic comparator sort.

### Time Limit Table

|Algorithm|n = 10⁵|n = 10⁶|n = 10⁷|Notes|
|---|---|---|---|---|
|DNF (O(n))|<1ms|~5ms|~50ms|Always fits 1s limit|
|3Sum (O(n²))|~10ms|~10s (TLE)|TLE|Only viable to n ~ 3×10³|
|Brute 3Sum (O(n³))|TLE|TLE|TLE|Never use in contest|
|4Sum (O(n³))|TLE at 10⁴|TLE|TLE|Viable only n ≤ 500|

**Key contest boundary:** 3Sum is viable for n ≤ ~3000 with a 2s limit. Above that, you need a fundamentally different approach (FFT-based convolution for counting, meet-in-the-middle for existence).
