## 1. Intuition First

### The Core Idea

Imagine you have two enormous bags of words — say, two web pages, each with millions of tokens. You want to know how _similar_ they are. The exact answer is easy to define:

$$J(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

This is the **Jaccard similarity** — the fraction of the combined vocabulary that both documents share. If two pages share 80% of their words, J = 0.8. If they share nothing, J = 0.0.

The problem: computing this exactly over billions of document pairs requires O(|A| + |B|) per pair, and when you have 10 billion web pages, that is not a number you can pay your AWS bill with.

**MinHash is a randomised trick that compresses each set into a tiny _signature_ — a vector of k integers — such that comparing two signatures gives you an unbiased estimate of their Jaccard similarity.**

The key metaphor: imagine randomly shuffling all the elements in the universe into a long list (a random permutation π). The _minimum_ element in set A under this permutation is `min_π(A)`. The insight — which is the entire algorithm in one sentence — is:

$$P[\min_\pi(A) = \min_\pi(B)] = \frac{|A \cap B|}{|A \cup B|} = J(A, B)$$

Why? The minimum of the union falls in the intersection if and only if both sets contain it. The probability of that is exactly the fraction of the union that the intersection covers. This is not an approximation — it is an _exact_ probabilistic identity.

### Why This Exists — The Complexity Gap

Naïve pairwise similarity over n documents costs O(n² · d) where d is average document length. For n = 10⁹, this is computationally infeasible. MinHash reduces each document to a signature of k integers (k ≈ 100–200), making pairwise comparison O(k) — a reduction from millions of operations to hundreds.

Moreover, the **variance** of the estimator decreases as O(1/k), so you can control the error budget precisely.

### The "Aha" Moment

You never need to actually generate random permutations. A hash function `h(x)` applied to set elements acts as a random permutation of the universe. So `min_{x ∈ A} h(x)` is your MinHash value for set A under permutation h. Repeat with k independent hash functions → k-dimensional signature. **Hashing replaces permutation.** This is the implementation insight that makes MinHash practical.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** MinHash itself is rare in standard CP contests. Its building block — random hashing for set comparison — appears in problems involving:

- Detecting duplicate or near-duplicate substrings in a string
- Comparing multisets efficiently
- Probabilistic verification of set equality (where an exact check is O(n) but you need O(1) amortised)

**Pattern signal:** Whenever you see a problem asking "find all pairs from n large sets with Jaccard ≥ threshold θ," the naive O(n²) scan is too slow. MinHash + banding (see §7) reduces this to near-linear time.

**Common trap:** Using the same hash function multiple times (e.g., calling `rand()` without resetting the seed) gives correlated MinHash values that do not reduce variance. Each of the k hash functions must be **independently** drawn — in practice, use `h_i(x) = (a_i * x + b_i) % p` with randomly chosen coefficients a_i, b_i and a prime p > |universe|.

**Another trap:** Treating MinHash as an exact algorithm. It estimates J with variance $\frac{J(1-J)}{k}$. For k=100, the standard deviation is at most $\frac{1}{2\sqrt{100}} = 0.05$. Accept this error or increase k.

---

### Machine Learning / AI

**Exact ML appearance:**

1. **Web-scale deduplication (Google, CommonCrawl, The Pile):** Near-duplicate web page detection before training large language models. The C4 dataset, RedPajama, and Dolma all use MinHash-based deduplication. The exact pipeline: shingling → MinHash signatures → LSH banding → exact deduplication of candidate pairs. The 2022 paper _"Deduplicating Training Data Makes Language Models Better"_ (Lee et al., NAACL 2022) uses this pipeline verbatim.
    
2. **Recommendation systems — Collaborative filtering via Jaccard:** User-item interaction sets (which movies has user A watched?) have high Jaccard similarity iff users have similar taste. MinHash compresses user histories into fixed-size vectors for fast ANN retrieval — this predates embedding-based approaches and is still used in production at Pinterest (Pixie) and LinkedIn.
    
3. **`datasketch` library (Python):** The de-facto standard. `datasketch.MinHash` and `datasketch.MinHashLSH` implement exactly what is described here. Understanding this note means you understand the library's internals, not just its API.
    
4. **Document similarity in ElasticSearch / OpenSearch:** The `more_like_this` query uses a variant of MinHash under the hood for candidate retrieval before BM25 rescoring.
    
5. **Better ML code from understanding this:** When you call `datasketch.MinHashLSH.query()`, you know it is running banded LSH — you can tune `num_perm` and `threshold` with understanding instead of grid search. You also know that MinHash is _set-based_ (word order doesn't matter), which tells you when to use it (bag-of-words deduplication) vs. when not to (semantic similarity, where embeddings + cosine distance are correct).

## 3. Algorithm / Pattern

### Step-by-Step Logic

**Setup:**

1. Represent each document as a **set of shingles** (k-grams of characters or words). A 3-shingle of "abcde" is `{"abc", "bcd", "cde"}`.
2. Choose k independent hash functions `h_1, h_2, ..., h_k`.
3. For each set A, compute its MinHash signature: `sig(A)[i] = min_{x ∈ A} h_i(x)` for i = 1..k

**Comparison:**

- `Ĵ(A, B) = (1/k) · |{i : sig(A)[i] == sig(B)[i]}|`
- This is an unbiased estimator of J(A, B).

**Decision Tree:**

```
Need to compare sets for similarity?
│
├─ Exact Jaccard needed?
│   └─ Yes → Compute directly. O(|A|+|B|) per pair.
│
├─ Approximate OK, small n (< 10k sets)?
│   └─ Yes → MinHash signatures, brute-force O(n²·k) comparison.
│
├─ Approximate OK, large n?
│   └─ Yes → MinHash + LSH banding → O(n·k + candidates·k)
│
└─ Sets have numeric features, not discrete items?
    └─ Use cosine similarity + SimHash instead (see §7).
```

### Complexity Derivation

**Signature construction:** For each document with d elements, and k hash functions:

- Each `min_{x ∈ A} h_i(x)` costs O(d) — one pass over the set.
- Total per document: O(k · d).
- Total for n documents: O(n · k · d).

**Pairwise comparison using signatures:** O(n² · k) — comparing every pair of k-length signature vectors.

**With LSH banding (b bands of r rows each, b·r = k):**

- A pair becomes a candidate if _any_ band matches exactly.
- Expected candidates: O(n · n_candidates) where n_candidates ≪ n.
- False positives and false negatives are controlled by choosing b and r (see §7).

**Space:** O(n · k) integers for all signatures.

### When to Use vs. Avoid

|Use MinHash|Avoid MinHash|
|---|---|
|Set-based similarity (bags of words, shingles)|Ordered sequence similarity (use edit distance)|
|Web-scale deduplication (n > 10⁶)|Numeric vector similarity (use cosine/Euclidean)|
|Streaming (update signature incrementally)|When exact similarity is mandatory|
|Jaccard threshold ≥ 0.5 (high-precision regime)|Dense sets where d ≈ \|universe\||

## 4. Pseudocode

```
Algorithm: MinHash Signature Construction
Input:  Set A ⊆ Universe U, integer k (number of hash functions)
Output: sig[1..k] — MinHash signature of A

  // Select k independent hash functions at random
  // Each h_i: U → {0, 1, ..., M-1} for large prime M
  // Practical: h_i(x) = (a_i * x + b_i) % p, p prime > |U|
  for i = 1 to k:
      a_i ← random integer in [1, p-1]
      b_i ← random integer in [0, p-1]

  // Compute signature
  for i = 1 to k:
      sig[i] ← +∞                // Will become the minimum

  for each element x in A:
      for i = 1 to k:
          h ← hash_i(x)          // Apply i-th hash function to x
          if h < sig[i]:
              sig[i] ← h         // Track the running minimum

  return sig


Algorithm: Estimate Jaccard Similarity
Input:  sig_A[1..k], sig_B[1..k]
Output: Estimated J(A, B) ∈ [0, 1]

  matches ← 0
  for i = 1 to k:
      if sig_A[i] == sig_B[i]:   // Same minimum → likely in intersection
          matches ← matches + 1

  return matches / k              // Unbiased estimator of J(A, B)


Algorithm: LSH Banding for Candidate Generation
Input:  Signatures {sig_1, ..., sig_n}, band size r, num bands b (b*r = k)
Output: Candidate pairs with estimated J > threshold

  // A pair is a candidate if at least one band hashes identically
  // Threshold θ ≈ (1/b)^(1/r) — tune b and r to target this

  for each band j = 1 to b:
      bucket_map ← empty HashMap
      for each document d = 1 to n:
          band_key ← sig_d[j*r .. (j+1)*r - 1]   // Slice of signature
          bucket_map[hash(band_key)].append(d)     // Documents sharing this band

      for each bucket in bucket_map:
          if |bucket| > 1:
              emit all pairs in bucket as candidates

  // Candidates: deduplicate, then verify with exact Jaccard if needed
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <algorithm>
#include <cstdint>
#include <limits>
#include <random>
#include <string>
#include <unordered_map>
#include <vector>

// MinHash signature for set similarity estimation.
// Uses the universal hash family: h_i(x) = (a_i * x + b_i) % PRIME
// Time:  O(k * |set|) per signature
// Space: O(k) per signature
class MinHash {
public:
    static constexpr uint64_t PRIME = (1ULL << 61) - 1;  // Mersenne prime

    explicit MinHash(int num_hashes, uint64_t seed = 42)
        : k_(num_hashes), a_(num_hashes), b_(num_hashes)
    {
        std::mt19937_64 rng(seed);
        std::uniform_int_distribution<uint64_t> dist(1, PRIME - 1);
        for (int i = 0; i < k_; ++i) {
            a_[i] = dist(rng);
            b_[i] = dist(rng);
        }
    }

    // Compute MinHash signature for a set of 64-bit integer elements.
    // Pass shingle hashes (e.g., std::hash<std::string>) as elements.
    std::vector<uint64_t> signature(const std::vector<uint64_t>& elements) const {
        std::vector<uint64_t> sig(k_, std::numeric_limits<uint64_t>::max());

        for (uint64_t x : elements) {
            for (int i = 0; i < k_; ++i) {
                // Modular multiplication under Mersenne prime (avoids overflow)
                uint64_t h = mod_prime(a_[i] * (__uint128_t)x + b_[i]);
                if (h < sig[i]) sig[i] = h;
            }
        }
        return sig;
    }

    // Estimate Jaccard similarity from two precomputed signatures.
    // Returns value in [0.0, 1.0]. Unbiased estimator, std_dev = sqrt(J(1-J)/k).
    static double estimate_jaccard(const std::vector<uint64_t>& sig_a,
                                   const std::vector<uint64_t>& sig_b)
    {
        if (sig_a.size() != sig_b.size()) return 0.0;
        int matches = 0;
        for (size_t i = 0; i < sig_a.size(); ++i)
            if (sig_a[i] == sig_b[i]) ++matches;
        return static_cast<double>(matches) / sig_a.size();
    }

private:
    int k_;
    std::vector<uint64_t> a_, b_;

    static uint64_t mod_prime(unsigned __int128 x) {
        // Efficient mod 2^61 - 1
        uint64_t lo = x & PRIME;
        uint64_t hi = x >> 61;
        uint64_t result = lo + hi;
        if (result >= PRIME) result -= PRIME;
        return result;
    }
};

// LSH Banding: find candidate pairs with J > threshold.
// b bands of r rows each (b * r == total hash count).
// Pairs sharing at least one band are candidates.
// Probability of being a candidate ≈ 1 - (1 - J^r)^b.
// Set r and b to make threshold = (1/b)^(1/r).
class MinHashLSH {
public:
    MinHashLSH(int num_bands, int rows_per_band)
        : b_(num_bands), r_(rows_per_band), buckets_(num_bands) {}

    void insert(int doc_id, const std::vector<uint64_t>& sig) {
        for (int band = 0; band < b_; ++band) {
            uint64_t band_hash = hash_band(sig, band);
            buckets_[band][band_hash].push_back(doc_id);
        }
    }

    // Return all document IDs that share at least one band with the query.
    std::vector<int> query(const std::vector<uint64_t>& sig) const {
        std::unordered_map<int, bool> seen;
        for (int band = 0; band < b_; ++band) {
            uint64_t band_hash = hash_band(sig, band);
            auto it = buckets_[band].find(band_hash);
            if (it != buckets_[band].end())
                for (int id : it->second) seen[id] = true;
        }
        std::vector<int> result;
        for (auto& [id, _] : seen) result.push_back(id);
        return result;
    }

private:
    int b_, r_;
    std::vector<std::unordered_map<uint64_t, std::vector<int>>> buckets_;

    uint64_t hash_band(const std::vector<uint64_t>& sig, int band) const {
        // FNV-1a over the band's rows
        uint64_t h = 14695981039346656037ULL;
        for (int row = band * r_; row < (band + 1) * r_; ++row) {
            h ^= sig[row];
            h *= 1099511628211ULL;
        }
        return h;
    }
};
```

### Python (Readable + Pythonic)

```python
"""
MinHash — Estimating Jaccard Similarity at Scale

Time:  O(k * d) per signature construction, d = |set|
Space: O(k) per signature

Unbiased estimator. Standard deviation: sqrt(J(1-J) / k).
For k=128, max std_dev ≈ 0.044.
"""

from __future__ import annotations
import hashlib
import struct
from dataclasses import dataclass, field
from typing import Iterable
from collections import defaultdict


# ---------------------------------------------------------------------------
# Core MinHash
# ---------------------------------------------------------------------------

MERSENNE_PRIME = (1 << 61) - 1   # 2^61 - 1, a large Mersenne prime
MAX_HASH       = (1 << 32) - 1   # We keep values in 32-bit range for speed


@dataclass
class MinHash:
    """
    MinHash signature for a set of hashable elements.

    Args:
        num_perm: Number of hash functions (permutations). Higher k → lower variance.
                  k=128 gives std_dev ≤ 0.044. k=256 gives ≤ 0.031.
        seed:     Random seed for reproducibility.
    """
    num_perm: int = 128
    seed:     int = 42
    _hashvalues: list[int] = field(init=False, repr=False)
    _a: list[int]          = field(init=False, repr=False)
    _b: list[int]          = field(init=False, repr=False)

    def __post_init__(self) -> None:
        import random
        rng = random.Random(self.seed)
        self._a = [rng.randint(1, MERSENNE_PRIME - 1) for _ in range(self.num_perm)]
        self._b = [rng.randint(0, MERSENNE_PRIME - 1) for _ in range(self.num_perm)]
        self._hashvalues = [MAX_HASH] * self.num_perm   # Initialise to +∞

    def update(self, element: bytes | str) -> None:
        """Add one element to the set and update the signature in-place."""
        if isinstance(element, str):
            element = element.encode("utf-8")
        # SHA-1 gives a uniform 160-bit digest; take first 8 bytes as uint64
        digest = hashlib.sha1(element).digest()
        hv = struct.unpack(">Q", digest[:8])[0]   # Big-endian unsigned 64-bit

        # Update each permutation's running minimum
        # h_i(x) = (a_i * hv + b_i) % MERSENNE_PRIME & MAX_HASH
        for i in range(self.num_perm):
            v = (self._a[i] * hv + self._b[i]) % MERSENNE_PRIME & MAX_HASH
            if v < self._hashvalues[i]:
                self._hashvalues[i] = v

    def update_batch(self, elements: Iterable[bytes | str]) -> None:
        """Convenience: add multiple elements at once."""
        for e in elements:
            self.update(e)

    def jaccard(self, other: "MinHash") -> float:
        """
        Estimate Jaccard similarity between self and other.

        Returns:
            Float in [0.0, 1.0]. Unbiased estimator of J(A, B).
        """
        if self.num_perm != other.num_perm:
            raise ValueError("num_perm must match between MinHash objects")
        matches = sum(
            1 for a, b in zip(self._hashvalues, other._hashvalues) if a == b
        )
        return matches / self.num_perm

    @property
    def hashvalues(self) -> list[int]:
        return list(self._hashvalues)


# ---------------------------------------------------------------------------
# LSH Banding for sub-linear candidate retrieval
# ---------------------------------------------------------------------------

class MinHashLSH:
    """
    Locality-Sensitive Hashing using banded MinHash signatures.

    A pair (A, B) becomes a candidate if they share at least one identical band.
    Probability of becoming a candidate: P ≈ 1 - (1 - J^r)^b.

    The S-curve defined by b and r creates a threshold at θ ≈ (1/b)^(1/r).
    Below θ: most dissimilar pairs are filtered out.
    Above θ: most similar pairs are kept.

    Args:
        threshold: Target Jaccard threshold. b and r are auto-tuned.
        num_perm:  Must match the MinHash objects used with this LSH index.
    """

    def __init__(self, threshold: float = 0.5, num_perm: int = 128) -> None:
        self.threshold = threshold
        self.num_perm  = num_perm
        self.b, self.r = self._optimal_params(threshold, num_perm)
        # buckets[band_index][band_hash] → list of keys
        self._buckets: list[dict[int, list]] = [defaultdict(list) for _ in range(self.b)]

    @staticmethod
    def _optimal_params(threshold: float, num_perm: int) -> tuple[int, int]:
        """
        Find b, r that minimise false positives + false negatives at given threshold.
        Searches over all valid (b, r) pairs where b * r == num_perm.
        """
        best_b, best_r, best_err = 1, num_perm, float("inf")
        for b in range(1, num_perm + 1):
            if num_perm % b != 0:
                continue
            r = num_perm // b
            # False negative rate at threshold: (1 - threshold^r)^b
            # False positive rate at threshold - epsilon: not tractable analytically
            # Minimise | (1/b)^(1/r) - threshold |
            approx_threshold = (1.0 / b) ** (1.0 / r)
            err = abs(approx_threshold - threshold)
            if err < best_err:
                best_err, best_b, best_r = err, b, r
        return best_b, best_r

    def insert(self, key: str, minhash: MinHash) -> None:
        """Insert a document with given key into the LSH index."""
        hv = minhash.hashvalues
        for band_idx in range(self.b):
            start = band_idx * self.r
            band  = tuple(hv[start : start + self.r])
            self._buckets[band_idx][hash(band)].append(key)

    def query(self, minhash: MinHash) -> list[str]:
        """Return all keys that are candidates (share ≥1 band) with the query."""
        hv   = minhash.hashvalues
        seen = set()
        for band_idx in range(self.b):
            start    = band_idx * self.r
            band     = tuple(hv[start : start + self.r])
            band_key = hash(band)
            for key in self._buckets[band_idx].get(band_key, []):
                seen.add(key)
        return list(seen)


# ---------------------------------------------------------------------------
# Helper: Shingle generation for documents
# ---------------------------------------------------------------------------

def shingle(text: str, k: int = 5) -> set[str]:
    """
    Generate k-character shingles from text.
    Standard preprocessing before MinHash.
    """
    text = text.lower()
    return {text[i:i+k] for i in range(len(text) - k + 1)}


# ---------------------------------------------------------------------------
# Demo
# ---------------------------------------------------------------------------

if __name__ == "__main__":
    doc_a = "the cat sat on the mat"
    doc_b = "the cat sat on the hat"
    doc_c = "completely unrelated document about quantum physics"

    # True Jaccard (5-shingles)
    sh_a, sh_b, sh_c = shingle(doc_a), shingle(doc_b), shingle(doc_c)
    true_ab = len(sh_a & sh_b) / len(sh_a | sh_b)
    true_ac = len(sh_a & sh_c) / len(sh_a | sh_c)
    print(f"True J(A,B)  = {true_ab:.4f}")
    print(f"True J(A,C)  = {true_ac:.4f}")

    # MinHash estimates
    mh_a = MinHash(num_perm=256); mh_a.update_batch(sh_a)
    mh_b = MinHash(num_perm=256); mh_b.update_batch(sh_b)
    mh_c = MinHash(num_perm=256); mh_c.update_batch(sh_c)

    print(f"Est  J(A,B)  = {mh_a.jaccard(mh_b):.4f}")  # Should be near true_ab
    print(f"Est  J(A,C)  = {mh_a.jaccard(mh_c):.4f}")  # Should be near true_ac

    # LSH: given threshold 0.5, which documents are candidates for A?
    lsh = MinHashLSH(threshold=0.5, num_perm=256)
    lsh.insert("B", mh_b)
    lsh.insert("C", mh_c)
    print(f"LSH candidates for A: {lsh.query(mh_a)}")  # Should include "B", not "C"
```

## 6. Visual Explanation

### Diagram 1: The Core Probability Identity

```
Universe U = { 1, 2, 3, 4, 5, 6, 7, 8 }
Set A      = { 1, 2, 3, 4, 5 }
Set B      = { 3, 4, 5, 6, 7 }

                A ∩ B = { 3, 4, 5 }        |A ∩ B| = 3
                A ∪ B = { 1,2,3,4,5,6,7 }  |A ∪ B| = 7

True Jaccard: J(A,B) = 3/7 ≈ 0.429

Random permutation π of U:   [ 6, 3, 8, 1, 5, 7, 2, 4 ]
                               ↑
                          index 0 = smallest

min_π(A) = first element of π that belongs to A = 3  (position 1)
min_π(B) = first element of π that belongs to B = 6  (position 0)

min_π(A) ≠ min_π(B) → no match for this permutation

Another permutation π': [ 5, 2, 3, 7, 1, 6, 4, 8 ]

min_π'(A) = 5  (position 0, first in π' that is in A)
min_π'(B) = 5  (position 0, first in π' that is in B)

min_π'(A) == min_π'(B) → MATCH ✓

WHY does this work?
The minimum of A ∪ B is determined by the permutation.
That minimum is in A ∩ B iff and only iff both sets contain it.
This happens with probability |A ∩ B| / |A ∪ B| = J(A,B). ∎
```

## 7. Common Variations & Extensions

### Variation 1: Weighted MinHash (for multisets)

Standard MinHash treats each element as either present or absent (Jaccard on sets). When elements have weights (e.g., TF-IDF scores), the correct similarity is the **weighted Jaccard**:

$$J_w(A, B) = \frac{\sum_i \min(a_i, b_i)}{\sum_i \max(a_i, b_i)}$$

**Ioffe's algorithm (2010)** extends MinHash to this case. Each element x with weight w_x generates a Poisson process; the element with the smallest value in this process defines the MinHash. Used in production recommendation systems when item frequencies matter.

### Variation 2: SimHash — for dense binary vectors

MinHash handles sparse sets. For dense vectors (e.g., document embeddings, binary feature vectors), **SimHash** (Charikar 2002) is the correct approach. Each bit of the SimHash is the sign of the dot product of the vector with a random Gaussian vector. Hamming distance in SimHash space approximates angular similarity. Used in Google's near-duplicate detection for the web. See [[38.Locality-sensitive hashing (LSH) — approximate nearest neighbour]] for the LSH connection.

### Variation 3: b-Bit MinHash — signature compression

Full MinHash stores 64-bit integers per hash function. **b-bit MinHash** (Li and König, 2011) stores only the lowest b bits of each hash value. This reduces signature size by 64/b× at the cost of slightly higher collision probability. For b=2 and k=128, you get 32-byte signatures instead of 1024 bytes — a 32× compression. Used in memory-constrained deduplication pipelines.

### Variation 4: Online/streaming MinHash

When documents arrive as streams (log lines, social media posts), you can **update the signature incrementally** — just call `update(element)` for each new element. This is O(k) per element. The signature converges to the true set MinHash as more elements arrive. Used in streaming deduplication in Kafka/Flink pipelines.

## 9. CP Contest Application

MinHash does not appear in competitive programming in its exact form. However, the underlying primitives are CP staples:

**Rolling hash for set signatures** appears in problems like:

- "Count pairs of substrings with Jaccard ≥ θ" — rare, but seen in ICPC regionals
- Hashing-based duplicate detection in string problems (Codeforces 1200E, AtCoder AGC)

**Practical CP trick:** To check if two sets A, B have |A ∩ B| / |A ∪ B| ≥ θ quickly in a contest:

1. Sort both, compute intersection size in O(|A| + |B|) with two-pointer merge.
2. For small k, this is faster than MinHash. MinHash wins only when n is large and you need _all pairs_.

**Time limit relevance:** If the problem gives n = 10⁵ sets and asks for pairs with high Jaccard, naive O(n²) at 10¹⁰ operations will TLE. MinHash + LSH is the intended approach, but contest problems of this type are rare (more common in ML engineering interviews than CP).

**Common CP optimisation:** Use `__builtin_popcountll` and bitmask representations for set intersection when the universe is small (|U| ≤ 64). For |U| ≤ 10⁶, use bitsets. MinHash becomes relevant only when |U| is huge and exact operations are infeasible.
