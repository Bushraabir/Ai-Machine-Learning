## 1. Intuition First

### The Core Idea

Imagine you're looking for a word in a physical dictionary — say, every entry for "run". You don't just want _one_ page; you want the _first_ page where "run" appears and the _last_ page where it appears. A naive reader scans every page: O(n). A trained librarian opens to the middle, decides "too early" or "too late," and halves the search space each time: O(log n).

That is exactly what `lower_bound` and `upper_bound` do, but with mathematical precision:

- **`lower_bound(target)`** — Returns the index of the **first element ≥ target**. If every occurrence of `target` in the array were a book, this points to the leftmost spine.
- **`upper_bound(target)`** — Returns the index of the **first element > target**. This points to _just past_ the last occurrence.

The count of `target` in a sorted array is therefore `upper_bound(target) - lower_bound(target)`.

### Why This Exists

A plain binary search answers: "Is this value here? If yes, give me _any_ index." But many problems demand:

- How many times does `k` appear?
- What is the leftmost valid position to insert `x`?
- What is the range `[l, r]` that satisfies a predicate?

None of these have clean answers from a standard binary search because when multiple identical elements exist, `mid == target` is ambiguous — you could be anywhere in a run of duplicates. A naive fix scans left and right from the found index, degrading to O(n) in the worst case (all elements equal).

`lower_bound` and `upper_bound` maintain O(log n) by _never stopping when they find the target_ — they keep narrowing toward the boundary.

### The "Aha" Moment

The insight is this: **treat the array as a binary predicate partition, not a value lookup.**

- `lower_bound`: the predicate is `arr[i] < target` (False) vs `arr[i] >= target` (True). Find the first True.
- `upper_bound`: the predicate is `arr[i] <= target` (False) vs `arr[i] > target` (True). Find the first True.

In both cases, the array is partitioned into a contiguous block of False followed by a contiguous block of True — this is the _monotonicity_ that makes binary search valid. You are not searching for a value; you are **searching for the boundary of a predicate**.

Once you internalize this framing, every binary-search-on-answer problem ([[59.The binary search on answer template — monotonic predicate]]) is just a generalisation of this same idea.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- Frequency queries on sorted arrays or sorted multisets.
- "How many elements in range [L, R]?" — answer is `upper_bound(R) - lower_bound(L)`.
- Counting inversions via merge sort + binary search.
- Patience sorting for O(n log n) LIS ([[168.Longest Increasing Subsequence (LIS) — O(n^2) and O(n log n)]]).
- Coordinate compression — mapping raw values to compact indices.

**Pattern signal:** Anytime you see a sorted array and need _range counts_, _insertion positions_, or _boundary indices_, reach for `lower_bound`/`upper_bound` before writing any loop.

**Common trap — off-by-one on the right boundary:**  
The canonical bug: a contestant computes `upper_bound(target) - 1` expecting the _last_ occurrence, but forgets to check whether `target` actually exists at that index. If `target` is absent, `lower_bound` returns an index pointing to a different value, and the subtraction gives a nonsensical answer. Always validate: `if lb < n and arr[lb] == target`.

**C++ STL:** `std::lower_bound` and `std::upper_bound` in `<algorithm>` work on any random-access iterator range and run in O(log n). They also accept a custom comparator, making them composable with `std::pair` and struct comparisons.

### Machine Learning / AI

**Threshold search in classification:** Given a sorted array of model confidence scores, `lower_bound` finds the exact index at which scores cross a decision threshold — this is the inner loop of [[63.Threshold optimisation — binary search on decision boundary]]. Iterating over thousands of candidate thresholds naively is O(n·k); with a sorted score array and binary search, each threshold lookup is O(log n).

**Embedding vocabulary lookup:** Tokenisers (BPE, WordPiece) maintain sorted vocabularies. When a subword is looked up during inference, the lookup is a `lower_bound` call on the sorted token list. HuggingFace's fast tokenisers (backed by the Rust `tokenizers` library) use sorted structures with binary search at their core.

**Quantile computation:** Computing percentiles (p50, p95, p99) of a metric array in monitoring systems (e.g., Prometheus) requires finding positions in a sorted data stream — structurally identical to `lower_bound`.

**`numpy.searchsorted`:** This is NumPy's direct implementation. `np.searchsorted(arr, v, side='left')` is `lower_bound`; `side='right'` is `upper_bound`. Used internally in `np.digitize` (histogram bin assignment) and `np.interp` (linear interpolation). Understanding that `searchsorted` is O(log n) — not O(1) — prevents you from calling it in a Python loop over a million points.

**`torch.bucketize`:** PyTorch's equivalent, used for quantisation boundary mapping when converting continuous activations to discrete bins. Each forward pass through a quantised model invokes this.

## 3. Algorithm / Pattern

### `lower_bound` — First index where `arr[i] >= target`

**Plain English:**

1. Maintain a search interval `[lo, hi)` where `lo` is inclusive and `hi` is exclusive.
2. At each step, compute `mid = lo + (hi - lo) / 2`.
3. If `arr[mid] < target`: the answer is strictly to the right → `lo = mid + 1`.
4. If `arr[mid] >= target`: `mid` is a _candidate_ answer, but there may be an earlier one → `hi = mid`.
5. Terminate when `lo == hi`. Return `lo`.

**Why this works:** The invariant is: _the answer always lies in `[lo, hi)`_. We never discard a valid candidate (when `arr[mid] >= target`, we keep `mid` reachable by setting `hi = mid`, not `mid - 1`). We always shrink the interval (either `lo` increases or `hi` decreases), so termination is guaranteed.

### `upper_bound` — First index where `arr[i] > target`

Same structure, one character changes:

- If `arr[mid] <= target`: answer is strictly to the right → `lo = mid + 1`.
- If `arr[mid] > target`: `mid` is a candidate → `hi = mid`.

### Decision Tree

```
Given sorted array arr, query target:

Need first occurrence of target?
  → lower_bound, then check arr[result] == target

Need last occurrence of target?
  → upper_bound - 1, then check arr[result] == target

Need count of target?
  → upper_bound(target) - lower_bound(target)

Need insertion point to maintain sorted order?
  → lower_bound (insert before first element ≥ target)

Need range [L, R] count?
  → upper_bound(R) - lower_bound(L)
```

### Complexity

- **Time:** O(log n). Each iteration halves the interval `[lo, hi)`. Starting size is n, so we need at most ⌈log₂ n⌉ iterations.
- **Space:** O(1) iterative. O(log n) recursive (stack frames, not recommended).
- **When to avoid:** On unsorted data — the monotonicity invariant breaks. On linked lists — O(n) even with the algorithm because random access is O(n).

## 4. Pseudocode

```
LOWER_BOUND(arr, n, target):
    lo ← 0
    hi ← n                          // half-open interval [lo, hi)

    while lo < hi:
        mid ← lo + (hi - lo) / 2   // avoids integer overflow vs (lo+hi)/2

        if arr[mid] < target:
            lo ← mid + 1            // mid is too small; shrink from left
        else:
            hi ← mid                // mid is a candidate; try to go left

    // Invariant restored: lo == hi, and answer is lo
    return lo                       // index of first element >= target


UPPER_BOUND(arr, n, target):
    lo ← 0
    hi ← n

    while lo < hi:
        mid ← lo + (hi - lo) / 2

        if arr[mid] <= target:
            lo ← mid + 1            // mid is still <= target; answer is to the right
        else:
            hi ← mid                // mid > target; mid is a candidate

    return lo                       // index of first element > target


FIRST_OCCURRENCE(arr, n, target):
    idx ← LOWER_BOUND(arr, n, target)
    if idx < n AND arr[idx] == target:
        return idx
    return -1                       // target not present


LAST_OCCURRENCE(arr, n, target):
    idx ← UPPER_BOUND(arr, n, target) - 1
    if idx >= 0 AND arr[idx] == target:
        return idx
    return -1
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <algorithm>
#include <vector>
#include <iostream>
#include <cassert>

// Manual implementations (mirror std:: for clarity)
// These replicate the behaviour of std::lower_bound / std::upper_bound
// on a random-access container.

namespace bsearch {

// Returns index of first element >= target.
// Returns n if all elements < target.
template <typename T>
int lower_bound(const std::vector<T>& arr, const T& target) {
    int lo = 0, hi = static_cast<int>(arr.size());  // half-open [lo, hi)
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;   // overflow-safe midpoint
        if (arr[mid] < target) {
            lo = mid + 1;               // mid is too small, search right
        } else {
            hi = mid;                   // mid is candidate, try left
        }
    }
    return lo;
}

// Returns index of first element > target.
// Returns n if all elements <= target.
template <typename T>
int upper_bound(const std::vector<T>& arr, const T& target) {
    int lo = 0, hi = static_cast<int>(arr.size());
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] <= target) {
            lo = mid + 1;               // mid still satisfies <=, move right
        } else {
            hi = mid;                   // mid > target, candidate
        }
    }
    return lo;
}

// Returns [first, last] indices of target in sorted arr.
// Returns {-1, -1} if target is not present.
template <typename T>
std::pair<int, int> equal_range(const std::vector<T>& arr, const T& target) {
    int lb = lower_bound(arr, target);
    int n  = static_cast<int>(arr.size());

    if (lb == n || arr[lb] != target) {
        return {-1, -1};            // target absent
    }
    return {lb, upper_bound(arr, target) - 1};
}

// Count occurrences of target in sorted arr. O(log n).
template <typename T>
int count(const std::vector<T>& arr, const T& target) {
    int lb = lower_bound(arr, target);
    int ub = upper_bound(arr, target);
    return ub - lb;
}

} // namespace bsearch


// ──────────────────────────────────────────────
// STL equivalents (preferred in production code)
// ──────────────────────────────────────────────

void stl_demo() {
    std::vector<int> v = {1, 2, 4, 4, 4, 6, 7};

    // std::lower_bound returns an iterator; subtract begin() for index
    auto lb = std::lower_bound(v.begin(), v.end(), 4);
    auto ub = std::upper_bound(v.begin(), v.end(), 4);

    std::cout << "lower_bound(4) index: " << (lb - v.begin()) << "\n";  // 2
    std::cout << "upper_bound(4) index: " << (ub - v.begin()) << "\n";  // 5
    std::cout << "count(4): " << (ub - lb) << "\n";                     // 3

    // equal_range returns both in one call
    auto [first, last] = std::equal_range(v.begin(), v.end(), 4);
    std::cout << "equal_range: [" << (first - v.begin())
              << ", " << (last - v.begin()) << ")\n";                    // [2, 5)
}


// ──────────────────────────────────────────────
// Practical: count target in range [L, R]
// ──────────────────────────────────────────────

// Given sorted arr, count elements in [lo_val, hi_val] inclusive. O(log n).
int range_count(const std::vector<int>& arr, int lo_val, int hi_val) {
    auto lo = std::lower_bound(arr.begin(), arr.end(), lo_val);
    auto hi = std::upper_bound(arr.begin(), arr.end(), hi_val);
    return static_cast<int>(hi - lo);
}


int main() {
    // ── Manual implementation tests ──
    std::vector<int> arr = {1, 2, 4, 4, 4, 6, 7};

    assert(bsearch::lower_bound(arr, 4) == 2);
    assert(bsearch::upper_bound(arr, 4) == 5);
    assert(bsearch::count(arr, 4)       == 3);
    assert(bsearch::count(arr, 5)       == 0);  // absent

    auto [f, l] = bsearch::equal_range(arr, 4);
    assert(f == 2 && l == 4);  // indices 2, 3, 4 all hold value 4

    // Target not in array
    assert(bsearch::lower_bound(arr, 5) == 5);  // points to 6
    assert(bsearch::lower_bound(arr, 9) == 7);  // past end

    // ── Range count test ──
    assert(range_count(arr, 3, 5) == 3);  // elements 4,4,4 are in [3,5]
    assert(range_count(arr, 4, 4) == 3);

    stl_demo();

    std::cout << "All assertions passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
"""
lower_bound and upper_bound — First and Last Occurrence
=======================================================
Time:  O(log n) per query
Space: O(1)

Python's bisect module is the standard library implementation.
  bisect.bisect_left  == lower_bound
  bisect.bisect_right == upper_bound
"""

from __future__ import annotations
import bisect


# ──────────────────────────────────────────────
# Manual implementations (educational)
# ──────────────────────────────────────────────

def lower_bound(arr: list[int], target: int) -> int:
    """
    Returns the index of the first element >= target.
    Returns len(arr) if all elements < target.
    Equivalent to bisect.bisect_left(arr, target).
    """
    lo, hi = 0, len(arr)          # half-open interval [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < target:
            lo = mid + 1          # mid too small, search right half
        else:
            hi = mid              # mid is candidate, try left half
    return lo


def upper_bound(arr: list[int], target: int) -> int:
    """
    Returns the index of the first element > target.
    Returns len(arr) if all elements <= target.
    Equivalent to bisect.bisect_right(arr, target).
    """
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] <= target:
            lo = mid + 1          # mid still <= target, answer is right
        else:
            hi = mid              # mid > target, candidate
    return lo


def first_occurrence(arr: list[int], target: int) -> int:
    """Returns index of first occurrence of target, or -1 if absent."""
    idx = lower_bound(arr, target)
    if idx < len(arr) and arr[idx] == target:
        return idx
    return -1


def last_occurrence(arr: list[int], target: int) -> int:
    """Returns index of last occurrence of target, or -1 if absent."""
    idx = upper_bound(arr, target) - 1
    if idx >= 0 and arr[idx] == target:
        return idx
    return -1


def count_occurrences(arr: list[int], target: int) -> int:
    """Count of target in sorted arr. O(log n)."""
    return upper_bound(arr, target) - lower_bound(arr, target)


def range_count(arr: list[int], lo_val: int, hi_val: int) -> int:
    """
    Count elements x in arr such that lo_val <= x <= hi_val.
    Sorted arr required. O(log n).
    """
    return upper_bound(arr, hi_val) - lower_bound(arr, lo_val)


# ──────────────────────────────────────────────
# bisect module (production usage)
# ──────────────────────────────────────────────

def bisect_demo(arr: list[int], target: int) -> None:
    lb = bisect.bisect_left(arr, target)    # lower_bound
    ub = bisect.bisect_right(arr, target)   # upper_bound
    print(f"bisect_left ({target}):  index {lb}")
    print(f"bisect_right({target}):  index {ub}")
    print(f"count of {target}: {ub - lb}")


# ──────────────────────────────────────────────
# NumPy connection (ML-relevant)
# ──────────────────────────────────────────────

def numpy_demo() -> None:
    """
    np.searchsorted is the vectorised lower/upper_bound.
    side='left'  → lower_bound (first element >= target)
    side='right' → upper_bound (first element >  target)

    Used internally by:
      - np.digitize  (histogram binning)
      - np.interp    (linear interpolation)
      - torch.bucketize (quantisation boundaries)
    """
    try:
        import numpy as np
        arr = np.array([1, 2, 4, 4, 4, 6, 7])
        print(np.searchsorted(arr, 4, side='left'))   # 2 — lower_bound
        print(np.searchsorted(arr, 4, side='right'))  # 5 — upper_bound

        # Vectorised: find positions for multiple targets at once
        targets = np.array([3, 4, 5])
        print(np.searchsorted(arr, targets, side='left'))  # [2 2 5]
    except ImportError:
        print("NumPy not installed — skip demo")


# ──────────────────────────────────────────────
# Tests
# ──────────────────────────────────────────────

if __name__ == "__main__":
    arr = [1, 2, 4, 4, 4, 6, 7]

    # lower_bound
    assert lower_bound(arr, 4) == 2,  "lb of 4 should be 2"
    assert lower_bound(arr, 5) == 5,  "lb of absent 5 should point to 6"
    assert lower_bound(arr, 0) == 0,  "lb of 0 should be 0 (before all)"
    assert lower_bound(arr, 9) == 7,  "lb of 9 should be past end"

    # upper_bound
    assert upper_bound(arr, 4) == 5,  "ub of 4 should be 5"
    assert upper_bound(arr, 5) == 5,  "ub of absent 5 should be 5"

    # first/last
    assert first_occurrence(arr, 4) == 2
    assert last_occurrence(arr, 4)  == 4
    assert first_occurrence(arr, 5) == -1
    assert last_occurrence(arr, 5)  == -1

    # count
    assert count_occurrences(arr, 4) == 3
    assert count_occurrences(arr, 5) == 0

    # range count
    assert range_count(arr, 3, 5) == 3   # elements 4,4,4
    assert range_count(arr, 1, 7) == 7   # entire array

    # bisect equivalence
    assert lower_bound(arr, 4) == bisect.bisect_left(arr, 4)
    assert upper_bound(arr, 4) == bisect.bisect_right(arr, 4)

    bisect_demo(arr, 4)
    numpy_demo()

    print("All tests passed.")
```

## 7. Common Variations & Extensions

### 7.1 Binary search on a struct or pair

In C++, `std::lower_bound` accepts a custom comparator:

```cpp
// Find first element with .value >= target among a vector of structs
struct Item { int value; std::string label; };
auto it = std::lower_bound(items.begin(), items.end(), target_val,
    [](const Item& item, int val) { return item.value < val; });
```

This pattern is essential for coordinate compression in CP problems.

### 7.2 Coordinate compression

Given a set of arbitrary integers (potentially huge), map them to compact indices `[0, 1, ..., k-1]` for use as array indices or DP states:

```python
values = sorted(set(raw_values))           # deduplicate and sort
compress = {v: i for i, v in enumerate(values)}
# To query the compressed index of any value x:
compressed_x = bisect.bisect_left(values, x)
```

This appears constantly in segment tree problems ([[155.Segment tree — range query and point update O(log n)]]) and Fenwick tree problems ([[156.Fenwick tree (BIT) — prefix sum with updates O(log n)]]).

### 7.3 O(n log n) LIS via patience sorting

The O(n log n) Longest Increasing Subsequence algorithm ([[168.Longest Increasing Subsequence (LIS) — O(n^2) and O(n log n)]]) maintains a sorted `tails` array and at each step calls `lower_bound(tails, x)` to find where to place the current element. Understanding `lower_bound` is a prerequisite to understanding why this works.

### 7.4 `searchsorted` for threshold optimisation

In classification, you have sorted predicted probabilities and want to find the threshold that achieves a target precision or recall. This is exactly `lower_bound` over the sorted score array — explored in depth in [[63.Threshold optimisation — binary search on decision boundary]].

### 7.5 Fractional / real-valued lower bound

When the search space is real-valued (e.g., find the smallest `t ≥ 0` such that `f(t) ≥ 0.95`), the same logic applies with a floating-point loop and an epsilon termination condition instead of `lo == hi`. See [[62.Fractional binary search — real-valued search spaces]].

## 9. CP Contest Application

### Typical Codeforces problem structure

"Given n integers and q queries. Each query asks: how many elements in the array lie in the range [L, R]?"

Standard approach: sort the array offline, then answer each query in O(log n) with `lower_bound(L)` and `upper_bound(R)`.

**Time complexity:** O(n log n) sort + O(q log n) queries. Total: O((n + q) log n).  
**This matters when** n, q ≤ 10^5 or 10^6. Naive O(nq) is 10^10 operations — TLE guaranteed.

### Coordinate compression template (CP staple)

```cpp
// Step 1: collect all relevant values, sort and deduplicate
std::vector<int> vals = /* all query bounds and array values */;
std::sort(vals.begin(), vals.end());
vals.erase(std::unique(vals.begin(), vals.end()), vals.end());

// Step 2: compress a value to its rank
auto compress = [&](int x) {
    return (int)(std::lower_bound(vals.begin(), vals.end(), x) - vals.begin());
};
// Now ranks are in [0, vals.size()), safe as array/Fenwick indices.
```

### Optimization note — avoid repeated `lower_bound` calls on the same sorted container

If you have sorted queries too, you can process both arrays with a two-pointer merge in O(n + q) instead of O(q log n). But this is only worthwhile when both n and q exceed ~10^6 and the constant factor matters.
