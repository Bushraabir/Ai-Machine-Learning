## 1. Intuition First

### The Core Idea

Imagine you're looking for your keys in a house. The naive approach: search every drawer in every room. The smart approach: you remember leaving them near the front door, so you don't bother searching the basement at all.

That's pruning. In a backtracking search tree, pruning means **cutting off entire subtrees before exploring them**, because you can _prove in advance_ that no solution exists in that subtree — or that the best solution reachable from there is worse than one you've already found.

Two complementary mechanisms do this work:

**Forward Checking:** When you assign a value to a variable, immediately propagate its consequences to constrain the remaining unassigned variables. If any unassigned variable's domain becomes _empty_, backtrack now — there is no solution reachable from the current partial assignment, regardless of what you choose later. Don't wait to discover this failure after burning through 10,000 more recursive calls.

**Bounding Functions (Branch-and-Bound):** Maintain the best solution found so far. At any point in the search tree, compute an **optimistic upper bound** (for maximisation) or **pessimistic lower bound** (for minimisation) on the best solution reachable from the current node. If that bound is worse than your current best, prune the entire subtree. You can't do better — stop.

### Why This Exists

The raw backtracking template from [[77. Backtracking template — choose, explore, unchoose]] has time complexity $O(b^d)$ where $b$ is the branching factor and $d$ is the depth. For a 20-variable CSP with domains of size 5, that's $5^{20} \approx 10^{14}$ nodes — computational heat death.

Pruning attacks both dimensions:

- **Forward checking reduces the effective branching factor** at each level by eliminating invalid choices _before_ making them.
- **Bounding reduces the effective depth** by proving entire subtrees cannot improve on the known best.

In practice, forward checking on the N-Queens problem reduces the search by ~60-90% compared to naïve backtracking. Branch-and-bound on 0/1 knapsack transforms an exponential problem into one solvable for $n \approx 40$ in milliseconds.

### The "Aha" Moment

The key insight is this: **the sooner you detect failure, the more work you save.** A failure detected at depth 3 prunes the entire subtree below it — which might have depth 10 remaining and branching factor 5. That's $5^{10} = 10$ million nodes saved from a single early detection.

Forward checking moves failure detection from _leaf time_ to _assignment time_. Bounding moves infeasibility detection from "we've found all solutions" to "we can prove this path is suboptimal."

Both are the same idea: **pay a small cost at each node to avoid exponential cost in the subtree.**

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- Any backtracking/search problem on Codeforces or AtCoder where the constraint is $n \leq 20$ or $n \leq 40$
- Combinatorial optimisation: knapsack variants, TSP on small graphs, subset sum problems where DP is infeasible due to large values
- Constraint satisfaction: scheduling, graph colouring, exact cover
- Problems explicitly labelled "find the maximum value subject to X" combined with subset enumeration

**Pattern signals:**

- "Find the optimal subset/assignment" + $n \leq 40$ → consider branch-and-bound (pure bitmask DP works for $n \leq 20$, see [[104. Subset enumeration with bitmask]])
- "Satisfy all constraints" + domains of size $\leq 10$ per variable → CSP with forward checking
- Recursive search that TLEs at a naive $O(n!)$ or $O(2^n)$ → add a bound function

**Common gotcha that kills submissions:** The most dangerous trap is writing a bounding function that is **not admissible** — it underestimates the true optimum, causing it to prune correct solutions. For a maximisation problem, the bound must be an _overestimate_ (never underestimate what you can achieve). For minimisation, it must be an _underestimate_ (never overestimate the cost). Getting this backwards means your pruning discards the optimal solution, and you submit a wrong answer with $O(\log n)$ runtime. Your code is fast and wrong.

Second trap: implementing forward checking but forgetting to **restore domains on backtrack**. This classic undo-failure causes later branches to inherit incorrectly constrained domains, producing wrong answers or missed solutions.

### Machine Learning / AI

**Where this algorithmic idea appears:**

1. **Neural Architecture Search (NAS):** The search space of all possible neural architectures is combinatorially enormous. Systems like DARTS and ENAS use pruning strategies — bounding on validation loss — to avoid evaluating architectures that early indicators suggest will be poor. This is exactly branch-and-bound on the architecture DAG. See [[82. Feature subset search as backtracking — ML connection]].
    
2. **Decision Tree Learning (CART):** The CART algorithm (see [[158. Decision tree structure — how CART maps to a binary tree]]) uses pre-pruning (forward checking analog: stop splitting if the node has fewer than `min_samples_split` examples) and post-pruning (cost-complexity pruning). The `min_impurity_decrease` parameter is a bounding function: if the best achievable Gini reduction from any split is below the threshold, prune the node.
    
3. **Beam Search (NLP/sequence generation):** Beam search is pruning applied to the token generation tree. At each step, it bounds the search to the top-$k$ partial sequences (a hard branching-factor bound). The pruning is not based on a proof of suboptimality but on a heuristic score — the log-probability. Used in every modern NLP decoder: HuggingFace `generate()`, OpenNMT, Fairseq. Understanding it as pruned beam backtracking (not magic) makes you understand why beam search sometimes misses the global optimum.
    
4. **Alpha-Beta Pruning (Game AI / RLHF reward model search):** Alpha-beta pruning is the canonical bounding function for minimax search. It maintains two bounds (alpha: best for maximiser, beta: best for minimiser) and prunes when a branch provably cannot affect the outcome. This appears in MCTS implementations and in some reward-model-guided decoding strategies.
    
5. **Scikit-learn internals:** `sklearn.tree.DecisionTreeClassifier` uses forward checking during construction via `splitter.node_impurity()` — it checks whether any valid split exists before recursing, equivalent to domain-checking in a CSP.
    

**Why understanding this makes you write better ML code:** When you tune `min_samples_leaf` or `min_impurity_decrease` in scikit-learn, you're not touching a magic number — you're setting the threshold of a bounding function. Setting it too tight → no pruning → deep trees that overfit. Too loose → aggressive pruning → underfitting. You can reason about this trade-off _precisely_ because you understand the bounding mechanism.

## 3. Algorithm / Pattern

### Forward Checking (CSP context)

**Step-by-step logic:**

1. Maintain a domain $D_i$ for each unassigned variable $x_i$ (set of currently valid values)
2. When you assign $x_j = v$:
    - For each unassigned variable $x_k$ that shares a constraint with $x_j$:
        - Remove all values from $D_k$ that are inconsistent with the assignment $x_j = v$
        - Record what you removed (for undo on backtrack)
3. Check if any $D_k$ has become empty → if yes, immediately backtrack
4. Otherwise, recurse on the next unassigned variable
5. On backtrack: restore all domains to their state before the assignment

**Decision tree:**

```
Has any domain become empty after propagation?
  YES → backtrack immediately (don't recurse)
  NO  → recurse into next variable
```

**Time complexity:**

- Naive backtracking: $O(d^n)$ where $d$ = max domain size, $n$ = number of variables
- With forward checking: hard to bound analytically (depends on constraint graph), but empirically $O(d^{n/k})$ for $k$ tightly-constrained variables (typically $k \approx 3$–$5$)
- Space: $O(n \cdot d)$ to store current domains

### Branch-and-Bound (Optimisation context)

**Step-by-step logic:**

1. Maintain a global `best_value` (initialise to $-\infty$ for maximisation)
2. At each node, compute `bound(current_state)` — an optimistic estimate of the best achievable value from this partial state
3. If `bound < best_value`, prune: `return` without recursing
4. Otherwise, for each valid choice:
    - Apply the choice
    - Recurse
    - Undo the choice
5. After recursing to a complete solution, update `best_value` if improved

**The quality of your bound function determines everything:**

- **Weak bound** (e.g., "assume all remaining items can be taken"): almost no pruning
- **Strong bound** (e.g., fractional relaxation of knapsack — sort remaining by value/weight and fill greedily allowing fractions): prunes aggressively
- **Perfect bound** (equals the true optimum) = we've solved the problem, no search needed

**Admissibility requirement:** For maximisation: `bound(state) >= true_optimum_from_state` (overestimate is safe; underestimate prunes valid solutions)

**Time complexity:** Worst case still $O(2^n)$ (no pruning occurs), but average case with a good bound function is $O(2^{n/2})$ to $O(n \log n)$ depending on problem structure.

**When to use vs. avoid:**

|Use Pruning When|Avoid / Consider Alternatives When|
|---|---|
|Search space is exponential but structured|State space is a DAG → use [[181. DP on DAG — longest path in a DAG]]|
|$n \leq 40$ with bitmask, $n \leq 100$ with good bounds|$n > 100$ → approximate methods (greedy, LP relaxation)|
|Hard constraints exist that eliminate most of the space|No natural bounding function exists|
|Optimal solution is required|Near-optimal is acceptable → use beam search|

## 4. Pseudocode

### Forward Checking for CSP

```
function BACKTRACK-FC(assignment, domains, constraints):
    if assignment is complete:
        return assignment
    
    var = SELECT-UNASSIGNED-VARIABLE(assignment, domains)  # e.g., MRV heuristic
    
    for each value v in ORDERED-DOMAIN-VALUES(var, assignment, domains):
        if v is consistent with assignment under constraints:
            assignment[var] = v
            
            # Forward checking: propagate and save removed values
            removals = {}
            failure = false
            
            for each unassigned neighbour n of var:
                for each value w in domains[n]:
                    if w is NOT consistent with (var = v):
                        domains[n].remove(w)
                        removals[(n, w)] = true
                
                if domains[n] is empty:
                    failure = true
                    break  # Domain wipeout: this assignment fails
            
            if not failure:
                result = BACKTRACK-FC(assignment, domains, constraints)
                if result is not FAILURE:
                    return result
            
            # Undo: restore removed values and clear assignment
            for (n, w) in removals:
                domains[n].add(w)
            delete assignment[var]
    
    return FAILURE  # All values tried, none worked
```

### Branch-and-Bound for 0/1 Knapsack

```
function KNAPSACK-BB(items, capacity):
    items = SORT by (value/weight) descending  # Critical for tight bounds
    best = 0
    
    function BOUND(index, current_weight, current_value):
        # Fractional relaxation: allow partial items
        bound_value = current_value
        remaining_capacity = capacity - current_weight
        
        for i from index to len(items):
            if items[i].weight <= remaining_capacity:
                bound_value += items[i].value
                remaining_capacity -= items[i].weight
            else:
                # Take fractional part
                bound_value += items[i].value * (remaining_capacity / items[i].weight)
                break
        
        return bound_value
    
    function DFS(index, current_weight, current_value):
        nonlocal best
        
        # Update best with complete or partial solution
        best = MAX(best, current_value)
        
        # Base case: no more items
        if index == len(items):
            return
        
        # Bounding function check
        if BOUND(index, current_weight, current_value) <= best:
            return  # This subtree cannot beat best
        
        # Branch: include items[index]
        if current_weight + items[index].weight <= capacity:
            DFS(index + 1,
                current_weight + items[index].weight,
                current_value + items[index].value)
        
        # Branch: exclude items[index]
        DFS(index + 1, current_weight, current_value)
    
    DFS(0, 0, 0)
    return best
```

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ================================================================
// PART 1: Forward Checking — N-Queens with domain propagation
// ================================================================
// Demonstrates forward checking on an archetypal CSP.
// We track which rows are "available" to each column using bitsets.

class NQueensFC {
    int n;
    vector<int> placement;       // placement[col] = row of queen in that col
    vector<int> used_rows;       // rows already occupied
    vector<int> used_diag1;      // row - col diagonals
    vector<int> used_diag2;      // row + col diagonals
    int solutions;

    // Get the domain of column `col` given current placements
    // Returns the set of valid rows as a bitmask
    int available_rows(int col) const {
        int mask = (1 << n) - 1;          // all rows initially available
        mask &= ~used_rows.back();        // remove occupied rows
        mask &= ~used_diag1.back();       // remove "/" diagonal threats
        mask &= ~used_diag2.back();       // remove "\" diagonal threats
        return mask;
    }

public:
    NQueensFC(int n) : n(n), solutions(0) {
        // Initialise constraint tracking stacks
        used_rows.push_back(0);
        used_diag1.push_back(0);
        used_diag2.push_back(0);
    }

    void solve(int col = 0) {
        if (col == n) {
            solutions++;
            return;
        }

        int domain = available_rows(col);

        // Forward check: if domain is empty, backtrack immediately
        if (domain == 0) return;

        // Iterate over valid rows in the domain
        while (domain) {
            int row_bit = domain & (-domain);   // lowest set bit
            domain &= domain - 1;               // remove it
            int row = __builtin_ctz(row_bit);   // bit index = row number

            // Propagate assignment: update constraint sets
            int new_rows  = used_rows.back()  | row_bit;
            int new_diag1 = (used_diag1.back() | row_bit) >> 1; // shift for next col
            int new_diag2 = (used_diag2.back() | row_bit) << 1;

            used_rows.push_back(new_rows);
            used_diag1.push_back(new_diag1);
            used_diag2.push_back(new_diag2);
            placement.push_back(row);

            // Recurse
            solve(col + 1);

            // Undo (restore domains — the core of forward checking correctness)
            used_rows.pop_back();
            used_diag1.pop_back();
            used_diag2.pop_back();
            placement.pop_back();
        }
    }

    int count() const { return solutions; }
};

// ================================================================
// PART 2: Branch-and-Bound — 0/1 Knapsack
// ================================================================
// Uses fractional relaxation as the bounding function.
// Items MUST be sorted by value/weight ratio descending before calling.

struct Item {
    int value, weight;
    double ratio;  // precomputed for efficiency
};

class KnapsackBB {
    vector<Item> items;
    int capacity;
    int best;

    // Bounding function: fractional knapsack relaxation.
    // This is ADMISSIBLE: it always overestimates the true 0/1 optimum.
    double bound(int idx, int cur_weight, int cur_value) const {
        double b = cur_value;
        int remaining = capacity - cur_weight;

        for (int i = idx; i < (int)items.size(); ++i) {
            if (items[i].weight <= remaining) {
                b += items[i].value;
                remaining -= items[i].weight;
            } else {
                // Fractional fill — this is what makes it an UPPER bound
                b += (double)items[i].value * remaining / items[i].weight;
                break;
            }
        }
        return b;
    }

    void dfs(int idx, int cur_weight, int cur_value) {
        // Update best with current partial solution
        best = max(best, cur_value);

        // Base case
        if (idx == (int)items.size()) return;

        // PRUNING: if even the fractional optimum can't beat best, cut
        if (bound(idx, cur_weight, cur_value) <= best) return;

        // Branch 1: Take item idx
        if (cur_weight + items[idx].weight <= capacity) {
            dfs(idx + 1, cur_weight + items[idx].weight,
                cur_value + items[idx].value);
        }

        // Branch 2: Skip item idx
        dfs(idx + 1, cur_weight, cur_value);
    }

public:
    KnapsackBB(vector<pair<int,int>>& raw_items, int cap) : capacity(cap), best(0) {
        for (auto& [v, w] : raw_items)
            items.push_back({v, w, (double)v / w});
        // Sort by ratio descending — CRITICAL for tight bounds
        sort(items.begin(), items.end(),
             [](const Item& a, const Item& b){ return a.ratio > b.ratio; });
    }

    int solve() {
        dfs(0, 0, 0);
        return best;
    }
};

// ================================================================
// PART 3: Generic Branch-and-Bound Template
// ================================================================
// Reusable pattern for combinatorial optimisation problems.
// Override `compute_bound()` for your specific problem.

template<typename State, typename Value>
class BranchAndBound {
public:
    Value best_value;

    // Override these in derived class
    virtual bool is_complete(const State& s) = 0;
    virtual Value compute_bound(const State& s) = 0;  // must be admissible
    virtual vector<State> get_children(const State& s) = 0;
    virtual Value solution_value(const State& s) = 0;

    void search(const State& s) {
        if (is_complete(s)) {
            best_value = max(best_value, solution_value(s));
            return;
        }
        if (compute_bound(s) <= best_value) return;  // prune

        for (auto& child : get_children(s)) {
            search(child);
        }
    }

    virtual ~BranchAndBound() = default;
};

// Test Cases
// ================================================================
int main() {
    // Test 1: N-Queens forward checking
    {
        NQueensFC solver(8);
        solver.solve();
        assert(solver.count() == 92); // Known: 8-queens has 92 solutions
        cout << "8-queens: " << solver.count() << " solutions ✓\n";
    }

    // Test 2: 0/1 Knapsack with branch-and-bound
    {
        // Items: (value, weight)
        vector<pair<int,int>> items = {{10,2},{6,2},{14,4},{3,1},{12,3}};
        int capacity = 7;

        KnapsackBB solver(items, capacity);
        int result = solver.solve();
        cout << "Knapsack optimal: " << result << "\n"; // Expected: 25
        assert(result == 25);
    }

    cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import List, Tuple, Optional
from dataclasses import dataclass, field


# ================================================================
# PART 1: Forward Checking — N-Queens
# ================================================================

def n_queens_fc(n: int) -> List[List[int]]:
    """
    Solve N-Queens using forward checking.
    
    Returns all solutions as lists of row positions (placement[col] = row).
    
    Complexity:
        Without pruning: O(n!)
        With forward checking: empirically O(n! / k) for k ≈ 3 on average
        Space: O(n) for recursion depth + O(n^2) for domain tracking
    """
    solutions = []
    placement = []  # placement[col] = row

    def solve(col: int,
              available_rows: int,    # bitmask of rows not yet taken
              diag_left: int,         # "/" diagonal constraints
              diag_right: int) -> None:  # "\" diagonal constraints
        
        if col == n:
            solutions.append(placement[:])
            return
        
        # Domain = rows available in this column
        # This is forward checking: we propagate constraints eagerly
        domain = available_rows & ~diag_left & ~diag_right
        
        # Forward check: empty domain → backtrack immediately
        if domain == 0:
            return
        
        # Iterate over valid rows
        d = domain
        while d:
            row_bit = d & (-d)   # lowest set bit
            d &= d - 1           # remove it
            row = row_bit.bit_length() - 1
            
            placement.append(row)
            
            # Key step: propagate assignment, shift diagonals for next column
            solve(col + 1,
                  available_rows ^ row_bit,
                  (diag_left | row_bit) >> 1,
                  (diag_right | row_bit) << 1)
            
            placement.pop()  # backtrack — undo choice
    
    all_rows = (1 << n) - 1
    solve(0, all_rows, 0, 0)
    return solutions


# ================================================================
# PART 2: Branch-and-Bound — 0/1 Knapsack
# ================================================================

@dataclass(order=True)
class Item:
    value: int
    weight: int
    ratio: float = field(init=False)
    
    def __post_init__(self):
        self.ratio = self.value / self.weight if self.weight > 0 else 0


def knapsack_branch_and_bound(items: List[Tuple[int, int]], capacity: int) -> int:
    """
    0/1 Knapsack via Branch-and-Bound with fractional relaxation bounding.
    
    Args:
        items: List of (value, weight) tuples
        capacity: Maximum total weight
    
    Returns:
        Maximum value achievable without exceeding capacity
    
    Complexity:
        Worst case: O(2^n) — no pruning possible
        Expected case with good bound: dramatically better for structured inputs
        Space: O(n) recursion depth
    
    Key insight: sorting by value/weight ratio is CRITICAL — it makes the
    fractional bound as tight as possible, maximising pruning power.
    """
    sorted_items = sorted(
        [Item(v, w) for v, w in items],
        key=lambda x: x.ratio,
        reverse=True  # Highest ratio first — tightens the bound
    )
    n = len(sorted_items)
    best = 0
    
    def bound(idx: int, cur_weight: int, cur_value: int) -> float:
        """
        Fractional knapsack relaxation — always an UPPER BOUND (admissible).
        Greedily take items by ratio, allowing a fractional last item.
        """
        b = float(cur_value)
        remaining = capacity - cur_weight
        
        for i in range(idx, n):
            item = sorted_items[i]
            if item.weight <= remaining:
                b += item.value
                remaining -= item.weight
            else:
                # Fractional fill — key to the admissible bound
                b += item.value * remaining / item.weight
                break
        
        return b
    
    def dfs(idx: int, cur_weight: int, cur_value: int) -> None:
        nonlocal best
        
        best = max(best, cur_value)
        
        if idx == n:
            return
        
        # PRUNE: if even fractional optimum can't beat best, give up
        if bound(idx, cur_weight, cur_value) <= best:
            return
        
        item = sorted_items[idx]
        
        # Branch 1: include item idx
        if cur_weight + item.weight <= capacity:
            dfs(idx + 1, cur_weight + item.weight, cur_value + item.value)
        
        # Branch 2: exclude item idx
        dfs(idx + 1, cur_weight, cur_value)
    
    dfs(0, 0, 0)
    return best


# ================================================================
# PART 3: General CSP with Forward Checking
# ================================================================

def solve_csp_fc(
    variables: List[str],
    domains: dict[str, List],
    constraints: List[Tuple]  # (var1, var2, predicate_fn)
) -> Optional[dict]:
    """
    General CSP solver with forward checking.
    
    Returns a satisfying assignment dict, or None if unsatisfiable.
    """
    # Build constraint graph: var -> list of (neighbour, predicate)
    graph = {v: [] for v in variables}
    for v1, v2, pred in constraints:
        graph[v1].append((v2, pred))
        graph[v2].append((v1, lambda b, a, p=pred: p(a, b)))  # symmetric
    
    assignment = {}
    current_domains = {v: list(d) for v, d in domains.items()}
    
    def backtrack() -> Optional[dict]:
        if len(assignment) == len(variables):
            return dict(assignment)
        
        # MRV (Minimum Remaining Values): choose most constrained variable
        unassigned = [v for v in variables if v not in assignment]
        var = min(unassigned, key=lambda v: len(current_domains[v]))
        
        for value in current_domains[var]:
            # Check direct consistency
            consistent = all(
                v2 not in assignment or pred(value, assignment[v2])
                for v2, pred in graph[var]
            )
            if not consistent:
                continue
            
            assignment[var] = value
            
            # Forward checking: propagate and record removals
            removals = []
            failed = False
            
            for neighbour, pred in graph[var]:
                if neighbour in assignment:
                    continue
                to_remove = [
                    v for v in current_domains[neighbour]
                    if not pred(value, v)  # value of var conflicts with v of neighbour
                ]
                for v in to_remove:
                    current_domains[neighbour].remove(v)
                    removals.append((neighbour, v))
                
                # Domain wipeout check — the core of forward checking
                if not current_domains[neighbour]:
                    failed = True
                    break
            
            if not failed:
                result = backtrack()
                if result is not None:
                    return result
            
            # Undo: restore all removed domain values
            for neighbour, v in removals:
                current_domains[neighbour].append(v)
            
            del assignment[var]
        
        return None
    
    return backtrack()

    assert len(set(result.values())) == 3  # All 3 different colours used
    print(f"3-colouring: {result} ✓")
    
    print("\nAll tests passed.")
```

## 7. Common Variations & Extensions

### 1. Arc Consistency (AC-3) — Stronger than Forward Checking

Forward checking only propagates _one level deep_ — from the assigned variable to its immediate neighbours. Arc Consistency (AC-3) propagates transitively: if removing a value from variable $X$ reduces the domain of $Y$, it re-enqueues all neighbours of $Y$ for re-checking.

This is used in `sklearn`'s `DecisionTreeClassifier` during split selection and in constraint programming solvers (OR-Tools, Choco). The cost is $O(ed^3)$ per call but can dramatically reduce the search space. See [[79. Sudoku solver — constraint propagation + backtracking]] for a direct application.

### 2. Alpha-Beta Pruning — Bounding for Two-Player Games

In minimax game trees, alpha ($\alpha$) and beta ($\beta$) serve as the bounding values. $\alpha$ = best guaranteed value for the maximiser so far. $\beta$ = best guaranteed value for the minimiser. If $\beta \leq \alpha$ at any node, the current subtree cannot affect the outcome → prune.

This is branch-and-bound where the _two players_ provide the admissible bound naturally. Achieves $O(b^{d/2})$ in the best case (effectively doubles the searchable depth for the same computation). Used in chess engines (Stockfish), Go bots, and MCTS rollout policies.

### 3. Least Constraining Value (LCV) Heuristic

When choosing _which value_ to assign next in a CSP, prefer the value that removes the fewest options from neighbouring domains. This doesn't reduce worst-case complexity but dramatically improves average case by keeping more options open — it's the inverse of forward checking's pruning focus. Pairs naturally with the Minimum Remaining Values (MRV) variable ordering heuristic used in the pseudocode above.

### 4. Iterative Deepening with Pruning (IDA*)

Combine depth-limited DFS with a bounding function based on a heuristic cost function $h$. At each node, if $g + h > \text{threshold}$, prune. Increment threshold and restart. Used in the 15-puzzle, robotic path planning, and some NLP parsing algorithms. Memory-efficient ($O(d)$) compared to A* ($O(b^d)$). The connection to [[117. Dijkstra's algorithm]] is that IDA* replaces the priority queue with iterated DFS, sacrificing speed for memory.

## 9. CP Contest Application

### Typical Problem Structure

**Codeforces problem pattern** (Div. 2 D or Div. 3 E/F):

> _"Given $n \leq 20$ items and a budget $B$, find the subset maximising value subject to $m$ constraints."_
> 
> Naive bitmask: $O(2^{20} \cdot m) = 10^7$ — borderline for 2 seconds. With branch-and-bound on the relaxed problem: often $10^3$–$10^5$ nodes in practice.

**Time limits where this matters:**

- $n \leq 20$: bitmask DP is usually fine ($O(2^n \cdot n)$). B&B only needed if there are additional constraints that make DP states expensive.
- $n \leq 40$: meet-in-the-middle is the standard approach (split into two halves of $2^{20}$ each). B&B can sometimes be faster with good bounds.
- $n \leq 100$: B&B with a strong LP-style bound is the only exact exponential approach. More typically, approximate or heuristic solutions are expected.

**Optimisation tricks for competitive settings:**

1. **Sort items by bound quality first**: For knapsack B&B, always sort by value/weight ratio descending before the search. This ensures the first complete solution found is near-optimal, making subsequent pruning aggressive.
    
2. **Fail-first principle**: In CSPs, assign the most constrained variable first (MRV). This causes failures to manifest earlier, higher in the tree, pruning larger subtrees.
    
3. **Maintain a running lower bound**: Don't initialise `best = 0`. Use a greedy solution (e.g., fractional knapsack) as the starting lower bound. This immediately makes the B&B pruning aggressive from the root.
    
4. **Symmetry breaking**: For N-Queens, only try rows $0 \leq r \leq n/2$ for the first column and double the count. Cuts the search space exactly in half with zero overhead.
    
5. **Combined approaches**: For exact cover problems (Sudoku, Dancing Links), forward checking + MRV + LCV combined often reduces an $O(n!)$ search to near-polynomial in practice. This is what Donald Knuth's Algorithm X achieves.
