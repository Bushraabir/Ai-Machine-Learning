## 1. Intuition First

### The Core Idea

A frequency map answers one question: **how many times does each distinct thing appear in a collection?** The "thing" can be anything that can be compared for equality — a character, a word, an integer, a tuple, a graph edge, a tensor shape, a URL.

The structure is simple: a HashMap where every key is a distinct element from the input, and every value is that element's occurrence count. Building it is a single linear scan:

```
for each element x in the input:
    freq[x] += 1     # or: freq[x] = freq.get(x, 0) + 1
```

That's it. The frequency map is then a **compressed representation of the input's distribution** — you've collapsed the original sequence into a summary that answers "how often?" for any element in O(1).

The reason this is its own topic, distinct from [[20.Character frequency arrays — fixed alphabet O(1) space]], is the key type. When elements are words, integers, tuples, substrings, or any type whose domain is too large or unknown to pre-allocate an array for, the HashMap is the only viable structure. You trade the perfect O(1) array indexing for amortised O(1) hashing — a small cost that unlocks counting over arbitrary domains.

### Why This Exists

The naive approach to "how many times does X appear?" is a linear scan every time you need to answer the question — O(n) per query, O(nq) for q queries. For a document with 10⁶ words and 10⁵ queries, that's 10¹¹ operations — infeasible.

The frequency map builds in O(n) and answers every subsequent query in O(1). Total: O(n + q). The HashMap pays an upfront construction cost that amortises over all queries.

Beyond query answering, the frequency map enables a pattern that appears throughout algorithms: **reduce a sequence problem to a distribution problem**. Instead of "find two elements in this list that sum to k," you ask "does the frequency map contain k − x for each x?" Instead of "find the longest subarray with equal 0s and 1s," you transform it into "find two indices with the same prefix sum" — and the frequency map of prefix sums answers it. The HashMap is the lookup structure that makes these reductions O(1) per step.

### The "Aha" Moment

> **A frequency map is a histogram. A histogram is a sufficient statistic for many problems.** Once you have the frequency map, you often don't need the original sequence anymore — the distribution tells you everything relevant. Is there a majority element? Check if any value exceeds n/2. Are two sequences permutations of each other? Their frequency maps are identical. What's the mode? It's argmax of the frequency map. The HashMap collapses the O(n) sequence into an O(|unique|) summary, and most questions about the sequence become O(|unique|) scans of the summary.

> **The `defaultdict(int)` and `Counter` in Python are the same structure with different ergonomics.** `Counter` adds arithmetic, most_common(), and set operations. `defaultdict(int)` is the raw building block. Knowing when to reach for each — and knowing that both are O(1) amortised per operation — is what separates people who use Python idiomatically from those who don't.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- Counting word frequencies, element occurrences, pair counts
- "Find the first non-repeating element" — freq map + linear scan
- "Find all elements appearing more than k times" — freq map + filter
- Two-sum, three-sum when array is unsorted and sorting would destroy required index information — see [[35.Two-sum and k-sum — the canonical HashMap pattern]]
- Subarray sum equals k — prefix sum stored in a freq map (see [[24.Subarray sum equals k — prefix sum + HashMap]])
- Grouping elements by a derived key (anagram groups, isomorphic strings)
- "Minimum window containing all elements of another array" — freq map as the requirement tracker
- Sliding window with arbitrary-key elements (integers, not just characters)

**Signal patterns:**

```
"Count occurrences of each [word / number / pair / substring]"
→ HashMap frequency counting, always

"Find element appearing exactly k times" / "more than k times"
→ build freq map, then filter by value

"Two elements satisfying a relationship f(a, b) = target"
→ fix a, look up f(a, target) in freq map: O(n) total

"Group by some derived property"
→ freq map where key = property, value = list/count
```

**Common traps that kill submissions:**

**Trap 1 — Forgetting to handle the default case in C++.**  
In C++, accessing a non-existent key in `unordered_map` with `[]` _inserts_ a zero-initialised entry. This silently corrupts the map size and can cause wrong answers when you later iterate over keys expecting only "seen" elements:

```cpp
unordered_map<int, int> freq;
// BUG: this inserts key=5 with value=0 if 5 isn't present
if (freq[5] > 0) { ... }

// CORRECT: use .count() or .find() for existence check
if (freq.count(5) > 0 && freq[5] > 0) { ... }
// Or: use .at() which throws on missing key
// Or: check with find() and dereference the iterator
```

**Trap 2 — Using mutable objects (lists, dicts) as HashMap keys.**  
In Python, only hashable (immutable) objects can be dictionary keys. A list cannot be a key. Convert to tuple first. Sorting a list and converting to tuple is a canonical "signature" pattern:

```python
# BUG: list is not hashable
freq[[1, 2, 3]] += 1  # TypeError

# CORRECT: convert to tuple
freq[tuple(sorted([1, 2, 3]))] += 1
```

**Trap 3 — Off-by-one in "exactly k occurrences" problems.**  
When counting elements appearing exactly k times, the subtlety is whether you decrement before or after checking. In sliding window problems that track a "satisfied" count, decrementing the freq map from k to k-1 loses a satisfied character; incrementing from k to k+1 gains an over-satisfied one. Both are state changes that require updating the satisfaction counter — missing either causes wrong results.

**Trap 4 — Iterating over a HashMap while modifying it.**  
In Python, modifying a dict during iteration raises `RuntimeError`. In C++, erasing during range-for has undefined behaviour. Always collect keys to modify, then modify after the loop:

```python
# BUG: RuntimeError in Python
for k, v in freq.items():
    if v == 0:
        del freq[k]

# CORRECT: collect then delete
to_delete = [k for k, v in freq.items() if v == 0]
for k in to_delete:
    del freq[k]
```

### Machine Learning / AI

**Where this appears:**

1. **Vocabulary construction in NLP tokenisation.**  
    Every tokeniser — word-level, subword (BPE, WordPiece, SentencePiece), or character-level — starts by building a frequency map over the training corpus. Words or byte-pairs with frequency below a threshold are discarded (or merged, in BPE). The frequency map _is_ the vocabulary builder. In HuggingFace's `tokenizers` library, `train_from_iterator()` internally maintains an `unordered_map<string, int>` (C++ backend) counting token frequencies. For a corpus of 100B tokens, this map has ~10⁶ unique entries and drives the entire tokeniser training process.
    
2. **TF-IDF: frequency maps at two levels.**  
    Term Frequency–Inverse Document Frequency requires a frequency map at two levels: (1) per-document term frequency (`freq[term]` within each document) and (2) document frequency across the corpus (`doc_freq[term]` = number of documents containing `term`). Scikit-learn's `TfidfVectorizer` builds both using Python dicts internally during `fit()`. Understanding that TF is a normalised frequency map and IDF is an inverse frequency map makes the formula `tf * log(N / df)` intuitive rather than arbitrary.
    
3. **Data deduplication via frequency maps.**  
    Large-scale ML dataset pipelines (C4, The Pile, Dolma, DCLM) deduplicate training data by hashing documents (MinHash, exact SHA-256) and building a frequency map over hashes. Documents appearing more than once are filtered. The frequency map of hashes is the deduplication index. At the scale of trillion-token corpora, this map lives in distributed key-value stores (Redis, RocksDB), but the algorithmic structure is identical to the single-machine frequency map.
    
4. **Feature importance via frequency in tree ensembles.**  
    Random forests and gradient boosted trees (XGBoost, LightGBM) compute feature importance as the total number of times each feature is used as a split across all trees — a frequency map where keys are feature indices and values are split counts. `model.feature_importances_` in scikit-learn is the normalised version of this frequency map. Understanding this reveals why "importance" from tree models is biased toward high-cardinality features (they appear more often as useful splits).
    
5. **Label distribution monitoring and dataset shift detection.**  
    In production ML systems, monitoring the frequency map of prediction labels over a sliding time window detects distribution shift: if `freq["class_A"]` drops from 40% to 5% over a day, something has changed. This is the core of tools like Evidently AI, Arize, and WhyLogs. The frequency map is computed over the prediction stream and compared against a reference distribution using KL divergence or chi-squared test — both of which operate on frequency counts directly.
    
6. **Attention pattern analysis in transformer interpretability.**  
    When analysing which tokens a transformer attention head attends to, researchers build frequency maps of `(query_position, key_position)` pairs across a dataset. "How often does position 3 attend to position 0?" is answered by the frequency map. Tools like BertViz and TransformerLens use this approach to characterise attention head behaviour. The frequency map over attention patterns is the summary statistic that drives mechanistic interpretability research.
    

**Why understanding this makes you better at ML code:**

The `Counter` and `defaultdict(int)` pattern is the difference between an O(n²) preprocessing loop and an O(n) one. Whenever you find yourself writing "for each element, scan the whole list to count it," you're missing a frequency map. At 10⁶ examples, O(n²) is 10¹² operations — a 30-minute wait. O(n) with a frequency map is a millisecond. More subtly, frequency maps enable one-pass streaming computation: you can update counts as data arrives without storing the full dataset — critical for pipelines that process data larger than RAM.

## 3. Algorithm / Pattern

### Core Pattern: Build and Query

```
BUILD: one pass over the input, O(n)
    freq = empty HashMap
    for each element x in sequence:
        freq[x] = freq.get(x, 0) + 1

QUERY: O(1) amortised per lookup
    count_of_x = freq.get(x, 0)
    exists      = x in freq
    all_keys    = freq.keys()   # O(|unique|) to iterate
```

### The Three Frequency-Map Idioms

**Idiom 1 — Count, then filter:**

```
Build freq map → iterate over it → yield keys where value satisfies predicate
e.g., "find all elements appearing exactly k times"
→ {x for x, count in freq.items() if count == k}
```

**Idiom 2 — Count, then lookup (complement search):**

```
Build freq map for one collection → query it for each element of another
e.g., "do arrays A and B have any element in common?"
→ Build freq(A), then for x in B: if freq.get(x, 0) > 0: return True
```

**Idiom 3 — Sliding window with freq map:**

```
Maintain a freq map for the current window
On expand (add element x): freq[x] += 1, update window-level invariant
On shrink (remove element x): freq[x] -= 1; if freq[x] == 0: del freq[x]
```

The deletion on zero is important: keeping zero-count entries inflates the map and corrupts `len(freq)` if you use it to track distinct element count.

### Complexity Analysis

**Time:**

- Build: O(n) — n insertions, each O(1) amortised
- Query: O(1) amortised per lookup
- Full iteration: O(|unique|) — may be ≪ n if duplicates are common
- Worst case single operation: O(n) if hash table resize triggers (amortised away)

**Space:** O(|unique|) — proportional to the number of distinct elements, not input length. If all elements are distinct, O(n). If one element repeats n times, O(1).

**Why amortised O(1)?** A hash table doubles capacity when the load factor exceeds a threshold (typically 0.75). Doubling takes O(current_size) to rehash all elements, but happens exponentially rarely — at sizes 1, 2, 4, 8, .... The total work across n insertions is n + n/2 + n/4 + ... = 2n = O(n). Per insertion: O(1) amortised. See [[33.unordered_map in C++ and dict in Python — internals and cost model]] for the full derivation.

### Decision: HashMap vs Frequency Array vs Sorting

```
Key type is a character / small integer (domain size ≤ ~1000)?
→ Frequency array (see [[20.Character frequency arrays — fixed alphabet O(1) space]])
  Reason: O(1) true (not amortised), cache-line resident, zero hash overhead

Key type is a word / large integer / tuple / arbitrary object?
→ HashMap frequency counting (this note)
  Reason: only option; amortised O(1) per operation

Need frequency in sorted order of keys?
→ sorted(freq.items()) after building, or use a sorted tree-map (C++ map)
  Reason: HashMap gives O(1) build+query but unordered; sort costs O(|unique| log |unique|)

Need top-k most frequent elements?
→ Build freq map, then partial sort / heap of size k
  Reason: no need to sort all |unique| elements; O(n + |unique| log k)
  See [[152.k-th largest element — heap vs quickselect]]
```

## 4. Pseudocode

### Core Frequency Map Operations

```
function BUILD_FREQ_MAP(sequence):
    freq ← empty HashMap with default value 0

    for each element x in sequence:
        freq[x] ← freq[x] + 1   # default 0 if x not present

    return freq


function FIRST_NON_REPEATING(sequence):
    freq ← BUILD_FREQ_MAP(sequence)

    # Second pass: preserve original order by scanning sequence again
    # Cannot scan freq.keys() — HashMap has no guaranteed order
    for each element x in sequence:
        if freq[x] == 1:
            return x

    return null   # all elements repeat


function TOP_K_FREQUENT(sequence, k):
    freq ← BUILD_FREQ_MAP(sequence)

    # Option A: sort all unique elements by frequency — O(|unique| log |unique|)
    # Option B: heap of size k — O(n + |unique| log k) — prefer for large |unique|

    return k largest entries of freq by value


function ELEMENTS_APPEARING_EXACTLY_K_TIMES(sequence, k):
    freq ← BUILD_FREQ_MAP(sequence)
    result ← []

    for each (element, count) in freq:
        if count == k:
            result.append(element)

    return result
```

### Sliding Window with HashMap

```
function LONGEST_SUBARRAY_AT_MOST_K_DISTINCT(arr, k):
    # Sliding window: maintain freq map of current window elements
    # Window is valid iff len(freq) <= k (at most k distinct elements)

    freq  ← empty HashMap with default 0
    left  ← 0
    best  ← 0

    for right ← 0 to len(arr) - 1:
        x ← arr[right]
        freq[x] ← freq[x] + 1   # expand window right

        # Shrink from left while too many distinct elements
        while len(freq) > k:
            left_elem ← arr[left]
            freq[left_elem] ← freq[left_elem] - 1
            if freq[left_elem] == 0:
                DELETE freq[left_elem]   # crucial: remove zero-count entries
            left ← left + 1

        best ← max(best, right - left + 1)

    return best


function SUBARRAY_EQUALS_K(arr, k):
    # Count subarrays with sum exactly k
    # Uses freq map of prefix sums (see [[24.Subarray sum equals k — prefix sum + HashMap]])

    prefix_freq ← HashMap {0: 1}   # empty prefix has sum 0, count 1
    prefix_sum  ← 0
    count       ← 0

    for each element x in arr:
        prefix_sum ← prefix_sum + x
        # If (prefix_sum - k) appeared before, those subarrays sum to k
        count ← count + prefix_freq.get(prefix_sum - k, 0)
        prefix_freq[prefix_sum] ← prefix_freq.get(prefix_sum, 0) + 1

    return count
```

### Frequency Map as Group-By

```
function GROUP_BY_FREQUENCY_CLASS(sequence):
    # Group elements by their frequency
    # e.g., elements appearing 3 times go in group 3

    freq      ← BUILD_FREQ_MAP(sequence)
    by_count  ← empty HashMap  # count → list of elements with that count

    for each (element, count) in freq:
        by_count[count].append(element)   # default: empty list

    return by_count
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <unordered_map>
#include <unordered_set>
#include <vector>
#include <string>
#include <algorithm>
#include <queue>
#include <iostream>
#include <cassert>

// ─────────────────────────────────────────────────────────────────
// Build frequency map from a vector
// Time: O(n) amortised   Space: O(|unique|)
// ─────────────────────────────────────────────────────────────────
template<typename T>
std::unordered_map<T, int> buildFreq(const std::vector<T>& seq) {
    std::unordered_map<T, int> freq;
    freq.reserve(seq.size());  // avoid rehashing — reserve upfront
    for (const T& x : seq) {
        freq[x]++;
    }
    return freq;
}

// ─────────────────────────────────────────────────────────────────
// First non-repeating element in sequence (preserves order)
// Time: O(n)   Space: O(|unique|)
// ─────────────────────────────────────────────────────────────────
int firstNonRepeating(const std::vector<int>& nums) {
    std::unordered_map<int, int> freq;
    freq.reserve(nums.size());
    for (int x : nums) freq[x]++;

    // Second pass: scan ORIGINAL sequence to preserve order
    // Cannot rely on HashMap iteration order
    for (int x : nums) {
        if (freq[x] == 1) return x;
    }
    return -1;  // all elements repeat
}

// ─────────────────────────────────────────────────────────────────
// Top-k most frequent elements — min-heap of size k
// Time: O(n + |unique| log k)   Space: O(|unique|)
// ─────────────────────────────────────────────────────────────────
std::vector<int> topKFrequent(const std::vector<int>& nums, int k) {
    // Build frequency map
    std::unordered_map<int, int> freq;
    freq.reserve(nums.size());
    for (int x : nums) freq[x]++;

    // Min-heap: keep the k largest frequencies
    // Heap element: {count, value}
    using P = std::pair<int, int>;
    std::priority_queue<P, std::vector<P>, std::greater<P>> min_heap;

    for (const auto& [val, count] : freq) {
        min_heap.push({count, val});
        if (static_cast<int>(min_heap.size()) > k) {
            min_heap.pop();  // evict smallest-frequency element
        }
    }

    std::vector<int> result;
    result.reserve(k);
    while (!min_heap.empty()) {
        result.push_back(min_heap.top().second);
        min_heap.pop();
    }
    return result;  // order not guaranteed; sort if needed
}

// ─────────────────────────────────────────────────────────────────
// Longest subarray with at most k distinct elements
// Sliding window + HashMap — O(1) distinct-count via map size
// Time: O(n)   Space: O(k) — window has at most k+1 distinct elements
// ─────────────────────────────────────────────────────────────────
int longestSubarrayKDistinct(const std::vector<int>& arr, int k) {
    std::unordered_map<int, int> freq;
    freq.reserve(k + 2);  // window holds at most k+1 distinct elements
    int left = 0, best = 0;

    for (int right = 0; right < static_cast<int>(arr.size()); ++right) {
        freq[arr[right]]++;

        // Shrink window until at most k distinct elements remain
        while (static_cast<int>(freq.size()) > k) {
            int left_val = arr[left];
            if (--freq[left_val] == 0) {
                freq.erase(left_val);  // remove zero-count entry
            }
            ++left;
        }

        best = std::max(best, right - left + 1);
    }
    return best;
}

// ─────────────────────────────────────────────────────────────────
// Subarray sum equals k — prefix sum + frequency map
// Counts subarrays (contiguous) whose elements sum to exactly k
// Time: O(n)   Space: O(n) for prefix sum counts
// ─────────────────────────────────────────────────────────────────
int subarraySumEqualsK(const std::vector<int>& nums, int k) {
    std::unordered_map<int, int> prefix_freq;
    prefix_freq[0] = 1;  // empty prefix sums to 0
    int prefix_sum = 0, count = 0;

    for (int x : nums) {
        prefix_sum += x;
        // subarrays ending here with sum k start where prefix_sum - k occurred
        count += prefix_freq.count(prefix_sum - k)
                     ? prefix_freq[prefix_sum - k]
                     : 0;
        prefix_freq[prefix_sum]++;
    }
    return count;
}

// ─────────────────────────────────────────────────────────────────
// Frequency of frequencies — second-order freq map
// Groups elements by their occurrence count
// Time: O(n)   Space: O(|unique|)
// ─────────────────────────────────────────────────────────────────
std::unordered_map<int, std::vector<int>>
freqOfFreq(const std::vector<int>& nums) {
    std::unordered_map<int, int> freq;
    for (int x : nums) freq[x]++;

    std::unordered_map<int, std::vector<int>> by_count;
    for (const auto& [val, count] : freq) {
        by_count[count].push_back(val);
    }
    return by_count;
}

// ─────────────────────────────────────────────────────────────────
// Isomorphic strings — bijective frequency map between two alphabets
// Two strings are isomorphic if characters can be remapped consistently
// Time: O(n)   Space: O(|unique chars|)
// ─────────────────────────────────────────────────────────────────
bool isIsomorphic(const std::string& s, const std::string& t) {
    if (s.size() != t.size()) return false;

    std::unordered_map<char, char> s_to_t, t_to_s;

    for (int i = 0; i < static_cast<int>(s.size()); ++i) {
        char sc = s[i], tc = t[i];

        // Check s → t mapping
        if (s_to_t.count(sc)) {
            if (s_to_t[sc] != tc) return false;
        } else {
            s_to_t[sc] = tc;
        }

        // Check t → s mapping (ensures bijection, not just injection)
        if (t_to_s.count(tc)) {
            if (t_to_s[tc] != sc) return false;
        } else {
            t_to_s[tc] = sc;
        }
    }
    return true;
}

// ─────── Tests ───────────────────────────────────────────────────
int main() {
    // Build freq
    auto freq = buildFreq<int>({1, 2, 2, 3, 3, 3});
    assert(freq[1] == 1 && freq[2] == 2 && freq[3] == 3);

    // First non-repeating
    assert(firstNonRepeating({1, 2, 1, 3, 2}) == 3);
    assert(firstNonRepeating({1, 1, 2, 2}) == -1);

    // Top-k frequent
    auto top = topKFrequent({1,1,1,2,2,3}, 2);
    std::sort(top.begin(), top.end());
    assert((top == std::vector<int>{1, 2}) || (top == std::vector<int>{2, 1}));

    // Longest k-distinct
    assert(longestSubarrayKDistinct({1,2,1,2,3}, 2) == 4);
    assert(longestSubarrayKDistinct({1,2,3,4,5}, 1) == 1);

    // Subarray sum = k
    assert(subarraySumEqualsK({1,1,1}, 2) == 2);
    assert(subarraySumEqualsK({1,2,3}, 3) == 2);  // [1,2] and [3]
    assert(subarraySumEqualsK({-1,-1,1}, 0) == 1);

    // Isomorphic
    assert(isIsomorphic("egg", "add"));
    assert(!isIsomorphic("foo", "bar"));
    assert(isIsomorphic("paper", "title"));
    assert(!isIsomorphic("ab", "aa"));  // two chars can't map to same

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations
from collections import defaultdict, Counter
from typing import TypeVar, Hashable, Sequence
import heapq

T = TypeVar('T', bound=Hashable)


# ─────────────────────────────────────────────────────────────────
# Counter vs defaultdict(int) — when to use each
#
# Counter:     use when you need .most_common(), arithmetic between
#              counters, or set-like operations (+, -, &, |)
# defaultdict: use when you're building a map incrementally and
#              need the zero-default but not Counter's extra API
# dict.get:    use for one-off lookups without committing to a type
# ─────────────────────────────────────────────────────────────────

def build_freq_counter(seq: Sequence[T]) -> Counter:
    """
    Build a frequency map using Counter.
    Counter[x] returns 0 for missing keys (no KeyError).

    Complexity: O(n) time, O(|unique|) space
    """
    return Counter(seq)


def build_freq_defaultdict(seq: Sequence[T]) -> defaultdict:
    """
    Build a frequency map using defaultdict(int).
    Equivalent to Counter for pure counting; no extra API.

    Complexity: O(n) time, O(|unique|) space
    """
    freq: defaultdict[T, int] = defaultdict(int)
    for x in seq:
        freq[x] += 1
    return freq


# ─────────────────────────────────────────────────────────────────
# First non-repeating element (preserves original order)
# Time: O(n)   Space: O(|unique|)
# ─────────────────────────────────────────────────────────────────
def first_non_repeating(seq: list) -> object:
    """
    Return first element that appears exactly once, preserving order.

    Critical insight: scan the original sequence a second time —
    not the freq map. HashMap iteration order is insertion order
    in Python 3.7+, but insertion order ≠ first-occurrence order
    when an element first appears multiple times.

    Actually in Python 3.7+ dict IS ordered by insertion, so Counter
    iteration would work — but the two-pass pattern is cleaner and
    works in all languages regardless of HashMap ordering guarantees.

    Complexity: O(n) time, O(|unique|) space
    """
    freq = Counter(seq)

    for x in seq:               # second pass: respects original order
        if freq[x] == 1:
            return x

    return None


# ─────────────────────────────────────────────────────────────────
# Top-k most frequent elements
# Time: O(n + |unique| log k)   Space: O(|unique|)
# ─────────────────────────────────────────────────────────────────
def top_k_frequent(nums: list[int], k: int) -> list[int]:
    """
    Return the k most frequent elements in nums.

    Uses Counter.most_common(k) which internally uses a heap —
    O(n + |unique| log k). This is better than sorting all unique
    elements when k << |unique|.

    Complexity: O(n + |unique| log k) time, O(|unique|) space
    """
    freq = Counter(nums)
    # most_common(k) uses heapq.nlargest internally — O(|unique| log k)
    return [val for val, _ in freq.most_common(k)]


def top_k_frequent_manual(nums: list[int], k: int) -> list[int]:
    """
    Same result, explicit heap for educational clarity.
    Shows the O(n + |unique| log k) structure explicitly.
    """
    freq = Counter(nums)

    # Min-heap of size k: (count, value)
    # We want the k largest counts — min-heap evicts smallest
    heap: list[tuple[int, int]] = []
    for val, count in freq.items():
        heapq.heappush(heap, (count, val))
        if len(heap) > k:
            heapq.heappop(heap)   # evict least frequent

    return [val for _, val in heap]


# ─────────────────────────────────────────────────────────────────
# Longest subarray with at most k distinct elements
# Sliding window + defaultdict — O(1) distinct count via len(freq)
# Time: O(n)   Space: O(k)
# ─────────────────────────────────────────────────────────────────
def longest_subarray_k_distinct(arr: list[int], k: int) -> int:
    """
    Find the length of the longest subarray with at most k distinct values.

    Window invariant: len(freq) <= k (at most k distinct elements).
    Critical: delete zero-count entries to keep len(freq) accurate.

    Complexity: O(n) time, O(k) space — window holds ≤ k+1 distinct
    """
    freq: defaultdict[int, int] = defaultdict(int)
    left = 0
    best = 0

    for right, x in enumerate(arr):
        freq[x] += 1

        # Shrink window while too many distinct elements
        while len(freq) > k:
            left_val = arr[left]
            freq[left_val] -= 1
            if freq[left_val] == 0:
                del freq[left_val]   # MUST delete to keep len(freq) correct
            left += 1

        best = max(best, right - left + 1)

    return best


# ─────────────────────────────────────────────────────────────────
# Subarray sum equals k — prefix sum + frequency map
# Time: O(n)   Space: O(n) for prefix sum freq map
# ─────────────────────────────────────────────────────────────────
def subarray_sum_equals_k(nums: list[int], k: int) -> int:
    """
    Count subarrays whose elements sum to exactly k.

    Key insight: prefix_sum[j] - prefix_sum[i] = k
                 ⟺ prefix_sum[i] = prefix_sum[j] - k

    For each j, we want to count how many i < j have
    prefix_sum[i] = prefix_sum[j] - k.
    That count is exactly freq[prefix_sum[j] - k].

    Works for negative numbers — unlike sliding window approaches.

    Complexity: O(n) time, O(n) space
    """
    prefix_freq: defaultdict[int, int] = defaultdict(int)
    prefix_freq[0] = 1   # empty prefix: sum=0, count=1
    prefix_sum = 0
    count = 0

    for x in nums:
        prefix_sum += x
        # How many subarrays ending here sum to k?
        count += prefix_freq[prefix_sum - k]
        prefix_freq[prefix_sum] += 1

    return count


# ─────────────────────────────────────────────────────────────────
# Frequency of frequencies — second-order structure
# Time: O(n)   Space: O(|unique|)
# ─────────────────────────────────────────────────────────────────
def freq_of_freq(nums: list[int]) -> dict[int, list[int]]:
    """
    Group elements by their frequency.
    Returns: {frequency: [elements with that frequency]}

    Used in: "find elements appearing exactly k times",
             "can all elements have same freq with one deletion?",
             "sort by frequency" problems.

    Complexity: O(n) time, O(|unique|) space
    """
    freq = Counter(nums)
    by_count: defaultdict[int, list[int]] = defaultdict(list)
    for val, count in freq.items():
        by_count[count].append(val)
    return dict(by_count)


# ─────────────────────────────────────────────────────────────────
# Isomorphic strings — bijective mapping between two alphabets
# Time: O(n)   Space: O(|unique chars| in both strings)
# ─────────────────────────────────────────────────────────────────
def is_isomorphic(s: str, t: str) -> bool:
    """
    Two strings are isomorphic if s's characters can be consistently
    remapped to t's characters (bijection: one-to-one and onto).

    Requires TWO maps (s→t and t→s) to enforce bijection.
    One map alone allows two distinct s-chars to map to same t-char.

    Complexity: O(n) time, O(|unique|) space
    """
    if len(s) != len(t):
        return False

    s_to_t: dict[str, str] = {}
    t_to_s: dict[str, str] = {}

    for sc, tc in zip(s, t):
        if sc in s_to_t:
            if s_to_t[sc] != tc:
                return False
        else:
            s_to_t[sc] = tc

        if tc in t_to_s:
            if t_to_s[tc] != sc:
                return False
        else:
            t_to_s[tc] = sc

    return True


# ─────────────────────────────────────────────────────────────────
# Word pattern matching — same structure as isomorphic strings
# Time: O(n)   Space: O(|unique|)
# ─────────────────────────────────────────────────────────────────
def word_pattern(pattern: str, s: str) -> bool:
    """
    Return True if s follows the same pattern as pattern.
    e.g., pattern="abba", s="dog cat cat dog" → True
          pattern="abba", s="dog cat cat fish" → False

    Structurally identical to is_isomorphic — bijection between
    pattern chars and words.

    Complexity: O(n) time, O(|unique|) space
    """
    words = s.split()
    if len(pattern) != len(words):
        return False

    char_to_word: dict[str, str] = {}
    word_to_char: dict[str, str] = {}

    for ch, word in zip(pattern, words):
        if ch in char_to_word:
            if char_to_word[ch] != word:
                return False
        else:
            char_to_word[ch] = word

        if word in word_to_char:
            if word_to_char[word] != ch:
                return False
        else:
            word_to_char[word] = ch

    return True


# ─────────────────────────────────────────────────────────────────
# Counter arithmetic — set operations on frequency maps
# Demonstrates Counter's unique capabilities vs plain dict
# ─────────────────────────────────────────────────────────────────
def demonstrate_counter_ops() -> None:
    """
    Counter supports arithmetic that defaultdict does not.
    These are genuinely useful in ML preprocessing.
    """
    a = Counter("aabbcc")          # {'a':2, 'b':2, 'c':2}
    b = Counter("aabbb")           # {'a':2, 'b':3}

    # Union: max counts (not sum)
    union = a | b                  # {'a':2, 'b':3, 'c':2}

    # Intersection: min counts
    inter = a & b                  # {'a':2, 'b':2}

    # Subtraction: saturates at 0 (no negatives)
    diff = a - b                   # {'c':2}  (b's 'a' and 'b' cancel or exceed a's)

    # Addition: sum counts
    total = a + b                  # {'a':4, 'b':5, 'c':2}

    assert union['b'] == 3
    assert inter['b'] == 2
    assert 'a' not in diff        # a:2 - a:2 = 0, removed
    assert total['b'] == 5

    # Practical use: combining word counts from multiple documents
    doc1_words = Counter("the cat sat on the mat".split())
    doc2_words = Counter("the dog sat on the log".split())
    combined = doc1_words + doc2_words
    assert combined['the'] == 4   # 2 from each doc
    assert combined['cat'] == 1
    assert combined['dog'] == 1
```

## 6. Visual Explanation

### HashMap Frequency Build: What Happens Internally

For input `[3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5]`:

```
Insertion sequence into the hash table (conceptual bucket view):

After processing:
  3 → bucket[hash(3) % capacity]: {3: 1}
  1 → bucket[hash(1) % capacity]: {1: 1}
  4 → ...                          {4: 1}
  1 → finds key 1 already exists:  {1: 2}   ← increment
  5 → new key:                     {5: 1}
  9 → new key:                     {9: 1}
  2 → new key:                     {2: 1}
  6 → new key:                     {6: 1}
  5 → finds key 5:                 {5: 2}   ← increment
  3 → finds key 3:                 {3: 2}   ← increment
  5 → finds key 5:                 {5: 3}   ← increment

Final frequency map:
  Key │ Count │ Meaning
  ────┼───────┼──────────────
   1  │   2   │ appears twice
   2  │   1   │ appears once
   3  │   2   │ appears twice
   4  │   1   │ appears once
   5  │   3   │ most frequent
   6  │   1   │ appears once
   9  │   1   │ appears once

Space: 7 entries (|unique| = 7), not 11 (input length n = 11)
When duplicates dominate, |unique| << n — significant space saving.
```

### Prefix Sum + Frequency Map: Subarray Sum = k

For `nums = [1, 2, 3]`, k = 3:

```
Index:      0    1    2
Value:      1    2    3

prefix_sum: 0    1    3    6
                ↑    ↑    ↑
               (after pos 0) (after pos 1) (after pos 2)

prefix_freq initialised: {0: 1}

Step i=0: x=1, prefix_sum=1
  Look up prefix_sum - k = 1 - 3 = -2 → freq[-2] = 0. count += 0.
  Record: prefix_freq = {0:1, 1:1}

Step i=1: x=2, prefix_sum=3
  Look up 3 - 3 = 0 → freq[0] = 1. count += 1.  ← [1,2] sums to 3 ✓
  Record: prefix_freq = {0:1, 1:1, 3:1}

Step i=2: x=3, prefix_sum=6
  Look up 6 - 3 = 3 → freq[3] = 1. count += 1.  ← [3] sums to 3 ✓
  Record: prefix_freq = {0:1, 1:1, 3:1, 6:1}

Final count = 2. Subarrays: [1,2] and [3]. ✓

Intuition: prefix_sum[j] - prefix_sum[i] = sum(nums[i..j-1]) = k
           So we want all i where prefix_sum[i] = prefix_sum[j] - k.
           freq[prefix_sum[j] - k] counts those i values at each j.
```

### Sliding Window with HashMap: Distinct Count via `len(freq)`

For `arr = [1, 2, 1, 2, 3]`, k = 2:

```
Window contents (freq map) at each right pointer:

right=0: add 1 → freq={1:1}. len=1 ≤ 2. window=[0..0], size=1
right=1: add 2 → freq={1:1, 2:1}. len=2 ≤ 2. window=[0..1], size=2
right=2: add 1 → freq={1:2, 2:1}. len=2 ≤ 2. window=[0..2], size=3 ← best so far
right=3: add 2 → freq={1:2, 2:2}. len=2 ≤ 2. window=[0..3], size=4 ← best
right=4: add 3 → freq={1:2, 2:2, 3:1}. len=3 > 2. SHRINK:
  remove arr[left=0]=1: freq[1]=1. len still 3.  left=1
  remove arr[left=1]=2: freq[2]=1. len still 3.  left=2
  remove arr[left=2]=1: freq[1]=0 → DELETE 1. len=2 ≤ 2. left=3
  freq={2:1, 3:1}. window=[3..4], size=2.

best = 4 (window [1,2,1,2]).

Key: len(freq) == number of distinct elements in current window.
     Deletion of zero-count entries is mandatory for this to be correct.
     If we kept freq={1:0, 2:1, 3:1}, len would wrongly report 3.
```

## 7. Common Variations & Extensions

### Variation 1: Frequency Map with Ordered Keys (sorted output)

When the problem requires results in sorted order by key, build the frequency map (O(n)), then iterate in sorted key order (O(|unique| log |unique|)). In C++, use `std::map` (red-black tree, O(log n) per insertion) if you need keys always sorted; in Python, `dict` is insertion-ordered but not sorted — use `sorted(freq.items())` after building.

The choice: if you need to insert and iterate in sorted order repeatedly, `std::map` / sorted structure is better. If you insert once and sort once, `unordered_map` + sort is faster (hash table build is O(n), sort is O(k log k) where k = |unique| ≤ n).

### Variation 2: Frequency Map as Multiset

The frequency map implements a **multiset** (a set where elements can appear multiple times). In C++, `std::multiset` supports this with O(log n) operations, but for integer keys, an `unordered_map<int,int>` is strictly faster. The multiset abstraction — insert, delete, count, find-min, find-max — is fully implementable using a frequency map plus a sorted structure (e.g., a sorted list or heap) for the order operations.

### Variation 3: Frequency Map for Sliding Window Maximum Distinct

"Minimum window in s containing all characters of t" (LC 76) — the freq map tracks character requirements. The `deficit` counter (see [[20.Character frequency arrays — fixed alphabet O(1) space]]) works for fixed alphabet; for arbitrary keys (integer arrays, word arrays), you need a HashMap. The logic is identical; only the key type changes.

### Variation 4: Frequency Map Serialisation as a HashMap Key

To use a frequency map _as a key_ in a higher-level map (e.g., grouping items by their frequency distribution), you must serialise it to a hashable type. Options: `tuple(sorted(freq.items()))` (canonical, order-independent), or `frozenset(freq.items())` if order doesn't matter. The sorted-tuple approach is the canonical signature for anagram grouping (see [[22.Anagram detection and group-by-signature patterns]]).

### Variation 5: Streaming Frequency Counting

When input is a stream (too large for memory), exact frequency counting requires O(n) space. Approximate alternatives:

- **Count-Min Sketch**: O(1/ε · log(1/δ)) space, overestimates frequencies by at most ε·n with probability 1-δ. Used in network traffic monitoring, streaming ML feature statistics.
- **Lossy Counting**: for finding elements with frequency > ε·n. Used in finding heavy hitters (approximately the same problem as majority element, see [[23.Majority element — Boyer-Moore voting algorithm]]). These are the production answers when the frequency map itself doesn't fit in memory — understanding the exact structure first is the prerequisite.

## 9. CP Contest Application

### Typical Problem Structures

**Type 1 — Element property counting (Div. 2 B):** "Given an array, find the number of elements that appear more than ⌊n/3⌋ times." Build freq map in O(n), scan for elements exceeding the threshold — O(|unique|). No Boyer-Moore needed if the threshold is not exactly n/2.

**Type 2 — Pair sum with frequency (Div. 2 C):** "Count pairs (i, j) with i < j such that arr[i] + arr[j] = k." Sort + two-pointer is O(n log n). Freq map approach: for each element x, count freq[k - x], then divide by 2 (or handle carefully for x = k/2). This becomes O(n) — faster and handles duplicates more naturally.

```cpp
long long countPairsWithSum(vector<int>& arr, int k) {
    unordered_map<int,long long> freq;
    for (int x : arr) freq[x]++;
    long long count = 0;
    for (auto& [x, fx] : freq) {
        int comp = k - x;
        if (comp == x) {
            count += fx * (fx - 1) / 2;   // pairs within same value
        } else if (comp > x && freq.count(comp)) {
            count += fx * freq[comp];      // count each pair once
        }
    }
    return count;
}
```

**Type 3 — Sliding window with arbitrary elements (Div. 2 C / Div. 1 B):** "Find the number of subarrays with exactly k distinct integers." Classic: exact-k = at-most-k minus at-most-(k-1). Both "at-most" problems are solved with sliding window + HashMap. At n = 10⁵, the HashMap overhead is acceptable; the total operations are O(n) amortised.

**Type 4 — Frequency map + DP (Div. 1 B/C):** "Given an array, you can delete all occurrences of a value x and gain x × freq[x] points, but deleting x also deletes all occurrences of x-1 and x+1 (like house robber). Maximise points." Build freq map, compute `value[x] = x * freq[x]`, then run house robber DP on the value array indexed by integer. The freq map converts the problem into a 1D DP over distinct values — O(n + max_value).

```python
def max_points(nums: list[int]) -> int:
    freq = Counter(nums)
    max_val = max(nums)
    # value[i] = total points from taking all occurrences of i
    values = [i * freq[i] for i in range(max_val + 1)]
    # House robber DP: can't take both i and i+1
    dp = [0] * (max_val + 1)
    dp[1] = values[1] if max_val >= 1 else 0
    for i in range(2, max_val + 1):
        dp[i] = max(dp[i-1], dp[i-2] + values[i])
    return dp[max_val]
```

### Performance Notes

`unordered_map` in C++ has a well-known worst-case problem: adversarial inputs can cause hash collisions that degrade all operations to O(n), making a solution that should be O(n) run in O(n²). In competitive programming, when you suspect anti-hash tests (Codeforces especially), use a custom hash:

```cpp
struct custom_hash {
    static uint64_t splitmix64(uint64_t x) {
        x += 0x9e3779b97f4a7c15;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9;
        x = (x ^ (x >> 27)) * 0x94d049bb133111eb;
        return x ^ (x >> 31);
    }
    size_t operator()(uint64_t x) const {
        static const uint64_t FIXED_RANDOM =
            chrono::steady_clock::now().time_since_epoch().count();
        return splitmix64(x + FIXED_RANDOM);
    }
};
unordered_map<int, int, custom_hash> freq;
```

This randomises the hash function per-run, making adversarial collision attacks impossible. Use this in any Codeforces problem where `unordered_map` gives TLE on an O(n) solution.
