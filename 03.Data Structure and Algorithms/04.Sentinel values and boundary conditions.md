## 1. Intuition First

### The Core Idea

A lighthouse does not guide ships that are already safely in harbour. It exists precisely for the dangerous boundary — the rocky coastline where open sea becomes land, where the normal rules of navigation stop applying cleanly. The lighthouse is a sentinel: a specially placed signal that marks the boundary so the ship's logic does not have to handle "am I about to hit rocks?" as a special case at every moment of the voyage. It handles it _once_, at the edge.

A sentinel value is a designated element — placed at the boundary of a data structure, or used as a flag in a computation — whose only job is to make the general-case logic work correctly at the edges without needing an `if` statement. Instead of writing:

```
if i > 0 and a[i-1] satisfies condition: ...
```

you place a sentinel at index -1 (or 0, or n, depending on direction) such that `a[-1]` always satisfies — or always fails — the condition. The loop body stays uniform. The boundary case disappears into the sentinel.

The deeper principle: **a boundary condition is a place where the uniform rule breaks down**. Sentinels repair this breakage by extending the data structure to make the uniform rule hold everywhere, including the edges.

### Why This Exists

Without sentinels, every algorithm that touches boundaries must branch: "if this is the first element, handle it separately; if this is the last, handle it separately." These branches are the #1 source of off-by-one errors in competitive programming and production code alike. They are not logically hard — they are _tedious_ and _invisible_ under pressure. A missing boundary check does not fail loudly; it corrupts the answer silently on the one test case where the subarray starts at index 0 or ends at index n-1.

Sentinels make the boundary case structurally identical to the general case. The result is:

- Fewer branches → fewer off-by-one opportunities
- Shorter, more readable loop bodies
- Provably correct edge behaviour (the sentinel's value is chosen by construction, not by hope)

The cost is always O(1): one extra element, one extra initialisation, sometimes one extra comparison. The benefit compounds across every algorithm that uses the structure.

### The "Aha" Moment

> **A sentinel does not solve the boundary problem — it relocates it. You move the special case from inside the loop (where it fires unpredictably) to the initialisation (where you handle it exactly once, deliberately).**

Once you see this, sentinel placement becomes a design decision: what value, at what position, makes the general-case rule hold at the boundary? Answer that question once during design, and the loop writes itself.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Sentinels are not a single algorithm — they are a technique woven into dozens of algorithms. You encounter them explicitly in:

- **Monotonic stack problems:** A sentinel of `0` or `-∞` pushed at the start ensures the stack is never empty when you pop, eliminating the `if stack is empty` check inside the loop. See [[87.Monotonic increasing stack — next greater element]] and [[89.Largest rectangle in histogram — the canonical monotonic stack problem]].
- **Linked list manipulation:** A dummy head node is a sentinel — it ensures that "insert before the first real node" and "insert in the middle" are the same operation. No special case for an empty list or head insertion.
- **Binary search:** The values `lo = 0`, `hi = n` (one past the end) are sentinels for the search space boundary. The invariant `a[lo-1] < target ≤ a[hi]` is maintained by choosing these boundary values to _define_ the invariant, not satisfy it by coincidence. See [[56.lower_bound and upper_bound — first and last occurrence]].
- **Sorting:** Insertion sort uses a sentinel at index -1 (a value of -∞) so the inner while loop never needs to check `j >= 0`. The loop terminates when it hits the sentinel. This is the textbook CLRS presentation of insertion sort.
- **String algorithms:** The null terminator `\0` in C strings is a sentinel — it makes "iterate until end of string" a uniform loop without a length parameter.

**Pattern signal — when to add a sentinel:**

```
You find yourself writing: if i == 0: (special case) else: (general case)
                        or: if i == n-1: (special case) else: (general case)
→ Ask: what value at index -1 or n would make the general case cover this?
→ Place that value. Delete the branch.
```

**Common trap 1 — sentinel value chosen incorrectly:** Placing `INT_MAX` as a sentinel in a min-heap problem when the comparison is `<` — the sentinel terminates the loop correctly. But placing `0` as a sentinel in a problem with valid zero values causes the sentinel to be mistaken for real data. The sentinel's value must be _outside the valid data range_ or _structurally distinguished_ (e.g., a separate boolean flag, a pointer to a special node).

**Common trap 2 — forgetting to account for the sentinel in the output:** If you push a sentinel onto a stack and then return `stack.size()`, you are off by 1. The sentinel is not part of the answer. Always strip sentinels from output or account for them in size calculations.

**Common trap 3 — boundary condition off-by-one in binary search:** The most common bug in binary search is `lo < hi` vs `lo <= hi`, and returning `lo` vs `lo - 1` vs `mid`. These are all boundary condition bugs. The sentinel approach: define your loop invariant precisely (`a[lo] < target ≤ a[hi]` for lower_bound), initialise `lo` and `hi` as sentinels that satisfy this invariant for an empty search space, and derive the termination condition from the invariant. Every `<` vs `<=` question has a unique answer once the invariant is fixed. See [[55.Binary search on a sorted array — exact match]].

### Machine Learning / AI

**1. Padding as a sentinel in sequence models.** Variable-length sequences (sentences, time series) must be batched into fixed-size tensors for GPU processing. **Padding tokens** — appended to shorter sequences to match the longest sequence in the batch — are sentinels. They mark "this position is not real data; ignore it." In Transformers, the attention mask is a binary tensor where `0` marks padded (sentinel) positions and the attention mechanism applies a mask of `-∞` (which softmax maps to probability 0) to those positions. The uniform attention computation works on all positions — padding sentinels make the boundary (end of a short sequence) structurally identical to the interior. PyTorch: `torch.nn.utils.rnn.pad_sequence`, attention mask in `transformers.BertModel`. See [[220.Data pipeline design — streaming vs batch, shuffling, prefetching]].

**2. `NaN` and `±inf` as sentinels in numerical computation.** IEEE 754 defines `NaN`, `+∞`, and `-∞` as sentinel values with algebraic properties designed to propagate through computation. `max(-∞, x) = x` for all real `x` — this is exactly the sentinel property that makes initialising a running maximum with `-∞` correct for an empty input. Similarly, `softmax` with a mask of `-∞` produces exactly 0 attention weight — the sentinel value propagates through the exponential cleanly. Understanding this prevents the instinctive "initialise max with 0" bug in ML aggregation code. See [[221.Numerical stability — log-sum-exp, softmax overflow prevention]].

**3. End-of-sequence tokens in language models.** The `<EOS>` token in autoregressive language models (GPT, T5, LLaMA) is a sentinel. During generation, the model produces tokens until it generates `<EOS>`, at which point the generation loop terminates. The loop body is uniform — predict the next token — and the sentinel value (`<EOS>`) is what makes "have we reached the end?" a condition that the loop can evaluate uniformly rather than requiring an external length counter. The `<BOS>` (beginning-of-sequence) token is the forward sentinel, placed at the start to give the model a valid "previous token" to condition on at position 0. This is the dummy-head-node pattern applied to token sequences.

**4. Sentinel initialisation in tree algorithms.** In decision tree implementations (scikit-learn's CART, XGBoost), the algorithm searches for the best split threshold. During this search, the "no split" case is represented by a sentinel split with gain = `-∞` or impurity = `+∞`. The argmax over all candidate splits naturally returns the best real split without a special case for "no valid split found yet." This is the running-maximum-with-sentinel pattern applied to split search. See [[158.Decision tree structure — how CART maps to a binary tree]].

## 3. Algorithm / Pattern

### The Five Sentinel Patterns

**Pattern 1 — Boundary sentinel in a loop (eliminate edge-case branches):**

```
Place a[−1] = SENTINEL_LOW  (or a[n] = SENTINEL_HIGH)
such that the loop condition is always false at the boundary.
The loop terminates at the sentinel without a separate length check.
```

**Pattern 2 — Identity-element initialisation (running aggregates):**

```
max_so_far = −∞    ← sentinel: max(−∞, x) = x for all real x
min_so_far = +∞    ← sentinel: min(+∞, x) = x for all real x
product    =  1    ← sentinel: 1 × x = x
sum        =  0    ← sentinel: 0 + x = x
```

These are not arbitrary choices — they are the identity elements of their respective operations, which are sentinels by definition.

**Pattern 3 — Dummy node (linked structures):**

```
head = DummyNode(val=−∞)   ← sentinel: head.next is the real first node
tail = DummyNode(val=+∞)   ← sentinel: tail.prev is the real last node
Every insert/delete operation works on real nodes only; boundaries handled by dummies.
```

**Pattern 4 — Exclusive boundary in binary search:**

```
lo = −1     ← sentinel: a[lo] is always < target (vacuously)
hi = n      ← sentinel: a[hi] is always ≥ target (vacuously)
Invariant: a[lo] < target ≤ a[hi] holds throughout.
Answer: lo + 1 (the first index where a[i] ≥ target).
```

**Pattern 5 — Flag value (out-of-band signal):**

```
Return −1 to mean "not found" (when all valid answers are ≥ 0).
Return None/null to mean "no result."
Use INT_MAX to mean "unreachable" in shortest-path algorithms.
The sentinel value must be impossible as a valid answer.
```

### Boundary Condition Taxonomy

Every array algorithm must handle these boundary cases explicitly or via sentinels:

|Boundary|What can go wrong|Sentinel fix|
|---|---|---|
|Empty array (`n = 0`)|Accessing `a[0]` on empty array → crash|Return early, or initialise aggregate with identity|
|Single element (`n = 1`)|Loop never executes, answer is `a[0]`|Identity initialisation makes loop correct for n=1|
|First element (`i = 0`)|`a[i-1]` is out of bounds|Dummy element at index -1|
|Last element (`i = n-1`)|`a[i+1]` is out of bounds|Dummy element at index n|
|All identical elements|Deduplication returns nothing|Write-pointer starts at 1, returns 1|
|All negative elements|Max aggregate initialised to 0 returns wrong answer|Initialise with `a[0]` or `-∞`|

### Complexity

**Time:** O(1) overhead — one sentinel initialisation. Does not change the asymptotic complexity of any algorithm.

**Space:** O(1) — one or two extra elements. For linked lists, two dummy nodes. For arrays, one or two extra entries (or just a separate variable).

## 4. Pseudocode

```
// ─── Pattern 1: Insertion Sort with Sentinel ──────────────────────────────
// Classic CLRS formulation: a[-1] = −∞ eliminates the j >= 0 boundary check.
// In practice: store sentinel at a[0], shift real data to a[1..n].

function insertion_sort_sentinel(a[0..n]):
    a[0] ← −∞        // sentinel: always less than any real element
    // Real data is in a[1..n] (1-indexed for this formulation)

    for i from 2 to n:
        key ← a[i]
        j   ← i - 1
        // No need to check j >= 1: when j=1, a[0]=−∞ < key, loop stops.
        while a[j] > key:
            a[j + 1] ← a[j]
            j ← j - 1
        a[j + 1] ← key


// ─── Pattern 2: Running Maximum with Identity Sentinel ────────────────────

function running_max(a[0..n-1]) → max_val:
    max_val ← −∞     // sentinel: any real value beats −∞
    for i from 0 to n-1:
        max_val ← max(max_val, a[i])
    // Correct even for n=0 (returns −∞, signalling "no elements")
    // Correct even for all-negative arrays


// ─── Pattern 3: Monotonic Stack with Sentinel ─────────────────────────────
// Find the span of each element: how far left can you go while a[j] <= a[i]?
// Sentinel 0 pushed first ensures stack is never empty during pop.

function stock_span(prices[0..n-1]) → spans[0..n-1]:
    stack ← empty stack
    stack.push(−1)    // sentinel index: represents a virtual element at −1
                      // with value −∞, which is smaller than any real price

    for i from 0 to n-1:
        // Pop indices of elements smaller than current price
        while stack.top() ≠ −1 and prices[stack.top()] <= prices[i]:
            stack.pop()
        // Stack top is the nearest element greater than prices[i]
        // Sentinel −1 means "no such element exists to the left"
        spans[i] ← i - stack.top()
        stack.push(i)

    return spans


// ─── Pattern 4: Binary Search with Exclusive Boundary Sentinels ──────────
// Lower bound: first index where a[i] >= target.
// lo and hi are exclusive boundaries — a[lo] < target <= a[hi] invariant.

function lower_bound(a[0..n-1], target) → index:
    lo ← −1     // sentinel: a[lo] is conceptually −∞ (less than target)
    hi ← n      // sentinel: a[hi] is conceptually +∞ (≥ target)

    while lo + 1 < hi:          // loop until boundaries are adjacent
        mid ← (lo + hi) / 2
        if a[mid] < target:
            lo ← mid            // mid is in the "less than" zone
        else:
            hi ← mid            // mid is in the "≥ target" zone

    return hi   // first index where a[i] >= target; returns n if none exists
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ─────────────────────────────────────────────────────────────────────────────
// Pattern 2: Safe running maximum — handles empty arrays, all-negative arrays.
// Returns {max_val, max_idx}. Sentinel: numeric_limits<int>::min().
// ─────────────────────────────────────────────────────────────────────────────
pair<int,int> safe_max(const vector<int>& a) {
    if (a.empty()) return {INT_MIN, -1};   // sentinel pair for empty input

    int best_val = INT_MIN;   // identity sentinel for max
    int best_idx = -1;        // sentinel index: "no element seen yet"

    for (int i = 0; i < (int)a.size(); ++i) {
        if (a[i] > best_val) {
            best_val = a[i];
            best_idx = i;
        }
    }
    return {best_val, best_idx};
}

// ─────────────────────────────────────────────────────────────────────────────
// Pattern 4: lower_bound with exclusive-boundary sentinel formulation.
// Returns first index i such that a[i] >= target. Returns n if none.
// This is the invariant-based derivation — no ad-hoc lo/hi adjustments.
// ─────────────────────────────────────────────────────────────────────────────
int lower_bound_sentinel(const vector<int>& a, int target) {
    // Invariant: a[lo] < target <= a[hi]  (a[-1] = -inf, a[n] = +inf vacuously)
    int lo = -1, hi = (int)a.size();

    while (lo + 1 < hi) {
        int mid = lo + (hi - lo) / 2;   // avoids overflow vs (lo+hi)/2
        if (a[mid] < target)
            lo = mid;   // mid is in the "strictly less" zone
        else
            hi = mid;   // mid is in the "≥ target" zone
    }
    return hi;   // first index where a[hi] >= target; equals n if target > a[n-1]
}

// ─────────────────────────────────────────────────────────────────────────────
// Pattern 3: Largest Rectangle in Histogram (LeetCode 84)
// Sentinel heights of 0 pushed at both ends of the stack.
// Left sentinel ensures the stack is never empty during pop.
// Right sentinel (height=0 appended to heights) forces all remaining bars
// to be processed at the end.
// ─────────────────────────────────────────────────────────────────────────────
int largest_rectangle_histogram(vector<int> heights) {
    // Append right sentinel: height 0 forces remaining stack elements to pop.
    heights.push_back(0);
    int n = heights.size();

    stack<int> st;
    st.push(-1);       // left sentinel: index -1 acts as left boundary

    int max_area = 0;

    for (int i = 0; i < n; ++i) {
        // Pop bars taller than current — they cannot extend further right.
        while (st.top() != -1 && heights[st.top()] > heights[i]) {
            int h   = heights[st.top()]; st.pop();
            // Width: current index i is the right boundary (exclusive),
            // st.top() is the new left boundary (exclusive).
            // The sentinel at -1 makes st.top() always valid here.
            int w   = i - st.top() - 1;
            max_area = max(max_area, h * w);
        }
        st.push(i);
    }
    return max_area;
}

// ─────────────────────────────────────────────────────────────────────────────
// Pattern 3 variant: Stock Span Problem
// For each day i, find the number of consecutive preceding days where
// prices[j] <= prices[i]. Uses sentinel index -1.
// ─────────────────────────────────────────────────────────────────────────────
vector<int> stock_span(const vector<int>& prices) {
    int n = prices.size();
    vector<int> spans(n);
    stack<int> st;
    st.push(-1);    // sentinel: virtual element to the left of index 0

    for (int i = 0; i < n; ++i) {
        while (st.top() != -1 && prices[st.top()] <= prices[i])
            st.pop();
        // st.top() is the index of the nearest element greater than prices[i].
        // If st.top() == -1, the sentinel means "no such element" → span = i+1.
        spans[i] = i - st.top();
        st.push(i);
    }
    return spans;
}

// ─────────────────────────────────────────────────────────────────────────────
// Boundary condition audit: the "trap" cases
// Shows explicitly what goes wrong without sentinels.
// ─────────────────────────────────────────────────────────────────────────────
int max_subarray_buggy(const vector<int>& a) {
    // BUG: initialising with 0 instead of a[0] or INT_MIN.
    // Fails for all-negative arrays: returns 0 (empty subarray) instead of
    // the largest (least negative) element.
    int best = 0;   // ← WRONG sentinel for "max of a non-empty array"
    int cur  = 0;
    for (int x : a) {
        cur  = max(x, cur + x);
        best = max(best, cur);
    }
    return best;   // returns 0 for {-3, -1, -2} instead of -1
}

int max_subarray_correct(const vector<int>& a) {
    assert(!a.empty());
    // Correct: initialise with a[0], loop from index 1.
    // a[0] is the sentinel "best subarray seen so far = just the first element."
    int best = a[0], cur = a[0];
    for (int i = 1; i < (int)a.size(); ++i) {
        cur  = max(a[i], cur + a[i]);
        best = max(best, cur);
    }
    return best;   // returns -1 for {-3, -1, -2} ✓
}

// ─────────────────────────────────────────────────────────────────────────────
// Test driver
// ─────────────────────────────────────────────────────────────────────────────
int main() {
    // safe_max
    assert(safe_max({3, 1, 4, 1, 5, 9}) == make_pair(9, 5));
    assert(safe_max({-5, -1, -3})        == make_pair(-1, 1));
    assert(safe_max({}).first            == INT_MIN);   // empty: sentinel returned

    // lower_bound_sentinel
    vector<int> sorted = {1, 3, 3, 5, 7};
    assert(lower_bound_sentinel(sorted, 3) == 1);   // first 3
    assert(lower_bound_sentinel(sorted, 4) == 3);   // first >= 4 is index 3 (value 5)
    assert(lower_bound_sentinel(sorted, 8) == 5);   // not found: returns n
    assert(lower_bound_sentinel(sorted, 0) == 0);   // all elements qualify

    // largest_rectangle_histogram
    assert(largest_rectangle_histogram({2, 1, 5, 6, 2, 3}) == 10);
    assert(largest_rectangle_histogram({2, 4})               == 4);
    assert(largest_rectangle_histogram({1})                  == 1);

    // stock_span
    auto spans = stock_span({100, 80, 60, 70, 60, 75, 85});
    assert((spans == vector<int>{1, 1, 1, 2, 1, 4, 6}));

    // boundary condition trap
    assert(max_subarray_buggy({-3, -1, -2})  == 0);    // WRONG
    assert(max_subarray_correct({-3, -1, -2}) == -1);  // CORRECT

    cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
import math
from typing import Optional


# ─── Pattern 2: Identity-sentinel initialisation ─────────────────────────────

def safe_max(a: list[int]) -> tuple[int, int]:
    """
    Returns (max_value, max_index) using -inf as the identity sentinel.
    Correct for: empty arrays, all-negative arrays, single elements.

    The sentinel -inf satisfies: max(-inf, x) = x for all real x.
    This makes the loop body uniform — no special case for "first element."

    Time:  O(n)
    Space: O(1)
    """
    best_val = -math.inf    # identity element of max operation
    best_idx = -1           # sentinel: "no element seen yet"

    for i, x in enumerate(a):
        if x > best_val:
            best_val = x
            best_idx = i

    return int(best_val) if best_idx != -1 else (-math.inf, -1)


# ─── Pattern 4: Binary search with exclusive-boundary sentinels ───────────────

def lower_bound(a: list[int], target: int) -> int:
    """
    First index i such that a[i] >= target. Returns len(a) if none.

    Invariant: a[lo] < target <= a[hi]
      - lo = -1  is the left sentinel  (a[-1] conceptually = -inf)
      - hi = n   is the right sentinel (a[n]  conceptually = +inf)

    This invariant is established at initialisation and preserved at every step.
    The loop terminates when lo + 1 == hi (adjacent), at which point hi is
    the first index satisfying a[hi] >= target.

    The power: EVERY binary search question about the boundary
    (< vs <=, lo vs hi vs mid as return value) is answered by the invariant.
    No guessing. No off-by-one patches.

    Time:  O(log n)
    Space: O(1)
    """
    lo, hi = -1, len(a)           # exclusive sentinels

    while lo + 1 < hi:
        mid = (lo + hi) // 2
        if a[mid] < target:
            lo = mid              # mid belongs to the "< target" zone
        else:
            hi = mid              # mid belongs to the ">= target" zone

    return hi                     # first index where a[hi] >= target


def upper_bound(a: list[int], target: int) -> int:
    """
    First index i such that a[i] > target. Returns len(a) if none.

    Invariant: a[lo] <= target < a[hi]
    Same structure, comparison changes from a[mid] < target
    to a[mid] <= target.
    """
    lo, hi = -1, len(a)

    while lo + 1 < hi:
        mid = (lo + hi) // 2
        if a[mid] <= target:      # only change from lower_bound
            lo = mid
        else:
            hi = mid

    return hi


# ─── Pattern 3: Monotonic stack with sentinel index ───────────────────────────

def largest_rectangle_histogram(heights: list[int]) -> int:
    """
    Largest rectangle in histogram (LeetCode 84).

    Two sentinels:
      - Left:  index -1 pushed first onto stack. Ensures st[-1] is always
               valid when computing width, eliminating "if stack empty" check.
      - Right: height 0 appended to heights. Ensures all remaining bars are
               flushed from the stack at the end of the loop.

    Without right sentinel: need a post-loop cleanup pass — duplicate logic.
    Without left sentinel:  need "if stack else 0" in the width formula.
    Both sentinels together make the loop body uniform across all positions.

    Time:  O(n)  — each index pushed and popped at most once
    Space: O(n)  — stack
    """
    heights = heights + [0]       # right sentinel: flushes remaining bars
    stack   = [-1]                # left sentinel: virtual left boundary

    max_area = 0

    for i, h in enumerate(heights):
        while stack[-1] != -1 and heights[stack[-1]] > h:
            height = heights[stack.pop()]
            width  = i - stack[-1] - 1
            # stack[-1] is always valid: left sentinel -1 is still there.
            # When stack[-1] == -1: width = i - (-1) - 1 = i (full span).
            max_area = max(max_area, height * width)
        stack.append(i)

    return max_area


def stock_span(prices: list[int]) -> list[int]:
    """
    For each day i, number of consecutive days (including i) where
    prices[j] <= prices[i].

    Sentinel -1 on the stack represents a virtual day to the left of day 0
    with price +inf, so prices[i] - (-1) = i + 1 (full span from the start).

    Time:  O(n)
    Space: O(n)
    """
    spans = []
    stack = [-1]    # left sentinel

    for i, p in enumerate(prices):
        while stack[-1] != -1 and prices[stack[-1]] <= p:
            stack.pop()
        spans.append(i - stack[-1])
        stack.append(i)

    return spans


# ─── Boundary condition audit: the most common sentinel bug ──────────────────

def max_subarray_buggy(a: list[int]) -> int:
    """
    BUG DEMONSTRATION: initialising with 0 instead of a[0].
    Returns 0 for all-negative arrays (treating empty subarray as valid).
    """
    best = cur = 0              # WRONG: 0 is not the identity for "max of non-empty"
    for x in a:
        cur  = max(x, cur + x)
        best = max(best, cur)
    return best                 # returns 0 for [-3, -1, -2] instead of -1


def max_subarray_correct(a: list[int]) -> int:
    """
    CORRECT: initialise with a[0] as the sentinel for "best seen so far."
    a[0] is the actual identity for the recurrence on a non-empty array:
    the answer must include at least one element.

    See [[167.Maximum subarray — Kadane's algorithm and its DP interpretation]]
    """
    if not a:
        raise ValueError("Array must be non-empty.")
    best = cur = a[0]
    for x in a[1:]:
        cur  = max(x, cur + x)
        best = max(best, cur)
    return best
```

## 7. Common Variations & Extensions

### Variation 1 — Sentinel in Merge Sort

The CLRS merge step places `+∞` at the end of both subarrays being merged. This eliminates the "which subarray is exhausted?" check inside the merge loop — once all real elements are consumed, the sentinel values ensure the comparison `L[i] <= R[j]` always picks the real element from the other array. Without sentinels, the merge loop needs a post-main-loop copy for whichever subarray has remaining elements. This connects directly to [[42.Merge sort — divide and conquer, stable, O(n log n)]].

### Variation 2 — Dummy Head Node in Linked List Problems

Every linked list problem that requires inserting before the head or deleting the head node benefits from a dummy head sentinel: `dummy = ListNode(0); dummy.next = head`. All operations work on `node.next`, never on `node` itself, so the head is never a special case. The real answer is `dummy.next` after all operations complete. This pattern appears in merge k sorted lists, remove nth from end, and partition list problems. See [[153.Merge k sorted lists — min-heap of size k]].

### Variation 3 — The `±∞` Sentinel in DP Initialisation

Many DP tables are initialised with `+∞` (meaning "not yet reachable" or "infinite cost") or `-∞` (meaning "no valid assignment yet"). The sentinel propagates through the recurrence correctly: `min(∞, real_cost) = real_cost`, so the first real transition overwrites the sentinel and subsequent transitions improve on it. Using `0` instead of `∞` as the "unreachable" sentinel is a common DP bug — it implies every state is reachable at cost 0, corrupting the reachability semantics. This connects to [[169.Coin change — minimum coins and number of ways]] and [[117.Dijkstra's algorithm — O((V+E) log V) with min-heap]].

### Variation 4 — Sentinel in Floating-Point Safety

Numerical algorithms use sentinel values to handle division-by-zero and overflow. The log-sum-exp trick: instead of computing `log(exp(a) + exp(b))` directly (which overflows for large `a`, `b`), subtract `max(a, b)` first. The `max` call uses `-∞` as the identity sentinel, making it correct even when the set of values is empty. This is the foundation of numerically stable softmax in PyTorch. See [[221.Numerical stability — log-sum-exp, softmax overflow prevention]].

## 9. CP Contest Application

### Typical Problem Structure

**Codeforces Div. 2 B / C — boundary condition minefield:**

> "Given an array of n elements, for each element find the nearest element to its left that is strictly greater. If no such element exists, output -1."

This is the previous greater element problem. The naive approach handles "no element to the left" as a special case at `i = 0`. The sentinel approach pushes index `-1` (with conceptual value `+∞`) onto the stack before the loop. Now "no element to the left" is handled by the sentinel automatically: when the stack contains only index `-1`, the answer is `-1` by definition. The loop body is identical for all `i`.

**Where sentinel bugs kill contest submissions:**

1. **All-negative arrays in Kadane's** — initialising `best = 0` returns 0 instead of the correct least-negative answer. One wrong initialisation fails every all-negative test case.
2. **Binary search returning `n` vs `n-1`** — off-by-one in the boundary formulation. The invariant-based derivation with sentinels `lo = -1, hi = n` gives the unique correct return value (`hi`) without ambiguity.
3. **Histogram problem without the right-sentinel flush** — the bars remaining on the stack at the end of the loop are never processed. The answer is whatever the maximum was _before_ the rightmost tall bars, which is silently wrong.

### Optimisation Notes

**Stack with sentinel vs stack with empty check:** The sentinel approach eliminates one branch per pop operation. In Codeforces problems with n = 10⁶ and tight time limits, the difference between `if (!st.empty() && ...)` and `while (st.top() != -1 && ...)` is functionally identical in performance — the branch predictor handles both efficiently. The real win is correctness, not speed.

**`INT_MIN` / `INT_MAX` sentinel overflow:** `INT_MAX + 1` overflows to `INT_MIN` in C++. If your sentinel is `INT_MAX` and you write `sentinel + 1` anywhere in the algorithm, you have undefined behaviour. Use `LLONG_MAX` / `LLONG_MIN` when arithmetic on sentinels is possible, or use `1e18` / `-1e18` as floating-point safe sentinels for integer problems where values fit in 60 bits.
