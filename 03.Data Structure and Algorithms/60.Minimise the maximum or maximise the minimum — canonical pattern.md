## 1. Intuition First

### The Core Idea

You have a set of items to distribute — tasks to workers, paintings to museums, packages to trucks, numbers into groups. Each group accumulates a cost (sum, max element, count). You want to make the _worst group as good as possible_: minimise the heaviest load, or maximise the lightest gap.

The naive mind tries to find the optimal partition directly. This is combinatorially explosive — there are exponentially many ways to partition n items into k groups.

The insight: **flip the question**. Instead of asking "what is the optimal partition?", ask "given a fixed cost limit x, can a valid partition exist?" This feasibility question is almost always answerable greedily in O(n). And crucially, feasibility is _monotone_ in x: if you can partition with max-cost ≤ x, you can certainly do it with max-cost ≤ x+1. That monotonicity is the binary search license.

You have converted a hard combinatorial optimisation into a sequence of easy greedy checks, one per binary search step. The optimal x is the boundary between feasible and infeasible in the answer space — and you find that boundary in O(log(range)) checks.

### Why This Exists

Two problems sit at the heart of this pattern:

**Minimise the maximum** (the "bottleneck" problem): distribute n items into k groups to minimise the maximum group cost. Direct approach: try all partitions — exponential. Greedy without binary search: no clear greedy criterion exists for the minimum. With binary search: fix a budget x, greedily assign items to the current group until adding the next would exceed x, then open a new group. Count groups — if ≤ k, x is feasible.

**Maximise the minimum** (the "spread" problem): place k points among n candidates to maximise the minimum pairwise distance. Direct approach: again exponential. With binary search: fix a minimum gap d, greedily place points at the first candidate that is ≥ d away from the last placed. Count placements — if ≥ k, d is feasible.

Both reduce to the same binary search template from [[59.The binary search on answer template — monotonic predicate]]. The only difference is predicate direction and what "greedy check" means for each.

### The "Aha" Moment

The optimisation problem is hard. The _decision_ version of the same problem — "is x achievable?" — is easy. Binary search converts the hard optimisation into repeated easy decisions. This is the same transformation that makes NP-complete problems tractable when the answer is bounded: you have not solved the hard problem, you have sidestepped it by exploiting monotonicity.

Once you spot that the objective function (maximum group cost, minimum pairwise gap) is monotone across the answer space, the algorithm writes itself.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

This is one of the five most common patterns in Codeforces Div. 2 C/D and AtCoder ABC E/F. Exact phrasings to recognise:

- "minimise the maximum sum of any segment" → split array into k parts
- "maximise the minimum distance between placed elements"
- "minimum time to complete all tasks with k workers"
- "minimum largest page count when dividing a book among k readers"
- "k painters, minimise the time for the slowest painter"

The last three are all the same problem (split array into k parts, minimise max sum) in different costumes.

**Pattern signals:**

Two simultaneous signals almost always indicate this pattern:

1. You are partitioning or assigning items to groups.
2. The objective involves _max_ or _min_ of group costs, and you want to _minimise_ or _maximise_ it.

If you see both, write the binary search template before reading the rest of the problem.

**Common trap — greedy predicate direction:**

In the "minimise the maximum" predicate, you greedily pack items into the current group until adding the next exceeds the budget x, then open a new group. The trap: counting groups wrong. If the last group is never "opened" by an overflow, you must count it. Off-by-one in group counting produces wrong answers that pass some test cases.

**Second trap — answer space bounds:**

For "minimise the maximum sum of k segments":

- `lo` = `max(arr)` — a single element must fit in any segment, so the budget cannot be smaller than the largest element.
- `hi` = `sum(arr)` — putting everything in one segment costs the total sum; this is always feasible.

Getting `lo` wrong (e.g., setting it to 0 or 1) causes the loop to explore infeasible regions and return wrong answers. Always derive `lo` from problem constraints, not intuition.

**Third trap — the maximise-the-minimum rounding bug:**

As covered in [[59.The binary search on answer template — monotonic predicate]], the `bsearch_max` template requires `mid = lo + (hi - lo + 1) // 2` (round up). Forgetting this causes an infinite loop when `lo + 1 == hi` and the predicate is True for `lo`. This bug is invisible in most test cases and only manifests on specific two-element inputs.

### Machine Learning / AI

**Federated learning — minimise the maximum training time:**

In federated learning (e.g., Google's Gboard, Apple's on-device ML), a central server distributes model shards or data batches to k devices. The round completion time is determined by the _slowest_ device. To minimise wall-clock time per round, the server must partition the work to minimise the maximum load — exactly the "minimise the maximum" problem. Binary search on the maximum allowed load, greedy assignment in the predicate. This is the scheduling bottleneck problem in distributed ML.

**Data parallelism — balancing gradient computation:**

In data-parallel training (PyTorch `DistributedDataParallel`), the training step time is dominated by the slowest GPU (due to the all-reduce synchronisation barrier). If dataset shards have variable sample complexity (e.g., variable-length sequences in NLP), naive uniform splitting creates load imbalance. The optimal split minimises the maximum shard cost (measured in flops or tokens), solved by binary search on max-cost with a greedy predicate. HuggingFace's `datasets` library includes a `shard` method; understanding why uniform sharding is suboptimal — and when binary search on shard size is needed — is the ML engineer's version of this problem.

**Hyperparameter range partitioning — maximise the minimum gap:**

When designing a grid search over a log-scale hyperparameter (e.g., learning rate from 10⁻⁵ to 10⁰), you want k evaluation points spread maximally apart on the log scale. "Maximise the minimum log-distance between any two chosen points" is the spread problem exactly. The greedy predicate: given minimum gap d, can you place k points in the sorted candidate list with consecutive gaps ≥ d? This is Bayesian optimisation's discrete acquisition equivalent without the surrogate model.

**Load balancing in model serving (inference):**

Production ML inference servers (TensorRT, TorchServe, Triton) route requests to GPU replicas. If requests have variable complexity (e.g., different sequence lengths for a transformer), optimal load balancing minimises the maximum queue depth or processing time per replica. This reduces to the same partition problem with a greedy predicate.

## 3. Algorithm / Pattern

### Pattern A — Minimise the Maximum (Split / Assign)

**Problem shape:** Distribute n items into _at most_ k groups. Each group has a cost (usually sum or count). Minimise the maximum cost among all groups.

**Predicate:** `can_split(x)` — "Can we partition all items into ≤ k groups such that each group's cost ≤ x?"

**Greedy check:**

1. Initialise group count = 1, current group cost = 0.
2. For each item: if adding it exceeds x, open a new group (group count++), reset current cost to this item alone.
3. Return group count ≤ k.

**Answer space:**

- `lo = max(items)` — the largest single item must fit; no budget smaller than this is feasible.
- `hi = sum(items)` — all items in one group always fits in k ≥ 1 groups.

**Template:** `bsearch_min(lo, hi, can_split)` — find the smallest feasible x.

### Pattern B — Maximise the Minimum (Place / Spread)

**Problem shape:** Choose k positions from n sorted candidates. Maximise the minimum gap between any two chosen positions.

**Predicate:** `can_place(d)` — "Can we choose k positions from candidates with every consecutive pair ≥ d apart?"

**Greedy check:**

1. Place first element at `candidates[0]`. Count = 1.
2. For each subsequent candidate: if it is ≥ d from the last placed, place here. Count++.
3. Return count ≥ k.

**Answer space:**

- `lo = 1` — any positive gap; or the minimum possible gap in the problem.
- `hi = (candidates[-1] - candidates[0]) // (k - 1)` — perfect even spread; or simply `candidates[-1] - candidates[0]`.

**Template:** `bsearch_max(lo, hi, can_place)` — find the largest feasible d.

### Unifying View

```
MINIMISE the MAXIMUM:
  Objective ↑ as x ↑ → feasible for large x, infeasible for small x
  Predicate: FFFTTTT → use bsearch_min

MAXIMISE the MINIMUM:
  Objective ↑ as d ↑ → feasible for small d, infeasible for large d
  Predicate: TTTFFFF → use bsearch_max
```

Both are instances of [[59.The binary search on answer template — monotonic predicate]]. The only variables are which direction the predicate monotones and what the greedy check computes.

### Complexity

|Component|Cost|
|---|---|
|Binary search iterations|O(log(hi − lo))|
|Greedy predicate|O(n) or O(n log n) if sorting needed|
|**Total**|**O(n log(hi − lo))**|

For the common case (n = 10⁵, range = 10⁹): 10⁵ × 30 = 3 × 10⁶ operations. Trivially fast.

## 4. Pseudocode

```
// ─────────────────────────────────────────────────────────────
// PATTERN A: Minimise the Maximum
// Split array into at most k groups, minimise max group sum.
// ─────────────────────────────────────────────────────────────

CAN_SPLIT(arr, k, max_cost):
    groups      ← 1
    current_sum ← 0

    for each item in arr:
        if current_sum + item > max_cost:
            groups      ← groups + 1        // open a new group
            current_sum ← item              // start fresh with this item
            if groups > k:
                return False                // too many groups needed
        else:
            current_sum ← current_sum + item

    return True                             // all items fit in <= k groups


MIN_MAX_SPLIT(arr, k):
    lo ← max(arr)                           // smallest possible budget
    hi ← sum(arr)                           // largest possible budget (1 group)

    // bsearch_min: find smallest x where CAN_SPLIT(arr, k, x) = True
    while lo < hi:
        mid ← lo + (hi - lo) / 2
        if CAN_SPLIT(arr, k, mid):
            hi ← mid                        // feasible; try smaller
        else:
            lo ← mid + 1                    // infeasible; need larger budget

    return lo


// ─────────────────────────────────────────────────────────────
// PATTERN B: Maximise the Minimum
// Place k elements from sorted candidates, maximise min gap.
// ─────────────────────────────────────────────────────────────

CAN_PLACE(candidates, k, min_gap):
    count ← 1
    last  ← candidates[0]

    for i from 1 to len(candidates)-1:
        if candidates[i] - last >= min_gap:
            count ← count + 1
            last  ← candidates[i]
            if count >= k:
                return True                 // early exit

    return count >= k


MAX_MIN_PLACE(candidates, k):
    sort(candidates)
    lo ← 1
    hi ← (candidates[last] - candidates[0]) / (k - 1)  // or just candidates[last]-candidates[0]

    // bsearch_max: find largest d where CAN_PLACE(candidates, k, d) = True
    while lo < hi:
        mid ← lo + (hi - lo + 1) / 2      // round UP for max variant
        if CAN_PLACE(candidates, k, mid):
            lo ← mid                        // feasible; try larger gap
        else:
            hi ← mid - 1                    // infeasible; need smaller gap

    return lo
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <vector>
#include <numeric>
#include <algorithm>
#include <iostream>
#include <cassert>

// ─────────────────────────────────────────────────────────────
// PATTERN A — Minimise the Maximum
// ─────────────────────────────────────────────────────────────

// Predicate: can all items be split into <= k groups with each sum <= budget?
// Time: O(n)
bool canSplit(const std::vector<int>& arr, int k, long long budget) {
    int groups = 1;
    long long cur = 0;
    for (int x : arr) {
        if (x > budget) return false;   // single item exceeds budget: impossible
        if (cur + x > budget) {
            groups++;
            cur = x;
            if (groups > k) return false;
        } else {
            cur += x;
        }
    }
    return true;
}

// Split array into at most k contiguous segments, minimise max segment sum.
// Time: O(n log(sum))
long long minMaxSplit(const std::vector<int>& arr, int k) {
    long long lo = *std::max_element(arr.begin(), arr.end());
    long long hi = std::accumulate(arr.begin(), arr.end(), 0LL);

    while (lo < hi) {
        long long mid = lo + (hi - lo) / 2;
        if (canSplit(arr, k, mid)) hi = mid;
        else                       lo = mid + 1;
    }
    return lo;
}


// ─────────────────────────────────────────────────────────────
// PATTERN B — Maximise the Minimum
// ─────────────────────────────────────────────────────────────

// Predicate: can we place k elements from sorted positions with min gap >= d?
// Time: O(n)
bool canPlace(const std::vector<int>& pos, int k, int d) {
    int count = 1, last = pos[0];
    for (int i = 1; i < (int)pos.size(); i++) {
        if (pos[i] - last >= d) {
            count++;
            last = pos[i];
            if (count >= k) return true;
        }
    }
    return count >= k;
}

// Place k elements from sorted positions, maximise minimum gap.
// Time: O(n log(range))
int maxMinPlace(std::vector<int> pos, int k) {
    std::sort(pos.begin(), pos.end());
    int lo = 1;
    int hi = (pos.back() - pos.front()) / (k - 1);   // tightest upper bound

    while (lo < hi) {
        int mid = lo + (hi - lo + 1) / 2;   // round up — critical for max variant
        if (canPlace(pos, k, mid)) lo = mid;
        else                       hi = mid - 1;
    }
    return lo;
}


// ─────────────────────────────────────────────────────────────
// Problem: Painter's Partition (same as split array largest sum)
// n boards, k painters, minimise the time for the slowest painter.
// Time: O(n log(sum))
// ─────────────────────────────────────────────────────────────
long long paintersPartition(const std::vector<int>& boards, int k) {
    return minMaxSplit(boards, k);  // identical structure
}


// ─────────────────────────────────────────────────────────────
// Problem: Allocate Minimum Number of Pages (LC 1231 variant)
// Books with pages[], k students, each student reads contiguous books.
// Minimise maximum pages assigned to any student.
// Time: O(n log(sum))
// ─────────────────────────────────────────────────────────────
long long allocatePages(const std::vector<int>& pages, int k) {
    if (k > (int)pages.size()) return -1;  // more students than books: impossible
    return minMaxSplit(pages, k);
}


// ─────────────────────────────────────────────────────────────
// Problem: Kth Largest Sum in a Contiguous Subarray (LC 2099 adj.)
// Demonstrates maximise-the-minimum variant.
// ─────────────────────────────────────────────────────────────

// Problem: EKO — Woodcutters (classic "maximise the minimum" adjacent variant)
// n trees with heights h[]. Set saw height H to cut exactly >= m wood.
// Maximise H (equivalent to maximise minimum — cut as little as possible).
// Trees give max(h[i] - H, 0) wood. Find max H s.t. total >= m.
long long maxSawHeight(const std::vector<long long>& h, long long m) {
    auto canCut = [&](long long H) -> bool {
        long long wood = 0;
        for (long long hi : h) wood += std::max(0LL, hi - H);
        return wood >= m;
    };

    long long lo = 0;
    long long hi = *std::max_element(h.begin(), h.end());

    // bsearch_max: find largest H where canCut(H) = True
    while (lo < hi) {
        long long mid = lo + (hi - lo + 1) / 2;
        if (canCut(mid)) lo = mid;
        else             hi = mid - 1;
    }
    return lo;
}


int main() {
    // ── Pattern A: Minimise the Maximum ──
    // Split [7,2,5,10,8] into 2 parts → optimal: [7,2,5] and [10,8] → max=18
    assert(minMaxSplit({7, 2, 5, 10, 8}, 2) == 18);
    // Split into 3 → [7,2,5], [10], [8] → max=14 ... or [7,2,5], [10], [8]
    assert(minMaxSplit({7, 2, 5, 10, 8}, 3) == 14);
    assert(minMaxSplit({1, 2, 3, 4, 5}, 2) == 9);
    assert(minMaxSplit({1, 4, 4}, 3) == 4);

    // ── Pattern B: Maximise the Minimum ──
    // [1,2,4,8,9], k=3 → place at 1,4,9 → min gap = 3
    assert(maxMinPlace({1, 2, 8, 4, 9}, 3) == 3);
    assert(maxMinPlace({1, 2, 4, 8, 9}, 4) == 2);
    assert(maxMinPlace({0, 3, 4, 7, 10, 9}, 4) == 3);

    // ── Painter's partition ──
    assert(paintersPartition({10, 20, 30, 40}, 2) == 60);  // [10,20,30], [40]
    assert(paintersPartition({10, 20, 30, 40}, 4) == 40);

    // ── Allocate pages ──
    assert(allocatePages({12, 34, 67, 90}, 2) == 113);
    assert(allocatePages({12, 34, 67, 90}, 4) == 90);

    // ── Woodcutters ──
    assert(maxSawHeight({20, 15, 10, 17}, 7) == 15);

    std::cout << "All assertions passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
"""
Minimise the Maximum / Maximise the Minimum — Canonical Pattern
===============================================================
Both reduce to: binary search on answer + O(n) greedy predicate.

Time:  O(n log(hi - lo))
Space: O(1)  (predicate uses O(1) beyond input)
"""

from __future__ import annotations


# ─────────────────────────────────────────────────────────────
# Reusable binary search templates (from note 59)
# ─────────────────────────────────────────────────────────────

def bsearch_min(lo: int, hi: int, pred) -> int:
    """Smallest x in [lo, hi] where pred(x) is True. Shape: FFFTTTT."""
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if pred(mid): hi = mid
        else:         lo = mid + 1
    return lo

def bsearch_max(lo: int, hi: int, pred) -> int:
    """Largest x in [lo, hi] where pred(x) is True. Shape: TTTFFFF."""
    while lo < hi:
        mid = lo + (hi - lo + 1) // 2  # round up — critical
        if pred(mid): lo = mid
        else:         hi = mid - 1
    return lo


# ─────────────────────────────────────────────────────────────
# PATTERN A — Minimise the Maximum
# Split array into at most k contiguous groups; minimise max sum.
# ─────────────────────────────────────────────────────────────

def min_max_split(arr: list[int], k: int) -> int:
    """
    Split arr into at most k contiguous segments.
    Minimise the maximum segment sum.

    Predicate: can_split(budget) — greedy: pack until overflow, then new group.
    Domain: [max(arr), sum(arr)]
    """
    def can_split(budget: int) -> bool:
        groups, cur = 1, 0
        for x in arr:
            if x > budget:
                return False        # single item exceeds budget: never feasible
            if cur + x > budget:
                groups += 1
                cur = x
                if groups > k:
                    return False
            else:
                cur += x
        return True

    return bsearch_min(max(arr), sum(arr), can_split)


# ─────────────────────────────────────────────────────────────
# PATTERN B — Maximise the Minimum
# Place k points in sorted candidates; maximise min pairwise gap.
# ─────────────────────────────────────────────────────────────

def max_min_place(positions: list[int], k: int) -> int:
    """
    Choose k positions from sorted `positions`.
    Maximise the minimum gap between any two chosen positions.

    Predicate: can_place(d) — greedy: place whenever gap >= d.
    Domain: [1, (max - min) // (k-1)]
    """
    positions = sorted(positions)

    def can_place(min_gap: int) -> bool:
        count, last = 1, positions[0]
        for pos in positions[1:]:
            if pos - last >= min_gap:
                count += 1
                last = pos
                if count >= k:
                    return True
        return count >= k

    lo = 1
    hi = (positions[-1] - positions[0]) // (k - 1)
    return bsearch_max(lo, hi, can_place)


# ─────────────────────────────────────────────────────────────
# Problem: Split Array Largest Sum (LC 410)
# Same as min_max_split — different name, identical structure.
# ─────────────────────────────────────────────────────────────

def split_array_largest_sum(nums: list[int], k: int) -> int:
    return min_max_split(nums, k)


# ─────────────────────────────────────────────────────────────
# Problem: Minimum Time to Complete Trips (LC 2187)
# k buses, each with a given time per trip. Find min total time
# for ALL buses together to complete >= totalTrips trips.
#
# Predicate: can_complete(t) = sum(t // time[i] for i) >= totalTrips
# Domain: [1, min(time) * totalTrips]  (one bus doing all trips)
# ─────────────────────────────────────────────────────────────

def min_time_trips(time: list[int], total_trips: int) -> int:
    def can_complete(t: int) -> bool:
        return sum(t // ti for ti in time) >= total_trips

    lo = 1
    hi = min(time) * total_trips
    return bsearch_min(lo, hi, can_complete)


# ─────────────────────────────────────────────────────────────
# Problem: Minimum Speed to Arrive on Time (LC 1870)
# n train rides with distance d[i]. Must finish in <= hour hours.
# All but last ride take ceil(d[i]/speed) hours. Last is exact.
# Find minimum integer speed.
# ─────────────────────────────────────────────────────────────

import math

def min_speed_on_time(dist: list[float], hour: float) -> int:
    n = len(dist)
    if hour <= n - 1:   # impossible: n-1 waits of >= 1hr each
        return -1

    def can_arrive(speed: int) -> bool:
        total = sum(math.ceil(d / speed) for d in dist[:-1])
        total += dist[-1] / speed      # last leg: exact, no ceiling
        return total <= hour

    return bsearch_min(1, 10**7, can_arrive)


# ─────────────────────────────────────────────────────────────
# Problem: EKO Woodcutters — maximise saw height
# ─────────────────────────────────────────────────────────────

def max_saw_height(heights: list[int], m: int) -> int:
    """
    Set saw height H. Each tree h[i] gives max(h[i]-H, 0) wood.
    Find maximum H such that total wood >= m.
    """
    def can_cut(H: int) -> bool:
        return sum(max(0, h - H) for h in heights) >= m

    return bsearch_max(0, max(heights), can_cut)


# ─────────────────────────────────────────────────────────────
# Tests
# ─────────────────────────────────────────────────────────────

if __name__ == "__main__":
    # Pattern A
    assert min_max_split([7, 2, 5, 10, 8], 2) == 18
    assert min_max_split([7, 2, 5, 10, 8], 3) == 14
    assert min_max_split([1, 2, 3, 4, 5], 2)  == 9
    assert min_max_split([1, 4, 4], 3)         == 4

    # Pattern B
    assert max_min_place([1, 2, 8, 4, 9], 3)    == 3
    assert max_min_place([1, 2, 4, 8, 9], 4)    == 2
    assert max_min_place([0, 3, 4, 7, 10, 9], 4) == 3

    # LC 410
    assert split_array_largest_sum([7,2,5,10,8], 2) == 18

    # LC 2187
    assert min_time_trips([1, 2, 3], 5) == 3
    assert min_time_trips([2], 1)       == 2

    # LC 1870
    assert min_speed_on_time([1, 3, 2], 6)   == 1
    assert min_speed_on_time([1, 3, 2], 2.7) == 3
    assert min_speed_on_time([1, 3, 2], 1.9) == -1

    # EKO
    assert max_saw_height([20, 15, 10, 17], 7) == 15
    assert max_saw_height([4, 2, 7, 6, 1], 3)  == 4

    print("All tests passed.")
```

## 7. Common Variations & Extensions

### 7.1 Non-contiguous assignment (workers and jobs)

When items can be assigned in any order (not just contiguous segments), the greedy predicate changes: instead of packing sequentially, simulate optimal assignment by repeatedly giving each new item to the worker with the smallest current load (min-heap). Binary search on max load, predicate uses a heap. Time: O(n log n log(range)).

This variant appears when the problem says "assign tasks to workers" without "contiguous" — a subtle keyword difference that changes the predicate entirely.

### 7.2 Minimise the maximum across a 2D grid

"Minimise the maximum sum along any row (or column) after k cuts" extends Pattern A to 2D. The predicate becomes: "can we make horizontal and vertical cuts such that each subgrid has sum ≤ x?" With 2D prefix sums (from [[07.2D prefix sum — submatrix sum queries]]), checking feasibility for a fixed x takes O(mn). Total: O(mn log(sum)).

### 7.3 Binary search on answer with graph predicates

"Find the minimum bottleneck path between two nodes" — minimise the maximum edge weight on any path. Predicate: "does a path exist using only edges with weight ≤ x?" Answered by BFS/DFS in O(V + E). Total: O((V + E) log W). This is related to [[125.Kruskal's algorithm — sort edges, Union-Find]] — the minimum spanning tree gives the optimal bottleneck path between any pair.

### 7.4 Weighted variation — items have both size and value

When groups have both a capacity and a value constraint, the greedy predicate may require a knapsack-style check rather than a simple sum. The binary search shell remains identical; only the inner predicate changes. Connects to [[175.0-1 Knapsack — item taken or not]].

### 7.5 Multiple constraints — Pareto frontier

When you must simultaneously minimise the maximum AND meet a secondary constraint (e.g., "minimise max load, but worker 1 must handle at least m tasks"), the binary search remains valid if both constraints are monotone in the same direction. Add both checks inside the predicate. If constraints are in opposing directions, the problem requires a different approach (Lagrangian relaxation or parametric search).

## 9. CP Contest Application

### Recognising the problem in < 30 seconds

Scan for these three keywords in the problem statement:

```
1. "k groups / workers / segments / parts"   → partition structure
2. "minimise the maximum" OR "maximise the minimum"  → objective direction
3. "contiguous" or "any order"  → determines predicate type (sequential vs heap)
```

If 1 and 2 appear together: binary search on answer. Write the predicate, done.

### Time limit calibration for C++

|n|range|predicate|total ops|verdict|
|---|---|---|---|---|
|10⁵|10⁹|O(n)|3 × 10⁶|✓ trivial|
|10⁵|10⁹|O(n log n)|5 × 10⁷|✓ safe at 1s|
|10⁶|10⁹|O(n)|3 × 10⁷|✓ safe at 1s|
|10⁶|10⁹|O(n log n)|5 × 10⁸|⚠ borderline 2s|

### The contiguous vs non-contiguous trap in contest

"Minimise the maximum sum of k subarrays" — contiguous. Greedy: scan left-to-right, open new group on overflow. O(n).

"Minimise the maximum load assigned to k workers" — non-contiguous. Greedy with heap: assign each job to the least-loaded worker. O(n log k).

Missing this distinction produces a solution that passes the sample test cases (which are often small enough that both approaches give the same answer) but fails on large inputs. In a contest, this burns a penalty. Always check: is the partition constrained to be contiguous?

### Two-step derivation under pressure

In a contest with 45 minutes left:

1. State the predicate in one sentence: "Can we achieve [objective] ≤ x with the given constraints?"
2. Confirm monotonicity with one small example: P(small x) = F, P(large x) = T.
3. Set lo, hi from problem constraints. Use `sum(arr)` and `max(arr)` without overthinking.
4. Write `bsearch_min` or `bsearch_max`. Substitute predicate. Submit.

The entire implementation from recognition to submission should take under 15 minutes for this pattern once it is internalised.
