## 1. Intuition First

### The Core Idea

Open a physical dictionary. To find the word "interview", you don't scan every page — you navigate: open to "i", then "in", then "int", then "inte", and so on. Every step eliminates an enormous branch of possibilities. A trie is the data structure that formalises exactly this navigation.

A trie is a rooted tree where **each edge is labelled with a character** and **each node represents a prefix** — specifically, the prefix formed by concatenating all edge labels from the root to that node. The root represents the empty string. A node is marked as a _terminal_ (or _end-of-word_) node if the prefix it represents is also a complete word in the dictionary.

Three operations:

- **insert(word):** Walk from the root, one character at a time, creating nodes that don't exist yet. Mark the final node as terminal.
- **search(word):** Walk from the root following the word's characters. If you fall off the tree (a child doesn't exist), return false. If you reach the end, return true _only if_ that node is terminal.
- **startsWith(prefix):** Same as search, but don't require the final node to be terminal — any node reached means the prefix exists.

The distinction between `search` and `startsWith` is the entire semantic difference between "this exact word exists" and "some word with this prefix exists." This one-bit flag at each node is what makes tries powerful.

### Why This Exists

A [[21.HashMap frequency counting — arbitrary keys|HashMap]] can answer "does word W exist?" in O(1) average time. Why build a trie?

Because a HashMap cannot answer "does _any_ word starting with prefix P exist?" without scanning all keys — O(total characters in dictionary) in the worst case. A trie answers this in O(|P|), independent of dictionary size.

More precisely:

|Operation|HashMap|Trie|
|---|---|---|
|Insert word of length L|O(L)|O(L)|
|Exact word lookup|O(L) avg|O(L) worst|
|Prefix existence check|O(total chars)|O(L)|
|All words with prefix P|O(total chars)|O(\|P\| + output)|
|Lexicographic enumeration|O(n log n) sort|O(total chars) DFS|
|Longest prefix of query|O(L²)|O(L)|

Tries trade space for the ability to answer prefix queries in time proportional to the query length, not the dictionary size. This is the gap that motivates the structure.

### The "Aha" Moment

**Shared prefixes are stored once.** The words "inter", "internal", "interview", and "intimate" all share the prefix "int" — in a trie, those four characters exist exactly once in the tree, shared among all four words. A HashMap stores each word independently, duplicating the "int" prefix four times. This structural sharing is what gives tries their prefix-query efficiency: to answer "does any word start with 'int'?", you just check if the node for "int" exists — one lookup, not four.

This shared-prefix structure is also why tries appear everywhere in systems: they are the natural data structure for any problem where the _relationship between keys_ (specifically, their common prefixes) matters, not just the keys in isolation.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- "Given a dictionary of words and Q queries, for each query check if it's a valid word / valid prefix" — trie is the clean solution; HashMap works for exact match but not prefix.
- "Find the word in the dictionary that maximises XOR with a given number" — binary trie on bit representations, greedy descent.
- "Find the longest word in the dictionary that is a prefix of a given string" — trie walk stopping at the deepest terminal node.
- "Count words with a given prefix" — store a count at each node during insertion.
- "Auto-complete: given prefix, return all words" — DFS from the prefix endpoint.
- Bitwise XOR maximisation problems (Codeforces Div 1 B/C level): build a trie on binary representations of integers, then greedily pick the opposite bit at each level.

**Signal patterns:**

- "prefix" appears in the problem statement → trie is almost certainly involved.
- "XOR maximum/minimum of pairs" → binary trie.
- Multiple strings sharing structure + prefix queries → trie beats repeated hashing.
- Word dictionary + online queries (queries arrive one by one) → trie preprocesses once, answers each query in O(L).

**The canonical trap — confusing `search` and `startsWith`:** Failing to set or check the `is_terminal` flag. The words "in" and "interview" both exist in the trie path to "interview", but "in" is only a valid word if its node was explicitly marked terminal during insertion. Students who forget the terminal flag return true for every prefix of every inserted word, not just the words themselves.

**Second trap — not handling deletions:** Standard trie insert/search don't support deletion. Deleting "interview" requires un-marking its terminal flag and then potentially pruning the path upward if no other word shares those nodes. Forgetting this is fine for most CP problems (dictionaries are static), but important in system design contexts.

**Third trap — memory blowup:** A naive trie with `children[26]` arrays at every node uses 26 pointers per node. For a dictionary of $n$ words with average length $L$, you allocate up to $O(nL)$ nodes, each with 26 pointers → $O(26 \cdot nL)$ space. For $n = 10^5$, $L = 20$: 52 million pointer slots. This fits in memory but is cache-hostile and slow. Use a HashMap for children (`unordered_map<char, TrieNode*>`) for sparse alphabets, or a flat array-of-nodes for competitive programming.

### Machine Learning / AI

The trie is not just a textbook data structure — it is active infrastructure in modern ML systems:

**1. BPE Tokenisation (every major LLM).** Byte Pair Encoding, used in GPT-2/3/4, LLaMA, Mistral, and virtually all transformer-based models, builds a vocabulary of subword tokens. During _inference_, the tokeniser must find the longest token in the vocabulary that matches the current position in the input string. This is exactly the "longest prefix match" operation — and the HuggingFace `tokenizers` library implements it using a trie internally (their Rust implementation uses a `TrieNode` struct directly). Every forward pass of every LLM depends on a trie traversal.

**2. Constrained Decoding / Structured Generation.** Libraries like Outlines, Guidance, and LMQL enforce output constraints (JSON schema, regex, grammar) during generation. They compile the allowed token sequences into a trie of valid continuations. At each decoding step, the beam search consults the trie to mask out invalid next tokens. This is a trie-based finite automaton intersection — trie structure enables O(1) per-step constraint checking versus O(vocabulary) scanning.

**3. Autocomplete and Search Suggestion.** Every search engine, IDE, and text editor uses a trie (or a compressed variant — a DAWG or Patricia tree) for prefix-based suggestion. Google's search suggestions, VS Code's IntelliSense, and terminal tab-completion all have a trie at the core.

**4. Named Entity Recognition (NER) with Gazetteer Matching.** NLP pipelines that match against large lists of entity names (company names, drug names, place names) use Aho-Corasick automata — which are tries with failure links added — to find all dictionary matches in a text in O(n + m + output) time. spaCy's `PhraseMatcher` is implemented this way.

**5. Approximate Nearest Neighbour Search (HNSW / KD-Trees).** KD-trees partition a metric space by alternating axis cuts — each internal node is a prefix decision in a binary trie over the bit representation of coordinates. HNSW (Hierarchical Navigable Small World graphs, used in FAISS and Pinecone) uses a layered structure whose navigation logic is analogous to trie descent. Understanding tries builds intuition for why hierarchical space-partitioning enables fast ANN search.

**6. Vocabulary Indexing in Embedding Tables.** In embedding layers (`nn.Embedding` in PyTorch), the vocabulary is an integer-indexed table. The mapping from token strings to integer IDs is built once during tokenisation and often stored in a trie for fast prefix lookup during vocabulary construction (e.g., in SentencePiece).

## 3. Algorithm / Pattern

### Core Operations

**Insert(word):** Start at root. For each character `c` in word:

- If `current.children[c]` doesn't exist, create a new node.
- Move to `current.children[c]`. After all characters, mark `current.is_terminal = True`.

**Time:** O(L) where L = word length. Each character creates at most one node.

**Search(word):** Start at root. For each character `c` in word:

- If `current.children[c]` doesn't exist, return False.
- Move to `current.children[c]`. Return `current.is_terminal`.

**Time:** O(L). Returns True only if the exact word was inserted.

**StartsWith(prefix):** Identical to Search but return True at the end regardless of `is_terminal`.

**Time:** O(L). Returns True if _any_ inserted word has this prefix.

### Extended Operations

**Count words with prefix P:** Walk to the node for P (same as startsWith). Return the `count` stored at that node. Maintain this count by incrementing at every node visited during each insertion.

**All words with prefix P:** Walk to the node for P. DFS from that node, collecting all paths to terminal nodes. Time: O(|P| + output size).

**Longest prefix of query Q that exists in dictionary:** Walk Q character by character. Track the deepest terminal node encountered. Return the prefix up to that node.

**XOR maximisation (binary trie):** Insert integers as 32-bit binary strings (MSB first). For query X, greedily descend: at each bit, try to go to the child that would give a `1` in the XOR (opposite of X's current bit). If that child exists, go there; otherwise take the other child.

### Complexity Summary

|Operation|Time|Space|
|---|---|---|
|Insert word length L|O(L)|O(L) new nodes (worst case)|
|Search / startsWith|O(L)|O(1)|
|Build trie of n words, avg length L̄|O(nL̄)|O(nL̄) nodes|
|All words with prefix P|O(\|P\| + output)|O(depth) stack|
|XOR max query|O(32) = O(1)|O(32n) for n integers|

**Space derivation:** Each node has at most $|\Sigma|$ children pointers ($|\Sigma| = 26$ for lowercase English). Total nodes ≤ total characters inserted = $\sum_i |w_i|$. Each node stores $|\Sigma|$ child pointers + 1 boolean → $O(|\Sigma| \cdot \sum |w_i|)$ space. For sparse children, use a HashMap per node to reduce to $O(\sum |w_i|)$.

### When to Use vs. Avoid

**Use when:**

- You need prefix queries (not just exact match).
- The dictionary is queried many times (preprocessing cost is amortised).
- Alphabet is small and fixed (lowercase English → dense array is fine).
- You need lexicographic order (DFS gives sorted output automatically).
- XOR maximisation on integers.

**Avoid when:**

- Only exact match is needed → HashMap is simpler and uses less memory.
- Alphabet is large and sparse (e.g., Unicode) → HashMap children, or use a compressed trie.
- Memory is severely constrained → [[27.Rabin-Karp — rolling hash for pattern matching|rolling hash]] or suffix array may be more compact.
- The dictionary changes constantly with deletions → trie deletion logic is complex.

## 4. Pseudocode

```
class TrieNode:
    children: map from character → TrieNode
    is_terminal: boolean = false
    count: integer = 0         // number of words with this as prefix
    word_count: integer = 0    // number of times this exact word was inserted


class Trie:
    root: TrieNode = new TrieNode()


function INSERT(trie, word):
    node ← trie.root
    for each character c in word:
        if c not in node.children:
            node.children[c] ← new TrieNode()  // Create path if missing
        node ← node.children[c]
        node.count ← node.count + 1            // Every prefix count incremented
    node.is_terminal ← true
    node.word_count ← node.word_count + 1      // Handle duplicate inserts


function SEARCH(trie, word) → boolean:
    node ← trie.root
    for each character c in word:
        if c not in node.children:
            return false    // Path doesn't exist → word never inserted
        node ← node.children[c]
    return node.is_terminal  // Path exists but must be a complete word


function STARTS_WITH(trie, prefix) → boolean:
    node ← trie.root
    for each character c in prefix:
        if c not in node.children:
            return false
        node ← node.children[c]
    return true              // Any node reached means some word has this prefix


function COUNT_WITH_PREFIX(trie, prefix) → integer:
    node ← trie.root
    for each character c in prefix:
        if c not in node.children:
            return 0
        node ← node.children[c]
    return node.count        // Maintained during insert


function ALL_WORDS_WITH_PREFIX(trie, prefix) → list of strings:
    // Phase 1: navigate to the prefix endpoint
    node ← trie.root
    for each character c in prefix:
        if c not in node.children:
            return []
        node ← node.children[c]

    // Phase 2: DFS from the prefix node, collecting all terminal paths
    results ← []
    DFS(node, prefix, results)
    return results


function DFS(node, current_string, results):
    if node.is_terminal:
        results.append(current_string)
    for each (char c, child_node) in node.children:
        DFS(child_node, current_string + c, results)


function XOR_MAX(trie, query) → integer:
    // Trie built on 32-bit binary representations (MSB first)
    node ← trie.root
    result ← 0
    for bit from 31 downto 0:
        query_bit ← (query >> bit) & 1
        desired_bit ← 1 - query_bit   // We want the opposite bit for max XOR
        if desired_bit in node.children:
            result ← result | (1 << bit)
            node ← node.children[desired_bit]
        else:
            node ← node.children[query_bit]
    return result
```

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <array>
#include <memory>
#include <functional>

// ─────────────────────────────────────────────────────────
// Array-based TrieNode: fast for lowercase English (26 chars)
// Uses fixed array[26] for O(1) child access (cache-friendly)
// ─────────────────────────────────────────────────────────
struct TrieNode {
    std::array<TrieNode*, 26> children{};  // nullptr = no child
    bool is_terminal = false;
    int count = 0;       // words sharing this prefix
    int word_count = 0;  // times this exact word was inserted

    TrieNode() { children.fill(nullptr); }
};

class Trie {
public:
    Trie() : root_(new TrieNode()) {}

    ~Trie() { destroy(root_); }

    // Insert a word. O(L).
    void insert(const std::string& word) {
        TrieNode* node = root_;
        for (char c : word) {
            int idx = c - 'a';
            if (!node->children[idx])
                node->children[idx] = new TrieNode();
            node = node->children[idx];
            ++node->count;
        }
        node->is_terminal = true;
        ++node->word_count;
    }

    // Returns true iff word was inserted exactly. O(L).
    bool search(const std::string& word) const {
        const TrieNode* node = navigate(word);
        return node && node->is_terminal;
    }

    // Returns true iff any inserted word starts with prefix. O(L).
    bool starts_with(const std::string& prefix) const {
        return navigate(prefix) != nullptr;
    }

    // Returns number of inserted words that start with prefix. O(L).
    int count_with_prefix(const std::string& prefix) const {
        const TrieNode* node = navigate(prefix);
        return node ? node->count : 0;
    }

    // Returns all inserted words with the given prefix. O(|prefix| + output).
    std::vector<std::string> all_with_prefix(const std::string& prefix) const {
        std::vector<std::string> results;
        const TrieNode* node = navigate(prefix);
        if (!node) return results;
        std::string current = prefix;
        dfs(node, current, results);
        return results;
    }

    // Delete a word (decrements counts, prunes dead branches). O(L).
    bool erase(const std::string& word) {
        return erase_helper(root_, word, 0);
    }

private:
    TrieNode* root_;

    // Navigate to the node corresponding to the last char of s.
    // Returns nullptr if path doesn't exist.
    const TrieNode* navigate(const std::string& s) const {
        const TrieNode* node = root_;
        for (char c : s) {
            int idx = c - 'a';
            if (!node->children[idx]) return nullptr;
            node = node->children[idx];
        }
        return node;
    }

    void dfs(const TrieNode* node, std::string& current,
             std::vector<std::string>& results) const {
        if (node->is_terminal)
            results.push_back(current);
        for (int i = 0; i < 26; ++i) {
            if (node->children[i]) {
                current.push_back('a' + i);
                dfs(node->children[i], current, results);
                current.pop_back();
            }
        }
    }

    // Recursive erase: returns true if the node can be deleted (no children, not terminal)
    bool erase_helper(TrieNode* node, const std::string& word, int depth) {
        if (depth == (int)word.size()) {
            if (!node->is_terminal) return false;  // Word not in trie
            --node->word_count;
            if (node->word_count == 0) node->is_terminal = false;
            return !node->is_terminal && all_null(node);
        }
        int idx = word[depth] - 'a';
        if (!node->children[idx]) return false;  // Word not in trie
        --node->children[idx]->count;
        bool should_delete = erase_helper(node->children[idx], word, depth + 1);
        if (should_delete) {
            delete node->children[idx];
            node->children[idx] = nullptr;
        }
        return !node->is_terminal && all_null(node);
    }

    bool all_null(const TrieNode* node) const {
        for (auto* c : node->children) if (c) return false;
        return true;
    }

    void destroy(TrieNode* node) {
        if (!node) return;
        for (auto* c : node->children) destroy(c);
        delete node;
    }
};

// ─────────────────────────────────────────────────────────
// Binary Trie — XOR maximisation on integers
// For each query x, find the value in the trie that maximises x XOR value
// ─────────────────────────────────────────────────────────
struct BinaryTrieNode {
    BinaryTrieNode* children[2]{nullptr, nullptr};
    int count = 0;
};

class BinaryTrie {
    static constexpr int BITS = 30;  // Adjust for problem constraints
public:
    BinaryTrie() : root_(new BinaryTrieNode()) {}

    void insert(int val) {
        BinaryTrieNode* node = root_;
        for (int b = BITS; b >= 0; --b) {
            int bit = (val >> b) & 1;
            if (!node->children[bit])
                node->children[bit] = new BinaryTrieNode();
            node = node->children[bit];
            ++node->count;
        }
    }

    // Returns the maximum XOR of query with any value in the trie. O(BITS).
    int max_xor(int query) const {
        BinaryTrieNode* node = root_;
        int result = 0;
        for (int b = BITS; b >= 0; --b) {
            int query_bit = (query >> b) & 1;
            int desired = 1 - query_bit;   // Opposite bit maximises XOR
            if (node->children[desired]) {
                result |= (1 << b);
                node = node->children[desired];
            } else {
                node = node->children[query_bit];
            }
        }
        return result;
    }

private:
    BinaryTrieNode* root_;
};

// ─────────────────────────────────────────────────────────
// Flat array trie — competitive programming style
// Pre-allocates all nodes; avoids dynamic allocation overhead
// Fastest possible for CP (no new/delete, cache-friendly)
// ─────────────────────────────────────────────────────────
namespace FlatTrie {
    constexpr int MAXNODES = 500005;
    int children[MAXNODES][26];
    bool terminal[MAXNODES];
    int cnt[MAXNODES];     // prefix count
    int node_count = 1;    // node 0 is root

    void init() {
        node_count = 1;
        std::fill(children[0], children[0] + 26, 0);
        terminal[0] = false;
        cnt[0] = 0;
    }

    void insert(const std::string& word) {
        int node = 0;
        for (char c : word) {
            int idx = c - 'a';
            if (!children[node][idx]) {
                std::fill(children[node_count], children[node_count] + 26, 0);
                terminal[node_count] = false;
                cnt[node_count] = 0;
                children[node][idx] = node_count++;
            }
            node = children[node][idx];
            ++cnt[node];
        }
        terminal[node] = true;
    }

    bool search(const std::string& word) {
        int node = 0;
        for (char c : word) {
            int idx = c - 'a';
            if (!children[node][idx]) return false;
            node = children[node][idx];
        }
        return terminal[node];
    }

    bool starts_with(const std::string& prefix) {
        int node = 0;
        for (char c : prefix) {
            int idx = c - 'a';
            if (!children[node][idx]) return false;
            node = children[node][idx];
        }
        return true;
    }
}

    std::cout << t.search("apple")       << "\n";  // 1

    // Prefix
    std::cout << t.starts_with("app")    << "\n";  // 1

    std::cout << t.count_with_prefix("app") << "\n";  // 4 (app, apple, application, apply)

    std::cout << "\n";  // app apple application apply (lexicographic order)

    // Binary trie XOR
    BinaryTrie bt;
    bt.insert(3); bt.insert(10); bt.insert(5); bt.insert(25); bt.insert(2); bt.insert(8);
    std::cout << bt.max_xor(5) << "\n";  // 28 (5 XOR 25 = 28, the maximum)

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations
from typing import Optional
from collections import defaultdict


class TrieNode:
    """Single node in a trie. Uses a dict for children — handles any alphabet."""
    __slots__ = ('children', 'is_terminal', 'count', 'word_count')

    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.is_terminal: bool = False
        self.count: int = 0       # words sharing this as a prefix
        self.word_count: int = 0  # exact insertions of this word


class Trie:
    """
    Trie (prefix tree) supporting insert, search, startsWith, and extensions.

    All operations run in O(L) where L is the length of the input string.
    Space: O(total characters across all inserted words) — shared prefixes stored once.
    """

    def __init__(self) -> None:
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        """Insert word into the trie. O(L)."""
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
            node.count += 1
        node.is_terminal = True
        node.word_count += 1

    def search(self, word: str) -> bool:
        """Return True iff word was inserted exactly. O(L)."""
        node = self._navigate(word)
        return node is not None and node.is_terminal

    def starts_with(self, prefix: str) -> bool:
        """Return True iff any inserted word starts with prefix. O(L)."""
        return self._navigate(prefix) is not None

    def count_with_prefix(self, prefix: str) -> int:
        """Return number of inserted words that start with prefix. O(L)."""
        node = self._navigate(prefix)
        return node.count if node else 0

    def all_with_prefix(self, prefix: str) -> list[str]:
        """
        Return all inserted words with the given prefix, in lexicographic order.
        Time: O(|prefix| + total chars in output).
        """
        node = self._navigate(prefix)
        if node is None:
            return []
        results: list[str] = []
        self._dfs(node, list(prefix), results)
        return results

    def erase(self, word: str) -> bool:
        """
        Remove one occurrence of word. Returns True if the word existed.
        Prunes now-empty branches upward. O(L).
        """
        return self._erase(self.root, word, 0)

    def longest_prefix_of(self, query: str) -> str:
        """
        Return the longest prefix of query that exists as a complete word
        in the trie. Returns '' if no prefix word exists. O(L).

        Example use: longest matching token in tokenisation.
        """
        node = self.root
        last_terminal_depth = -1
        for i, ch in enumerate(query):
            if ch not in node.children:
                break
            node = node.children[ch]
            if node.is_terminal:
                last_terminal_depth = i + 1
        return query[:last_terminal_depth] if last_terminal_depth >= 0 else ''

    # ── Private helpers ──────────────────────────────────────────

    def _navigate(self, s: str) -> Optional[TrieNode]:
        """Walk the trie following s. Returns final node or None if path missing."""
        node = self.root
        for ch in s:
            if ch not in node.children:
                return None
            node = node.children[ch]
        return node

    def _dfs(self, node: TrieNode, path: list[str], results: list[str]) -> None:
        if node.is_terminal:
            results.append(''.join(path))
        for ch in sorted(node.children):  # sorted → lexicographic order
            path.append(ch)
            self._dfs(node.children[ch], path, results)
            path.pop()

    def _erase(self, node: TrieNode, word: str, depth: int) -> bool:
        if depth == len(word):
            if not node.is_terminal:
                return False  # Word not in trie
            node.word_count -= 1
            if node.word_count == 0:
                node.is_terminal = False
            return True
        ch = word[depth]
        if ch not in node.children:
            return False
        child = node.children[ch]
        child.count -= 1
        found = self._erase(child, word, depth + 1)
        if found and child.count == 0 and not child.is_terminal:
            del node.children[ch]  # Prune dead branch
        return found

class BinaryTrie:
    """
    Trie over binary representations of integers.
    Supports: insert, max_xor(query).

    Classic application: given array A, find max(A[i] XOR A[j]).
    Insert all elements, then for each A[i] query max_xor(A[i]).

    Time: O(BITS) per operation. Space: O(n * BITS).
    """
    BITS = 30  # Handles integers up to 2^31 - 1; adjust as needed

    def __init__(self) -> None:
        self.root = TrieNode()

    def insert(self, val: int) -> None:
        node = self.root
        for b in range(self.BITS, -1, -1):
            bit = (val >> b) & 1
            key = str(bit)
            if key not in node.children:
                node.children[key] = TrieNode()
            node = node.children[key]

    def max_xor(self, query: int) -> int:
        """Return maximum XOR of query with any value in the trie. O(BITS)."""
        node = self.root
        result = 0
        for b in range(self.BITS, -1, -1):
            query_bit = (query >> b) & 1
            desired = str(1 - query_bit)   # Opposite bit gives XOR bit = 1
            if desired in node.children:
                result |= (1 << b)
                node = node.children[desired]
            else:
                node = node.children[str(query_bit)]
        return result


# ─────────────────────────────────────────────────────────
# Tests
# ─────────────────────────────────────────────────────────
if __name__ == "__main__":
    t = Trie()
    for word in ["apple", "app", "application", "apply", "banana"]:
        t.insert(word)

    # Exact search
    assert t.search("app")          == True
    assert t.search("ap")           == False  # "ap" was never inserted
    assert t.search("apple")        == True
    assert t.search("application")  == True
    assert t.search("appl")         == False  # prefix only, not a word

    # Prefix
    assert t.starts_with("app")     == True
    assert t.starts_with("ban")     == True
    assert t.starts_with("cat")     == False

    # Count
    assert t.count_with_prefix("app") == 4   # app, apple, application, apply
    assert t.count_with_prefix("ban") == 1

    # All with prefix — lexicographic
    assert t.all_with_prefix("app") == ["app", "apple", "application", "apply"]
    assert t.all_with_prefix("cat") == []

    # Longest prefix
    assert t.longest_prefix_of("applesauce") == "apple"
    assert t.longest_prefix_of("application_xyz") == "application"
    assert t.longest_prefix_of("xyz") == ""

    # Erase
    t.erase("app")
    assert t.search("app")          == False
    assert t.starts_with("app")     == True   # "apple", "apply" still exist
    assert t.count_with_prefix("app") == 3

    # Binary trie XOR
    bt = BinaryTrie()
    for v in [3, 10, 5, 25, 2, 8]:
        bt.insert(v)
    assert bt.max_xor(5) == 28    # 5 XOR 25 = 11101 = 28

    print("All tests passed.")
```

### Trie Structure After Inserting {"app", "apple", "apply", "banana"}

```
                    root
                   /    \
                 'a'    'b'
                  |      |
                 [a]    [a]
                  |      |
                 'p'    'n'
                  |      |
                 [p]    [a]

                  |      |
               [p]✓     [a]
              /    \      |
            'l'   'y'    'n'
             |      |     |
            [l]   [y]✓  [a]
             |           |

             |
           [e]✓

Legend: [x] = node storing char x,  ✓ = is_terminal = True
```

Every path from root to a `✓` node spells out exactly one inserted word. The path root→[a]→[p]→[p] is shared by all three "app*" words — this is the structural sharing that makes tries efficient.

### The `search` vs `startsWith` Distinction

```
Query: search("ap")

root → 'a' → [a] → 'p' → [p]
                            |
                      is_terminal? NO → return FALSE

Query: starts_with("ap")

root → 'a' → [a] → 'p' → [p]
                            |
                      node exists? YES → return TRUE

Query: search("app")

root → 'a' → [a] → 'p' → [p] → 'p' → [p]✓
                                         |
                                   is_terminal? YES → return TRUE

The node [p] at depth 2 and [p]✓ at depth 3 are DIFFERENT nodes.
"ap" ends at depth 2 (non-terminal). "app" ends at depth 3 (terminal).
This is why a single is_terminal flag per node handles both operations.
```

### Binary Trie — XOR Maximisation

```
Insert: 5 (101), 3 (011), 6 (110)   (using 3 bits for clarity)

             root
            /    \
           0      1           ← bit 2
          / \    / \
         1   -  1   0         ← bit 1
         |      |    \
         1      0     1       ← bit 0
        (3)    (6)   (5)
        011    110   101

Query: max XOR with 5 (101)

Bit 2: query_bit=1, desired=0.  child[0] exists → go left, result |= 4
Bit 1: query_bit=0, desired=1.  child[1] exists → go right, result |= 2
Bit 0: query_bit=1, desired=0.  child[0] exists → go down, result |= 1

result = 4 + 2 + 1 = 7.   Check: 5 XOR 2 (010)? No. 5 XOR 3 (011) = 110 = 6.
                                   5 XOR 6 (110) = 011 = 3. Hmm.
Actually: path followed = 0→1→0 = 010 = 2. 5 XOR 2 = 7. ✓

KEY INSIGHT: At every bit position, you GREEDILY choose the opposite bit if it
exists. Greedy works here because a 1 in bit position k contributes 2^k to XOR,
which always outweighs any combination of lower bits (2^k > sum_{i<k} 2^i).
This greedy-on-trie pattern is optimal — no backtracking needed.
```

## 7. Common Variations & Extensions

### 7.1 Compressed Trie (Patricia Tree / Radix Tree)

A standard trie wastes nodes on long chains where each internal node has exactly one child. A compressed trie merges these chains: each edge stores a _substring_, not a single character. A chain `a→p→p→l→e` becomes a single edge labelled `"apple"`. Space drops from O(total characters) to O(number of words). Used in Linux kernel routing tables (radix trees for IP prefix matching) and in some tokeniser implementations. The trade-off: insertion and search logic becomes more complex (you must split edges when a new word diverges mid-edge).

### 7.2 DAWG (Directed Acyclic Word Graph)

A DAWG is the minimal automaton accepting exactly the inserted words — it merges not just common prefixes (like a trie) but also common _suffixes_. If a trie is a tree, a DAWG is a DAG. A trie for {"test", "testing", "tested"} has separate paths for the suffix "ed" and "ing". A DAWG shares suffix nodes wherever possible. DAWGs are used in spell-checkers and dictionary compression. The construction algorithm (Daciuk's algorithm) is O(n) for sorted inputs.

### 7.3 Aho-Corasick Automaton

Add **failure links** to a trie: for each node, the failure link points to the longest proper suffix of the current prefix that is also a prefix in the trie. With failure links, you can search for all $k$ pattern occurrences simultaneously in text $T$ in O(|T| + total output) — the same guarantee as KMP for single patterns, extended to multi-pattern. spaCy's `PhraseMatcher`, grep's multi-pattern mode, and antivirus signature matching all use Aho-Corasick. This is the direct generalisation of both [[26.KMP algorithm — failure function and O(n+m) matching]] and tries.

### 7.4 Trie for Bitmasked DP / Set Membership

In bitmask DP (see [[105.Bitmask DP — state compression]]), you sometimes need to query: "does any previously seen bitmask agree with the current mask on certain bits?" A binary trie over the bits of the mask enables this in O(32) per query, far faster than scanning all seen masks. This technique appears in competitive programming problems involving XOR bases (linear algebra over GF(2)) where you maintain a basis of vectors in a binary trie structure.

## 9. CP Contest Application

### Typical Problem Structures

**1. "Dictionary + Q prefix queries" (Codeforces Div 2 B/C):** Insert all dictionary words, answer each query with `starts_with` or `count_with_prefix`. O((N + Q) × L̄). The challenge is often in recognising that prefix queries cannot be answered with a plain HashMap.

**2. "Maximum XOR pair in array" (Div 1 B, classic):** Build a binary trie of all array elements, then for each element query `max_xor`. Total O(n × BITS). This is LC 421 and appears frequently in Indian competitive programming circuits. The greedy argument (higher bits dominate) is the key insight to justify why greedy trie descent works.

**3. "Shortest unique prefix for each word" (Div 2 D):** Insert all words, storing counts at each node. For each word, walk until you reach a node with `count == 1` — that's the shortest prefix unique to this word. The trie makes this O(total chars) total.

**4. "Number of distinct substrings" (Div 1 C/D):** Insert all suffixes of a string into a trie. The number of nodes (excluding root) equals the number of distinct substrings. This is O(n²) space in the worst case — a suffix array (see [[30.Suffix array — construction and LCP array]]) is strictly better for this, but the trie approach is simpler to implement under time pressure.

### Time Limit Considerations

For $n$ words of average length $L$, trie construction is O(nL). For $n = 10^5$, $L = 20$: 2 million character operations — trivially fast. The bottleneck is usually memory allocation for dynamic nodes. The flat array trie (shown in the C++ implementation) eliminates `new`/`delete` overhead entirely and is 3–5× faster than pointer-based approaches in practice. Pre-allocate $n \times L_{\max}$ nodes (e.g., `MAXNODES = 2 \times 10^6$) and index by integer. This is the standard CP trie pattern for problems with tight time limits.

For binary tries on integers: BITS = 30 handles all values up to $10^9$. BITS = 19 for values up to $5 \times 10^5$. Always set BITS to the minimum needed — it directly controls both time and memory per operation.
