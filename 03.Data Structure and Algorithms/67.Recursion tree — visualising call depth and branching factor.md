## 1. Intuition First

### The Core Idea

A recursive function is a function that calls itself. That description is mechanically accurate but intellectually useless — it tells you what recursion _is_, not what it _does_ or why it costs what it costs.

The recursion tree gives you the geometric reality. Every time a function calls itself, draw a child node. The original call is the root. Each self-call spawns children. When the base case fires and the function returns without calling itself again, that node is a leaf. The resulting tree is the complete execution transcript of the algorithm.

Two numbers characterise any recursion tree, and between them they determine the total cost:

- **Branching factor `b`:** How many recursive calls does one invocation make? A function that calls itself twice has branching factor 2. One that calls itself three times: branching factor 3.
- **Depth `d`:** How many levels deep does the tree go before hitting a base case?

From these two numbers, the tree's structure is determined: it has `b^d` leaves (approximately), and the total number of nodes is `(b^(d+1) - 1) / (b - 1)` — a geometric series. Every complexity analysis of a recursive algorithm is, at its core, a count of nodes in this tree, weighted by the cost of the work done at each node.

### Why This Exists

The alternative to the recursion tree is "staring at the recurrence and hoping intuition kicks in." That works for simple cases — `T(n) = T(n-1) + O(1)` is obviously `O(n)`. But it fails the moment the recurrence is non-trivial:

- `T(n) = 2T(n/2) + O(n)` — merge sort. What is this?
- `T(n) = 2T(n/2) + O(n²)` — is the root-level work now dominant?
- `T(n) = 3T(n/3) + O(n log n)` — and this?

Without the tree, you are guessing. With the tree, you are reading off a geometric sum. The recurrence becomes a picture, and the picture has an answer.

The Master Theorem (the mechanical shortcut) works precisely because it is a compressed description of what the recursion tree always looks like. Understanding the tree _first_ makes the Master Theorem a memorable summary rather than a formula to memorise.

### The "Aha" Moment

The total cost of a recursive algorithm is the sum of work done at every node in its recursion tree. The shape of that sum — whether it is dominated by the root, evenly spread across levels, or dominated by the leaves — is the entire story of recursive complexity.

Once you can draw the tree and label each node with the work done there, the complexity analysis reduces to summing a geometric series. There is no further mystery.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When does the recursion tree appear in contests?**

Almost every non-trivial recursive function you write in a contest has a recursion tree hiding its complexity. The three highest-stakes situations:

1. **Backtracking:** A backtracking function that generates all subsets has branching factor 2 and depth `n` — giving `2^n` leaf nodes. A function generating all permutations has branching factor that decreases from `n` to 1 — giving `n!` leaves. Before submitting a backtracking solution, sketch the tree: if the leaf count at maximum input exceeds ~10^7, it will TLE.
    
2. **Divide and conquer:** Merge sort, quicksort, binary search on answer — all have recursion trees. Recognising that merge sort's tree has `log n` levels, each doing `O(n)` work, immediately gives `O(n log n)`. The tree makes this one-second reasoning rather than three-minute derivation.
    
3. **DP optimisation:** When you switch from naive recursion to memoisation (see [[70.Memoisation — converting naive recursion to top-down DP]]), you are collapsing the recursion tree — nodes that would be duplicated are computed once. The number of _unique_ nodes in the tree (after collapsing) is the time complexity of the memoised version. Without the tree picture, it is unclear what "unique subproblems" means concretely.
    

**Pattern signal:** When you see a recursion and need its complexity, ask: what is `b`? What is `d`? Is work at each node constant, `O(n)`, or `O(n log n)`? Draw two or three levels of the tree. The pattern becomes obvious.

**Common trap that kills submissions:** A function with branching factor 2 and depth 20 has `2^20 ≈ 10^6` leaves — fine. With depth 40: `2^40 ≈ 10^12` — instant TLE. The recursion tree makes this visible before you run a single test case. Contestants who do not think in trees submit exponential solutions to problems that require polynomial ones.

### Machine Learning / AI

**Computation graph as recursion tree:**

The backpropagation algorithm in neural networks is a traversal of a computation graph — which is structurally a directed acyclic graph (DAG) that _looks like_ a recursion tree for feed-forward networks. Each layer is a level of the tree. The forward pass is a top-down traversal (root to leaves); the backward pass (gradient computation) is a bottom-up traversal (leaves to root). See [[215.Gradient computation as a graph traversal — autograd intuition]].

Understanding the recursion tree makes the structure of autograd frameworks (PyTorch, JAX) legible: the `backward()` call walks a tree of operations accumulated during the forward pass, applying the chain rule at each node. The "branching factor" at each node is the number of inputs to that operation (for addition: 2; for a matrix multiply: 2; for a softmax: 1). The "depth" is the number of layers. Gradient flow problems (vanishing/exploding gradients) are pathologies of the tree: signals decay or amplify exponentially with depth — exactly what the recursion tree predicts for `b > 1` or `b < 1` at each level.

**Decision tree learning:**

The CART algorithm (see [[158.Decision tree structure — how CART maps to a binary tree]]) builds a binary recursion tree explicitly. Each `fit()` call on a node recursively calls `fit()` on two children (left and right splits). The branching factor is 2. The depth is controlled by the `max_depth` hyperparameter. The total number of nodes is `2^(max_depth+1) - 1`. Overfitting in decision trees is literally an overly deep recursion tree with too many leaves (each memorising a single training point). Pruning is reducing the depth.

**Recursive neural architectures:**

TreeLSTMs (Tai et al., 2015) process sentences according to their parse tree structure. The recursion tree _is_ the model architecture. The branching factor is the syntactic branching factor of the sentence. Understanding how depth and branching factor affect gradient flow in a recursion tree directly explains why TreeLSTMs are harder to train on deeply nested syntax than on flat structures.

## 3. Algorithm / Pattern

### Reading a Recurrence as a Tree

Given a recurrence `T(n) = a · T(n/b) + f(n)`:

- **`a`** = branching factor (number of recursive calls per invocation)
- **`n/b`** = problem size at the next level (how fast the input shrinks)
- **`f(n)`** = work done at the current node outside of recursive calls
- **Depth** = `log_b(n)` (how many levels until `n/b^d = 1`)

**Level-by-level analysis:**

|Level|# Nodes|Problem size per node|Work per node|Total work at level|
|---|---|---|---|---|
|0 (root)|1|`n`|`f(n)`|`f(n)`|
|1|`a`|`n/b`|`f(n/b)`|`a · f(n/b)`|
|2|`a²`|`n/b²`|`f(n/b²)`|`a² · f(n/b²)`|
|…|…|…|…|…|
|`k`|`a^k`|`n/b^k`|`f(n/b^k)`|`a^k · f(n/b^k)`|
|`log_b(n)` (leaves)|`a^(log_b(n))` = `n^(log_b(a))`|1|`O(1)`|`Θ(n^(log_b(a)))`|

**Total cost = sum over all levels.** The sum is a geometric series with ratio `r = a · f(n/b) / f(n)`. Three cases:

```
r < 1  (ratio decreasing): series converges → root dominates → T(n) = Θ(f(n))
r = 1  (ratio constant):   each level equal cost → log levels → T(n) = Θ(f(n) · log n)
r > 1  (ratio increasing): leaves dominate → T(n) = Θ(n^(log_b a))
```

This is the Master Theorem — but derived from the tree, not memorised as a formula.

**Decision tree for complexity analysis:**

```
Given T(n) = a·T(n/b) + f(n):

Step 1: Compute n^(log_b a)  — this is the "leaf work" term
Step 2: Compare f(n) to n^(log_b a):

  f(n) = O(n^(log_b a - ε))  for some ε > 0?
  → Leaves dominate → T(n) = Θ(n^(log_b a))
  
  f(n) = Θ(n^(log_b a))?
  → All levels equal → T(n) = Θ(n^(log_b a) · log n)
  
  f(n) = Ω(n^(log_b a + ε))  for some ε > 0?
  → Root dominates → T(n) = Θ(f(n))

For cases not fitting Master Theorem (e.g., T(n) = 2T(n-1) + O(1)):
  Draw the tree. Count nodes directly.
```

**When to use each complexity derivation method:**

|Situation|Method|
|---|---|
|`T(n) = aT(n/b) + f(n)` form|Master Theorem (check 3 cases)|
|Non-standard recurrence|Draw the tree, count nodes|
|Overlapping subproblems exist|Count _unique_ nodes after memoisation|
|Backtracking / combinatorial|Count leaves (= output size), not internal nodes|

## 4. Pseudocode

```
ANALYSE_RECURSION_TREE(recurrence T, input_size n):
    """
    Systematic procedure for deriving complexity from a recursion tree.
    Not an algorithm to implement — a mental procedure to execute on paper.
    """
    
    // Step 1: Extract the parameters
    a = branching_factor(T)       // How many recursive calls per invocation?
    b = reduction_factor(T)       // How much does input shrink per level? (n → n/b)
    f = per_node_work(T)          // Work at each node outside recursive calls?
    
    // Step 2: Compute tree dimensions
    depth     = log_b(n)                  // Levels from root to leaf
    leaf_count = a^(log_b n) = n^(log_b a)  // Number of leaves
    
    // Step 3: Compute work per level k (0-indexed from root)
    //   nodes_at_level(k) = a^k
    //   size_per_node(k)  = n / b^k
    //   work_per_node(k)  = f(n / b^k)
    //   total_at_level(k) = a^k * f(n / b^k)
    
    // Step 4: Sum over all levels
    //   total = Σ_{k=0}^{log_b n} a^k * f(n / b^k)
    //   This is a geometric series. Find the ratio r = a * f(n/b) / f(n).
    
    if r < 1:
        return Θ(f(n))                   // Root level dominates
    elif r == 1:
        return Θ(f(n) * log_b(n))        // All levels equal (log levels × f(n) each)
    else:  // r > 1
        return Θ(n^(log_b a))            // Leaf level dominates

    // Step 5 (sanity check): verify by substitution
    //   Substitute your answer back into the recurrence.
    //   T(n) = a * T(n/b) + f(n) should be consistent.


RECURSION_TREE_FOR_BACKTRACKING(n, branching_factor b, pruning_fraction p):
    """
    For backtracking: the "recursion tree" is the search tree.
    Pruning reduces effective branching factor from b to b*(1-p).
    Without pruning: O(b^n) nodes.
    With pruning fraction p at each level: O((b*(1-p))^n) nodes.
    Even small p dramatically reduces the tree.
    """
    effective_b = b * (1 - p)
    
    if effective_b < 1:
        return POLYNOMIAL   // Tree collapses; rare in practice
    else:
        return Θ(effective_b^n)  // Still exponential, but smaller base
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <functional>
#include <cmath>
#include <cassert>

/**
 * RecursionTreeAnalyser
 *
 * Instruments a recursive function to:
 *   1. Count total nodes visited (total calls made)
 *   2. Track depth reached
 *   3. Count leaf nodes (base case hits)
 *   4. Print the tree structure for small inputs
 *
 * Use this to verify your theoretical analysis against empirical counts.
 * The ratio nodes(n) / nodes(n/2) should converge to the branching factor.
 */
struct RecursionStats {
    long long total_calls = 0;
    long long leaf_calls  = 0;
    int       max_depth   = 0;

    void reset() { total_calls = 0; leaf_calls = 0; max_depth = 0; }

    void print() const {
        std::cout << "Total calls (nodes): " << total_calls  << "\n";
        std::cout << "Leaf calls:          " << leaf_calls   << "\n";
        std::cout << "Max depth reached:   " << max_depth    << "\n";
        std::cout << "Internal nodes:      " << total_calls - leaf_calls << "\n";
    }
};


// ─────────────────────────────────────────────────────────────────
// Example 1: Fibonacci — T(n) = T(n-1) + T(n-2) + O(1)
// Branching factor ≈ 2, depth = n → O(φ^n) where φ = (1+√5)/2
// The tree VISIBLY shows why naive fib is exponential.
// ─────────────────────────────────────────────────────────────────

long long fib_naive(int n, RecursionStats& stats, int depth = 0) {
    stats.total_calls++;
    stats.max_depth = std::max(stats.max_depth, depth);

    if (n <= 1) {
        stats.leaf_calls++;
        return n;
    }
    return fib_naive(n - 1, stats, depth + 1)
         + fib_naive(n - 2, stats, depth + 1);
}

// With memoisation: unique nodes = O(n), because the tree collapses.
// The recursion tree becomes a DAG — each unique (n) computed once.
long long fib_memo(int n, std::vector<long long>& memo,
                   RecursionStats& stats, int depth = 0) {
    stats.total_calls++;
    stats.max_depth = std::max(stats.max_depth, depth);

    if (n <= 1) { stats.leaf_calls++; return n; }
    if (memo[n] != -1) {
        stats.leaf_calls++;   // Cache hit — acts like a leaf (no further recursion)
        return memo[n];
    }
    memo[n] = fib_memo(n - 1, memo, stats, depth + 1)
            + fib_memo(n - 2, memo, stats, depth + 1);
    return memo[n];
}


// ─────────────────────────────────────────────────────────────────
// Example 2: Merge sort — T(n) = 2T(n/2) + O(n)
// Branching factor 2, depth log₂(n), O(n) work per node per level
// Total: O(n log n). The tree PROVES this — each level does O(n) work total.
// ─────────────────────────────────────────────────────────────────

void merge_sort(std::vector<int>& arr, int lo, int hi,
                RecursionStats& stats, int depth = 0) {
    stats.total_calls++;
    stats.max_depth = std::max(stats.max_depth, depth);

    if (lo >= hi) {
        stats.leaf_calls++;
        return;
    }

    int mid = lo + (hi - lo) / 2;
    merge_sort(arr, lo, mid,     stats, depth + 1);   // Left child
    merge_sort(arr, mid + 1, hi, stats, depth + 1);   // Right child

    // O(n) merge step — this is the f(n) term at this node
    std::vector<int> tmp;
    int l = lo, r = mid + 1;
    while (l <= mid && r <= hi)
        tmp.push_back(arr[l] <= arr[r] ? arr[l++] : arr[r++]);
    while (l <= mid) tmp.push_back(arr[l++]);
    while (r <= hi)  tmp.push_back(arr[r++]);
    for (int i = lo; i <= hi; ++i) arr[i] = tmp[i - lo];
}


// ─────────────────────────────────────────────────────────────────
// Example 3: Powerset generation — T(n) = 2T(n-1) + O(1)
// Branching factor 2, depth n → O(2^n) leaves (one per subset)
// ─────────────────────────────────────────────────────────────────

void generate_subsets(const std::vector<int>& nums, int idx,
                      std::vector<int>& current,
                      std::vector<std::vector<int>>& result,
                      RecursionStats& stats, int depth = 0) {
    stats.total_calls++;
    stats.max_depth = std::max(stats.max_depth, depth);

    if (idx == static_cast<int>(nums.size())) {
        stats.leaf_calls++;
        result.push_back(current);
        return;
    }
    // Branch 1: exclude nums[idx]
    generate_subsets(nums, idx + 1, current, result, stats, depth + 1);

    // Branch 2: include nums[idx]
    current.push_back(nums[idx]);
    generate_subsets(nums, idx + 1, current, result, stats, depth + 1);
    current.pop_back();
}


// ─────────────────────────────────────────────────────────────────
// Tree printer: shows the actual recursion tree for small n
// ─────────────────────────────────────────────────────────────────

void print_fib_tree(int n, int depth = 0) {
    std::string indent(depth * 3, ' ');
    std::cout << indent << "fib(" << n << ")\n";
    if (n <= 1) return;
    print_fib_tree(n - 1, depth + 1);
    print_fib_tree(n - 2, depth + 1);
}


// ─────────────────────────────────────────────────────────────────
// Master Theorem calculator
// ─────────────────────────────────────────────────────────────────

enum class Case { LEAVES_DOMINATE, ALL_EQUAL, ROOT_DOMINATES, IRREGULAR };

struct MasterResult {
    Case   which_case;
    double exponent;       // log_b(a) — the "leaf exponent"
    std::string complexity;
};

MasterResult master_theorem(int a, int b, double f_exponent) {
    // T(n) = a·T(n/b) + Θ(n^f_exponent)
    // leaf_exponent = log_b(a)
    assert(a >= 1 && b > 1);

    double leaf_exp = std::log(a) / std::log(b);
    double eps = 1e-9;

    MasterResult res;
    res.exponent = leaf_exp;

    if (f_exponent < leaf_exp - eps) {
        res.which_case  = Case::LEAVES_DOMINATE;
        res.complexity  = "Θ(n^" + std::to_string(leaf_exp) + ")";
    } else if (std::abs(f_exponent - leaf_exp) <= eps) {
        res.which_case  = Case::ALL_EQUAL;
        res.complexity  = "Θ(n^" + std::to_string(leaf_exp) + " · log n)";
    } else {
        res.which_case  = Case::ROOT_DOMINATES;
        res.complexity  = "Θ(n^" + std::to_string(f_exponent) + ")";
    }
    return res;
}


int main() {
    // ── Demo 1: Fibonacci tree statistics ──
    std::cout << "=== Fibonacci Recursion Tree ===\n";
    std::cout << "Structure (n=5):\n";
    print_fib_tree(5);
    std::cout << "\n";

    for (int n : {5, 10, 15, 20}) {
        RecursionStats stats;
        fib_naive(n, stats);
        std::cout << "fib_naive(" << n << "): ";
        stats.print();
        std::cout << "  Theoretical leaf count: " << std::round(std::pow(1.618, n))
                  << " (φ^n)\n\n";
    }

    // ── Demo 2: Memoisation collapses the tree ──
    std::cout << "=== Memoised Fibonacci (tree collapsed to DAG) ===\n";
    for (int n : {5, 10, 15, 20}) {
        RecursionStats stats;
        std::vector<long long> memo(n + 1, -1);
        fib_memo(n, memo, stats);
        std::cout << "fib_memo(" << n << "): total_calls=" << stats.total_calls
                  << " (vs naive: ~" << static_cast<long long>(std::pow(1.618, n))
                  << ")\n";
    }
    std::cout << "\n";

    // ── Demo 3: Merge sort tree ──
    std::cout << "=== Merge Sort Recursion Tree ===\n";
    for (int n : {8, 16, 32, 64}) {
        std::vector<int> arr(n);
        for (int i = 0; i < n; ++i) arr[i] = n - i;
        RecursionStats stats;
        merge_sort(arr, 0, n - 1, stats);
        std::cout << "merge_sort(n=" << n << "): total_nodes=" << stats.total_calls
                  << ", depth=" << stats.max_depth
                  << ", theoretical_depth=" << static_cast<int>(std::log2(n)) << "\n";
    }
    std::cout << "\n";

    // ── Demo 4: Powerset (2^n leaves) ──
    std::cout << "=== Powerset Recursion Tree ===\n";
    for (int n : {3, 4, 5, 6}) {
        std::vector<int> nums(n);
        std::iota(nums.begin(), nums.end(), 1);
        std::vector<int> current;
        std::vector<std::vector<int>> result;
        RecursionStats stats;
        generate_subsets(nums, 0, current, result, stats);
        std::cout << "subsets(n=" << n << "): leaves=" << stats.leaf_calls
                  << " (=2^" << n << "=" << (1 << n) << ")"
                  << ", total_nodes=" << stats.total_calls
                  << " (=2^(n+1)-1=" << ((1 << (n + 1)) - 1) << ")\n";
    }
    std::cout << "\n";

    // ── Demo 5: Master Theorem ──
    std::cout << "=== Master Theorem Calculator ===\n";
    struct TestCase { int a, b; double f_exp; std::string name; };
    std::vector<TestCase> tests = {
        {2, 2, 1.0,  "Merge sort:      T(n)=2T(n/2)+O(n)"},
        {1, 2, 0.0,  "Binary search:   T(n)=T(n/2)+O(1)"},
        {4, 2, 1.0,  "Strassen-like:   T(n)=4T(n/2)+O(n)"},
        {2, 2, 2.0,  "Root dominates:  T(n)=2T(n/2)+O(n²)"},
```

### Python (Readable + Pythonic)

```python
"""
Recursion Tree — Visualising Call Depth and Branching Factor
Topic 67, Tier T1

The recursion tree is the geometric picture of a recursive algorithm.
Two numbers determine everything: branching factor b and depth d.
Total nodes ≈ b^d. Total cost = sum of work at every node.
"""

from __future__ import annotations
import sys
import math
from dataclasses import dataclass, field
from typing import Callable, Any
from functools import lru_cache


# ─────────────────────────────────────────────────────────────────
# Core instrumentation: wrap any recursive function to expose its tree
# ─────────────────────────────────────────────────────────────────

@dataclass
class TreeStats:
    """Empirical statistics of a recursion tree, collected during execution."""
    total_calls:  int = 0
    leaf_calls:   int = 0
    max_depth:    int = 0
    depth_counts: dict = field(default_factory=dict)  # depth → call count

    @property
    def internal_nodes(self) -> int:
        return self.total_calls - self.leaf_calls

    @property
    def empirical_branching_factor(self) -> float:
        """Estimate b from total_calls / (total_calls - leaf_calls)."""
        if self.internal_nodes == 0:
            return 0.0
        return self.total_calls / self.internal_nodes

    def report(self, label: str = "") -> None:
        if label:
            print(f"\n{'='*50}\n{label}\n{'='*50}")
        print(f"  Total nodes (calls):   {self.total_calls:>10,}")
        print(f"  Leaf nodes:            {self.leaf_calls:>10,}")
        print(f"  Internal nodes:        {self.internal_nodes:>10,}")
        print(f"  Max depth:             {self.max_depth:>10}")
        print(f"  Empirical branch. fac: {self.empirical_branching_factor:>10.3f}")


# ─────────────────────────────────────────────────────────────────
# Example 1: Fibonacci — T(n) = T(n-1) + T(n-2) + O(1)
#
# Branching factor: ≈ φ ≈ 1.618 (not exactly 2, because one branch is n-2)
# Depth: n
# Leaves: fib(n+1)  [exact, provable by induction]
# Total nodes: 2·fib(n+1) - 1
# Complexity: O(φ^n) where φ = (1+√5)/2
#
# THIS IS THE CANONICAL EXAMPLE of why the recursion tree matters.
# The exponential complexity is invisible from reading the code.
# It is immediately obvious from the tree.
# ─────────────────────────────────────────────────────────────────

def fib_naive(n: int, stats: TreeStats, depth: int = 0) -> int:
    stats.total_calls += 1
    stats.max_depth = max(stats.max_depth, depth)
    stats.depth_counts[depth] = stats.depth_counts.get(depth, 0) + 1

    if n <= 1:
        stats.leaf_calls += 1
        return n

    return (fib_naive(n - 1, stats, depth + 1) +
            fib_naive(n - 2, stats, depth + 1))


def fib_memoised(n: int, stats: TreeStats, memo: dict, depth: int = 0) -> int:
    """
    Memoisation COLLAPSES the recursion tree into a DAG.
    Unique subproblems: n (one per distinct argument 0..n).
    Total calls: O(n) instead of O(φ^n).

    This is the visual intuition behind why memoisation works:
    you are recognising that many tree nodes are IDENTICAL (same argument),
    and computing each only once.
    """
    stats.total_calls += 1
    stats.max_depth = max(stats.max_depth, depth)

    if n <= 1:
        stats.leaf_calls += 1
        return n
    if n in memo:
        stats.leaf_calls += 1   # Cache hit = leaf (no further branching)
        return memo[n]

    memo[n] = (fib_memoised(n - 1, stats, memo, depth + 1) +
               fib_memoised(n - 2, stats, memo, depth + 1))
    return memo[n]


# ─────────────────────────────────────────────────────────────────
# Example 2: Merge sort — T(n) = 2T(n/2) + O(n)
#
# Branching factor: exactly 2
# Depth: log₂(n)
# Work per node at level k: O(n / 2^k) ... but there are 2^k nodes
# → Total work per level: O(n) [constant across all log n levels]
# → Total: O(n log n)
#
# The tree PROVES this: draw log n levels, each with O(n) total work.
# ─────────────────────────────────────────────────────────────────

def merge_sort(arr: list[int], stats: TreeStats, depth: int = 0) -> list[int]:
    """
    Merge sort with recursion tree instrumentation.

    The key insight from the tree:
      Level 0 (root):  1 call,  n elements to merge  → O(n) work
      Level 1:         2 calls, n/2 elements each     → O(n) total
      Level 2:         4 calls, n/4 elements each     → O(n) total
      ...
      Level log₂n:     n calls, 1 element each        → O(n) total (base cases)

    log₂n levels × O(n) work per level = O(n log n). QED.
    """
    stats.total_calls += 1
    stats.max_depth = max(stats.max_depth, depth)

    if len(arr) <= 1:
        stats.leaf_calls += 1
        return arr

    mid = len(arr) // 2
    left  = merge_sort(arr[:mid], stats, depth + 1)   # Left child
    right = merge_sort(arr[mid:], stats, depth + 1)   # Right child

    # O(n) merge — the f(n) term: this is the work done AT this node
    merged = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged


# ─────────────────────────────────────────────────────────────────
# Example 3: Subset generation — T(n) = 2T(n-1) + O(1)
#
# Branching factor: exactly 2 (include / exclude each element)
# Depth: n
# Leaves: 2^n (one per subset)
# Total nodes: 2^(n+1) - 1 (full binary tree)
# Complexity: O(2^n)
# ─────────────────────────────────────────────────────────────────

def generate_subsets(
    nums: list[int],
    idx: int,
    current: list[int],
    result: list[list[int]],
    stats: TreeStats,
    depth: int = 0
) -> None:
    stats.total_calls += 1
    stats.max_depth = max(stats.max_depth, depth)

    if idx == len(nums):
        stats.leaf_calls += 1
        result.append(current[:])
        return

    # Branch 1: exclude nums[idx]
    generate_subsets(nums, idx + 1, current, result, stats, depth + 1)

    # Branch 2: include nums[idx]
    current.append(nums[idx])
    generate_subsets(nums, idx + 1, current, result, stats, depth + 1)
    current.pop()


# ─────────────────────────────────────────────────────────────────
# Master Theorem: derived from the tree, implemented as a classifier
# ─────────────────────────────────────────────────────────────────

def master_theorem(a: int, b: int, f_exponent: float, eps: float = 1e-9) -> str:
    """
    Classify T(n) = a·T(n/b) + Θ(n^f_exponent) using the three cases.

    The three cases correspond to which level of the tree dominates:
      Case 1: leaves dominate   (bottom-heavy tree)
      Case 2: all levels equal  (uniform tree)
      Case 3: root dominates    (top-heavy tree)

    Args:
        a:           branching factor (number of recursive calls)
        b:           reduction factor (input shrinks by factor b)
        f_exponent:  exponent p such that per-node work is Θ(n^p)

    Returns:
        String describing the asymptotic complexity.

    Examples:
        master_theorem(2, 2, 1)   → "Θ(n log n)"    [merge sort]
        master_theorem(1, 2, 0)   → "Θ(log n)"       [binary search]
        master_theorem(4, 2, 1)   → "Θ(n²)"          [leaves dominate]
        master_theorem(2, 2, 2)   → "Θ(n²)"          [root dominates]
    """
    assert a >= 1 and b > 1, "Need a ≥ 1, b > 1"

    leaf_exp = math.log(a) / math.log(b)   # log_b(a) — the leaf exponent

    if f_exponent < leaf_exp - eps:
        # Leaves dominate: the tree is bottom-heavy
        # More work accumulates as we go down → leaves determine the cost
        return f"Θ(n^{leaf_exp:.4g})  [Case 1: leaves dominate]"

    elif abs(f_exponent - leaf_exp) <= eps:
        # All levels equal: work per level is the same at every depth
        # log_b(n) levels × equal work → multiply by log
        if leaf_exp == 0:
            return "Θ(log n)  [Case 2: all levels equal]"
        return f"Θ(n^{leaf_exp:.4g} · log n)  [Case 2: all levels equal]"

    else:
        # Root dominates: the top level does the most work
        # Geometric series converges to the first term
        return f"Θ(n^{f_exponent:.4g})  [Case 3: root dominates]"


# ─────────────────────────────────────────────────────────────────
# Tree printer: render the recursion tree as ASCII (for small n)
# ─────────────────────────────────────────────────────────────────

def print_recursion_tree(
    label_fn: Callable[[Any], str],
    children_fn: Callable[[Any], list[Any]],
    root: Any,
    max_depth: int = 4,
    prefix: str = "",
    is_last: bool = True,
    depth: int = 0
) -> None:
    """
    Generic recursion tree ASCII printer.

    label_fn(node)    → str  (what to display at each node)
    children_fn(node) → list (what are the children of this node)
    max_depth         → don't print below this depth (tree too large)
    """
    connector = "└── " if is_last else "├── "
    print(prefix + connector + label_fn(root))

    if depth >= max_depth:
        return

    children = children_fn(root)
    new_prefix = prefix + ("    " if is_last else "│   ")
    for i, child in enumerate(children):
        print_recursion_tree(
            label_fn, children_fn, child,
            max_depth, new_prefix,
            is_last=(i == len(children) - 1),
            depth=depth + 1
        )
```

## 7. Common Variations & Extensions

### Variation 1: Non-Uniform Trees — T(n) = T(n-1) + T(n-2) + O(1)

Not all recursion trees are regular `a`-ary trees. Fibonacci's `T(n) = T(n-1) + T(n-2)` has branches of different lengths — the left subtree (argument `n-1`) has depth 1 greater than the right subtree (argument `n-2`). The tree is right-skewed. The Master Theorem does not apply (it requires `n/b` form, not `n-c`). Instead, the characteristic equation of the recurrence gives `T(n) = Θ(φ^n)`. The tree argument: the number of leaves equals `fib(n+1)`, which is `Θ(φ^n)`. For non-uniform trees, draw explicitly and count leaves by induction. See [[68.Base cases and the cost of missing them]] for what happens to this tree when the base case is missing.

### Variation 2: Recursion Trees in Quicksort Analysis

Quicksort's tree is non-uniform in a different way: the partition step splits `n` elements into two subarrays of size `k` and `n-k-1`, where `k` depends on the pivot. In the worst case (sorted input, bad pivot), the tree is a path (`b=1, d=n`) — `O(n²)`. In the best case (median pivot), the tree is balanced (`b=2, d=log n`) — `O(n log n)`. In the expected case over random pivots, the tree is _approximately_ balanced, and the expected depth is `O(log n)`. This connects to [[44.Quicksort — partition, pivot selection, expected O(n log n)]]: the expected complexity proof is an argument about the expected shape of the recursion tree.

### Variation 3: The Akra-Bazzi Method for Irregular Recurrences

When the recursion does not fit the strict `a·T(n/b)` form — e.g., `T(n) = T(n/3) + T(2n/3) + O(n)` (unequal splits) — the Master Theorem fails. The Akra-Bazzi method generalises it: find `p` such that `Σᵢ aᵢ · bᵢ^p = 1`, then `T(n) = Θ(n^p · (1 + ∫₁ⁿ f(u)/u^(p+1) du))`. For `T(n) = T(n/3) + T(2n/3) + O(n)`: the characteristic exponent `p = 1` (since `(1/3)^1 + (2/3)^1 = 1`), and the integral gives an extra `log n` factor — so `T(n) = Θ(n log n)`. This is the tree for mergesort's unequal-split variant.

### Variation 4: Space Complexity from the Tree — Stack Depth

The space complexity of a recursive algorithm is determined not by the total number of nodes in the tree, but by the **maximum depth** of a single root-to-leaf path. This is because only one path's worth of stack frames is alive at any given moment (the active call chain). For merge sort: depth is `log₂ n`, so space is `O(log n)` stack frames (ignoring the merge auxiliary arrays). For fibonacci: depth is `n`, so stack space is `O(n)`. For backtracking subset generation: depth is `n`, so stack space is `O(n)`. This is the direct connection to [[71.The call stack — stack frames, stack overflow, iterative conversion]]: deep recursion trees produce deep call stacks, which overflow for large `n`.

## 9. CP Contest Application

### Typical Problem Structure

The recursion tree appears in three contest contexts:

**1. Complexity prediction (pre-submission):** Before submitting a recursive solution, sketch its tree. Count the leaves. If the leaf count exceeds `~10^7` at `n = 20`, it will TLE. This is the most common contest use of the recursion tree — not analysis, but _feasibility checking_. Backtracking solutions that pass at `n = 20` but TLE at `n = 25` are almost always `2^n` or `n!` trees where the programmer did not check the leaf count.

**2. Divide and conquer design:** When designing a divide-and-conquer algorithm, you want the tree to be as uniform and shallow as possible. Branching factor 2, depth `log n`: optimal. Branching factor `n`, depth `n`: disastrous. This is why binary search halves the input (not thirds or quarters — any constant fraction gives `O(log n)`) and why merge sort is preferred over a "split into one and n-1" variant.

**3. Bitmask DP connection:** State-space enumeration problems often have an explicit recursion tree over `2^n` subsets (e.g., travelling salesman bitmask DP from [[182.Bitmask DP — state as a set, travelling salesman]]). The recursion tree has `2^n` leaves. Memoisation collapses it to `2^n` unique states. This is why bitmask DP has `O(2^n · n)` time complexity: `2^n` unique nodes in the collapsed tree, each doing `O(n)` work.

**Fixed iteration count (CP idiom):** For recursive divide-and-conquer in contests, track the actual node count empirically on the largest expected input to verify the theoretical analysis:

```cpp
// In contest: add a global counter to verify your tree analysis
int node_count = 0;

long long solve(int n) {
    node_count++;              // Count this call
    if (n <= 1) return n;      // Leaf
    return solve(n/2) + solve(n/2) + n;  // Two children + O(n) work
}
// After running: assert(node_count == 2*n - 1) for merge-sort-like recursion
```

This takes 3 lines and has saved many incorrect complexity analyses from becoming Wrong Answer or TLE submissions.
