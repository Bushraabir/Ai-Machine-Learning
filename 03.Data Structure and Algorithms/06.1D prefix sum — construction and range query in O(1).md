## 1. Intuition First

### The Core Idea

Imagine a bank account ledger with n daily transactions. You want to answer questions like: "What was the net balance change between day 14 and day 87?" The naïve approach reads every transaction between those two days — O(n) per query. But a trained accountant keeps a running total: the _cumulative balance_ on each day. To find the change between day 14 and day 87, she subtracts the cumulative balance on day 13 from the cumulative balance on day 87. Two lookups, one subtraction — O(1).

The prefix sum array `pre[i]` is this running cumulative total:

$$pre[i] = a[0] + a[1] + \cdots + a[i]$$

With this precomputed, any range sum query `sum(a[l..r])` is answered instantly:

$$\text{sum}(l, r) = pre[r] - pre[l-1]$$

This is the entire algorithm. Its power is not in complexity — it is in the _separation of concerns_: do all the work once during construction (O(n)), then answer every subsequent query in O(1). For q queries on a static array, the total cost drops from O(nq) naïve to O(n + q) with prefix sums.

### Why This Exists

The naïve range sum iterates from `l` to `r` every time. If n = 10⁵ and q = 10⁵ queries all touch the full range, that is 10¹⁰ operations — unusable. The prefix sum precomputes all partial sums in one O(n) pass, then answers each query with a single subtraction. This is the simplest and most universal example of the **preprocessing for fast queries** paradigm that extends to sparse tables, segment trees, and wavelet trees.

The key precondition: the array must be **static** during the query phase (no updates). The moment elements change, all prefix sums from the changed index onward are invalid. For dynamic arrays with updates, see [[155.Segment tree — range query and point update O(log n)]] and [[156.Fenwick tree (BIT) — prefix sum with updates O(log n)]].

### The "Aha" Moment

> **The range sum `sum(l, r)` is the difference of two prefix sums: `pre[r] - pre[l-1]`. Any range property that is "reversible" under its aggregation operation can be queried in O(1) using a prefix array. Sums, XORs, and products (with care) are reversible. Max and min are not.**

The reversibility condition is what separates prefix sums from prefix maximums. `max(l, r)` cannot be computed from `pre_max[r]` and `pre_max[l-1]` because max has no inverse operation. This is why sparse tables or segment trees are needed for range max/min but prefix sums suffice for range sum/XOR.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Prefix sums are a prerequisite subroutine, not a standalone algorithm. They appear inside solutions to harder problems as often as they appear alone. Recognise the signal:

- "Sum of elements in range `[l, r]`" with multiple queries → prefix sum directly
- "Number of elements in `[l, r]` satisfying condition X" → prefix count array (binary array where `a[i] = 1` if condition holds, then prefix sum it)
- "Subarray sum equals k" → `pre[r] - pre[l-1] = k` → `pre[r] - k = pre[l-1]` → HashMap lookup (see [[24.Subarray sum equals k — prefix sum + HashMap]])
- "Maximum subarray sum of length exactly k" → sliding window over prefix sum differences
- "Check if subarray is all-equal" → prefix sum of differences array; range sum = 0 iff all adjacent differences are zero
- "2D submatrix sums" → 2D prefix sum ([[07.2D prefix sum — submatrix sum queries]])

**Pattern signal → decision rule:**

```
Multiple range sum queries on a static array?
  └── Yes → Build prefix sum in O(n), answer each query in O(1)
        ├── Array updates between queries?
        │     └── Yes → Fenwick tree or Segment tree
        └── Range max/min instead of sum?
              └── Yes → Sparse table (O(n log n) build, O(1) query)
                        or Segment tree (O(n) build, O(log n) query)
```

**Common trap 1 — off-by-one in the boundary formula:** `sum(l, r) = pre[r] - pre[l-1]`. When `l = 0`, `pre[l-1] = pre[-1]` is out of bounds. The standard fix: shift the prefix array by one — define `pre[0] = 0` (empty prefix) and `pre[i] = a[0] + ... + a[i-1]` for i ≥ 1. Then `sum(l, r) = pre[r+1] - pre[l]` and `l = 0` gives `pre[r+1] - pre[0] = pre[r+1]`, which is always safe.

Two conventions exist and both are correct — the danger is mixing them:

|Convention|`pre[i]` means|Range query formula|
|---|---|---|
|**Inclusive**|`a[0] + ... + a[i]`|`pre[r] - (l > 0 ? pre[l-1] : 0)`|
|**Exclusive (shifted)**|`a[0] + ... + a[i-1]`, `pre[0] = 0`|`pre[r+1] - pre[l]`|

Pick one, annotate it in your variable name (`prefix_sum_inclusive` vs `prefix_sum_exclusive`), and never switch mid-problem.

**Common trap 2 — integer overflow:** If elements are up to 10⁹ and n is up to 10⁵, the prefix sum can reach 10¹⁴, which overflows a 32-bit integer. Always use `long long` in C++ and check whether Python's arbitrary precision is needed (it usually is not, but the bound computation matters).

**Common trap 3 — applying prefix sums to non-invertible operations:** Prefix XOR is valid: `XOR(l, r) = pre_xor[r] XOR pre_xor[l-1]` because XOR is its own inverse. Prefix product is dangerous: `product(l, r) = pre_prod[r] / pre_prod[l-1]` requires division, which fails if any element is zero. Handle zero-containing subarrays explicitly. Prefix max/min has no inverse — cannot be decomposed this way.

### Machine Learning / AI

**1. Cumulative distribution functions and quantile computation.** The empirical CDF at value `v` is `F(v) = count(x ≤ v) / n`. For a sorted array of observations, computing `F(v)` for multiple query values is a prefix count problem: build a frequency histogram, prefix-sum it to get cumulative counts, then each CDF query is a binary search + O(1) lookup. NumPy's `np.cumsum()` is the vectorised prefix sum construction. scikit-learn's `QuantileTransformer` and calibration methods use this internally. See [[218.Sampling strategies — uniform, stratified, importance sampling]].

**2. Attention mask prefix sums for variable-length sequence batching.** In Transformer inference with variable-length sequences, a prefix sum over sequence lengths gives the start offset of each sequence in a packed (non-padded) token buffer. If sequences have lengths `[5, 3, 8, 2]`, the prefix sum `[0, 5, 8, 16, 18]` gives the start position of each sequence in the flat buffer. This is how FlashAttention and vLLM implement efficient attention over packed sequences without padding overhead. The prefix sum converts a sequence of lengths into a sequence of offsets — the standard trick in compressed sparse row (CSR) matrix representation. See [[220.Data pipeline design — streaming vs batch, shuffling, prefetching]].

**3. Rolling/windowed feature engineering.** A fixed-window sum feature (sum of the last k values at each timestep) is computed in O(n) using prefix sums: `window_sum[i] = pre[i] - pre[i-k]`. Without prefix sums, this is O(nk). In a feature pipeline with n = 10⁷ timesteps and k = 1000, this is the difference between milliseconds and hours. `pandas.Series.rolling(k).sum()` uses a running-sum variant (not a full prefix array, but equivalent for fixed k). See [[15.Windowed time-series features — ML connection to rolling()]].

**4. Prefix sums in sparse matrix formats (CSR/CSC).** Compressed Sparse Row (CSR) format stores a matrix as three arrays: `data` (non-zero values), `col_idx` (column indices), and `row_ptr` (prefix sums of per-row non-zero counts). `row_ptr[i]` = total non-zeros in rows 0 through i-1. To access row i, read `data[row_ptr[i] : row_ptr[i+1]]`. This prefix-sum indexing makes row access O(1) rather than O(nnz). SciPy's `scipy.sparse.csr_matrix`, PyTorch's `torch.sparse_csr_tensor`, and the internal representation of embedding tables in recommendation systems all use this structure. See [[213.Vectorisation thinking — replacing loops with matrix operations]].

**5. Integral images in computer vision (2D prefix sum).** The Viola-Jones face detection algorithm (2001) uses integral images — the 2D prefix sum of pixel intensities — to compute the sum of any rectangular region in O(1). This made real-time face detection feasible on 2001 hardware. Haar feature computation in OpenCV still uses this technique. The algorithmic idea is identical to 1D prefix sums; the 2D extension is covered in [[07.2D prefix sum — submatrix sum queries]].

## 3. Algorithm / Pattern

### Construction

**Inclusive convention** (used in most contest code):

```
pre[0] = a[0]
for i = 1 to n-1:
    pre[i] = pre[i-1] + a[i]
```

**Exclusive/shifted convention** (cleaner for queries, avoids l=0 edge case):

```
pre[0] = 0          ← empty prefix: sum of zero elements
for i = 1 to n:
    pre[i] = pre[i-1] + a[i-1]
```

`pre` has length `n+1`. `pre[i] = a[0] + a[1] + ... + a[i-1]`.

### Query

```
// Exclusive convention (preferred):
sum(l, r) = pre[r+1] - pre[l]       // 0-indexed l, r; pre has n+1 elements
                                     // l=0: pre[r+1] - pre[0] = pre[r+1] ✓

// Inclusive convention:
sum(l, r) = pre[r] - (l > 0 ? pre[l-1] : 0)
```

### Prefix XOR

XOR has the property `x XOR x = 0` and `x XOR 0 = x`, making it self-inverse. The formula `xor(l, r) = pre_xor[r] XOR pre_xor[l-1]` holds because:

- `pre_xor[r] = a[0] XOR a[1] XOR ... XOR a[r]`
- `pre_xor[l-1] = a[0] XOR a[1] XOR ... XOR a[l-1]`
- Their XOR cancels `a[0]..a[l-1]`, leaving `a[l] XOR ... XOR a[r]`

### Difference Array (Inverse of Prefix Sum)

The **difference array** `d[i] = a[i] - a[i-1]` (with `d[0] = a[0]`) is the "inverse" construction: given `d`, recovering `a` requires a prefix sum of `d`. Difference arrays enable O(1) _range updates_ (add a value to every element in `[l, r]`) when queries are deferred to the end. See [[10.Difference array — range update in O(1)]].

```
// Range update: add val to a[l..r]
d[l]   += val
d[r+1] -= val   ← undo the addition past r

// After all updates, recover the modified array:
a[0] = d[0]
for i = 1 to n-1:
    a[i] = a[i-1] + d[i]   ← prefix sum of d gives the modified a
```

### Complexity

**Construction:** O(n) time, O(n) space (the prefix array).

**Query:** O(1) time, O(1) space per query.

**Total for q queries:** O(n + q) vs O(nq) naïve. For n = q = 10⁵, this is 2×10⁵ vs 10¹⁰ — eight orders of magnitude.

**When prefix sums cannot be used:**

|Situation|Why it fails|Alternative|
|---|---|---|
|Array is modified between queries|All sums from update index onward are invalid|Fenwick tree, Segment tree|
|Range max/min query|Max has no inverse operation|Sparse table, Segment tree|
|Online queries with unknown l, r|Must build pre first; then O(1) per query is fine|Build pre, then answer|
|Streaming data, unknown n|Cannot allocate pre upfront|Running sum + difference|

## 4. Pseudocode

```
// ─── Construction: Exclusive (Shifted) Convention ────────────────────────
// pre has length n+1. pre[0] = 0 (identity sentinel).
// pre[i] = a[0] + a[1] + ... + a[i-1].

function build_prefix_sum(a[0..n-1]) → pre[0..n]:
    pre[0] ← 0
    for i from 1 to n:
        pre[i] ← pre[i-1] + a[i-1]
    return pre


// ─── Range Query: O(1) ───────────────────────────────────────────────────
// Sum of a[l..r], 0-indexed, inclusive on both ends.

function range_sum(pre[0..n], l, r) → sum:
    // Precondition: 0 <= l <= r <= n-1
    return pre[r+1] - pre[l]


// ─── Prefix XOR Construction and Query ───────────────────────────────────

function build_prefix_xor(a[0..n-1]) → pre_xor[0..n]:
    pre_xor[0] ← 0
    for i from 1 to n:
        pre_xor[i] ← pre_xor[i-1] XOR a[i-1]
    return pre_xor

function range_xor(pre_xor[0..n], l, r) → xor_val:
    return pre_xor[r+1] XOR pre_xor[l]


// ─── Subarray Count: Number of subarrays with sum = k ────────────────────
// Key insight: sum(l,r) = k ↔ pre[r+1] - pre[l] = k ↔ pre[l] = pre[r+1] - k
// For each r, look up how many past l's had pre[l] = pre[r+1] - k.

function count_subarrays_sum_k(a[0..n-1], k) → count:
    freq ← HashMap, initialised with {0: 1}   ← pre[0]=0 seen once
    running ← 0
    count   ← 0
    for i from 0 to n-1:
        running ← running + a[i]              ← this is pre[i+1]
        count   ← count + freq.get(running - k, 0)
        freq[running] ← freq.get(running, 0) + 1
    return count


// ─── Difference Array: Range Update in O(1) ──────────────────────────────

function range_update(d[0..n], l, r, val):
    d[l]   ← d[l] + val
    d[r+1] ← d[r+1] - val    ← sentinel: d has length n+1

function materialise(d[0..n]) → a[0..n-1]:
    a[0] ← d[0]
    for i from 1 to n-1:
        a[i] ← a[i-1] + d[i]
    return a
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ─────────────────────────────────────────────────────────────────────────────
// PrefixSum: exclusive (shifted) convention.
// pre[0] = 0, pre[i] = a[0] + ... + a[i-1].
// Range query: sum(l, r) = pre[r+1] - pre[l].   (0-indexed, inclusive)
// ─────────────────────────────────────────────────────────────────────────────
struct PrefixSum {
    vector<long long> pre;

    explicit PrefixSum(const vector<int>& a) {
        int n = a.size();
        pre.resize(n + 1, 0);
        for (int i = 0; i < n; ++i)
            pre[i + 1] = pre[i] + a[i];
    }

    // Sum of a[l..r], 0-indexed, both inclusive.
    long long query(int l, int r) const {
        assert(0 <= l && l <= r && r < (int)pre.size() - 1);
        return pre[r + 1] - pre[l];
    }

    // Number of elements in a[l..r] (trivially r - l + 1, but useful as
    // a pattern when the array is a binary indicator array).
    int count(int l, int r) const {
        return r - l + 1;
    }
};

// ─────────────────────────────────────────────────────────────────────────────
// PrefixXOR: same shifted convention, XOR instead of addition.
// range_xor(l, r) = a[l] XOR a[l+1] XOR ... XOR a[r].
// ─────────────────────────────────────────────────────────────────────────────
struct PrefixXOR {
    vector<int> pre;

    explicit PrefixXOR(const vector<int>& a) {
        int n = a.size();
        pre.resize(n + 1, 0);
        for (int i = 0; i < n; ++i)
            pre[i + 1] = pre[i] ^ a[i];
    }

    int query(int l, int r) const {
        assert(0 <= l && l <= r && r < (int)pre.size() - 1);
        return pre[r + 1] ^ pre[l];
    }
};

// ─────────────────────────────────────────────────────────────────────────────
// Subarray sum equals k (LeetCode 560).
// Uses prefix sum + HashMap: for each position, count past prefixes
// whose value equals (current_prefix - k).
// O(n) time, O(n) space.
// ─────────────────────────────────────────────────────────────────────────────
int subarray_sum_equals_k(const vector<int>& a, int k) {
    unordered_map<long long, int> freq;
    freq[0] = 1;        // empty prefix seen once (handles subarrays starting at 0)
    long long running = 0;
    int count = 0;

    for (int x : a) {
        running += x;
        auto it = freq.find(running - k);
        if (it != freq.end()) count += it->second;
        ++freq[running];
    }
    return count;
}

// ─────────────────────────────────────────────────────────────────────────────
// Difference Array — O(1) range updates, O(n) materialisation.
// Use case: apply m range updates, then query final array values.
// Total complexity: O(n + m) instead of O(nm).
// ─────────────────────────────────────────────────────────────────────────────
struct DifferenceArray {
    vector<long long> d;
    int n;

    explicit DifferenceArray(int n, long long init = 0) : n(n), d(n + 1, 0) {
        if (init != 0) { d[0] = init; }
        // If initialising from an existing array a[], call range_update
        // for each element, or build d[i] = a[i] - a[i-1] directly.
    }

    explicit DifferenceArray(const vector<int>& a) : n(a.size()), d(a.size() + 1, 0) {
        d[0] = a[0];
        for (int i = 1; i < n; ++i)
            d[i] = a[i] - a[i - 1];
    }

    // Add val to every element in a[l..r].
    void update(int l, int r, long long val) {
        assert(0 <= l && l <= r && r < n);
        d[l]     += val;
        d[r + 1] -= val;    // sentinel position r+1 reverses the effect past r
    }

    // Recover the final array after all updates.
    vector<long long> materialise() const {
        vector<long long> a(n);
        a[0] = d[0];
        for (int i = 1; i < n; ++i)
            a[i] = a[i - 1] + d[i];
        return a;
    }
};

// ─────────────────────────────────────────────────────────────────────────────
// Maximum sum subarray of length exactly k (using prefix sums).
// sum(i-k+1, i) = pre[i+1] - pre[i-k+1].
// Slide i from k-1 to n-1, compute each window sum in O(1).
// O(n) time, O(n) space (or O(1) with a running sum — shown below).
// ─────────────────────────────────────────────────────────────────────────────
long long max_sum_fixed_window(const vector<int>& a, int k) {
    int n = a.size();
    if (k > n) return LLONG_MIN;

    PrefixSum ps(a);
    long long best = ps.query(0, k - 1);       // first window
    for (int i = k; i < n; ++i) {
        best = max(best, ps.query(i - k + 1, i));
    }
    return best;
}

// ─────────────────────────────────────────────────────────────────────────────
// Test driver
// ─────────────────────────────────────────────────────────────────────────────
int main() {
    // PrefixSum queries
    vector<int> a = {3, 1, 4, 1, 5, 9, 2, 6};
    PrefixSum ps(a);
    assert(ps.query(0, 7) == 31);   // sum of entire array
    assert(ps.query(0, 0) == 3);    // single element
    assert(ps.query(2, 5) == 19);   // 4+1+5+9
    assert(ps.query(6, 7) == 8);    // 2+6

    // PrefixXOR
    vector<int> b = {5, 7, 3, 1};
    PrefixXOR px(b);
    assert(px.query(0, 3) == (5^7^3^1));
    assert(px.query(1, 2) == (7^3));

    // Subarray sum = k
    assert(subarray_sum_equals_k({1, 1, 1}, 2) == 2);     // [1,1] at 0-1 and 1-2
    assert(subarray_sum_equals_k({1, 2, 3}, 3) == 2);     // [3] and [1,2]
    assert(subarray_sum_equals_k({-1, -1, 1}, 0) == 1);   // [-1,1] wait: -1+(-1)+1=-1, -1+1=0 ✓

    // DifferenceArray
    DifferenceArray da(5);      // array of 5 zeros
    da.update(1, 3, 10);        // add 10 to positions 1..3
    da.update(2, 4, 5);         // add 5  to positions 2..4
    auto result = da.materialise();
    assert((result == vector<long long>{0, 10, 15, 15, 5}));

    DifferenceArray da2({1, 2, 3, 4, 5});
    da2.update(0, 4, -1);       // subtract 1 from all
    da2.update(2, 3,  3);       // add 3 to middle
    auto r2 = da2.materialise();
    assert((r2 == vector<long long>{0, 1, 5, 6, 4}));

    // Max sum fixed window
    assert(max_sum_fixed_window({2, 1, 5, 1, 3, 2}, 3) == 9);  // [5,1,3]
    assert(max_sum_fixed_window({-1,-2,-3,-4}, 2)       == -3); // [-1,-2]

    cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations
from itertools import accumulate
from typing import Sequence


class PrefixSum:
    """
    Exclusive (shifted) prefix sum.
    pre[0] = 0, pre[i] = a[0] + ... + a[i-1].
    Range query: sum(l, r) = pre[r+1] - pre[l].   (0-indexed, inclusive)

    Construction: O(n)
    Query:        O(1)
    Space:        O(n)
    """

    def __init__(self, a: Sequence[int | float]) -> None:
        # itertools.accumulate with initial=0 gives the shifted prefix sum
        # directly: [0, a[0], a[0]+a[1], ...]
        self._pre = list(accumulate(a, initial=0))
        self._n   = len(a)

    def query(self, l: int, r: int) -> int | float:
        """Sum of a[l..r], 0-indexed, inclusive. O(1)."""
        assert 0 <= l <= r < self._n, f"Invalid range [{l}, {r}] for n={self._n}"
        return self._pre[r + 1] - self._pre[l]

    def __len__(self) -> int:
        return self._n


class PrefixXOR:
    """
    Prefix XOR array. xor_range(l, r) = a[l] XOR ... XOR a[r].
    Works because XOR is its own inverse: (A XOR B) XOR B = A.

    Construction: O(n)
    Query:        O(1)
    """

    def __init__(self, a: Sequence[int]) -> None:
        self._pre = list(accumulate(a, func=lambda acc, x: acc ^ x, initial=0))
        self._n   = len(a)

    def query(self, l: int, r: int) -> int:
        assert 0 <= l <= r < self._n
        return self._pre[r + 1] ^ self._pre[l]


class DifferenceArray:
    """
    Supports O(1) range updates and O(n) materialisation.
    Use when: many range updates, queries only needed at the end.

    Dual to prefix sum: prefix_sum(difference_array) = original_array.

    Construction: O(n)
    Range update: O(1)
    Materialise:  O(n)
    """

    def __init__(self, n: int, initial: list[int] | None = None) -> None:
        self._n = n
        self._d = [0] * (n + 1)   # extra slot acts as sentinel for r+1
        if initial:
            assert len(initial) == n
            self._d[0] = initial[0]
            for i in range(1, n):
                self._d[i] = initial[i] - initial[i - 1]

    def update(self, l: int, r: int, val: int) -> None:
        """Add val to every element a[l..r] in O(1)."""
        assert 0 <= l <= r < self._n
        self._d[l]     += val
        self._d[r + 1] -= val   # sentinel slot r+1 reverts past position r

    def materialise(self) -> list[int]:
        """Recover the final array. O(n)."""
        result = [0] * self._n
        result[0] = self._d[0]
        for i in range(1, self._n):
            result[i] = result[i - 1] + self._d[i]
        return result


def subarray_sum_equals_k(a: list[int], k: int) -> int:
    """
    Count subarrays with sum exactly k (LeetCode 560).

    Key identity: sum(l, r) = k
      ↔  pre[r+1] - pre[l] = k
      ↔  pre[l] = pre[r+1] - k

    For each position r, look up how many past prefix sums equal (running - k).
    HashMap freq maps prefix_sum_value → count of times seen.

    Initialise freq[0] = 1 because the empty prefix (pre[0] = 0) is always
    present and enables counting subarrays that start at index 0.

    Time:  O(n)
    Space: O(n)
    """
    from collections import defaultdict
    freq: dict[int, int] = defaultdict(int)
    freq[0] = 1     # empty prefix seen once
    running = 0
    count   = 0

    for x in a:
        running += x                  # this is pre[current_index + 1]
        count   += freq[running - k]  # how many l's have pre[l] = running - k
        freq[running] += 1

    return count


def max_sum_fixed_window(a: list[int], k: int) -> int:
    """
    Maximum sum of any contiguous subarray of length exactly k.
    Uses prefix sums: window_sum(i) = pre[i+1] - pre[i-k+1].

    Alternatively: O(1) space running sum (shown as naive_version).
    Shown here using PrefixSum to illustrate the pattern.

    Time:  O(n)
    Space: O(n) with prefix sum, O(1) with running sum
    """
    n = len(a)
    if k > n:
        return float('-inf')

    ps   = PrefixSum(a)
    best = ps.query(0, k - 1)
    for i in range(k, n):
        best = max(best, ps.query(i - k + 1, i))
    return best


def count_prefix_sum_in_range(a: list[int], lo: int, hi: int) -> int:
    """
    Count subarrays whose sum is in [lo, hi].
    Uses the identity: count(sum in [lo,hi]) = count(sum <= hi) - count(sum <= lo-1).
    Each count(sum <= X) is itself a prefix-sum + sorted-order query (merge sort
    or BIT), but shown here with the simpler O(n²) approach for illustration.

    Production approach: use a Fenwick tree over coordinate-compressed prefix sums.
    See [[156.Fenwick tree (BIT) — prefix sum with updates O(log n)]].

    Time:  O(n²) here; O(n log n) with BIT
    """
    n  = len(a)
    ps = PrefixSum(a)
    count = 0
    for l in range(n):
        for r in range(l, n):
            s = ps.query(l, r)
            if lo <= s <= hi:
                count += 1
    return count

### Diagram 3 — Difference Array: Range Update Visualised

`n = 6`, two updates: add 3 to `[1, 4]`, add -1 to `[2, 3]`.

```

  a[1] = a[0]+d[1]  = 0+3  = 3
  a[2] = a[1]+d[2]  = 3-1  = 2
  a[3] = a[2]+d[3]  = 2+0  = 2
  a[4] = a[3]+d[4]  = 2+1  = 3

Verification:
  Positions 1-4 got +3: [3, 3, 3, 3] at indices 1-4 ✓  (before second update)
  Positions 2-3 got -1: [3, 2, 2, 3] at indices 1-4 ✓  (combined)

The "spike" d[1]=3 activates the +3 at index 1.
The "cancel" d[5]=-3 deactivates it at index 5.
Each update is O(1). m updates costs O(m). Materialise once in O(n).

## 7. Common Variations & Extensions

### Variation 1 — Prefix Count (Binary Indicator Array)

When the question is "how many elements in `[l, r]` satisfy property P?", build a binary array `b` where `b[i] = 1` if `a[i]` satisfies P, else `b[i] = 0`. Then `count(l, r) = prefix_sum(b, l, r)`. This converts any counting range query into a prefix sum. Example: "count even numbers in `[l, r]`" — build `b[i] = a[i] % 2 == 0 ? 1 : 0`, then query prefix sum of `b`.

### Variation 2 — Prefix Sum of Frequencies (Counting Sort Range Query)

Build a frequency array `freq[v] = count of v in a`. Prefix-sum it: `pre[v] = count of elements ≤ v`. Then "count elements in `[l, r]` with value in `[x, y]`" = `pre[y] - pre[x-1]` per the prefix sum formula. This combines counting sort with prefix sums for O(1) value-range queries after O(V) preprocessing (V = value range). Used in offline algorithms and coordinate-compressed range queries.

### Variation 3 — Prefix Product with Zero Handling

`product(l, r) = pre_prod[r] / pre_prod[l-1]` requires division, which is undefined when any prefix product is zero. The workaround: track the count of zeros separately. If `zero_count(l, r) > 0`, the product is 0. Otherwise, divide the non-zero prefix products. This is the "product of array except self" pattern — see [[03.In-place modification — overwriting the input array]].

### Variation 4 — Offline vs Online Queries

Prefix sums answer **offline** queries: all queries must be known before construction. For **online** queries (each query's `l, r` depends on the previous answer), the same O(1) query time holds — the prefix array is just precomputed once and queried on demand. The constraint is that the array itself must be static. For dynamic arrays with point updates between queries, see [[156.Fenwick tree (BIT) — prefix sum with updates O(log n)]].

## 9. CP Contest Application

### Typical Problem Structures

**Codeforces Div. 2 B / C — direct range sum with q queries:**

> "Given array a of n integers and q queries, each query gives (l, r) and asks for the sum a[l] + a[l+1] + ... + a[r]. n, q ≤ 10⁵."

Pure prefix sum. O(n + q). Any O(n) per query solution gets TLE.

**Div. 2 C / D — prefix sum as a subroutine:**

> "Find the number of subarrays with sum divisible by k."

Transform: `sum(l, r) % k == 0 ↔ pre[r+1] % k == pre[l] % k`. Build a frequency array of `pre[i] % k` values (size k), count pairs with equal remainders using `C(freq[rem], 2) = freq[rem] * (freq[rem] - 1) / 2`. The prefix sum is a subroutine enabling the combinatorial count.

**Div. 2 D / E — difference array for range updates:**

> "You have an array initialised to zero. Process m operations, each adding val to all positions in [l, r]. After all operations, output the final array."

Difference array: O(m + n). Naïve: O(mn). For m = n = 10⁵, naïve is 10¹⁰ operations (TLE). Difference array is 2×10⁵ (instant).

### Optimisation Notes

**`itertools.accumulate` in Python:** The Python implementation uses `accumulate(a, initial=0)` which is implemented in C and is ~5× faster than a Python for-loop building the prefix array. Always prefer it over manual loop construction in Python.

**Memory layout:** The prefix array is accessed sequentially during construction (cache-friendly) and at two arbitrary positions per query (potential cache miss if l and r are far apart). For n = 10⁷ with q = 10⁷ random queries, memory bandwidth, not computation, is the bottleneck. Reducing the element size from `int64` to `int32` (when overflow is not a concern) halves the memory footprint and doubles the effective cache capacity — a practical 2× speedup.

**`long long` by default in C++:** The maximum prefix sum for n = 10⁵ elements each of value 10⁹ is 10¹⁴, which overflows `int32` (max ~2×10⁹) but fits in `int64` (max ~9×10¹⁸). Use `long long` for the prefix array unconditionally in competitive programming.
