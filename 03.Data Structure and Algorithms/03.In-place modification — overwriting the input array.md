## Intuition First

### The Core Idea

A film editor working on a tight budget cannot afford a second reel. Every cut must be made on the original footage itself — splicing out unwanted frames, compressing scenes in place, reordering shots without duplicating the tape. The editor must always know: _which part of the tape has already been processed and is safe to overwrite, and which part still holds original footage that must be read before being destroyed?_

In-place modification is this discipline applied to arrays. You are given one block of memory — the input array — and you must produce the output in that same block. **The fundamental constraint is the read-write ordering**: you may only overwrite a cell after you have finished reading it. The entire craft is in managing this boundary.

Two structural patterns arise:

1. **Write pointer / read pointer separation:** A `write` pointer trails behind a `read` pointer. The read pointer scans every element; the write pointer advances only when an element deserves to be kept. Because `write ≤ read` always holds, the write pointer never destroys data that the read pointer has not yet consumed.
    
2. **Value-as-pointer encoding:** The array's values themselves are used as indices into the same array — encoding extra information (sign, visited marker, offset) into the values without allocating any additional space. This is more advanced and requires careful decoding.
    

### Why This Exists

The naive approach allocates a second array of size n, writes results into it, then copies back or returns the new array. This is O(n) extra space. For arrays of size 10⁸ elements (common in ML data pipelines), that extra allocation is gigabytes of memory, cache misses, and allocation overhead.

In-place modification achieves O(1) auxiliary space — the same O(n) time but with zero additional allocations. In embedded systems, mobile inference, and competitive programming with tight memory limits, this is non-negotiable.

The deeper reason it matters: **it teaches you to treat the array as both the data structure and the communication channel**. This discipline — using the data itself to encode state — is a recurring idea in algorithms: Morris traversal of a tree (thread the tree in-place), Floyd's cycle detection (use position itself as the marker), index-as-hash tricks.

### The "Aha" Moment

> **The write pointer is always at or behind the read pointer. Everything at indices `[0, write)` is already the final answer. Everything at `[write, read)` has been consumed and is now safe garbage. Everything at `[read, n)` is untouched input.**

Once you see this invariant, every in-place problem becomes a question of: what is the condition for advancing `write`? The answer to that question _is_ the algorithm.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** In-place modification is the required approach whenever a problem says "modify the array in-place" or "do not allocate extra space" or "O(1) extra memory." It also appears implicitly in problems where a naive O(n) space solution exists but the intended solution is O(1) — often signalled by the memory limit being 4MB or less (typical for embedded/online judge constraints).

**Pattern signals — what to think when you see:**

- "Remove duplicates from sorted array" → write pointer keeps last accepted value
- "Move all zeros to end" → write pointer counts non-zeros, sweep zeros to tail
- "Remove element equal to val" → write pointer skips matching elements
- "Rotate array in-place" → reverse-based rotation (three reverses, no extra array)
- "Find the duplicate / missing number in `[1..n]`" → sign-flip or index-as-hash trick

**Common trap 1 — overwriting before reading:** The write pointer advances past the read pointer in some edge case (e.g., when the array is already in its target state), causing data loss. Always verify that `write ≤ read` is a loop invariant, not just an initial condition.

**Common trap 2 — forgetting to return the new length:** Problems like "remove duplicates" don't shrink the underlying array — they cannot, in most languages. The contract is: return the new logical length `k`; the first `k` elements of the array are the answer; elements after index `k` are undefined and the judge ignores them. Submitting without updating the return value causes wrong answers on the length check.

**Common trap 3 — the sign-flip trick on arrays with zeros:** The value-as-pointer encoding uses `sign(a[abs(a[i])-1])` as a visited marker. If the array contains zeros, this breaks (zero has no sign, and `abs(0)-1 = -1` is an invalid index). The problem statement will guarantee values are in `[1..n]`; always check before applying this pattern.

### Machine Learning / AI

**1. In-place tensor operations in PyTorch and NumPy.** PyTorch distinguishes in-place operations with a trailing underscore: `tensor.add_(1)`, `tensor.relu_()`, `tensor.zero_()`. These modify the storage buffer directly, avoiding a new allocation. In a forward pass processing millions of activations, the difference between `x = torch.relu(x)` (allocates new tensor) and `x.relu_()` (in-place) can be the difference between fitting a model in GPU VRAM and running out of memory. The constraint: **in-place operations on tensors that require gradient computation break the autograd graph**, because the backward pass needs the original value. PyTorch will raise a `RuntimeError` if you do this incorrectly. Understanding why — the backward pass is a right-to-left pass that reads values written during the forward pass, exactly the read-write ordering problem — connects directly to [[02.Two-pass traversal — forward and backward in one problem]].

**2. Shuffling and permutation of training datasets.** `numpy.random.shuffle(arr)` is an in-place Fisher-Yates shuffle: at each step `i`, it swaps `arr[i]` with a random element from `arr[i..n-1]`. No copy of the array is made. For a dataset of 10⁷ samples stored as a NumPy array, an out-of-place shuffle would double the memory footprint. The algorithm is structurally a write pointer advancing left-to-right with random swaps — a specific case of in-place rearrangement. See [[218.Sampling strategies — uniform, stratified, importance sampling]].

**3. Quantisation and weight packing for model compression.** Post-training quantisation converts float32 weights (4 bytes each) to int8 (1 byte) in-place. In TensorFlow Lite and ONNX Runtime, this is done by iterating over the weight buffer and overwriting each float with its quantised integer representation — the same buffer, smaller values. The read-write ordering constraint is trivially satisfied here (read float at position i, write int8 at position i, move on), but the general principle of "process the buffer in a single pass without a second copy" is the in-place discipline at work. See [[107.Quantisation and model compression — ML connection to bit ops]].

**4. Data deduplication in feature pipelines.** The "remove duplicates from sorted array" algorithm is literally used in data pipeline preprocessing when deduplicating sorted feature indices (e.g., in sparse feature encodings where the same feature ID appears multiple times in a row after sorting). Libraries like `numpy.unique` are out-of-place, but a custom Cython/C pass over a pre-sorted sparse index array uses the in-place write pointer pattern for O(1) extra space at scale.

## 3. Algorithm / Pattern

### Pattern A — The Write Pointer (Filter / Compress)

Used when: you want to keep a subset of elements (those satisfying a predicate) and pack them to the front.

```
Invariant: a[0..write-1] contains the final answer at all times.
           a[write..read-1] is processed garbage, safe to overwrite.
           a[read..n-1] is untouched input.

write ← 0
for read from 0 to n-1:
    if keep(a[read]):
        a[write] ← a[read]     ← only write when keeping
        write ← write + 1
return write    ← new logical length
```

**Condition for write ≤ read:** In the worst case, every element is kept → write == read (never overtakes). In the best case (nothing kept) → write stays at 0. The invariant holds for all inputs.

### Pattern B — The Sign-Flip / Index-as-Hash Trick

Used when: values are in `[1..n]` and you need O(1) space to track which values have been seen, duplicated, or are missing.

```
For each value v = abs(a[i]):
    idx = v - 1                    ← map value v to index v-1
    if a[idx] > 0:
        a[idx] = -a[idx]           ← mark index as "seen" by flipping sign
    else:
        // a[idx] already negative → v was seen before → v is a duplicate

// After the pass:
// a[i] > 0 means value i+1 was never seen → it is the missing value
// Restore: a[i] = abs(a[i]) to recover original values
```

**Constraint:** Values must be in `[1..n]` where n = array length. The value `v` maps to index `v-1`, which is always valid. Zero breaks this — avoid.

### Pattern C — In-Place Reversal / Rotation

Used when: rotating or reversing a subarray without extra space.

```
// Reverse a[l..r] in-place
l ← 0, r ← n-1
while l < r:
    swap(a[l], a[r])
    l ← l + 1
    r ← r - 1

// Rotate right by k positions: reverse all, reverse first k, reverse last n-k
reverse(a, 0, n-1)
reverse(a, 0, k-1)
reverse(a, k, n-1)
```

### Decision Tree

```
Does the problem require O(1) extra space?
  └── Yes → In-place modification
        ├── Keep a subset of elements?
        │     └── Write pointer pattern (Pattern A)
        ├── Values in [1..n], need to track presence?
        │     └── Sign-flip / index-as-hash (Pattern B)
        ├── Reorder elements (rotation, reversal)?
        │     └── Reversal / swap-based (Pattern C)
        └── Rearrange by some partition criterion?
              └── Dutch National Flag / three-pointer
                  → [[18.Three pointers — Dutch National Flag, 3Sum]]
```

### Complexity

**Time: O(n)** — single or constant number of passes over the array.

**Space: O(1) auxiliary** — no allocations proportional to input size. The input array itself is O(n) but is given; auxiliary space refers to extra allocations beyond the input.

**When to avoid:** When the caller still needs the original array after your function returns. In-place modification is destructive. If the problem guarantees the input won't be re-used, or explicitly asks for in-place, proceed. Otherwise, clarify.

## 4. Pseudocode

```
// ─── Pattern A: Remove Duplicates from Sorted Array ──────────────────────
// Returns new length k such that a[0..k-1] contains unique elements in order.

function remove_duplicates(a[0..n-1]) → k:
    if n == 0: return 0

    write ← 1       // a[0] is always kept; write starts at 1
    for read from 1 to n-1:
        if a[read] ≠ a[write-1]:    // new unique value found
            a[write] ← a[read]      // place it at the write frontier
            write ← write + 1
    return write


// ─── Pattern A variant: Move Zeros to End ────────────────────────────────
// Non-zeros are packed to the front; zeros fill the tail.
// Relative order of non-zeros is preserved.

function move_zeros(a[0..n-1]):
    write ← 0
    for read from 0 to n-1:
        if a[read] ≠ 0:
            a[write] ← a[read]
            write ← write + 1
    // Fill tail with zeros
    for i from write to n-1:
        a[i] ← 0


// ─── Pattern B: Find the Duplicate (values in [1..n]) ────────────────────
// Marks visited indices by flipping sign. Duplicate found when index already negative.

function find_duplicate(a[0..n-1]) → duplicate:
    for i from 0 to n-1:
        idx ← abs(a[i]) - 1     // map value to index
        if a[idx] < 0:
            return abs(a[i])    // already marked → this value appeared before
        a[idx] ← -a[idx]        // mark as visited
    return -1                   // no duplicate (problem guarantees one exists)


// ─── Pattern C: Rotate Array Right by k ──────────────────────────────────
// Three-reversal trick. k is normalised to [0, n-1].

function rotate(a[0..n-1], k):
    k ← k mod n
    if k == 0: return
    reverse(a, 0, n-1)
    reverse(a, 0, k-1)
    reverse(a, k, n-1)

function reverse(a, l, r):
    while l < r:
        swap(a[l], a[r])
        l ← l + 1
        r ← r - 1
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ─────────────────────────────────────────────────────────────────────────────
// Pattern A: Remove Duplicates from Sorted Array (LeetCode 26)
// Returns new length. First k elements of a[] hold the unique values.
// O(n) time, O(1) space.
// ─────────────────────────────────────────────────────────────────────────────
int remove_duplicates(vector<int>& a) {
    if (a.empty()) return 0;

    int write = 1;                      // a[0] is unconditionally kept
    for (int read = 1; read < (int)a.size(); ++read) {
        if (a[read] != a[write - 1]) {  // new value: different from last kept
            a[write++] = a[read];
        }
        // else: duplicate — read pointer advances, write pointer stays
    }
    return write;
}

// ─────────────────────────────────────────────────────────────────────────────
// Pattern A variant: Move Zeroes (LeetCode 283)
// Non-zero elements packed to front in original relative order; zeros to tail.
// O(n) time, O(1) space.
// ─────────────────────────────────────────────────────────────────────────────
void move_zeroes(vector<int>& a) {
    int write = 0;
    for (int read = 0; read < (int)a.size(); ++read) {
        if (a[read] != 0) {
            a[write++] = a[read];
        }
    }
    // Zero-fill the tail
    fill(a.begin() + write, a.end(), 0);
}

// ─────────────────────────────────────────────────────────────────────────────
// Pattern B: Find the Duplicate Number (LeetCode 287, sign-flip variant)
// Array contains n+1 integers in [1..n]. Find one duplicate. Restores array.
// O(n) time, O(1) space. NOTE: Modifies a[] temporarily (restores at end).
// ─────────────────────────────────────────────────────────────────────────────
int find_duplicate_sign(vector<int>& a) {
    int duplicate = -1;
    for (int i = 0; i < (int)a.size(); ++i) {
        int idx = abs(a[i]) - 1;        // value v maps to index v-1
        if (a[idx] < 0) {               // already marked → a[i] is the duplicate
            duplicate = abs(a[i]);
            break;
        }
        a[idx] = -a[idx];               // mark index as visited
    }
    // Restore array (problem may require original values after return)
    for (int& x : a) x = abs(x);
    return duplicate;
}

// ─────────────────────────────────────────────────────────────────────────────
// Pattern C: Rotate Array (LeetCode 189)
// Rotates array right by k positions. In-place, O(n) time, O(1) space.
// ─────────────────────────────────────────────────────────────────────────────
void rotate(vector<int>& a, int k) {
    int n = a.size();
    k %= n;
    if (k == 0) return;
    // Three-reversal: reverse all → reverse [0,k-1] → reverse [k,n-1]
    auto rev = [&](int l, int r) {
        while (l < r) swap(a[l++], a[r--]);
    };
    rev(0, n - 1);
    rev(0, k - 1);
    rev(k, n - 1);
}

// ─────────────────────────────────────────────────────────────────────────────
// Pattern B extended: Find All Disappeared Numbers (LeetCode 448)
// Returns all values in [1..n] not present in the array.
// Uses sign-flip to mark presence. O(n) time, O(1) auxiliary space.
// ─────────────────────────────────────────────────────────────────────────────
vector<int> find_disappeared_numbers(vector<int>& a) {
    int n = a.size();

    // Mark each seen value by negating the element at its index.
    for (int i = 0; i < n; ++i) {
        int idx = abs(a[i]) - 1;        // value maps to index
        if (a[idx] > 0) a[idx] = -a[idx];
    }

    // Positions still positive → those values (index+1) never appeared.
    vector<int> result;
    for (int i = 0; i < n; ++i) {
        if (a[i] > 0) result.push_back(i + 1);
    }
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Test driver
// ─────────────────────────────────────────────────────────────────────────────
int main() {
    // remove_duplicates
    vector<int> a = {1, 1, 2, 3, 3, 4};
    int k = remove_duplicates(a);
    assert(k == 4);
    assert((vector<int>(a.begin(), a.begin() + k) == vector<int>{1, 2, 3, 4}));

    // move_zeroes
    vector<int> b = {0, 1, 0, 3, 12};
    move_zeroes(b);
    assert((b == vector<int>{1, 3, 12, 0, 0}));

    // find_duplicate_sign
    vector<int> c = {1, 3, 4, 2, 2};
    assert(find_duplicate_sign(c) == 2);
    // Verify restoration
    sort(c.begin(), c.end());
    assert((c == vector<int>{1, 2, 2, 3, 4}));

    // rotate
    vector<int> d = {1, 2, 3, 4, 5, 6, 7};
    rotate(d, 3);
    assert((d == vector<int>{5, 6, 7, 1, 2, 3, 4}));
    rotate(d, 7);   // full rotation → no change
    assert((d == vector<int>{5, 6, 7, 1, 2, 3, 4}));

    // find_disappeared_numbers
    vector<int> e = {4, 3, 2, 7, 8, 2, 3, 1};
    auto missing = find_disappeared_numbers(e);
    assert((missing == vector<int>{5, 6}));

    cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
def remove_duplicates(a: list[int]) -> int:
    """
    Remove duplicates from sorted array in-place.
    Returns k: first k elements are the unique values.

    Invariant: a[0..write-1] is the deduplicated prefix at all times.

    Time:  O(n)
    Space: O(1) auxiliary
    """
    if not a:
        return 0

    write = 1                           # a[0] is always kept
    for read in range(1, len(a)):
        if a[read] != a[write - 1]:     # strictly new value
            a[write] = a[read]
            write += 1
    return write


def move_zeroes(a: list[int]) -> None:
    """
    Move all zeros to end of array, preserving relative order of non-zeros.
    Modifies a in-place. Returns None.

    Time:  O(n)
    Space: O(1)
    """
    write = 0
    for read in range(len(a)):
        if a[read] != 0:
            a[write] = a[read]
            write += 1
    # Fill the tail with zeros
    for i in range(write, len(a)):
        a[i] = 0


def find_disappeared_numbers(a: list[int]) -> list[int]:
    """
    Find all values in [1..n] not present in a (length n, values in [1..n]).
    Uses sign-flip encoding: negate a[v-1] to mark value v as seen.

    Time:  O(n)
    Space: O(1) auxiliary (output list is not auxiliary)
    """
    n = len(a)

    # Marking pass: for each value v, negate a[v-1] to record v's presence.
    for i in range(n):
        idx = abs(a[i]) - 1         # abs() because a[i] may already be negated
        if a[idx] > 0:
            a[idx] = -a[idx]

    # Collection pass: positive entries at index i mean value i+1 never appeared.
    result = [i + 1 for i in range(n) if a[i] > 0]

    # Restore array for caller (good practice; problem may not require it)
    for i in range(n):
        a[i] = abs(a[i])

    return result


def rotate(a: list[int], k: int) -> None:
    """
    Rotate array right by k positions in-place. Three-reversal method.

    Why it works:
      Original:      [1, 2, 3 | 4, 5, 6, 7]  (split at n-k)
      Reverse all:   [7, 6, 5, 4, 3, 2, 1]
      Reverse [0,k): [5, 6, 7, 4, 3, 2, 1]
      Reverse [k,n): [5, 6, 7, 1, 2, 3, 4]  ← correct rotation

    Time:  O(n)
    Space: O(1)
    """
    n = len(a)
    k %= n
    if k == 0:
        return

    def reverse(l: int, r: int) -> None:
        while l < r:
            a[l], a[r] = a[r], a[l]
            l += 1
            r -= 1

    reverse(0, n - 1)
    reverse(0, k - 1)
    reverse(k, n - 1)


# ─── Why three reversals work — mathematical derivation ───────────────────
# Right-rotate by k means element at position i goes to position (i+k) % n.
# Equivalently: the last k elements become the first k elements.
#
# Reverse all n elements: element at i goes to n-1-i.
# Reverse first k:        element at i (i < k) goes to k-1-i.
#   Net after both:       originally at n-k+j, now at j. ✓ (first k slots filled)
# Reverse last n-k:       element at k+i goes to n-1-i.
#   Net after all three:  originally at j (j < n-k), now at k+j. ✓


# ─── Naive out-of-place versions for correctness cross-checking ───────────
def remove_duplicates_naive(a: list[int]) -> int:
    seen = sorted(set(a))
    for i, v in enumerate(seen):
        a[i] = v
    return len(seen)


def rotate_naive(a: list[int], k: int) -> None:
    n = len(a)
    k %= n
    tmp = a[-k:] + a[:-k]
    a[:] = tmp


# ─── Tests ────────────────────────────────────────────────────────────────
if __name__ == "__main__":
    # remove_duplicates
    a = [1, 1, 2, 3, 3, 4]
    k = remove_duplicates(a)
    assert k == 4 and a[:k] == [1, 2, 3, 4], f"Got {a[:k]}"

    # edge cases
    a = []
    assert remove_duplicates(a) == 0
    a = [7]
    assert remove_duplicates(a) == 1

    # move_zeroes
    b = [0, 1, 0, 3, 12]
    move_zeroes(b)
    assert b == [1, 3, 12, 0, 0], f"Got {b}"

    b = [0, 0, 0]
    move_zeroes(b)
    assert b == [0, 0, 0]

    # find_disappeared_numbers
    c = [4, 3, 2, 7, 8, 2, 3, 1]
    assert find_disappeared_numbers(c) == [5, 6]

    # rotate
    d = [1, 2, 3, 4, 5, 6, 7]
    d_ref = d[:]
    rotate(d, 3)
    rotate_naive(d_ref, 3)
    assert d == d_ref == [5, 6, 7, 1, 2, 3, 4], f"Got {d}"

    rotate(d, 0)        # no-op
    rotate(d, 7)        # full rotation
    assert d == [5, 6, 7, 1, 2, 3, 4]

    print("All tests passed.")
```

### Diagram 1 — Write Pointer Invariant (Remove Duplicates)

Array: `a = [1, 1, 2, 3, 3, 4]`

```
State at each step. W = write pointer, R = read pointer.
Shaded region [0, W) is the committed answer. Region [R, n) is unread input.

Initial:
  [ 1,  1,  2,  3,  3,  4 ]
    W
    R

Step R=1: a[1]=1 == a[W-1]=1 → duplicate, skip. W stays.
  [ 1,  1,  2,  3,  3,  4 ]
    W   R

Step R=2: a[2]=2 ≠ a[W-1]=1 → new value. Write a[W]=2, advance W.
  [ 1,  2,  2,  3,  3,  4 ]
         W   R
    ^^^^
    committed

Step R=3: a[3]=3 ≠ a[W-1]=2 → new. Write, advance W.
  [ 1,  2,  3,  3,  3,  4 ]
              W   R
    ^^^^^^^^^
    committed

Step R=4: a[4]=3 == a[W-1]=3 → duplicate, skip.
  [ 1,  2,  3,  3,  3,  4 ]
              W       R

Step R=5: a[5]=4 ≠ a[W-1]=3 → new. Write, advance W.
  [ 1,  2,  3,  4,  3,  4 ]
                   W       R(done)
    ^^^^^^^^^^^^
    committed answer (k=4)

Return k=4. Caller uses a[0..3] = [1, 2, 3, 4].
Elements at indices 4+ are irrelevant.

KEY INVARIANT: W ≤ R at every step.
W only advances when W < R (strict inequality, no overwrite risk).
When W == R: we are writing a[R] to a[W=R] — same cell, a no-op.
```

```
    reversed

Step 3: Reverse last n-k=4 elements
  [ 5, 6, 7, 1, 2, 3, 4 ]
             ↑↑↑↑↑↑↑↑↑
             reversed

Result: [5, 6, 7, 1, 2, 3, 4] ✓

Why no extra space? Each reversal is a sequence of two-pointer swaps.
Each swap moves exactly 2 elements. Total swaps = n/2 per reversal × 3 = 3n/2.
No element is stored outside the array at any point.
```

## 7. Common Variations & Extensions

### Variation 1 — Remove Duplicates II (Allow at Most k Duplicates)

Generalise Pattern A: instead of checking `a[read] != a[write-1]`, check `a[read] != a[write-k]`. The write pointer now allows up to `k` copies of each value before skipping. This single-line change handles the entire family of "keep at most k" problems (LeetCode 80). The invariant is the same; only the look-back distance changes.

### Variation 2 — Dutch National Flag (Three-Way Partition)

When the partition has three categories (less than, equal to, greater than a pivot) rather than two (keep/discard), you need three pointers: `lo`, `mid`, `hi`. This is [[18.Three pointers — Dutch National Flag, 3Sum]] and is the in-place partition step of quicksort — see [[44.Quicksort — partition, pivot selection, expected O(n log n)]]. The write pointer generalises to a three-boundary system.

### Variation 3 — Cyclic Sort

For arrays where values are in `[1..n]` and the goal is to sort in-place in O(n), cyclic sort places each value at its correct index by swapping: while `a[i] != i+1`, swap `a[i]` with `a[a[i]-1]`. Each swap places at least one element correctly, so the total number of swaps is at most n. After sorting, all misplaced positions reveal missing or duplicate values. This is a strict upgrade over the sign-flip trick — it sorts the array rather than just detecting anomalies, and connects directly to the cycle-detection idea in [[17.Same-direction two pointers — fast and slow]].

### Variation 4 — In-Place Matrix Transposition and Rotation

Rotating an n×n matrix 90° in-place uses the same three-reversal idea generalised to 2D: reverse the rows, then transpose (swap `a[i][j]` with `a[j][i]` for `i < j`). Transposition is an in-place operation on the upper triangle. For non-square matrices, true in-place transposition requires following permutation cycles — a harder variant that connects to [[05.Cyclic traversal and modular indexing]].

## 9. CP Contest Application

### Typical Problem Structure

**Codeforces Div. 2 B / Div. 3 C archetype:**

> "Given an array of n integers where each value is in [1..n], determine if all values are distinct and identify any duplicates or missing values. Memory limit: 4MB."

At n = 10⁶, a boolean visited array uses 1MB and is acceptable. But at n = 10⁷ with a 4MB limit, you cannot afford it. The sign-flip trick uses the input array as the visited array, consuming 0 extra bytes. This is the O(1) space solution that fits within the memory constraint.

**Harder variant — Div. 2 C with ordering constraint:**

> "Rearrange the array so that even-indexed positions contain even values and odd-indexed positions contain odd values. Do it in-place."

This is a two-pointer partition problem: one pointer scans from the left for a misplaced even value, one scans from the right for a misplaced odd value (or vice versa), and they swap. The write pointer pattern generalises to a bidirectional scan. See [[16.Opposite-end two pointers — sorted array problems]].

### Time Limits and Optimisation Tricks

**Constant factor:** In-place algorithms have excellent cache behaviour — they access a single contiguous array with no pointer chasing. Expect ~3–5× faster wall-clock time versus equivalent algorithms with auxiliary arrays of the same size, due to cache line reuse.

**Swap cost:** `std::swap` in C++ with `-O2` compiles to three register moves for integers — essentially free. For large structs or strings, swapping is expensive. In those cases, sort indices rather than the data itself, then permute in-place following permutation cycles (O(n) time, O(1) extra space beyond a visited-bit per element, which can itself be encoded in a sign-flip if values permit).

**The `fill` vs loop debate for zero-filling the tail:** After the write pointer finishes, `std::fill(a.begin() + write, a.end(), 0)` is the canonical C++ idiom. It compiles to `memset` for trivial types under `-O2`, which uses SIMD instructions and is 4–8× faster than a scalar loop. Use it.
