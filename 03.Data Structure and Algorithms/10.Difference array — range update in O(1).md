# 10. Difference Array — Range Update in O(1)

> _"Instead of painting every wall in a hallway, just mark the start and the end — and derive the painting later."_

---

## The Problem It Solves

You have an array `A` of `n` numbers. You receive `q` queries of the form:

> **"Add `v` to every element from index `l` to index `r` (inclusive)."**

Then, after all updates, you are asked to report the final array.

**Naïve approach:** For each query, loop from `l` to `r` and add `v`. That is O(n) per query → **O(n · q)** total. For n = 10⁵ and q = 10⁵, this is 10¹⁰ operations. Too slow.

**Difference array approach:** Each update in **O(1)**. Final reconstruction in **O(n)**. Total: **O(n + q)**. That is the trick.

---

## Core Idea — The Difference Array

Define the **difference array** `D` of `A` as:

$$D[i] = A[i] - A[i-1], \quad \text{with } D[0] = A[0]$$

Observe that `A` is the **prefix sum** of `D`:

$$A[i] = D[0] + D[1] + \cdots + D[i] = \sum_{k=0}^{i} D[k]$$

This is the key duality:

|Direction|Operation|
|---|---|
|`A → D`|Take differences (derivative)|
|`D → A`|Take prefix sums (integral)|

---

## The O(1) Range Update

Suppose we want: **Add `v` to A[l], A[l+1], ..., A[r]**.

What does this do to `D`?

- `D[l]` increases by `v` (because `A[l]` jumped but `A[l-1]` did not).
- `D[r+1]` decreases by `v` (because `A[r+1]` did not jump but `A[r]` did).
- All other `D[i]` are unchanged — the delta cancels internally.

So the **entire range update reduces to exactly two point updates on D**:

```
D[l]   += v
D[r+1] -= v      (if r+1 < n)
```

After all queries, reconstruct `A` by taking the prefix sum of `D`:

```
A[i] = D[0] + D[1] + ... + D[i]
```

That is it. No loop over the range. No touching A during updates.

---

## Step-by-Step Example

**Initial array:** `A = [3, 1, 4, 1, 5]` (indices 0–4)

**Build D:**

```
D[0] = A[0]           = 3
D[1] = A[1] - A[0]   = 1 - 3 = -2
D[2] = A[2] - A[1]   = 4 - 1 =  3
D[3] = A[3] - A[2]   = 1 - 4 = -3
D[4] = A[4] - A[3]   = 5 - 1 =  4

D = [3, -2, 3, -3, 4]
```

**Query 1:** Add `2` to range `[1, 3]`

```
D[1] += 2   →  D[1] = 0
D[4] -= 2   →  D[4] = 2

D = [3, 0, 3, -3, 2]
```

**Query 2:** Add `-1` to range `[0, 2]`

```
D[0] += -1   →  D[0] = 2
D[3] -= -1   →  D[3] = -2

D = [2, 0, 3, -2, 2]
```

**Reconstruct A via prefix sums of D:**

```
A[0] = 2
A[1] = 2 + 0  = 2
A[2] = 2 + 3  = 5
A[3] = 5 + (-2) = 3
A[4] = 3 + 2  = 5

Final A = [2, 2, 5, 3, 5]
```

**Verify manually:**

- Start: [3, 1, 4, 1, 5]
- Add 2 to [1,3]: [3, 3, 6, 3, 5]
- Add -1 to [0,2]: [2, 2, 5, 3, 5] ✓

## Implementation

### Python

```python
def apply_queries(n, queries):
    """
    n       : length of original array (all zeros here)
    queries : list of (l, r, v) — add v to A[l..r]
    """
    D = [0] * (n + 1)          # extra cell to absorb D[r+1] when r = n-1

    for l, r, v in queries:
        D[l]   += v
        D[r+1] -= v             # safe because len(D) = n+1

    # Prefix sum to reconstruct A
    A = [0] * n
    running = 0
    for i in range(n):
        running += D[i]
        A[i] = running

    return A


# Example
A = apply_queries(5, [(1, 3, 2), (0, 2, -1)])
print(A)   # [2, 2, 5, 3, 5]
```

### NumPy (vectorised reconstruction)

```python
import numpy as np

def apply_queries_np(n, queries):
    D = np.zeros(n + 1, dtype=np.int64)
    for l, r, v in queries:
        D[l]   += v
        D[r+1] -= v
    A = np.cumsum(D[:n])        # prefix sum = reconstruction
    return A

print(apply_queries_np(5, [(1, 3, 2), (0, 2, -1)]))
# [2 2 5 3 5]
```

`np.cumsum` is the vectorised prefix sum — exactly the reconstruction step.

## Complexity

|Step|Time|Space|
|---|---|---|
|Build D|O(n)|O(n)|
|Each query|**O(1)**|—|
|Reconstruct A|O(n)|O(n)|
|**Total**|**O(n + q)**|**O(n)**|

Compare this to the naïve O(n · q). For n = q = 10⁵:

- Naïve: ~10¹⁰ ops (10+ seconds)
- Difference array: ~2 × 10⁵ ops (microseconds)

---

## Formal Proof of Correctness

**Claim:** After doing `D[l] += v` and `D[r+1] -= v`, the prefix sum `prefix[i] = Σ D[0..i]` satisfies `prefix[i] = A[i] + v` for `l ≤ i ≤ r`, and `prefix[i] = A[i]` otherwise.

**Proof:**

For `i < l`: neither `D[l]` nor `D[r+1]` has been reached in the prefix sum yet. No change.

For `l ≤ i ≤ r`: `D[l]` has been summed (contributing `+v`), but `D[r+1]` has not. Net effect: `+v`. ✓

For `i > r`: both `D[l] += v` and `D[r+1] -= v` have been accumulated. Net effect: `v − v = 0`. ✓

The update is perfectly self-cancelling outside the range. That is the elegance: it is a **localised perturbation in D-space** that propagates exactly as a uniform additive shift in A-space over the range `[l, r]`. □

## 2D Difference Array (Extension)

For a 2D grid where you want to add `v` to all cells in the rectangle `(r1, c1)` to `(r2, c2)`:

```python
# 2D difference array D of size (m+1) x (n+1)
D[r1][c1]     += v
D[r2+1][c1]   -= v
D[r1][c2+1]   -= v
D[r2+1][c2+1] += v   # inclusion-exclusion correction
```

Reconstruct via 2D prefix sums (row-wise then column-wise). Each 2D query is still **O(1)** — four point updates.

```python
import numpy as np

def apply_2d_queries(m, n, queries):
    D = np.zeros((m + 1, n + 1), dtype=np.int64)
    for r1, c1, r2, c2, v in queries:
        D[r1][c1]     += v
        D[r2+1][c1]   -= v
        D[r1][c2+1]   -= v
        D[r2+1][c2+1] += v
    # Reconstruct: prefix sum along rows, then columns
    return np.cumsum(np.cumsum(D[:m, :n], axis=0), axis=1)
```

## Connection to AI / ML / Deep Learning

The difference array is not merely a competitive programming trick. It appears in several ML contexts:

### 1. Segment-level label encoding

When building training data for sequence models (NER, token classification), labels are often defined over spans: "tokens 5–12 are entity X." A difference array lets you mark all `q` such spans in O(q) and fill the label array in O(n) — faster than looping over every span.

### 2. Attention masks and padding masks

In Transformer batching, you mark valid token ranges per sequence. With a difference array, you set the mask for each sequence in O(1) per sequence, then prefix-sum to materialise the full batch mask. In NumPy this is `np.cumsum(D, axis=-1)`.

### 3. Reward shaping in Reinforcement Learning

When a reward `v` is assigned to a trajectory from step `l` to `r` (e.g., discounted returns over a window), the difference array pattern underlies efficient batch computation of advantage estimates.

### 4. Histogram construction

`np.bincount` is conceptually related — a special case where each "range" is of width 1 and the reconstruction is O(n). For variable-width bin updates, the difference array is the right generalisation.

### 5. Feature engineering for time-series

Adding a constant offset to a time window (e.g., "sensor was active between t=100 and t=400, add its baseline") is a range-add problem. Done for thousands of sensors, a difference array makes this O(n + q) instead of O(n · q).

## Variants and Related Structures

|Technique|Supports|Query|Update|
|---|---|---|---|
|Difference array|Range add, point query|O(n) to reconstruct|O(1)|
|Prefix sum array|Point update, range sum query|O(1)|O(n) rebuild|
|Fenwick tree (BIT)|Both|O(log n)|O(log n)|
|Segment tree with lazy propagation|Both|O(log n)|O(log n)|

Use the difference array when: all updates come before all queries (offline setting). Use a Fenwick tree or segment tree when updates and queries are interleaved (online setting).

## Common Mistakes

```python
# Mistake 1: Forgetting the extra cell
D = [0] * n          # WRONG — D[r+1] crashes when r = n-1
D = [0] * (n + 1)    # correct

# Mistake 2: Reconstructing before all queries are applied
# Wrong order:
for l, r, v in queries:
    D[l] += v; D[r+1] -= v
    A = prefix_sum(D)    # reconstructing inside the loop — wrong

# Correct order:
for l, r, v in queries:
    D[l] += v; D[r+1] -= v
A = prefix_sum(D)        # reconstruct ONCE at the end

# Mistake 3: Off-by-one on r+1
D[r] -= v      # WRONG — this subtracts one cell too early
D[r+1] -= v    # correct — cancellation begins AFTER index r

# Mistake 4: Querying the middle state
# The difference array D is NOT A. You cannot read D[i] and expect A[i].
# You must prefix-sum D to get A. Never read D directly as the answer.
```

## Summary

|Concept|One-liner|
|---|---|
|What is D|D[i] = A[i] − A[i−1]; the discrete derivative of A|
|Range update|D[l] += v, D[r+1] -= v (two writes, O(1))|
|Reconstruction|A = prefix_sum(D) (one O(n) pass at the end)|
|Why it works|+v at l propagates forward in prefix sums; −v at r+1 cancels it|
|When to use|Multiple range-add queries, queries answered offline|
|NumPy idiom|`np.cumsum(D[:n])` is the reconstruction|
|2D version|Four corner updates; 2D prefix sum to reconstruct|

The difference array is the simplest instance of a broader principle: **work in the derivative space, accumulate cheaply, integrate once at the end.**
