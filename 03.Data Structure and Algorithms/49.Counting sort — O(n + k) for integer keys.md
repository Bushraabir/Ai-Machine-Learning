## 1. Intuition First

### The Core Idea

Every comparison-based sort has a fundamental lower bound of O(n log n). This is not a limitation of clever algorithm design — it is a mathematical fact provable from information theory. A sort of n elements must distinguish between n! possible orderings; each binary comparison reveals at most one bit of information; therefore at least log₂(n!) = O(n log n) comparisons are required.

Counting sort escapes this bound by not making comparisons at all. Instead of asking "is a less than b?", it asks "how many elements have value exactly x?" — and answers that question for every x in the key range simultaneously using a single pass over the input.

The mechanism is embarrassingly simple. Given an array of integers with values in [0, k−1], allocate a count array of size k. Make one pass over the input, incrementing `count[x]` for each element x. Then reconstruct the sorted output: emit `count[0]` copies of 0, then `count[1]` copies of 1, and so on. That is the entire algorithm — two passes, no comparisons.

The prefix-sum variant (the one that preserves associated data and maintains stability) adds one more phase: convert counts to starting positions, then place each original element into its correct output index. This is the version used as a subroutine in radix sort and in any setting where elements carry satellite data beyond their key.

### Why This Exists

Comparison sorts treat keys as opaque objects with one operation: compare. Counting sort treats keys as integers with a richer operation: use them directly as array indices. This is only possible when the key range k is known and bounded. When k = O(n), the entire sort runs in O(n) — a qualitative improvement over O(n log n).

The canonical use case: sort n students by exam score where scores are integers in [0, 100]. Here k = 101, n could be millions. Every comparison sort takes O(n log n). Counting sort takes O(n + 101) = O(n).

### The "Aha" Moment

The prefix-sum phase is the non-obvious piece. After counting, `count[x]` tells you how many elements have value x. After prefix-summing, `count[x]` tells you how many elements have value _at most_ x — equivalently, the index in the output array where the _last_ copy of value x should land. Decrementing count[x] before each placement gives consecutive output positions for repeated values. This transforms a frequency table into a direct address table, and that transformation is what allows the algorithm to place every element in O(1) without any comparisons or searching.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

Counting sort appears in contests as both a standalone sort and as a subroutine. Recognising when the key range is small enough to use it is a recurring optimisation decision.

When it appears:

- Sorting arrays where values are known to be bounded integers: scores, ranks, ages, character ASCII values, digit values
- As the inner sort in a hand-rolled radix sort for large-n string or integer problems
- Sorting characters in a string — the character frequency array is a degenerate counting sort over the ASCII alphabet (k = 256)
- Frequency-based problems that require sorted output: "output all elements sorted by their frequency of occurrence"

Pattern signal: when n is large but the value range k is small (k much less than n log n), counting sort is the correct tool. Specifically, when k is O(n), counting sort beats any comparison sort. When k is O(n log n), they are comparable. When k is O(n²) or larger, counting sort is worse.

Common trap: forgetting to handle negative integers. The standard formulation assumes keys in [0, k−1]. For keys in [min, max], shift all values by subtracting min, making the effective range [0, max−min]. Forgetting this shift produces an array index out of bounds.

A second trap: using the simplified "emit copies" version on problems that require tracking original positions or preserving satellite data. That version loses all positional information and is therefore useless for radix sort subroutine use and for any problem requiring stable output. Always implement the prefix-sum variant.

### Machine Learning / AI

**Histogram computation in image preprocessing:** Image histograms — used in histogram equalisation, normalisation, and contrast adjustment — are exactly the counting phase of counting sort. For an 8-bit grayscale image, k = 256. Computing the histogram is one pass over all pixels incrementing `count[pixel_value]`. The prefix sum of that histogram gives the cumulative distribution function used for equalisation. OpenCV's `cv2.calcHist` and PIL's `Image.histogram()` both implement this pattern internally.

**Tokeniser vocabulary frequency counting:** Building a BPE (Byte-Pair Encoding) tokeniser or a word-level vocabulary requires counting token frequencies across a corpus. The counting phase of counting sort is the frequency pass. When the vocabulary is bounded (e.g., character-level models with k = 256, or models with a fixed vocabulary of size 50,000), this is a direct application of the count array pattern. Hugging Face's tokenisers library uses this for frequency accumulation before merge rule selection.

**Bucket assignment in quantisation:** Post-training quantisation maps floating-point weights to integers in a fixed range (e.g., INT8: k = 256). After mapping, counting sort can sort the quantised weights in O(n + 256) = O(n). More importantly, the count array gives the weight distribution across quantisation buckets directly — which is used for calibration statistics. Understanding that the count array is a discrete probability mass function, and the prefix sum is its CDF, makes the connection between counting sort and quantisation analysis immediate.

**Label frequency computation in class-imbalanced datasets:** `sklearn`'s `compute_class_weight` and `np.bincount` are counting sort's count phase applied to label arrays. `np.bincount(y)` takes a label array y with integer values in [0, k−1] and returns an array of counts — identical to the count phase of counting sort. For datasets with millions of samples and a modest number of classes (k in the hundreds), this runs in O(n) rather than O(n log n). The result feeds into loss weighting, oversampling ratios, and stratified sampling — all of which depend on getting exact class frequencies cheaply.

**`np.bincount` as production counting sort:** `np.bincount(x, weights=None, minlength=0)` is the NumPy implementation of counting sort's count phase, running at C speed. For the full sort (producing sorted indices), `np.argsort(x, kind='stable')` on integer arrays internally uses a counting-sort-based algorithm when the range is detected as small. Knowing when NumPy switches strategies allows deliberate exploitation of the fast path.

## 3. Algorithm / Pattern

### Two Variants

**Variant 1 — Simple (no satellite data, destructive):** Allocate count array. Count occurrences. Overwrite input with sorted values by emitting each value count[x] times. O(n + k) time, O(k) space. Use when elements are their own keys with no associated data and output order within equal keys does not matter.

**Variant 2 — Stable with output array (the production variant):** Allocate count array. Count occurrences. Prefix-sum the count array. Place each input element into the output array using count as a position table. O(n + k) time, O(n + k) space. Use when elements carry satellite data or when stability is required (e.g., as a radix sort subroutine).

### Step-by-Step Logic

Phase 1 — Count: one forward pass over input. For each element, increment count[key(element)].

Phase 2 — Prefix sum: one forward pass over count. Replace each count[i] with the cumulative sum of count[0] through count[i]. After this pass, count[x] = number of elements with key at most x = the exclusive upper bound of where x-keyed elements go in the output.

Phase 3 — Place (right to left for stability): one backward pass over input. For each element, decrement count[key(element)], then place the element at output[count[key(element)]]. The backward pass ensures that among elements with equal keys, the one appearing earlier in the input gets the earlier output position — which is exactly the definition of stability.

### When to Use vs When to Avoid

Use counting sort when:

- Keys are non-negative integers (or mappable to non-negative integers by a linear shift)
- The key range k is O(n) or smaller
- Stability is required (use the prefix-sum variant)
- The sort is a subroutine inside radix sort

Avoid counting sort when:

- Keys are floating-point numbers, strings, or arbitrary objects
- The key range k is much larger than n (e.g., sorting 100 elements with values up to 10⁹ — the count array would have 10⁹ entries)
- Memory is severely constrained and k is large
- The sort must be in-place (counting sort requires O(n + k) space)

### Complexity

|Phase|Time|Space|
|---|---|---|
|Count|O(n)|O(k)|
|Prefix sum|O(k)|O(1) additional|
|Place|O(n)|O(n) output array|
|Total|O(n + k)|O(n + k)|

The O(n + k) bound is tight. When k = O(n), this is O(n). When k = O(n log n), this matches comparison sorts. When k = O(n²), it is worse.

## 4. Pseudocode

### Variant 1 — Simple (in-place overwrite, no satellite data)

```
COUNTING_SORT_SIMPLE(arr, k):
    # arr contains integers in [0, k-1]
    count ← array of zeros, length k

    # Phase 1: count occurrences
    for x in arr:
        count[x] ← count[x] + 1

    # Phase 2: overwrite arr with sorted values
    pos ← 0
    for x from 0 to k-1:
        for freq from 1 to count[x]:
            arr[pos] ← x
            pos ← pos + 1
    # Output is arr itself, modified in place
    # This variant is NOT stable — original positions are lost
```

### Variant 2 — Stable with output array (production variant)

```
COUNTING_SORT_STABLE(arr, k):
    # arr is an array of records; key(r) returns integer in [0, k-1]
    n ← len(arr)
    count ← array of zeros, length k
    output ← array of length n

    # Phase 1: count key occurrences
    for i from 0 to n-1:
        count[key(arr[i])] ← count[key(arr[i])] + 1

    # Phase 2: prefix sum
    # After this: count[x] = number of elements with key <= x
    #           = exclusive upper bound of x's block in output
    for i from 1 to k-1:
        count[i] ← count[i] + count[i-1]

    # Phase 3: place — RIGHT TO LEFT for stability
    # Iterating backward ensures that among elements with equal keys,
    # the earlier-appearing element (smaller original index) gets the
    # earlier output position.
    for i from n-1 DOWN TO 0:
        k_i ← key(arr[i])
        count[k_i] ← count[k_i] - 1       # decrement BEFORE indexing
        output[count[k_i]] ← arr[i]

    return output
```

Edge cases:

- All elements equal: count[x] = n for one x; prefix sum puts all in positions 0..n-1 correctly.
- k much larger than n: algorithm is correct but wasteful; the count array is mostly zeros.
- Negative keys: shift all keys by subtracting min(arr) before applying the algorithm; k becomes max(arr) - min(arr) + 1.
- n = 0: both loops produce no iterations; output is an empty array.

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <algorithm>
#include <iostream>
#include <numeric>
#include <vector>

// Variant 1: simple in-place overwrite, integer keys in [0, k-1].
// Destroys satellite data; not stable. Use only when elements are their own keys.
// Time: O(n + k)   Space: O(k)
void counting_sort_simple(std::vector<int>& arr, int k) {
    std::vector<int> count(k, 0);

    for (int x : arr)
        count[x]++;

    int pos = 0;
    for (int x = 0; x < k; ++x)
        while (count[x]-- > 0)
            arr[pos++] = x;
}

// Variant 2: stable sort preserving satellite data.
// Elements are pairs (key, value); keys in [0, k-1].
// Time: O(n + k)   Space: O(n + k)
template <typename T>
std::vector<T> counting_sort_stable(const std::vector<T>& arr, int k,
                                    std::function<int(const T&)> key_fn) {
    int n = static_cast<int>(arr.size());
    std::vector<int> count(k, 0);
    std::vector<T>   output(n);

    // Phase 1: count
    for (const auto& elem : arr)
        count[key_fn(elem)]++;

    // Phase 2: prefix sum — count[x] becomes the exclusive upper bound
    // of positions assigned to key x.
    std::partial_sum(count.begin(), count.end(), count.begin());

    // Phase 3: place right to left (stability)
    for (int i = n - 1; i >= 0; --i) {
        int k_i = key_fn(arr[i]);
        output[--count[k_i]] = arr[i];
    }

    return output;
}

// Handling negative keys: shift by min value.
// Time: O(n + (max - min))   Space: O(max - min + 1)
void counting_sort_with_negatives(std::vector<int>& arr) {
    if (arr.empty()) return;

    int lo = *std::min_element(arr.begin(), arr.end());
    int hi = *std::max_element(arr.begin(), arr.end());
    int k  = hi - lo + 1;

    std::vector<int> count(k, 0);
    for (int x : arr)
        count[x - lo]++;           // shift by lo

    int pos = 0;
    for (int i = 0; i < k; ++i)
        while (count[i]-- > 0)
            arr[pos++] = i + lo;   // unshift
}

// np.bincount equivalent: just the count phase, no sort output.
// Useful when you only need frequencies.
std::vector<int> bincount(const std::vector<int>& arr, int k) {
    std::vector<int> count(k, 0);
    for (int x : arr)
        count[x]++;
    return count;
}

int main() {
    // Simple variant
    std::vector<int> v = {3, 1, 4, 1, 5, 9, 2, 6, 5, 3};
    counting_sort_simple(v, 10);
    for (int x : v) std::cout << x << ' ';
    std::cout << '\n';
    // 1 1 2 3 3 4 5 5 6 9

    // Stable variant with satellite data
    using Record = std::pair<int, std::string>;  // (grade, name)
    std::vector<Record> records = {{3,"C"},{1,"A"},{2,"B"},{1,"D"},{3,"E"}};
    auto result = counting_sort_stable<Record>(records, 4,
        [](const Record& r) { return r.first; });
    for (const auto& [k, v] : result)
        std::cout << k << ':' << v << ' ';
    std::cout << '\n';
    // 1:A 1:D 2:B 3:C 3:E   (stable: A before D, C before E)

    // Negative keys
    std::vector<int> neg = {-3, 1, -1, 4, 0, 2};
    counting_sort_with_negatives(neg);
    for (int x : neg) std::cout << x << ' ';
    std::cout << '\n';
    // -3 -1 0 1 2 4

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from typing import TypeVar, Callable

T = TypeVar('T')


def counting_sort_simple(arr: list[int], k: int) -> list[int]:
    """
    In-place counting sort for integers in [0, k-1].
    Not stable. Elements are their own keys.
    Time: O(n + k)   Space: O(k)
    """
    count = [0] * k
    for x in arr:
        count[x] += 1

    pos = 0
    for x in range(k):
        for _ in range(count[x]):
            arr[pos] = x
            pos += 1
    return arr


def counting_sort_stable(arr: list[T], k: int,
                         key_fn: Callable[[T], int]) -> list[T]:
    """
    Stable counting sort preserving satellite data.
    key_fn maps each element to an integer in [0, k-1].
    Time: O(n + k)   Space: O(n + k)

    The right-to-left placement loop is what guarantees stability:
    among elements with equal keys, the one with the smaller original
    index ends up at the earlier output position.
    """
    n = len(arr)
    count = [0] * k

    # Phase 1: count
    for elem in arr:
        count[key_fn(elem)] += 1

    # Phase 2: prefix sum
    # count[x] = number of elements with key <= x
    #          = exclusive upper bound of x's block in output
    for i in range(1, k):
        count[i] += count[i - 1]

    # Phase 3: place right to left
    output: list[T] = [None] * n  # type: ignore
    for i in range(n - 1, -1, -1):
        ki = key_fn(arr[i])
        count[ki] -= 1
        output[count[ki]] = arr[i]

    return output


def counting_sort_with_negatives(arr: list[int]) -> list[int]:
    """
    Counting sort extended to handle negative integers.
    Shifts all values into [0, max - min] range.
    Time: O(n + (max - min))   Space: O(max - min + 1)
    """
    if not arr:
        return arr
    lo, hi = min(arr), max(arr)
    k = hi - lo + 1
    count = [0] * k
    for x in arr:
        count[x - lo] += 1
    pos = 0
    for i, freq in enumerate(count):
        for _ in range(freq):
            arr[pos] = i + lo
            pos += 1
    return arr


# np.bincount: the count phase only, at C speed
def demo_numpy_bincount():
    """
    np.bincount is exactly counting sort's count phase.
    For large label arrays in ML, this is the idiomatic tool.
    """
    import numpy as np
    labels = [0, 2, 1, 0, 2, 2, 1, 0]
    counts = np.bincount(labels)
    print(counts)   # [3 2 3] — class 0: 3, class 1: 2, class 2: 3

    # Weighted bincount: sum weights per bucket (e.g., loss per class)
    weights = [0.5, 0.1, 0.2, 0.3, 0.4, 0.6, 0.7, 0.8]
    weighted = np.bincount(labels, weights=weights)
    print(weighted)  # [1.6 0.9 1.1]


if __name__ == '__main__':
    # Simple variant
    arr = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3]
    print(counting_sort_simple(arr, 10))
    # [1, 1, 2, 3, 3, 4, 5, 5, 6, 9]

    # Stable variant
    records = [(3,'C'), (1,'A'), (2,'B'), (1,'D'), (3,'E')]
    result = counting_sort_stable(records, 4, key_fn=lambda r: r[0])
    print(result)
    # [(1,'A'), (1,'D'), (2,'B'), (3,'C'), (3,'E')]  — A before D, C before E

    # Negative keys
    neg = [-3, 1, -1, 4, 0, 2]
    print(counting_sort_with_negatives(neg))
    # [-3, -1, 0, 1, 2, 4]

    demo_numpy_bincount()
```

## 6. Visual Explanation

### Counting Sort on a Concrete Array

```
Input:  [3, 1, 4, 1, 5, 2, 3]     k = 6  (keys in [0, 5])

Phase 1 — Count:
  index:   0  1  2  3  4  5
  count:  [0, 2, 1, 2, 1, 1]
           ^  ^     ^
           |  two 1s   two 3s

Phase 2 — Prefix sum:
  count[0] = 0
  count[1] = 0 + 2 = 2
  count[2] = 2 + 1 = 3
  count[3] = 3 + 2 = 5
  count[4] = 5 + 1 = 6
  count[5] = 6 + 1 = 7

  index:   0  1  2  3  4  5
  count:  [0, 2, 3, 5, 6, 7]
  Interpretation: count[x] = first position AFTER all x-keyed elements.
  Key 1 occupies output positions [0, 2).
  Key 3 occupies output positions [3, 5).

Phase 3 — Place right to left:
  Process arr[6] = 3:  count[3] = 5 -> 4;  output[4] = 3
  Process arr[5] = 2:  count[2] = 3 -> 2;  output[2] = 2
  Process arr[4] = 5:  count[5] = 7 -> 6;  output[6] = 5
  Process arr[3] = 1:  count[1] = 2 -> 1;  output[1] = 1
  Process arr[2] = 4:  count[4] = 6 -> 5;  output[5] = 4
  Process arr[1] = 1:  count[1] = 1 -> 0;  output[0] = 1
  Process arr[0] = 3:  count[3] = 4 -> 3;  output[3] = 3

  output: [1, 1, 2, 3, 3, 4, 5]   sorted
```

### Why Right-to-Left Guarantees Stability

```
Input:  [(1,'A'), (1,'D')]   — two elements with key = 1
         idx=0    idx=1

After prefix sum: count[1] = 2
(meaning: output positions [0, 2) are for key-1 elements)

Right-to-left placement:
  i=1: elem=(1,'D')  count[1]: 2->1  output[1] = (1,'D')
  i=0: elem=(1,'A')  count[1]: 1->0  output[0] = (1,'A')

Output: [(1,'A'), (1,'D')]   A (idx=0) before D (idx=1)  STABLE

Left-to-right placement (wrong):
  i=0: elem=(1,'A')  count[1]: 2->1  output[1] = (1,'A')
  i=1: elem=(1,'D')  count[1]: 1->0  output[0] = (1,'D')

Output: [(1,'D'), (1,'A')]   D before A  UNSTABLE — earlier element loses
```

### Count Array as a Discrete Distribution

```
Input:  exam scores of 10 students, range [0, 5]
scores: [3, 5, 2, 3, 5, 3, 1, 2, 3, 4]

count:  [0, 1, 2, 4, 1, 2]
         key values: 0  1  2  3  4  5

This IS the discrete probability mass function of scores (unnormalised).
Normalise by dividing by 10:  [0.0, 0.1, 0.2, 0.4, 0.1, 0.2]

prefix sum of count:  [0, 1, 3, 7, 8, 10]
This IS the cumulative distribution function (CDF).

In image histogram equalisation:
  - count array = pixel intensity histogram
  - prefix sum  = CDF used to remap intensities for uniform distribution
  Same computation, different framing.
```

## 7. Common Variations and Extensions

### 7.1 Counting Sort as a Subroutine in Radix Sort

Radix sort ([[50.Radix sort — digit-by-digit, O(d(n+k))]]) applies counting sort independently on each digit position, from least significant to most significant. Each pass uses k = 10 (decimal digits) or k = 256 (byte values). Because each pass is stable, the final result is correctly sorted by all digits combined. This is the primary production context for counting sort — it rarely appears standalone in large systems but is exercised millions of times inside radix sort implementations.

### 7.2 Character Frequency Arrays

Sorting characters in a string by counting sort over the ASCII alphabet (k = 128 or 256) is the degenerate case where each "element" is a single character and the key is its ASCII value. This underlies anagram detection ([[22.Anagram detection and group-by-signature patterns]]), frequency-based string problems, and the character frequency map pattern in sliding window problems ([[13.Sliding window with frequency map — character problems]]). The count array of size 26 (lowercase Latin) or 128 (ASCII) is a counting sort structure.

### 7.3 `np.bincount` with Weights

`np.bincount(x, weights=w)` accumulates weights instead of counts: `result[i] = sum of w[j] for all j where x[j] == i`. This generalises counting sort's count phase to weighted histograms. Applications in ML: computing per-class loss sums, accumulating gradient magnitudes per token, building weighted vocabulary frequency tables. It runs at C speed on integer label arrays — always prefer it over Python loops for this pattern.

### 7.4 2D Histogram as a Counting Sort Extension

A 2D histogram is a counting sort over pairs (x, y) where x in [0, k₁−1] and y in [0, k₂−1]. The count array becomes a 2D matrix of size k₁ × k₂. This is used in image processing (joint histograms for mutual information estimation, used in image registration), in computing confusion matrices for classification models, and in co-occurrence matrix construction for word embedding models. The flat counting sort is the 1D case of this generalised structure.

## 9. CP Contest Application

### Typical Contest Structures

**Structure 1 — Direct application (Div. 2 B/C):** Array of n integers with values guaranteed in [1, 10⁵]. Sort and output. Using `std::sort` works but counting sort is O(n) instead of O(n log n). At n = 10⁷ with tight time limit, counting sort is the expected solution.

**Structure 2 — Frequency query:** After sorting via the count array, frequency queries `count[x]` are O(1). Prefix queries "how many elements have value at most x" are O(1) after prefix summing. Problems that combine sorting with frequency queries are solved in a single pass over the count array rather than with a sorted array plus binary search.

**Structure 3 — Lexicographic string sort:** Suffix array construction (for hard string problems) uses counting sort internally for O(n) suffix ranking. The DC3/SA-IS algorithms that construct suffix arrays in O(n) depend on stable counting sort over small alphabets. This is where counting sort appears in Div. 1 D/E problems.

### Practical Time Limits

At n = 10⁶ with k = 10⁶: counting sort takes roughly 10–15 ms in C++. `std::sort` takes roughly 60–80 ms. At time limit of 1 second, both pass. At time limit of 200 ms with n = 10⁷, only counting sort (or radix sort) passes. Recognising this threshold — n × log(n) vs n + k — is the contest skill.

### The Coordinate Compression Alternative

When the values are large (up to 10⁹) but only n distinct values appear, coordinate compression ([[47.Custom comparators — Python key= and C++ lambda comparators]]) maps them to [0, n−1] and then counting sort over range k = n is valid. This makes counting sort applicable even when the raw key range is huge, as long as the number of distinct keys is bounded.

```cpp
// Coordinate compression enabling counting sort on large values
std::vector<int> vals = arr;
std::sort(vals.begin(), vals.end());
vals.erase(std::unique(vals.begin(), vals.end()), vals.end());
auto compress = [&](int x) {
    return (int)(std::lower_bound(vals.begin(), vals.end(), x) - vals.begin());
};
// Now keys are in [0, vals.size()-1]; apply counting sort.
```
