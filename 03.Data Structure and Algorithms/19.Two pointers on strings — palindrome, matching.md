## 1. Intuition First

### The Core Idea

Strings are sequences, and sequences have two natural traversal directions: left-to-right and right-to-left. Two pointers on strings exploit the tension between these directions — or the coordination between them — to answer structural questions about a string in a single pass.

There are two distinct modes:

**Mode 1 — Opposite-end convergence (palindrome family).**  
Start `left` at index 0 and `right` at index n−1. March them toward each other, comparing characters. A palindrome is just a string that looks the same from both ends simultaneously. If `s[left] == s[right]` at every step until the pointers meet, the string is a palindrome. If they ever disagree, you have a structural violation — and the question becomes what to do with it (skip one character? tolerate k mismatches?).

**Mode 2 — Same-direction coordination (subsequence / matching family).**  
Both pointers move left-to-right, but at different rates governed by a matching condition. A classic: "is string `t` a subsequence of string `s`?" Keep one pointer on `s` (fast, always advances) and one on `t` (slow, advances only when `t[j] == s[i]`). When `j` reaches `len(t)`, every character of `t` has been matched in order.

Both modes share a core property: **the pointers enforce a structural constraint on the string without building any auxiliary data structure.** No hash map. No DP table (usually). Just two indices and a loop condition.

### Why This Exists

The naive approach to palindrome checking builds a reversed copy of the string and compares: O(n) time but O(n) space. For a 1GB string (genomic sequence, log file), that's 1GB of extra memory for what should be an O(1)-space operation. Two pointers check palindromes in O(n) time and **O(1) space** by never materialising the reversed string — the right pointer _is_ the reversed traversal.

For subsequence matching, the naive approach checks all C(n, k) subsequences of length k — exponential. The two-pointer approach is O(n + m): scan `s` once, advance `t`-pointer on matches.

For _approximate_ palindrome checking ("valid palindrome II" — can you make it a palindrome by deleting at most one character?), DP would work in O(n²) but two pointers with a single recursive call on mismatch does it in O(n) — the structural insight replaces the state space entirely.

### The "Aha" Moment

> **A palindrome is not a property of the whole string — it's a constraint between pairs of positions.** `s[i]` must equal `s[n-1-i]` for all i < n/2. Two pointers check these constraints one by one, from outside in, and fail fast on the first violation. The pointer positions are the constraint index — you don't need to store the pairs explicitly.

> **Subsequence matching is a greedy algorithm in disguise.** Matching `t[j]` to the _earliest possible_ position in `s` is always at least as good as any later match — because matching early leaves more of `s` available for the remaining characters of `t`. Two pointers implement this greedy without any explicit proof needed: just always advance `s`-pointer, advance `t`-pointer on match.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- "Check if a string is a palindrome (ignoring non-alphanumeric characters)" → opposite-end, skip invalid chars
- "Can you make a string a palindrome by deleting at most k characters?" → opposite-end with tolerance counter or recursive mismatch handling
- "Is `t` a subsequence of `s`?" → same-direction, advance on match
- "Find the minimum number of characters to insert to make a string a palindrome" → palindrome two-pointer sets up the DP boundary (related to LCS / edit distance, see [[171.Edit distance (Levenshtein) — string alignment DP]])
- "Given n strings, find how many are subsequences of a master string" → same-direction matching, possibly with binary search acceleration for large n
- "Longest palindromic substring" — expand-from-center (two pointers growing outward from each position, rather than converging inward)

**Signal patterns:**

```
"Is/check palindrome" + "O(1) space required"
→ opposite-end two pointers

"Is t a subsequence of s" (single query)
→ same-direction greedy two pointers in O(n+m)

"Is t a subsequence of s" (many queries, same s)
→ precompute next-occurrence table, binary search per char in O(m log n)

"Palindrome with at most k deletions"
→ opposite-end + mismatch budget or DP for k > 1
```

**Common traps that kill submissions:**

**Trap 1 — Palindrome with filtering: mutating vs. virtual skipping.**  
A common approach is to clean the string first (remove non-alphanumeric, lowercase), then run the palindrome check. This is O(n) space. The cleaner approach skips invalid characters _inside the loop_ using a helper:

```cpp
// BUG-PRONE: cleaning first allocates O(n) space
string cleaned = "";
for (char c : s) if (isalnum(c)) cleaned += tolower(c);
// Then check cleaned as palindrome.

// BETTER: skip in-place with pointer advancement
while (left < right) {
    while (left < right && !isalnum(s[left]))  left++;
    while (left < right && !isalnum(s[right])) right--;
    if (tolower(s[left]) != tolower(s[right])) return false;
    left++; right--;
}
```

**Trap 2 — "Valid Palindrome II" recursive call forgetting the bounds.**  
When you hit a mismatch and try skipping either `s[left]` or `s[right]`, you recurse (or call a helper) on a sub-range. Forgetting to pass the exact bounds `[left+1, right]` vs `[left, right-1]` causes checking the wrong substring or going out of bounds.

**Trap 3 — Subsequence matching: confusing `i` and `j` advancement.**  
`i` (pointer into `s`, the longer string) must always advance. `j` (pointer into `t`, the pattern) advances only on a match. Swapping these gives wrong answers that are hard to spot because the code still terminates.

```python
# BUG: j always advances — checks existence, not subsequence order
for i in range(len(s)):
    if j < len(t) and s[i] == t[j]:
        j += 1   # correct
    i += 1       # implicit — but if you also do j += 1 unconditionally: BUG
```

### Machine Learning / AI

**Where this appears:**

1. **Sequence alignment in NLP preprocessing — edit distance warm-up.**  
    The two-pointer subsequence check (`is t a subsequence of s?`) is the O(n+m) special case of the general sequence alignment problem. Understanding it grounds your intuition for why the full DP in [[171.Edit distance (Levenshtein) — string alignment DP]] costs O(nm): subsequence matching allows only insertions (no substitutions, no deletions from `t`), which collapses the 2D DP table to a 1D greedy scan. In BLEU score computation (machine translation evaluation), the "longest common subsequence" check between hypothesis and reference is a direct extension.
    
2. **Palindrome structure in RNA secondary structure prediction.**  
    RNA strands fold when complementary subsequences form base pairs. A hairpin loop is a palindromic segment: position `i` pairs with position `n-1-i` under Watson-Crick complementarity (A↔U, G↔C). The two-pointer palindrome check, extended with a complementarity function instead of equality, is the first-pass O(n) check before running the full O(n³) Nussinov DP. Tools like **ViennaRNA** and **RNAfold** do exactly this for fast pre-screening.
    
3. **Tokenizer boundary detection — subsequence matching in BPE.**  
    Byte-Pair Encoding (BPE) tokenisation, used in GPT-2/3/4 and LLaMA, repeatedly finds the most frequent adjacent pair and merges it. A key subroutine is checking whether a candidate merge sequence appears as a subsequence of the training corpus vocabulary. For efficiency, this is implemented as a two-pointer scan across the sorted vocabulary list — the same greedy matching pattern. The HuggingFace `tokenizers` library's Rust core uses this in its `BPE::merge` step.
    
4. **Data deduplication by string similarity — palindrome as a symmetry check.**  
    In training data deduplication (critical for LLM pretraining — see the DataComp and Dolma pipelines), one fast pre-filter is checking whether two strings are near-palindromes of each other (common in OCR-reversed duplicates, bidirectional text errors). The two-pointer palindrome check with a Hamming-distance counter (tolerate up to k mismatches) runs in O(n) per pair — fast enough to apply before the expensive MinHash comparison.
    
5. **Time-series symmetry detection.**  
    In anomaly detection on sensor data, palindromic patterns (a signal that rises then falls symmetrically) are a feature. A two-pointer scan with a tolerance for approximate equality (`|s[left] - s[right]| < ε`) detects these in O(n) per window. Streaming anomaly detection frameworks like **River** and **STUMPY** (matrix profile) use similar two-ended scans for motif detection.
    

**Why understanding this makes you better at ML code:**

String two-pointer teaches the **fail-fast with structural reasoning** pattern: rather than building a full DP table or frequency map to answer a structural question, ask "can I enforce the constraint one pair at a time?" When the answer is yes, two pointers give you O(1) space. The same mindset applies in ML: before writing an O(n²) pairwise similarity matrix, ask whether the constraint has enough structure (e.g., sorted order, monotonicity) to reduce to a linear scan.

## 3. Algorithm / Pattern

### Algorithm A: Palindrome Check (Opposite-End)

**Invariant:** At every step, `s[0..left-1]` and `s[right+1..n-1]` have been verified as matching mirror pairs.

1. `left = 0`, `right = len(s) - 1`
2. While `left < right`: a. (Optional) Skip invalid characters: advance `left` while `!valid(s[left])`, retreat `right` while `!valid(s[right])` b. If `normalise(s[left]) != normalise(s[right])` → return False (or handle mismatch) c. `left++`, `right--`
3. Return True

**Termination:** Pointers cross when all pairs checked. Odd-length strings leave the middle element unchecked — this is correct, as no character mirrors itself.

---

### Algorithm B: Valid Palindrome II (One Deletion Allowed)

When you hit a mismatch at `(left, right)`, you have exactly two choices: skip `s[left]` or skip `s[right]`. Check if _either_ of the resulting sub-ranges is a palindrome. If yes → valid. If neither → not valid.

```
function IS_PALINDROME(s, left, right):
    while left < right:
        if s[left] != s[right]: return False
        left++, right--
    return True

function VALID_PALINDROME_II(s):
    left, right = 0, len(s)-1
    while left < right:
        if s[left] != s[right]:
            return IS_PALINDROME(s, left+1, right) OR
                   IS_PALINDROME(s, left, right-1)
        left++, right--
    return True
```

**Why this is O(n):** The outer loop runs until the first mismatch — at most n/2 steps. The two IS_PALINDROME calls each run at most n/2 steps. Total: O(n).

**For k deletions (k > 1):** This approach requires O(k) recursive levels → O(kn) time. At k ≥ 3, it's cleaner to use DP: `dp[i][j]` = minimum deletions to make `s[i..j]` a palindrome. See [[171.Edit distance (Levenshtein) — string alignment DP]] for the generalised form.

---

### Algorithm C: Subsequence Matching (Same-Direction)

**Invariant:** `t[0..j-1]` has been matched to characters in `s[0..i-1]`, in order.

1. `i = 0` (pointer into `s`), `j = 0` (pointer into `t`)
2. While `i < len(s)` and `j < len(t)`:
    - If `s[i] == t[j]`: match found, advance both `i++, j++`
    - Else: advance only `i++`
3. Return `j == len(t)` (all of `t` matched)

**Greedy correctness:** Matching `t[j]` to the earliest occurrence in `s` is always optimal. Proof: suppose we skip an occurrence at position `p` and match at `p' > p`. Every subsequent character of `t` still needs to be found _after_ its match position. Using `p` instead of `p'` leaves more of `s` available (positions `[p+1, len(s)-1]` vs `[p'+1, len(s)-1]`). So matching early is never worse. ∎

---

### Algorithm D: Expand-from-Center (Palindromic Substring)

For finding the _longest palindromic substring_ (not just checking), two pointers grow _outward_ from a center rather than converging inward.

1. For each center position `c` in `[0, 2n-1]` (both odd-length centers at `c` and even-length centers between `c` and `c+1`):
    - `left = c // 2`, `right = (c + 1) // 2`
    - Expand while `left >= 0` and `right < n` and `s[left] == s[right]`
    - Record the longest found
2. Return the longest palindromic substring.

**Complexity:** O(n) centers × O(n) expansion each = **O(n²)**. (Manacher's algorithm reduces this to O(n) using previously computed palindrome lengths — but O(n²) is sufficient for most interview and contest problems up to n = 10⁴.)

---

### Decision Tree

```
String two-pointer problem?
│
├── "Is this string a palindrome?"
│   ├── Exact check, O(1) space → opposite-end convergence
│   ├── With character filtering (alphanumeric only) → skip invalid in-place
│   ├── With at most 1 deletion → opposite-end + IS_PALINDROME helper on mismatch
│   └── With at most k deletions (k > 1) → DP (LCS / edit distance family)
│
├── "Find longest palindromic substring"
│   ├── O(n²) acceptable → expand-from-center
│   └── O(n) required → Manacher's algorithm
│
├── "Is t a subsequence of s?" (single query)
│   └── Same-direction greedy: i always advances, j advances on match
│
├── "Is t a subsequence of s?" (many queries, s fixed)
│   └── Precompute next[i][c] = next occurrence of char c at or after index i
│       Then binary search per character of t: O(m log n) per query
│
└── "Minimum insertions/deletions to make palindrome"
    └── DP: LCS(s, reverse(s)) gives answer. Two-pointer identifies structure.
```

## 4. Pseudocode

### Palindrome Check with Filtering

```
function IS_PALINDROME_FILTERED(s):
    left  ← 0
    right ← len(s) - 1

    while left < right:

        # Skip non-alphanumeric characters from the left
        while left < right AND NOT isAlphanumeric(s[left]):
            left ← left + 1

        # Skip non-alphanumeric characters from the right
        while left < right AND NOT isAlphanumeric(s[right]):
            right ← right - 1

        # Compare normalised characters
        if toLowerCase(s[left]) ≠ toLowerCase(s[right]):
            return False

        left  ← left + 1
        right ← right - 1

    return True
```

### Valid Palindrome II (At Most One Deletion)

```
function IS_PALINDROME_RANGE(s, left, right):
    # Helper: check s[left..right] is a palindrome with no skips
    while left < right:
        if s[left] ≠ s[right]: return False
        left ← left + 1
        right ← right - 1
    return True

function VALID_PALINDROME_II(s):
    left  ← 0
    right ← len(s) - 1

    while left < right:
        if s[left] ≠ s[right]:
            # Mismatch: try skipping left character OR right character
            # Whichever sub-range is a palindrome makes the whole string valid
            return IS_PALINDROME_RANGE(s, left + 1, right) OR
                   IS_PALINDROME_RANGE(s, left, right - 1)
        left  ← left + 1
        right ← right - 1

    return True   # No mismatch found: already a palindrome
```

### Subsequence Matching

```
function IS_SUBSEQUENCE(t, s):
    # Is t a subsequence of s?
    i ← 0   # pointer into s (source, always advances)
    j ← 0   # pointer into t (pattern, advances only on match)

    while i < len(s) AND j < len(t):
        if s[i] == t[j]:
            j ← j + 1   # matched t[j]; look for t[j+1] next
        i ← i + 1       # always advance through s

    return j == len(t)   # all of t matched?


function NEXT_OCCURRENCE_TABLE(s, alphabet_size):
    # Precompute for many-query variant
    # next[i][c] = smallest index >= i where character c appears in s
    # Used for O(m log n) per-query subsequence check

    n ← len(s)
    next ← 2D array [n+1][alphabet_size], initialised to n (sentinel = "not found")

    for i ← n - 1 downto 0:
        for each character c in alphabet:
            next[i][c] ← next[i + 1][c]   # inherit from right
        next[i][ord(s[i])] ← i            # update current character

    return next
    # Query: for each char t[j], jump to next[current][t[j]]
    # If ever >= n: t is not a subsequence
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <string>
#include <vector>
#include <cctype>
#include <algorithm>
#include <iostream>
#include <cassert>

// ─────────────────────────────────────────────────────────────────
// Palindrome check — skip non-alphanumeric, case-insensitive
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
bool isPalindrome(const std::string& s) {
    int left = 0, right = static_cast<int>(s.size()) - 1;

    while (left < right) {
        // Advance left past non-alphanumeric
        while (left < right && !std::isalnum(s[left]))  ++left;
        // Retreat right past non-alphanumeric
        while (left < right && !std::isalnum(s[right])) --right;

        if (std::tolower(s[left]) != std::tolower(s[right]))
            return false;

        ++left;
        --right;
    }
    return true;
}

// ─────────────────────────────────────────────────────────────────
// Helper: is s[left..right] a palindrome? (exact, no filtering)
// ─────────────────────────────────────────────────────────────────
static bool isPalindromeRange(const std::string& s, int left, int right) {
    while (left < right) {
        if (s[left] != s[right]) return false;
        ++left; --right;
    }
    return true;
}

// ─────────────────────────────────────────────────────────────────
// Valid Palindrome II — at most one character deletion allowed
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
bool validPalindromeII(const std::string& s) {
    int left = 0, right = static_cast<int>(s.size()) - 1;

    while (left < right) {
        if (s[left] != s[right]) {
            // Try skipping left character or right character
            return isPalindromeRange(s, left + 1, right) ||
                   isPalindromeRange(s, left, right - 1);
        }
        ++left; --right;
    }
    return true;
}

// ─────────────────────────────────────────────────────────────────
// Valid Palindrome with at most k deletions
// k=0: exact palindrome; k=1: same as above; k>1: DP generalisation
// This recursive version works correctly but is O(2^k * n) — use DP for k > 2
// Time: O(kn) for small k   Space: O(k) call stack
// ─────────────────────────────────────────────────────────────────
bool validPalindromeK(const std::string& s, int left, int right, int k) {
    while (left < right) {
        if (s[left] != s[right]) {
            if (k == 0) return false;
            return validPalindromeK(s, left + 1, right, k - 1) ||
                   validPalindromeK(s, left, right - 1, k - 1);
        }
        ++left; --right;
    }
    return true;
}

// ─────────────────────────────────────────────────────────────────
// Subsequence check — is t a subsequence of s?
// Time: O(n + m)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
bool isSubsequence(const std::string& t, const std::string& s) {
    int i = 0, j = 0;
    const int n = s.size(), m = t.size();

    while (i < n && j < m) {
        if (s[i] == t[j]) ++j;   // match: advance pattern pointer
        ++i;                      // always advance source pointer
    }

    return j == m;  // all of t matched?
}

// ─────────────────────────────────────────────────────────────────
// Precomputed next-occurrence table for many-query subsequence
// Answers "is t a subsequence of s?" in O(m log n) per query
// after O(n * |alphabet|) preprocessing.
// ─────────────────────────────────────────────────────────────────
class SubsequenceOracle {
public:
    // next[i][c] = first index >= i in s where character c appears
    //              (= s.size() if c doesn't appear at or after i)
    std::vector<std::array<int, 128>> next;
    int n;

    explicit SubsequenceOracle(const std::string& s) : n(s.size()) {
        next.assign(n + 1, {});
        // Initialise last row: no characters available past end
        next[n].fill(n);

        for (int i = n - 1; i >= 0; --i) {
            next[i] = next[i + 1];           // inherit from right
            next[i][static_cast<int>(s[i])] = i;  // update current char
        }
    }

    bool isSubsequence(const std::string& t) const {
        int pos = 0;  // current position in s
        for (char c : t) {
            if (pos >= n) return false;
            pos = next[pos][static_cast<int>(c)];
            if (pos >= n) return false;  // character not found
            ++pos;  // move past matched character
        }
        return true;
    }
};

// ─────────────────────────────────────────────────────────────────
// Longest palindromic substring — expand from center
// Time: O(n²)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
std::string longestPalindrome(const std::string& s) {
    if (s.empty()) return "";
    const int n = s.size();
    int best_start = 0, best_len = 1;

    auto expand = [&](int left, int right) {
        while (left >= 0 && right < n && s[left] == s[right]) {
            if (right - left + 1 > best_len) {
                best_len   = right - left + 1;
                best_start = left;
            }
            --left; ++right;
        }
    };

    for (int c = 0; c < n; ++c) {
        expand(c, c);     // odd-length palindromes centred at c
        expand(c, c + 1); // even-length palindromes centred between c and c+1
    }

    return s.substr(best_start, best_len);
}

// ─────── Tests ───────────────────────────────────────────────────
int main() {
    // Palindrome with filtering
    assert(isPalindrome("A man, a plan, a canal: Panama"));
    assert(!isPalindrome("race a car"));
    assert(isPalindrome(" "));

    // Valid Palindrome II
    assert(validPalindromeII("aba"));
    assert(validPalindromeII("abca"));  // delete 'c' or 'b'
    assert(!validPalindromeII("abc"));

    // Valid Palindrome k deletions
    assert(validPalindromeK("abcba", 0, 4, 0));
    assert(validPalindromeK("abcda", 0, 4, 1));   // delete 'c' or 'd'
    assert(!validPalindromeK("abcde", 0, 4, 1));

    // Subsequence
    assert(isSubsequence("ace", "abcde"));
    assert(!isSubsequence("aec", "abcde"));
    assert(isSubsequence("", "anything"));
    assert(!isSubsequence("a", ""));

    // Many-query oracle
    SubsequenceOracle oracle("abcde");
    assert(oracle.isSubsequence("ace"));
    assert(!oracle.isSubsequence("aec"));
    assert(oracle.isSubsequence(""));

    // Longest palindrome
    assert(longestPalindrome("babad") == "bab" ||
           longestPalindrome("babad") == "aba");
    assert(longestPalindrome("cbbd") == "bb");
    assert(longestPalindrome("a") == "a");

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations


# ─────────────────────────────────────────────────────────────────
# Palindrome check — skip non-alphanumeric, case-insensitive
# Time: O(n)   Space: O(1)
# ─────────────────────────────────────────────────────────────────
def is_palindrome(s: str) -> bool:
    """
    Check if s reads the same forward and backward,
    ignoring non-alphanumeric characters and case.

    Complexity: O(n) time, O(1) space
    """
    left, right = 0, len(s) - 1

    while left < right:
        # Skip non-alphanumeric from both ends
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1

        if s[left].lower() != s[right].lower():
            return False

        left += 1
        right -= 1

    return True


# ─────────────────────────────────────────────────────────────────
# Helper: exact palindrome check on s[left..right]
# ─────────────────────────────────────────────────────────────────
def _is_palindrome_range(s: str, left: int, right: int) -> bool:
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True


# ─────────────────────────────────────────────────────────────────
# Valid Palindrome II — at most one deletion allowed
# Time: O(n)   Space: O(1)
# ─────────────────────────────────────────────────────────────────
def valid_palindrome_ii(s: str) -> bool:
    """
    Return True if s can become a palindrome by deleting at most one character.

    On mismatch at (left, right): try skipping left character or right character.
    Whichever yields a palindrome validates s.

    Complexity: O(n) time — outer loop at most n/2, each helper call at most n/2
    """
    left, right = 0, len(s) - 1

    while left < right:
        if s[left] != s[right]:
            # Try both skips — at most one mismatch is allowed
            return (_is_palindrome_range(s, left + 1, right) or
                    _is_palindrome_range(s, left, right - 1))
        left += 1
        right -= 1

    return True


# ─────────────────────────────────────────────────────────────────
# Valid Palindrome — at most k deletions (recursive, for small k)
# Time: O(kn)   Space: O(k) call stack depth
# For k > 2, prefer DP (LCS-based approach)
# ─────────────────────────────────────────────────────────────────
def valid_palindrome_k(s: str, left: int, right: int, k: int) -> bool:
    """
    Return True if s[left..right] can become a palindrome with at most k deletions.
    """
    while left < right:
        if s[left] != s[right]:
            if k == 0:
                return False
            return (valid_palindrome_k(s, left + 1, right, k - 1) or
                    valid_palindrome_k(s, left, right - 1, k - 1))
        left += 1
        right -= 1
    return True


# ─────────────────────────────────────────────────────────────────
# Subsequence check — is t a subsequence of s? (single query)
# Time: O(n + m)   Space: O(1)
# ─────────────────────────────────────────────────────────────────
def is_subsequence(t: str, s: str) -> bool:
    """
    Return True if t is a subsequence of s.

    Greedy: match t[j] to the earliest possible occurrence in s.
    This is always optimal — matching early leaves more of s for
    remaining characters of t.

    Complexity: O(n + m) time, O(1) space
    """
    i = j = 0  # i → s (source), j → t (pattern)

    while i < len(s) and j < len(t):
        if s[i] == t[j]:
            j += 1   # character matched; look for next in t
        i += 1       # always advance through s

    return j == len(t)   # did we match all of t?


# ─────────────────────────────────────────────────────────────────
# Next-occurrence oracle for many-query subsequence checking
# Preprocessing: O(n * |alphabet|)   Per query: O(m log n)
# ─────────────────────────────────────────────────────────────────
class SubsequenceOracle:
    """
    Precompute a next-occurrence table for string s, enabling efficient
    repeated subsequence queries.

    next_occ[i][c] = smallest index >= i where character c appears in s,
                     or len(s) if c does not appear at or after i.

    Build: O(n * |alphabet|) time and space
    Query: O(m log n) time using the table (or O(m) with direct table jumps)
    """

    def __init__(self, s: str) -> None:
        self.n = len(s)
        # Use direct table lookup: next_occ[i] maps char → next index
        self.next_occ: list[dict[str, int]] = [{}] * (self.n + 1)
        self.next_occ[self.n] = {}  # sentinel: nothing beyond end

        for i in range(self.n - 1, -1, -1):
            self.next_occ[i] = dict(self.next_occ[i + 1])  # inherit
            self.next_occ[i][s[i]] = i                      # update

    def is_subsequence(self, t: str) -> bool:
        pos = 0  # current search position in s
        for c in t:
            nxt = self.next_occ[pos].get(c, self.n)
            if nxt >= self.n:
                return False   # character c not found at or after pos
            pos = nxt + 1      # move past matched character
        return True


# ─────────────────────────────────────────────────────────────────
# Longest palindromic substring — expand from center
# Time: O(n²)   Space: O(1)
# ─────────────────────────────────────────────────────────────────
def longest_palindrome(s: str) -> str:
    """
    Find the longest palindromic substring in s.

    Strategy: for each possible center (n odd centers, n-1 even centers),
    expand outward as long as characters match.

    Complexity: O(n²) time, O(1) space
    Note: Manacher's algorithm achieves O(n) but is rarely needed in interviews.
    """
    if not s:
        return ""

    best_start, best_len = 0, 1

    def expand(left: int, right: int) -> None:
        nonlocal best_start, best_len
        while left >= 0 and right < len(s) and s[left] == s[right]:
            if right - left + 1 > best_len:
                best_len = right - left + 1
                best_start = left
            left -= 1
            right += 1

    for c in range(len(s)):
        expand(c, c)      # odd-length: center at c
        expand(c, c + 1)  # even-length: center between c and c+1

    return s[best_start : best_start + best_len]


# ─────────────────────────────────────────────────────────────────
# Count palindromic substrings — same expand-from-center approach
# Time: O(n²)   Space: O(1)
# ─────────────────────────────────────────────────────────────────
def count_palindromic_substrings(s: str) -> int:
    """
    Count all palindromic substrings (not unique) in s.
    Each expansion that succeeds contributes one palindrome.

    Complexity: O(n²) time, O(1) space
    """
    count = 0

    def expand(left: int, right: int) -> None:
        nonlocal count
        while left >= 0 and right < len(s) and s[left] == s[right]:
            count += 1
            left -= 1
            right += 1

    for c in range(len(s)):
        expand(c, c)
        expand(c, c + 1)

    return count


# ─── Smoke tests ──────────────────────────────────────────────────
```

## 6. Visual Explanation

### Palindrome Convergence — What the Pointers Enforce

For `s = "racecar"`:

```
Step 0:  r  a  c  e  c  a  r
         L                 R    s[L]='r' == s[R]='r' ✓  →  L++, R--

Step 1:  r  a  c  e  c  a  r
            L           R       s[L]='a' == s[R]='a' ✓  →  L++, R--

Step 2:  r  a  c  e  c  a  r
               L     R          s[L]='c' == s[R]='c' ✓  →  L++, R--

Step 3:  r  a  c  e  c  a  r
                  LR            L == R (odd-length: middle element)
                                L < R is False → loop exits → True ✓

Invariant at each step:
  s[0..L-1] and s[R+1..n-1] are verified mirror pairs.
  Only s[L..R] remains to check.
  When L >= R, no unchecked pairs remain.
```

### Valid Palindrome II — The Branching Moment

For `s = "abca"`:

```
Step 0:  a  b  c  a
         L        R    s[L]='a' == s[R]='a' ✓  →  L++, R--

Step 1:  a  b  c  a
            L  R       s[L]='b' ≠ s[R]='c'  →  MISMATCH

Two sub-problems spawned:

Branch A: skip L — check s[L+1..R] = s[2..2] = "c"
  a  b  [c]  a          Is "c" a palindrome? YES ✓

Branch B: skip R — check s[L..R-1] = s[1..1] = "b"
  a  [b]  c  a          Is "b" a palindrome? YES ✓

Either branch succeeds → return True.
(Only one mismatch encountered → only one deletion needed.)
```

### Subsequence Matching — The Two Speeds

For `t = "ace"`, `s = "abcde"`:

```
 s:  a  b  c  d  e
     i                  j=0: t[0]='a'. s[0]='a' == 'a' → MATCH. j=1, i=1.

 s:  a  b  c  d  e
        i               j=1: t[1]='c'. s[1]='b' ≠ 'c' → no match. i=2.

 s:  a  b  c  d  e
           i            j=1: t[1]='c'. s[2]='c' == 'c' → MATCH. j=2, i=3.

 s:  a  b  c  d  e
              i          j=2: t[2]='e'. s[3]='d' ≠ 'e' → no match. i=4.

 s:  a  b  c  d  e
                 i       j=2: t[2]='e'. s[4]='e' == 'e' → MATCH. j=3, i=5.

i=5 >= len(s)=5. Loop exits. j=3 == len(t)=3. → True ✓

Key: i touched every element of s exactly once.
     j only moved 3 times (once per character of t matched).
     Total: O(n + m) = O(5 + 3) = O(8) steps.
```

### Expand-from-Center — Both Directions Simultaneously

For `s = "cbbd"`, finding "bb":

```
Center c=0 (char 'c'): expand(0,0)
  s[0]='c' == s[0]='c' → palindrome "c" (len 1). Expand: L=-1, stop.

Center c=0 even: expand(0,1)
  s[0]='c' ≠ s[1]='b' → stop immediately. No even palindrome here.

Center c=1 (char 'b'): expand(1,1)
  s[1]='b' → palindrome "b". Expand: L=0, R=2. s[0]='c' ≠ s[2]='b' → stop.

Center c=1 even: expand(1,2)
  s[1]='b' == s[2]='b' → palindrome "bb" (len 2) ← NEW BEST
  Expand: L=0, R=3. s[0]='c' ≠ s[3]='d' → stop.

Center c=2 even: expand(2,3)
  s[2]='b' ≠ s[3]='d' → stop.

Result: "bb" ✓

Pointers grow OUTWARD from center — opposite direction to palindrome check.
Palindrome check: inward convergence (verification).
Expand from center: outward growth (discovery).
```

## 7. Common Variations & Extensions

### Variation 1: Palindrome Pairs (Hard — Trie + Two-Pointer Reasoning)

Given a list of words, find all pairs `(i, j)` such that `words[i] + words[j]` is a palindrome. Brute force O(n² · k) where k = word length. Efficient solution: for each word, check if its reverse exists in a HashMap, and check palindrome prefixes/suffixes using the two-pointer palindrome check as a subroutine. Understanding the O(n) palindrome check is a prerequisite (LC 336).

### Variation 2: Shortest Palindrome (KMP Connection)

Find the shortest palindrome you can make by adding characters only to the _front_ of string `s`. Equivalently: find the longest palindromic prefix of `s`. This connects directly to [[26.KMP algorithm — failure function and O(n+m) matching]]: construct `s + '#' + reverse(s)` and compute the KMP failure function — the last value gives the longest palindromic prefix length. Two-pointer reasoning motivates _why_ we need this — the naive approach is O(n²) expansion.

### Variation 3: Subsequence Count (DP Extension)

"How many distinct subsequences of `s` equal `t`?" The two-pointer greedy check answers existence in O(n). Counting requires DP: `dp[i][j]` = number of ways to match `t[0..j-1]` using `s[0..i-1]`. See [[172.Longest Common Subsequence (LCS)]] for the structural parallel. Two-pointer establishes the matching structure; DP counts it.

### Variation 4: Minimum Insertions to Make Palindrome

Minimum characters to insert to make `s` a palindrome = `len(s) - LCS(s, reverse(s))`. The two-pointer palindrome check identifies which characters already match (they don't need insertion); the unmatched characters are the DP subproblem. This bridges two-pointer intuition to [[171.Edit distance (Levenshtein) — string alignment DP]].

### Variation 5: Palindrome Partitioning

"Partition `s` into the fewest palindromic substrings." For each possible split point, use the palindrome check to validate each piece. Precompute `is_palindrome[i][j]` using expand-from-center in O(n²), then DP for the minimum cuts in O(n). Two-pointer fills the palindrome table that DP consumes.

## 9. CP Contest Application

### Typical Problem Structures

**Type 1 — Filtered palindrome (warmup / Div. 2 A):** Input is a sentence with punctuation; check if it reads the same ignoring spaces and punctuation, case-insensitive. Pure opposite-end two-pointer with in-loop skipping. O(n) time, O(1) space.

**Type 2 — Palindrome validation with budget (Div. 2 C):** "Given a string, find the minimum number of characters to change to make it a palindrome." Opposite-end two-pointer; each mismatch costs 1 change. O(n). Variant: "at most k changes — is it possible?" Same scan, count mismatches, compare to k.

**Type 3 — Subsequence count / existence under constraints (Div. 2 C / Div. 1 B):** "Given m queries each asking if string `t_i` is a subsequence of `s`, answer all queries efficiently." Naive: O(n·m). With precomputed next-occurrence table: O(n·|alphabet|) build + O(m·|t_i|) queries. At n = 10⁵ and m = 10⁵, this is the difference between 10¹⁰ and 10⁶ operations — mandatory optimisation.

```cpp
// Many-query subsequence template (C++)
// Build: O(n * 26) for lowercase alphabet
vector<array<int,26>> nxt(n + 1);
nxt[n].fill(n);
for (int i = n - 1; i >= 0; --i) {
    nxt[i] = nxt[i + 1];
    nxt[i][s[i] - 'a'] = i;
}

// Query: O(|t|) per query using table jumps
auto query = [&](const string& t) -> bool {
    int pos = 0;
    for (char c : t) {
        if (pos >= n) return false;
        pos = nxt[pos][c - 'a'];
        if (pos >= n) return false;
        ++pos;
    }
    return true;
};
```

**Type 4 — Palindrome substring precomputation (Div. 1 C):** Many problems require `is_palindrome[i][j]` for all pairs. Expand-from-center fills this in O(n²) time and O(n²) space. For n ≤ 5000, this is feasible. For n > 5000 with O(n²) space constraints, use Manacher's algorithm to answer point queries in O(1) after O(n) preprocessing — but this is rare in contests below Div. 1 A level.

|---|---|---|---|---|---|
|10³|<1ms|<1ms|<1ms|10⁶ ops (ok)|—|
|10⁴|<1ms|~10ms|<1ms|10⁸ ops (slow)|~10⁴ per query|
