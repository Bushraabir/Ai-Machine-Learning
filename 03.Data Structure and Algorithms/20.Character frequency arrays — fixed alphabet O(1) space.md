
## 1. Intuition First

### The Core Idea

Every character in a fixed alphabet — lowercase English letters, ASCII printable characters, Unicode code points within a bounded range — maps to an integer. `'a'` is 97, `'z'` is 122, `'A'` is 65. This is not incidental. It means a string over a fixed alphabet is secretly a sequence of small integers, and a **frequency array** is simply a direct-address table: an array of size |Σ| (the alphabet size) where index `c` stores how many times character `c` appears.

No hashing. No collision. No pointer chasing. Just `freq[s[i] - 'a']++` — a single array index computation and an integer increment. The entire frequency distribution of a string lives in an array of 26 integers (for lowercase English) or 128 integers (for ASCII).

This is the most cache-friendly frequency counting structure possible: 26 integers fit in a single cache line (64 bytes). Accessing any frequency is O(1) with a constant so small it embarrasses HashMap.

### Why This Exists

A HashMap over characters is general — it works for arbitrary key types, arbitrary alphabet sizes, Unicode, emoji, whatever. But generality has costs: hash computation per key, potential collision resolution, dynamic resizing, pointer indirection to buckets, cache misses from scattered memory layout.

When your alphabet is fixed and small, all of that is waste. The character _is_ the index. No hash needed. The frequency array exploits this bijection between characters and integers to reduce the entire frequency-counting problem to array indexing — the single fastest operation in any architecture.

The space cost is O(|Σ|), which is O(1) for fixed alphabets — 26 ints for lowercase letters, 128 ints for ASCII. This is not a typo. It is genuinely O(1) space in the complexity-theoretic sense, because |Σ| is a constant independent of input length n.

### The "Aha" Moment

> **A character is already its own hash code.** For fixed alphabets, the bijection `char → integer` is perfect, collision-free, and computed for free by the hardware (it's just the character's numeric value). A frequency array is a hash table where the hash function is the identity, the table has no collisions by construction, and every operation is a single memory access.

The deeper insight: **frequency arrays convert a string comparison problem into an integer array comparison problem.** Two strings are anagrams if and only if their frequency arrays are identical. Checking two 26-element integer arrays for equality is a fixed-cost operation — it doesn't grow with string length. This is why anagram detection, sliding window character problems, and permutation checks all reach for frequency arrays first.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- Anagram detection, permutation check, grouping by character composition
- Sliding window problems tracking character counts (how many distinct chars, how many chars exceed a threshold)
- "Find all characters appearing more than k times" — linear scan of the frequency array
- Comparing character distributions between two strings or substrings
- Counting sort on characters (the frequency array is the counting sort histogram)
- Problems with constraints like "lowercase English letters only" — this is the signal to use a frequency array over HashMap

**Signal pattern:**

```
String problem + "lowercase letters" / "uppercase letters" / "ASCII characters"
→ frequency array over HashMap, always

Sliding window + "at most k distinct characters"
→ frequency array as the window's state; distinct count tracked separately

"Are these two strings anagrams / permutations of each other?"
→ single frequency array, increment for s1, decrement for s2, check all zeros
```

**Common traps that kill submissions:**

**Trap 1 — Wrong alphabet offset.** Using `s[i] - 'A'` when the string contains lowercase letters gives negative indices or wrong slots. Always verify: lowercase → `- 'a'`, uppercase → `- 'A'`, digits → `- '0'`, mixed ASCII → use raw `(unsigned char)s[i]` as index into a 128-element array.

**Trap 2 — Array not zeroed between test cases.** In competitive programming, multiple test cases often share the same frequency array. If you declare it globally (common for performance) but forget to reset it between test cases, frequencies from the previous case corrupt the current one. Use `memset(freq, 0, sizeof(freq))` or `fill(freq, freq+26, 0)` at the start of each test.

```cpp
// BUG: global array carries state between test cases
int freq[26];  // global — initialized once at program start

int main() {
    int T; cin >> T;
    while (T--) {
        string s; cin >> s;
        // Missing: memset(freq, 0, sizeof(freq));
        for (char c : s) freq[c-'a']++;
        // freq still contains counts from previous test case
    }
}
```

**Trap 3 — Overflow on large inputs.** If n = 10⁶ and the string is all `'a'`s, `freq[0] = 10⁶`. That fits in `int`. But if n = 10⁹ (streaming count), use `long long`. In contest problems, check the constraint on n before choosing the frequency array element type.

---

### Machine Learning / AI

**Where this appears:**

1. **Bag-of-Words and character n-gram models.** The simplest text representation in ML is a frequency vector: for each word (or character) in the vocabulary, count its occurrences. A character frequency array over a 26-letter alphabet is exactly the character-level bag-of-words representation. Scikit-learn's `CountVectorizer` at `analyzer='char'` with `lowercase=True` produces this — it internally builds exactly a frequency array indexed by character. For n-gram character models (sequences of 2–4 characters), the same structure scales to |Σ|ⁿ entries.
    
2. **Vocabulary compression in tokenisation.** BPE (Byte-Pair Encoding) tokenisation, used in GPT-series and LLaMA, initialises its vocabulary with character frequencies. The first step of BPE training is building a character frequency array over the entire corpus to determine which characters exist and how common they are — this directly determines which characters get their own token versus which are merged immediately. In the HuggingFace `tokenizers` library, this is the `initial_alphabet` computation.
    
3. **Categorical feature encoding in tabular ML.** When encoding a categorical column with a fixed alphabet (e.g., country codes, currency symbols, amino acid sequences), a frequency array over the category space is the first-pass statistics collector before binning, target encoding, or embedding. The "fixed alphabet → direct-address table" pattern appears in feature engineering pipelines in Spark ML and scikit-learn's `LabelEncoder`.
    
4. **Suffix array construction via counting sort on characters.** Suffix arrays — used in full-text search, sequence alignment, and LLM training data deduplication — are built using DC3/skew or SA-IS algorithms, both of which perform multiple rounds of counting sort over character frequencies. The character frequency array is the histogram that drives the counting sort. Understanding this connects to [[49.Counting sort — O(n + k) for integer keys]] and explains why suffix array construction is O(n) rather than O(n log n).
    
5. **Genomics: k-mer frequency profiles.** In bioinformatics, a DNA sequence over alphabet {A, C, G, T} is characterised by its k-mer frequency profile — an array of length 4ᵏ counting occurrences of each k-length substring. For k=1, this is a 4-element frequency array. For k=4 (common in read classification), it's a 256-element array. Tools like Jellyfish (k-mer counting) and Kraken2 (taxonomic classification) use frequency arrays as their core data structure. The connection to ML: k-mer profiles are fixed-length feature vectors fed directly into classical ML classifiers (SVM, RF) and as inputs to genomics-specific transformers.
    
6. **Character-level language models and tokenizer-free NLP.** Models like ByT5 and CANINE operate directly on byte/character sequences. Their "vocabulary" is exactly the 256-element ASCII/byte alphabet. The frequency array over this alphabet is used during preprocessing to build character-level statistics (character coverage, entropy, most-common characters) that guide the model's embedding table initialisation. A character with frequency zero in the training corpus gets a zero-initialised embedding — knowing this comes from the frequency array structure.
    

**Why understanding this makes you better at ML code:**

When you build a feature pipeline over text data, your first question should be: "Is my alphabet fixed and small?" If yes — character n-grams over ASCII, amino acid k-mers over {A,C,G,T,...}, Unicode category labels — a frequency array is strictly better than a dictionary. It's 10–100× faster to build (no hashing), has zero collision overhead, and produces a fixed-size feature vector directly usable as a numpy array without conversion. The `collections.Counter` in Python is convenient but carries dict overhead. For fixed alphabets, a 26-element list beats it on every metric that matters at scale.

## 3. Algorithm / Pattern

### Core Operations

**Build frequency array from string:**

```
freq[c] = number of times character c appears in string s
Time: O(n)   Space: O(|Σ|) = O(1) for fixed alphabet
```

**Query frequency of character c:** `freq[c - base]` — O(1).

**Check if two strings are anagrams:** Build freq arrays for both (or build one, decrement with the other), check all entries are zero — O(n + |Σ|) = O(n).

**Find characters present / absent:** Linear scan of freq array — O(|Σ|) = O(1).

**Most / least frequent character:** Linear scan for max / min — O(|Σ|) = O(1).

**Sliding window character tracking:** Increment on window expansion, decrement on window shrink. Maintain a separate `distinct_count` or `satisfied_count` integer to avoid re-scanning the array on each step.

---

### The Difference Array Trick (for Comparison)

Instead of building two separate frequency arrays and comparing them, build one and use it as a **difference counter**: increment for string A, decrement for string B. If all entries are zero at the end, the strings have identical character distributions.

```
for c in s1: freq[c - 'a']++
for c in s2: freq[c - 'a']--
return all(freq[i] == 0 for i in range(26))
```

This saves one array allocation and makes the "are these equal?" check trivially a zero-detection scan.

---

### The `nonzero_count` Sentinel

For sliding window problems, maintaining a `nonzero_count` integer (count of freq array entries that are non-zero) avoids scanning the entire freq array after each window step:

```
When freq[c] changes from 0 to nonzero: nonzero_count++
When freq[c] changes from nonzero to 0: nonzero_count--
Window is "satisfied" when nonzero_count == 0 (or == k, depending on problem)
```

This reduces the per-step cost from O(|Σ|) to O(1), which matters when |Σ| = 128 and n = 10⁶.

---

### Complexity Summary

|Operation|Time|Space|
|---|---|---|
|Build freq array|O(n)|O(\|Σ\|) = O(1)|
|Query single character frequency|O(1)|—|
|Compare two freq arrays|O(\|Σ\|) = O(1)|—|
|Find max/min frequency character|O(\|Σ\|) = O(1)|—|
|Sliding window step|O(1) per step|O(\|Σ\|) = O(1)|

The key point: **all operations on the freq array itself are O(1)** because |Σ| is a constant. The only O(n) cost is building it from the string.

---

### When to Use Frequency Array vs HashMap

|Condition|Use Frequency Array|Use HashMap|
|---|---|---|
|Alphabet is fixed, size ≤ 1000|✓ Always||
|Alphabet is unbounded (Unicode, words)||✓|
|Need ordered iteration by key||✓ (ordered map)|
|Need to minimise memory at all costs||✓ (sparse keys)|
|Need maximum speed, keys are chars|✓||
|Alphabet known at compile time|✓||

## 4. Pseudocode

### Basic Frequency Array

```
function BUILD_FREQ(s, base_char):
    freq ← array of size ALPHABET_SIZE, all zeros

    for each character c in s:
        freq[ord(c) - ord(base_char)] ← freq[ord(c) - ord(base_char)] + 1

    return freq


function ARE_ANAGRAMS(s1, s2):
    if len(s1) ≠ len(s2): return False

    freq ← array of size ALPHABET_SIZE, all zeros

    # Increment for s1, decrement for s2 (difference counter trick)
    for each character c in s1: freq[ord(c) - ord('a')] ← freq[...] + 1
    for each character c in s2: freq[ord(c) - ord('a')] ← freq[...] - 1

    # If any entry is nonzero, character distributions differ
    for i ← 0 to ALPHABET_SIZE - 1:
        if freq[i] ≠ 0: return False

    return True
```

### Sliding Window with Frequency Array and nonzero_count

```
function MIN_WINDOW_CONTAINING_ALL(s, t):
    # Find minimum substring of s containing all characters of t
    # Uses frequency array + nonzero_count sentinel

    need ← array[ALPHABET_SIZE], all zeros      # characters needed from t
    for each character c in t: need[ord(c) - 'a'] ← need[...] + 1

    window ← array[ALPHABET_SIZE], all zeros    # current window counts
    nonzero_deficits ← count of nonzero entries in need  # characters still needed

    left ← 0, min_len ← ∞, min_start ← 0

    for right ← 0 to len(s) - 1:
        c ← s[right]
        idx ← ord(c) - ord('a')
        window[idx] ← window[idx] + 1

        # Did this character help satisfy a deficit?
        if need[idx] > 0 AND window[idx] == need[idx]:
            nonzero_deficits ← nonzero_deficits - 1

        # Shrink from left while all deficits satisfied
        while nonzero_deficits == 0:
            if right - left + 1 < min_len:
                min_len ← right - left + 1
                min_start ← left

            left_c ← s[left]
            left_idx ← ord(left_c) - ord('a')
            window[left_idx] ← window[left_idx] - 1

            # Did removing this character create a new deficit?
            if need[left_idx] > 0 AND window[left_idx] < need[left_idx]:
                nonzero_deficits ← nonzero_deficits + 1

            left ← left + 1

    if min_len == ∞: return ""
    return s[min_start .. min_start + min_len - 1]
```

### Frequency Array as Canonical Signature

```
function FREQ_SIGNATURE(s):
    # Returns a fixed-size tuple/array usable as a HashMap key
    # All anagrams of s produce the same signature
    freq ← array[26], all zeros
    for each character c in s: freq[ord(c) - ord('a')] ← freq[...] + 1
    return tuple(freq)   # immutable, hashable

function GROUP_ANAGRAMS(words):
    groups ← HashMap: signature → list of words
    for each word in words:
        sig ← FREQ_SIGNATURE(word)
        groups[sig].append(word)
    return groups.values()
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <string>
#include <vector>
#include <array>
#include <unordered_map>
#include <algorithm>
#include <climits>
#include <iostream>
#include <cassert>

constexpr int ALPHA = 26;  // lowercase English letters

// ─────────────────────────────────────────────────────────────────
// Build frequency array from string (lowercase letters only)
// Time: O(n)   Space: O(1) — 26-element array
// ─────────────────────────────────────────────────────────────────
std::array<int, ALPHA> buildFreq(const std::string& s) {
    std::array<int, ALPHA> freq{};  // zero-initialised
    for (unsigned char c : s) {
        freq[c - 'a']++;
    }
    return freq;
}

// ─────────────────────────────────────────────────────────────────
// Anagram check — difference counter trick
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
bool areAnagrams(const std::string& s1, const std::string& s2) {
    if (s1.size() != s2.size()) return false;

    std::array<int, ALPHA> freq{};
    for (char c : s1) freq[c - 'a']++;
    for (char c : s2) freq[c - 'a']--;

    // All entries zero iff same character distribution
    for (int count : freq) {
        if (count != 0) return false;
    }
    return true;
}

// ─────────────────────────────────────────────────────────────────
// Find all anagram starting positions of pattern p in text s
// Sliding window with O(1) window state comparison
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
std::vector<int> findAnagrams(const std::string& s, const std::string& p) {
    std::vector<int> result;
    const int n = s.size(), m = p.size();
    if (n < m) return result;

    std::array<int, ALPHA> need{}, window{};
    for (char c : p) need[c - 'a']++;

    // Count how many distinct characters still have unmet requirements
    int deficit = 0;
    for (int x : need) if (x > 0) deficit++;

    // Initialise first window
    for (int i = 0; i < m; ++i) {
        int idx = s[i] - 'a';
        window[idx]++;
        if (window[idx] == need[idx]) deficit--;
    }
    if (deficit == 0) result.push_back(0);

    // Slide the window one character at a time
    for (int right = m; right < n; ++right) {
        // Add new character on the right
        int r_idx = s[right] - 'a';
        window[r_idx]++;
        if (window[r_idx] == need[r_idx]) deficit--;

        // Remove character leaving on the left
        int l_idx = s[right - m] - 'a';
        if (window[l_idx] == need[l_idx]) deficit++;
        window[l_idx]--;

        if (deficit == 0) result.push_back(right - m + 1);
    }

    return result;
}

// ─────────────────────────────────────────────────────────────────
// Minimum window substring — smallest window in s containing all of t
// Uses frequency array + deficit counter (nonzero_count pattern)
// Time: O(n + m)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
std::string minWindow(const std::string& s, const std::string& t) {
    if (s.empty() || t.empty()) return "";

    // Use 128-element array for full ASCII (handles uppercase + lowercase)
    std::array<int, 128> need{}, window{};
    for (unsigned char c : t) need[c]++;

    int deficit = 0;
    for (int x : need) if (x > 0) deficit++;

    int left = 0, min_len = INT_MAX, min_start = 0;

    for (int right = 0; right < static_cast<int>(s.size()); ++right) {
        unsigned char rc = s[right];
        window[rc]++;
        if (need[rc] > 0 && window[rc] == need[rc]) deficit--;

        while (deficit == 0) {
            if (right - left + 1 < min_len) {
                min_len   = right - left + 1;
                min_start = left;
            }
            unsigned char lc = s[left];
            window[lc]--;
            if (need[lc] > 0 && window[lc] < need[lc]) deficit++;
            left++;
        }
    }

    return min_len == INT_MAX ? "" : s.substr(min_start, min_len);
}

// ─────────────────────────────────────────────────────────────────
// Group anagrams — freq array as HashMap key
// Time: O(n * L) where L = average word length   Space: O(n)
// ─────────────────────────────────────────────────────────────────
std::vector<std::vector<std::string>> groupAnagrams(
    const std::vector<std::string>& words)
{
    // Key: frequency array serialised as std::array<int,26>
    std::unordered_map<std::string, std::vector<std::string>> groups;

    for (const std::string& w : words) {
        std::array<int, ALPHA> freq{};
        for (char c : w) freq[c - 'a']++;

        // Serialise freq array to string key (compact, collision-free)
        std::string key(ALPHA * 2, 0);
        for (int i = 0; i < ALPHA; ++i) {
            // Store as two bytes to handle counts up to 65535
            key[2*i]   = freq[i] & 0xFF;
            key[2*i+1] = (freq[i] >> 8) & 0xFF;
        }
        groups[key].push_back(w);
    }

    std::vector<std::vector<std::string>> result;
    result.reserve(groups.size());
    for (auto& [key, group] : groups) {
        result.push_back(std::move(group));
    }
    return result;
}

// ─────────────────────────────────────────────────────────────────
// Character frequency statistics
// ─────────────────────────────────────────────────────────────────
struct FreqStats {
    char most_frequent;
    char least_frequent;  // among characters that appear
    int  unique_count;
    int  max_freq;
};

FreqStats analyseFreq(const std::string& s) {
    std::array<int, ALPHA> freq{};
    for (char c : s) freq[c - 'a']++;

    FreqStats stats{0, 0, 0, 0};
    int min_freq = INT_MAX;

    for (int i = 0; i < ALPHA; ++i) {
        if (freq[i] > 0) {
            stats.unique_count++;
            if (freq[i] > stats.max_freq) {
                stats.max_freq = freq[i];
                stats.most_frequent = 'a' + i;
            }
            if (freq[i] < min_freq) {
                min_freq = freq[i];
                stats.least_frequent = 'a' + i;
            }
        }
    }
    return stats;
}

// ─────── Tests ───────────────────────────────────────────────────
int main() {
    // Anagram check
    assert(areAnagrams("listen", "silent"));
    assert(areAnagrams("anagram", "nagaram"));
    assert(!areAnagrams("rat", "car"));
    assert(!areAnagrams("ab", "a"));

    // Find anagrams
    auto positions = findAnagrams("cbaebabacd", "abc");
    assert((positions == std::vector<int>{0, 6}));

    positions = findAnagrams("abab", "ab");
    assert((positions == std::vector<int>{0, 1, 2}));

    // Minimum window
    assert(minWindow("ADOBECODEBANC", "ABC") == "BANC");
    assert(minWindow("a", "a") == "a");
    assert(minWindow("a", "aa") == "");

    // Group anagrams
    auto groups = groupAnagrams({"eat","tea","tan","ate","nat","bat"});
    assert(groups.size() == 3);

    // Freq stats
    auto stats = analyseFreq("aabbbbcc");
    assert(stats.most_frequent == 'b' && stats.max_freq == 4);
    assert(stats.unique_count == 3);

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations
from collections import defaultdict
from typing import NamedTuple


ALPHA = 26  # lowercase English letters


# ─────────────────────────────────────────────────────────────────
# Build frequency array — lowercase letters
# Time: O(n)   Space: O(1) — 26-element list
# ─────────────────────────────────────────────────────────────────
def build_freq(s: str) -> list[int]:
    """
    Returns a 26-element list where freq[i] = count of chr(ord('a') + i) in s.
    Strictly faster than Counter for fixed lowercase-letter alphabet.

    Complexity: O(n) time, O(1) space (26 integers = constant)
    """
    freq = [0] * ALPHA
    for c in s:
        freq[ord(c) - ord('a')] += 1
    return freq


# ─────────────────────────────────────────────────────────────────
# Anagram check — difference counter trick
# Time: O(n)   Space: O(1)
# ─────────────────────────────────────────────────────────────────
def are_anagrams(s1: str, s2: str) -> bool:
    """
    Return True if s1 and s2 are anagrams of each other.

    Uses single frequency array: increment for s1, decrement for s2.
    All zeros at end iff same character multiset.

    Complexity: O(n) time, O(1) space
    """
    if len(s1) != len(s2):
        return False

    freq = [0] * ALPHA
    for c in s1:
        freq[ord(c) - ord('a')] += 1
    for c in s2:
        freq[ord(c) - ord('a')] -= 1

    return all(x == 0 for x in freq)


# ─────────────────────────────────────────────────────────────────
# Find all anagram start positions of pattern p in text s
# Sliding window — O(1) window state via freq array + deficit counter
# Time: O(n)   Space: O(1)
# ─────────────────────────────────────────────────────────────────
def find_anagrams(s: str, p: str) -> list[int]:
    """
    Return list of start indices where an anagram of p begins in s.

    Sliding fixed-size window of length len(p). Track 'deficit':
    number of characters whose count in window < required count.
    Window is valid (anagram found) when deficit == 0.

    Complexity: O(n) time, O(1) space
    """
    n, m = len(s), len(p)
    if n < m:
        return []

    need   = [0] * ALPHA
    window = [0] * ALPHA
    result = []

    for c in p:
        need[ord(c) - ord('a')] += 1

    # deficit = number of characters with unmet count requirement
    deficit = sum(1 for x in need if x > 0)

    # Initialise first window
    for i in range(m):
        idx = ord(s[i]) - ord('a')
        window[idx] += 1
        if window[idx] == need[idx]:   # exactly met requirement for this char
            deficit -= 1

    if deficit == 0:
        result.append(0)

    # Slide the window
    for right in range(m, n):
        # Add incoming character (right side)
        r_idx = ord(s[right]) - ord('a')
        window[r_idx] += 1
        if window[r_idx] == need[r_idx]:
            deficit -= 1

        # Remove outgoing character (left side)
        l_idx = ord(s[right - m]) - ord('a')
        if window[l_idx] == need[l_idx]:   # about to break the requirement
            deficit += 1
        window[l_idx] -= 1

        if deficit == 0:
            result.append(right - m + 1)

    return result


# ─────────────────────────────────────────────────────────────────
# Minimum window substring
# Time: O(n + m)   Space: O(1) for ASCII-128 freq arrays
# ─────────────────────────────────────────────────────────────────
def min_window(s: str, t: str) -> str:
    """
    Find the minimum substring of s that contains all characters of t
    (with correct multiplicity).

    Uses 128-element ASCII freq arrays. Deficit counter avoids
    rescanning the freq array at each step.

    Complexity: O(n + m) time, O(1) space
    """
    if not s or not t:
        return ""

    need   = [0] * 128
    window = [0] * 128

    for c in t:
        need[ord(c)] += 1

    deficit = sum(1 for x in need if x > 0)

    left = 0
    min_len = float('inf')
    min_start = 0

    for right, rc in enumerate(s):
        r_ord = ord(rc)
        window[r_ord] += 1
        if need[r_ord] > 0 and window[r_ord] == need[r_ord]:
            deficit -= 1

        while deficit == 0:
            if right - left + 1 < min_len:
                min_len   = right - left + 1
                min_start = left

            lc_ord = ord(s[left])
            window[lc_ord] -= 1
            if need[lc_ord] > 0 and window[lc_ord] < need[lc_ord]:
                deficit += 1
            left += 1

    return "" if min_len == float('inf') else s[min_start:min_start + min_len]


# ─────────────────────────────────────────────────────────────────
# Freq array as canonical signature for anagram grouping
# Time: O(n * L)   Space: O(n)
# ─────────────────────────────────────────────────────────────────
def freq_signature(word: str) -> tuple[int, ...]:
    """
    Returns the frequency array as a tuple (immutable, hashable).
    All anagrams of a word share the same signature.
    This is a perfect hash for anagram equivalence classes.
    """
    freq = [0] * ALPHA
    for c in word:
        freq[ord(c) - ord('a')] += 1
    return tuple(freq)


def group_anagrams(words: list[str]) -> list[list[str]]:
    """
    Group words into anagram equivalence classes.

    Key insight: use frequency array tuple as the HashMap key.
    All anagrams map to the same key. No string sorting needed.

    Two approaches:
    1. freq_signature (this implementation) — O(L) per word, O(1) space per key
    2. sorted(word) as key — O(L log L) per word

    Frequency array signature is faster for long words.

    Complexity: O(n * L) time, O(n) space
    """
    groups: dict[tuple[int, ...], list[str]] = defaultdict(list)
    for word in words:
        groups[freq_signature(word)].append(word)
    return list(groups.values())


# ─────────────────────────────────────────────────────────────────
# Frequency-based palindrome check (at most one odd-count character)
# Time: O(n)   Space: O(1)
# ─────────────────────────────────────────────────────────────────
def can_form_palindrome(s: str) -> bool:
    """
    Return True if the characters of s can be rearranged into a palindrome.

    A palindrome permutation is possible iff at most one character
    has an odd frequency (the center character for odd-length strings).

    Uses freq array — faster than Counter for fixed alphabet.

    Complexity: O(n) time, O(1) space
    """
    freq = build_freq(s)
    odd_count = sum(1 for x in freq if x % 2 == 1)
    return odd_count <= 1


# ─────────────────────────────────────────────────────────────────
# Comparing freq arrays as a fixed-size vector (ML feature connection)
# ─────────────────────────────────────────────────────────────────
def char_freq_vector(s: str, alphabet: str = "abcdefghijklmnopqrstuvwxyz") -> list[float]:
    """
    Normalised character frequency vector — a fixed-size feature vector.
    freq[i] = fraction of characters in s that equal alphabet[i].

    This is the character-level bag-of-words representation used in
    text classification, language identification, and authorship detection.
    All strings map to the same-dimensional space regardless of length.

    Complexity: O(n) time, O(|alphabet|) space
    """
    alpha_size = len(alphabet)
    freq = [0] * alpha_size
    for c in s:
        idx = alphabet.find(c)
        if idx != -1:
            freq[idx] += 1

    total = sum(freq)
    if total == 0:
        return freq
    return [f / total for f in freq]
```

### Anagram Detection: Difference Counter Visualised

Checking `"listen"` vs `"silent"`:

```
Step 1 — Increment for "listen":
  l:+1  i:+1  s:+1  t:+1  e:+1  n:+1

  freq: e=1, i=1, l=1, n=1, s=1, t=1  (all others 0)

Step 2 — Decrement for "silent":
  s:-1  i:-1  l:-1  e:-1  n:-1  t:-1

  After: e=0, i=0, l=0, n=0, s=0, t=0

All zeros → TRUE (anagrams) ✓

For "rat" vs "car" (NOT anagrams):
  Increment "rat": a=1, r=1, t=1
  Decrement "car": a=0, c=-1, r=0  (c goes negative — novel character)

  freq: c=-1, t=1  (nonzero entries remain)
  → FALSE ✓
```

### Sliding Window Anagram Detection: The Deficit Counter

Finding anagrams of `p = "ab"` in `s = "abab"` (window size = 2):

```
need = [a:1, b:1],  deficit = 2  (2 distinct required chars)

Initial window s[0..1] = "ab":
  Add 'a': window[a]=1 == need[a]=1 → deficit=1
  Add 'b': window[b]=1 == need[b]=1 → deficit=0
  deficit==0 → RECORD position 0 ✓

Slide to s[1..2] = "ba":
  Add s[2]='a': window[a]=2. need[a]=1. 2≠1, no deficit change. deficit=0
  Remove s[0]='a': window[a] was 2, dropping to 1.
    Was window[a]==need[a]? No (2≠1). No deficit created.
    window[a]=1.
  deficit==0 → RECORD position 1 ✓

Slide to s[2..3] = "ab":
  Add s[3]='b': window[b]=2. 2≠1, no deficit change. deficit=0
  Remove s[1]='b': window[b] was 2, dropping to 1.
    Was window[b]==need[b]? No (2≠1). No deficit created.
    window[b]=1.
  deficit==0 → RECORD position 2 ✓

Result: [0, 1, 2] — every position is a valid anagram start.

Key: deficit counter tells us validity in O(1). We never scan
     the full freq array after each slide step.
```

## 7. Common Variations & Extensions

### Variation 1: Sorted String as Signature (vs. Freq Array as Signature)

Two equivalent ways to define an anagram's canonical form:

```python
# Method A: sort the string — O(L log L)
key = ''.join(sorted(word))

# Method B: frequency array tuple — O(L)
key = tuple(build_freq(word))
```

Method B is asymptotically faster and produces a fixed-size key (always 26 integers) regardless of word length. For words with L > 26, Method B is always faster. For very short words (L ≤ 5), the sort constant wins in practice. The freq array approach also **directly encodes what matters** (character counts) without the intermediate sorted string. See [[22.Anagram detection and group-by-signature patterns]] for the full treatment.

### Variation 2: XOR-Based Frequency Trick

For problems asking "which single character appears an odd number of times?", XOR all characters together. XOR is self-inverse: identical characters cancel. The result is the character appearing oddly. This is O(n) time and O(1) space — even O(1) space in the truest sense (one integer register). It's the frequency array concept taken to its logical extreme. See [[100.XOR patterns — finding the missing element, single non-duplicate]].

```python
def odd_occurring_char(s: str) -> str:
    result = 0
    for c in s:
        result ^= ord(c)
    return chr(result)  # works when exactly one char has odd count
```

### Variation 3: Frequency of Frequencies

Some problems ask about the distribution of frequencies: "can you make all character frequencies equal by removing at most one character?" (LC 1347). Build the freq array, then build a second-level freq array (frequency of each frequency value). This nested structure is O(|Σ|) to build from the freq array. It collapses multiple different frequency values into a histogram of histograms.

### Variation 4: DNA / Protein Alphabets

For genomics problems with alphabet {A, C, G, T} (size 4), the freq array has 4 entries — fitting in a single machine word. For protein sequences with 20 amino acids, 20 entries. The same pattern applies with a different base and alphabet size. The ML connection is direct: k-mer profiles for genomic ML are frequency arrays over these small alphabets, producing fixed-length feature vectors.

### Variation 5: Frequency Array for Counting Sort

The frequency array _is_ the histogram that drives counting sort. After building `freq`, the sorted output is: output `freq[0]` copies of `'a'`, then `freq[1]` copies of `'b'`, etc. — O(n + |Σ|) total. This is the direct link to [[49.Counting sort — O(n + k) for integer keys]]. For strings of lowercase letters, counting sort is O(n) — faster than any comparison-based sort.

## 9. CP Contest Application

### Typical Problem Structures

**Type 1 — Anagram / permutation existence (Div. 2 B):** "Given strings s and t, find the minimum number of character replacements to make t an anagram of s." Build freq arrays for both, compute the total "excess" on one side: `sum(max(0, freq_s[i] - freq_t[i]) for i in range(26))`. This equals the number of replacements. O(n) — always fits any time limit.

**Type 2 — Sliding window character constraint (Div. 2 C):** "Find the length of the longest substring containing at most k distinct characters." Sliding window with a freq array and a `distinct_count` integer updated at each step. O(n) solution. The freq array is the window state; `distinct_count` is the invariant monitor. The naive approach of scanning the freq array at each step is O(n × |Σ|) — acceptable for |Σ| = 26 at n = 10⁵ (2.6 × 10⁶ ops), but the distinct counter approach is cleaner and handles |Σ| = 128 or 256 without worry.

**Type 3 — Multi-string freq comparison (Div. 2 C / Div. 1 B):** "Given n strings, group them into equivalence classes where two strings are equivalent if one is a permutation of the other. Output the number of classes." Compute freq signature for each string, use a HashMap. O(n × L) time where L = max string length. For n = 10⁵ and L = 100, this is 10⁷ operations — fast.

**Type 4 — Frequency of frequencies (Div. 1 B / C):** "Find the minimum number of character deletions to make all remaining characters have the same frequency." Build freq array, then frequency-of-frequencies array, then reason about which target frequency minimises deletions. The two-level frequency structure is the key insight. O(n + |Σ|²) at worst — for |Σ| = 26, this is O(n).

### Time Limit Notes

The freq array is so fast that it almost never causes TLE. The only scenario where freq array operations appear in TLE analysis:

- **Scanning the full freq array at each window step**: O(n × |Σ|). For |Σ| = 26 and n = 10⁵, this is 2.6 × 10⁶ — fine. For |Σ| = 256 and n = 10⁶, it's 2.56 × 10⁸ — borderline. Use the deficit counter instead.
- **Clearing the freq array between test cases**: Use `memset` or `fill`, not a loop written with an inner branch. `memset(freq, 0, sizeof(freq))` is a single instruction on modern CPUs for small arrays.
