## 1. Intuition First

### The Core Idea

Picture a race track. Two runners start at the same point. One jogs at 1 step per second — the **slow pointer**. The other sprints at 2 steps per second — the **fast pointer**. If the track is a **straight line**, the fast runner reaches the end first and you can use the gap between them as a ruler. If the track is a **loop**, the fast runner will eventually lap the slow runner — they must meet again somewhere on the loop.

This is the same-direction two-pointer technique, and those two scenarios map precisely to its two canonical uses:

1. **Straight-line (array) problems:** `fast` scouts ahead while `slow` marks a write position, a partition boundary, or a validated frontier. The gap `fast - slow` is information.
2. **Cyclic (linked list) problems:** If fast moves at 2× and there's a cycle, fast will catch slow _inside_ the cycle. No cycle → fast hits null. This is Floyd's Tortoise and Hare.

Both cases share a single invariant: **slow always points to the last confirmed correct position; fast explores ahead and reports back.**

### Why This Exists

The naive approach to "remove duplicates from a sorted array in-place" is to build a new array — O(n) space. Or to shift elements left every time you remove one — O(n²) time. Neither is acceptable for n = 10⁷ (genomics data, log processing, streaming sensor reads).

Same-direction two pointers achieve **O(n) time and O(1) space** by treating the input array as _simultaneously_ a source (read by `fast`) and a destination (written by `slow`). You never need extra memory because `fast` is always ahead of `slow` — reads happen before writes overwrite anything.

For cyclic detection, the naive approach stores every visited node in a HashSet — O(n) space. Floyd's algorithm uses two pointers and O(1) space by exploiting a mathematical property: in a cycle of length λ, a 2× speed pointer _must_ eventually overlap a 1× speed pointer.

### The "Aha" Moment

> **Slow is a commitment; fast is a question.** Fast asks "is this element worth keeping / is there still cycle ahead?" Slow commits to the answer. The two pointers partition the array into: [confirmed valid | unprocessed] with slow as the boundary, and fast as the probe that decides what crosses that boundary.

For Floyd's specifically:

> **Two runners on a loop, one twice as fast — they must eventually share a position. The meeting point encodes the cycle's structure.** This isn't magic: in a cycle of length λ, after μ steps to reach the cycle entry and some steps inside, fast is always (fast_steps - slow_steps) = slow_steps ahead of slow _within the cycle_, and that difference is periodic.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- "Remove duplicates from sorted array in-place" → slow/fast write pointer
- "Move all zeros to end" → fast scans, slow marks next write position
- "Find the middle of a linked list" → fast moves 2×, slow moves 1×, when fast hits end, slow is at middle
- "Detect cycle in linked list" → Floyd's; "find cycle entry" → Floyd's phase 2
- "Remove n-th node from end" → advance fast n steps first, then move both until fast hits end
- "Find duplicate number in array 1..n" (Floyd's on implicit linked list — LC 287)

**Signal pattern:**

```
In-place array transformation with a "write cursor" → slow/fast write pointer
Linked list + cycle or middle or k-from-end     → Floyd's fast/slow
"Without extra space" + linked list structure   → always think fast/slow first
```

**Common trap that kills submissions:**

**Trap 1 — Off-by-one in the write pointer:** After the loop, `slow` is the index of the last written element, not the count. Count = `slow + 1`. Returning `slow` instead of `slow + 1` causes wrong-answer on every test case that isn't empty:

```cpp
// BUG: returns index, not length
return slow;  // ← Wrong

// CORRECT:
return slow + 1;  // slow is 0-indexed position of last valid element
```

**Trap 2 — Fast pointer null check order:** In Floyd's detection, always check `fast != null` before `fast->next != null`. The short-circuit evaluation must be in this order or you get a null pointer dereference:

```cpp
// BUG: if fast == null, fast->next crashes
while (fast->next != null && fast != null)

// CORRECT: check fast first
while (fast != null && fast->next != null)
```

**Trap 3 — Cycle entry vs cycle detection:** Floyd's phase 1 finds _that_ a cycle exists and a meeting point. Phase 2 (reset one pointer to head, advance both at 1× speed) finds _where_ the cycle _enters_. Students consistently confuse these as one step.

---

### Machine Learning / AI

**Where this appears:**

1. **Dataset deduplication in preprocessing pipelines:** When a dataset is sorted (or sorted by hash), removing duplicate rows in-place is a two-pointer scan: `slow` marks the last unique row written, `fast` scans forward. NumPy's `np.unique()` with `return_index=True` uses exactly this after sorting — it's a slow/fast write-pointer sweep over the sorted index array. For a 100M-row DataFrame, the difference between O(n) in-place and O(n) copy-based matters for RAM.
    
2. **Attention mask construction in Transformer batching:** When packing variable-length sequences into a batch (see [[15.Windowed time-series features — ML connection to rolling()]]), a slow pointer tracks the current fill level of the batch while a fast pointer walks through the candidate sequence list. The fast/slow gap = remaining batch capacity. This is the algorithmic core of HuggingFace's `DataCollatorWithPadding` packing logic.
    
3. **Gradient checkpointing — the "two-speed traversal" of the computation graph:** In PyTorch's `torch.utils.checkpoint`, the forward pass stores only _checkpoint_ activations (slow pointer, every k layers), not all intermediate activations. During backward, a fast recomputation pass re-runs forward from the last checkpoint. This is conceptually a fast/slow sweep over the computation graph — slow marks checkpoints, fast recomputes between them. The same O(n/k) space, O(n + n/k · k) = O(n) time trade-off.
    
4. **Cycle detection in computational graphs and RL environment loops:** Detecting infinite loops in RL environment rollouts (a buggy environment that cycles its state) is a direct application of Floyd's algorithm on the state sequence. If `env.step()` ever returns a state it's seen before, the fast/slow pointer on the state sequence detects it in O(cycle_length) time without storing all visited states — critical for long rollouts.
    
5. **Reservoir sampling and streaming data:** The "find the k-th element from the end of a stream" problem (solved by advancing fast k steps, then moving both) is directly analogous to the algorithm used in **streaming data pipelines** (Apache Kafka consumers, PyTorch `IterableDataset`) where you need a fixed-lag look-ahead window without buffering the entire stream.
    

**Why understanding this makes you better at ML code:**

When you see an in-place transformation loop in preprocessing or an "avoid re-allocating" constraint in a high-throughput data pipeline, reach for the write-pointer pattern. Replacing a list comprehension + concatenation with an in-place slow/fast sweep can eliminate an entire memory allocation — at batch sizes of 10⁶, this is the difference between fitting in L3 cache and going to RAM.

## 3. Algorithm / Pattern

### The Two Sub-patterns

Same-direction two pointers splits into two fundamentally different mechanical patterns that share the same directional intuition:

---

**Pattern A: Write Pointer (Arrays)**

Used for: in-place filter, partition, deduplication, compression.

```
slow = first position that needs to be written (or the last confirmed valid position)
fast = current element being examined

Invariant: arr[0..slow] is always the valid/confirmed prefix
           arr[slow+1..fast-1] has been processed and discarded/overwritten
           arr[fast..n-1] is unexamined
```

1. Initialise `slow = 0` (or -1 if slow means "last written"), `fast = 0` (or 1 for dedup).
2. For each `fast` from 0 to n−1:
    - If `arr[fast]` satisfies the keep condition:
        - Write `arr[slow] = arr[fast]` (or `arr[slow+1] = arr[fast]`; `slow++`)
3. Return `slow` (length = slow+1, or slow depending on initialisation).

---

**Pattern B: Floyd's Tortoise and Hare (Linked Lists / Implicit Graphs)**

Used for: cycle detection, middle finding, k-from-end, duplicate detection.

**Phase 1 — Detect:**

1. `slow = head`, `fast = head`.
2. While `fast != null && fast.next != null`:
    - `slow = slow.next`
    - `fast = fast.next.next`
3. If loop exits with `fast == null`: **no cycle**.
4. If loop exits with `slow == fast`: **cycle exists**, meeting point is `slow`.

**Phase 2 — Locate entry (if cycle found):**

1. Reset `slow = head`. Keep `fast` at meeting point.
2. Advance both one step at a time until `slow == fast`.
3. That node is the **cycle entry**.

**Why Phase 2 works — the math:**

Let μ = distance from head to cycle entry, λ = cycle length.  
At meeting: slow has traveled μ + a steps (a steps inside cycle).  
Fast has traveled μ + a + kλ steps for some integer k (same position, but lapped k times).  
Since fast = 2 × slow: `2(μ + a) = μ + a + kλ` → `μ + a = kλ` → `μ = kλ − a`.  
Resetting slow to head and advancing both at 1×: slow travels μ steps (reaches cycle entry), fast travels μ = kλ − a steps from meeting point, which lands exactly at the cycle entry (since it's travelling kλ − a steps within a cycle of length λ). ∎

---

### Decision Tree

```
Same-direction two-pointer problem?
├── Array-based?
│   ├── "Remove/filter elements in-place" → Write pointer pattern
│   │   slow = next write position, fast scans all elements
│   ├── "Partition array" (zeros to end, negatives left) → Write pointer
│   ├── "Remove duplicates from sorted array" → slow = last unique, fast probes
│   └── "Find two elements with gap k" → advance fast k steps first, then both
│
└── Linked list / implicit graph?
    ├── "Does a cycle exist?" → Floyd's Phase 1
    ├── "Where does the cycle start?" → Floyd's Phase 1 + Phase 2
    ├── "Find middle node" → fast moves 2×, stop when fast hits end
    ├── "Find k-th from end" → advance fast k steps, then move both 1×
    └── "Find duplicate in 1..n array" → treat as implicit linked list, Floyd's
```

### Complexity

**Write Pointer:**

- Time: O(n) — fast visits each element exactly once
- Space: O(1) — in-place, no auxiliary structures

**Floyd's Cycle Detection:**

- Time: O(μ + λ) = O(n) — meeting happens within one full loop traversal
- Space: O(1) — two pointers only

**Derivation of Floyd's O(n):** Fast pointer moves at 2×. After μ steps, slow enters cycle. Fast is at position 2μ mod λ in the cycle. Gap between fast and slow inside the cycle = (2μ − μ) mod λ = μ mod λ. Each step reduces this gap by 1 (fast gains 1 on slow within the cycle). Gap ≤ λ steps to close. Total steps ≤ μ + λ = O(n).

## 4. Pseudocode

### Pattern A: Write Pointer (Remove Duplicates from Sorted Array)

```
function REMOVE_DUPLICATES(arr[0..n-1]):
    # Precondition: arr is sorted
    # Postcondition: arr[0..slow] contains unique elements in order
    # Returns: count of unique elements

    if n == 0: return 0

    slow ← 0   # slow = index of last confirmed unique element written

    for fast ← 1 to n-1:
        if arr[fast] ≠ arr[slow]:
            # arr[fast] is a new unique element — commit it
            slow ← slow + 1
            arr[slow] ← arr[fast]   # write to next position after confirmed prefix
        # else: arr[fast] is a duplicate — fast advances, slow stays
        # The duplicate is "overwritten" when the next unique element arrives

    return slow + 1   # count = last valid index + 1
```

### Pattern B: Floyd's Tortoise and Hare

```
function DETECT_CYCLE(head):
    slow ← head
    fast ← head

    # Phase 1: Find meeting point
    while fast ≠ null AND fast.next ≠ null:
        slow ← slow.next        # tortoise: 1 step
        fast ← fast.next.next  # hare: 2 steps

        if slow == fast:
            # Cycle confirmed. Locate the entry.
            # Phase 2: Reset slow to head, keep fast at meeting point
            slow ← head
            while slow ≠ fast:
                slow ← slow.next
                fast ← fast.next   # BOTH move 1 step now
            return slow   # cycle entry node

    return null   # no cycle


function FIND_MIDDLE(head):
    slow ← head
    fast ← head

    # When fast reaches end, slow is at middle
    # For even-length lists: slow lands on the first of two middles
    while fast ≠ null AND fast.next ≠ null:
        slow ← slow.next
        fast ← fast.next.next

    return slow


function FIND_KTH_FROM_END(head, k):
    slow ← head
    fast ← head

    # Advance fast k steps ahead
    repeat k times:
        if fast == null: return null   # list shorter than k
        fast ← fast.next

    # Now move both until fast hits end
    # When fast == null, slow is k steps from end
    while fast ≠ null:
        slow ← slow.next
        fast ← fast.next

    return slow
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <vector>
#include <cassert>

// ─────────────────────────────────────────────────────────────────
// Pattern A1: Remove duplicates from sorted array in-place
// Returns: new length (unique elements count)
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
int removeDuplicates(std::vector<int>& nums) {
    if (nums.empty()) return 0;

    int slow = 0;  // index of last confirmed unique element

    for (int fast = 1; fast < static_cast<int>(nums.size()); ++fast) {
        if (nums[fast] != nums[slow]) {
            // New unique element found — advance slow and write
            ++slow;
            nums[slow] = nums[fast];
        }
        // Duplicate: fast advances, slow holds its position
    }

    return slow + 1;  // length = last valid index + 1
}

// ─────────────────────────────────────────────────────────────────
// Pattern A2: Move zeros to end, preserve relative order of non-zeros
// Classic write-pointer: slow = next write position for non-zeros
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
void moveZeros(std::vector<int>& nums) {
    int slow = 0;  // next position to write a non-zero element

    // Pass 1: write all non-zeros to [0..slow-1]
    for (int fast = 0; fast < static_cast<int>(nums.size()); ++fast) {
        if (nums[fast] != 0) {
            nums[slow++] = nums[fast];
        }
    }

    // Pass 2: fill remaining positions with zeros
    while (slow < static_cast<int>(nums.size())) {
        nums[slow++] = 0;
    }
}

// ─────────────────────────────────────────────────────────────────
// Linked list node definition
// ─────────────────────────────────────────────────────────────────
struct ListNode {
    int val;
    ListNode* next;
    ListNode(int x, ListNode* n = nullptr) : val(x), next(n) {}
};

// ─────────────────────────────────────────────────────────────────
// Pattern B1: Floyd's cycle detection + cycle entry location
// Returns: pointer to cycle entry node, or nullptr if no cycle
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
ListNode* detectCycle(ListNode* head) {
    if (!head || !head->next) return nullptr;

    ListNode* slow = head;
    ListNode* fast = head;

    // Phase 1: find meeting point inside cycle
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;

        if (slow == fast) {
            // Phase 2: find cycle entry
            // Reset slow to head; fast stays at meeting point
            // Both advance 1 step at a time — they meet at cycle entry
            slow = head;
            while (slow != fast) {
                slow = slow->next;
                fast = fast->next;
            }
            return slow;  // cycle entry
        }
    }

    return nullptr;  // no cycle
}

// ─────────────────────────────────────────────────────────────────
// Pattern B2: Find middle of linked list
// For even length, returns the SECOND middle (modify condition for first)
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
ListNode* middleNode(ListNode* head) {
    ListNode* slow = head;
    ListNode* fast = head;

    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
    }

    return slow;
}

// ─────────────────────────────────────────────────────────────────
// Pattern B3: Remove k-th node from end of list
// Returns: new head (head may be removed)
// Time: O(n)   Space: O(1)
// ─────────────────────────────────────────────────────────────────
ListNode* removeNthFromEnd(ListNode* head, int n) {
    // Dummy node handles edge case where head is removed
    ListNode dummy(0, head);
    ListNode* slow = &dummy;
    ListNode* fast = head;

    // Advance fast n steps ahead
    for (int i = 0; i < n; ++i) {
        fast = fast->next;
    }

    // Move both until fast hits end
    // slow will be the node BEFORE the one to delete
    while (fast) {
        slow = slow->next;
        fast = fast->next;
    }

    // Delete the target node
    ListNode* to_delete = slow->next;
    slow->next = slow->next->next;
    delete to_delete;

    return dummy.next;
}

// ─────── Minimal tests ──────────────────────────────────────────
int main() {
    // Test A1: remove duplicates
    std::vector<int> v = {1, 1, 2, 3, 3, 4};
    int len = removeDuplicates(v);
    assert(len == 4);
    assert(v[0]==1 && v[1]==2 && v[2]==3 && v[3]==4);

    // Test A2: move zeros
    std::vector<int> z = {0, 1, 0, 3, 12};
    moveZeros(z);
    assert((z == std::vector<int>{1, 3, 12, 0, 0}));

    // Test B1: cycle detection
    // Build: 3 -> 2 -> 0 -> -4 -> (back to 2)
    ListNode* n4 = new ListNode(-4);
    ListNode* n3 = new ListNode(0, n4);
    ListNode* n2 = new ListNode(2, n3);
    ListNode* n1 = new ListNode(3, n2);
    n4->next = n2;  // cycle: -4 points back to 2
    ListNode* entry = detectCycle(n1);
    assert(entry == n2 && entry->val == 2);

    // Test B2: middle node
    // Build: 1 -> 2 -> 3 -> 4 -> 5
    ListNode* list = new ListNode(1, new ListNode(2, new ListNode(3,
                     new ListNode(4, new ListNode(5)))));
    assert(middleNode(list)->val == 3);

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations
from typing import Optional


# ─────────────────────────────────────────────────────────────────
# Pattern A1: Remove duplicates from sorted array in-place
# ─────────────────────────────────────────────────────────────────
def remove_duplicates(nums: list[int]) -> int:
    """
    Remove duplicates from sorted list in-place.
    Returns the count of unique elements.
    The first `count` elements of nums hold the unique values.

    Complexity: O(n) time, O(1) space
    """
    if not nums:
        return 0

    slow = 0  # last confirmed unique position

    for fast in range(1, len(nums)):
        if nums[fast] != nums[slow]:
            slow += 1
            nums[slow] = nums[fast]
            # Key insight: we only write when we find something new.
            # Duplicates are simply jumped over by fast.

    return slow + 1  # count = index of last unique + 1


# ─────────────────────────────────────────────────────────────────
# Pattern A2: Move zeros to end, preserve relative order
# ─────────────────────────────────────────────────────────────────
def move_zeros(nums: list[int]) -> None:
    """
    Move all zeros to end of list in-place.
    Non-zero elements preserve their relative order.

    Complexity: O(n) time, O(1) space
    """
    slow = 0  # next write position for non-zero elements

    for fast in range(len(nums)):
        if nums[fast] != 0:
            nums[slow] = nums[fast]
            slow += 1

    # Fill rest with zeros
    for i in range(slow, len(nums)):
        nums[i] = 0


# ─────────────────────────────────────────────────────────────────
# Linked list node
# ─────────────────────────────────────────────────────────────────
class ListNode:
    def __init__(self, val: int = 0, next: Optional[ListNode] = None):
        self.val = val
        self.next = next

    def __repr__(self) -> str:
        """Safe repr — only follows next up to 10 nodes to avoid cycle infinite loop."""
        nodes, curr, seen = [], self, set()
        while curr and id(curr) not in seen:
            seen.add(id(curr))
            nodes.append(str(curr.val))
            curr = curr.next
        if curr:
            nodes.append(f"→ cycle at {curr.val}")
        return " → ".join(nodes)


# ─────────────────────────────────────────────────────────────────
# Pattern B1: Floyd's cycle detection + cycle entry
# ─────────────────────────────────────────────────────────────────
def detect_cycle(head: Optional[ListNode]) -> Optional[ListNode]:
    """
    Detect if linked list has a cycle. If so, return the entry node.
    Returns None if no cycle.

    Math: if μ = dist(head → entry), λ = cycle length,
    meeting point satisfies: μ ≡ -a (mod λ), so resetting slow
    to head and advancing both 1× meets at entry. (See note 3 above.)

    Complexity: O(n) time, O(1) space
    """
    if not head or not head.next:
        return None

    slow, fast = head, head

    # Phase 1: detect meeting point
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            break
    else:
        return None  # fast hit end → no cycle

    # Phase 2: locate entry
    slow = head
    while slow is not fast:
        slow = slow.next
        fast = fast.next

    return slow  # cycle entry node


# ─────────────────────────────────────────────────────────────────
# Pattern B2: Find middle of linked list
# ─────────────────────────────────────────────────────────────────
def find_middle(head: Optional[ListNode]) -> Optional[ListNode]:
    """
    Return the middle node of a linked list.
    For even-length lists, returns the second middle node.
    (Change condition to `fast.next and fast.next.next` for first middle.)

    Complexity: O(n) time, O(1) space
    """
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow


# ─────────────────────────────────────────────────────────────────
# Pattern B3: Find duplicate number in array [1..n] using Floyd's
# This treats the array as an implicit linked list: index → value → index
# ─────────────────────────────────────────────────────────────────
def find_duplicate(nums: list[int]) -> int:
    """
    Given n+1 integers in [1, n], find the one duplicate.
    No modification, O(1) extra space.

    Key insight: treat nums[i] as a 'next pointer'. Since values are
    in [1,n] and indices are [0,n], there's guaranteed to be a cycle
    (by pigeonhole), and the cycle entry IS the duplicate value.

    Complexity: O(n) time, O(1) space
    """
    # Phase 1: find intersection point
    slow, fast = nums[0], nums[nums[0]]
    while slow != fast:
        slow = nums[slow]
        fast = nums[nums[fast]]

    # Phase 2: find cycle entry = duplicate value
    slow = 0
    while slow != fast:
        slow = nums[slow]
        fast = nums[fast]

    return slow


# ─────────────────────────────────────────────────────────────────
# Pattern B4: k-th node from end
# ─────────────────────────────────────────────────────────────────
def kth_from_end(head: Optional[ListNode], k: int) -> Optional[ListNode]:
    """
    Return the k-th node from the end of a linked list.
    k=1 returns the last node.

    Complexity: O(n) time, O(1) space
    """
    slow = fast = head

    # Advance fast k steps ahead
    for _ in range(k):
        if not fast:
            return None  # list shorter than k
        fast = fast.next

    # Move both until fast hits end
    while fast:
        slow = slow.next
        fast = fast.next

    return slow  # now exactly k steps from end


# ─────── Smoke tests ─────────────────────────────────────────────
if __name__ == "__main__":
    # A1: remove duplicates
    nums = [1, 1, 2, 3, 3, 4]
    length = remove_duplicates(nums)
    assert length == 4 and nums[:4] == [1, 2, 3, 4], f"Got {nums[:length]}"

    # A2: move zeros
    z = [0, 1, 0, 3, 12]
    move_zeros(z)
    assert z == [1, 3, 12, 0, 0], f"Got {z}"

    # B1: cycle detection
    # Build 3 → 2 → 0 → -4 → (back to node with val 2)
    n4 = ListNode(-4)
    n3 = ListNode(0, n4)
    n2 = ListNode(2, n3)
    n1 = ListNode(3, n2)
    n4.next = n2  # cycle: -4 → 2
    entry = detect_cycle(n1)
    assert entry is n2 and entry.val == 2, f"Got {entry}"

    # B2: middle node
    nodes = [ListNode(i) for i in range(1, 6)]
    for i in range(4): nodes[i].next = nodes[i+1]
    # 1 → 2 → 3 → 4 → 5
    assert find_middle(nodes[0]).val == 3

    # B3: find duplicate
    # [1,3,4,2,2]: nums[0]=1, nums[1]=3, nums[2]=4, nums[3]=2, nums[4]=2
    assert find_duplicate([1, 3, 4, 2, 2]) == 2
    assert find_duplicate([3, 1, 3, 4, 2]) == 3

    # B4: kth from end
    head = nodes[0]  # 1→2→3→4→5
    assert kth_from_end(head, 2).val == 4  # 2nd from end

    print("All tests passed.")
```

## 6. Visual Explanation

### Pattern A: Write Pointer in Action

Removing duplicates from `[1, 1, 2, 3, 3, 3, 4]`:

```
Initial:
  [1,  1,  2,  3,  3,  3,  4]
   S                              slow=0: "1 is confirmed unique"
   F                              fast=0 (starts at 1 next iteration)

Step 1: fast=1, nums[1]=1 == nums[slow=0]=1 → duplicate, skip
  [1,  1,  2,  3,  3,  3,  4]
   S   F                          slow stays at 0

Step 2: fast=2, nums[2]=2 ≠ nums[slow=0]=1 → NEW, commit
  [1,  2,  2,  3,  3,  3,  4]
       S   F                      slow advances to 1, write nums[1]=2

Step 3: fast=3, nums[3]=3 ≠ nums[slow=1]=2 → NEW, commit
  [1,  2,  3,  3,  3,  3,  4]
           S   F                  slow advances to 2, write nums[2]=3

Step 4: fast=4, nums[4]=3 == nums[slow=2]=3 → duplicate, skip
Step 5: fast=5, nums[5]=3 == nums[slow=2]=3 → duplicate, skip
  [1,  2,  3,  3,  3,  3,  4]
           S           F

Step 6: fast=6, nums[6]=4 ≠ nums[slow=2]=3 → NEW, commit
  [1,  2,  3,  4,  3,  3,  4]
               S           F      slow=3, write nums[3]=4

Loop ends. Return slow+1 = 4.
Valid prefix: [1, 2, 3, 4] ✓

Key observation: everything in [slow+1 .. fast-1] is "garbage" — it's
either duplicates or elements that have been "moved forward" and left
a copy behind. We don't care. Only [0..slow] matters.
```

### Pattern B: Floyd's Algorithm — Phase 1 and Phase 2

For list: `head → A → B → C → D → E → C` (cycle entry at C):

```
Notation: s=slow, f=fast. Start: both at head.

Step 0:  head→A→B→C→D→E→C→...
         sf

Step 1:  s moves 1, f moves 2
         s at A,  f at B

Step 2:  s at B,  f at D

Step 3:  s at C,  f at C    ← MEETING POINT (inside cycle)
                               (fast lapped slow inside C→D→E→C→D loop)

Phase 2: Reset s to head. Both move 1× step.

         s at head, f at C

Step 1:  s at A,   f at D
Step 2:  s at B,   f at E
Step 3:  s at C,   f at C   ← BOTH AT C = CYCLE ENTRY ✓

Why? μ=3 (head→A→B→C), λ=3 (C→D→E→C).
Meeting at C means a=0 (met exactly at entry here).
In general: from meeting point, fast needs μ more steps to
reach entry (since μ = kλ - a by the proof above).
```

### The Implicit Linked List (LC 287 — Find the Duplicate)

For `nums = [1, 3, 4, 2, 2]`, treat `i → nums[i]` as a linked list edge:

```
Index:  0   1   2   3   4
Value:  1   3   4   2   2

Edges (index → value):
  0 → 1 → 3 → 2 → 4 → 2 (cycle!)
                  ↑_______↓
  
Cycle entry = 2 = the duplicate value.

Floyd's on this implicit graph:
  slow starts at nums[0]=1, fast at nums[nums[0]]=nums[1]=3
  
  Step 1: slow=nums[1]=3,  fast=nums[nums[3]]=nums[2]=4
  Step 2: slow=nums[3]=2,  fast=nums[nums[4]]=nums[2]=4
  Step 3: slow=nums[2]=4,  fast=nums[nums[4]]=nums[2]=4  → MEET at 4

  Phase 2: slow=0 (index, not value!), fast stays at 4
  Step 1: slow=nums[0]=1,  fast=nums[4]=2
  Step 2: slow=nums[1]=3,  fast=nums[2]=4
  Step 3: slow=nums[3]=2,  fast=nums[4]=2  → MEET at 2 = duplicate ✓
```

## 7. Common Variations & Extensions

### Variation 1: Remove Duplicates — Allow At Most K Copies

Generalisation of the sorted dedup: instead of `nums[fast] != nums[slow]`, compare `nums[fast] != nums[slow - k + 1]`. Allows at most k duplicates of any element:

```python
def remove_duplicates_k(nums: list[int], k: int) -> int:
    slow = 0
    for fast in range(len(nums)):
        # slow < k: never skip (haven't written k elements yet)
        # nums[fast] != nums[slow - k]: the element k positions ago differs
        if slow < k or nums[fast] != nums[slow - k]:
            nums[slow] = nums[fast]
            slow += 1
    return slow
```

### Variation 2: Linked List Palindrome Check

Find middle (fast/slow), reverse the second half, compare with first half using two pointers from opposite ends. This chains [[17.Same-direction two pointers — fast and slow]] → [[16.Opposite-end two pointers — sorted array problems]] → [[19.Two pointers on strings — palindrome, matching]] all in one algorithm.

### Variation 3: Cycle in 2D Grid (Implicit Floyd's)

In certain problems (LC 457 — Circular Array Loop), the "next pointer" is computed from an array of jumps rather than explicit links. Apply Floyd's on the computed traversal sequence. The cycle detection logic is identical; only `next(i) = (i + nums[i]) % n` changes.

### Variation 4: Find the Start of a Cycle in RL State Spaces

In reinforcement learning, if an environment's state transition function has a cycle (buggy sim), treating state hashes as linked list values and applying Floyd's can detect this in O(cycle_length) with O(1) extra storage — no visited-set needed. This is practically useful in fuzzing RL environments.

### Connection to Sliding Window

The write-pointer variant of same-direction two pointers is a degenerate sliding window where the window always shrinks to the element just confirmed valid. See [[12.Variable-size sliding window — shrink and expand logic]] for the generalisation where the window itself is the unit of interest, not the write position. If your fast/slow logic involves a _condition on the window contents_ (not just a single element), upgrade to sliding window.

### Connection to Recursion / Stack

Floyd's cycle detection is the iterative answer to the recursive question "has this computation converged?". The call stack in recursive DFS implicitly stores the path — Floyd's avoids that cost. See [[71.The call stack — stack frames, stack overflow, iterative conversion]] for when to convert between the two forms.

## 9. CP Contest Application

### Typical Problem Structure

**Type 1 — In-place array processing (Codeforces Div. 2 B/C):** "Given a sequence, compress it by removing all consecutive duplicates greater than k, in-place, report the final sequence length." The naive approach shifts elements left (O(n²)). Write-pointer does it in O(n). At n = 2×10⁵ and time limit 1s, naive is 4×10¹⁰ operations — definite TLE.

**Type 2 — Functional graph cycle detection (Div. 1 B/C):** A **functional graph** — where each node has exactly one outgoing edge — is the natural habitat of Floyd's. Every connected component has exactly one cycle. Problems involving "what does node i eventually reach?", "are nodes i and j in the same cycle?", or "what's the period of this sequence?" all reduce to Floyd's on the functional graph.

```
Example: given a permutation P of [0..n-1], find the smallest k such
that applying P k times returns to the identity. Answer = LCM of all
cycle lengths in the permutation's functional graph. Floyd's per cycle,
then LCM. Time: O(n log n), Space: O(1) after marking visited.
```

**Type 3 — Happy Number / Sequence Periodicity (often appears as warm-up):** Any sequence defined by `x_{n+1} = f(x_n)` on a finite domain must eventually cycle (by pigeonhole, see [[192.Pigeonhole principle — and its use in hashing collision arguments]]). Floyd's detects the cycle without storing all prior values — critical when the domain is large (e.g., 64-bit integers).

### Time Limit and Optimisation Notes

|n|Write-pointer O(n)|Naive shift O(n²)|Floyd's O(n)|Verdict|
|---|---|---|---|---|
|10⁵|~10⁵ ops|~10¹⁰ ops|~10⁵ ops|Both two-pointer req|
|10⁶|~10⁶ ops|TLE|~10⁶ ops|Two-pointer required|
|10⁷|~10⁷ ops|TLE|~10⁷ ops|Only O(n) viable|

**CP optimisation trick — avoid the second pass for zeros:** Instead of two passes (write non-zeros, then fill zeros), use a swap:

```cpp
int slow = 0;
for (int fast = 0; fast < n; ++fast) {
    if (nums[fast] != 0) {
        std::swap(nums[slow++], nums[fast]);
    }
}
// One pass, O(n) swaps. Cache-friendly, branch-predictor friendly.
```

**CP optimisation trick — Floyd's on arrays, not nodes:** When the "linked list" is an implicit functional graph over array indices, Floyd's runs on integer arithmetic (index arithmetic), not pointer dereferencing. This is significantly faster in practice — no cache misses from pointer chasing. For competitive programming, the integer-index version is always preferable to pointer-based linked lists.
