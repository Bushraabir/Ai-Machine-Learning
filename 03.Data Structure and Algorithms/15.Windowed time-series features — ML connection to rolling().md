## Motivation — Why Windows?

A raw time series is a sequence of scalars:

$$ x_0, x_1, x_2, \ldots, x_{n-1} $$

A model trained directly on $x_t$ sees only one number. It has no notion of _trend_, _volatility_, _seasonality_, or _local context_. Windowed features give the model a structured view of the recent past.

The core operation: replace each scalar $x_t$ with a **feature vector** derived from the window $[x_{t-k+1}, \ldots, x_t]$:

$$ x_t ;\longrightarrow; \phi(x_{t-k+1}, \ldots, x_t) \in \mathbb{R}^d $$

This is feature engineering, and it is the difference between a model that learns and one that memorises noise.

---

## The Taxonomy of Windowed Features

Every windowed feature is one of four types. Know all four.

### Type 1 — Location (Where is the centre of mass?)

|Feature|Formula|Intuition|
|---|---|---|
|Rolling mean|$\bar{x}_t = \frac{1}{k}\sum_{j=0}^{k-1} x_{t-j}$|Smoothed signal, removes noise|
|Rolling median|$\text{median}(x_{t-k+1:t})$|Robust to outliers|
|Exponential weighted mean|$\mu_t = \alpha x_t + (1-\alpha)\mu_{t-1}$|Recency-weighted, $O(1)$ update|

### Type 2 — Spread (How volatile is the window?)

|Feature|Formula|Intuition|
|---|---|---|
|Rolling std|$\sigma_t = \sqrt{\frac{1}{k}\sum(x_{t-j} - \bar{x}_t)^2}$|Local volatility|
|Rolling var|$\sigma_t^2$|Variance, used in Bollinger Bands|
|Rolling range|$\max - \min$|Peak-to-trough spread|
|Rolling IQR|$Q_{75} - Q_{25}$|Robust spread|

### Type 3 — Extrema (What are the boundaries?)

|Feature|Formula|Intuition|
|---|---|---|
|Rolling max|$\max(x_{t-k+1:t})$|Upper envelope|
|Rolling min|$\min(x_{t-k+1:t})$|Lower envelope|
|Rolling argmax|$\arg\max$ position in window|When did the peak occur?|

### Type 4 — Shape (What is the local structure?)

|Feature|Formula|Intuition|
|---|---|---|
|Rolling skewness|$\frac{\mu_3}{\sigma^3}$|Asymmetry of distribution|
|Rolling kurtosis|$\frac{\mu_4}{\sigma^4} - 3$|Tail heaviness|
|Rolling autocorrelation (lag $\ell$)|$\text{corr}(x_t, x_{t-\ell})$|Periodicity detection|
|Rolling slope (linear trend)|OLS slope over window|Is the signal rising or falling?|

## From-Scratch Implementations

Before reaching for Pandas, implement every feature manually. This is the only way to understand what `rolling()` is doing and debug it when it goes wrong.

### Rolling Mean — $O(n)$ via Running Sum

```python
def rolling_mean(a: list[float], k: int) -> list[float]:
    """
    Computes rolling mean with a running sum — O(n) total.
    The naive approach recomputes the sum each window: O(nk).
    """
    n = len(a)
    result = [None] * n

    window_sum = sum(a[:k])
    result[k - 1] = window_sum / k

    for i in range(k, n):
        window_sum += a[i] - a[i - k]   # O(1) update: add new, drop old
        result[i] = window_sum / k

    return result
```

**The running sum trick** is the foundation. Instead of recomputing $\sum_{j=i-k+1}^{i} x_j$ from scratch each step (cost $O(k)$), we maintain it incrementally:

$$ S_i = S_{i-1} + x_i - x_{i-k} $$

This is the **prefix sum** idea applied online.

---

### Rolling Variance — $O(n)$ via Welford's Algorithm

Naively computing variance requires two passes (mean, then squared deviations). For a sliding window, we need an online single-pass update.

**Welford's online variance update** (numerically stable, the algorithm used in NumPy and Pandas internally):

$$ \delta_1 = x_{\text{new}} - \bar{x}_{\text{old}} $$ $$ \bar{x}_{\text{new}} = \bar{x}_{\text{old}} + \frac{\delta_1}{n} $$ $$ \delta_2 = x_{\text{new}} - \bar{x}_{\text{new}} $$ $$ M_{\text{new}} = M_{\text{old}} + \delta_1 \cdot \delta_2 \quad \text{where } \sigma^2 = M / n $$

For a **sliding** window we also need to remove the outgoing element. The two-pass version is cleaner for fixed $k$:

```python
def rolling_variance(a: list[float], k: int) -> list[float]:
    """
    Rolling variance using the running sum-of-squares trick.
    Var = E[X^2] - (E[X])^2
    """
    n = len(a)
    result = [None] * n

    sum_x  = sum(a[:k])
    sum_x2 = sum(xi**2 for xi in a[:k])
    result[k - 1] = (sum_x2 / k) - (sum_x / k) ** 2

    for i in range(k, n):
        # Add incoming element
        sum_x  += a[i]
        sum_x2 += a[i] ** 2
        # Remove outgoing element
        sum_x  -= a[i - k]
        sum_x2 -= a[i - k] ** 2

        result[i] = (sum_x2 / k) - (sum_x / k) ** 2

    return result

def rolling_std(a: list[float], k: int) -> list[float]:
    return [v**0.5 if v is not None else None for v in rolling_variance(a, k)]
```

**Numerical caveat.** The formula $\text{Var} = E[X^2] - (E[X])^2$ is algebraically exact but numerically unstable when values are large (catastrophic cancellation). Welford's algorithm avoids this. For production code, use Pandas; for understanding, use this.

### Rolling Max / Min — $O(n)$ via Monotonic Deque

Already derived in [[14.Sliding Window Maximum — Monotonic Deque]]. For completeness:

```python
from collections import deque

def rolling_max(a: list[float], k: int) -> list[float]:
    n = len(a)
    result = [None] * n
    dq: deque = deque()  # indices, decreasing values

    for r in range(n):
        while dq and a[dq[-1]] <= a[r]:
            dq.pop()
        dq.append(r)
        if dq[0] < r - k + 1:
            dq.popleft()
        if r >= k - 1:
            result[r] = a[dq[0]]

    return result

def rolling_min(a: list[float], k: int) -> list[float]:
    n = len(a)
    result = [None] * n
    dq: deque = deque()  # indices, increasing values

    for r in range(n):
        while dq and a[dq[-1]] >= a[r]:
            dq.pop()
        dq.append(r)
        if dq[0] < r - k + 1:
            dq.popleft()
        if r >= k - 1:
            result[r] = a[dq[0]]

    return result
```

### Rolling Slope (Linear Trend) — $O(n)$ via Incremental OLS

The slope of the OLS line through the window $(0, x_{t-k+1}), (1, x_{t-k+2}), \ldots, (k-1, x_t)$:

$$ \hat{\beta} = \frac{\sum_{j=0}^{k-1}(j - \bar{j})(x_{t-k+1+j} - \bar{x})}{\sum_{j=0}^{k-1}(j - \bar{j})^2} $$

The denominator $\sum (j - \bar{j})^2 = \frac{k(k^2-1)}{12}$ is a constant for fixed $k$. Only the numerator changes per window.

```python
def rolling_slope(a: list[float], k: int) -> list[float]:
    """
    Linear trend (OLS slope) over each window of size k.
    Denominator is constant for fixed k.
    """
    n = len(a)
    result = [None] * n

    j_bar = (k - 1) / 2                         # mean of [0, 1, ..., k-1]
    denom = sum((j - j_bar)**2 for j in range(k))  # constant

    for i in range(k - 1, n):
        window = a[i - k + 1 : i + 1]
        x_bar = sum(window) / k
        numer = sum((j - j_bar) * (window[j] - x_bar) for j in range(k))
        result[i] = numer / denom

    return result
```

This is $O(nk)$ as written. The fully incremental version (updating the numerator in $O(1)$) exists but requires maintaining several running sums simultaneously — left as an exercise.

## The Pandas `rolling()` API

Pandas wraps all of the above in a clean, vectorised interface backed by Cython/NumPy.

```python
import pandas as pd
import numpy as np

# Simulate a stock price series
np.random.seed(42)
prices = pd.Series(
    100 + np.cumsum(np.random.randn(200) * 0.5),
    name="price"
)

k = 20  # 20-day rolling window

# Location
roll_mean = prices.rolling(k).mean()
roll_median = prices.rolling(k).median()
ewm_mean = prices.ewm(span=k).mean()   # exponential — separate API

# Spread
roll_std = prices.rolling(k).std()     # ddof=1 by default (sample std)
roll_var = prices.rolling(k).var()

# Extrema  (O(n) internally using deque — same as our implementation)
roll_max = prices.rolling(k).max()
roll_min = prices.rolling(k).min()

# Shape
roll_skew = prices.rolling(k).skew()
roll_kurt = prices.rolling(k).kurt()

# Aggregate into feature DataFrame
features = pd.DataFrame({
    "price"      : prices,
    "mean_20"    : roll_mean,
    "std_20"     : roll_std,
    "max_20"     : roll_max,
    "min_20"     : roll_min,
    "range_20"   : roll_max - roll_min,
    "z_score_20" : (prices - roll_mean) / roll_std,  # normalised position
    "slope_20"   : prices.rolling(k).apply(
                       lambda w: np.polyfit(range(k), w, 1)[0], raw=True
                   ),
    "ewm_20"     : ewm_mean,
})

print(features.tail())
```

### The `min_periods` Parameter

By default, `rolling(k)` produces `NaN` for the first $k-1$ rows (insufficient data). You can relax this:

```python
# Allow computation with as few as 1 data point
prices.rolling(k, min_periods=1).mean()
```

**Be careful.** In ML, `NaN` rows are typically dropped or imputed. Setting `min_periods=1` changes the semantics of the early windows and can introduce distribution shift. Be explicit about your choice.

### The `closed` Parameter

Controls which endpoint is included:

```python
prices.rolling(k, closed='left')   # excludes current row — lookahead-free lag feature
prices.rolling(k, closed='right')  # default — includes current row
prices.rolling(k, closed='both')   # includes both endpoints (window size k+1 effectively)
prices.rolling(k, closed='neither')
```

In ML, `closed='right'` is standard: the feature at time $t$ uses data up to and including $t$.

## The Data Leakage Trap

This is the most dangerous mistake in time-series ML feature engineering.

**Leakage** occurs when a feature at time $t$ uses information from time $t+1$ or later. The model appears to perform well in backtesting because it has access to the future during training — but it will fail completely in production.

```python
# ❌ LEAKY — centred window uses future data
prices.rolling(k, center=True).mean()
# The window for index t is [t - k//2, ..., t, ..., t + k//2]
# At training time this is computable; at inference on the latest t, it is not

# ✅ CORRECT — trailing window, only past and present
prices.rolling(k).mean()
# The window for index t is [t - k + 1, ..., t]
```

**The shift(1) pattern for lag features:**

```python
# Feature: yesterday's mean (available at time t, computed from t-k to t-1)
prices.rolling(k).mean().shift(1)
```

This is correct and common. The `.shift(1)` ensures the feature at row $t$ uses data up through row $t-1$.

**The golden rule:**

> Any feature at time $t$ must be computable using only $x_0, x_1, \ldots, x_t$.

## Building a Full Feature Matrix

A production feature engineering pipeline for a time series:

```python
def build_ts_features(series: pd.Series, windows: list[int]) -> pd.DataFrame:
    """
    Constructs a feature matrix from a univariate time series.
    All features are backward-looking (no leakage).
    NaN rows (from rolling warmup) are retained — caller decides how to handle.
    """
    features = pd.DataFrame(index=series.index)
    features["raw"] = series

    for k in windows:
        roll = series.rolling(k)
        tag = f"_{k}"

        # Location
        features[f"mean{tag}"]    = roll.mean()
        features[f"median{tag}"]  = roll.median()
        features[f"ewm{tag}"]     = series.ewm(span=k).mean()

        # Spread
        features[f"std{tag}"]     = roll.std()
        features[f"range{tag}"]   = roll.max() - roll.min()

        # Extrema
        features[f"max{tag}"]     = roll.max()
        features[f"min{tag}"]     = roll.min()

        # Normalised position within window (0 = at min, 1 = at max)
        r_max = roll.max()
        r_min = roll.min()
        denom = (r_max - r_min).replace(0, np.nan)
        features[f"pct_rank{tag}"] = (series - r_min) / denom

        # Trend
        features[f"slope{tag}"]   = roll.apply(
            lambda w: np.polyfit(range(len(w)), w, 1)[0], raw=True
        )

        # Z-score: how many stds is current value from the rolling mean?
        features[f"zscore{tag}"]  = (series - features[f"mean{tag}"]) / features[f"std{tag}"]

        # Lag features (shift to avoid leakage if needed)
        features[f"lag1{tag}"]    = roll.mean().shift(1)

    return features


# Usage
windows = [5, 10, 20, 50]
feat_df = build_ts_features(prices, windows)
print(f"Feature matrix shape: {feat_df.shape}")
# Shape: (200, 1 + 4 * 10) = (200, 41) features
```

## Complexity Summary

|Feature|Naive|Optimised|Method|
|---|---|---|---|
|Rolling mean|$O(nk)$|$O(n)$|Running sum|
|Rolling variance|$O(nk)$|$O(n)$|Running sum of squares|
|Rolling max/min|$O(nk)$|$O(n)$|Monotonic deque|
|Rolling median|$O(nk \log k)$|$O(n \log k)$|Two heaps or order statistics|

|Rolling skewness|$O(nk)$|$O(n)$|Running higher moments|

Pandas implements the $O(n)$ versions in Cython. Your from-scratch implementations are for understanding. Both produce the same output (up to floating point precision).

## Connection to AI / ML / Deep Learning

### 1. Classical Tabular ML (XGBoost, LightGBM, Random Forests)

These models have no notion of time. They receive a fixed-size feature vector per sample. Windowed features are the **only** mechanism through which temporal structure enters the model.

```
raw series → rolling features → feature matrix → XGBoost
```

The feature matrix is static. The model treats each row as an i.i.d. sample. This works because we have encoded the temporal dependencies into the features themselves.

### 2. Time-Series Forecasting Models

Classical forecasting models like ARIMA are parametric versions of windowed features: AR terms are rolling lags, MA terms are rolling averages of errors. Understanding rolling features makes these models transparent.

### 3. Recurrent Neural Networks — The Implicit Rolling Window

An RNN with hidden state $h_t$ computes:

$$ h_t = f(W_h h_{t-1} + W_x x_t + b) $$

The hidden state $h_t$ is a learned, compressed representation of the rolling window — it is the model learning _which_ windowed features matter rather than you hand-crafting them. Rolling features are the _explicit, interpretable_ version of what an RNN does implicitly.

|Manual rolling features|RNN hidden state|
|---|---|
|Fixed windows: $k = 5, 10, 20$|Adaptive effective window|
|Interpretable statistics|Learned representation|
|$O(n \cdot|\text{features}|
|Works with any model|Requires backprop through time|

### 4. Temporal Convolutional Networks (TCN)

A 1D convolution with kernel size $k$ computes a _learned_ linear combination of the window $[x_{t-k+1}, \ldots, x_t]$. Rolling mean is a 1D conv with uniform kernel weights $\frac{1}{k}$. The convolution learns the optimal weights from data.

```python
import torch.nn as nn

# Rolling mean (handcrafted)
# weight = [1/k, 1/k, ..., 1/k]

# Learnable 1D convolution (TCN layer)
conv = nn.Conv1d(in_channels=1, out_channels=16, kernel_size=20, padding=19)
# Learns 16 different "rolling" features simultaneously
```

### 5. Attention Mechanisms — Weighted Rolling Mean

Self-attention computes:

$$ \text{Attention}(Q, K, V) = \text{softmax}!\left(\frac{QK^T}{\sqrt{d}}\right) V $$

For a single query at position $t$ attending to positions $[t-k+1, \ldots, t]$, this reduces to a **data-dependent weighted rolling mean** — the weights are learned from the content of the sequence, not fixed. Rolling mean is the special case where all attention weights are $\frac{1}{k}$.

### 6. Feature Importance in ML Models

After training an XGBoost model on rolling features, SHAP values reveal which window size and statistic the model relies on. This is interpretable signal about the data's temporal structure — invaluable for domain understanding.

```python
import shap

model = xgb.XGBRegressor().fit(X_train, y_train)
explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(X_test)

# If std_20 has the highest mean |SHAP|, the model is primarily uncertainty-driven
shap.summary_plot(shap_values, X_test)
```

## Worked Example — Sensor Anomaly Detection

A real pattern: use rolling mean and rolling std to detect anomalies in a sensor stream.

```python
import pandas as pd
import numpy as np

np.random.seed(0)
n = 500
signal = pd.Series(np.random.randn(n))

# Inject two anomalies
signal.iloc[150] = 8.0
signal.iloc[350] = -7.0

k = 30

roll_mean = signal.rolling(k).mean()
roll_std  = signal.rolling(k).std()

# Z-score of current value relative to rolling window
z_score = (signal - roll_mean) / roll_std

# Flag anomalies: |z| > 3
anomalies = z_score[z_score.abs() > 3]
print(f"Anomalies detected at indices: {list(anomalies.index)}")
# Anomalies detected at indices: [150, 350]
```

This is the statistical foundation behind:

- AWS CloudWatch anomaly detection
- Prometheus alerting rules
- Industrial IoT monitoring pipelines

And it is entirely built from two windowed features: `rolling().mean()` and `rolling().std()`.

## The Stationarity Connection

ML models assume (usually implicitly) that the training and test distributions are the same — i.e., the data is **stationary**. Financial and sensor time series are typically non-stationary: the mean and variance drift over time.

Rolling z-scores address this directly:

$$ z_t = \frac{x_t - \bar{x}_{t,k}}{\sigma_{t,k}} $$

By subtracting the rolling mean and dividing by the rolling std, we normalise each value to its _local_ distribution. This is a form of **adaptive standardisation** that makes a non-stationary series approximately stationary — and therefore learnable by standard ML models.

This is why rolling z-score is one of the most universally useful features in time-series ML.
