## 1. Intuition First

### The Core Idea

Imagine you're solving a Sudoku by hand. You don't pick up your pencil, guess a number, and then check the entire board 81 times. You _look_ first. You scan row 3 and notice that 7 already appears — so 7 is eliminated from every empty cell in that row. You scan the top-right 3×3 box and see that 1, 4, and 9 are already placed — those three numbers vanish from the candidate lists of all other cells in that box. You repeat this across all rows, columns, and boxes until you've squeezed every cell down to its smallest possible candidate set. **Only then**, when logic alone can't reduce any cell further, do you guess — and you guess at the cell with the _fewest_ remaining options (if a cell has only 2 candidates, a random guess is 50/50; if it has 5, it's 20%). If a contradiction appears (some cell has zero candidates), you backtrack and try the next option.

This is **constraint propagation + backtracking**: a systematic interleaving of logical deduction (eliminate impossibilities) and guided search (guess at the best remaining candidate).

### Why This Exists — The Complexity Gap

Naïve backtracking without constraint propagation visits roughly $9^{81}$ states in the worst case (9 choices per cell, 81 cells). That number has 77 digits. Even with feasibility pruning — checking row/column/box validity before continuing — the branching factor stays enormous. The insight is that _most_ branches can be pruned before ever entering them, simply by propagating the consequences of each assignment forward.

Specifically, the algorithm known as **AC-3** (Arc Consistency 3) achieves this: after placing a digit $d$ in cell $(r, c)$, it queues every peer cell (same row, column, or box) and removes $d$ from their candidate lists. If any peer's candidate list shrinks to exactly one value, that value is forced — and _its_ placement propagates again recursively. This cascade of forced assignments is what makes Sudoku feel solvable by logic alone for easy puzzles: constraint propagation fully solves them. Hard puzzles require at least one guess, but propagation keeps the search tree narrow.

### The "Aha" Moment

The single insight that makes everything click: **the constraint graph tells you where to guess**. By always branching on the cell with the _minimum remaining values_ (MRV heuristic), you automatically hit contradictions sooner, which means you backtrack sooner, which means you prune more of the tree. This is the core of _intelligent backtracking_: not just "try something and undo it," but "try the thing most likely to fail fast."

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

Sudoku solving appears in CP as a **constraint satisfaction problem (CSP)** — a problem where you must assign values to variables such that all constraints are simultaneously satisfied. The Sudoku structure generalises to any grid-filling puzzle with overlapping conflict zones.

**Pattern signal:** When you see

- A grid where each cell must be assigned a value from a small fixed domain
- Constraints that link cells (rows, columns, regions)
- "How many valid completions" or "find one valid assignment"

→ think constraint propagation + backtracking.

**Common trap:** Implementing backtracking without constraint propagation, then wondering why it TLEs on harder inputs. The fix is always the same: before recursing, eliminate impossible candidates from peer cells. On Codeforces and AtCoder, CSP problems with $n \leq 30$ variables and tight constraints almost always need propagation; pure backtracking won't pass in time.

**Gotcha that kills submissions:** Forgetting to _undo_ the propagation on backtrack. When you backtrack from a guess, you must restore the candidate sets of every cell that was modified during propagation — not just the cell you guessed. Failing to restore candidate sets means subsequent branches see a corrupted state. Use a stack or explicit undo list.

### Machine Learning / AI

This algorithm is the canonical example of **constraint satisfaction** in classical AI, as treated in AIMA (Russell & Norvig, Ch. 6). Its ideas surface directly in modern ML systems:

**Inference engines and probabilistic graphical models:** Belief propagation in factor graphs, used in models like **Loopy BP for CRF inference** (conditional random fields in NLP), is structurally identical to constraint propagation: you pass messages along graph edges, updating marginal beliefs at each node, until convergence. The "message" in BP is the probabilistic analogue of the "candidate set" in Sudoku propagation.

**SAT solvers and formal verification:** PyTorch's `torch.compile()` and TensorFlow's XLA compiler use constraint-propagation ideas during **shape inference** — given input tensor shapes and a computational graph, they propagate shape constraints forward to determine output shapes without executing any operations. When a shape conflict is detected, it's analogous to a Sudoku contradiction: the computation is invalid.

**Neural architecture search (NAS):** The MRV heuristic is structurally identical to the **variable ordering** strategies in NAS: search frameworks like DARTS and ENAS preferentially explore architectural decisions at bottleneck layers first (fewer feasible options) before exploring the rest. Understanding MRV explains _why_ this heuristic works — it's not just a gut feeling.

**Hyperparameter tuning:** Tools like **Optuna** and **Ray Tune** implement Bayesian optimisation, but when hard constraints exist (e.g. `hidden_size` must be divisible by `num_heads`), they fall back to feasibility checking that is conceptually identical to constraint propagation — pruning the search space before evaluating a configuration.

## 3. Algorithm / Pattern

### Step-by-Step Logic

**Data model:**

- Board: 9×9 grid of cells. Empty cells are `'.'`.
- Candidate sets: for each empty cell, maintain the set of digits ${1…9}$ that could legally be placed there, given current assignments.

**Initialisation:**

1. For each pre-filled cell $(r, c)$ with digit $d$, remove $d$ from the candidate sets of all peers: cells in the same row, column, and 3×3 box.

**Main loop — constraint propagation (one step):**

1. Find any empty cell whose candidate set has been reduced to exactly 1 value (called a _naked single_). Place that value and propagate its removal to peers. Repeat until no more naked singles exist.
2. _(Optional, stronger)_ Find any digit $d$ in a row/column/box that appears in the candidate sets of exactly one cell in that unit (called a _hidden single_). Assign $d$ to that cell and propagate. Repeat.

**Backtracking search:**

1. If no empty cells remain and no contradiction: **solved**.
2. If any empty cell has an empty candidate set: **contradiction** — return `False`.
3. Select the empty cell $C$ with the minimum number of candidates (MRV heuristic).
4. For each candidate $d$ in $C$'s candidate set: a. Make a deep copy of the board state (or use an undo stack). b. Assign $d$ to $C$, propagate constraints. c. Recurse. d. If recursion returns `True`: done. e. Otherwise: restore the copied state (backtrack) and try next $d$.
5. If all candidates fail: return `False`.

### Decision Tree

```
See: assignment problem on a constrained grid
    → Is the domain of each variable small (≤ 9)?
        → Yes: constraint propagation + backtracking (this note)
    → Do constraints link many variables?
        → Yes: propagation is worth the overhead
    → After propagation, cells left ambiguous?
        → Yes: guess at MRV cell and recurse
        → No (propagation fully solves): done, no search needed
```

### Complexity

Let $E$ = number of empty cells (≤ 81 for Sudoku).

- **Naive backtracking:** $O(9^E)$ — exponential, clearly infeasible.
- **Backtracking + feasibility check only:** practically much better, but still exponential in worst case with adversarial inputs.
- **Backtracking + constraint propagation + MRV:** empirically solves any valid Sudoku in microseconds. The theoretical worst case remains exponential (Sudoku is NP-complete), but the MRV heuristic and propagation collapse the effective search tree to near-linear depth for well-posed puzzles.
- **Space:** $O(E \cdot 9)$ for candidate sets, $O(E)$ for the recursive call stack.

### When to Use vs. Avoid

|Use|Avoid|
|---|---|
|Small fixed-domain CSPs (Sudoku, nonograms, Latin squares)|When constraints are soft/probabilistic (use LP, MIP instead)|
|Problems where propagation + MRV gives fast convergence|When domain size is large (continuous values — use gradient methods)|
|"Find one valid assignment" or "count all valid assignments"|When greedy or DP suffices (no conflicting constraints)|

## 4. Pseudocode

```
function SOLVE(board, candidates):
    // Propagation phase
    changed ← true
    while changed:
        changed ← false
        for each empty cell C:
            if |candidates[C]| == 0:
                return FAIL           // contradiction
            if |candidates[C]| == 1:
                d ← the single element of candidates[C]
                ASSIGN(board, C, d, candidates)
                changed ← true

    // Check if solved
    if no empty cells remain:
        return SUCCESS

    // MRV: pick cell with fewest candidates
    C ← argmin over empty cells of |candidates[C]|

    // Branch over each candidate of C
    for d in candidates[C]:
        saved_state ← deep copy of (board, candidates)
        ASSIGN(board, C, d, candidates)
        result ← SOLVE(board, candidates)
        if result == SUCCESS:
            return SUCCESS
        restore (board, candidates) from saved_state

    return FAIL                       // all options exhausted


function ASSIGN(board, cell C = (r,c), digit d, candidates):
    board[r][c] ← d
    candidates[C] ← ∅                // cell is now filled
    for each peer P of C:            // same row, col, or box
        candidates[P] ← candidates[P] \ {d}
        // Note: do NOT recurse here for naked singles in pseudocode;
        // the outer while-loop in SOLVE handles them.
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <array>
#include <vector>
#include <string>
#include <bitset>
#include <cassert>

// ─────────────────────────────────────────────────────────────────
// SudokuSolver: constraint propagation + backtracking with MRV.
// Board is represented as a flat array of 81 chars ('1'..'9' or '.').
// Candidate sets use bitsets: bit i set ↔ digit (i+1) is possible.
// ─────────────────────────────────────────────────────────────────
class SudokuSolver {
    static constexpr int N = 81;

    // Peer cells: for each cell index, the set of cells sharing
    // a row, column, or box (20 peers per cell, precomputed).
    static std::array<std::array<int, 20>, N> PEERS;
    static bool peers_computed;

    static void compute_peers() {
        if (peers_computed) return;
        for (int c = 0; c < N; ++c) {
            int r = c / 9, col = c % 9, box_r = (r / 3) * 3, box_c = (col / 3) * 3;
            int idx = 0;
            for (int i = 0; i < 9; ++i) {
                int row_peer = r * 9 + i;
                if (row_peer != c) PEERS[c][idx++] = row_peer;
            }
            for (int i = 0; i < 9; ++i) {
                int col_peer = i * 9 + col;
                if (col_peer != c) {
                    bool dup = false;
                    for (int j = 0; j < idx; ++j) if (PEERS[c][j] == col_peer) { dup = true; break; }
                    if (!dup) PEERS[c][idx++] = col_peer;
                }
            }
            for (int dr = 0; dr < 3; ++dr) for (int dc = 0; dc < 3; ++dc) {
                int box_peer = (box_r + dr) * 9 + (box_c + dc);
                if (box_peer != c) {
                    bool dup = false;
                    for (int j = 0; j < idx; ++j) if (PEERS[c][j] == box_peer) { dup = true; break; }
                    if (!dup) PEERS[c][idx++] = box_peer;
                }
            }
        }
        peers_computed = true;
    }

    using Candidates = std::array<uint16_t, N>; // bit i set ↔ digit (i+1) possible

    // Assign digit d (0-indexed) to cell c; propagate to peers.
    // Returns false if a contradiction is found.
    bool assign(std::array<char, N>& board, Candidates& cands, int c, int d) {
        board[c] = char('1' + d);
        cands[c] = 0; // cell filled — no candidates needed
        for (int peer : PEERS[c]) {
            if (board[peer] != '.') continue;
            cands[peer] &= ~(1u << d); // remove digit d from peer
            if (cands[peer] == 0) return false; // contradiction
        }
        return true;
    }

    // Propagate naked singles until no more are found.
    // Returns false on contradiction.
    bool propagate(std::array<char, N>& board, Candidates& cands) {
        bool changed = true;
        while (changed) {
            changed = false;
            for (int c = 0; c < N; ++c) {
                if (board[c] != '.') continue;
                if (cands[c] == 0) return false;
                if (__builtin_popcount(cands[c]) == 1) {
                    int d = __builtin_ctz(cands[c]); // index of the only set bit
                    if (!assign(board, cands, c, d)) return false;
                    changed = true;
                }
            }
        }
        return true;
    }

    // Backtracking search with MRV.
    bool solve(std::array<char, N> board, Candidates cands) {
        if (!propagate(board, cands)) return false;

        // Find first empty cell with minimum candidates (MRV)
        int best = -1, best_count = 10;
        for (int c = 0; c < N; ++c) {
            if (board[c] != '.') continue;
            int cnt = __builtin_popcount(cands[c]);
            if (cnt < best_count) { best = c; best_count = cnt; }
        }

        if (best == -1) { // no empty cells — solved
            solution_ = board;
            return true;
        }

        // Branch on each candidate of best cell
        uint16_t mask = cands[best];
        while (mask) {
            int d = __builtin_ctz(mask);
            mask &= mask - 1;
            auto b2 = board; auto c2 = cands;
            if (assign(b2, c2, best, d) && solve(b2, c2)) return true;
        }
        return false;
    }

    std::array<char, N> solution_{};

public:
    SudokuSolver() { compute_peers(); }

    // Input: 81-char string, '.' for empty, '1'-'9' for filled.
    // Returns solved board string, or empty string on failure.
    std::string solve(const std::string& input) {
        assert(input.size() == 81);
        std::array<char, N> board;
        Candidates cands;
        cands.fill(0x1FF); // all 9 bits set = digits 1–9 all possible
        for (int i = 0; i < N; ++i) board[i] = input[i];

        // Initialise: apply pre-filled cells
        for (int i = 0; i < N; ++i) {
            if (board[i] != '.') {
                int d = board[i] - '1';
                cands[i] = 0;
                for (int peer : PEERS[i]) cands[peer] &= ~(1u << d);
            }
        }

        if (!solve(board, cands)) return "";
        return std::string(solution_.begin(), solution_.end());
    }
};

std::array<std::array<int, 20>, SudokuSolver::N> SudokuSolver::PEERS{};
bool SudokuSolver::peers_computed = false;

// ─── Minimal test ──────────────────────────────────────────────
#include <iostream>
int main() {
    SudokuSolver solver;
    // "World's hardest Sudoku" (Inkala, 2012)
    std::string puzzle =
        "8........"
        "..36....."
        ".7..9.2.."
        ".5...7..."
        "....457.."
        "...1...3."
        "..1....68"
        "..85...1."
        ".9....4..";
    std::string sol = solver.solve(puzzle);
    if (sol.empty()) std::cout << "No solution\n";
    else {
        for (int r = 0; r < 9; ++r) {
            for (int c = 0; c < 9; ++c) std::cout << sol[r*9+c] << " ";
            std::cout << "\n";
        }
    }
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations
from typing import Optional
from copy import deepcopy


def _build_peers() -> list[list[int]]:
    """Precompute the 20 peer indices for each of the 81 cells."""
    peers = []
    for c in range(81):
        r, col = divmod(c, 9)
        box_r, box_c = (r // 3) * 3, (col // 3) * 3
        peer_set: set[int] = set()
        peer_set.update(r * 9 + i for i in range(9))          # row
        peer_set.update(i * 9 + col for i in range(9))         # col
        peer_set.update(
            (box_r + dr) * 9 + (box_c + dc)
            for dr in range(3) for dc in range(3)
        )
        peer_set.discard(c)
        peers.append(sorted(peer_set))
    return peers


PEERS: list[list[int]] = _build_peers()


def _assign(board: list[str], cands: list[set[int]], c: int, d: int) -> bool:
    """
    Assign digit d to cell c. Remove d from all peer candidate sets.
    Returns False if any peer's candidate set becomes empty (contradiction).

    Time: O(20) per call — constant w.r.t. board size.
    """
    board[c] = str(d)
    cands[c] = set()
    for peer in PEERS[c]:
        if board[peer] != ".":
            continue
        cands[peer].discard(d)
        if not cands[peer]:
            return False   # contradiction
    return True


def _propagate(board: list[str], cands: list[set[int]]) -> bool:
    """
    Repeatedly apply the naked-single rule until no more forced cells exist.
    Returns False on contradiction.

    Time: O(81 * 20) per full pass, multiple passes until stable.
    """
    changed = True
    while changed:
        changed = False
        for c in range(81):
            if board[c] != ".":
                continue
            if not cands[c]:
                return False
            if len(cands[c]) == 1:
                (d,) = cands[c]
                if not _assign(board, cands, c, d):
                    return False
                changed = True
    return True


def _solve(board: list[str], cands: list[set[int]]) -> bool:
    """
    Backtracking search. Modifies board and cands in-place.
    Returns True if a solution is found (board is then fully assigned).

    Complexity:
        Empirical: sub-millisecond for any published Sudoku puzzle.
        Theoretical worst-case: still exponential (Sudoku is NP-complete).
    """
    if not _propagate(board, cands):
        return False

    # MRV: find empty cell with fewest remaining candidates
    best = min(
        (c for c in range(81) if board[c] == "."),
        key=lambda c: len(cands[c]),
        default=None,
    )
    if best is None:
        return True   # no empty cells — solved

    # Branch on each candidate of the chosen cell
    for d in sorted(cands[best]):   # sorted for determinism
        b2 = board[:]
        c2 = [s.copy() for s in cands]
        if _assign(b2, c2, best, d) and _solve(b2, c2):
            board[:] = b2
            return True

    return False   # all candidates failed


def solve_sudoku(puzzle: str) -> Optional[str]:
    """
    Solve a 9×9 Sudoku puzzle given as an 81-character string.
    '.' (or '0') represents an empty cell.

    Returns the solved board as an 81-character string, or None if unsolvable.

    Complexity:
        Time:  empirically O(n) for well-formed puzzles (propagation dominates).
        Space: O(81 * 9) = O(729) for candidate sets + O(81) call stack depth.

    >>> sol = solve_sudoku("8" + "." * 8 + "..36....." + ...)
    """
    assert len(puzzle) == 81, "Puzzle must be 81 characters."
    board = [c if c in "123456789" else "." for c in puzzle]
    cands: list[set[int]] = [set(range(1, 10)) if board[c] == "." else set()
                             for c in range(81)]

    # Initialise candidate sets from pre-filled cells
    for c in range(81):
        if board[c] != ".":
            d = int(board[c])
            for peer in PEERS[c]:
                cands[peer].discard(d)

    if not _solve(board, cands):
        return None

    return "".join(board)


# ─── Minimal test ─────────────────────────────────────────────
if __name__ == "__main__":
    # LeetCode 37 / "World's hardest Sudoku" (Inkala, 2012)
    puzzle = (
        "8........"
        "..36....."
        ".7..9.2.."
        ".5...7..."
        "....457.."
        "...1...3."
        "..1....68"
        "..85...1."
        ".9....4.."
    )
    sol = solve_sudoku(puzzle)
    if sol:
        for r in range(9):
            print(" ".join(sol[r*9:(r+1)*9]))
    else:
        print("No solution found.")
```

When we place digit 5 in cell (0, 0), its removal ripples through the entire peer set — row 0, column 0, and the top-left 3×3 box. Any cell that gets reduced to a single candidate immediately triggers another forced assignment.

```
          ↑ placed               5 removed from all →

Col 0:   [ 5 ]
         [ ? ]  ← 5 removed
         [ ? ]  ← 5 removed
         ...

Box (0,0):
┌─────────────────┐
│ [5] [?] [?]     │   ← all cells in this box lose 5 from
│ [?] [?] [?]     │     their candidate sets
│ [?] [?] [?]     │
```

## 7. Common Variations & Extensions

### Variation 1: Hidden Singles

Beyond naked singles (one candidate in a cell), apply _hidden singles_: if digit $d$ appears in exactly one cell's candidate set within a given row/column/box, $d$ must go there. Adding this reduces the search tree further and is worth implementing for competitive puzzle-solving.

**Adaptation:** After each naked-single pass, loop over all 27 units (9 rows + 9 cols + 9 boxes). For each unit and each digit $d$, count cells where $d$ is still a candidate. If count == 1, assign $d$ there.

### Variation 2: Backtracking Without State Copies — Undo Stack

The copy-based approach is simple but allocates heavily. An alternative: maintain an explicit undo stack of `(cell, removed_digit)` pairs. When you call `assign`, push all removals onto the stack. On backtrack, pop and re-add. This reduces memory allocation from $O(81 \cdot 9)$ per branch to $O(20)$ entries per assignment.

**Link:** [[80.Pruning strategies — forward checking, bounding functions]] — the undo-stack approach is a form of _forward checking with chronological backtracking_.

### Variation 3: Generalised CSP — $n \times n$ Latin Squares

Sudoku is a 9×9 Latin square with additional box constraints. Remove the box constraint and you get a pure Latin square. Increase $n$ and you get constraint satisfaction at scale. The same algorithm applies; only the peer computation changes. This generalises to $k$-colouring problems on graphs ([[116.Bipartite check — 2-colouring via BFS]]).

### Variation 4: Counting All Solutions

Replace the `return True` on success with `count += 1; return False` (to force continued search). Useful for "how many valid completions exist" queries. For competitive problems, this typically requires additional pruning (symmetry breaking) to remain tractable.

## 9. CP Contest Application

### Typical Codeforces/AtCoder Problem Structure

**Format:** Given a partially filled grid (Sudoku variant or generalised CSP), determine if a unique valid completion exists, or find one such completion. Often embedded inside a larger problem (e.g., "encrypt a message using a valid Sudoku as a key").

**Time limits where this matters:**

- Standard 2-second limits are fine for well-formed 9×9 Sudoku with propagation + MRV.
- Problems that ask for _all_ solutions or involve adversarial inputs designed to maximise backtracking may require symmetry breaking or stronger propagation (full AC-3) to pass.
- For $n > 16$ (e.g., 16×16 Sudoku variants), profile carefully; the peer set grows quadratically.

**Optimisation tricks for CP:**

1. **Bitset candidate sets in C++:** Represent each cell's candidates as a `uint16_t` bitmask. Testing if a candidate is valid is `(mask >> d) & 1`, and counting candidates is `__builtin_popcount(mask)`. Operations on all 81 cells fit in a few hundred bytes — cache-friendly.
    
2. **Peer lists as static arrays:** Precompute PEERS once at program start. Avoid recomputing row/column/box membership inside the recursion.
    
3. **Early termination:** Before branching, check if any empty cell already has zero candidates (a contradiction). This catches many invalid states without recursing.
    
4. **Least Constraining Value (LCV):** Within the chosen MRV cell, try digits that eliminate the fewest candidates from peers first. This is the opposite of "fail fast" — it attempts the most promising assignment first, which matters when you want _one_ solution quickly rather than proving unsolvability.
    
5. **Template pattern for CSP in competitive code:**
    

```cpp
// Generic CSP backtracking skeleton for CP:
bool solve(State& state) {
    if (!propagate(state)) return false;
    int cell = pick_mrv_cell(state);
    if (cell == -1) return true;  // solved
    for (int val : state.candidates[cell]) {
        State next = state;
        next.assign(cell, val);
        if (solve(next)) return true;
    }
    return false;
}
```

This skeleton reappears in nearly every combinatorial constraint problem: timetabling, graph colouring, Latin square completion, and more.

## Summary

The Sudoku solver is the textbook case study for why **search without inference is exponentially wasteful**. The key contributions:

1. **Constraint propagation** (arc consistency / naked singles) collapses forced assignments without branching — shrinks the effective search space by orders of magnitude.
2. **MRV heuristic** ensures that when branching is unavoidable, we hit contradictions as early as possible, pruning entire subtrees.
3. **Backtracking with state restoration** is the safety net — logically complete, ensuring we never miss a valid solution.

Together these three ideas constitute the core of **classical AI constraint satisfaction**, which surfaces directly in belief propagation, compiler shape inference, and NAS search strategies in modern ML.
