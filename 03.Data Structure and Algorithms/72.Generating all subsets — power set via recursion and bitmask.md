## 1. Intuition First

### The Core Idea

You have a set of n items. For every possible subset — including the empty set and the full set — you want to enumerate it. The total number of subsets is 2ⁿ, because for each item you face exactly one binary decision: **include it or exclude it**. n independent binary choices yield 2ⁿ outcomes.

The **recursive** approach mirrors this decision directly: process items one at a time, branching into "include" and "exclude" at each step. The recursion tree is a perfect binary tree of depth n with 2ⁿ leaves — each leaf is one subset.

The **bitmask** approach recognises a cleaner equivalence: every integer from 0 to 2ⁿ−1 is a binary string of length n. Bit k of integer m tells you whether item k belongs to the subset corresponding to m. Enumerating all subsets is literally counting from 0 to 2ⁿ−1 and reading off the bits.

Think of it as a combination lock with n dials, each set to 0 or 1. Every possible lock configuration is a distinct subset. The bitmask counts through all configurations; the recursion explores the same space by turning each dial in sequence.

### Why This Exists

Many problems in combinatorial optimisation, constraint satisfaction, and machine learning feature search require examining all possible selections from a set. The brute-force approach — checking every possible subset — appears in:

- Exact algorithms for NP-hard problems when n is small (n ≤ 20 is often tractable)
- Generating training data for set-based models
- Feature selection over small feature sets
- State space exploration in backtracking when the state _is_ a subset

The naive approach of nested loops fails because the depth of nesting equals n — you cannot write a loop nest that adapts to an arbitrary n. Recursion and bitmasks both solve the "variable depth" problem cleanly.

### The "Aha" Moment

The binary decision tree for subsets and the binary representation of integers are the **same structure**. The bitmask approach is not a trick — it is the direct hardware realisation of the mathematical equivalence between subsets of an n-element set and n-bit integers.

> **Every subset of {a₀, a₁, ..., aₙ₋₁} corresponds to exactly one integer in [0, 2ⁿ−1], and vice versa. Enumerating subsets is counting in binary.**

This equivalence also explains why bitmask DP (see [[105.Bitmask DP — state compression]]) works: the DP state "which items have been selected so far" is naturally represented as an integer, making it indexable as an array rather than requiring a hashmap.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- "Find all subsets with property P" — enumerate and filter
- "Does any subset sum to target?" — if n ≤ 20, enumerate all 2ⁿ subsets
- Meet-in-the-middle: split into two halves, enumerate 2^(n/2) subsets each
- Bitmask DP: state = subset of elements processed (n ≤ 20 for TSP, assignment problems)
- "Number of subsets with XOR equal to k" — generate and count

**Pattern signals:**

```
n ≤ 20  →  enumerate all 2ⁿ subsets directly (bitmask loop: clean and fast)
n ≤ 40  →  meet-in-the-middle: split into halves of 2^20 each
n > 40  →  subset enumeration is infeasible; need DP or greedy
```

**Common traps:**

1. **Off-by-one in bitmask loop.** The loop runs from `0` to `(1 << n) - 1` inclusive. Writing `< (1 << n)` is correct; writing `<= (1 << n)` generates a spurious extra iteration. And `1 << n` overflows a 32-bit int for n ≥ 32 — use `1LL << n` in C++ when n is close to 32.
    
2. **Forgetting the empty subset.** Mask 0 represents the empty set. Some problems explicitly exclude it ("non-empty subsets only"), requiring the loop to start at 1. Forgetting to handle or skip it is a common source of wrong answers.
    
3. **Duplicate elements.** If the input array has duplicates and you want _distinct_ subsets, the recursive approach needs a sorted array and a skip-duplicate condition. The bitmask approach generates all 2ⁿ index-subsets regardless — you must deduplicate using a set of sorted tuples, or use the recursive skip approach.
    
4. **Modifying the current path.** In the recursive approach, the `path` list (current subset being built) must be passed as a copy when appending to results, not as a reference. `result.append(path)` stores a reference; `result.append(path[:])` or `result.append(list(path))` stores a snapshot.
    

**Competitive usage — bitmask DP prerequisite:** Before you can tackle TSP or assignment problems via bitmask DP (see [[105.Bitmask DP — state compression]]), you must be comfortable enumerating subsets and iterating over set bits. This topic is the direct prerequisite.

### Machine Learning / AI

**1. Feature subset selection.** Given n features, find the subset that maximises some evaluation metric (validation accuracy, mutual information, F-score). For small n (say, n ≤ 20), exhaustive enumeration over all 2ⁿ subsets is tractable and optimal. Scikit-learn's `SequentialFeatureSelector` uses a greedy approximation precisely because exhaustive subset search is exponential — but when n is small enough, the exhaustive version finds the true optimum that greedy misses.

**2. Combinatorial data augmentation.** In multi-label classification and multi-modal learning, training samples can be augmented by masking random subsets of input modalities or features. Enumerating all possible masks (subsets of features to zero out) and sampling from them uniformly is the principled approach — used in masked autoencoders (MAE, He et al. 2021) and in tabular data augmentation via feature dropout.

**3. SHAP values and Shapley-based feature importance.** The Shapley value of feature i is a weighted average over _all subsets of features not containing i_ of the marginal contribution of adding i to each subset. Computing exact Shapley values requires iterating over all 2ⁿ subsets — O(2ⁿ) for n features. The `shap` library's `ExactExplainer` does precisely this for small n; `TreeExplainer` and `KernelExplainer` use approximations for large n. Understanding subset enumeration is understanding the ground truth that approximate SHAP methods target.

**4. Ensemble combinatorics.** Given k trained models, evaluating all possible ensembles (subsets of models to include) is a subset enumeration over k elements. For k ≤ 20 this is feasible; model selection by exhaustive ensemble search is a legitimate technique when k is small.

**5. Boolean satisfiability in ML constraint systems.** Constraint-based approaches to fairness, interpretability, and causal discovery involve Boolean satisfiability over binary variables. The brute-force SAT solver — enumerate all 2ⁿ truth assignments — is exactly power set enumeration, making this the theoretical foundation for understanding why SAT is NP-complete (exponential in the worst case).

## 3. Algorithm / Pattern

### Approach 1: Recursive Backtracking

At each index `i`, make two choices: include `nums[i]` in the current subset, or exclude it. Recurse on index `i+1`. When `i == n`, record the current subset.

```
State: (current_index, current_path)
Branching: binary at each step — include or exclude
Depth: n (one level per element)
Leaves: 2ⁿ (one per subset)
Time: O(n × 2ⁿ) — 2ⁿ subsets, each takes O(n) to copy into results
Space: O(n) recursion depth + O(n × 2ⁿ) for output
```

### Approach 2: Bitmask Enumeration

Iterate integer `mask` from `0` to `2ⁿ−1`. For each mask, collect items at positions where the corresponding bit is set.

```
Time: O(n × 2ⁿ) — 2ⁿ masks, each scanned in O(n)
Space: O(1) extra beyond output — no recursion, no path storage
```

### Approach 3: Iterative Subset Building

Start with `[[]]` (containing only the empty set). For each new element, duplicate all existing subsets and append the new element to each duplicate.

```
Time: O(n × 2ⁿ) — at step k, you process 2^k subsets
Space: O(n × 2ⁿ) for the growing result list
```

### When to Use Each

|Approach|Best when|
|---|---|
|Recursive backtracking|Need to prune (not all 2ⁿ subsets needed), or generating with constraints|
|Bitmask loop|n is small (≤ 20), need maximum speed, or using as precursor to bitmask DP|
|Iterative building|Conceptually clearest, no stack risk, but builds all subsets eagerly|

### Handling Duplicates

If `nums` has duplicates and you want distinct subsets:

1. Sort `nums` first
2. In the recursive approach: at each level, skip `nums[i]` if `nums[i] == nums[i-1]` and `i > start` (you've already generated subsets starting with this value at this level)
3. In the bitmask approach: collect results into a `set` of tuples

## 4. Pseudocode

```
# ── Approach 1: Recursive ──────────────────────────────────────────────────

FUNCTION subsets_recursive(nums):
    result ← []
    CALL backtrack(index=0, path=[])
    RETURN result

FUNCTION backtrack(index, path):
    # Record current subset at every node — not just leaves
    result.APPEND(COPY of path)

    FOR i FROM index TO len(nums) - 1:
        path.APPEND(nums[i])              # choose: include nums[i]
        CALL backtrack(i + 1, path)       # explore: recurse on remaining
        path.POP()                        # unchoose: backtrack


# ── Approach 2: Bitmask ────────────────────────────────────────────────────

FUNCTION subsets_bitmask(nums):
    n ← len(nums)
    result ← []

    FOR mask FROM 0 TO (2^n - 1):         # iterate all n-bit integers
        subset ← []
        FOR bit FROM 0 TO n - 1:
            IF mask has bit `bit` set:     # test: (mask >> bit) & 1 == 1
                subset.APPEND(nums[bit])
        result.APPEND(subset)

    RETURN result


# ── Approach 3: Iterative cascading ───────────────────────────────────────

FUNCTION subsets_iterative(nums):
    result ← [[]]                          # start: only the empty subset

    FOR each element IN nums:
        new_subsets ← []
        FOR each existing_subset IN result:
            new_subsets.APPEND(existing_subset + [element])  # extend each subset
        result.EXTEND(new_subsets)          # add all new subsets

    RETURN result


# ── Handling duplicates (recursive with sorted input) ─────────────────────

FUNCTION subsets_with_duplicates(nums):
    SORT nums
    result ← []
    CALL backtrack_dedup(index=0, path=[])
    RETURN result

FUNCTION backtrack_dedup(index, path):
    result.APPEND(COPY of path)
    FOR i FROM index TO len(nums) - 1:
        IF i > index AND nums[i] == nums[i-1]:
            CONTINUE                        # skip duplicate at same recursion level
        path.APPEND(nums[i])
        CALL backtrack_dedup(i + 1, path)
        path.POP()
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <cassert>

// ─────────────────────────────────────────────────────────────────────────────
// Approach 1: Recursive backtracking
// Appends result at every node — not just leaves — to collect all subsets.
// ─────────────────────────────────────────────────────────────────────────────
void backtrack(int index, std::vector<int>& path,
               const std::vector<int>& nums,
               std::vector<std::vector<int>>& result) {
    result.push_back(path);   // record current subset (snapshot, not reference)

    for (int i = index; i < (int)nums.size(); ++i) {
        path.push_back(nums[i]);          // choose
        backtrack(i + 1, path, nums, result);  // explore
        path.pop_back();                  // unchoose
    }
}

std::vector<std::vector<int>> subsets_recursive(std::vector<int> nums) {
    std::vector<std::vector<int>> result;
    std::vector<int> path;
    backtrack(0, path, nums, result);
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Approach 2: Bitmask enumeration
// 1LL << n avoids overflow for n up to 63. Use only for n ≤ 20 in contests.
// ─────────────────────────────────────────────────────────────────────────────
std::vector<std::vector<int>> subsets_bitmask(const std::vector<int>& nums) {
    int n = nums.size();
    std::vector<std::vector<int>> result;
    result.reserve(1 << n);

    for (int mask = 0; mask < (1 << n); ++mask) {
        std::vector<int> subset;
        for (int bit = 0; bit < n; ++bit) {
            if ((mask >> bit) & 1) {      // test if bit `bit` is set in mask
                subset.push_back(nums[bit]);
            }
        }
        result.push_back(std::move(subset));
    }
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Approach 3: Iterative cascading
// At step k: result size doubles from 2^k to 2^(k+1)
// ─────────────────────────────────────────────────────────────────────────────
std::vector<std::vector<int>> subsets_iterative(const std::vector<int>& nums) {
    std::vector<std::vector<int>> result = {{}};  // start with empty subset

    for (int x : nums) {
        int sz = result.size();           // only iterate existing subsets
        for (int i = 0; i < sz; ++i) {
            result.push_back(result[i]);  // duplicate existing subset
            result.back().push_back(x);  // append new element
        }
    }
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Duplicates variant: distinct subsets from array with repeated elements
// ─────────────────────────────────────────────────────────────────────────────
void backtrack_dedup(int index, std::vector<int>& path,
                     const std::vector<int>& nums,
                     std::vector<std::vector<int>>& result) {
    result.push_back(path);

    for (int i = index; i < (int)nums.size(); ++i) {
        // Skip duplicates at the same recursion level
        // i > index (not i > 0): allow using same value from different positions
        if (i > index && nums[i] == nums[i - 1]) continue;

        path.push_back(nums[i]);
        backtrack_dedup(i + 1, path, nums, result);
        path.pop_back();
    }
}

std::vector<std::vector<int>> subsets_with_duplicates(std::vector<int> nums) {
    std::sort(nums.begin(), nums.end());  // must sort first for dedup to work
    std::vector<std::vector<int>> result;
    std::vector<int> path;
    backtrack_dedup(0, path, nums, result);
    return result;
}

// ─────────────────────────────────────────────────────────────────────────────
// Utility: sort inner vectors and outer vector for comparison
// ─────────────────────────────────────────────────────────────────────────────
void normalise(std::vector<std::vector<int>>& v) {
    for (auto& s : v) std::sort(s.begin(), s.end());
    std::sort(v.begin(), v.end());
}

int main() {
    std::vector<int> nums = {1, 2, 3};

    auto r1 = subsets_recursive(nums);
    auto r2 = subsets_bitmask(nums);
    auto r3 = subsets_iterative(nums);

    // All three approaches must produce the same 2^3 = 8 subsets
    assert(r1.size() == 8);
    assert(r2.size() == 8);
    assert(r3.size() == 8);

    normalise(r1); normalise(r2); normalise(r3);
    assert(r1 == r2);
    assert(r2 == r3);

    // Duplicates: {1, 2, 2} → distinct subsets only
    auto rd = subsets_with_duplicates({1, 2, 2});
    assert(rd.size() == 6);  // {}, {1}, {2}, {1,2}, {2,2}, {1,2,2}
    normalise(rd);

    // Single element
    auto single = subsets_bitmask({5});
    assert(single.size() == 2);  // {}, {5}

    // Empty input
    auto empty = subsets_bitmask({});
    assert(empty.size() == 1);   // just {{}}

    std::cout << "All tests passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
from itertools import combinations

# ─────────────────────────────────────────────────────────────────────────────
# Approach 1: Recursive backtracking
# ─────────────────────────────────────────────────────────────────────────────

def subsets_recursive(nums: list[int]) -> list[list[int]]:
    """
    Generate all 2ⁿ subsets via recursive backtracking.

    Appends at every node of the recursion tree (not just leaves),
    so every prefix of every branch is recorded as a subset.

    Time:  O(n × 2ⁿ) — 2ⁿ subsets, each copied in O(n)
    Space: O(n) recursion depth + O(n × 2ⁿ) output

    >>> sorted(subsets_recursive([1,2,3]))  # 8 subsets
    [[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]
    """
    result = []

    def backtrack(index: int, path: list[int]) -> None:
        result.append(path[:])   # snapshot — NOT path (reference)

        for i in range(index, len(nums)):
            path.append(nums[i])       # choose
            backtrack(i + 1, path)     # explore
            path.pop()                 # unchoose

    backtrack(0, [])
    return result


# ─────────────────────────────────────────────────────────────────────────────
# Approach 2: Bitmask enumeration
# ─────────────────────────────────────────────────────────────────────────────

def subsets_bitmask(nums: list[int]) -> list[list[int]]:
    """
    Generate all 2ⁿ subsets by treating each integer 0..2ⁿ-1 as a bitmask.

    Bit k of mask indicates whether nums[k] is included.
    This is the most hardware-natural representation of the subset lattice.

    Time:  O(n × 2ⁿ)
    Space: O(1) extra (beyond output)

    >>> sorted(subsets_bitmask([1,2,3]))
    [[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]
    """
    n = len(nums)
    result = []

    for mask in range(1 << n):          # 0 to 2ⁿ-1
        subset = [nums[bit]
                  for bit in range(n)
                  if (mask >> bit) & 1]  # test bit `bit` of mask
        result.append(subset)

    return result


# ─────────────────────────────────────────────────────────────────────────────
# Approach 3: Iterative cascading (most Pythonic for explanation)
# ─────────────────────────────────────────────────────────────────────────────

def subsets_iterative(nums: list[int]) -> list[list[int]]:
    """
    Build up all subsets incrementally:
      After 0 elements: [[]]
      After 1 element:  [[], [1]]
      After 2 elements: [[], [1], [2], [1,2]]
      After 3 elements: [[], [1], [2], [1,2], [3], [1,3], [2,3], [1,2,3]]

    At each step, result doubles in size: invariant is |result| == 2^k
    after processing k elements.

    Time:  O(n × 2ⁿ)
    Space: O(n × 2ⁿ) output only — no recursion stack
    """
    result = [[]]

    for x in nums:
        # For each existing subset, create a new subset that includes x
        result += [subset + [x] for subset in result]

    return result


# ─────────────────────────────────────────────────────────────────────────────
# Duplicates variant: distinct subsets when input has repeated elements
# ─────────────────────────────────────────────────────────────────────────────

def subsets_with_duplicates(nums: list[int]) -> list[list[int]]:
    """
    Generate distinct subsets from an array that may contain duplicates.

    Key invariant: nums must be sorted. At each recursion level, if
    nums[i] == nums[i-1] and i > start (not the first choice at this level),
    skip — we already generated subsets starting with this value.

    Time:  O(n × 2ⁿ) worst case (all distinct), but fewer if many duplicates
    Space: O(n) recursion depth

    >>> sorted(subsets_with_duplicates([1,2,2]))
    [[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]
    """
    nums.sort()
    result = []

    def backtrack(start: int, path: list[int]) -> None:
        result.append(path[:])

        for i in range(start, len(nums)):
            # Skip duplicate values at the same level of the recursion tree
            # i > start: allow using the same value from a deeper level (different position)
            if i > start and nums[i] == nums[i - 1]:
                continue
            path.append(nums[i])
            backtrack(i + 1, path)
            path.pop()

    backtrack(0, [])
    return result


# ─────────────────────────────────────────────────────────────────────────────
# ML application: exact Shapley value computation for n features
# The Shapley value for feature i = weighted average of marginal contribution
# across all subsets S not containing i.
# This is a direct application of power set enumeration.
# ─────────────────────────────────────────────────────────────────────────────

def exact_shapley(model_value_fn, n_features: int, x: list[float]) -> list[float]:
    """
    Compute exact Shapley values for all features using full subset enumeration.

    model_value_fn(feature_mask) → float: model output when only the features
    indicated by feature_mask (a list of booleans) are active.

    Only tractable for small n (n ≤ 15 or so).
    The 'shap' library's ExactExplainer does exactly this.

    Time:  O(n × 2ⁿ) — every subset weighted once per feature

    This demonstrates why approximate SHAP methods exist for large n:
    exact computation requires iterating all 2ⁿ subsets.
    """
    from math import factorial

    shapley = [0.0] * n_features

    for feature_i in range(n_features):
        for mask in range(1 << n_features):
            if (mask >> feature_i) & 1:
                continue   # skip subsets that already contain feature_i

            # Subset S = features in mask (not including feature_i)
            s_size = bin(mask).count('1')
            weight = (factorial(s_size) * factorial(n_features - s_size - 1)
                      / factorial(n_features))

            # Marginal contribution: v(S ∪ {i}) - v(S)
            mask_with_i = mask | (1 << feature_i)
            marginal = model_value_fn(mask_with_i) - model_value_fn(mask)
            shapley[feature_i] += weight * marginal

    return shapley


# ─────────────────────────────────────────────────────────────────────────────
# Tests
# ─────────────────────────────────────────────────────────────────────────────

if __name__ == "__main__":
    nums = [1, 2, 3]
    expected = sorted([[], [1], [2], [3], [1,2], [1,3], [2,3], [1,2,3]])

    r1 = sorted(subsets_recursive(nums))
    r2 = sorted(subsets_bitmask(nums))
    r3 = sorted(subsets_iterative(nums))

    assert r1 == expected, f"recursive failed: {r1}"
    assert r2 == expected, f"bitmask failed: {r2}"
    assert r3 == expected, f"iterative failed: {r3}"

    # All three must agree
    assert r1 == r2 == r3

    # Edge cases
    assert subsets_bitmask([]) == [[]]         # empty set → one subset (the empty set)
    assert sorted(subsets_bitmask([7])) == [[], [7]]   # single element

    # Duplicates
    dedup = sorted(subsets_with_duplicates([1, 2, 2]))
    assert dedup == [[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]
    assert len(dedup) == 6   # not 8 — duplicates collapsed

    dedup2 = sorted(subsets_with_duplicates([1, 1, 1]))
    assert len(dedup2) == 4  # {}, {1}, {1,1}, {1,1,1}

    # Count verification: 2^n subsets for distinct elements
    for n in range(6):
        assert len(subsets_bitmask(list(range(n)))) == 2 ** n

    print("All tests passed.")

### The Recursion Tree for {1, 2, 3}

Each level corresponds to one element. At each node, the left branch excludes the element and the right branch includes it. Every path from root to leaf is one subset.

                       /                \
          backtrack(1, [])          backtrack(1, [1])
            /         \               /            \
  bt(2,[])        bt(2,[2])   bt(2,[1])        bt(2,[1,2])
   /    \           /    \      /     \           /      \
bt(3,[]) bt(3,[3]) bt(3,[2]) bt(3,[2,3]) bt(3,[1]) bt(3,[1,3]) bt(3,[1,2]) bt(3,[1,2,3])
  ↓        ↓        ↓         ↓           ↓          ↓           ↓            ↓
  {}      {3}      {2}       {2,3}        {1}        {1,3}       {1,2}       {1,2,3}

Depth = n = 3.  Leaves = 2³ = 8.
Every internal node is also recorded as a subset (at the result.append step).
```

```
mask (binary)   mask (decimal)   bits set   subset
─────────────   ──────────────   ────────   ──────────
     000              0          none       {}
     001              1          bit 0      {nums[0]} = {1}
     010              2          bit 1      {nums[1]} = {2}
     011              3          bits 0,1   {1, 2}
     100              4          bit 2      {nums[2]} = {3}
     101              5          bits 0,2   {1, 3}
     110              6          bits 1,2   {2, 3}
     111              7          bits 0,1,2 {1, 2, 3}

Reading across: incrementing the mask in binary systematically
visits every subset exactly once.
The binary digits ARE the include/exclude decisions.
```

### Iterative Cascading: Doubling at Each Step

```
Start:          [[]]                       size = 1 = 2⁰

Add 1:          [[]]  +  [[1]]             size = 2 = 2¹
                 ↑            ↑
           existing     existing + [1]

Add 2:     [[],[1]]  +  [[2],[1,2]]        size = 4 = 2²
            existing     existing + [2]

Add 3:  [[],[1],[2],[1,2]]  +  [[3],[1,3],[2,3],[1,2,3]]    size = 8 = 2³
           existing                  existing + [3]

Invariant: after processing k elements, result contains exactly 2^k subsets.
At each step, result[0..prev_size-1] are old subsets (without new element),
result[prev_size..] are those same subsets with new element appended.
```

## 7. Common Variations & Extensions

**Subsets of size exactly k.** Instead of collecting all subsets, only collect those where `len(path) == k`. This is combination generation — covered in [[74.Generating all combinations — nCr without repetition]]. The bitmask approach can filter by `bin(mask).count('1') == k`, or use `itertools.combinations` directly.

**Subset sum / partition problems.** Once you can enumerate subsets, a large class of problems reduces to: enumerate all subsets, check which satisfy a property. The 0/1 Knapsack (see [[175.0-1 Knapsack — item taken or not]]) is subset enumeration with pruning — DP is the efficient version, but understanding it as "which subsets of items fit in the knapsack" grounds the recurrence. Partition Equal Subset Sum (see [[178.Partition equal subset sum — knapsack as a decision problem]]) asks whether any subset sums to total/2.

**Enumerating subsets of a bitmask (sub-masks).** A harder variant: given a mask M, enumerate all subsets of M (submasks). The trick is `for (int s = M; s > 0; s = (s-1) & M)` in C++. This appears in bitmask DP optimisations and is covered in [[104.Subset enumeration with bitmask — iterating over all 2^n subsets]]. Total work across all masks is O(3ⁿ) — each element is either in neither, in the outer mask only, or in both.

**Meet in the middle.** For n up to 40, split into two halves of n/2 each. Enumerate all 2^(n/2) ≈ 2^20 ≈ 10^6 subsets for each half. For subset sum problems, sort one half's sums and binary-search from the other half. Total: O(2^(n/2) × n) ≈ O(n × 10^6) for n=40, vs O(2^40) ≈ 10^12 for brute force. This extends the tractable range from n=20 to n=40.

## 9. CP Contest Application

**Bitmask enumeration template — contest-ready:**

```cpp
// C++: enumerate all subsets, process each in O(n)
// Safe for n ≤ 20 within 1–2 seconds time limit
int n = nums.size();
for (int mask = 0; mask < (1 << n); ++mask) {
    long long subset_sum = 0;
    for (int i = 0; i < n; ++i)
        if ((mask >> i) & 1)
            subset_sum += nums[i];
    // process subset represented by mask
}
```

```python
# Python: same pattern, use 1 << n (Python ints don't overflow)
n = len(nums)
for mask in range(1 << n):
    subset = [nums[i] for i in range(n) if (mask >> i) & 1]
    # process subset
```

**Tight time limit guide:**

- n = 20: 2²⁰ = 1,048,576 subsets. Inner loop O(n) = 20 ops. Total ≈ 2×10⁷. Comfortably within 1s in C++, tight in Python.
- n = 25: 2²⁵ ≈ 3.3×10⁷. OK in C++, TLE in Python.
- n = 30: 2³⁰ ≈ 10⁹. TLE in C++ for O(n) inner work. Needs meet-in-the-middle.

**Popcount trick for subset filtering** — count set bits in O(1) with `__builtin_popcount(mask)` in C++ or `bin(mask).count('1')` in Python to quickly check subset size before doing heavier processing.
