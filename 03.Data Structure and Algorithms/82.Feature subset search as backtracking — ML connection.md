## 1. Intuition First

### The Core Idea

You have a dataset with 50 features. Your model is overfitting. You know the answer lives somewhere in a _subset_ of those features — but which subset?

The brute-force answer: try all 2⁵⁰ subsets, train a model on each, pick the best. That is approximately 10¹⁵ model evaluations. At one millisecond per evaluation, this takes 30,000 years.

This is not a hardware problem. It is a _search problem_. And it has the exact shape of every combinatorial search problem you have studied: a tree where each node is a partial decision (include feature _i_ or not), each path from root to leaf is a complete feature subset, and the vast majority of paths are not worth exploring.

The algorithm that makes this tractable is **backtracking** — the same algorithm that solves N-Queens and Sudoku — applied to the _feature lattice_.

A feature lattice is the set of all 2ⁿ subsets of n features, organised as a directed graph where each node is connected to the node with one more feature added. It is a hypercube graph. Moving from ∅ upward toward {f₁, f₂, …, fₙ} by adding one feature at a time traces a path through this lattice, and the path _is_ the call stack of a backtracking recursion.

### Why This Exists

The naive approach — exhaustive search — is infeasible for n > 30. But exhaustive search is not the only alternative to random guessing. The structure of the problem supports pruning:

**Monotone constraints:** If a subset S already performs _worse_ than the best known subset on some validation criterion, adding more features to S may or may not help — but if the evaluation criterion is monotone (e.g., training error never increases with more features), then all supersets of S are also suboptimal and the entire branch can be pruned. This is the **branch-and-bound** specialisation of backtracking.

**Forward and backward greedy search:** Instead of choosing any feature at each node, heuristically choose the feature that maximally improves the current subset's performance. This biases the search toward good solutions early and prunes implicitly by never revisiting bad directions. This is the production algorithm used in `sklearn`'s `SequentialFeatureSelector` and in RFE (Recursive Feature Elimination).

The insight that connects DSA to ML here is precise: **feature selection is a search problem over an exponential space, and every feature selection algorithm is implicitly a search strategy on the feature lattice — differing only in which nodes they visit and which they prune.**

### The "Aha" Moment

Every feature selection method — filter, wrapper, embedded — is secretly a position on the backtracking-to-random-search spectrum:

- **Exhaustive search** = backtracking with no pruning = O(2ⁿ).
- **Branch and bound** = backtracking with a bounding function on subset quality = feasible for n ≤ ~30.
- **Sequential forward selection (SFS)** = backtracking that only ever _adds_ one feature per level and picks greedily = O(n²) evaluations but finds only locally optimal subsets.
- **Genetic algorithms for feature selection** = random restarts in the backtracking tree with crossover = escapes local optima at the cost of theoretical guarantees.
- **LASSO / L1 regularisation** = continuous relaxation of the discrete backtracking problem = no tree search at all, but the sparsity structure of the solution is the continuous analog of a subset.

Once you see this, all feature selection literature collapses into one framework.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:** Any problem of the form "choose a subset of items satisfying constraints and maximising/minimising some objective" where n ≤ 20. This includes exact cover problems, set cover, weighted independent set, and any problem that can be modelled as selecting a subset of columns from a binary matrix.

**Pattern signals:**

- "Select k features/items from n such that some constraint holds" with n ≤ 20 → backtracking with pruning or bitmask DP ([[104. Subset enumeration with bitmask]]).
- n > 20 but constraints are monotone → branch and bound.
- The constraint is separable across items → DP on subsets ([[175. 0-1 Knapsack]]).
- "Find all subsets satisfying condition X" → backtracking, enumerate power set.

**Common trap:** Conflating subset selection with subset enumeration. If you need _the best_ subset and the evaluation function is additive, DP is almost always faster than backtracking (O(n · 2ⁿ) vs O(2ⁿ) but with much better constant factors due to pruning). But if the evaluation function is **non-decomposable** (e.g., model accuracy on a validation set, which depends on all selected features jointly), DP does not apply and backtracking is the only systematic approach.

**Time limit guidance:** Backtracking on n = 20 with tight pruning: ~10⁶ nodes visited, safe under 1s. Bitmask enumeration for n = 20: 2²⁰ ≈ 10⁶, borderline at 1s. For n = 25 with pruning: feasible. For n = 30 without pruning: marginal. Beyond n = 35: meet-in-the-middle (split into two halves of n/2) or approximation.

### Machine Learning / AI

**Wrapper methods are backtracking.** The wrapper method for feature selection trains a model on each candidate subset and uses model performance as the evaluation criterion. Sequential Forward Selection (SFS), Sequential Backward Elimination (SBE), and their floating variants (SFFS, SFBS) are all heuristic traversals of the feature lattice — they differ only in their traversal order and pruning strategy.

`sklearn`'s `SequentialFeatureSelector` implements SFS and SBE directly. The `mlxtend` library (`SequentialFeatureSelector` with `floating=True`) implements SFFS. Both are wrapper methods that call `cross_val_score` at each node of the backtracking tree.

**Recursive Feature Elimination (RFE)** — used in `sklearn.feature_selection.RFE` — is backward elimination guided by model-internal importance scores (e.g., SVM coefficients, tree feature importances). At each level of the backtracking tree, it removes the least important feature and recurses. It is backtracking with a fixed pruning heuristic derived from the model itself.

**Boruta** (Kursa & Rudnicki, 2010) is a statistically principled wrapper that compares each feature's importance against a shuffled "shadow" version of itself, iteratively eliminating unimportant features. It is backtracking with a statistical bounding function.

**AutoML feature pipelines:** H2O AutoML and Google AutoML internally run feature subset search as part of their pipeline optimisation. The search is framed as a combinatorial optimisation problem and solved with evolutionary algorithms (genetic search over the backtracking tree) or Bayesian optimisation (a learned bounding function that replaces the hand-crafted branch-and-bound bound).

**The L1 connection (critical):** LASSO regression solves the continuous relaxation of the feature subset selection problem. The L1 penalty term `λ∑|wᵢ|` acts as a _soft_ pruning function — features whose marginal contribution to the loss is smaller than λ are zeroed out. The sparsity pattern of the LASSO solution corresponds to a node in the feature lattice. The regularisation path (solutions for all values of λ) traces a path through the lattice from the full model (λ=0) toward the empty model (λ→∞). This is the continuous analog of the backtracking path from the full-feature-set leaf up to the root.

Understanding backtracking makes this connection immediate: LASSO is backtracking with a differentiable bounding function.

## 3. Algorithm / Pattern

### The Feature Lattice Formally

For n features {f₁, …, fₙ}, the feature lattice L is the power set 2^{f₁,…,fₙ} ordered by inclusion. Each node S ∈ L is a feature subset. An evaluation function `score(S, model, data)` maps each node to a real number.

Feature selection = find S* = argmax_{S ∈ L} score(S).

### Three Traversal Strategies

**1. Exhaustive backtracking (feasible: n ≤ 25)**

Standard power set enumeration with pruning. At each node, include or exclude the current feature. Prune if:

- Current subset already exceeds a resource constraint (e.g., size limit k).
- A bounding function certifies the best possible completion is worse than the current best.

Complexity: O(2ⁿ) nodes visited without pruning; potentially O(nᵏ) with tight bounding for k-sparse solutions.

**2. Sequential Forward Selection (greedy backtracking)**

Start from ∅. At each depth d, evaluate all n - d candidates for the next feature, add the best one, and recurse. Never removes a feature once added. Finds a locally optimal path through the lattice in O(n²) model evaluations.

This is DFS that always takes the locally best branch — greedy backtracking. It cannot recover from bad early choices (no backtracking step), but it is O(n²) instead of O(2ⁿ).

**3. Sequential Floating Forward Selection (SFFS)**

After each forward step, attempt backward steps that improve the current subset. This adds a limited backtracking capability: if a previously added feature becomes unhelpful after more features are added, it can be removed. In practice, SFFS explores a much richer portion of the lattice than pure SFS while remaining O(n²) to O(n³) in evaluations.

### Decision Tree for Algorithm Choice

```
n ≤ 20?
├── YES → Exhaustive backtracking with branch-and-bound
│         (exact optimal solution guaranteed)
n ≤ 100?
├── YES → SFS / SBE / SFFS with cross-validation scoring
│         (good solution in O(n²)–O(n³) evaluations)
n ≤ 1000?
├── YES → Embedded methods: LASSO, ElasticNet, tree importance
│         (continuous relaxation, O(n) effective cost)
n > 1000?
└── → Filter methods: mutual information, correlation, ANOVA F-test
    (no model training, O(n) per feature, zero backtracking)
```

### Complexity Summary

|Method|Evaluations|Optimality|
|---|---|---|
|Exhaustive|O(2ⁿ)|Global|
|Branch and bound|O(2ⁿ) worst, much less in practice|Global|
|SFS / SBE|O(n²)|Local|
|SFFS|O(n²)–O(n³)|Near-local|
|LASSO path|O(n) per λ step|Continuous relaxation|
|Filter (MI, corr)|O(n)|No joint interaction modelled|

## 4. Pseudocode

```
// Exhaustive feature subset search with branch and bound
// score(subset) = cross-validated model accuracy
// upper_bound(subset, remaining_features) = optimistic estimate
//   of best achievable score by adding any subset of remaining features

BranchAndBound(features, subset, start_idx, best_score, best_subset):
    current_score ← score(subset)
    if current_score > best_score:
        best_score ← current_score
        best_subset ← copy(subset)
    
    for i from start_idx to len(features):
        f ← features[i]
        
        // BOUNDING FUNCTION: can adding f and any subsequent features
        // possibly beat the current best?
        // If not, prune the entire subtree rooted here.
        if upper_bound(subset ∪ {f}, features[i+1:]) ≤ best_score:
            continue  // PRUNE
        
        // CHOOSE
        subset.add(f)
        
        // EXPLORE
        BranchAndBound(features, subset, i+1, best_score, best_subset)
        
        // UNCHOOSE (backtrack)
        subset.remove(f)
    
    return best_score, best_subset


// Sequential Forward Selection (greedy, O(n^2))
SFS(features, model, k):
    selected ← []
    remaining ← set(features)
    
    repeat k times:
        best_f ← None
        best_score ← -∞
        
        for f in remaining:
            s ← cross_val_score(model, data[:, selected + [f]])
            if s > best_score:
                best_score ← s
                best_f ← f
        
        selected.append(best_f)
        remaining.remove(best_f)
    
    return selected


// Upper bound for branch and bound
// Optimistic: assume every remaining feature, if added, gives its
// individual marginal gain simultaneously (ignores interactions)
upper_bound(subset, remaining):
    base ← score(subset)
    for f in remaining:
        base += max(0, score(subset ∪ {f}) - score(subset))
    return base
    // This is an OVERESTIMATE — actual joint gain ≤ sum of marginal gains
    // (sub-modularity assumption), so it is a valid upper bound
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <bits/stdc++.h>
using namespace std;

// ============================================================
// Feature Subset Search via Backtracking with Branch and Bound
//
// Problem: given n binary features and a scoring function,
// find the subset of size exactly k that maximises score.
// This models exact-k wrapper feature selection.
//
// Time: O(C(n,k)) visited nodes with pruning
// Space: O(k) call stack
// ============================================================

// Simulated scoring function — in production this calls a model
// Here: score = sum of selected feature indices (proxy for signal strength)
// Replace with cross_val_score(model, X[:, subset]) in real ML code
double scoreSubset(const vector<int>& subset, int n_features) {
    // Simulate: features with higher index are more informative
    // but feature pairs {0,3} and {1,2} are correlated (redundant)
    double s = 0.0;
    bool has0 = false, has1 = false, has2 = false, has3 = false;
    for (int f : subset) {
        s += (f + 1) * 0.5; // marginal signal
        if (f == 0) has0 = true;
        if (f == 1) has1 = true;
        if (f == 2) has2 = true;
        if (f == 3) has3 = true;
    }
    // Redundancy penalty: {0,3} and {1,2} are correlated
    if (has0 && has3) s -= 1.5;
    if (has1 && has2) s -= 1.0;
    return s;
}

// Greedy upper bound: sum of marginal gains of remaining features
// This is valid only under submodularity (satisfied here approximately)
double upperBound(const vector<int>& current, const vector<int>& remaining,
                  int k, int n_features) {
    if ((int)current.size() >= k) return scoreSubset(current, n_features);
    int slots = k - (int)current.size();
    double bound = scoreSubset(current, n_features);
    // Optimistically add the top 'slots' marginal gains
    vector<double> gains;
    for (int f : remaining) {
        vector<int> trial = current;
        trial.push_back(f);
        gains.push_back(scoreSubset(trial, n_features) - scoreSubset(current, n_features));
    }
    sort(gains.rbegin(), gains.rend());
    for (int i = 0; i < min(slots, (int)gains.size()); ++i)
        bound += max(0.0, gains[i]);
    return bound;
}

struct BnBState {
    double best_score = -1e18;
    vector<int> best_subset;
    int nodes_visited = 0;
};

void branchAndBound(int n_features, int k, int start,
                    vector<int>& current, BnBState& state) {
    state.nodes_visited++;

    double cur_score = scoreSubset(current, n_features);
    if ((int)current.size() == k) {
        if (cur_score > state.best_score) {
            state.best_score = cur_score;
            state.best_subset = current;
        }
        return;
    }

    // Build remaining features
    vector<int> remaining;
    set<int> cur_set(current.begin(), current.end());
    for (int f = start; f < n_features; ++f)
        remaining.push_back(f);

    // Prune: not enough remaining features to fill k slots
    if ((int)current.size() + (int)remaining.size() < k) return;

    for (int i = 0; i < (int)remaining.size(); ++i) {
        int f = remaining[i];

        // Build remaining after choosing f
        vector<int> rest(remaining.begin() + i + 1, remaining.end());

        // BOUNDING FUNCTION: can we possibly beat best?
        vector<int> trial = current;
        trial.push_back(f);
        if (upperBound(trial, rest, k, n_features) <= state.best_score) {
            continue; // PRUNE entire subtree
        }

        // Choose
        current.push_back(f);
        // Explore
        branchAndBound(n_features, k, start + i + 1, current, state);
        // Unchoose
        current.pop_back();
    }
}

// ============================================================
// Sequential Forward Selection — O(n^2) greedy wrapper
// ============================================================
vector<int> sequentialForwardSelection(int n_features, int k) {
    vector<int> selected;
    vector<bool> used(n_features, false);

    for (int step = 0; step < k; ++step) {
        double best_gain = -1e18;
        int best_f = -1;
        for (int f = 0; f < n_features; ++f) {
            if (used[f]) continue;
            selected.push_back(f);
            double s = scoreSubset(selected, n_features);
            if (s > best_gain) {
                best_gain = s;
                best_f = f;
            }
            selected.pop_back();
        }
        selected.push_back(best_f);
        used[best_f] = true;
    }
    return selected;
}

// ============================================================
// Bitmask enumeration for small n — exhaustive, no pruning
// O(2^n * k) — baseline comparison
// ============================================================
pair<double, vector<int>> exhaustiveBitmask(int n_features, int k) {
    double best = -1e18;
    int best_mask = 0;

    for (int mask = 0; mask < (1 << n_features); ++mask) {
        if (__builtin_popcount(mask) != k) continue;
        vector<int> subset;
        for (int i = 0; i < n_features; ++i)
            if (mask & (1 << i)) subset.push_back(i);
        double s = scoreSubset(subset, n_features);
        if (s > best) { best = s; best_mask = mask; }
    }

    vector<int> result;
    for (int i = 0; i < n_features; ++i)
        if (best_mask & (1 << i)) result.push_back(i);
    return {best, result};
}

int main() {
    int n = 8, k = 3; // 8 features, select 3

    // Method 1: Branch and Bound (exact)
    BnBState state;
    vector<int> current;
    branchAndBound(n, k, 0, current, state);
    cout << "Branch and Bound:\n";
    cout << "  Best score: " << state.best_score << "\n";
    cout << "  Best subset: {";
    for (int f : state.best_subset) cout << f << " ";
    cout << "}\n";
    cout << "  Nodes visited: " << state.nodes_visited
         << " / " << (1 << n) << " total\n\n";

    // Method 2: Sequential Forward Selection (greedy)
    auto sfs = sequentialForwardSelection(n, k);
    cout << "Sequential Forward Selection:\n";
    cout << "  Selected: {";
    for (int f : sfs) cout << f << " ";
    cout << "}, score=" << scoreSubset(sfs, n) << "\n\n";

    // Method 3: Exhaustive bitmask (ground truth)
    auto [ex_score, ex_subset] = exhaustiveBitmask(n, k);
    cout << "Exhaustive:\n";
    cout << "  Best score: " << ex_score << "\n";
    cout << "  Best subset: {";
    for (int f : ex_subset) cout << f << " ";
    cout << "}\n";

    return 0;
}
```

### Python (Readable + Pythonic)

```python
from __future__ import annotations
from itertools import combinations
from dataclasses import dataclass, field
from typing import Callable

import numpy as np

# ============================================================
# Type alias: a feature subset is a frozenset of column indices
# Scoring function: subset -> float (e.g., cross-val accuracy)
# ============================================================
ScoreFn = Callable[[frozenset[int]], float]


@dataclass
class SearchState:
    """Tracks search statistics across the backtracking tree."""
    best_score: float = float("-inf")
    best_subset: frozenset[int] = field(default_factory=frozenset)
    nodes_visited: int = 0
    nodes_pruned: int = 0


# ============================================================
# Branch and Bound — exact feature subset search
#
# Time: O(C(n,k)) in best case with tight bounds, O(2^n) worst case
# Space: O(k) recursion depth + O(n) for remaining list
#
# The bounding function is the key: it must be:
#   (a) computable cheaply (else pruning is more expensive than exploring)
#   (b) an overestimate (else we might prune valid optima)
# ============================================================
def branch_and_bound(
    n_features: int,
    k: int,
    score_fn: ScoreFn,
    upper_bound_fn: Callable[[frozenset[int], list[int], int], float] | None = None,
) -> tuple[frozenset[int], float]:
    """
    Find the k-feature subset maximising score_fn via branch and bound.

    Args:
        n_features: total number of features (0..n_features-1)
        k: exact subset size to select
        score_fn: callable(subset) -> float, higher is better
        upper_bound_fn: optional callable(current, remaining, k) -> float
                        providing an optimistic upper bound on the best
                        achievable score. Defaults to additive marginal gains.

    Returns:
        (best_subset, best_score)
    """
    state = SearchState()

    def marginal_upper_bound(current: frozenset[int], remaining: list[int], k: int) -> float:
        """Additive marginal gains bound — valid under submodularity."""
        slots = k - len(current)
        if slots <= 0:
            return score_fn(current)
        base = score_fn(current)
        gains = sorted(
            [max(0.0, score_fn(current | {f}) - base) for f in remaining],
            reverse=True
        )
        return base + sum(gains[:slots])

    bound_fn = upper_bound_fn or marginal_upper_bound

    def _search(current: frozenset[int], remaining: list[int]) -> None:
        state.nodes_visited += 1

        if len(current) == k:
            s = score_fn(current)
            if s > state.best_score:
                state.best_score = s
                state.best_subset = current
            return

        # Prune: not enough remaining to complete to size k
        if len(current) + len(remaining) < k:
            state.nodes_pruned += 1
            return

        for i, f in enumerate(remaining):
            candidate = current | {f}
            rest = remaining[i + 1:]

            # BOUNDING: can completing this branch ever beat current best?
            bound = bound_fn(candidate, rest, k)
            if bound <= state.best_score:
                state.nodes_pruned += 1
                continue  # prune subtree

            _search(candidate, rest)

    all_features = list(range(n_features))
    _search(frozenset(), all_features)
    return state.best_subset, state.best_score


# ============================================================
# Sequential Forward Selection — greedy, O(n^2) evaluations
# sklearn analog: SequentialFeatureSelector(direction='forward')
# ============================================================
def sequential_forward_selection(
    n_features: int,
    k: int,
    score_fn: ScoreFn,
) -> tuple[frozenset[int], float]:
    """
    Greedily add the feature that most improves score until |subset| = k.

    This is backtracking that only ever explores the locally best branch.
    It cannot undo a poor early choice — the classic greedy failure mode.
    """
    selected: frozenset[int] = frozenset()
    remaining = set(range(n_features))

    for _ in range(k):
        best_gain = float("-inf")
        best_f = -1
        for f in remaining:
            s = score_fn(selected | {f})
            if s > best_gain:
                best_gain = s
                best_f = f
        selected = selected | {best_f}
        remaining.remove(best_f)

    return selected, score_fn(selected)


# ============================================================
# Sequential Floating Forward Selection (SFFS)
# mlxtend analog: SequentialFeatureSelector(floating=True)
#
# After each forward step, attempt backward steps that improve score.
# This recovers from some greedy mistakes — limited backtracking.
# ============================================================
def sffs(
    n_features: int,
    k: int,
    score_fn: ScoreFn,
) -> tuple[frozenset[int], float]:
    """
    SFFS: forward step + optional backward steps until no improvement.

    The floating part is the backtracking ingredient: after adding a
    feature, we check whether removing any previously added feature
    (other than the one just added) improves the score.
    """
    selected: frozenset[int] = frozenset()
    remaining = set(range(n_features))

    while len(selected) < k:
        # Forward step: add best feature
        best_f = max(remaining, key=lambda f: score_fn(selected | {f}))
        selected = selected | {best_f}
        remaining.remove(best_f)

        # Backward floating steps: remove worst feature if it helps
        improved = True
        while improved and len(selected) > 1:
            improved = False
            worst_f = min(selected, key=lambda f: score_fn(selected - {f}))
            if score_fn(selected - {worst_f}) > score_fn(selected):
                selected = selected - {worst_f}
                remaining.add(worst_f)
                improved = True

    return selected, score_fn(selected)


# ============================================================
# Demonstration with synthetic data
# ============================================================
def make_synthetic_score_fn(n_features: int, seed: int = 42) -> ScoreFn:
    """
    Synthetic score function simulating correlated/redundant features.

    - Features 0,1,2 are highly informative (high individual signal)
    - Features 3,4 are redundant with feature 0 (interaction penalty)
    - Features 5..n are noise (low marginal signal)
    - Optimal 3-subset is {0, 1, 2} with score ≈ 0.91
    """
    rng = np.random.default_rng(seed)
    base_signal = rng.uniform(0.3, 0.9, n_features)
    base_signal[:3] = [0.85, 0.80, 0.75]  # informative
    base_signal[3:5] = [0.60, 0.55]        # redundant with feature 0
    base_signal[5:] = rng.uniform(0.1, 0.3, n_features - 5)  # noise

    def score(subset: frozenset[int]) -> float:
        if not subset:
            return 0.0
        s = sum(base_signal[f] for f in subset) / len(subset)
        # Redundancy penalty: {0,3} or {0,4} overlap
        if 0 in subset and 3 in subset:
            s -= 0.15
        if 0 in subset and 4 in subset:
            s -= 0.10
        # Synergy bonus: {0,1,2} complement each other
        if {0, 1, 2}.issubset(subset):
            s += 0.06
        return min(1.0, max(0.0, s))

    return score


if __name__ == "__main__":
    N, K = 10, 3
    score_fn = make_synthetic_score_fn(N)

    # Ground truth: exhaustive
    best_ex = max(combinations(range(N), K), key=lambda s: score_fn(frozenset(s)))
    best_ex_fs = frozenset(best_ex)
    print(f"Exhaustive optimal:  {set(best_ex_fs)}, score={score_fn(best_ex_fs):.4f}")

    # Branch and Bound
    bnb_subset, bnb_score = branch_and_bound(N, K, score_fn)
    print(f"Branch and Bound:    {set(bnb_subset)}, score={bnb_score:.4f}")

    # SFS (greedy)
    sfs_subset, sfs_score = sequential_forward_selection(N, K, score_fn)
    print(f"SFS (greedy):        {set(sfs_subset)}, score={sfs_score:.4f}")

    # SFFS (floating)
    sffs_subset, sffs_score = sffs(N, K, score_fn)
    print(f"SFFS (floating):     {set(sffs_subset)}, score={sffs_score:.4f}")

    # Verify BnB matches exhaustive
    assert bnb_subset == best_ex_fs, "Branch and Bound must match exhaustive"
    print("\nAll methods agree on optimal subset. BnB is exact; SFS/SFFS are heuristic.")
```

### Diagram 2 — SFS vs SFFS: When Greedy Fails

```
n=5 features, k=3. Scoring function has a "trap":
  Feature 0 has high individual signal (score boost: +0.40)
  But {0, 1, 2} is suboptimal vs {1, 2, 3} due to redundancy penalty.

SFS traversal (cannot undo):
  Step 1: Evaluate {0},{1},{2},{3},{4} → {0}=0.42 is best → ADD 0
  Step 2: Evaluate {0,1},{0,2},{0,3},{0,4} → {0,1}=0.71 is best → ADD 1
  Step 3: Evaluate {0,1,2},{0,1,3},{0,1,4} → {0,1,2}=0.78 is best → ADD 2
  Final: {0,1,2} = 0.78  ← SUBOPTIMAL (fell into greedy trap)

SFFS traversal (with floating backward steps):
  Step 1: ADD 0 → selected={0}
          Backward check: nothing to remove, skip
  Step 2: ADD 1 → selected={0,1}
          Backward check: remove 0? score({1})=0.38 < 0.71, skip
  Step 3: ADD 2 → selected={0,1,2}
          Backward check: remove 0? score({1,2})=0.82 > 0.78 → REMOVE 0
          selected={1,2}, backward check: nothing improves → stop
  Step 4: ADD 3 (best remaining) → selected={1,2,3}
  Final: {1,2,3} = 0.89  ← OPTIMAL recovered by backward step

The backward step IS the backtracking step: SFFS undoes a greedy mistake
by detecting that a previously committed choice is now suboptimal.
```

## 7. Common Variations & Extensions

**Bidirectional search on the lattice (SFS + SBE combined):** Start SFS from ∅ and SBE from the full feature set simultaneously. Terminate when they agree on a subset of size k. Useful when the optimal subset is neither very small nor very large.

**Interaction-aware feature selection:** When the scoring function captures feature _interactions_ (e.g., mutual information of feature pairs with the target), the bounding function must account for synergy. The Joint Mutual Information (JMI) criterion — used in the JMIM algorithm — is a tractable surrogate bounding function. This is the domain where naive greedy methods fail hardest and branch-and-bound gives the largest advantage. See [[38. Locality-sensitive hashing]] for dimensionality-reduction alternatives that sidestep discrete feature selection entirely.

**Feature selection as multi-armed bandit:** Modern AutoML systems (Optuna, HyperOpt) frame feature subset search as a bandit problem over the lattice, allocating more evaluations to promising branches. The tree structure of the bandit search space is identical to the backtracking tree; the difference is that evaluation cost is amortised across samples rather than paid in full at each node. The Tree-structured Parzen Estimator (TPE) in Optuna is precisely a learned bounding function for this bandit-backtracking hybrid.

**Group feature selection:** Features come in semantic groups (e.g., all one-hot encodings of a categorical variable, or all lags of a time-series). The backtracking tree is then over groups rather than individual features, reducing effective n dramatically. Group LASSO (Yuan & Lin, 2006) is the continuous analog. See [[220. Data pipeline design]] for how feature group structure maps to ML pipeline stages.

## 9. CP Contest Application

Feature subset search as a standalone CP problem appears disguised as:

**Exact cover / set cover variants (n ≤ 20):** "Given a universe of m elements and n sets, find the minimum number of sets covering the universe." This is exact cover — the canonical backtracking problem. Donald Knuth's Algorithm X + Dancing Links (DLX) is the state-of-the-art exact cover solver and is pure backtracking with tight pruning. On Codeforces, problems of this shape have n ≤ 20 for backtracking solutions and n ≤ 100,000 for approximate/greedy solutions.

**Weighted feature selection on Codeforces:** "Given n sensors, select at most k of them to maximise coverage while minimising cost" — this is feature subset selection with a resource constraint. The signal for backtracking: n ≤ 20, non-decomposable objective (coverage depends on the joint placement, not individual sensors).

**Template for exact-k subset optimisation (n ≤ 20):**

```cpp
double best = -1e18;
vector<int> best_subset;

void bt(int idx, int rem_slots, vector<int>& current, vector<int>& features) {
    if (rem_slots == 0 || idx == (int)features.size()) {
        if (rem_slots == 0) {
            double s = score(current);
            if (s > best) { best = s; best_subset = current; }
        }
        return;
    }
    // Pruning: not enough features left
    if ((int)(features.size() - idx) < rem_slots) return;

    // Include features[idx]
    current.push_back(features[idx]);
    if (upper_bound(current, features, idx+1, rem_slots-1) > best)
        bt(idx + 1, rem_slots - 1, current, features);
    current.pop_back();

    // Exclude features[idx]
    bt(idx + 1, rem_slots, current, features);
}
```

The bounding function is the entire difference between AC and TLE for n=25+. Spending 10 minutes designing a tight bound is always worth it over brute force enumeration.

_Commentary:_ The reason this note exists at the T2 boundary — neither pure CP nor pure ML — is that feature selection is where combinatorial search theory and statistical learning theory genuinely collide. Every ML practitioner who uses `sklearn`'s `RFE` or AutoML's feature engineering pipeline is running a backtracking search without knowing it. And every competitive programmer who has solved subset selection problems already has the intellectual substrate to understand modern neural architecture search and hyperparameter optimisation.

The non-obvious insight is that the evaluation function's _structure_ — not its domain — determines the algorithm. If `score(A ∪ B) ≤ score(A) + score(B)` (submodularity), then greedy selection achieves a (1 - 1/e) ≈ 63% approximation guarantee (Nemhauser et al., 1978). This is a theoretical result about the backtracking tree's greedy approximation quality, and it is the reason that greedy feature selection works surprisingly well in practice even though it cannot see the full lattice.
