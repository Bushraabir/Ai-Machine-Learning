## 1. Intuition First

### The Core Idea

Take a sorted 1D array and fold it into rows. If you choose the fold carefully — specifically, making each row's last element smaller than the next row's first element — the entire matrix reads as one long sorted sequence, left-to-right, top-to-bottom. The 2D grid is a 1D array in disguise.

The key operation is the **index mapping**: a single integer index `k` in `[0, m×n)` maps to row `k // n` and column `k % n`. This transforms a 2D binary search into a 1D binary search with a coordinate translation at the `mid` step. No extra space, no flattening — just arithmetic.

But not all 2D search problems give you this luxury. The second canonical structure — sometimes called the "staircase matrix" — has each row sorted left-to-right and each column sorted top-to-bottom, but the rows are _not_ chained end-to-end. Here the 1D flattening trick breaks down, and a completely different strategy emerges: **start at the top-right corner and eliminate an entire row or column at each step**, achieving O(m + n) — not O(log(mn)), but still far better than O(mn) and often the only correct approach.

Understanding which structure you have — and therefore which algorithm applies — is the real skill this topic teaches.

### Why This Exists

The naive approach scans every cell: O(mn). For a 1000×1000 matrix that is 10⁶ operations per query. With q queries, this is untenable. The sorted structure of the matrix is unused information in the naive approach — binary search extracts it.

The complexity gap:

|Structure|Naive|Binary Search / Staircase|
|---|---|---|
|Fully chained (LC 74)|O(mn)|O(log(mn))|
|Row+col sorted (LC 240)|O(mn)|O(m + n)|

For m = n = 10³ and q = 10⁵ queries: naive = 10¹¹ ops (TLE). Binary search = 2×10⁷ ops (trivially fast).

### The "Aha" Moment

**For the chained matrix:** The 2D array _is_ a 1D array. The only work is the index translation `mid → (mid // n, mid % n)`. Everything else is standard binary search on a sorted sequence.

**For the staircase matrix:** The top-right corner is the unique position where you have a _binary decision with no ambiguity_. If `arr[r][c] > target`: the entire column `c` has values ≥ `arr[r][c]` > target for all rows ≥ r, so column `c` is eliminated → move left. If `arr[r][c] < target`: the entire row `r` has values ≤ `arr[r][c]` < target for all columns ≤ c, so row `r` is eliminated → move down. Each step eliminates a full row or column. After at most m + n steps, you either find the target or exhaust the matrix.

## 2. Why We Need It — CP + ML Dual Context

### Competitive Programming

**When it appears:**

- Direct 2D search queries on sorted matrices (LC 74, LC 240).
- "Count elements ≤ k in a sorted matrix" — used as the inner check in binary search on answer for LC 378 (k-th smallest in sorted matrix).
- 2D range queries after coordinate compression: elements mapped to a grid, then counted with binary search.
- Sparse matrix search in problems involving grid-based scoring.

**Pattern signal:** You see a 2D grid with an explicit sorting guarantee — either "each row and column is sorted" or "each row's last element < next row's first element." The second condition is the chained signal; the first alone is the staircase signal. If neither condition is stated, binary search does not apply and you need different tools ([[112.Depth-First Search (DFS) — recursive and iterative]], [[113.Breadth-First Search (BFS) — level-order, shortest path in unweighted graph]]).

**Common trap — applying the wrong algorithm:**

Applying the O(log(mn)) 1D flattening to a staircase matrix (LC 240) gives wrong answers — rows are not chained, so the flat index does not correspond to sorted order. The reverse mistake (using O(m + n) staircase search on a chained matrix) is correct but suboptimal. In a contest, this costs time. Learn to distinguish them by reading the problem constraints carefully: "integers in each row are sorted left to right, and the first integer of each row is greater than the last integer of the previous row" → chained. "integers in each row are sorted left to right, and integers in each column are sorted top to bottom" → staircase.

**Second common trap — off-by-one in index translation:**

In the chained matrix binary search, computing `row = mid // n` requires `n` to be the _number of columns_, not rows. Swapping m and n here produces a valid-looking but wrong index and causes access violations or wrong answers.

### Machine Learning / AI

**Sorted 2D similarity matrices in retrieval systems:**

In dense retrieval (e.g., FAISS, DPR — Dense Passage Retrieval), a similarity matrix between query embeddings and document embeddings is computed. When this matrix is pre-sorted per row (sorted similarity scores per query), the staircase search pattern appears: finding all documents above a similarity threshold for a given query is a `lower_bound` call on that row. Finding documents above threshold across all queries is a 2D structured search.

**Hyperparameter grid search with monotone objectives:**

When tuning two hyperparameters (e.g., learning rate and regularisation strength) on a grid where the validation loss is monotone in both parameters — more regularisation + lower learning rate always increases loss — the optimal region forms a "staircase" boundary. Binary search on each row/column of the evaluation grid locates the Pareto frontier in O(m log n) instead of O(mn). This is a direct application of the staircase structure.

**`np.searchsorted` on 2D arrays:**

`numpy.searchsorted` does not natively handle 2D arrays — it flattens or operates row-by-row. Knowing that a properly structured 2D array _can_ be searched as 1D (if chained) means you can call `np.searchsorted(matrix.ravel(), target)` and translate the flat index back with `divmod`. For the staircase case, a vectorised implementation runs `np.searchsorted` independently on each row (O(m log n)) or uses the staircase walk in a Cython/Numba loop.

**K-th smallest in a sorted matrix — used in quantile computation:**

LC 378 (k-th smallest element in sorted matrix) uses binary search on answer: the predicate "how many elements ≤ mid?" is answered by a staircase count in O(m + n). This appears in ML monitoring pipelines computing the k-th percentile of a metric matrix across experiments × time-steps without sorting the full matrix.

## 3. Algorithm / Pattern

### Algorithm A — Chained Matrix (Fully Sorted, LC 74)

The matrix satisfies: `matrix[i][n-1] < matrix[i+1][0]` for all rows i.

**Plain English:**

1. Treat the entire matrix as a sorted 1D array of length `m × n`.
2. Maintain `lo = 0`, `hi = m * n - 1`.
3. At each step: `mid = (lo + hi) // 2`. Translate: `r = mid // n`, `c = mid % n`.
4. Compare `matrix[r][c]` to target. Standard binary search from here.
5. Time: O(log(mn)) = O(log m + log n).

### Algorithm B — Staircase Matrix (Row + Column Sorted, LC 240)

The matrix satisfies: each row sorted left-to-right AND each column sorted top-to-bottom.

**Plain English:**

1. Start at the **top-right corner**: `r = 0`, `c = n - 1`.
2. If `matrix[r][c] == target`: found.
3. If `matrix[r][c] > target`: column `c` eliminated (all values in col ≥ current, all > target) → `c -= 1`.
4. If `matrix[r][c] < target`: row `r` eliminated (all values in row ≤ current, all < target) → `r += 1`.
5. If `r >= m` or `c < 0`: target absent.
6. Time: O(m + n). Each step decrements `c` or increments `r`; at most m + n steps total.

**Why top-right, not top-left or bottom-left?**

- **Top-left** (`matrix[0][0]`): both right and down are larger. A miss gives no elimination direction — you don't know whether to go right or down.
- **Bottom-right** (`matrix[m-1][n-1]`): both left and up are smaller. Same problem in reverse.
- **Top-right** and **bottom-left** are the two valid starting corners — each has one direction for "eliminate row" and one for "eliminate column," creating a deterministic decision at every step.

### Decision Tree

```
Given m × n matrix with sorted guarantees:

Is each row's last element < next row's first element?
  YES → Chained matrix
        → Flatten to 1D index, standard binary search
        → O(log(mn))

  NO, but each row AND column individually sorted?
        → Staircase matrix
        → Start top-right, eliminate row or column at each step
        → O(m + n)

  Neither guarantee holds?
        → Binary search does not apply
        → BFS/DFS or brute force O(mn)
```

### Complexity

|Algorithm|Time|Space|
|---|---|---|
|Chained (1D flatten)|O(log(mn)) = O(log m + log n)|O(1)|
|Staircase (top-right walk)|O(m + n)|O(1)|
|Naive scan|O(mn)|O(1)|

Note: O(log(mn)) < O(m + n) when m, n are both large. For a 1000×1000 matrix: log(10⁶) ≈ 20 vs 2000. The chained matrix algorithm is strictly stronger — but it requires the stronger constraint.

## 4. Pseudocode

```
// ─────────────────────────────────────────────
// Algorithm A: Chained Matrix Binary Search
// Precondition: matrix[i][n-1] < matrix[i+1][0]
// ─────────────────────────────────────────────
SEARCH_CHAINED(matrix, m, n, target):
    lo ← 0
    hi ← m * n - 1                   // treat as flat 1D array

    while lo <= hi:
        mid ← lo + (hi - lo) / 2
        r   ← mid / n                // row index
        c   ← mid % n                // column index
        val ← matrix[r][c]

        if val == target:
            return (r, c)             // found; return coordinates
        else if val < target:
            lo ← mid + 1             // target is to the right in flat order
        else:
            hi ← mid - 1             // target is to the left in flat order

    return NOT_FOUND


// ─────────────────────────────────────────────
// Algorithm B: Staircase Search
// Precondition: rows sorted L→R, cols sorted T→B
// ─────────────────────────────────────────────
SEARCH_STAIRCASE(matrix, m, n, target):
    r ← 0
    c ← n - 1                        // start at top-right corner

    while r < m AND c >= 0:
        val ← matrix[r][c]

        if val == target:
            return (r, c)             // found
        else if val > target:
            c ← c - 1                // eliminate column c (all vals ≥ val > target)
        else:
            r ← r + 1                // eliminate row r (all vals ≤ val < target)

    return NOT_FOUND


// ─────────────────────────────────────────────
// Bonus: Count elements <= k in staircase matrix
// Used as inner predicate in k-th smallest search
// ─────────────────────────────────────────────
COUNT_LEQ(matrix, m, n, k):
    count ← 0
    r ← m - 1                        // start at bottom-left corner
    c ← 0

    while r >= 0 AND c < n:
        if matrix[r][c] <= k:
            count ← count + (r + 1)  // all r+1 elements in column c above are also <= k
            c ← c + 1                // move right
        else:
            r ← r - 1                // move up

    return count
```

## 5. Implementation

### C++ (Production-Ready)

```cpp
#include <vector>
#include <iostream>
#include <cassert>

// ─────────────────────────────────────────────────────────
// Algorithm A: Binary search on chained sorted matrix
// Each row's last element < next row's first element.
// Returns {row, col} or {-1, -1} if not found.
// Time: O(log(mn))  Space: O(1)
// ─────────────────────────────────────────────────────────
std::pair<int,int> searchChained(const std::vector<std::vector<int>>& mat, int target) {
    int m = mat.size();
    if (m == 0) return {-1, -1};
    int n = mat[0].size();

    int lo = 0, hi = m * n - 1;

    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        int r   = mid / n;           // row: integer division by column count
        int c   = mid % n;           // col: remainder
        int val = mat[r][c];

        if (val == target) return {r, c};
        if (val < target)  lo = mid + 1;
        else               hi = mid - 1;
    }
    return {-1, -1};
}


// ─────────────────────────────────────────────────────────
// Algorithm B: Staircase search on row+column sorted matrix
// Each row sorted L→R, each column sorted T→B.
// Returns {row, col} or {-1, -1} if not found.
// Time: O(m + n)  Space: O(1)
// ─────────────────────────────────────────────────────────
std::pair<int,int> searchStaircase(const std::vector<std::vector<int>>& mat, int target) {
    int m = mat.size();
    if (m == 0) return {-1, -1};
    int n = mat[0].size();

    int r = 0, c = n - 1;            // start: top-right corner

    while (r < m && c >= 0) {
        int val = mat[r][c];
        if (val == target) return {r, c};
        if (val > target)  c--;      // eliminate column c
        else               r++;      // eliminate row r
    }
    return {-1, -1};
}


// ─────────────────────────────────────────────────────────
// Count elements <= k in a row+col sorted matrix.
// Used as the predicate in k-th smallest (LC 378).
// Walks from bottom-left corner upward.
// Time: O(m + n)  Space: O(1)
// ─────────────────────────────────────────────────────────
int countLeq(const std::vector<std::vector<int>>& mat, int k) {
    int m = mat.size(), n = mat[0].size();
    int count = 0;
    int r = m - 1, c = 0;            // start: bottom-left corner

    while (r >= 0 && c < n) {
        if (mat[r][c] <= k) {
            count += r + 1;          // all r+1 cells above (and this cell) in col c are <= k
            c++;                     // advance right
        } else {
            r--;                     // move up to find a cell <= k
        }
    }
    return count;
}


// ─────────────────────────────────────────────────────────
// K-th smallest element in sorted matrix (LC 378)
// Binary search on value range + countLeq as predicate.
// Time: O((m+n) * log(max-min))  Space: O(1)
// ─────────────────────────────────────────────────────────
int kthSmallest(const std::vector<std::vector<int>>& mat, int k) {
    int m = mat.size(), n = mat[0].size();
    int lo = mat[0][0];
    int hi = mat[m-1][n-1];

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        // If there are >= k elements <= mid, answer is in [lo, mid]
        if (countLeq(mat, mid) >= k) hi = mid;
        else                          lo = mid + 1;
    }
    return lo;
}


int main() {
    // ── Chained matrix ──
    std::vector<std::vector<int>> chained = {
        {1,  3,  5,  7},
        {10, 11, 16, 20},
        {23, 30, 34, 60}
    };

    assert((searchChained(chained, 3)  == std::pair{0, 1}));
    assert((searchChained(chained, 13) == std::pair{-1, -1}));
    assert((searchChained(chained, 1)  == std::pair{0, 0}));   // top-left
    assert((searchChained(chained, 60) == std::pair{2, 3}));   // bottom-right

    // ── Staircase matrix ──
    std::vector<std::vector<int>> staircase = {
        {1,  4,  7,  11, 15},
        {2,  5,  8,  12, 19},
        {3,  6,  9,  16, 22},
        {10, 13, 14, 17, 24},
        {18, 21, 23, 26, 30}
    };

    assert((searchStaircase(staircase, 5)  == std::pair{1, 1}));
    assert((searchStaircase(staircase, 20) == std::pair{-1, -1}));
    assert((searchStaircase(staircase, 1)  == std::pair{0, 0}));
    assert((searchStaircase(staircase, 30) == std::pair{4, 4}));

    // ── K-th smallest ──
    std::vector<std::vector<int>> mat = {
        {1, 5, 9},
        {10, 11, 13},
        {12, 13, 15}
    };
    assert(kthSmallest(mat, 8) == 13);
    assert(kthSmallest(mat, 1) == 1);
    assert(kthSmallest(mat, 9) == 15);

    std::cout << "All assertions passed.\n";
    return 0;
}
```

### Python (Readable + Pythonic)

```python
"""
Binary Search on 2D Matrix
===========================
Two canonical structures, two algorithms:

  Chained matrix  → O(log(mn))  via 1D index flattening
  Staircase matrix → O(m + n)   via top-right corner walk

Both use O(1) space.
"""

from __future__ import annotations


def search_chained(matrix: list[list[int]], target: int) -> tuple[int, int] | None:
    """
    Search in a matrix where each row's last element < next row's first.
    The matrix reads as a sorted 1D array in row-major order.
    Returns (row, col) or None.
    Time: O(log(m*n))
    """
    if not matrix or not matrix[0]:
        return None
    m, n = len(matrix), len(matrix[0])
    lo, hi = 0, m * n - 1

    while lo <= hi:
        mid = (lo + hi) // 2
        r, c = divmod(mid, n)        # key translation: flat index → 2D coords
        val = matrix[r][c]

        if val == target:   return (r, c)
        if val < target:    lo = mid + 1
        else:               hi = mid - 1

    return None


def search_staircase(matrix: list[list[int]], target: int) -> tuple[int, int] | None:
    """
    Search in a matrix where each row and each column is sorted.
    Rows need NOT chain into each other.
    Start top-right; eliminate a row or column at each step.
    Returns (row, col) or None.
    Time: O(m + n)
    """
    if not matrix or not matrix[0]:
        return None
    m, n = len(matrix), len(matrix[0])
    r, c = 0, n - 1                  # top-right corner

    while r < m and c >= 0:
        val = matrix[r][c]
        if val == target:  return (r, c)
        if val > target:   c -= 1    # col c eliminated: all vals >= val > target
        else:              r += 1    # row r eliminated: all vals <= val < target

    return None


def count_leq(matrix: list[list[int]], k: int) -> int:
    """
    Count elements <= k in a row+col sorted matrix.
    Walks from bottom-left corner. Each step eliminates a row or advances a col.
    Time: O(m + n)
    """
    m, n = len(matrix), len(matrix[0])
    count = 0
    r, c = m - 1, 0                  # bottom-left corner

    while r >= 0 and c < n:
        if matrix[r][c] <= k:
            count += r + 1           # all cells above this one in col c are also <= k
            c += 1
        else:
            r -= 1

    return count


def kth_smallest(matrix: list[list[int]], k: int) -> int:
    """
    K-th smallest element in a row+col sorted matrix.
    Binary search on the value range; countLeq is the monotone predicate.
    Time: O((m + n) * log(max - min))
    """
    m, n = len(matrix), len(matrix[0])
    lo, hi = matrix[0][0], matrix[m-1][n-1]

    while lo < hi:
        mid = (lo + hi) // 2
        # Predicate: "at least k elements are <= mid"
        if count_leq(matrix, mid) >= k:
            hi = mid                 # mid may be the answer; don't exclude it
        else:
            lo = mid + 1            # not enough elements; answer is larger

    return lo


# ── Tests ─────────────────────────────────────────────────────────────────

if __name__ == "__main__":
    # Chained matrix
    chained = [
        [1,  3,  5,  7],
        [10, 11, 16, 20],
        [23, 30, 34, 60],
    ]
    assert search_chained(chained, 3)  == (0, 1)
    assert search_chained(chained, 13) is None
    assert search_chained(chained, 1)  == (0, 0)
    assert search_chained(chained, 60) == (2, 3)

    # Single row / single column edge cases
    assert search_chained([[1, 3, 5]], 3) == (0, 1)
    assert search_chained([[1], [3], [5]], 3) == (1, 0)

    # Staircase matrix
    staircase = [
        [1,  4,  7,  11, 15],
        [2,  5,  8,  12, 19],
        [3,  6,  9,  16, 22],
        [10, 13, 14, 17, 24],
        [18, 21, 23, 26, 30],
    ]
    assert search_staircase(staircase, 5)  == (1, 1)
    assert search_staircase(staircase, 20) is None
    assert search_staircase(staircase, 1)  == (0, 0)
    assert search_staircase(staircase, 30) == (4, 4)

    # k-th smallest
    mat = [
        [1,  5,  9],
        [10, 11, 13],
        [12, 13, 15],
    ]
    assert kth_smallest(mat, 8) == 13
    assert kth_smallest(mat, 1) == 1
    assert kth_smallest(mat, 9) == 15

    # count_leq
    assert count_leq(mat, 10) == 4   # elements: 1, 5, 9, 10
    assert count_leq(mat, 13) == 8   # all except 15

    print("All tests passed.")
```

### Diagram 3 — Why Top-Right, Not Top-Left

```
Starting at TOP-LEFT (0,0):
  val < target → go right OR go down  ← AMBIGUOUS, no elimination possible
  val > target → impossible (nothing smaller above/left)

Starting at TOP-RIGHT (0, n-1):
  val > target → go LEFT  (entire column eliminated downward: all vals ≥ this)
  val < target → go DOWN  (entire row eliminated leftward: all vals ≤ this)
  ✓ Every comparison eliminates exactly one full row or column.

Starting at BOTTOM-LEFT (m-1, 0):
  val > target → go UP    (entire row eliminated rightward)
  val < target → go RIGHT (entire column eliminated upward)
  ✓ Also valid. Mirror of top-right logic.

Starting at BOTTOM-RIGHT (m-1, n-1):
  val > target → go left OR go up ← AMBIGUOUS again.

The two valid corners are the ones where exactly one direction
increases values and exactly one decreases them.
```

## 7. Common Variations & Extensions

### 7.1 K-th smallest in a sorted matrix (LC 378)

Binary search on answer using `count_leq` as the predicate:

- Search space: `[matrix[0][0], matrix[m-1][n-1]]`.
- Predicate: "count of elements ≤ mid ≥ k" — this is monotone increasing in mid.
- Apply `lower_bound` (from [[56.lower_bound and upper_bound — first and last occurrence]]) on the value range.
- Time: O((m + n) × log(max − min)).

This is the canonical example of a binary search on answer where the predicate itself requires an O(m + n) inner computation.

### 7.2 Count negatives in a row-wise sorted matrix (LC 1351)

Each row is sorted descending. Find the boundary between non-negatives and negatives in each row using binary search: O(m log n). Or use the staircase walk starting from bottom-left: O(m + n). The staircase is faster and simpler once you see the pattern.

### 7.3 Search in a 2D matrix with sorted diagonals

If diagonals are sorted (not rows/columns), neither algorithm applies directly. This requires a different decomposition — typically extracting each diagonal as a 1D array and binary-searching within it: O(min(m,n) × log(max(m,n))).

### 7.4 Median in a row-wise sorted matrix

Binary search on value range. For each candidate median value `mid`, count elements ≤ mid using binary search on each row in O(m log n). Full algorithm: O(m log n × log(max − min)). Appears in problems where you cannot sort the full matrix. Connects directly to [[52.Quickselect — k-th smallest in expected O(n)]] as an alternative when the matrix is small.

### 7.5 Sparse matrix search (CTCI-style)

An M × N matrix where each row and column is sorted but has an unbounded sparse structure (blank/null entries interspersed). Binary search must skip nulls, degrading to O(m × log n) worst case with binary search per row. The staircase walk does not handle nulls cleanly.

## 9. CP Contest Application

### Typical Codeforces structure

**Pattern — "Count pairs (i, j) such that A[i] + B[j] ≤ k":**  
Sort both arrays. For each A[i], binary search in B for the count of elements ≤ k − A[i]. The result is a 2D search problem reduced to m binary searches: O(m log n). Recognising this as a 2D structure with the staircase property (sorted rows from the conceptual "A × B" matrix) gives the O(m + n) two-pointer solution.

**Pattern — "K-th smallest in a virtual matrix" (Codeforces Div. 1 C/D):**  
The matrix is defined implicitly (e.g., all pairwise products of two sorted arrays). You cannot materialise it. Binary search on value + count_leq on the virtual matrix via two-pointer or binary search per row. Time complexity depends on the count_leq implementation.

### Time limits where this matters

At m = n = 500 and q = 10^4 queries on a sorted matrix:

- Naïve scan: 500 × 500 × 10^4 = 2.5 × 10^9 → TLE.
- Staircase per query: (500 + 500) × 10^4 = 10^7 → fast.
- Chained binary search: log(250000) × 10^4 ≈ 1.8 × 10^5 → extremely fast.

The choice between algorithms matters most when the matrix is known to be chained — do not default to the staircase when the stronger O(log(mn)) is available.
