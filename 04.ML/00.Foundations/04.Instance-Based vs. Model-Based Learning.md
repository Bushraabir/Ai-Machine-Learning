## 1. The Core Question

When a learning algorithm encounters new training data, it faces a fundamental architectural decision:

> **Does it extract and compress the knowledge into a fixed set of parameters — or does it keep the raw data and use it directly at prediction time?**

This is the distinction between **model-based** and **instance-based** learning.

It is not about accuracy. It is about **where and when generalisation happens.**

||Model-Based|Instance-Based|
|---|---|---|
|**When does learning happen?**|During training — upfront|At prediction time — deferred|
|**What does the algorithm store?**|A compact set of parameters $\theta$|The training data itself|
|**What does the algorithm discard?**|The raw training examples|Nothing|
|**Generalisation mechanism**|Global function approximation|Local similarity comparison|

Every ML algorithm you will ever use falls into one of these two families, or is a hybrid of both. Understanding this distinction at the first-principles level determines how you reason about memory, speed, data requirements, and failure modes.

---

## 2. Model-Based Learning

### 2.1 What Is It?

A model-based learner **fits a parameterised function** to the training data. The training process searches for parameters $\theta^_$ that minimise a loss function. Once found, the raw training data is no longer needed — all the learned knowledge is compressed into $\theta^_$.

**Formal definition.** Given a hypothesis class $\mathcal{H} = {h_\theta \mid \theta \in \Theta}$ and a training set $\mathcal{D} = {(x_i, y_i)}_{i=1}^n$, model-based learning solves:

$$\theta^* = \arg\min_{\theta \in \Theta} \frac{1}{n} \sum_{i=1}^n \mathcal{L}(h_\theta(x_i),, y_i) + \lambda,\Omega(\theta)$$

At prediction time, for a new input $x$:

$$\hat{y} = h_{\theta^*}(x)$$

The raw training set $\mathcal{D}$ plays no role in this prediction. Only $\theta^*$ matters.

**Analogy.** A student reads 500 pages of a textbook, distils the knowledge into a set of formulas and principles in their notebook, then closes the textbook forever. At exam time, they use only their notebook. The textbook is gone.

### 2.2 The Training Pipeline

```
Training data D = {(x_i, y_i)}
        │
        ▼
  Choose hypothesis class H
  (linear, neural net, decision tree, ...)
        │
        ▼
  Optimise: find θ* that minimises loss over D
        │
        ▼
  Store θ* only — discard D
        │
        ▼
  At prediction time: ŷ = h_θ*(x_new)
  (no reference to D)
```

### 2.3 Examples of Model-Based Algorithms

|Algorithm|What $\theta$ Represents|Hypothesis Class|
|---|---|---|
|Linear regression|Weight vector $w$, bias $b$|${x \mapsto w^\top x + b}$|
|Logistic regression|Weight vector $w$, bias $b$|${x \mapsto \sigma(w^\top x + b)}$|
|Neural network|All layer weights and biases|Compositions of nonlinear transformations|
|Decision tree|Split rules and leaf values|Piecewise constant functions|
|Naive Bayes|Class priors $P(y)$, likelihoods $P(x \mid y)$|Generative probabilistic model|
|SVM (with kernel)|Support vectors + dual weights $\alpha_i$|Maximum-margin hyperplane|
|Linear Discriminant Analysis|Class means $\mu_k$, shared covariance $\Sigma$|Gaussian class-conditional model|

> [!note] SVM is a hybrid SVMs technically store a subset of training points (the support vectors), but only a small fixed number — not the full dataset. At prediction time, only support vectors are used, not the full training set. This makes SVMs closer to model-based, despite storing some instances.

### 2.4 The Inductive Bias Is Global

Model-based learners make **global assumptions** about $f^*$:

- Linear regression says $f^*$ is globally linear everywhere in $\mathcal{X}$.
- A 3-layer neural network says $f^*$ is a specific composition of nonlinear transformations globally.

These assumptions allow the model to generalise to any $x \in \mathcal{X}$, even regions of input space with no training data nearby. This is both a strength and a risk — the model extrapolates according to its global structure, which may be wrong far from the training data.

## 3. Instance-Based Learning

### 3.1 What Is It?

An instance-based learner (also called a **memory-based** or **lazy** learner) makes **no upfront generalisation**. It stores the entire training dataset and defers all computation to prediction time. When a new query $x$ arrives, it looks up the most similar stored examples and uses them directly to produce a prediction.

**Formal definition.** Store $\mathcal{D} = {(x_i, y_i)}_{i=1}^n$ in memory. At prediction time, for query $x$:

1. Compute similarity (or distance) between $x$ and every stored $x_i$
2. Identify the most relevant neighbours
3. Aggregate their labels $y_i$ to produce $\hat{y}$

There is no $\theta^*$. There is no loss minimisation. The "model" **is** the training data.

**Analogy.** A student has never read the textbook. At exam time, they bring all 500 pages of notes and flip through them, find the most similar past problem, and copy the solution. They have done zero upfront processing. All work happens at the exam.

### 3.2 The K-Nearest Neighbours Algorithm

KNN is the canonical instance-based algorithm. It is so simple it can be stated in one paragraph, yet it has deep theoretical properties.

**Algorithm (KNN regression):**

Given training set $\mathcal{D}$, distance function $d$, and hyperparameter $k$:

$$\hat{y} = \frac{1}{k} \sum_{i \in \mathcal{N}_k(x)} y_i$$

where $\mathcal{N}_k(x) = {k \text{ indices } i \text{ such that } x_i \text{ are the } k \text{ nearest points to } x}$.

**For classification**, replace the mean with a majority vote:

$$\hat{y} = \arg\max_{c} \sum_{i \in \mathcal{N}_k(x)} \mathbf{1}[y_i = c]$$

**The role of $k$:**

|$k$|Behaviour|Risk|
|---|---|---|
|$k = 1$|Predict exactly the label of the nearest neighbour|Overfitting — decision boundary is jagged, sensitive to noise|
|$k = n$|Predict the global average of all training labels|Underfitting — ignores all local structure|
|$k$ moderate|Smooth local average|Must be tuned via cross-validation|

As $n \to \infty$ with $k \to \infty$ and $k/n \to 0$, the 1-NN error rate converges to at most **twice the Bayes error rate** — an asymptotically strong guarantee.

### 3.3 Distance Functions Matter Critically

Instance-based learning is only as good as its notion of similarity. The distance function is the inductive bias.

|Distance|Formula|When to Use|
|---|---|---|
|Euclidean|$d(x, z) = \|x - z\|_2$|Continuous, isotropic features|
|Manhattan|$d(x, z) = \|x - z\|_1$|Robust to outliers; high-dimensional|
|Cosine similarity|$1 - \frac{x \cdot z}{\|x\|z\|}$|Text / sparse vectors; magnitude irrelevant|
|Hamming|Count of positions where $x_i \neq z_i$|Categorical or binary features|
|Mahalanobis|$\sqrt{(x-z)^\top \Sigma^{-1} (x-z)}$|Accounts for feature correlations and scale|

> [!warning] The Curse of Dimensionality In high dimensions, Euclidean distance becomes meaningless. As $d \to \infty$, the ratio of the farthest to nearest neighbour approaches 1 — every point becomes equidistant from every other point. Instance-based learning degrades rapidly in high-dimensional raw feature spaces. Feature engineering, PCA, or learned embeddings are essential preprocessors.

### 3.4 Other Instance-Based Algorithms

KNN is the simplest, but the family is broader:

|Algorithm|Mechanism|
|---|---|
|**Kernel regression**|Weighted average of all training labels, weights decay with distance|
|**Locally weighted regression**|Fit a local linear model around each query point using distance-based weights|
|**Radial Basis Function networks**|Neural network with RBF units centred on training examples|
|**Case-Based Reasoning**|Retrieves similar past cases, adapts their solutions; used in expert systems|
|**Parzen window density estimation**|Estimates $P(x)$ by placing kernels at each training point|

## 4. The Fundamental Tradeoff

The choice between instance-based and model-based learning is a tradeoff along four axes:

### 4.1 Computation: Training vs. Prediction

||Training Cost|Prediction Cost|
|---|---|---|
|**Model-based**|High — optimise over all parameters|$O(1)$ or $O(d)$ — evaluate $h_{\theta^*}(x)$|
|**Instance-based**|$O(0)$ — just store the data|$O(nd)$ — compute distance to all $n$ examples|

Model-based learners **pay at training time**. Instance-based learners **pay at prediction time**. For systems that must respond in microseconds (real-time search, autonomous driving), paying $O(nd)$ per query is often unacceptable.

Approximation methods (KD-trees, ball trees, locality-sensitive hashing) reduce KNN prediction to $O(\log n)$ or $O(1)$ amortised — but at the cost of exactness.

### 4.2 Memory

||Memory Required|
|---|---|
|**Model-based**|$O(|
|**Instance-based**|$O(nd)$ — grows with dataset size $n$ and dimensionality $d$|

A trained ResNet-50 with 25 million parameters uses ~100MB regardless of whether it was trained on 10,000 or 10 million images. A KNN classifier trained on 10 million images in $d=1000$ dimensions stores 10 billion floats — ~40GB.

### 4.3 Adaptability

||Adapting to New Data|
|---|---|
|**Model-based**|Requires retraining (expensive) or online updates (if supported)|
|**Instance-based**|Trivial — just append to $\mathcal{D}$. New examples are immediately used|

This is why instance-based methods are naturally suited to online, non-stationary settings — adding a new example costs $O(d)$ storage and immediately affects future predictions.

### 4.4 Transparency of Generalisation

||How Does It Generalise?|
|---|---|
|**Model-based**|Explicit global function encoded in $\theta^*$ — you can inspect the model|
|**Instance-based**|Implicitly — by proximity to stored examples. Predictions are black-box|

A linear model's weights tell you which features matter. A KNN classifier gives you no such summary — you can only ask "why this prediction?" and the answer is "because these $k$ neighbours had these labels."

## 5. When to Use Each

### 5.1 When to Use Model-Based Learning

> [!note] When to Use Model-Based Learning
> 
> 1. **Fast predictions required** — real-time systems, embedded devices, serving at scale
> 2. **Memory is constrained** — you cannot store the full training set at inference time
> 3. **Data distribution is understood** — you have strong prior knowledge about the functional form of $f^*$ (e.g., it really is linear)
> 4. **Interpretability is needed** — regulators, stakeholders, or debugging require understanding the model
> 5. **Large datasets** — $n$ is too large to store and query at prediction time
> 6. **High-dimensional inputs** — images, text, audio; instance-based methods degrade in high dimensions

### 5.2 When to Use Instance-Based Learning

> [!note] When to Use Instance-Based Learning
> 
> 1. **No strong prior on $f^*$** — you do not know the functional form; let the data speak locally
> 2. **Dataset is small** — KNN with small $n$ is computationally feasible and can outperform poorly specified models
> 3. **Distribution changes over time** — adding new examples is trivial; adapts without retraining
> 4. **Irregular decision boundaries** — true $f^*$ has complex, non-smooth structure that parametric models would need enormous capacity to capture
> 5. **Explainability by example** — "this patient was classified as high-risk because 4 of the 5 most similar past patients had the same outcome" is interpretable to clinicians
> 6. **Prototyping** — KNN is a fast, strong baseline before committing to a complex model

## 6. Advantages and Disadvantages

### 6.1 Model-Based Learning

**Advantages:**

|Advantage|Explanation|
|---|---|
|**$O(1)$ prediction**|Evaluate $h_{\theta^*}(x)$ in constant time — scales to billions of queries|
|**Fixed memory footprint**|Model size is independent of training set size|
|**Compact knowledge representation**|Parameters encode structured knowledge that can be inspected|
|**Generalises beyond training data**|Global function approximation extrapolates to unseen regions|
|**Well-understood theory**|PAC bounds, VC theory, bias-variance decomposition all apply|

**Disadvantages:**

|Disadvantage|Explanation|
|---|---|
|**Assumes a functional form**|If the chosen $\mathcal{H}$ is wrong, no amount of data corrects it|
|**Expensive to update**|New data requires retraining; online updates are limited|
|**Training can be slow**|Gradient descent on deep models can take days to weeks|
|**Extrapolation risk**|Global model may behave unpredictably far from training distribution|
|**Hyperparameter sensitivity**|Architecture, regularisation, learning rate all require careful tuning|

---

### 6.2 Instance-Based Learning

**Advantages:**

|Advantage|Explanation|
|---|---|
|**No training phase**|Immediately usable after storing data; no optimisation required|
|**No functional form assumption**|Makes no global claim about $f^*$; adapts to arbitrary complexity locally|
|**Naturally handles new data**|Appending examples costs $O(d)$ and takes effect immediately|
|**Interpretable by example**|Predictions are explained by pointing to the nearest neighbours|
|**Strong theoretical guarantees**|1-NN error $\leq 2 \times$ Bayes error as $n \to \infty$|

**Disadvantages:**

|Disadvantage|Explanation|
|---|---|
|**$O(nd)$ prediction cost**|Querying every training example is slow for large $n$|
|**Memory scales with data**|Must store all training examples; prohibitive at scale|
|**Curse of dimensionality**|Distance becomes meaningless in high dimensions; degrades rapidly|
|**Sensitive to irrelevant features**|All features contribute equally unless weighted; noise dominates|
|**Sensitive to scale**|Euclidean distance is affected by feature magnitude; normalisation mandatory|
|**No compact knowledge summary**|Cannot extract "what the model learned" as a set of rules or weights|

## 7. Code — Model-Based Learning

### 7.1 Linear Regression from Scratch

```python
import numpy as np

# ── Dataset: y = 3x₁ + 2x₂ - 1 + noise ──────────────────────────
np.random.seed(42)
n, d = 200, 2
X = np.random.randn(n, d)
y = 3*X[:,0] + 2*X[:,1] - 1 + 0.3*np.random.randn(n)

# ── Model-based: find θ* = [w, b] that minimise MSE ───────────────
# Training phase: compress all knowledge into θ* 
# Closed-form solution: θ* = (XᵀX)⁻¹ Xᵀy
X_aug = np.hstack([X, np.ones((n, 1))])       # augment with bias column
theta = np.linalg.lstsq(X_aug, y, rcond=None)[0]
w, b = theta[:d], theta[d]

print("=== Model-Based: Linear Regression ===")
print(f"Learned weights: w={w}, b={b:.3f}")
print(f"True weights:    w=[3, 2], b=-1.000")

# ── Prediction: O(d) — no reference to training data ──────────────
# Training data D is no longer needed after this point
del X, y                                      # simulate discarding training data

x_new = np.array([1.0, 0.5])
y_hat = w @ x_new + b
print(f"\nPrediction for x={x_new}: {y_hat:.3f}")
print(f"True value:               {3*1.0 + 2*0.5 - 1:.3f}")
print("(Training data was discarded — only θ* was used)")
```

### 7.2 Neural Network (model-based, sklearn)

```python
from sklearn.neural_network import MLPRegressor
from sklearn.preprocessing import StandardScaler
import numpy as np

np.random.seed(0)
X = np.random.randn(300, 2)
y = np.sin(X[:,0]) * np.cos(X[:,1])     # nonlinear target

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

# Training phase: gradient descent fits weights θ*
# After fit(), the raw training data is no longer needed
model = MLPRegressor(
    hidden_layer_sizes=(64, 64),
    activation='relu',
    max_iter=500,
    random_state=0
)
model.fit(X_scaled, y)

# Prediction: O(d) forward pass through θ* — no training data needed
x_new = np.array([[0.5, -0.3]])
x_new_scaled = scaler.transform(x_new)
print(f"Prediction: {model.predict(x_new_scaled)[0]:.4f}")
print(f"True value: {np.sin(0.5) * np.cos(-0.3):.4f}")
print(f"Model parameters stored: {sum(w.size for w in model.coefs_)} weights")
print(f"Training data stored:    0 examples (discarded after training)")
```

## 8. Code — Instance-Based Learning

### 8.1 KNN from Scratch — Full Implementation

```python
import numpy as np
from collections import Counter

class KNNClassifier:
    """
    Pure instance-based learner.
    Training = storing data.
    Prediction = distance computation + majority vote.
    """

    def __init__(self, k=3, distance='euclidean'):
        self.k = k
        self.distance = distance
        self.X_train = None
        self.y_train = None

    def fit(self, X, y):
        # "Training" is just storing the data — O(nd) memory, O(0) compute
        self.X_train = np.array(X)
        self.y_train = np.array(y)
        print(f"KNN fitted: storing {len(X)} examples. No optimisation done.")

    def _distance(self, x1, x2):
        if self.distance == 'euclidean':
            return np.sqrt(np.sum((x1 - x2) ** 2))
        elif self.distance == 'manhattan':
            return np.sum(np.abs(x1 - x2))

    def predict_one(self, x):
        # Compute distance from x to every stored training example — O(nd)
        distances = [self._distance(x, x_train) for x_train in self.X_train]

        # Find indices of k nearest neighbours
        k_indices = np.argsort(distances)[:self.k]

        # Majority vote among their labels
        k_labels = [self.y_train[i] for i in k_indices]
        most_common = Counter(k_labels).most_common(1)[0][0]
        return most_common

    def predict(self, X):
        return np.array([self.predict_one(x) for x in X])


# ── Demo ──────────────────────────────────────────────────────────
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=200, n_features=2, n_informative=2,
                            n_redundant=0, random_state=42)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)

knn = KNNClassifier(k=5)
knn.fit(X_train, y_train)          # just stores data

y_pred = knn.predict(X_test)
accuracy = np.mean(y_pred == y_test)
print(f"Test accuracy (k=5): {accuracy:.3f}")
```

### 8.2 Effect of k — Underfitting vs. Overfitting

```python
import numpy as np
import matplotlib
matplotlib.use('Agg')
from sklearn.neighbors import KNeighborsClassifier
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)

print(f"{'k':>4} | {'Train Acc':>10} | {'Test Acc':>9} | Behaviour")
print("-" * 50)

for k in [1, 3, 5, 11, 25, 50, 150]:
    knn = KNeighborsClassifier(n_neighbors=k)

        note = "← perfect train fit, overfitting"
    elif k >= 100:
        note = "← ignores local structure, underfitting"
    else:
        note = ""

    print(f"{k:>4} | {train_acc:>10.3f} | {test_acc:>9.3f} | {note}")
```

### 8.3 Feature Scaling — Why It's Mandatory

```python
import numpy as np
from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import StandardScaler
from sklearn.datasets import make_classification

# Dataset where feature 0 is in [0, 1] and feature 1 is in [0, 1000]
# Without scaling, Euclidean distance is dominated by feature 1
np.random.seed(7)
X, y = make_classification(n_samples=500, n_features=2, n_informative=2,
                            n_redundant=0, random_state=7)
X[:, 1] *= 1000     # artificially inflate feature 1's scale

from sklearn.model_selection import train_test_split
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)

# Without scaling
knn_raw = KNeighborsClassifier(n_neighbors=5)
knn_raw.fit(X_train, y_train)
acc_raw = knn_raw.score(X_test, y_test)

# With scaling
scaler = StandardScaler()
X_train_s = scaler.fit_transform(X_train)
X_test_s  = scaler.transform(X_test)

knn_scaled = KNeighborsClassifier(n_neighbors=5)
knn_scaled.fit(X_train_s, y_train_s := y_train)
acc_scaled = knn_scaled.score(X_test_s, y_test)

print(f"KNN without scaling: {acc_raw:.3f}")
print(f"KNN with scaling:    {acc_scaled:.3f}")
print("Scaling is mandatory for instance-based learning.")
```

### 8.4 Locally Weighted Regression (Instance-Based, Continuous)

A more powerful instance-based approach: instead of averaging the $k$ nearest neighbours, fit a **local linear model** around each query point, weighting training examples by their proximity.

```python
import numpy as np

def gaussian_kernel(distances, bandwidth=1.0):
    """Weight = exp(-d²/2h²) — nearby points get high weight."""
    return np.exp(- (distances ** 2) / (2 * bandwidth ** 2))

def locally_weighted_regression(x_query, X_train, y_train, bandwidth=0.5):
    """
    Fit a weighted linear model around x_query.
    Each training point's weight decays with distance from x_query.
    This is a pure instance-based method — no stored parameters.
    """
    # Compute distances from query to all training points
    distances = np.abs(X_train - x_query)        # 1D case for clarity

    # Compute weights: nearby points matter more
    weights = gaussian_kernel(distances, bandwidth)
    W = np.diag(weights)

    # Weighted least squares: θ = (XᵀWX)⁻¹ XᵀWy
    X_aug = np.column_stack([X_train, np.ones(len(X_train))])
    theta = np.linalg.lstsq(X_aug.T @ W @ X_aug,
                             X_aug.T @ W @ y_train,
                             rcond=None)[0]

    # Predict at query point using LOCAL model
    return np.array([x_query, 1]) @ theta


# ── Demo: fit a nonlinear function locally ────────────────────────
np.random.seed(5)
X_train = np.linspace(0, 2*np.pi, 100)
y_train = np.sin(X_train) + 0.1 * np.random.randn(100)

# Predict at several query points
query_points = [0.5, 1.5, 3.0, 5.0]
print(f"{'x_query':>10} | {'LWR prediction':>15} | {'True sin(x)':>12}")
print("-" * 42)
for xq in query_points:
    pred = locally_weighted_regression(xq, X_train, y_train, bandwidth=0.3)
    print(f"{xq:>10.2f} | {pred:>15.4f} | {np.sin(xq):>12.4f}")

print("\nKey: LWR builds a new local model for EVERY query point.")
print("No global parameters are stored — this is instance-based.")
```

## 9. Direct Comparison

|Dimension|Model-Based|Instance-Based|
|---|---|---|
|**Training cost**|High — optimise loss over $\mathcal{D}$|Zero — just store $\mathcal{D}$|
|**Prediction cost**|$O(d)$ — evaluate $h_{\theta^*}$|$O(nd)$ — compare to all stored examples|
|**Memory (inference)**|$O(\|\theta\|)$ — fixed, independent of $n$|$O(nd)$ — grows with dataset size|
|**Assumption about $f^*$**|Global functional form (linear, neural net, ...)|Local similarity — nearby points share labels|
|**Adapts to new data**|Requires retraining|Append example — immediate effect|
|**High dimensions**|Generally handles well (with right architecture)|Degrades badly — curse of dimensionality|
|**Small $n$**|Risks overfitting; needs regularisation|Often strong — no parametric restrictions|
|**Large $n$**|Scales well — model size is fixed|Slow prediction; storage becomes prohibitive|
|**Interpretability**|Global structure in $\theta^*$ (weights, rules)|By example — "these neighbours voted this way"|
|**Feature scaling needed**|Depends on algorithm|Always mandatory|
|**Offline / online**|Primarily offline|Naturally online — append and query|
|**Extrapolation**|Yes — global model extends to unseen regions|Poor — no training data nearby = no prediction basis|

## 10. Connections and What Comes Next

### Where This Fits in the Bigger Picture

This distinction cross-cuts the entire ML taxonomy from [[01. The Learning Problem]]:

- **Supervised learning** uses both: linear regression (model-based), KNN (instance-based)
- **Batch vs. online**: instance-based methods are naturally online; model-based methods are typically batch
- **Inductive bias**: model-based learners have explicit global inductive bias encoded in $\mathcal{H}$; instance-based learners have implicit local inductive bias encoded in the distance function

### The Bias-Variance Lens

From [[03. The Bias-Variance Tradeoff]]:

- Model-based with rigid $\mathcal{H}$ → **high bias, low variance** (e.g., linear regression on nonlinear data)
- Instance-based with $k=1$ → **low bias, high variance** (memorises every training point)
- Instance-based with large $k$ → **high bias, low variance** (smooths too aggressively)

### Hybrid Methods

Many modern algorithms blur the boundary:

|Algorithm|Why It's a Hybrid|
|---|---|
|**SVM**|Stores only support vectors (instance-like), but constructs a parametric decision boundary (model-like)|
|**Gaussian Processes**|Defines a prior over functions (model-like), but predictions are posterior means involving all training points (instance-like)|
|**Attention mechanisms**|Neural networks (model-based) but use a soft version of nearest-neighbour lookup (instance-based) at the attention layer|
|**Retrieval-Augmented Generation**|LLM (model-based) + document store (instance-based)|

> [!important] The Key Insight The model-based / instance-based distinction is not a binary label. It is a **spectrum of where and when the generalisation computation happens**: eagerly at training time, or lazily at prediction time. Understanding this spectrum tells you immediately what tradeoffs a system is making in memory, latency, adaptability, and complexity.

|Model-based learning|Fits a parameterised function $h_{\theta^*}$ to $\mathcal{D}$; discards raw data after training|
|Instance-based learning|Stores $\mathcal{D}$ and defers computation to prediction time; no upfront optimisation|
|Lazy learner|Synonym for instance-based; computation is deferred ("lazy") until query time|
|Eager learner|Synonym for model-based; computation is done upfront ("eager") during training|
|KNN|K-Nearest Neighbours; predicts by majority vote / mean of $k$ closest training points|
|Locally weighted regression|Instance-based: fits a local linear model around each query, weighted by proximity|
|Curse of dimensionality|In high $d$, distances concentrate; nearest neighbours are no longer meaningfully "near"|
|Support vectors|Subset of training instances retained by SVM; the hybrid between paradigms|
