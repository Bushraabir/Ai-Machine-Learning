## The Pipeline at a Glance

```
┌──────────────────────────────────────────────────────────────┐
│                   THE ML PIPELINE                            │
│                                                              │
│  1. Frame the problem          → define T, E, P              │
│         │                                                    │
│  2. Collect data               → raw inputs + labels         │
│         │                                                    │
│  3. Exploratory data analysis  → understand distributions    │
│         │                                                    │
│  4. Preprocessing              → clean, encode, split        │
│         │                                                    │
│  5. Feature engineering        → create informative inputs   │
│         │                                                    │
│  6. Model selection + training → choose H, find θ*           │
│         │                                                    │
│  7. Evaluation + error analysis → measure P on test set      │
│         │                                                    │
│  8. Deployment + monitoring    → serve, watch, retrain       │
│         │                                                    │
│         └──────────────────────────────────↩ iterate        │
└──────────────────────────────────────────────────────────────┘
```

> [!important] The Pipeline Is Not Linear You will loop. EDA reveals preprocessing problems. Error analysis reveals missing features. Deployment reveals distribution shift that requires new data. The pipeline is a spiral, not a waterfall — each pass tightens the solution.

## Step 1 — Frame the Problem

### Why This Step Exists

The most expensive ML mistake is building the right model for the wrong problem. Framing forces precision before any code is written.

### The T-E-P Triple

Every ML problem must be specified as:

|Component|Question to answer|Example|
|---|---|---|
|**Task T**|What is the system trying to do?|Predict whether a loan will default|
|**Experience E**|What data is available?|5 years of loan applications + repayment outcomes|
|**Performance P**|How will success be measured?|F1 score on held-out test set, minimising false negatives|

### Questions to Answer Before Writing Code

- Is this supervised, unsupervised, or reinforcement learning?
- Is the output continuous (regression), discrete (classification), or structured?
- What is the cost of each type of error? (False positive vs false negative)
- What is an acceptable baseline? (Random classifier? Human expert? Existing heuristic?)
- What latency and throughput constraints exist at deployment?
- Is the training distribution likely to match the deployment distribution?
- Are there legal or ethical constraints on the data or the decisions?

### Output

A written problem statement in the form:

```
Task:        Binary classification — predict loan default (yes/no)
Experience:  540,000 historical loan records with payment outcomes
Performance: Maximise recall (minimise false negatives) at ≥ 80% precision
Baseline:    Bank's current rule-based system: 72% recall, 75% precision
Constraint:  Prediction must be available within 100ms of application submission
```

## Step 2 — Collect and Store Data

### What Happens Here

Data must be gathered, validated, and stored in a form accessible to the training pipeline. This step is almost always underestimated.

### Sources of Data

|Source Type|Examples|Notes|
|---|---|---|
|**Internal databases**|Transaction logs, CRM records, sensor streams|Usually the cleanest; access controlled|
|**Public datasets**|UCI ML repository, Kaggle, government open data|Inspect licences carefully|
|**APIs**|Twitter/X, weather services, financial data|Rate limits; snapshot vs stream|
|**Web scraping**|Product reviews, news articles|Legal review required; HTML parsing is brittle|
|**Human annotation**|Labelling services, Mechanical Turk|Expensive; manage inter-annotator agreement|
|**Synthetic data**|GANs, simulators, rule-based generators|Useful for rare events or privacy-sensitive data|

### Data Documentation Checklist

```
[ ] Source and collection date recorded
[ ] Licence and usage rights confirmed
[ ] PII / sensitive data identified and handled per policy
[ ] Label provenance documented (who labelled? when? using what schema?)
[ ] Known biases or gaps in coverage documented
[ ] Data stored in versioned, reproducible form
```

### Storage Formats

|Format|Use Case|
|---|---|
|CSV / Parquet|Tabular data; Parquet is columnar and faster for large datasets|
|HDF5 / NumPy `.npy`|Numerical arrays, matrix data|
|TFRecord / WebDataset|Large-scale streaming for deep learning training|
|SQL database|Structured data with query needs|
|Object store (S3, GCS)|Raw files, images, audio, large-scale archives|

## Step 3 — Exploratory Data Analysis (EDA)

### Purpose

EDA answers: _what does the data actually look like?_ It drives every downstream decision about preprocessing, feature engineering, and model choice. Skipping EDA is the second most common source of wasted effort.

### What to Investigate

**Univariate analysis** — one variable at a time:

- Distributions of numerical features (histogram, box plot)
- Value counts for categorical features
- Missing value rates per feature
- Outlier detection

**Bivariate analysis** — feature vs target:

- Correlation of each numerical feature with the target
- Target rates by category level
- Scatter plots for continuous feature pairs

**Data quality checks:**

- Duplicate records
- Impossible values (negative ages, future dates)
- Target leakage (features that directly encode the label)
- Class imbalance

```python
import pandas as pd
import numpy as np

def eda_report(df: pd.DataFrame, target: str) -> None:
    """Run a structured EDA report on a dataframe."""
    n, d = df.shape
    print(f"{'='*50}")
    print(f"DATASET: {n:,} rows x {d} columns")
    print(f"{'='*50}\n")

    # ── Target distribution ────────────────────────────────────────
    print("TARGET DISTRIBUTION")
    vc = df[target].value_counts(normalize=True)
    for val, pct in vc.items():
        bar = '█' * int(pct * 30)
        print(f"  {val}: {pct:.1%}  {bar}")

    # ── Missing values ─────────────────────────────────────────────
    missing = df.isnull().mean().sort_values(ascending=False)
    missing = missing[missing > 0]
    if len(missing):
        print(f"\nMISSING VALUES ({len(missing)} features affected)")
        for col, pct in missing.items():
            print(f"  {col:<30} {pct:.1%}")
    else:
        print("\nMISSING VALUES: none")

    # ── Numerical feature summary ──────────────────────────────────
    num_cols = df.select_dtypes(include=np.number).columns.drop(target, errors='ignore')
    if len(num_cols):
        print(f"\nNUMERICAL FEATURES ({len(num_cols)})")
        stats = df[num_cols].describe().T[['mean','std','min','max']]
        print(stats.round(2).to_string())

    # ── Correlation with target ────────────────────────────────────
    if df[target].dtype in [np.float64, np.int64]:
        print(f"\nCORRELATION WITH TARGET")
        corr = df[num_cols].corrwith(df[target]).abs().sort_values(ascending=False)
        for col, r in corr.head(10).items():
            bar = '█' * int(r * 20)
            print(f"  {col:<30} {r:.3f}  {bar}")

    # ── Categorical features ───────────────────────────────────────
    cat_cols = df.select_dtypes(include='object').columns
    if len(cat_cols):
        print(f"\nCATEGORICAL FEATURES ({len(cat_cols)})")
        for col in cat_cols:
            n_unique = df[col].nunique()
            top = df[col].value_counts().index[0]
            print(f"  {col:<30} {n_unique} unique  (top: {top})")

    print(f"\n{'='*50}")
```

## Step 4 — Data Preprocessing

### Purpose

Raw data is never model-ready. Preprocessing transforms it into a numerical matrix $X \in \mathbb{R}^{n \times d}$ and label vector $y \in \mathbb{R}^n$ (or ${0,1,\ldots,k}^n$) that a model can consume.

### The Train/Validation/Test Split

> [!warning] Do This First Split the data before any preprocessing. Fitting scalers, imputers, or encoders on the full dataset leaks test information into training — a subtle but serious form of data leakage that inflates evaluation metrics.

```
Full dataset (n examples)
        │
        ├── Train set (70–80%)     ← fit everything here
        ├── Validation set (10–15%) ← hyperparameter tuning
        └── Test set (10–20%)      ← touched ONCE at the very end
```

Use **stratified splitting** for classification to preserve class proportions in each split.

### Preprocessing Operations

|Operation|When|How|
|---|---|---|
|**Missing value imputation**|Any NaN present|Mean/median/mode; KNN imputation; model-based|
|**Outlier handling**|Numerical features with extreme values|Cap (Winsorise), remove, or use robust models|
|**Feature scaling**|Linear models, KNN, neural nets, SVM|StandardScaler (zero mean, unit variance) or MinMaxScaler|
|**Categorical encoding**|Any string/categorical feature|One-hot (low cardinality), ordinal, target encoding|
|**Duplicate removal**|Exact or near-duplicate rows|`df.drop_duplicates()`|
|**Type casting**|Wrong dtypes (e.g. numeric stored as string)|`df.astype()`|

> [!note] Tree Models Don't Need Scaling Decision trees, random forests, and gradient boosted trees split on feature thresholds — they are invariant to monotonic transformations. Scaling is mandatory for linear models, KNN, SVMs, and neural networks.

```python
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline

def build_preprocessor(num_features: list, cat_features: list):
    """
    Construct a sklearn ColumnTransformer that handles:
    - Numerical: impute median → standard scale
    - Categorical: impute mode → one-hot encode
    All steps are fit on training data only.
    """
    num_pipe = Pipeline([
        ('impute', SimpleImputer(strategy='median')),
        ('scale',  StandardScaler())
    ])

    cat_pipe = Pipeline([
        ('impute',  SimpleImputer(strategy='most_frequent')),
        ('encode',  OneHotEncoder(handle_unknown='ignore', sparse_output=False))
    ])

    preprocessor = ColumnTransformer([
        ('num', num_pipe, num_features),
        ('cat', cat_pipe, cat_features),
    ])

    return preprocessor
```

## Step 5 — Feature Engineering

### Purpose

Feature engineering transforms raw variables into representations that make the underlying structure of $f^*$ easier for the model to learn. It is the highest-leverage activity in most classical ML projects.

> [!important] The Core Principle A model can only learn what is present in its inputs. If the relevant signal is hidden in a combination of features, the model must discover that combination — which requires more data and capacity. Exposing the combination directly saves both.

### Techniques

|Technique|Example|
|---|---|
|**Mathematical transforms**|`log(income)` for right-skewed income data|
|**Interaction features**|`age × income` if the combined effect matters|
|**Ratio features**|`debt / income` (debt-to-income ratio) is more predictive than debt alone|
|**Temporal features**|Extract `hour_of_day`, `day_of_week`, `is_weekend` from a timestamp|
|**Aggregation features**|`customer_avg_transaction_last_30d`, `max_purchase_last_week`|
|**Text features**|TF-IDF, word embeddings, sentence embeddings|
|**Binning**|Convert continuous age into age brackets when the effect is non-monotonic|
|**Target encoding**|Replace category level with average target value for that level|

### Feature Selection

After creation, remove features that add noise rather than signal:

```python
from sklearn.feature_selection import SelectKBest, mutual_info_classif
from sklearn.linear_model import LassoCV
import numpy as np

def select_features_mi(X_train, y_train, k=20):
    """Select top-k features by mutual information with target."""
    selector = SelectKBest(mutual_info_classif, k=k)
    selector.fit(X_train, y_train)
    selected_idx = selector.get_support(indices=True)
    scores = selector.scores_
    print("Top features by mutual information:")
    ranked = np.argsort(scores)[::-1][:k]
    for rank, idx in enumerate(ranked):
        print(f"  {rank+1:2d}. Feature {idx:3d}: MI = {scores[idx]:.4f}")
    return selected_idx

def select_features_lasso(X_train, y_train):
    """L1 regularisation shrinks irrelevant feature weights to zero."""
    lasso = LassoCV(cv=5, random_state=42).fit(X_train, y_train)
    nonzero = np.where(lasso.coef_ != 0)[0]
    print(f"LASSO kept {len(nonzero)}/{X_train.shape[1]} features")
    return nonzero
```

## Step 6 — Model Selection and Training

### The Model Selection Decision

Choosing a hypothesis class $\mathcal{H}$ is the core architectural decision. It encodes your belief about the structure of $f^*$.

**Start simple. Always.**

```
Simple baseline first:
    Linear / logistic regression → decision tree → random forest →
    gradient boosting → neural network

Stop when the gain from complexity no longer justifies the cost.
```

### The Bias-Variance Lens for Model Selection

|Model|Bias|Variance|When to Use|
|---|---|---|---|
|Linear regression|High|Low|Data is genuinely linear; large $n$|
|Decision tree (deep)|Low|High|Non-linear, interpretable; small $n$ with caution|
|Random forest|Low-Medium|Low-Medium|General purpose; robust default|
|Gradient boosting|Low|Low-Medium|Tabular data; state-of-the-art baseline|
|Neural network|Low|Low (with regularisation)|Images, text, audio; large $n$; high compute|
|KNN|Low|High|Irregular boundaries; small $n$; non-parametric|

### The Training Loop

```python
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.model_selection import cross_val_score, GridSearchCV
from sklearn.metrics import classification_report
import numpy as np

def train_and_validate(X_train, y_train, X_val, y_val):
    """Train with cross-validation and hyperparameter tuning."""

    # ── Step 1: Baseline ───────────────────────────────────────────
    from sklearn.dummy import DummyClassifier
    baseline = DummyClassifier(strategy='most_frequent')
    baseline.fit(X_train, y_train)
    base_score = baseline.score(X_val, y_val)
    print(f"Baseline accuracy (most frequent class): {base_score:.3f}")

    # ── Step 2: Logistic regression ────────────────────────────────
    from sklearn.linear_model import LogisticRegression
    lr = LogisticRegression(max_iter=1000, random_state=42)
    lr_cv = cross_val_score(lr, X_train, y_train, cv=5, scoring='f1').mean()
    print(f"Logistic regression CV F1:               {lr_cv:.3f}")

    # ── Step 3: Gradient boosting with hyperparam search ──────────
    param_grid = {
        'n_estimators': [100, 200],
        'max_depth':    [3, 5],
        'learning_rate':[0.05, 0.1],
    }
    gb = GradientBoostingClassifier(random_state=42)
    search = GridSearchCV(gb, param_grid, cv=5, scoring='f1', n_jobs=-1)
    search.fit(X_train, y_train)

    best = search.best_estimator_
    val_score = best.score(X_val, y_val)
    print(f"Gradient boosting best CV F1:            {search.best_score_:.3f}")
    print(f"Gradient boosting val accuracy:          {val_score:.3f}")
    print(f"Best params: {search.best_params_}")

    return best
```

## Step 7 — Evaluation and Error Analysis

### The Test Set Rule

> [!warning] The Test Set Is Sacred The test set is touched exactly **once** — after all modelling decisions are finalised. Using the test set to select hyperparameters or compare models is data leakage. The test set exists to estimate how the model will perform on data it has never influenced.

### Evaluation Metrics by Task

|Task|Primary Metric|When to Use Alternative|
|---|---|---|
|Binary classification|Accuracy|Imbalanced classes → use F1, AUC-ROC, precision-recall|
|Multi-class|Macro F1|Imbalanced → weighted F1|
|Regression|RMSE|Outliers dominate → use MAE; percentage errors → MAPE|
|Ranking|NDCG, MAP|Recommendation, search|
|Probability calibration|Brier score, reliability diagram|When probability estimates matter (risk scoring)|

### Error Analysis

The aggregate metric is just the start. Error analysis asks: _which examples does the model get wrong, and why?_

```python
from sklearn.metrics import (classification_report, confusion_matrix,
                              roc_auc_score, ConfusionMatrixDisplay)
import numpy as np
import pandas as pd

def full_evaluation(model, X_test, y_test, feature_names=None):
    """Comprehensive model evaluation with error analysis."""

    y_pred = model.predict(X_test)
    y_prob = model.predict_proba(X_test)[:, 1] if hasattr(model, 'predict_proba') else None

    print("="*52)
    print("MODEL EVALUATION REPORT")
    print("="*52)

    # ── Classification metrics ─────────────────────────────────────
    print(classification_report(y_test, y_pred))

    if y_prob is not None:
        auc = roc_auc_score(y_test, y_prob)
        print(f"AUC-ROC: {auc:.4f}")

    # ── Confusion matrix ───────────────────────────────────────────
    cm = confusion_matrix(y_test, y_pred)
    tn, fp, fn, tp = cm.ravel()
    print(f"\nConfusion matrix:")
    print(f"  True Positives:  {tp:5d}  (correctly flagged)")
    print(f"  True Negatives:  {tn:5d}  (correctly cleared)")
    print(f"  False Positives: {fp:5d}  (false alarms)")
    print(f"  False Negatives: {fn:5d}  (missed — often the costly error)")

    # ── Error analysis: inspect false negatives ────────────────────
    false_neg_idx = np.where((y_pred == 0) & (y_test == 1))[0]
    false_pos_idx = np.where((y_pred == 1) & (y_test == 0))[0]
    print(f"\nError analysis:")
    print(f"  {len(false_neg_idx)} false negatives — inspect these cases")
    print(f"  {len(false_pos_idx)} false positives — inspect these cases")

    # ── Feature importance (if available) ─────────────────────────
    if hasattr(model, 'feature_importances_') and feature_names is not None:
        importances = model.feature_importances_
        ranked = np.argsort(importances)[::-1][:10]
        print(f"\nTop 10 features by importance:")
        for i, idx in enumerate(ranked):
            bar = '█' * int(importances[idx] * 50)
            print(f"  {i+1:2d}. {feature_names[idx]:<30} {importances[idx]:.4f}  {bar}")

    print("="*52)
```

## Step 8 — Deployment and Monitoring

### The Gap Between Research and Production

Training a model that works on your laptop is the beginning, not the end. Production requires:

- **Serving infrastructure:** an API that accepts requests and returns predictions
- **Reproducibility:** the exact same model, dependencies, and preprocessing must run in production
- **Latency:** the model must respond within acceptable time constraints
- **Monitoring:** catch silent failures — performance degradation, input drift, prediction drift
- **Retraining pipeline:** a mechanism to retrain and redeploy when drift is detected

### Deployment Checklist

```
[ ] Model serialised (joblib, pickle, ONNX, TorchScript)
[ ] Preprocessing pipeline bundled with model (not separate)
[ ] Docker container with pinned dependencies
[ ] Input validation on API (type checks, range checks)
[ ] Output validation (predictions in expected range)
[ ] Logging: log inputs + predictions + latency for every request
[ ] Monitoring: data drift, prediction drift, downstream metrics
[ ] Rollback: previous model version can be restored in < 5 minutes
[ ] A/B test: gradual traffic ramp before full cutover
```

### Minimal Serving Example

```python
# serve.py — minimal FastAPI serving script
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import joblib
import numpy as np
import logging
from datetime import datetime

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

app = FastAPI(title="ML Model API")

# Load model + preprocessor once at startup
model        = joblib.load("artifacts/model.pkl")
preprocessor = joblib.load("artifacts/preprocessor.pkl")

class PredictRequest(BaseModel):
    features: list[float]

class PredictResponse(BaseModel):
    prediction: int
    probability: float
    model_version: str

MODEL_VERSION = "1.2.0"

@app.post("/predict", response_model=PredictResponse)
def predict(request: PredictRequest):
    try:
        X = np.array(request.features).reshape(1, -1)
        X_processed = preprocessor.transform(X)
        pred = int(model.predict(X_processed)[0])
        prob = float(model.predict_proba(X_processed)[0, pred])

        # Log for monitoring
        logger.info(f"prediction={pred} prob={prob:.4f} ts={datetime.utcnow().isoformat()}")

        return PredictResponse(
            prediction=pred,
            probability=prob,
            model_version=MODEL_VERSION
        )
    except Exception as e:
        logger.error(f"Prediction failed: {e}")
        raise HTTPException(status_code=500, detail=str(e))

@app.get("/health")
def health():
    return {"status": "ok", "model_version": MODEL_VERSION}

# Run: uvicorn serve:app --host 0.0.0.0 --port 8000
```

### Monitoring — Detecting Concept Drift

```python
import numpy as np
from scipy.stats import ks_2samp

class ProductionMonitor:
    """
    Track feature distributions and prediction distributions.
    Alert when they diverge from the training reference.
    """

    def __init__(self, reference_X, reference_preds, threshold=0.05):
        self.reference_X     = reference_X
        self.reference_preds = reference_preds
        self.threshold       = threshold    # p-value threshold for KS test
        self.window          = []
        self.pred_window     = []

    def log(self, X_batch, preds_batch):
        """Add a batch of live predictions to the monitoring window."""
        self.window.extend(X_batch.tolist())
        self.pred_window.extend(preds_batch.tolist())

    def check_drift(self):
        """Run KS test on each feature and on predictions."""
        if len(self.window) < 50:
            print("Not enough data yet for drift detection.")
            return

        live_X = np.array(self.window)
        alerts = []

        for feature_idx in range(live_X.shape[1]):
            ref  = self.reference_X[:, feature_idx]
            live = live_X[:, feature_idx]
            stat, p_value = ks_2samp(ref, live)
            if p_value < self.threshold:
                alerts.append(f"Feature {feature_idx}: KS p={p_value:.4f} [DRIFT]")

        # Check prediction distribution
        _, p_pred = ks_2samp(self.reference_preds, self.pred_window)
        if p_pred < self.threshold:
            alerts.append(f"Predictions: KS p={p_pred:.4f} [DRIFT]")

        if alerts:
            print("DRIFT ALERTS — consider retraining:")
            for a in alerts:
                print(f"  {a}")
        else:
            print("No significant drift detected.")
```

## The Iteration Loop

The pipeline is a loop, not a sequence. After deployment, new information flows backward:

```
Deployment reveals:
  → Input distribution has shifted    → collect new data (Step 2)
  → Model makes systematic errors     → revisit feature engineering (Step 5)
  → Business metric disagrees with ML metric → reframe the problem (Step 1)
  → New data source available         → expand preprocessing (Step 4)
  → Model too slow for production     → choose simpler H (Step 6)
```

The rate of iteration — how quickly you can go from "model is underperforming" to "new model deployed" — is often the most important factor in the long-run success of an ML system.

```python
print("Task: binary classification | Metric: AUC-ROC")
print("="*52)


# ══════════════════════════════════════════════════════════════════
# STEP 2 — Data collection (simulated)
# ══════════════════════════════════════════════════════════════════

X, y = make_classification(
    n_samples=1000, n_features=20, n_informative=5,
    n_redundant=3, flip_y=0.05,      # 5% label noise
    random_state=RANDOM_STATE
)
feature_names = [f"feature_{i}" for i in range(X.shape[1])]

# Inject some missing values (realistic)
mask = np.random.rand(*X.shape) < 0.05
X[mask] = np.nan

print(f"\nSTEP 2: Data collected — {X.shape[0]} examples, {X.shape[1]} features")
print(f"Missing values: {np.isnan(X).sum()} ({np.isnan(X).mean():.1%})")


# ══════════════════════════════════════════════════════════════════
# STEP 3 — EDA (abbreviated)
# ══════════════════════════════════════════════════════════════════

print(f"\nSTEP 3: EDA")
print(f"Class distribution: {np.bincount(y)} ({np.bincount(y)/len(y)*100}%)")
print(f"Feature range (non-null): [{np.nanmin(X):.2f}, {np.nanmax(X):.2f}]")


# ══════════════════════════════════════════════════════════════════
# STEP 4 — Preprocessing + Split
# CRITICAL: split before fitting any preprocessor
# ══════════════════════════════════════════════════════════════════

X_trainval, X_test, y_trainval, y_test = train_test_split(
    X, y, test_size=0.15, stratify=y, random_state=RANDOM_STATE)
X_train, X_val, y_train, y_val = train_test_split(
    X_trainval, y_trainval, test_size=0.15, stratify=y_trainval, random_state=RANDOM_STATE)

print(f"\nSTEP 4: Split — train={len(X_train)}, val={len(X_val)}, test={len(X_test)}")


# ══════════════════════════════════════════════════════════════════
# STEP 5 — Feature engineering + selection
# ══════════════════════════════════════════════════════════════════

# Impute for MI calculation (MI cannot handle NaN)
imputer_temp = SimpleImputer(strategy='median')
X_train_imp = imputer_temp.fit_transform(X_train)
mi_scores = mutual_info_classif(X_train_imp, y_train, random_state=RANDOM_STATE)
top_features = np.argsort(mi_scores)[::-1][:10]    # keep top 10

print(f"\nSTEP 5: Selected top 10 features by mutual information")
print(f"Top 3 MI scores: {mi_scores[top_features[:3]].round(4)}")


# ══════════════════════════════════════════════════════════════════
# STEP 6 — Model selection + training
# ══════════════════════════════════════════════════════════════════

print(f"\nSTEP 6: Model training")

# Build full pipeline (preprocessing + model)
def make_pipeline(classifier):
    return Pipeline([
        ('impute', SimpleImputer(strategy='median')),
        ('scale',  StandardScaler()),
        ('model',  classifier)
    ])

models = {
    'Logistic regression':  LogisticRegression(max_iter=500, random_state=RANDOM_STATE),
    'Gradient boosting':    GradientBoostingClassifier(n_estimators=100, random_state=RANDOM_STATE),
}

best_name, best_pipe, best_cv = None, None, 0.0

for name, clf in models.items():
    pipe = make_pipeline(clf)
    cv_auc = cross_val_score(pipe, X_train, y_train, cv=5, scoring='roc_auc').mean()
    pipe.fit(X_train, y_train)
    val_auc = roc_auc_score(y_val, pipe.predict_proba(X_val)[:, 1])
    print(f"  {name:<25} CV AUC={cv_auc:.3f}  Val AUC={val_auc:.3f}")
    if cv_auc > best_cv:
        best_cv, best_name, best_pipe = cv_auc, name, pipe

print(f"\nSelected: {best_name}")


# ══════════════════════════════════════════════════════════════════
# STEP 7 — Evaluation (test set touched once, here, at the end)
# ══════════════════════════════════════════════════════════════════

print(f"\nSTEP 7: Final evaluation on test set")
y_pred = best_pipe.predict(X_test)
y_prob = best_pipe.predict_proba(X_test)[:, 1]
test_auc = roc_auc_score(y_test, y_prob)
print(classification_report(y_test, y_pred))
print(f"Test AUC-ROC: {test_auc:.4f}")
```
