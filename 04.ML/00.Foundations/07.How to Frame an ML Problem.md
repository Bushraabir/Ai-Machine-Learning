## 1. What Is Problem Framing?

Framing is the act of converting a vague business or research goal into a mathematically precise learning problem. It is **Step 1** of the ML pipeline (→ [[04. Steps of Machine Learning]]) and the most consequential step of all.

Every downstream decision — what data to collect, which model to use, how to evaluate, when to stop — flows directly from the frame. A wrong frame means you build something that works perfectly and solves the wrong thing.

> [!important] The Core Rule Do not write a single line of modelling code until the T-E-P triple is written down and agreed upon. Framing is a document, not a thought.

---

## 2. The T-E-P Triple

From [[01. The Learning Problem]], every ML problem is a triple $(T, E, P)$:

|Component|Question|Must Answer|
|---|---|---|
|**Task $T$**|What prediction or decision does the system produce?|Define the output space $\mathcal{Y}$ precisely|
|**Experience $E$**|What data is available, in what form, at what volume?|Source, size, label availability, quality|
|**Performance $P$**|What metric determines whether the system is working?|Specific function, threshold, evaluation protocol|

**Vague vs. well-posed:**

|Vague|Well-posed|
|---|---|
|"Predict customer churn"|Binary classifier: predict churn within 30 days; F1 ≥ 0.70 on held-out test set|
|"Build a recommendation system"|Rank top-10 products per user session; Precision@10 ≥ 0.35|
|"Detect anomalies in sensor data"|Flag readings > 4σ from rolling 24h baseline; Recall ≥ 0.90, FPR ≤ 0.01|

## 3. Output Type — The First Decision

The output type determines the model family, the loss function, and the metric — before any data is examined.

|Output|Formal space|Model family|Example|
|---|---|---|---|
|Binary class|$\mathcal{Y} = {0,1}$|Logistic regression, SVM, tree|Fraud: yes/no|
|Multi-class|$\mathcal{Y} = {1,\ldots,k}$|Softmax classifier|Digit: 0–9|
|Continuous value|$\mathcal{Y} = \mathbb{R}$|Linear regression, neural net|House price|
|Probability score|$\mathcal{Y} = [0,1]$|Calibrated classifier|Default risk|
|Ranked list|$\mathcal{Y} = $ permutation|Learning-to-rank|Search results|
|Sequence|$\mathcal{Y} = \mathcal{V}^*$|Seq2seq, transformer|Translation|
|Cluster label|$\mathcal{Y} = {1,\ldots,k}$ (unordered)|K-means, DBSCAN|Customer segments|

Getting this wrong means mismatching a loss function to the actual goal — one of the most common and expensive framing mistakes.

## 4. Choosing the Right Metric P

The metric is not the output type. It is the specific function used to measure how well predictions match reality. It must reflect the **real cost of errors** in the deployment context.

### For Classification

|Situation|Metric|Reason|
|---|---|---|
|Balanced classes|Accuracy|Reliable when class sizes are equal|
|Imbalanced classes|F1, AUC-ROC|Accuracy is deceptive — predicting majority class looks "good"|
|False negatives costly|Recall (sensitivity)|Minimise missed positives (disease, fraud, safety)|
|False positives costly|Precision|Minimise wrong positives (spam filter, surgical intervention)|
|Asymmetric costs|$F_\beta$ score|$\beta > 1$ weights recall; $\beta < 1$ weights precision|
|Threshold-free evaluation|AUC-ROC|Measures ranking quality across all decision thresholds|

### For Regression

|Situation|Metric|Reason|
|---|---|---|
|Large errors are disproportionately bad|RMSE|Squares errors — amplifies outliers|
|All errors equally bad|MAE|Linear — treats all errors the same|
|Percentage errors matter|MAPE|Relative to the true value|

### Metric / Output Compatibility

> [!warning] Hard Rule — Metric Must Match Output Type
> 
> ```
> Classification outputs → F1, AUC-ROC, Accuracy, Precision, Recall
> Regression outputs     → RMSE, MAE, MAPE, R²
> Clustering outputs     → Silhouette, Davies-Bouldin (no labels needed)
> Sequence outputs       → BLEU, ROUGE, perplexity
> ```
> 
> Using RMSE on a binary output or F1 on a continuous output is a formal error in framing.

### The $F_\beta$ Score

When false negatives and false positives have different costs, use $F_\beta$:

$$F_\beta = (1 + \beta^2) \cdot \frac{\text{precision} \cdot \text{recall}}{\beta^2 \cdot \text{precision} + \text{recall}}$$

- $\beta = 1$: equal weight to precision and recall (standard F1)
- $\beta = 2$: recall twice as important (medical screening)
- $\beta = 0.5$: precision twice as important (spam filtering)

```python
from sklearn.metrics import fbeta_score

# Medical screening: false negatives are twice as costly
# → weight recall more heavily → β = 2
score = fbeta_score(y_true, y_pred, beta=2)
print(f"F2 score: {score:.4f}")

# Spam filter: false positives (blocking real email) are costly
# → weight precision more heavily → β = 0.5
score = fbeta_score(y_true, y_pred, beta=0.5)
print(f"F0.5 score: {score:.4f}")
```

## 5. The Baseline — The Most Overlooked Element

Before training any model, define what "beating" looks like. Three levels:

**Level 1 — Naive baseline.** A classifier that always predicts the majority class, or a regressor that always predicts the mean. If your model doesn't beat this, nothing has been learned — regardless of what the training loss says.

**Level 2 — Existing system.** If a rule-based system or human expert currently handles the task, measure their performance on the same metric. This is the actual bar your model must clear to be worth deploying.

**Level 3 — Simple ML model.** Logistic regression or a single decision tree trained in minutes. If a complex model doesn't clearly outperform this, the added complexity is not justified.

```python
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import f1_score

def compute_baselines(X_train, X_test, y_train, y_test):
    """
    Always run this before building any real model.
    These are the numbers every model must beat.
    """
    results = {}

    # Level 1a: always predict majority class
    d1 = DummyClassifier(strategy='most_frequent').fit(X_train, y_train)
    results['Majority class'] = f1_score(y_test, d1.predict(X_test), average='macro')

    # Level 1b: random prediction (stratified)
    d2 = DummyClassifier(strategy='stratified', random_state=42).fit(X_train, y_train)
    results['Random stratified'] = f1_score(y_test, d2.predict(X_test), average='macro')

    # Level 3: logistic regression (2-minute model)
    lr = Pipeline([
        ('scale', StandardScaler()),
        ('clf',   LogisticRegression(max_iter=500, random_state=42))
    ]).fit(X_train, y_train)
    results['Logistic regression'] = f1_score(y_test, lr.predict(X_test), average='macro')

    print("Baselines — every model must beat the LR baseline:")
    for name, score in results.items():
        bar = '█' * int(score * 40)
        print(f"  {name:<25} {score:.4f}  {bar}")

    return results, lr   # return LR as the starting model
```

## 6. The Six Framing Questions

Answer all six before writing modelling code. If you cannot answer any one, stop and find the answer first.

### Q1 — What exactly is one prediction?

Define the unit of prediction at the finest granularity. Not "predict fraud" but:

> "Given a single credit card transaction characterised by merchant category, amount, timestamp, and cardholder history, predict whether the transaction is fraudulent (1) or legitimate (0)."

Ambiguities to resolve: per-transaction or per-user? Per-day or per-session? Point-in-time or rolling?

### Q2 — What does deployment look like?

- Synchronous API or batch scoring?
- Latency budget? (< 50ms rules out many deep learning architectures)
- Will the input distribution at deployment match training? If not, what will differ?
- What hardware is available at inference?

Deployment constraints can eliminate entire model families before you look at data.

### Q3 — What is the cost of each error type?

False positives and false negatives have different real-world consequences:

|Domain|False Positive|False Negative|Implication|
|---|---|---|---|
|Cancer screening|Unnecessary follow-up test (anxiety, cost)|Missed cancer (life)|Recall >> Precision|
|Spam filter|Legitimate email blocked|Spam delivered (annoyance)|Precision >> Recall|
|Autonomous vehicle|Unnecessary braking (minor)|Missed obstacle (collision)|Recall >> Precision|
|Loan approval|Rejected creditworthy applicant|Approved defaulting applicant|Context-dependent|

If the costs are asymmetric, a single accuracy score hides the failure mode that matters.

### Q4 — Is ML the right tool?

ML is not always the answer. Apply this decision tree:

```
Are the rules simple and known?
    YES → write rules, not ML
    NO  ↓
Is the dataset too small to generalise? (< ~100 labelled examples)
    YES → gather more data first; use heuristics meanwhile
    NO  ↓
Would a simple model (LR, decision tree) be sufficient?
    YES → use it; complexity is a cost
    NO  ↓
→ proceed with ML
```

ML adds value when the rules are unknown, complex, or too numerous to write by hand — and when sufficient data exists to learn them.

### Q5 — What is minimum viable performance?

Define the threshold above which the model is useful:

> "The model must achieve Recall ≥ 0.85 at Precision ≥ 0.50. Below this, the existing rule-based system is preferable."

This prevents endless iteration chasing marginal improvements when the model is already good enough — and prevents deployment of a model that is not good enough.

### Q6 — How will you know if the model is wrong in production?

Ground truth often arrives late (loan default takes months) or never. Plan for:

- Input drift detection: are incoming features shifting away from training distribution?
- Prediction drift detection: is the model's output distribution changing?
- Delayed ground truth: when and how will actual outcomes arrive?
- Performance re-estimation: how will you estimate true performance when labels are delayed?

If you cannot answer this, you cannot safely deploy.

## 7. Is ML the Right Tool?

Before committing to ML, rule out simpler alternatives:

|Situation|Better approach|
|---|---|
|Rules are simple and explicit|Hand-coded rules|
|< 100 labelled examples|Collect more data; heuristics|
|Output is deterministic|Exact algorithm (sorting, search)|
|The relationship is linear and known|Analytical formula|
|Interpretability is legally required|Linear model or decision tree|
|Real-time constraints are extremely tight|Lookup table or precomputed scores|

ML introduces complexity, uncertainty, and maintenance overhead. That overhead is only worth paying when ML genuinely outperforms simpler alternatives on the metric that matters.

## 8. The Framing Document

The output of this step is a written specification. Fill this template before any modelling work.

```
══════════════════════════════════════════════════════
ML PROBLEM SPECIFICATION
══════════════════════════════════════════════════════

Business goal:
  [What business outcome does this model support?]

Task T:
  [Exact prediction: input → output. Name the output space.]

Experience E:
  [Data source, volume, label availability, time range, class balance]

Performance P:
  [Primary metric + threshold. Secondary metrics if applicable.]

Baselines:
  - Majority class:      [score]
  - Existing system:     [score]
  - Logistic regression: [score]

Minimum viable performance:
  [Below this threshold, do not deploy]

Deployment context:
  - Serving: [synchronous / batch / streaming]
  - Latency: [acceptable response time]
  - Scale:   [requests per second]
  - Hardware: [CPU / GPU / edge]

Error cost asymmetry:
  - False positive cost: [describe]
  - False negative cost: [describe]
  - Recommended metric weight: [F_β with β = ?]

Known risks:
  - [Class imbalance / distribution shift / label delay / ...]

Monitoring plan:
  - [Input drift, prediction drift, delayed ground truth strategy]

ML justified?
  - [Why a simpler rule-based approach is insufficient]
══════════════════════════════════════════════════════
```

## 9. Common Framing Mistakes

|Mistake|Consequence|Fix|
|---|---|---|
|Using accuracy on imbalanced data|Model that predicts majority class scores "well" but learns nothing|Use F1, AUC-ROC, or precision-recall|
|Metric chosen after seeing results|Overfitting to the test set at the framing level|Fix the metric in the framing document before EDA|
|No baseline defined|Cannot assess whether any model is useful|Always compute majority-class and LR baselines|
|Output type ambiguous|Wrong loss function, wrong model family|State $\mathcal{Y}$ formally before touching data|
|Deployment context ignored|Model too slow, too large, or wrong latency class|Define latency + hardware budget at framing|
|"Predict X" without unit of prediction|Granularity mismatch between training and deployment|Specify exactly what one row of input looks like|
|Skipping the "is ML necessary" check|Overengineered solution for a trivial problem|Apply the ML necessity decision tree|

## 10. Code — Framing Checklist in Python

```python
"""
framing_checklist.py
Run this before starting any ML project.
It does not train any model — it only validates that the problem
is well-posed and documents it reproducibly.
"""

from dataclasses import dataclass, field
from typing import Optional
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import f1_score, mean_squared_error
import numpy as np

@dataclass
class MLProblemFrame:
    """
    A complete ML problem specification.
    Fill all fields before writing modelling code.
    """
    # ── T-E-P ─────────────────────────────────────────────────────
    task_description: str = ""
    output_type: str = ""           # "binary", "multiclass", "regression", "ranking", ...
    data_description: str = ""
    primary_metric: str = ""        # "f1", "auc", "rmse", "mae", ...
    metric_threshold: Optional[float] = None

    # ── Context ───────────────────────────────────────────────────
    serving_mode: str = ""          # "synchronous", "batch", "streaming"
    latency_budget_ms: Optional[int] = None
    fp_cost_description: str = ""
    fn_cost_description: str = ""
    fbeta: float = 1.0              # β for F_β score

    # ── Validation flags ──────────────────────────────────────────
    _issues: list = field(default_factory=list, init=False)

    def validate(self) -> bool:
        """Check all required fields are filled and consistent."""
        self._issues = []

        required = ['task_description', 'output_type', 'data_description',
                    'primary_metric', 'serving_mode']
        for f in required:
            if not getattr(self, f):
                self._issues.append(f"Missing: {f}")

        # Metric / output compatibility
        clf_metrics = {'f1', 'auc', 'accuracy', 'precision', 'recall'}
        reg_metrics = {'rmse', 'mae', 'mape', 'r2'}
        if self.output_type == 'regression' and self.primary_metric in clf_metrics:
            self._issues.append(f"Mismatch: regression output but classification metric '{self.primary_metric}'")
        if self.output_type in ('binary', 'multiclass') and self.primary_metric in reg_metrics:
            self._issues.append(f"Mismatch: classification output but regression metric '{self.primary_metric}'")

        return len(self._issues) == 0

    def report(self):
        """Print the full framing document."""
        ok = self.validate()
        print("="*54)
        print("ML PROBLEM SPECIFICATION")
        print("="*54)
        print(f"Task:            {self.task_description}")
        print(f"Output type:     {self.output_type}")
        print(f"Data:            {self.data_description}")
        print(f"Metric:          {self.primary_metric}" +
              (f" ≥ {self.metric_threshold}" if self.metric_threshold else ""))
        print(f"Serving:         {self.serving_mode}" +
              (f"  ({self.latency_budget_ms}ms budget)" if self.latency_budget_ms else ""))
        print(f"FP cost:         {self.fp_cost_description}")
        print(f"FN cost:         {self.fn_cost_description}")
        print(f"F_β weight:      β = {self.fbeta}")

        if ok:
            print("\nFRAMING STATUS: Well-posed — proceed to data collection")
        else:
            print("\nFRAMING STATUS: Issues found — resolve before proceeding")
            for issue in self._issues:
                print(f"  [{issue}]")
        print("="*54)


def compute_baselines(X_train, X_test, y_train, y_test, task='classification'):
    """Compute all three baseline tiers."""
    results = {}

    if task == 'classification':
        d = DummyClassifier(strategy='most_frequent').fit(X_train, y_train)
        results['Majority class'] = f1_score(y_test, d.predict(X_test), average='macro')

        dr = DummyClassifier(strategy='stratified', random_state=42).fit(X_train, y_train)
        results['Random'] = f1_score(y_test, dr.predict(X_test), average='macro')

        lr = Pipeline([('s', StandardScaler()),
                       ('m', LogisticRegression(max_iter=500, random_state=42))])
        lr.fit(X_train, y_train)
        results['Logistic regression'] = f1_score(y_test, lr.predict(X_test), average='macro')

    elif task == 'regression':
        from sklearn.dummy import DummyRegressor
        dr = DummyRegressor(strategy='mean').fit(X_train, y_train)
        results['Mean predictor'] = np.sqrt(mean_squared_error(y_test, dr.predict(X_test)))

        from sklearn.linear_model import LinearRegression
        lr = Pipeline([('s', StandardScaler()), ('m', LinearRegression())])
        lr.fit(X_train, y_train)
        results['Linear regression'] = np.sqrt(mean_squared_error(y_test, lr.predict(X_test)))

    print("Baselines:")
    for name, score in results.items():
        print(f"  {name:<25} {score:.4f}")
    print("Your model must clearly beat the LR/Linear baseline.")
    return results


# ── Example usage ─────────────────────────────────────────────────
if __name__ == "__main__":
    frame = MLProblemFrame(
        task_description     = "Predict credit card fraud (binary: 1=fraud, 0=legit)",
        output_type          = "binary",
        data_description     = "18M transactions, 0.3% positive, 18-month window",
        primary_metric       = "f1",
        metric_threshold     = 0.70,
        serving_mode         = "synchronous",
        latency_budget_ms    = 200,
        fp_cost_description  = "Transaction blocked; customer inconvenienced",
        fn_cost_description  = "Fraud succeeds; financial loss + reputational damage",
        fbeta                = 2.0    # recall twice as important
    )
    frame.report()
```

## Key Definitions Cheatsheet

|Term|Definition|
|---|---|
|T-E-P triple|Task, Experience, Performance — the three components of any learning problem|
|Output type|The formal space $\mathcal{Y}$ of predictions — binary, multiclass, continuous, etc.|
|Performance metric|The specific function measuring how well predictions match reality|
|Baseline|Naive or simple reference model; defines what "useful" means|
|$F_\beta$ score|Weighted harmonic mean of precision and recall; $\beta > 1$ weights recall|
|Minimum viable performance|Threshold below which the model should not be deployed|
|False positive|Model predicts positive; truth is negative|
|False negative|Model predicts negative; truth is positive|
|Metric/output mismatch|Using a classification metric on regression output or vice versa — a framing error|
