## 1. What Is Learning?

Before writing a single line of code or touching a dataset, the question must be asked precisely: **what does it mean for a machine to _learn_?**

The intuitive answer — "it gets better with experience" — is Mitchell's definition above. But intuition is not enough. To build algorithms, to prove guarantees, and to know when things will fail, we need a mathematical formalisation.

The formalisation has three parts.

---

## 2. The Three Components of a Learning Problem

Every learning problem decomposes as a triple $(T, E, P)$.

|Component|Definition|Example|
|---|---|---|
|**Task $T$**|What the system is trying to do|Classify email as spam / not spam|
|**Experience $E$**|What the system has access to during training|Dataset of labelled emails|
|**Performance $P$**|How we evaluate whether $T$ is done well|Classification accuracy on held-out set|

The learning problem: given $E$, improve performance on $T$ as measured by $P$.

This decomposition enforces precision. "Build a model that predicts customer churn" is **not** a well-posed learning problem. "Train a binary classifier ($T$) on 12 months of transaction history ($E$) to maximise F1 score on a held-out test set ($P$)" is.

---

## 3. The Formal Setup

Let:

- $\mathcal{X}$ = **input space** (e.g., $\mathbb{R}^d$, images, sentences)
- $\mathcal{Y}$ = **output space** (e.g., $\mathbb{R}$ for regression, ${0,1}$ for binary classification)

We assume an **unknown target function**:

$$f^* : \mathcal{X} \to \mathcal{Y}$$

We never observe $f^*$ directly. Instead we observe a training set:

$$\mathcal{D} = {(x_1, y_1), (x_2, y_2), \ldots, (x_n, y_n)}$$

where each $(x_i, y_i) \overset{\text{i.i.d.}}{\sim} P_{\mathcal{X} \times \mathcal{Y}}$, an unknown joint distribution.

The goal: find $h : \mathcal{X} \to \mathcal{Y}$ that approximates $f^*$ — **not just on training data, but on unseen inputs drawn from the same distribution.**

> [!important] The Core Difficulty Fitting training data is easy. Generalising to unseen data is the entire problem.

### 3.1 The Hypothesis Class

We restrict the search to a **hypothesis class** $\mathcal{H}$:

$$\mathcal{H} = {h_\theta : \mathcal{X} \to \mathcal{Y} \mid \theta \in \Theta}$$

Learning becomes: find $\theta^* \in \Theta$ such that $h_{\theta^_}$ best approximates $f^_$.

|Model|Hypothesis Class $\mathcal{H}$|
|---|---|
|Linear regression|${x \mapsto w^\top x + b \mid w \in \mathbb{R}^d, b \in \mathbb{R}}$|
|Logistic regression|${x \mapsto \sigma(w^\top x + b) \mid w \in \mathbb{R}^d, b \in \mathbb{R}}$|
|Depth-$k$ decision tree|All binary trees with depth $\leq k$|
|2-layer neural network|${x \mapsto W_2,\sigma(W_1 x + b_1) + b_2}$|

The choice of $\mathcal{H}$ is **the most consequential modelling decision you make**. It encodes what you believe about $f^*$ before seeing any data — this belief is called **inductive bias**.

---

## 4. Inductive Bias

No algorithm can learn without assumptions. This is a theorem, not an opinion.

> **Definition.** The **inductive bias** of a learning algorithm is the set of assumptions it makes about $f^*$, beyond what the training data alone can establish.

|Model|Inductive Bias|
|---|---|
|Linear regression|$f^*$ is linear in the inputs|
|KNN ($k=1$)|$f^*$ is locally constant; nearby inputs share the same output|
|Gaussian Process (RBF kernel)|$f^_$ is smooth; small $\Delta x \Rightarrow$ small $\Delta f^_(x)$|
|CNN|$f^*$ is translation-equivariant; same pattern at different positions detected identically|

**Inductive bias is not a flaw — it is a deliberate design choice.** Choosing a linear model for a nonlinear problem is not rigour; it is a systematic error. Choosing an overly rich model for a simple problem invites overfitting.

---

## 5. The No Free Lunch Theorem

**Theorem (Wolpert, 1996 — informal).** Averaged over _all_ possible target functions $f^* : \mathcal{X} \to \mathcal{Y}$, every learning algorithm performs equally well.

> [!warning] What This Means vs. What It Does Not Mean **Means:** No universally superior algorithm. Gains on some problems are paid by losses elsewhere. **Does not mean:** Stop choosing algorithms. In practice we care about the specific structure of real-world processes — those have regularity, and exploiting it is what ML is.

**The lesson:** your algorithm choice encodes an assumption about the problem. Make that assumption explicit. There is no free lunch — you pay with assumptions.

---

## 6. Types of Learning — By Supervision

### 6.1 Supervised Learning

$$\mathcal{D} = {(x_i, y_i)}_{i=1}^n$$

Labels provided by a supervisor. Task: learn a mapping from inputs to outputs.

- **Regression** — $\mathcal{Y} = \mathbb{R}$. Predict a continuous quantity.
- **Classification** — $\mathcal{Y} = {1,\ldots,k}$. Predict a discrete category.
- **Structured prediction** — $\mathcal{Y}$ is structured (sequence, tree, graph). E.g., machine translation.

**Fundamental bottleneck:** labels are expensive and do not scale.

### 6.2 Unsupervised Learning

$$\mathcal{D} = {x_i}_{i=1}^n \quad \text{(no labels)}$$

Task: discover the underlying structure of $P(\mathcal{X})$.

Sub-tasks: clustering, dimensionality reduction, density estimation, representation learning.

### 6.3 Semi-Supervised Learning

$$\mathcal{D} = {(x_i, y_i)}_{i=1}^m \cup {x_j}_{j=m+1}^n, \quad m \ll n$$

Small labelled set + large unlabelled set. Key assumption: unlabelled data carries information about $P(\mathcal{X})$ that improves learning of $P(\mathcal{Y} \mid \mathcal{X})$.

### 6.4 Self-Supervised Learning

Supervision generated automatically from the data — no human annotation.

|Method|Mechanism|
|---|---|
|BERT (masked LM)|Mask 15% of tokens; predict them. Labels = original tokens|
|GPT (next-token prediction)|Predict the next token given all prior tokens|
|SimCLR (contrastive)|Two views of same image → similar rep; different images → different rep|

The dominant paradigm for pretraining large models. Pretrained representations are fine-tuned on small labelled sets — **transfer learning**.

### 6.5 Reinforcement Learning

No fixed dataset. An **agent** interacts with an **environment**, takes actions, receives scalar **rewards**. Task: learn policy $\pi : \mathcal{S} \to \mathcal{A}$ maximising:

$$G_t = \sum_{k=0}^{\infty} \gamma^k r_{t+k}, \quad \gamma \in [0,1)$$

Two critical differences from supervised learning:

1. No supervisor — only a delayed, noisy reward signal.
2. Data distribution depends on the agent's own behaviour.

## 7. Batch Learning

### 7.1 What Is It?

**Batch learning** (also called _offline learning_) trains the model on the **entire dataset at once**. Once training completes, parameters are **frozen**. The model is deployed and does not change until you explicitly retrain it from scratch.

**Formal objective:**

$$\theta^* = \arg\min_{\theta \in \Theta} \frac{1}{n} \sum_{i=1}^n \mathcal{L}(h_\theta(x_i),, y_i) + \lambda,\Omega(\theta)$$

This optimisation runs once (or for a fixed number of epochs). After it completes, $\theta^*$ is frozen.

**Lifecycle:**

```
Collect full dataset
        │
        ▼
   Train on all n examples
        │
        ▼
   Evaluate on held-out test set
        │
        ▼
   Deploy frozen model
        │
        ▼
   Monitor → retrain periodically when performance degrades
```

---

### 7.2 When to Use Batch Learning

> [!note] When to Use
> 
> 1. **Stationary distribution** — the data-generating process does not change over time
> 2. **Full data available upfront** — you have the complete dataset before training begins
> 3. **High accuracy is the priority** — you can afford long training times for better performance
> 4. **Stability and auditability matter** — model must behave deterministically after deployment
> 5. **Standard ML tasks** — image classifiers, NLP models, recommendation systems trained nightly

---

### 7.3 Advantages

|Advantage|Explanation|
|---|---|
|**Higher accuracy**|Sees the full data distribution at once; finds a globally better optimum|
|**Stable behaviour**|Frozen post-training; predictions are reproducible and auditable|
|**Well-understood theory**|PAC learning, VC theory, and cross-validation all apply cleanly|
|**Parallelisable**|Training distributes freely across GPUs and machines|
|**Easier debugging**|Fixed dataset → reproducible experiments → clean error analysis|

---

### 7.4 Disadvantages

|Disadvantage|Explanation|
|---|---|
|**Cannot adapt to new data**|New data has no effect until a full retrain is triggered|
|**Expensive retraining**|Incorporating new data requires reprocessing the entire dataset|
|**Concept drift blindness**|If $P_{\mathcal{X} \times \mathcal{Y}}$ shifts after deployment, the model silently degrades|
|**Memory intensive**|Full dataset must be accessible during training|
|**High latency to production**|Changes in the world take hours to weeks to reach the model|

---

### 7.5 Code — Batch Learning

**From scratch — batch gradient descent:**

```python
import numpy as np

# ── Toy dataset: y = 2x + 1 + noise ──────────────────────────────
np.random.seed(42)
X = np.random.randn(100)        # 100 training examples
y = 2 * X + 1 + 0.1 * np.random.randn(100)

# ── Model parameters ──────────────────────────────────────────────
w, b = 0.0, 0.0
lr = 0.01
epochs = 50

# ── Batch training loop ───────────────────────────────────────────
for epoch in range(epochs):

    # Forward pass: predict on the ENTIRE dataset at once
    y_hat = w * X + b

    # Mean Squared Error over all n=100 examples
    loss = np.mean((y_hat - y) ** 2)

    # Gradients = average over ALL examples  ← this is batch learning
    grad_w = np.mean((y_hat - y) * X)   # dL/dw
    grad_b = np.mean(y_hat - y)          # dL/db

    # One parameter update per epoch
    w -= lr * grad_w
    b -= lr * grad_b

    if epoch % 10 == 0:
        print(f"Epoch {epoch:3d} | Loss: {loss:.4f} | w={w:.3f} b={b:.3f}")

print(f"\nLearned: w={w:.3f}, b={b:.3f}")
print(f"True:    w=2.000, b=1.000")
```

> The key line is `grad_w = np.mean(...)` — gradient is **averaged over all 100 examples** before a single step is taken. One update per epoch.

**Using scikit-learn (batch by default):**

```python
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import train_test_split
import numpy as np

np.random.seed(42)
X = np.random.randn(100, 1)
y = 2 * X.squeeze() + 1 + 0.1 * np.random.randn(100)

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)

model = LinearRegression()
model.fit(X_train, y_train)       # trains on ENTIRE X_train at once

print(f"w={model.coef_[0]:.3f}, b={model.intercept_:.3f}")
print(f"Test R²: {model.score(X_test, y_test):.4f}")

# To incorporate new data → must retrain from scratch:
# model.fit(X_all, y_all)
```

## 8. Online Learning

### 8.1 What Is It?

**Online learning** updates the model **one example at a time** as new data arrives. There is no separate training phase — the model is always live, always updating, and never stops learning.

**The online protocol:**

```
for t = 1, 2, 3, ...:
    ┌─ receive new input x_t
    ├─ predict  ŷ_t = h_{θ_{t-1}}(x_t)   ← use current params
    ├─ receive true label y_t
    ├─ compute loss  ℓ_t = L(ŷ_t, y_t)
    └─ update  θ_t ← θ_{t-1} - η_t · ∇ℓ_t  ← update immediately
                                              (discard x_t, y_t)
```

Each update uses **only the current example**. Past examples are discarded — no history stored.

**Performance criterion — Cumulative Regret:**

Online learning is not evaluated by test set accuracy. The correct metric is **regret** against the best fixed model in hindsight:

$$R_T = \sum_{t=1}^T \ell_t(\hat{y}_t) - \min_{\theta \in \Theta} \sum_{t=1}^T \ell_t(h_\theta(x_t))$$

An algorithm has **sublinear regret** if $R_T / T \to 0$ as $T \to \infty$ — the online learner asymptotically matches the best fixed strategy, even without ever seeing the future.

Online Gradient Descent with $\eta_t = 1/\sqrt{t}$ achieves $R_T = O(\sqrt{T})$ under convexity.

---

### 8.2 When to Use Online Learning

> [!note] When to Use
> 
> 1. **Where there is concept drift** — the distribution $P_{\mathcal{X} \times \mathcal{Y}}$ changes over time; the model must adapt continuously rather than go stale
> 2. **Cost effective** — you cannot afford to store a growing dataset or pay for full periodic retrains; online learning uses $O(1)$ memory and spreads compute evenly
> 3. **Faster solution** — decisions must be made immediately as data arrives, with no time for a retraining cycle; the model is always up to date
> 4. **Unbounded data streams** — financial tick data, network traffic, sensor feeds, click logs; the data never stops arriving
> 5. **Adaptive systems** — spam filters, fraud detectors, ad rankers that must track shifting user behaviour in real time

---

### 8.3 Advantages

|Advantage|Explanation|
|---|---|
|**Handles concept drift**|Parameters update continuously; model tracks shifting distributions naturally|
|**Memory efficient**|Only stores current parameters — not the full history|
|**Zero latency to incorporate new data**|Every new example is immediately reflected in the model|
|**Scales to infinite streams**|Works on unbounded data; batch learning would eventually exhaust memory|
|**Cost effective**|No expensive periodic full retrains; compute is constant and evenly spread|
|**Proven regret guarantees**|Theoretically matches the best fixed model over time ($R_T = O(\sqrt{T})$)|

---

### 8.4 Disadvantages

|Disadvantage|Explanation|
|---|---|
|**Sensitive to noisy examples**|A single corrupted data point immediately damages the model; no averaging|
|**Sensitive to example order**|Results depend on the sequence of data, not just its content|
|**Harder to debug**|Model state changes every step; reproducing a specific failure is difficult|
|**Hyperparameter sensitivity**|Learning rate $\eta_t$ must be tuned carefully; too large = unstable, too small = slow|
|**No global optimum guarantee**|Per-step updates may not converge to the same solution as batch training|
|**Less intuitive evaluation**|Regret-based evaluation is harder to communicate than test accuracy|

### 8.5 Code — Online Learning

**From scratch — online gradient descent:**

```python
import numpy as np

# ── Simulated data stream ──────────────────────────────────────────
# In real online learning, examples arrive from the world one by one.
# Here we simulate a stream. The model never sees all data at once.

np.random.seed(0)

def data_stream(n=300):
    """Yields one (x, y) pair at a time — simulates live data."""
    for _ in range(n):
        x = np.random.randn()
        y = 3 * x + 2 + 0.2 * np.random.randn()   # true: w=3, b=2
        yield x, y

# ── Model parameters ───────────────────────────────────────────────
w, b = 0.0, 0.0

# ── Online learning loop ───────────────────────────────────────────
for t, (x, y) in enumerate(data_stream(), start=1):

    # Decaying learning rate → sublinear regret guarantee
    lr = 1.0 / np.sqrt(t)

    # Predict with CURRENT parameters
    y_hat = w * x + b

    # Loss on this single example
    loss = (y_hat - y) ** 2

    # Gradient from THIS EXAMPLE ONLY  ← key difference from batch
    grad_w = 2 * (y_hat - y) * x
    grad_b = 2 * (y_hat - y)

    # Update immediately — then discard this example
    w -= lr * grad_w
    b -= lr * grad_b

    if t % 75 == 0:
        print(f"t={t:3d} | loss={loss:.4f} | w={w:.3f} b={b:.3f}")

print(f"\nLearned: w={w:.3f}, b={b:.3f}")
print(f"True:    w=3.000, b=2.000")
```

> The key difference: `grad_w = 2 * (y_hat - y) * x` — gradient from **one example only**, computed and applied immediately. The example is then discarded. No history kept.

**Concept drift — where online learning beats batch:**

```python
import numpy as np

# ── Scenario: distribution shifts halfway through ─────────────────
# t = 1..500:   y = 2x + 1   (Phase 1)
# t = 501..1000: y = -3x + 5  (Phase 2 — concept drift!)

np.random.seed(1)

def drifting_stream(n=1000):
    for t in range(1, n + 1):
        x = np.random.randn()
        if t <= 500:
            y = 2 * x + 1 + 0.1 * np.random.randn()
        else:
            y = -3 * x + 5 + 0.1 * np.random.randn()  # drift!
        yield t, x, y

# ── Online model (adapts) ──────────────────────────────────────────
w_on, b_on = 0.0, 0.0

# ── Batch model (frozen after Phase 1) ────────────────────────────
# Simulates a model trained once and never retrained
w_bt, b_bt = 2.0, 1.0   # perfectly fit to Phase 1

online_losses, batch_losses = [], []

for t, x, y in drifting_stream():
    lr = 0.05   # fixed small learning rate

    # Online: predict → compute loss → update
    y_hat_on = w_on * x + b_on
    loss_on  = (y_hat_on - y) ** 2
    w_on -= lr * 2 * (y_hat_on - y) * x
    b_on -= lr * 2 * (y_hat_on - y)

    # Batch: predict only (never updates)
    y_hat_bt = w_bt * x + b_bt
    loss_bt  = (y_hat_bt - y) ** 2

    online_losses.append(loss_on)
    batch_losses.append(loss_bt)

# ── Results ────────────────────────────────────────────────────────
print("=== Before drift (t = 1..500) ===")
print(f"  Online avg loss: {np.mean(online_losses[:500]):.4f}")
print(f"  Batch  avg loss: {np.mean(batch_losses[:500]):.4f}")

print("\n=== After drift (t = 501..1000) ===")
print(f"  Online avg loss: {np.mean(online_losses[500:]):.4f}")
print(f"  Batch  avg loss: {np.mean(batch_losses[500:]):.4f}")
# Online adapts to the new relationship.
# Batch loss explodes because it is still fitting the old pattern.
```

**Using scikit-learn — `partial_fit()` for online learning:**

```python
from sklearn.linear_model import SGDRegressor
import numpy as np

# SGDRegressor with partial_fit() = online learning interface
# learning_rate='invscaling' → η_t = η_0 / t^power_t (decaying)
model = SGDRegressor(learning_rate='invscaling', eta0=0.1, power_t=0.5)

np.random.seed(2)

for t in range(1, 401):
    # Simulate one new example arriving
    x = np.random.randn(1, 1)                          # shape (1, n_features)
    y_true = 3 * x[0, 0] + 2 + 0.1 * np.random.randn()

    # partial_fit() updates the model on THIS ONE example only
    model.partial_fit(x, [y_true])

    if t % 100 == 0:
        print(f"t={t:3d} | w={model.coef_[0]:.3f}, b={model.intercept_[0]:.3f}")

# Model is always ready to predict — no separate "deploy" step
x_new = np.array([[1.5]])
print(f"\nPrediction for x=1.5: {model.predict(x_new)[0]:.3f}")
print(f"True value:           {3 * 1.5 + 2:.3f}")
```

> [!tip] `partial_fit()` is the scikit-learn interface for online learning Any estimator implementing `partial_fit()` supports incremental updates. Key classes: `SGDRegressor`, `SGDClassifier`, `PassiveAggressiveClassifier`, `MiniBatchKMeans`, `MultinomialNB`.

## 9. Batch vs. Online — Direct Comparison

|Dimension|Batch Learning|Online Learning|
|---|---|---|
|**Data access**|Full dataset simultaneously|One example at a time|
|**When model updates**|After training completes (frozen)|After every single example|
|**Memory**|$O(n)$ — stores full dataset|$O(1)$ — discards past examples|
|**Handles concept drift**|No — silently degrades|Yes — adapts continuously|
|**Cost**|Expensive periodic full retrains|Cheap constant per-example updates|
|**Speed to incorporate new data**|Slow (full retrain cycle)|Immediate|
|**Stability**|High — frozen post-training|Lower — evolves every step|
|**Noise sensitivity**|Low — averaged over full dataset|High — one bad example corrupts model|
|**Theoretical guarantee**|Generalisation error, PAC bounds|Regret bounds: $R_T = O(\sqrt{T})$|
|**Debugging**|Easy — fixed dataset, reproducible|Hard — model state changes every step|
|**Typical use**|Image classifiers, NLP, batch recos|Fraud detection, spam filters, ad ranking|

> [!warning] Common Confusion — Mini-Batch SGD ≠ Online Learning Running SGD with mini-batches of 32 or 64 on a **fixed offline dataset** is still **batch learning**. The dataset is closed and fixed. Online learning means new data arrives from the world continuously — the model updates and discards the example, never replaying it.

## 10. The Generalisation Problem

We can always find $h \in \mathcal{H}$ that perfectly fits $\mathcal{D}$ — just memorise it. But memorisation is not learning.

**Overfitting:** model captures noise in $\mathcal{D}$. Low training error, high test error. $|\mathcal{H}|$ too large relative to $n$.

**Underfitting:** $\mathcal{H}$ too restricted to capture $f^*$. High training and test error regardless of $n$.

$$\text{Too small } \mathcal{H} \Rightarrow \text{underfitting} \qquad \text{Too large } \mathcal{H} \text{ relative to } n \Rightarrow \text{overfitting}$$

More data always helps. More flexible models help only when data is sufficient to constrain them.

## 11. A Taxonomy of ML Problems

|Dimension|Options|
|---|---|
|**Supervision**|Supervised, Unsupervised, Semi-supervised, Self-supervised, Reinforcement|
|**Update regime**|Batch (offline), Online, Mini-batch streaming (hybrid)|
|**Output type**|Continuous (regression), Discrete (classification), Structured (sequence, graph)|
|**Output cardinality**|Binary, Multi-class, Multi-label, Ordinal|
|**Data modality**|Tabular, Image, Text, Audio, Time series, Graph|
|**Stationarity**|Stationary ($P$ fixed), Non-stationary (concept drift)|
|**Task scope**|Single-task, Multi-task, Transfer learning, Meta-learning|

**Identifying where your problem sits in this taxonomy is the first decision before choosing any algorithm.**
