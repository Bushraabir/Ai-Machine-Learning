# 27. `__init__` and `self`

## The Problem They Solve

When you create multiple objects from the same class, each object needs its own private storage — its own data that doesn't bleed into other objects. `self` is the mechanism that gives each object its own namespace. `__init__` is the function that initializes that namespace the moment the object is created.

Without understanding these two, OOP in Python is cargo-cult syntax. With them, everything else in OOP becomes obvious.

---

## `self` — What It Actually Is

`self` is a **reference to the instance that called the method**. It is not a keyword — it is a naming convention. Python passes it automatically as the first argument to every instance method.

```python
class Dog:
    def bark(self):
        print(f"I am dog at memory address: {id(self)}")

d1 = Dog()
d2 = Dog()

d1.bark()   # I am dog at memory address: 140234567891234
d2.bark()   # I am dog at memory address: 140234567891456
```

`d1.bark()` is syntactic sugar for `Dog.bark(d1)`. Python rewrites it that way internally. The instance is always passed as the first argument — `self` just gives it a name inside the method body.

```python
# These two calls are identical
d1.bark()
Dog.bark(d1)
```

This is not magic. It is a deliberate design choice: methods are functions stored on the class, and the instance is threaded through explicitly. There is no hidden implicit `this` pointer like in C++ or Java — Python makes it visible.

---

## `__init__` — The Initializer Method

`__init__` is a **dunder (double underscore) method** that Python calls automatically immediately after creating a new object. Its job is to set up the object's initial state by assigning instance attributes via `self`.

```python
class Dog:
    def __init__(self, name, breed, age):
        self.name = name       # instance attribute
        self.breed = breed
        self.age = age

d = Dog("Rex", "Labrador", 3)
print(d.name)    # Rex
print(d.breed)   # Labrador
print(d.age)     # 3
```

**What happens when `Dog("Rex", "Labrador", 3)` is called:**

1. Python calls `Dog.__new__(Dog)` — allocates memory for a new Dog object
2. Python calls `Dog.__init__(new_object, "Rex", "Labrador", 3)` — initializes it
3. The initialized object is returned and bound to `d`

You define `__init__`, Python handles `__new__`. In 99% of cases you never touch `__new__`.

---

## Instance Attributes — Stored on `self`

Every `self.something = value` inside `__init__` creates an **instance attribute** — data that belongs to that specific object alone.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p1 = Point(1, 2)
p2 = Point(10, 20)

print(p1.x)   # 1
print(p2.x)   # 10

# Each object has its own __dict__
print(p1.__dict__)   # {'x': 1, 'y': 2}
print(p2.__dict__)   # {'x': 10, 'y': 20}
```

`__dict__` is the actual dictionary backing an object's attributes. Every instance has its own. Assigning to `self.x` in one instance has zero effect on any other instance.

---

## `self` in Methods Beyond `__init__`

`self` is available in every instance method, not just `__init__`. It's how methods access the object's own data and other methods.

```python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount         # reads and writes self's data

    def withdraw(self, amount):
        if amount > self.balance:
            raise ValueError("Insufficient funds")
        self.balance -= amount

    def statement(self):
        return f"{self.owner}: ${self.balance:.2f}"

acc = BankAccount("Alice", 1000)
acc.deposit(500)
acc.withdraw(200)
print(acc.statement())   # Alice: $1300.00
```

Every method uses `self` to refer to the instance it was called on. There is no global state — each `BankAccount` object manages its own `balance`.

## What Happens Without `self`

A common mistake is forgetting `self` when assigning attributes, creating a local variable that dies when the method returns.

```python
class Bad:
    def __init__(self, value):
        value = value   # ← assigns to a local variable, NOT the object
        # self.value never created

b = Bad(42)
print(b.value)   # AttributeError: 'Bad' object has no attribute 'value'
```

```python
class Good:
    def __init__(self, value):
        self.value = value   # ← stored on the object

g = Good(42)
print(g.value)   # 42
```

The rule: if you want data to persist on the object, it must be assigned to `self.something`.

## `__init__` with Default Arguments

```python
class Vector:
    def __init__(self, x=0, y=0, z=0):
        self.x = x
        self.y = y
        self.z = z

    def magnitude(self):
        return (self.x**2 + self.y**2 + self.z**2) ** 0.5

    def __repr__(self):
        return f"Vector({self.x}, {self.y}, {self.z})"

v1 = Vector(1, 2, 3)
v2 = Vector(x=4)        # y and z default to 0
v3 = Vector()           # all default to 0

print(v1)               # Vector(1, 2, 3)
print(v2)               # Vector(4, 0, 0)
print(v1.magnitude())   # 3.7416...
```

All default argument rules from [[20. Default and keyword arguments]] apply directly to `__init__`. The mutable default argument trap applies here too — never use `[]`, `{}`, or `set()` as a default in `__init__`.

```python
# Bug — all instances share the same list
class Bad:
    def __init__(self, items=[]):
        self.items = items   # ← mutable default shared across all instances

# Fix
class Good:
    def __init__(self, items=None):
        self.items = items if items is not None else []
```

## `__init__` Does Not Return a Value

`__init__` must return `None`. Returning anything else raises a `TypeError`.

```python
class Wrong:
    def __init__(self, x):
        self.x = x
        return self   # TypeError: __init__() should return None

class Right:
    def __init__(self, x):
        self.x = x
        # implicit return None
```

If you want to control what is _returned_ when constructing an object, that is the job of `__new__`, which is almost never overridden.

## Object Identity and `self`

`self` is always the same object as the variable you assigned the instance to.

```python
class Tracker:
    def __init__(self):
        print(f"Inside __init__, id(self) = {id(self)}")

t = Tracker()
print(f"Outside, id(t) = {id(t)}")
# Both print the same memory address — they are the same object
```

This is important for understanding that mutations inside methods affect the original object, not a copy.

```python
class Container:
    def __init__(self):
        self.data = []

    def add(self, item):
        self.data.append(item)   # mutates the list on self — permanent

c = Container()
c.add(1)
c.add(2)
print(c.data)   # [1, 2]
```

## Building a Real Example — Neural Network Layer

```python
class LinearLayer:
    """A single fully-connected layer: output = W @ x + b"""

    def __init__(self, in_features, out_features):
        import random
        # Initialize weights as a 2D list (out x in)
        self.weights = [
            [random.gauss(0, 0.01) for _ in range(in_features)]
            for _ in range(out_features)
        ]
        # Initialize bias as a 1D list
        self.bias = [0.0] * out_features
        self.in_features = in_features
        self.out_features = out_features

    def info(self):
        return (f"LinearLayer({self.in_features} → {self.out_features}) | "
                f"params: {self.in_features * self.out_features + self.out_features}")

layer = LinearLayer(784, 128)
print(layer.info())
# LinearLayer(784 → 128) | params: 100480
```

This is structurally identical to how `torch.nn.Linear.__init__` works — it stores weight tensors on `self`. When you eventually read PyTorch source code, you will see exactly this pattern.

## Introspection — Inspecting Objects

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        import math
        return math.pi * self.radius ** 2

c = Circle(5)

# See all instance attributes
print(c.__dict__)           # {'radius': 5}

# See the class
print(type(c))              # <class '__main__.Circle'>
print(c.__class__.__name__) # Circle

# Check if attribute exists before accessing
print(hasattr(c, 'radius'))     # True
print(hasattr(c, 'diameter'))   # False

# Get attribute by name dynamically
print(getattr(c, 'radius'))     # 5
print(getattr(c, 'color', 'unknown'))  # 'unknown' — default if missing

# Set attribute dynamically
setattr(c, 'color', 'red')
print(c.color)   # red
```

`hasattr`, `getattr`, `setattr` are the programmatic interface to `self.__dict__`. You will use these in ML frameworks that dynamically configure layers.

## `self` is Just a Convention

The name `self` has no special meaning to Python. You could name it anything — but you never should.

```python
class Point:
    def __init__(this, x, y):   # valid Python, terrible practice
        this.x = x
        this.y = y

    def distance(this):
        return (this.x**2 + this.y**2) ** 0.5
```

PEP 8 mandates `self`. Every Python programmer, every library, every framework uses it. Deviating breaks readability for no gain.

## Common Errors

```python
# 1. Forgetting self as first parameter
class Bad:
    def __init__(name):       # TypeError when instantiating
        self.name = name

# 2. Typo in self — creates new attribute instead of setting intended one
class Typo:
    def __init__(self, value):
        self.valeu = value    # typo — self.value never set

t = Typo(10)
print(t.value)   # AttributeError

# 3. Accessing attribute before it's set
class Order:
    def __init__(self, items):
        self.total = self.compute_total()   # Error — self.items doesn't exist yet
        self.items = items

    def compute_total(self):
        return sum(self.items)   # AttributeError: 'Order' has no attribute 'items'

# Fix — set attributes before using them
class Order:
    def __init__(self, items):
        self.items = items
        self.total = self.compute_total()   # now items exists

    def compute_total(self):
        return sum(self.items)

# 4. Mutable default argument
class Graph:
    def __init__(self, edges=[]):   # all Graph() instances share this list
        self.edges = edges
```

## Summary Table

|Concept|Key Point|
|---|---|
|`self`|Reference to the calling instance — passed automatically|
|`self` name|Convention only — could be anything, never change it|
|`d.method()`|Python rewrites as `Dog.method(d)`|
|`__init__`|Called automatically after object creation — sets up state|
|`__init__` return|Must be `None` — returning anything else raises `TypeError`|
|Instance attributes|Created via `self.attr = value` — stored in `self.__dict__`|
|No `self.`|Assigns a local variable — dies when method returns|
|Mutable defaults|Never use `[]` or `{}` as `__init__` defaults|
