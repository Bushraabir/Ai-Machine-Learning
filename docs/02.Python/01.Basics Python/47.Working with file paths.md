## The Core Problem

A file path is a string like `"data/train/images/img_001.png"`. But strings are dumb — they know nothing about the file system. Concatenating them with `+` produces platform-dependent bugs, and querying their properties requires a zoo of `os` functions.

Python gives you two interfaces:

|Module|Style|When to use|
|---|---|---|
|`os.path`|Procedural, string-based|Legacy codebases, stdlib interop|
|`pathlib.Path`|Object-oriented, modern|Everything new you write|

The rest of this note teaches both, but the bias is toward `pathlib`. It is the right abstraction and has been the standard since Python 3.4.

---

## `pathlib.Path` — The Object-Oriented Interface

A `Path` object represents a file system path. It knows whether it is absolute or relative, what its components are, and how to interact with the OS.

```python
from pathlib import Path

p = Path("data/train/labels.csv")
```

`p` is not a string. It is an object that wraps the path and provides methods. It does print like a string, though:

```python
print(p)          # data/train/labels.csv
print(repr(p))    # PosixPath('data/train/labels.csv')  [on Unix]
                  # WindowsPath('data/train/labels.csv') [on Windows]
```

Python automatically returns the correct subclass (`PosixPath` or `WindowsPath`) based on the OS. Your code stays the same.

## Constructing Paths

```python
from pathlib import Path

# From a string
p = Path("data/train/img.png")

# From parts — the / operator joins components
p = Path("data") / "train" / "img.png"

# Absolute path
p = Path("/home/user/project/data")

# Current working directory
cwd = Path.cwd()

# Home directory
home = Path.home()

# From an environment variable
import os
root = Path(os.environ.get("DATA_ROOT", "data"))
```

The `/` operator is overloaded on `Path` objects. It calls `__truediv__` and joins path segments correctly for the current OS — no manual slash handling.

```python
base = Path("data")
full = base / "train" / "images" / "img_001.png"
print(full)   # data/train/images/img_001.png
```

This works identically on Windows (produces backslashes internally) and Unix (forward slashes). You never write `os.sep` or `\\`.

## Path Components — Anatomy

Given `p = Path("/home/user/project/data/train.csv")`:

```python
p.name        # "train.csv"          — filename with extension
p.stem        # "train"              — filename without extension
p.suffix      # ".csv"               — extension including the dot
p.suffixes    # [".csv"]             — list (handles .tar.gz → [".tar", ".gz"])
p.parent      # Path("/home/user/project/data")
p.parents[0]  # Path("/home/user/project/data")
p.parents[1]  # Path("/home/user/project")
p.parts       # ('/', 'home', 'user', 'project', 'data', 'train.csv')
p.anchor      # '/'                  — root on Unix, drive on Windows
p.root        # '/'
```

Visual anatomy:

```
/home/user/project/data/train.csv
└──────────────────────┘└───────┘
       p.parent          p.name
                         └───┘└───┘
                         p.stem p.suffix
```

## Querying the File System

```python
p = Path("data/train.csv")

p.exists()          # True if path exists (file or directory)
p.is_file()         # True if it exists and is a regular file
p.is_dir()          # True if it exists and is a directory
p.is_symlink()      # True if it is a symbolic link
p.stat().st_size    # size in bytes
p.stat().st_mtime   # last modified time (Unix timestamp)
```

```python
# Check before opening
if p.exists():
    with p.open() as f:
        content = f.read()
else:
    raise FileNotFoundError(f"Expected file at {p}")
```

## Manipulating Paths (Without Touching the File System)

These methods return new `Path` objects — they do not move or rename anything:

```python
p = Path("data/train/img_001.png")

# Change extension
p.with_suffix(".jpg")        # Path("data/train/img_001.jpg")

# Change filename
p.with_name("img_002.png")   # Path("data/train/img_002.png")

# Change stem only
p.with_stem("img_002")       # Path("data/train/img_002.png")  [Python 3.9+]

# Make absolute (resolves relative to cwd, resolves symlinks)
p.resolve()                  # Path("/absolute/path/to/data/train/img_001.png")

# Relative path from a base
p.relative_to("data")        # Path("train/img_001.png")
```

## File System Operations

```python
p = Path("output/results")

# Create directory (and parents if needed)
p.mkdir(parents=True, exist_ok=True)

# Create an empty file (like Unix touch)
Path("output/results/run.log").touch()

# Rename / move
Path("old_name.txt").rename("new_name.txt")

# Delete a file
Path("temp.txt").unlink(missing_ok=True)   # missing_ok: no error if absent [3.8+]

# Delete an empty directory
Path("empty_dir").rmdir()

# Copy (pathlib doesn't have copy — use shutil)
import shutil
shutil.copy(Path("src.txt"), Path("dst.txt"))
shutil.copytree(Path("src_dir"), Path("dst_dir"))
```

## Listing and Globbing

```python
d = Path("data/train")

# List immediate contents
for item in d.iterdir():
    print(item)

# Glob — match patterns in one directory
for f in d.glob("*.png"):
    print(f)

# Recursive glob — match across all subdirectories
for f in d.rglob("*.png"):
    print(f)

# Collect into a sorted list
png_files = sorted(d.rglob("*.png"))
```

`rglob("*.png")` is equivalent to `glob("**/*.png")`. Both return generators — they do not load all paths into memory at once, which matters when walking millions of image files.

## Reading and Writing via `Path`

`Path` objects have their own I/O methods — for small files, these are more concise than `open()`:

```python
p = Path("config.txt")

# Write and read text
p.write_text("learning_rate=0.001\nepochs=50\n")
content = p.read_text()           # returns full string

# Write and read bytes
p_bin = Path("weights.bin")
p_bin.write_bytes(b"\x00\x01\x02")
data = p_bin.read_bytes()         # returns bytes object

# For anything complex, use open() via pathlib
with p.open("r", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

`Path.open()` is identical to the built-in `open()` — it returns the same file object, supports the same modes and encoding arguments.

## Absolute vs. Relative Paths

A **relative path** is resolved relative to the current working directory at the time it is used:

```python
Path("data/train.csv")        # relative — depends on cwd
Path.cwd() / "data/train.csv" # same thing, made explicit
```

An **absolute path** is unambiguous regardless of cwd:

```python
Path("/home/user/project/data/train.csv")   # Unix absolute
Path("C:/Users/user/project/data/train.csv") # Windows absolute
```

`p.resolve()` converts any path to its absolute form and resolves symlinks:

```python
p = Path("../../data/train.csv")
print(p.resolve())    # /home/user/project/data/train.csv
```

**In ML projects:** always resolve paths at startup and pass `Path` objects (not strings) throughout. This eliminates the entire class of "works on my machine" path bugs.

## The `os.path` Interface — Legacy Reference

You will encounter this in older code. Knowing it is necessary:

```python
import os

os.path.join("data", "train", "img.png")   # "data/train/img.png"
os.path.basename("/data/train/img.png")    # "img.png"
os.path.dirname("/data/train/img.png")     # "/data/train"
os.path.splitext("img.png")               # ("img", ".png")
os.path.exists("data/train.csv")           # True/False
os.path.isfile("data/train.csv")           # True/False
os.path.isdir("data/train")               # True/False
os.path.abspath("data/train.csv")          # absolute path string
os.path.expanduser("~/project")           # expands ~ to home dir
os.getcwd()                                # current working directory
os.listdir("data")                         # list directory contents
os.makedirs("output/run_01", exist_ok=True) # mkdir -p
```

`os.path.join` is the critical one — never use string concatenation for paths. `"data" + "/" + "train"` breaks on Windows.

**The `pathlib` equivalents:**

|`os.path`|`pathlib.Path`|
|---|---|
|`os.path.join(a, b)`|`Path(a) / b`|
|`os.path.basename(p)`|`p.name`|
|`os.path.dirname(p)`|`p.parent`|
|`os.path.splitext(p)`|`(p.stem, p.suffix)`|
|`os.path.exists(p)`|`p.exists()`|
|`os.path.abspath(p)`|`p.resolve()`|
|`os.path.expanduser(p)`|`Path(p).expanduser()`|
|`os.makedirs(p, exist_ok=True)`|`p.mkdir(parents=True, exist_ok=True)`|
|`os.getcwd()`|`Path.cwd()`|

## Interoperability — Strings vs. Path Objects

Most Python stdlib functions accept both strings and `Path` objects. But older third-party libraries sometimes require strings. Convert explicitly:

```python
p = Path("data/train.csv")

str(p)          # "data/train.csv"    — explicit conversion
os.fspath(p)    # "data/train.csv"    — the official protocol (PEP 519)

# Most stdlib functions accept Path directly
open(p)         # works
os.stat(p)      # works

# If a library requires a string
old_library.load(str(p))
```

`os.fspath()` is the right way to convert — it calls `p.__fspath__()`, which is the official protocol for path-like objects defined in PEP 519.

## Patterns — Building a File Hierarchy Programmatically

This is the pattern you will write constantly in ML projects:

```python
from pathlib import Path

def build_project_dirs(root: str | Path, run_name: str) -> dict:
    root = Path(root)
    dirs = {
        "data":        root / "data",
        "checkpoints": root / "checkpoints" / run_name,
        "logs":        root / "logs" / run_name,
        "outputs":     root / "outputs" / run_name,
    }
    for d in dirs.values():
        d.mkdir(parents=True, exist_ok=True)
    return dirs

dirs = build_project_dirs("project", "resnet50_baseline")
print(dirs["checkpoints"])
# project/checkpoints/resnet50_baseline
```

And for loading a dataset where every class is a subdirectory:

```python
data_root = Path("data/imagenet/train")
class_dirs = sorted(d for d in data_root.iterdir() if d.is_dir())

dataset = {}
for class_dir in class_dirs:
    images = sorted(class_dir.glob("*.JPEG"))
    dataset[class_dir.name] = images

print(f"{len(dataset)} classes, "
      f"{sum(len(v) for v in dataset.values())} images")
```

## Connection to AI / Machine Learning / Deep Learning

File path handling is the unglamorous foundation of every ML pipeline. Bugs here surface as `FileNotFoundError` at 3am during a training run, or silently corrupt your train/test split by loading the wrong directory.

### Dataset Loading — `torchvision.datasets.ImageFolder`

`ImageFolder` is a standard PyTorch dataset that reads an ImageNet-style directory:

```
data/
├── train/
│   ├── cat/     img_001.jpg  img_002.jpg ...
│   └── dog/     img_001.jpg  img_002.jpg ...
└── val/
    ├── cat/
    └── dog/
```

```python
from torchvision import datasets, transforms
from pathlib import Path

data_root = Path("data")

train_dataset = datasets.ImageFolder(
    root=data_root / "train",
    transform=transforms.Compose([
        transforms.Resize(256),
        transforms.CenterCrop(224),
        transforms.ToTensor(),
    ])
)

print(train_dataset.classes)      # ['cat', 'dog']
print(train_dataset.class_to_idx) # {'cat': 0, 'dog': 1}
```

The directory structure _is_ the label. Getting the paths wrong here corrupts your entire dataset.

### Custom Dataset — Walking a Directory Tree

```python
import torch
from torch.utils.data import Dataset
from pathlib import Path
from PIL import Image

class ImageDataset(Dataset):
    def __init__(self, root: Path, transform=None):
        self.root = Path(root)
        self.transform = transform
        # rglob collects all images across nested subdirectories
        self.image_paths = sorted(self.root.rglob("*.jpg"))

    def __len__(self):
        return len(self.image_paths)

    def __getitem__(self, idx):
        path = self.image_paths[idx]
        image = Image.open(path).convert("RGB")
        if self.transform:
            image = self.transform(image)
        return image, str(path)   # return path for debugging
```

### Checkpoint Management

```python
from pathlib import Path
import torch

def save_checkpoint(model, optimizer, epoch, loss, ckpt_dir: Path):
    ckpt_dir.mkdir(parents=True, exist_ok=True)
    path = ckpt_dir / f"epoch_{epoch:04d}_loss_{loss:.4f}.pt"
    torch.save({
        "epoch": epoch,
        "model_state_dict": model.state_dict(),
        "optimizer_state_dict": optimizer.state_dict(),
        "loss": loss,
    }, path)
    return path

def load_latest_checkpoint(ckpt_dir: Path):
    checkpoints = sorted(ckpt_dir.glob("epoch_*.pt"))
    if not checkpoints:
        return None
    latest = checkpoints[-1]    # sorted alphabetically → latest epoch last
    return torch.load(latest)
```

`f"epoch_{epoch:04d}"` zero-pads to 4 digits, so lexicographic sort and numeric sort agree. This is the kind of detail that saves you from loading the wrong checkpoint.

### Configuration and Reproducibility

```python
from pathlib import Path
import json

def setup_experiment(config: dict) -> Path:
    run_dir = Path("runs") / config["run_name"]
    run_dir.mkdir(parents=True, exist_ok=True)

    # Save config alongside the run for reproducibility
    config_path = run_dir / "config.json"
    config_path.write_text(json.dumps(config, indent=2))

    return run_dir

run_dir = setup_experiment({
    "run_name": "resnet50_lr1e-3_bs256",
    "learning_rate": 1e-3,
    "batch_size": 256,
    "epochs": 90,
})
```

Every experiment writes its own config, checkpoints, and logs into an isolated directory. Reproducibility is a path discipline problem as much as a code discipline problem.

## Common Mistakes and Pitfalls

**1. String concatenation for paths**

```python
# Wrong — breaks on Windows, ugly, error-prone
path = base + "/" + subdir + "/" + filename

# Right
path = Path(base) / subdir / filename
```

**2. Hardcoded absolute paths**

```python
# Wrong — only works on your machine
data = Path("/home/yourname/project/data/train.csv")

# Right — relative to project root, or from an environment variable
data = Path("data/train.csv")
data = Path(os.environ["DATA_ROOT"]) / "train.csv"
```

**3. Not resolving paths before storing them**

```python
# If cwd changes during execution, relative paths break
p = Path("data/train.csv")

# Resolve immediately to an absolute path
p = Path("data/train.csv").resolve()
```

**4. Iterating `rglob` multiple times**

`rglob` returns a generator — it is consumed after one pass:

```python
files = path.rglob("*.png")
count = sum(1 for _ in files)    # generator exhausted
first = next(iter(files))        # StopIteration — nothing left

# Fix: materialise into a list immediately
files = sorted(path.rglob("*.png"))
```

**5. Assuming directory exists before writing**

```python
# Wrong — FileNotFoundError if parent dirs don't exist
Path("output/run_01/logs/train.log").write_text("...")

# Right
log_path = Path("output/run_01/logs/train.log")
log_path.parent.mkdir(parents=True, exist_ok=True)
log_path.write_text("...")
```

## Summary

|Task|`pathlib`|`os.path`|
|---|---|---|
|Join paths|`Path(a) / b / c`|`os.path.join(a, b, c)`|
|Filename|`p.name`|`os.path.basename(p)`|
|Directory|`p.parent`|`os.path.dirname(p)`|
|Extension|`p.suffix`|`os.path.splitext(p)[1]`|
|Exists?|`p.exists()`|`os.path.exists(p)`|
|Absolute|`p.resolve()`|`os.path.abspath(p)`|
|Make dirs|`p.mkdir(parents=True, exist_ok=True)`|`os.makedirs(p, exist_ok=True)`|
|List dir|`p.iterdir()`|`os.listdir(p)`|
|Glob|`p.glob("*.png")`|`glob.glob(str(p / "*.png"))`|
|Recursive glob|`p.rglob("*.png")`|`glob.glob(str(p / "**/*.png"), recursive=True)`|

**Mental model:** a `Path` object is a smart string that knows it represents a location in the file system. The `/` operator is path joining. Methods that end in questions (`exists()`, `is_file()`) query the OS. Methods that sound like verbs (`mkdir()`, `unlink()`, `rename()`) modify the OS. Methods that return new `Path` objects (`with_suffix()`, `relative_to()`) compute without touching disk.
