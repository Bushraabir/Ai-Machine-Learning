# 25. Recursion

## What is Recursion

Recursion is a technique where a function **calls itself** to solve a smaller version of the same problem. The key insight is that many problems have a self-similar structure — the solution to the full problem can be expressed in terms of solutions to smaller instances of the same problem.

```python
def countdown(n):
    if n == 0:
        print("Done")
        return
    print(n)
    countdown(n - 1)   # function calls itself with a smaller input

countdown(3)
# 3
# 2
# 1
# Done
```

This is not a trick or shortcut. Recursion is a **fundamental computational model** — it is how compilers think, how tree structures are traversed, how search algorithms explore spaces, and how mathematical induction maps to code.

---

## The Two Mandatory Parts

Every correct recursive function has exactly two parts. Missing either one produces broken code.

### 1. Base Case — The Stopping Condition

The input so small that the answer is known directly, without recursion.

```python
if n == 0:
    return 1
```

Without a base case, the function recurses forever until Python raises a `RecursionError`.

### 2. Recursive Case — The Self-Similar Step

The function calls itself with a **strictly smaller** input, moving toward the base case.

```python
return n * factorial(n - 1)
```

The input must get smaller on every call. If it doesn't converge toward the base case, you have infinite recursion.

---

## Anatomy of a Recursive Call — The Call Stack

Understanding what Python actually does is non-negotiable. Each function call creates a **stack frame** — a block of memory holding that call's local variables and return address. Recursive calls stack these frames on top of each other.

```python
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)

factorial(4)
```

**Call stack — growing down, resolving upward:**

```
factorial(4)  →  4 * factorial(3)
                     factorial(3)  →  3 * factorial(2)
                                          factorial(2)  →  2 * factorial(1)
                                                               factorial(1)  →  1 * factorial(0)
                                                                                    factorial(0)  →  1  ← BASE CASE

# Now unwinds:
factorial(1)  →  1 * 1  =  1
factorial(2)  →  2 * 1  =  2
factorial(3)  →  3 * 2  =  6
factorial(4)  →  4 * 6  =  24
```

Each frame is only resolved **after** all frames below it return. This is why recursive functions appear to "wait" — they are literally suspended mid-execution on the stack.

## Canonical Examples — From Simple to Deep

### Factorial

```python
def factorial(n):
    """n! = n * (n-1) * ... * 1.  Base case: 0! = 1"""
    if n == 0:          # base case
        return 1
    return n * factorial(n - 1)   # recursive case

print(factorial(5))    # 120
print(factorial(0))    # 1
```

**Mathematical structure being expressed:**

```
0! = 1
n! = n × (n-1)!
```

The code is a direct translation of the mathematical definition. This is the recursive mindset.

---

### Fibonacci

```python
def fib(n):
    """fib(0)=0, fib(1)=1, fib(n)=fib(n-1)+fib(n-2)"""
    if n <= 1:              # two base cases
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(6))   # 8  (0,1,1,2,3,5,8)
```

This naive implementation has **exponential time complexity O(2^n)** — `fib(50)` takes minutes. Every subproblem is recomputed from scratch multiple times. This is the canonical example that motivates **memoization**.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(50))   # 12586269025 — instant
```

`lru_cache` stores results of previous calls. The time complexity drops to O(n). This pattern — recursion + memoization — is **dynamic programming**.

---

### Sum of a List

```python
def sum_list(lst):
    if not lst:           # base case: empty list
        return 0
    return lst[0] + sum_list(lst[1:])   # head + sum of tail

print(sum_list([1, 2, 3, 4, 5]))   # 15
```

**Mental model:** A list is either empty, or a head element followed by a smaller list. This head/tail decomposition is how functional languages think about all list operations.

---

### Binary Search

```python
def binary_search(arr, target, lo, hi):
    if lo > hi:                     # base case: not found
        return -1

    mid = (lo + hi) // 2

    if arr[mid] == target:          # base case: found
        return mid
    elif arr[mid] < target:
        return binary_search(arr, target, mid + 1, hi)   # search right half
    else:
        return binary_search(arr, target, lo, mid - 1)   # search left half

arr = [2, 5, 8, 12, 16, 23, 38, 56]
print(binary_search(arr, 23, 0, len(arr) - 1))   # 5
print(binary_search(arr, 10, 0, len(arr) - 1))   # -1
```

Each recursive call eliminates half the search space. Time complexity: O(log n). The recursive structure mirrors the divide-and-conquer logic cleanly.

### Tree Traversal

Recursion's most natural domain. Trees are inherently recursive structures — a tree is either empty, or a node with subtrees that are themselves trees.

```python
class Node:
    def __init__(self, val, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def inorder(node):
    """Left → Root → Right"""
    if node is None:       # base case
        return
    inorder(node.left)
    print(node.val)
    inorder(node.right)

#         4
#        / \
#       2   6
#      / \ / \
#     1  3 5  7

root = Node(4, Node(2, Node(1), Node(3)), Node(6, Node(5), Node(7)))
inorder(root)   # 1 2 3 4 5 6 7
```

No iterative solution can match this in clarity. The recursive call stack _is_ the traversal algorithm.

### Power Function — Efficient Exponentiation

```python
def power(base, exp):
    """Computes base^exp in O(log exp) instead of O(exp)"""
    if exp == 0:
        return 1
    if exp % 2 == 0:
        half = power(base, exp // 2)
        return half * half            # avoid calling twice
    return base * power(base, exp - 1)

print(power(2, 10))   # 1024
print(power(3, 5))    # 243
```

This is **fast exponentiation** — a divide-and-conquer strategy. It reduces O(n) multiplications to O(log n).

## Recursion vs Iteration — When to Use Which

|Factor|Recursion|Iteration|
|---|---|---|
|Problem structure|Self-similar / tree / graph|Linear / sequential|
|Code clarity|Often cleaner for divide-and-conquer|Cleaner for simple loops|
|Stack usage|O(depth) stack frames|O(1)|
|Risk|Stack overflow on deep input|None|
|Performance|Function call overhead per frame|Generally faster|
|Tail call optimization|Python does NOT optimize|N/A|

**Use recursion when:** the problem decomposes naturally into identical subproblems (trees, graphs, divide-and-conquer algorithms, mathematical induction). Use iteration when: the problem is a simple linear scan or accumulation.

Every recursive solution can be converted to iteration using an explicit stack. Python sometimes forces this due to recursion depth limits.

---

## Python's Recursion Limit

Python enforces a maximum call stack depth (default: 1000 frames) to prevent stack overflow from crashing the interpreter.

```python
import sys

print(sys.getrecursionlimit())   # 1000

# You can raise it — but this is a workaround, not a fix
sys.setrecursionlimit(10000)
```

```python
def infinite(n):
    return infinite(n + 1)

infinite(0)   # RecursionError: maximum recursion depth exceeded
```

If you hit the recursion limit, the right fix is usually to convert to iteration or apply memoization — not to raise the limit.

## Tail Recursion — Why Python Doesn't Optimize It

In some languages (Scheme, Haskell, modern JavaScript), a recursive call in **tail position** (the very last operation before returning) is optimized: the compiler reuses the current stack frame instead of creating a new one, making it as efficient as a loop.

```python
# Tail-recursive factorial (the recursive call is the LAST operation)
def factorial_tail(n, accumulator=1):
    if n == 0:
        return accumulator
    return factorial_tail(n - 1, accumulator * n)   # tail call
```

Python **does not perform tail call optimization**. Every call still creates a new frame. Guido van Rossum deliberately chose not to add this, arguing that stack traces become unreadable with TCO. Accept this and use iteration or `lru_cache` when depth is a concern.

## Memoization — Caching Recursive Results

When a recursive function recomputes the same subproblems repeatedly, cache the results.

```python
# Manual memoization with a dictionary
def fib(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]
```

**Warning on mutable default arguments:** Using `memo={}` as a default is a Python footgun — the dict persists across calls (it's created once at function definition, not per call). It works here intentionally, but is generally a bad pattern. Prefer `lru_cache` or pass the cache explicitly.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
```

## Designing a Recursive Solution — The 3-Step Method

When you encounter a problem, apply this process:

**Step 1 — Identify the base case(s)** What is the smallest input where the answer is trivially known?

**Step 2 — Assume the recursive call works** Pretend `f(smaller_input)` already returns the correct answer. What do you do with it to solve `f(n)`?

**Step 3 — Ensure progress toward the base case** Does every recursive call use a strictly smaller input? If not, you have infinite recursion.

```
Problem: Count occurrences of x in a list

Step 1: Base case → empty list → count is 0
Step 2: If head == x, count = 1 + count(tail). Else count = count(tail).
Step 3: Each call uses lst[1:], which is shorter. ✓
```

```python
def count(lst, x):
    if not lst:
        return 0
    return (1 if lst[0] == x else 0) + count(lst[1:], x)

print(count([1, 2, 1, 3, 1], 1))   # 3
```

## Mutual Recursion

Two functions that call each other. Less common but valid.

```python
def is_even(n):
    if n == 0:
        return True
    return is_odd(n - 1)

def is_odd(n):
    if n == 0:
        return False
    return is_even(n - 1)

print(is_even(4))   # True
print(is_odd(7))    # True
```

Both functions must be defined before either is called. The base case must still exist in the mutual chain.

## Common Errors

```python
# 1. Missing base case → infinite recursion
def bad_factorial(n):
    return n * bad_factorial(n - 1)   # never stops
    # RecursionError

# 2. Base case never reached — wrong condition
def bad_sum(n):
    if n == 0:
        return 0
    return n + bad_sum(n + 1)   # n grows, never hits 0
    # RecursionError

# 3. Wrong return — forgetting to return the recursive call
def bad_search(lst, x):
    if not lst:
        return False
    if lst[0] == x:
        return True
    bad_search(lst[1:], x)   # ← missing return → always returns None

# Fix:
    return bad_search(lst[1:], x)

# 4. Off-by-one in base case
def bad_fib(n):
    if n == 0:       # missing n == 1 case
        return 0
    return bad_fib(n - 1) + bad_fib(n - 2)
    # bad_fib(1) → bad_fib(0) + bad_fib(-1) → infinite descent
```
