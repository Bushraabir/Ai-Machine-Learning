# 24. Lambda Functions

## What is a Lambda Function

A lambda function is an **anonymous function** — a function defined without a name, in a single expression, using the `lambda` keyword. It is not a replacement for `def`; it is a tool for situations where defining a full function would be disproportionately verbose.

```python
# Regular function
def square(x):
    return x ** 2

# Equivalent lambda
square = lambda x: x ** 2

print(square(5))   # 25
```

The name `square` here is just a variable binding — the lambda itself is nameless. Assigning a lambda to a variable and then calling it defeats most of the purpose; the real power is in passing lambdas _inline_.

---

## Syntax

```
lambda <parameters> : <expression>
```

- **`lambda`** — keyword
- **`<parameters>`** — zero or more comma-separated inputs (same rules as `def`)
- **`:`** — separator
- **`<expression>`** — a single expression whose value is automatically returned

```python
# Zero parameters
greet = lambda: "Hello"
print(greet())          # Hello

# One parameter
double = lambda x: x * 2
print(double(7))        # 14

# Multiple parameters
add = lambda x, y: x + y
print(add(3, 4))        # 7

# With default argument
power = lambda x, n=2: x ** n
print(power(3))         # 9
print(power(3, 3))      # 27
```

**Critical constraint**: A lambda body must be a single **expression**, not a statement. No `if/else` blocks, no `for` loops, no `return`, no assignments.

```python
# Valid — ternary expression IS an expression
clamp = lambda x: x if x > 0 else 0

# Invalid — if/else block is a statement, not an expression
# lambda x: if x > 0: return x   ← SyntaxError
```

## Where Lambdas Are Actually Useful

### 1. `sorted()` — Custom Sort Keys

The `key` parameter of `sorted()` accepts any callable. Lambdas are perfect here.

```python
students = [("Alice", 88), ("Bob", 95), ("Carol", 72)]

# Sort by score (index 1)
by_score = sorted(students, key=lambda s: s[1])
print(by_score)
# [('Carol', 72), ('Alice', 88), ('Bob', 95)]

# Sort by name length
by_name_len = sorted(students, key=lambda s: len(s[0]))
print(by_name_len)
# [('Bob', 95), ('Alice', 88), ('Carol', 72)]

# Sort descending
by_score_desc = sorted(students, key=lambda s: s[1], reverse=True)
print(by_score_desc)
# [('Bob', 95), ('Alice', 88), ('Carol', 72)]
```

### 2. `map()` — Applying a Transformation

```python
numbers = [1, 2, 3, 4, 5]

squared = list(map(lambda x: x ** 2, numbers))
print(squared)   # [1, 4, 9, 16, 25]

# With two iterables
a = [1, 2, 3]
b = [10, 20, 30]
sums = list(map(lambda x, y: x + y, a, b))
print(sums)      # [11, 22, 33]
```

### 3. `filter()` — Selecting Elements

```python
numbers = range(-5, 6)

positives = list(filter(lambda x: x > 0, numbers))
print(positives)   # [1, 2, 3, 4, 5]

evens = list(filter(lambda x: x % 2 == 0, numbers))
print(evens)       # [-4, -2, 0, 2, 4]
```

### 4. Immediately Invoked Lambda

Call the lambda right where it is defined. Rare in Python, but valid.

```python
result = (lambda x, y: x * y)(6, 7)
print(result)   # 42
```

### 5. Inside `min()` / `max()`

```python
data = [{"name": "Alice", "age": 30}, {"name": "Bob", "age": 25}]

youngest = min(data, key=lambda d: d["age"])
print(youngest)   # {'name': 'Bob', 'age': 25}
```

## Lambda vs `def` — When to Use Which

|Situation|Use|
|---|---|
|Short throwaway key/callback, used once|`lambda`|
|Any logic requiring statements (`for`, `if/else` block, `try`)|`def`|
|Function you will call by name in multiple places|`def`|
|Needs a docstring|`def`|
|Needs more than one expression|`def`|

PEP 8 explicitly discourages assigning a lambda to a variable name:

```python
# PEP 8 discourages this
double = lambda x: x * 2

# Prefer this
def double(x):
    return x * 2
```

The reason: `def` gives a function a proper `__name__` attribute, which aids debugging and stack traces. A named lambda still shows as `<lambda>` in tracebacks.

## Lambdas and Closures

A lambda captures variables from its enclosing scope — it forms a **closure**, just like a nested `def`.

```python
def make_multiplier(n):
    return lambda x: x * n

triple = make_multiplier(3)
print(triple(7))    # 21
print(triple(10))   # 30
```

**Classic closure trap — late binding:**

```python
# Bug: all lambdas capture the same variable i
funcs = [lambda x: x * i for i in range(5)]
print(funcs[0](1))   # 4, not 0 — i is 4 when called
print(funcs[2](1))   # 4

# Fix: bind i at definition time with a default argument
funcs = [lambda x, i=i: x * i for i in range(5)]
print(funcs[0](1))   # 0
print(funcs[2](1))   # 2
```

This late-binding behavior is identical to closures formed with `def`. The default-argument fix works for both.

## Lambdas in ML/Data Code

You will encounter lambdas constantly in NumPy, Pandas, and PyTorch pipelines:

```python
import pandas as pd

df = pd.DataFrame({"score": [55, 78, 92, 41, 88]})

# Apply a transformation row-by-row
df["grade"] = df["score"].apply(lambda x: "pass" if x >= 60 else "fail")
print(df)
#    score grade
# 0     55  fail
# 1     78  pass
# 2     92  pass
# 3     41  fail
# 4     88  pass
```

In PyTorch, custom transforms for datasets are often lambdas:

```python
from torchvision import transforms

transform = transforms.Lambda(lambda x: x / 255.0)
```

## Internal Model — What `lambda` Really Is

A `lambda` expression evaluates to a **function object**, exactly like `def` creates one. The difference is purely syntactic — lambda is limited to a single expression body.

```python
f = lambda x: x + 1

print(type(f))        # <class 'function'>
print(f.__name__)     # <lambda>
print(f.__code__)     # <code object <lambda> at ...>
```

The interpreter compiles the lambda body into a code object at definition time. When called, it executes that code object and returns the expression's value.

---

## Common Errors

```python
# SyntaxError: lambda body cannot contain assignment
bad = lambda x: (y = x + 1)   # ← invalid

# SyntaxError: no return statement allowed
bad = lambda x: return x       # ← invalid

# TypeError: calling with wrong number of args
f = lambda x, y: x + y
f(1)                            # TypeError: missing 1 required argument

# Silent bug: late binding in loops (see Closures section)
funcs = [lambda x: x * i for i in range(5)]   # all capture final i
```

## Summary Table

|Feature|Behavior|
|---|---|
|Syntax|`lambda params: expression`|
|Return|Implicit — the expression value|
|Body|Single expression only|
|Parameters|All types: positional, default, `*args`, `**kwargs`|
|Name|Always `<lambda>` in tracebacks|
|Closure|Yes — captures enclosing scope|
|Type|`function` — identical to `def` objects|
|PEP 8|Do not assign to a variable name|
