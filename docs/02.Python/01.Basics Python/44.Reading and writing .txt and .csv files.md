# 44. Reading and Writing `.txt` and `.csv` Files

> _"A file is a sequence of bytes on disk. Everything else — lines, fields, rows, headers — is an interpretation layered on top of that sequence. Understanding the layers prevents you from conflating them."_

---

## The Conceptual Stack

Before any code, understand what you are actually working with:

```
Your Python objects   (strings, lists, dicts)
        ↕   encode / decode
Text layer            (Unicode characters, lines, fields)
        ↕   read / write
Bytes layer           (raw bytes on disk)
        ↕   OS file system
Physical storage      (SSD, HDD, network)
```

`open()` operates at the text layer by default — it handles the bytes-to-characters translation for you via an encoding (almost always UTF-8). The `csv` module operates one layer above that — it handles the characters-to-fields translation. Knowing which layer a problem lives on tells you which tool to reach for.

---

## `open()` — The Gateway

Every file operation in Python flows through `open()`.

```python
open(file, mode='r', encoding=None, newline=None, errors='strict')
```

### Mode strings

|Mode|Meaning|File must exist?|Truncates?|
|---|---|---|---|
|`'r'`|Read text|Yes|No|
|`'w'`|Write text|No (creates)|Yes|
|`'a'`|Append text|No (creates)|No|
|`'x'`|Exclusive create|No (fails if exists)|—|
|`'r+'`|Read + write|Yes|No|
|`'rb'`|Read binary|Yes|No|
|`'wb'`|Write binary|No (creates)|Yes|

**Always specify encoding explicitly.** The default is platform-dependent — `cp1252` on Windows, `utf-8` on Linux/macOS. A file written on one machine may fail to read on another if encoding is left implicit.

```python
# Fragile — encoding depends on the OS
f = open("data.txt")

# Correct — explicit, portable
f = open("data.txt", encoding="utf-8")
```

### Always use `with`

```python
with open("data.txt", encoding="utf-8") as f:
    content = f.read()
# file is closed here automatically — even if an exception was raised inside the block
```

The `with` statement calls `f.__exit__()` on exit, which calls `f.close()`. Without `with`, an uncaught exception between `open()` and `f.close()` leaves the file handle open — a resource leak. On long-running ML training processes, accumulated open handles exhaust OS file descriptor limits. Always use `with`.

## Reading `.txt` Files

Three reading methods, three different use cases:

### `read()` — entire file as one string

```python
with open("notes.txt", encoding="utf-8") as f:
    content = f.read()

type(content)   # str
```

Reads the entire file into memory at once. Correct for small files. For files larger than available RAM — multi-gigabyte datasets — this will crash with `MemoryError`. Use line-by-line iteration instead.

### `readline()` — one line at a time

```python
with open("data.txt", encoding="utf-8") as f:
    first  = f.readline()   # "header line\n"
    second = f.readline()   # "first data line\n"
    third  = f.readline()   # "" — empty string signals EOF
```

The newline character `\n` is included in the returned string. An empty string `""` — not `"\n"` — signals end of file. This distinction matters:

```python
with open("data.txt", encoding="utf-8") as f:
    while True:
        line = f.readline()
        if not line:       # EOF — empty string is falsy
            break
        process(line.rstrip("\n"))
```

### `readlines()` — all lines as a list

```python
with open("data.txt", encoding="utf-8") as f:
    lines = f.readlines()

# lines = ["line one\n", "line two\n", "line three\n"]
```

Each element retains its `\n`. Strip it when needed:

```python
lines = [line.rstrip("\n") for line in lines]
```

`readlines()` loads everything into memory — same caveat as `read()` for large files.

### Iterating the file object directly — the idiomatic pattern

```python
with open("data.txt", encoding="utf-8") as f:
    for line in f:             # file object is its own iterator
        process(line.rstrip())
```

This is the most memory-efficient pattern. Python reads one line at a time from disk, discards it after processing, and never holds the entire file in memory. For large text corpora — the kind used in NLP pre-training — this is not optional. It is the only viable approach.

```python
# Counting lines in a large file without loading it
count = 0
with open("corpus.txt", encoding="utf-8") as f:
    for _ in f:
        count += 1
```

## Writing `.txt` Files

### `write()` — write a string

```python
with open("output.txt", "w", encoding="utf-8") as f:
    f.write("first line\n")
    f.write("second line\n")
```

`write()` does not add a newline automatically. You must include `\n` explicitly. The return value is the number of characters written — usually ignored.

### `writelines()` — write a list of strings

```python
lines = ["alpha\n", "beta\n", "gamma\n"]

with open("output.txt", "w", encoding="utf-8") as f:
    f.writelines(lines)
```

`writelines()` does not add newlines between elements. The newlines must already be in the strings. It is exactly equivalent to calling `write()` for each element in sequence — no separator is inserted.

### Appending vs. overwriting

```python
# 'w' — overwrites. Every run starts fresh.
with open("log.txt", "w", encoding="utf-8") as f:
    f.write("run started\n")

# 'a' — appends. Adds to the end of existing content.
with open("log.txt", "a", encoding="utf-8") as f:
    f.write(f"epoch 1 loss: 0.342\n")
```

Append mode is the correct choice for logs that accumulate across training runs.

## The `newline` Parameter — A Precision Detail

On Windows, the default text mode translates `\n` to `\r\n` on write and `\r\n` back to `\n` on read. This is usually invisible — until you are writing a CSV file and Excel opens it with blank rows between every data row.

```python
# Safe, platform-consistent CSV writing
with open("data.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    ...
```

`newline=""` disables Python's newline translation entirely and lets the `csv` module handle line endings itself. The `csv` module documentation explicitly requires this. For plain text files you do not intend to process as CSV, the default (`newline=None`) is fine.

## The `csv` Module

A CSV (Comma-Separated Values) file is a text file where each line is a record and fields within a line are separated by a delimiter (usually a comma). The interpretation is not trivial — fields can be quoted, quotes can be escaped, delimiters can appear inside quoted fields, and different systems use different conventions. Do not parse CSV with `str.split(",")`.

```python
# This breaks on:  Alice,"Smith, Jr.",30
line.split(",")   # ['Alice', '"Smith', ' Jr."', '30']  — WRONG

# The csv module handles it correctly:
import csv
```

### Reading CSV

#### `csv.reader` — rows as lists

```python
import csv

with open("data.csv", encoding="utf-8", newline="") as f:
    reader = csv.reader(f)
    for row in reader:
        print(row)   # each row is a list of strings
```

```
# data.csv
name,age,score
Alice,30,98.5
Bob,25,87.0

# Output:
['name', 'age', 'score']
['Alice', '30', '98.5']
['Bob', '25', '87.0']
```

**Important:** every field is a string. `'30'` is not `30`. Convert explicitly:

```python
with open("data.csv", encoding="utf-8", newline="") as f:
    reader = csv.reader(f)
    next(reader)    # skip header row
    for name, age, score in reader:
        age   = int(age)
        score = float(score)
```

#### `csv.DictReader` — rows as dicts

```python
with open("data.csv", encoding="utf-8", newline="") as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(row)
```

```
{'name': 'Alice', 'age': '30', 'score': '98.5'}
{'name': 'Bob',   'age': '25', 'score': '87.0'}
```

`DictReader` reads the first row as field names and maps each subsequent row to an `OrderedDict` (Python 3.8+: a regular `dict` preserving insertion order). This is almost always preferable to `csv.reader` because it is self-documenting and robust to column reordering.

```python
with open("features.csv", encoding="utf-8", newline="") as f:
    reader = csv.DictReader(f)
    records = []
    for row in reader:
        records.append({
            "name":  row["name"],
            "age":   int(row["age"]),
            "score": float(row["score"]),
        })
```

### Writing CSV

#### `csv.writer` — write rows as lists

```python
import csv

rows = [
    ["name", "age", "score"],
    ["Alice", 30, 98.5],
    ["Bob", 25, 87.0],
]

with open("output.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerows(rows)    # write all rows at once
```

Or write one row at a time:

```python
with open("output.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["name", "age", "score"])    # header
    for record in data:
        writer.writerow([record.name, record.age, record.score])
```

#### `csv.DictWriter` — write rows as dicts

```python
fieldnames = ["name", "age", "score"]
records = [
    {"name": "Alice", "age": 30, "score": 98.5},
    {"name": "Bob",   "age": 25, "score": 87.0},
]

with open("output.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=fieldnames)
    writer.writeheader()       # writes the fieldnames row
    writer.writerows(records)
```

`DictWriter` requires `fieldnames` to be declared upfront. If a dict row contains a key not in `fieldnames`, it raises `ValueError`. If a dict row is missing a key, it writes an empty field (configurable via `extrasaction` and `restval`).

## Dialects and Delimiters

CSV is not a strict standard. Different systems use different separators and quoting rules. The `csv` module handles this through the `dialect` system.

```python
# Tab-separated values (TSV) — common in NLP datasets
with open("data.tsv", encoding="utf-8", newline="") as f:
    reader = csv.reader(f, delimiter="\t")

# Semicolon-separated — common in European locales (Excel default when locale uses comma as decimal)
with open("data.csv", encoding="utf-8", newline="") as f:
    reader = csv.reader(f, delimiter=";")

# Pipe-separated
with open("data.txt", encoding="utf-8", newline="") as f:
    reader = csv.reader(f, delimiter="|")
```

```python
# Inspecting the default dialect
import csv
print(csv.get_dialect("excel"))
# delimiter=',', quotechar='"', quoting=QUOTE_MINIMAL, lineterminator='\r\n'
```

### Quoting modes

```python
csv.QUOTE_MINIMAL    # default — only quote fields that contain delimiter, quotechar, or newline
csv.QUOTE_ALL        # quote every field
csv.QUOTE_NONNUMERIC # quote all non-numeric fields; reader converts unquoted to float
csv.QUOTE_NONE       # never quote — raises if delimiter appears in field
```

## Encoding Errors — `errors` Parameter

When a file contains bytes that are invalid for the declared encoding:

```python
# Default — raises UnicodeDecodeError on first invalid byte
open("data.txt", encoding="utf-8", errors="strict")

# Replaces invalid bytes with the replacement character U+FFFD (�)
open("data.txt", encoding="utf-8", errors="replace")

# Silently skips invalid bytes
open("data.txt", encoding="utf-8", errors="ignore")

# Detect encoding automatically (requires chardet or charset_normalizer)
import chardet
with open("data.txt", "rb") as f:
    raw = f.read()
detected = chardet.detect(raw)
text = raw.decode(detected["encoding"])
```

In ML data pipelines, `errors="replace"` is usually the right choice for text corpora — you want to continue processing and mark the problematic bytes visually rather than crash.

## Large File Patterns

### Streaming line by line — the universal pattern

```python
def stream_lines(path, encoding="utf-8"):
    with open(path, encoding=encoding) as f:
        for line in f:
            yield line.rstrip("\n")

for line in stream_lines("corpus.txt"):
    tokens = tokenize(line)
    # processes one line, then discards it — constant memory
```

### Streaming CSV rows

```python
def stream_csv(path, encoding="utf-8"):
    with open(path, encoding=encoding, newline="") as f:
        reader = csv.DictReader(f)
        for row in reader:
            yield row

for row in stream_csv("large_dataset.csv"):
    features = extract_features(row)
    # one row in memory at a time
```

### Chunked reading for binary analysis

```python
CHUNK_SIZE = 1024 * 1024   # 1 MB

with open("large_file.bin", "rb") as f:
    while True:
        chunk = f.read(CHUNK_SIZE)
        if not chunk:
            break
        process(chunk)
```

## Seeking — Random Access

File objects maintain a position pointer. You can move it explicitly.

```python
with open("data.txt", encoding="utf-8") as f:
    f.read(10)        # read 10 characters — pointer moves to position 10
    f.tell()          # 10 — current position
    f.seek(0)         # rewind to the start
    f.read(10)        # same 10 characters again

    f.seek(0, 2)      # seek to end (offset 0 from end)
    f.tell()          # total file size in bytes
```

`seek()` takes an optional `whence` argument: `0` = from start (default), `1` = from current position, `2` = from end. In text mode, only `seek(0)` (rewind) and positions returned by `tell()` are reliable — arbitrary seeks in text mode are not portable because multi-byte encodings make byte position ≠ character position.

## Practical Patterns

### Reading a config or results file

```python
def read_results(path):
    results = {}
    with open(path, encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if not line or line.startswith("#"):   # skip blank lines and comments
                continue
            key, _, value = line.partition("=")
            results[key.strip()] = value.strip()
    return results
```

### Writing a training log

```python
import csv
from datetime import datetime

log_fields = ["timestamp", "epoch", "train_loss", "val_loss", "lr"]

def create_log(path):
    with open(path, "w", encoding="utf-8", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=log_fields)
        writer.writeheader()

def append_log(path, epoch, train_loss, val_loss, lr):
    with open(path, "a", encoding="utf-8", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=log_fields)
        writer.writerow({
            "timestamp":  datetime.now().isoformat(),
            "epoch":      epoch,
            "train_loss": f"{train_loss:.6f}",
            "val_loss":   f"{val_loss:.6f}",
            "lr":         f"{lr:.2e}",
        })
```

### Loading a dataset into memory

```python
import csv

def load_dataset(path):
    X, y = [], []
    with open(path, encoding="utf-8", newline="") as f:
        reader = csv.DictReader(f)
        for row in reader:
            features = [float(row[f"feature_{i}"]) for i in range(10)]
            label    = int(row["label"])
            X.append(features)
            y.append(label)
    return X, y
```

## Connection to AI, Machine Learning, and Deep Learning

Text and CSV files are the universal interchange format for ML data. You will use these patterns throughout the entire stack.

### The raw data layer

Before Pandas, before NumPy, before any ML framework, data arrives as files. Every real project begins here: understanding the encoding, the delimiter, whether the header row exists, whether fields are quoted, what the missing value sentinel is.

```python
# The first thing you do with any new dataset
with open("mystery_data.csv", "rb") as f:
    raw = f.read(512)
print(raw)    # look at the raw bytes — encoding, line endings, delimiter
```

### CSV → NumPy → Model

The canonical pipeline:

```python
import csv
import numpy as np

def csv_to_numpy(path, label_col="label"):
    rows = []
    labels = []
    with open(path, encoding="utf-8", newline="") as f:
        reader = csv.DictReader(f)
        feature_cols = [k for k in reader.fieldnames if k != label_col]
        for row in reader:
            rows.append([float(row[c]) for c in feature_cols])
            labels.append(int(row[label_col]))
    X = np.array(rows,   dtype=np.float32)
    y = np.array(labels, dtype=np.int64)
    return X, y

X, y = csv_to_numpy("train.csv")
# X.shape: (n_samples, n_features)
# y.shape: (n_samples,)
```

Once in NumPy, the data is ready for sklearn, PyTorch, or any other framework.

### NLP: reading large text corpora line by line

```python
def build_vocabulary(corpus_path, max_vocab=50000):
    from collections import Counter
    counts = Counter()
    with open(corpus_path, encoding="utf-8") as f:
        for line in f:
            tokens = line.strip().split()
            counts.update(tokens)
    vocab = {"<PAD>": 0, "<UNK>": 1}
    for token, _ in counts.most_common(max_vocab - 2):
        vocab[token] = len(vocab)
    return vocab
```

This processes arbitrarily large corpora in constant memory — the same technique used for building vocabularies over Wikipedia-scale text.

### Writing training metrics for analysis

ML training logs written as CSV can be loaded directly into Pandas for visualisation:

```python
import pandas as pd
import matplotlib.pyplot as plt

log = pd.read_csv("training_log.csv", parse_dates=["timestamp"])
plt.plot(log["epoch"], log["train_loss"], label="train")
plt.plot(log["epoch"], log["val_loss"],   label="val")
plt.legend()
plt.savefig("loss_curve.png")
```

The CSV log you write with `csv.DictWriter` is the data source for `pd.read_csv`. The two tools are complementary: the `csv` module for writing and streaming reads, Pandas for analysis and visualisation.

### Why not just use Pandas from the start?

Pandas `read_csv` is convenient but not transparent. When something goes wrong — wrong encoding, malformed rows, unexpected delimiter — knowing what the `csv` module is doing underneath makes the error interpretable. You cannot debug `pd.read_csv(path, error_bad_lines=False)` without knowing what "bad lines" means at the CSV parsing level.

## Summary Reference

|Operation|Method|Notes|
|---|---|---|
|Read entire file|`f.read()`|Loads all into memory|
|Read one line|`f.readline()`|`""` signals EOF|
|Read all lines to list|`f.readlines()`|Loads all into memory|
|Iterate lines|`for line in f`|Memory-efficient, idiomatic|
|Write string|`f.write(s)`|No automatic newline|
|Write list of strings|`f.writelines(lst)`|No separator added|
|Read CSV to lists|`csv.reader(f)`|All fields are strings|
|Read CSV to dicts|`csv.DictReader(f)`|Uses header row as keys|
|Write CSV from lists|`csv.writer(f).writerow()`|Handles quoting|
|Write CSV from dicts|`csv.DictWriter(f).writerow()`|Requires `fieldnames`|

**Checklist for any file operation:**

- [ ] `with` statement — not bare `open()`
- [ ] `encoding="utf-8"` — explicit, not platform default
- [ ] `newline=""` — for all CSV operations
- [ ] Correct mode (`"r"`, `"w"`, `"a"`) — intentional, not default-assumed
- [ ] Large file? — iterate, do not `read()` or `readlines()`
