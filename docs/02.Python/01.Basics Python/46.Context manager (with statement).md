## The Core Idea

A **context manager** is an object that defines a runtime context — a block of code during which some resource is _guaranteed_ to be acquired before entry and _guaranteed_ to be released on exit, **even if an exception is raised inside the block.**

The `with` statement is the syntactic mechanism that invokes this protocol.

```python
with open("data.txt", "r") as f:
    content = f.read()
# f is closed here — guaranteed, even if read() raised an exception
```

This is not magic. It is a protocol: any object that implements `__enter__` and `__exit__` is a context manager.

---

## Why This Exists — The Problem It Solves

Without context managers, resource management looks like this:

```python
f = open("data.txt", "r")
try:
    content = f.read()
    process(content)      # what if this raises?
finally:
    f.close()             # without this, the file handle leaks
```

This pattern is:

- **Verbose** — you repeat this boilerplate everywhere
- **Error-prone** — if you forget the `try/finally`, the resource leaks
- **Not composable** — nesting multiple resources is ugly

The `with` statement collapses this into a clean, single expression, and the protocol guarantees cleanup is always called. This is the design pattern known as **RAII** (Resource Acquisition Is Initialisation), borrowed from C++, adapted for Python.

---

## The Protocol — What Actually Happens

When Python executes:

```python
with EXPR as VAR:
    BLOCK
```

it does **exactly** the following:

```
1. Evaluate EXPR → get the context manager object cm
2. Call cm.__enter__() → return value bound to VAR
3. Execute BLOCK
4. Call cm.__exit__(exc_type, exc_val, exc_tb)
   - If BLOCK completed normally: all three args are None
   - If BLOCK raised: the exception info is passed in
5. If __exit__ returns a truthy value → exception is suppressed
   If __exit__ returns falsy (or None) → exception propagates
```

The variable after `as` receives the return value of `__enter__`, not the context manager itself. For files, `__enter__` returns `self` (the file object), so `f` is the file. For other managers, the distinction matters.

## Implementing a Custom Context Manager — The Class-Based Way

```python
class ManagedResource:
    def __init__(self, name):
        self.name = name

    def __enter__(self):
        print(f"[ENTER] Acquiring {self.name}")
        return self          # this is bound to the 'as' variable

    def __exit__(self, exc_type, exc_val, exc_tb):
        print(f"[EXIT]  Releasing {self.name}")
        if exc_type is not None:
            print(f"  Exception caught: {exc_type.__name__}: {exc_val}")
        return False         # False → do not suppress the exception
```

```python
with ManagedResource("GPU Memory") as res:
    print(f"  Using {res.name}")
    raise ValueError("something went wrong")
```

Output:

```
[ENTER] Acquiring GPU Memory
  Using GPU Memory
[EXIT]  Releasing GPU Memory
  Exception caught: ValueError: something went wrong
Traceback ...  ValueError: something went wrong
```

Change `return False` to `return True` and the `ValueError` is silently swallowed — the execution continues past the `with` block as if nothing happened. Use this only when suppression is intentional (e.g., a context manager that handles expected errors).

## The `__exit__` Signature in Full

```python
def __exit__(self, exc_type, exc_val, exc_tb):
    ...
```

|Parameter|Type|Value when no exception|Value when exception raised|
|---|---|---|---|
|`exc_type`|`type` or `None`|`None`|The exception class|
|`exc_val`|exception or `None`|`None`|The exception instance|
|`exc_tb`|traceback or `None`|`None`|The traceback object|

To inspect or re-raise selectively:

```python
def __exit__(self, exc_type, exc_val, exc_tb):
    self._cleanup()
    if exc_type is ValueError:
        print("Handled ValueError gracefully")
        return True        # suppress it
    return False           # let everything else propagate
```

## The `contextlib` Way — Using a Generator

Writing a full class for a simple context manager is often overkill. The `contextlib.contextmanager` decorator lets you write one as a generator function:

```python
from contextlib import contextmanager

@contextmanager
def managed_resource(name):
    print(f"[ENTER] Acquiring {name}")
    try:
        yield name            # everything before yield → __enter__
    finally:
        print(f"[EXIT]  Releasing {name}")  # always runs → __exit__
```

```python
with managed_resource("Database Connection") as conn:
    print(f"  Working with {conn}")
```

The `yield` value is bound to the `as` variable. The `finally` clause plays the role of `__exit__`. This is the idiomatic way to write lightweight context managers.

If you need to catch exceptions inside the generator form:

```python
@contextmanager
def safe_resource(name):
    print(f"Acquiring {name}")
    try:
        yield name
    except ValueError as e:
        print(f"Caught in context manager: {e}")
        # not re-raising → exception suppressed
    finally:
        print(f"Releasing {name}")
```

## Nesting Context Managers

### Sequential (comma syntax — preferred):

```python
with open("input.txt") as infile, open("output.txt", "w") as outfile:
    outfile.write(infile.read())
```

This is exactly equivalent to two nested `with` statements. Both files are guaranteed to close, in reverse order of acquisition.

### Nested (older style, still valid):

```python
with open("input.txt") as infile:
    with open("output.txt", "w") as outfile:
        outfile.write(infile.read())
```

### Using `contextlib.ExitStack` for dynamic nesting:

```python
from contextlib import ExitStack

files = ["a.txt", "b.txt", "c.txt"]

with ExitStack() as stack:
    handles = [stack.enter_context(open(f)) for f in files]
    for h in handles:
        print(h.read())
# all handles closed here
```

`ExitStack` is essential when the number of resources is not known at compile time — a common situation in ML pipelines when opening a variable number of data shards.

## Practical Examples

### Timer context manager

```python
import time
from contextlib import contextmanager

@contextmanager
def timer(label=""):
    start = time.perf_counter()
    yield
    elapsed = time.perf_counter() - start
    print(f"{label}: {elapsed:.4f}s")

with timer("matrix multiplication"):
    result = [[sum(a*b for a,b in zip(row, col))
               for col in zip(*B)]
              for row in A]
```

### Temporary directory

```python
import tempfile
import os

with tempfile.TemporaryDirectory() as tmpdir:
    path = os.path.join(tmpdir, "temp_data.csv")
    # write intermediate results, process them
    # directory and all contents deleted automatically on exit
```

### Suppressing specific exceptions

```python
from contextlib import suppress

with suppress(FileNotFoundError):
    os.remove("file_that_may_not_exist.txt")
# no try/except needed — cleaner for intentional no-ops
```

### Redirecting stdout

```python
import io
from contextlib import redirect_stdout

buffer = io.StringIO()
with redirect_stdout(buffer):
    print("this goes to the buffer, not the terminal")

captured = buffer.getvalue()
print(f"Captured: {repr(captured)}")
```

## Visualisation — Control Flow

```
with EXPR as var:          ┌─────────────────────────────────┐
    ─────────────          │  cm = EXPR                      │
    BLOCK                  │  var = cm.__enter__()           │
    ─────────────          │                                 │
                           │  ┌─ BLOCK ──────────────────┐  │
                           │  │  (your code runs here)   │  │
                           │  └──────────────────────────┘  │
                           │       ↓ normal    ↓ exception   │
                           │  __exit__(None,  __exit__(T,    │
                           │          None,           V,     │
                           │          None)           TB)    │
                           │                                 │
                           │  returns falsy → propagate      │
                           │  returns truthy → suppress      │
                           └─────────────────────────────────┘
```

The key invariant: **`__exit__` is always called.** There is no code path through a `with` block that skips it, not even `sys.exit()` or `os._exit()` — well, the latter does bypass it, but that's a process kill, not Python control flow.

## Common Built-In Context Managers

|Context Manager|Acquires|Releases|
|---|---|---|
|`open(file)`|File handle|`f.close()`|
|`threading.Lock()`|Lock|`lock.release()`|
|`decimal.localcontext()`|Decimal precision ctx|Restores previous context|
|`unittest.mock.patch()`|Monkey-patch|Restores original object|
|`torch.no_grad()`|Gradient tracking off|Restores gradient tracking|
|`tf.GradientTape()`|Gradient tape|Closes tape|
|`psycopg2.connect()`|DB connection|`conn.close()`|
|`tempfile.TemporaryDirectory()`|Temp dir|Deletes directory + contents|

## Connection to AI / Machine Learning / Deep Learning

Context managers are not incidental to ML code — they are structurally embedded in the two dominant deep learning frameworks.

### PyTorch — `torch.no_grad()`

During inference, you do not need to compute or store gradients. Doing so wastes memory and computation.

```python
import torch

model.eval()

with torch.no_grad():
    predictions = model(test_inputs)
    loss = criterion(predictions, test_labels)
```

Internally, `torch.no_grad()` implements `__enter__` to disable gradient tracking globally (sets `torch.is_grad_enabled()` to `False`) and `__exit__` to restore the prior state. This is precisely the context manager pattern: acquire a mode, guarantee restoration on exit.

**Why this matters:** without `torch.no_grad()`, every forward pass during evaluation builds a computation graph and retains intermediate activations in memory, causing GPU OOM errors on large models.

### PyTorch — `torch.autocast()` (Mixed Precision)

```python
with torch.autocast(device_type="cuda", dtype=torch.float16):
    output = model(input)
    loss = criterion(output, target)

scaler.scale(loss).backward()
```

Mixed precision training uses `float16` for forward passes (faster, less memory) and `float32` for gradient accumulation (numerically stable). The context manager switches the precision mode for its scope and restores it on exit.

### TensorFlow / Keras — `tf.GradientTape()`

```python
with tf.GradientTape() as tape:
    predictions = model(inputs, training=True)
    loss = loss_fn(targets, predictions)

gradients = tape.gradient(loss, model.trainable_variables)
optimizer.apply_gradients(zip(gradients, model.trainable_variables))
```

`GradientTape` records all operations on watched tensors inside the `with` block. On `__exit__`, it stops recording. `tape.gradient()` then traverses the recorded computation graph to compute derivatives. The context manager defines the _scope of differentiation_ — a conceptually precise use of the pattern.

### Data Loading — File and Dataset Contexts

```python
import h5py

with h5py.File("dataset.h5", "r") as f:
    X_train = f["X_train"][:]
    y_train = f["y_train"][:]
```

HDF5 files are the standard format for large numerical datasets in ML. `h5py` uses context managers to ensure file handles are released even if a downstream operation fails — critical when loading datasets too large to fit in RAM.

### Experiment Tracking — MLflow, W&B

```python
import mlflow

with mlflow.start_run(run_name="baseline_experiment"):
    mlflow.log_param("learning_rate", 0.001)
    mlflow.log_param("epochs", 50)
    
    for epoch in range(50):
        train_loss = train_one_epoch(model, loader)
        mlflow.log_metric("train_loss", train_loss, step=epoch)
    
    mlflow.log_artifact("model.pkl")
# run is automatically closed and committed to the tracking server
```

`mlflow.start_run()` is a context manager that opens a run on entry and finalises/flushes it on exit. If your training script crashes mid-run, the run is still cleanly closed.

### Profiling — `torch.profiler`

```python
with torch.profiler.profile(
    activities=[torch.profiler.ProfilerActivity.CPU,
                torch.profiler.ProfilerActivity.CUDA],
    record_shapes=True
) as prof:
    model(inputs)

print(prof.key_averages().table(sort_by="cuda_time_total"))
```

The profiler starts recording on `__enter__` and stops on `__exit__`, dumping the profiling data. Context managers are the natural interface for "measure this block."

## The Design Pattern — Why Context Managers Are the Right Abstraction

The context manager protocol enforces a discipline that is critical in systems that hold scarce resources: GPU memory, file handles, network connections, database transactions, locks.

The alternative — manual `try/finally` — relies on programmer discipline. Context managers make correctness the path of least resistance. This is why every serious ML library uses them for resource management.

The pattern generalises beyond cleanup. Context managers can:

- Switch global state (precision mode, gradient tracking)
- Measure elapsed time or resource consumption
- Implement transactional semantics (commit on success, rollback on failure)
- Temporarily monkey-patch objects (testing)
- Define the scope of any operation that has a natural start and end

When you see `with X as y` in a codebase, ask: what does `X.__enter__` acquire, and what does `X.__exit__` release? That question always has a crisp answer in well-designed code.

## Common Mistakes and Pitfalls

**1. Forgetting that `as VAR` receives `__enter__`'s return value, not the manager itself**

```python
class BadExample:
    def __enter__(self):
        return 42     # not self
    def __exit__(self, *args):
        return False

with BadExample() as x:
    print(x)   # 42, not the BadExample instance
```

**2. Suppressing exceptions accidentally**

```python
def __exit__(self, exc_type, exc_val, exc_tb):
    self.cleanup()
    # if you forget 'return False', Python returns None implicitly
    # None is falsy → exceptions propagate → this is fine
    # BUT if you return True by accident → exception silently eaten
    return True   # dangerous if unintentional
```

**3. Using `with` where the resource does not support the protocol**

Not every object is a context manager. If `obj.__enter__` does not exist, you get `AttributeError`. Check with `hasattr(obj, '__enter__')` or use `contextlib.closing()`:

```python
from contextlib import closing
import urllib.request

with closing(urllib.request.urlopen("https://example.com")) as response:
    data = response.read()
```

`contextlib.closing` wraps any object with a `.close()` method into a context manager.

**4. Assuming `with` means the resource is thread-safe**

A context manager guarantees acquisition and release, not mutual exclusion. For thread safety, use `threading.Lock()` as the resource inside the `with`.

## Summary

|Concept|What to remember|
|---|---|
|`with EXPR as VAR`|`VAR = EXPR.__enter__()`|
|On normal exit|`__exit__(None, None, None)` called|
|On exception|`__exit__(type, val, tb)` called|
|`return True` in `__exit__`|Exception suppressed|
|`return False` / `None`|Exception propagates|
|`@contextmanager`|Generator-based shorthand; `yield` splits enter/exit|
|`ExitStack`|Dynamic number of context managers|
|ML relevance|`torch.no_grad()`, `torch.autocast()`, `tf.GradientTape()`, `mlflow.start_run()`|
