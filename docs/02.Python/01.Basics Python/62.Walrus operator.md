# 62. Walrus Operator — `:=`

## What Is the Walrus Operator?

The walrus operator `:=` is the **assignment expression** operator, introduced in Python 3.8. It assigns a value to a variable **and** returns that value as part of an expression -- in a single step.

```python
# Normal assignment -- statement only, no return value
x = 10

# Walrus operator -- assignment inside an expression
if (x := 10) > 5:
    print(x)   # 10
```

The name comes from the resemblance of `:=` to a walrus face on its side -- two eyes and tusks. Officially it is called the **assignment expression**.

---

## The Problem It Solves

The core problem: you need to compute a value, check it, and then use it -- without computing it twice or introducing a throwaway variable before the conditional.

```python
# Pattern 1 -- compute, then check, then use
data = get_data()
if data:
    process(data)

# Pattern 2 -- compute twice (wasteful or incorrect if side effects)
if get_data():
    process(get_data())   # called twice

# Pattern 3 -- walrus -- compute once, check, use
if data := get_data():
    process(data)
```

Pattern 3 is not always better than Pattern 1. The walrus operator earns its place when the variable is only relevant inside the block, or when used inside a `while` loop or comprehension where a pre-assignment would be awkward.

---

## Syntax Rules

```python
name := expression
```

**The parentheses rule:** `:=` has lower precedence than almost every other operator. In most contexts outside comprehensions and `while`, you need parentheses to avoid a `SyntaxError`.

```python
# SyntaxError -- := at top level of if without parens
if x := 10:        # SyntaxError in some contexts
    pass

# Correct
if (x := 10):
    pass
```

The parentheses are not always required -- inside `while` and comprehensions they are often omitted -- but adding them is never wrong and prevents confusion.

---

## Usage Patterns

### while loop -- read until sentinel

The most natural use case. Eliminates the "read, check, process" duplication.

```python
# Without walrus -- duplicated read
line = input("Enter: ")
while line != "quit":
    print(f"You said: {line}")
    line = input("Enter: ")

# With walrus -- single read expression
while (line := input("Enter: ")) != "quit":
    print(f"You said: {line}")
```

```python
# Reading chunks from a file
import io

data = io.BytesIO(b"hello world this is a test")

while chunk := data.read(5):
    print(chunk)

# b'hello'
# b' worl'
# b'd thi'
# b's is '
# b'a tes'
# b't'
```

Without walrus, this requires either duplicating the `read()` call or using a `while True` with a `break`.

```python
# Equivalent without walrus -- less clean
while True:
    chunk = data.read(5)
    if not chunk:
        break
    print(chunk)
```

Both are readable. The walrus version makes the loop condition self-contained.

---

### Avoiding repeated function calls

```python
import re

text = "Order ID: 48291, Amount: $340"

# Without walrus -- match computed, then checked, then used
match = re.search(r"\d+", text)
if match:
    print(match.group())

# With walrus -- one line, match available in block
if match := re.search(r"\d+", text):
    print(match.group())   # "48291"
```

```python
# Processing pipeline -- only proceed if each step succeeds
def parse(raw):
    return raw.strip() or None

def validate(data):
    return data if len(data) > 3 else None

raw = "  hello  "

if (data := parse(raw)) and (valid := validate(data)):
    print(f"Valid: {valid}")
```

---

### List comprehensions -- filter and transform in one pass

Without walrus, you cannot filter on a transformed value without computing the transformation twice.

```python
# Compute transformation twice -- wasteful
results = [expensive(x) for x in data if expensive(x) > 0]

# Walrus -- compute once, filter, keep
results = [y for x in data if (y := expensive(x)) > 0]
```

```python
# Concrete example -- only keep valid parsed integers
strings = ["1", "abc", "3", "", "5"]

def try_parse(s):
    try:
        return int(s)
    except ValueError:
        return None

values = [v for s in strings if (v := try_parse(s)) is not None]
print(values)   # [1, 3, 5]
```

Without walrus:

```python
# Alternative without walrus -- two-pass or helper
values = list(filter(None, [try_parse(s) for s in strings]))
# works here but loses the None-specific filter
```

---

### Caching a condition mid-expression

```python
# Check length once, use it in two places
data = [1, 2, 3, 4, 5]

if (n := len(data)) > 3:
    print(f"Large dataset: {n} elements")
```

```python
# Avoid calling len() twice in a formatted message
numbers = list(range(100))

description = f"List has {(n := len(numbers))} items" + (
    " (large)" if n > 50 else " (small)"
)
print(description)   # "List has 100 items (large)"
```

## Scope Behavior

Variables assigned with `:=` leak into the **enclosing scope**, not just the expression's scope. This differs from loop variables in comprehensions.

```python
# Regular comprehension variable -- does NOT leak
result = [x for x in range(5)]
# print(x)   # NameError in Python 3 -- x is local to comprehension

# Walrus variable -- DOES leak into enclosing scope
result = [y := x * 2 for x in range(5)]
print(y)   # 8 -- last value assigned, visible outside comprehension
```

This is intentional -- it is the mechanism that allows walrus to return a value for use after a comprehension -- but it can be a source of confusion. The leaked variable holds the last value assigned during the expression.

```python
# Practical consequence
filtered = [clean for s in strings if (clean := s.strip())]
print(clean)   # last non-empty stripped string -- may or may not be useful
```

Do not rely on leaked walrus variables unless the intent is explicit. Use them when you want to extract the last matched value; otherwise treat the leak as a side effect to be aware of.

---

## Where Walrus Cannot Be Used

```python
# 1. Top-level assignment statement -- use = instead
(x := 5)      # valid but pointless -- just use x = 5

# 2. Left side of augmented assignment
(x := x + 1)  # valid but use x += 1 instead

# 3. f-string without explicit parentheses -- ambiguous
f"{x := 5}"   # SyntaxError
f"{(x := 5)}" # valid

# 4. Annotated assignment
x: int := 5   # SyntaxError -- cannot combine type annotation with walrus
```

---

## When Not to Use It

The walrus operator improves clarity only in specific patterns. Misuse produces code that is harder to read, not easier.

```python
# Unnecessary -- normal assignment is cleaner
(result := compute())   # no conditional, no loop -- just use result = compute()

# Overloaded -- too much happening in one line
if (a := f()) and (b := g(a)) and (c := h(b)):
    use(a, b, c)
# Acceptable if the chain is meaningful, but test by reading it aloud
```

Use walrus when it removes a genuine awkwardness -- duplicated computation, a loop pattern that requires pre-reading, or a comprehension filter that needs the transformed value. Do not use it to be concise for its own sake.

---

## Comparison Table

|Pattern|Without walrus|With walrus|
|---|---|---|
|Read-until-sentinel loop|`while True` + `break`|`while (x := read()) != sentinel`|
|Regex match and use|two lines (assign then check)|`if m := re.search(...)`|
|Filter + transform|compute twice or two-pass|`[y for x in data if (y := f(x))]`|
|Condition reuse|`n = len(x)` before `if`|`if (n := len(x)) > k`|

## Common Pitfalls

```python
# Pitfall 1 -- forgetting parentheses
if x := compute():    # may raise SyntaxError depending on context
    pass

if (x := compute()):  # always safe
    pass
```

```python
# Pitfall 2 -- walrus inside comprehension leaks
nums = [1, 2, 3]
squares = [last := n**2 for n in nums]
print(last)   # 9 -- leaked, may not be intended
```

```python
# Pitfall 3 -- using walrus where = is clearer
# This works but is needlessly obscure
data = (buffer := []) or buffer
# Just write: buffer = []; data = buffer
```

```python
# Pitfall 4 -- scope confusion in nested comprehensions
matrix = [[1, 2], [3, 4], [5, 6]]
flat = [val for row in matrix if (s := sum(row)) > 4 for val in row]
# s is the sum of the last row where sum > 4
# leaks s = 11 into enclosing scope
```
