# 58. Writing and Applying Decorators (@decorator)

> _"A decorator is not syntax sugar for a clever trick. It is the formal mechanism by which Python lets you separate what a function does from how it is instrumented, wrapped, or transformed — without touching the function's source code."_

## Part I — What a Decorator Is

### The Desugared Form

The `@decorator` syntax is **exactly equivalent** to:

```python
@decorator
def func():
    pass

# is identical to:

def func():
    pass
func = decorator(func)
```

That is the entire definition. A decorator is a callable that receives a function and returns a callable. The `@` syntax is assignment notation for that pattern.

```python
def my_decorator(func):
    def wrapper():
        print("before")
        result = func()
        print("after")
        return result
    return wrapper

@my_decorator
def say_hello():
    print("hello")

say_hello()
# before
# hello
# after
```

`say_hello` is now `wrapper`. The original function object is captured inside `wrapper`'s closure.

```
After @my_decorator:

    say_hello ──────────────► wrapper (closure)
                                  │
                                  └── free variable: func ──► original say_hello body
```

## Part II — The Correct Skeleton

### The Universal Wrapper

Any decorator that wraps a function of unknown signature must use `*args, **kwargs` to forward arguments faithfully:

```python
def decorator(func):
    def wrapper(*args, **kwargs):
        # --- pre-call logic ---
        result = func(*args, **kwargs)
        # --- post-call logic ---
        return result
    return wrapper
```

Without `*args, **kwargs`, the decorator only works on functions with the exact signature it expects — it breaks on everything else.

```python
# WRONG — only works on zero-argument functions
def timer(func):
    def wrapper():                  # fixed signature
        ...
        return func()
    return wrapper

@timer
def train(model, epochs):           # TypeError at call time
    pass
```

```python
# CORRECT
def timer(func):
    import time
    def wrapper(*args, **kwargs):   # forwards anything
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{func.__name__}: {elapsed:.4f}s")
        return result
    return wrapper

@timer
def train(model, epochs):
    pass

@timer
def predict(x):
    pass
```

### `functools.wraps` — Non-Negotiable

Without it, the decorated function loses its identity:

```python
def timer(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@timer
def train(model, epochs):
    """Train the model."""
    pass

print(train.__name__)   # 'wrapper'   ← WRONG
print(train.__doc__)    # None        ← WRONG
```

The decorated name is `wrapper`. Its docstring is `None`. Any framework that uses `__name__` for routing, logging, or test discovery will break silently.

**Always use `functools.wraps`:**

```python
import functools

def timer(func):
    @functools.wraps(func)          # copies __name__, __doc__, __module__,
    def wrapper(*args, **kwargs):   # __qualname__, __annotations__, __dict__
        import time
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__}: {time.perf_counter() - start:.4f}s")
        return result
    return wrapper

@timer
def train(model, epochs):
    """Train the model."""
    pass

print(train.__name__)   # 'train'          ← correct
print(train.__doc__)    # 'Train the model.' ← correct
```

`functools.wraps` is itself a decorator — a decorator that decorates `wrapper` to copy metadata from `func`. It also sets `wrapper.__wrapped__ = func`, giving you access to the original function:

```python
original = train.__wrapped__   # the unwrapped function
```

## Part III — Decorators with Arguments

A decorator with arguments needs **one extra layer of nesting** — a factory that receives the arguments and returns the actual decorator.

```python
# No arguments:     @decorator
# With arguments:   @decorator(arg1, arg2)

# @decorator(arg) desugars to:
# func = decorator(arg)(func)
#         ─────────────  ────
#         returns decorator  applied to func
```

```python
import functools

def repeat(n):                          # Layer 1: receives decorator arguments
    def decorator(func):                # Layer 2: receives the function
        @functools.wraps(func)
        def wrapper(*args, **kwargs):   # Layer 3: the actual call wrapper
            for _ in range(n):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def greet(name):
    print(f"Hello, {name}")

greet("Alice")
# Hello, Alice
# Hello, Alice
# Hello, Alice
```

The three-layer structure is mechanical and always the same:

```
repeat(3)          → returns decorator  (closes over n=3)
decorator(greet)   → returns wrapper    (closes over func=greet, n=3)
wrapper(...)       → calls greet(...)   (the actual execution)
```

### Decorator That Works With or Without Arguments

Using `functools.wraps` and a check on whether `func` was passed directly:

```python
import functools

def retry(func=None, *, times=3, exceptions=(Exception,)):
    """Can be used as @retry or @retry(times=5)"""
    if func is None:
        # Called with arguments: @retry(times=5)
        # Return the decorator
        return functools.partial(retry, times=times, exceptions=exceptions)

    # Called without arguments: @retry
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        last_exc = None
        for attempt in range(times):
            try:
                return func(*args, **kwargs)
            except exceptions as e:
                last_exc = e
                print(f"Attempt {attempt + 1} failed: {e}")
        raise last_exc
    return wrapper

@retry
def unstable_call():
    import random
    if random.random() < 0.7:
        raise ConnectionError("timeout")
    return "success"

@retry(times=5, exceptions=(ConnectionError, TimeoutError))
def api_call():
    pass
```

## Part IV — Practical Decorator Patterns

### 1. Caching / Memoisation

```python
import functools

def memoize(func):
    cache = {}                          # lives in the closure

    @functools.wraps(func)
    def wrapper(*args):
        if args not in cache:
            cache[args] = func(*args)
        return cache[args]
    return wrapper

@memoize
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

print(fibonacci(50))   # instant — each subproblem computed once
```

Python provides this built-in as `functools.lru_cache`:

```python
@functools.lru_cache(maxsize=128)
def fibonacci(n):
    if n < 2: return n
    return fibonacci(n - 1) + fibonacci(n - 2)

# Inspect the cache
print(fibonacci.cache_info())
# CacheInfo(hits=48, misses=51, maxsize=128, currsize=51)

# Clear it
fibonacci.cache_clear()
```

`functools.cache` (Python 3.9+) is `lru_cache(maxsize=None)` — unbounded cache, slightly faster.

### 2. Timing and Profiling

```python
import functools, time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"[{func.__name__}] {elapsed*1000:.2f}ms")
        return result
    return wrapper

@timer
def matrix_multiply(A, B):
    return [[sum(A[i][k] * B[k][j] for k in range(len(B)))
             for j in range(len(B[0]))]
            for i in range(len(A))]
```

### 3. Input Validation

```python
import functools

def validate_positive(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        for arg in args:
            if isinstance(arg, (int, float)) and arg < 0:
                raise ValueError(f"{func.__name__}: negative argument {arg}")
        return func(*args, **kwargs)
    return wrapper

@validate_positive
def sqrt(x):
    return x ** 0.5

sqrt(4)    # 2.0
sqrt(-1)   # ValueError: sqrt: negative argument -1
```

### 4. Logging

```python
import functools, logging

logging.basicConfig(level=logging.INFO)

def log_calls(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        logging.info(f"CALL  {func.__name__}  args={args}  kwargs={kwargs}")
        result = func(*args, **kwargs)
        logging.info(f"RETURN {func.__name__} → {result!r}")
        return result
    return wrapper

@log_calls
def load_dataset(path, split="train"):
    pass
```

### 5. Access Control / Authentication

```python
import functools

def require_auth(func):
    @functools.wraps(func)
    def wrapper(user, *args, **kwargs):
        if not user.get("authenticated"):
            raise PermissionError(f"User not authenticated for {func.__name__}")
        return func(user, *args, **kwargs)
    return wrapper

@require_auth
def get_model_weights(user, model_id):
```

### 6. Type Checking (Simplified)

```python
import functools, inspect

def enforce_types(func):
    hints = func.__annotations__

    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        sig    = inspect.signature(func)
        bound  = sig.bind(*args, **kwargs)
        bound.apply_defaults()

        for param, val in bound.arguments.items():
            if param in hints and not isinstance(val, hints[param]):
                raise TypeError(
                    f"{func.__name__}: {param} expected "
                    f"{hints[param].__name__}, got {type(val).__name__}"
                )
        return func(*args, **kwargs)
    return wrapper

@enforce_types
def train(model: object, epochs: int, lr: float):
    pass

train(model, 10, 0.001)        # fine
train(model, "ten", 0.001)     # TypeError: epochs expected int, got str
```

## Part V — Stacking Decorators

Multiple decorators stack bottom-up. The decorator closest to `def` is applied first.

```python
@A
@B
@C
def func():
    pass

# Equivalent to:
func = A(B(C(func)))
```

```
Application order (inside-out):
    C(func)       → func_c
    B(func_c)     → func_bc
    A(func_bc)    → func_abc   ← what the name 'func' now points to

Call order (outside-in):
    func_abc called → A's wrapper runs
                      → B's wrapper runs
                        → C's wrapper runs
                          → original func runs
                        → C's wrapper continues
                      → B's wrapper continues
                    → A's wrapper continues
```

```python
@log_calls
@timer
@validate_positive
def compute(x):
    return x ** 0.5

compute(9)
# INFO: CALL compute args=(9,) kwargs={}
# [compute] 0.003ms
# INFO: RETURN compute → 3.0
```

The order matters when decorators interact. Putting `@timer` outside `@log_calls` would time the logging overhead too.

## Part VI — Class-Based Decorators

A class can be a decorator if it implements `__call__`. This is useful when the decorator needs to maintain richer state than a closure easily allows.

```python
import functools

class CountCalls:
    def __init__(self, func):
        functools.update_wrapper(self, func)   # equivalent to @functools.wraps
        self.func  = func
        self.count = 0

    def __call__(self, *args, **kwargs):
        self.count += 1
        print(f"{self.func.__name__} called {self.count} time(s)")
        return self.func(*args, **kwargs)

@CountCalls
def train_step(batch):
    pass

train_step(batch1)   # train_step called 1 time(s)
train_step(batch2)   # train_step called 2 time(s)

print(train_step.count)   # 2  ← state directly on the object
```

The class-based form shines when you need methods to manipulate the decorator's state, or when you want to expose that state as attributes.

## Part VII — The ML and Deep Learning Connection

### PyTorch `@torch.no_grad()` — A Decorator in Production

```python
import torch

@torch.no_grad()
def evaluate(model, dataloader):
    """Run inference without building a computation graph."""
    model.eval()
    total_correct = 0
    for X, y in dataloader:
        preds = model(X)
        total_correct += (preds.argmax(1) == y).sum().item()
    return total_correct / len(dataloader.dataset)
```

`torch.no_grad()` is a context manager **and** a decorator. When used as `@torch.no_grad()`, it wraps the function so that no gradient tape is built during its execution — saving memory and compute during evaluation loops. The implementation is exactly the class-based decorator pattern above.

### Writing a `@gpu_timer` for Training Diagnostics

```python
import functools, torch

def gpu_timer(func):
    """Time a function using CUDA events for accurate GPU timing."""
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        if torch.cuda.is_available():
            start = torch.cuda.Event(enable_timing=True)
            end   = torch.cuda.Event(enable_timing=True)
            start.record()
            result = func(*args, **kwargs)
            end.record()
            torch.cuda.synchronize()
            print(f"[{func.__name__}] GPU time: {start.elapsed_time(end):.2f}ms")
        else:
            result = func(*args, **kwargs)
        return result
    return wrapper

@gpu_timer
def forward_pass(model, batch):
    return model(batch)
```

### `@property`, `@staticmethod`, `@classmethod`

These are built-in decorators — the same mechanism, provided by Python itself. They are covered in depth in [[59. @staticmethod, @classmethod, @property]], but recognising them as decorators is important:

```python
class NeuralNet:
    def __init__(self, layers):
        self._layers = layers
        self._param_count = sum(l.numel() for l in layers)

    @property
    def param_count(self):               # getter — called as net.param_count
        return self._param_count

    @staticmethod
    def xavier_init(shape):              # no self, no cls
        import math
        std = math.sqrt(2.0 / sum(shape))
        return [[std] * shape[1]] * shape[0]

    @classmethod
    def from_config(cls, config):        # receives class, not instance
        layers = [build_layer(c) for c in config["layers"]]
        return cls(layers)
```

Each of `@property`, `@staticmethod`, `@classmethod` is a built-in that takes a function and returns a **descriptor object** — a different return type from a closure, but the same `@` syntax, the same mechanism.

## Skeleton Reference

```python
# ── Decorator without arguments ──────────────────────────────
import functools

def decorator_name(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        # pre-call logic
        result = func(*args, **kwargs)
        # post-call logic
        return result
    return wrapper


# ── Decorator with arguments ─────────────────────────────────
def decorator_name(arg1, arg2):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            # use arg1, arg2 here
            result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator


# ── Class-based decorator ─────────────────────────────────────
class DecoratorName:
    def __init__(self, func):
        functools.update_wrapper(self, func)
        self.func = func

    def __call__(self, *args, **kwargs):
        # pre-call logic
        result = self.func(*args, **kwargs)
        # post-call logic
        return result
```

## Common Mistakes — Checklist

```
□ Forgot *args, **kwargs in wrapper     → breaks on any non-zero-arg function
□ Forgot functools.wraps                → __name__, __doc__ are wrong; frameworks break
□ Forgot to return result               → decorated function always returns None
□ Forgot the extra layer for arguments  → @decorator(n) raises TypeError
□ Stacked decorators in wrong order     → outer decorator runs outermost at call time
□ Mutable state in closure (not cell)   → shared across all calls unexpectedly
□ Used func() instead of func(*args)    → silently drops all arguments
```

## Summary

```
@decorator is syntactic sugar for: func = decorator(func)

The skeleton is always:
    outer function  → receives configuration (optional layer)
    decorator       → receives func, returns wrapper
    wrapper         → the new function; closes over func

functools.wraps copies __name__, __doc__, __module__ from func to wrapper.
It is mandatory. Without it, decorated functions lose their identity.

*args, **kwargs in wrapper makes the decorator signature-agnostic.
Without it, the decorator breaks on any function it wasn't written for.

Stacking: @A @B @C applies C first, then B, then A.
Call order is the reverse: A's wrapper runs first.

Class-based decorators use __call__ instead of a closure.
Prefer them when the decorator needs persistent state with rich access.

In ML: @torch.no_grad(), @property, @staticmethod, @classmethod are
all decorators. The mechanism is identical to anything you write yourself.
```
