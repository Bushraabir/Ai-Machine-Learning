# 28. Instance vs Class vs Static Methods

## The Core Question

A method is a function defined inside a class. But not all methods are the same — they differ in **what they have access to** and **what Python automatically passes as the first argument**.

There are exactly three kinds:

|Method type|Decorator|First argument|Has access to|
|---|---|---|---|
|Instance method|_(none)_|`self` — the instance|Instance state + class state|
|Class method|`@classmethod`|`cls` — the class itself|Class state only|
|Static method|`@staticmethod`|_(nothing)_|Neither instance nor class|

The choice between them is not stylistic — it is a statement about **what data the method needs to do its job**.

---

## Instance Methods — The Default

An instance method receives the calling instance as `self`. It can read and write both instance attributes (`self.x`) and class attributes (`self.__class__.x` or `ClassName.x`).

This is the most common method type. If you are writing a method and it needs to access or modify the object's own data, it is an instance method.

```python
class Circle:
    PI = 3.14159   # class attribute

    def __init__(self, radius):
        self.radius = radius   # instance attribute

    def area(self):                         # instance method
        return self.PI * self.radius ** 2

    def scale(self, factor):                # instance method
        self.radius *= factor               # modifies instance state

c = Circle(5)
print(c.area())    # 78.53975
c.scale(2)
print(c.radius)    # 10
```

`self.PI` works because Python looks up `PI` on the instance first, then on the class. Since `PI` is not on the instance, it finds it on the class.

---

## Class Methods — `@classmethod`

A class method receives the **class itself** as the first argument, named `cls` by convention. It has no access to instance data — there may not even be an instance.

Use a class method when the method logically belongs to the class but does not operate on any specific instance. The most important use case is **alternative constructors**.

```python
class Date:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day

    @classmethod
    def from_string(cls, date_str):
        """Alternative constructor: Date.from_string('2024-03-15')"""
        year, month, day = map(int, date_str.split('-'))
        return cls(year, month, day)   # calls __init__ via cls()

    @classmethod
    def today(cls):
        """Alternative constructor using current date"""
        import datetime
        d = datetime.date.today()
        return cls(d.year, d.month, d.day)

    def __repr__(self):
        return f"Date({self.year}, {self.month}, {self.day})"

d1 = Date(2024, 3, 15)
d2 = Date.from_string("2024-03-15")
d3 = Date.today()

print(d1)   # Date(2024, 3, 15)
print(d2)   # Date(2024, 3, 15)
```

**Why `cls` instead of the class name directly?**

Because `cls` refers to whatever class actually called the method — which matters for inheritance.

```python
class Animal:
    def __init__(self, name):
        self.name = name

    @classmethod
    def create(cls, name):
        return cls(name)   # creates an instance of whatever class called this

class Dog(Animal):
    def speak(self):
        return "Woof"

d = Dog.create("Rex")
print(type(d))    # <class '__main__.Dog'> — not Animal
print(d.speak())  # Woof
```

If `create` used `Animal(name)` instead of `cls(name)`, subclasses could never get instances of their own type. `cls` makes class methods inheritance-aware.

## Static Methods — `@staticmethod`

A static method receives nothing automatically — no `self`, no `cls`. It is a plain function that lives inside a class for **organizational reasons only**.

Use a static method when the logic is related to the class conceptually but does not need any class or instance data.

```python
class MathUtils:
    @staticmethod
    def clamp(value, min_val, max_val):
        """Constrain value to [min_val, max_val]"""
        return max(min_val, min(value, max_val))

    @staticmethod
    def is_prime(n):
        if n < 2:
            return False
        for i in range(2, int(n ** 0.5) + 1):
            if n % i == 0:
                return False
        return True

print(MathUtils.clamp(15, 0, 10))   # 10
print(MathUtils.is_prime(17))       # True
```

Static methods can also be called on instances, but calling them on the class is the cleaner pattern — it signals that no instance is involved.

```python
m = MathUtils()
print(m.clamp(5, 0, 10))   # 10 — works, but misleading
```

**Static methods vs module-level functions:**

If a function genuinely has no relationship to a class, put it at module level. Use `@staticmethod` when the function is tightly coupled to the class's domain — it belongs there semantically, even if it doesn't need instance or class data.

## All Three Together — A Cohesive Example

```python
class Temperature:
    ABSOLUTE_ZERO_C = -273.15   # class attribute — physical constant

    def __init__(self, celsius):
        if celsius < self.ABSOLUTE_ZERO_C:
            raise ValueError(f"Below absolute zero: {celsius}°C")
        self.celsius = celsius

    # --- Instance methods --- #
    def to_fahrenheit(self):
        return self.celsius * 9/5 + 32

    def to_kelvin(self):
        return self.celsius - self.ABSOLUTE_ZERO_C

    # --- Class methods (alternative constructors) --- #
    @classmethod
    def from_fahrenheit(cls, f):
        return cls((f - 32) * 5/9)

    @classmethod
    def from_kelvin(cls, k):
        return cls(k + cls.ABSOLUTE_ZERO_C)

    # --- Static methods (utilities) --- #
    @staticmethod
    def celsius_to_fahrenheit(c):
        return c * 9/5 + 32

    @staticmethod
    def is_valid_celsius(c):
        return c >= Temperature.ABSOLUTE_ZERO_C

    def __repr__(self):
        return f"Temperature({self.celsius:.2f}°C)"


# Instance method — needs object state
t = Temperature(100)
print(t.to_fahrenheit())    # 212.0
print(t.to_kelvin())        # 373.15

# Class method — alternative constructor, no existing object needed
t2 = Temperature.from_fahrenheit(212)
print(t2)                   # Temperature(100.00°C)

t3 = Temperature.from_kelvin(0)
print(t3)                   # Temperature(-273.15°C)

# Static method — pure utility
print(Temperature.celsius_to_fahrenheit(0))    # 32.0
print(Temperature.is_valid_celsius(-300))      # False
```

## How Python Implements This — Descriptors

Under the hood, the three decorators produce different **descriptor objects**:

- A plain function becomes a **bound method** when accessed via an instance — Python automatically prepends the instance as the first argument.
- `@classmethod` wraps the function in a `classmethod` descriptor — Python prepends the class instead.
- `@staticmethod` wraps the function in a `staticmethod` descriptor — Python prepends nothing.

```python
class Demo:
    def instance_method(self): pass

    @classmethod
    def class_method(cls): pass

    @staticmethod
    def static_method(): pass

d = Demo()

# Type of each when accessed via instance
print(type(d.instance_method))   # <class 'method'>         — bound to instance
print(type(d.class_method))      # <class 'method'>         — bound to class
print(type(d.static_method))     # <class 'function'>       — no binding

# Type when accessed via class
print(type(Demo.instance_method))  # <class 'function'>     — unbound
print(type(Demo.class_method))     # <class 'method'>       — bound to class
print(type(Demo.static_method))    # <class 'function'>     — no binding
```

You do not need to implement descriptors — but knowing this model explains why the three method types behave differently and why calling an unbound instance method on the class requires manually passing an instance.

## Inheritance Behavior

This is where the distinction between instance and class methods becomes critical.

```python
class Animal:
    category = "Animal"

    def __init__(self, name):
        self.name = name

    def describe(self):                    # instance method
        return f"{self.name} is a {self.__class__.category}"

    @classmethod
    def kingdom(cls):                      # class method
        return f"{cls.category} belongs to kingdom Animalia"

    @staticmethod
    def breathes():                        # static method
        return "Breathes oxygen"

class Dog(Animal):
    category = "Dog"

d = Dog("Rex")
print(d.describe())     # Rex is a Dog      — self.__class__ is Dog
print(Dog.kingdom())    # Dog belongs to kingdom Animalia — cls is Dog
print(Dog.breathes())   # Breathes oxygen  — no class reference at all
```

- `self.__class__` resolves to the **actual runtime class** of the instance — always `Dog` for `Dog` instances, even if the method is defined on `Animal`.
- `cls` resolves to the **class that received the call** — `Dog` when called as `Dog.kingdom()`.
- Static methods inherit but carry **no class information** — they cannot be made polymorphic.

## Decision Guide — Which One Do You Need?

Work through these questions in order:

```
Does the method need to read or modify THIS object's data (self.x)?
    YES → instance method

Does the method need to create a new instance of THIS class (or a subclass)?
    YES → class method  (alternative constructor)

Does the method need to access class-level data (class attributes)?
    YES → class method  (or instance method, both work)

Is the method a utility that only processes its arguments, unrelated to
instance or class state?
    YES → static method

Would this function make equal sense as a module-level function?
    YES → consider making it a module-level function instead
```

## Real-World Pattern — ML Model Class

This pattern appears constantly in PyTorch, scikit-learn, and custom ML code:

```python
class LinearRegression:
    learning_rate_default = 0.01   # class attribute

    def __init__(self, weights, bias=0.0, lr=None):
        self.weights = weights
        self.bias = bias
        self.lr = lr if lr is not None else self.__class__.learning_rate_default
        self.history = []

    # Instance method — operates on this model's weights
    def predict(self, x):
        return sum(w * xi for w, xi in zip(self.weights, x)) + self.bias

    def update(self, gradient):
        self.weights = [w - self.lr * g for w, g in zip(self.weights, gradient)]

    # Class method — alternative constructor: load from a config dict
    @classmethod
    def from_config(cls, config):
        return cls(
            weights=config["weights"],
            bias=config.get("bias", 0.0),
            lr=config.get("lr")
        )

    # Static method — pure math utility, no model state needed
    @staticmethod
    def mse_loss(predictions, targets):
        n = len(predictions)
        return sum((p - t) ** 2 for p, t in zip(predictions, targets)) / n

    @staticmethod
    def normalize(data):
        mean = sum(data) / len(data)
        std = (sum((x - mean)**2 for x in data) / len(data)) ** 0.5
        return [(x - mean) / std for x in data] if std != 0 else data


# Usage
model = LinearRegression(weights=[0.5, -0.3, 0.8])
print(model.predict([1, 2, 3]))   # 0.5*1 + (-0.3)*2 + 0.8*3 + 0 = 2.3

config = {"weights": [1.0, 2.0], "lr": 0.001}
model2 = LinearRegression.from_config(config)

preds = [2.1, 3.9, 5.2]
targets = [2.0, 4.0, 5.0]
print(LinearRegression.mse_loss(preds, targets))   # 0.02
```

## Common Errors

```python
# 1. Calling instance method on class without passing instance
class Foo:
    def greet(self):
        return "hello"

Foo.greet()   # TypeError: greet() missing 1 required positional argument: 'self'
Foo.greet(Foo())   # Correct — manually pass an instance

# 2. Forgetting @classmethod — cls is treated as a regular parameter
class Bar:
    def make(cls):   # missing @classmethod — cls is just a name, not the class
        return cls()

Bar.make()   # TypeError: make() missing 1 required positional argument: 'cls'

# 3. Trying to access self inside a static method
class Baz:
    def __init__(self, x):
        self.x = x

    @staticmethod
    def show():
        print(self.x)   # NameError: name 'self' is not defined

# 4. Using class name instead of cls in a classmethod — breaks inheritance
class Parent:
    @classmethod
    def create(cls):
        return Parent()   # ← hardcoded — subclasses always get a Parent instance

class Child(Parent):
    pass

c = Child.create()
print(type(c))   # <class 'Parent'> — wrong, should be Child

# Fix: use cls()
```

## Summary Table

||Instance method|Class method|Static method|
|---|---|---|---|
|Decorator|none|`@classmethod`|`@staticmethod`|
|Auto first arg|`self` (instance)|`cls` (class)|nothing|
|Access instance data|✅|❌|❌|
|Access class data|✅|✅|❌ (use class name directly)|
|Called on instance|✅|✅|✅|
|Called on class|✅ (need to pass instance)|✅|✅|
|Inheritance-aware|via `self.__class__`|via `cls`|❌|
|Primary use case|Object behavior|Alternative constructors|Utilities|
