# 39. `any()` and `all()`

> _"Two of the most semantically precise functions in Python. One is existential quantification. The other is universal quantification. You have been doing logic all along."_

---

## The Core Idea

These two builtins are Python's direct implementation of the two most fundamental logical quantifiers from predicate logic and set theory.

|Python|Logic|Meaning|
|---|---|---|
|`all(iterable)`|$\forall x \in S : P(x)$|Every element satisfies the condition|
|`any(iterable)`|$\exists x \in S : P(x)$|At least one element satisfies the condition|

This is not a metaphor. They are literally the same thing. Whenever you write `any(P(x) for x in S)`, you are asserting the existential statement $\exists x \in S : P(x)$.

---

## Signatures

```python
any(iterable) -> bool
all(iterable) -> bool
```

Both accept **any iterable** — list, tuple, generator, set, dict, string, range, custom iterator. They evaluate **truthiness**, not strict equality to `True`.

---

## Formal Definitions

### `all()`

```
all(iterable) = True   iff every element in iterable is truthy
              = False   as soon as one falsy element is found
```

Edge case — the **vacuous truth**: an empty iterable returns `True`.

```python
all([])        # True  — "all zero elements satisfy the condition" is vacuously true
```

This is mathematically correct. $\forall x \in \emptyset : P(x)$ is true in classical logic because there is no $x$ to violate it.

### `any()`

```
any(iterable) = False  iff every element in iterable is falsy
              = True   as soon as one truthy element is found
```

Edge case — the **vacuous falsity**: an empty iterable returns `False`.

```python
any([])        # False — "there exists an element" is false when the set is empty
```

---

## Short-Circuit Evaluation

Both functions **short-circuit** — they stop as soon as the result is determined. This is not a minor optimization. It is semantically meaningful and must be understood.

```python
# all() stops at the first False
all([True, True, False, ...])   # stops at False — never evaluates the rest

# any() stops at the first True
any([False, False, True, ...])  # stops at True — never evaluates the rest
```

**Why this matters — generators:**

```python
def expensive_check(x):
    print(f"checking {x}")
    return x > 0

result = any(expensive_check(x) for x in [1, 2, 3])
# Output: checking 1
# Stops immediately — never checks 2 or 3

result = any(expensive_check(x) for x in [-1, -2, 5])
# Output: checking -1
#         checking -2
#         checking 5
# Evaluates all three before finding a True
```

Always pass a **generator expression**, not a list comprehension, to `any()` and `all()`. A list comprehension evaluates all elements first, defeating short-circuiting.

```python
# BAD — evaluates the entire list before any() sees it
any([f(x) for x in large_list])

# GOOD — short-circuits; stops at first truthy value
any(f(x) for x in large_list)
```

## Basic Examples

```python
nums = [2, 4, 6, 8, 10]

# Is every number even?
all(x % 2 == 0 for x in nums)   # True

# Is any number greater than 9?
any(x > 9 for x in nums)        # True

# Is any number negative?
any(x < 0 for x in nums)        # False

# Are all numbers positive?
all(x > 0 for x in nums)        # True
```

**With strings:**

```python
words = ["alpha", "beta", "gamma"]

all(w.isalpha() for w in words)     # True  — all alphabetic
any(w.startswith("z") for w in words)  # False — none starts with z
any(len(w) > 4 for w in words)     # True  — "alpha", "gamma"
```

**With mixed types and truthiness:**

```python
values = [1, "hello", [1, 2], True]
all(values)     # True  — all truthy

values2 = [1, "", [1, 2], True]
all(values2)    # False — empty string is falsy
any(values2)    # True  — 1 is truthy
```

## De Morgan's Laws in Code

From logic: $\neg (\forall x : P(x)) \iff \exists x : \neg P(x)$

In Python:

```python
not all(P(x) for x in S)   ==   any(not P(x) for x in S)
not any(P(x) for x in S)   ==   all(not P(x) for x in S)
```

These are exactly De Morgan's laws. They hold in Python as they hold in logic.

```python
data = [2, 4, 5, 8]

# "Not all are even" == "at least one is odd"
not all(x % 2 == 0 for x in data)   # True
any(x % 2 != 0 for x in data)       # True  — same thing

# "None are negative" == "all are non-negative"
not any(x < 0 for x in data)        # True
all(x >= 0 for x in data)           # True  — same thing
```

This is not a coincidence. Python's `any` and `all` are logical operators lifted to iterables. When refactoring conditions, these equivalences let you choose whichever form is more readable.

## Common Patterns

### Validation

```python
def is_valid_matrix(M):
    """All rows must have the same length."""
    if not M:
        return True
    row_len = len(M[0])
    return all(len(row) == row_len for row in M)

def has_missing(data):
    """Check if any value is None or NaN."""
    return any(v is None or v != v for v in data)  # v != v catches float('nan')
```

### Membership and Search

```python
# Does any string in a list contain a substring?
keywords = ["error", "warning", "info"]
log_line = "ERROR: connection refused"

any(kw in log_line.lower() for kw in keywords)   # True

# Do all required fields exist in a dict?
required = {"name", "age", "email"}
record = {"name": "Alice", "age": 30, "email": "a@b.com", "city": "Dhaka"}

all(field in record for field in required)   # True
```

### Working with Booleans Directly

```python
flags = [True, False, True, True]

any(flags)    # True  — equivalent to any(f for f in flags)
all(flags)    # False
```

## `any()` and `all()` on Dicts

When applied to a dict directly, iteration is over **keys**.

```python
d = {"a": 1, "b": 2, "c": 3}

any(d)          # True — keys are non-empty strings, all truthy
all(k > "a" for k in d)   # False — "a" > "a" is False

# To check values:
all(v > 0 for v in d.values())   # True
any(v > 2 for v in d.values())   # True

# To check items:
any(k == "b" and v == 2 for k, v in d.items())   # True
```

## Edge Cases Reference

```python
# Empty iterables
all([])        # True   (vacuous truth)
any([])        # False  (vacuous falsity)

# Single-element
all([0])       # False
any([0])       # False
all([1])       # True
any([1])       # True

# None and 0 are falsy
all([1, 2, None])   # False
all([1, 2, 0])      # False
any([None, 0, ""])  # False
any([None, 0, " "])  # True  — space is truthy!
```

## Implementation from Scratch

Understanding `any` and `all` well enough to implement them is the floor, not the ceiling.

```python
def my_any(iterable):
    for element in iterable:
        if element:
            return True
    return False

def my_all(iterable):
    for element in iterable:
        if not element:
            return False
    return True
```

Notice:

- `my_any` returns `False` after exhausting the loop (no truthy element found)
- `my_all` returns `True` after exhausting the loop (no falsy element found)
- Both short-circuit naturally — `return` exits immediately

The CPython implementations are essentially these loops written in C for speed, with no semantic difference.

## Combining `any()` and `all()`

```python
matrix = [
    [1, 2, 3],
    [4, 0, 6],
    [7, 8, 9],
]

# Does every row contain at least one even number?
all(any(x % 2 == 0 for x in row) for row in matrix)
# Row 0: any([False, True, False]) = True
# Row 1: any([True, True, True])   = True
# Row 2: any([False, True, False]) = True
# all([True, True, True])          = True

# Is there any row where all elements are positive?
any(all(x > 0 for x in row) for row in matrix)
# Row 0: all([True, True, True])   = True  → short-circuits here
# Result: True
```

The nesting structure mirrors the logical quantifier nesting: $\forall \text{ row } \exists \text{ element}$ maps directly to `all(any(...) for row in matrix)`.

## Visualisation: Short-Circuit Behaviour

```
any([F, F, T, F, T])
     ↓  ↓  ↓
     ✗  ✗  ✓ → returns True immediately

all([T, T, F, T, T])
     ↓  ↓  ↓
     ✓  ✓  ✗ → returns False immediately

any([F, F, F, F, F])
     ↓  ↓  ↓  ↓  ↓
     ✗  ✗  ✗  ✗  ✗ → exhausted → returns False

all([T, T, T, T, T])
     ↓  ↓  ↓  ↓  ↓
     ✓  ✓  ✓  ✓  ✓ → exhausted → returns True
```

## Connection to AI, Machine Learning, and Deep Learning

`any()` and `all()` appear directly in several ML engineering patterns. Here is where you will actually use them.

### 1. Data Validation Pipelines

Before training, you need to assert data integrity.

```python
import numpy as np

def validate_batch(X, y):
    checks = [
        not any(np.isnan(x).any() for x in X),   # no NaN in features
        not any(np.isinf(x).any() for x in X),   # no Inf
        len(X) == len(y),                          # labels match
        all(label in {0, 1} for label in y),      # binary labels only
    ]
    if not all(checks):
        raise ValueError("Batch failed validation")
```

NumPy has its own `.any()` and `.all()` methods — vectorised, operating element-wise over arrays. They are the same concept at array scale.

```python
arr = np.array([1, 2, 3, -1, 5])

np.any(arr < 0)    # True  — at least one negative
np.all(arr > 0)    # False — not all positive
```

### 2. Early Stopping and Training Loop Control

```python
class EarlyStopping:
    def __init__(self, patience=5):
        self.patience = patience
        self.history = []

    def should_stop(self, val_loss):
        self.history.append(val_loss)
        if len(self.history) < self.patience:
            return False
        recent = self.history[-self.patience:]
        # Stop if ALL recent losses are worse than the one before them
        return all(recent[i] >= recent[i-1] for i in range(1, len(recent)))
```

### 3. Gradient Sanity Checking

During training, checking that gradients are well-behaved:

```python
def check_gradients(model):
    grads = [p.grad for p in model.parameters() if p.grad is not None]

    if not all(torch.isfinite(g).all() for g in grads):
        raise RuntimeError("Non-finite gradient detected — training unstable")

    if any(g.abs().max() > 1e3 for g in grads):
        print("Warning: large gradient norms detected")
```

### 4. Hyperparameter and Config Validation

```python
REQUIRED_KEYS = {"learning_rate", "batch_size", "epochs", "optimizer"}

def validate_config(cfg: dict):
    if not all(k in cfg for k in REQUIRED_KEYS):
        missing = REQUIRED_KEYS - cfg.keys()
        raise KeyError(f"Missing config keys: {missing}")

    if any(cfg[k] <= 0 for k in ["learning_rate", "batch_size", "epochs"]):
        raise ValueError("Numeric hyperparameters must be positive")
```

### 5. Prediction Confidence and Thresholding

In multi-label classification — where each sample can belong to multiple classes simultaneously:

```python
def predict_multilabel(logits, threshold=0.5):
    probs = sigmoid(logits)
    predictions = probs > threshold  # shape: (batch, n_classes)

    # Is the model confident about at least one class for each sample?
    confident = [any(row) for row in predictions]

    # Is the model confident about ALL classes for each sample?
    fully_confident = [all(row) for row in predictions]

    return predictions, confident, fully_confident
```

### 6. The Logical Connection to Attention Mechanisms

In **Transformer attention**, the softmax over query-key products computes a soft version of `any` — it assigns high weight to the most relevant positions rather than returning a hard True/False. The temperature of the softmax controls how "hard" this selection is:

- Temperature → 0: approaches hard `argmax` (select exactly one position)
- Temperature → ∞: approaches uniform (every position equally)

`any()` is the limit of attention as temperature goes to zero with a binary scoring function. This is the deep connection — `any` and `all` are the discrete, Boolean ancestors of the soft, differentiable operations that power modern deep learning.

## Summary

|Function|Returns `True` when|Returns `False` when|Empty iterable|
|---|---|---|---|
|`all(it)`|Every element is truthy|Any element is falsy|`True` (vacuous)|
|`any(it)`|Any element is truthy|Every element is falsy|`False` (vacuous)|

**Rules to internalise:**

1. Always pass a **generator expression**, not a list, to exploit short-circuiting.
2. `not all(P)` $\equiv$ `any(not P)` and `not any(P)` $\equiv$ `all(not P)` — De Morgan's laws apply directly.
3. `all([])` is `True`. `any([])` is `False`. These are mathematically correct, not bugs.
4. In NumPy/PyTorch, `.any()` and `.all()` are the vectorised equivalents — same logic, array semantics.
