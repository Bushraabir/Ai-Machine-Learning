03.Stacking

03.Stacking

Apr 24, 202615 min read

“Bagging asks many learners the same question and averages. Boosting asks the next learner to fix the last one’s mistakes. Stacking asks a smarter learner: given what everyone else predicted, what is the answer?”

✦ The Setup: Beyond Simple Aggregation

Bagging averages predictions with equal weights: y^​=B1​∑b​f^​b​(x). This is optimal only when all base learners are equally good and make uncorrelated errors — a strong assumption that rarely holds exactly.

Boosting learns weights αm​ for each weak learner, but those weights are fixed by the boosting algorithm itself, not learned from held-out data.

Stacking (Wolpert, 1992) takes a different position: treat the predictions of base models as features, and train a second model — the meta-learner — to optimally combine them. The meta-learner learns which base models to trust, when, and how much.

Formally:

  • Level-0 (base learners): f^​1​,f^​2​,…,f^​K​ — trained on the original features x∈Rd
  • Level-1 (meta-learner): g^​ — trained on x~=[f^​1​(x),f^​2​(x),…,f^​K​(x)]∈RK

The final prediction is: y^​=g^​(f^​1​(x),f^​2​(x),…,f^​K​(x))

The meta-learner g^​ can be anything: linear regression, logistic regression, another gradient-boosted tree, or a neural network. In practice, simple meta-learners (regularised linear models) are strongly preferred for reasons we will make precise.

✦ The Leakage Problem

Why You Cannot Naively Stack

Suppose you train all base learners on the full training set, then collect their predictions on the training set as meta-features, and train the meta-learner on those meta-features.

The base learners have memorised the training set. A fully grown decision tree has zero training error — it predicts every training point perfectly. The meta-features on the training set are then [f^​1​(xi​),…,f^​K​(xi​)]=[yi​,yi​,…,yi​] — the true labels, leaked through the base model predictions.

The meta-learner trains on leaked information. Its learned weights are meaningless. When you deploy, the base learners make real predictions (not memorised ones), and the meta-learner — trained on leaked perfect predictions — behaves erratically.

This is target leakage through the meta-features. It is the central technical problem in stacking.

The Fix: Out-of-Fold Predictions

The solution is to ensure that when training the meta-learner, each meta-feature f^​k​(xi​) was produced by a base learner that never saw (xi​,yi​) during training. This is achieved with k-fold cross-validation:

Divide training data 𝒟 into K folds: F₁, F₂, ..., F_K

for k = 1, 2, ..., K:
    Train base learner f̂_1 on 𝒟 \ F_k
    Predict on F_k → store predictions for fold k

After K iterations:
    Every training point has an out-of-fold (OOF) prediction from f̂_1
    Repeat for all base learners f̂_2, ..., f̂_K

Result:
    Meta-feature matrix Z ∈ ℝ^(n × K_models)
    Z[i, k] = prediction of base model k on x_i,
               made by a model that never saw x_i

The OOF predictions are uncontaminated: no base model saw the points it predicted on. The meta-learner trains on these OOF predictions — an honest signal.

✦ The Full Stacking Algorithm

Training Phase

Input: training data 𝒟 = {(xᵢ, yᵢ)}ⁿᵢ₌₁, K base models {f̂₁,...,f̂_K}, 
       meta-learner g, n_folds J

Step 1 — Generate OOF meta-features:
    Initialise Z ∈ ℝ^(n × K) = 0

    for j = 1, ..., J:
        (𝒟_train^(j), 𝒟_val^(j)) ← jth fold split of 𝒟

        for k = 1, ..., K:
            Train f̂_k on 𝒟_train^(j)
            Predict on 𝒟_val^(j) → fill Z[val indices, k]

Step 2 — Retrain base models on full training data:
    for k = 1, ..., K:
        Train f̂_k^(full) on entire 𝒟

Step 3 — Train meta-learner:
    Train g on (Z, y)    ← Z is the OOF meta-feature matrix

Inference Phase

Input: new point x

Step 1 — Collect base model predictions:
    z̃ = [f̂₁^(full)(x), f̂₂^(full)(x), ..., f̂_K^(full)(x)]

Step 2 — Meta-learner prediction:
    ŷ = g(z̃)

Why retrain base models on the full data in Step 2? The OOF models were each trained on (J−1)/J of the training data. At inference time, we want the best possible base model predictions, so we retrain on all of D. The meta-learner was trained to interpret predictions from models with this power level — slight inconsistency, but empirically beneficial.

✦ Stacking From Scratch

✦ What the Meta-Learner Learns

Consider binary classification with two base models. The OOF meta-features are:

Z=[p^​1​(x1​)​p^​2​(x1​) p^​1​(x2​)​p^​2​(x2​) ⋮​⋮​]

If the meta-learner is logistic regression:

P(y^​=1∣x)=σ(w1​p^​1​(x)+w2​p^​2​(x)+b)

The weights w1​,w2​ learned by logistic regression encode how much to trust each base model. If Model 1 is consistently better on hard examples and Model 2 is better on easy ones, a linear meta-learner can learn this. If the trust depends on where in the input space you are (Model 1 is better for high x3​, Model 2 for low x3​), a nonlinear meta-learner can learn this.

Including the original features in the meta-feature matrix allows the meta-learner to condition on the input:

Zextended​=[p^​1​(x),p^​2​(x),x1​,x2​,…,xd​]

This lets the meta-learner learn: “if the SVM predicts 0.9 AND x3​>2, then the true label is almost certainly 1.” Adds power but also variance — use with regularisation.

✦ Why Simple Meta-Learners?

A natural question: why not use a powerful meta-learner like XGBoost? The meta-feature space has only K dimensions (number of base models) — typically 3–10. Training a complex model on a handful of features with n samples is wasteful and prone to overfitting the idiosyncrasies of the OOF predictions.

More fundamentally: the meta-features are not raw inputs. They are already processed predictions, living in a compressed space. A linear meta-learner is often sufficient to extract the residual signal. Using a complex meta-learner risks:

  1. Fitting noise in the OOF predictions
  2. Being sensitive to the specific fold splits used for OOF
  3. Poor calibration of the final output

Preferred meta-learners in practice:

  • Logistic regression (classification, L2 regularised)
  • Ridge regression (regression)
  • ElasticNet (when base models are correlated)
  • Shallow GBM with strong regularisation (only if meta-feature space is large)

One exception: When the meta-feature space is large (many base models, original features included), a regularised nonlinear meta-learner can help. Kaggle competition stacks often use LightGBM as a second-level learner over 20–50 base model predictions.

✦ Blending: The Simpler Variant

Blending replaces cross-validation OOF with a simple holdout:

Split training data: 𝒟 = 𝒟_train ∪ 𝒟_blend   (e.g., 80/20)

Train all base models on 𝒟_train

Predict on 𝒟_blend → get meta-features Z_blend
Predict on 𝒟_test  → get meta-features Z_test

Train meta-learner on (Z_blend, y_blend)
Final prediction: g(Z_test)

Blending vs. Stacking:

PropertyStacking (OOF)Blending (Holdout)
Data efficiencyUses all data for base trainingBase models see only 80%
OOF qualityn×(J−1)/J samples per foldFixed n×0.8 for all
VarianceLower (averages over J folds)Higher (depends on split)
SimplicityComplex (many training runs)Simple (one pass)
Leakage riskMinimal if done correctlyMinimal if split is clean
SpeedJ×K base model fitsK base model fits

When to use blending: Time pressure, large datasets where K-fold is expensive, or when the base models are very slow. On Kaggle competitions, blending is common in the final hours before the deadline.

When to use stacking: When data is limited (every sample matters for training the meta-learner), or when you want the most reliable OOF estimates.

✦ Multi-Level Stacking

Nothing prevents adding a third level:

Level 0: Base models f̂₁, ..., f̂_K₀        (original features)
Level 1: Meta-models ĝ₁, ..., ĝ_K₁         (level-0 OOF predictions)
Level 2: Meta-meta-model h                   (level-1 OOF predictions)

Each level requires its own OOF generation via cross-validation, or the leakage problem compounds. In practice, gains diminish rapidly beyond two levels. Three levels is rarely worth the complexity outside top Kaggle finishes.

Computational cost: For J-fold CV, K0​ level-0 models, and K1​ level-1 models:

  • Level-0 training: J×K0​ fits
  • Level-1 training: J×K1​ fits (on the level-0 OOF predictions)
  • Total: J(K0​+K1​) fits + K0​+K1​ full-data refits

For J=5, K0​=5, K1​=3: 5×8+8=48 model fits. At 10 minutes per fit, that’s 8 hours.

✦ Designing the Base Model Ensemble

Stacking works best when base models are diverse — making different kinds of errors. If all base models are gradient-boosted trees with slightly different hyperparameters, their predictions will be highly correlated: the meta-learner learns little from combining them.

Sources of diversity:

1. Model family diversity: Random forests, gradient boosting, SVMs, neural networks, linear models. Each has different inductive biases and makes different errors.

2. Feature subset diversity: Train some models on all features, others on subsets, others on different feature transformations. One model on raw features, another on PCA-transformed features.

3. Hyperparameter diversity: Within a model family, use very different hyperparameter settings. An overfit random forest and an underfit random forest make complementary errors.

4. Training data diversity: Bootstrap samples (like bagging), or train on different time windows for time-series problems.

5. Task formulation diversity: For classification, train some models as classifiers and others as ranking models. Use predicted probabilities from some, calibrated probabilities from others.

Measuring diversity: The pairwise correlation of OOF predictions is a direct measure. If corr(f^​j​(x),f^​k​(x))≈1 for base models j and k, one of them is redundant.

✦ Stacking for Regression

The setup is identical. Base models produce real-valued predictions. Meta-features are these predictions. Meta-learner is ridge regression (recommended).

One practical addition: include base model residuals as meta-features, not just predictions. This gives the meta-learner direct access to error signals:

Zresidual​=[f^​1​(x),…,f^​K​(x),y−f^​1​(x),…,y−f^​K​(x)]

Wait — the residuals y−f^​k​(x) contain y, the target. You cannot use them as meta-features directly (that’s leakage). But you can use them only on the OOF fold, where y is held out from the base model. The OOF residual is: yi​−f^​k(OOF)​(xi​), which is valid.

✦ Probability Calibration in Stacking

Base classifiers often output poorly calibrated probabilities:

  • SVMs output scores that don’t correspond to true probabilities without Platt scaling
  • Gradient boosting overestimates probabilities near 0 and 1
  • Random forests tend to be biased toward 0.5

When the meta-learner receives poorly calibrated probabilities as input, it learns a distorted view of each model’s confidence. Calibrate base model outputs before stacking:

Alternatively, train the meta-learner to be robust to miscalibration — a regularised logistic regression with L2 penalty handles moderate miscalibration well because the weights adapt to the scale of the inputs.

✦ sklearn’s StackingClassifier

sklearn provides a native implementation since version 0.22:

The passthrough=True option: Passes original features alongside base model predictions to the meta-learner. Useful when base models are not expressive enough — the meta-learner can learn patterns in the input space that the base models missed. Increases meta-feature dimensionality from K to K+d.

✦ When Stacking Helps (and When It Doesn’t)

Stacking helps when:

  • Base models are diverse and make complementary errors
  • Individual base models are already strong (stacking a set of weak models rarely helps; you want strong, diverse models)
  • The dataset is large enough that OOF estimates are stable
  • The competition/deployment metric rewards small improvements (Kaggle: top 1% gap is often 0.001 AUC)

Stacking doesn’t help when:

  • Base models are all from the same family with similar hyperparameters
  • Dataset is small (OOF estimates are high-variance → meta-features are noisy)
  • Base models are already well-calibrated and the best single model’s error is largely irreducible noise
  • Production constraints prevent serving multiple models simultaneously

The practical rule of thumb: If your best single model scores 0.920 and your second-best scores 0.918, stacking them will likely reach 0.921–0.922. If your best model scores 0.920 and your second-best scores 0.850, the second model is probably not diverse enough in the right way to help.

✦ Connection to AI / ML / Deep Learning

Stacking as learned combination. Simple averaging of ensemble predictions is a fixed equal-weight combiner. Stacking replaces it with a learned combiner. This is the same logic that underlies attention mechanisms in transformers — attention is a learned, input-conditioned weighting of value vectors. The “meta-learner” in a transformer is the attention softmax; the “base models” are the value representations.

Mixture of Experts (MoE). Modern large language models (GPT-4, Mixtral, Gemini) use Sparse Mixture of Experts: multiple “expert” feed-forward networks at each layer, with a gating network that routes each token to a subset of experts. This is stacking applied at the sub-layer level: the gating network is the meta-learner, the expert networks are the base models. Unlike standard stacking, MoE is trained end-to-end (no separate OOF phase) and the experts specialise during training.

Knowledge Distillation. A trained ensemble (the “teacher”) is used to generate soft predictions on unlabelled data, and a single smaller model (the “student”) is trained on those soft predictions. The student is a form of meta-learner that learns to mimic the ensemble’s behaviour — compressed stacking.

Ensemble methods in AutoML. Auto-sklearn, H2O AutoML, and Google’s AutoML systems all use stacking as the final step: they train a portfolio of diverse models and use regularised stacking to combine them. The OOF meta-feature generation is automated. This is state-of-the-art AutoML on tabular benchmarks.

The bias-variance view. Stacking, unlike bagging (pure variance reduction) or boosting (bias + variance reduction), is harder to categorise cleanly. The meta-learner can learn to:

  • Assign lower weight to high-variance base models → reduces variance
  • Correct systematic biases of base models → reduces bias
  • Learn input-conditional weighting → reduces both

In the limit of a perfect meta-learner with no overfitting, stacking dominates any single base model. The practical constraint is that the meta-learner itself can overfit the OOF predictions.
