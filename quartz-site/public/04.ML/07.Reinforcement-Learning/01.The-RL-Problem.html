01.The RL Problem

01.The RL Problem

Apr 26, 202616 min read

\

“The agent does not know the rules of the game. It only knows what it did, and what happened next.”

✦ Why RL Is Different

In supervised learning, someone hands you (xi​,yi​) pairs. A teacher has already labelled the correct answer. In unsupervised learning, you have xi​ alone and look for structure.

Reinforcement learning has neither. There is no teacher. There is only an agent living inside an environment, taking actions, and receiving rewards. The agent must figure out, entirely from this signal, what to do.

This changes everything:

-SupervisedUnsupervisedReinforcement
FeedbackCorrect labelNoneScalar reward (delayed, noisy)
i.i.d. data?YesYesNo — actions affect future observations
Exploration needed?NoNoYes — must try things to learn
Credit assignmentImmediateN/ADelayed — which action caused the reward?

The credit assignment problem is the central difficulty: the reward you receive now may be the consequence of an action you took ten steps ago. How do you know which action to credit?

✦ 1. The Markov Decision Process (MDP)

Every RL problem is formalised as a Markov Decision Process. An MDP is a tuple:

M=⟨S,A,P,R,γ⟩

SymbolNameMeaning
SState spaceAll possible situations the agent can be in
AAction spaceAll possible actions the agent can take
P(s′∥s,a)Transition kernelProbability of landing in s′ after taking a in s
R(s,a,s′)Reward functionScalar feedback received after transition
γ∈[0,1)Discount factorHow much the agent cares about future rewards

The Markov property (the thing that makes MDPs tractable):

P(st+1​∣st​,at​,st−1​,at−1​,…)=P(st+1​∣st​,at​)

The future depends on the present state and action only — not on the full history. This is the fundamental assumption. It is often violated in practice (partially observable environments), and we will note when this matters.

1.1 The Agent-Environment Loop

         ┌─────────────────────────────────────────┐
         │                                         │
         ▼                                         │
    ┌─────────┐   a_t    ┌─────────────┐           │
    │  Agent  │ ──────►  │ Environment │           │
    │         │          │             │           │
    │  π(a|s) │ ◄──────  │  P(s'|s,a)  │           │
    └─────────┘  s_{t+1} └─────────────┘           │
         │         r_{t+1}       │                 │
         │                       │                 │
         └───────────────────────┘─────────────────┘
                    one time step

At each time step t:

  1. Agent observes state st​∈S
  2. Agent samples action at​∼π(⋅∣st​)
  3. Environment transitions to st+1​∼P(⋅∣st​,at​)
  4. Agent receives reward rt+1​=R(st​,at​,st+1​)
  5. Repeat

The sequence (s0​,a0​,r1​,s1​,a1​,r2​,s2​,…) is called a trajectory or episode.

1.2 Concrete Examples

DomainSAR
ChessBoard positionLegal moves+1 win, −1 loss, 0 otherwise
CartPole(x,x˙,θ,θ˙)Left/Right+1 per timestep upright
Atari BreakoutRaw pixels (screen)Joystick directionsScore increment
Robot armJoint angles, velocitiesTorquesDistance to target (negated)
Recommender systemUser historyItem to showClick, purchase, dwell time

Notice: in chess, reward is received only at the end of the game. In CartPole, reward is received at every step. The discount factor γ is the mechanism for handling both cases.

✦ 2. The Return

The agent’s goal is not to maximise the immediate reward. It is to maximise the expected sum of future rewards. Define the return (or discounted cumulative reward) from time t:

Gt​=rt+1​+γrt+2​+γ2rt+3​+⋯=∑k=0∞​γkrt+k+1​

Why discount?

  1. Mathematical: ensures Gt​ is finite for bounded rewards. If ∣r∣≤Rmax​, then Gt​≤1−γRmax​​.
  2. Economic: future rewards are uncertain; a reward now is worth more than a reward later.
  3. Practical: γ<1 allows the algorithm to converge. At γ=1, many algorithms diverge.

The recursive structure of the return — this is what makes dynamic programming possible: Gt​=rt+1​+γGt+1​

The return from t equals the immediate reward plus the discounted return from t+1. This single equation is the seed from which Bellman equations grow.

2.1 Finite vs. Infinite Horizon

HorizonSettingReturn
Finite (T<∞)Episodes end (chess, Atari)Gt​=∑k=0T−t​rt+k+1​, γ=1 possible
Infinite (T=∞)Continuing tasks (robot control)Gt​=∑k=0∞​γkrt+k+1​, requires γ<1

For episodic tasks, it is common to define a terminal state sterminal​ that absorbs all transitions with zero reward — this makes finite and infinite horizon mathematically equivalent.

✦ 3. The Policy

The policy π is the agent’s behaviour — the mapping from states to actions.

Stochastic policy: π(a∣s)=P(At​=a∣St​=s) — a probability distribution over actions given state.

Deterministic policy: π(s)=a — a single action for each state.

Stochastic policies are more general and necessary for some environments (e.g., rock-paper-scissors — a deterministic policy is exploitable). Deterministic policies are a special case.

The goal of RL: find the optimal policy: π∗=argmaxπ​Eπ​[G0​]

Everything in RL — value functions, Bellman equations, Q-learning, policy gradients — is a different approach to this optimisation.

✦ 4. Value Functions

Value functions answer the question: “How good is it to be in state s (or to take action a in state s) when following policy π?“

4.1 The State-Value Function Vπ

Vπ(s)=Eπ​[Gt​,​,St​=s]=Eπ​[∑k=0∞​γkrt+k+1​,​,St​=s]

This is the expected return starting from state s, following policy π thereafter.

Intuition: Vπ(s) is the “long-term value” of being in state s under policy π. If Vπ(s)=100, state s is great under π. If Vπ(s)=−50, state s is terrible.

4.2 The Action-Value Function Qπ

Qπ(s,a)=Eπ​[Gt​,​,St​=s,At​=a]

This is the expected return starting from state s, first taking action a, then following policy π thereafter.

The relationship between Vπ and Qπ: Vπ(s)=∑a​π(a∣s)⋅Qπ(s,a)

Vπ(s) is the π-weighted average of Qπ(s,a) over all actions — exactly what you’d expect. The value of a state is the expected value of the actions you’d take there.

Why Qπ is more useful for learning. If you know Qπ(s,a) for all (s,a), you can improve the policy greedily: π′(s)=argmaxa​Qπ(s,a)

without needing to know P(s′∣s,a) — the transition dynamics. This is the key to model-free RL.

4.3 The Advantage Function

Aπ(s,a)=Qπ(s,a)−Vπ(s)

The advantage measures how much better action a is compared to the average action under π in state s. If Aπ(s,a)>0, action a is better than average. If Aπ(s,a)<0, it’s worse.

The advantage function appears naturally in policy gradient methods (Advantage Actor-Critic, PPO) because it reduces variance: instead of asking “is the total return good?”, we ask “is this action better than expected?”

✦ 5. Bellman Equations — The Engine of RL

The Bellman equations express a consistency condition: the value of a state must equal the immediate reward plus the discounted value of the next state. They are derived directly from the recursive structure of the return.

5.1 Bellman Expectation Equations

For Vπ: Start from the definition and expand using Gt​=rt+1​+γGt+1​:

Vπ(s)=Eπ​[Gt​∣St​=s] =Eπ​[rt+1​+γGt+1​∣St​=s] =∑a​π(a∣s)∑s′​P(s′∣s,a)[R(s,a,s′)+γEπ​[Gt+1​∣St+1​=s′]]

Vπ(s)=a∑​π(a∣s)s′∑​P(s′∣s,a)[R(s,a,s′)+γVπ(s′)]​

For Qπ: Same derivation, conditioning on (s,a):

Qπ(s,a)=s′∑​P(s′∣s,a)[R(s,a,s′)+γa′∑​π(a′∣s′)Qπ(s′,a′)]​

These are linear equations in Vπ (or Qπ). Given π and the model P,R, they can be solved exactly by linear algebra (for small state spaces) or by iterative methods.

5.2 The Backup Diagram

Bellman equation for V^π:

         s
        / \
       a₁  a₂        ← weighted by π(a|s)
      / \  / \
    s₁' s₂' s₃'      ← weighted by P(s'|s,a)
    
V^π(s) = Σ_a π(a|s) Σ_{s'} P(s'|s,a) [R + γ V^π(s')]

The value of s is computed by "backing up" from its successor states.

Bellman equation for Q^π:

        (s,a)
        /   \
      s₁'   s₂'       ← weighted by P(s'|s,a)
      / \   / \
    a₁' a₂' ...       ← weighted by π(a'|s')

Q^π(s,a) = Σ_{s'} P(s'|s,a) [R + γ Σ_{a'} π(a'|s') Q^π(s',a')]

5.3 Bellman Optimality Equations

The optimal value functions V^_ and Q^_ satisfy the Bellman optimality equations — the same structure, but with max in place of ∑a​π(a∣s):

\boxed{V^_(s) = \max_a \sum_{s'} P(s'|s,a)\left[R(s,a,s') + \gamma V^_(s')\right]}

\boxed{Q^_(s,a) = \sum_{s'} P(s'|s,a)\left[R(s,a,s') + \gamma \max_{a'} Q^_(s',a')\right]}

Why the max? The optimal policy always takes the best action. So instead of averaging over π(a∣s), we take the maximum.

The optimal policy from Q∗: \pi^_(s) = \arg\max_a Q^_(s,a)

If you have Q∗, the optimal policy is free — just act greedily. This is the core of Q-learning.

5.4 Bellman Equations Are Not Learning Algorithms

The Bellman equations are fixed-point conditions — they characterise what Vπ or Q∗ must look like. They are not algorithms by themselves. The algorithms (Value Iteration, Q-learning, TD learning) use these equations as update rules:

AlgorithmUpdate ruleComes from
Value IterationV(s)←maxa​∑s′​P(s′∥s,a)[R+γV(s′)]Bellman optimality for V∗
Policy IterationEvaluate Vπ exactly, then π←greedy(Vπ)Bellman expectation for Vπ
Q-learningQ(s,a)←Q(s,a)+α[r+γmaxa′​Q(s′,a′)−Q(s,a)]Bellman optimality for Q∗
TD(0)V(s)←V(s)+α[r+γV(s′)−V(s)]Bellman expectation for Vπ

✦ 6. The Optimal Policy Exists — And We Can Find It

Theorem (Existence of π∗). For any finite MDP, there exists at least one deterministic optimal policy \pi^_ such that V^{\pi^_}(s) \geq V^\pi(s) for all s and all π.

Proof sketch. Define V^_(s) = \max_\pi V^\pi(s) pointwise. One can show that the Bellman optimality equation has a unique fixed point V^_ (by contraction mapping — the Bellman operator is a γ-contraction in the ℓ∞ norm). The greedy policy with respect to V∗ is then optimal.

Theorem (Contraction of the Bellman operator). Define the Bellman optimality operator T: (TV)(s)=maxa​∑s′​P(s′∣s,a)[R(s,a,s′)+γV(s′)]

Then ∣TV−TU∣∞​≤γ∣V−U∣∞​ for all V,U.

By Banach’s fixed-point theorem, iterating T converges to the unique fixed point V∗. This is Value Iteration — and the contraction guarantees convergence at rate γk after k iterations.

✦ 7. Key Dichotomies in RL

These distinctions determine which algorithm is appropriate for a given problem. Each is a design choice, not a fact about RL in general.

7.1 Model-Based vs. Model-Free

Model-BasedModel-Free
Uses P(s′∥s,a)?Yes (known or learned)No
PlanningYes — can simulate trajectoriesNo
Sample efficiencyHighLow
ComputationHigh (planning)Low
ExamplesValue Iteration, Dyna-Q, AlphaZeroQ-learning, REINFORCE, PPO

Model-free is the dominant paradigm in deep RL because the transition model is often too complex to learn accurately (e.g., Atari pixels → next pixels). Model-based RL is preferred when the model is available (board games, physics simulators) or the sample budget is tiny (robotics).

7.2 On-Policy vs. Off-Policy

On-PolicyOff-Policy
What data is used?Data from the current policy πData from any policy (including old ones)
Sample efficiencyLower (must discard old data)Higher (can reuse data)
ConvergenceEasier to guaranteeHarder (deadly triad)
ExamplesSARSA, REINFORCE, PPOQ-learning, DQN, SAC

Q-learning is off-policy because the update uses maxa′​Q(s′,a′) — the greedy action — regardless of what policy actually generated the data. This allows learning from a replay buffer of old experience.

7.3 Value-Based vs. Policy-Based vs. Actor-Critic

Value-BasedPolicy-BasedActor-Critic

7.4 Tabular vs. Function Approximation

TabularFunction Approximation

The deadly triad (Sutton & Barto): combining function approximation + bootstrapping + off-policy learning can cause divergence. DQN carefully avoids this with experience replay and target networks — see 02.Model-Free Methods.

✦ 8. Exploration vs. Exploitation — The Fundamental Tension

The agent must explore (try new actions to gain information) and exploit (take the best known action to maximise reward). These are in direct conflict.

The multi-armed bandit is the pure form of this problem (no states, no transitions) — see 03.Exploration vs Exploitation.

In full MDPs, exploration is harder because:

  • The consequences of an action are delayed and entangled with future actions.
  • Some states are only reachable through specific action sequences.

Basic strategies:

StrategyIdeaWhen to use
ϵ-greedyWith prob ϵ, take random actionAlways a reasonable default
Boltzmann / Softmaxπ(a∥s)∝exp(Q(s,a)/τ)When you want graded exploration
UCB (Upper Confidence Bound)Favour actions with high uncertaintyBandits, tabular RL
Thompson SamplingSample from posterior over Q valuesBayesian RL
Intrinsic motivationReward for visiting novel statesSparse reward environments

✦ 9. Worked Example — GridWorld MDP

Setup. A 4×4 grid. Agent starts at top-left. Goal state at bottom-right (reward +1). Cliff state at bottom-left (reward −1, terminal). All other transitions: reward 0. Actions: {N, S, E, W}. γ=0.9.

┌─────┬─────┬─────┬─────┐
│  S  │     │     │     │
├─────┼─────┼─────┼─────┤
│     │     │     │     │
├─────┼─────┼─────┼─────┤
│     │     │     │     │
├─────┼─────┼─────┼─────┤
│  C  │     │     │  G  │
└─────┴─────┴─────┴─────┘
S = Start, G = Goal (+1), C = Cliff (-1)

MDP components:

  • S: 16 grid positions (plus 2 terminal states)
  • A: {N, S, E, W}
  • P(s′∣s,a): deterministic (actions succeed with prob 1, hit wall → stay)
  • R: +1 at G, −1 at C, 0 elsewhere
  • γ=0.9

Value Iteration (first two sweeps, for the state adjacent to G):

Let sG−​ denote the state immediately left of G.

Sweep 1: V(sG−​)=maxa​∑s′​P[R+γV(s′)]=max(…,0+0.9⋅0,…,1+0.9⋅0)=1

(Taking action East reaches G, reward +1, V(G)=0 since terminal.)

Sweep 2: The state two steps left of G updates: V=0+0.9⋅1=0.9

After convergence, V∗(s) decreases with distance to G (and increases near C — the agent learns to avoid it). The optimal policy points toward G everywhere except near C, where it routes around.

✦ 10. Partial Observability — When the Markov Property Fails

The MDP assumes the agent observes the full state st​. Often it doesn’t:

  • Poker: you cannot see opponents’ cards.
  • Robot navigation: the robot sees only its camera, not the full map.
  • Medical treatment: the patient’s true health state is hidden; only symptoms are observed.

The correct model is a Partially Observable MDP (POMDP): M=⟨S,A,O,P,O,R,γ⟩

where O is the observation space and O(o∣s′,a) is the observation model.

The agent maintains a belief state bt​=P(st​∣o0​,a0​,…,ot​) — a probability distribution over states. The belief state is a sufficient statistic for the history, so bt​ is itself Markovian. But ∣B∣ (belief space) is infinite even if ∣S∣ is finite.

Deep RL approximation: use an RNN (LSTM, GRU) to maintain a hidden state that approximates the belief state. This is why RNNs appear in RL for partially observable environments.

✦ 11. Connection to AI / ML / Deep Learning

11.1 Deep RL — Approximating Value Functions with Neural Networks

In the tabular setting, Q(s,a) is stored as a table. For large state spaces (Atari: 210×160×3 pixel screens), this is impossible. Deep Q-Networks (DQN) approximate: Q(s,a)≈Q(s,a;θ)

where θ are the parameters of a convolutional neural network. The Bellman optimality equation becomes the training target: L(θ)=E[(r+γmaxa′​Q(s′,a′;θ−)−Q(s,a;θ))2]

where θ− is a target network — a periodically frozen copy of θ that stabilises training. See 02.Model-Free Methods.

11.2 RL as the Third Pillar of ML

Supervised learning: learn from labelled data. Unsupervised learning: find structure without labels. RL: learn to act from reward signals. These three are genuinely distinct and complementary:

  • A speech recogniser is trained with supervised learning.
  • A language model is pre-trained with self-supervised (unsupervised) learning.
  • A dialogue agent is fine-tuned with RL (RLHF — Reinforcement Learning from Human Feedback).

RLHF is the mechanism behind GPT-4, Claude, and similar models — the MDP is: state = conversation history, action = next token, reward = human preference signal. The policy is the language model.

11.3 The Connection to Optimal Control

RL is essentially optimal control without a known model. Classical optimal control (LQR, MPC) assumes P(s′∣s,a) is known analytically. RL discovers the policy without knowing the model — making it applicable wherever simulation or interaction is possible but analytical models are not.

11.4 AlphaGo / AlphaZero

AlphaZero (Silver et al., 2017) is a model-based RL system for board games:

  • State: board position.
  • Action: legal moves.
  • Model: known (rules of chess/Go).
  • Value network: approximates V∗(s) — trained by self-play.
  • Policy network: approximates π∗(a∣s) — guides Monte Carlo Tree Search.

The Bellman equations are the foundation; the neural networks are the approximation; Monte Carlo Tree Search is the planning algorithm. The MDP formalism unifies all of it.
