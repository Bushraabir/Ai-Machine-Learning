02.Model Free Methods

02.Model-Free Methods

Apr 26, 202625 min read

“Model-free methods are the empiricists of RL — they refuse to model the world, and instead learn entirely from what they experience.”

✦ Where This Note Lives in the Map

01.The RL Problem established the MDP ⟨S,A,P,R,γ⟩, the Bellman equations, and the goal: find π∗.

Dynamic Programming (Value Iteration, Policy Iteration) solves this exactly — but requires knowing P(s′∣s,a) and R(s,a,s′) in closed form, and iterating over the entire state space. Neither assumption holds in most real problems.

Model-free methods discard both requirements. They learn directly from experience — sequences of (st​,at​,rt+1​,st+1​) — without ever building a model of the environment. The price is sample efficiency. The payoff is generality.

This note covers the full hierarchy:

Model-Free RL
├── Dynamic Programming (model-based baseline — for contrast)
│   ├── Policy Evaluation
│   ├── Policy Iteration
│   └── Value Iteration
├── Monte Carlo Methods (learn from complete episodes)
│   ├── MC Prediction
│   └── MC Control (with ε-greedy)
├── Temporal Difference Learning (learn from incomplete episodes)
│   ├── TD(0) — Prediction
│   ├── SARSA — On-Policy Control
│   └── Q-Learning — Off-Policy Control
├── Deep Q-Networks (DQN)
│   ├── Experience Replay
│   └── Target Network
└── Policy Gradient Methods
    ├── REINFORCE
    ├── Actor-Critic (A2C)
    └── Proximal Policy Optimisation (PPO)

✦ Part I — Dynamic Programming (The Ideal Baseline)

Dynamic Programming (DP) solves MDPs exactly when the model P,R is known. We cover it here to establish the benchmark that model-free methods approximate.

1.1 Policy Evaluation — Computing Vπ

Given a fixed policy π, compute Vπ by iterating the Bellman expectation equation:

Vk+1​(s)←∑a​π(a∣s)∑s′​P(s′∣s,a)[R(s,a,s′)+γVk​(s′)]

starting from V0​(s)=0 for all s. This is a synchronous sweep — every state is updated using the values from the previous iteration.

Convergence: Vk​→Vπ as k→∞, at rate γk (from the contraction mapping theorem — see 01.The RL Problem §6).

Complexity per sweep: O(∣S∣2∣A∣) — must loop over all states, actions, and next states.

1.2 Policy Iteration

Alternate between evaluation and improvement:

π₀ →[evaluate]→ V^{π₀} →[improve]→ π₁ →[evaluate]→ V^{π₁} →[improve]→ π₂ → ···

Policy Improvement step: given Vπ, construct a strictly better (or equal) policy: π′(s)=argmaxa​∑s′​P(s′∣s,a)[R(s,a,s′)+γVπ(s′)]

Policy Improvement Theorem. If π′=π, then Vπ′(s)≥Vπ(s) for all s, with strict inequality for at least one s.

Proof. Let s be any state. Since π′ takes the greedy action: Vπ(s)≤maxa​Qπ(s,a)=Qπ(s,π′(s))=E[r+γVπ(s′)∣s,π′(s)] ≤E[r+γmaxa′​Qπ(s′,a′)∣s,π′(s)]≤⋯≤Vπ′(s)

Each step applies the greedy improvement and the Bellman equation. The chain terminates at Vπ′(s). □

Convergence: Policy Iteration converges in a finite number of iterations (at most ∣A∣∣S∣ policies, but in practice much fewer).

1.3 Value Iteration

Collapse evaluation and improvement into a single sweep:

Vk+1​(s)←maxa​∑s′​P(s′∣s,a)[R(s,a,s′)+γVk​(s′)]

This applies the Bellman optimality operator T directly. Convergence follows from the γ-contraction: |V_{k+1} - V^_|_\infty = |\mathcal{T}V_k - \mathcal{T}V^_|_\infty \leq \gamma |V_k - V^*|_\infty

Value Iteration vs. Policy Iteration:

Policy IterationValue Iteration
Inner loopFull policy evaluation (many sweeps)Single sweep
Outer loopFew iterationsMany iterations
When to preferWhen evaluation is cheapWhen convergence speed matters
ConvergenceFinite (in policy space)Asymptotic (in value space)

The fundamental limitation of DP: requires iterating over all s∈S explicitly, and knowing P(s′∣s,a). For Atari (screen pixels) or continuous state spaces, both are intractable. Model-free methods address this.

✦ Part II — Monte Carlo Methods

Monte Carlo (MC) methods learn from complete episodes — they wait until the end of an episode, compute the actual return Gt​, and use it as the target.

Key idea: the expected return E[Gt​∣St​=s] is exactly Vπ(s). So average the actual returns observed after visiting s.

2.1 MC Prediction — Estimating Vπ

Algorithm: First-Visit MC Prediction
─────────────────────────────────────────────────
Input: policy π, number of episodes N
Initialise: V(s) = 0, Returns(s) = [] for all s

For episode = 1, ..., N:
    Generate trajectory: s₀,a₀,r₁,s₁,a₁,r₂,...,sT
    G ← 0
    For t = T-1, T-2, ..., 0:
        G ← γG + r_{t+1}
        If s_t not in {s₀,...,s_{t-1}}:        ← first-visit condition
            Append G to Returns(s_t)
            V(s_t) ← mean(Returns(s_t))
─────────────────────────────────────────────────

First-visit vs. every-visit: First-visit MC only averages returns from the first occurrence of s in each episode; every-visit MC averages all occurrences. Both converge to Vπ by the law of large numbers.

The incremental update form. Instead of storing all returns: V(s)←V(s)+N(s)1​[Gt​−V(s)]

where N(s) is the visit count. With a fixed step size α in place of N(s)1​, this becomes: V(s)←V(s)+α[Gt​−V(s)]

The term [Gt​−V(s)] is the prediction error — how wrong our estimate was. This is the prototype of the TD error we derive next.

Properties of MC:

  • Unbiased: Gt​ is the true return — no approximation.
  • High variance: Gt​ is one sample of a potentially long stochastic trajectory. Variance grows with episode length.
  • Non-bootstrapping: MC does not use estimates of V to update V. It uses the actual return.
  • Requires complete episodes: cannot be used for continuing tasks.

2.2 MC Control — Finding π∗

For control, we need Qπ(s,a) (not Vπ), because without the model we cannot do the greedy improvement step argmaxa​∑s′​P[R+γV(s′)] — we don’t know P.

With Q, greedy improvement requires no model: π′(s)=argmaxa​Q(s,a).

But greedy policies don’t explore — they commit to the currently best-known action and never discover better ones. The standard fix: ϵ-greedy policy:

π(a∣s)={1−ϵ+∣A∣ϵ​​if a=argmaxa′​Q(s,a′) ∣A∣ϵ​​otherwise​

With probability 1−ϵ, exploit; with probability ϵ, explore uniformly.

GLIE (Greedy in the Limit with Infinite Exploration): MC control converges to π∗ if:

  1. Every (s,a) pair is visited infinitely often.
  2. π→π∗ (greedy) in the limit.

This is achieved by decaying ϵ→0 as t→∞.

✦ Part III — Temporal Difference Learning

Temporal Difference (TD) learning is the central idea in RL. It combines:

  • The sampling of Monte Carlo — learns from experience, no model needed.
  • The bootstrapping of Dynamic Programming — updates estimates using other estimates, without waiting for the end of the episode.

3.1 TD(0) — The Simplest TD Method

After each step (st​,at​,rt+1​,st+1​), update:

V(st​)←V(st​)+α​TD targetrt+1​+γV(st+1​)​​−V(st​)​​

The term δt​=rt+1​+γV(st+1​)−V(st​) is the TD error — the difference between the Bellman-predicted value and the current estimate.

Why “temporal difference”? The update uses the difference between value estimates at two different times — V(st​) and V(st+1​).

The bootstrapping insight: instead of waiting for the true return Gt​=rt+1​+γrt+2​+⋯, we substitute rt+1​+γV(st+1​) — a one-step estimate that uses our current (imperfect) value function. This is called bootstrapping.

3.2 MC vs. TD — A Precise Comparison

PropertyMonte CarloTD(0)
TargetGt​ (actual return)rt+1​+γV(st+1​) (bootstrap)
BiasZero (unbiased)Biased (uses approximate V)
VarianceHigh (long trajectory)Low (one-step transition)
Requires episode end?YesNo — updates online
Bootstrapping?NoYes
ConvergenceTo VπTo Vπ (with appropriate α)

The bias-variance tradeoff of TD vs. MC is a direct analogue of the model complexity tradeoff. MC is unbiased but high-variance (like a flexible model with no regularisation). TD is biased but low-variance (like a regularised model). TD typically learns faster in practice.

3.3 The TD(λ) Spectrum

TD(0) uses a 1-step return. MC uses the full return. The n-step return interpolates:

Gt(n)​=rt+1​+γrt+2​+⋯+γn−1rt+n​+γnV(st+n​)

TD(λ) uses an exponentially weighted average of all n-step returns:

Gtλ​=(1−λ)∑n=1∞​λn−1Gt(n)​

  • λ=0: TD(0) — pure bootstrapping.
  • λ=1: Monte Carlo — no bootstrapping.
  • λ∈(0,1): intermediate — often best in practice.
         λ=0                              λ=1
         TD(0)                             MC
          |────────────────────────────────|
     low variance                    high variance
     high bias                        zero bias
     fast learning               slow/stable learning
          ↑
     often works well
     in deep RL (λ≈0)

Eligibility traces are the efficient implementation of TD(λ) — they maintain a decaying credit to each state, allowing multi-step updates in O(∣S∣) per step.

✦ Part IV — TD Control: SARSA and Q-Learning

For control, we extend TD to learn Q(s,a) and derive a policy from it.

4.1 SARSA — On-Policy TD Control

At each step, after taking action at​ and observing rt+1​,st+1​, sample next action at+1​∼π(⋅∣st+1​) and update:

Q(st​,at​)←Q(st​,at​)+α[rt+1​+γQ(st+1​,at+1​)−Q(st​,at​)]

The name SARSA comes from the quintuple (St​,At​,Rt+1​,St+1​,At+1​) used in the update.

On-policy: the target uses Q(st+1​,at+1​) where at+1​ is drawn from the current policy π (e.g., ϵ-greedy). SARSA learns the value of the policy it is actually following — including its exploratory actions.

SARSA converges to Qπ∗ under GLIE conditions (all pairs visited, ϵ→0, ∑αt​=∞, ∑αt2​<∞).

4.2 Q-Learning — Off-Policy TD Control

Q(st​,at​)←Q(st​,at​)+α[rt+1​+γmaxa′​Q(st+1​,a′)−Q(st​,at​)]

One difference from SARSA: the target uses maxa′​Q(st+1​,a′) — the greedy action — regardless of what policy actually generated at+1​.

Off-policy: Q-learning learns Q∗ directly, even while following an exploratory ϵ-greedy policy. The behaviour policy (what generates data) and the target policy (what is being evaluated) are different. This is the defining property of off-policy learning.

Q-learning converges to Q∗ with probability 1 under the same step-size conditions, for any behaviour policy that visits all (s,a) pairs infinitely often.

4.3 SARSA vs. Q-Learning — The Cliff Walking Example

Consider a gridworld with a cliff along the bottom edge. The optimal path hugs the cliff. An ϵ-greedy policy occasionally falls off.

┌────────────────────────────────────────┐
│  S                                     │
│                                        │
│                                        │
│  S ──[Q-learning]──────────────────► G │
│     ──[SARSA]─────────────────────► G  │
│  C  C  C  C  C  C  C  C  C  C  C  C  │
└────────────────────────────────────────┘
  • Q-learning learns the optimal (cliff-hugging) path, because its target is always maxa′​Q. But during training, it occasionally falls off the cliff (due to ϵ-greedy), incurring high reward penalties.
  • SARSA learns a safer path (away from the cliff), because it accounts for the exploratory policy’s occasional falls. SARSA optimises the policy it is actually following.

The lesson: Q-learning optimises for the optimal policy. SARSA optimises for the current policy. In safety-critical settings, SARSA’s conservative behaviour during training is preferable.

4.4 Tabular Q-Learning Algorithm

Algorithm: Q-Learning (Tabular)
──────────────────────────────────────────────────────────
Initialise Q(s,a) = 0 for all s,a; Q(terminal,·) = 0

For each episode:
    s ← initial state
    While s is not terminal:
        a ← ε-greedy(Q, s)                 ← behaviour policy
        Take action a, observe r, s'
        Q(s,a) ← Q(s,a) + α[r + γ max_{a'} Q(s',a') - Q(s,a)]
        s ← s'
──────────────────────────────────────────────────────────

Convergence conditions (Robbins-Monro): ∑t=0∞​αt​=∞∑t=0∞​αt2​<∞

e.g., αt​=t1​ satisfies both. A fixed α (common in practice) does not guarantee convergence to Q∗, but tracks non-stationarity.

✦ Part V — Deep Q-Networks (DQN)

Tabular Q-learning breaks when ∣S∣ is large (continuous states, high-dimensional inputs like images). The fix: approximate Q(s,a)≈Q(s,a;θ) with a neural network.

Naïve function approximation fails. If we simply run Q-learning with a neural network, training is catastrophically unstable. Two reasons:

  1. Correlated updates: consecutive steps (st​,st+1​,st+2​,…) are highly correlated. SGD assumes i.i.d. samples. Correlated gradients cause the network to overfit to recent experience and forget old experience.

  2. Moving targets: the target r+γmaxa′​Q(s′,a′;θ) changes every time θ changes — we are chasing a moving goalpost. This creates instability analogous to trying to hit a target that moves whenever you shoot at it.

DQN (Mnih et al., 2015) fixes both with two mechanisms.

5.1 Experience Replay

Maintain a replay buffer D of past transitions: D=(st​,at​,rt+1​,st+1​)t​

At each training step, sample a random minibatch from D:

  1. Breaks temporal correlations — sampled transitions are approximately i.i.d.
  2. Allows each transition to be used for multiple gradient updates — improves data efficiency.
  3. Smooths the gradient signal over many past experiences.

Buffer size is a hyperparameter (typically 105–106 transitions). Old transitions are discarded when the buffer is full (FIFO).

5.2 Target Network

Maintain a target network Q(s,a;θ−) — a copy of the main network Q(s,a;θ) whose parameters θ− are frozen for C steps (typically C=104) before being updated to θ.

The loss is: L(θ)=E(s,a,r,s′)∼D​[(r+γmaxa′​Q(s′,a′;θ−)−Q(s,a;θ))2]

The target r+γmaxa′​Q(s′,a′;θ−) is now stationary for C steps — the goalpost stops moving. Gradient descent on θ has a stable target to chase.

Main network θ: updated every step via SGD
Target network θ⁻: frozen for C steps, then copied from θ

Step:  1  2  3  ...  C  |  C+1  C+2  ...  2C  |  2C+1  ...
θ:     updated at every step
θ⁻:   ───────────────────┤ copied ───────────────┤ copied

5.3 The DQN Algorithm

Algorithm: DQN
──────────────────────────────────────────────────────────────
Initialise Q(s,a;θ) with random weights θ
Initialise target network θ⁻ ← θ
Initialise replay buffer D with capacity N

For each episode:
    s ← initial state (preprocessed frames)
    While not terminal:
        a ← ε-greedy(Q(s,·;θ))
        Execute a, observe r, s'
        Store (s,a,r,s') in D

        Sample minibatch {(sⱼ,aⱼ,rⱼ,s'ⱼ)} from D
        
        yⱼ ← rⱼ                                   if s'ⱼ is terminal
        yⱼ ← rⱼ + γ max_{a'} Q(s'ⱼ,a';θ⁻)        otherwise

        Gradient step: θ ← θ - α ∇_θ (yⱼ - Q(sⱼ,aⱼ;θ))²
        
        Every C steps: θ⁻ ← θ
──────────────────────────────────────────────────────────────

5.4 DQN Architecture for Atari

Input: 4 stacked 84×84 grayscale frames
       (stacking provides velocity information)
         ↓
Conv1: 32 filters, 8×8, stride 4, ReLU
         ↓

         ↓

         ↓

         ↓

Why no softmax on output? We want raw Q-values, not probabilities. The policy is ϵ-greedy over these values.

5.5 DQN Variants

Double DQNReduces overestimation biasUse θ to select action, θ− to evaluate it

Double DQN deserves a derivation. Standard Q-learning overestimates Q∗ because: E[maxa​Q(s,a)]≥maxa​E[Q(s,a)]

(Jensen’s inequality applied to a convex function of random variables — the max). Fix: decouple action selection from action evaluation:

y=r+γQ!(s′,argmaxa′​Q(s′,a′;θ);,θ−)

Use the online network θ to select the action, but the target network θ− to evaluate it. This breaks the feedback loop that causes overestimation.

✦ Part VI — Policy Gradient Methods

All methods so far are value-based — they learn a value function and derive a policy implicitly (e.g., π(s)=argmaxa​Q(s,a)). The argmax becomes problematic for:

  • Continuous action spaces: argmaxa​Q(s,a) requires a continuous optimisation at every step.
  • Stochastic policies: value-based methods produce deterministic policies; some environments require randomness (e.g., card games, mixed-strategy Nash equilibria).

Policy gradient methods directly parameterise the policy πθ​(a∣s) and optimise the expected return:

J(θ)=Eτ∼πθ​​[G0​]=Eτ∼πθ​​[∑t=0T​rt+1​]

6.1 The Policy Gradient Theorem

Theorem. For any differentiable policy πθ​ and any start state distribution:

∇θ​J(θ)=Eτ∼πθ​​[∑t=0T​∇θ​logπθ​(at​∣st​)⋅Qπθ​(st​,at​)]

Proof (finite horizon, no discount for clarity). Define trajectory τ=(s0​,a0​,r1​,…,sT​):

J(θ)=∑τ​P(τ;θ)R(τ)

∇θ​J(θ)=∑τ​∇θ​P(τ;θ)R(τ)

Apply the log-derivative trick: ∇θ​P(τ;θ)=P(τ;θ)∇θ​logP(τ;θ):

=∑τ​P(τ;θ)∇θ​logP(τ;θ)⋅R(τ) =Eτ∼πθ​​[∇θ​logP(τ;θ)⋅R(τ)]

Now expand logP(τ;θ): logP(τ;θ)=logP(s0​)+∑t​logP(st+1​∣st​,at​)+∑t​logπθ​(at​∣st​)

Taking gradient with respect to θ: the first two terms vanish (they don’t depend on θ): ∇θ​logP(τ;θ)=∑t​∇θ​logπθ​(at​∣st​)

Therefore: ∇θ​J(θ)=Eτ∼πθ​​[∑t​∇θ​logπθ​(at​∣st​)⋅R(τ)]

Replacing R(τ) with the causally correct Qπθ​(st​,at​) (rewards after t only — past rewards don’t depend on at​):

∇θ​J(θ)=Eτ∼πθ​​[t∑​∇θ​logπθ​(at​∣st​)⋅Qπθ​(st​,at​)]​

□

Intuition. The gradient increases the log-probability of actions proportional to how good they were (Q value). If action a in state s led to high return, push θ to make a more likely in s. If it led to low return, make it less likely. This is gradient ascent on J(θ).

The log-derivative trick is also called the REINFORCE trick or score function estimator. It appears throughout variational inference, generative models, and RL.

6.2 REINFORCE — Monte Carlo Policy Gradient

The simplest policy gradient algorithm: replace Qπθ​(st​,at​) with the Monte Carlo estimate Gt​ (actual return from t):

θ←θ+α∑t​∇θ​logπθ​(at​∣st​)⋅Gt​

Algorithm: REINFORCE
─────────────────────────────────────────────────────
For each episode:
    Generate trajectory τ = (s₀,a₀,r₁,...,sT) using π_θ
    For t = 0, ..., T-1:
        G_t ← Σ_{k=t}^{T-1} γ^{k-t} r_{k+1}    (actual return)
        θ ← θ + α G_t ∇_θ log π_θ(a_t|s_t)
─────────────────────────────────────────────────────

The baseline trick — variance reduction. We can subtract any function b(st​) from Gt​ without introducing bias:

∇θ​J(θ)=E[∑t​∇θ​logπθ​(at​∣st​)⋅(Gt​−b(st​))]

Proof that the baseline term vanishes in expectation: E[∇θ​logπθ​(a∣s)⋅b(s)]=∑a​πθ​(a∣s)∇θ​logπθ​(a∣s)⋅b(s) =b(s)∑a​πθ​(a∣s)πθ​(a∣s)∇θ​πθ​(a∣s)​=b(s)∇θ​∑a​πθ​(a∣s)=b(s)∇θ​1=0

The standard choice: b(st​)=Vπθ​(st​). Then Gt​−Vπθ​(st​) is an estimate of the advantage Aπθ​(st​,at​). This dramatically reduces variance.

Problems with REINFORCE:

  • High variance: Gt​ is a full-trajectory Monte Carlo estimate.
  • Slow convergence: must complete episodes before updating.
  • On-policy: must generate new data with the current policy after every update.

6.3 Actor-Critic — Bootstrapped Policy Gradients

Replace the Monte Carlo return Gt​ in the policy gradient with a bootstrapped estimate from a learned value function (the critic):

∇θ​J(θ)≈E[∑t​∇θ​logπθ​(at​∣st​)⋅δt​]

where δt​=rt+1​+γVϕ​(st+1​)−Vϕ​(st​) is the TD error — an estimate of Aπθ​(st​,at​).

Two networks:

  • Actor: πθ​(a∣s) — the policy being optimised.
  • Critic: Vϕ​(s) — estimates the state-value function, trained by TD.
              ┌─────────────────┐
    s_t ─────►│   Actor  π_θ    │──── a_t ────► environment
              └─────────────────┘                  │
                       ↑                           │ r_{t+1}, s_{t+1}
              ∇_θ log π_θ · δ_t                    │
                       │                           ▼
              ┌─────────────────┐         δ_t = r+γV_φ(s')-V_φ(s)
    s_t ─────►│  Critic  V_φ    │◄──────────────────┘
              └─────────────────┘

Actor update: θ←θ+αθ​∇θ​logπθ​(at​∣st​)⋅δt​

Critic update: ϕ←ϕ+αϕ​δt​∇ϕ​Vϕ​(st​)

Why better than REINFORCE?

  • TD critic has much lower variance than MC return Gt​.
  • Can update online — no need to wait for episode end.

Why better than DQN?

  • Works naturally for continuous action spaces (no argmax needed).
  • Stochastic policy enables natural exploration.

A2C (Advantage Actor-Critic): synchronous version — multiple parallel workers generate experience, gradients are averaged, one synchronous update is performed. Stable and parallelisable.

A3C (Asynchronous Advantage Actor-Critic): asynchronous workers update a shared set of parameters independently. Faster wall-clock time, but noisier updates.

6.4 Proximal Policy Optimisation (PPO)

A central problem with policy gradient methods: step size. If we take too large a step in θ-space, the policy changes drastically — the new policy is so different from the old one that the old data is irrelevant, performance collapses, and recovery is difficult. If the step is too small, learning is slow.

Trust Region Policy Optimisation (TRPO) (Schulman et al., 2015) constrains updates to stay within a trust region: maxθ​E[πθold​​(a∣s)πθ​(a∣s)​Aπθold​​(s,a)]s.t.E[DKL​(πθ​∣πθold​​)]≤δ

The constraint is enforced via a conjugate gradient + line search — expensive and complex.

PPO (Schulman et al., 2017) achieves similar results with a simpler objective. Define the probability ratio: rt​(θ)=πθold​​(at​∣st​)πθ​(at​∣st​)​

PPO-Clip objective: LCLIP(θ)=Et​[min(rt​(θ)At​,;clip(rt​(θ),1−ϵ,1+ϵ)At​)]

The clip prevents rt​(θ) from moving too far from 1 in either direction:

  • If At​>0 (action was better than average): we want to increase πθ​(at​∣st​), so rt​>1. But we clip at 1+ϵ — don’t increase probability too aggressively.
  • If At​<0 (action was worse than average): we want to decrease πθ​(at​∣st​), so rt​<1. But we clip at 1−ϵ — don’t decrease probability too aggressively.
   L^CLIP
    ↑
    │         clipped               unclipped
    │    ┌────────────┐           /
    │    │            │          /
    │    │            │         /
    │    │            │        /
    │────┼────────────┼───────/────────► r_t(θ)
    │  1-ε           1      1+ε
    │ (if A>0, clip here)

PPO training loop:

    Collect N steps of data using π_{θ_old}
    Compute advantages Â_t using GAE (see below)
    
    For K epochs:
        For each minibatch:
            r_t(θ) ← π_θ(a_t|s_t) / π_{θ_old}(a_t|s_t)
            L_CLIP ← E[min(r_t·Â_t, clip(r_t,1-ε,1+ε)·Â_t)]
            L_VF ← E[(V_θ(s_t) - V_target_t)²]
            L_entropy ← E[H[π_θ(·|s_t)]]  ← exploration bonus
            
            L_total = L_CLIP - c₁·L_VF + c₂·L_entropy
            θ ← θ + α ∇_θ L_total
    
    θ_old ← θ
────────────────────────────────────────────────────────────

Generalised Advantage Estimation (GAE). The advantage At​ in PPO is estimated using GAE (Schulman et al., 2015b) — a λ-weighted blend of n-step TD errors:

A^t​=∑l=0∞​(γλ)lδt+l​,δt​=rt+1​+γVϕ​(st+1​)−Vϕ​(st​)

  • λ=0: one-step TD advantage — low variance, high bias.
  • λ=1: Monte Carlo advantage — high variance, low bias.
  • λ≈0.95: typical in practice.

GAE with (γ,λ)=(0.99,0.95) is the standard configuration for PPO in continuous control tasks.

✦ Part VII — The Deadly Triad and When Things Diverge

The deadly triad (Sutton & Barto, Ch. 11): instability or divergence arises when all three of the following are combined:

  1. Function approximation (e.g., neural network for Q)
  2. Bootstrapping (TD learning — using estimated values as targets)
  3. Off-policy learning (data not generated by the current policy)

Each pair is fine:

  • Function approx + bootstrapping + on-policy: stable (TD with linear function approx converges on-policy).
  • Function approx + MC + off-policy: stable (no bootstrapping, so no dangerous circularity).
  • Tabular + bootstrapping + off-policy: stable (tabular Q-learning provably converges).

All three together: can diverge. DQN manages this by:

  • Making it “approximately on-policy” via the target network (reduces the extent of off-policy-ness).
  • Using experience replay to stabilise gradients.

This is why deep RL is notoriously fragile — small hyperparameter changes can push a system into the deadly triad regime.

✦ Connection to AI / ML / Deep Learning

The RL Training Loop as Gradient Descent

Value-based methods (Q-learning, DQN) minimise the Bellman residual — a regression loss. Policy gradient methods maximise J(θ) — a non-convex objective. Both are stochastic gradient methods, connected to everything in 01.Linear Regression through 02.Boosting.

RLHF — Language Models as RL Policies

Reinforcement Learning from Human Feedback (the training mechanism for GPT-4, Claude, Gemini):

  1. Supervised Fine-Tuning (SFT): train a language model on high-quality demonstrations — supervised learning.
  2. Reward Model: train a model to predict human preferences between pairs of outputs.
  3. RL Fine-Tuning: treat the language model as a policy πθ​, the reward model as R, and run PPO.

The MDP: state = prompt + generated tokens so far, action = next token, reward = reward model score at end of generation. PPO updates the language model policy to generate text that scores highly on human preference.

KL penalty in RLHF: the PPO objective includes a KL penalty −βDKL​(πθ​∣πSFT​) to prevent the policy from drifting too far from the supervised baseline (which would cause incoherent text). This is analogous to the clip in PPO-Clip.

AlphaGo / AlphaZero — Policy Gradients + MCTS

AlphaZero’s policy network is trained by a policy gradient update where the “policy” is the MCTS output distribution (not πθ​ directly). The value network is trained by TD-style updates. The combination — deep function approximation + planning — is more sample efficient than model-free RL alone.

The Connection: Q-Learning = Gradient Descent on the Bellman Residual

Q-learning’s update: Q(s,a)←Q(s,a)+α[r+γmaxa′​Q(s′,a′)−Q(s,a)]

is exactly a gradient descent step on the loss: L(θ)=E[(r+γmaxa′​Q(s′,a′;θ−)−Q(s,a;θ))2]

with the target held fixed (treating θ− as constant). This connects Q-learning to the linear regression framework — the Bellman target is the “label” and Q(s,a;θ) is the “prediction.”
