05.Hyperparameter Tuning

05.Hyperparameter Tuning

Apr 24, 202616 min read

“The art is not in the model — it’s in knowing which knob to turn, how far, and why.”

✦ What Even Is a Hyperparameter?

Before we tune anything, let’s be precise. A parameter is learned from data during training — the weights w in linear regression, the split thresholds in a decision tree. A hyperparameter is set before training and governs the learning process itself: the regularisation strength λ, the tree depth, the learning rate α.

The distinction matters because hyperparameters are not optimised by the training objective R^(f^​). If you tried to include them in gradient descent, you’d collapse: setting λ=0 always minimises the regularised training loss, giving you a degenerate solution. So we need a separate loop.

Outer loop (hyperparameter search):
  for each candidate config θ_h:
    Inner loop (training):
      fit model on training data → get parameters w*(θ_h)
    Evaluate w*(θ_h) on validation data
  Return θ_h* that minimises validation loss

This is the meta-learning loop. The training loss tells you how well you fit the data you’ve seen. The validation loss tells you how well you generalise. You optimise the latter by searching over θh​.

✦ The Setup: What You’re Searching Over

Let Θ be the hyperparameter space. In practice this is a product of different types:

Θ=Θcontinuous​×Θinteger​×Θcategorical​

Example (Random Forest):

  • ne​stimators∈50,100,200,500,… — integer
  • maxd​epth∈3,5,10,None — integer + None
  • maxf​eatures∈"sqrt","log2",0.5,1.0 — categorical + continuous
  • mins​ampless​plit∈[2,50] — integer

Example (Neural Network):

  • α∈[10−5,10−1] — continuous, log scale
  • \text{batch_size} \in {32, 64, 128, 256} — integer
  • optimizer∈Adam,SGD,RMSProp — categorical
  • \text{n_layers} \in {2, 3, 4, 5} — integer
  • dropout∈[0,0.5] — continuous

The space is high-dimensional, mixed-type, and the objective function is expensive to evaluate — each evaluation requires a full training run. This is what makes hyperparameter optimisation hard.

✦ 1. Grid Search

The Method

Enumerate a finite grid over the hyperparameter space and evaluate every combination.

Θgrid​=λ1​,λ2​,…×C1​,C2​,…×⋯

For k hyperparameters with ni​ values each, the number of evaluations is:

Neval​=∏i=1k​ni​

Example:

  • λ∈0.001,0.01,0.1,1.0 → 4 values
  • C∈0.1,1.0,10.0 → 3 values
  • kernel∈rbf,poly → 2 values

Total evaluations: 4×3×2=24. With 5-fold CV, that’s 24×5=120 model fits.

Properties

  • Exhaustive within the grid — you will find the best combination that exists in your grid
  • Wasteful by design — it allocates equal budget to every dimension, even unimportant ones
  • Scales exponentially — adding one 5-value hyperparameter quintuples the cost
  • Blind to continuous structure — if the true optimum is between λ=0.01 and λ=0.1, you’ll never find it

When to Use

Small search spaces (2-3 hyperparameters, few values each). When you want a reproducible, interpretable sweep. Baseline to compare against.

✦ 2. Random Search

The Key Insight (Bergstra & Bengio, 2012)

“Random search is more efficient than grid search for hyperparameter optimisation of neural networks.”

Why? Consider searching over two hyperparameters, one important and one unimportant. Grid search wastes most of its budget exploring the unimportant dimension. Random search, sampling independently, gets more distinct values of the important parameter for the same budget.

Formal argument. Suppose the effective dimensionality of the problem is deff​≪d (only a few hyperparameters actually matter). With n random trials, you get n distinct values along each important dimension. With n grid trials over a d-dimensional space, you get only n1/d distinct values along each dimension.

For n=100, d=5: grid gives you 1001/5≈2.5 values per dimension. Random gives you 100.

Distribution Choices Matter

Sampling from the wrong distribution concentrates probability mass in the wrong region.

HyperparameterWrong DistributionRight Distribution
Learning rate αUniform [10−5,10−1]Log-uniform: 10U(−5,−1)
Regularisation λUniform [0,1]Log-uniform: 10U(−4,0)
ne​stimatorsUniform [10,1000]Uniform integers
Dropout rate—Uniform [0,0.5]

Why log-uniform for scale parameters? If the optimal α is around 0.001, uniform sampling gives that neighbourhood probability ≈0.001/0.1=1. Log-uniform assigns equal probability to each order of magnitude.

Properties

  • Anytime algorithm — stop early and still have a good result
  • No combinatorial explosion — cost is O(ni​ter) regardless of dimension
  • Non-exhaustive — no guarantee of finding the global optimum
  • Embarrassingly parallel — each trial is independent

✦ 3. Bayesian Optimisation

This is where things get principled. Grid and random search are model-free — they ignore what they’ve learned from previous evaluations. Bayesian optimisation builds a probabilistic model of the objective function and uses it to decide where to evaluate next.

The Framework

Let f:Θ→R be the validation loss as a function of hyperparameters. We want: θ∗=argminθ∈Θ​f(θ)

f is expensive to evaluate (each call = full training run), so we want to be smart about which θ to query.

The Bayesian approach:

  1. Place a prior over f: typically a Gaussian Process f∼GP(m(θ),k(θ,θ′))
  2. After observing Dt​=(θi​,f(θi​))i=1t​, compute the posterior p(f∣Dt​)
  3. Use an acquisition function α(θ;Dt​) to decide θt+1​=argmaxθ​α(θ;Dt​)
  4. Evaluate f(θt+1​), update posterior, repeat

The posterior gives us both a mean prediction μt​(θ) and an uncertainty estimate σt​(θ). The acquisition function balances exploitation (go where μt​ is small) and exploration (go where σt​ is large).

Gaussian Process Surrogate

Recall from Gaussian Processes: a GP is fully specified by its mean and covariance function. The posterior after t observations has closed form:

μt​(θ)=kt​(θ)T(Kt​+σ2I)−1ft​ σt2​(θ)=k(θ,θ)−kt​(θ)T(Kt​+σ2I)−1kt​(θ)

where kt​(θ)=[k(θ,θ1​),…,k(θ,θt​)]T and Kt​ is the t×t Gram matrix.

The cost is O(t3) — GPs don’t scale to large t. In practice, this means Bayesian optimisation is used for ≤ a few hundred evaluations.

Acquisition Functions

Expected Improvement (EI)

Let f∗=mini≤t​f(θi​) be the current best. Define improvement I(θ)=max(f∗−f(θ),0).

EI(θ)=Ef(θ)∼N(μt​,σt2​)​[max(f∗−f(θ),0)]

This has a closed form:

EI(θ)=(f∗−μt​(θ))Φ(Z)+σt​(θ)ϕ(Z),Z=σt​(θ)f∗−μt​(θ)​

where Φ and ϕ are the standard normal CDF and PDF.

Intuition: EI is high when either (a) μt​(θ) is much better than f∗ (exploitation) or (b) σt​(θ) is large (exploration). The balance emerges automatically.

Upper Confidence Bound (UCB)

UCB(θ)=−μt​(θ)+κσt​(θ)

(Negative because we minimise f.) The parameter κ directly controls the exploration-exploitation tradeoff. κ=0 is pure exploitation; κ→∞ is pure exploration.

UCB has strong theoretical guarantees — the cumulative regret ∑t=1T​(f(θt​)−f(θ∗)) grows sublinearly for many kernel families.

Probability of Improvement (PI)

PI(θ)=P(f(θ)<f∗−ξ)=Φ!(σt​(θ)f∗−ξ−μt​(θ)​)

The ξ>0 “exploration jitter” prevents the algorithm from being too greedy. PI is simpler than EI but tends to be more exploitative.

Visualisation: The Bayesian Optimisation Loop

Iteration 1:
  Prior GP (no data)
  ───────────────────────────────────────────────
  μ(θ) = 0 everywhere, σ(θ) = large everywhere
  EI is flat → sample at random → evaluate f(θ₁)

Iteration 2:
  Posterior conditioned on (θ₁, f(θ₁))
  ───────────────────────────────────────────────
  Near θ₁: σ collapses (we know what's there)
  Away from θ₁: σ still large
  EI peaks somewhere promising → evaluate f(θ₂)

...

Iteration t:
  Posterior tightly fits observations
  ───────────────────────────────────────────────
  μ(θ) is a good surrogate for f(θ)
  EI peaks at the suspected optimum or a
  high-uncertainty region → converges

Alternative Surrogate: Tree-structured Parzen Estimator (TPE)

Used by Hyperopt and Optuna. Instead of modelling p(f∣θ) directly, TPE models two densities:

  • ℓ(θ): distribution of θ given f(θ)<fγ∗​ (good configs)
  • g(θ): distribution of θ given f(θ)≥fγ∗​ (bad configs)

where fγ∗​ is the γ-quantile of observed f values (γ=0.15 typically).

The acquisition function is EI∝ℓ(θ)/g(θ). New candidates are sampled from ℓ and selected by maximising ℓ/g.

Why TPE scales better: It uses kernel density estimates in the original hyperparameter space, handles conditional hyperparameters naturally, and avoids the O(t3) GP bottleneck.

✦ 4. Successive Halving and Hyperband

The Problem with Standard Methods

Every evaluation in grid/random/Bayesian search uses the full training budget — all epochs, all data. But most configurations are clearly bad after seeing 1 of the data. We’re wasting 99 of the budget on doomed runs.

Successive Halving

Setup: n configurations, total budget B. Allocate equal budget B/n to each, then eliminate the bottom half, double the budget for survivors, repeat.

Algorithm:

Input: n configurations {θ₁, ..., θₙ}, total budget B, η = 2 (halving rate)
───────────────────────────────────────────────────────────────────────────
S₀ = {θ₁, ..., θₙ}
r₀ = B / (n · ceil(log_η(n)))   # initial budget per config

for k = 0, 1, ..., ceil(log_η(n)) - 1:
    Evaluate each θ ∈ Sₖ with budget rₖ
    Sₖ₊₁ = top ⌊|Sₖ|/η⌋ configs by validation loss
    rₖ₊₁ = rₖ · η
    
Return best config in S_final

Tradeoff: Large n (explore many configs) vs. large r0​ (accurate early estimates). Successive halving forces you to choose.

Hyperband

Hyperband removes the n vs. r0​ dilemma by running multiple brackets of Successive Halving with different initial budgets.

For maximum budget R and η:

  • smax​=⌊logη​R⌋
  • Run brackets s=smax​,smax​−1,…,0
  • Bracket s starts with ns​=⌈s+1smax​+1​ηs⌉ configs and budget rs​=R/ηs

Why it works: Bracket smax​ (many configs, small budget) is great at exploration. Bracket 0 (one config, full budget) is great at exploitation. Hyperband gets both, spending total budget proportional to smax​⋅R.

✦ The Leakage Trap

This deserves its own section because it kills more projects than wrong algorithms do.

The trap: You tune hyperparameters on the validation set. After tuning, you use the same validation set to report final performance. You’ve effectively trained on the validation set — your reported metric is optimistic.

The fix: Three-way split (or nested CV).

Wrong protocol:
  Train → fit model parameters w*(θ_h)
  Val   → select θ_h*
  Val   → report final score ← LEAKAGE

Correct protocol:
  Train → fit model parameters w*(θ_h)
  Val   → select θ_h*
  Test  → report final score ← held out the entire time

The test set must be held out the entire time — never used for model selection, hyperparameter tuning, feature selection, or anything that drives decisions. It is a single-use oracle.

If you don’t have enough data for a three-way split, use nested cross-validation:

Outer loop (k_outer folds):
  for fold (train_outer, test_outer):
    Inner loop (k_inner folds on train_outer):
      for fold (train_inner, val_inner):
        fit model, evaluate → find best θ_h*
    Retrain best θ_h* on full train_outer
    Evaluate on test_outer → one unbiased estimate
Average estimates over outer folds → final generalisation estimate

Nested CV is expensive (kouter​×kinner​×ni​ter fits) but gives an unbiased estimate of generalisation performance.

✦ Practical Notes

Log-scale Hyperparameters

Whenever a hyperparameter spans multiple orders of magnitude, search on a log scale:

λ∼10U(a,b)notλ∼U(10a,10b)

The difference: uniform in [10−4,1] gives 99.99 of mass to [0.1,1]. Log-uniform gives 25 to each decade.

Early Stopping as Regularisation

For gradient-based models, early stopping during hyperparameter search is legitimate and cheap. Stop training when validation loss stops decreasing. This is itself a hyperparameter (patience), but usually less sensitive than learning rate.

Warm Starting

Some algorithms (sklearn estimators with warm_start=True) allow you to reuse previous fits. This can dramatically speed up grid search over ne​stimators in Random Forest: fit with 100 trees, then extend to 200, then 500 — rather than fitting from scratch three times.

Population Based Training (PBT)

A more aggressive strategy for deep learning: run a population of models simultaneously, and periodically replace poorly-performing models with mutated copies of the best ones. Conceptually: genetic algorithms applied to hyperparameter schedules. Used at DeepMind for game-playing agents.

✦ Connection to AI / ML / Deep Learning

Hyperparameter tuning is not a peripheral concern — it is central to modern ML:

Deep Learning is especially sensitive. A neural network with α=0.1 might diverge entirely. The same network with α=10−3 converges to 94% accuracy. With α=10−4, it converges to 96%. The difference between a useless and state-of-the-art model is often the hyperparameters, not the architecture.

AutoML automates this loop. Systems like Auto-sklearn, AutoKeras, and Google’s AutoML pipeline use Bayesian optimisation + Hyperband + Neural Architecture Search (NAS) to automate the entire model selection and tuning process. The “learning” in AutoML is learning the hyperparameter objective.

Neural Architecture Search (NAS) treats the architecture itself as a hyperparameter. DARTS reformulates discrete architecture choices as continuous parameters and differentiates through them. This is hyperparameter optimisation taken to its logical conclusion.

Meta-learning (“learning to learn”) goes further: train a model to predict good hyperparameters for a new task based on dataset meta-features. This is the same spirit as warm-starting Bayesian optimisation with knowledge from previous tasks. MAML (Model-Agnostic Meta-Learning) learns initial parameters that require minimal fine-tuning — another form of optimising across the outer loop.

Foundation Model Fine-Tuning. When fine-tuning BERT or GPT-style models, the learning rate schedule, warmup steps, and weight decay are the most critical hyperparameters. The LLM literature has accumulated strong defaults (e.g., linear warmup + cosine decay, α≈2×10−5 for BERT fine-tuning), but these are themselves the product of massive hyperparameter searches.
