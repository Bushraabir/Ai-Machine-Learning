03.Performance Metrics

03.Performance Metrics

Apr 24, 202619 min read

“A metric is a compressed summary of model behaviour. Every compression loses information. The art is knowing which information you can afford to lose — and which losses will cost you in production.”

✦ Why Metrics Matter More Than People Think

A metric does three things simultaneously:

  1. Defines what “better” means — it is the objective function of model selection
  2. Summarises a distribution of errors into a scalar — information is always lost
  3. Encodes a value judgement about which errors cost more

Choosing the wrong metric is not a technical mistake — it is a specification mistake. A model that perfectly optimises the wrong metric can be actively harmful. Classic examples:

  • Accuracy on imbalanced data: a cancer detector that predicts “no cancer” for everyone achieves 99.5% accuracy when prevalence is 0.5%. It has zero clinical utility.
  • MSE for demand forecasting: penalises overestimation and underestimation equally. If overstock costs 1/unitandstockoutcosts10/unit, MSE optimises the wrong objective.
  • BLEU score for translation: maximises n-gram overlap. A model can score well by producing fluent but factually wrong translations.

The sections below derive each metric from first principles and make explicit what value judgement it encodes.

✦ Part I — Regression Metrics

Setting: y∈R, predictions y^​i​, residuals ei​=yi​−y^​i​.

Mean Squared Error (MSE)

MSE=n1​∑i=1n​(yi​−y^​i​)2=n1​∑i=1n​ei2​

What it encodes: squared error penalises large residuals quadratically. An error of 10 is penalised 100× more than an error of 1. MSE is the right metric when large errors are disproportionately costly.

Probabilistic derivation: MSE is the negative log-likelihood of a Gaussian noise model. If yi​=f(xi​)+ϵi​ with ϵi​∼N(0,σ2):

−logP(D∣θ)=2n​log(2πσ2)+2σ21​∑i​ei2​

Minimising MSE is therefore equivalent to maximum likelihood estimation under Gaussian noise. This is the probabilistic justification for OLS.

Units: squared units of y. Hard to interpret directly.

Sensitivity to outliers: extreme. A single outlier with ∣ei​∣=100 contributes 104 to the sum. For robust regression, prefer MAE or Huber loss.

Root Mean Squared Error (RMSE)

RMSE=MSE​=n1​∑i​ei2​​

Same units as y. Directly interpretable as “typical error magnitude” — but still outlier-sensitive. Preferred over MSE for reporting because of interpretability.

RMSE vs. standard deviation of residuals:

se​=n−p1​∑i​ei2​​

RMSE divides by n; se​ divides by n−p (degrees of freedom, p = number of parameters). For large n, the difference is negligible. se​ is unbiased; RMSE is slightly biased downward.

Mean Absolute Error (MAE)

MAE=n1​∑i=1n​∣yi​−y^​i​∣=n1​∑i​∣ei​∣

What it encodes: all errors penalised linearly. Robust to outliers — a single large ∣ei​∣ contributes proportionally, not quadratically.

Probabilistic derivation: MAE is the negative log-likelihood under a Laplace noise model. If ϵi​∼Laplace(0,b):

P(ϵi​)=2b1​exp!(−b∣ϵi​∣​)

−logP(D∣θ)∝∑i​∣ei​∣

Minimising MAE is MLE under Laplace noise. The optimal predictor under MAE is the conditional median y^​=median(y∣x); under MSE it is the conditional mean y^​=E[y∣x].

Gradient: MAE is not differentiable at ei​=0. The subgradient is sign(ei​). In practice this causes instability near convergence for gradient-based optimisers — use Huber loss instead.

Huber Loss

Combines MSE’s smoothness near zero with MAE’s robustness to outliers:

Lδ​(e)={21​e2​if ∣e∣≤δ δ∣e∣−21​δ2​if ∣e∣>δ​

Quadratic for small residuals (smooth, fast convergence), linear for large residuals (robust to outliers). The hyperparameter δ controls the transition point.

Why it matters in practice: Huber loss is the default in robust regression and is used as the regression head loss in many object detection networks (e.g., Faster R-CNN uses smooth L1, which is Huber with δ=1).

R2 (Coefficient of Determination)

R2=1−SStot​SSres​​=1−∑i​(yi​−yˉ​)2∑i​(yi​−y^​i​)2​

Interpretation: fraction of variance in y explained by the model. R2=1 means perfect prediction; R2=0 means the model does no better than predicting the mean yˉ​; R2<0 means the model is worse than the mean predictor.

Derivation of the decomposition. For OLS specifically (and OLS only, when an intercept is included):

SStot​=SSreg​+SSres​

∑i​(yi​−yˉ​)2=∑i​(y^​i​−yˉ​)2+∑i​(yi​−y^​i​)2

This follows from ϵ^⊥y^​ in OLS (the residuals are orthogonal to the fitted values — a consequence of the normal equations). This decomposition does not hold for arbitrary models or without an intercept.

Pitfalls:

  • R2 always increases as you add features (even noise features). Use adjusted R2: Rˉ2=1−n−p−1(1−R2)(n−1)​, which penalises model complexity
  • R2 is not a measure of predictive accuracy for new data — a model can have high R2 in-sample and poor generalisation
  • For non-OLS models (random forests, NNs), R2 can be negative on the test set even if the model performs well

Mean Absolute Percentage Error (MAPE)

MAPE=n100​∑i​∣yi​∣∣yi​−y^​i​∣​

Scale-free: useful for comparing models across datasets with different units or magnitudes. Used heavily in forecasting (demand, finance).

Critical failure mode: undefined when yi​=0; heavily penalises underestimates relative to overestimates (asymmetric). Prefer sMAPE (symmetric MAPE) or MASE (mean absolute scaled error) for forecasting.

✦ Part II — Classification Metrics

The Confusion Matrix — The Foundation

For binary classification (y∈0,1, positive class = 1):

\begin{array}{c|cc} & \hat{y} = 1 & \hat{y} = 0 \ \hline y = 1 & \text{TP} & \text{FN} \ y = 0 & \text{FP} & \text{TN} \end{array}

  • TP (True Positive): correctly predicted positive
  • FP (False Positive): incorrectly predicted positive — Type I error
  • FN (False Negative): incorrectly predicted negative — Type II error
  • TN (True Negative): correctly predicted negative

Every binary classification metric is a function of these four numbers. Understanding the matrix is understanding all classification metrics.

Accuracy

Accuracy=TP+TN+FP+FNTP+TN​=ncorrect predictions​

When it is meaningful: balanced classes, equal cost of FP and FN.

When it is misleading: class imbalance. If 95% of samples are negative, the trivial classifier y^​=0 achieves 95% accuracy. This is the accuracy paradox.

The deeper problem: accuracy treats all errors equally. In most real problems, FP and FN have different costs. Accuracy ignores this.

Precision and Recall — The Fundamental Tradeoff

Precision=TP+FPTP​Recall=TP+FNTP​

Precision answers: of all instances we predicted positive, what fraction actually are positive? It measures the quality of positive predictions. Low precision = many false alarms.

Recall (sensitivity, true positive rate) answers: of all actual positives, what fraction did we catch? It measures coverage of the positive class. Low recall = many missed positives.

The tradeoff is inherent and real. For any probabilistic classifier, predictions are p^​(y=1∣x), and a threshold τ determines the decision: y^​=1[p^​≥τ].

  • Increase τ: predict positive only when very confident → fewer FP (higher precision), more FN (lower recall)
  • Decrease τ: predict positive more liberally → more TP (higher recall), more FP (lower precision)

Domain determines which matters more:

DomainCostly ErrorPreferredReasoning
Cancer screeningFN (missed cancer)High recallMissing cancer is catastrophic
Spam filteringFP (lost legitimate email)High precisionFalse alarms destroy user trust
Information retrievalDepends on use casePR curvePlot the full tradeoff
Fraud detectionFN (missed fraud)High recallFinancial losses from undetected fraud

F1-Score — Harmonic Mean of Precision and Recall

F1​=Precision+Recall2⋅Precision⋅Recall​=2TP+FP+FN2TP​

Why harmonic mean, not arithmetic? The harmonic mean penalises extreme imbalance between precision and recall. If precision = 1.0 and recall = 0.01:

Arithmetic mean=21.0+0.01​=0.505(looks decent) F1​=1.0+0.012×1.0×0.01​=0.020(correctly poor)

The harmonic mean is ≤ the arithmetic mean, with equality only when both terms are equal. It rewards balanced precision and recall.

Fβ​ generalisation: when FP and FN have different costs, weight recall β times more than precision:

Fβ​=(1+β2)⋅β2⋅Precision+RecallPrecision⋅Recall​

  • β=0.5: precision matters twice as much as recall
  • β=1: F1​, equal weight
  • β=2: recall matters twice as much as precision (use for cancer detection)

Specificity and False Positive Rate

Specificity=TN+FPTN​FPR=1−Specificity=FP+TNFP​

Specificity measures how well the classifier identifies negatives. FPR = probability of a false alarm given a truly negative instance. These appear on the x-axis of the ROC curve.

ROC Curve and AUC

The Receiver Operating Characteristic (ROC) curve plots TPR (recall) vs. FPR at every possible threshold τ∈[0,1].

ROC=(FPR(τ),TPR(τ)):τ∈[0,1]

Key reference points:

  • (0,0): threshold = 1, predict everything negative
  • (1,1): threshold = 0, predict everything positive
  • (0,1): perfect classifier
  • Diagonal: random classifier

AUC (Area Under the ROC Curve):

AUC=∫01​TPR(FPR),d(FPR)

Probabilistic interpretation (Mann-Whitney U statistic): AUC equals the probability that the classifier assigns a higher score to a randomly chosen positive than to a randomly chosen negative:

AUC=P(p^​(y=1∣x+)>p^​(y=1∣x−))

where x+ is a random positive and x− a random negative. This is a threshold-free measure of ranking quality.

Derivation. Let n+​,n−​ be the number of positives and negatives. Order all n predictions by score. The Mann-Whitney U statistic counts concordant pairs:

U=∑i:yi​=1​∑j:yj​=0​1[p^​i​>p^​j​]

Then AUC=U/(n+​⋅n−​). This gives an O(nlogn) algorithm for computing AUC exactly (sort by score, count inversions).

When AUC is appropriate: ranking quality matters, threshold is not fixed. AUC is threshold-invariant — good for comparing classifiers when the operating threshold will be chosen later.

When AUC is misleading: severe class imbalance. AUC can be high even when precision is catastrophically low. Consider a dataset with 1000 negatives and 10 positives. A classifier that ranks all positives above all negatives achieves AUC = 1.0, but at FPR = 1% it may have only 50% precision. Use the PR curve instead.

Precision-Recall Curve

The PR curve plots Precision vs. Recall at every threshold τ.

PR curve=(Recall(τ),Precision(τ)):τ∈[0,1]

Average Precision (AP):

AP=∑k​(Recallk​−Recallk−1​)⋅Precisionk​

This is the area under the PR curve, approximated by the step function of threshold-sorted predictions.

Why PR is preferred under class imbalance: Precision = TP/(TP+FP) — FP is in the denominator. When negatives are abundant, a classifier that generates many FP is correctly penalised by low precision. The ROC curve’s FPR = FP/(FP+TN) — TN is in the denominator — so large TN dilutes the penalty for many FP. The ROC curve is “too forgiving” when negatives vastly outnumber positives.

Comparison:

ScenarioUse
Balanced classes, threshold flexibilityROC / AUC
Imbalanced classes (fraud, disease, rare events)PR curve / AP
Fixed operating point (specific threshold)Precision + Recall at that threshold
Final report scalarF1 (balanced) or Fβ​ (asymmetric costs)

Matthews Correlation Coefficient (MCC)

MCC=(TP+FP)(TP+FN)(TN+FP)(TN+FN)​TP⋅TN−FP⋅FN​

MCC ranges from −1 (perfect inverse prediction) to +1 (perfect prediction). MCC =0 for a random predictor regardless of class balance.

Why MCC is more informative than F1​:

F1​ ignores TN entirely — it does not appear in the formula. This makes F1​ insensitive to how well the classifier identifies negatives. MCC uses all four cells of the confusion matrix. For imbalanced binary classification, MCC is now the recommended metric in computational biology and is increasingly standard in ML (Chicco & Jurman, 2020).

Worked example: dataset with 90 negatives, 10 positives. Classifier predicts all negative:

TP=0, FP=0, FN=10, TN=90

Accuracy=90 Recall=0 F1​=0 MCC=0⋅10⋅90⋅90​0−0​=0

MCC = 0 correctly identifies this as a random-level classifier. Accuracy (90%) is wildly misleading.

✦ Part III — Multi-Class Classification

For C classes, extend the binary confusion matrix to a C×C matrix where entry (i,j) counts samples of true class i predicted as class j.

Macro-averaging: compute the metric for each class independently, then take the unweighted mean. Treats all classes equally regardless of frequency. Sensitive to performance on rare classes.

Micro-averaging: aggregate TP, FP, FN across all classes first, then compute the metric once. Dominated by frequent classes. Equivalent to accuracy for F1.

Weighted averaging: weight each class by its support (number of true samples). Standard in sklearn’s classification_report.

F1macro​=C1​∑c=1C​F1(c)​F1micro​=2∑c​TPc​+∑c​FPc​+∑c​FNc​2∑c​TPc​​

When to use which:

  • Macro: when every class matters equally (e.g., multi-disease diagnosis)
  • Micro: when overall per-sample performance matters (e.g., tag prediction)
  • Weighted: when class frequency should inform the metric (standard reporting)

✦ Part IV — Probabilistic Classifiers

Some classifiers output calibrated probabilities p^​(y=1∣x) rather than hard labels. Evaluating these requires metrics that account for the full probability output.

Log-Loss (Binary Cross-Entropy)

Llog​=−n1​∑i=1n​[yi​logp^​i​+(1−yi​)log(1−p^​i​)]

What it measures: the average negative log-likelihood of the true labels under the predicted distribution. A perfectly calibrated classifier achieves log-loss equal to the entropy of the label distribution. Lower is better.

Why it penalises overconfident wrong predictions so harshly: if the true label is y=1 and the model predicts p^​=0.001, the contribution is −log(0.001)≈6.9. A confident wrong prediction is catastrophically penalised. This incentivises calibration.

Log-loss is the training objective for logistic regression and the output layer of classification neural networks. Using it as the evaluation metric aligns training and evaluation objectives perfectly.

Brier Score

BS=n1​∑i=1n​(p^​i​−yi​)2

MSE for probability predictions. Ranges from 0 (perfect) to 1 (maximally wrong). Less sensitive to extreme predictions than log-loss (quadratic vs. logarithmic penalty).

Brier score decomposition:

BS=Calibrationn1​k∑​nk​(pˉ​k​−yˉ​k​)2​​−Resolutionn1​k∑​nk​yˉ​k​(1−yˉ​k​)​​+Uncertaintyyˉ​(1−yˉ​)​​

where bins k group predictions into intervals of p^​. Calibration measures whether predicted probabilities match empirical frequencies; Resolution measures how much predicted probabilities differ from the base rate (informative classifiers have high resolution); Uncertainty is a property of the data, not the model.

Calibration

A classifier is calibrated if among all instances where it predicts p^​=0.7, approximately 70% are truly positive.

Calibration plot (reliability diagram): bin predictions by p^​, plot mean predicted probability vs. empirical positive rate per bin. A perfectly calibrated classifier lies on the diagonal y=x.

Common miscalibration patterns:

  • Sigmoid-shaped curve (over-confident): model predicts probabilities too close to 0 and 1. Common in SVMs and boosting
  • Inverse sigmoid (under-confident): probabilities too moderate. Common in Naive Bayes

Calibration methods:

  • Platt scaling: fit a logistic regression on top of the raw model scores. Works well for SVMs
  • Isotonic regression: non-parametric, more flexible. Risk of overfitting on small datasets

Calibration matters whenever probabilities are used downstream — risk stratification, decision thresholds based on cost-benefit analysis, ensembling.

✦ Connection to AI, Machine Learning, and Deep Learning

Loss Functions as Training Metrics

The training loss and the evaluation metric should ideally be the same — or at least tightly aligned. When they diverge, optimising the training loss does not optimise the evaluation metric:

Evaluation MetricMatching Training LossNotes
Log-lossBinary cross-entropyPerfect alignment
Brier scoreMSE on probabilitiesGood alignment
AUCSurrogate losses (pairwise ranking losses, ListNet)AUC is non-differentiable; surrogates approximate it
F1Weighted cross-entropy / focal lossF1 is non-differentiable; focal loss addresses class imbalance
BLEU (NLP)Cross-entropy on tokensSevere mismatch — active research in RLHF, minimum Bayes risk decoding

The mismatch between training loss and evaluation metric is a fundamental tension in applied ML. It motivates reinforcement learning from human feedback (RLHF) in language models: the evaluation “metric” is human preference, which is non-differentiable, so a reward model is trained to approximate it, and policy gradient methods optimise the approximation.

Focal Loss — Addressing Imbalance in Deep Learning

Lin et al. (2017, RetinaNet) introduced focal loss for object detection, where the class imbalance between background and objects is extreme (∼ 1000:1):

FL(pt​)=−αt​(1−pt​)γlog(pt​)

where pt​ is the model’s probability for the true class, γ>0 is the focusing parameter, and αt​ is a class weight.

The term (1−pt​)γ down-weights easy negatives (where pt​≈1 for class 0, so the model is already confident). For γ=0, focal loss reduces to standard cross-entropy. For γ=2, a well-classified example with pt​=0.9 contributes only (0.1)2=0.01× its cross-entropy loss — effectively, easy examples barely affect the gradient.

This is a direct consequence of the precision-recall tradeoff baked into the loss function.

Metrics in LLM Evaluation

Evaluating large language models is an open research problem precisely because no single metric captures the relevant properties:

PropertyMetricProblem
FluencyPerplexityLow perplexity ≠ useful output
Translation qualityBLEUFails on paraphrases; doesn’t measure factuality
SummarisationROUGERecall-oriented; rewards copying source
FactualityFactScore, SAFEExpensive; requires retrieval
Human preferenceWin rate, EloNo ground truth; expensive; inconsistent
ReasoningAccuracy on benchmarksContamination, saturation issues

The impossibility of a single metric for language model quality is why RLHF was developed: learn a reward model from human comparisons, then optimise it. The reward model is itself a learned metric.

✦ You Know This When…

  • You can derive MSE as MLE under Gaussian noise and MAE as MLE under Laplace noise — from the likelihood function, not from memory
  • You can explain why the optimal predictor under MSE is the conditional mean and under MAE is the conditional median
  • You can derive the AUC as the Mann-Whitney U statistic and implement it in NumPy without sklearn
  • You can construct a dataset where accuracy is 95% and the model is completely useless — and explain which metrics correctly identify this
  • You can explain the precision-recall tradeoff mechanistically (in terms of the decision threshold) and choose the right operating point for a given cost structure
  • You can explain what calibration means, draw a reliability diagram, and name two calibration methods
  • You can explain focal loss as a direct response to the class-imbalance problem, and derive it from cross-entropy
