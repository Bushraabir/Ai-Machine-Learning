05.Kapsack Problem

05.Kapsack Problem

Apr 02, 202619 min read

“The knapsack problem is one of the most honest problems in all of computer science. It looks trivial — I have items with weights and values, I want to fill a bag optimally — and yet it is NP-hard. Every approach I try turns out to either be exponential in the worst case, or only approximate, or pseudopolynomial (which sounds polynomial but isn’t). And then, astonishingly, someone turned it into a public-key cryptosystem — and then someone else broke that cryptosystem using the very structure that was supposed to make it hard. The knapsack problem is where algorithms, complexity theory, and cryptography all collide.”

The Problem

0-1 Knapsack. Given n items, each with weight wi​>0 and value vi​>0, and a knapsack of capacity W, find the subset S⊆1,…,n that maximises total value subject to the weight constraint:

maxS⊆1,…,n​∑i∈S​vi​subject to∑i∈S​wi​≤W

The “0-1” means each item is either taken (xi​=1) or not (xi​=0) — no fractional items, no duplicates. In integer programming notation:

max∑i=1n​vi​xi​s.t.∑i=1n​wi​xi​≤W,xi​∈0,1

Variants:

  • Fractional knapsack: Items can be taken in fractions. Solvable in O(nlogn) by a greedy algorithm — take items in decreasing order of value density vi​/wi​.
  • Unbounded knapsack: Each item can be taken any number of times.
  • Bounded knapsack: Item i can be taken at most ci​ times.
  • Multi-dimensional knapsack: Multiple weight constraints (e.g., weight and volume).

The 0-1 version is the hard one. All complexity discussion below is about 0-1 knapsack unless stated.

Brute Force: O(2n)

The naive approach: enumerate all 2n subsets, compute total weight and value for each, return the feasible subset with maximum value.

Correctness: Trivially correct — we check every possibility.

Complexity: Θ(2n⋅n) — one factor of n for computing the sum. For n=30, that’s ≈1010 operations. For n=60, ≈1019. Completely impractical.

Meet-in-the-middle (slight improvement): Split items into two halves of size n/2. Enumerate all 2n/2 subsets of each half, storing (weight, value) pairs. For each subset of the left half, binary search the right half for the highest-value subset that fits in the remaining capacity. Total: O(2n/2⋅n). For n=60: ≈1010 — still impractical but better. This is the best known exact algorithm in the exponential family.

Dynamic Programming: O(nW)

The standard exact algorithm for small W.

Recurrence. Define:

dp[i][w]=maximum value using items 1,…,i with weight capacity w

Base case: dp[0][w]=0 for all w (no items, no value).

Transition: For item i with weight wi​ and value vi​:

dp[i][w]={dp[i−1][w]​if wi​>w(can’t take item i) max!(dp[i−1][w],;vi​+dp[i−1][w−wi​])​if wi​≤w​

The second case: either skip item i (value dp[i−1][w]) or take it (value vi​ plus the best we can do with the remaining capacity w−wi​, using items 1,…,i−1).

Correctness proof by induction.

Claim: dp[i][w] is the maximum value achievable using items 1,…,i with capacity w.

Base case: dp[0][w]=0 — no items available, maximum value is 0. ✓

Inductive step: Assume dp[i−1][⋅] is correct. In any optimal solution for items 1,…,i with capacity w, either item i is included or not.

  • If not included: optimal value =dp[i−1][w] by the inductive hypothesis.
  • If included: wi​≤w (feasibility), and the remaining items 1,…,i−1 must be packed optimally in capacity w−wi​, giving value vi​+dp[i−1][w−wi​] by the inductive hypothesis.

Taking the max of both cases gives dp[i][w]. ■

Complexity: O(nW) time, O(W) space (maintain only the previous row — note that the transition only reads dp[i−1], so I can overwrite in place if I scan w from W down to wi​).

Reconstruction: To recover the optimal subset (not just the value), maintain a boolean table keep[i][w]=1[item i is taken in the optimal solution for (i,w)]. Then backtrack from (n,W).

Why O(nW) is NOT Polynomial

Here is the subtlety that trips people up.

The complexity O(nW) looks polynomial. It is not. It is pseudopolynomial.

Why? The input size is O(nlogW+∑i​logwi​+∑i​logvi​) bits — to specify W requires log2​W bits, not W bits. If I double the number of bits used to represent W (i.e., replace W with W2), the DP table size doubles exponentially in the input size.

Formally: Polynomial time means polynomial in the length of the input. The input length is L=O(nlogW). The DP runs in time O(nW)=O(n⋅2logW)=O(n⋅2L/n) — exponential in L/n.

Intuition: W=1018 can be written in 60 bits — a tiny input. But the DP table has 1018 entries — completely infeasible. The DP is only practical when W is small (say, ≤106 or so).

This distinction — polynomial vs pseudopolynomial — is critical. The knapsack DP is not a polynomial-time algorithm. The knapsack problem remains NP-hard.

I remember being confused about this the first time I saw it. ”O(nW) — that’s linear in n and W, which are the problem parameters!” But the problem parameters are not the input size. The input size is the number of bits needed to write down the problem. W contributes logW bits, not W bits. Pseudopolynomial algorithms are fast when the parameter values are small but slow when the values are large — even if the values are written compactly.

NP-Hardness

Theorem. 0-1 Knapsack is NP-hard.

Proof (reduction from Subset Sum).

Subset Sum: Given integers a1​,…,an​ and target T, does there exist S⊆1,…,n with ∑i∈S​ai​=T?

Subset Sum is NP-complete (standard result — reduce from 3-SAT or from Partition).

Reduction: Given a Subset Sum instance (a1​,…,an​,T), construct a Knapsack instance:

  • Set wi​=vi​=ai​ for all i.
  • Set W=T.

Claim: The Subset Sum instance has a solution iff the Knapsack instance has optimal value ≥T.

  • (⇒) If ∑i∈S​ai​=T, then ∑i∈S​wi​=T≤W (feasible) and ∑i∈S​vi​=T.
  • (⇐) If the Knapsack has value ≥T, then there exists S with ∑i∈S​vi​≥T and ∑i∈S​wi​≤T. Since vi​=wi​=ai​>0 and ∑ai​≤T, combined with ∑ai​≥T, we get ∑i∈S​ai​=T.

The reduction is polynomial (linear time). So Knapsack is NP-hard. ■

Knapsack is also in NP: Given a candidate subset S, verify feasibility and value in O(n). So 0-1 Knapsack is NP-complete (as a decision problem: “is there a feasible subset with value ≥V?”).

Approximation: The FPTAS

Since exact solution is NP-hard (assuming P=NP), what can we approximate?

Definition. An algorithm is a (1−ϵ)-approximation for maximization if it returns a solution of value ≥(1−ϵ)⋅OPT for any ϵ>0.

Definition. A Fully Polynomial-Time Approximation Scheme (FPTAS) is a (1−ϵ)-approximation algorithm that runs in time polynomial in both n and 1/ϵ.

Theorem. 0-1 Knapsack has an FPTAS.

Construction.

  1. Let vmax​=maxi​vi​. Set the scaling factor K=⌊ϵvmax​/n⌋.
  2. Define scaled values vi′​=⌊vi​/K⌋ (integer division).
  3. Run the DP on the scaled instance: the scaled optimal value is at most V′=∑i​vi′​≤∑i​vi​/K≤n⋅vmax​/K≤n2/ϵ.
  4. DP runs in time O(n⋅V′)=O(n3/ϵ) — polynomial in n and 1/ϵ.
  5. Return the optimal solution for the scaled instance.

Approximation guarantee. Let S∗ be the true optimum and S^ the FPTAS solution. For any item i: vi′​=⌊vi​/K⌋≥vi​/K−1, so:

\sum_{i \in S^_} v_i' \geq \sum_{i \in S^_} (v_i/K - 1) = \frac{\text{OPT}}{K} - |S^*| \geq \frac{\text{OPT}}{K} - n

Since S^ is optimal in the scaled problem:

∑i∈S^​vi′​≥∑i∈S∗​vi′​≥KOPT​−n

So the unscaled value of S^:

∑i∈S^​vi​≥K∑i∈S^​vi′​≥K!(KOPT​−n)=OPT−nK≥OPT−ϵvmax​≥OPT(1−ϵ)

using nK≤ϵvmax​ and vmax​≤OPT (the single best item is a lower bound on OPT). ■

The FPTAS is one of the most elegant tricks in approximation algorithms. The DP is pseudopolynomial because W and V can be large. The fix: scale down the values so that V′ is bounded by a polynomial in n and 1/ϵ. The scaling introduces a small additive error per item, which telescopes to a (1−ϵ) multiplicative bound. The insight is that if I only care about an ϵ-approximation, I don’t need the last few bits of precision in the values — rounding them loses at most ϵ⋅OPT.

Greedy and Its Failure

Fractional knapsack greedy: Sort items by value density vi​/wi​ descending, take items greedily until the knapsack is full (take the last item fractionally if needed). This is optimal for the fractional variant — provably. Standard exchange argument proof.

0-1 knapsack greedy failure: The greedy fails for 0-1 knapsack. Counterexample:

ItemWeightValueDensity v/w
1111.0
21090.9

W=10. Greedy takes item 1 (highest density), then item 2 (fits, since 1+10>10… wait, 1+10=11>10). So greedy takes only item 1, value =1. Optimal: take item 2 alone, value =9.

How bad can greedy be? The greedy can be arbitrarily worse than optimal. In the example above, the ratio is 1/9→0 as I scale the values. There is no constant approximation ratio for the greedy on 0-1 knapsack.

A 1/2-approximation: Run the greedy on the fractional problem to get a fractional solution of value OPTf​≥OPT. The fractional solution uses at most one fractionally taken item (the “break” item). Compare: (value of all items except break item) vs (value of break item alone). Take the better. This gives value ≥OPTf​/2≥OPT/2. A 1/2-approximation in O(nlogn).

Probabilistic Analysis: How Hard Is Knapsack on Average?

Worst-case NP-hardness doesn’t mean every instance is hard. What does a “random” knapsack instance look like?

Model. Draw wi​∼Uniform(0,1) and vi​∼Uniform(0,1) i.i.d. Set W=n/2 (half the total expected weight).

Expected total weight: E[∑wi​]=n/2=W. So the capacity is exactly at the “interesting” point — not so loose that everything fits, not so tight that nothing fits.

Observation. For random instances with W=Θ(n), the DP runs in O(nW)=O(n2) — polynomial in n. The pseudopolynomiality bites only when W is exponentially large relative to n.

The continuous relaxation (fractional knapsack) is tight on average. For random instances:

OPTinteger​/OPTfractional​→1as n→∞

Informal argument: In the fractional solution, the break item is taken fractionally. But as n→∞, the break item’s fractional part becomes a negligible fraction of the total value — O(vmax​/OPT)=O(1/n) contribution. So the integrality gap vanishes.

More precisely: By concentration inequalities (Chernoff/Hoeffding), the total value of items packed by the greedy concentrates sharply around its expectation. The fractional “wasted” portion of the break item has expected value E[vbreak​/2]=O(1/n⋅OPT) — vanishing relative to OPT.

This is the usual phenomenon with NP-hard problems on random instances: the hard instances are rare, specially structured, and the typical case is much easier. The “hard” instances for knapsack are ones where many subsets have weights very close to W — an arithmetic coincidence that doesn’t arise generically. Random instances with continuous weights are easy.

The hardest instances. The knapsack problem is hardest when:

  1. Many subsets have total weight exactly W — many feasible solutions to compare.
  2. Items have similar value densities vi​/wi​ — hard to discriminate between items.
  3. W is large (making DP infeasible) but not so large that all items fit.

Instances with weights drawn from 1,…,poly(n) uniformly are in the “easy” regime because W is polynomial and DP works. The hard regime is W=Θ(2n) — but then the weights themselves require Ω(n) bits to specify, so the input is large anyway.

Branch and Bound

In practice, exact knapsack solvers use branch and bound — an implicit enumeration of the 2n subsets, pruning branches that can’t beat the current best solution.

Algorithm skeleton:

def branch_and_bound(items, W):
    best = greedy_solution(items, W)     # Initial lower bound
    
    def recurse(i, remaining_W, current_value):
        nonlocal best
        if i == n:
            best = max(best, current_value)
            return
        
        # Upper bound: fractional knapsack on remaining items
        ub = current_value + fractional_knapsack(items[i:], remaining_W)
        if ub <= best:
            return   # Prune: can't beat current best
        
        # Branch: include item i
        if items[i].weight <= remaining_W:
            recurse(i+1, remaining_W - items[i].weight,
                    current_value + items[i].value)
        
        # Branch: exclude item i
        recurse(i+1, remaining_W, current_value)
    
    recurse(0, W, 0)
    return best

The bounding function — fractional knapsack on remaining items — is an upper bound on what’s achievable from state (i, \text{remaining_W}), because the fractional relaxation is always ≥ the integer optimum.

Correctness: The tree enumerates all 2n subsets implicitly, but prunes branches where the upper bound can’t improve the best known solution. Correctness follows from the validity of the upper bound.

Complexity: Worst case O(2n) (no pruning, all branches explored). In practice, with good bounding and smart branching order (e.g., by value density), branch and bound solves instances with n=100–1000 in seconds — far better than the worst case.

LP relaxation as bound. An even tighter upper bound: solve the LP relaxation (allow xi​∈[0,1], not just 0,1). This requires solving an LP at each node — more expensive per node, but fewer nodes explored. This is the basis of modern mixed-integer programming (MIP) solvers.

The Merkle-Hellman Knapsack Cryptosystem

Here is where things get strange. In 1978, Merkle and Hellman proposed a public-key cryptosystem based on the knapsack problem. The idea: hiding a structured (easy) knapsack problem inside an apparently random (hard) one.

Superincreasing Sequences

Definition. A sequence a1​,a2​,…,an​ is superincreasing if each element exceeds the sum of all preceding elements:

ak​>∑j=1k−1​aj​for all k=2,…,n

Example: 1,2,4,8,16,… — powers of 2 are superincreasing.

Key property: A superincreasing knapsack is solvable in O(n) by a greedy algorithm.

Algorithm: Given target T and superincreasing a1​,…,an​ (sorted descending for clarity: an​>an−1​>⋯):

For i = n, n-1, ..., 1:
    if a_i <= T:
        include a_i  (set x_i = 1)
        T -= a_i

Correctness: Since an​>∑j=1n−1​aj​, if the target T≥an​, then item n must be included in any solution — all other items combined are insufficient. So we greedily include or exclude the largest element, reduce the target, and recurse. Unique solution exists iff the target is achievable. ■

Key Generation

  1. Generate a superincreasing sequence a=(a1​,…,an​) — the private key.
  2. Choose modulus m>∑i​ai​ and multiplier w with gcd(w,m)=1 — so w has a multiplicative inverse w−1modm.
  3. Compute the public key b=(b1​,…,bn​) where bi​=w⋅ai​modm.

The public key b looks like a random knapsack instance — hard to solve.

Encryption and Decryption

Encryption (sender knows b, wants to send n-bit message x∈0,1n):

c=∑i=1n​bi​xi​=∑i=1n​(wai​modm)xi​

Send ciphertext c.

Decryption (receiver knows a,w,m):

  1. Compute c′=w−1cmodm.
  2. Note: c′=w−1∑i​(wai​modm)xi​modm=∑i​ai​xi​modm.
  3. Since m>∑i​ai​≥∑i:xi​=1​ai​, there is no wraparound — c′=∑i​ai​xi​ exactly.
  4. Solve the superincreasing knapsack ∑i​ai​xi​=c′ in O(n).

Why it seems secure: An adversary sees b and c. To decrypt, they must solve ∑i​bi​xi​=c — an apparently random knapsack instance. NP-hard!

Breaking It: The Shamir-Zippel Attack (1982)

Shamir (and independently others) broke the Merkle-Hellman system in 1982 using lattice reduction — specifically, the LLL algorithm.

The attack, intuitively. The public key b is not a truly random knapsack. It is a modular transformation of a superincreasing sequence. The structure is hidden, but not destroyed — it lives in a lattice.

Setup. The attacker wants to find w−1modm (or equivalently, a pair (w′,m′) that transforms b back into a superincreasing sequence). This is a problem of finding a short vector in a lattice.

The lattice. Construct the (n+1)×(n+1) lattice basis matrix:

B=(m​0​0​⋯​0 b1​​1​0​⋯​0 b2​​0​1​⋯​0 ⋮​​​⋱​⋮ bn​​0​0​⋯​1​)

Any vector in the lattice L(B) has the form Bz for integer z. One particular short vector encodes (w−1,a1​,a2​,…,an​) scaled appropriately — the private key.

LLL algorithm (Lenstra-Lenstra-Lovász, 1982): given a lattice basis, find a “reasonably short” vector in polynomial time. For the Merkle-Hellman lattice, this short vector recovers (or approximates) the private key.

Result: The Merkle-Hellman cryptosystem is completely broken in practice. Any ciphertext can be decrypted by an adversary using the LLL algorithm in polynomial time.

The Merkle-Hellman break is one of the most instructive failures in cryptography. The designers believed that modular transformation destroyed the superincreasing structure — and it does, in the sense that b is indistinguishable from a random sequence by naive tests. But the structure is preserved in a higher-dimensional sense: the transformation bi​=wai​modm maps the private key to a specific short vector in a lattice, and lattice basis reduction finds short vectors efficiently. “Hiding” structure by modular arithmetic is not the same as destroying it. The lesson: security arguments must be rigorous, not intuitive.

Connections to Other Topics

To Code-Breaking — Classical Ciphers & Information Theory: The Merkle-Hellman break uses the LLL algorithm, which is a polynomial-time algorithm for an apparently hard problem. Similarly, Vigenère seemed secure but had exploitable structure. The common theme: security must be proved against all polynomial-time algorithms, not just obvious ones.

To Dynamic Programming: The knapsack DP is the canonical example of DP over subsets, illustrating the principle of optimal substructure. The recurrence dp[i][w]=max(dp[i−1][w],vi​+dp[i−1][w−wi​]) is the template I reach for whenever I see a binary include/exclude decision.

To NP and Computational Complexity: The reduction from Subset Sum to Knapsack is a prototypical polynomial-time reduction. The FPTAS illustrates that NP-hardness doesn’t preclude efficient approximation — a subtlety that distinguishes knapsack from problems like Max-Clique (which has no FPTAS unless P=NP).

To probability: The probabilistic analysis (random instances are easy) is an instance of a general phenomenon. Many NP-hard problems are easy on average. The theoretically hard instances are measure-zero in the space of all instances. This motivates the study of smoothed complexity (Spielman and Teng) — worst case over small random perturbations of instances — as a more realistic complexity measure than worst-case.

One-Line Summary for Future Me

0-1 Knapsack is NP-complete; the DP is O(nW) but pseudopolynomial (not truly polynomial since W contributes logW bits of input); there is an FPTAS giving (1−ϵ)-approximation in O(n3/ϵ); and the Merkle-Hellman cryptosystem — which tried to hide a superincreasing knapsack behind a modular transformation — was broken in polynomial time by LLL lattice reduction, illustrating that hiding structure is not the same as destroying it.
