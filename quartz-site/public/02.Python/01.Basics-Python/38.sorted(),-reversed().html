38. sorted() and reversed()

“Sorting is not a primitive operation — it is a decision. Every call to sorted() encodes an assumption about what ‘order’ means. Making that assumption explicit is what the key= parameter is for.”

Two Functions, Two Contracts

Python gives you two built-in ordering tools:

The critical distinction: sorted() always returns a new list. list.sort() sorts in place and returns None — a common source of bugs. reversed() returns a lazy iterator, not a list.

The key= Parameter — The Real Power

key= accepts a callable. Before comparing any two elements, Python calls key(element) and compares the results, not the elements themselves. The original elements are returned; only the comparison uses the key values.

Multi-Key Sorting — Tuples as Keys

To sort by multiple criteria, return a tuple from key=. Python compares tuples lexicographically: first element first, then second on ties, and so on.

The negation trick for descending numeric keys: negate the number to flip the sort order for that field while keeping other fields ascending. This avoids having to call sorted() multiple times.

Sorting Dictionaries

operator Module — Faster Than Lambdas

operator.attrgetter and operator.itemgetter are faster than equivalent lambdas because they are implemented in C.

Use operator module functions in performance-critical sorting code and anywhere you need the idiom to be readable without a lambda.

Python’s Sort Algorithm — Timsort

Python uses Timsort, a hybrid merge sort / insertion sort algorithm.

  • Time complexity: O(nlogn) worst case, O(n) on already-sorted or nearly-sorted data
  • Space complexity: O(n) auxiliary space
  • Stable: elements with equal keys appear in the same relative order as in the input

Stability matters. It means you can sort by multiple criteria through sequential sorts, and the last sort’s order is preserved for elements equal under the last key.

The single-pass tuple key approach is preferred, but the sequential-sort technique appears in legacy code and is worth recognising.

list.sort() vs sorted() — When to Use Which

Rule: use sorted() when you need the original preserved, or when sorting a non-list iterable. Use .sort() when mutating in place is acceptable and you want to avoid the memory cost of a new list.

reversed() — Lazy Reversal

reversed(seq) returns a reversed iterator that yields elements from the end to the start. It does not copy the sequence.

reversed() vs Slice [::-1]

Use reversed() when you only need to iterate once and don’t need a list. Use [::-1] when you need a concrete reversed copy to pass around, index, or iterate multiple times.

reversed() Requires a Sequence

reversed() does not work on arbitrary iterables — only on sequences (objects with __len__ and __getitem__, or a __reversed__ method).

Custom Sort Order — functools.cmp_to_key

Occasionally you have a comparison function cmp(a, b) that returns negative/zero/positive rather than a key. Use functools.cmp_to_key to convert it.

cmp_to_key is the escape hatch for legacy comparison functions or cases where expressing a total order as a single key value is difficult. Use it rarely — key= covers almost everything more cleanly.

Summary

sorted() is a pure function: it takes any iterable, returns a new sorted list, never mutates. reversed() is a lazy iterator over a sequence in reverse, costing O(1) memory. The key= parameter is the entire theory of sorting in Python — every ordering decision is expressed as a function from element to comparable value.
