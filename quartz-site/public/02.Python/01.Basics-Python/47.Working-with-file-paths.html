The Core Problem

A file path is a string like "data/train/images/img_001.png". But strings are dumb — they know nothing about the file system. Concatenating them with + produces platform-dependent bugs, and querying their properties requires a zoo of os functions.

Python gives you two interfaces:

ModuleStyleWhen to use
os.pathProcedural, string-basedLegacy codebases, stdlib interop
pathlib.PathObject-oriented, modernEverything new you write

The rest of this note teaches both, but the bias is toward pathlib. It is the right abstraction and has been the standard since Python 3.4.

pathlib.Path — The Object-Oriented Interface

A Path object represents a file system path. It knows whether it is absolute or relative, what its components are, and how to interact with the OS.

p is not a string. It is an object that wraps the path and provides methods. It does print like a string, though:

Python automatically returns the correct subclass (PosixPath or WindowsPath) based on the OS. Your code stays the same.

Constructing Paths

The / operator is overloaded on Path objects. It calls __truediv__ and joins path segments correctly for the current OS — no manual slash handling.

This works identically on Windows (produces backslashes internally) and Unix (forward slashes). You never write os.sep or \\.

Connection to AI / Machine Learning / Deep Learning

File path handling is the unglamorous foundation of every ML pipeline. Bugs here surface as FileNotFoundError at 3am during a training run, or silently corrupt your train/test split by loading the wrong directory.

Dataset Loading — torchvision.datasets.ImageFolder

ImageFolder is a standard PyTorch dataset that reads an ImageNet-style directory:

data/
├── train/
│   ├── cat/     img_001.jpg  img_002.jpg ...
│   └── dog/     img_001.jpg  img_002.jpg ...
└── val/
    ├── cat/
    └── dog/

The directory structure is the label. Getting the paths wrong here corrupts your entire dataset.

Mental model: a Path object is a smart string that knows it represents a location in the file system. The / operator is path joining. Methods that end in questions (exists(), is_file()) query the OS. Methods that sound like verbs (mkdir(), unlink(), rename()) modify the OS. Methods that return new Path objects (with_suffix(), relative_to()) compute without touching disk.
