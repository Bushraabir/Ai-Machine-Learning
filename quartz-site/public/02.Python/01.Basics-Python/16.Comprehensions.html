16.Comprehensions

Apr 24, 202611 min read

Core Idea

A comprehension is a concise, readable syntax for building a new collection by transforming and/or filtering an existing iterable — all in a single expression.

Python has four types:

TypeSyntaxReturns
List comprehension[expr for x in it]list
Dict comprehension{k: v for x in it}dict
Set comprehension{expr for x in it}set
Generator expression(expr for x in it)generator (lazy)

Comprehensions are not just syntactic sugar. They are:

  • Faster than equivalent for loops with .append() — the bytecode is optimized
  • More readable when the logic is simple
  • Functional in style — they express what you want, not how to build it step by step

Generator Expressions

A generator expression looks like a list comprehension in parentheses, but it is fundamentally different. It does not build the collection upfront — it produces values one at a time, on demand.

Generators are exhausted after one pass. You cannot re-iterate them without recreating.

Comprehension vs Loop — When to Use Which

Use a comprehension when:

  • You are building a new collection from an existing one
  • The transformation and filter logic fits cleanly on one or two lines
  • There are no side effects (comprehensions are for producing values, not doing work)

Use a regular loop when:

  • The body has multiple statements
  • There are side effects (logging, writing to files, modifying external state)
  • The logic is complex enough that a one-liner would obscure intent
  • You need break or continue — these do not work inside comprehensions

Readability Limit

Comprehensions become unreadable past a certain complexity. There is no fixed rule — use judgment.

Extracting the condition into a named function preserves the comprehension style while making the logic readable and testable independently.
