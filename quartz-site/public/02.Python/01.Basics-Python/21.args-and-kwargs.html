21. *args and **kwargs

Core Idea

*args and **kwargs are mechanisms for writing functions that accept a variable number of arguments — when you do not know at definition time exactly how many arguments a caller will supply.

  • *args — collects any number of extra positional arguments into a tuple
  • **kwargs — collects any number of extra keyword arguments into a dict

The names args and kwargs are conventions. The * and ** are the actual syntax. You could write *numbers or **options — the behavior is identical.

The Forwarding Pattern

The most important production use of *args, **kwargs: passing all arguments through to another function unchanged. This is the foundation of decorators, wrappers, and middleware.

The inner wrapper does not need to know anything about func’s signature — it blindly forwards *args and **kwargs. This works for any function regardless of its parameters.

Validating kwargs

Always validate **kwargs in production code — silently accepted typos are a common source of bugs.

Alternatively, use explicit keyword-only parameters instead of **kwargs when the set of options is fixed — they provide built-in validation, better IDE autocomplete, and clearer documentation.

*args vs Explicit List Parameter

Use *args when callers will typically pass values directly. Use an explicit list parameter when callers will typically pass an already-constructed collection.
