32. Dunder (Magic) Methods

What Dunder Methods Are

Dunder methods — short for double underscore methods — are special methods with names like __str__, __len__, __add__. Python calls them automatically in response to built-in operations. You never call them directly; you define them, and Python invokes them when the right operation is applied to your object.

Every built-in operation in Python maps to a dunder method. By implementing these methods on your own classes, your objects integrate seamlessly with Python syntax — they can be printed, compared, added, iterated, indexed, and used in with statements, just like built-in types.

This is called the Python data model. It is one of the most powerful design decisions in the language.

__repr__ and __str__ — String Representation

These are the two most universally needed dunder methods.

__repr__ — Unambiguous, Developer-Facing

__repr__ should return a string that could recreate the object. It is called by repr(obj), by the REPL when you evaluate an expression, and as the fallback when __str__ is not defined.

Rule: repr is for developers. It should be precise and unambiguous.

__str__ — Readable, User-Facing

__str__ is called by str(obj) and print(obj). It should return a human-readable representation.

Rule: str is for end users. It should be clean and readable.

Fallback rule: If __str__ is not defined, Python falls back to __repr__. If neither is defined, Python uses object.__repr__ which gives <__main__.Vector object at 0x...>.

Minimum requirement: Always define __repr__. It is the one dunder method every class should have.

__len__ — The len() Protocol

Any object with __len__ automatically participates in Python’s truthiness protocol: bool(obj) returns False if len(obj) == 0, True otherwise — unless __bool__ is also defined (which takes precedence).

__eq__, __lt__, __le__, __gt__, __ge__, __ne__ — Comparison

By default, == checks object identity (same as is). Defining __eq__ changes what equality means for your class.

NotImplemented vs NotImplementedError:

Return NotImplemented (not raise) when the comparison is not supported. Python then tries the reflected operation on the other operand. Returning NotImplemented is part of the protocol — it tells Python to keep trying. Raising NotImplementedError would crash instead.

@functools.total_ordering — Define only __eq__ and one comparison:

Warning: Defining __eq__ makes your class unhashable by default (Python sets __hash__ = None). If you need objects to be usable in sets or as dict keys, also define __hash__.

__add__, __sub__, __mul__ — Arithmetic Operators

Reflected operations (__radd__, __rmul__, etc.):

When a + b is evaluated, Python first tries a.__add__(b). If that returns NotImplemented or is not defined, Python tries b.__radd__(a). Defining __rmul__ on Vector makes 3 * vector work even though int.__mul__ does not know about vectors.

Augmented assignment (__iadd__, __imul__, etc.):

If __iadd__ is not defined, v1 += v2 falls back to v1 = v1.__add__(v2) — creates a new object. Define __iadd__ for true in-place modification.

__getitem__, __setitem__, __delitem__ — Indexing Protocol

NumPy arrays use exactly this mechanism — arr[0, 1] calls arr.__getitem__((0, 1)). Pandas DataFrames use __getitem__ for column access: df["col"] is df.__getitem__("col").

__contains__ — The in Operator

Without __contains__, in falls back to iterating via __iter__ (or __getitem__). Defining __contains__ lets you provide O(1) lookup.

__iter__ and __next__ — Iteration Protocol

Making your object iterable so it works in for loops, list(), zip(), etc.

Iterable vs Iterator:

  • Iterable: has __iter__ returning an iterator. Can be looped over multiple times.
  • Iterator: has both __iter__ and __next__. Maintains its own position. Exhausted after one pass.

Combining both on the same class (as above) is the simplest pattern but means only one active iteration at a time. For concurrent iterations, return a separate iterator object from __iter__.

__call__ — Making Objects Callable

An object with __call__ is callable — it can be used anywhere a function is expected. This is how PyTorch’s nn.Module works: model(x) calls model.__call__(x), which internally calls model.forward(x) plus hooks.

__enter__ and __exit__ — Context Manager Protocol

__exit__ receives exception info if one was raised inside the with block. Returning True suppresses the exception; returning False (or None) lets it propagate.

See 60. Writing custom context managers for full treatment.

__bool__ — Truthiness

Priority: __bool__ takes precedence over __len__. If both are defined, Python uses __bool__ for truthiness evaluation.

__hash__ — Hashability

Objects that define __eq__ become unhashable by default (Python sets __hash__ = None). To use them in sets or as dict keys, define __hash__.

Rule: If a == b then hash(a) == hash(b) must hold. The reverse need not be true (hash collisions are allowed).

__del__ — Destructor

Called when the object is about to be garbage collected. Use sparingly — the timing is not guaranteed.

Do not rely on __del__ for critical cleanup — use context managers (__enter__/__exit__) instead. __del__ is not guaranteed to run at a specific time, and in CPython it may not run at all in some circular reference scenarios.

Exercises

E1. Build a Polynomial class representing ax² + bx + c with:

  • __repr__ returning "Polynomial(a, b, c)"
  • __str__ returning a human-readable form like "3x² + 2x + 1"
  • __add__ combining two polynomials
  • __call__ evaluating the polynomial at a given x value
  • __eq__ comparing coefficients

E2. Build a SortedList class backed by a Python list that:

  • Maintains sorted order on every insertion via __setitem__ and an insert method
  • Implements __len__, __getitem__, __contains__, __iter__, __repr__
  • Verify that for x in SortedList([3,1,2]) yields 1, 2, 3

E3. Implement a Fraction class with full arithmetic:

  • __add__, __sub__, __mul__, __truediv__
  • __eq__, __lt__ (reduce to common denominator to compare)
  • __repr__ returning "3/4"
  • __float__ returning the decimal value
  • Use math.gcd to reduce fractions to lowest terms after each operation
