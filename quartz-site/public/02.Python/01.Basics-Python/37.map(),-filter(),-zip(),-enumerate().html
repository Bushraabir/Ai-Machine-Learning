37. map(), filter(), zip(), enumerate()

“These four functions are the vocabulary of lazy transformation. Each one takes an iterable and returns an iterator — a promise to compute values on demand, not a list of results already sitting in memory.”

Prerequisites: 34.iter() and next() · 35.Generator functions · 24.Lambda functions · 18.Defining and calling functions

The Unifying Idea

All four functions share a design philosophy:

  1. They accept one or more iterables as input
  2. They return an iterator — not a list
  3. They are lazy — no computation happens until you call next() or iterate
  4. They compose cleanly — you can chain them without intermediate storage

This laziness is not a curiosity — it is the property that makes them usable on datasets too large to fit in memory. You will see this pattern throughout NumPy, PyTorch, and every production data pipeline.

map() — Apply a Function to Every Element

Signature

Returns an iterator that applies function to each element of iterable. If multiple iterables are given, function is called with one argument from each — stopping at the shortest.

filter() — Keep Elements That Satisfy a Predicate

Signature

Returns an iterator yielding elements of iterable for which function(element) is truthy. If function is None, filters out falsy values.

Basic Usage

filter() vs List Comprehension

filter(None, iterable) is the idiomatic way to strip falsy values — more readable than filter(lambda x: x, iterable) or (x for x in iterable if x).

zip() — Pair Up Elements Across Iterables

Signature

Returns an iterator of tuples, where the i-th tuple contains the i-th element from each iterable. Stops at the shortest iterable.

enumerate() — Pair Elements with Their Index

Signature

Returns an iterator of (index, element) tuples. start sets the initial index value.

Basic Usage

Why enumerate() Exists — Never Use range(len(...))

range(len(x)) is a code smell in Python. It is fragile (breaks if x doesn’t support len), verbose, and misses the point — enumerate communicates intent clearly.

Practical Uses

Composition — Chaining All Four

The real power emerges when you compose these functions. Each returns an iterator, so they chain without allocating intermediate lists.

Order of composition matters. Think carefully about whether you want original indices or reindexed indices.

Summary

map, filter, zip, and enumerate are four lazy iterators over iterables. They do not compute until consumed. They compose without allocating intermediate lists. They are the functional vocabulary for expressing data transformation intent clearly:

  • map(f, it) — transform every element
  • filter(pred, it) — select elements that pass a test
  • zip(*its) — pair elements from parallel sequences
  • enumerate(it) — index elements of a sequence

They are not always the most readable choice — list comprehensions often are. But they are indispensable when building lazy pipelines, working with infinite iterators, or composing transformations across large datasets.
