# 38. sorted() and reversed()

> _"Sorting is not a primitive operation — it is a decision. Every call to sorted() encodes an assumption about what 'order' means. Making that assumption explicit is what the key= parameter is for."_

**Prerequisites:** [[12.Lists]] · [[13.Tuples]] · [[14.Dictionaries]] · [[24.Lambda functions]] · [[34.iter() and next()]]

## Two Functions, Two Contracts

Python gives you two built-in ordering tools:

|Function|Input|Output|Mutates original?|Works on|
|---|---|---|---|---|
|`sorted(iterable)`|Any iterable|New `list`|No|Anything iterable|
|`reversed(sequence)`|Sequence or iterator|`reversed` iterator|No|Sequences with `__reversed__` or `__len__` + `__getitem__`|
|`list.sort()`|list (method)|`None`|**Yes**|Lists only|

The critical distinction: `sorted()` always returns a **new list**. `list.sort()` sorts in place and returns `None` — a common source of bugs. `reversed()` returns a lazy iterator, not a list.

## `sorted()` — The Full Picture

### Basic Usage

```python
nums = [3, 1, 4, 1, 5, 9, 2, 6]
print(sorted(nums))          # [1, 1, 2, 3, 4, 5, 6, 9]
print(nums)                  # [3, 1, 4, 1, 5, 9, 2, 6]  — unchanged

# Works on any iterable, always returns a list:
print(sorted("hello"))       # ['e', 'h', 'l', 'l', 'o']
print(sorted((3, 1, 2)))     # [1, 2, 3]
print(sorted({3, 1, 2}))     # [1, 2, 3]
print(sorted({'b': 2, 'a': 1}))  # ['a', 'b']  — sorts keys
```

### `reverse=True` — Descending Order

```python
nums = [3, 1, 4, 1, 5, 9, 2, 6]
print(sorted(nums, reverse=True))   # [9, 6, 5, 4, 3, 2, 1, 1]
```

## The `key=` Parameter — The Real Power

`key=` accepts a callable. Before comparing any two elements, Python calls `key(element)` and compares the _results_, not the elements themselves. The original elements are returned; only the comparison uses the key values.

```python
sorted(iterable, key=func)
# Equivalent to: sort by func(element) for each element
```

### Sorting Strings by Length

```python
words = ["banana", "fig", "apple", "kiwi", "date"]
print(sorted(words))                      # alphabetical: ['apple', 'banana', 'date', 'fig', 'kiwi']
print(sorted(words, key=len))             # by length:    ['fig', 'kiwi', 'date', 'apple', 'banana']
print(sorted(words, key=len, reverse=True))  # longest first: ['banana', 'apple', 'date', 'kiwi', 'fig']
```

### Sorting Strings Case-Insensitively

```python
words = ["Banana", "apple", "Cherry", "date"]
print(sorted(words))                      # ['Banana', 'Cherry', 'apple', 'date']  — uppercase first (ASCII)
print(sorted(words, key=str.lower))       # ['apple', 'Banana', 'Cherry', 'date']  — case-insensitive
```

### Sorting by a Computed Value

```python
nums = [-4, 2, -1, 5, -3]
print(sorted(nums, key=abs))   # [2, -1, -3, -4, 5]  — by absolute value: -1, -3, -4, 2, 5... wait:
# abs(-1)=1, abs(2)=2, abs(-3)=3, abs(-4)=4, abs(5)=5
# → [-1, 2, -3, -4, 5]
```

### Sorting Objects by Attribute

```python
from dataclasses import dataclass

@dataclass
class Student:
    name: str
    gpa: float
    year: int

students = [
    Student("Alice", 3.8, 3),
    Student("Bob",   3.2, 2),
    Student("Carol", 3.8, 2),
    Student("Dave",  3.5, 4),
]

# Sort by GPA descending:
by_gpa = sorted(students, key=lambda s: s.gpa, reverse=True)
for s in by_gpa:
    print(f"{s.name}: {s.gpa}")
# Alice: 3.8
# Carol: 3.8
# Dave:  3.5
# Bob:   3.2
```

### Multi-Key Sorting — Tuples as Keys

To sort by multiple criteria, return a tuple from `key=`. Python compares tuples lexicographically: first element first, then second on ties, and so on.

```python
# Sort by GPA descending, then by name ascending on ties:
by_gpa_then_name = sorted(
    students,
    key=lambda s: (-s.gpa, s.name)   # negate GPA for descending
)
for s in by_gpa_then_name:
    print(f"{s.name}: {s.gpa}")
# Alice: 3.8   (Alice < Carol alphabetically)
# Carol: 3.8
# Dave:  3.5
# Bob:   3.2
```

**The negation trick for descending numeric keys:** negate the number to flip the sort order for that field while keeping other fields ascending. This avoids having to call `sorted()` multiple times.

```python
# Sort students: year descending, then gpa descending, then name ascending:
sorted(students, key=lambda s: (-s.year, -s.gpa, s.name))
```

### Sorting Dictionaries

```python
scores = {"Alice": 92, "Bob": 85, "Carol": 97, "Dave": 85}

# Sort by value:
by_score = sorted(scores.items(), key=lambda kv: kv[1], reverse=True)
print(by_score)
# [('Carol', 97), ('Alice', 92), ('Bob', 85), ('Dave', 85)]

# Reconstruct ordered dict:
ranked = dict(by_score)

# Sort by value then key (stable tiebreak):
by_score_then_name = sorted(scores.items(), key=lambda kv: (-kv[1], kv[0]))
print(by_score_then_name)
# [('Carol', 97), ('Alice', 92), ('Bob', 85), ('Dave', 85)]
```

## `operator` Module — Faster Than Lambdas

`operator.attrgetter` and `operator.itemgetter` are faster than equivalent lambdas because they are implemented in C.

```python
from operator import attrgetter, itemgetter

# Equivalent pairs:
sorted(students, key=lambda s: s.gpa)
sorted(students, key=attrgetter('gpa'))          # faster

sorted(scores.items(), key=lambda kv: kv[1])
sorted(scores.items(), key=itemgetter(1))        # faster

# Multi-attribute with attrgetter:
sorted(students, key=attrgetter('gpa', 'name'))  # sort by gpa, then name — no lambda needed
```

Use `operator` module functions in performance-critical sorting code and anywhere you need the idiom to be readable without a lambda.

## Python's Sort Algorithm — Timsort

Python uses **Timsort**, a hybrid merge sort / insertion sort algorithm.

- **Time complexity:** $O(n \log n)$ worst case, $O(n)$ on already-sorted or nearly-sorted data
- **Space complexity:** $O(n)$ auxiliary space
- **Stable:** elements with equal keys appear in the same relative order as in the input

**Stability matters.** It means you can sort by multiple criteria through sequential sorts, and the last sort's order is preserved for elements equal under the last key.

```python
# Stable sort: sort by name first, then by GPA
# Result: within the same GPA, names are alphabetical
by_name = sorted(students, key=lambda s: s.name)
by_gpa  = sorted(by_name,  key=lambda s: s.gpa, reverse=True)
# Equivalent to the single-pass tuple key approach, because sort is stable
```

The single-pass tuple key approach is preferred, but the sequential-sort technique appears in legacy code and is worth recognising.

## `list.sort()` vs `sorted()` — When to Use Which

```python
nums = [3, 1, 4, 1, 5]

# sorted() — non-mutating, returns new list:
new = sorted(nums)
print(nums)   # [3, 1, 4, 1, 5]  — original preserved
print(new)    # [1, 1, 3, 4, 5]

# list.sort() — in-place, returns None:
result = nums.sort()
print(result)  # None  ← common bug: assigning the return value
print(nums)    # [1, 1, 3, 4, 5]  — original mutated
```

**Rule:** use `sorted()` when you need the original preserved, or when sorting a non-list iterable. Use `.sort()` when mutating in place is acceptable and you want to avoid the memory cost of a new list.

```python
# BUG — returns None, not a sorted list:
data = sorted_data = [3, 1, 2].sort()   # sorted_data is None

# CORRECT:
data = [3, 1, 2]
data.sort()                             # mutate in place
# or:
sorted_data = sorted([3, 1, 2])        # new list
```

## `reversed()` — Lazy Reversal

`reversed(seq)` returns a `reversed` iterator that yields elements from the end to the start. It does **not** copy the sequence.

```python
nums = [1, 2, 3, 4, 5]

rev = reversed(nums)
print(type(rev))    # <class 'list_reverseiterator'>
print(list(rev))    # [5, 4, 3, 2, 1]
print(nums)         # [1, 2, 3, 4, 5]  — unchanged

# Works on strings, tuples, range, and any sequence:
print(list(reversed("hello")))         # ['o', 'l', 'l', 'e', 'h']
print(list(reversed((1, 2, 3))))       # [3, 2, 1]
print(list(reversed(range(5))))        # [4, 3, 2, 1, 0]
```

### `reversed()` vs Slice `[::-1]`

```python
nums = [1, 2, 3, 4, 5]

# Slice reversal — creates a new list immediately:
rev_list = nums[::-1]     # [5, 4, 3, 2, 1]  — new list in memory
print(type(rev_list))     # <class 'list'>

# reversed() — lazy iterator, no copy:
rev_iter = reversed(nums)
print(type(rev_iter))     # <class 'list_reverseiterator'>
```

||`reversed(seq)`|`seq[::-1]`|
|---|---|---|
|Returns|Lazy iterator|New list (or string/tuple)|
|Memory|$O(1)$|$O(n)$|
|Works on|Sequences (needs `__len__` + `__getitem__` or `__reversed__`)|Any sequence|
|Mutation safe|Yes — reads original|Yes — independent copy|

**Use `reversed()`** when you only need to iterate once and don't need a list. **Use `[::-1]`** when you need a concrete reversed copy to pass around, index, or iterate multiple times.

### `reversed()` Requires a Sequence

`reversed()` does not work on arbitrary iterables — only on sequences (objects with `__len__` and `__getitem__`, or a `__reversed__` method).

```python
reversed([1, 2, 3])       # OK — list
reversed((1, 2, 3))       # OK — tuple
reversed("hello")         # OK — str
reversed(range(5))        # OK — range has __reversed__

reversed({1, 2, 3})       # TypeError: argument to reversed() must be a sequence
reversed({"a": 1})        # TypeError
reversed(x for x in [])  # TypeError — generator has no length or index
```

To reverse a non-sequence iterable, materialise it first:

```python
gen = (x**2 for x in range(5))
list(reversed(list(gen)))   # [16, 9, 4, 1, 0]
```

### Adding `__reversed__` to a Custom Class

```python
class Countdown:
    def __init__(self, start):
        self.start = start

    def __len__(self):
        return self.start + 1

    def __getitem__(self, i):
        if i < 0 or i > self.start:
            raise IndexError(i)
        return self.start - i

    def __reversed__(self):
        """Custom reverse — counts up instead of counting down reversed."""
        for i in range(self.start + 1):
            yield i

c = Countdown(5)
print(list(c))             # [5, 4, 3, 2, 1, 0]  — via __getitem__
print(list(reversed(c)))   # [0, 1, 2, 3, 4, 5]  — via __reversed__
```

If `__reversed__` is not defined, `reversed()` falls back to using `__len__` and `__getitem__` to iterate backwards. If neither is present, it raises `TypeError`.

## Combining `sorted()` and `reversed()`

```python
nums = [3, 1, 4, 1, 5, 9, 2, 6]

# These are equivalent for simple reversal:
sorted(nums, reverse=True)          # [9, 6, 5, 4, 3, 2, 1, 1]
list(reversed(sorted(nums)))        # [9, 6, 5, 4, 3, 2, 1, 1]

# But reversed(sorted(...)) is subtly different for complex keys:
words = ["fig", "apple", "kiwi", "banana"]

# Sort by length ascending, then reverse to get descending:
sorted(words, key=len, reverse=True)         # ['banana', 'apple', 'kiwi', 'fig']
list(reversed(sorted(words, key=len)))       # ['banana', 'apple', 'kiwi', 'fig']
# Same result here — but reversed() does NOT apply the key, it just reverses order.
# Use reverse=True on sorted() — it's the canonical approach.
```

## Custom Sort Order — `functools.cmp_to_key`

Occasionally you have a comparison function `cmp(a, b)` that returns negative/zero/positive rather than a key. Use `functools.cmp_to_key` to convert it.

```python
from functools import cmp_to_key

def compare_by_last_char(a, b):
    if a[-1] < b[-1]: return -1
    if a[-1] > b[-1]: return 1
    return 0

words = ["apple", "banana", "fig", "kiwi"]
print(sorted(words, key=cmp_to_key(compare_by_last_char)))
# ['banana', 'apple', 'kiwi', 'fig']
# last chars: a < a < e < i < g  wait:
# 'banana'→a, 'apple'→e, 'fig'→g, 'kiwi'→i
# sorted: banana(a) apple(e) fig(g) kiwi(i)
```

`cmp_to_key` is the escape hatch for legacy comparison functions or cases where expressing a total order as a single key value is difficult. Use it rarely — `key=` covers almost everything more cleanly.

## Connection to AI/ML and Deep Learning

### Ranking and Beam Search

Sorting is the engine of ranking. In NLP, **beam search** maintains the top-$k$ candidate sequences at each decoding step:

```python
def beam_search_step(candidates, scores, beam_width=5):
    """
    candidates: list of token sequences
    scores:     corresponding log-probabilities
    Returns top beam_width candidates by score.
    """
    ranked = sorted(
        zip(scores, candidates),
        key=lambda sc: sc[0],
        reverse=True          # highest score first
    )
    return [cand for _, cand in ranked[:beam_width]]
```

Sorting by score with `key=` is exactly this operation. At scale, partial sorting (heapq.nlargest) is used instead of full sort, but the semantics are identical.

### Top-k Predictions

After a softmax, retrieving the top-$k$ class predictions:

```python
import numpy as np

logits = np.array([0.1, 2.3, 0.5, 1.8, 0.9])
probs  = np.exp(logits) / np.exp(logits).sum()

# Top-3 classes by probability:
top3 = sorted(enumerate(probs), key=lambda ip: ip[1], reverse=True)[:3]
for class_idx, prob in top3:
    print(f"Class {class_idx}: {prob:.4f}")
# Class 1: 0.5765
# Class 3: 0.3486  (approx — depends on actual values)
# Class 4: ...

# NumPy equivalent (more efficient for large arrays):
top3_idx = np.argsort(probs)[::-1][:3]
```

The Python `sorted()` version with `key=` is readable and correct for small output spaces. For large vocabulary (50,000+ tokens in language models), `np.argsort` or `torch.topk` is used for speed.

### Sorting in Data Preprocessing

```python
import numpy as np

# Sort a dataset by label for stratified sampling or visualisation:
X = np.random.randn(100, 10)
y = np.random.randint(0, 5, 100)

# Sort both X and y by label:
order = np.argsort(y)       # argsort returns indices that would sort y
X_sorted = X[order]
y_sorted = y[order]

# Python equivalent for small datasets:
data = list(zip(X.tolist(), y.tolist()))
data.sort(key=lambda xy: xy[1])   # sort by label
```

`np.argsort` is `sorted(enumerate(arr), key=lambda ia: ia[1])` expressed as a vectorised operation returning indices. The concept is identical.

### Curriculum Learning — Sorting Training Examples by Difficulty

Curriculum learning presents training examples in order of increasing difficulty. Sorting is the mechanism:

```python
def difficulty_score(example):
    """
    Proxy for difficulty: prediction confidence of a pretrained model.
    Low confidence → difficult example.
    """
    return model.predict_proba(example).max()

train_data = load_dataset()

# Sort from easiest (high confidence) to hardest (low confidence):
curriculum = sorted(train_data, key=difficulty_score, reverse=True)

for epoch in range(n_epochs):
    # Progressively include harder examples as training proceeds:
    cutoff = int(len(curriculum) * min(1.0, (epoch + 1) / n_epochs))
    batch_pool = curriculum[:cutoff]
    train_epoch(batch_pool)
```

This is a real training strategy used in large language model fine-tuning and speech recognition. The `sorted()` call with a domain-specific `key=` function is the full implementation.

## Summary

`sorted()` is a pure function: it takes any iterable, returns a new sorted list, never mutates. `reversed()` is a lazy iterator over a sequence in reverse, costing $O(1)$ memory. The `key=` parameter is the entire theory of sorting in Python — every ordering decision is expressed as a function from element to comparable value.

|Operation|Returns|Mutates|Memory|Notes|
|---|---|---|---|---|
|`sorted(it)`|new `list`|No|$O(n)$|Works on any iterable|
|`sorted(it, key=f)`|new `list`|No|$O(n)$|Sorts by `f(element)`|
|`sorted(it, reverse=True)`|new `list`|No|$O(n)$|Descending|
|`list.sort()`|`None`|**Yes**|$O(1)$ extra|In-place; lists only|
|`reversed(seq)`|lazy iterator|No|$O(1)$|Sequences only|
|`seq[::-1]`|new sequence|No|$O(n)$|Any sequence; concrete copy|

**Timsort guarantees:** $O(n \log n)$ worst case, $O(n)$ best case (nearly sorted), stable.
