
## Core Idea

A class is a blueprint for creating objects. An object is an instance of a class — a concrete entity that bundles together **data** (attributes) and **behavior** (methods) into a single unit.

This is the foundation of Object-Oriented Programming (OOP). The goal is not to write classes for everything — it is to recognize when grouping state and behavior together produces cleaner, more maintainable code than standalone functions and variables.

```python
# Without a class — data and behavior are separate and unrelated
name   = "Alice"
age    = 30
salary = 75000

def give_raise(salary, amount):
    return salary + amount

# With a class — data and behavior are bundled into one coherent unit
class Employee:
    def __init__(self, name, age, salary):
        self.name   = name
        self.age    = age
        self.salary = salary

    def give_raise(self, amount):
        self.salary += amount

alice = Employee("Alice", 30, 75000)
alice.give_raise(5000)
print(alice.salary)    # 80000
```

## Defining a Class

```python
class ClassName:
    """Docstring describing the class."""

    # class body — attributes and methods
```

By convention, class names use PascalCase (also called UpperCamelCase). Every word capitalized, no underscores.

```python
class Dog:
    pass    # minimal valid class
```

## `__init__` — The Constructor

`__init__` is called automatically when an object is created. It initializes the instance's attributes.

```python
class Dog:
    def __init__(self, name, breed, age):
        self.name  = name     # instance attribute
        self.breed = breed
        self.age   = age
```

`self` is the first parameter of every instance method. It refers to the specific object being created or operated on. Python passes it automatically — you never supply it when calling.

```python
rex = Dog("Rex", "German Shepherd", 3)
print(rex.name)     # Rex
print(rex.breed)    # German Shepherd
print(rex.age)      # 3
```

`Dog("Rex", "German Shepherd", 3)` calls `Dog.__init__(rex, "Rex", "German Shepherd", 3)` internally. Python handles the `self` binding.

---

## Instance Attributes

Attributes set on `self` inside `__init__` (or any method) belong to the specific instance. Each object has its own copy.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p1 = Point(1, 2)
p2 = Point(5, 7)

print(p1.x)    # 1
print(p2.x)    # 5  — p1 and p2 have independent x attributes

p1.x = 99     # modifies only p1
print(p1.x)   # 99
print(p2.x)   # 5  — unchanged
```

Attributes can also be added outside `__init__`, but this is generally avoided — it makes the object's structure unpredictable.

```python
p1.z = 10    # valid but not recommended unless intentional
```

## Class Attributes

Defined directly in the class body, outside any method. Shared across all instances.

```python
class Dog:
    species = "Canis lupus familiaris"    # class attribute — shared

    def __init__(self, name):
        self.name = name                  # instance attribute — unique

rex  = Dog("Rex")
luna = Dog("Luna")

print(rex.species)     # Canis lupus familiaris
print(luna.species)    # Canis lupus familiaris
print(Dog.species)     # Canis lupus familiaris — access via class name

Dog.species = "Canis familiaris"    # modifying class attribute
print(rex.species)     # Canis familiaris — all instances see the change
```

**Instance attribute shadows class attribute when names collide:**

```python
class Dog:
    legs = 4

    def __init__(self, name):
        self.name = name

rex = Dog("Rex")
print(rex.legs)    # 4 — reads class attribute (no instance attribute named legs)

rex.legs = 3       # creates an instance attribute that shadows the class attribute
print(rex.legs)    # 3 — reads instance attribute
print(Dog.legs)    # 4 — class attribute unchanged
```

Python looks up attributes in this order: instance `__dict__` → class `__dict__` → base classes.

## Methods

A method is a function defined inside a class. Instance methods automatically receive `self` as the first argument.

```python
class Circle:
    PI = 3.14159265358979

    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return Circle.PI * self.radius ** 2

    def perimeter(self):
        return 2 * Circle.PI * self.radius

    def scale(self, factor):
        self.radius *= factor    # modifies the instance's radius

    def __repr__(self):
        return f"Circle(radius={self.radius})"


c = Circle(5)
print(c.area())         # 78.539...
print(c.perimeter())    # 31.415...
c.scale(2)
print(c.radius)         # 10
print(c)                # Circle(radius=10)
```

## The Three Method Types

### Instance Methods

The default. Receive `self` — operate on the specific instance.

```python
class Counter:
    def __init__(self):
        self.count = 0

    def increment(self):       # instance method
        self.count += 1

    def reset(self):
        self.count = 0

    def value(self):
        return self.count

c = Counter()
c.increment()
c.increment()
print(c.value())    # 2
```

---

### Class Methods — `@classmethod`

Receive `cls` (the class itself) instead of `self`. Operate on class-level state. Often used as alternative constructors.

```python
class Date:
    def __init__(self, year, month, day):
        self.year  = year
        self.month = month
        self.day   = day

    @classmethod
    def from_string(cls, date_string):
        """Alternative constructor — create from 'YYYY-MM-DD' string."""
        year, month, day = map(int, date_string.split("-"))
        return cls(year, month, day)    # calls __init__

    @classmethod
    def today(cls):
        """Alternative constructor — create from current date."""
        import datetime
        d = datetime.date.today()
        return cls(d.year, d.month, d.day)

    def __repr__(self):
        return f"Date({self.year}, {self.month}, {self.day})"


d1 = Date(2024, 1, 15)
d2 = Date.from_string("2024-06-20")
d3 = Date.today()
print(d2)    # Date(2024, 6, 20)
```

`cls` is used instead of `Date` directly so that subclasses can inherit the class method and return instances of themselves, not the base class.

---

### Static Methods — `@staticmethod`

Receive neither `self` nor `cls`. Just a regular function namespaced inside the class. Used for utility functions that logically belong to the class but do not need access to instance or class state.

```python
class MathUtils:
    @staticmethod
    def is_prime(n):
        if n < 2:
            return False
        for i in range(2, int(n ** 0.5) + 1):
            if n % i == 0:
                return False
        return True

    @staticmethod
    def clamp(value, lo, hi):
        return max(lo, min(value, hi))


print(MathUtils.is_prime(17))        # True
print(MathUtils.clamp(150, 0, 100))  # 100
```

Static methods can also be called on an instance (`obj.static_method()`) but calling via the class is clearer.

## Dunder (Magic) Methods

Double-underscore methods that Python calls automatically in response to operators and built-in functions. They define how objects behave with standard Python syntax.

### `__repr__` and `__str__`

```python
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        """Unambiguous — for developers. Called by repr() and in REPL."""
        return f"Vector({self.x}, {self.y})"

    def __str__(self):
        """Human-readable — for end users. Called by print() and str()."""
        return f"({self.x}, {self.y})"


v = Vector(3, 4)
print(repr(v))    # Vector(3, 4)
print(str(v))     # (3, 4)
print(v)          # (3, 4)  — print() calls __str__
```

If only `__repr__` is defined, it is used for both. Always define at minimum `__repr__` — it makes debugging significantly easier.

### Arithmetic Operators

```python
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __sub__(self, other):
        return Vector(self.x - other.x, self.y - other.y)

    def __mul__(self, scalar):
        return Vector(self.x * scalar, self.y * scalar)

    def __rmul__(self, scalar):
        """Called when scalar * vector (scalar on the left)."""
        return self.__mul__(scalar)

    def __neg__(self):
        return Vector(-self.x, -self.y)

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"


v1 = Vector(1, 2)
v2 = Vector(3, 4)

print(v1 + v2)     # Vector(4, 6)
print(v1 - v2)     # Vector(-2, -2)
print(v1 * 3)      # Vector(3, 6)
print(3 * v1)      # Vector(3, 6)  — uses __rmul__
print(-v1)         # Vector(-1, -2)
```

### Comparison Operators

```python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    def __eq__(self, other):
        return self.celsius == other.celsius

    def __lt__(self, other):
        return self.celsius < other.celsius

    def __le__(self, other):
        return self.celsius <= other.celsius

    def __gt__(self, other):
        return self.celsius > other.celsius

    def __repr__(self):
        return f"Temperature({self.celsius}°C)"


t1 = Temperature(20)
t2 = Temperature(30)

print(t1 < t2)     # True
print(t1 == t2)    # False
print(sorted([t2, t1]))    # [Temperature(20°C), Temperature(30°C)]
```

Define `__eq__` and `__lt__` and Python can derive the rest (with `@functools.total_ordering`).

### Container Behavior

```python
class Bag:
    def __init__(self):
        self.items = []

    def add(self, item):
        self.items.append(item)

    def __len__(self):
        return len(self.items)

    def __contains__(self, item):
        return item in self.items

    def __getitem__(self, index):
        return self.items[index]

    def __iter__(self):
        return iter(self.items)

    def __repr__(self):
        return f"Bag({self.items})"


bag = Bag()
bag.add("apple")
bag.add("banana")

print(len(bag))            # 2
print("apple" in bag)      # True
print(bag[0])              # apple
for item in bag:
    print(item)
```

### `__call__` — Making Objects Callable

```python
class Multiplier:
    def __init__(self, factor):
        self.factor = factor

    def __call__(self, x):
        return x * self.factor


double = Multiplier(2)
triple = Multiplier(3)

print(double(5))    # 10
print(triple(5))    # 15
print(callable(double))    # True
```

`__call__` makes an object behave like a function. This is how PyTorch neural network modules work — `model(input)` calls `model.__call__(input)` which internally invokes `model.forward(input)`.

## Object Identity and Equality

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

p1 = Point(1, 2)
p2 = Point(1, 2)
p3 = p1

print(p1 == p2)     # True  — __eq__ compares values
print(p1 is p2)     # False — different objects in memory
print(p1 is p3)     # True  — same object
```

Without `__eq__`, Python uses identity (`is`) for equality by default — two objects are equal only if they are the same object.

**Defining `__eq__` disables the default `__hash__`.** If you define `__eq__`, also define `__hash__` if you need the object to be hashable (usable in sets and as dict keys).

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __hash__(self):
        return hash((self.x, self.y))    # hash of the tuple of fields


p = Point(1, 2)
s = {p}                    # works — Point is hashable
d = {p: "origin-ish"}      # works as dict key
```

## Instance, Class, and Static — Decision Guide

|Need|Use|
|---|---|
|Access or modify instance state (`self.x`)|Instance method|
|Access or modify class state, alternative constructor|Class method|
|Utility function logically grouped with class, no state needed|Static method|

```python
class Connection:
    max_connections = 100          # class attribute

    def __init__(self, host):
        self.host = host           # instance attribute
        self.active = False

    def connect(self):             # instance method — uses self
        self.active = True

    @classmethod
    def set_max(cls, n):           # class method — uses cls
        cls.max_connections = n

    @staticmethod
    def validate_host(host):       # static method — uses neither
        return isinstance(host, str) and len(host) > 0
```

## `__dict__` — Inspecting Object State

Every instance has a `__dict__` that stores its attributes as a dictionary.

```python
class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age  = age

rex = Dog("Rex", 3)
print(rex.__dict__)    # {"name": "Rex", "age": 3}
```

This is how attribute access works under the hood. `rex.name` is effectively `rex.__dict__["name"]`. Useful for debugging and serialization.

## Dataclasses (Python 3.7+)

For classes that primarily hold data, `@dataclass` auto-generates `__init__`, `__repr__`, and `__eq__`.

```python
from dataclasses import dataclass, field

@dataclass
class Point:
    x: float
    y: float
    z: float = 0.0    # default value

@dataclass
class ModelConfig:
    lr:          float = 0.001
    epochs:      int   = 100
    batch_size:  int   = 32
    hidden_dims: list  = field(default_factory=list)
    # field(default_factory=list) — correct way to use mutable default

p = Point(1.0, 2.0)
print(p)                # Point(x=1.0, y=2.0, z=0.0)
print(p == Point(1.0, 2.0))    # True — __eq__ auto-generated

cfg = ModelConfig(lr=0.01, epochs=50)
print(cfg)    # ModelConfig(lr=0.01, epochs=50, batch_size=32, hidden_dims=[])
```

Use `@dataclass` for configuration objects, dataset records, and any class whose primary purpose is holding named fields. It eliminates boilerplate while keeping all the OOP benefits.

## Common Patterns in ML

**Model configuration as a class:**

```python
from dataclasses import dataclass

@dataclass
class TrainingConfig:
    model_name:    str   = "resnet50"
    learning_rate: float = 0.001
    batch_size:    int   = 32
    epochs:        int   = 100
    weight_decay:  float = 1e-4
    device:        str   = "cuda"

cfg = TrainingConfig(learning_rate=0.01, epochs=50)
```

**Stateful metric tracker:**

```python
class AverageMeter:
    """Track running average of a metric."""

    def __init__(self, name):
        self.name  = name
        self.reset()

    def reset(self):
        self.sum   = 0.0
        self.count = 0

    def update(self, value, n=1):
        self.sum   += value * n
        self.count += n

    @property
    def average(self):
        return self.sum / self.count if self.count > 0 else 0.0

    def __repr__(self):
        return f"AverageMeter({self.name}: {self.average:.4f})"


loss_meter = AverageMeter("loss")
for batch_loss in batch_losses:
    loss_meter.update(batch_loss)
print(loss_meter)    # AverageMeter(loss: 0.3421)
```

**Custom dataset class (PyTorch pattern):**

```python
class ImageDataset:
    def __init__(self, image_paths, labels, transform=None):
        self.image_paths = image_paths
        self.labels      = labels
        self.transform   = transform

    def __len__(self):
        return len(self.image_paths)

    def __getitem__(self, idx):
        image = load_image(self.image_paths[idx])
        label = self.labels[idx]
        if self.transform:
            image = self.transform(image)
        return image, label
```

This is exactly how `torch.utils.data.Dataset` works — you subclass it and implement `__len__` and `__getitem__`. The DataLoader then uses these dunder methods to iterate batches. Understanding OOP at this level is what makes PyTorch feel natural rather than magical.

## Summary

|Concept|Key Point|
|---|---|
|Class|Blueprint for objects — defined with `class`|
|Object / Instance|Concrete entity created from a class|
|`__init__`|Constructor — called automatically on creation|
|`self`|Reference to the current instance — passed automatically|
|Instance attribute|Belongs to one object — set via `self.name = ...`|
|Class attribute|Shared across all instances — defined in class body|
|Instance method|Takes `self` — most common method type|
|Class method|Takes `cls` — `@classmethod` — alternative constructors|
|Static method|Takes neither — `@staticmethod` — utility functions|
|Dunder methods|`__repr__`, `__add__`, `__len__` etc. — define operator behavior|
|`__repr__`|Always define — makes debugging possible|
|`__eq__`|Define when value equality matters — disables default `__hash__`|
|`__call__`|Makes object callable like a function|
|`@dataclass`|Auto-generates `__init__`, `__repr__`, `__eq__` for data-holding classes|

## Common Mistakes to Avoid

```python
# Mistake 1: forgetting self in method definition
class Dog:
    def bark():    # missing self — TypeError when called on instance
        print("Woof")

# Mistake 2: using class attribute for mutable shared state
class Team:
    members = []       # shared across ALL instances — almost always wrong

    def add(self, name):
        self.members.append(name)    # modifies class-level list

# fix: initialize in __init__
class Team:
    def __init__(self):
        self.members = []

# Mistake 3: mutable default in dataclass
from dataclasses import dataclass
@dataclass
class Config:
    items: list = []              # SyntaxError in dataclass
    items: list = field(default_factory=list)    # correct

# Mistake 4: defining __eq__ without __hash__
class Point:
    def __eq__(self, other): ...
    # __hash__ is now None — Point cannot be put in a set or used as dict key
    # fix: also define __hash__

# Mistake 5: accessing class attribute via instance when shadowing occurs
class Dog:
    legs = 4
rex = Dog()
rex.legs = 3            # creates instance attribute
print(Dog.legs)         # 4 — class attribute unchanged
print(rex.legs)         # 3 — reads instance attribute (shadows class)

# Mistake 6: calling self method without parentheses
class Counter:
    def value(self):
        return self.count

c = Counter()
print(c.value)      # <bound method ...> — forgot ()
print(c.value())    # correct
```
