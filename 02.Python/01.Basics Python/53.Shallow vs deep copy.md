# 53. Shallow vs Deep Copy

> _"Copying an object and copying what it points to are two entirely different operations. Most bugs in this space come from not knowing which one you did."_

---

## The Core Problem

When you write `b = a` in Python, you are **not** creating a copy. You are creating a second label pointing to the **same object in memory**. This is assignment, not copying.

```python
a = [1, 2, 3]
b = a           # b and a point to the same list

b.append(4)
print(a)        # [1, 2, 3, 4]  ← a was "mutated" through b
```

This surprises people. The fix is to copy — but the word "copy" hides a crucial distinction.

---

## Mental Model: The Box-and-Arrow Diagram

Before any formal definition, draw this in your head.

```
Assignment (b = a):
    a ──────────────┐
                    ▼
                 [1, [2, 3], 4]
                    ▲
    b ──────────────┘

Shallow Copy (b = a.copy()):
    a ──────► [1,  ●──────────────► [2, 3],  4]
                   │
    b ──────► [1,  ●──────────────► [2, 3],  4]
                   │                   ▲
                   └───────────────────┘
              (outer lists differ, inner list is shared)

Deep Copy (b = copy.deepcopy(a)):
    a ──────► [1,  ●──────────────► [2, 3],  4]

    b ──────► [1,  ●──────────────► [2, 3],  4]
              (completely independent at every level)
```

The nested list `[2, 3]` is the trap. A shallow copy creates a **new outer container** but still **shares the inner objects**. A deep copy recursively copies everything.

---

## Definitions

### Shallow Copy

A **shallow copy** creates a new container object but fills it with **references to the same child objects** as the original.

```python
import copy

original = [1, [2, 3], 4]
shallow  = copy.copy(original)        # or original.copy() or original[:]

print(original is shallow)            # False  ← different outer lists
print(original[1] is shallow[1])      # True   ← same inner list object

shallow[0] = 99
print(original[0])                    # 1  ← unaffected (int is immutable)

shallow[1].append(99)
print(original[1])                    # [2, 3, 99]  ← AFFECTED (shared mutable object)
```

Mutation of an **immutable** child (like `int`, `str`, `tuple`) is safe — those objects cannot be changed in place. Mutation of a **mutable** child (like `list`, `dict`, `set`) propagates back to the original.

---

### Deep Copy

A **deep copy** recursively creates new objects for every level of nesting. The result is **fully independent** of the original.

```python
import copy

original = [1, [2, 3], 4]
deep     = copy.deepcopy(original)

print(original is deep)               # False
print(original[1] is deep[1])         # False  ← different inner list objects

deep[1].append(99)
print(original[1])                    # [2, 3]  ← completely unaffected
```

---

## Ways to Shallow Copy (and when each appears)

|Method|Works on|Notes|
|---|---|---|
|`a.copy()`|`list`, `dict`, `set`|The cleanest, most readable|
|`a[:]`|`list`, `str`, `tuple`|Slice syntax; returns same type|
|`list(a)` / `dict(a)`|any iterable / mapping|Constructor call|
|`copy.copy(a)`|any object|General-purpose; works on custom classes|

```python
lst  = [1, 2, 3]
d    = {"x": 1, "y": 2}
s    = {1, 2, 3}

lst_copy  = lst[:]          # shallow copy of list
dict_copy = d.copy()        # shallow copy of dict
set_copy  = s.copy()        # shallow copy of set
```

All four methods above are **shallow**. None of them protect nested mutable objects.

---

## Deep Copy: `copy.deepcopy`

```python
import copy

data = {"users": ["alice", "bob"], "scores": [95, 87]}

snapshot = copy.deepcopy(data)
data["users"].append("charlie")

print(snapshot["users"])    # ["alice", "bob"]  ← untouched
```

`deepcopy` handles:

- Arbitrary nesting depth
- Circular references (via a memo dict — it tracks already-copied objects)
- Custom classes (via `__deepcopy__` if defined)

## The Numpy / PyTorch Connection (Critical for ML)

This is not an academic exercise. Shallow-vs-deep copy is one of the most common sources of bugs in numerical computing and ML code.

### NumPy: Three Levels of "Copy"

```python
import numpy as np

a = np.array([1, 2, 3, 4])

# 1. No copy — same array, same data buffer
b = a
b[0] = 99
print(a[0])           # 99  — a is mutated

# 2. View (shallow) — same data buffer, different array object
v = a.view()
v[0] = 0
print(a[0])           # 0   — still shares underlying data

v = a[1:3]            # Slicing in NumPy returns a VIEW, not a copy
v[0] = -1
print(a)              # [ 0 -1  3  4]  ← a[1] changed

# 3. Deep copy — completely independent data buffer
c = a.copy()
c[0] = 999
print(a[0])           # 0   — a is unaffected
```

**Key rule:** NumPy slices are **views**, not copies. This is an intentional design for memory efficiency, but it means `arr[start:end]` is a live window into the original array.

```python
# Dangerous pattern in data preprocessing:
train = X[:800]    # This is a VIEW of X
train -= train.mean()   # This modifies X in place too!

# Safe pattern:
train = X[:800].copy()
train -= train.mean()
```

### PyTorch: `.detach()`, `.clone()`, and the Computation Graph

In PyTorch, tensors carry a **computation graph** for automatic differentiation. Copy semantics interact with gradients.

```python
import torch

x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)

# view / slice: shares data AND stays in the computation graph
y = x[1:]

# detach: new tensor, shares data, severs from computation graph
z = x.detach()        # z will not receive gradients

# clone: new tensor, independent data, stays in computation graph
w = x.clone()         # safe copy for in-place operations in training loops

# clone().detach(): fully independent, no gradient tracking
snapshot = x.clone().detach()
```

|Operation|New Data Buffer|In Computation Graph|
|---|---|---|
|`x[i:j]` or `x.view(...)`|No (shared)|Yes|
|`x.detach()`|No (shared)|**No**|
|`x.clone()`|**Yes**|Yes|
|`x.clone().detach()`|**Yes**|**No**|

In training loops, failing to `.clone()` before in-place modification is a silent bug that corrupts gradients or tensors stored in a replay buffer.

## Custom Classes and `__copy__` / `__deepcopy__`

```python
import copy

class ModelConfig:
    def __init__(self, layers, hyperparams):
        self.layers      = layers         # mutable list
        self.hyperparams = hyperparams    # mutable dict

    def __copy__(self):
        # Shallow: new object, but same layers/hyperparams lists
        new = ModelConfig.__new__(ModelConfig)
        new.__dict__.update(self.__dict__)
        return new

    def __deepcopy__(self, memo):
        # Deep: new object with independently copied contents
        new = ModelConfig.__new__(ModelConfig)
        memo[id(self)] = new
        new.layers      = copy.deepcopy(self.layers, memo)
        new.hyperparams = copy.deepcopy(self.hyperparams, memo)
        return new
```

The `memo` dict in `__deepcopy__` is passed by the deepcopy machinery to handle **circular references** — without it, an object that references itself would cause infinite recursion.

## Worked Example: Why This Destroys ML Experiments

```python
# Bug: shallow copy of hyperparameter dicts in a sweep
base_config = {"lr": 0.01, "layers": [64, 128, 64]}

configs = []
for dropout in [0.1, 0.3, 0.5]:
    cfg = base_config.copy()        # SHALLOW COPY
    cfg["dropout"] = dropout
    cfg["layers"].append(32)        # Mutates base_config["layers"]!
    configs.append(cfg)

print(base_config["layers"])        # [64, 128, 64, 32, 32, 32]  ← corrupted

# Fix:
import copy
configs = []
for dropout in [0.1, 0.3, 0.5]:
    cfg = copy.deepcopy(base_config)
    cfg["dropout"] = dropout
    cfg["layers"].append(32)
    configs.append(cfg)

print(base_config["layers"])        # [64, 128, 64]  ← safe
```

## When to Use What

```
Object with no nested mutables (int, str, tuple of ints)
    → Assignment is safe. No copy needed.

Object with one level of nesting (list of ints, dict of strs)
    → Shallow copy is sufficient and faster.

Object with nested mutable containers (list of lists, dict of lists)
    → Use deepcopy.

NumPy array you're about to modify
    → arr.copy() before modification, especially after slicing.

PyTorch tensor for inference logging / replay buffer
    → tensor.clone().detach()

Custom class in a sweep or multi-trial experiment
    → deepcopy to guarantee independent state per trial.
```

---

## Performance Note

`deepcopy` is **significantly slower** than `copy` because it must traverse the entire object graph. For large nested structures in hot loops (e.g., batching training data), profile before defaulting to deepcopy. Often the right design is to restructure so that sharing is intentional and controlled, rather than copying everything defensively.

```python
import copy, timeit

data = {"matrix": list(range(10000))}

t_shallow = timeit.timeit(lambda: copy.copy(data),     number=10000)
t_deep    = timeit.timeit(lambda: copy.deepcopy(data), number=10000)

print(f"Shallow: {t_shallow:.3f}s")
print(f"Deep:    {t_deep:.3f}s")
# Shallow: ~0.003s
# Deep:    ~2.1s   ← ~700x slower on this data
```

## Summary Table

|Operation|New Object|Nested Shared|Use When|
|---|---|---|---|
|`b = a`|No|Yes (everything shared)|Intentional alias|
|`copy.copy(a)`|Yes|Yes (nested shared)|Flat container, or nested is immutable|
|`copy.deepcopy(a)`|Yes|No (fully independent)|Nested mutable, experiment configs|
|`np_arr.copy()`|Yes|N/A (flat data buffer)|NumPy in-place ops after slicing|
|`tensor.clone()`|Yes|N/A|PyTorch in-place ops, keep gradient|
|`tensor.clone().detach()`|Yes|N/A|PyTorch snapshot, no gradient|
