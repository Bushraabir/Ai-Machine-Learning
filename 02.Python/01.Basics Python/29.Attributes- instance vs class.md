# 29. Attributes — Instance vs Class

## The Core Distinction

An **attribute** is any data stored on an object or a class. Python has two kinds:

- **Instance attributes** — belong to one specific object. Each instance has its own copy, stored in `self.__dict__`. Changes to one instance never affect another.
- **Class attributes** — belong to the class itself. Shared across every instance unless explicitly overridden on an instance. Stored in `ClassName.__dict__`.

The lookup rule determines which one you get when you access `obj.attr`. Understanding that rule is the entire topic.

---

## Declaring Each Type

```python
class Dog:
    species = "Canis lupus familiaris"   # class attribute — shared by all dogs

    def __init__(self, name, age):
        self.name = name    # instance attribute — unique to this dog
        self.age = age      # instance attribute — unique to this dog

d1 = Dog("Rex", 3)
d2 = Dog("Bella", 5)

# Instance attributes — each dog has its own
print(d1.name)   # Rex
print(d2.name)   # Bella

# Class attribute — same for all
print(d1.species)   # Canis lupus familiaris
print(d2.species)   # Canis lupus familiaris
print(Dog.species)  # Canis lupus familiaris — accessible directly on class
```

---

## The Attribute Lookup Chain

When you write `obj.attr`, Python searches in this exact order:

```
1. obj.__dict__          (instance namespace)
2. type(obj).__dict__    (class namespace)
3. base classes          (MRO — method resolution order)
4. AttributeError        (if not found anywhere)
```

This is called the **descriptor protocol / attribute lookup chain**. The instance always wins over the class if the name exists in both.

```python
class Config:
    debug = False    # class attribute

c1 = Config()
c2 = Config()

print(c1.debug)    # False — found on class, no instance attr exists yet
print(c2.debug)    # False

# Now shadow the class attribute on c1 only
c1.debug = True    # creates a NEW instance attribute on c1

print(c1.debug)    # True  — found on instance (shadows class attr)
print(c2.debug)    # False — still reads class attr (no instance attr on c2)
print(Config.debug) # False — class attribute unchanged
```

Assigning to `obj.attr` **never modifies the class attribute**. It always creates or updates an instance attribute. The class attribute is untouched and still visible on other instances.

---

## Modifying a Class Attribute

To actually change the class attribute — for all instances simultaneously — assign through the class, not through an instance.

```python
class Config:
    debug = False

c1 = Config()
c2 = Config()

# Change via class — affects ALL instances that haven't shadowed it
Config.debug = True

print(c1.debug)    # True
print(c2.debug)    # True

# Now shadow on c1
c1.debug = False

Config.debug = True    # change class again
print(c1.debug)        # False — c1's instance attr shadows the class
print(c2.debug)        # True  — c2 still reads class attr
```

**Mental model:** Think of the class attribute as a default. The moment you do `self.attr = value`, you create a personal copy on the instance that permanently shadows the class default for that instance.

## Inspecting `__dict__` Directly

The most direct way to see what's happening:

```python
class Player:
    max_health = 100      # class attribute

    def __init__(self, name):
        self.name = name       # instance attribute
        self.health = 100      # instance attribute

p = Player("Alice")

print(p.__dict__)          # {'name': 'Alice', 'health': 100}
print(Player.__dict__)     # {'max_health': 100, '__init__': ..., ...}

# max_health is NOT in p.__dict__ — it lives on the class
print('max_health' in p.__dict__)      # False
print('max_health' in Player.__dict__) # True
```

This is the ground truth. If it is not in `p.__dict__`, it is not an instance attribute — Python is finding it on the class.

## The Critical Trap — Mutable Class Attributes

Mutable class attributes (lists, dicts, sets) are **shared across all instances**. Mutating them (`.append()`, `update()`, etc.) modifies the shared object — it does not create an instance-level copy.

```python
# Bug — all instances share the same list
class Bag:
    items = []    # class attribute — one list object shared by all

b1 = Bag()
b2 = Bag()

b1.items.append("apple")   # mutates the shared list — does NOT create instance attr
b1.items.append("bread")

print(b1.items)   # ['apple', 'bread']
print(b2.items)   # ['apple', 'bread']  ← b2 is affected!
print(id(b1.items) == id(b2.items))   # True — same object
```

Why does this happen? `b1.items.append(...)` does not assign to `b1.items` — it reads `b1.items` (finds the class attribute) and then mutates it in place. No instance attribute is ever created on `b1`.

```python
# Contrast: assignment creates a new instance attribute
b1.items = ["apple"]   # NOW b1 gets its own list — class attr untouched
b2.items               # still the original shared [] — empty
```

**The fix: always initialize mutable attributes in `__init__`:**

```python
class Bag:
    def __init__(self):
        self.items = []   # each instance gets its own fresh list

b1 = Bag()
b2 = Bag()

b1.items.append("apple")
print(b1.items)   # ['apple']
print(b2.items)   # []  — unaffected
```

This is one of the most common bugs in Python OOP. It also appears in `__init__` with mutable defaults — see [[27. init, self]].

## When Class Attributes Are Intentional and Correct

Not all class attributes are accidents. Some legitimate uses:

### Shared Constants

```python
class Circle:
    PI = 3.14159265358979   # mathematical constant — should be shared

    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return self.PI * self.radius ** 2
```

### Shared Configuration / Defaults

```python
class NeuralLayer:
    activation = "relu"        # default activation for all layers
    weight_init = "xavier"     # default initialization strategy

    def __init__(self, units):
        self.units = units
        # Can override per-instance if needed
        # self.activation = "sigmoid"
```

### Instance Counter — Tracking All Instances

```python
class Connection:
    count = 0   # tracks how many connections exist

    def __init__(self, host):
        self.host = host
        Connection.count += 1    # modify via class name — intentional

    def close(self):
        Connection.count -= 1

c1 = Connection("db1")
c2 = Connection("db2")
print(Connection.count)   # 2

c1.close()
print(Connection.count)   # 1
```

Notice: `Connection.count += 1` is used, not `self.count += 1`. The latter would create an instance attribute on the first call and never modify the class attribute again.

---

## `self.count += 1` vs `ClassName.count += 1` — The Subtle Bug

```python
class Counter:
    count = 0

    def increment_wrong(self):
        self.count += 1      # creates instance attr — class attr unchanged

    def increment_right(self):
        Counter.count += 1   # modifies class attr directly

c = Counter()
c.increment_wrong()
print(c.count)       # 1  — instance attr
print(Counter.count) # 0  — class attr untouched

c2 = Counter()
c2.increment_right()
print(Counter.count) # 1  — class attr updated
print(c2.count)      # 1  — reads class attr (no instance attr on c2)
```

`self.count += 1` expands to `self.count = self.count + 1`. The right side reads the class attr (0), adds 1, and then assigns 1 to a new **instance attribute**. The class attribute stays at 0. Any other instance that calls `increment_wrong()` starts fresh from the class attr.

## Class Attributes and Inheritance

Class attributes are inherited by subclasses. Each subclass gets its own `__dict__`, but looks up the parent's class attributes through the MRO.

```python
class Animal:
    kingdom = "Animalia"
    sound = "..."

class Dog(Animal):
    sound = "Woof"    # overrides class attr at the class level

class Cat(Animal):
    sound = "Meow"

print(Dog.kingdom)   # Animalia  — inherited from Animal
print(Dog.sound)     # Woof      — overridden on Dog
print(Cat.sound)     # Meow      — overridden on Cat
print(Animal.sound)  # ...       — parent unchanged
```

Changing `Animal.kingdom` after the fact propagates to all subclasses that haven't overridden it:

```python
Animal.kingdom = "ANIMALIA"
print(Dog.kingdom)   # ANIMALIA — Dog has no own kingdom, reads Animal's
```

## `vars()` — Another Way to Inspect

```python
class Rectangle:
    shape = "rectangle"

    def __init__(self, w, h):
        self.width = w
        self.height = h

r = Rectangle(4, 6)

print(vars(r))           # {'width': 4, 'height': 6}
print(vars(Rectangle))   # mappingproxy({'shape': 'rectangle', '__init__': ..., ...})
```

`vars(obj)` is equivalent to `obj.__dict__`. `vars(ClassName)` returns a `mappingproxy` — a read-only view of the class namespace.

## `__slots__` — Restricting Attributes

By default, Python uses a `__dict__` for every instance — flexible but memory-heavy. For classes with many instances and a fixed set of attributes, `__slots__` replaces the per-instance dict with a compact structure.

```python
class Point:
    __slots__ = ('x', 'y')   # only these attributes allowed

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
print(p.x)      # 1

p.z = 3         # AttributeError: 'Point' has no attribute 'z'
print(p.__dict__)   # AttributeError — no __dict__ with __slots__
```

**Consequences of `__slots__`:**

- No `__dict__` on instances — saves ~50 bytes per instance
- Only the declared attributes can be set — stricter but cleaner
- Class attributes still work normally
- Inheritance with `__slots__` requires care — every class in the chain should define `__slots__`

Use `__slots__` when you have millions of lightweight instances (e.g., graph nodes, data records, particle simulations).

## Full Reference — Lookup Behavior

```python
class Base:
    x = "class attr on Base"

class Child(Base):
    pass

obj = Child()

# Lookup order for obj.x:
# 1. obj.__dict__           → not found
# 2. Child.__dict__         → not found
# 3. Base.__dict__          → found: "class attr on Base"

print(obj.x)   # class attr on Base

# Shadow at instance level
obj.x = "instance attr"
print(obj.x)   # instance attr  — instance wins

# Shadow at subclass level
Child.x = "class attr on Child"
del obj.x                       # remove instance attr
print(obj.x)   # class attr on Child — Child wins over Base
```

## Side-by-Side Comparison

```python
class Example:
    class_attr = "shared"      # in Example.__dict__

    def __init__(self):
        self.instance_attr = "mine"   # in self.__dict__

e1 = Example()
e2 = Example()

#                     e1          e2          Example
# class_attr        "shared"    "shared"    "shared"
# instance_attr     "mine"      "mine"      (not here)

e1.class_attr = "overridden"   # creates instance attr on e1

#                     e1              e2          Example
# class_attr        "overridden"    "shared"    "shared"
# instance_attr     "mine"          "mine"      (not here)

Example.class_attr = "new shared"   # changes class attr

#                     e1              e2              Example
# class_attr        "overridden"    "new shared"    "new shared"
```

## Summary Table

||Instance attribute|Class attribute|
|---|---|---|
|Defined in|`__init__` via `self.attr = val`|Class body, outside any method|
|Stored in|`instance.__dict__`|`ClassName.__dict__`|
|Unique per instance|✅|❌ — shared unless shadowed|
|Access via instance|✅|✅ (via lookup chain)|
|Access via class|❌|✅|
|Mutable default danger|Rare|**High** — shared mutations affect all|
|Memory|One copy per instance|One copy total|
|Use case|Object-specific state|Shared constants, counters, defaults|
