# 22. Return Values

---

## Core Idea

A return value is the output a function sends back to its caller. It is how a function communicates its result — the product of its computation — to the code that invoked it.

Every Python function returns something. If no `return` statement is reached, Python returns `None` implicitly. Understanding return values deeply means understanding what your functions produce, how callers use that output, and how to design clean function interfaces.

```python
def add(a, b):
    return a + b      # explicit return

def greet(name):
    print(f"Hello, {name}")    # no return statement

result1 = add(3, 4)
print(result1)        # 7

result2 = greet("Alice")
print(result2)        # None — function printed but returned nothing
```

---

## The return Statement

### Mechanics

`return` does two things simultaneously:

1. Sends the specified value back to the caller
2. Exits the function immediately — no further code in the function runs

```python
def classify(x):
    if x > 0:
        return "positive"     # exits here when x > 0
    if x < 0:
        return "negative"     # exits here when x < 0
    return "zero"             # reached only when x == 0

print(classify(5))     # positive
print(classify(-3))    # negative
print(classify(0))     # zero
```

Code after a `return` in the same branch is unreachable:

```python
def f(x):
    return x * 2
    print("this never runs")    # unreachable — not a SyntaxError but pointless
```

---

### Implicit None Return

A function with no `return` statement, or a `return` with no value, returns `None`.

```python
def do_nothing():
    pass

def early_exit(x):
    if x < 0:
        return    # bare return — returns None
    return x * 2

print(do_nothing())        # None
print(early_exit(-1))      # None
print(early_exit(5))       # 10
```

Bare `return` is used as an early exit to stop execution when there is no meaningful value to return — equivalent to `return None` but more concise.

---

### Return Any Type

A function can return any Python object.

```python
def return_int():        return 42
def return_float():      return 3.14
def return_str():        return "hello"
def return_bool():       return True
def return_none():       return None
def return_list():       return [1, 2, 3]
def return_dict():       return {"a": 1}
def return_tuple():      return (1, 2)
def return_function():   return lambda x: x ** 2
def return_class():      return list    # the list class itself
```

Functions are objects and can return functions, classes, or other callables. This is the foundation of closures and decorators.

## Returning Multiple Values

Python functions can return multiple values by packing them into a tuple. The parentheses are optional — the comma is what creates the tuple.

```python
def min_max(data):
    return min(data), max(data)    # implicitly returns (min, max)

result = min_max([3, 1, 4, 1, 5, 9])
print(result)           # (1, 9)
print(type(result))     # <class 'tuple'>

# Unpack immediately — preferred
lo, hi = min_max([3, 1, 4, 1, 5, 9])
print(lo, hi)           # 1 9
```

```python
def split_data(data, ratio=0.8):
    split = int(len(data) * ratio)
    return data[:split], data[split:]

train, test = split_data(list(range(100)))
print(len(train), len(test))    # 80 20
```

```python
def compute_stats(data):
    n    = len(data)
    mean = sum(data) / n
    variance = sum((x - mean) ** 2 for x in data) / n
    return mean, variance, n

mean, var, count = compute_stats([2, 4, 4, 4, 5, 5, 7, 9])
print(f"mean={mean}, var={var}, n={count}")
```

**Unpack immediately at the call site.** Carrying around a tuple and later accessing `result[0]` and `result[1]` loses all readability. Names matter.

## Named Return Values — namedtuple and dataclass

When a function returns several values, named tuples and dataclasses document what each value means.

```python
from collections import namedtuple

Stats = namedtuple("Stats", ["mean", "variance", "count"])

def compute_stats(data):
    n    = len(data)
    mean = sum(data) / n
    var  = sum((x - mean) ** 2 for x in data) / n
    return Stats(mean=mean, variance=var, count=n)

result = compute_stats([2, 4, 4, 4, 5, 5, 7, 9])
print(result.mean)       # 5.0
print(result.variance)   # 4.0
print(result.count)      # 8

# Still unpackable as a tuple
mean, var, count = result
```

```python
from dataclasses import dataclass

@dataclass
class TrainResult:
    train_loss: float
    val_loss:   float
    accuracy:   float
    epochs_run: int

def train(model, data):
    # ... training logic ...
    return TrainResult(
        train_loss = 0.342,
        val_loss   = 0.391,
        accuracy   = 0.873,
        epochs_run = 50,
    )

result = train(model, data)
print(result.accuracy)    # 0.873
```

Use named returns when:

- Returning more than two or three values
- The meaning of each value is not obvious from context
- The return value will be passed around and accessed by field

## Return Value vs Side Effect

A function should either return a value or cause a side effect — ideally not both, and never confusingly mix the two.

```python
# Pure — returns a value, no side effects
def double(x):
    return x * 2

# Side effect — modifies external state, returns None
def log(message):
    print(message)

# Mixed — modifies and returns — acceptable when mutation is the point
def append_and_return(lst, item):
    lst.append(item)
    return lst
```

**The in-place vs return distinction is critical in Python:**

```python
# list.sort() — sorts in place, returns None
data = [3, 1, 2]
result = data.sort()
print(result)     # None  — common mistake
print(data)       # [1, 2, 3]  — data was mutated

# sorted() — returns new sorted list, original unchanged
data = [3, 1, 2]
result = sorted(data)
print(result)     # [1, 2, 3]
print(data)       # [3, 1, 2]  — unchanged
```

Python's built-in mutable methods (`.sort()`, `.append()`, `.reverse()`, `.update()`, `.clear()`) return `None`. They signal: "I mutated the object, there is no separate return value." `sorted()`, `reversed()`, `dict.copy()` return new objects and do not mutate.

Design your own functions the same way — be consistent. If a function mutates its argument, returning `None` signals that clearly. If it produces a new value, return it without mutating the input.

## Early Return — Guard Clause Pattern

Return early to handle special cases. Keep the happy path unindented and at the bottom.

```python
# Deeply nested — hard to follow
def process(data, threshold):
    if data is not None:
        if len(data) > 0:
            if isinstance(data, list):
                result = [x for x in data if x > threshold]
                return result

# Flat — guard clauses up front
def process(data, threshold):
    if data is None:
        return None
    if len(data) == 0:
        return []
    if not isinstance(data, list):
        raise TypeError(f"expected list, got {type(data).__name__}")

    return [x for x in data if x > threshold]
```

Each guard clause handles one failure mode and exits. The main logic is reached only when all preconditions are met.

## Returning Functions — Closures and Factories

Functions can return other functions. The returned function captures variables from the enclosing scope — this is a closure.

```python
def make_multiplier(factor):
    def multiply(x):
        return x * factor    # factor captured from enclosing scope
    return multiply           # return the function itself, not its result

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(5))    # 10
print(triple(5))    # 15
print(double(triple(4)))    # double(12) = 24
```

```python
def make_power(exponent):
    return lambda x: x ** exponent

square = make_power(2)
cube   = make_power(3)

print(square(4))    # 16
print(cube(3))      # 27
```

```python
# Factory pattern — return configured function
def make_validator(min_val, max_val):
    def validate(x):
        return min_val <= x <= max_val
    return validate

is_valid_age    = make_validator(0, 150)
is_valid_score  = make_validator(0, 100)
is_valid_rating = make_validator(1, 5)

print(is_valid_age(25))       # True
print(is_valid_score(105))    # False
print(is_valid_rating(3))     # True
```

Returning functions is the mechanism behind decorators, callback patterns, and much of the functional programming style used in ML pipelines.

## Returning None Intentionally vs Accidentally

Returning `None` intentionally signals "no result" or "operation complete":

```python
def find_first(data, predicate):
    for item in data:
        if predicate(item):
            return item
    return None    # explicit — nothing found

result = find_first([1, 2, 3, 4], lambda x: x > 10)
if result is None:
    print("not found")
```

Returning `None` accidentally is a bug:

```python
def double_all(data):
    result = [x * 2 for x in data]
    # forgot return

doubled = double_all([1, 2, 3])
print(doubled)    # None — forgot return statement
```

Always check: does every code path that should produce a value actually hit a `return` statement?

## Type Hints for Return Values

Type hints document what a function returns. They are not enforced at runtime but are used by IDEs, type checkers (mypy), and documentation tools.

```python
def add(a: int, b: int) -> int:
    return a + b

def greet(name: str) -> str:
    return f"Hello, {name}"

def process(data: list) -> None:
    for item in data:
        print(item)

def find(data: list, target) -> int | None:
    for i, item in enumerate(data):
        if item == target:
            return i
    return None
```

```python
from typing import Optional, Tuple, List

def min_max(data: List[float]) -> Tuple[float, float]:
    return min(data), max(data)

def maybe_find(data: list, key: str) -> Optional[str]:
    return data.get(key)    # returns str or None
```

For ML code, type hints are especially useful on functions that transform tensors — documenting the expected shape and type prevents a class of bugs at design time.

## Common Patterns in ML

**Returning train and validation split:**

```python
def train_val_split(dataset, val_ratio=0.2, seed=42):
    import random
    random.seed(seed)
    data = dataset.copy()
    random.shuffle(data)
    split = int(len(data) * (1 - val_ratio))
    return data[:split], data[split:]

train_data, val_data = train_val_split(full_dataset)
```

**Returning loss and metrics from a training step:**

```python
def train_step(model, batch, optimizer, criterion):
    inputs, targets = batch
    outputs  = model(inputs)
    loss     = criterion(outputs, targets)
    accuracy = compute_accuracy(outputs, targets)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

    return loss.item(), accuracy    # return scalar values, not tensors
```

**Returning model and tokenizer together:**

```python
def load_model(checkpoint_path):
    model     = build_model()
    tokenizer = build_tokenizer()
    state     = load_checkpoint(checkpoint_path)
    model.load_state_dict(state["model"])
    tokenizer.load_state(state["tokenizer"])
    return model, tokenizer

model, tokenizer = load_model("checkpoint_epoch_50.pt")
```

**Returning early on invalid input:**

```python
def safe_divide(a, b):
    if b == 0:
        return None    # or raise ValueError — depends on your contract
    return a / b

result = safe_divide(10, 0)
if result is None:
    print("division by zero")
```

## Summary

|Scenario|Return behavior|
|---|---|
|`return value`|Sends value to caller, exits immediately|
|`return` (bare)|Returns None, exits immediately|
|No return statement|Returns None implicitly|
|`return a, b`|Returns tuple (a, b) — unpack at call site|
|Mutable method (`.sort()`)|Returns None — signals in-place mutation|
|`sorted()`|Returns new object — signals no mutation|
|Returning a function|Closure — function captures enclosing scope|
|Type hint `-> T`|Documents expected return type|
|`-> None`|Function is called for side effects|
|`-> T \| None`|Returns T on success, None on failure|

## Common Mistakes to Avoid

```python
# Mistake 1: forgetting the return statement
def square(x):
    result = x ** 2    # computed but never returned

y = square(5)
print(y)    # None

# Mistake 2: using return value of in-place method
result = my_list.sort()    # None
result = sorted(my_list)   # correct

# Mistake 3: not unpacking multiple return values
result = min_max(data)
print(result[0])           # works but loses readability
lo, hi = min_max(data)     # correct — unpack immediately

# Mistake 4: checking returned None incorrectly
result = find(data, target)
if result:                  # wrong — 0 is falsy but a valid index
    use(result)
if result is not None:      # correct — explicit None check
    use(result)

# Mistake 5: returning inside a loop when you want all results
def get_evens(data):
    for x in data:
        if x % 2 == 0:
            return x        # returns first even only
    # correct:
    return [x for x in data if x % 2 == 0]

# Mistake 6: mixing mutation and return inconsistently
def process(lst):
    lst.append(0)
    return lst              # mutates AND returns — surprising
# either mutate (return None) or return new (don't mutate input)
```
