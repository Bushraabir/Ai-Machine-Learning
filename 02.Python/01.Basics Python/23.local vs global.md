# 23. Scope — Local vs Global

---

## Core Idea

Scope determines where in your code a variable name is visible and accessible. Python enforces strict rules about which names are visible from which locations. Understanding scope prevents bugs caused by accidentally reading or modifying the wrong variable, and explains why code that looks correct sometimes raises `NameError` or produces unexpected values.

Every name in Python lives in exactly one scope at a time.

---

## The LEGB Rule

Python resolves names in this fixed order, stopping at the first match:

```
L — Local       — names defined inside the current function
E — Enclosing   — names defined in any enclosing function (for nested functions)
G — Global      — names defined at module level (the file)
B — Built-in    — names provided by Python itself (len, print, range, etc.)
```

```python
x = "global"           # G — global scope

def outer():
    x = "enclosing"    # E — enclosing scope (relative to inner)

    def inner():
        x = "local"    # L — local scope
        print(x)       # local — found at L, stops here

    inner()
    print(x)           # enclosing — found at E

outer()
print(x)               # global — found at G
```

Python walks up the chain from L to B. The first match wins. If no match is found anywhere, `NameError` is raised.

---

## Local Scope

Variables assigned inside a function are local to that function. They exist only during the function's execution and are destroyed when the function returns.

```python
def f():
    x = 10          # local variable — exists only inside f
    print(x)        # 10

f()
print(x)            # NameError: name 'x' is not defined
```

Parameters are also local:

```python
def double(n):
    result = n * 2    # n and result are both local
    return result

double(5)
print(n)         # NameError — n is local to double
print(result)    # NameError — result is local to double
```

Local variables are completely isolated. Two different function calls each get their own independent copies of local variables.

```python
def counter():
    count = 0
    count += 1
    return count

print(counter())    # 1
print(counter())    # 1  — fresh local variable each call, not shared
```

---

## Global Scope

Variables assigned at module level (outside any function) are global. They are visible anywhere in the module.

```python
PI = 3.14159    # global

def circle_area(r):
    return PI * r ** 2    # reads PI from global scope — allowed

print(circle_area(5))    # 78.539...
```

**Reading a global from inside a function works without any special syntax.** Python follows LEGB — it does not find `PI` locally, so it looks in global scope and finds it there.

**Assigning to a global from inside a function does NOT work without `global`.**

```python
count = 0

def increment():
    count += 1    # UnboundLocalError — Python sees assignment, treats count as local

increment()
```

When Python sees an assignment to `count` inside `increment`, it marks `count` as a local variable for that entire function — even if the assignment happens later. Reading `count` before the assignment (as in `count += 1`, which is `count = count + 1`) tries to read a local variable that does not exist yet.

---

## The global Keyword

Declares that a name refers to the global variable, not a new local one.

```python
count = 0

def increment():
    global count      # tell Python: count refers to the global variable
    count += 1

increment()
increment()
print(count)    # 2
```

```python
total = 0
items = []

def add(value):
    global total, items    # multiple names on one line
    total += value
    items.append(value)

add(10)
add(20)
print(total)    # 30
print(items)    # [10, 20]
```

### When to Use global — Rarely

`global` creates hidden coupling between a function and module-level state. The function is no longer self-contained — it depends on and modifies external state invisibly. This makes code harder to test, debug, and reason about.

```python
# With global — hidden dependency, hard to test
count = 0

def increment():
    global count
    count += 1

# Without global — explicit, testable, pure
def increment(count):
    return count + 1

count = 0
count = increment(count)
```

Acceptable uses of `global`:

- Module-level constants (but prefer reading, not writing)
- Simple counters in scripts (not in production libraries)
- Caches that need to persist across calls (but prefer a class or `functools.lru_cache`)

Avoid `global` in any function that is part of a reusable module or library.

## Enclosing Scope — Nested Functions

When a function is defined inside another function, it has access to the enclosing function's local variables. This is the E in LEGB.

```python
def outer():
    message = "hello"       # enclosing scope variable

    def inner():
        print(message)      # reads from enclosing scope — works without nonlocal

    inner()

outer()    # hello
```

The inner function can read enclosing variables freely. It cannot assign to them without `nonlocal`.

```python
def outer():
    count = 0

    def inner():
        count += 1    # UnboundLocalError — same problem as with global
        print(count)

    inner()
```

---

## The nonlocal Keyword

Declares that a name refers to a variable in the nearest enclosing (non-global) scope.

```python
def outer():
    count = 0

    def inner():
        nonlocal count    # refer to outer's count, not a new local
        count += 1

    inner()
    inner()
    print(count)    # 2

outer()
```

### Closures — Capturing Enclosing State

A closure is a function that remembers variables from its enclosing scope even after the enclosing function has returned.

```python
def make_counter():
    count = 0            # enclosing variable

    def increment():
        nonlocal count
        count += 1
        return count

    return increment     # return the inner function

c1 = make_counter()
c2 = make_counter()

print(c1())    # 1
print(c1())    # 2
print(c1())    # 3
print(c2())    # 1  — c2 has its own independent count
```

Each call to `make_counter()` creates a new enclosing scope with its own `count`. `c1` and `c2` are independent because they close over different `count` variables.

```python
def make_multiplier(factor):
    def multiply(x):
        return x * factor    # factor captured from enclosing scope
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(5))    # 10
print(triple(5))    # 15
```

Closures are the mechanism behind decorators, factory functions, and stateful callbacks. When you see a function that returns a function, it is almost always using closure to capture state.

## Built-in Scope

Python's built-in names — `len`, `print`, `range`, `type`, `int`, `list`, `True`, `None`, etc. — live in the built-in scope. They are always available as a last resort in LEGB lookup.

```python
print(len([1, 2, 3]))    # len and print found in built-in scope
```

**You can shadow built-in names — do not.**

```python
# This is valid Python but catastrophically wrong
list = [1, 2, 3]         # shadows the built-in list class
print(list([4, 5, 6]))   # TypeError — list is now [1, 2, 3], not the class

# Fix: delete the shadowing variable or rename it
del list
print(list([4, 5, 6]))   # works again
```

Common names accidentally shadowed: `list`, `dict`, `set`, `tuple`, `id`, `type`, `input`, `len`, `min`, `max`, `sum`, `sorted`, `filter`, `map`, `zip`, `range`, `open`, `format`, `str`, `int`, `float`.

In ML code, `input` is especially dangerous to shadow because it is a built-in function and also a common name for neural network inputs.

---

## Variable Lifetime

|Scope|Created|Destroyed|
|---|---|---|
|Local|When function is called|When function returns|
|Enclosing|When outer function is called|When outer function returns (unless closure exists)|
|Global|When module is imported|When program exits|
|Built-in|At Python startup|At Python shutdown|

When a closure captures an enclosing variable, that variable's lifetime is extended — it persists as long as the closure exists.

```python
def make_counter():
    count = 0                    # normally destroyed when make_counter returns
    def increment():
        nonlocal count
        count += 1
        return count
    return increment

c = make_counter()               # make_counter returned, but count survives
print(c())                       # 1 — count still alive because c holds a reference
```

## Scope and Comprehensions

List, dict, and set comprehensions have their own scope in Python 3. The loop variable does not leak.

```python
result = [x for x in range(5)]
print(x)    # NameError in Python 3 — x is local to the comprehension
```

Generator expressions also have their own scope:

```python
gen = (x for x in range(5))
print(x)    # NameError — x is local to the generator
```

`for` loops do NOT create their own scope — the loop variable persists:

```python
for i in range(5):
    pass
print(i)    # 4 — i persists after the loop
```

This is a source of subtle bugs when you use the same variable name in a loop and rely on it afterward thinking it holds the last value intentionally.

---

## Scope in Classes

Class bodies create a local namespace during class definition, but this namespace does not form part of the LEGB chain for methods inside the class.

```python
class MyClass:
    class_var = 10

    def method(self):
        print(class_var)          # NameError — class scope not in LEGB for methods
        print(self.class_var)     # correct — access via self or MyClass
        print(MyClass.class_var)  # also correct
```

Methods look up names in local → enclosing → global → built-in. The class namespace is skipped. Always access class attributes explicitly via `self.name` or `ClassName.name`.

---

## Practical Rules

```
1. Keep functions pure — take inputs as parameters, return outputs.
   Avoid reading mutable globals inside functions.

2. Never write to a global from inside a function without global.
   If you think you need global, consider passing the value as a parameter
   and returning the modified value instead.

3. Never shadow built-in names.
   Do not use: list, dict, set, type, id, input, len, min, max, sum, etc.

4. Use nonlocal sparingly.
   If you find yourself using nonlocal often, consider whether a class
   with instance attributes would be cleaner.

5. Name enclosing scope variables clearly.
   When a closure captures a variable, its name should make its role obvious
   to anyone reading the inner function.
```

## LEGB Lookup — Full Example

```python
x = "global_x"          # G

def outer():
    x = "enclosing_x"   # E (relative to inner)
    y = "enclosing_y"   # E

    def inner():
        x = "local_x"   # L — shadows enclosing x
        print(x)         # local_x    (L wins)
        print(y)         # enclosing_y (E — no local y)
        print(len)       # <built-in function len> (B — not in L, E, G)

    inner()
    print(x)             # enclosing_x (inner's local x does not affect this)

outer()
print(x)                 # global_x
```

## Common Patterns

**Accumulator using return instead of global:**

```python
# Avoid — hidden global mutation
total = 0
def add(x):
    global total
    total += x

# Prefer — explicit, testable, composable
def add(total, x):
    return total + x

total = 0
total = add(total, 10)
total = add(total, 20)
print(total)    # 30
```

**Persistent state using a class instead of global:**

```python
# Avoid — global state
call_count = 0
def process(x):
    global call_count
    call_count += 1
    return x * 2

# Prefer — encapsulated state
class Processor:
    def __init__(self):
        self.call_count = 0

    def process(self, x):
        self.call_count += 1
        return x * 2

p = Processor()
p.process(5)
print(p.call_count)    # 1
```

**Module-level constants — the legitimate use of global names:**

```python
# Constants — global names that are only read, never written
MAX_RETRIES    = 5
DEFAULT_LR     = 0.001
VOCAB_SIZE     = 50000
PADDING_TOKEN  = "<PAD>"
DEVICE         = "cuda"

def train(model, data):
    for attempt in range(MAX_RETRIES):    # reading a constant — fine
        ...
```

Constants should be named in `UPPER_SNAKE_CASE` to signal that they are not meant to be reassigned.

---

## Summary

|Scope|Keyword to modify|Lifetime|Accessible from|
|---|---|---|---|
|Local (L)|— (default assignment)|Duration of function call|Inside function only|
|Enclosing (E)|`nonlocal`|Duration of outer function (or closure)|Inner functions|
|Global (G)|`global`|Duration of module|Anywhere in module|
|Built-in (B)|N/A (cannot reassign)|Duration of interpreter|Everywhere|

## Common Mistakes to Avoid

```python
# Mistake 1: expecting assignment inside function to affect global
x = 10
def f():
    x = 20    # creates a new local x — global x unchanged
f()
print(x)      # 10

# Mistake 2: UnboundLocalError from mixed read/write
count = 0
def increment():
    count += 1    # Python sees assignment -> count is local -> read before assign
# fix: global count, or pass count as argument and return new value

# Mistake 3: shadowing a built-in
list = [1, 2, 3]    # now list() is broken
del list            # fix: remove the shadowing name

# Mistake 4: assuming comprehension variable leaks (Python 3)
[x for x in range(5)]
print(x)    # NameError in Python 3 — x is local to comprehension

# Mistake 5: loop variable confusion
for i in range(5):
    pass
print(i)    # 4 — this DOES leak in a for loop (unlike comprehensions)

# Mistake 6: closure captures variable by reference, not by value
funcs = [lambda: i for i in range(5)]
print([f() for f in funcs])    # [4, 4, 4, 4, 4] — all see final value of i
# fix: capture by value using default argument
funcs = [lambda i=i: i for i in range(5)]
print([f() for f in funcs])    # [0, 1, 2, 3, 4]
```
