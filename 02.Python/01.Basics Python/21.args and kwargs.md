# 21. *args and **kwargs

---

## Core Idea

`*args` and `**kwargs` are mechanisms for writing functions that accept a variable number of arguments — when you do not know at definition time exactly how many arguments a caller will supply.

- `*args` — collects any number of extra **positional** arguments into a **tuple**
- `**kwargs` — collects any number of extra **keyword** arguments into a **dict**

The names `args` and `kwargs` are conventions. The `*` and `**` are the actual syntax. You could write `*numbers` or `**options` — the behavior is identical.

```python
def f(*args, **kwargs):
    print(args)     # tuple of positional arguments
    print(kwargs)   # dict of keyword arguments

f(1, 2, 3, name="Alice", age=30)
# (1, 2, 3)
# {"name": "Alice", "age": 30}
```

---

## *args — Variable Positional Arguments

### In a Function Definition

`*args` absorbs all positional arguments that are not matched by earlier parameters, packing them into a **tuple**.

```python
def total(*args):
    print(type(args))    # <class 'tuple'>
    print(args)
    return sum(args)

total(1, 2, 3)           # args = (1, 2, 3)         -> 6
total(10, 20, 30, 40)    # args = (10, 20, 30, 40)  -> 100
total()                  # args = ()                 -> 0
```

### Mixed with Regular Parameters

Regular parameters are matched first, left to right. `*args` captures the remainder.

```python
def f(a, b, *args):
    print(f"a={a}, b={b}, args={args}")

f(1, 2)              # a=1, b=2, args=()
f(1, 2, 3)           # a=1, b=2, args=(3,)
f(1, 2, 3, 4, 5)    # a=1, b=2, args=(3, 4, 5)
```

```python
def log(level, *messages):
    header = f"[{level}]"
    for msg in messages:
        print(header, msg)

log("INFO", "Server started")
log("ERROR", "Connection failed", "Retrying in 5s", "Attempt 1 of 3")
```

### Iterating Over *args

Inside the function, `args` is a plain tuple — index it, iterate it, pass to `sum()`, `len()`, etc.

```python
def describe(*args):
    print(f"received {len(args)} arguments")
    for i, val in enumerate(args):
        print(f"  [{i}] {val!r} (type: {type(val).__name__})")

describe(1, "hello", [1, 2], None)
# received 4 arguments
#   [0] 1 (type: int)
#   [1] 'hello' (type: str)
#   [2] [1, 2] (type: list)
#   [3] None (type: NoneType)
```

## **kwargs — Variable Keyword Arguments

### In a Function Definition

`**kwargs` absorbs all keyword arguments that are not matched by earlier parameters, packing them into a **dict**.

```python
def display(**kwargs):
    print(type(kwargs))    # <class 'dict'>
    for key, value in kwargs.items():
        print(f"  {key}: {value}")

display(name="Alice", age=30, role="Engineer")
# {"name": "Alice", "age": 30, "role": "Engineer"}
```

### Mixed with Regular Parameters

```python
def connect(host, port=5432, **kwargs):
    print(f"Connecting to {host}:{port}")
    for option, value in kwargs.items():
        print(f"  option {option} = {value}")

connect("localhost")
connect("localhost", 5433, timeout=30, ssl=True, pool_size=5)
# Connecting to localhost:5433
#   option timeout = 30
#   option ssl = True
#   option pool_size = 5
```

### Accessing **kwargs

Inside the function, `kwargs` is a plain dict — use `.get()`, iterate `.items()`, check with `in`, etc.

```python
def configure(**kwargs):
    lr      = kwargs.get("lr", 0.001)
    epochs  = kwargs.get("epochs", 100)
    verbose = kwargs.get("verbose", True)
    print(lr, epochs, verbose)

configure(lr=0.01, epochs=50)
```

## Combining *args and **kwargs

When both appear together, `*args` must come before `**kwargs`.

```python
def f(*args, **kwargs):
    print(f"positional: {args}")
    print(f"keyword:    {kwargs}")

f(1, 2, 3, name="Alice", score=95)
# positional: (1, 2, 3)
# keyword:    {"name": "Alice", "score": 95}
```

Full combined signature — in the correct order:

```python
def full(a, b, c=10, *args, kw_only=None, **kwargs):
    print(f"a={a}, b={b}, c={c}")
    print(f"args={args}")
    print(f"kw_only={kw_only}")
    print(f"kwargs={kwargs}")

full(1, 2, 3, 4, 5, kw_only="x", extra="y")
# a=1, b=2, c=3
# args=(4, 5)
# kw_only=x
# kwargs={"extra": "y"}
```

## Argument Unpacking at the Call Site

`*` and `**` are also used at the **call site** to unpack collections into arguments. This is the mirror operation.

### Unpacking a List/Tuple with *

```python
def add(a, b, c):
    return a + b + c

values = [1, 2, 3]
print(add(*values))      # equivalent to add(1, 2, 3)  -> 6

t = (10, 20, 30)
print(add(*t))           # equivalent to add(10, 20, 30)  -> 60

print(add(*range(3)))    # add(0, 1, 2)  -> 3
```

### Unpacking a Dict with **

```python
def greet(name, greeting="Hello", punctuation="!"):
    return f"{greeting}, {name}{punctuation}"

params = {"name": "Alice", "greeting": "Hi", "punctuation": "."}
print(greet(**params))   # Hi, Alice.
```

### Mixing Both at the Call Site

```python
def f(a, b, c, d, e):
    print(a, b, c, d, e)

f(*[1, 2], **{"c": 3, "d": 4, "e": 5})    # 1 2 3 4 5
```

### Unpacking into Another Collection

```python
a = [1, 2, 3]
b = [4, 5, 6]
merged = [*a, *b]               # [1, 2, 3, 4, 5, 6]
merged = [*a, 99, *b]           # [1, 2, 3, 99, 4, 5, 6]

x = {"a": 1, "b": 2}
y = {"c": 3, "d": 4}
merged = {**x, **y}             # {"a": 1, "b": 2, "c": 3, "d": 4}
merged = {**x, "b": 99, **y}    # b overwritten to 99
```

Dict merging with `**` is the standard pattern for config overrides:

```python
DEFAULTS = {"lr": 0.001, "epochs": 100, "batch_size": 32}
overrides = {"lr": 0.01, "epochs": 50}

config = {**DEFAULTS, **overrides}
# {"lr": 0.01, "epochs": 50, "batch_size": 32}
# overrides win on conflict
```

## The Forwarding Pattern

The most important production use of `*args, **kwargs`: passing all arguments through to another function unchanged. This is the foundation of decorators, wrappers, and middleware.

```python
def wrapper(func, *args, **kwargs):
    print(f"Calling {func.__name__}")
    result = func(*args, **kwargs)    # forward everything
    print("Done")
    return result

def add(a, b):
    return a + b

wrapper(add, 3, 4)         # works with positional
wrapper(add, a=3, b=4)     # works with keyword
```

```python
# Decorator using forwarding
def timer(func):
    import time
    def inner(*args, **kwargs):
        start  = time.time()
        result = func(*args, **kwargs)    # forward all args
        end    = time.time()
        print(f"{func.__name__} took {end - start:.4f}s")
        return result
    return inner

@timer
def slow_function(n):
    return sum(range(n))

slow_function(1_000_000)
# slow_function took 0.0312s
```

The inner wrapper does not need to know anything about `func`'s signature — it blindly forwards `*args` and `**kwargs`. This works for any function regardless of its parameters.

## Practical Patterns

### Flexible API with **kwargs

```python
class Model:
    def fit(self, X, y, **kwargs):
        lr         = kwargs.get("lr", 0.001)
        epochs     = kwargs.get("epochs", 100)
        batch_size = kwargs.get("batch_size", 32)
        verbose    = kwargs.get("verbose", True)

model = Model()
model.fit(X_train, y_train, lr=0.01, epochs=50, batch_size=64)
```

### Calling Parent Class Methods

```python
class Animal:
    def __init__(self, name, sound):
        self.name  = name
        self.sound = sound

class Dog(Animal):
    def __init__(self, name, breed, **kwargs):
        super().__init__(name, **kwargs)    # forward remaining kwargs to parent
        self.breed = breed

rex = Dog("Rex", "Labrador", sound="Woof")
```

### Config Override Pattern

```python
def build_config(**overrides):
    defaults = {
        "lr":         0.001,
        "epochs":     100,
        "batch_size": 32,
        "optimizer":  "adam",
    }
    return {**defaults, **overrides}

cfg = build_config(lr=0.01, epochs=50)
# {"lr": 0.01, "epochs": 50, "batch_size": 32, "optimizer": "adam"}
```

### Callbacks via *args

```python
def train(model, data, *callbacks, **hyperparams):
    lr     = hyperparams.get("lr", 0.001)
    epochs = hyperparams.get("epochs", 100)

    for epoch in range(epochs):
        loss = train_epoch(model, data, lr)
        for cb in callbacks:
            cb(epoch, loss)

def on_epoch_end(epoch, loss):
    print(f"Epoch {epoch}: loss={loss:.4f}")

def checkpoint(epoch, loss):
    if epoch % 10 == 0:
        save_model(f"ckpt_{epoch}.pt")

train(model, data, on_epoch_end, checkpoint, lr=0.01, epochs=100)
```

## Validating kwargs

Always validate `**kwargs` in production code — silently accepted typos are a common source of bugs.

```python
VALID_OPTIONS = {"lr", "epochs", "batch_size", "optimizer", "verbose"}

def train(model, data, **kwargs):
    unknown = set(kwargs) - VALID_OPTIONS
    if unknown:
        raise TypeError(f"unexpected keyword arguments: {unknown}")

    lr = kwargs.get("lr", 0.001)

train(model, data, lr=0.01, lrr=0.01)
# TypeError: unexpected keyword arguments: {"lrr"}
```

Alternatively, use explicit keyword-only parameters instead of `**kwargs` when the set of options is fixed — they provide built-in validation, better IDE autocomplete, and clearer documentation.

```python
# Prefer this when options are known and fixed
def train(model, data, *, lr=0.001, epochs=100, batch_size=32):
    ...

# Use **kwargs when options are genuinely open-ended
def train(model, data, **kwargs):
    ...
```

## *args vs Explicit List Parameter

```python
# Explicit list — caller must construct a list
def total(numbers):
    return sum(numbers)

total([1, 2, 3])       # caller builds list

# *args — caller passes values directly
def total(*numbers):
    return sum(numbers)

total(1, 2, 3)         # cleaner at call site
total(*existing_list)  # can also unpack
```

Use `*args` when callers will typically pass values directly. Use an explicit list parameter when callers will typically pass an already-constructed collection.

## Type Hints with *args and **kwargs

```python
from typing import Any

def log(*args: Any) -> None:
    print(*args)

def configure(**kwargs: Any) -> dict:
    return kwargs

# Specific types when all args must be same type
def concat(*strings: str) -> str:
    return "".join(strings)

def merge(**counts: int) -> dict[str, int]:
    return {**{"a": 0}, **counts}
```

## Summary

|Syntax|Location|Effect|
|---|---|---|
|`*args` in definition|Function signature|Packs extra positional args into tuple|
|`**kwargs` in definition|Function signature|Packs extra keyword args into dict|
|`*iterable` at call site|Function call|Unpacks iterable as positional args|
|`**dict` at call site|Function call|Unpacks dict as keyword args|
|`*` bare in signature|Between params|Forces following params to be keyword-only|

|Variable|Type inside function|Operations|
|---|---|---|
|`args`|`tuple`|Index, iterate, `len()`, `sum()`|
|`kwargs`|`dict`|`.get()`, `.items()`, `in`, `[]`|

## Common Mistakes to Avoid

```python
# Mistake 1: treating args as a list — it is a tuple
def f(*args):
    args.append(1)       # AttributeError — tuples have no append
    args = list(args)    # convert first if you need mutation

# Mistake 2: wrong order in signature
def f(**kwargs, *args): ...    # SyntaxError — *args must come first

# Mistake 3: positional after keyword at call site
f(1, 2, key="x", 3)    # SyntaxError

# Mistake 4: duplicate argument
def f(a, b): ...
f(1, a=2)    # TypeError: multiple values for argument 'a'

# Mistake 5: forgetting * when unpacking at call site
def add(a, b, c): ...
values = [1, 2, 3]
add(values)     # TypeError — passes list as single arg
add(*values)    # correct

# Mistake 6: not validating **kwargs — swallows typos silently
def train(**kwargs):
    lr = kwargs.get("lr", 0.001)
    # if caller passes lrr=0.01 it silently uses default
# validate known keys or switch to keyword-only params

# Mistake 7: not returning result in wrapper
def wrapper(func, *args, **kwargs):
    func(*args, **kwargs)       # return value lost
    return func(*args, **kwargs)  # correct

# Mistake 8: using **kwargs when keys must be strings
def f(**kwargs): ...
f(**{1: "a"})    # TypeError — keyword names must be valid identifiers
```
