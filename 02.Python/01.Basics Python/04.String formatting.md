String formatting is the process of embedding values — variables, expressions, computed results — into a string template. Python has four mechanisms for this, each from a different era of the language. Only two are used in modern code. Knowing all four lets you read any Python codebase regardless of age.

|Method|Syntax|Era|Use|
|---|---|---|---|
|Concatenation|`"hello " + name`|Always|Avoid — verbose, error-prone|
|%-formatting|`"hello %s" % name`|Python 2|Legacy — still seen in old code|
|str.format()|`"hello {}".format(name)`|Python 2.6+|Acceptable, verbose|
|f-strings|`f"hello {name}"`|Python 3.6+|Preferred — concise, readable, fast|

- ## Method 1: String Concatenation
Joining strings with `+`. Works but does not scale.
```python
name  = "Alice"
score = 95

result = "Name: " + name + ", Score: " + str(score)
print(result)    # Name: Alice, Score: 95
```
Problems:
- Non-string values must be manually converted with `str()`
- Becomes unreadable with more than two or three variables
- Creates multiple intermediate string objects — inefficient for many parts

Acceptable for two strings. Use f-strings for anything more complex.

- ## Method 2:  %-formatting (Old Style)
Inherited from C's `printf`. Still valid Python, still appears in logging and legacy codebases.
```python
name  = "Alice"
score = 95
pi    = 3.14159

print("Name: %s" % name)                       # Name: Alice
print("Score: %d" % score)                     # Score: 95
print("Pi: %.2f" % pi)                         # Pi: 3.14
print("Name: %s, Score: %d" % (name, score))   # multiple values — tuple
```
### Format Specifiers

| Specifier | Meaning                            |
| --------- | ---------------------------------- |
| `%s`      | String (calls str() on any object) |
| `%d`      | Integer                            |
| `%f`      | Float                              |
| `%e`      | Scientific notation                |
| `%r`      | repr() of object                   |
| `%.2f`    | Float with 2 decimal places        |
| `%10d`    | Integer, minimum width 10          |
| `%-10s`   | Left-aligned, minimum width 10     |

```python
print("%-10s %5d %8.2f" % ("Alice", 95, 3.14159))
# Alice           95     3.14
```

Do not use `%`-formatting in new code. It is error-prone (single value vs tuple rules), harder to read, and f-strings do everything it does more clearly.

- ## Method 3: str.format()
Introduced in Python 2.6 as a cleaner alternative to `%`.
```python
name  = "Alice"
score = 95

# Positional — {} filled left to right
print("Name: {}, Score: {}".format(name, score))
# Name: Alice, Score: 95

# Indexed — {0}, {1} etc.
print("Name: {0}, Score: {1}, Name again: {0}".format(name, score))
# Name: Alice, Score: 95, Name again: Alice

# Named — {name}
print("Name: {name}, Score: {score}".format(name=name, score=score))
# Name: Alice, Score: 95
```

### Format Specifiers with .format()

Specifiers go after `:` inside the braces.

```python
pi = 3.14159265

print("{:.2f}".format(pi))          # 3.14
print("{:10.3f}".format(pi))        # "     3.142"  — width 10, 3 decimal places
print("{:e}".format(pi))            # 3.141593e+00
print("{:>10}".format("hi"))        # "        hi"  — right-aligned
print("{:<10}".format("hi"))        # "hi        "  — left-aligned
print("{:^10}".format("hi"))        # "    hi    "  — centered
print("{:0>10}".format("42"))       # "0000000042"  — zero-padded
print("{:,}".format(1000000))       # "1,000,000"   — thousands separator
print("{:+.2f}".format(3.14))       # "+3.14"       — explicit sign
print("{:#b}".format(42))           # "0b101010"    — binary with prefix
print("{:#x}".format(255))          # "0xff"        — hex with prefix
```

`str.format()` is more explicit than f-strings for cases where the template and values are separate (e.g. templates stored in config files). Otherwise, prefer f-strings.


- ## Method 4: f-strings (Formatted String Literals)
The modern standard. Prefix the string with `f` or `F`. Any expression inside `{}` is evaluated at runtime and embedded.
```python
name  = "Alice"
score = 95

print(f"Name: {name}, Score: {score}")    # Name: Alice, Score: 95
```

### Expressions Inside f-strings
Any valid Python expression works inside `{}`:
```python
x = 10
print(f"x squared is {x ** 2}")            # x squared is 100
print(f"type of x is {type(x).__name__}")   # type of x is int
print(f"x is {'even' if x % 2 == 0 else 'odd'}")   # x is even

data = [1, 2, 3, 4, 5]
print(f"sum = {sum(data)}, mean = {sum(data) / len(data):.2f}")
# sum = 15, mean = 3.00

import math
print(f"sqrt(2) = {math.sqrt(2):.6f}")     # sqrt(2) = 1.414214
```

### Format Specifiers in f-strings

Same specifier syntax as `.format()`, placed after `:` inside the braces.

```python
pi    = 3.14159265
value = 1234567.89

# Decimal places
print(f"{pi:.2f}")            # 3.14
print(f"{pi:.6f}")            # 3.141593

# Scientific notation
print(f"{value:.3e}")         # 1.235e+06

# Integer formatting
n = 42
print(f"{n:05d}")             # 00042   — zero-padded to width 5
print(f"{n:b}")               # 101010  — binary
print(f"{n:x}")               # 2a      — hexadecimal
print(f"{n:o}")               # 52      — octal
print(f"{n:#x}")              # 0x2a    — hex with prefix

# Alignment
print(f"{'left':<10}|")       # left      |
print(f"{'right':>10}|")      #      right|
print(f"{'center':^10}|")     #   center  |
print(f"{'fill':*^10}|")      # **fill*** |  — fill char before alignment

# Thousands separator
print(f"{1_000_000:,}")       # 1,000,000
print(f"{value:,.2f}")        # 1,234,567.89

# Percentage
ratio = 0.8735
print(f"{ratio:.1%}")         # 87.4%

# Sign
print(f"{3.14:+.2f}")         # +3.14
print(f"{-3.14:+.2f}")        # -3.14
```

### Self-Documenting Expressions: `=` Specifier (Python 3.8+)

`{expr=}` prints both the expression text and its value. Invaluable for debugging.

```python
x = 42
y = [1, 2, 3]

print(f"{x=}")          # x=42
print(f"{y=}")          # y=[1, 2, 3]
print(f"{x * 2 + 1=}")  # x * 2 + 1=85
print(f"{len(y)=}")     # len(y)=3
```

Use this instead of `print("x =", x)` — it is shorter and the variable name cannot get out of sync with the value.

### Multiline f-strings

```python
name  = "Alice"
score = 95
grade = "A"

report = (
    f"Student: {name}\n"
    f"Score:   {score}\n"
    f"Grade:   {grade}"
)
print(report)
# Student: Alice
# Score:   95
# Grade:   A
```

Triple-quoted f-strings:

```python
report = f"""
Student: {name}
Score:   {score}
Grade:   {grade}
"""
print(report)
```

### Nested f-strings

```python
width  = 10
value  = 3.14159

# Dynamic width specifier — the inner f-string evaluates first
print(f"{value:{width}.3f}")    # "     3.142"

# Dynamic fill character
fill = "*"
print(f"{'hi':{fill}^{width}}")    # "****hi****"
```

### Escaping Braces

```python
print(f"{{literal braces}}")    # {literal braces}
print(f"{{{name}}}")            # {Alice}  — outer {{ }} are literal, inner {} is expression
```

Backslashes cannot be used inside the `{}` expression part of an f-string (Python < 3.12). Use a variable instead:

```python
# Python < 3.12
newline = "\n"
print(f"line1{newline}line2")

# Python 3.12+ — backslashes allowed inside {}
print(f"{'hello\nworld'}")
```

## Format Specification Mini-Language

The full format spec reference — applies to both `.format()` and f-strings:

```
{value : [fill][align][sign][z][#][0][width][grouping][.precision][type]}
```

|Component|Options|Meaning|
|---|---|---|
|fill|any char|Character to pad with|
|align|`<` `>` `^` `=`|Left, right, center, pad after sign|
|sign|`+` `-`|Always show, only negative, space for positive|
|`#`|flag|Alternate form (0b, 0o, 0x prefixes)|
|`0`|flag|Zero-pad (equivalent to fill=0, align==)|
|width|integer|Minimum field width|
|grouping|`,` `_`|Thousands separator|
|.precision|integer|Decimal places for float, max chars for string|
|type|see below|How to interpret the value|

|Type|Meaning|
|---|---|
|`d`|Integer|
|`f`|Fixed-point float|
|`e` `E`|Scientific notation|
|`g` `G`|General (fixed or scientific, whichever is shorter)|
|`%`|Percentage (multiplies by 100, appends %)|
|`s`|String|
|`b`|Binary|
|`o`|Octal|
|`x` `X`|Hex (lowercase / uppercase)|
|`c`|Character (int to Unicode)|

## Choosing Between Methods

```python
# Simple embedding — f-string
print(f"Hello, {name}!")

# Template stored separately (config file, database) — .format()
template = "Hello, {name}! Your score is {score}."
print(template.format(name=name, score=score))

# Legacy code maintenance — % formatting
# read it, do not write it

# Dynamic format spec — f-string with nested {}
print(f"{value:{width}.{precision}f}")
```

The rule is simple: use f-strings by default. Switch to `.format()` only when the template must be defined separately from the values (config files, internationalization, late binding).

## Summary

|Feature|f-string|.format()|
|---|---|---|
|Syntax|`f"{expr}"`|`"{0}".format(val)`|
|Expressions|Any Python expression|Only names/indices|
|Performance|Fastest|Slower|
|Readability|Highest|Good|
|Template separation|No|Yes|
|`=` debug specifier|Yes (3.8+)|No|
|Format specs|Full support|Full support|

## Common Mistakes to Avoid

```python
# Mistake 1: concatenating non-strings without str()
name  = "Alice"
score = 95
print("Score: " + score)       # TypeError
print("Score: " + str(score))  # works
print(f"Score: {score}")       # better — f-string handles conversion

# Mistake 2: using % with a single non-tuple value (old style)
print("Value: %s" % name)      # fine
print("Values: %s %s" % name, score)   # TypeError — must be a tuple
print("Values: %s %s" % (name, score)) # correct

# Mistake 3: calling .format() with wrong number of arguments
"{} {}".format("only_one")     # IndexError

# Mistake 4: backslash in f-string expression (Python < 3.12)
print(f"{'\n'.join(items)}")   # SyntaxError
items_str = '\n'.join(items)   # compute outside
print(f"{items_str}")          # correct

# Mistake 5: forgetting the f prefix
name = "Alice"
print("Hello, {name}")         # Hello, {name} — not evaluated, missing f

# Mistake 6: misreading format specifier order
f"{value:.2f}"    # correct — precision 2, float
f"{value:2.f}"    # wrong — not a valid specifier

# Mistake 7: using {=} outside debug context
# {x=} includes the variable name in output — do not use in production logs
# use it only for debugging
```
