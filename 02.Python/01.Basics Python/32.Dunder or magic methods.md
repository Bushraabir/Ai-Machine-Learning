# 32. Dunder (Magic) Methods

## What Dunder Methods Are

Dunder methods — short for **double underscore** methods — are special methods with names like `__str__`, `__len__`, `__add__`. Python calls them **automatically** in response to built-in operations. You never call them directly; you define them, and Python invokes them when the right operation is applied to your object.

```python
x = [1, 2, 3]
len(x)        # Python calls x.__len__()
str(x)        # Python calls x.__str__()
x + [4]       # Python calls x.__add__([4])
x[0]          # Python calls x.__getitem__(0)
```

Every built-in operation in Python maps to a dunder method. By implementing these methods on your own classes, your objects integrate seamlessly with Python syntax — they can be printed, compared, added, iterated, indexed, and used in `with` statements, just like built-in types.

This is called the **Python data model**. It is one of the most powerful design decisions in the language.

---

## `__repr__` and `__str__` — String Representation

These are the two most universally needed dunder methods.

### `__repr__` — Unambiguous, Developer-Facing

`__repr__` should return a string that could recreate the object. It is called by `repr(obj)`, by the REPL when you evaluate an expression, and as the fallback when `__str__` is not defined.

**Rule:** `repr` is for developers. It should be precise and unambiguous.

### `__str__` — Readable, User-Facing

`__str__` is called by `str(obj)` and `print(obj)`. It should return a human-readable representation.

**Rule:** `str` is for end users. It should be clean and readable.

```python
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Vector({self.x!r}, {self.y!r})"   # unambiguous, could recreate

    def __str__(self):
        return f"({self.x}, {self.y})"              # clean, readable

v = Vector(3, 4)

print(repr(v))    # Vector(3, 4)       — calls __repr__
print(str(v))     # (3, 4)             — calls __str__
print(v)          # (3, 4)             — print calls __str__

# In a list, repr is used for each element
print([v])        # [Vector(3, 4)]     — list uses repr on elements
```

**Fallback rule:** If `__str__` is not defined, Python falls back to `__repr__`. If neither is defined, Python uses `object.__repr__` which gives `<__main__.Vector object at 0x...>`.

**Minimum requirement:** Always define `__repr__`. It is the one dunder method every class should have.

## `__len__` — The `len()` Protocol

```python
class Playlist:
    def __init__(self, songs):
        self.songs = songs

    def __len__(self):
        return len(self.songs)

p = Playlist(["Song A", "Song B", "Song C"])
print(len(p))    # 3

# __len__ also enables truthiness evaluation
print(bool(Playlist([])))       # False — len is 0
print(bool(Playlist(["x"])))    # True  — len is non-zero
```

Any object with `__len__` automatically participates in Python's truthiness protocol: `bool(obj)` returns `False` if `len(obj) == 0`, `True` otherwise — unless `__bool__` is also defined (which takes precedence).

## `__eq__`, `__lt__`, `__le__`, `__gt__`, `__ge__`, `__ne__` — Comparison

By default, `==` checks object identity (same as `is`). Defining `__eq__` changes what equality means for your class.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return self.x == other.x and self.y == other.y

    def __lt__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return (self.x**2 + self.y**2) < (other.x**2 + other.y**2)

    def __repr__(self):
        return f"Point({self.x}, {self.y})"

p1 = Point(1, 2)
p2 = Point(1, 2)
p3 = Point(3, 4)

print(p1 == p2)    # True   — value equality via __eq__
print(p1 is p2)    # False  — different objects
print(p1 < p3)     # True   — p1 is closer to origin
```

**`NotImplemented` vs `NotImplementedError`:**

Return `NotImplemented` (not raise) when the comparison is not supported. Python then tries the reflected operation on the other operand. Returning `NotImplemented` is part of the protocol — it tells Python to keep trying. Raising `NotImplementedError` would crash instead.

**`@functools.total_ordering` — Define only `__eq__` and one comparison:**

```python
from functools import total_ordering

@total_ordering
class Temperature:
    def __init__(self, degrees):
        self.degrees = degrees

    def __eq__(self, other):
        return self.degrees == other.degrees

    def __lt__(self, other):
        return self.degrees < other.degrees

    # total_ordering fills in __le__, __gt__, __ge__ automatically

t1 = Temperature(100)
t2 = Temperature(200)
print(t1 <= t2)   # True
print(t1 > t2)    # False
```

**Warning:** Defining `__eq__` makes your class unhashable by default (Python sets `__hash__ = None`). If you need objects to be usable in sets or as dict keys, also define `__hash__`.

```python
def __hash__(self):
    return hash((self.x, self.y))
```

## `__add__`, `__sub__`, `__mul__` — Arithmetic Operators

```python
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __sub__(self, other):
        return Vector(self.x - other.x, self.y - other.y)

    def __mul__(self, scalar):
        return Vector(self.x * scalar, self.y * scalar)

    def __rmul__(self, scalar):
        return self.__mul__(scalar)    # handles scalar * vector

    def __neg__(self):
        return Vector(-self.x, -self.y)   # unary negation

    def __abs__(self):
        return (self.x**2 + self.y**2) ** 0.5

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

v1 = Vector(1, 2)
v2 = Vector(3, 4)

print(v1 + v2)    # Vector(4, 6)
print(v2 - v1)    # Vector(2, 2)
print(v1 * 3)     # Vector(3, 6)
print(3 * v1)     # Vector(3, 6)   — uses __rmul__
print(-v1)        # Vector(-1, -2)
print(abs(v2))    # 5.0
```

**Reflected operations (`__radd__`, `__rmul__`, etc.):**

When `a + b` is evaluated, Python first tries `a.__add__(b)`. If that returns `NotImplemented` or is not defined, Python tries `b.__radd__(a)`. Defining `__rmul__` on `Vector` makes `3 * vector` work even though `int.__mul__` does not know about vectors.

**Augmented assignment (`__iadd__`, `__imul__`, etc.):**

```python
def __iadd__(self, other):
    self.x += other.x
    self.y += other.y
    return self    # must return self for in-place operations

v1 += v2    # calls v1.__iadd__(v2)
```

If `__iadd__` is not defined, `v1 += v2` falls back to `v1 = v1.__add__(v2)` — creates a new object. Define `__iadd__` for true in-place modification.

## `__getitem__`, `__setitem__`, `__delitem__` — Indexing Protocol

```python
class Grid:
    def __init__(self, rows, cols):
        self.data = [[0] * cols for _ in range(rows)]

    def __getitem__(self, pos):
        row, col = pos
        return self.data[row][col]

    def __setitem__(self, pos, value):
        row, col = pos
        self.data[row][col] = value

    def __delitem__(self, pos):
        row, col = pos
        self.data[row][col] = 0   # reset to zero on delete

g = Grid(3, 3)
g[1, 2] = 99       # calls __setitem__((1, 2), 99)
print(g[1, 2])     # 99   — calls __getitem__((1, 2))
del g[1, 2]        # calls __delitem__((1, 2))
print(g[1, 2])     # 0
```

NumPy arrays use exactly this mechanism — `arr[0, 1]` calls `arr.__getitem__((0, 1))`. Pandas DataFrames use `__getitem__` for column access: `df["col"]` is `df.__getitem__("col")`.

## `__contains__` — The `in` Operator

```python
class WordList:
    def __init__(self, words):
        self.words = set(words)

    def __contains__(self, word):
        return word.lower() in self.words

wl = WordList(["Python", "Java", "C++"])
print("python" in wl)    # True  — calls __contains__
print("Ruby" in wl)      # False
```

Without `__contains__`, `in` falls back to iterating via `__iter__` (or `__getitem__`). Defining `__contains__` lets you provide O(1) lookup.

## `__iter__` and `__next__` — Iteration Protocol

Making your object iterable so it works in `for` loops, `list()`, `zip()`, etc.

```python
class CountDown:
    def __init__(self, start):
        self.start = start
        self.current = start

    def __iter__(self):
        self.current = self.start    # reset on each iteration
        return self                  # return self as the iterator

    def __next__(self):
        if self.current <= 0:
            raise StopIteration      # signal that iteration is done
        value = self.current
        self.current -= 1
        return value

cd = CountDown(3)
for n in cd:
    print(n)
# 3
# 2
# 1

print(list(CountDown(5)))   # [5, 4, 3, 2, 1]
```

**Iterable vs Iterator:**

- **Iterable**: has `__iter__` returning an iterator. Can be looped over multiple times.
- **Iterator**: has both `__iter__` and `__next__`. Maintains its own position. Exhausted after one pass.

Combining both on the same class (as above) is the simplest pattern but means only one active iteration at a time. For concurrent iterations, return a separate iterator object from `__iter__`.

## `__call__` — Making Objects Callable

```python
class Multiplier:
    def __init__(self, factor):
        self.factor = factor

    def __call__(self, x):
        return x * self.factor

double = Multiplier(2)
triple = Multiplier(3)

print(double(5))     # 10   — calls double.__call__(5)
print(triple(5))     # 15
print(callable(double))   # True
```

An object with `__call__` is **callable** — it can be used anywhere a function is expected. This is how PyTorch's `nn.Module` works: `model(x)` calls `model.__call__(x)`, which internally calls `model.forward(x)` plus hooks.

```python
# Simplified PyTorch pattern
class Module:
    def __call__(self, x):
        # runs pre-hooks
        result = self.forward(x)
        # runs post-hooks
        return result

    def forward(self, x):
        raise NotImplementedError
```

## `__enter__` and `__exit__` — Context Manager Protocol

```python
class ManagedFile:
    def __init__(self, path, mode='r'):
        self.path = path
        self.mode = mode
        self.file = None

    def __enter__(self):
        self.file = open(self.path, self.mode)
        return self.file      # value bound to 'as' variable

    def __exit__(self, exc_type, exc_val, exc_tb):
        if self.file:
            self.file.close()
        return False          # False = don't suppress exceptions

with ManagedFile("data.txt", "w") as f:
    f.write("hello")
# file is closed automatically, even if an exception occurs
```

`__exit__` receives exception info if one was raised inside the `with` block. Returning `True` suppresses the exception; returning `False` (or `None`) lets it propagate.

See [[60. Writing custom context managers]] for full treatment.

## `__bool__` — Truthiness

```python
class Budget:
    def __init__(self, amount):
        self.amount = amount

    def __bool__(self):
        return self.amount > 0

b1 = Budget(100)
b2 = Budget(0)
b3 = Budget(-50)

print(bool(b1))   # True
print(bool(b2))   # False
print(bool(b3))   # False

if b1:
    print("Budget available")    # prints

if not b2:
    print("No budget")           # prints
```

**Priority:** `__bool__` takes precedence over `__len__`. If both are defined, Python uses `__bool__` for truthiness evaluation.

## `__hash__` — Hashability

Objects that define `__eq__` become unhashable by default (Python sets `__hash__ = None`). To use them in sets or as dict keys, define `__hash__`.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)

    def __hash__(self):
        return hash((self.x, self.y))   # must be consistent with __eq__

p1 = Point(1, 2)
p2 = Point(1, 2)

print(p1 == p2)         # True
print(hash(p1) == hash(p2))   # True — equal objects must have equal hashes

seen = {p1}
print(p2 in seen)       # True — hash lookup works
```

**Rule:** If `a == b` then `hash(a) == hash(b)` must hold. The reverse need not be true (hash collisions are allowed).

## `__del__` — Destructor

Called when the object is about to be garbage collected. Use sparingly — the timing is not guaranteed.

```python
class Resource:
    def __init__(self, name):
        self.name = name
        print(f"{name} acquired")

    def __del__(self):
        print(f"{self.name} released")

r = Resource("DB Connection")   # DB Connection acquired
del r                            # DB Connection released
```

Do not rely on `__del__` for critical cleanup — use context managers (`__enter__`/`__exit__`) instead. `__del__` is not guaranteed to run at a specific time, and in CPython it may not run at all in some circular reference scenarios.

|Dunder|Triggered by|Notes|
|---|---|---|
|`__repr__`|`repr(obj)`, REPL, fallback for `str`|Always define this|
|`__str__`|`str(obj)`, `print(obj)`|Falls back to `__repr__`|
|`__len__`|`len(obj)`|Enables truthiness via length|
|`__bool__`|`bool(obj)`, `if obj:`|Takes precedence over `__len__`|
|`__eq__`|`obj == other`|Disables `__hash__` by default|
|`__ne__`|`obj != other`|Auto-derived from `__eq__` in Python 3|
|`__lt__`|`obj < other`|Use `@total_ordering` for full set|

|`__add__`|`obj + other`|Return new object|
|`__radd__`|`other + obj`|Reflected — when left operand fails|
|`__iadd__`|`obj += other`|In-place — must return `self`|
|`__mul__`|`obj * other`||

|`__abs__`|`abs(obj)`||
|`__getitem__`|`obj[key]`|Enables indexing|
|`__setitem__`|`obj[key] = val`||

|`__setattr__`|`obj.attr = val`|Intercepts all attribute setting|

## A Complete Class Using Multiple Dunders

```python
from functools import total_ordering

@total_ordering
class Matrix:
    """2x2 matrix with full operator support."""

    def __init__(self, data):
        # data is a 2x2 list: [[a, b], [c, d]]
        self.data = [row[:] for row in data]

    def __repr__(self):
        return f"Matrix({self.data!r})"

    def __str__(self):
        rows = [f"  {row}" for row in self.data]
        return "[\n" + "\n".join(rows) + "\n]"

    def __eq__(self, other):
        if not isinstance(other, Matrix):
            return NotImplemented
        return self.data == other.data

    def __lt__(self, other):
        return self._det() < other._det()

    def __add__(self, other):
        return Matrix([
            [self.data[i][j] + other.data[i][j] for j in range(2)]
            for i in range(2)
        ])

    def __mul__(self, other):
        if isinstance(other, (int, float)):
            return Matrix([[v * other for v in row] for row in self.data])
        # Matrix multiplication
        result = [[0, 0], [0, 0]]
        for i in range(2):
            for j in range(2):
                for k in range(2):
                    result[i][j] += self.data[i][k] * other.data[k][j]
        return Matrix(result)

    def __rmul__(self, scalar):
        return self.__mul__(scalar)

    def __len__(self):
        return 2    # number of rows

    def __getitem__(self, pos):
        row, col = pos
        return self.data[row][col]

    def __setitem__(self, pos, value):
        row, col = pos
        self.data[row][col] = value

    def __contains__(self, value):
        return any(value in row for row in self.data)

    def __iter__(self):
        return iter(self.data)

    def _det(self):
        return self.data[0][0]*self.data[1][1] - self.data[0][1]*self.data[1][0]

    def __hash__(self):
        return hash(tuple(tuple(row) for row in self.data))


m1 = Matrix([[1, 2], [3, 4]])
m2 = Matrix([[5, 6], [7, 8]])

print(m1 + m2)          # Matrix addition
print(m1 * 2)           # Scalar multiply
print(2 * m1)           # __rmul__
print(m1 * m2)          # Matrix multiply
print(m1[0, 1])         # 2  — __getitem__
print(3 in m1)          # True — __contains__
print(m1 < m2)          # True — by determinant
print(len(m1))          # 2
for row in m1:
    print(row)          # iterates rows
```

## Common Errors

```python
# 1. __str__ returns non-string — TypeError
class Bad:
    def __str__(self):
        return 42    # TypeError: __str__ returned non-string

# 2. __eq__ without __hash__ — object becomes unhashable
class Point:
    def __eq__(self, other):
        return True

p = Point()
{p}   # TypeError: unhashable type: 'Point'
# Fix: define __hash__ alongside __eq__

# 3. __iadd__ not returning self
class Vec:
    def __iadd__(self, other):
        self.x += other.x
        # forgot: return self
        # v += other now sets v to None

# 4. Raising NotImplementedError instead of returning NotImplemented
class Num:
    def __add__(self, other):
        if not isinstance(other, Num):
            raise NotImplementedError   # wrong — crashes instead of trying __radd__
            return NotImplemented       # correct — tells Python to try reflected op

# 5. __next__ without StopIteration — infinite loop
class Counter:
    def __next__(self):
        self.n += 1
        return self.n   # never raises StopIteration — for loop never ends
```
