# 59. @staticmethod, @classmethod, @property

> _"The three built-in method decorators are not syntax sugar — they are descriptors that redefine what gets passed as the first argument, and what the return value of attribute access means. Understanding them at that level makes every design decision obvious."_

---

## The Problem They Each Solve

A regular method receives the **instance** as its first argument (`self`). But not every method logically belongs to an instance:

- Some methods belong to the **class** — they operate on class-level state or construct instances
- Some methods are merely **utility functions** that live inside a class for namespace reasons, with no connection to instance or class state
- Some **attributes** need to be computed on access, validated on assignment, or made read-only — without changing the call syntax

`@classmethod`, `@staticmethod`, and `@property` address these three cases respectively.

---

## Part I — `@staticmethod`

### What It Does

A static method is a **plain function** that happens to live in a class's namespace. Python does **not** pass the instance (`self`) or the class (`cls`) automatically. It receives exactly the arguments you give it — nothing more.

```python
class MathUtils:
    @staticmethod
    def clamp(value, lo, hi):
        return max(lo, min(hi, value))

# Call on the class — no instance needed
print(MathUtils.clamp(15, 0, 10))   # 10

# Call on an instance — works, but instance is NOT passed
utils = MathUtils()
print(utils.clamp(-3, 0, 10))       # 0
```

The function `clamp` has no relationship to `MathUtils` state. It is placed inside the class purely for **organisational cohesion** — it belongs conceptually to `MathUtils`, so it lives there.

---

### When to Use It

Use `@staticmethod` when:

- The function does not read or write any instance or class state
- It is logically related to the class but does not depend on it
- You want to signal clearly to the reader: _this function has no side effects on the object_

```python
class NeuralNetwork:
    def __init__(self, layers):
        self.layers = layers

    def forward(self, x):
        for layer in self.layers:
            x = layer(x)
        return x

    @staticmethod
    def relu(x):
        return max(0.0, x)

    @staticmethod
    def sigmoid(x):
        import math
        return 1 / (1 + math.exp(-x))
```

`relu` and `sigmoid` are pure mathematical functions. They touch no instance state. `@staticmethod` communicates this contract explicitly.

---

### Under the Hood: The Descriptor Protocol

Every function in Python is a **descriptor** — it implements `__get__`. When you access `instance.method`, Python calls `function.__get__(instance, type)`, which returns a **bound method** with `self` pre-filled.

`@staticmethod` wraps the function in a `staticmethod` object whose `__get__` returns the raw function unchanged, with no binding at all:

```python
class Foo:
    @staticmethod
    def bar():
        pass

print(type(Foo.__dict__['bar']))   # <class 'staticmethod'>
print(type(Foo.bar))               # <class 'function'>  ← unwrapped, not bound
```

## Part II — `@classmethod`

### What It Does

A class method receives the **class itself** as its first argument, by convention named `cls`. It does **not** receive the instance.

```python
class Animal:
    kingdom = "Animalia"

    def __init__(self, name, species):
        self.name    = name
        self.species = species

    @classmethod
    def describe_kingdom(cls):
        print(f"All animals belong to kingdom: {cls.kingdom}")

Animal.describe_kingdom()   # All animals belong to kingdom: Animalia
```

`cls` is the actual class object — not a string, not a proxy. You can call `cls(...)` to create instances, access `cls.attribute` to read class state, and pass `cls` to other functions.

---

### Primary Use Case: Alternative Constructors

This is the dominant use of `@classmethod` in real code. Python only allows one `__init__`, but you often need multiple ways to construct an object from different input formats.

```python
class Dataset:
    def __init__(self, data, labels):
        self.data   = data
        self.labels = labels
        self.size   = len(data)

    @classmethod
    def from_csv(cls, filepath):
        import csv
        data, labels = [], []
        with open(filepath) as f:
            for row in csv.reader(f):
                *features, label = row
                data.append([float(x) for x in features])
                labels.append(int(label))
        return cls(data, labels)       # calls Dataset.__init__

    @classmethod
    def from_numpy(cls, X, y):
        return cls(X.tolist(), y.tolist())

    @classmethod
    def empty(cls):
        return cls([], [])

# Three ways to construct — all go through __init__
ds1 = Dataset.from_csv("train.csv")
ds2 = Dataset.from_numpy(X_train, y_train)
ds3 = Dataset.empty()
```

The key line is `return cls(data, labels)`. It uses `cls` rather than `Dataset` directly. This is critical for **inheritance** — if a subclass inherits `from_csv`, `cls` will be the subclass, not `Dataset`, so the returned object will be of the correct type.

```python
class LabelledDataset(Dataset):
    def __init__(self, data, labels, label_names=None):
        super().__init__(data, labels)
        self.label_names = label_names or []

# from_csv inherited from Dataset — but cls is LabelledDataset
ds = LabelledDataset.from_csv("train.csv")
print(type(ds))   # <class '__main__.LabelledDataset'>  ← correct type
```

If `from_csv` had hardcoded `return Dataset(data, labels)`, subclasses would receive a `Dataset` instance instead of a `LabelledDataset` — a subtle and serious bug.

---

### Secondary Use Case: Class-Level State

```python
class Config:
    _instances = {}

    @classmethod
    def register(cls, name, value):
        cls._instances[name] = value

    @classmethod
    def get(cls, name):
        return cls._instances.get(name)

Config.register("learning_rate", 0.001)
Config.register("batch_size", 32)

print(Config.get("learning_rate"))   # 0.001
```

---

### Under the Hood

`@classmethod` wraps the function in a `classmethod` descriptor. Its `__get__` returns a bound method with `cls` (the class, not the instance) pre-filled:

```python
print(type(Animal.__dict__['describe_kingdom']))  # <class 'classmethod'>
print(type(Animal.describe_kingdom))              # <class 'method'>  ← bound to Animal
```

When called on an instance `animal.describe_kingdom()`, Python still passes the **class** as `cls`, not the instance. The instance is discarded.

## Part III — `@property`

### What It Does

`@property` turns a **method into a managed attribute**. From the caller's side, it looks like a plain attribute access. Under the hood, it calls your method.

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def area(self):
        import math
        return math.pi * self.radius ** 2

c = Circle(5)
print(c.area)    # 78.539...  ← accessed like an attribute, NOT c.area()
```

No parentheses. No `get_area()`. The caller writes `c.area` and gets the computed value.

---

### The Full Interface: getter, setter, deleter

`@property` creates a **descriptor object** with three slots: `fget`, `fset`, `fdel`. You fill them using the decorator syntax:

```python
class Temperature:
    def __init__(self, celsius=0.0):
        self._celsius = celsius    # private storage, single underscore by convention

    @property
    def celsius(self):             # getter
        return self._celsius

    @celsius.setter
    def celsius(self, value):      # setter
        if value < -273.15:
            raise ValueError(f"Temperature {value}°C is below absolute zero.")
        self._celsius = value

    @celsius.deleter
    def celsius(self):             # deleter
        del self._celsius

    @property
    def fahrenheit(self):          # computed, read-only (no setter defined)
        return self._celsius * 9/5 + 32

t = Temperature(25)
print(t.celsius)       # 25.0   ← calls getter
print(t.fahrenheit)    # 77.0   ← computed property, read-only

t.celsius = 100        # calls setter — validated
print(t.fahrenheit)    # 212.0

t.celsius = -300       # ValueError: Temperature -300°C is below absolute zero.

del t.celsius          # calls deleter
```

**The naming convention:** store the actual value in `self._celsius` (private by convention). The property `celsius` wraps it. The underscore signals "don't access this directly."

---

### Why Not Just Use `get_x()` / `set_x()` Methods?

The property approach is superior for three reasons:

**1. Uniform access principle.** You can start with a plain attribute and later add validation or computation _without changing the public interface_. All callers that wrote `obj.celsius` continue to work.

```python
# Version 1 — simple attribute, no validation
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius    # plain attribute

# Version 2 — need validation? Add @property with same name
# All callers are unaffected. No interface change.
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius    # now calls the setter

    @property
    def celsius(self): ...

    @celsius.setter
    def celsius(self, value): ...   # validation added here
```

**2. Pythonic API.** `t.celsius = 100` reads like a natural assignment. `t.set_celsius(100)` reads like boilerplate from Java.

**3. Read-only attributes.** Define a getter with no setter — assignment raises `AttributeError` automatically.

```python
class Model:
    def __init__(self, weights):
        self._weights = weights
        self._num_params = sum(w.numel() for w in weights)

    @property
    def num_params(self):
        return self._num_params          # read-only

model = Model(weights)
print(model.num_params)    # works
model.num_params = 0       # AttributeError: can't set attribute
```

### `@property` with Caching

For expensive computed properties, combine with manual caching:

```python
class DocumentCorpus:
    def __init__(self, texts):
        self.texts = texts
        self._vocab = None              # sentinel: not yet computed

    @property
    def vocabulary(self):
        if self._vocab is None:
            words = set()
            for text in self.texts:
                words.update(text.lower().split())
            self._vocab = frozenset(words)   # compute once, cache forever
        return self._vocab

corpus = DocumentCorpus(["hello world", "hello python"])
print(corpus.vocabulary)   # computed on first access
print(corpus.vocabulary)   # returned from cache — O(1)
```

Python 3.8+ provides `functools.cached_property` for a cleaner version of this pattern — it computes on first access and stores the result directly in the instance's `__dict__`, bypassing the descriptor on subsequent accesses:

```python
from functools import cached_property

class DocumentCorpus:
    def __init__(self, texts):
        self.texts = texts

    @cached_property
    def vocabulary(self):
        words = set()
        for text in self.texts:
            words.update(text.lower().split())
        return frozenset(words)
```

### Under the Hood: The Descriptor Protocol in Full

`property` is a **data descriptor** — it implements both `__get__` and `__set__`. This is important because data descriptors take **priority over instance `__dict__`**:

```python
# property is roughly equivalent to this class:
class property:
    def __init__(self, fget=None, fset=None, fdel=None):
        self.fget = fget
        self.fset = fset
        self.fdel = fdel

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self          # accessed on class, not instance → return descriptor itself
        if self.fget is None:
            raise AttributeError("unreadable attribute")
        return self.fget(obj)

    def __set__(self, obj, value):
        if self.fset is None:
            raise AttributeError("can't set attribute")
        self.fset(obj, value)

    def __delete__(self, obj):
        if self.fdel is None:
            raise AttributeError("can't delete attribute")
        self.fdel(obj)

    def setter(self, fset):
        return property(self.fget, fset, self.fdel)

    def deleter(self, fdel):
        return property(self.fget, self.fset, fdel)
```

When you write `@celsius.setter`, you are calling `celsius.setter(new_function)`, which returns a **new property object** with `fset` filled in. That new property object replaces the old one under the name `celsius` in the class namespace.

## Comparison Table

||`@staticmethod`|`@classmethod`|`@property`|
|---|---|---|---|
|First arg|_(none)_|`cls` — the class|_(none — attribute access)_|
|Access instance state?|No|No|Yes (`self` via `fget`)|
|Access class state?|No|Yes|Yes|
|Primary use|Utility functions|Alternative constructors, class-state ops|Computed/validated attributes|
|Call syntax|`Cls.method()`|`Cls.method()`|`obj.attr` (no parentheses)|
|Inheritance-safe?|Yes (no binding)|**Yes — `cls` is the actual subclass**|Yes|
|Returns new instance?|Rarely|Often|No — returns attribute value|

## Combined Example: A Complete ML Model Config Class

```python
import json
import math
from functools import cached_property

class ModelConfig:
    _registry = {}   # class-level registry of all named configs

    def __init__(self, name, hidden_dim, num_layers, dropout=0.1):
        self.name       = name
        self.hidden_dim = hidden_dim
        self.num_layers = num_layers
        self.dropout    = dropout    # calls setter — validated

    # ── @property ──────────────────────────────────────────────────────
    @property
    def dropout(self):
        return self._dropout

    @dropout.setter
    def dropout(self, value):
        if not 0.0 <= value < 1.0:
            raise ValueError(f"dropout must be in [0, 1), got {value}")
        self._dropout = value

    @cached_property
    def total_params_estimate(self):
        """Rough O(1) estimate; expensive to compute, cached after first access."""
        d = self.hidden_dim
        L = self.num_layers
        return L * (4 * d * d)   # dominant term: attention projections

    # ── @staticmethod ──────────────────────────────────────────────────
    @staticmethod
    def validate_power_of_two(n):
        """Hidden dim should be a power of two for GPU efficiency."""
        return n > 0 and (n & (n - 1)) == 0

    # ── @classmethod ───────────────────────────────────────────────────
    @classmethod
    def from_json(cls, filepath):
        with open(filepath) as f:
            data = json.load(f)
        return cls(**data)          # cls, not ModelConfig → subclass-safe

    @classmethod
    def register(cls, config):
        cls._registry[config.name] = config

    @classmethod
    def get_registered(cls, name):
        return cls._registry.get(name)

# Usage
cfg = ModelConfig("bert-base", hidden_dim=768, num_layers=12, dropout=0.1)
ModelConfig.register(cfg)

print(ModelConfig.validate_power_of_two(768))        # False (768 = 3 × 256)
print(ModelConfig.validate_power_of_two(1024))       # True
print(cfg.total_params_estimate)                     # 28311552  (computed once)
print(cfg.total_params_estimate)                     # same value, from cache
print(ModelConfig.get_registered("bert-base").name)  # "bert-base"
```

## Summary

```
@staticmethod
    Plain function in a class namespace.
    No automatic first argument.
    Use for: pure utility functions with no instance or class state.
    Signal to reader: this function has no side effects on the object.

@classmethod
    First argument is cls — the class itself, not the instance.
    Use for: alternative constructors, class-level state operations.
    Key rule: use cls(...) not ClassName(...) for subclass safety.

@property
    Turns a method into a managed attribute.
    Caller writes obj.attr — no parentheses.
    Getter: @property def attr(self)
    Setter: @attr.setter def attr(self, value)
    Deleter: @attr.deleter def attr(self)
    No setter → read-only attribute (AttributeError on assignment).
    Use for: computed attributes, validation on set, uniform access principle.

All three are implemented via the descriptor protocol (__get__, __set__, __delete__).
Understanding descriptors is the key to understanding all three simultaneously.
```
