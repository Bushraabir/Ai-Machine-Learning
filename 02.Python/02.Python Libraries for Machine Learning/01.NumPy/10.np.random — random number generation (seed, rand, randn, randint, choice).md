# 10. `np.random` — Random Number Generation

> _Every neural network you will ever train begins with random numbers. Weight initialization, data shuffling, dropout masks, minibatch selection, data augmentation — all of it flows from a random number generator. Understanding how NumPy's random module works at a mechanical level is not optional. It is the foundation of reproducible ML._

---

## The Big Picture — What Is a Random Number Generator?

Computers cannot generate truly random numbers. What they generate are **pseudorandom** numbers — a deterministic sequence that _looks_ random, produced by a mathematical formula called a **pseudorandom number generator (PRNG)**.

```
seed (integer)  →  internal state  →  number₁ → number₂ → number₃ → ...
                        ↑
                 deterministic formula
                 (Mersenne Twister in NumPy's legacy API)
                 (PCG64 in the modern Generator API)
```

The same seed always produces the same sequence. This is the entire basis of **reproducibility** in ML research — you set the seed at the top of your script, and every random operation (weight init, data split, augmentation) is determined. Another person with your code and your seed gets identical results.

---

## Two APIs — Legacy vs Modern

NumPy has **two interfaces**. You will see both in the wild.

||Legacy API|Modern Generator API|
|---|---|---|
|How to use|`np.random.randn(...)`|`rng = np.random.default_rng(seed)` then `rng.standard_normal(...)`|
|Global state?|✅ Yes — one global RNG|❌ No — each `rng` is independent|
|Reproducibility|Fragile|Robust|
|PRNG algorithm|Mersenne Twister (MT19937)|PCG64 (better statistical properties)|
|Introduced|NumPy 1.0|NumPy 1.17 (2019)|

**Which to use?**

- **Learn both** — legacy is everywhere in existing code (papers, tutorials, Stack Overflow)
- **Write new code** with the modern Generator API (`default_rng`)
- This note covers both. The modern API is covered in [[67.The Generator API]]

For now, the legacy API is sufficient and what you'll encounter most.

## `np.random.seed()` — Reproducibility

```python
import numpy as np

# Without seed — different every run
print(np.random.randn(3))   # [ 0.374  -1.234   0.891]  (changes each run)
print(np.random.randn(3))   # [-0.512   0.023  -1.102]  (different again)

# With seed — same every run
np.random.seed(42)
print(np.random.randn(3))   # [ 0.497  -0.138   0.648]  (always this)

np.random.seed(42)           # reset to same seed
print(np.random.randn(3))   # [ 0.497  -0.138   0.648]  (identical)

# Seed 0 vs seed 1 — completely different sequences
np.random.seed(0)
print(np.random.randn(3))   # [ 1.764   0.400   0.978]

np.random.seed(1)
print(np.random.randn(3))   # [ 1.624   0.611  -0.528]
```

**The seed is consumed as you draw numbers.** It does not "re-apply" automatically. Once you've drawn 100 numbers from seed 42, the 101st draw is deterministic but not the same as the first.

```python
np.random.seed(42)
a = np.random.randn(5)   # draws 5 numbers — state advances
b = np.random.randn(5)   # draws 5 more — state advances again
# a and b are different — same seed, sequential draws

np.random.seed(42)
c = np.random.randn(10)  # draws 10 numbers
# c[:5] == a  and  c[5:] == b   (same sequence, just drawn together)
print(np.allclose(c[:5], a))   # True
print(np.allclose(c[5:], b))   # True
```

This reveals something important: **order of operations matters**. If you add a random call anywhere in your code before the part you care about, the sequence shifts. This is why global seed state is fragile.

### Standard Seed Practice in ML

```python
# Top of every experiment script — set ALL relevant seeds
SEED = 42

np.random.seed(SEED)

# Also set Python's random module if used
import random
random.seed(SEED)

# Also set framework seeds
import torch
torch.manual_seed(SEED)
torch.cuda.manual_seed_all(SEED)

# Also set environment variable for full determinism
import os
os.environ['PYTHONHASHSEED'] = str(SEED)
```

## `np.random.rand()` — Uniform Distribution [0, 1)

Generates numbers drawn from a **uniform distribution** between 0 (inclusive) and 1 (exclusive).

```
Probability density:

P(x)
  │
1 ├────────────────────
  │                    │
  │                    │
0 └────────────────────── x
  0                    1

Every value between 0 and 1 is equally likely.
```

```python
np.random.seed(42)

# Single number
print(np.random.rand())           # 0.3745401188473625

# 1D array — pass size as positional args (NOT a tuple)
print(np.random.rand(5))
# [0.950  0.732  0.599  0.156  0.058]

# 2D array — pass rows then cols
print(np.random.rand(3, 4))
# [[0.866  0.708  0.021  0.970]
#  [0.832  0.212  0.182  0.183]
#  [0.304  0.524  0.432  0.291]]

print(np.random.rand(3, 4).dtype)   # float64
```

**Syntax quirk:** `rand` takes dimensions as **separate positional arguments**, NOT as a tuple.

```python
np.random.rand(3, 4)       # correct — 3×4 array
np.random.rand((3, 4))     # WRONG — TypeError
```

This is inconsistent with the rest of NumPy (which uses tuples for shape). It's a historical accident. The modern API fixes this.

### Scaling Uniform Output to Any Range [a, b)

```python
a, b = -1, 1
# Uniform in [a, b)
x = a + (b - a) * np.random.rand(1000)
print(x.min(), x.max())   # approximately -1 and 1
```

## `np.random.randn()` — Standard Normal Distribution

Generates numbers from the **standard normal distribution**: mean=0, standard deviation=1.

$$X \sim \mathcal{N}(0, 1)$$

```
Probability density (bell curve):

P(x)
  │         ╭──╮
  │        ╭╯  ╰╮
  │      ╭─╯    ╰─╮
  │   ╭──╯         ╰──╮
  └───────────────────────── x
     -3  -2  -1   0   1   2   3

68% of values fall within [-1, 1]
95% of values fall within [-2, 2]
99.7% of values fall within [-3, 3]
```

```python
np.random.seed(42)

# Single number
print(np.random.randn())           # 0.4967141530112327

# 1D array
print(np.random.randn(5))
# [ 0.497  -0.138   0.648   1.524   1.458]

# 2D array — same positional-arg syntax as rand
print(np.random.randn(3, 4))
# [[ 0.046  -0.188   1.533   1.469]
#  [ 0.155   0.378  -0.888  -1.981]
#  [-0.347   0.156   1.231   1.202]]
```

### Scaling to Any Normal Distribution N(μ, σ²)

$$X \sim \mathcal{N}(\mu, \sigma^2) \implies X = \mu + \sigma \cdot Z \quad \text{where } Z \sim \mathcal{N}(0, 1)$$

```python
mu    = 5.0
sigma = 2.0

# Shift and scale standard normal
samples = mu + sigma * np.random.randn(10000)
print(samples.mean())    # ≈ 5.0
print(samples.std())     # ≈ 2.0
```

### `rand` vs `randn` — The Critical Distinction

```python
# rand  — UNIFORM distribution [0, 1)
x = np.random.rand(5)
print(x)    # [0.37  0.95  0.73  0.60  0.16]  — all between 0 and 1

# randn — NORMAL distribution, mean=0, std=1
x = np.random.randn(5)
print(x)    # [ 0.50  -0.14   0.65   1.52   1.46]  — can be negative, >1
```

The single letter difference (`rand` vs `randn`) encodes a completely different distribution. The `n` stands for **normal**. Confusing them is a frequent source of bugs.

## `np.random.randint()` — Random Integers

Generates **integer** samples from a discrete uniform distribution.

```python
np.random.seed(42)

# Single integer in [0, 10)
print(np.random.randint(10))          # 6

# Single integer in [low, high)
print(np.random.randint(2, 8))        # 7

# Array of integers
print(np.random.randint(0, 10, size=5))
# [6 1 4 4 8]

# 2D array
print(np.random.randint(0, 100, size=(3, 4)))
# [[38 13 73 10]
#  [76  6 80 65]
#  [ 2 77 28 53]]

# dtype control
print(np.random.randint(0, 2, size=5, dtype=np.int8))
# [0 1 1 0 1]  — binary values, small dtype
```

**Signature:**

```python
np.random.randint(low, high=None, size=None, dtype=int)
```

- If `high` is `None`, generates from `[0, low)`
- `high` is **exclusive** (like `range`)
- `size` accepts a tuple for ND arrays (unlike `rand`/`randn`)

```python
# Common gotcha: single-argument form
np.random.randint(5)       # draws from [0, 5) — high=None case
np.random.randint(5, 10)   # draws from [5, 10)
```

## `np.random.choice()` — Sampling From an Array

Randomly selects elements from a given array. The most flexible of the sampling functions.

```python
np.random.seed(42)

arr = np.array([10, 20, 30, 40, 50])

# Single sample
print(np.random.choice(arr))           # 30

# Multiple samples WITH replacement (default)
print(np.random.choice(arr, size=3))
# [30 40 20]  — elements can repeat

# Multiple samples WITHOUT replacement
print(np.random.choice(arr, size=3, replace=False))
# [10 30 50]  — no repeats, like a draw from a deck

# Weighted sampling — non-uniform probabilities
probs = [0.1, 0.1, 0.6, 0.1, 0.1]   # 30 is 6x more likely
print(np.random.choice(arr, size=10, p=probs))
# [30 30 30 50 30 30 20 30 30 40]  — 30 dominates
```

**From integer n — shorthand for `np.arange(n)`:**

```python
# choice(n) is equivalent to choice(np.arange(n))
print(np.random.choice(5))             # random int from [0, 5)
print(np.random.choice(5, size=3))     # [4 0 3]
```

**Signature:**

```python
np.random.choice(a, size=None, replace=True, p=None)
```

- `a` — 1D array or integer
- `size` — output shape (int or tuple)
- `replace` — sample with (True) or without (False) replacement
- `p` — probabilities for each element (must sum to 1)

## Connection to AI / ML / Deep Learning

### 1. Weight Initialization — The Most Critical Use

The distribution you use to initialize weights determines whether your network trains at all.

```python
# Xavier / Glorot initialization — used for tanh, sigmoid
# W ~ N(0, 1/fan_in)  or  W ~ U(-√(6/(fan_in+fan_out)), +√(6/(fan_in+fan_out)))
fan_in  = 784
fan_out = 256

# Xavier Normal
W_xavier = np.random.randn(fan_in, fan_out) * np.sqrt(1.0 / fan_in)

# He / Kaiming initialization — used for ReLU
# W ~ N(0, 2/fan_in)
W_he = np.random.randn(fan_in, fan_out) * np.sqrt(2.0 / fan_in)

# Uniform Xavier
limit = np.sqrt(6.0 / (fan_in + fan_out))
W_uniform = np.random.uniform(-limit, limit, size=(fan_in, fan_out))

print(W_he.std())      # ≈ sqrt(2/784) ≈ 0.0505
```

**Why not initialize to zeros?** If all weights are zero, all neurons compute the same value, all gradients are equal, and the network never breaks symmetry — it can never learn different features. The randomness is not for stochasticity; it is for **symmetry breaking**.

**Why not initialize with large values?** Large weights → large activations → saturated sigmoids/tanh → near-zero gradients → vanishing gradient problem. Xavier/He scale variance to keep activations stable across layers.

### 3. Dropout Masks

```python
def dropout(x, p_drop=0.5, training=True):
    """
    x      — input activations, shape (batch, features)
    p_drop — probability of dropping a neuron
    """
    if not training:
        return x   # no dropout at inference
    
    # Bernoulli mask: 1 = keep, 0 = drop
    mask = (np.random.rand(*x.shape) > p_drop).astype(np.float32)
    
    # Inverted dropout: scale up kept neurons so expected value unchanged
    return x * mask / (1.0 - p_drop)

# Example
x = np.ones((4, 8))
out = dropout(x, p_drop=0.5)
print(out)
# Approximately half the values are 0, rest are 2.0 (scaled by 1/0.5)
```

`np.random.rand` generates the uniform values. The `> p_drop` comparison creates the binary mask. This is exactly how dropout is implemented in PyTorch's C++ backend.

### 4. Data Augmentation

```python
def augment_image(image):
    """Random augmentation for training."""
    # Random horizontal flip
    if np.random.rand() < 0.5:
        image = np.fliplr(image)
    
    # Random brightness shift
    brightness = np.random.uniform(-0.2, 0.2)
    image = np.clip(image + brightness, 0, 1)
    
    # Random crop — select a random top-left corner
    max_offset = 4
    dy = np.random.randint(0, max_offset)
    dx = np.random.randint(0, max_offset)
    image = image[dy:dy+28, dx:dx+28]   # for 32×32 → 28×28
    
    return image
```

### 6. Monte Carlo Estimation

```python
# Estimate π using Monte Carlo — classic use of uniform random numbers
n_samples = 10_000_000

np.random.seed(42)
x = np.random.rand(n_samples)   # uniform [0,1)
y = np.random.rand(n_samples)   # uniform [0,1)

inside_circle = (x**2 + y**2) < 1.0
pi_estimate   = 4 * inside_circle.mean()

print(f"π estimate: {pi_estimate:.5f}")   # ≈ 3.14159
```

Monte Carlo methods underlie reinforcement learning (policy gradient estimates), Bayesian inference (MCMC), and approximate inference in generative models.

### 7. Noise Injection — Regularization

```python
def add_gaussian_noise(x, sigma=0.01):
    """Add Gaussian noise during training — acts as regularizer."""
    noise = np.random.randn(*x.shape) * sigma
    return x + noise

# In GANs, the latent vector z is pure random noise
def sample_latent(batch_size, latent_dim):
    return np.random.randn(batch_size, latent_dim)

z = sample_latent(32, 100)   # 32 samples from 100-dim standard normal
print(z.shape)               # (32, 100)
```

## `np.random.shuffle()` vs `np.random.permutation()`

These two are constantly confused.

```python
arr = np.array([1, 2, 3, 4, 5])

# shuffle — in-place, returns None
np.random.shuffle(arr)
print(arr)        # [3 1 4 5 2]  — original modified
# return value:
result = np.random.shuffle(arr)
print(result)     # None  ← common mistake: result = shuffle(arr) gives None

# permutation — returns NEW array, original unchanged
arr = np.array([1, 2, 3, 4, 5])
shuffled = np.random.permutation(arr)
print(arr)        # [1 2 3 4 5]  — unchanged
print(shuffled)   # [3 5 1 2 4]  — new array

# permutation(n) — generates shuffled arange(n)
print(np.random.permutation(5))   # [2 0 4 1 3]
```

||`shuffle`|`permutation`|
|---|---|---|
|Modifies input|✅ In-place|❌ Returns new array|
|Return value|`None`|New shuffled array|
|Works on int n|❌|✅ (treats as `arange(n)`)|
|Use when|You want to save memory|You want to keep original|

## Other Important Distributions

```python
# Uniform between any [low, high)
x = np.random.uniform(low=-5, high=5, size=(3, 3))

# Normal with custom mean and std
x = np.random.normal(loc=10, scale=2.5, size=1000)  # N(10, 2.5²)

# Binomial — n trials, p probability of success
# e.g. simulating coin flips
x = np.random.binomial(n=1, p=0.5, size=100)   # 100 coin flips

# Poisson — arrival counts, rate λ
x = np.random.poisson(lam=3.5, size=1000)

# Exponential — time between events
x = np.random.exponential(scale=2.0, size=1000)

# Dirichlet — distribution over probability simplices
# Used in topic models, Bayesian ML, attention analysis
x = np.random.dirichlet(alpha=[0.5, 0.5, 0.5], size=10)
print(x.sum(axis=1))   # [1. 1. 1. ...] — each row sums to 1
```

## Common Mistakes

```python
# Mistake 1: rand vs randn — wrong distribution for weight init
W = np.random.rand(784, 256)    # WRONG — uniform [0,1), no negatives
W = np.random.randn(784, 256)   # correct — normal, mean=0

# Mistake 2: rand takes positional args, NOT a tuple
W = np.random.rand((784, 256))  # TypeError
W = np.random.rand(784, 256)    # correct

# randint and choice take size= keyword for shape
x = np.random.randint(0, 10, size=(3, 4))  # correct
x = np.random.choice(arr, size=(3, 4))     # correct

# Mistake 3: shuffle returns None
shuffled = np.random.shuffle(arr)   # shuffled is None!
np.random.shuffle(arr)              # correct — arr is now shuffled
shuffled = np.random.permutation(arr)  # if you need the return value

# Mistake 4: seed does not persist across sessions automatically
# You must call np.random.seed() at the START of each script/notebook run

# Mistake 5: randint high is exclusive
dice = np.random.randint(1, 6)    # WRONG — gives [1,5], misses 6
dice = np.random.randint(1, 7)    # correct — gives [1,6]

# Mistake 6: replace=False with size > population
arr = np.array([1, 2, 3])
np.random.choice(arr, size=5, replace=False)  # ValueError — can't draw 5 from 3 without replacement

# Mistake 7: forgetting to set ALL seeds in a DL framework
np.random.seed(42)           # sets NumPy's seed
# torch.manual_seed(42)      # ALSO needed for PyTorch operations
# Without this, PyTorch will still be non-deterministic
```
