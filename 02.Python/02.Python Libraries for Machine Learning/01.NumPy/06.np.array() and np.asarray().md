# 06. np.array() and np.asarray()

> _np.array() is the constructor. np.asarray() is the contract. One always builds something new. The other says: "give me an ndarray — copy only if you absolutely must."_

---

## Why These Two Functions Exist

Every NumPy workflow starts with turning _something_ — a Python list, a tuple, another array, a nested structure — into an ndarray. There are two primary ways to do that, and they differ on exactly one question:

**Should we always allocate new memory, or reuse existing memory when possible?**

```
np.array()   → always copies (by default). Safe. Predictable. Slightly wasteful.
np.asarray() → copies only when necessary. Efficient. Requires you to understand views.
```

This distinction maps directly back to [[05.Views vs copies — when does NumPy share memory]].

---

## `np.array()` — The Constructor

### Full Signature

```python
np.array(object, dtype=None, copy=True, order='K', subok=False, ndmin=0)
```

|Parameter|What it does|
|---|---|
|`object`|The input — list, tuple, ndarray, nested structure, scalar|
|`dtype`|Force a specific dtype. If `None`, NumPy infers it|
|`copy`|If `True` (default), always copy. If `False`, copy only if needed|
|`order`|Memory layout: `'C'` (row-major), `'F'` (col-major), `'K'` (keep input order)|
|`subok`|If `True`, pass through subclasses (e.g. `np.matrix`). Default `False`|
|`ndmin`|Minimum number of dimensions. Prepends size-1 axes if needed|

### Basic Usage

```python
import numpy as np

# From a Python list
a = np.array([1, 2, 3, 4, 5])
print(a)        # [1 2 3 4 5]
print(a.dtype)  # int64

# From a nested list → 2D array
b = np.array([[1, 2, 3],
              [4, 5, 6]])
print(b.shape)  # (2, 3)

# From a tuple
c = np.array((10, 20, 30))
print(c)        # [10 20 30]

# From a range object
d = np.array(range(5))
print(d)        # [0 1 2 3 4]

# Scalar → 0D array
s = np.array(42)
print(s.shape)  # ()
print(s.ndim)   # 0
```

### dtype Inference and Coercion

```python
# All integers → int64
np.array([1, 2, 3]).dtype           # int64

# Any float present → float64
np.array([1, 2.0, 3]).dtype         # float64

# Any complex → complex128
np.array([1, 2, 3+0j]).dtype        # complex128

# Explicit dtype — coerces all elements
np.array([1, 2, 3], dtype=np.float32).dtype   # float32

# Lossy coercion — silent truncation
np.array([1.9, 2.7, 3.5], dtype=np.int32)
# array([1, 2, 3])  ← truncated, not rounded — no warning
```

The coercion hierarchy:

```
bool → int → float → complex
         ↑
         any mixed input promotes to the most general type
```

### The `copy` Parameter

```python
a = np.array([1, 2, 3])

# Default: copy=True — always allocates new buffer
b = np.array(a)
print(np.shares_memory(a, b))   # False — independent copy

# copy=False — reuse buffer if possible
c = np.array(a, copy=False)
print(np.shares_memory(a, c))   # True  — same buffer (no copy needed)

# copy=False but dtype differs → copy forced anyway
d = np.array(a, copy=False, dtype=np.float64)
print(np.shares_memory(a, d))   # False — had to copy to change dtype
```

### The `ndmin` Parameter

Forces the result to have at least `ndmin` dimensions by prepending size-1 axes:

```python
a = np.array([1, 2, 3], ndmin=1)
print(a.shape)   # (3,)  — already 1D, no change

b = np.array([1, 2, 3], ndmin=2)
print(b.shape)   # (1, 3)  — 1 row, 3 columns

c = np.array([1, 2, 3], ndmin=3)
print(c.shape)   # (1, 1, 3)

# Common use: ensure batch dimension exists
sample = np.array([0.1, 0.5, 0.9])           # shape (3,)
batch  = np.array(sample, ndmin=2)            # shape (1, 3) — single-sample batch
```

### The `order` Parameter

```python
a = np.array([[1, 2, 3],
              [4, 5, 6]], order='C')   # row-major (default)
print(a.strides)   # (24, 8)

b = np.array([[1, 2, 3],
              [4, 5, 6]], order='F')   # column-major
print(b.strides)   # (8, 24)

# order='K' — keep the memory order of the input
c_input = np.asfortranarray(np.zeros((3, 4)))
d = np.array(c_input, order='K')
print(d.flags['F_CONTIGUOUS'])   # True — preserved F-order
```

## `np.asarray()` — The Converter

### Full Signature

```python
np.asarray(a, dtype=None, order=None)
```

Simpler than `np.array()` — no `copy`, no `subok`, no `ndmin`. The contract is:

> _Return an ndarray. Copy only if the input is not already an ndarray, or if a dtype conversion is required._

```python
a = np.array([1, 2, 3])

# Input is already a compatible ndarray → no copy, returns view
b = np.asarray(a)
print(np.shares_memory(a, b))   # True

# Input needs dtype conversion → copy
c = np.asarray(a, dtype=np.float64)
print(np.shares_memory(a, c))   # False

# Input is a Python list → always copies (list has no buffer to share)
d = np.asarray([1, 2, 3])
# (fresh ndarray — no existing buffer to share from a list)
```

### When `np.asarray()` Copies vs When It Does Not

```
Input type                 dtype matches?   Result
────────────────────────────────────────────────────
ndarray                    yes              VIEW  (no copy)
ndarray                    no               COPY  (dtype conversion)
Python list / tuple        any              COPY  (no existing buffer)
Python scalar              any              COPY  (new 0-D array)
np.matrix                  yes              COPY  (subclass → base class)
memoryview / buffer        yes              VIEW  (shared buffer)
```

## Side-by-Side Comparison

```python
a = np.array([1.0, 2.0, 3.0], dtype=np.float64)

# np.array() — always copies by default
b = np.array(a)
print(np.shares_memory(a, b))      # False ← copy

# np.asarray() — no copy if compatible
c = np.asarray(a)
print(np.shares_memory(a, c))      # True  ← view

# Both force a copy when dtype differs
d = np.array(a, dtype=np.float32)
e = np.asarray(a, dtype=np.float32)
print(np.shares_memory(a, d))      # False
print(np.shares_memory(a, e))      # False
```

**Rule of thumb:**

- Use `np.array()` when you want a guaranteed independent copy
- Use `np.asarray()` when you want to normalise input to ndarray with zero cost if already ndarray

## Handling Nested Structures

### Uniform nesting → N-D array

```python
# 2D
np.array([[1, 2], [3, 4]])           # shape (2, 2)

# 3D
np.array([[[1, 2], [3, 4]],
          [[5, 6], [7, 8]]])         # shape (2, 2, 2)

# NumPy infers shape from nesting depth and consistency
```

### Non-uniform nesting → object array (the trap)

```python
# Rows of different lengths — NumPy cannot make a rectangular array
a = np.array([[1, 2, 3], [4, 5]])
print(a.dtype)   # object  ← not float64 or int64!
print(a.shape)   # (2,)    ← 1D array of Python lists

# This is almost never what you want
# Fix: pad to uniform length before converting
```

```python
# Detecting the trap
a = np.array([[1, 2, 3], [4, 5]])
if a.dtype == object:
    raise ValueError("Ragged input — pad sequences to uniform length first")
```

In ML, ragged sequences (variable-length text, variable-length audio) must be **padded** to a fixed length before batching into an ndarray. This is what the `padding` argument in tokenisers does.

## Copying Behaviour — The Full Picture

```python
a = np.array([1, 2, 3], dtype=np.int64)

# These copy:
np.array(a)                          # copy=True by default
np.array(a, dtype=np.float32)        # dtype change forces copy
np.array(a, order='F')               # order change forces copy

# These do NOT copy (when input is already a matching ndarray):
np.array(a, copy=False)              # explicit no-copy request
np.asarray(a)                        # asarray contract
np.asarray(a, dtype=np.int64)        # same dtype — no copy

# These always copy regardless:
np.array([1, 2, 3])                  # from list — no buffer to share
np.asarray([1, 2, 3])                # from list — same
```

## `np.ascontiguousarray()` and `np.asfortranarray()` — Specialised Variants

These are `np.asarray()` with a forced memory layout:

```python
a = np.zeros((3, 4))         # C-order
b = a.T                      # F-order view

# Force C-contiguous — copies if input is not C-contiguous
c = np.ascontiguousarray(b)
print(c.flags['C_CONTIGUOUS'])   # True
print(np.shares_memory(b, c))    # False (b was F-order, had to copy)

# Force F-contiguous — copies if input is not F-contiguous
d = np.asfortranarray(a)
print(d.flags['F_CONTIGUOUS'])   # True
print(np.shares_memory(a, d))    # False
```

Use these when passing arrays to BLAS/LAPACK routines or C extensions that require a specific layout.

## `np.asanyarray()` — The Subclass-Preserving Variant

```python
# np.asarray() always returns base ndarray — strips subclasses
# np.asanyarray() passes subclasses through unchanged

class MyArray(np.ndarray):
    pass

a = np.array([1, 2, 3]).view(MyArray)
print(type(np.asarray(a)))      # <class 'numpy.ndarray'>    ← subclass lost
print(type(np.asanyarray(a)))   # <class '__main__.MyArray'> ← preserved
```

You will see `np.asanyarray()` inside NumPy's own source code and in library code that wants to work with ndarray subclasses (like `np.ma.MaskedArray`).

## Common Patterns in Real Code

### Pattern 1 — Library function that accepts "array-like" input

```python
def my_function(X):
    # Normalise input to ndarray, no copy if already ndarray
    X = np.asarray(X)
    # ... rest of function
    return X.mean(axis=0)

my_function([1, 2, 3])           # list input — converted
my_function(np.array([1, 2, 3])) # ndarray input — zero cost
my_function((1, 2, 3))           # tuple input — converted
```

This is the pattern used inside scikit-learn, SciPy, and every serious numerical library. The first line of almost every function body is `X = np.asarray(X)`.

### Pattern 2 — Ensuring independent copy before mutation

```python
def augment(image):
    img = np.array(image)       # guaranteed copy — safe to mutate
    img = random_flip(img)
    img = random_crop(img)
    return img
```

### Pattern 3 — dtype enforcement at a pipeline boundary

```python
def preprocess(X):
    # Enforce float32 for GPU training — copy if needed
    return np.asarray(X, dtype=np.float32)
```

### Pattern 4 — Checking input without copying

```python
def validate_input(X):
    X = np.asarray(X)          # no copy if already ndarray
    if X.ndim != 2:
        raise ValueError(f"Expected 2D array, got {X.ndim}D")
    if X.dtype.kind not in ('f', 'i'):
        raise TypeError(f"Expected numeric dtype, got {X.dtype}")
    return X
```

## Connection to AI / ML / Deep Learning

### Every scikit-learn estimator starts with `np.asarray()`

Open any scikit-learn source file:

```python
# From sklearn's LinearRegression.fit():
X = np.asarray(X)   # normalise input
y = np.asarray(y)
```

This is intentional: scikit-learn promises to accept "array-like" inputs — lists, DataFrames, other arrays. `np.asarray()` is the normalisation step that makes that promise work at zero cost for NumPy inputs.

### PyTorch's `torch.as_tensor()` is the same idea

```python
import torch

a = np.array([1.0, 2.0, 3.0])

# torch.tensor()    → always copies  (like np.array())
# torch.as_tensor() → no copy if compatible  (like np.asarray())

t1 = torch.tensor(a)           # copy
t2 = torch.as_tensor(a)        # view — shares memory with a

t2[0] = 99
print(a)   # [99.  2.  3.]  ← a was modified through t2
```

The naming convention is intentional and consistent:

```
np.array()      ↔   torch.tensor()       always copy
np.asarray()    ↔   torch.as_tensor()    copy only if needed
```

### The dtype=np.float32 pattern is everywhere in ML

```python
# Loading image data
from PIL import Image
img = Image.open("photo.jpg")
arr = np.asarray(img)                          # uint8, (H, W, 3)
arr_f = np.asarray(img, dtype=np.float32)      # float32 — copy forced
arr_n = arr_f / 255.0                          # normalise to [0, 1]

# The pipeline:
# PIL Image → np.asarray() → uint8 ndarray → /255 → float32 ndarray → tensor
```

### Ragged sequences in NLP

```python
# Tokenised sentences of different lengths
sentences = [[101, 2054, 2003], [101, 1996, 4937, 2003, 2204]]

# This creates an object array — NOT what you want
bad = np.array(sentences)
print(bad.dtype)   # object ← broken

# Correct: pad to uniform length first
max_len = max(len(s) for s in sentences)
padded = [s + [0] * (max_len - len(s)) for s in sentences]
good = np.array(padded, dtype=np.int32)
print(good.shape)   # (2, 5)  ← correct rectangular array
print(good.dtype)   # int32   ← correct
```

This is exactly what `transformers.tokenizer(..., padding=True)` does internally before returning a NumPy or tensor batch.

## Summary

||`np.array()`|`np.asarray()`|
|---|---|---|
|Default behaviour|Always copies|Copies only if needed|
|Input: ndarray, same dtype|Copy|**View**|
|Input: ndarray, diff dtype|Copy|Copy|
|Input: list / tuple|Copy|Copy|
|`copy` parameter|Yes (`copy=True/False`)|No|
|`ndmin` parameter|Yes|No|
|`subok` parameter|Yes|No|
|Typical use|Safe mutation, guaranteed independence|Library input normalisation|
|Equivalent to|`np.asarray(a, copy=True)` (default)|`np.array(a, copy=False)`|

**The one-line decision rule:**

> Writing a function that accepts array-like input from a user? Start with `np.asarray()`.  
> About to mutate an array and want to protect the original? Use `np.array()`.

## Common Mistakes

```python
# Mistake 1: Assuming np.asarray() always makes a copy
a = np.array([1, 2, 3])
b = np.asarray(a)
b[0] = 99
print(a)   # [99  2  3]  ← a was modified! b was a view.

# Mistake 2: Ragged input silently producing object array
data = np.array([[1, 2, 3], [4, 5]])  # rows have different lengths
print(data.dtype)   # object — NOT a numeric array
# This will crash later with a cryptic error about object arrays
# Fix: ensure uniform length before calling np.array()

# Mistake 3: Forgetting that np.array() from a list always copies
a = [1, 2, 3]
b = np.asarray(a)
b[0] = 99
print(a)   # [1, 2, 3]  ← list is unchanged
# np.asarray() from a list still creates a new ndarray
# there is no list buffer to share

# Mistake 4: Using np.array() inside a hot loop
for i in range(10000):
    arr = np.array(existing_ndarray)   # unnecessary copy every iteration!
    process(arr)
# Fix: use np.asarray() if you don't need to mutate
for i in range(10000):
    arr = np.asarray(existing_ndarray)  # zero cost — no copy
    result = read_only_process(arr)

# Mistake 5: dtype coercion truncates silently
a = np.array([1.9, 2.7, 3.5], dtype=np.int32)
print(a)   # [1 2 3]  ← truncated, not rounded — no warning raised
# Fix: round explicitly first if rounding is intended
a = np.array(np.round([1.9, 2.7, 3.5]), dtype=np.int32)
print(a)   # [2 3 4]
```
