# 02. `dtype` — Data Types and Precision

> _Choosing the wrong dtype is like measuring a marathon in millimetres — technically correct, computationally wasteful, and occasionally catastrophically wrong._

---

## What Is a `dtype`?

Every element in an ndarray has the **same type** — that is the price of living in a contiguous memory buffer. The `dtype` object encodes:

- **What kind of number** is stored (integer, float, complex, boolean, …)
- **How many bytes** each element occupies
- **How those bytes are interpreted** (signed vs unsigned, byte order)

```python
import numpy as np

a = np.array([1.0, 2.0, 3.0])
print(a.dtype)        # float64
print(a.itemsize)     # 8  bytes per element
print(a.nbytes)       # 24 bytes total
```

The dtype is not decoration — it determines **numerical precision**, **memory footprint**, **speed**, and **compatibility with hardware** (GPUs prefer float32).

---

## The dtype Family Tree

```
NumPy dtypes
│
├── Integer
│   ├── Signed:    int8  int16  int32  int64
│   └── Unsigned:  uint8 uint16 uint32 uint64
│
├── Floating point
│   ├── float16  (half precision)
│   ├── float32  (single precision)
│   └── float64  (double precision)  ← Python's default float
│
├── Complex
│   ├── complex64   (two float32s)
│   └── complex128  (two float64s)
│
├── Boolean
│   └── bool_   (1 byte, True/False)
│
└── String / Object  (rarely used in numerical work)
    ├── str_
    └── object_
```

## Integer Types

Signed integers can hold negative numbers. Unsigned integers cannot — but they get double the positive range for the same byte count.

|dtype|Bytes|Min|Max|
|---|---|---|---|
|`int8`|1|−128|127|
|`int16`|2|−32,768|32,767|
|`int32`|4|−2,147,483,648|~2.1 billion|
|`int64`|8|−9.2 × 10¹⁸|9.2 × 10¹⁸|
|`uint8`|1|0|255|
|`uint16`|2|0|65,535|
|`uint32`|4|0|~4.3 billion|
|`uint64`|8|0|1.8 × 10¹⁹|

```python
# int8 overflow — silent and deadly
a = np.array([127], dtype=np.int8)
a[0] += 1
print(a)  # [-128]  ← wrapped around! No error raised.

# uint8 — perfect for image pixels (0–255)
img = np.array([0, 128, 255], dtype=np.uint8)
```

> **Rule of thumb:** use `int32` as your default integer. Use `int64` when indexing very large datasets. Use `uint8` for image pixels. Use smaller types only when memory is genuinely constrained.

## Floating Point Types

This is where precision lives and where ML practitioners make expensive mistakes.

|dtype|Bytes|Decimal digits|Range|
|---|---|---|---|
|`float16`|2|~3|±65504|
|`float32`|4|~7|±3.4 × 10³⁸|
|`float64`|8|~15|±1.8 × 10³⁰⁸|

### How floating point numbers are stored

Every float is stored in three parts using the **IEEE 754** standard:

```
float32 (32 bits total):
┌─┬──────────┬─────────────────────────┐
│S│ Exponent │       Mantissa          │
│1│    8     │           23            │
└─┴──────────┴─────────────────────────┘
S = sign bit (0 = positive, 1 = negative)
Exponent = where the decimal point sits
Mantissa = the actual significant digits

Value = (-1)^S × 2^(Exponent-127) × (1 + Mantissa/2^23)
```

What this means practically: **floats cannot represent most decimal numbers exactly**.

```python
# Classic floating point trap
print(0.1 + 0.2)          # 0.30000000000000004
print(0.1 + 0.2 == 0.3)   # False

# float32 loses precision faster than float64
a32 = np.float32(1.0) + np.float32(1e-8)
a64 = np.float64(1.0) + np.float64(1e-8)
print(a32 - 1.0)  # 0.0        ← float32 cannot see 1e-8
print(a64 - 1.0)  # 1e-08      ← float64 can
```

### float16 — half precision

Only ~3 significant decimal digits. Maximum value is 65504 — exceed that and you get `inf`.

```python
a = np.float16(60000)
b = np.float16(60000)
print(a + b)  # inf  ← overflow at 65504
```

Used almost exclusively in deep learning inference on GPUs where memory bandwidth is the bottleneck and the small precision loss is acceptable.

## Boolean Type

`bool_` stores `True` or `False`, each occupying **1 byte**.

```python
mask = np.array([True, False, True, True])
print(mask.dtype)     # bool

# Arithmetic on booleans — True = 1, False = 0
print(mask.sum())     # 3  ← counts True values
print(mask.mean())    # 0.75

# Boolean arrays are used for masking
data = np.array([10, 20, 30, 40])
print(data[mask])     # [10 30 40]
```

Boolean arrays are the foundation of **attention masks** in Transformers — a bool array saying "which tokens are real vs padding".

---

## Complex Types

A complex number is two floats bundled together: real part + imaginary part.

|dtype|Bytes|Each part|
|---|---|---|
|`complex64`|8|two `float32`|
|`complex128`|16|two `float64`|

```python
z = np.array([1 + 2j, 3 + 4j], dtype=np.complex64)
print(z.real)  # [1. 3.]
print(z.imag)  # [2. 4.]
print(np.abs(z))  # [2.236 5.   ]  ← magnitude
```

Used in **Fourier transforms** — `np.fft.fft()` returns complex64/128 arrays because frequency components have both magnitude (amplitude) and phase.

## dtype Inference — What NumPy Chooses Automatically

When you do not specify a dtype, NumPy infers it from your data:

```python
np.array([1, 2, 3])            # int64   (integers)
np.array([1.0, 2.0, 3.0])     # float64 (floats)
np.array([1, 2.0, 3])         # float64 (mixed → upcasts to float)
np.array([True, False])        # bool
np.array([1+2j])               # complex128
np.array(["hello", "world"])   # <U5 (Unicode string)
```

**The upcasting rule:** when types mix, NumPy always promotes to the type that can represent all values without loss:

```
bool → int → float → complex
```

```python
a = np.array([1, 2, 3], dtype=np.int32)
b = np.array([1.0, 2.0, 3.0], dtype=np.float64)
c = a + b
print(c.dtype)  # float64  ← int32 was upcast
```

## Inspecting and Converting dtypes

```python
a = np.array([1, 2, 3], dtype=np.int32)

# Inspect
print(a.dtype)           # int32
print(a.dtype.name)      # 'int32'
print(a.dtype.itemsize)  # 4

# Convert — astype() always returns a copy
b = a.astype(np.float64)
print(b.dtype)           # float64
print(np.shares_memory(a, b))  # False — new buffer

# Dangerous downcast — data loss is silent
c = np.array([3.9, 7.6], dtype=np.float64)
d = c.astype(np.int32)
print(d)  # [3 7]  ← truncated, not rounded
```

**Checking at runtime:**

```python
a = np.array([1.0, 2.0])

# Check dtype kind
print(a.dtype.kind)    # 'f' = float
                       # 'i' = signed int
                       # 'u' = unsigned int
                       # 'b' = boolean
                       # 'c' = complex

# Safer checks
np.issubdtype(a.dtype, np.floating)   # True
np.issubdtype(a.dtype, np.integer)    # False
np.issubdtype(a.dtype, np.number)     # True
```

|String|dtype|

|`'f4'` or `'float32'`|float32|
|`'f8'` or `'float64'`|float64|
|`'i4'` or `'int32'`|int32|
|`'i8'` or `'int64'`|int64|
|`'u1'` or `'uint8'`|uint8|
|`'b'` or `'bool'`|bool|
|`'c8'` or `'complex64'`|complex64|

```python

b = np.ones(5, dtype='i4')    # int32
```

## Memory Layout Visualised

The same logical value `1.0` looks completely different in memory depending on dtype:

```
float64 (8 bytes):
[ 3F | F0 | 00 | 00 | 00 | 00 | 00 | 00 ]  (IEEE 754 double)

float32 (4 bytes):
[ 3F | 80 | 00 | 00 ]                       (IEEE 754 single)

float16 (2 bytes):
[ 3C | 00 ]                                 (IEEE 754 half)

int32 (4 bytes):
[ 01 | 00 | 00 | 00 ]                       (two's complement)
```

An array of 1 million float64s costs **8 MB**.  
The same array in float32 costs **4 MB**.  
In float16: **2 MB**.

For a model with 175 billion parameters (GPT-3), the difference between float32 and float16 is **350 GB vs 175 GB** of GPU memory.

## Connection to AI / ML / Deep Learning

This is where dtype choice has real, money-on-the-line consequences.

### float32 — The Default of Deep Learning

GPUs are designed to crunch float32 at maximum throughput. Modern NVIDIA GPUs do float32 matrix multiplications in their CUDA cores at the chip's full rated performance.

```python
# PyTorch defaults to float32 — this is intentional
import torch
W = torch.randn(512, 512)
print(W.dtype)  # torch.float32
```

**Why not float64?** Because float64 halves memory bandwidth and halves GPU throughput. The extra precision almost never improves model accuracy — and costs 2× in time and memory.

### float16 / bfloat16 — Mixed Precision Training

Modern training uses **mixed precision**: keep the master weights in float32 for numerical stability during the gradient update, but do the forward/backward pass in float16 for speed.

```
Forward pass:    float16  (fast, less memory)
Loss compute:    float32  (stable)
Gradient:        float16 → scaled to float32
Weight update:   float32 (master copy)
```

NVIDIA's **Tensor Cores** run float16 matrix multiplications at 8× the throughput of float32 cores. This is why mixed precision gives nearly free 2–3× speedups.

### int8 — Quantisation (Inference)

After training, weights are **quantised** from float32 → int8 to deploy on edge devices:

```python
# A float32 weight: 4 bytes, ~7 significant digits
# An int8 weight:   1 byte, values from -128 to 127

# 4× memory compression, 4× faster memory bandwidth
# Tiny accuracy loss, usually acceptable for inference
```

GPT-4 running on your phone uses int8 or int4 quantised weights. Without this, the model would not fit.

### bool — Attention Masks

Every Transformer uses a boolean mask to hide padding tokens:

```python
# Sequence lengths vary per sample in a batch
# Shorter sequences are padded with zeros
# The attention mask tells the model which tokens to ignore

mask = np.array([
    [1, 1, 1, 0, 0],   # sentence of 3 tokens, padded to 5
    [1, 1, 1, 1, 1],   # sentence of 5 tokens, no padding
], dtype=np.bool_)
```

### The dtype Precision Cascade

```
Training         → float32  (stability + GPU native)
Large models     → float16/bfloat16 (mixed precision)
Inference edge   → int8 / int4 (quantisation)
Image pixels     → uint8 (0–255, before normalisation)
Normalised image → float32 (after dividing by 255)
```

```
            PRECISION
                △
                │
         float64│
                │
         float32│ ← sweet spot for ML training
                │
         float16│
```

You cannot have all three. Every dtype choice is a point on this triangle. Knowing where your task sits is the mark of someone who understands the stack end-to-end.

## Common Mistakes

```python
# Mistake 1: Overflow with small integer types — no error, silent wrap
a = np.array([200], dtype=np.uint8)
print(a + 100)   # [44]  ← 300 mod 256 = 44. Silent.

# Mistake 2: Assuming astype() rounds — it truncates
a = np.array([3.9, 7.8])
print(a.astype(np.int32))   # [3 7]  ← not [4 8]
# Fix:
print(np.round(a).astype(np.int32))  # [4 8]

# Mistake 3: float16 overflow in intermediate computations
a = np.float16(1000)
b = np.float16(1000)
print(a * b)   # inf  ← 1,000,000 > 65504

# Mistake 4: comparing floats with ==
a = np.float32(0.1) + np.float32(0.2)
print(a == np.float32(0.3))     # False
print(np.isclose(a, 0.3))       # True  ← correct way

# Mistake 5: Forgetting that int arrays do integer division
a = np.array([1, 2, 3], dtype=np.int32)
print(a / 2)    # [0.5 1.  1.5]  ← actually fine in NumPy (returns float64)
print(a // 2)   # [0 1 1]        ← integer floor division
```
